 14장 실습 03 — buffer busy waits 재현과 원인 세그먼트 지목 (V$SEGMENT_STATISTICS)
 목표: 여러 세션이 같은 세그먼트에 동시에 DML을 몰아 buffer busy waits를
       유발하고, V$WAITSTAT(블록 클래스) → V$SEGMENT_STATISTICS(세그먼트)
       → ROW_WAIT_OBJ#(지금 막힌 객체) 순으로 진원지를 지목한다.
 환경: non-CDB=orcl 19.3 (진단 SYS AS SYSDBA / 부하 SQLT@orcl 여러 세션)
 라이선스: V$ 실시간 조회는 라이선스 무관.
 부하: 프리리스트가 하나뿐인 작은 표 BB_TEST 에 여러 세션이 동시 INSERT(핫 블록 경합).
 주의: 개인 실습 환경 전용. 원본 REVIEW_LOG은 건드리지 않는다(복제본만 DML).
================================================================================

-- [터미널 B~] 업무 계정 여러 세션이 같은 세그먼트에 동시 INSERT 를 몰아 핫 블록 경합을 만든다.
--   프리리스트가 하나뿐(FREELISTS 1)인 작은 표라 모든 세션이 같은 블록에 몰린다.
-- [준비] 실습용 표 생성(SQLT). 원본 7개 표는 건드리지 않는다.
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> DROP TABLE bb_test PURGE;   -- 이전 잔재가 있으면

Table dropped.

SQLT@orcl> CREATE TABLE bb_test (id NUMBER, pad VARCHAR2(30))
  2       SEGMENT CREATION IMMEDIATE STORAGE (FREELISTS 1);

Table created.

SQLT@orcl> EXIT

-- [터미널 A] 진단 계정으로 부하 전 기준선을 잡는다.
$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) buffer busy waits 의 부하 전 누적을 적어 둔다(기준선).
--------------------------------------------------------------------------------
SYS@orcl> COLUMN event FORMAT A20

SYS@orcl> SELECT event, total_waits, wait_class
  2       FROM  v$system_event WHERE event = 'buffer busy waits';

EVENT                TOTAL_WAITS WAIT_CLASS
-------------------- ----------- ----------------------------------------------------------------
buffer busy waits         243705 Concurrency

-- 해석: buffer busy 는 Concurrency 클래스다. 디스크에서 블록을 못 가져와 기다리는 I/O 가 아니라,
--   이미 메모리에 있는(올라오는 중인) 같은 블록을 놓고 세션들이 줄 선 것이다. 부하 후 델타를 본다.

-- [터미널 B~] 8세션이 BB_TEST 에 동시 INSERT(각 30만 건, 50건마다 커밋). 약 30~60초.
-- ▶ 부하: bb_insert.sql × 8

--------------------------------------------------------------------------------
-- [2] (조회) 어느 '블록 클래스'에서 경합했나 — V$WAITSTAT.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN class FORMAT A18

SYS@orcl> SELECT class, count, time
  2       FROM  v$waitstat
  3       WHERE count > 0 ORDER BY count DESC FETCH FIRST 4 ROWS ONLY;

CLASS                   COUNT       TIME
------------------ ---------- ----------
data block             302274      78579
undo header              8846        639
1st level bmb             210         21
segment header            126          2

-- 해석: data block 경합이 크면 같은 데이터 블록에 동시 DML 이 몰린 것이다(FREELISTS 1 의 결과).
--   segment header/bmb 는 공간 관리 경합(ASSM/프리리스트), undo header 는 언두 경합이다.

--------------------------------------------------------------------------------
-- [3] (조회) 어느 '세그먼트'가 진원지인가 — V$SEGMENT_STATISTICS(커서보다 오래 남아 안정적).
--------------------------------------------------------------------------------
SYS@orcl> COLUMN object_name FORMAT A18

SYS@orcl> SELECT object_name, statistic_name, value
  2       FROM  v$segment_statistics
  3       WHERE owner='SQLT' AND statistic_name = 'buffer busy waits'
  4         AND value > 0
  5       ORDER BY value DESC FETCH FIRST 5 ROWS ONLY;

OBJECT_NAME        STATISTIC_NAME                                                        VALUE
------------------ ---------------------------------------------------------------- ----------
BB_TEST            buffer busy waits                                                     43178

-- 해석: BB_TEST 가 buffer busy waits 1위다 — 경합의 진원지가 이 세그먼트임이 세그먼트 통계로 확정된다.
--   (V$WAITSTAT 는 '어떤 종류의 블록', V$SEGMENT_STATISTICS 는 '어느 객체'를 알려 준다.)

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: "buffer busy 가 보이니 디스크가 느리다, 스토리지를 늘리자"고 한다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인 파악: 지금 그 순간 대기 중인 세션을 잡을 수도 있다(각 대기가 1ms 미만이라 포착은 확률적).
SYS@orcl> COLUMN event FORMAT A20

SYS@orcl> SELECT sid, event, row_wait_obj#
  2       FROM  v$session
  3       WHERE event = 'buffer busy waits';

no rows selected

-- 원인 확정: data block 경합 + 진원지 BB_TEST. 디스크가 느린 게 아니라 '같은 블록에 동시 INSERT 가 몰린'
--   동시성 문제다. 조치는 '경합 분산'이다 — FREELISTS 를 늘리거나 ASSM 을 쓰고, 순차 증가 PK 는 역키 인덱스로,
--   핫 세그먼트는 해시 파티션으로 쪼갠다. 디스크 교체는 buffer busy 의 처방이 아니다.
SYS@orcl> -- 재확인: 분산 후 같은 부하를 다시 걸어 V$WAITSTAT data block count 와
SYS@orcl> --   V$SEGMENT_STATISTICS 의 buffer busy waits 증가분이 줄었는지 확인한다.

--------------------------------------------------------------------------------
-- [준비 정리] 실습용 표를 삭제한다.
--------------------------------------------------------------------------------
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> DROP TABLE bb_test PURGE;

Table dropped.

SQLT@orcl> EXIT

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) buffer busy waits는 I/O가 아니라 동시성(Concurrency) 문제다.
-- 2) 추적 순서: V$WAITSTAT(블록 클래스) → V$SEGMENT_STATISTICS(세그먼트)
--    → ROW_WAIT_OBJ#(지금 막힌 객체).
-- 3) 처방은 '디스크'가 아니라 '경합 분산'(역키·해시 파티션·세그먼트 분산).
-- 4) 원본은 불변, 실습용 BB_TEST 에서만 경합을 재현하고 끝에 삭제했다.

SYS@orcl> EXIT
