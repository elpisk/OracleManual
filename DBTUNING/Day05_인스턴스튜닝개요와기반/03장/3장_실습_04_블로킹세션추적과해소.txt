       SID USERNAME EVENT                                   BLK WAIT_CLASS
---------- -------- -------------------------------- ---------- ------------

-- 해석(핵심): SID 602 이 대기자다. EVENT 가 'enq: TX - row lock contention',
--   WAIT_CLASS 가 Application 이며 BLK(blocking_session)에 596 이 찍혔다.
--   즉 602 은 596 에 막혀 있다.
-- ★ 오판 주의 ★ 블로커 596 의 WAIT_CLASS 는 Idle 이다(이 실습에서는 PL/SQL 안에서
--   잠들어 있어 'PL/SQL lock timer', 실무에서는 흔히 'SQL*Net message from client').
--   진짜 범인(596)은 지금 아무 일도 안 하고 유휴 상태로 잠금만 쥐고 있다.
--   '가장 바쁜 세션(602)'을 범인으로 지목하면 정작 유휴 블로커 596 을 놓친다.

  2       FROM  v$lock
  3       WHERE type = 'TX'
  4       ORDER BY sid;

       SID TY      LMODE    REQUEST      BLOCK
---------- -- ---------- ---------- ----------
       203 TX          6          0          1
       602 TX          0          6          0

-- 해석: 596 은 LMODE=6(배타) 보유 + BLOCK=1(다른 세션을 막는 중), REQUEST=0.
--   602 은 LMODE=0(보유 없음), REQUEST=6(배타 요청), BLOCK=0(대기자).
--   V$SESSION 의 BLOCKING_SESSION=596 과 V$LOCK 의 block=1(596)/request=6(602)이
--   같은 사실을 두 각도에서 확인해 준다 → 진단 확신.
