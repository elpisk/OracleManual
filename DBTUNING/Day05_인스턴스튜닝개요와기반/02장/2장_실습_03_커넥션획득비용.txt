================================================================================
 2장 실습 03 — 커넥션 획득 비용 측정: 접속 반복 vs 커넥션 재사용
 목표: 데이터베이스 접속을 매번 새로 여는 것과 하나를 재사용하는 것의 차이를
       logons cumulative 통계로 확인한다. 접속을 닫지 않고 계속 열면 어떤 이상(상한 초과:
       인스턴스면 ORA-00018, 프로파일이면 ORA-02391)이 나는지 재현하고, 커넥션 재사용이 왜 필수인지 확인한다.
 환경: non-CDB=orcl 19.3. 측정·권한 부여는 SYS, 부하는 SQLT로 수행.
 주의: 개인 실습 환경 전용. 세션을 대량으로 여는 부하가 포함된다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 접속 관련 통계와 세션 한도를 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT name, value FROM v$sysstat
  2         WHERE name IN ('logons cumulative','logons current');

NAME                                                                  VALUE
---------------------------------------------------------------- ----------
logons cumulative                                                      1961
logons current                                                           59

SYS@orcl> COLUMN name FORMAT A20

SYS@orcl> COLUMN pvalue FORMAT A10

SYS@orcl> SELECT name, value pvalue FROM v$parameter WHERE name IN ('sessions','processes');

NAME                 PVALUE
-------------------- ----------
processes            500
sessions             772

-- 해석: logons cumulative는 기동 이후 누적 로그온 수(재접속마다 증가),
--   logons current는 현재 접속 수다. sessions는 동시 세션 상한이다.
--   이 값들을 기준선으로 두고 아래 두 시나리오를 대조한다.

--------------------------------------------------------------------------------
-- [2] (조치/조회 A) 시나리오 A: 접속을 반복한다(매 작업마다 로그온/로그오프).
--------------------------------------------------------------------------------
SYS@orcl> -- OS 셸에서 반복 접속을 흉내 낸다(예: 100회 로그온-쿼리-로그아웃).
$ for i in $(seq 1 100); do echo "SELECT 1 FROM dual;" | sqlplus -s sqlt/sqlt@orcl >/dev/null; done

SYS@orcl> SELECT name, value FROM v$sysstat WHERE name = 'logons cumulative';

NAME                      VALUE
-------------------- ----------
logons cumulative          2061

-- 해석: 반복 접속 100회만큼 logons cumulative가 늘었다. 접속 자체가
--   프로세스 생성·세션 메모리 할당·인증을 매번 유발하는 비싼 작업임을 보여 준다.

--------------------------------------------------------------------------------
-- [3] (이상 → 원인 → 조치 → 재확인) 커넥션을 닫지 않고 계속 열면?
--------------------------------------------------------------------------------
SYS@orcl> -- 닫지 않은 채 세션을 계속 여는 부하를 흉내 내면 상한에 걸린다. 인스턴스 상한(sessions)까지
SYS@orcl> --   수백 개를 열면 실습 VM 이 버티지 못하므로, 프로파일로 SQLT 의 동시 세션 상한을 5 로 낮춰 같은
SYS@orcl> --   현상을 작게 재현한다(resource_limit=TRUE 여야 프로파일 제한이 작동한다).
SYS@orcl> SHOW PARAMETER resource_limit

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
resource_limit                       boolean     TRUE

SYS@orcl> CREATE PROFILE demo_pool LIMIT SESSIONS_PER_USER 5;

Profile created.

SYS@orcl> ALTER USER sqlt PROFILE demo_pool;

User altered.

SYS@orcl> -- 반환하지 않는 커넥션 5개: 각 세션이 접속만 하고 120초 동안 아무것도 안 한다(유휴 누수).
$ for i in 1 2 3 4 5; do (echo "EXEC DBMS_SESSION.SLEEP(120)" | sqlplus -s sqlt/sqlt@orcl >/dev/null &); done

-- ▶ 잠시 대기: 5초

$ sqlplus sqlt/sqlt@orcl

ERROR:
ORA-02391: exceeded simultaneous SESSIONS_PER_USER limit

-- 이상 징후: 새 접속이 ORA-02391(SESSIONS_PER_USER 초과)로 거부된다. 인스턴스 상한이었다면 ORA-00018.
-- 원인 파악: 커넥션을 반납/종료하지 않고 계속 새로 열어 상한을 소진했다.
--   이는 커넥션 풀 없이 매 요청마다 접속하고 닫지 않을 때의 전형적 장애다.
-- 조치: 유휴 세션을 정리하고, 근본적으로 커넥션 풀을 도입해 재사용한다.

SYS@orcl> COLUMN username FORMAT A10

SYS@orcl> COLUMN status FORMAT A8

SYS@orcl> COLUMN event FORMAT A30

SYS@orcl> SELECT sid, serial#, username, status, event
  2         FROM v$session WHERE username = 'SQLT'
  3        FETCH FIRST 5 ROWS ONLY;

       SID    SERIAL# USERNAME   STATUS   EVENT
---------- ---------- ---------- -------- ------------------------------
        24      59168 SQLT       ACTIVE   PL/SQL lock timer
       217      12595 SQLT       ACTIVE   PL/SQL lock timer
       409      36211 SQLT       ACTIVE   PL/SQL lock timer
       601       9884 SQLT       ACTIVE   PL/SQL lock timer
       602      48019 SQLT       ACTIVE   PL/SQL lock timer

SYS@orcl> -- (개인 실습) 누수된 유휴 세션을 정리한다 — 5개를 한 번에.
SYS@orcl> --   잠들어 있는(DBMS_SESSION.SLEEP 중) 세션은 KILL 이 즉시 끝나지 않고 ORA-00031(표시만 됨)을
SYS@orcl> --   돌려주는 일이 잦다. 이 오류는 '곧 죽는다'는 뜻이므로 삼키고 넘어간 뒤 잠시 후 재확인한다.
SYS@orcl> SET SERVEROUTPUT ON

SYS@orcl> DECLARE
  2         n NUMBER := 0;
  3       BEGIN
  4         FOR r IN (SELECT sid, serial# FROM v$session
  5                    WHERE username = 'SQLT' AND status <> 'KILLED') LOOP
  6           BEGIN
  7             EXECUTE IMMEDIATE 'ALTER SYSTEM KILL SESSION ''' || r.sid || ',' || r.serial# || ''' IMMEDIATE';
  8           EXCEPTION WHEN OTHERS THEN
  9             IF SQLCODE <> -31 THEN RAISE; END IF;   -- ORA-00031: session marked for kill
 10           END;
 11           n := n + 1;
 12         END LOOP;
 13         DBMS_OUTPUT.PUT_LINE('killed: ' || n);
 14       END;
 15       /

killed: 5

PL/SQL procedure successfully completed.

-- ▶ 잠시 대기: 5초

SYS@orcl> SELECT COUNT(*) alive FROM v$session WHERE username = 'SQLT' AND status <> 'KILLED';

     ALIVE
----------
         0

-- 재확인: 세션을 정리한 뒤 다시 접속하면 성공한다.
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> -- 접속 성공. ORA-02391 해소.
SQLT@orcl> EXIT

SYS@orcl> -- 실습용 프로파일 원복
SYS@orcl> ALTER USER sqlt PROFILE DEFAULT;

User altered.

SYS@orcl> DROP PROFILE demo_pool;

Profile dropped.

--------------------------------------------------------------------------------
-- [4] (조치/조회 B) 시나리오 B: 커넥션 하나를 재사용한다.
--------------------------------------------------------------------------------
SYS@orcl> -- [3] 에서 세션을 여럿 여닫았으니 기준선을 다시 잡는다.
SYS@orcl> SELECT name, value FROM v$sysstat WHERE name = 'logons cumulative';

NAME                      VALUE
-------------------- ----------
logons cumulative          2068

SYS@orcl> -- 한 세션을 유지한 채 같은 100개 작업을 수행한다.
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> DECLARE
  2         d NUMBER;
  3       BEGIN
  4         FOR i IN 1..100 LOOP
  5           EXECUTE IMMEDIATE 'SELECT 1 FROM dual' INTO d;
  6         END LOOP;
  7       END;
  8       /

PL/SQL procedure successfully completed.

SQLT@orcl> EXIT

SYS@orcl> SELECT name, value FROM v$sysstat WHERE name = 'logons cumulative';

NAME                      VALUE
-------------------- ----------
logons cumulative          2069

-- 해석: 같은 100개 작업인데 접속은 1회만 늘었다(직전 기준선 +1). 커넥션을 재사용하면
--   접속 비용을 요청마다가 아니라 최초 1회만 치른다.

--------------------------------------------------------------------------------
-- [5] (결과 해석) 두 시나리오 대조.
--------------------------------------------------------------------------------
-- * 시나리오 A(반복 접속): logons cumulative가 작업 수만큼 증가(약 +100).
-- * 시나리오 B(재사용):    logons cumulative가 거의 불변(약 +1).
-- * 짧은 시간에 logons cumulative가 급증하면 = 매 요청 재접속 설계를 의심.
-- * 4-CPU OLTP 테스트: 무파싱 270 / 소프트 150 / 하드 60 / 재접속 30명.
--   재접속은 하드 파싱보다도 나쁘다(빈 세션이라 파싱 비용까지 겹침).

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 접속은 비싸다. 반복 접속은 logons cumulative를 작업 수만큼 늘린다.
-- 2) 커넥션을 닫지 않고 계속 열면 상한 초과(ORA-00018, 프로파일 제한이면 ORA-02391)가 난다.
-- 3) 커넥션 풀로 재사용하면 접속 비용과 파싱 비용을 함께 줄인다.
-- 4) 진단은 V$SYSSTAT·V$SESSION 조회로 충분(라이선스 불필요).

SYS@orcl> EXIT
