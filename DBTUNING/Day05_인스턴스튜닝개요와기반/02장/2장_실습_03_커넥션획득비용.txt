================================================================================
 2장 실습 03 — 커넥션 획득 비용 측정: 접속 반복 vs 커넥션 재사용
 목표: 데이터베이스 접속을 매번 새로 여는 것과 하나를 재사용하는 것의 차이를
       logons cumulative 통계로 확인한다. 접속을 반복하면 어떤 이상(ORA-00018)이
       나타날 수 있는지 재현하고, 커넥션 재사용이 왜 필수인지 확인한다.
 환경: non-CDB=orcl 19.3. 측정·권한 부여는 SYS, 부하는 SQLT로 수행.
 주의: 개인 실습 환경 전용. 세션을 대량으로 여는 부하가 포함된다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 접속 관련 통계와 세션 한도를 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT name, value FROM v$sysstat
  2         WHERE name IN ('logons cumulative','logons current');

NAME                                VALUE
------------------------------ ----------
logons cumulative                <환경값>
logons current                   <환경값>

SYS@orcl> SELECT name, value FROM v$parameter WHERE name IN ('sessions','processes');

NAME                                VALUE
------------------------------ ----------
processes                        <환경값>
sessions                         <환경값>

-- 해석: logons cumulative는 기동 이후 누적 로그온 수(재접속마다 증가),
--   logons current는 현재 접속 수다. sessions는 동시 세션 상한이다.
--   이 값들을 기준선으로 두고 아래 두 시나리오를 대조한다.

--------------------------------------------------------------------------------
-- [2] (조치/조회 A) 시나리오 A: 접속을 반복한다(매 작업마다 로그온/로그오프).
--------------------------------------------------------------------------------
SYS@orcl> -- OS 셸에서 반복 접속을 흉내 낸다(예: 100회 로그온-쿼리-로그아웃).
$ for i in $(seq 1 100); do echo "SELECT 1 FROM dual;" | sqlplus -s sqlt/sqlt@orcl >/dev/null; done

SYS@orcl> SELECT name, value FROM v$sysstat WHERE name = 'logons cumulative';

NAME                                VALUE
------------------------------ ----------
logons cumulative                <환경값>   -- 기준선보다 약 100 증가

-- 해석: 반복 접속 100회만큼 logons cumulative가 늘었다. 접속 자체가
--   프로세스 생성·세션 메모리 할당·인증을 매번 유발하는 비싼 작업임을 보여 준다.

--------------------------------------------------------------------------------
-- [3] (이상 → 원인 → 조치 → 재확인) 커넥션을 닫지 않고 계속 열면?
--------------------------------------------------------------------------------
SYS@orcl> -- 닫지 않은 채 세션을 계속 여는 부하를 흉내 내면 세션 상한에 걸린다.
$ (반환하지 않는 커넥션을 sessions 상한까지 반복 생성)

$ sqlplus sqlt/sqlt@orcl
ERROR:
ORA-00018: maximum number of sessions exceeded

-- 이상 징후: 새 접속이 ORA-00018로 거부된다.
-- 원인 파악: 커넥션을 반납/종료하지 않고 계속 새로 열어 sessions 상한을 소진했다.
--   이는 커넥션 풀 없이 매 요청마다 접속하고 닫지 않을 때의 전형적 장애다.
-- 조치: 유휴 세션을 정리하고, 근본적으로 커넥션 풀을 도입해 재사용한다.

SYS@orcl> SELECT sid, serial#, username, status, logon_time
  2         FROM v$session WHERE username = 'SQLT' AND status = 'INACTIVE'
  3        FETCH FIRST 5 ROWS ONLY;

       SID    SERIAL# USERNAME   STATUS     LOGON_TIME
---------- ---------- ---------- ---------- -------------------
   <환경값>   <환경값> SQLT       INACTIVE   <환경값>

SYS@orcl> -- (개인 실습) 누수된 유휴 세션을 정리한다.
SYS@orcl> ALTER SYSTEM KILL SESSION '<sid>,<serial#>' IMMEDIATE;
System altered.

-- 재확인: 세션을 정리한 뒤 다시 접속하면 성공한다.
$ sqlplus sqlt/sqlt@orcl
SQLT@orcl> -- 접속 성공. ORA-00018 해소.
SQLT@orcl> EXIT

--------------------------------------------------------------------------------
-- [4] (조치/조회 B) 시나리오 B: 커넥션 하나를 재사용한다.
--------------------------------------------------------------------------------
SYS@orcl> -- 한 세션을 유지한 채 같은 100개 작업을 수행한다.
$ sqlplus sqlt/sqlt@orcl
SQLT@orcl> BEGIN
  2         FOR i IN 1..100 LOOP
  3           EXECUTE IMMEDIATE 'SELECT 1 FROM dual' INTO :d;
  4         END LOOP;
  5       END;
  6       /
PL/SQL procedure successfully completed.
SQLT@orcl> EXIT

SYS@orcl> SELECT name, value FROM v$sysstat WHERE name = 'logons cumulative';

NAME                                VALUE
------------------------------ ----------
logons cumulative                <환경값>   -- 시나리오 B에서는 약 1만 증가

-- 해석: 같은 100개 작업인데 접속은 1회만 늘었다. 커넥션을 재사용하면
--   접속 비용을 요청마다가 아니라 최초 1회만 치른다.

--------------------------------------------------------------------------------
-- [5] (결과 해석) 두 시나리오 대조.
--------------------------------------------------------------------------------
-- * 시나리오 A(반복 접속): logons cumulative가 작업 수만큼 증가(약 +100).
-- * 시나리오 B(재사용):    logons cumulative가 거의 불변(약 +1).
-- * 짧은 시간에 logons cumulative가 급증하면 = 매 요청 재접속 설계를 의심.
-- * 4-CPU OLTP 테스트: 무파싱 270 / 소프트 150 / 하드 60 / 재접속 30명.
--   재접속은 하드 파싱보다도 나쁘다(빈 세션이라 파싱 비용까지 겹침).

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 접속은 비싸다. 반복 접속은 logons cumulative를 작업 수만큼 늘린다.
-- 2) 커넥션을 닫지 않고 계속 열면 ORA-00018(세션 상한 초과)이 날 수 있다.
-- 3) 커넥션 풀로 재사용하면 접속 비용과 파싱 비용을 함께 줄인다.
-- 4) 진단은 V$SYSSTAT·V$SESSION 조회로 충분(라이선스 불필요).

SYS@orcl> EXIT
