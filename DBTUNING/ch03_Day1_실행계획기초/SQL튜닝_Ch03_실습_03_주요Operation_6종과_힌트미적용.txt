 Ch03 실습 03 — 주요 Operation 6종 관찰 (PK 인덱스만으로) 과 힌트가 무시되는 이상 징후
 목표: 같은 PK 인덱스가 조건 성격에 따라 INDEX UNIQUE / RANGE / FULL / FAST FULL SCAN 으로
       갈리는 것을 Buffers 와 함께 본다. 힌트를 썼는데 계획이 바뀌지 않는 이상 징후를 재현해
       원인(별칭 불일치 — 힌트는 틀려도 오류가 나지 않는다)을 교정한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. DDL 변경 없음.
 주의: 개인 실습 환경 전용. 조회만 수행한다.

--   (단일 블록, 정렬 순서)보다 싸다. 표(3,090)를 읽지 않고 인덱스(1,891)만 읽었다.
--   Q4 처럼 순서가 필요하면 FULL SCAN, Q5 처럼 순서가 필요 없으면 FAST FULL SCAN — 옵티마이저는
--   요구(정렬 여부)에 따라 같은 인덱스를 다르게 읽는다.

--   6종 정리 (이 실습 + 실습 01·02)
--   ┌────┬─────────────────────────────────────┬──────────────────────────────────────┬─────────┐
--   │ #  │ 조건                                │ 핵심 Operation                       │ Buffers │
--   ├────┼─────────────────────────────────────┼──────────────────────────────────────┼─────────┤
--   │ Q1 │ 비인덱스 두 컬럼 (실습 01)          │ TABLE ACCESS FULL                    │  3,117  │
--   │ Q2 │ PK 등치                             │ INDEX UNIQUE SCAN → BY INDEX ROWID   │      4  │
--   │ Q3 │ PK 범위                             │ INDEX RANGE SCAN → ...BATCHED        │      9  │
--   │ Q4 │ ORDER BY PK, 상위 5건               │ INDEX FULL SCAN + WINDOW NOSORT      │      4  │
--   │ Q4'│ 같은 SQL, FULL(m) 강제              │ TABLE ACCESS FULL + WINDOW SORT      │  3,090  │
--   │ Q5 │ COUNT(PK)                           │ INDEX FAST FULL SCAN + SORT AGGREGATE│  1,891  │
--   │ Q6 │ 조인 + GROUP BY (실습 02)           │ HASH JOIN + HASH GROUP BY            │  3,093  │
--   └────┴─────────────────────────────────────┴──────────────────────────────────────┴─────────┘

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 같은 PK 인덱스도 등치/범위/정렬 활용/집계에 따라 UNIQUE/RANGE/FULL/FAST FULL 로 읽힌다.
-- 2) 힌트는 틀려도 오류가 없다. 별칭을 썼으면 힌트도 별칭으로. 반드시 계획(+HINT_REPORT)으로 검증.
-- 3) INDEX FULL SCAN 은 정렬 순서가 필요할 때, FAST FULL SCAN 은 순서가 필요 없을 때.
-- 4) SELECT 목록이 인덱스 컬럼뿐이면 표를 읽지 않는다(Q4·Q5) — Ch04 의 "Index-Only" 로 이어진다.
