================================================================================
 5장 실습 02 — 세션 시간 모델로 부하 구간의 시간 사용 분해 (V$SESS_TIME_MODEL)
 목표: 내 세션의 부하 전후 DB Time을 델타로 재서 '이 구간이 DB Time을 얼마나
       썼는가'를 분해한다. 짧은 구간(0.3초)에서 CPU/대기 분해가 불안정해지는
       이상 징후를 재현하고, 대기의 실체는 V$SESSION_EVENT로 확인함을 익힌다.
 환경: non-CDB=orcl 19.3 (업무 계정 SQLT로 수행 — 자기 세션 측정)
 주의: 개인 실습 환경 전용. 아래 [2]에서 버퍼 캐시를 비운다(FLUSH BUFFER_CACHE).
       ★ 이 명령은 운영 DB 절대 금지 ★ — 전체 응답시간이 급락한다.
================================================================================

-- (터미널 A) 부하·측정 세션
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> SET LINESIZE 200

SQLT@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 내 세션의 SID와 부하 전 시간 모델 누적값을 캡처한다.
--------------------------------------------------------------------------------
SQLT@orcl> SELECT sys_context('USERENV','SID') my_sid FROM dual;

MY_SID
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
601

SQLT@orcl> -- 부하 전(T0) DB time / DB CPU 누적값 (V$SESS_TIME_MODEL, 내 세션)
SQLT@orcl> COLUMN stat_name FORMAT A12

SQLT@orcl> SELECT stat_name, value
  2       FROM  v$sess_time_model
  3       WHERE sid = sys_context('USERENV','SID')
  4         AND stat_name IN ('DB time','DB CPU');

STAT_NAME         VALUE
------------ ----------
DB time           21174
DB CPU            14244

SQLT@orcl> -- 같은 값을 치환 변수에 담아 두면 델타를 SQL 로 뺄 수 있다.
SQLT@orcl> COLUMN t0_time NEW_VALUE t0_time

SQLT@orcl> COLUMN t0_cpu  NEW_VALUE t0_cpu

SQLT@orcl> SELECT MAX(DECODE(stat_name, 'DB time', value)) t0_time,
  2              MAX(DECODE(stat_name, 'DB CPU',  value)) t0_cpu
  3       FROM   v$sess_time_model WHERE sid = sys_context('USERENV','SID');

   T0_TIME     T0_CPU
---------- ----------
     24501      15896

--------------------------------------------------------------------------------
-- [2] (조치) 물리 I/O가 DB time에 잡히도록 캐시를 비운 뒤 대량 스캔을 돌린다.
--     ★ 개인 실습 환경 전용 ★  운영 DB에서는 절대 실행하지 않는다.
--------------------------------------------------------------------------------
-- (터미널 B) SYSDBA 세션에서 1회 — 버퍼 캐시를 비운다.
$ sqlplus / as sysdba

SYS@orcl> ALTER SYSTEM FLUSH BUFFER_CACHE;

System altered.

-- (터미널 A) 이후 조회는 디스크부터 다시 읽어 db file scattered read 가 발생한다.
SQLT@orcl> ALTER SESSION SET "_serial_direct_read" = NEVER;

Session altered.

SQLT@orcl> -- 약 0.3초짜리 대량 스캔(WL_06 축약). 벽시계 약 0.3초.
SQLT@orcl> SELECT /*+ FULL(d) NO_PARALLEL(d) */ SUM(d.amt)
  2       FROM claim_details d WHERE d.qty >= 0;

SUM(D.AMT)
----------
4.5396E+10

--------------------------------------------------------------------------------
-- [3] (결과) 부하 후(T1) 시간 모델을 다시 캡처해 델타를 계산한다.
--------------------------------------------------------------------------------
SQLT@orcl> SELECT stat_name, value FROM v$sess_time_model
  2       WHERE sid = sys_context('USERENV','SID')
  3         AND stat_name IN ('DB time','DB CPU');

STAT_NAME         VALUE
------------ ----------
DB time           92526
DB CPU            84716

SQLT@orcl> -- 델타 = T1 - T0 를 SQL 로 뺀다.
SQLT@orcl> SELECT MAX(DECODE(stat_name, 'DB time', value)) - &t0_time dbtime_delta_us,
  2              MAX(DECODE(stat_name, 'DB CPU',  value)) - &t0_cpu  dbcpu_delta_us,
  3              ROUND(100 * (MAX(DECODE(stat_name, 'DB CPU', value)) - &t0_cpu)
  4                        / (MAX(DECODE(stat_name, 'DB time', value)) - &t0_time), 1) cpu_pct
  5       FROM   v$sess_time_model WHERE sid = sys_context('USERENV','SID');

old   1: SELECT MAX(DECODE(stat_name, 'DB time', value)) - &t0_time dbtime_delta_us,
new   1: SELECT MAX(DECODE(stat_name, 'DB time', value)) -      24501 dbtime_delta_us,
old   2:             MAX(DECODE(stat_name, 'DB CPU',  value)) - &t0_cpu  dbcpu_delta_us,
new   2:             MAX(DECODE(stat_name, 'DB CPU',  value)) -      15896  dbcpu_delta_us,
old   3:             ROUND(100 * (MAX(DECODE(stat_name, 'DB CPU', value)) - &t0_cpu)
new   3:             ROUND(100 * (MAX(DECODE(stat_name, 'DB CPU', value)) -      15896)
old   4:                       / (MAX(DECODE(stat_name, 'DB time', value)) - &t0_time), 1) cpu_pct
new   4:                       / (MAX(DECODE(stat_name, 'DB time', value)) -      24501), 1) cpu_pct

DBTIME_DELTA_US DBCPU_DELTA_US    CPU_PCT
--------------- -------------- ----------
          69144          69546      100.6

-- 이번 캡처의 부하 구간 델타(실측): DB time 69,144us(약 0.07초) / DB CPU 69,546us → CPU 100.6%, 대기 -0.6%.
--   (SSD 위의 VM 이라 90만 행 전체 스캔이 0.07초에 끝난다.)

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: DB CPU 델타(69,546)가 DB time 델타(69,144)보다 크다.
--       'DB time - DB CPU = 대기'가 음수(-0.6%)가 된다. 물리적으로 불가능해 보인다.
--------------------------------------------------------------------------------
SQLT@orcl> -- 원인 파악: 버그가 아니다. 구간이 0.07초로 너무 짧아 DB time과 DB CPU
SQLT@orcl> --   카운터의 갱신 시점이 미세하게 어긋나고 반올림이 겹쳐 분해가 불안정한 것.
SQLT@orcl> --   짧은 순간에는 시간 모델의 CPU/대기 쪼개기를 곧이곧대로 믿으면 안 된다.
SQLT@orcl> -- 조치: 대기의 실체는 시간 모델 비율이 아니라 V$SESSION_EVENT에서 확인한다.
SQLT@orcl> COLUMN event FORMAT A30

SQLT@orcl> SELECT event, total_waits, ROUND(time_waited_micro/1000) ms
  2       FROM  v$session_event
  3       WHERE sid = sys_context('USERENV','SID')
  4         AND wait_class <> 'Idle'
  5       ORDER BY time_waited_micro DESC;

EVENT                          TOTAL_WAITS         MS
------------------------------ ----------- ----------
db file sequential read                  6         24
db file scattered read                  69         21
Disk file operations I/O                 4          0
events in waitclass Other               12          0
SQL*Net message to client               22          0
log file sync                            1          0

6 rows selected.

-- 재확인: db file scattered read 를 69회·21ms 기다렸다 → 물리 I/O 대기가
--   분명히 있었다. 짧은 구간의 -0.6% 는 노이즈였고, 21ms(+ sequential read 24ms)가 대기의 실체다.
--   scattered read(다중 블록) 횟수가 sequential read(단일 블록)보다 압도적으로 많은 것은
--   이 부하가 대량 전체 스캔 위주였음을 말해 준다. (CPU 69ms + 대기 45ms > DB time 69ms —
--   짧은 구간에서는 이렇게 합이 맞지 않는다.)
-- 결론: 정확한 CPU/대기 비율이 필요하면 순간이 아니라 수 분짜리 AWR 구간으로
--   봐야 한다(→ 6장). 이것이 5장이 6장으로 이어지는 다리다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 세션 뷰(V$SESS_TIME_MODEL)로 다른 세션 영향을 배제하고 내 구간만 쟀다.
-- 2) 부하 구간 DB time 델타 69,144us / DB CPU 델타 69,546us (짧은 구간이라 불안정).
-- 3) 대기의 증거는 V$SESSION_EVENT의 db file scattered read 69회·21ms.
-- 4) 짧은 구간은 시간 모델 분해가 흔들린다 → 수 분 구간(AWR)이 필요하다.
-- ※ V$SESS_TIME_MODEL·V$SESSION_EVENT 조회는 라이선스가 필요 없다.

SQLT@orcl> EXIT
