 Ch06 실습 01 — 묵시적 형변환: 따옴표 하나 차이로 인덱스가 죽는다 (BIRTH_DATE 세 조건)
 목표: PATIENTS.BIRTH_DATE(VARCHAR2 'YYYYMMDD')에 인덱스를 만들고 문자열 리터럴 / 숫자 리터럴 /
       명시적 함수 세 조건을 실측한다(148 / 442 / 442). Predicate Information 에서 컬럼이
       TO_NUMBER() 로 감싸인 것을 "옵티마이저가 컬럼 쪽을 변환했다" 는 증거로 읽는다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. DDL 포함 — 마지막에 지운다.
 주의: 개인 실습 환경 전용.
================================================================================

SQLT@orcl> -- 이상 징후: 결과는 같은데 148 → 442. SQL 은 따옴표 두 개가 사라졌을 뿐이다.
SQLT@orcl> -- 원인 파악: Predicate 가 답이다. filter(TO_NUMBER("BIRTH_DATE")<=19901231) — 문자열 컬럼과
SQLT@orcl> --   숫자 리터럴을 비교하면 Oracle 은 문자열 쪽을 숫자로 바꾼다(숫자가 우선). 즉 리터럴이
SQLT@orcl> --   아니라 컬럼이 변환됐다. 인덱스는 문자열 순서로 정렬돼 있는데 TO_NUMBER(컬럼) 의 순서와는
SQLT@orcl> --   무관하므로 인덱스를 쓸 수 없다. 개발자가 함수를 쓰지 않았는데 함수가 생긴 것이다.
SQLT@orcl> --   (덤으로, BIRTH_DATE 에 숫자가 아닌 값이 하나라도 있으면 ORA-01722 invalid number 가 난다 —
SQLT@orcl> --    오늘은 안 나던 SQL 이 데이터 한 건 때문에 내일 죽을 수 있다.)
SQLT@orcl> -- 조치: 리터럴의 자료형을 컬럼에 맞춘다 — Q1 로 돌아간다. 응용 프로그램에서는 바인드 변수의
SQLT@orcl> --   자료형(setString vs setInt)이 같은 문제를 일으킨다.
SQLT@orcl> -- 재확인: Q1 재실행 → Buffers 148, filter("BIRTH_DATE"<='19901231') (위 [2] 와 동일, 생략)

-- 해석: Plan hash value 가 Q2 와 같다. "묵시적으로 생긴 TO_NUMBER" 와 "개발자가 쓴 TO_NUMBER(SUBSTR())"
--   는 옵티마이저에게 똑같이 "컬럼이 가공됐다" 이다. 결과는 같지만(1990년 이전) 인덱스는 못 쓴다.

--   ┌──────────────────────────────┬──────────────────────┬─────────┬────────────────────────────────────┐
--   │ 조건                         │ Operation            │ Buffers │ Predicate                          │
--   ├──────────────────────────────┼──────────────────────┼─────────┼────────────────────────────────────┤
--   │ Q1 birth_date <= '19901231'  │ INDEX FAST FULL SCAN │   148   │ filter("BIRTH_DATE"<=…)            │
--   │ Q2 birth_date <= 19901231    │ TABLE ACCESS FULL    │   442   │ filter(TO_NUMBER("BIRTH_DATE")<=…) │
--   │ Q3 TO_NUMBER(SUBSTR(…))<=1990│ TABLE ACCESS FULL    │   442   │ filter(TO_NUMBER(SUBSTR(…))<=…)    │
--   └──────────────────────────────┴──────────────────────┴─────────┴────────────────────────────────────┘

SQLT@orcl> DROP INDEX ix_birth;

-- [정리]

-- 1) 문자열 컬럼 vs 숫자 리터럴 → 컬럼이 TO_NUMBER 로 변환된다. 인덱스 무력화 + ORA-01722 위험.
-- 2) 변환이 일어났는지는 Predicate Information 에서 컬럼이 함수로 감싸였는지로 판정한다.
-- 3) 명시적 함수와 묵시적 변환은 옵티마이저에게 같다(Plan hash 동일).
-- 4) 리터럴·바인드의 자료형을 컬럼에 맞춘다. 컬럼을 가공하지 말고 값을 가공한다(실습 02).
