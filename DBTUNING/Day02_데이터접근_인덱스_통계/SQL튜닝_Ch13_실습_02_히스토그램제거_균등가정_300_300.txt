 Ch13 실습 02 — 히스토그램을 지우면: 두 병원 모두 E-Rows 300 (균등 가정의 실체, ORA-20000 교정)
 목표: METHOD_OPT => 'FOR COLUMNS HOSP_ID SIZE 1' 로 HOSP_ID 히스토그램을 없애고 hosp_id=1·500 의
       E-Rows 가 똑같이 300 이 되는 것을 실측한다. 소유자 이름을 잘못 적어 나는 ORA-20000 을
       재현·교정하고, 과소추정(10배)이 조인 계획에 전파되는 위험을 EXPLAIN PLAN 으로 본다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. 통계를 바꾼다 — 실습 03 에서 반드시 복원한다.
 주의: 개인 실습 환경 전용. 통계 변경은 이 스키마의 모든 SQL 계획에 영향을 준다.

-- [정리]

-- 1) SIZE 1 = 버킷 하나 = 히스토그램 없음. 옵티마이저는 균등 분포(행 수 ÷ 고유값 수)로 추정한다.
-- 2) 스큐 컬럼에서 균등 가정은 popular value 를 10배 과소추정한다(300 vs 3,058).
-- 3) 단일 표 Full Scan 에서는 손해가 안 보이지만, 조인의 입력이 되면 위로 곱해져 전파된다.
-- 4) DBMS_STATS 의 ORA-20000 은 오타와 권한을 구분해 주지 않는다. 소유자는 USER 로 준다.
