================================================================================
 10장 실습 04 — 세션 단위 추적: 한 세션이 무엇을 기다렸는지 시간순 재구성
 목표: 상위 세션 하나를 골라 SAMPLE_TIME 순으로 상태 변화를 펼쳐, '언제 무엇
       때문에 멈췄나'를 복원한다. 블로킹이 의심될 때 BLOCKING_SESSION으로
       역추적하는 절차를 익힌다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 라이선스: 🔒 Diagnostics Pack 필요. 미보유 시 대안은 실습 후반 [5] 참조.
 주의: 개인 실습 환경 전용. 읽기 전용 조회만 수행한다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

SYS@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 추적 대상 세션을 고른다 — 상위 세션 + SERIAL# 확보.
--     세션 번호는 재사용되므로 SERIAL#를 함께 잡아 다른 접속과 섞이지 않게 한다.
--     상위 1개를 치환 변수(&sid,&ser)로 받아 이후 조회에 그대로 쓴다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN sid NEW_VALUE sid

SYS@orcl> COLUMN ser NEW_VALUE ser

SYS@orcl> SELECT session_id sid, session_serial# ser, COUNT(*) AS samples
  2       FROM  v$active_session_history
  3       WHERE sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  4       GROUP BY session_id, session_serial#
  5       ORDER BY samples DESC FETCH FIRST 3 ROWS ONLY;

       SID        SER    SAMPLES
---------- ---------- ----------
        21      62681        127
       409      43576        127
       203      33428        127

SYS@orcl> SET VERIFY OFF

-- 해석: 맨 위 세션(&sid, serial &ser)이 가장 활성 시간이 길었다. 이 세션을 추적한다.

--------------------------------------------------------------------------------
-- [2] (조회) 그 세션의 샘플을 SAMPLE_TIME 순으로 펼친다 — 시간순 재구성.
--     (최근 130초 중 처음 8개 샘플. 절대 시각이 아니라 상대 구간으로 잡는다.)
--------------------------------------------------------------------------------
SYS@orcl> COLUMN event FORMAT A24

SYS@orcl> COLUMN sql_id FORMAT A13

SYS@orcl> SELECT sample_time, session_state AS st, event, sql_id
  2       FROM  v$active_session_history
  3       WHERE session_id = &sid AND session_serial# = &ser
  4         AND sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  5       ORDER BY sample_time FETCH FIRST 8 ROWS ONLY;

-- 해석: 이 세션은 대부분 상위 SQL 을 CPU 에서 수행했고, 중간에 커밋을 하며 log file sync 를
--   잠깐 기다렸다가 CPU 로 복귀한다. 집계로는 안 보이던 '언제 무엇 때문에 멈췄나'가
--   시간축에 드러난다(WAITING 행의 EVENT·SQL_ID).

--------------------------------------------------------------------------------
-- [3] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 시간순으로 펼쳤더니 중간중간 초가 비어 있다며
--       "ASH가 샘플을 놓쳤다(버그)"고 의심한다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인 파악: ASH 는 활성 세션만 담는다. '펼친 구간의 초 수' vs '실제 샘플 수'를 비교한다.
SYS@orcl> SELECT COUNT(DISTINCT CAST(sample_time AS DATE)) AS distinct_seconds,
  2         COUNT(*) AS samples,
  3         ROUND((CAST(MAX(sample_time) AS DATE) - CAST(MIN(sample_time) AS DATE)) * 86400) AS span_seconds
  4       FROM  v$active_session_history
  5       WHERE session_id = &sid AND session_serial# = &ser
  6         AND sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND;

DISTINCT_SECONDS    SAMPLES SPAN_SECONDS
---------------- ---------- ------------
             127        127          129

-- 원인 확정: 샘플 수가 구간 초 수(span_seconds)보다 적다 = 비어 있는 초에는 세션이 활성이
--   아니었다(Idle). 버그가 아니라 정상이다. ASH 의 '빈칸'도 정보다.
-- 조치: 빈 초를 '샘플 누락'이 아니라 'Idle 구간'으로 해석한다. 필요하면
--   V$SESSION 으로 그 세션의 현재 상태를 교차 확인한다.

SYS@orcl> -- 재확인: 세션의 활성 상태 분포(ON CPU vs WAITING)를 본다.
SYS@orcl> SELECT session_state AS st, COUNT(*) AS samples
  2       FROM  v$active_session_history
  3       WHERE session_id = &sid AND session_serial# = &ser
  4         AND sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  5       GROUP BY session_state ORDER BY samples DESC;

ST         SAMPLES
------- ----------
ON CPU          65
WAITING         62

-- 재확인 완료: 이 세션은 대부분 ON CPU, 잠깐씩 WAITING 이었다. 빈 초는
--   활성 아님(Idle) 구간이며 누락이 아니다.

--------------------------------------------------------------------------------
-- [4] (조회) 블로킹 추적 — 이 세션이 다른 세션에 막혔던 적이 있나.
--------------------------------------------------------------------------------
SYS@orcl> SELECT event, blocking_session, COUNT(*) AS samples
  2       FROM  v$active_session_history
  3       WHERE session_id = &sid AND session_serial# = &ser
  4         AND blocking_session IS NOT NULL
  5         AND sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  6       GROUP BY event, blocking_session ORDER BY samples DESC;

-- 해석: blocking_session 이 채워진 샘플이 있으면(여기서는 여러 세션이 같은 복제 표를
--   갱신하며 log file switch·buffer busy 로 잠깐씩 서로를 막았다) 그 BLOCKING_SESSION 번호로
--   넘어가 역추적한다(3장 잠금 실습). 없으면 '이 세션은 막히지 않고 스스로 CPU 를 태웠다'가
--   결론이다. 어느 쪽이든 샘플 수가 작으면 지배 요인은 아니다.

--------------------------------------------------------------------------------
-- [5] (라이선스 대안 경로) V$SESSION으로 지금 그 세션을 실시간 추적.
--------------------------------------------------------------------------------
SYS@orcl> -- 과거 재구성은 ASH만 가능하지만, '지금 이 순간'의 세션 상태·블로커는
SYS@orcl> -- V$SESSION 으로 라이선스 없이 볼 수 있다. 반복 조회하면 근사 추적이 된다.
SYS@orcl> COLUMN state FORMAT A10

SYS@orcl> COLUMN event FORMAT A26

SYS@orcl> SELECT sid, state, event, sql_id, blocking_session
  2       FROM  v$session WHERE sid = &sid;

       SID STATE      EVENT                      SQL_ID        BLOCKING_SESSION
---------- ---------- -------------------------- ------------- ----------------
       203 WAITED KNO resmgr:cpu quantum         8yy5q06wvrpga
           WN TIME

-- 대안 해석: V$SESSION 은 현재 상태만 보여준다. 과거의 시간순 재구성은 못 하지만,
--   짧은 주기로 반복 조회해 적재하면 '수제 세션 추적'이 된다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 세션 추적은 SESSION_ID + SESSION_SERIAL#로 대상을 특정한 뒤 시작한다.
-- 2) SAMPLE_TIME 순으로 펼치면 ON CPU/WAITING 상태 변화가 이야기로 보인다.
-- 3) 빈 초는 샘플 누락이 아니라 그 순간 Idle이었다는 신호다(빈칸도 정보).
-- 4) BLOCKING_SESSION으로 블로커를 역추적한다. 없으면 '블로킹 없음'이 결론.

SYS@orcl> EXIT
