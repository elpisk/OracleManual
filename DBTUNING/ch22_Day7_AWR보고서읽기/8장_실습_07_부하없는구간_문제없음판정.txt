 목표: 유휴 구간의 AWR 보고서를 읽고, 부하가 없어 판정 대상이 아님을 근거
       (AAS·DB Time)와 함께 명시한다. Idle 이벤트(SQL*Net message from client)를
       병목으로 오판하는 상황을 재현·교정한다. 부하 구간(479~480)과 대조한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA)
 대상 구간: 유휴 구간 스냅샷 447~448 (부하 없음) vs 부하 구간 479~480 (대조)
 라이선스: 🔒 Diagnostics Pack. 미보유 시 V$SYSMETRIC/V$SYS_TIME_MODEL로 대체(하단).

-- [2] (조회) 머리말에서 DB Time·Elapsed 로 AAS 를 계산한다 — 부하가 있었나?

         minimal foreground activity in the snapshot period.
   Elapsed:               60.17 (mins)

SYS@orcl> SELECT ROUND(0.00/60.17,3) AS aas_idle FROM dual;

  AAS_IDLE
----------

-- 해석: AAS = DB Time/Elapsed = 0.00/60.17 = 0. 평균 활성 세션이 0 이다(60분 동안 DB Time 이
--   1초도 안 된다). 이 구간에는 '진단할 부하 자체가 없다.'

--------------------------------------------------------------------------------
-- [3] (조회) 그럼에도 Top Events 는 채워져 나온다 — 무엇이 1위인가?
--------------------------------------------------------------------------------
SYS@orcl> HOST awk '/^Top 10 Foreground Events/,/^Wait Classes by Total Wait Time/' awrrpt_1_447_448.txt | head -9

--   상대적일 뿐 절대 크기를 말하지 않는다. (Idle 이벤트인 SQL*Net message from client 는
--   AWR 이 Top 10 에서 아예 제외해 주지만, V$ 로 직접 집계할 때는 5장에서 본 대로 스스로 빼야 한다.)

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 신입이 "DB CPU 가 100% 이니 이 시간대는 CPU 병목이다"라고 판정했다.
--------------------------------------------------------------------------------
-- 원인 파악: 순위·% 만 보고 부하 유무를 확인하지 않은 오판이다.
--   % DB time 은 'DB Time 중 몇 %'다 — 분모(DB Time)가 0 이면 100% 도 0초다.
SYS@orcl> HOST grep -E "^ *DB CPU\(s\)|^ *DB Time\(s\)" awrrpt_1_447_448.txt

             DB Time(s):               0.0               0.0      0.00      0.00
              DB CPU(s):               0.0               0.0      0.00      0.00

-- 원인 확정: Load Profile 의 초당 DB CPU 가 0.0 이다. 보고서 스스로 WARNING 으로 '% 값은
--   무효'라고 말했고, AAS 0 은 애초에 부하가 없었음을 말한다.
-- 조치: '이 구간은 부하가 없어 성능 문제를 논할 대상이 아니다'를 근거(AAS 0,
--   DB Time 0.00분, WARNING)와 함께 기록한다. CPU 증설·튜닝은 하지 않는다.
--   (신고 시각인데 DB 가 한가했다면 병목은 DB 밖 → 20장으로 연결)
-- 재확인: 부하 구간(479~480)과 대조해 판정을 뒷받침한다(아래 [5]).

--------------------------------------------------------------------------------
-- [5] (조치 후 상태) 부하 구간(479~480)과 나란히 대조한다.
--------------------------------------------------------------------------------
SYS@orcl> HOST grep -E "Elapsed:|DB Time:" awrrpt_1_479_480.txt

   Elapsed:                1.22 (mins)
   DB Time:                0.81 (mins)

SYS@orcl> SELECT ROUND(0.81/1.22,2) AS aas_load FROM dual;

  AAS_LOAD
----------
       .66

-- 해석: 부하 구간 AAS ≈ 0.66(=DB Time 49초/Elapsed 73초, 7세션 부하). 유휴 구간 0 과
--   비교하면 유한 대 무한이다. '문제 없음'과 '문제 있음'은 머리말의 AAS 한 줄로 갈린다.
--   Top Events 순위를 보기 전에 반드시 AAS 부터 확인한다. (AAS 0.66 도 4 CPU 대비 낮은
--   편이다 — 이 부하 구간 자체가 '가벼운 부하'였음을 같은 잣대로 말할 수 있다.)

--------------------------------------------------------------------------------
-- [대안 경로] 🔒 미보유 — V$로 부하 유무를 판정한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT ROUND(value,3) aas
  2       FROM  v$sysmetric
  3       WHERE metric_name='Average Active Sessions'
  4         AND intsize_csec BETWEEN 5900 AND 6100;

       AAS
----------
      .044

-- 해석: V$SYSMETRIC 의 Average Active Sessions 로 현재 부하 유무를 즉시 본다.
--   AAS 가 1보다 훨씬 작으면 부하 없음 = 판정 대상 아님. 라이선스 없이도
--   '문제 없음'을 근거와 함께 판정할 수 있다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 부하 유무는 머리말의 AAS=DB Time/Elapsed 로 판정한다(WARNING 이 붙으면 % 는 무효).
-- 2) 유휴 구간(AAS 0)은 Top10 이 채워져도 진단 대상이 아니다.
-- 3) 'DB CPU 100%' 는 0초의 100% 일 수 있다 → 절대량(초, Load Profile) 없이 % 만 읽으면 오판.
-- 4) '문제 없음'도 근거(AAS·DB Time)와 함께 명시하는 것이 좋은 판독이다.
-- 5) 부하 구간(AAS 0.66)과 대조하면 판정이 명확해진다.
-- 6) 라이선스 없으면 V$SYSMETRIC 의 Average Active Sessions 로 동일 판정.

SYS@orcl> EXIT
