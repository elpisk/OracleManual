================================================================================
 16장 실습 04 — 자동 조정 이력 추적(V$SGA_RESIZE_OPS, V$MEMORY_RESIZE_OPS)
 목표: ASMM에서 SGA 풀들이 어떻게 자동으로 커지고 줄었는지 이력을 추적한다.
       GROW/SHRINK가 짝을 이루는 원리를 확인하고, 방식에 따라 어느 뷰가 채워지는지 본다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행), 조회 위주.
 주의: 조회만 수행한다. 이력은 인스턴스가 쌓아 둔 값이라 <환경값>이다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 지금 각 풀이 어느 범위에서 움직여 왔는지 동적 구성을 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT component, ROUND(current_size/1024/1024,1) cur_mb,
  2         ROUND(min_size/1024/1024,1) min_mb,
  3         ROUND(max_size/1024/1024,1) max_mb
  4       FROM v$sga_dynamic_components
  5       WHERE current_size>0 ORDER BY current_size DESC;

COMPONENT                CUR_MB   MIN_MB   MAX_MB
------------------------ -------- -------- --------
DEFAULT buffer cache     <환경값> <환경값> <환경값>
shared pool              <환경값> <환경값> <환경값>
Shared IO Pool           <환경값> <환경값> <환경값>
KEEP buffer cache        <환경값> <환경값> <환경값>
DEFAULT 4K buffer cache  <환경값> <환경값> <환경값>
streams pool             <환경값> <환경값> <환경값>
large pool               <환경값> <환경값> <환경값>

-- 관찰: min≠max 인 풀(예: DEFAULT buffer cache·large pool)은 그동안 자동 조정을 겪었다는
--   뜻이다. min=cur=max 로 고정된 풀은 조정 없이 유지된 것이다. 실제 폭·값은 그 인스턴스가
--   겪은 부하 이력에 따라 다르다(<환경값>).

--------------------------------------------------------------------------------
-- [2] (조회) 완료된 조정 이력을 시간순으로 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT component, oper_type,
  2         ROUND(initial_size/1024/1024,1) from_mb,
  3         ROUND(final_size/1024/1024,1) to_mb,
  4         TO_CHAR(start_time,'MM-DD HH24:MI') t
  5       FROM (SELECT * FROM v$sga_resize_ops ORDER BY start_time DESC)
  6       WHERE ROWNUM<=10;

COMPONENT             OPER_TYPE FROM_MB  TO_MB    T
--------------------- --------- -------- -------- -----------
large pool            GROW      <환경값> <환경값> <환경값>
DEFAULT buffer cache  SHRINK    <환경값> <환경값> <환경값>
DEFAULT buffer cache  GROW      <환경값> <환경값> <환경값>
large pool            SHRINK    <환경값> <환경값> <환경값>
...                   ...       ...      ...      ...

-- 실제 행·값·시각은 <환경값>이다(인스턴스가 쌓아 둔 최근 조정 이력). 형태만 보면:
--   같은 시각대에 한 풀의 GROW 와 다른 풀의 SHRINK 가 짝을 이뤄 나타난다(아래 [3] 원리).
--   증감은 모두 그래뉼(16MB) 배수다.

--------------------------------------------------------------------------------
-- [3] (해석) GROW/SHRINK가 짝을 이루는 원리.
--------------------------------------------------------------------------------
-- - 관찰 예: 한 시각대에 large pool GROW 와 DEFAULT buffer cache SHRINK 가 함께 나고,
--     잠시 뒤 반대(large pool SHRINK + buffer cache GROW)로 되돌아온다.
-- - 원리: SGA 총량(SGA_TARGET=1504M)은 고정이다. 한 풀이 16MB 커지려면 다른 풀이
--     16MB 내놓아야 한다. 그래서 조정은 반대 방향으로 짝을 이룬다.
-- - 모든 증감이 16의 배수인 것은 그래뉼이 16MB이기 때문이다.
-- - 이것이 '전체는 고정, 내부는 자동 재분배'라는 ASMM의 본질이다.
-- - 이 이력은 정상이다: 짧게 왕복하고 되돌아왔다(thrashing 아님). large pool을 쓰는
--     작업(병렬·RMAN 등)이 잠깐 메모리를 요구했다 반납한 정황으로 읽힌다.

--------------------------------------------------------------------------------
-- [4] (이상 → 원인 → 조치 → 재확인) V$MEMORY_RESIZE_OPS가 비어 있어 당황한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT component, oper_type, ROUND(final_size/1024/1024,1) to_mb
  2       FROM v$memory_resize_ops
  3       WHERE final_size IS NOT NULL AND ROWNUM<=5;

COMPONENT                OPER_TYPE  TO_MB
------------------------ ---------- --------
<환경값>                 <환경값>   <환경값>
...

-- * 관찰/함정: V$MEMORY_RESIZE_OPS 는 SGA↔PGA 를 아우르는 '통합' 조정 이력이며, 그런
--     통합 재분배는 AMM(MEMORY_TARGET>0)에서 일어난다. 지금은 ASMM(MEMORY_TARGET=0)이라
--     '새' 통합 조정은 생기지 않는다.
--   - 이 인스턴스처럼 과거에 한 번이라도 AMM 이었다면(예: 실습 02), 그때의 통합 조정
--     기록이 이 뷰(메모리 순환 버퍼)에 남아 몇 건 보일 수 있다 — 뷰 결함이 아니라 '과거
--     AMM 흔적'이다.
--   - AMM 이력이 전혀 없는 순수 ASMM 인스턴스라면 여기서 'no rows selected'가 정상이다.
-- * 핵심(뷰 선택): 지금 방식(ASMM)의 '진행 중' SGA 조정은 V$SGA_RESIZE_OPS 로 본다([2]).
--     통합 조정을 관찰하려면 AMM 환경(실습 02)에서 이 뷰를 본다.

SYS@orcl> SELECT display_value FROM v$parameter WHERE name='memory_target';
DISPLAY_VALUE
--------------
0
-- * 재확인: memory_target=0 이므로 '새' 통합 조정은 생기지 않음을 확정했다(과거 AMM
--     흔적은 남아 있을 수 있다). 지금 방식의 조정 이력은 V$SGA_RESIZE_OPS 가 올바른 뷰다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) V$SGA_DYNAMIC_COMPONENTS의 min≠max가 자동 조정을 겪은 흔적이다.
-- 2) V$SGA_RESIZE_OPS의 GROW/SHRINK는 짝을 이룬다(총량 고정 → 한쪽이 커지면 다른쪽 축소).
-- 3) 모든 증감은 그래뉼(16MB) 단위. 오라클은 최근 800건을 보관한다.
-- 4) 뷰 선택이 핵심: 지금(ASMM) 조정=V$SGA_RESIZE_OPS, 통합(AMM) 조정=V$MEMORY_RESIZE_OPS.
--    (후자는 과거 AMM 흔적이 남아 있을 수 있음에 유의.)
-- ※ 이력 값·시각은 환경 의존 <환경값>이다. 핵심은 '짝 원리'와 '뷰 선택'이다.

SYS@orcl> EXIT
