================================================================================
 Ch09 실습 03 — UNION 을 UNION ALL 로 바꿔도 되는가: 겹침 판정 절차와 배타 조건 재작성
 목표: 두 집합이 논리적으로 겹칠 수 있는지를 데이터가 아니라 조건으로 판정하는 절차를 세운다.
       같은 표를 두 조건으로 나눠 UNION 하는 흔한 패턴(입원 ∪ 외래)에서 표를 두 번 읽는 이상 징후를
       보고, 조건이 배타적이면 UNION ALL 로, 나아가 IN/OR 한 번 읽기로 바꿔 3,532 → 3,090 을 얻는다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. 조회만.
 주의: 개인 실습 환경 전용. UNION → UNION ALL 은 결과가 바뀔 수 있는 변경이다 — 판정을 먼저 한다.
================================================================================

$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> SET LINESIZE 200
SQLT@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (이상 징후 → 원인 → 조치 → 재확인: [1]~[3]) 흔한 패턴 — 같은 표를 조건별로 나눠 UNION
--------------------------------------------------------------------------------
SQLT@orcl> -- "입원 청구와 외래 청구의 청구 ID 목록" 을 이렇게 쓴 화면이 있다.
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(*)
  2       FROM  (SELECT claim_id FROM medical_claims WHERE claim_type = '입원'
  3              UNION
  4              SELECT claim_id FROM medical_claims WHERE claim_type = '외래');

  COUNT(*)
----------
    300000

SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST +MEMSTATS'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------------------
| Id  | Operation             | Name           | Starts | A-Rows |   A-Time   | Buffers | Used-Mem |
------------------------------------------------------------------------------------------------------
|   1 |  SORT AGGREGATE       |                |      1 |      1 |  <환경값>  |    6180 |          |
|   2 |   VIEW                |                |      1 |   300K |  <환경값>  |    6180 |          |
|   3 |    SORT UNIQUE        |                |      1 |   300K |  <환경값>  |    6180 | <환경값> |
|   4 |     UNION-ALL         |                |      1 |   300K |  <환경값>  |    6180 |          |
|*  5 |      TABLE ACCESS FULL| MEDICAL_CLAIMS |      1 |  59511 |  <환경값>  |    3090 |          |
|*  6 |      TABLE ACCESS FULL| MEDICAL_CLAIMS |      1 |   240K |  <환경값>  |    3090 |          |
------------------------------------------------------------------------------------------------------

-- 이상 징후 1: 같은 표를 두 번 Full Scan 했다(3,090 × 2 = 6,180).
-- 이상 징후 2: 30만 행을 SORT UNIQUE 로 정렬했다(Used-Mem <환경값>: 수 MB, 넘치면 (1)).
--   결과 300,000 = 표 전체 — 입원·외래 말고 다른 claim_type 이 없다는 뜻이기도 하다.

--------------------------------------------------------------------------------
-- [2] (판정 절차) UNION ALL 로 바꿔도 되는가 — 조건으로 판정한다
--------------------------------------------------------------------------------
SQLT@orcl> -- 질문 ①: 두 집합이 겹칠 수 있는가 → 같은 행이 claim_type='입원' 이면서 '외래' 일 수는 없다.
SQLT@orcl> --         조건이 서로 배타적(한 컬럼의 서로 다른 등치값)이므로 집합 간 중복은 논리적으로 0.
SQLT@orcl> -- 질문 ②: 각 집합 안에 중복이 있는가 → claim_id 는 PK. 각 집합은 이미 유일하다.
SQLT@orcl> -- 둘 다 "없음" 이므로 UNION ALL 로 바꿔도 결과가 같다. 데이터로도 확인해 둔다(근거 남기기).
SQLT@orcl> SELECT COUNT(*) FROM medical_claims WHERE claim_type NOT IN ('입원','외래');

  COUNT(*)
----------
         0

SQLT@orcl> COLUMN constraint_type FORMAT A2
SQLT@orcl> SELECT constraint_name, constraint_type, status FROM user_constraints
  2       WHERE  table_name = 'MEDICAL_CLAIMS' AND constraint_type = 'P';

CONSTRAINT_NAME        CO STATUS
---------------------- -- --------
PK_MEDICAL_CLAIMS      P  ENABLED

-- 판정: 배타 조건 + PK 컬럼 + 제약 ENABLED → UNION ALL 안전. (조건이 범위·LIKE 로 겹칠 수 있거나
--   컬럼이 PK 가 아니면 이 판정은 실패이고 UNION 을 유지한다.)

--------------------------------------------------------------------------------
-- [3] (조치 → 재확인) UNION ALL, 그리고 한 번 읽기
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(*)
  2       FROM  (SELECT claim_id FROM medical_claims WHERE claim_type = '입원'
  3              UNION ALL
  4              SELECT claim_id FROM medical_claims WHERE claim_type = '외래');
(결과 300000)
SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------
| Id  | Operation             | Name           | Starts | A-Rows | Buffers |
------------------------------------------------------------------------------------------
|   3 |    UNION-ALL          |                |      1 |   300K |    6180 |         -- SORT UNIQUE 사라짐
|*  4 |     TABLE ACCESS FULL | MEDICAL_CLAIMS |      1 |  59511 |    3090 |
|*  5 |     TABLE ACCESS FULL | MEDICAL_CLAIMS |      1 |   240K |    3090 |
------------------------------------------------------------------------------------------

SQLT@orcl> -- 정렬은 없어졌지만 표는 여전히 두 번이다. 같은 표의 배타 조건 합집합은 OR/IN 으로 한 번에 읽는다.
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(*)
  2       FROM   medical_claims WHERE claim_type IN ('입원', '외래');
(결과 300000)
SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------
| Id  | Operation          | Name           | Starts | A-Rows | Buffers |
------------------------------------------------------------------------------------------
|   1 |  SORT AGGREGATE    |                |      1 |      1 |    3090 |
|*  2 |   TABLE ACCESS FULL| MEDICAL_CLAIMS |      1 |   300K |    3090 |
------------------------------------------------------------------------------------------
   2 - filter(("CLAIM_TYPE"='입원' OR "CLAIM_TYPE"='외래'))

-- 재확인: 같은 300,000. Buffers 6,180 → 3,090, 정렬 없음.
--   ┌──────────────────────────┬─────────┬──────────────────┐
--   │ 작성법                   │ Buffers │ 정렬             │
--   ├──────────────────────────┼─────────┼──────────────────┤
--   │ UNION (표 2회 + 정렬)    │  6,180  │ SORT UNIQUE 30만 │
--   │ UNION ALL (표 2회)       │  6,180  │ 없음             │
--   │ IN (표 1회)              │  3,090  │ 없음             │
--   └──────────────────────────┴─────────┴──────────────────┘

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) UNION → UNION ALL 판정: ① 집합 간 겹침이 조건상 불가능한가 ② 각 집합이 이미 유일한가. 둘 다 예일 때만.
-- 2) 판정 근거는 데이터가 아니라 조건과 제약(배타 등치값, PK ENABLED)이다. 데이터 확인은 근거 보강.
-- 3) 같은 표의 배타 조건 합집합은 UNION 자체가 불필요하다 — IN/OR 로 한 번 읽는다(6,180 → 3,090).
-- 4) 다른 표의 합집합(실습 01)은 UNION ALL 까지가 한계다. 표를 줄일 수는 없다.

SQLT@orcl> EXIT
