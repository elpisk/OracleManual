================================================================================
 4장 실습 04 — 전용 서버 vs 공유 서버 접속 방식 비교
 목표: 현재 접속이 전용 서버인지 확인하고(V$SESSION.SERVER), 접속마다 서버
       프로세스가 붙는 구조를 관찰한다. 공유 서버를 임시로 구성해 디스패처·
       공유 서버 프로세스가 생기는 것과 진단 뷰(V$DISPATCHER_RATE·V$QUEUE·
       V$SHARED_SERVER)를 확인한 뒤 원복한다. 프로세스·메모리(UGA) 차이를 이해.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA)
 주의: 개인 실습 환경 전용. SHARED_SERVERS·DISPATCHERS 파라미터 변경이
       포함된다. 마지막에 전용 서버 구성으로 원복한다. 공용 DB에서 수행 금지.
================================================================================

-- (터미널 A)
$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 접속 방식과 관련 파라미터를 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN username FORMAT A9

SYS@orcl> COLUMN server FORMAT A10

SYS@orcl> COLUMN program FORMAT A26

SYS@orcl> SELECT sid, username, server, program
  2       FROM  v$session
  3       WHERE username IS NOT NULL AND type='USER'
  4       ORDER BY sid;

       SID USERNAME  SERVER     PROGRAM
---------- --------- ---------- --------------------------
        14 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

        19 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

        25 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

       595 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

       603 SYS       DEDICATED  sqlplus@oel7v9.localdomain
                                 (TNS V1-V3)

-- 해석: 모든 사용자 세션의 SERVER=DEDICATED. 이 인스턴스는 전용 서버 구성이다.
--   즉 접속 하나마다 전용 서버 프로세스가 하나씩 붙어 있다.

SYS@orcl> COLUMN name FORMAT A20

SYS@orcl> COLUMN value FORMAT A30

SYS@orcl> SELECT name, value FROM v$parameter
  2       WHERE name IN ('shared_servers','dispatchers','max_shared_servers',
  3              'max_dispatchers','large_pool_size');

NAME                 VALUE
-------------------- ------------------------------
large_pool_size      0
dispatchers          (PROTOCOL=TCP)(DISPATCHERS=0)
shared_servers       0
max_shared_servers   10
max_dispatchers

-- 조치 전 요약: shared_servers=0, dispatchers 실효 0 → 공유 서버 미구성.
--   large_pool_size=0 → 공유 서버를 켜면 UGA 가 갈 라지 풀을 확보해야 한다(ASMM 이 켜져 있어
--   자동으로도 잡히지만, 명시해 두면 그 값이 하한이 된다).

--------------------------------------------------------------------------------
-- [2] (조회) 전용 서버에서 '접속 = 프로세스'임을 프로세스 수로 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT COUNT(*) server_procs
  2       FROM  v$process p
  3       WHERE EXISTS (SELECT 1 FROM v$session s WHERE s.paddr = p.addr
  4                       AND s.type='USER' AND s.username IS NOT NULL);

SERVER_PROCS
------------
           5

-- 해석: 사용자 세션 수 = 서버 프로세스 수. 전용 서버는 접속 수에 비례해
--   프로세스가 늘어난다. 접속이 수천이면 그만큼 프로세스·메모리가 든다.

SYS@orcl> -- 공유 서버 큐(V$QUEUE)는 아직 COMMON 행의 TOTALQ=0 이다.
SYS@orcl> COLUMN type FORMAT A10

SYS@orcl> SELECT type, queued, totalq, wait FROM v$queue;

TYPE           QUEUED     TOTALQ       WAIT
---------- ---------- ---------- ----------
COMMON              0          0          0
COMMON              0          0          0

--------------------------------------------------------------------------------
-- [3] (구성 변경) 공유 서버를 임시로 켠다. 라지 풀부터 확보한다.
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET large_pool_size=128M SCOPE=MEMORY;

System altered.

SYS@orcl> ALTER SYSTEM SET dispatchers='(PROTOCOL=TCP)(DISPATCHERS=2)' SCOPE=MEMORY;

System altered.

SYS@orcl> ALTER SYSTEM SET shared_servers=2 SCOPE=MEMORY;

System altered.

-- ▶ 잠시 대기: 5초

--------------------------------------------------------------------------------
-- [4] (조치 후 상태) 디스패처·공유 서버 프로세스가 생겼는지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN status FORMAT A8

SYS@orcl> SELECT name, status, (SELECT COUNT(*) FROM v$dispatcher) disp_cnt
  2       FROM  v$dispatcher WHERE ROWNUM=1;

NAME                 STATUS     DISP_CNT
-------------------- -------- ----------
D000                 WAIT              2

SYS@orcl> SELECT COUNT(*) "Shared Server Processes"
  2       FROM  v$shared_server WHERE status != 'QUIT';

Shared Server Processes
-----------------------
                      2

-- 해석: 디스패처 2개, 공유 서버 프로세스 2개가 떴다. 이제 새 공유 접속은
--   디스패처를 거쳐 소수의 공유 서버가 나눠 처리한다(전용처럼 1:1이 아니다).

-- (터미널 B) 공유 서버로 접속해 본다. ORCL 별칭은 (SERVER=DEDICATED) 라 서술자를 직접 적는다.
$ sqlplus sqlt/sqlt@"(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=oel7v9)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=orcl)(SERVER=SHARED)))"

SQLT@orcl> COLUMN server FORMAT A10

SQLT@orcl> SELECT sid, server FROM v$session WHERE sid = USERENV('SID');

       SID SERVER
---------- ----------
       218 SHARED

SQLT@orcl> -- 공유 서버에 요청을 몇 건 보낸다(각 문장이 디스패처 → 공유 서버 큐를 거친다).
SQLT@orcl> SELECT COUNT(*) FROM medical_claims;

  COUNT(*)
----------
    300000

SQLT@orcl> SELECT COUNT(*) FROM claim_details;

  COUNT(*)
----------
    899894

SQLT@orcl> SELECT COUNT(*) FROM review_log;

  COUNT(*)
----------
    500000

-- (터미널 A) 접속 방식이 섞여 있음을 확인한다.
SYS@orcl> SELECT sid, username, server, program
  2       FROM  v$session
  3       WHERE username IS NOT NULL AND type='USER'
  4       ORDER BY sid;

       SID USERNAME  SERVER     PROGRAM
---------- --------- ---------- --------------------------
        14 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

        19 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

        25 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

       218 SQLT      NONE       sqlplus@oel7v9.localdomain
                                 (TNS V1-V3)

       595 SYS       DEDICATED  rman@oel7v9.localdomain (T
                                NS V1-V3)

       603 SYS       DEDICATED  sqlplus@oel7v9.localdomain
                                 (TNS V1-V3)

6 rows selected.

-- 해석: 공유 접속 세션은 요청을 처리하는 순간에만 SERVER=SHARED 이고, 쉬는 동안은 NONE 이다
--   (어느 공유 서버에도 붙어 있지 않다는 뜻). 전용 세션은 늘 DEDICATED 다.

--------------------------------------------------------------------------------
-- [5] (진단 뷰) 공유 서버 경합을 어떻게 보는지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT type, queued, totalq, wait,
  2              DECODE(totalq, 0, 'No Requests',
  3                     ROUND(wait/totalq, 2) || ' HUNDREDTHS OF SECONDS') "AVG WAIT PER REQUEST"
  4       FROM v$queue WHERE type='COMMON';

TYPE           QUEUED     TOTALQ       WAIT AVG WAIT PER REQUEST
---------- ---------- ---------- ---------- --------------------------------------------------------------
COMMON              0          9          0 0 HUNDREDTHS OF SECONDS
COMMON              0          9          0 0 HUNDREDTHS OF SECONDS

-- 해석: 터미널 B 의 요청들이 공용 큐(COMMON)를 거쳤다(TOTALQ). 요청당 평균 대기(1/100초)가
--   꾸준히 커지면 공유 서버가 모자란 것이다 — 그때는 shared_servers 를 늘린다.

SYS@orcl> COLUMN name FORMAT A5

SYS@orcl> SELECT name, cur_event_rate, avg_event_rate, max_event_rate
  2       FROM   v$dispatcher_rate;

NAME  CUR_EVENT_RATE AVG_EVENT_RATE MAX_EVENT_RATE
----- -------------- -------------- --------------
D000              40              0              0
D001               0              0              0

-- 해석: 디스패처 부하는 V$DISPATCHER_RATE 의 CUR_/AVG_/MAX_ 를 비교해 판정한다:
--   현재값이 MAX 근처에 머물면 디스패처 추가, 한참 낮으면 과다.

--------------------------------------------------------------------------------
-- [6] (메모리 관점) 공유 서버 세션의 UGA 는 어디로 갔나 — 라지 풀.
--     라지 풀이 부족하면 공유 서버 세션 메모리(UGA)를 확보하지 못해 ORA-04031 이 난다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN pool FORMAT A12

SYS@orcl> COLUMN name FORMAT A26

SYS@orcl> SELECT pool, name, ROUND(bytes/1024) kb
  2       FROM   v$sgastat WHERE pool = 'large pool' ORDER BY bytes DESC;

POOL         NAME                               KB
------------ -------------------------- ----------
large pool   free memory                    124316
large pool   CTWR dba buffer                  3788
large pool   krcc extent chunk                2028
large pool   PX msg pool                       480
large pool   session heap                      460

-- 해석: 'session heap' 이 라지 풀에 잡혀 있다 — 공유 서버 세션의 UGA 다. 전용 서버라면
--   이 메모리는 서버 프로세스의 PGA 에 있었을 것이다.
-- 오류 시나리오(재현하지 않고 서술만): 라지 풀이 UGA 총량보다 작으면 새 공유 세션이
--   ORA-04031: unable to allocate ... ("large pool", ...) 로 실패한다. 조치는 라지 풀을
--   충분히 키우는 것(공유 서버 세션 수 × UGA 추정치 이상) — 18장에서 ORA-04031 을 심화한다.
--   (이 랩은 SGA_TARGET 자동 관리라 라지 풀을 4M 로 줄여도 필요 시 자동으로 늘어난다.)

--------------------------------------------------------------------------------
-- [7] (원복) 전용 서버 구성으로 되돌린다. 공유 접속 세션부터 끊는다.
--------------------------------------------------------------------------------
-- (터미널 B)
SQLT@orcl> EXIT

SYS@orcl> ALTER SYSTEM SET large_pool_size=0 SCOPE=MEMORY;

System altered.

DISPATCHERS SHARED_SERVERS

          0              0

-- 1) 접속 방식은 V$SESSION.SERVER로 본다: DEDICATED/SHARED/NONE/POOLED.
-- 2) 전용 서버는 '접속=프로세스'라 접속 수만큼 프로세스·메모리가 든다.
--    공유 서버는 소수 공유 서버+디스패처로 다중 처리해 자원을 절감한다.
-- 3) 공유 서버는 UGA가 SGA(라지 풀)로 이동한다 → large_pool_size 확보 필수.
--    부족하면 ORA-04031이 난다.
-- 4) 공유 서버 경합 진단: V$QUEUE(요청 큐 대기)·V$DISPATCHER_RATE(CUR/AVG/MAX)·
--    V$SHARED_SERVER(STATUS!='QUIT' 개수). 늘리기 전 메모리 문제부터 배제한다.
-- 5) 간헐 OLTP 다수 접속·고접속률 → 공유 서버 / 장시간·배치·관리 작업 → 전용.
-- ※ 이 조회들은 관리 팩 라이선스가 필요 없다.

SYS@orcl> EXIT
