## 1. 과정 개요

SQL 튜닝 과정과 성능 튜닝 과정을 하나의 과목으로 합친다. 두 과정은 층위가 다르다.

| 층위 | 원 과정 | 질문 | 종착점 |
|---|---|---|---|
| SQL 한 문장 | SQLTUNING 14장 | 이 SQL 은 왜 느리고 어떻게 고치는가 | 실행계획·인덱스·재작성·재측정 |
| 인스턴스·시스템 | Tuning 20장 | 어느 SQL 이, 어떤 대기 때문에, DB Time 의 몇 % 를 쓰는가 | AWR/ADDM/ASH 판독, 대기 이벤트 추적, 어드바이저, SGA·PGA·I/O |

합친 과정의 목표는 **두 층위를 한 절차로 잇는 것**이다.

```
[인스턴스]  DB Time → 상위 대기 이벤트 → 원인 SQL 지목
                                            ↓
[SQL]       실행계획 판독 → 인덱스·재작성 → Buffers/A-Rows 재측정
                                            ↓
[인스턴스]  AWR 기간 비교로 시스템 수준 개선 확인
```

SQL 을 먼저 배우고 인스턴스로 올라간다. Tuning PRD 2.2 절이 정한 대로 SQL 튜닝이 하위 층위이며,
Day 5 도입부에서 "SQL 한 문장에서 시스템 전체로" 시야를 넓히는 브리지를 둔다.

## 2. 시간 배분 원칙

### 2-1. 4 : 6 배분

| 부문 | 일자 | 시수 | 원 과정 장 수 | 장당 평균 |

20장은 강의 1h 에 종합 평가 Section 2·3 으로 실습을 대체한다.

### 2-2. 학습량 상한 — 하루 8h 수업 + 저녁 과제 1.5h 이내

v1 은 Tuning 원 과정의 과제(장당 50 문항 + 추가서술형 20)를 그대로 가져와 하루 3~4장이면 저녁 과제가 7~10시간이었다.
v2 는 다음 세 가지로 상한을 지킨다.

| 조치 | 규칙 | 효과 |
|---|---|---|
| **과제 2단계** | 당일 과제는 장당 **[하-01]~[하-10] + [중-01]~[중-05] = 15 문항**. 나머지(하 10·중 15·상 10·추가서술형 20 = 55 문항)는 **수료 후 자습** 으로 문제지 첫머리에 명시 | 저녁 과제 최대 60 문항(약 1.5h) |
| **자습 실습 = 선택** | 트랜스크립트 목록의 "선택" 은 당일 의무가 아니다. 단, 인덱스·통계 원복이 걸린 실습(표시)은 당일 필수 | 수업 실습만 따라 하면 과정이 성립 |
| **장 압축 4곳** | 2장 → 1h(실습 02·05) · 11장 → 8장 뒤 1h · 12장 → 14장 뒤 1h · 16장 → 17장 앞 1h | 3h 확보 → Day 5 정리 0.5h, 13·14장 +1h, Day 10 총정리 1.2h |

SQL 부문(Day 1~4)은 챕터가 짧아(교안 800~1,400단어, 실습 3개, 문제 10) 2h/장이 맞다. 감량 대상은 인스턴스 부문이다.

