================================================================================
 11장 실습 02 — 두 기간 Load Profile 차이 판독
 목표: Compare Periods 보고서의 Load Profile 에서 '초당값'과 '트랜잭션당값'을
       함께 읽는다. 두 열이 반대 방향으로 움직이는 실측(+136.8% vs -99.7%)을
       해석하고, 한쪽만 보면 정반대 결론에 이르는 것을 확인한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 부하: WL_06_mixed.sql 로 만든 구간A(497→498) / 구간B(499→500) 비교 보고서 사용.
 주의: 개인 실습 환경 전용. 🔒 Diagnostics Pack 필요(대안은 [5] 참고).
================================================================================

$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 판독할 보고서의 Workload Comparison(Load Profile 차이) 부분을 연다.
--     실습 01에서 만든 awrdiff_497_498_vs_499_500.txt 에서 섹션 제목으로 발췌한다.
--------------------------------------------------------------------------------

-- 해석 준비: 각 행은 구간A(1st) 초당, 구간B(2nd) 초당, %Diff, 구간A 트랜잭션당,
--   구간B 트랜잭션당, %Diff 순이다. 초당값과 트랜잭션당값을 나눠서 읽는다.
--   (참고: 머리말의 Avg Active Users 가 0.4 → 3.1 이다 — 구간B 가 8배 '바빴다'.
--    아래 Workload Comparison 이 그 8배의 정체를 설명한다.)

--------------------------------------------------------------------------------
-- [2] (조회) 초당값만 먼저 본다 — '전부 늘었다'.
--------------------------------------------------------------------------------
-- DB time/초        :      0.4 →      1.4  (+286.5%)
-- Logical read/초   : 22,406.0 → 74,848.4  (+234.1%)  약 3.3배
-- Executes/초       :  3,076.1 →  9,105.5  (+196.0%)
-- → 초당값만 보면 "구간B 가 훨씬 바쁘다 = 나빠졌다"고 오판하기 쉽다.

--------------------------------------------------------------------------------
-- [3] (조회) 트랜잭션당값을 본다 — '그대로거나 오히려 줄었다'.
--------------------------------------------------------------------------------
-- Logical read/txn : 35.5 → 36.1 (+1.8%)
-- Executes/txn     :  4.9 →  4.4 (-9.9%)
-- Hard parses/txn  :  0.5 →  0.2 (-72.7%)
-- → 같은 항목이 트랜잭션당으로는 제자리이거나 줄었다. 초당은 3배 늘고 트랜잭션당은 안 늘었다.

--------------------------------------------------------------------------------
-- [4] (해석) 모순처럼 보이는 두 방향의 원인 = 맨 아래 Transactions 행.
--------------------------------------------------------------------------------
-- Transactions/초 : 631.4 → 2,072.1  (+228.2%, 약 3.3배)
--
-- 분자(총 논리읽기)는 3.3배가 됐는데 분모(트랜잭션 수)도 3.3배가 됐다.
--   그래서 나눈 값(트랜잭션당)은 그대로다. 모순이 아니라 '무엇으로 나눴나'의 문제다.
-- 판정: 초당값 하나만 보면 성능 저하로, 트랜잭션당값을 함께 보면 '같은 효율로 일을 3배 더 한
--   부하 증가'로 정반대 결론에 이른다. 반드시 두 열을 함께 읽어야 한다.
--   (하드 파싱/txn 이 -72.7% 인 것은 구간B 에서 리터럴 SQL 이 공유 풀에 이미 캐시돼 있던 덕이다 —
--    같은 부하 스크립트를 두 번 돌리면 두 번째가 유리한 '캐시 효과'도 함께 읽어야 한다.)
--
-- ※ 절대 수치 주의: 이 값들은 이 부하 구간 고유의 값이라 학습자 환경에서는 다르다.
--   주목할 것은 방향과 관계(초당↑·트랜잭션당→)다.

--------------------------------------------------------------------------------
-- [5] (이상 징후 → 원인 → 조치 → 재확인) 라이선스 없이 같은 판독 재현.
--     이상 징후: 동료 환경은 Diagnostics Pack 이 없어 Compare Periods 를 못 연다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인: DBA_HIST/AWR 은 🔒. 라이선스 없이는 보고서 자체가 불가하다.
-- 조치: V$SYSSTAT 을 두 시점에 캡처해 초당·트랜잭션당을 직접 계산한다.
SYS@orcl> COLUMN name FORMAT A24

SYS@orcl> SELECT name, value FROM v$sysstat
  2       WHERE name IN ('session logical reads','user commits','user rollbacks');

-- 재확인: (t1-t0) 논리읽기 델타를 (t1-t0) 트랜잭션 델타로 나누면
--   Workload Comparison 의 '트랜잭션당 논리읽기'가 그대로 재현된다.
--   판정 원리(단위 작업당으로 나눈다)는 도구와 무관하게 동일하다.

-- 1) Load Profile(Workload Comparison)은 초당값과 트랜잭션당값을 반드시 함께 본다.
-- 2) 실측: 초당 논리읽기 +234.1% 인데 트랜잭션당 +1.8% → 원인은 트랜잭션 3.3배 증가.
-- 3) 초당만 보면 성능 저하, 트랜잭션당까지 보면 부하 증가로 판정이 갈린다.
-- 4) 라이선스가 없으면 V$SYSSTAT 두 시점 델타로 같은 판독을 재현한다.
-- ※ 🔒 Compare Periods 보고서는 Diagnostics Pack 필요.
