================================================================================
 11장 실습 02 — 두 기간 Load Profile 차이 판독
 목표: Compare Periods 보고서의 Load Profile 에서 '초당값'과 '트랜잭션당값'을
       함께 읽는다. 두 열이 반대 방향으로 움직이는 실측(+136.8% vs -99.7%)을
       해석하고, 한쪽만 보면 정반대 결론에 이르는 것을 확인한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 부하: WL_06_mixed.sql 로 만든 구간A(303→304) / 구간B(305→306) 비교 보고서 사용.
 주의: 개인 실습 환경 전용. 🔒 Diagnostics Pack 필요(대안은 [5] 참고).
================================================================================

$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 판독할 보고서의 Load Profile 부분을 연다.
--     실습 01에서 만든 awrdiff_303_304_vs_305_306.txt 의 Load Profile 발췌.
--------------------------------------------------------------------------------
SYS@orcl> HOST type awrdiff_303_304_vs_305_306.txt | more   -- (Load Profile 구획)

Load Profile
~~~~~~~~~~~~                     구간A/초       구간B/초    %Diff    A/txn      B/txn   %Diff
  Logical read (blocks):      577,591.8    1,367,654.2    136.8  1,916,243.2   4,949.9  -99.7
          Block changes:          183.1        1,249.2    582.4        607.4       4.5  -99.3
             User calls:          712.7        1,391.5     95.2      2,364.5       5.0  -99.8
           Parses (SQL):          183.5          526.3    186.8        608.9       1.9  -99.7
      Hard parses (SQL):          146.4          399.6    173.0        485.6       1.4  -99.7
         Executes (SQL):          343.1          760.3    121.6      1,138.3       2.8  -99.8
           Transactions:            0.3          276.3  92,000.0

-- 해석 준비: 각 행은 구간A 초당, 구간B 초당, %Diff, 구간A 트랜잭션당,
--   구간B 트랜잭션당, %Diff 순이다. 초당값과 트랜잭션당값을 나눠서 읽는다.
--   (참고: 이 두 구간의 DB time 은 구간A 81.8초, 구간B 302.0초로 약 3.7배다.
--    아래 Load Profile 이 그 3.7배의 정체를 설명한다.)

--------------------------------------------------------------------------------
-- [2] (조회) 초당값만 먼저 본다 — '전부 늘었다'.
--------------------------------------------------------------------------------
-- Logical read/초 : 577,591.8 → 1,367,654.2 (+136.8%)  약 2.37배
-- Hard parses/초  :     146.4 →     399.6    (+173.0%)
-- Executes/초     :     343.1 →     760.3    (+121.6%)
-- → 초당값만 보면 "구간B가 훨씬 바쁘다 = 나빠졌다"고 오판하기 쉽다.

--------------------------------------------------------------------------------
-- [3] (조회) 트랜잭션당값을 본다 — '전부 줄었다'.
--------------------------------------------------------------------------------
-- Logical read/txn : 1,916,243.2 → 4,949.9 (-99.7%)
-- Hard parses/txn  :       485.6 →     1.4 (-99.7%)
-- Executes/txn     :     1,138.3 →     2.8 (-99.8%)
-- → 같은 항목이 트랜잭션당으로는 급감했다. 초당은 늘고 트랜잭션당은 줄었다.

--------------------------------------------------------------------------------
-- [4] (해석) 모순처럼 보이는 두 방향의 원인 = 맨 아래 Transactions 행.
--------------------------------------------------------------------------------
-- Transactions/초 : 0.3 → 276.3  (약 920배)
--
-- 분자(총 논리읽기)는 2.37배가 됐는데 분모(트랜잭션 수)가 약 920배가 됐다.
--   그래서 나눈 값(트랜잭션당)은 급감한다. 모순이 아니라 '무엇으로 나눴나'의 차이다.
-- 판정: 초당값 하나만 보면 성능 저하로, 트랜잭션당값을 함께 보면 부하 증가로
--   정반대 결론에 이른다. 반드시 두 열을 함께 읽어야 한다.
--
-- ※ 절대 수치 주의: 구간A 트랜잭션당 논리읽기 1,916,243 은 트랜잭션이 극히
--   적어(초당 0.3건) 분모가 작을 때 나오는 값이다. 절대값은 이 부하 구간 고유의
--   값이라 학습자 환경에서는 다르다. 주목할 것은 방향과 관계(초당↑·트랜잭션당↓)다.

--------------------------------------------------------------------------------
-- [5] (이상 징후 → 원인 → 조치 → 재확인) 라이선스 없이 같은 판독 재현.
--     이상 징후: 동료 환경은 Diagnostics Pack 이 없어 Compare Periods 를 못 연다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인: DBA_HIST/AWR 은 🔒. 라이선스 없이는 보고서 자체가 불가하다.
-- 조치: V$SYSSTAT 을 두 시점에 캡처해 초당·트랜잭션당을 직접 계산한다.
SYS@orcl> SELECT name, value FROM v$sysstat
  2       WHERE name IN ('session logical reads','user commits','user rollbacks');
NAME                          VALUE
----------------------------- ----------
session logical reads         <환경값>     -- 시작 시점 t0 값을 기록
user commits                  <환경값>
user rollbacks                <환경값>
-- ... 부하 구간 경과 후 같은 조회를 다시 해 t1 값을 얻는다 ...
-- 재확인: (t1-t0) 논리읽기 델타를 (t1-t0) 트랜잭션 델타로 나누면
--   Load Profile 의 '트랜잭션당 논리읽기'가 그대로 재현된다.
--   판정 원리(단위 작업당으로 나눈다)는 도구와 무관하게 동일하다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) Load Profile 은 초당값과 트랜잭션당값을 반드시 함께 본다.
-- 2) 실측: 초당 논리읽기 +136.8% 인데 트랜잭션당 -99.7% → 원인은 트랜잭션 920배 폭증.
-- 3) 초당만 보면 성능 저하, 트랜잭션당까지 보면 부하 증가로 판정이 갈린다.
-- 4) 라이선스가 없으면 V$SYSSTAT 두 시점 델타로 같은 판독을 재현한다.
-- ※ 🔒 Compare Periods 보고서는 Diagnostics Pack 필요.

SYS@orcl> EXIT
