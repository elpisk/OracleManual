================================================================================
 20장 실습 03 — 비동기 I/O 설정 확인
 목표: FILESYSTEMIO_OPTIONS·DISK_ASYNCH_IO 현재 설정을 조회하고,
       데이터파일의 비동기 I/O 활성 여부(V$IOSTAT_FILE ASYNCH_IO)를 점검한다.
       'none = 무조건 문제'라는 오판을 교정한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 주의: 개인 실습 환경 전용. 파라미터 변경·재기동은 개인 환경에서만, 사전 백업 후.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) I/O 관련 파라미터를 한자리에서 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT name, display_value FROM v$parameter
  2    WHERE name IN ('filesystemio_options','disk_asynch_io',
  3                   'db_file_multiblock_read_count','db_writer_processes')
  4    ORDER BY name;

NAME                            DISPLAY_VALUE
------------------------------- --------------
db_file_multiblock_read_count   128
db_writer_processes             1
disk_asynch_io                  TRUE
filesystemio_options            none

-- 해석: DISK_ASYNCH_IO=TRUE → 데이터파일 비동기 I/O 자체는 허용.
--   FILESYSTEMIO_OPTIONS=none → 파일 시스템 수준 비동기·직접 I/O는 꺼짐.
--   ※ 값 자체(none)를 아직 '문제'로 단정하지 않는다.

--------------------------------------------------------------------------------
-- [2] (조회) 데이터파일이 실제로 비동기 I/O로 열렸는지 확인한다.
--     파라미터 '선언'과 실제 '활성'은 다를 수 있다. ASYNCH_IO로 최종 확인.
--------------------------------------------------------------------------------
SYS@orcl> COL name FORMAT A50
SYS@orcl> SELECT f.name, i.asynch_io
  2    FROM  v$datafile f, v$iostat_file i
  3    WHERE f.file# = i.file_no
  4      AND i.filetype_name = 'Data File';

NAME                                               ASYNCH_IO
-------------------------------------------------- ---------
/u02/oradata/orcl/system01.dbf                     ASYNC_ON
/u02/oradata/orcl/sysaux01.dbf                     ASYNC_ON
/u02/oradata/orcl/users01.dbf                      ASYNC_ON
/u02/oradata/orcl/undotbs01.dbf                    ASYNC_ON
...

-- 해석: DISK_ASYNCH_IO=TRUE 덕분에 데이터파일은 ASYNC_ON으로 열렸다.
--   즉 FILESYSTEMIO_OPTIONS=none이어도 데이터파일 비동기 I/O는 켜져 있다.
--   (파일 시스템 종류·플랫폼에 따라 결과가 다를 수 있어 <환경값> 원칙.)

--------------------------------------------------------------------------------
-- [3] (조회) FILESYSTEMIO_OPTIONS 네 값의 의미를 정리한다.
--------------------------------------------------------------------------------
SYS@orcl> -- ASYNCH   : 파일 시스템 파일에 비동기 I/O만 활성
SYS@orcl> -- DIRECTIO : 직접 I/O만 활성(파일 시스템 캐시 우회)
SYS@orcl> -- SETALL   : 비동기 + 직접 I/O 모두 활성
SYS@orcl> -- NONE     : 둘 다 비활성
SYS@orcl> -- ※ 플랫폼별 기본값이 다르다. Windows는 항상 FS 캐시를 우회한다.

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 한 DBA가 "filesystemio_options가 none이니 성능 문제다.
--       즉시 SETALL로 바꾸고 재기동하자"고 주장한다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인 파악: [2]에서 데이터파일은 이미 ASYNC_ON이다. 비동기 I/O가
SYS@orcl> --   꺼진 상태가 아니므로 'none이라 성능 문제'라는 전제부터 틀렸다.
SYS@orcl> --   none이 문제인지는 (a) 파일 시스템 데이터파일 여부, (b) 이중 캐싱·
SYS@orcl> --   CPU 낭비 관측, (c) 캘리브레이션이 요구하는 직접 I/O 필요성으로 판단한다.

SYS@orcl> -- 조치(가정: 이중 캐싱이 확인돼 SETALL이 필요한 개인 환경):
SYS@orcl> -- (4-1) 반드시 SPFILE 백업부터.
SYS@orcl> CREATE PFILE='/tmp/pfile_before.ora' FROM SPFILE;
File created.

SYS@orcl> -- (4-2) 값 변경(정적 파라미터 → 재기동 필요).
SYS@orcl> ALTER SYSTEM SET filesystemio_options='SETALL' SCOPE=SPFILE;
System altered.

SYS@orcl> -- (개인 환경에서만) SHUTDOWN IMMEDIATE; STARTUP;  ← 재기동으로 반영

SYS@orcl> -- 재확인: 재기동 후 값과 데이터파일 활성 상태를 다시 본다.
SYS@orcl> SELECT display_value FROM v$parameter WHERE name='filesystemio_options';
DISPLAY_VALUE
-------------
SETALL

-- 재확인: 값이 SETALL로 바뀌었고 데이터파일은 여전히 ASYNC_ON(직접 I/O 추가).
--   ※ 교육 목적이므로 학습 후 원복한다. 근거 없이 운영에 적용하지 않는다.
SYS@orcl> ALTER SYSTEM SET filesystemio_options='none' SCOPE=SPFILE;
System altered.
-- (원복도 재기동 후 반영된다. 개인 환경에서만 수행.)

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 실측: disk_asynch_io=TRUE, filesystemio_options=none.
-- 2) 파라미터 '선언'과 실제 '활성'은 다르다 → V$IOSTAT_FILE.ASYNCH_IO로 확인.
--    실측 데이터파일은 ASYNC_ON이었다.
-- 3) none을 무조건 문제로 단정하지 않는다(플랫폼 기본값·Windows 예외·활성 여부).
-- 4) SETALL 변경은 정적 → 재기동 필요. 개인 환경에서만, 백업·원복과 함께.
-- ※ 이 조회들은 라이선스 무관. 재기동 실습은 반드시 개인 환경 전용 경고.

SYS@orcl> EXIT
