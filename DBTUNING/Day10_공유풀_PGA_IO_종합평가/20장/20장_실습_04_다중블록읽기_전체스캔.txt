================================================================================
 20장 실습 04 — 다중 블록 읽기 크기와 전체 스캔 성능
 목표: DB_FILE_MULTIBLOCK_READ_COUNT를 확인하고, WL_02_io의 전체 스캔을
       세션 수준 값 변경 전후로 돌려 db file scattered read 대기와 스캔 시간을
       비교한다. 값이 크면 스캔이 빨라지지만 옵티마이저가 스캔을 선호할 수 있음을 본다.
 환경: non-CDB=orcl 19.3 (업무 계정 SQLT@orcl>로 스캔, SYS@orcl>로 대기 관찰)
 부하: WL_02_io.sql(대량 전체 스캔). 세션 수준 변경이라 접속 종료 시 자동 원복.
 주의: 개인 실습 환경 전용.
================================================================================

$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 다중 블록 읽기 개수를 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT display_value FROM v$parameter
  2    WHERE name='db_file_multiblock_read_count';

DISPLAY_VALUE
-------------
128

-- 해석: 128. 8KB 블록 기준 한 번의 다중 블록 I/O로 최대 약 1MB를 읽는다.
--   전체 스캔의 순차 처리량을 좌우하는 값이다.

--------------------------------------------------------------------------------
-- [2] (조치 전 대기 스냅샷) scattered read 누적을 기록한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT event, total_waits, time_waited,
  2         ROUND(time_waited/GREATEST(total_waits,1),3) avg_cs
  3    FROM  v$system_event
  4    WHERE event='db file scattered read';

EVENT                     TOTAL_WAITS  TIME_WAITED  AVG_CS
------------------------- -----------  -----------  ------
db file scattered read       <환경값>     <환경값>  <환경값>

--------------------------------------------------------------------------------
-- [부하 A] 업무 세션에서 큰 값(기본 128)으로 전체 스캔을 돌린다.
--------------------------------------------------------------------------------
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> ALTER SESSION SET db_file_multiblock_read_count=128;
Session altered.

SQLT@orcl> SET TIMING ON
SQLT@orcl> -- @WL_02_io.sql 의 대표 전체 스캔 1회 (진료비 대형 테이블 풀 스캔)
SQLT@orcl> SELECT /*+ FULL(c) */ COUNT(*) FROM claim c WHERE amount > 0;

  COUNT(*)
----------
   <환경값>

Elapsed: 00:00:0<환경값>   -- (A) 큰 값에서의 스캔 시간

SQLT@orcl> -- 이 세션의 실행계획이 전체 스캔인지 확인
SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(FORMAT=>'BASIC'));
-- ... TABLE ACCESS FULL  CLAIM ...

--------------------------------------------------------------------------------
-- [부하 B] 같은 스캔을 작은 값(예: 4)으로 다시 돌린다 — 세션 수준 변경.
--------------------------------------------------------------------------------
SQLT@orcl> ALTER SESSION SET db_file_multiblock_read_count=4;
Session altered.

SQLT@orcl> SELECT /*+ FULL(c) */ COUNT(*) FROM claim c WHERE amount > 0;

  COUNT(*)
----------
   <환경값>

Elapsed: 00:00:0<환경값>   -- (B) 작은 값에서의 스캔 시간

--------------------------------------------------------------------------------
-- [3] (조치 후 상태) SYS 세션에서 scattered read 대기 델타를 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT event, total_waits, time_waited,
  2         ROUND(time_waited/GREATEST(total_waits,1),3) avg_cs
  3    FROM  v$system_event
  4    WHERE event='db file scattered read';

EVENT                     TOTAL_WAITS  TIME_WAITED  AVG_CS
------------------------- -----------  -----------  ------
db file scattered read       <환경값>     <환경값>  <환경값>

-- 해석(전후 비교):
--   큰 값(128): 한 번에 많은 블록 → I/O 호출 횟수 적음 → 스캔 시간 짧음.
--   작은 값(4): I/O 호출 횟수 많음 → scattered read total_waits 증가, 스캔 시간 김.
--   → 다중 블록 읽기 크기가 순차 스캔 성능을 좌우함을 대기·시간으로 확인.

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: "값을 무조건 크게 하면 항상 빨라진다"며 인스턴스 전역으로
--       큰 값을 강제했더니, 인덱스로 빨랐던 OLTP 조회가 전체 스캔으로 바뀌어 느려졌다.
--------------------------------------------------------------------------------
SQLT@orcl> -- 원인 파악: 값이 크면 옵티마이저가 전체 스캔 비용을 낮게 계산해
SQLT@orcl> --   인덱스 대신 전체 스캔을 선호할 수 있다. 순차 스캔엔 이득이지만
SQLT@orcl> --   소량 행을 뽑는 OLTP 조회엔 손해다.
SQLT@orcl> SELECT /*+ INDEX(c claim_pk) */ * FROM claim c WHERE claim_id = :id;
-- (인덱스 강제 시 계획이 INDEX RANGE SCAN으로 돌아옴 → 근거 확인)

SQLT@orcl> -- 조치: 인스턴스 전역 강제를 풀고 기본 자동값에 맡긴다.
SQLT@orcl> --   특정 배치만 큰 값이 필요하면 세션 수준으로 지정한다.
SQLT@orcl> ALTER SESSION SET db_file_multiblock_read_count=128;  -- 배치 세션만
Session altered.

SQLT@orcl> -- 재확인: OLTP 조회는 인덱스 계획으로, 배치 스캔은 큰 값으로 각각 최적.
SQLT@orcl> --   전후 실행계획·응답시간·scattered read 대기를 비교해 개선을 판정한다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 실측 db_file_multiblock_read_count=128. 8KB 기준 한 번에 약 1MB 순차 읽기.
-- 2) 값을 키우면 순차 스캔 I/O 호출↓·시간↓, 하지만 옵티마이저가 스캔 선호 가능.
-- 3) 효과는 db file scattered read 대기(total_waits·평균)와 스캔 시간으로 확인.
-- 4) 19c는 미지정 시 자동값. 전역 강제보다 세션 수준 조정이 안전하다.
-- ※ 세션 수준 변경이라 접속 종료 시 자동 원복. 조회·대기 관찰은 라이선스 무관.

SQLT@orcl> EXIT
SYS@orcl> EXIT
