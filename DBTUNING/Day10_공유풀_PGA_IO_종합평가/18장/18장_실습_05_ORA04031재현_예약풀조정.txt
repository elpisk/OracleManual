================================================================================
 18장 실습 05 — ORA-04031 재현과 원인 영역 식별 → 예약 풀·크기 조정으로 해소
 목표: 공유 풀을 비정상적으로 좁힌 상태에서 리터럴 부하를 퍼부어 ORA-04031을
       재현하고, 오류 메시지로 원인 영역을 식별한다. 어드바이저로 확대 유효성을
       판정한 뒤, 순서(바인드→FORCE→예약 풀→크기)대로 해소하고 재확인한다.
 환경: non-CDB=orcl 19.3, ASMM. SYS로 파라미터 변경, SQLT로 부하.
 *** 경고: 개인 실습 환경 전용 ***
   이 실습은 공유 풀을 의도적으로 좁히고 오류를 유발한다. 인스턴스가 불안정해질
   수 있고 다른 세션의 파싱까지 실패시킨다. 공용·운영 DB에서는 절대 하지 않는다.
   변경한 파라미터는 [원복] 절에서 반드시 되돌린다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 공유 풀 크기와 예약 풀 상태를 기록(원복 기준).
--------------------------------------------------------------------------------
SYS@orcl> SELECT ROUND(bytes/1024/1024,0) mb
  2       FROM v$sgainfo WHERE name='Shared Pool Size';

        MB
----------
       416

SYS@orcl> SELECT request_failures, last_failure_size,
  2         ROUND(free_space/1024/1024,2) free_mb
  3       FROM v$shared_pool_reserved;

REQUEST_FAILURES LAST_FAILURE_SIZE   FREE_MB
---------------- ----------------- ---------
               0                 0    <환경값>

-- 해석(Before): 공유 풀 416MB, 예약 풀 요청 실패 0(정상). 이 값을 원복 기준으로 둔다.

--------------------------------------------------------------------------------
-- [2] (조치) 공유 풀을 비정상적으로 좁히고 자동 확장을 막는다(재현 준비).
--------------------------------------------------------------------------------
SYS@orcl> -- ASMM 자동 조정이 공유 풀을 다시 키우지 못하도록 하한을 낮춘다.
SYS@orcl> -- (개인 환경 전용) 매우 작은 값으로 강제한다.
SYS@orcl> ALTER SYSTEM SET shared_pool_size=64M SCOPE=MEMORY;
System altered.

SYS@orcl> ALTER SYSTEM FLUSH SHARED_POOL;
System altered.

--------------------------------------------------------------------------------
-- [3] (재현) 리터럴 부하를 퍼부어 ORA-04031을 유발.
--------------------------------------------------------------------------------
-- (별도 터미널) SQLT에서 리터럴 폭증:
$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> ALTER SESSION SET cursor_sharing=EXACT;
Session altered.

SQLT@orcl> BEGIN
  2         FOR i IN 1..100000 LOOP
  3           EXECUTE IMMEDIATE
  4             'SELECT /*WL01_LIT*/ COUNT(*) FROM patients WHERE patient_id='||i
  5             INTO :n;
  6         END LOOP;
  7       END;
  8       /
BEGIN
*
ERROR at line 1:
ORA-04031: unable to allocate 4160 bytes of shared memory ("shared pool",
"SELECT /*WL01_LIT*/ COUNT(*) FROM patients WHERE patient_id=99231","SQLA",
"kkscsAddChildNode")
ORA-06512: at line 3

-- 재현 성공: 리터럴 커서가 64MB 공유 풀을 파편화해 4160바이트 연속 공간조차
--   못 얻었다.

--------------------------------------------------------------------------------
-- [4] (원인 영역 식별) 오류 메시지 괄호를 해부.
--------------------------------------------------------------------------------
-- ("shared pool", "SELECT ... WHERE patient_id=99231", "SQLA", "kkscsAddChildNode")
--   │              │                                    │       │
--   실패 영역      실패를 유발한 대상(리터럴 커서)       하위영역  할당 요청 함수
--
-- · shared pool     → 실패 영역은 공유 풀(라지 풀이면 large pool로 표기).
-- · SELECT ... 99231→ 리터럴 SQL이 방아쇠.
-- · SQLA           → 공유 SQL 영역 하위에서 할당 시도.
-- · kkscsAddChildNode → 자식 커서를 '추가'하려다 실패.
-- 판정: 리터럴 SQL이 자식 커서를 계속 추가하다 공유 SQL 영역에서 연속 공간을
--   못 찾았다 → 진짜 원인은 하드 파싱이다(크기만의 문제가 아니다).

SYS@orcl> -- 예약 풀 요청 실패가 늘었는지 확인.
SYS@orcl> SELECT request_failures, last_failure_size
  2       FROM v$shared_pool_reserved;

REQUEST_FAILURES LAST_FAILURE_SIZE
---------------- -----------------
            <환경값>          <환경값>   -- (0보다 커짐: 큰 연속 할당 실패 증거)

--------------------------------------------------------------------------------
-- [5] (해소) 순서대로 조치한다 — 근본부터, 크기 확대는 최후.
--------------------------------------------------------------------------------
-- 1순위(근본): 애플리케이션 바인드 변수 전환. (여기서는 앱 수정 대신 2순위로 완화)
-- 2순위(완화): CURSOR_SHARING=FORCE로 리터럴 커서 폭증을 막는다.
SQLT@orcl> ALTER SESSION SET cursor_sharing=FORCE;
Session altered.

SQLT@orcl> BEGIN
  2         FOR i IN 1..100000 LOOP
  3           EXECUTE IMMEDIATE
  4             'SELECT /*WL01_LIT*/ COUNT(*) FROM patients WHERE patient_id='||i
  5             INTO :n;
  6         END LOOP;
  7       END;
  8       /
PL/SQL procedure successfully completed.

-- 해석: FORCE가 리터럴을 :SYS_B_0로 치환해 커서 1개를 공유 → 좁은 64MB에서도
--   ORA-04031 없이 완료됐다. 하드 파싱(자식 커서 추가)이 사라졌기 때문이다.

-- 3순위(완충): 큰 연속 할당까지 대비하려면 예약 풀을 조정한다(개인 환경 전용).
SYS@orcl> ALTER SYSTEM SET shared_pool_reserved_size=8M SCOPE=MEMORY;
System altered.

-- 4순위(최후): 어드바이저가 확대 유효를 보일 때만 크기를 키운다. 이 부하의
--   원인은 파싱이므로(실습 04에서 확대 곡선 평평) 크기 확대는 임시 봉합이다.

--------------------------------------------------------------------------------
-- [6] (재확인) 원인 조치 후 오류가 사라졌는지, 지표가 안정됐는지 확인.
--------------------------------------------------------------------------------
SYS@orcl> SELECT request_failures FROM v$shared_pool_reserved;

REQUEST_FAILURES
----------------
            <환경값>   -- (더 증가하지 않으면 대형 할당 실패가 멈춤)

SQLT@orcl> -- FORCE 상태에서 리터럴 커서가 몇 개로 수렴했는지 확인.
SQLT@orcl> SELECT COUNT(*) cursors FROM v$sqlarea WHERE sql_text LIKE '%WL01_LIT%';

   CURSORS
----------
        <환경값>   -- (1~소수 개 → 커서 폭증 해소)

-- 재확인 결과: 크기를 키우지 않고도(파싱 제거로) ORA-04031이 해소됐다.
--   '크기만 키워 임시 봉합'하지 않았다는 것이 이 실습의 핵심이다.

--------------------------------------------------------------------------------
-- [원복] 변경한 파라미터를 반드시 되돌린다(개인 환경 전용).
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET shared_pool_size=0 SCOPE=MEMORY;   -- ASMM 자동 조정 복귀
System altered.
SYS@orcl> ALTER SYSTEM SET shared_pool_reserved_size=<환경값> SCOPE=MEMORY;  -- 원래 값
System altered.
-- SPFILE로 강제했다면 SCOPE=BOTH 값을 원상 복구하고, 필요 시 인스턴스를
-- 재기동해 원래 SGA 구성으로 되돌린다. (SQLT 세션의 CURSOR_SHARING은 접속
-- 종료 시 자동 원복)

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 재현: 공유 풀 64M + 리터럴 10만 → ORA-04031(SQLA/자식 커서 추가).
-- 2) 원인 영역 식별: 메시지 괄호 4조각 → shared pool·SQLA·하드 파싱이 범인.
-- 3) 해소 순서: 바인드(근본)→FORCE(완화)→예약 풀(완충)→크기(최후, 이 부하엔 무효).
-- 4) 재확인: 크기 확대 없이 파싱 제거만으로 오류 해소 → 임시 봉합을 피했다.
-- ※ 경고 재강조: 파라미터 변경·오류 유발은 개인 환경 전용. 원복 필수.

SQLT@orcl> EXIT
SYS@orcl> EXIT
