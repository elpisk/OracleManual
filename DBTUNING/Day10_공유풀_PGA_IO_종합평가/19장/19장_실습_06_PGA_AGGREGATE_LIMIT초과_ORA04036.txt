================================================================================
 19장 실습 06 — PGA_AGGREGATE_LIMIT 초과(ORA-04036) 재현과 조정
 목표: 세션 한도(리소스 관리자 또는 세션 메모리)를 이용해 PGA 한도 초과를
       재현하고, ORA-04036을 '메모리 부족'으로 오판하지 않는다. 원인 세션을
       V$PROCESS_MEMORY로 지목해 올바른 조정 순서(코드 먼저, 한도는 마지막)를 익힌다.
 환경: non-CDB=orcl 19.3 (SYS 및 SQLT)
 주의: ★개인 실습 환경 전용★ 인스턴스 파라미터 변경·세션 강제 종료를 포함한다.
       운영 환경에서는 절대 수행하지 않는다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 target·limit 값을 먼저 캡처한다(원복 대비).
--------------------------------------------------------------------------------
SYS@orcl> SHOW PARAMETER pga_aggregate_target
NAME                    TYPE        VALUE
----------------------- ----------- -------
pga_aggregate_target    big integer 700M

SYS@orcl> SHOW PARAMETER pga_aggregate_limit
NAME                    TYPE        VALUE
----------------------- ----------- -------
pga_aggregate_limit     big integer <환경값>

-- 해석: target=700M(목표), limit=<환경값>(절대 한도). limit 기본값은
--   max(2GB, target의 200%, PROCESSES×3MB)이며 물리메모리 120%-SGA를 넘지 않는다.
--   ★ 위 두 값을 반드시 기록해 둔다. 실습 끝에 이 값으로 원복한다. ★

--------------------------------------------------------------------------------
-- [2] (조치) 재현을 위해 한도를 아주 낮게 내린다(개인 환경 전용).
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET PGA_AGGREGATE_LIMIT = 600M SCOPE=MEMORY;
System altered.
-- 해석: limit을 낮춰 조정 불가능 PGA 폭주가 한도를 쉽게 넘도록 만든다.
--   SCOPE=MEMORY라 재기동하면 spfile 값으로 돌아간다.

--------------------------------------------------------------------------------
-- [3] (이상/오류 재현 → 원인 → 조치 → 재확인)
--     한 세션이 조정 불가능한 PGA(거대 PL/SQL 컬렉션)를 폭주시킨다.
--------------------------------------------------------------------------------
$ sqlplus sqlt/sqlt@orcl
SQLT@orcl> -- 조정 불가능 PGA를 크게 확보하는 블록(BULK COLLECT LIMIT 미사용 흉내).
SQLT@orcl> DECLARE
  2           TYPE t_tab IS TABLE OF claim_details%ROWTYPE;
  3           v t_tab;
  4         BEGIN
  5           SELECT * BULK COLLECT INTO v FROM claim_details;   -- 100만+ 행을 통째로
  6           DBMS_OUTPUT.PUT_LINE(v.COUNT);
  7         END;
  8         /
DECLARE
*
ERROR at line 1:
ORA-04036: PGA memory used by the instance exceeds PGA_AGGREGATE_LIMIT

-- 원인: BULK COLLECT가 100만+ 행을 컬렉션에 통째로 담으며 '조정 불가능한' PGA가
--   폭주했다. 인스턴스 전체 PGA가 limit(600M)을 넘자, 오라클이 조정 불가능 PGA를
--   가장 많이 쓰는 이 세션의 콜을 중단시켰다. ORA-04036은 '메모리 부족'이 아니라
--   '절대 한도 초과 → 안전장치 작동'이다.

SYS@orcl> -- 원인 세션 지목: 어느 프로세스가 어느 범주에서 PGA를 많이 쓰는가?
SYS@orcl> SELECT p.spid, m.category, ROUND(m.allocated/1024/1024,1) alloc_mb
  2         FROM  v$process_memory m JOIN v$process p ON p.pid=m.pid
  3         WHERE m.allocated > 10*1024*1024
  4         ORDER BY m.allocated DESC
  5         FETCH FIRST 5 ROWS ONLY;
SPID     CATEGORY   ALLOC_MB
-------- ---------- ---------
<환경값>  PL/SQL     <환경값>    -- PL/SQL 범주에서 대량 할당 → 범인 지목

-- 조치(올바른 순서): ① 범인은 물리 메모리 부족이 아니라 특정 세션의 조정 불가능
--   PGA 폭주다. ② 코드를 고친다 — BULK COLLECT에 LIMIT을 준다.
SQLT@orcl> DECLARE
  2           CURSOR c IS SELECT * FROM claim_details;
  3           TYPE t_tab IS TABLE OF claim_details%ROWTYPE;
  4           v t_tab;
  5         BEGIN
  6           OPEN c;
  7           LOOP
  8             FETCH c BULK COLLECT INTO v LIMIT 1000;   -- 1000행씩만
  9             EXIT WHEN v.COUNT = 0;
 10           END LOOP;
 11           CLOSE c;
 12         END;
 13        /
PL/SQL procedure successfully completed.

-- 재확인: LIMIT 1000으로 조정 불가능 PGA를 억제하니 같은 데이터를 처리해도
--   ORA-04036이 나지 않는다. 원인(코드)을 고쳤기 때문이다. 한도를 키운 게 아니다.

--------------------------------------------------------------------------------
-- [4] (원복) 낮췄던 한도를 [1]에서 캡처한 원래 값으로 되돌린다.
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET PGA_AGGREGATE_LIMIT = <원래값: [1]에서 기록> SCOPE=MEMORY;
System altered.
SYS@orcl> SHOW PARAMETER pga_aggregate_limit   -- 원복 확인

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) ORA-04036 = 인스턴스 PGA가 절대 한도(PGA_AGGREGATE_LIMIT) 초과. '부족' 아님.
-- 2) 진짜 원인은 대개 특정 세션의 조정 불가능 PGA 폭주(BULK COLLECT LIMIT 미사용 등).
-- 3) 올바른 순서: V$PROCESS_MEMORY로 범인 지목 → 코드 수정 → (마지막) 한도 조정.
-- 4) target은 목표, limit은 천장. limit을 무작정 키우는 것은 안전장치를 푸는 것.
-- 5) 세션 단위 한도가 필요하면 리소스 관리자 SESSION_PGA_LIMIT(초과 시 ORA-10260).

SYS@orcl> EXIT
