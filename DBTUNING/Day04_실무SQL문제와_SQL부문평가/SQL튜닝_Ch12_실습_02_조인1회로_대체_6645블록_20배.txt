 Ch12 실습 02 — N+1 을 조인 1회로: 132,468 → 6,645 (19.9배), 그리고 외부 조인이 필요한 이유
 목표: 목록 20건과 상세 건수를 한 번의 조인으로 얻어 Buffers 6,645 를 실측하고 실습 01 과 대조한다.
       내부 조인으로 썼다가 "상세가 없는 청구가 목록에서 사라지는" 이상 징후를 재현해 외부 조인으로
       교정한다. 20건 → 100건으로 늘려도 비용이 거의 그대로임을 본다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. PK 외 인덱스 없음.
 주의: 개인 실습 환경 전용. 조회만 수행한다.
================================================================================

$ sqlplus sqlt/sqlt@orcl

-- [1] (이상 징후 → 원인) 내부 조인 — 목록이 줄어든다
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ c.claim_id, COUNT(*) cnt
  2       FROM  (SELECT claim_id FROM medical_claims WHERE hosp_id = 1 AND ROWNUM <= 20) c,
  3              claim_details d
  4       WHERE  c.claim_id = d.claim_id
  5       GROUP  BY c.claim_id;

<환경값> rows selected.                                   -- 20 이 아닐 수 있다

SQLT@orcl> -- 이상 징후: 목록은 20건인데 결과가 20건이 아니거나, 어떤 청구는 cnt 가 0 이 아니라 아예 없다.
SQLT@orcl> -- 원인 파악: 내부 조인은 짝이 있는 행만 남긴다. 상세가 한 건도 없는 청구는 목록에서 사라진다.
SQLT@orcl> --   실습 01 의 N+1 은 상세가 없으면 COUNT(*)=0 을 돌려줬으니, 같은 결과를 내려면 외부 조인이어야 한다.
SQLT@orcl> --   또 COUNT(*) 는 외부 조인에서 짝 없는 행도 1 로 센다 — COUNT(d.detail_id) 로 세야 0 이 나온다.
SQLT@orcl> --   "재작성 전후 결과가 같은가" 를 먼저 증명하지 않은 튜닝은 튜닝이 아니다.

--------------------------------------------------------------------------------
-- [2] (조치 → 재확인) 외부 조인 + COUNT(컬럼)
--------------------------------------------------------------------------------

  3              claim_details d
  4       WHERE  c.claim_id = d.claim_id(+)

-- 재확인: 결과 20행(상세 없는 청구는 cnt 0). Buffers 6,645 = 목록 23 + CLAIM_DETAILS Full Scan 6,622 한 번.

--   Id 5 MEDICAL_CLAIMS 가 23 Buffers 인 것은 ROWNUM<=20 으로 20행 찾자마자 멈춰서다(COUNT STOPKEY).
--   Id 2 A-Rows 65: 20건 청구에 상세가 총 65건(청구당 평균 3.25건).

--------------------------------------------------------------------------------
-- [3] (재확인) N 을 100 으로 — 조인은 N 에 둔감하다
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ c.claim_id, COUNT(d.detail_id) cnt
  2       FROM  (SELECT claim_id FROM medical_claims WHERE hosp_id = 1 AND ROWNUM <= 100) c,
  3              claim_details d
  4       WHERE  c.claim_id = d.claim_id(+)
  5       GROUP  BY c.claim_id;

100 rows selected.
SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------------
|*  2 |   HASH JOIN OUTER     |                |      1 |  <환경값> |  <환경값>  |  <환경값> |   -- 6,700 안팎
|   6 |    TABLE ACCESS FULL  | CLAIM_DETAILS  |      1 |    899K|  <환경값>  |    6622 |
------------------------------------------------------------------------------------------------

-- 재확인: 목록이 5배 늘었는데 Buffers 는 6,645 → 6,700 안팎(<환경값>). CLAIM_DETAILS 는 여전히 한 번.
--   N+1 이었다면 100 × 6,623 = 662,300 이다.

--   ┌────────────────────────┬──────┬────────────┬──────────────────────────┐
--   │ 방식                   │  N   │ 총 Buffers │ 비고                     │
--   ├────────────────────────┼──────┼────────────┼──────────────────────────┤
--   │ N+1 (실습 01)          │  20  │   132,468  │ CLAIM_DETAILS Full × 20  │
--   │ N+1 (실습 01, 재확인)  │  60  │   397,404  │ 정비례                   │
--   │ 조인 1회               │  20  │     6,645  │ CLAIM_DETAILS Full × 1   │
--   │ 조인 1회               │ 100  │  <환경값>  │ 거의 그대로              │
--   └────────────────────────┴──────┴────────────┴──────────────────────────┘

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 반복 조회를 조인 1회로 바꾸면 비용이 N 에서 1 로 준다(132,468 → 6,645).
-- 2) 재작성은 결과 동일성이 먼저다 — 상세 없는 청구가 사라지지 않게 외부 조인, 0 이 나오게 COUNT(컬럼).
-- 3) 조인 1회는 N 이 100 이 돼도 표를 한 번 읽는다. N+1 은 N 에 정비례한다.
-- 4) 이 조인도 CLAIM_DETAILS 를 Full Scan 한다(6,622). 이것마저 줄이는 것이 실습 03 의 인덱스다.
