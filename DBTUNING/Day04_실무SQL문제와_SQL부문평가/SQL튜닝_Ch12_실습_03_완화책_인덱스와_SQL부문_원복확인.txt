 Ch12 실습 03 — 완화책: CLAIM_DETAILS(CLAIM_ID) 인덱스로 회당 비용을 줄인다, 그리고 SQL 부문 원복 확인
 목표: 조인이 당장 어려운 응용을 가정해 CLAIM_DETAILS.CLAIM_ID 에 인덱스를 만들고, N+1 의 회당 비용이
       6,623 에서 수 블록으로 주는 것을 V$SQL 델타로 확인한다. 그래도 반복 구조는 남아 N 에 정비례함을
       보고, 조인 1회 쪽도 인덱스로 어떻게 바뀌는지 본다. 마지막에 인덱스를 지우고 SQL 부문 전체 원복
       (PK 만, 통계 원상)을 검증한다 — 이것이 Day 5 인스턴스 부문의 전제다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. DDL 포함.
 주의: 개인 실습 환경 전용. 이 실습의 [4] 는 Day 4 종료 점검이기도 하다.

SQLT@orcl> DECLARE
  2         v_cnt NUMBER;

  6         END LOOP;
  7       END;

-- 재확인: 회당 6,623 → 3~4 Buffers. 20회 합 60~80. Full Scan 이 INDEX RANGE SCAN(Index-Only)이 됐다.
--   그러나 EXECUTIONS 는 여전히 20 — 반복 구조는 그대로다. N 이 10,000 이면 30,000~40,000 Buffers 에
--   왕복 10,000회. 인덱스는 "회당" 을 줄일 뿐 "회수" 를 줄이지 못한다.

-- 재확인: HASH JOIN OUTER(6,645) → NESTED LOOPS OUTER(<환경값>, 100 안팎). Id 6 의 Starts=20 — 조인 안에서
--   20번 인덱스를 탐색했다. "N+1 과 같은 20번" 이지만 세션 왕복 없이 서버 안에서 도는 것이 다르다.
--   결국 최선은 조인 1회 + FK 인덱스다: 왕복 1회, 표 접근 최소.

--   ┌──────────────────────────────┬──────────┬───────────┬──────────────────────┐
--   │ 방식                         │ 왕복     │ Buffers   │ 구조                 │
--   ├──────────────────────────────┼──────────┼───────────┼──────────────────────┤
--   │ N+1, 인덱스 없음 (실습 01)   │ 20       │ 132,468   │ Full × 20            │
--   │ 조인 1회, 인덱스 없음(실습 02)│ 1        │   6,645   │ HASH JOIN, Full × 1  │
--   │ N+1, 인덱스 있음 (이 실습)   │ 20       │  60~80    │ RANGE SCAN × 20      │
--   │ 조인 1회, 인덱스 있음        │ 1        │ 100 안팎  │ NL, RANGE SCAN × 20  │
--   └──────────────────────────────┴──────────┴───────────┴──────────────────────┘

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) FK 컬럼 인덱스는 N+1 의 회당 비용을 6,623 → 3~4 로 줄인다. 그러나 회수(왕복)는 그대로다.
-- 2) 근본 해법은 조인 1회, 완화책은 인덱스, 최선은 둘 다(NL + RANGE SCAN, 왕복 1회).
-- 3) Starts=20 인 NL 과 왕복 20회인 N+1 은 "20번" 이 같아도 비용이 다르다 — 왕복이 비싸다.
-- 4) PK 인덱스는 제약이 쓰고 있어 지울 수 없다(ORA-02429). 원복 대상은 IX_ 로 시작하는 것뿐.
-- 5) SQL 부문 종료 점검 4항목: PK 외 인덱스 0, _WL 표 0, HOSP_ID HYBRID 254, 표 건수 원상.
