 Ch12 실습 01 — N+1 재현: 청구 20건에 상세를 건별로 조회하면 132,420 Buffers (PLS-00428 교정)
 목표: PL/SQL 로 "목록 1회 + 건별 상세 20회" 의 N+1 패턴을 재현하고, V$SQL 에서 상세 SQL 이 20번 실행돼
       BUFFER_GETS 132,420(회당 6,621)이 누적된 것을 확인한다. SELECT INTO 를 빼먹어 나는 PLS-00428 을
       교정하고, 화면에서는 왜 이 문제가 안 보이는지(건당 0.02초) 시간과 블록을 함께 본다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. PK 외 인덱스 없음(CLAIM_DETAILS.CLAIM_ID 에 인덱스 없음).
 주의: 개인 실습 환경 전용. 조회만 수행한다.
================================================================================

SQLT@orcl> -- 조치: INTO v_cnt 를 넣는다. (실제 응용은 이 자리에서 상세를 화면에 그린다.)

--------------------------------------------------------------------------------
-- [2] (조치 전 상태) N+1 실행 — 목록 1회 + 상세 20회
--------------------------------------------------------------------------------
SQLT@orcl> -- 측정을 위해 상세 SQL 에 태그를 붙인다. 힌트 형식(/*+ */)으로 쓰는 이유: PL/SQL 은 컴파일 때 일반
SQLT@orcl> --   주석(/* */)을 지우지만 힌트 주석은 SQL 텍스트에 남긴다 — 그래야 V$SQL 에서 찾을 수 있다.
SQLT@orcl> --   (모르는 힌트는 옵티마이저가 무시한다. Ch14 실습 03 의 BEFORE_CH14 태그도 같은 방식.)
SQLT@orcl> DECLARE
  2         v_cnt NUMBER;
  3       BEGIN
  4         FOR r IN (SELECT claim_id FROM medical_claims WHERE hosp_id = 1 AND ROWNUM <= 20) LOOP
  5           SELECT /*+ N1_DETAIL */ COUNT(*) INTO v_cnt FROM claim_details WHERE claim_id = r.claim_id;
  6         END LOOP;
  7       END;
  8       /

PL/SQL procedure successfully completed.

SQLT@orcl> -- 화면에서는 이렇게 보인다: 20건 목록에 상세 건수가 붙어 "금방" 나온다(합계 0.31초).
SQLT@orcl> --   개발자는 문제를 못 느낀다.

SQLT@orcl> -- 이상 징후: SQL 하나가 EXECUTIONS 20, BUFFER_GETS 132,420. 회당 6,621 — Ch04 실습 01 에서 본
SQLT@orcl> --   CLAIM_DETAILS Full Scan(6,621) 그대로다. 20건 목록 하나 그리는 데 90만 행짜리 표를 20번 읽었다.
SQLT@orcl> -- 원인 파악: (1) CLAIM_DETAILS.CLAIM_ID 에 인덱스가 없어 회당 Full Scan, (2) 그것을 목록 건수만큼
SQLT@orcl> --   반복. 비용 = 회당 비용 × N. 바인드 변수(:B1)라 SQL_ID 는 하나 — 파싱은 문제가 아니다. 실행 횟수가 문제다.
SQLT@orcl> --   회당 15.3ms 라 화면은 0.31초에 끝난다. 목록이 100건이면 1.5초, 1,000건이면 15초 — 선형으로 나빠진다.
SQLT@orcl> -- 재확인: "N" 을 바꿔 선형임을 본다 — 40건으로 다시 실행.
SQLT@orcl> DECLARE
  2         v_cnt NUMBER;
  3       BEGIN
  4         FOR r IN (SELECT claim_id FROM medical_claims WHERE hosp_id = 1 AND ROWNUM <= 40) LOOP
  5           SELECT /*+ N1_DETAIL */ COUNT(*) INTO v_cnt FROM claim_details WHERE claim_id = r.claim_id;
  6         END LOOP;
  7       END;
  8       /

-- [4] (조치 후 관점) 두 갈래 처방 — 실습 02·03
--------------------------------------------------------------------------------
-- * 근본: 반복을 없앤다 — 목록과 상세를 조인 1회로(실습 02). N 이 커져도 표는 한 번.
-- * 완화: 회당 비용을 줄인다 — CLAIM_DETAILS(CLAIM_ID) 인덱스(실습 03). 6,621 → 수 블록. 반복 구조는 남는다.
-- * 인스턴스 부문에서는 이 SQL 이 AWR "SQL ordered by Executions·Gets" 상위에 오른다(TUN 8장 실습 04).
--   회당은 싸 보이는데 합이 큰 SQL — 그것이 N+1 의 시스템 관점 지문이다(브리지 02 의 마지막 행).

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) PL/SQL 안의 SELECT 는 INTO 가 필수(PLS-00428, 컴파일 오류).
-- 2) N+1 = 회당 비용 × N. 20건에 132,420 Buffers, 60건에 397,260 — 정비례.
-- 3) 화면 시간(0.31초)으론 안 보인다. V$SQL 의 EXECUTIONS × AVG_BUFFERS 로 본다.
-- 4) 바인드 변수를 써도 N+1 은 N+1 이다 — 파싱이 아니라 실행 횟수의 문제.
