================================================================================
 15장 실습 05 — 자동 SQL 튜닝 어드바이저 결과 조회와 자동 채택 정책
 목표: 밤마다 도는 SYS_AUTO_SQL_TUNING_TASK의 결과를 조회하고,
       발견된 SQL 프로파일의 '자동 채택' 정책(ACCEPT_SQL_PROFILES)을 확인한다.
       프로파일이 근본 해결이 아님을 이해하고, 수동 채택·삭제 흐름을 익힌다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 라이선스(🔒): 자동/수동 SQL Tuning Advisor 모두 Tuning Pack이 필요하다.
 주의: 개인 실습 환경 전용. 프로파일은 '확인' 위주로 다룬다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LONG 200000 LINESIZE 130 PAGESIZE 0

--------------------------------------------------------------------------------
-- [1] (조치 전) 자동 튜닝 작업이 켜져 있고 최근에 돌았는지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT status FROM dba_advisor_tasks
  2       WHERE task_name = 'SYS_AUTO_SQL_TUNING_TASK';

STATUS
-----------
COMPLETED

SYS@orcl> -- 1장 실측에서 DBA_FEATURE_USAGE_STATISTICS의
SYS@orcl> --   'Automatic SQL Tuning Advisor' detected_usages=2 (2026-08-21)로,
SYS@orcl> --   이 기능이 실제로 사용된 이력이 있음을 확인했다(🔒 Tuning Pack 근거).

--------------------------------------------------------------------------------
-- [2] (조회) 자동 튜닝 작업의 요약 보고서를 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT DBMS_AUTO_SQLTUNE.REPORT_AUTO_TUNING_TASK(
  2           type => 'TEXT', level => 'TYPICAL', section => 'SUMMARY') FROM dual;

GENERAL INFORMATION SECTION
-------------------------------------------------------------------------------
Tuning Task Name                   : SYS_AUTO_SQL_TUNING_TASK
Tuning Task Owner                  : SYS
Workload Type                      : Automatic High-Load SQL Workload
Completion Status                  : COMPLETED
-------------------------------------------------------------------------------
SUMMARY SECTION
-------------------------------------------------------------------------------
Global SQL Tuning Result Statistics
  Number of SQLs Analyzed            : <환경값>
  Number of SQLs with Findings       : <환경값>
  Number of SQLs with SQL profiles   : <환경값>
-------------------------------------------------------------------------------

-- 해석: 자동 작업이 고부하 SQL을 골라 분석한 결과다. 분석 건수·발견 건수는
--   워크로드에 따라 다르므로 <환경값>. 핵심은 '프로파일이 몇 건 발견됐나'와
--   '그것을 자동으로 채택하게 둘 것인가'다(아래 [3]).

--------------------------------------------------------------------------------
-- [3] (조회 — 핵심 판단) 자동 프로파일 채택 정책을 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN parameter_value FORMAT A16
SYS@orcl> SELECT parameter_name, parameter_value
  2       FROM  dba_advisor_parameters
  3       WHERE task_name = 'SYS_AUTO_SQL_TUNING_TASK'
  4         AND parameter_name = 'ACCEPT_SQL_PROFILES';

PARAMETER_NAME          PARAMETER_VALUE
----------------------- ----------------
ACCEPT_SQL_PROFILES     FALSE

-- 해석: FALSE = 자동 작업이 프로파일을 찾아도 사람 검토 전에는 적용하지 않는다.
--   권장 설정이다. TRUE로 바꾸면 검토 없는 프로파일이 운영 계획을 바꾼다(위험).

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 특정 SQL의 계획이 며칠 새 갑자기 바뀌었다는 신고.
--       자동으로 채택된 SQL 프로파일이 원인인지 의심한다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN name FORMAT A26
SYS@orcl> SELECT name, type, status, TO_CHAR(created,'YYYY-MM-DD') created
  2       FROM  dba_sql_profiles
  3       ORDER BY created DESC;

no rows selected

SYS@orcl> -- 원인 파악: 자동 채택 프로파일은 없다(ACCEPT_SQL_PROFILES=FALSE와 일치).
SYS@orcl> --   즉 계획 변화의 원인은 '자동 프로파일'이 아니다. 다른 원인을 봐야 한다
SYS@orcl> --   (통계 재수집, SQL Plan Directive, 적응형 계획 → 실습 08).
SYS@orcl> -- 조치: 계획 변화 원인을 좁히기 위해, 자동 프로파일이 아님을 근거로 남긴다.
SYS@orcl> -- 재확인: dba_sql_profiles가 비어 있으므로 자동 프로파일 가설은 기각된다.

--------------------------------------------------------------------------------
-- [5] (참고) 수동 채택이 필요할 때의 흐름 — 검토 후에만 적용한다.
--------------------------------------------------------------------------------
-- 발견된 프로파일을 검토해 채택하려면(실습 04의 태스크 기준 예시):
--   EXEC DBMS_SQLTUNE.ACCEPT_SQL_PROFILE( -
--     task_name => '<태스크명>', name => 'PROF_XXX', force_match => TRUE);
-- 채택한 프로파일은 dba_sql_profiles에 남고 STATUS=ENABLED가 된다.
-- 되돌리기:  EXEC DBMS_SQLTUNE.DROP_SQL_PROFILE('PROF_XXX');
-- ※ 프로파일은 SQL 텍스트를 고치지 않고 계획만 보정한다 → '응급 처치'다.
--   데이터 분포가 바뀌면 보정이 틀어질 수 있고, SQL의 나쁜 구조는 그대로 남는다.
--   근본 원인(통계·인덱스·SQL 구조)은 별도로 추적한다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 자동 SQL 튜닝은 SYS_AUTO_SQL_TUNING_TASK로 밤마다 고부하 SQL을 분석한다(🔒).
-- 2) REPORT_AUTO_TUNING_TASK로 결과를, DBA_ADVISOR_PARAMETERS로 정책을 본다.
-- 3) ACCEPT_SQL_PROFILES 기본 FALSE(자동 채택 off) — 권장. 검토 후 수동 채택한다.
-- 4) SQL 프로파일은 근본 해결이 아니라 응급 처치다.
-- 5) 계획 변화의 원인 분석에서 'dba_sql_profiles가 비었다'는 자동 프로파일 가설을 기각한다.

SYS@orcl> EXIT
