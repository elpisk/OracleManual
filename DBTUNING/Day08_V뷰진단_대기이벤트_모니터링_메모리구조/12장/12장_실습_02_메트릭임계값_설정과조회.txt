================================================================================
 12장 실습 02 — 메트릭 임계값 설정과 현재 설정 조회
 목표: DBA_THRESHOLDS로 현재 임계값을 확인하고, DBMS_SERVER_ALERT.SET_THRESHOLD로
       임계값을 설정·초기화한다. 연속 관측(consecutive)의 의미를 확인한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA)
 라이선스: 임계값 설정·조회는 기본 기능(라이선스 무관).
 주의: 개인 실습 환경 전용. 설정 변경 후 원복까지 수행한다.
 메트릭 선택: 표본으로 '테이블스페이스 사용률'(TABLESPACE_PCT_FULL)을 쓴다. 이 메트릭은
       DB 전역 기본값(85/97)이 있어 SET_THRESHOLD 설정·해제가 깔끔히 왕복되기 때문이다.
       (서비스의 '호출당 CPU/응답시간' 메트릭은 이 릴리스에서 DO_NOT_CHECK 해제가
        거부되어 실습 원복이 지저분하므로 표본으로 쓰지 않는다 — 실습 07의 주석 참조.)
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 120
SYS@orcl> COLUMN metrics_name FORMAT A24
SYS@orcl> COLUMN w  FORMAT A8
SYS@orcl> COLUMN c  FORMAT A8
SYS@orcl> COLUMN object_name FORMAT A14

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) DB 전역 기본 임계값을 먼저 캡처한다(원복 목표값).
--------------------------------------------------------------------------------
SYS@orcl> SELECT metrics_name, warning_value w, critical_value c,
  2         consecutive_occurrences cons, object_name
  3       FROM  dba_thresholds
  4       WHERE metrics_name = 'Tablespace Space Usage'
  5         AND object_name IS NULL;

METRICS_NAME             W        C              CONS OBJECT_NAME
------------------------ -------- -------- ---------- --------------
Tablespace Space Usage   85       97                1

-- 해석: object_name 이 비어 있는 이 행이 '데이터베이스 전역 기본값'이다(경고 85%·위험 97%).
--   개별 테이블스페이스에 SET_THRESHOLD 를 걸면 그 TS 이름으로 '재정의(override)' 행이 따로 생긴다.
--   CONSEC=1 은 1회 초과 시 곧바로 알림.

--------------------------------------------------------------------------------
-- [2] (설정) 특정 테이블스페이스(USERS)에만 더 엄격한 임계값을 재정의한다.
--     경고 80%·위험 90%, 연속 2회 초과해야 울리게 한다.
--------------------------------------------------------------------------------
SYS@orcl> BEGIN
  2    DBMS_SERVER_ALERT.SET_THRESHOLD(
  3      metrics_id             => DBMS_SERVER_ALERT.TABLESPACE_PCT_FULL,
  4      warning_operator       => DBMS_SERVER_ALERT.OPERATOR_GE,
  5      warning_value          => '80',
  6      critical_operator      => DBMS_SERVER_ALERT.OPERATOR_GE,
  7      critical_value         => '90',
  8      observation_period     => 1,
  9      consecutive_occurrences=> 2,
 10      instance_name          => NULL,
 11      object_type            => DBMS_SERVER_ALERT.OBJECT_TYPE_TABLESPACE,
 12      object_name            => 'USERS');
 13  END;
 14  /

PL/SQL procedure successfully completed.

-- 해석: 5개의 손잡이 — 경고·위험 값, 연산자(GE=이상), 관측주기(1분),
--   연속 관측(2회), 대상(테이블스페이스 USERS). consecutive=2 라 연속 2회 초과해야 울린다.

--------------------------------------------------------------------------------
-- [3] (조회) 방금 건 재정의가 DBA_THRESHOLDS에 반영됐는지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT metrics_name, warning_value w, critical_value c,
  2         consecutive_occurrences cons, object_name
  3       FROM  dba_thresholds
  4       WHERE metrics_name = 'Tablespace Space Usage'
  5         AND object_name = 'USERS';

METRICS_NAME             W        C              CONS OBJECT_NAME
------------------------ -------- -------- ---------- --------------
Tablespace Space Usage   80       90                2 USERS

-- 해석: USERS 에 경고 80·위험 90·연속 2회로 재정의됐다. 전역 기본값(85/97)은 그대로 있고,
--   USERS 만 이 값을 우선 적용받는다.

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 재정의를 지우려고 딕셔너리 뷰에서 DELETE 를 시도한다.
--------------------------------------------------------------------------------
SYS@orcl> -- (잘못된 시도) DBA_THRESHOLDS는 뷰라 DELETE 로 지울 수 없다.
SYS@orcl> DELETE FROM dba_thresholds
  2       WHERE metrics_name='Tablespace Space Usage' AND object_name='USERS';
DELETE FROM dba_thresholds
            *
ERROR at line 1:
ORA-01732: data manipulation operation not legal on this view

SYS@orcl> -- 원인 파악: 임계값은 딕셔너리 뷰를 직접 지우는 게 아니라
SYS@orcl> --   SET_THRESHOLD 에 연산자 DO_NOT_CHECK 를 주어 재정의를 해제하는 것이다.
SYS@orcl> -- 조치: warning/critical 연산자를 DO_NOT_CHECK 로 지정해 재정의를 해제한다.
SYS@orcl> BEGIN
  2    DBMS_SERVER_ALERT.SET_THRESHOLD(
  3      metrics_id=>DBMS_SERVER_ALERT.TABLESPACE_PCT_FULL,
  4      warning_operator =>DBMS_SERVER_ALERT.OPERATOR_DO_NOT_CHECK, warning_value =>NULL,
  5      critical_operator=>DBMS_SERVER_ALERT.OPERATOR_DO_NOT_CHECK, critical_value=>NULL,
  6      observation_period=>1, consecutive_occurrences=>1,
  7      instance_name=>NULL,
  8      object_type=>DBMS_SERVER_ALERT.OBJECT_TYPE_TABLESPACE, object_name=>'USERS');
  9  END;
 10  /

PL/SQL procedure successfully completed.

SYS@orcl> -- 재확인: '활성 재정의'(연산자가 DO_NOT_CHECK 가 아닌 행)가 사라졌는지 센다.
SYS@orcl> SELECT COUNT(*) active_override FROM dba_thresholds
  2       WHERE metrics_name='Tablespace Space Usage' AND object_name='USERS'
  3         AND warning_operator <> 'DO NOT CHECK';

ACTIVE_OVERRIDE
---------------
              0

-- 재확인: USERS 의 활성 재정의가 사라져 다시 전역 기본값(85/97)을 따른다. 실습 환경을 원복했다.
-- 참고(중요): DO_NOT_CHECK 해제는 딕셔너리 '행 자체'를 지우는 게 아니라 그 행을
--   'DO NOT CHECK / 0 / 0'(검사 안 함) 상태로 바꾼다. 그래서 DBA_THRESHOLDS 에는
--   비활성 흔적 행이 남을 수 있다(알림은 발생하지 않는다). 행까지 완전히 없애려면
--   대상 객체를 없애거나 내부 저장소를 관리자 권한으로 정리해야 한다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 현재 임계값은 DBA_THRESHOLDS로 본다(뷰라 직접 수정 불가 → ORA-01732).
-- 2) 설정·변경·해제는 모두 SET_THRESHOLD로 한다. DO_NOT_CHECK = 재정의 해제(기본값 복원).
-- 3) consecutive_occurrences로 순간 스파이크를 흡수한다(예: 2회 연속 초과해야 알림).
-- 4) 어떤 값을 넣을지는 감이 아니라 이력에서 정한다(실습 03).

SYS@orcl> EXIT
