================================================================================
 16장 실습 02 — AMM 구성과 MEMORY_TARGET 조정 후 재기동 확인 (실측)
 목표: ASMM인 인스턴스를 자동 메모리 관리(AMM)로 전환하는 절차를 익힌다.
       전환 실패(파라미터 충돌)를 재현하고, 그 상태에서 '재기동으로 못 살리는' 함정과
       올바른 복구(백업 pfile)를 실측으로 확인한 뒤, 정상값으로 AMM 전환·원복한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA). 이 랩은 sga_max_size=2G 가 명시돼 있다.
 ⚠ 주의: SHUTDOWN/STARTUP 을 여러 번 포함한다. 반드시 '다른 세션이 없는' 격리된 개인
        실습 DB에서만 수행한다. SHUTDOWN IMMEDIATE 는 접속 중인 모든 세션(다른 사용자·RMAN
        포함)을 강제 종료한다.
 ⚠ 필수: 시작 전 [1]에서 현재 파라미터를 pfile 로 백업한다. 전환 실패 시 이 백업이
        유일한 복구 수단이다(아래 [3]에서 STARTUP NOMOUNT 로는 못 살리는 것을 확인한다).
================================================================================

$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태 + 백업) 현재 값을 기록하고, pfile 로 반드시 백업한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT name, display_value FROM v$parameter
  2       WHERE name IN ('memory_target','memory_max_target',
  3         'sga_target','sga_max_size','pga_aggregate_target')
  4       ORDER BY name;

NAME                   DISPLAY_VALUE
---------------------- --------------
memory_max_target      0
memory_target          0
pga_aggregate_target   700M
sga_max_size           2G
sga_target             1504M

-- 조치 전: MEMORY_TARGET=0 → ASMM. SGA(1504M)+PGA(700M) ≈ 2204M 가 대략의 총 수요다.
--   ★ 이 랩은 SGA_MAX_SIZE=2G 가 명시돼 있다 — 이 값이 아래 [3] 오류의 핵심이 된다.

SYS@orcl> -- (필수) 현재 spfile 을 pfile 로 백업한다. 전환 실패 시 복구의 유일한 근거다.
SYS@orcl> CREATE PFILE='/home/oracle/wl/pf_16_02_bak.ora' FROM SPFILE;

File created.

--------------------------------------------------------------------------------
-- [2] (조치 → 오류 재현) MEMORY_TARGET 을 SGA_MAX_SIZE 보다 작게 주고 재기동한다.
--------------------------------------------------------------------------------
SYS@orcl> -- MEMORY_MAX_TARGET(정적, 상한)을 먼저 잡는다.
SYS@orcl> ALTER SYSTEM SET memory_max_target=2800M SCOPE=SPFILE;
System altered.

SYS@orcl> -- (오류 유발) MEMORY_TARGET 을 SGA_MAX_SIZE(2G)보다 작은 800M 로 준다.
SYS@orcl> ALTER SYSTEM SET memory_target=800M SCOPE=SPFILE;
System altered.

SYS@orcl> SHUTDOWN IMMEDIATE
Database closed.
Database dismounted.
ORACLE instance shut down.

SYS@orcl> STARTUP
ORA-00844: Parameter not taking MEMORY_TARGET into account
ORA-00851: SGA_MAX_SIZE 2147483648 cannot be set to more than MEMORY_TARGET
838860800.
ORA-01078: failure in processing system parameters

-- * 이상/오류: 인스턴스가 기동하지 못하고 멈춘다. 전사(轉寫) 통념의 ORA-00838 이 아니라
--   ORA-00844/ORA-00851 이다 — 이 랩은 SGA_MAX_SIZE 가 2G 로 명시돼 있어, MEMORY_TARGET(800M)
--   이 그보다 작으면 'SGA_MAX_SIZE 를 MEMORY_TARGET 보다 크게 둘 수 없다'며 먼저 거부한다.
--   (SGA_MAX_SIZE 를 명시하지 않은 환경이라면 대신 ORA-00838: needs to be at least … 가 난다.)

--------------------------------------------------------------------------------
-- [3] (함정 확인) '재기동으로 살린다'가 안 통한다 — NOMOUNT 도 같은 오류다.
--------------------------------------------------------------------------------
SYS@orcl> STARTUP NOMOUNT
ORA-00844: Parameter not taking MEMORY_TARGET into account
ORA-00851: SGA_MAX_SIZE 2147483648 cannot be set to more than MEMORY_TARGET
838860800.
ORA-01078: failure in processing system parameters

-- * 함정: NOMOUNT 도 실패한다. 메모리 파라미터는 인스턴스가 SGA 를 잡는 '기동 최초 단계'에서
--   검증되므로, spfile 에 잘못된 값이 있으면 NOMOUNT 조차 못 간다. 즉 'STARTUP NOMOUNT 로
--   접근해 ALTER SYSTEM 으로 고친다'는 흔한 절차가 이 경우엔 통하지 않는다.

--------------------------------------------------------------------------------
-- [4] (복구) 백업 pfile 로 spfile 을 다시 만들어 살린다.
--     인스턴스가 내려간(idle) 상태라 CREATE SPFILE 이 가능하다([6]의 ORA-32002 대비).
--------------------------------------------------------------------------------
SYS@orcl> CREATE SPFILE FROM PFILE='/home/oracle/wl/pf_16_02_bak.ora';

File created.

SYS@orcl> STARTUP
ORACLE instance started.

Total System Global Area 2147481656 bytes
Fixed Size                  8898616 bytes
Variable Size            1375731712 bytes
Database Buffers          754974720 bytes
Redo Buffers                7876608 bytes
Database mounted.
Database opened.

SYS@orcl> SHOW PARAMETER memory_target
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
memory_target                        big integer 0

-- * 복구: 백업 pfile(MEMORY_TARGET=0 등 ASMM 값)로 spfile 을 재생성하고 기동하니 정상으로
--   돌아왔다. 잘못된 memory 파라미터의 유일한 확실한 복구는 '백업 pfile 로 spfile 재생성'이다.

--------------------------------------------------------------------------------
-- [5] (조치 → 재확인) 이번엔 올바른 값으로 AMM 로 전환한다.
--     MEMORY_TARGET 을 SGA_MAX_SIZE(2G) 이상이자 최소 수요 이상으로 준다.
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET memory_max_target=2800M SCOPE=SPFILE;
System altered.
SYS@orcl> ALTER SYSTEM SET memory_target=2800M SCOPE=SPFILE;   -- 2800M > SGA_MAX_SIZE 2G
System altered.

SYS@orcl> SHUTDOWN IMMEDIATE
Database closed.
Database dismounted.
ORACLE instance shut down.

SYS@orcl> STARTUP
ORACLE instance started.
...
Database opened.

SYS@orcl> SHOW PARAMETER memory_target
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
memory_target                        big integer 2800M

-- * 재확인: MEMORY_TARGET=2800M(>0) → 판별 규칙 ①에 의해 이제 AMM 이다. 2800M 은 SGA_MAX_SIZE
--   (2G)보다 크고 SGA+PGA 최소 수요(≈2204M)보다도 커서 ORA-00851/ORA-00838 없이 기동했다.

SYS@orcl> -- AMM 에서는 SGA 와 PGA 를 하나의 통합 구성으로 조정한다. 그 흔적을 본다.
SYS@orcl> COLUMN component FORMAT A26
SYS@orcl> SELECT component, ROUND(current_size/1024/1024) cur_mb
  2       FROM v$memory_dynamic_components
  3       WHERE current_size>0 ORDER BY current_size DESC;

COMPONENT                  CUR_MB
-------------------------- ------
SGA Target                   1504
PGA Target                   1296
shared pool                <환경값>
DEFAULT buffer cache       <환경값>
Shared IO Pool             <환경값>
KEEP buffer cache          <환경값>
DEFAULT 4K buffer cache    <환경값>
large pool                 <환경값>
streams pool               <환경값>

-- 해석: ASMM(실습 01)과 달리 'SGA Target'·'PGA Target' 이 함께 나타난다 — 이것이 AMM 의 표시다.
--   SGA Target 1504 + PGA Target 1296 = 2800 = MEMORY_TARGET. 즉 오라클이 총 2800M 를 SGA 와
--   PGA 로 나눠 잡았다(SGA 는 sga_target 1504M 하한을 지켜 배정). 하위 풀 크기는 자동조정이라 <환경값>.

--------------------------------------------------------------------------------
-- [6] (원복) 다시 ASMM 으로 되돌린다 — 실행 중 CREATE SPFILE 은 거부됨에 유의.
--------------------------------------------------------------------------------
SYS@orcl> -- (함정) 인스턴스가 떠 있는 채로 백업 pfile 로 spfile 을 만들려 하면 거부된다.
SYS@orcl> CREATE SPFILE FROM PFILE='/home/oracle/wl/pf_16_02_bak.ora';
CREATE SPFILE FROM PFILE='/home/oracle/wl/pf_16_02_bak.ora'
*
ERROR at line 1:
ORA-32002: cannot create SPFILE already being used by the instance

SYS@orcl> -- 조치: 먼저 SHUTDOWN 으로 내린 뒤(그러면 spfile 을 안 쓰는 상태) 재생성한다.
SYS@orcl> SHUTDOWN IMMEDIATE
Database closed.
Database dismounted.
ORACLE instance shut down.

SYS@orcl> CREATE SPFILE FROM PFILE='/home/oracle/wl/pf_16_02_bak.ora';

File created.

SYS@orcl> STARTUP
ORACLE instance started.
...
Database opened.

SYS@orcl> SHOW PARAMETER memory_target
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
memory_max_target                    big integer 0
memory_target                        big integer 0

SYS@orcl> SHOW PARAMETER sga_target
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
sga_target                           big integer 1504M

-- * 재확인: MEMORY_TARGET=0·MEMORY_MAX_TARGET=0·SGA_TARGET=1504M → 다시 ASMM(실습 01 상태)로
--   복원됐다. 실습 환경을 원복했다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) AMM 전환: MEMORY_MAX_TARGET(정적) → 재기동 → MEMORY_TARGET(동적) 설정. 판별은 MEMORY_TARGET>0.
-- 2) MEMORY_TARGET 이 SGA_MAX_SIZE 보다 작으면 ORA-00844/ORA-00851 로 기동 실패(SGA_MAX_SIZE 미명시
--    환경이면 ORA-00838). 그래서 MEMORY_TARGET 은 SGA_MAX_SIZE 이상이자 SGA+PGA 수요 이상으로 준다.
-- 3) ★ 잘못된 memory 파라미터는 STARTUP NOMOUNT 로도 못 살린다(파라미터가 기동 최초 단계에서 검증됨).
--    유일한 복구는 '백업 pfile 로 spfile 재생성 → STARTUP'. 그래서 시작 전 pfile 백업이 필수다.
-- 4) 인스턴스가 떠 있으면 CREATE SPFILE 은 ORA-32002 — 반드시 SHUTDOWN 후 재생성한다.
-- 5) 재기동·파라미터 변경은 개인 격리 환경 전용. 실습 후 반드시 원복한다.
-- ※ 절대값은 환경 의존 <환경값>. 핵심은 전환 절차·오류 흐름·pfile 복구의 이해다.

SYS@orcl> EXIT
