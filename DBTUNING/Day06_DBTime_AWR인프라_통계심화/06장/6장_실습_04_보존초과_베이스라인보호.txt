================================================================================
 6장 실습 04 — 보존 기간 초과 상황 확인과 베이스라인 보호
 목표: 보존 기간이 지나면 스냅샷이 사라진다는 것을 확인하고, 필요한 구간을
       베이스라인으로 지정해 자동 퍼지에서 살려 두는 절차를 익힌다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 라이선스 주의(🔒): AWR·DBMS_WORKLOAD_REPOSITORY는 Diagnostics Pack 필요.
       미보유 시 Statspack sppurge 정책과 보존 관리로 대응(정리 참조).
 주의: 개인 실습 환경 전용. 소실은 사고가 아니라 예정된 동작임을 이해한다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 보존 기간과, 현재 남아 있는 스냅샷의 범위를 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT retention FROM dba_hist_wr_control;

RETENTION
--------------------
+00008 00:00:00.0

SYS@orcl> SELECT MIN(snap_id) oldest, MAX(snap_id) newest,
  2         TO_CHAR(MIN(begin_interval_time),'MM-DD HH24:MI') oldest_t
  3       FROM dba_hist_snapshot;

    OLDEST     NEWEST OLDEST_T
---------- ---------- -----------
       230        296 08-17 09:00

-- 해석: 보존 8일. 가장 오래된 스냅샷은 230번(08-17 09:00)이다.
--   8일보다 오래된 구간은 자동 퍼지로 이미 사라진 상태다.

--------------------------------------------------------------------------------
-- [2] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: "지난달 그 시간대 보고서를 만들자"며 옛 구간을 지정하니 없다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT COUNT(*) FROM dba_hist_snapshot
  2       WHERE begin_interval_time <
  3             TO_DATE('2026-08-10 00:00','YYYY-MM-DD HH24:MI');

  COUNT(*)
----------
         0        -- ← 08-10 이전 스냅샷이 하나도 없다

SYS@orcl> -- 원인 파악: 오늘(08-25) 기준 8일 보존이면 08-17 이전은 자동 퍼지 대상.
SYS@orcl> --   "AWR이 고장났다"가 아니라 "보존 초과로 정상 삭제"된 것이다.
SYS@orcl> -- 조치: 앞으로 반드시 남길 구간은 사라지기 전에 베이스라인으로 보호한다.
SYS@orcl> --   여기서는 사고 구간이라 가정한 295~296을 즉시 얼려 둔다.
SYS@orcl> EXEC DBMS_WORKLOAD_REPOSITORY.CREATE_BASELINE(295,296,'INCIDENT_0825');

PL/SQL procedure successfully completed.

SYS@orcl> -- 재확인: 보호가 걸렸는지 본다.
SYS@orcl> SELECT baseline_name, start_snap_id, end_snap_id
  2       FROM dba_hist_baseline WHERE baseline_name='INCIDENT_0825';

BASELINE_NAME    START_SNAP_ID END_SNAP_ID
---------------  ------------- -----------
INCIDENT_0825              295         296

--------------------------------------------------------------------------------
-- [3] (검증) 보호된 스냅샷은 수동 퍼지로도 지워지지 않음을 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> BEGIN
  2    DBMS_WORKLOAD_REPOSITORY.DROP_SNAPSHOT_RANGE(295,296);
  3  END;
  4  /

PL/SQL procedure successfully completed.

SYS@orcl> -- 명령은 성공했지만, 베이스라인에 묶인 스냅샷은 남아야 한다.
SYS@orcl> SELECT COUNT(*) FROM dba_hist_snapshot WHERE snap_id IN (295,296);

  COUNT(*)
----------
         2        -- ← 여전히 2건. 베이스라인이 보호했다

-- 해석: DROP_SNAPSHOT_RANGE가 "실패"한 게 아니다. 베이스라인 보호로 인해
--   해당 구간이 삭제 대상에서 제외된 것이 정상 동작이다.

--------------------------------------------------------------------------------
-- [4] (조치 후 상태 → 원복) 실습 후 보호를 해제한다(스냅샷은 보존).
--------------------------------------------------------------------------------
SYS@orcl> BEGIN
  2    DBMS_WORKLOAD_REPOSITORY.DROP_BASELINE('INCIDENT_0825', FALSE);
  3  END;
  4  /

PL/SQL procedure successfully completed.

SYS@orcl> SELECT COUNT(*) FROM dba_hist_baseline WHERE baseline_name='INCIDENT_0825';

  COUNT(*)
----------
         0

-- 재확인: 보호 해제 완료. 이제 이 구간은 다시 보존 규칙(8일)을 따른다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 보존 기간이 지난 스냅샷은 자동 퍼지된다(버그 아님, 설계다).
-- 2) "옛 구간 데이터가 없다" → 보존·최고령 스냅샷부터 확인(소실은 예정된 동작).
-- 3) 반드시 남길 구간(정상 기준·사고 구간)은 사라지기 전에 CREATE_BASELINE.
-- 4) 베이스라인 스냅샷은 DROP_SNAPSHOT_RANGE로도 안 지워진다(보호=삭제 면제).
-- 5) 라이선스 미보유 시: 베이스라인이 없으므로 보존을 늘리고 Statspack은
--    sppurge 정책으로 필요한 구간을 남긴다.

SYS@orcl> EXIT
