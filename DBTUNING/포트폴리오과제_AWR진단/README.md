# AWR 진단 포트폴리오 과제

DBTUNING 과정 ch20~ch25(AWR·ASH·ADDM)를 마친 수강생이 취업 서류에 쓸 수 있는
진단 보고서를 만드는 과제다. 수료 후 개인 과제이고 성적에 들어가지 않는다.

장애 하나를 재현하고, AWR 로 원인을 찾고, 조치하고, 같은 방법으로 다시 재서
보고서 한 편을 쓴다. 되돌리기까지가 과제에 포함된다.

## 스크립트

| 스크립트 | 접속 | 하는 일 |
|---|---|---|
| `PF_00_환경점검.sql` | SYS | 측정 환경 기록. 기준과 어긋난 것을 보고 |
| `PF_10_시나리오주입.sql` | SYS | 환경 결함(C·D·H) 주입과 원복. **강사용** |
| `PF_11_부하패턴.sql` | SQLT | 부하 패턴(A·B·E·F·G·I·J) 실행 |
| `PF_20_측정보조.sql` | SYS | 구간 캡처와 AWR·ASH·ADDM·TOPSQL·DIFF |
| `PF_99_원복.sql` | SYS | PF_ 객체 제거와 기준 통계 복원 |

`PF_20` 의 명령은 아래와 같다. 인자는 항상 3개를 넘기고 빈 자리에는 하이픈을 넣는다.

```
SNAP   T0 -        구간 시작·끝 캡처 (AWR 스냅샷도 함께 만든다)
DELTA  T0 T1       전/후/델타 3열 + DB Time 분해 + AAS
TOPSQL T0 T1       구간 상위 SQL + 리터럴로 쪼개진 SQL 묶음
AWR    T0 T1       AWR 보고서 본문
ASH    T0 T1       ASH 보고서 본문
ADDM   T0 T1       ADDM 분석과 보고서
DIFF   A0:A1 B0:B1 두 구간 나란히 (Compare Periods)
LIST   -  -        잡아 둔 태그 목록
CLEAR  T0 -        캡처 삭제
```

## 카드 10종

| 카드 | 결함 | 실측 |
|---|---|---|
| A | 리터럴 SQL 폭주 | 2,000번 17.15초, 하드 파싱 98.6%, 커서 1,323개 잔존 |
| B | 행별 커밋 | 0.42초 vs 0.03초 (14배) |
| C | 히스토그램 삭제 | E-Rows 3,506→300 (A-Rows 3,058, 10.2배 과소) |
| D | 표현식 통계 부재 | E-Rows 3,000 vs A-Rows 24,655 → 조치 후 일치 |
| E | 인덱스 부재 | 회당 버퍼 3,090→3 (1,026배) |
| F | 행 잠금 경쟁 | 44.18초 대기, `enq: TX - row lock contention` |
| G | 작업 영역 축소 | 임시 I/O 12,627 블록 |
| H | 리소스 관리자 제한 | 플랜·그룹·매핑 생성과 삭제 |
| I | 호출 횟수 폭주 | 30,000번 0.16초 vs 조인 0.01초 (16배) |
| J | 짧은 폭주 | 조용 3초 / 폭주 3.88초 / 조용 3초 |

전부 2026-10-14 에 실습 VM 에서 측정한 값이다. 카드별 상세와 AWR 에서 볼 자리는
각 스크립트의 카드 블록 주석에 있다.

C·D·H 는 환경 결함이라 강사가 미리 걸어 둔다. 나머지 일곱 장은 부하 자체가
결함이므로 수강생이 직접 돌린다.

## 시작하기

```sql
-- 1. 환경 기록
SQL> CONNECT / AS SYSDBA
SQL> SPOOL 01_근거/00_환경점검.log
SQL> @PF_00_환경점검.sql
SQL> SPOOL OFF

-- 2. 구간 잡고 부하 (SYS 창과 SQLT 창을 따로 열어 둔다)
[SYS]  @PF_20_측정보조.sql SNAP T0 -
[SQLT] @PF_11_부하패턴.sql E 2000
[SYS]  @PF_20_측정보조.sql SNAP T1 -

-- 3. 읽기
[SYS]  @PF_20_측정보조.sql DELTA  T0 T1
[SYS]  @PF_20_측정보조.sql TOPSQL T0 T1
[SYS]  SPOOL 01_근거/AWR_T0_T1.txt
[SYS]  @PF_20_측정보조.sql AWR T0 T1
[SYS]  SPOOL OFF

-- 4. 조치하고 같은 길이 구간에서 다시 측정

-- 5. 원복
[SYS]  SPOOL 01_근거/99_원복.log
[SYS]  @PF_99_원복.sql
[SYS]  SPOOL OFF
```

## 반드시 지킬 것

- 보고서 표지와 1장에 **"개인 실습 VM 재현 사례"** 를 적는다. 운영 실적이 아니다
- 진료비청구심사 7개 표에 INSERT·UPDATE·DELETE 를 하지 않는다. 쓰기는 `PF_` 복제표에만
- 만드는 객체 이름은 `PF_` 로 시작한다. 그러지 않으면 원복 스크립트가 못 지운다
- 남의 객체를 지우지 않는다. 기준과 달라도 '수동확인' 으로 적어 두기만 한다
- `ALTER SYSTEM` 은 카드 H 에서만 쓴다. 끝나면 반드시 되돌린다
- 측정 환경의 한계를 숨기지 않는다. 밝히는 것이 가점이다
