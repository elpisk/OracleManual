================================================================================
 10장 실습 01 — V$ACTIVE_SESSION_HISTORY 구조와 샘플링 주기 확인
 목표: 메모리 ASH의 구조(주요 컬럼)와 1초 샘플링 주기, '활성 세션만 담는다'는
       원리를 실측으로 확인한다. samples를 실행 횟수로 오해하는 이상 징후를
       재현하고, 그 원인과 올바른 해석법을 익힌다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 라이선스: 🔒 Diagnostics Pack 필요. 미보유 시 대안은 실습 후반 [7] 참조.
 주의: 개인 실습 환경 전용. 이 실습은 읽기 전용 조회만 수행한다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 라이선스 경계부터 확인한다. ASH는 Diagnostics Pack이다.
--     파라미터가 기능을 허용하는지 본다(값이 라이선스 보유 증명은 아님).
--------------------------------------------------------------------------------
SYS@orcl> SHOW PARAMETER control_management_pack_access

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
control_management_pack_access       string      DIAGNOSTIC+TUNING

-- 해석: DIAGNOSTIC 이상이므로 ASH 관련 기능이 동작한다. 이 값은 '기능 켜짐'을
--   뜻할 뿐, 계약상 라이선스를 보유했다는 증명은 아니다(1장 라이선스 절 참조).

--------------------------------------------------------------------------------
-- [2] (조회) V$ACTIVE_SESSION_HISTORY의 구조 — 한 행 = 한 세션의 1초 샘플.
--------------------------------------------------------------------------------
SYS@orcl> SELECT column_name, data_type
  2       FROM  dba_tab_columns
  3       WHERE table_name='V_$ACTIVE_SESSION_HISTORY'
  4         AND column_name IN ('SAMPLE_TIME','SESSION_ID','SESSION_SERIAL#',
  5              'SESSION_STATE','EVENT','SQL_ID','BLOCKING_SESSION')
  6       ORDER BY column_name;

COLUMN_NAME              DATA_TYPE
------------------------ ------------------------------
BLOCKING_SESSION         NUMBER
EVENT                    VARCHAR2
SAMPLE_TIME              TIMESTAMP(3)
SESSION_ID               NUMBER
SESSION_SERIAL#          NUMBER
SESSION_STATE            VARCHAR2
SQL_ID                   VARCHAR2

-- 해석: SESSION_STATE(ON CPU/WAITING)가 진단의 첫 갈림길이다. ON CPU면 EVENT가
--   NULL, WAITING이면 EVENT에 무엇을 기다렸는지가 담긴다.

--------------------------------------------------------------------------------
-- [3] (조회) 샘플링 주기 확인 — 최근 샘플의 SAMPLE_TIME 간격을 본다.
--     인접 샘플 시각의 차이가 약 1초임을 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT DISTINCT sample_time
  2       FROM  v$active_session_history
  3       WHERE sample_time > SYSTIMESTAMP - INTERVAL '6' SECOND
  4       ORDER BY sample_time;

SAMPLE_TIME
---------------------------------
25-AUG-26 12.16.55.121
25-AUG-26 12.16.56.123
25-AUG-26 12.16.57.121
25-AUG-26 12.16.58.123
25-AUG-26 12.16.59.121

-- 해석: 서로 다른 샘플 시각이 약 1초 간격으로 찍힌다. ASH의 기본 샘플링 주기가
--   1초임을 눈으로 확인한 것이다.

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 파악 → 조치 → 재확인)
--     이상 징후: 어떤 SQL_ID의 samples가 186으로 크게 나오자, 옆자리 동료가
--       "이 SQL이 186번 실행됐다"고 단정한다. 정말 그런지 검증한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT sql_id, COUNT(*) AS samples
  2       FROM  v$active_session_history
  3       WHERE sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  4         AND sql_id IS NOT NULL
  5       GROUP BY sql_id ORDER BY samples DESC FETCH FIRST 1 ROWS ONLY;

SQL_ID          SAMPLES
------------- ----------
9vmszgd1ft9x0        186

SYS@orcl> -- 원인 파악: samples는 '실행 횟수'가 아니라 '1초 샘플에 수행 중으로
SYS@orcl> --   포착된 수'다. 실제 실행 횟수는 V$SQL.EXECUTIONS로 확인해야 한다.
SYS@orcl> SELECT executions FROM v$sql WHERE sql_id='9vmszgd1ft9x0'
  2         AND rownum=1;

EXECUTIONS
----------
   <환경값>

-- 원인 확정: samples(186)와 executions(<환경값>)는 서로 다른 값이다. 만약
--   이 SQL이 1회 실행에 오래 걸렸다면 executions가 작아도 samples는 클 수 있다.
--   즉 samples는 '소비 시간(DB Time)'의 근사이지 실행 횟수가 아니다.
-- 조치: 'samples 큰 SQL = 시간을 많이 쓴 대상'으로만 받아들이고, 실행 횟수·
--   1회당 비용(buffer_gets)은 V$SQL로 따로 확인해 튜닝 방향을 정한다.

SYS@orcl> -- 재확인: 같은 SQL의 1회당 논리 읽기를 V$SQL로 본다(횟수·비용 분리).
SYS@orcl> SELECT executions, buffer_gets,
  2         ROUND(buffer_gets/NULLIF(executions,0)) AS gets_per_exec
  3       FROM  v$sql WHERE sql_id='9vmszgd1ft9x0' AND rownum=1;

EXECUTIONS  BUFFER_GETS  GETS_PER_EXEC
----------- ------------ --------------
   <환경값>      <환경값>          <환경값>

-- 재확인 완료: ASH는 시간을, V$SQL은 횟수를 센다. 두 값을 겹쳐 읽어야 한다.

--------------------------------------------------------------------------------
-- [5] (조회) '활성 세션만' 담는다 — Idle은 빠진다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT session_state, COUNT(*) AS samples
  2       FROM  v$active_session_history
  3       WHERE sample_time > SYSTIMESTAMP - INTERVAL '130' SECOND
  4       GROUP BY session_state ORDER BY samples DESC;

SESSION_STATE   SAMPLES
--------------- ----------
ON CPU               529
WAITING               54

-- 해석: 담긴 것은 모두 활성 세션이다. Idle(SQL*Net message from client 등)
--   세션은 아예 샘플에 없다. 그래서 ASH 크기는 작업량에 비례한다.

--------------------------------------------------------------------------------
-- [6] (정리)
--------------------------------------------------------------------------------
-- 1) V$ACTIVE_SESSION_HISTORY 한 행 = 한 세션의 1초 샘플. SESSION_STATE가 핵심.
-- 2) 샘플링 주기는 기본 1초임을 SAMPLE_TIME 간격으로 확인했다.
-- 3) samples는 실행 횟수가 아니라 소비 시간의 근사다(대표 오판 교정).
-- 4) ASH는 활성 세션만 담아 크기가 작업량에 비례한다.

--------------------------------------------------------------------------------
-- [7] (라이선스 대안 경로) Diagnostics Pack이 없다면 — V$SESSION 폴링.
--------------------------------------------------------------------------------
SYS@orcl> -- V$SESSION은 라이선스 없이 조회 가능하다. '지금 활성 세션'을 본다.
SYS@orcl> SELECT NVL(event,'ON CPU') AS event, COUNT(*) AS active_now
  2       FROM  v$session
  3       WHERE status='ACTIVE' AND wait_class <> 'Idle'
  4       GROUP BY NVL(event,'ON CPU') ORDER BY active_now DESC;

EVENT                             ACTIVE_NOW
--------------------------------- ----------
ON CPU                                     5
log file sync                              1

-- 대안 해석: 이 조회를 1초마다 반복해 테이블에 적재하면 '수제 ASH'가 된다.
--   wait_class<>'Idle' 조건이 ASH의 '활성 세션만' 규칙을 재현한다. 다만
--   V$SESSION은 현재 순간만 보여줘 폴링을 멈추면 과거는 사라진다는 한계가 있다.

SYS@orcl> EXIT
