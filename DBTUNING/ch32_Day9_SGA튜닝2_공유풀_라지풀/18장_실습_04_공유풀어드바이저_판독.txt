================================================================================
 18장 실습 04 — 공유 풀 어드바이저(V$SHARED_POOL_ADVICE) 판독
 목표: 여러 가상 크기에서의 파싱 절약 효과(estd_lc_time_saved_factor)를 읽고,
       곡선의 '무릎(knee)'을 찾아 크기 확대가 유효한지 판정한다. ORA-04031
       대응에서 '크기로 풀 문제인가'를 가르는 관문으로 쓴다.
 환경: non-CDB=orcl 19.3, ASMM. SYS로 수행. 조회 위주.
 주의: 개인 실습 환경 전용. V$SHARED_POOL_ADVICE는 라이선스와 무관한 뷰다.
       어드바이저가 채워지려면 STATISTICS_LEVEL이 TYPICAL 이상이어야 한다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 공유 풀 크기와 어드바이저 활성 여부 확인.
--------------------------------------------------------------------------------
SYS@orcl> SELECT ROUND(bytes/1024/1024,0) mb
  2       FROM v$sgainfo WHERE name='Shared Pool Size';

        MB
----------
  <환경값>

SYS@orcl> SHOW PARAMETER statistics_level
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
statistics_level                     string      TYPICAL

-- 해석: 현재 공유 풀 크기는 ASMM 자동 조정값(<환경값>), STATISTICS_LEVEL=TYPICAL →
--   어드바이저가 채워진다.

--------------------------------------------------------------------------------
-- [2] (조회) 공유 풀 어드바이저 — 크기별 파싱 절약 효과.
--------------------------------------------------------------------------------
SYS@orcl> SELECT ROUND(shared_pool_size_for_estimate,0) sp_mb,
  2         shared_pool_size_factor factor,
  3         estd_lc_time_saved_factor saved
  4       FROM  v$shared_pool_advice
  5       ORDER BY shared_pool_size_for_estimate;

    SP_MB   FACTOR    SAVED
--------- -------- --------
  <환경값>  <1.0     <1.0     -- 현재보다 작은 크기: SAVED가 1 미만(줄이면 파싱 절약 급락)
  <환경값>  1.0000   1.0000   <-- 현재(size_factor=1.0)
  <환경값>  >1.0     1.0000   -- 현재보다 큰 크기: SAVED가 계속 1.0(키워도 이득 없음)
  <환경값>  >1.0     ~1.0     -- 아주 큰 크기에서도 거의 평평
  ...       ...      ...

-- 해석(읽는 법): SAVED(estd_lc_time_saved_factor)는 '현재 대비 파싱 절약 배율'이다.
--   · 현재보다 작은 크기에서 SAVED가 1 미만으로 급락하면 → 지금 크기가 이 부하에 '필요'.
--   · 현재보다 큰 크기에서 SAVED가 계속 1.0(평평)이면 → 키워도 파싱이 더 안 줄어 '확대 무효'.
-- 결론(전형): 이 랩처럼 확대 구간이 평평하면 곡선의 무릎이 현재 크기 부근이라는 뜻 —
--   줄이면 손해, 늘려도 이득 없음 → '크기로 풀 문제가 아니다'를 어드바이저가 증명한다.
--   (구체적 크기·배율은 현재 풀 크기·워크로드에 따라 <환경값>.)

--------------------------------------------------------------------------------
-- [3] (해석) saved_factor를 풀어 읽는다.
--------------------------------------------------------------------------------
-- estd_lc_time_saved_factor = 해당 크기에서 라이브러리 캐시가 '파싱을 재사용으로
--   절약한 시간'을 현재 대비로 나타낸 배율.
--   · 1.0보다 작으면 절약 감소(파싱 증가) = 손해
--   · 1.0이면 현재 수준
--   · 1.0보다 크면 절약 증가(파싱 감소) = 이득
-- 확대 구간이 계속 1.0이라는 것은 '더 줄 파싱이 없다'는 뜻이다. 못 아끼는
--   파싱은 크기가 아니라 리터럴 때문이라는 결정적 단서다(실습 01·02와 일치).

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 다른 실습 인스턴스에서 같은 쿼리가 '행이 선택되지 않았습니다'.
--       어드바이저 표가 비어 있다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT COUNT(*) FROM v$shared_pool_advice;

  COUNT(*)
----------
         0

SYS@orcl> -- 원인을 찾는다: 어드바이저는 STATISTICS_LEVEL에 의존한다.
SYS@orcl> SHOW PARAMETER statistics_level
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
statistics_level                     string      BASIC

-- 원인: STATISTICS_LEVEL=BASIC이면 어드바이저 통계 수집이 꺼져 있어
--   V$SHARED_POOL_ADVICE가 채워지지 않는다(빈 표).
-- 조치: TYPICAL 이상으로 올린다(개인 환경 전용, 시스템 파라미터 변경).
SYS@orcl> ALTER SYSTEM SET statistics_level=TYPICAL;
System altered.

SYS@orcl> -- 잠시 부하가 돈 뒤 어드바이저가 채워졌는지 재확인.
SYS@orcl> SELECT COUNT(*) rows_now FROM v$shared_pool_advice;

  ROWS_NOW
----------
        <환경값>   -- (0이 아니면 어드바이저 활성화 성공)

-- 재확인: TYPICAL로 올린 뒤 표가 채워졌다. 어드바이저가 안 보이면 크기부터
--   의심하지 말고 STATISTICS_LEVEL을 먼저 확인한다.

--------------------------------------------------------------------------------
-- [5] (판정) ORA-04031을 만났다고 가정하고 이 표로 방향을 정한다.
--------------------------------------------------------------------------------
-- · 확대 곡선이 '가파른' 구간(무릎 이전)이면 → 크기 확대가 유효.
-- · 확대 곡선이 '평평'하면(이 실측) → 크기 확대는 임시 봉합. 답은 파싱 제거
--   (바인드 변수 / CURSOR_SHARING). 실습 05의 ORA-04031 해소로 이어진다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 무릎은 대개 현재 크기 부근: 축소하면 SAVED 급락, 확대하면 SAVED 평평(값은 <환경값>).
-- 2) saved_factor는 '현재 대비 파싱 절약 배율'. 확대 평평 = 더 줄 파싱 없음.
-- 3) 이상 흐름: 어드바이저 빈 표 → STATISTICS_LEVEL=BASIC이 원인 → TYPICAL로 해소.
-- 4) 이 표는 ORA-04031 대응의 관문: 확대 유효성 판정 → 평평하면 파싱 제거로 전환.
-- ※ 라이선스: V$SHARED_POOL_ADVICE·V$SGAINFO 무관. 이력은 DBA_HIST_SHARED_POOL_
--    ADVICE(🔒) 또는 위 V$를 두 시점에 직접 조회.

SYS@orcl> EXIT
