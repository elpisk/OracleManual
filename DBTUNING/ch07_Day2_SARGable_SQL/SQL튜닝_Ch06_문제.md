# Chapter 6. SARGable SQL — 실습문제 10제

`SQL튜닝_Ch06_교안.md`를 먼저 읽고 푸시기 바랍니다. 모든 결과는 실습 DB 실측입니다.
실습에서 만든 인덱스는 각자 실습 종료 시 반드시 `DROP INDEX`로 정리하시오.

---

**1. [상]** `BIRTH_DATE`에 인덱스가 있는 상태에서 `WHERE birth_date <= '19901231'`
(Buffers 148)과 `WHERE birth_date <= 19901231`(Buffers 442)은 작은따옴표 유무만 다른데
실행계획이 다르다. `Predicate Information`에서 두 쿼리의 차이를 근거로 원인을 설명하시오.

**2. [최상]** 2번(Q2) 쿼리의 `Predicate Information`은
`filter(TO_NUMBER("BIRTH_DATE")<=19901231)`로 나타난다. 개발자는 `TO_NUMBER`를 SQL
어디에도 직접 쓰지 않았는데 왜 이 함수가 나타났는지, `BIRTH_DATE`의 데이터 타입
(VARCHAR2)과 `19901231`의 데이터 타입(NUMBER)을 근거로 설명하시오.

**3. [상]** Q2(묵시적 형변환)와 Q3(`TO_NUMBER(SUBSTR(birth_date,1,4))`, 명시적 함수)의
실행계획(Plan hash value)이 완전히 동일했다. 개발자가 명시적으로 함수를 쓴 것과, 타입을
잘못 맞춰서 묵시적으로 함수가 생긴 것이 옵티마이저 입장에서 왜 같은 문제로 취급되는지
설명하시오.

**4. [상]** `RECEIPT_DATE`에 인덱스가 있는 상태에서 `TO_CHAR(receipt_date,'YYYYMM') =
'202406'`(Buffers 3,090)을 `receipt_date >= DATE'2024-06-01' AND receipt_date <
DATE'2024-07-01'`(Buffers 68)로 바꾸면 결과는 같은데 Buffers가 45배 이상 차이 난다. 두
조건이 논리적으로 같은 결과를 내는데도 이런 차이가 나는 이유를 설명하시오.

**5. [상]** "이번 달 데이터를 조회하자"는 요구사항을 받은 개발자가 `TO_CHAR(receipt_date,
'YYYYMM') = TO_CHAR(SYSDATE,'YYYYMM')`처럼 작성했다. 이 코드가 왜 문제가 될 수 있는지,
그리고 어떻게 바꿔야 SARGable해지는지 4번 문항을 참고해 다시 작성하시오.

**6. [최상]** `WHERE birth_date <= 19901231`(형변환 발생)와 `WHERE birth_date <=
'19901231'`(형변환 없음)의 실제 결과 건수는 둘 다 37,425건으로 동일했다. "결과가 똑같이
나오니 성능 차이는 무시해도 된다"는 주장에 대해, 이 컬럼이 훨씬 큰 테이블(예: 수백만 건)의
일부였다면 어떻게 달라질지를 근거로 반박하시오.

**7. [상]** 교안 07절은 `LIKE '%검색어%'`(앞에 `%`가 붙는 패턴)가 일반 인덱스로 지원되지
않는다고 설명한다. `LIKE '검색어%'`(뒤에만 `%`가 붙는 패턴)는 일반 B-Tree 인덱스로 지원될
수 있는지, 인덱스가 값의 정렬 순서를 활용한다는 원리(교안 03절, Chapter 5)를 근거로
추론하시오.

**8. [상]** 부정 조건(`!=`, `NOT IN`)과 `IS NULL` 조건이 왜 일반 B-Tree 인덱스와 궁합이
나쁜지 각각 설명하시오.

**9. [최상]** 코드 리뷰에서 다음 두 조건절 중 어느 쪽이 SARGable한지 판단하고 이유를
설명하시오.
   - (a) `WHERE hosp_id || '' = '100'`
   - (b) `WHERE hosp_id = 100`
   (힌트: `HOSP_ID`는 `NUMBER` 컬럼이다. `||`는 문자열 결합 연산자다.)

**10. [최상]** 이번 챕터에서 배운 원칙을 적용해, `PATIENTS.BIRTH_DATE`(VARCHAR2 YYYYMMDD)
에서 "1990년대생 환자"를 조회하는 SARGable한 조건절을 작성하시오. `BETWEEN`을 쓰는 방법과
범위 비교(`>=`/`<`)를 쓰는 방법 두 가지로 작성하고, 둘 다 함수를 쓰지 않고 인덱스를 탈 수
있는 이유를 설명하시오.
