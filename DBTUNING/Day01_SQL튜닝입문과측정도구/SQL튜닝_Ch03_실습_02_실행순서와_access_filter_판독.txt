 목표: 조인 + GROUP BY 계획을 놓고 "Id 순서로 읽어 실행 순서를 거꾸로 해석하는" 오판을
       재현한 뒤 들여쓰기 규칙으로 교정한다. 같은 hosp_id<=10 조건이 한 표에서는 access,
       다른 표에서는 filter 로 나타나는 이유(인덱스 유무)를 Predicate Information 으로 확인한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT.
 주의: 개인 실습 환경 전용. 조회만 수행한다.

SQLT@orcl> --         (3) 자식이 끝나야 부모가 완성된다.

SQLT@orcl> --   Id 4 INDEX RANGE SCAN PK_HOSPITALS (hosp_id<=10 로 10건의 ROWID)
SQLT@orcl> --   → Id 3 그 ROWID 로 HOSPITALS 10행 (hosp_type 확보)           ← 해시 테이블(build) 쪽
SQLT@orcl> --   → Id 5 MEDICAL_CLAIMS Full Scan, 읽으며 hosp_id<=10 필터    ← probe 쪽
SQLT@orcl> --   → Id 2 HASH JOIN: probe 각 행을 build 해시에서 찾아 결합(292행 추정)
SQLT@orcl> --   → Id 1 HASH GROUP BY hosp_type → Id 0 반환

--   부모의 Buffers 는 자식들의 합이므로 "자식이 먼저 실행돼 부모에 올라간다" 는 방향이 숫자로 보인다.
--   E-Rows 292 vs A-Rows 29,786: 조인 결과는 100배 과소 추정이다. Id 5 의 단독 추정(29,128)은 히스토그램
--   덕에 정확한데, 조인 카디널리티 계산에서 HOSPITALS 10행 × 평균 청구 수(300)로 줄여 버렸다 —
--   "쏠린 병원 1~10" 이 조인 뒤에도 쏠려 있다는 것까지는 모른다(Ch13).

--------------------------------------------------------------------------------
-- [3] (판독) 같은 조건이 왜 한쪽은 access, 다른 쪽은 filter 인가
--------------------------------------------------------------------------------
-- Predicate Information 을 다시 본다.
--   4 - access("H"."HOSP_ID"<=10)   ← HOSPITALS: PK_HOSPITALS 인덱스로 "찾아간다"
--   5 - filter("M"."HOSP_ID"<=10)   ← MEDICAL_CLAIMS: 인덱스가 없어 다 읽고 "걸러낸다"
--   2 - access("H"."HOSP_ID"="M"."HOSP_ID") ← 조인 조건은 해시 탐색 키이므로 access
--
-- 같은 hosp_id<=10 인데 표마다 다른 이유는 인덱스 유무 하나다. 이 조건은 옵티마이저가 조인
-- 조건(h.hosp_id = m.hosp_id)을 통해 M 쪽으로 옮겨 적은 것(transitive predicate)이며,
-- M 에 인덱스가 생기면 5번도 access 로 바뀐다 — Ch07 실습 03 에서 실제로 확인한다.
--
-- 판독 요령: "이 조건이 인덱스를 타는가?" 는 계획의 Operation 이름이 아니라 Predicate 의
-- access/filter 로 판정한다. INDEX RANGE SCAN 아래에 filter 만 있으면 인덱스를 읽되 조건은
-- 못 쓴 것이다(Ch05 실습 02 의 후행 컬럼 사례).

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 실행 순서 = 들여쓰기 깊은 것부터, 같은 깊이면 위쪽부터. Id 번호 순서가 아니다.
-- 2) 부모 Buffers = 자식 Buffers 의 합. 이 합산 방향이 실행 방향의 증거다.
-- 3) access = 찾아가는 조건(인덱스·해시 키), filter = 읽은 뒤 걸러내는 조건.
--    같은 조건도 인덱스가 있으면 access, 없으면 filter.
-- 4) 조인 조건을 통해 옮겨진 조건(transitive)이 상대 표에 filter 로 붙는다.
