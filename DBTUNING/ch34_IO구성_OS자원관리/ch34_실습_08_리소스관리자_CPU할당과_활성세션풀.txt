================================================================================
 ch34 실습 08 — 리소스 관리자: CPU 할당과 활성 세션 풀 (PTW_RSRC_MGR 교재 실측)
 목표: 소비자 그룹 → 리소스 플랜 → 플랜 지시어 → 사용자 매핑 순으로 리소스 관리자를
       구성하고, EMPHASIS 와 RATIO 두 CPU 할당 방식의 차이를 확인한다. 그리고
       교재가 다루지 않는 마지막 한 걸음 — "플랜을 켜서 실제로 작동시키는 것" 까지
       해서, 활성 세션 풀이 세션을 큐에 넣고 타임아웃으로 끊는 것을 눈으로 본다.
 환경: non-CDB=orcl 19.3.0.0, SYS AS SYSDBA + SQLT. CPU 4개.
       리소스 관리자는 Enterprise Edition 기본 기능이다(별도 팩 라이선스 불필요).
 전제: 교재 `PTW_RSRC_MGR.pdf` 의 세 절(기본 설정 / RATIO 방식 / 활성 세션 풀)을
       그대로 실행해 보고, 19c 에서 실제로 어떻게 되는지 확인한다.
       교재 명령 중 이 버전에서 그대로 통하지 않는 것이 네 군데 있다 — 아래에서
       오류 원문과 함께 다룬다.
 주의: ★ 개인 실습 환경 전용 ★  RESOURCE_MANAGER_PLAN 은 인스턴스 전체에 걸린다.
       플랜을 켜면 그 순간부터 모든 세션의 CPU 와 동시 세션 수가 제한된다.
       시작 전 현재 값을 반드시 적어 두고, 끝나면 [9] 로 원복한다.
       2026-10-13 실측. 모든 출력은 그날 세션의 것이다.

-- 1) 구성 순서는 **소비자 그룹 → 플랜 → 지시어 → 권한 → 매핑 → 플랜 활성화** 다.
--    마지막 한 단계(ALTER SYSTEM SET resource_manager_plan)를 빼면 아무 일도
--    일어나지 않는다. V$RSRC_PLAN.CPU_MANAGED 가 ON 인지로 확인한다.
--
-- 2) 모든 변경은 Pending Area 를 거친다. 개별 호출은 통과해도 **SUBMIT 에서 검증**된다.
--    VALIDATE_PENDING_AREA 를 SUBMIT 앞에 습관처럼 둔다.
--      ORA-29377  최상위 플랜에 OTHER_GROUPS 지시어가 없다
--      ORA-29375  EMPHASIS 에서 레벨 합이 100 을 넘었다
--
-- 3) EMPHASIS 와 RATIO 는 같은 MGMT_P1 컬럼을 다르게 해석한다.
--      EMPHASIS  레벨별 백분율, 레벨마다 합 100 이하, 남은 몫은 다음 레벨로
--      RATIO     상대 가중치, 합계 제한 없음, 레벨 1 만 사용 (4:3:2:1 → 40/30/20/10%)
--    남의 플랜을 읽을 때 DBA_RSRC_PLANS.MGMT_METHOD 를 먼저 본다.
--    (MGMT_MTH 는 프로시저 파라미터 이름이고 뷰 컬럼이 아니다 — ORA-00904)
--
-- 4) Oracle 공급 객체와 이름이 겹치면 못 만든다(ORA-29357). BATCH_GROUP·DSS_GROUP·
--    LOW_GROUP·INTERACTIVE_GROUP·ETL_GROUP·DSS_CRITICAL_GROUP 은 이미 있다.
--    조직 약어를 접두로 붙인다.
--
-- 5) MANDATORY='YES' 는 "삭제 불가" 일 뿐 "수정 불가" 가 아니다. DEFAULT_PLAN 에
--    지시어를 추가하는 것이 **된다** — 그래서 더 위험하다. 교재 3절을 그대로 따르면
--    Oracle 공급 플랜이 조용히 바뀐 채 남는다. 항상 자기 플랜에 건다.
--
-- 6) 활성 세션 풀은 "접속 수" 가 아니라 "동시에 실행 중인 세션 수" 제한이다.
--    넘치면 큐에 들어가고 대기 이벤트는 resmgr:become active,
--    V$SESSION.CURRENT_QUEUE_DURATION 으로 얼마나 기다리는지 보인다.
--    QUEUEING_P1 을 넘기면 ORA-07454 로 **업무가 실패한다**.
--    사이징 근거는 V$RSRC_CONSUMER_GROUP 의 네 값이다 —
--    ACTIVE_SESSION_LIMIT_HIT / QUEUED_TIME / QUEUE_TIME_OUTS / CONSUMED_CPU_TIME.
--
-- 7) SET_INITIAL_CONSUMER_GROUP 은 19c 에서도 동작하지만 비권장이다.
--    현행은 SET_CONSUMER_GROUP_MAPPING 이고, 사용자 말고도 서비스·모듈·프로그램으로
--    매핑할 수 있어 같은 계정의 배치와 온라인을 갈라 놓을 수 있다.
--    어느 쪽이든 GRANT_SWITCH_CONSUMER_GROUP 이 먼저다.
--
-- 8) 원복은 **플랜 끄기 → 사용자 권한·매핑 → DEFAULT_PLAN 지시어 → 플랜/그룹 삭제**
--    순서다. 활성 플랜은 삭제되지 않으므로 끄는 것이 맨 앞이다.
