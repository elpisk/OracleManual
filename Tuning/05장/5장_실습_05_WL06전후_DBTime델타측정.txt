================================================================================
 5장 실습 05 — WL_06_mixed.sql 전후 DB Time 증가분 측정 (델타 계산 방식)
 목표: 종합 부하 WL_06_mixed.sql 전후로 시간 모델·통계를 캡처해 DB Time 델타를
       계산하고, 초당·트랜잭션당 값(Load Profile 형식)으로 환산한다. 첫 측정이
       너무 짧아 분해가 불안정한 이상 징후를 재현하고 구간을 넓혀 교정한다.
 환경: non-CDB=orcl 19.3 (부하는 SQLT, 측정은 SQLT 자기 세션)
 참조: 공용 부하 스크립트  부하스크립트\WL_06_mixed.sql  (5·6·8·9·10·11장 공용)
 주의: 개인 실습 환경 전용. WL_06은 CPU·I/O·리두·임시 영역을 동시에 소모한다.
       공유 DB에서 실행하면 다른 업무 응답시간이 눈에 띄게 나빠진다.
================================================================================

$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> SET LINESIZE 200
SQLT@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 부하 직전(T0) 시간 모델·주요 통계 누적값을 캡처한다.
--------------------------------------------------------------------------------
SQLT@orcl> COLUMN stat_name FORMAT A26
SQLT@orcl> SELECT stat_name, value FROM v$sess_time_model
  2       WHERE sid = sys_context('USERENV','SID')
  3         AND stat_name IN ('DB time','DB CPU');       -- (T0 시간모델)

STAT_NAME                   VALUE
-------------------------- ----------
DB time                    <환경값>
DB CPU                     <환경값>

SQLT@orcl> SELECT name, value FROM v$mystat s JOIN v$statname n USING (statistic#)
  2       WHERE n.name IN ('session logical reads','physical reads',
  3              'user commits','parse count (hard)');    -- (T0 통계)

NAME                             VALUE
------------------------------ ----------
session logical reads          <환경값>
physical reads                 <환경값>
user commits                   <환경값>
parse count (hard)             <환경값>

--------------------------------------------------------------------------------
-- [2] (조치) 종합 부하를 실행한다. 첫 시도는 기본값(wl_cycles=3, 약 3~5분)이
--     아니라 아주 짧게(예: wl_cycles=1 미만 축약) 돌려 본다 — 이상 징후 재현용.
--------------------------------------------------------------------------------
SQLT@orcl> -- (짧은 부하: 약 0.3초 구간)  실습 02와 같은 축약 스캔 1회
SQLT@orcl> SELECT /*+ FULL(d) NO_PARALLEL(d) */ SUM(d.amt)
  2       FROM claim_details d WHERE d.qty >= 0;

  SUM(AMT)
----------
<환경값>

--------------------------------------------------------------------------------
-- [3] (결과) 부하 후(T1) 캡처 → 델타 = T1 - T0.
--------------------------------------------------------------------------------
-- 이번 짧은 구간의 시간 모델 델타(실측):
--   DB time 델타 : 275,636 us  (약 0.28초)
--   DB CPU  델타 : 297,047 us  (약 0.30초)
--   → DB time 대비 CPU 107.8% ,  대기 -7.8%   (음수?!)

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: DB CPU 델타가 DB time 델타보다 커서 대기가 -7.8%로 나온다.
--------------------------------------------------------------------------------
SQLT@orcl> -- 원인: 구간이 0.3초로 너무 짧아 카운터 갱신 시점 어긋남 + 반올림으로
SQLT@orcl> --   시간 모델의 CPU/대기 분해가 불안정해진 것. 버그가 아니다.
SQLT@orcl> -- 조치: 구간을 충분히(수 분) 넓혀 다시 잰다. WL_06의 wl_cycles를 올린다.
SQLT@orcl> --   10분 구간을 원하면 wl_cycles=8 정도. (부하스크립트\WL_06_mixed.sql)
SQLT@orcl> -- 예)  DEFINE wl_cycles = 8
SQLT@orcl> --      @WL_06_mixed.sql
SQLT@orcl> -- WL_06은 전후 델타와 초당·트랜잭션당 요약(Load Profile 형식)을 스스로 출력한다:
SQLT@orcl> --
SQLT@orcl> --   [Load Profile]  구간 <환경값> 초 / 트랜잭션 <환경값> 건
SQLT@orcl> --   항목                구간 합계        초당       트랜잭션당
SQLT@orcl> --   -----------------------------------------------------------
SQLT@orcl> --   DB Time (ms)        <환경값>       <환경값>     <환경값>
SQLT@orcl> --   DB CPU  (ms)        <환경값>       <환경값>     <환경값>
SQLT@orcl> --   Logical reads       <환경값>       <환경값>     <환경값>
SQLT@orcl> --   Physical reads      <환경값>       <환경값>     <환경값>
SQLT@orcl> --   Hard parses         <환경값>       <환경값>     <환경값>

SQLT@orcl> -- 재확인: 구간을 넓히면 'DB time 델타 - DB CPU 델타 ≈ 대기'가 양수로,
SQLT@orcl> --   대기 클래스 델타의 합과 앞뒤가 맞게 안정된다. 넓은 구간에서 대기가
SQLT@orcl> --   음수로 나오지 않는지 확인한다. (정확한 구간 관리는 6장 AWR로 이어진다.)

--------------------------------------------------------------------------------
-- [5] (조치 후 관점) 왜 초당·트랜잭션당으로 환산하나
--------------------------------------------------------------------------------
-- * 구간 길이가 다른 측정을 비교하려면 시간으로 정규화해야 한다 → 초당 값.
-- * 트랜잭션당 값은 '부하 증가(트랜잭션↑)'와 '트랜잭션이 무거워짐'을 구분해 준다(11장).
-- * 같은 부하라도 AWR 구간을 넓게 잡으면 초당 값이 낮게 나온다 — 구간이 수치를 좌우(8장).
-- * 단, 트랜잭션이 몇 건뿐이면 트랜잭션당 값은 대표성이 없다 — 원시 카운트로 검증.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 부하 전후 캡처 → 델타 = T1 - T0. 이것이 이 구간의 실제 부하다.
-- 2) 짧은 구간(0.3초)은 CPU/대기 분해가 불안정(실측 CPU 107.8%, 대기 -7.8%).
-- 3) 조치: wl_cycles를 올려 구간을 수 분으로 넓히면 델타가 안정된다.
-- 4) 델타는 초당·트랜잭션당으로 환산해 비교한다(Load Profile 형식).
-- ※ 이 실습의 V$ 조회는 라이선스가 필요 없다. AWR 스냅샷부터 🔒 Diagnostics Pack.
