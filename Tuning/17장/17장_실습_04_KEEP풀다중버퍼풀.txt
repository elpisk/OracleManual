================================================================================
 17장 실습 04 - 다중 버퍼 풀 구성 (KEEP 풀에 소형 참조 테이블 배치)
 목표: 소형 참조 테이블 DRUG_MASTER를 KEEP 풀에 배치하고 전체 스캔으로
       예열한 뒤, 풀별 히트율로 효과를 확인한다. '풀을 바꿨는데 그대로'인
       흔한 오해(즉시 이동 안 함)를 재현하고 예열로 해소한다.
 환경: non-CDB=orcl 19.3. 풀 지정은 SYS, 확인은 SYS/SQLT.
 주의: 개인 실습 환경 전용. ALTER TABLE은 개인 환경에서만 수행한다.
================================================================================

$ sqlplus / as sysdba

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) DRUG_MASTER가 현재 어느 풀에 지정돼 있는지 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT table_name, buffer_pool, blocks
  2       FROM  dba_tables
  3       WHERE owner='SQLT' AND table_name='DRUG_MASTER';

TABLE_NAME     BUFFER_POOL     BLOCKS
-------------- ----------- ----------
DRUG_MASTER    DEFAULT        <환경값>

-- 해석: 기본값 DEFAULT다. BLOCKS(통계 기준 블록 수)로 KEEP에 담길 크기를
--   가늠한다. KEEP 풀(48M)은 소형 참조 테이블 몇 개를 담기에 넉넉하다.

--------------------------------------------------------------------------------
-- [2] (조치) DRUG_MASTER를 KEEP 풀로 지정한다.
--------------------------------------------------------------------------------
SYS@orcl> ALTER TABLE sqlt.drug_master STORAGE (BUFFER_POOL KEEP);
Table altered.

SYS@orcl> SELECT buffer_pool FROM dba_tables
  2       WHERE owner='SQLT' AND table_name='DRUG_MASTER';
BUFFER_POOL
-----------
KEEP

-- 해석: 지정은 즉시 반영된다. 그러나 '이미 DEFAULT에 올라와 있던 블록'은
--   아직 KEEP으로 옮겨지지 않았다(다음 단계에서 확인).

--------------------------------------------------------------------------------
-- [3] (이상 징후 -> 원인 -> 조치 -> 재확인)
--     지정 직후 조회해도 KEEP 풀 사용이 기대만큼 안 보인다.
--------------------------------------------------------------------------------
SYS@orcl> -- 이상 징후: 풀은 KEEP인데, 기존 블록이 여전히 DEFAULT에 남아 있어
SYS@orcl> --   KEEP 풀 활동이 곧바로 늘지 않는다.
SYS@orcl> -- 원인: STORAGE 변경은 '새로 읽히거나 재적재되는 블록'부터 새 풀에
SYS@orcl> --   놓는다. 기존 블록은 즉시 이동하지 않는다.
SYS@orcl> -- 조치: 전체 스캔으로 블록을 KEEP 풀에 예열(warm-up)한다.
SYS@orcl> SELECT /*+ FULL(d) */ COUNT(*) FROM sqlt.drug_master d;

  COUNT(*)
----------
   <환경값>

SYS@orcl> -- 재확인: KEEP 풀 통계로 블록이 KEEP에 올라왔는지 본다.
SYS@orcl> SELECT name, set_msize buf_cnt,
  2         ROUND(100*(1-physical_reads/
  3               GREATEST(db_block_gets+consistent_gets,1)),2) hit_pct
  4       FROM  v$buffer_pool_statistics
  5       WHERE name='KEEP' AND set_msize>0;

NAME       BUF_CNT    HIT_PCT
-------- --------- ----------
KEEP          5874        100

-- 재확인 결과: KEEP 풀 히트율 100%. 예열 후 반복 조회는 미스 없이 처리된다.

--------------------------------------------------------------------------------
-- [4] (해석) KEEP 풀의 100%와 DEFAULT 풀의 100%는 의미가 다르다.
--------------------------------------------------------------------------------
-- * KEEP 풀 100%: 작고 자주 쓰는 참조 테이블만 담아 항상 적중 = 설계된 정상.
-- * DEFAULT 풀 99.98%: 반복 스캔으로 부풀려졌을 수 있다(실습 02 참조).
-- => 같은 100%라도 어느 풀인지에 따라 해석이 갈린다. 맥락이 중요하다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) STORAGE(BUFFER_POOL KEEP)로 소형 참조 테이블을 KEEP에 배치한다.
-- 2) 지정은 즉시지만 기존 블록은 안 옮겨진다 -> 전체 스캔으로 예열 필요.
-- 3) KEEP 풀 히트율 100%는 설계된 정상 결과다.
-- 4) 원복하려면 STORAGE(BUFFER_POOL DEFAULT)로 되돌린다.

SYS@orcl> EXIT
