================================================================================
 8장 실습 07 — 부하 없는 구간 보고서를 읽고 '문제 없음'을 근거와 함께 판정
 목표: 유휴 구간의 AWR 보고서를 읽고, 부하가 없어 판정 대상이 아님을 근거
       (AAS·DB Time)와 함께 명시한다. Idle 이벤트(SQL*Net message from client)를
       병목으로 오판하는 상황을 재현·교정한다. 부하 구간(295~296)과 대조한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA)
 대상 구간: 유휴 구간 스냅샷 293~294 (부하 없음) vs 부하 구간 295~296 (대조)
 라이선스: 🔒 Diagnostics Pack. 미보유 시 V$SYSMETRIC/V$SYS_TIME_MODEL로 대체(하단).
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 유휴 구간(293~294)으로 AWR 보고서를 생성한다.
--------------------------------------------------------------------------------
SYS@orcl> @$ORACLE_HOME/rdbms/admin/awrrpt.sql
Enter value for report_type: text
Enter value for num_days: 1
Enter value for begin_snap: 293
Enter value for end_snap: 294
Using the report name awrrpt_1_293_294.txt
Report written to awrrpt_1_293_294.txt

-- 293~294는 부하 없이 흘러간 유휴 구간이다.

--------------------------------------------------------------------------------
-- [2] (조회) 머리말에서 DB Time·Elapsed로 AAS를 계산한다 — 부하가 있었나?
--------------------------------------------------------------------------------
SYS@orcl> HOST grep -E "Elapsed:|DB Time:" awrrpt_1_293_294.txt

              Elapsed:               10.02 (mins)
              DB Time:                0.04 (mins)

SYS@orcl> SELECT ROUND(0.04/10.02,3) AS aas_idle FROM dual;

  AAS_IDLE
----------
      .004

-- 해석: AAS = DB Time/Elapsed = 0.04/10.02 ≈ 0.004. 평균 활성 세션이 사실상
--   0이다. 이 구간에는 '진단할 부하 자체가 없다.'

--------------------------------------------------------------------------------
-- [3] (조회) 그럼에도 Top Events는 채워져 나온다 — 무엇이 1위인가?
--------------------------------------------------------------------------------
SYS@orcl> HOST sed -n '/Top 10 Foreground/,+6p' awrrpt_1_293_294.txt

Top 10 Foreground Events by Total Wait Time
                                           Total Wait       Avg   % DB Wait
Event                                Waits Time (sec)      Wait   time Class
------------------------------ ----------- ---------- --------- ------ --------
SQL*Net message from client        <환경값>       <환경값>   <환경값>   <환경값> Idle
DB CPU                                          <환경값>       <환경값>
log file sync                        <환경값>       <환경값>   <환경값>   <환경값> Commit

-- 해석: 보고서는 유휴 구간에도 Top 10을 비워 두지 않고 가장 큰 것부터 채운다.
--   그래서 Idle 이벤트인 SQL*Net message from client가 1위로 올라온다. 순위는
--   상대적일 뿐 절대 크기를 말하지 않는다.

--------------------------------------------------------------------------------
-- [4] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 신입이 "SQL*Net message from client가 1위이니 네트워크가
--       병목이다"라고 판정했다.
--------------------------------------------------------------------------------
-- 원인 파악: 순위만 보고 부하 유무를 확인하지 않은 오판이다.
--   SQL*Net message from client는 클라이언트의 다음 요청을 기다리는 Idle
--   이벤트다 — DB가 일이 없어 노는 시간이지 병목이 아니다.
SYS@orcl> SELECT wait_class FROM v$event_name
  2       WHERE name='SQL*Net message from client';

WAIT_CLASS
--------------------
Idle

-- 원인 확정: 이 이벤트의 클래스가 Idle이다. % DB time으로 순위를 매기는 대상이
--   아니며, AAS 0.004는 애초에 부하가 없었음을 말한다.
-- 조치: '이 구간은 부하가 없어 성능 문제를 논할 대상이 아니다'를 근거(AAS
--   0.004, DB Time 0.04분)와 함께 기록한다. 네트워크 튜닝은 하지 않는다.
--   (신고 시각인데 DB가 한가했다면 병목은 DB 밖 → 20장으로 연결)
-- 재확인: 부하 구간(295~296)과 대조해 판정을 뒷받침한다(아래 [5]).

--------------------------------------------------------------------------------
-- [5] (조치 후 상태) 부하 구간(295~296)과 나란히 대조한다.
--------------------------------------------------------------------------------
SYS@orcl> HOST grep -E "Elapsed:|DB Time:" awrrpt_1_295_296.txt

              Elapsed:                1.70 (mins)
              DB Time:                9.57 (mins)

SYS@orcl> SELECT ROUND(9.57/1.70,2) AS aas_load FROM dual;

  AAS_LOAD
----------
      5.63

-- 해석: 부하 구간 AAS ≈ 5.63(=DB Time 574s/Elapsed 102s). 유휴 구간 0.004와
--   비교하면 차이가 1,400배가 넘는다. '문제 없음'과 '문제 있음'은 머리말의
--   AAS 한 줄로 갈린다. Top Events 순위를 보기 전에 반드시 AAS부터 확인한다.

--------------------------------------------------------------------------------
-- [대안 경로] 🔒 미보유 — V$로 부하 유무를 판정한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT ROUND(value,3) aas
  2       FROM  v$sysmetric
  3       WHERE metric_name='Average Active Sessions'
  4         AND intsize_csec BETWEEN 5900 AND 6100;

       AAS
----------
   <환경값>

-- 해석: V$SYSMETRIC의 Average Active Sessions로 현재 부하 유무를 즉시 본다.
--   AAS가 1보다 훨씬 작으면 부하 없음 = 판정 대상 아님. 라이선스 없이도
--   '문제 없음'을 근거와 함께 판정할 수 있다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 부하 유무는 머리말의 AAS=DB Time/Elapsed로 판정한다.
-- 2) 유휴 구간(AAS 0.004)은 Top10이 채워져도 진단 대상이 아니다.
-- 3) SQL*Net message from client는 Idle 이벤트 → 병목으로 지목하면 오판.
-- 4) '문제 없음'도 근거(AAS·DB Time)와 함께 명시하는 것이 좋은 판독이다.
-- 5) 부하 구간(AAS 5.63)과 대조하면 판정이 명확해진다.
-- 6) 라이선스 없으면 V$SYSMETRIC의 Average Active Sessions로 동일 판정.

SYS@orcl> EXIT
