 8장 실습 06 — Advisory 섹션(버퍼 캐시·공유 풀·PGA) 판독과 권고 크기 확인
 목표: Buffer Pool / Shared Pool / PGA Advisory를 읽어 '메모리를 늘리면 효과가
       있는지'를 숫자로 판정한다. 물리읽기가 낮은 구간에서 버퍼 캐시 확대가
       무효임을, 하드파싱은 공유 풀 확대가 증상 완화뿐임을 확인한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA)
 부하: WL_06_mixed.sql (7세션). 보고서 awrrpt_1_295_296.txt 사용.
 라이선스: 🔒 Diagnostics Pack. 미보유 시 V$DB_CACHE_ADVICE 등 직접 조회(하단).

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> SET PAGESIZE 100

-- 근거: 실습 02에서 Physical read 48.8/s로 이미 낮았다. 줄일 물리읽기가 없다.

--   나오므로 공유 풀을 키워도 파싱량은 그대로다 → 확대는 증상 완화조차 약하다.

--------------------------------------------------------------------------------

--   102.5MB 정렬은 전부 메모리에서 처리됐다(sorts disk 0, 실습 05와 일치).

--------------------------------------------------------------------------------
-- [4] (해석) Advisory 종합 — 이 구간은 메모리로 해결할 문제가 아니다.
--------------------------------------------------------------------------------
-- 버퍼: 확대 무효(물리읽기 낮음). 공유 풀: 확대 효과 미미(원인은 리터럴).
--   PGA: 이미 100%. 세 Advisory가 모두 '메모리 증설로 해결 안 됨'을 숫자로
--   증명한다. 답은 메모리가 아니라 주범 SQL(9vmszgd1ft9x0)과 리터럴 제거다.
-- 요령: 각 Advisory는 '효과 곡선의 기울기가 평평해지는 지점'까지만 키운다.
--   여기서는 현재 크기에서 이미 평평 → 키울 이유가 없다.

--------------------------------------------------------------------------------
-- [5] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: "성능이 나쁘니 일단 SGA를 2배로 늘리자"는 요청이 들어왔다.
--------------------------------------------------------------------------------
-- 원인 파악: Advisory를 보지 않고 메모리부터 늘리려는 근거 없는 조치다.
SYS@orcl> SELECT 4880 AS phys_reads_now, 4880 AS phys_reads_2x,
  2         0 AS reduction FROM dual;

PHYS_READS_NOW PHYS_READS_2X  REDUCTION
-------------- ------------- ----------
          4880          4880          0

-- 원인 확정: 버퍼 2배로도 물리읽기 감소 0. SGA 증설은 이 구간에서 효과가
--   없고 메모리만 낭비한다. 성능 저하 원인은 메모리 부족이 아니다.
-- 조치: 증설 요청을 Advisory 근거와 함께 보류하고, 주범 SQL 개선(실습 04)과
--   리터럴→바인드 전환을 우선한다.
-- 재확인: 세 Advisory 모두 확대 효과 미미/0 → 메모리 증설은 해법이 아님 확정.

-- 1) Advisory는 크기 변경의 예상 효과를 정량화 → 방향이지 명령이 아니다.
-- 2) 버퍼: 물리읽기 낮아 확대 무효. 공유 풀: 원인이 리터럴이라 확대 효과 미미.
-- 3) PGA: 이미 cache hit 100% → 확대 불필요.
-- 4) 종합: 이 구간은 '메모리로 해결할 문제가 아니다'를 숫자로 증명.
-- 5) 근거 없이 SGA 2배 증설은 오판 → Advisory로 효과 0 확인 후 보류.
-- 6) 라이선스 없으면 V$DB_CACHE_ADVICE/V$SHARED_POOL_ADVICE/V$PGA_TARGET_ADVICE.
