================================================================================
 9장 실습 03 — ADDM 분석 모드 확인 (Database / Instance / Partial)  🔒
 목표: 단일 인스턴스 non-CDB 환경에서 ANALYZE_DB와 ANALYZE_INST가 같은 결과를
       내는 것을 확인하고, 존재하지 않는 인스턴스로 Partial 모드를 실행했을 때의
       오류를 재현·교정한다. 여러 인스턴스가 있을 때만 모드 구분이 의미를 갖는다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA). 단일 인스턴스(instance_number=1).
 참조: 스냅샷 295~296 (실습 01 부하 구간)
 라이선스: 🔒 Diagnostics Pack 필요.
 주의: 개인 실습 환경 전용.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200 PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 현재 인스턴스 구성을 확인한다. 단일 인스턴스다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT instance_number, instance_name, status FROM v$instance;

INSTANCE_NUMBER INSTANCE_NAME    STATUS
--------------- ---------------- ------------
              1 orcl             OPEN

-- RAC가 아니라 인스턴스가 하나(번호 1)뿐이다. 따라서 ADDM은 사실상
-- Instance 모드로만 동작하며, Database 모드로 실행해도 이 한 인스턴스를 분석한다.

--------------------------------------------------------------------------------
-- [2] (조치) Database 모드로 실행한다(ANALYZE_DB).
--------------------------------------------------------------------------------
SYS@orcl> VAR t1 VARCHAR2(40);
SYS@orcl> BEGIN
  2         :t1 := 'CH9_MODE_DB';
  3         DBMS_ADDM.ANALYZE_DB(:t1, 295, 296);
  4       END;
  5       /

PL/SQL 처리가 정상적으로 완료되었습니다.

--------------------------------------------------------------------------------
-- [3] (조치) Instance 모드로 실행한다(ANALYZE_INST, instance_number=1).
--------------------------------------------------------------------------------
SYS@orcl> VAR t2 VARCHAR2(40);
SYS@orcl> BEGIN
  2         :t2 := 'CH9_MODE_INST';
  3         DBMS_ADDM.ANALYZE_INST(:t2, 295, 296, 1);
  4       END;
  5       /

PL/SQL 처리가 정상적으로 완료되었습니다.

--------------------------------------------------------------------------------
-- [4] (해석·비교) 두 태스크의 최상위 Finding이 동일한지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT t.task_name, f.finding_name,
  2         ROUND(f.impact/1000000,2) impact_sec
  3       FROM dba_advisor_findings f JOIN dba_advisor_tasks t USING (task_id)
  4       WHERE t.task_name IN ('CH9_MODE_DB','CH9_MODE_INST')
  5         AND f.type='PROBLEM'
  6       ORDER BY t.task_name, f.impact DESC;

TASK_NAME       FINDING_NAME                     IMPACT_SEC
--------------- -------------------------------- ----------
CH9_MODE_DB     Top SQL Statements                   348.72
CH9_MODE_DB     Hard Parse Due to Literal Usage       33.38
CH9_MODE_DB     Commits and Rollbacks                 21.15
CH9_MODE_INST   Top SQL Statements                   348.72
CH9_MODE_INST   Hard Parse Due to Literal Usage       33.38
CH9_MODE_INST   Commits and Rollbacks                 21.15

-- 두 모드의 결과가 동일하다. 단일 인스턴스에서는 Database 모드가 Instance 모드처럼
-- 동작하기 때문이다. (수치는 이 부하의 실측이라 학습자 환경에선 <환경값>.)

--------------------------------------------------------------------------------
-- [5] (이상 징후 재현) Partial 모드로 존재하지 않는 인스턴스 '2'를 지정한다.
--------------------------------------------------------------------------------
SYS@orcl> VAR t3 VARCHAR2(40);
SYS@orcl> BEGIN
  2         :t3 := 'CH9_MODE_PARTIAL';
  3         DBMS_ADDM.ANALYZE_PARTIAL(:t3, '2', 295, 296);
  4       END;
  5       /
BEGIN
*
1행에 오류:
ORA-13639: The parameter instance_numbers has an invalid instance number 2.
ORA-06512: at "SYS.DBMS_ADDM", line ...
ORA-06512: at line 3

--    → 원인: Partial 모드는 실재하는 인스턴스 번호의 부분집합만 받는다.
--            이 환경엔 인스턴스 1뿐이라 '2'는 유효하지 않다.
--    → 조치: 단일 인스턴스에서는 Partial 모드가 필요 없다. 존재하는 번호(1)로
--            지정하거나, 애초에 ANALYZE_DB/ANALYZE_INST를 쓴다.

--------------------------------------------------------------------------------
-- [6] (조치·재확인) 유효한 인스턴스 번호(1)로 Partial 모드를 실행한다.
--------------------------------------------------------------------------------
SYS@orcl> BEGIN
  2         :t3 := 'CH9_MODE_PARTIAL';
  3         DBMS_ADDM.ANALYZE_PARTIAL(:t3, '1', 295, 296);
  4       END;
  5       /

PL/SQL 처리가 정상적으로 완료되었습니다.

-- 해석: 세 모드(DB/Instance/Partial)의 구분은 RAC처럼 인스턴스가 여럿일 때
--       비로소 의미가 생긴다. 단일 인스턴스 non-CDB 환경에서는 어느 모드로
--       실행해도 그 한 인스턴스가 분석 대상이다. 멀티 인스턴스(RAC) 통합
--       환경의 세분화는 이 과정 범위 밖이며 개념으로만 알아 둔다.

--------------------------------------------------------------------------------
-- [7] (정리) 실습용 태스크를 삭제한다.
--------------------------------------------------------------------------------
SYS@orcl> EXEC DBMS_ADVISOR.DELETE_TASK('CH9_MODE_DB');
SYS@orcl> EXEC DBMS_ADVISOR.DELETE_TASK('CH9_MODE_INST');
SYS@orcl> EXEC DBMS_ADVISOR.DELETE_TASK('CH9_MODE_PARTIAL');

================================================================================
 라이선스 없이 같은 것을 보는 대안 경로 (Diagnostics Pack 미보유 시)
 - ANALYZE_* 프로시저는 쓸 수 없다.
 - 단일 인스턴스 실시간 진단은 V$INSTANCE·V$SYSSTAT·V$SYSTEM_EVENT 델타로 한다.
 - 인스턴스 단위 비교가 필요한 RAC 진단은 GV$ 계열로 인스턴스별 값을 본다.
