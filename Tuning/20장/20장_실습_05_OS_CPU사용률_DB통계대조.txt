================================================================================
 20장 실습 05 — OS CPU 사용률과 DB 통계 대조 (병목이 DB 안인지 밖인지)
 목표: V$OSSTAT로 CPU 사용률을 계산하고 DB Time 구성과 대조해 병목의 위치를
       가른다. 무부하 구간과 WL_02_io 부하 구간의 델타를 비교해 판정한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 부하: WL_02_io.sql(대량 전체 스캔·랜덤 읽기)로 CPU·I/O 부하 유발.
 주의: 개인 실습 환경 전용.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태 · 무부하) V$OSSTAT로 호스트 용량과 부하를 캡처한다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT stat_name, value FROM v$osstat
  2    WHERE stat_name IN ('NUM_CPUS','NUM_CPU_CORES',
  3         'PHYSICAL_MEMORY_BYTES','LOAD','IDLE_TIME','BUSY_TIME')
  4    ORDER BY stat_name;

STAT_NAME               VALUE
----------------------- ---------------
BUSY_TIME                      653492
IDLE_TIME                    35695635
LOAD                    0.2099609375
NUM_CPUS                            8
NUM_CPU_CORES                       8
PHYSICAL_MEMORY_BYTES      8044179456

-- 해석(용량): 8코어, 물리 메모리 약 7.5GiB.
-- 해석(부하): LOAD 0.21 → 실행 큐 대기가 1보다 훨씬 작다 = CPU 거의 유휴.
-- CPU 사용률 = BUSY/(BUSY+IDLE) = 653492 / 36349127 ≈ 0.018 = 약 1.8%.
--   ※ 이 값은 부팅 이후 누적 평균이다. 짧은 피크를 감춘다.

--------------------------------------------------------------------------------
-- [2] (조치 전 상태 · DB Time 구성) V$SYS_TIME_MODEL로 DB CPU 비중을 본다.
--------------------------------------------------------------------------------
SYS@orcl> SELECT stat_name, value FROM v$sys_time_model
  2    WHERE stat_name IN ('DB time','DB CPU') ORDER BY value DESC;

STAT_NAME     VALUE
------------- ----------
DB time       <환경값>
DB CPU        <환경값>

-- 해석: 무부하 구간에선 DB Time 변화가 거의 없다. 대조군일 뿐이다.
--   성능 지표는 부하가 있어야 나타난다(1장 원칙).

--------------------------------------------------------------------------------
-- [3] (조치 전 델타 준비) OS·DB 누적값을 스냅샷한다.
--------------------------------------------------------------------------------
SYS@orcl> CREATE GLOBAL TEMPORARY TABLE os_snap ON COMMIT PRESERVE ROWS AS
  2    SELECT stat_name, value FROM v$osstat
  3    WHERE stat_name IN ('BUSY_TIME','IDLE_TIME');
Table created.

--------------------------------------------------------------------------------
-- [부하 유발] 업무 세션에서 WL_02_io.sql 을 약 60초 돌린다.
--------------------------------------------------------------------------------
SYS@orcl> -- (다른 세션) SQLT@orcl> @WL_02_io.sql   -- 약 60초 후 중단

--------------------------------------------------------------------------------
-- [4] (조치 후 상태) 부하 구간의 CPU 사용률 델타를 계산한다.
--------------------------------------------------------------------------------
SYS@orcl> WITH now AS (
  2    SELECT MAX(DECODE(stat_name,'BUSY_TIME',value)) busy,
  3           MAX(DECODE(stat_name,'IDLE_TIME',value)) idle FROM v$osstat),
  4  was AS (
  5    SELECT MAX(DECODE(stat_name,'BUSY_TIME',value)) busy,
  6           MAX(DECODE(stat_name,'IDLE_TIME',value)) idle FROM os_snap)
  7  SELECT ROUND( (now.busy-was.busy) /
  8         GREATEST((now.busy-was.busy)+(now.idle-was.idle),1) *100, 1) cpu_pct
  9    FROM now, was;

  CPU_PCT
---------
 <환경값>   -- 부하 구간의 실제 CPU 사용률(누적 아님, 구간 델타)

-- 해석: 무부하 누적 1.8%와 달리, 부하 구간 델타는 크게 오른다(값은 환경 의존).
--   이렇게 '구간 델타'로 봐야 짧은 부하의 CPU 사용을 놓치지 않는다.

--------------------------------------------------------------------------------
-- [5] (판정) 병목이 DB 안인가 밖인가 — OS CPU와 DB CPU 비중을 대조.
--------------------------------------------------------------------------------
SYS@orcl> -- 판정 논리:
SYS@orcl> --  (a) OS CPU 높음 + 오라클이 씀 + DB CPU 비중 높음 → 병목 DB 안(SQL 튜닝).
SYS@orcl> --  (b) OS CPU 높음 + 비오라클 프로세스가 씀       → 병목 DB 밖.
SYS@orcl> --  (c) OS CPU 한가 + DB Time 대부분 대기          → I/O·잠금 대기.
SYS@orcl> -- WL_02_io는 전체 스캔·랜덤 읽기라 대개 (c) db file scattered/sequential read.

--------------------------------------------------------------------------------
-- [6] (이상 징후 → 원인 → 조치 → 재확인)
--     이상 징후: 무부하 때 캡처한 누적 1.8%만 보고 "이 서버는 CPU가 한가하니
--       세션을 더 붙여도 된다"고 단정했다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인 파악: 1.8%는 부팅 이후 누적 평균이다. 부하 구간 델타([4])는
SYS@orcl> --   전혀 다르게 높을 수 있다. 누적값만으로 여유를 단정하면 피크를 놓친다.
SYS@orcl> -- 조치: 판정은 반드시 부하 구간의 델타로 한다. 무부하 누적은 대조군.
SYS@orcl> -- 재확인: [4]의 구간 CPU_PCT와 [5]의 대기 성격을 함께 보고,
SYS@orcl> --   병목이 CPU인지 I/O인지 근거를 가지고 판정한다. → 누적값 오판 교정.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) V$OSSTAT: 8코어, 물리 약 7.5GiB, LOAD 0.21, 누적 CPU 사용률 약 1.8%(무부하).
-- 2) CPU 사용률 = BUSY/(BUSY+IDLE). 누적값이라 구간은 델타로 재계산한다.
-- 3) 병목 위치는 OS CPU 사용률과 DB CPU 비중을 대조해 세 경우로 가른다.
-- 4) 무부하 누적만 보고 여유를 단정하면 피크를 놓친다 → 부하 구간 델타로 판정.
-- ※ V$OSSTAT·V$SYS_TIME_MODEL 조회는 라이선스 무관.

SYS@orcl> DROP TABLE os_snap PURGE;
Table dropped.

SYS@orcl> EXIT
