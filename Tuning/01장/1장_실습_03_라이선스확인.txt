================================================================================
 1장 실습 03 — 관리 팩 라이선스 확인
 목표: DBA_FEATURE_USAGE_STATISTICS로 관리 팩 사용 이력을 조회하고,
       CONTROL_MANAGEMENT_PACK_ACCESS 설정별 접근 차이를 재현·원복한다.
 환경: non-CDB=orcl 19.3 (SYS AS SYSDBA로 수행)
 라이선스 주의(🔒): 이 실습 자체는 라이선스 경계를 '점검'하는 것이 목적이다.
       AWR·ADDM·ASH=Diagnostics Pack, SQL Tuning/Access Advisor=Tuning Pack.
 주의: 개인 실습 환경 전용. 파라미터를 잠시 바꾸므로 반드시 원복한다.
================================================================================

$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
-- [1] (조치 전 상태) 어떤 팩이 사용 가능하도록 선언돼 있는지 확인한다.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN name  FORMAT A32
SYS@orcl> COLUMN value FORMAT A20
SYS@orcl> SELECT name, value FROM v$parameter
  2       WHERE name = 'control_management_pack_access';

NAME                             VALUE
-------------------------------- --------------------
control_management_pack_access   DIAGNOSTIC+TUNING

-- 해석: DIAGNOSTIC+TUNING → 두 팩 기능을 쓸 수 있게 '선언'돼 있다.
--   주의: 이 값이 켜져 있다는 것이 곧 '라이선스 보유'를 뜻하지는 않는다.
--   파라미터 설정과 실제 계약은 별개이므로 계약과 대조해야 한다.

--------------------------------------------------------------------------------
-- [2] (조회) 실제 사용 이력 — DBA_FEATURE_USAGE_STATISTICS.
--------------------------------------------------------------------------------
SYS@orcl> COLUMN name FORMAT A32
SYS@orcl> SELECT name, detected_usages,
  2         TO_CHAR(last_usage_date,'YYYY-MM-DD') last_used
  3       FROM  dba_feature_usage_statistics
  4       WHERE name IN ('Automatic Workload Repository','ADDM',
  5              'Active Session History','AWR Baseline',
  6              'SQL Tuning Advisor','Automatic SQL Tuning Advisor',
  7              'SQL Access Advisor')
  8       ORDER BY name;

NAME                             DETECTED_USAGES LAST_USED
-------------------------------- --------------- ----------
ADDM                                           0
AWR Baseline                                   0
Automatic SQL Tuning Advisor                   2 2026-08-21
Automatic Workload Repository                  0
SQL Access Advisor                             0
SQL Tuning Advisor                             0

--------------------------------------------------------------------------------
-- [3] (이상 징후 → 원인 → 조치)
--     이상 징후: Automatic SQL Tuning Advisor가 2회(마지막 2026-08-21) 감지됐다.
--       이 환경에 Tuning Pack 라이선스가 없다고 가정하면 이는 위반 증거가 된다.
--------------------------------------------------------------------------------
SYS@orcl> -- 원인 파악: Automatic SQL Tuning Advisor는 Tuning Pack 기능이며,
SYS@orcl> --   자동 유지관리 작업으로 야간에 자동 실행됐을 수 있다(15장에서 다룸).
SYS@orcl> --   detected_usages > 0 이면 LMS 감사에서 유상 기능 사용으로 잡힌다.
SYS@orcl> -- 조치(가정: 라이선스 미보유 환경): 자동 SQL 튜닝을 끄고, 팩 접근을 제한한다.
SYS@orcl> --   (실제 운영 반영 전 반드시 라이선스 담당과 확인)

SYS@orcl> -- (3-1) 사용 가능 팩을 NONE 으로 낮춰 수집·접근을 막는 상황을 재현한다.
SYS@orcl> ALTER SYSTEM SET control_management_pack_access='NONE' SCOPE=BOTH;

System altered.

SYS@orcl> SELECT value FROM v$parameter WHERE name='control_management_pack_access';

VALUE
--------------------
NONE

SYS@orcl> -- NONE 상태에서는 AWR 자동 수집·ADDM·자동 SQL 튜닝이 동작하지 않는다.
SYS@orcl> -- (스냅샷 자동 생성과 자동 태스크가 멈춘다 → 유상 기능 사용을 원천 차단)

--------------------------------------------------------------------------------
-- [4] (조치 후 상태 → 원복 → 재확인)
--     학습용 환경이므로 원래 값(DIAGNOSTIC+TUNING)으로 되돌린다.
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET control_management_pack_access='DIAGNOSTIC+TUNING' SCOPE=BOTH;

System altered.

SYS@orcl> SELECT value FROM v$parameter WHERE name='control_management_pack_access';

VALUE
--------------------
DIAGNOSTIC+TUNING

-- 재확인: 원복 완료. (실무 미보유 환경이라면 NONE 또는 DIAGNOSTIC로 둔다.)

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) CONTROL_MANAGEMENT_PACK_ACCESS: NONE / DIAGNOSTIC / DIAGNOSTIC+TUNING.
--    이 값은 '사용 가능 선언'일 뿐 라이선스 보유를 보장하지 않는다.
-- 2) DBA_FEATURE_USAGE_STATISTICS로 유상 기능 사용 이력을 점검한다(감사 대비).
-- 3) 실측에서 Automatic SQL Tuning Advisor만 감지 → Tuning Pack 사용 흔적.
-- 4) 라이선스가 없으면 NONE으로 두고, 진단은 V$ 직접 조회·Statspack으로 한다.

SYS@orcl> EXIT
