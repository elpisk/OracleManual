 과정      : Oracle Database 19c LOB 실습
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / AL32UTF8 + AL16UTF16 / 8K 블록

[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 문서 관리 테이블을 만들면서 BLOB·CLOB·NCLOB·BFILE 네 타입을 한 테이블에 둔다.
-- 목표는 세 가지다.
--   ① 각 타입이 딕셔너리에 어떻게 보이는가
--   ② LOB 컬럼 하나가 세그먼트를 몇 개 쓰는가
--   ③ 값이 행 안에 들어가는 경계가 어디인가 (실측으로 숫자를 확정한다)
-- 작업 유형 : 구조 확인 (장애 복구 아님)

[5] 진행 로그 — 인라인 저장 경계를 실측한다
--------------------------------------------------------------------------------
-- 판정 방법
--   값이 행 안에 있으면 : 테이블 세그먼트가 커지고 LOB 세그먼트는 초기 128KB 에 머문다
--   값이 행 밖에 있으면 : LOB 세그먼트가 커지고 테이블 세그먼트는 64KB 에 머문다
-- 이 대비를 이용해 경계를 찾는다.

-- 5-1. BLOB — 바이트 기준

LOBLAB@orcl> CREATE TABLE bf_3968 (id NUMBER, b BLOB) TABLESPACE lobtbs
  2    LOB (b) STORE AS SECUREFILE (ENABLE STORAGE IN ROW);

Table created.

LOBLAB@orcl> CREATE TABLE bf_3969 (id NUMBER, b BLOB) TABLESPACE lobtbs
  2    LOB (b) STORE AS SECUREFILE (ENABLE STORAGE IN ROW);

Table created.

-- RAW 는 SQL 에서 2000 바이트가 한계다. 3968 바이트는 PL/SQL 로 이어 붙인다.
-- (SQL 에서 UTL_RAW.CAST_TO_RAW 에 2000 바이트를 넘기면 ORA-06502 가 난다)

LOBLAB@orcl> DECLARE
  2    v_b BLOB;
  3    r1  RAW(1989) := UTL_RAW.CAST_TO_RAW(RPAD('A',1989,'A'));
  4  BEGIN
  5    FOR i IN 1..300 LOOP
  6      INSERT INTO bf_3968 VALUES (i, EMPTY_BLOB()) RETURNING b INTO v_b;
  7      DBMS_LOB.WRITEAPPEND(v_b, 1983, r1); DBMS_LOB.WRITEAPPEND(v_b, 1985, r1);
  8    END LOOP;
  9    FOR i IN 1..300 LOOP
 10      INSERT INTO bf_3969 VALUES (i, EMPTY_BLOB()) RETURNING b INTO v_b;
 11      DBMS_LOB.WRITEAPPEND(v_b, 1983, r1); DBMS_LOB.WRITEAPPEND(v_b, 1986, r1);
 12    END LOOP;
 13    COMMIT;
 14  END;
 15  /

PL/SQL procedure successfully completed.

[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) LOB 컬럼 하나는 세그먼트 두 개(LOBSEGMENT + LOBINDEX)를 더 만든다.
--    컬럼 10개에 LOB 을 쓰면 세그먼트가 21개다. 테이블스페이스 용량 계획에 포함한다.
--
-- 2) 인라인 경계는 3968 바이트다. CLOB·NCLOB 은 문자당 2바이트로 계산되므로 1984 문자다.
--    "4000 바이트까지 행 안에 들어간다" 는 흔한 설명은 대략적인 값이다.
--    용량을 산정할 때는 이 측정값을 쓴다.
--
-- 3) CLOB 의 저장 크기는 문자 수 × 2 바이트다(가변폭 문자집합).
--    한글 1만 자 문서는 CLOB 에서 약 20KB 를 쓴다. UTF-8 파일(약 30KB)과 다르다.
--    반대로 ASCII 문서는 파일보다 두 배로 커진다.
--
-- 4) DATA_LENGTH 4000 을 값의 최대 크기로 오해하지 않는다. 실제 한계는 약 15.9TB 다.
--
-- 5) 지연 세그먼트 생성 때문에 CREATE TABLE 직후에는 세그먼트가 없다.
--    "테이블을 만들었는데 dba_segments 에 없다" 는 문의의 대부분이 이것이다.
--
-- 6) LOB 을 읽지 않는 조회가 많은 테이블은 DISABLE STORAGE IN ROW 를 검토한다.
--    테이블 세그먼트가 작아져 전체 스캔이 빨라진다(6-1 의 48배 차이).
