[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 실습 01~08 을 시작하기 전에 필요한 것을 한 번에 만든다.
-- 이 실습을 건너뛰면 뒤의 모든 실습이 ORA-00942 · ORA-22285 로 막힌다.
--
-- 만들 것
--   ① 테이블스페이스 두 개   lobtbs(ASSM) · lobmssm(MSSM)
--      -> MSSM 이 왜 필요한가 : 실습 06 이 MSSM 에서 SecureFile 이 거부되는 것을
--         (ORA-43853) 재현한다. ASSM 하나만 있으면 그 실습을 할 수 없다
--   ② 계정 loblab            시스템 권한 + v$ 뷰 조회 권한
--   ③ 디렉터리 객체 lob_dir  /home/oracle/lobfiles
--   ④ 실습용 OS 파일 세 개   manual.txt · photo.bin · big.dat
--      -> 실습 03·04 가 이 파일들의 **정확한 크기**를 전제로 한다
--
-- 마지막에 loblab 으로 직접 접속해 네 가지를 검증한다.
--   LOB 컬럼 생성 / 임시 LOB / v$ 뷰 조회 / BFILE 로 디렉터리 읽기
-- 작업 유형 : 환경 구성

-- 두 테이블스페이스의 차이가 실습 06 의 핵심이다.
--
--   항목                     | LOBTBS              | LOBMSSM
--   -------------------------|---------------------|------------------
--   extent_management        | LOCAL               | LOCAL
--   allocation_type          | SYSTEM(AUTOALLOCATE)| UNIFORM
--   segment_space_management | AUTO (ASMM)         | MANUAL (MSSM)
--   initial_extent           | 65536               | 65536
--
-- SecureFile LOB 은 ASSM 테이블스페이스에서만 만들 수 있다.
-- MSSM 에서 SECUREFILE 을 지정하면 ORA-43853 이다 (실습 06 에서 재현한다).
-- 그래서 두 개를 미리 만들어 둔다.
--
-- lobtbs 를 200M 로 잡은 이유 : 실습 06·07 이 200건 x 100KB(약 20MB) 를
-- 여섯 가지 구성으로 적재한다. AUTOEXTEND 를 켜 두었으므로 부족하면 늘어난다.

-- 여기서 두 가지 오류를 일부러 만나 본다. 둘 다 v$ 뷰 권한과 관련된 것이다.
--
--   ORA-02030: can only select from fixed tables/views
--     GRANT SELECT ON v$temporary_lobs 는 안 된다.
--     v$ 는 뷰가 아니라 **공용 동의어**다. 권한은 기반 뷰 v_$temporary_lobs 에 준다.
--     조회는 v$ 이름으로 하면 된다 ([7] 에서 확인한다).
--
--   ORA-00942: table or view does not exist
--     v_$tempseg_usage 라는 이름은 없다. v$tempseg_usage 의 기반 뷰는
--     **v_$sort_usage** 다. 이름이 바뀐 뷰라 짝이 다르다.
--     실습 05 가 임시 세그먼트를 확인할 때 이 뷰를 쓴다.
--
-- 권한 결과
--   시스템 권한 5개 : CREATE SESSION · TABLE · PROCEDURE · SEQUENCE · VIEW
--                     (LOB 을 쓰기 위한 별도 권한은 없다. 평범한 테이블 권한으로 충분하다)
--   객체 권한 5개   : V_$MYSTAT · V_$SESSION · V_$SORT_USAGE · V_$STATNAME
--                     · V_$TEMPORARY_LOBS
--   기본 테이블스페이스 LOBTBS, 임시 TEMP
--   쿼터 max_bytes = -1 은 UNLIMITED 를 뜻한다 (세 테이블스페이스 모두)

-- 파일 세 개와 그 의미
--
--   파일        | 크기            | 쓰이는 곳          | 이유
--   ------------|-----------------|--------------------|---------------------------
--   manual.txt  | 7,566 바이트    | 실습 03 CLOB 적재  | 문자 수와 바이트 수가 다르다
--               | 5,154 문자      | 실습 04 BFILE      | (한글 UTF-8 3바이트)
--   photo.bin   | 12,288 바이트   | 실습 03 BLOB 적재  | 난수 이진 데이터
--   big.dat     | 2,097,152 바이트| 실습 03 대용량 적재| 2MB 적재 시간 측정
--
-- manual.txt 의 구성 : 안내 1줄 + 구분선 1줄 + 본문 100줄 = 102줄.
--   본문 한 줄에 한글 12자와 ASCII 38자(줄바꿈 포함) 가 섞여 있다. 한 줄 50문자 / 74바이트.
--   -> 5,154문자 / 7,566바이트. 차이 2,412바이트가 한글 1,206자 x 2 다.
--
-- wc 를 두 번 쓴 이유
--   wc -m (문자 수) 은 **로케일에 의존한다.** LANG 이 C 이면 바이트 수를 돌려준다.
--   그래서 LC_ALL=en_US.UTF-8 을 붙여야 5,154 가 나온다.
--   실습 03 에서 CLOB 문자 수 5,154 와 비교할 값이므로 이 차이를 알고 있어야 한다.

-- 검증 결과를 읽는 법
--
-- ① LOB 컬럼 생성
--    BLOB · CLOB · NCLOB 세 개가 user_lobs 에 나왔다. securefile YES, in_row YES.
--    **BFILE 컬럼(f) 은 user_lobs 에 없다.** BFILE 은 DB 안에 저장하지 않으므로
--    LOB 세그먼트가 없다. 실습 04 에서 다시 확인한다.
--    user_segments 가 비어 있는 것은 deferred_segment_creation 때문이다.
--    행을 한 건도 넣지 않았으므로 세그먼트가 아직 없다.

-- 1. LOB 을 쓰기 위한 별도 권한은 없다.
--    CREATE TABLE 권한만 있으면 BLOB·CLOB 컬럼을 만들 수 있다.
--    필요한 것은 테이블스페이스 쿼터와, BFILE 을 쓸 때의 디렉터리 객체 권한이다.
--
-- 2. v$ 뷰 권한은 v_$ 에 준다.
--    GRANT SELECT ON v$xxx 는 ORA-02030 이다. v$ 는 공용 동의어이고
--    실제 뷰는 v_$xxx 다. 조회는 v$ 이름으로 한다.
--    이름이 다른 짝도 있다 : v$tempseg_usage -> v_$sort_usage
--
-- 3. 디렉터리 객체는 서버 경로다.
--    Oracle 이 경로 존재를 검사하지 않으므로 객체는 만들어지고 사용할 때 실패한다.
--    만든 직후 BFILENAME + FILEEXISTS 로 검증하는 습관을 들인다.
--    운영에서는 경로를 /home/oracle 밖(전용 파일시스템) 에 두고 권한을 좁힌다.
--
-- 4. ASSM 과 MSSM 을 구분해 둔다.
--    SecureFile 은 ASSM 전용이다. 예전에 만든 MSSM 테이블스페이스가 남아 있으면
--    그 위에서는 SecureFile LOB 을 만들 수 없다 (ORA-43853).
--    신규 테이블스페이스는 항상 ASSM 으로 만든다.
--
-- 5. 문자 수와 바이트 수를 구분하는 습관을 여기서부터 들인다.
--    OS 의 wc -m 도 로케일에 따라 달라진다. DB 의 GETLENGTH(CLOB) 은 문자 수,
--    GETLENGTH(BLOB) 과 GETLENGTH(BFILE) 은 바이트 수다.
--    LOB 과정에서 숫자가 안 맞을 때는 거의 항상 이 구분 때문이다.
--
-- 6. 전 과정을 마친 뒤 철거
--      SYS@orcl> DROP USER loblab CASCADE;
--      SYS@orcl> DROP DIRECTORY lob_dir;
--      SYS@orcl> DROP TABLESPACE lobtbs  INCLUDING CONTENTS AND DATAFILES;
--      SYS@orcl> DROP TABLESPACE lobmssm INCLUDING CONTENTS AND DATAFILES;
--      [oracle@oel7v9 ~]$ rm -rf /home/oracle/lobfiles
--
-- 7. 이 실습에서 본 오류
