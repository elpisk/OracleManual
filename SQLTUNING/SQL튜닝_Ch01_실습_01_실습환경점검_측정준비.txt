================================================================================
 Ch01 실습 01 — 실습 환경 점검과 측정 준비 (Before 상태 확인, DISPLAY_CURSOR 실행 통계)
 목표: 진료비청구심사 스키마 7개 테이블의 건수와 "PK 외 인덱스 없음" 상태를 확인해
       이후 모든 실측의 기준선을 잡는다. DBMS_XPLAN.DISPLAY_CURSOR 로 실행 통계
       (A-Rows·Buffers)를 보는 준비를 하고, 통계 열이 비어 나오는 이상 징후를 재현해
       원인(GATHER_PLAN_STATISTICS 힌트 부재)을 교정한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT (sqlplus sqlt/sqlt@orcl). 관리 팩 라이선스 불필요.
 주의: 개인 실습 환경 전용. 이 실습은 조회만 수행하며 DDL 변경이 없다.
================================================================================

$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> SET LINESIZE 200


SQLT@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
-- [2] (조치 전 상태) 인덱스 현황 — PK 만 있어야 한다. 이것이 의도된 Before 상태다.
--------------------------------------------------------------------------------
SQLT@orcl> COLUMN table_name FORMAT A16


SQLT@orcl> COLUMN index_name FORMAT A20

-- 해석: PK 7개뿐이다. 만약 IX_ 로 시작하는 인덱스가 보이면 이전 실습의 원복이 빠진 것이다.
--   그대로 두면 이 과정의 모든 Buffers 실측값이 교안과 달라진다 → 소유자가 DROP 한 뒤 진행.

SQLT@orcl> -- 통계 기준 상태: 히스토그램은 MEDICAL_CLAIMS.HOSP_ID 하나뿐이어야 한다(Day 0 준비 명령).
SQLT@orcl> COLUMN column_name FORMAT A12


SQLT@orcl> SELECT table_name, column_name, histogram, num_buckets
  2       FROM   user_tab_col_statistics WHERE histogram <> 'NONE';

TABLE_NAME       COLUMN_NAME  HISTOGRAM       NUM_BUCKETS
---------------- ------------ --------------- -----------
MEDICAL_CLAIMS   HOSP_ID      HYBRID                  254

-- 해석: HOSP_ID(HYBRID 254) 하나다. 이 과정의 E-Rows 실측값은 이 상태를 전제한다. 다른 컬럼에 히스토그램이
--   보이면(SIZE AUTO 로 수집한 이력) Day 0 준비 명령으로 되돌린다:
--   EXEC DBMS_STATS.GATHER_SCHEMA_STATS(USER, METHOD_OPT => 'FOR ALL COLUMNS SIZE 1')
--   EXEC DBMS_STATS.GATHER_TABLE_STATS(USER, 'MEDICAL_CLAIMS', METHOD_OPT => 'FOR ALL COLUMNS SIZE 1 FOR COLUMNS SIZE 254 HOSP_ID')

--------------------------------------------------------------------------------
-- [3] (이상 징후 → 원인 → 조치 → 재확인) 실행 통계 열이 비어 나온다
--     이상 징후: DISPLAY_CURSOR 를 ALLSTATS LAST 로 봤는데 A-Rows·Buffers 열이 없다.
--------------------------------------------------------------------------------
SQLT@orcl> SELECT COUNT(*) FROM medical_claims WHERE hosp_id = 1;

SQLT@orcl> -- 원인 파악: Note 절이 답을 말해 준다. 실행 통계(A-Rows·A-Time·Buffers)는
SQLT@orcl> --   커서를 실행할 때 수집돼야 하는데, 기본 STATISTICS_LEVEL=TYPICAL 에서는
SQLT@orcl> --   수집하지 않는다. E-Rows(추정)만 남고 A-Rows(실제)가 빈 이유다.
SQLT@orcl> SHOW PARAMETER statistics_level

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
client_statistics_level              string      TYPICAL
statistics_level                     string      TYPICAL

SQLT@orcl> -- 조치: 문장 단위로 힌트를 붙인다. 세션 전체를 ALL 로 올리는 방법도 있으나
SQLT@orcl> --   모든 SQL 의 실행 통계를 수집해 세션이 느려지므로 이 과정은 힌트 방식을 표준으로 쓴다.
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(*) FROM medical_claims WHERE hosp_id = 1;

-- [4] (조치 후 관점) 힌트 없이 실행한 이전 커서는 어떻게 되나
--------------------------------------------------------------------------------
SQLT@orcl> COLUMN sql_text FORMAT A60


SQLT@orcl> SELECT sql_id, child_number, executions, buffer_gets, sql_text
  2       FROM  v$sql
  3       WHERE sql_text LIKE '%medical_claims WHERE hosp_id = 1'
  4       AND   sql_text NOT LIKE '%v$sql%';

SQL_ID        CHILD_NUMBER EXECUTIONS BUFFER_GETS SQL_TEXT
------------- ------------ ---------- ----------- ------------------------------------------------------------
0fqfut0m2jfxw            0          1        3090 SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(*) FROM medical_c
                                                  laims WHERE hosp_id = 1

7fs0awt4bjsdu            0          1        3219 SELECT COUNT(*) FROM medical_claims WHERE hosp_id = 1

-- 해석: 힌트는 SQL 텍스트의 일부이므로 힌트 유무에 따라 SQL_ID 가 달라진다(Ch02 의 리터럴과 같은
--   원리). V$SQL.BUFFER_GETS 는 힌트 없이도 항상 누적되므로, 행 단위 A-Rows 가 필요 없을 때는
--   V$SQL 만으로도 Buffers 를 볼 수 있다(Ch14 실습 03).

-- 1) 7개 표 건수와 "PK 만 존재" 가 이 과정의 Before 상태다. IX_ 인덱스가 남아 있으면 먼저 지운다.
-- 2) DISPLAY_CURSOR('ALLSTATS LAST') 에 A-Rows·Buffers 가 없으면 Note 절을 읽는다 —
--    실행 통계는 GATHER_PLAN_STATISTICS 힌트(또는 STATISTICS_LEVEL=ALL)로만 수집된다.
-- 3) 이 과정의 측정 표준: 힌트를 붙여 1회 실행 → DISPLAY_CURSOR(NULL,NULL,'ALLSTATS LAST').
-- 4) MEDICAL_CLAIMS Full Scan = Buffers 3,090. 이 숫자를 기억해 둔다.
