 Ch03 실습 01 — EXPLAIN PLAN(추정) vs DISPLAY_CURSOR(실측), 그리고 190배 카디널리티 추정 오류
 목표: 같은 SQL 을 EXPLAIN PLAN 으로 본 추정 계획과 실제 실행 후 실행 통계로 대조한다.
       PLAN_TABLE 이 비어 있을 때 DBMS_XPLAN.DISPLAY 가 내는 오류를 재현·교정하고,
       E-Rows 77,946 vs A-Rows 411 의 원인(독립 가정 곱셈)을 단일 조건 추정으로 분해한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. PLAN_TABLE 은 SYS 의 공용 PLAN_TABLE$ 동의어를 쓴다.
 주의: 개인 실습 환경 전용. 조회만 수행한다.

-- 해석: E-Rows 77,946 vs A-Rows 411 — 약 190배 과대 추정. 계획 자체(Full Scan)는 인덱스가
--   없으니 어차피 같지만, 이 SQL 이 조인의 한쪽이었다면 77,946 이라는 잘못된 크기를 근거로

--   다시 읽은 몫 — Ch02 실습 03 의 arraysize 효과).

SQLT@orcl> -- 원인 파악: 옵티마이저는 두 조건을 독립으로 보고 선택도를 곱한다.
SQLT@orcl> --   (a)/300,000 × (b)/300,000 × 300,000 ≈ 77,946 이 나온다(각 단독 추정치를 대입해 확인).
SQLT@orcl> --   실제로는 "입원" 과 "고액" 이 서로 상관돼 있어 동시에 만족하는 행이 곱셈 추정치보다
SQLT@orcl> --   훨씬 적다(411). 옵티마이저는 컬럼 간 상관관계를 스스로 알지 못한다.
SQLT@orcl> -- 실제 값과 대조
SQLT@orcl> SELECT COUNT(*) FROM medical_claims WHERE claim_type = '입원';

  COUNT(*)
----------
     59511

SQLT@orcl> SELECT COUNT(*) FROM medical_claims WHERE total_amt > 500000;

  COUNT(*)
----------
      1997

-- 재확인: (a) 150K vs 실제 59,511 — 2.5배. 히스토그램이 없어 CLAIM_TYPE 의 두 값(외래·입원)을 반반으로
--   본 것이다. (b) 155K vs 실제 1,997 — 78배. TOTAL_AMT 를 최소~최대 사이에 고르게 퍼진 것으로 보지만
--   실제 고액 청구는 소수다. 두 오차의 곱(150K × 155K ÷ 300K = 77,946)이 411 과 190배 어긋난다.
--   오차의 큰 몫은 컬럼별 분포(히스토그램 부재), 나머지는 "입원이면 고액" 이라는 두 컬럼의 상관이다.
--   처방은 두 가지 — 컬럼 히스토그램(Ch13)과 컬럼 그룹 확장 통계(TUN 7장 실습 03).

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) EXPLAIN PLAN + DISPLAY = 실행 전 추정(Rows·Cost). DISPLAY_CURSOR = 실행 후 실측(A-Rows·Buffers).
--    DISPLAY 는 PLAN_TABLE 을 읽으므로 EXPLAIN PLAN 이 먼저다.
-- 2) Cost 는 같은 SQL 의 대안 계획끼리만 비교한다. 다른 SQL 과 비교하지 않는다.
-- 3) E-Rows/A-Rows 가 수십 배 이상 어긋나면 카디널리티 추정 오류 — 원인은 대개 히스토그램 부재,
--    컬럼 간 상관, 오래된 통계 중 하나다. 여기서는 앞의 둘이 겹쳤다.
-- 4) 조건을 하나씩 떼어 EXPLAIN PLAN 하면 어느 가정(독립 곱셈)이 깨졌는지 보인다.
