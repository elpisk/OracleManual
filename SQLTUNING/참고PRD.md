
핵심 방향은 단순한 SQL 문법 교육이 아니라, **“느린 SQL을 발견 → 원인 분석 → 실행계획 해석 → 개선안 수립 → 튜닝 → 개선 효과 검증”**의 전체 사이클을 반복 실습하는 과정으로 잡는 것이 좋습니다.

# 2. 문제 정의

현업에서 SQL 성능 문제는 단순히 SQL 문법을 잘 작성한다고 해결되지 않는다.

예를 들어 다음과 같은 상황이 발생할 수 있다.

* 인덱스가 있는데도 Full Table Scan이 발생한다.
* 같은 SQL인데 특정 조건에서만 느려진다.
* JOIN 대상 데이터가 많아지면서 응답 시간이 급격하게 증가한다.
* WHERE 조건을 조금 변경했더니 실행계획이 달라진다.
* `SELECT *` 또는 불필요한 JOIN 때문에 조회 비용이 증가한다.
* 함수나 형 변환 때문에 인덱스를 제대로 사용하지 못한다.
* 실행계획상 비용은 낮아 보이는데 실제 실행 시간은 길다.
* OFFSET 기반 페이징이 데이터 증가에 따라 느려진다.
* 서브쿼리, JOIN, EXISTS 등의 작성 방식에 따라 성능이 달라진다.
* 통계정보나 데이터 분포에 따라 Oracle 옵티마이저의 판단이 달라진다.

따라서 교육에서는 단순히 "이렇게 작성하면 빠르다"를 가르치는 것이 아니라,

> **왜 느린가? → Oracle은 어떻게 실행하는가? → 실행계획은 무엇을 말하는가? → 어떤 방법으로 개선할 것인가? → 정말 빨라졌는가?**

라는 사고 과정을 반복적으로 훈련해야 한다.

# 6. 실습 문제 유형

실습 문제는 난이도를 4단계로 구성한다.

## Level 1 — 실행계획 읽기

목표: 실행계획에 익숙해지기

예시:

> 다음 SQL의 실행계획을 확인하고 TABLE ACCESS FULL이 발생하는 테이블을 찾으시오.

## Level 2 — 문제 원인 찾기

목표: 성능 저하 원인을 분석하기

예시:

> ORDER_DATE 컬럼에 인덱스가 존재하지만 해당 SQL에서 INDEX RANGE SCAN이 발생하지 않는다. 원인을 찾으시오.

---

## Level 3 — SQL 튜닝

목표: 직접 SQL을 개선하기

예시:

> 아래 SQL은 평균 5초가 소요된다. 실행계획과 실행 통계를 분석하여 500ms 이하로 개선하시오.

평가 기준:

* SQL 변경
* 실행계획 변화
* Buffer Gets 변화
* Elapsed Time 변화
* 튜닝 근거

---

## Level 4 — 종합 튜닝

# 11. 교육용 데이터셋 설계

실습 데이터는 단순한 예제용 데이터보다 **성능 차이가 명확하게 나타나는 데이터**로 설계한다.

특히 다음 특성을 의도적으로 포함한다.

* 대용량 테이블
* 데이터 분포가 불균등한 컬럼
* 선택도가 높은 컬럼
* 선택도가 낮은 컬럼
* 날짜 데이터
* NULL 데이터
* 중복 데이터
* 대량 JOIN
* 1:N 관계
* 복합 인덱스가 필요한 상황
* 잘못된 인덱스가 존재하는 상황
* 불필요한 인덱스가 존재하는 상황

이를 통해 학습자가 단순히 "인덱스를 추가하면 된다"는 잘못된 습관을 갖지 않도록 한다.

# 17. 핵심 제품 방향

이 교육 과정의 핵심은 **"SQL 문법을 가르치는 과정"이 아니라 "성능 문제를 해결하는 사고방식을 훈련하는 과정"**으로 정의한다.

따라서 모든 교육 콘텐츠는 다음 질문을 중심으로 설계한다.

> **SQL이 왜 느린가?**

↓

> **Oracle은 이 SQL을 어떻게 실행하고 있는가?**

↓

> **실행계획에서 병목은 어디인가?**

↓

> **SQL / Index / 데이터 접근 방식을 어떻게 바꿀 것인가?**

↓

> **실제로 얼마나 개선되었는가?**

↓

> **데이터가 증가해도 이 튜닝이 유효한가?**

최종적으로 학습자가 새로운 SQL 성능 문제를 만났을 때, 특정 튜닝 기법을 암기해서 적용하는 것이 아니라 **실행계획과 측정 데이터를 근거로 스스로 원인을 찾고 해결할 수 있는 수준**에 도달하는 것을 본 과정의 최종 목표로 한다.

다음 단계에서는 이 PRD를 바탕으로 **① 2일/3일/5일 교육 일정표 → ② 15개 Chapter의 상세 교안 목차 → ③ 실제 Oracle 실습용 테이블/데이터셋 → ④ 50개 실습 문제와 정답·해설** 순서로 구체화하면 바로 제작 단계로 넘어갈 수 있습니다.
