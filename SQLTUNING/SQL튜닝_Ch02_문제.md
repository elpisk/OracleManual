# Chapter 2. SQL은 어떻게 실행되는가? — 실습문제 10제

`SQL튜닝_Ch02_교안.md`를 먼저 읽고 푸시기 바랍니다. 모든 결과는 실습 DB 실측입니다.

---

**1. [상]** SQL 처리 4단계(Parse/Bind/Execute/Fetch) 각각에서 무슨 일이 일어나는지
설명하고, 이 중 옵티마이저가 실행계획을 만드는 단계가 어디인지 지목하시오.

**2. [상]** 다음은 실측 결과다.

```text
SQL_ID          EXECUTIONS  PARSE_CALLS  SQL_TEXT
5awbw1wcprrj2   1           1            ...WHERE hosp_id = 500
92p460f4hj858   1           1            ...WHERE hosp_id = 1
```

`WHERE hosp_id = 1`과 `WHERE hosp_id = 500`은 숫자 하나만 다른데도 왜 서로 다른 SQL_ID를
부여받는지 설명하시오.

**3. [최상]** 바인드 변수 버전은 `:b_hosp`에 1과 500을 순서대로 대입해 두 번 실행했는데도
SQL_ID가 `3zakhp3a1b0ac` 하나로 유지됐다(EXECUTIONS=2). 하루에 수만 명의 사용자가 각자
다른 병원 ID로 "내 병원 청구 목록 조회" API를 호출하는 상황을 가정하고, 이 API의 SQL을
리터럴로 짤 때와 바인드 변수로 짤 때 공유 풀에 어떤 차이가 생길지 설명하시오.

**4. [상]** `HOSP_ID=1` 조회는 E-Rows 3,039, `HOSP_ID=500` 조회는 E-Rows 109로 실제
차이(3,058 vs 177)에 가깝게 나왔다. 두 SQL이 같은 문장 구조인데 왜 예상치가 이렇게 다르게
나왔는지, `USER_TAB_COL_STATISTICS`에서 확인한 `HOSP_ID` 컬럼의 통계정보(HISTOGRAM=HYBRID,
NUM_BUCKETS=254)를 근거로 설명하시오.

**5. [상]** 교안 03절은 "히스토그램이 없으면 옵티마이저가 균등 분포를 가정한다"고 설명한다.
`HOSP_ID`처럼 히스토그램이 있는 컬럼이라면, 같은 SQL 텍스트라도 리터럴 값에 따라 Cost와
E-Rows가 달라질 수 있다. 이것이 왜 "SQL 텍스트가 같으면 항상 같은 실행계획이 나온다"는
가정이 틀릴 수 있는지 보여주는 사례인지 서술하시오.

**6. [최상]** 4번 문항에서 확인했듯 `HOSP_ID`는 히스토그램 덕분에 리터럴 SQL에서 정확한
추정이 가능했다. 그런데 만약 이 컬럼에 바인드 변수를 썼다면 어떤 문제가 생길 수 있을지
추론하시오. (힌트: 바인드 변수는 SQL_ID가 하나로 고정되고 실행계획도 하나만 저장된다.
그런데 `HOSP_ID=1`처럼 쏠린 값과 `HOSP_ID=500`처럼 일반적인 값은 원래 최적의 실행 방법이
다를 수 있다.)

**7. [상]** Chapter 3(실행계획 기초)에서 다룬 `EXPLAIN PLAN`(추정치 확인)과
`DBMS_XPLAN.DISPLAY_CURSOR(...'ALLSTATS LAST')`(실측치 확인)의 차이를, 이번 챕터의
Parse/Bind/Execute/Fetch 흐름과 연결지어 설명하시오. `EXPLAIN PLAN`은 이 네 단계 중
어디까지만 수행하는 것인가?

**8. [상]** Cost는 Parse 단계에서 계산된다. 리터럴 SQL 두 건(HOSP_ID=1, HOSP_ID=500)이
각각 별도로 하드 파싱된다는 사실과, Cost가 그 파싱 과정에서 통계정보를 근거로 계산된다는
사실을 연결해, 왜 두 SQL이 서로 다른 Cost/E-Rows를 가질 수 있는지 설명하시오.

**9. [최상]** "실행계획이 다르게 나온다"는 사실과 "실제 성능이 다르다"는 사실은 항상
같이 가는 것이 아니다. 이번 챕터의 사례(HOSP_ID=1, HOSP_ID=500)에서 두 SQL의 Buffers는
동일하게 3,090이었다는 점을 근거로, E-Rows가 다르게 나온 것이 실제 이 두 조회의 물리적
비용(Buffers)에는 왜 영향을 주지 못했는지 설명하시오.

**10. [최상]** 리터럴 SQL을 계속 다른 값으로 반복 실행하면 공유 풀에 SQL_ID가 계속
쌓인다. 이것이 실무에서 어떤 문제로 이어질 수 있을지(메모리 관점, 파싱 부하 관점에서)
추론하시오. 이 문제를 근본적으로 완화하는 방법(바인드 변수 사용)을 이미 이번 챕터에서
확인했지만, 바인드 변수 사용이 6번 문항에서처럼 항상 좋기만 한 것은 아니라는 점까지
포함해 종합적으로 서술하시오.
