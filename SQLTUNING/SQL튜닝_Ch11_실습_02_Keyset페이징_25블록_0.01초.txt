 Ch11 실습 02 — Keyset 페이징: "마지막으로 본 값" 으로 들어가면 25 Buffers, 0.01초
 목표: OFFSET 280,000 과 같은 깊이를 WHERE receipt_date < :last_seen 으로 조회해 INDEX RANGE SCAN DESCENDING
       + WINDOW NOSORT STOPKEY 로 20건만 읽고 멈추는 것을 실측한다(3,090 → 25). 바인드 자료형을 문자열로 줘
       인덱스를 못 타는 이상 징후를 재현·교정한다(Ch06 의 묵시적 형변환이 페이징에서 재발).
 환경: non-CDB=orcl 19.3, 스키마 SQLT. 실습 01 의 IX_RECEIPT 가 있는 상태.
 주의: 개인 실습 환경 전용.
================================================================================

$ sqlplus sqlt/sqlt@orcl

SQLT@orcl> SET LINESIZE 200
SQLT@orcl> SET PAGESIZE 100

--------------------------------------------------------------------------------
-- [1] (준비) OFFSET 280,000 페이지의 마지막 값을 구한다 — Keyset 의 커서
--------------------------------------------------------------------------------
SQLT@orcl> SELECT receipt_date FROM medical_claims ORDER BY receipt_date DESC
  2       OFFSET 279999 ROWS FETCH NEXT 1 ROWS ONLY;

RECEIPT_DATE
------------
<환경값>                                                  -- 예: 2024-01-1x

SQLT@orcl> -- 실제 화면에서는 이 값을 "직전 페이지의 마지막 행" 에서 받는다. 여기서는 실측 비교를 위해 구했다.
SQLT@orcl> VARIABLE last_seen VARCHAR2(20)
SQLT@orcl> EXEC :last_seen := '<환경값을 YYYY-MM-DD 로>'

--------------------------------------------------------------------------------
-- [2] (이상 징후 → 원인 → 조치) 문자열 바인드 — 인덱스를 못 탄다
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ claim_id, receipt_date
  2       FROM   medical_claims
  3       WHERE  receipt_date < :last_seen
  4       ORDER  BY receipt_date DESC
  5       FETCH FIRST 20 ROWS ONLY;
WHERE  receipt_date < :last_seen
                      *
ERROR at line 3:
ORA-01861: literal does not match format string

SQLT@orcl> -- 이상 징후: Ch06 실습 02 와 같은 오류다. (형식이 우연히 맞는 값이면 오류 없이 실행되지만
SQLT@orcl> --   Predicate 에 TO_DATE(:LAST_SEEN) 이 생겨 세션 NLS 에 의존하고, 형식이 어긋난 값이 오면 그때 죽는다.)
SQLT@orcl> -- 원인 파악: VARCHAR2 바인드를 DATE 컬럼과 비교했다. 응용 프로그램이 마지막 값을 문자열로 들고
SQLT@orcl> --   다니다 그대로 바인드하면 정확히 이 상황이 된다.
SQLT@orcl> -- 조치: 바인드 자료형을 컬럼에 맞춘다. SQL*Plus 는 DATE 바인드가 없으므로 TO_DATE(:v, 형식) 으로
SQLT@orcl> --   "값 쪽" 을 변환한다(컬럼을 변환하지 않는다). JDBC 라면 setDate/setTimestamp.
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ claim_id, receipt_date
  2       FROM   medical_claims
  3       WHERE  receipt_date < TO_DATE(:last_seen, 'YYYY-MM-DD')
  4       ORDER  BY receipt_date DESC
  5       FETCH FIRST 20 ROWS ONLY;

20 rows selected.
(출력 생략)

-- 재확인: Buffers 25, A-Time 0.01초. OFFSET 280,000(3,090, 0.18초)과 같은 깊이를 120배 싸게 얻었다.
--   Id 4: 인덱스에서 :last_seen 바로 아래 지점을 찾아 내림차순으로 읽기 시작(access, 값 쪽 변환).
--   Id 2: 인덱스가 이미 정렬돼 있으니 NOSORT, 20건 채우면 STOPKEY 로 중단 — A-Rows 가 전 단계 20.
--   "몇 번째 행인지" 를 셀 필요가 없으니 깊이와 비용이 무관하다. Ch10 실습 03 의 상위 N 원리 그대로.

--   ┌──────────────────────────┬─────────┬─────────┬────────────────────────────┐
--   │ 방식                     │ Buffers │ A-Time  │ 핵심 Operation             │
--   ├──────────────────────────┼─────────┼─────────┼────────────────────────────┤
--   │ OFFSET 280,000 (실습 01) │  3,090  │ 0.18초  │ WINDOW SORT PUSHED RANK    │
--   │ Keyset 같은 깊이         │     25  │ 0.01초  │ WINDOW NOSORT STOPKEY      │
--   └──────────────────────────┴─────────┴─────────┴────────────────────────────┘

-- ※ IX_RECEIPT 는 실습 03 에서 지운다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) Keyset = "마지막으로 본 값보다 작은 것부터 N 건". WHERE 가 생기므로 인덱스가 접근 경로가 된다.
-- 2) INDEX RANGE SCAN DESCENDING + WINDOW NOSORT STOPKEY: 정렬 없이 N 건에서 멈춘다(25 Buffers).
-- 3) 바인드 자료형이 컬럼과 다르면 ORA-01861 또는 TO_DATE(:bind) 로 NLS 의존 — 값 쪽을 변환한다.
-- 4) 인덱스가 있어도 접근 경로가 되려면 WHERE 가 있어야 한다. OFFSET 은 WHERE 를 만들지 않는다.
