 Ch13 실습 03 — 히스토그램 복원(SIZE AUTO)과 통계 이력: 3,285 로 돌아온다, 그리고 되돌리는 두 길
 목표: METHOD_OPT => 'FOR ALL COLUMNS SIZE AUTO' 로 히스토그램을 복원해 HYBRID 254 와 E-Rows 3,285 를
       확인한다. "복원했는데 3,470 이 아니다" 는 이상 징후를 표본 통계로 설명하고, 통계 이력
       (USER_TAB_STATS_HISTORY)과 RESTORE_TABLE_STATS 로 "수집 전 통계로 되돌리는" 두 번째 길을 익힌다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. 실습 02 로 HOSP_ID 히스토그램이 없는 상태에서 시작.
 주의: 개인 실습 환경 전용. 이 실습을 마치면 통계가 원상태(HYBRID 254)여야 한다.

SQLT@orcl> -- 원인 파악: 히스토그램은 표본으로 만든다. 수집할 때마다 표본이 달라 버킷 경계·반복 수가
SQLT@orcl> --   조금씩 다르고, popular value 의 추정치도 그만큼 흔들린다. 3,470 과 3,285 는 둘 다 실제
SQLT@orcl> --   3,058 에 대해 1.07~1.13배 — 같은 자릿수의 정확한 추정이다. 실습 02 의 300 과 비교하면
SQLT@orcl> --   무엇이 "복원" 인지 분명하다.
SQLT@orcl> -- 재확인: 500번 병원도 다시 1번과 다른 값을 받는지 본다(균등 가정 탈출 확인).

--   ├────────────────────────┼──────────────────┼────────────────────┼──────────────┤
--   │ 원본(실습 01)          │      3,470       │       159          │ 다름         │
--   │ 제거 SIZE 1(실습 02)   │        300       │       300          │ 같음(균등)   │
--   │ 복원 SIZE AUTO(실습 03)│      3,285       │     <환경값>       │ 다시 다름    │
--   └────────────────────────┴──────────────────┴────────────────────┴──────────────┘

-- [4] (조치 후 관점) 바인드 변수와 히스토그램 — Ch02 실습 02 의 뒷이야기

-- * 히스토그램이 있는 컬럼을 바인드 변수로 조회하면, 최초 값(peek)으로 만든 계획이 다른 값에도
--   재사용된다. 값에 따라 인덱스/Full Scan 이 갈리는 컬럼이면 한쪽이 손해를 본다.
-- * Oracle 은 이를 적응형 커서 공유(IS_BIND_SENSITIVE/AWARE, Ch04 실습 02)로 완화하지만 "몇 번
--   틀린 뒤" 에야 새 자식 커서를 만든다. 리터럴이 옳은 경우(값 종류가 적고 분포가 극단적)도 있다.
-- * 이 판단(히스토그램 + 바인드 + 커서 공유)은 TUN 7장 실습 02·06 과 TUN 2장 실습 02 로 이어진다.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) FOR ALL COLUMNS SIZE AUTO 가 표준. 사용 이력과 분포를 보고 필요한 컬럼에만 히스토그램을 만든다.
-- 2) 복원 후 3,285 ≠ 3,470 은 표본 오차. 300(균등) 과 비교하면 복원이 맞다.
-- 3) 통계 이력(31일)과 RESTORE_TABLE_STATS 로 "수집 전" 으로 결정적으로 되돌릴 수 있다.
-- 4) 히스토그램 컬럼 + 바인드 변수 = peeking 문제. 리터럴이 옳은 경우도 있다.
-- 5) 이 실습을 마친 뒤 HOSP_ID 는 HYBRID 254 여야 한다. 아니면 Day 6 TUN 7장 실측이 어긋난다.
