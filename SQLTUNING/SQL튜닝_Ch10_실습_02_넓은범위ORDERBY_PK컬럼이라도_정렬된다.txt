 Ch10 실습 02 — 넓은 범위(8.5%)의 ORDER BY: PK 컬럼으로 정렬해도 SORT ORDER BY 가 생긴다 (3,090)
 목표: 1개월 범위(25,406건)를 total_amt(비인덱스)와 claim_id(PK)로 각각 정렬해 두 경우 모두
       SORT ORDER BY + TABLE ACCESS FULL 인 것을 실측한다. "PK 로 정렬했는데 왜 정렬하나" 는 이상 징후를
       Ch04 의 선택도 전환으로 설명하고, +MEMSTATS 로 정렬 작업 영역과 넘침 여부를 본다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. 조회만. 바인드 :end_id 사용.
 주의: 개인 실습 환경 전용.

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 정렬 생략 조건은 두 가지: ① 정렬 컬럼이 인덱스 컬럼 ② 그 인덱스가 실제 접근 경로. 하나라도 빠지면 정렬.
-- 2) 넓은 범위(8.5%)에서는 ②가 깨진다 — Full Scan 은 순서를 보장하지 않으므로 PK 컬럼이라도 정렬.
-- 3) 인덱스를 강제해 정렬을 없애면 읽기가 폭증한다. 정렬 비용(메모리·CPU)과 읽기 비용(Buffers)의 교환.
-- 4) 정렬은 +MEMSTATS 로 본다. (0) 이면 메모리 안, (1)·(2) 면 임시 세그먼트로 넘친 것 — TUN 19장.
