 Ch06 실습 02 — DATE 컬럼: TO_CHAR(컬럼) 가공 vs 범위 조건 — 같은 24,655건, 3,090 vs 68 (ORA-01861 교정)
 목표: RECEIPT_DATE 에 인덱스를 만들고 "이번 달 데이터" 를 TO_CHAR(receipt_date,'YYYYMM')='202406'
       으로 쓴 경우와 범위 조건으로 쓴 경우를 실측한다. 문자열 '2024-06-01' 을 DATE 와 비교하다
       나는 ORA-01861 을 재현하고 DATE 리터럴로 교정한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. NLS_DATE_FORMAT 은 기본(DD-MON-RR)을 가정. DDL 포함.
 주의: 개인 실습 환경 전용. 마지막에 인덱스를 지운다.

-- 재확인: 같은 24,655건, Buffers 3,090 → 68 (45배). access 로 인덱스 안에서 시작점을 찾아 6월 구간만

--   E-Rows 도 25,477 로 실제(24,655)에 근접한다 — 컬럼을 맨몸으로 두면 통계가 살아난다.

--------------------------------------------------------------------------------
-- [3] (조치 후 관점) "다음 달 1일 미만" 으로 쓰는 이유
--------------------------------------------------------------------------------
-- * receipt_date <= DATE '2024-06-30' 은 6월 30일 00:00:00 까지다. 시각이 있는 DATE 면 30일 낮 데이터가
--   빠진다. 상한은 항상 "다음 구간 시작 미만(<)" 으로 쓴다.
-- * BETWEEN 도 같은 함정이 있다(상한 포함). 월·일 경계는 >= 와 < 의 짝으로.
-- * TRUNC(receipt_date) = DATE '…' 도 컬럼 가공이다 — 같은 이유로 인덱스를 못 쓴다.

SQLT@orcl> DROP INDEX ix_receipt;

-- [정리]

-- 1) TO_CHAR(날짜컬럼)='202406' 은 인덱스를 못 쓰고(3,090) 추정도 기본 선택도에 기대 틀리기 쉽다.
-- 2) 범위 조건(>= DATE, < DATE)으로 바꾸면 같은 결과를 68 로 얻는다.
-- 3) DATE 와 문자열 비교는 NLS_DATE_FORMAT 에 의존한다 — ORA-01861. DATE 리터럴로 쓴다.
-- 4) 상한은 "다음 구간 시작 미만". 컬럼은 가공하지 않고 값을 가공한다.
