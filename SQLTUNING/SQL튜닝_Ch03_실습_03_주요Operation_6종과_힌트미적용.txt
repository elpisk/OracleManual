 Ch03 실습 03 — 주요 Operation 6종 관찰 (PK 인덱스만으로) 과 힌트가 무시되는 이상 징후
 목표: 같은 PK 인덱스가 조건 성격에 따라 INDEX UNIQUE / RANGE / FULL / FAST FULL SCAN 으로
       갈리는 것을 Buffers 와 함께 본다. 힌트를 썼는데 계획이 바뀌지 않는 이상 징후를 재현해
       원인(별칭 불일치 — 힌트는 틀려도 오류가 나지 않는다)을 교정한다.
 환경: non-CDB=orcl 19.3, 스키마 SQLT. DDL 변경 없음.
 주의: 개인 실습 환경 전용. 조회만 수행한다.

SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ pat_id, pat_name
  2       FROM   patients WHERE pat_id BETWEEN 100 AND 130;

31 rows selected.
(출력 생략)

SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------------
| Id  | Operation                           | Name        | Starts | E-Rows | A-Rows | Buffers |
------------------------------------------------------------------------------------------------
|   0 | SELECT STATEMENT                    |             |      1 |        |     31 |       9 |
|   1 |  TABLE ACCESS BY INDEX ROWID BATCHED| PATIENTS    |      1 |     31 |     31 |       9 |
|*  2 |   INDEX RANGE SCAN                  | PK_PATIENTS |      1 |     31 |     31 |       4 |

-- 해석: 등치 → UNIQUE SCAN(Buffers 4), 범위 → RANGE SCAN + BATCHED(Buffers 9).
--   BATCHED 는 인덱스에서 모은 ROWID 를 블록 단위로 묶어 표를 읽는 방식이다.

--------------------------------------------------------------------------------
-- [2] (이상 징후 → 원인 → 조치 → 재확인) 힌트를 썼는데 계획이 그대로다
--     Q4. 정렬 결과 상위 5건 — 인덱스 정렬 순서를 그대로 쓰게 INDEX FULL SCAN 을 강제하려 한다
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS INDEX(medical_claims PK_MEDICAL_CLAIMS) */ claim_id
  2       FROM   medical_claims m
  3       ORDER  BY claim_id
  4       FETCH FIRST 5 ROWS ONLY;

CLAIM_ID

SQLT@orcl> -- 이상 징후: INDEX 힌트를 줬는데 INDEX FULL SCAN 이 아니라 FAST FULL SCAN + 정렬(WINDOW
SQLT@orcl> --   SORT)이 나왔고 Buffers 도 1,891 이다. 오류는 나지 않았다.
SQLT@orcl> -- 원인 파악: 힌트 안의 표 이름이 FROM 절과 맞지 않는다. FROM 에 별칭 m 을 줬으면 힌트도
SQLT@orcl> --   별칭 m 으로 써야 한다(medical_claims 라고 쓰면 대상을 못 찾는다). 힌트는 문법이 틀리거나
SQLT@orcl> --   대상을 못 찾아도 오류 없이 조용히 무시된다 — 그래서 반드시 계획으로 검증해야 한다.
SQLT@orcl> --   힌트 보고서로 확인한다(19c: +HINT_REPORT 형식).

SQLT@orcl> -- 조치: 별칭으로 고쳐 쓰고, 오름차순 정렬을 인덱스가 대신하도록 INDEX(m PK_...) 를 준다.
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS INDEX(m PK_MEDICAL_CLAIMS) */ claim_id
  2       FROM   medical_claims m
  3       ORDER  BY claim_id
  4       FETCH FIRST 5 ROWS ONLY;

CLAIM_ID
----------------
<환경값> (5행)

SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------------
| Id  | Operation               | Name              | Starts | E-Rows | A-Rows | Buffers |
------------------------------------------------------------------------------------------------
|   0 | SELECT STATEMENT        |                   |      1 |        |      5 |       4 |
|*  1 |  VIEW                   |                   |      1 |      5 |      5 |       4 |
|*  2 |   WINDOW NOSORT STOPKEY |                   |      1 |    300K|      5 |       4 |
|   3 |    INDEX FULL SCAN      | PK_MEDICAL_CLAIMS |      1 |    300K|      5 |       4 |
------------------------------------------------------------------------------------------------

-- 재확인: INDEX FULL SCAN(정렬된 순서로 읽기) + WINDOW NOSORT STOPKEY(정렬 없이 5건에서 중단).
--   Buffers 1,891 → 4. A-Rows 도 300K → 5 — 필요한 5건만 읽고 멈췄다.
--   힌트 보고서를 다시 보면 U(Unused) 가 사라진다.

--------------------------------------------------------------------------------
-- [3] (조치 후 관점) 집계는 FAST FULL SCAN 이 맞다 — Q5
--------------------------------------------------------------------------------
SQLT@orcl> SELECT /*+ GATHER_PLAN_STATISTICS */ COUNT(claim_id) FROM medical_claims;

COUNT(CLAIM_ID)
---------------
         300000

SQLT@orcl> SELECT * FROM TABLE(DBMS_XPLAN.DISPLAY_CURSOR(NULL, NULL, 'ALLSTATS LAST'));

PLAN_TABLE_OUTPUT
------------------------------------------------------------------------------------------------
| Id  | Operation             | Name              | Starts | E-Rows | A-Rows | Buffers |
------------------------------------------------------------------------------------------------
|   0 | SELECT STATEMENT      |                   |      1 |        |      1 |    1891 |
|   1 |  SORT AGGREGATE       |                   |      1 |      1 |      1 |    1891 |
|   2 |   INDEX FAST FULL SCAN| PK_MEDICAL_CLAIMS |      1 |    300K|    300K|    1891 |
------------------------------------------------------------------------------------------------

-- 해석: COUNT 는 순서가 필요 없다. 인덱스 블록을 다중 블록 읽기로 훑는 FAST FULL SCAN 이 FULL SCAN
--   (단일 블록, 정렬 순서)보다 싸다. 표(3,090)를 읽지 않고 인덱스(1,891)만 읽었다.
--   Q4 처럼 순서가 필요하면 FULL SCAN, Q5 처럼 순서가 필요 없으면 FAST FULL SCAN — 옵티마이저는
--   요구(정렬 여부)에 따라 같은 인덱스를 다르게 읽는다.

--   6종 정리 (이 실습 + 실습 01·02)
--   ┌────┬─────────────────────────────────────┬──────────────────────────────────────┬─────────┐
--   │ #  │ 조건                                │ 핵심 Operation                       │ Buffers │
--   ├────┼─────────────────────────────────────┼──────────────────────────────────────┼─────────┤
--   │ Q1 │ 비인덱스 두 컬럼 (실습 01)          │ TABLE ACCESS FULL                    │  3,117  │
--   │ Q2 │ PK 등치                             │ INDEX UNIQUE SCAN → BY INDEX ROWID   │      4  │
--   │ Q3 │ PK 범위                             │ INDEX RANGE SCAN → ...BATCHED        │      9  │
--   │ Q4 │ ORDER BY PK, 상위 5건 (힌트 교정 후)│ INDEX FULL SCAN + WINDOW NOSORT      │      4  │
--   │ Q5 │ COUNT(PK)                           │ INDEX FAST FULL SCAN + SORT AGGREGATE│  1,891  │
--   │ Q6 │ 조인 + GROUP BY (실습 02)           │ HASH JOIN + HASH GROUP BY            │  3,093  │
--   └────┴─────────────────────────────────────┴──────────────────────────────────────┴─────────┘

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 같은 PK 인덱스도 등치/범위/정렬 활용/집계에 따라 UNIQUE/RANGE/FULL/FAST FULL 로 읽힌다.
-- 2) 힌트는 틀려도 오류가 없다. 별칭을 썼으면 힌트도 별칭으로. 반드시 계획(+HINT_REPORT)으로 검증.
-- 3) INDEX FULL SCAN 은 정렬 순서가 필요할 때, FAST FULL SCAN 은 순서가 필요 없을 때.
-- 4) SELECT 목록이 인덱스 컬럼뿐이면 표를 읽지 않는다(Q4·Q5) — Ch04 의 "Index-Only" 로 이어진다.
