================================================================================
 실습 8-5 : 백업 받지 않은 테이블스페이스를 새 위치로 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 18분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 백업이 없는 테이블스페이스의 데이터파일이 유실되었고 원래 디스크도 쓸 수 없다.
-- CREATE DATAFILE 의 AS 절로 새 위치에 빈 파일을 만든다.
-- 컨트롤파일의 경로가 함께 갱신되므로 RENAME이 필요 없다.
-- 실습 8-4의 변형이며 경로 변경 후속 작업을 함께 다룬다.
-- 복구 유형 : 완전 복구(CREATE DATAFILE + 경로 변경)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 8-4를 마친 상태에서 이어서 진행한다.
-- /u02 파일 시스템에 여유 공간이 있어야 한다.

[oracle@oel7v9r1 ~]$ df -h /u01 /u02

/dev/mapper/ol-u01     40G   19G   21G  48% /u01
/dev/mapper/ol-u02     20G  3.6G   17G  18% /u02

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL name FOR a48

[4] 장애 유발 : 파일 유실과 디스크 사용 불가

-- 실습에서는 디렉터리 권한을 제거해 그 상황을 재현한다.

SYS@orcl> !mkdir -p /u01/app/oracle/oradata/ORCL_ro
SYS@orcl> !chmod 500 /u01/app/oracle/oradata/ORCL_ro

-- 판정
--   ① 백업본 : 없음 → CREATE DATAFILE 경로
--   ② 아카이브 : 연속 보유 → 성립
--   ③ 원래 위치 : 사용 불가 → AS 절로 새 위치 지정
--   → OFFLINE → CREATE DATAFILE AS 새경로 → RECOVER → ONLINE

SYS@orcl> !mkdir -p /u02/oradata/ORCL
SYS@orcl> !ls -ld /u02/oradata/ORCL
drwxr-x---. 2 oracle oinstall 4096 May 11 11:20 /u02/oradata/ORCL

-- 새 위치의 권한과 여유 공간을 미리 확인했다.

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
SYS@orcl> ALTER TABLESPACE tbs02 OFFLINE IMMEDIATE;
Tablespace altered.

-- 쓸 수 없는 디렉터리를 대상으로 시도해 본다.

SYS@orcl> ALTER DATABASE CREATE DATAFILE 12
  2  AS '/u01/app/oracle/oradata/ORCL_ro/tbs02.dbf';
ALTER DATABASE CREATE DATAFILE 12
*
ERROR at line 1:
ORA-01119: error in creating database file
           '/u01/app/oracle/oradata/ORCL_ro/tbs02.dbf'
ORA-27040: file create error, unable to create file
Linux-x86_64 Error: 13: Permission denied

-- << 원인 파악 >>
-- oracle 계정이 그 디렉터리에 쓸 수 없다.
-- CREATE DATAFILE 은 새 파일을 만드는 명령이므로 쓰기 권한이 필요하다.
-- 새 위치를 정할 때는 권한과 여유 공간을 먼저 확인해야 한다.
-- 준비해 둔 /u02/oradata/ORCL 로 대상을 바꾼다.

SYS@orcl> !ls -ld /u01/app/oracle/oradata/ORCL_ro
dr-x------. 2 oracle oinstall 4096 May 11 11:18 /u01/app/oracle/oradata/ORCL_ro

-- << 수정 >>

SYS@orcl> ALTER DATABASE CREATE DATAFILE 12
  2  AS '/u02/oradata/ORCL/tbs02.dbf';

Database altered.

SYS@orcl> SELECT file#, name, status FROM v$datafile WHERE file# = 12;

     FILE# NAME                                       STATUS
---------- ------------------------------------------ -------
        12 /u02/oradata/ORCL/tbs02.dbf                RECOVER

-- 컨트롤파일의 경로가 새 위치로 자동 갱신되었다. RENAME이 필요 없다.

SYS@orcl> SET AUTORECOVERY ON
SYS@orcl> RECOVER TABLESPACE tbs02;
Media recovery complete.

SYS@orcl> ALTER TABLESPACE tbs02 ONLINE;

Tablespace altered.

-- 구조가 바뀌었으므로 컨트롤파일 백업을 다시 받는다.

SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO
  2    '/home/oracle/backup/control_after_ch08_05.bkp';
SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO TRACE
  2    AS '/home/oracle/backup/cf_after_ch08_05.sql';

-- 새 파일의 백업도 받아 둔다.

SYS@orcl> ALTER TABLESPACE tbs02 BEGIN BACKUP;
SYS@orcl> !cp -p /u02/oradata/ORCL/tbs02.dbf /home/oracle/backup/ch08/
SYS@orcl> ALTER TABLESPACE tbs02 END BACKUP;
Tablespace altered.

-- 디스크가 복구되면 원래 위치로 되돌린다(19c 온라인 이동).

SYS@orcl> ALTER DATABASE MOVE DATAFILE
  2    '/u02/oradata/ORCL/tbs02.dbf'
  3  TO '/u01/app/oracle/oradata/ORCL/tbs02.dbf';

Database altered.

SYS@orcl> SELECT file#, name, status FROM v$datafile WHERE file# = 12;

     FILE# NAME                                       STATUS
---------- ------------------------------------------ -------

SYS@orcl> !ls /u02/oradata/ORCL/tbs02.dbf
ls: cannot access '/u02/oradata/ORCL/tbs02.dbf': No such file or directory

-- KEEP 옵션을 붙이지 않아 원본이 삭제되었다. 서비스는 중단되지 않았다.

SYS@orcl> !chmod 700 /u01/app/oracle/oradata/ORCL_ro
SYS@orcl> !rmdir /u01/app/oracle/oradata/ORCL_ro

-- 실습 정리를 마쳤다.

-- 실무 포인트
-- 1) CREATE DATAFILE 의 AS 절로 새 위치를 지정하면 경로가 자동 갱신된다.
--    별도의 RENAME FILE 이 필요 없다는 점이 복원 후 RENAME 하는 경우와 다르다.
--
-- 2) 새 위치는 권한과 여유 공간을 먼저 확인한다.
--    쓸 수 없는 디렉터리를 지정하면 ORA-01119와 ORA-27040이 발생한다.
--    Linux 오류 번호 13은 Permission denied 를 뜻한다.
--
-- 3) 경로가 바뀌면 체계가 어긋난다.
--    백업 스크립트, 매니페스트, 모니터링 대상에 새 경로를 반영해야 한다.
--    반영하지 않으면 다음 백업이 조용히 실패한다.
--
-- 4) 구조가 바뀌었으므로 컨트롤파일 백업을 즉시 다시 받는다.
--    6장과 7장에서 반복한 원칙이 여기서도 그대로 적용된다.
--
-- 5) 임시 위치는 나중에 MOVE DATAFILE 로 정리한다.
--    19c에서는 온라인으로 옮길 수 있어 서비스 중단 없이 체계를 되돌릴 수 있다.
--    KEEP 옵션을 붙이지 않으면 원본이 삭제된다.
--
-- 6) 새로 만든 테이블스페이스는 그 자리에서 첫 백업을 받아 둔다.
--    이 실습의 모든 절차는 백업이 없었기 때문에 필요했던 것이다.

SYS@orcl> EXIT
