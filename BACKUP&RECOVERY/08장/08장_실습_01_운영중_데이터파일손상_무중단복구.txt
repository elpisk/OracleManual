 실습 8-1 : 운영 중 데이터파일 손상 — 무중단 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 20분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 운영 중 사용자 테이블스페이스의 데이터파일이 유실되었다.
-- ARCHIVELOG 모드이므로 Oracle이 그 파일을 자동으로 OFFLINE 처리한다.
-- 데이터베이스를 한 번도 내리지 않고 복원·복구해 되돌린다.
-- 이 장의 표준 절차이며 나머지 실습은 모두 이 절차의 변형이다.
-- 복구 유형 : 완전 복구(무중단)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- ARCHIVELOG 모드여야 하며 아카이브 대상에 여유 공간이 있어야 한다.
-- 실습 전 Hot Backup 또는 Cold Backup을 받아 둔다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> COL name FOR a48

[3] 초기 상태 확인 : 백업과 실습 데이터
--------------------------------------------------------------------------------
SYS@orcl> !mkdir -p /home/oracle/backup/ch08

SYS@orcl> ALTER TABLESPACE users BEGIN BACKUP;
Tablespace altered.

SYS@orcl> !cp -p /u01/app/oracle/oradata/ORCL/users01.dbf /home/oracle/backup/ch08/

SYS@orcl> ALTER TABLESPACE users END BACKUP;
Tablespace altered.

-- 열린 상태에서 받은 Hot Backup이다.

SYS@orcl> CREATE TABLE hr.emp81 TABLESPACE users
  2  AS SELECT ROWNUM AS id, object_name FROM dba_objects WHERE ROWNUM <= 1000;
Table created.

SYS@orcl> COMMIT;
SYS@orcl> SELECT COUNT(*) FROM hr.emp81;

  COUNT(*)
----------
      1000

-- 백업 이후 커밋한 데이터다. 완전 복구되면 살아 있어야 한다.

SYS@orcl> ALTER SYSTEM SWITCH LOGFILE;
SYS@orcl> ALTER SYSTEM ARCHIVE LOG CURRENT;
System altered.

SYS@orcl> SELECT sequence#, status FROM v$archived_log
  2  ORDER BY sequence# DESC FETCH FIRST 3 ROWS ONLY;

 SEQUENCE# S
---------- -
        21 A
        20 A
        19 A

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 파일을 복원하고 바로 복구를 시도한다.

SYS@orcl> !cp -p /home/oracle/backup/ch08/users01.dbf /u01/app/oracle/oradata/ORCL/

SYS@orcl> RECOVER TABLESPACE users;
ORA-00283: recovery session canceled due to errors
ORA-01124: cannot recover data file 7 - file is in use or recovery
ORA-01110: data file 7: '/u01/app/oracle/oradata/ORCL/users01.dbf'

-- << 원인 파악 >>
-- 파일이 여전히 데이터베이스에 붙어 있는 상태다.
-- Oracle은 사용 중인 파일에 리두를 적용하지 않는다. 일관성이 깨지기 때문이다.
-- 열린 상태에서 복구하려면 대상을 먼저 OFFLINE 으로 내려야 한다.
-- 이 제약에서 OFFLINE → 복원 → RECOVER → ONLINE 이라는 표준 절차가 나온다.

SYS@orcl> ALTER TABLESPACE users OFFLINE NORMAL;
ALTER TABLESPACE users OFFLINE NORMAL
*
ERROR at line 1:
ORA-01191: file 7 is already offline - cannot do a normal offline
ORA-01110: data file 7: '/u01/app/oracle/oradata/ORCL/users01.dbf'

-- NORMAL은 체크포인트를 수행하려 하는데 이미 문제가 있는 파일이라 실패한다.

-- << 수정 >>

SYS@orcl> ALTER TABLESPACE users OFFLINE IMMEDIATE;

Tablespace altered.

SYS@orcl> SELECT file#, status FROM v$datafile WHERE file# = 7;

     FILE# STATUS
---------- -------
         7 OFFLINE

SYS@orcl> SET AUTORECOVERY ON
SYS@orcl> RECOVER TABLESPACE users;
Media recovery complete.

-- 프롬프트 없이 완료되었다. 아카이브 경로가 자동으로 계산되었다.

SYS@orcl> ALTER TABLESPACE users ONLINE;

Tablespace altered.

--------------------------------------------------------------------------------

-- 백업 이후 커밋한 데이터가 살아 있다. 완전 복구가 성공했다.

SYS@orcl> SELECT resetlogs_change#, resetlogs_time FROM v$database;

RESETLOGS_CHANGE# RESETLOGS_TIME
----------------- ---------------------
                1 08-MAY-25

-- RESETLOGS 이력이 늘지 않았다. 인카네이션이 그대로다.
-- 4~7장에서 RESETLOGS가 강제되던 상황과 대비된다.

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
OPEN

-- 데이터베이스를 한 번도 내리지 않았다.

SYS@orcl> ALTER SYSTEM SWITCH LOGFILE;
SYS@orcl> ALTER SYSTEM ARCHIVE LOG CURRENT;
System altered.

SYS@orcl> SELECT sequence#, status FROM v$archived_log
  2  ORDER BY sequence# DESC FETCH FIRST 2 ROWS ONLY;

 SEQUENCE# S
---------- -
        23 A
        22 A

SYS@orcl> !df -h /u02/arch1
Filesystem            Size  Used Avail Use% Mounted on
/dev/mapper/ol-u02     20G  3.4G   17G  17% /u02

-- 아카이브가 정상 생성되고 여유 공간도 충분하다.

-- 실무 포인트
-- 1) ARCHIVELOG 모드에서는 손상된 파일이 자동으로 OFFLINE 처리된다.
--    v$datafile의 STATUS가 RECOVER로 바뀌는 것이 그 신호다.
--    덕분에 손상 범위가 그 파일에 든 객체로 제한되고 나머지는 계속 서비스된다.
--
-- 2) 복구하려면 대상을 먼저 OFFLINE 으로 내려야 한다.
--    사용 중인 파일에는 리두를 적용할 수 없기 때문이며 ORA-01124나 ORA-01121이 나온다.
--    이 제약에서 OFFLINE → 복원 → RECOVER → ONLINE 이라는 표준 절차가 도출된다.
--
-- 3) 손상된 파일에는 OFFLINE IMMEDIATE 를 쓴다.
--    NORMAL은 체크포인트를 시도하다 실패한다. 선택의 여지가 없다.
--
-- 4) 복구 전 아카이브 연속성을 먼저 검증한다.
--    v$recover_file 의 CHANGE# 를 포함하는 시퀀스부터 현재까지가 필요한 구간이다.
--    중간이 빠지면 복구 도중 멈추므로 시작 전에 확인하는 편이 낫다.
--
-- 5) 마지막 ONLINE을 잊지 않는다.
--    '복구했는데 여전히 조회가 안 된다'는 신고의 가장 흔한 원인이다.
--
-- 6) 검증에 아카이브 생성 확인을 포함한다.
--    복구 중 아카이브 대상이 가득 찼다면 몇 시간 뒤 ORA-00257로 다시 멈춘다.

SYS@orcl> EXIT
