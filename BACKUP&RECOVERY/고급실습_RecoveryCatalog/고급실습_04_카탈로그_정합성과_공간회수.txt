================================================================================
 고급 실습 04 : 카탈로그·컨트롤파일 불일치 해소와 백업 공간 회수
 과정      : Oracle Database 19c Backup & Recovery — Recovery Catalog 고급
 환경      : Oracle 19.3.0 / Oracle Linux 7 / oel7v9r1(운영계) + oel7v9r2(관리계)
 대상 DB   : orcl, sales (oel7v9r1) / hrdb (oel7v9r2)
 카탈로그  : rcat @ oel7v9r2
 소요 시간 : 약 2시간 30분
 선행 조건 : 고급 실습 01~03 완료
================================================================================

--------------------------------------------------------------------------------
[1] 실무 상황
--------------------------------------------------------------------------------
-- 백업 파일 시스템이 91% 찼다는 경보가 왔다.
--
-- 담당자가 이미 시도한 것들
--   ① DELETE OBSOLETE 를 돌렸다 → "no obsolete backups found"
--   ② 오래된 파일을 눈으로 골라 rm 으로 지웠다 → 공간은 줄었다
--   ③ 그런데 LIST BACKUP 에는 지운 파일이 그대로 보인다
--   ④ 지난주 테이프로 옮긴 백업이 어떻게 처리되었는지 모른다
--
-- 그리고 더 심각한 것이 하나 있다.
--   지난달 nocatalog 로 받은 백업이 있었는데
--   컨트롤파일에서도 카탈로그에서도 찾을 수 없다.
--   파일은 /backup 아래에 그대로 있다.
--
-- 요구 사항
--   ① 공간을 안전하게 회수한다. 필요한 백업은 절대 지우지 않는다
--   ② 카탈로그 기록과 실제 파일을 일치시킨다
--   ③ 저장소에서 사라진 기록을 되살린다
--   ④ 같은 상황이 반복되지 않도록 정기 작업을 만든다
--
-- 13.5절에서 CROSSCHECK 와 DELETE 를 다뤘다.
-- 이 실습에서는 다중 DB 환경에서 그것을 안전하게 운영하는 절차를 만든다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 네 가지 상태를 구분한다
--
--   상태        | 뜻                              | 판정 명령      | 조치
--   ------------|---------------------------------|----------------|-------------
--   AVAILABLE   | 기록도 있고 파일도 있다         | (기본)         | 없음
--   EXPIRED     | 기록은 있는데 파일이 없다       | CROSSCHECK     | DELETE EXPIRED
--   OBSOLETE    | 보존 정책상 더 이상 필요 없다   | REPORT OBSOLETE| DELETE OBSOLETE
--   UNAVAILABLE | 사람이 일시적으로 제외 표시함   | (수동 지정)    | 확인 후 복원
--
--   가장 흔한 오해
--     EXPIRED 는 "오래되었다"는 뜻이 아니다. "파일이 없다"는 뜻이다.
--     OBSOLETE 는 파일 유무와 무관하다. 보존 정책만 본다.
--     둘은 완전히 다른 축이며 동시에 성립할 수 있다.

-- 2-2. 처리 순서와 그 이유
--
--   ① 보존 정책 확인          — 정책이 없으면 OBSOLETE 판정 자체가 안 된다
--   ② 저장 장치 마운트 확인    — 안 되어 있으면 CROSSCHECK 가 전량 EXPIRED 로 만든다
--   ③ CROSSCHECK              — 기록과 파일을 대조한다
--   ④ EXPIRED 목록 검토       — 지우기 전에 사람이 본다
--   ⑤ DELETE EXPIRED          — 기록만 지운다. 파일은 이미 없다
--   ⑥ REPORT OBSOLETE         — 지울 대상을 미리 본다
--   ⑦ DELETE OBSOLETE         — 기록과 파일을 함께 지운다
--   ⑧ CATALOG START WITH      — 기록 없는 파일을 되찾는다
--   ⑨ RESTORE PREVIEW 로 검증 — 지운 뒤에도 복구 가능한지 확인
--
--   ②가 이 순서에서 가장 중요하다. 이 단계를 건너뛰면 사고가 난다.

-- 2-3. 안전 원칙
--
--   원칙 1. CROSSCHECK 전에 반드시 마운트 상태를 확인한다
--   원칙 2. DELETE EXPIRED 전에 목록을 사람이 검토한다
--   원칙 3. DELETE OBSOLETE 는 REPORT OBSOLETE 로 먼저 확인한다
--   원칙 4. KEEP 이 걸린 백업은 보존 정책의 대상이 아니다 (실습 06)
--   원칙 5. 작업 후 RESTORE PREVIEW 로 복구 가능성을 재확인한다
--
--   지워도 되는 것과 지우면 안 되는 것을 판별하는 기준은
--   "지금 시점에서 복구 목표 기간까지 되돌아갈 수 있는가"이다.

-- 2-4. 두 저장소의 수명 차이
--
--   컨트롤파일 : CONTROL_FILE_RECORD_KEEP_TIME 일 (기본 7)
--                순환 재사용 영역이므로 오래된 기록이 덮인다
--   카탈로그   : 명시적으로 지울 때까지 유지
--
--   이 차이 때문에 카탈로그가 필요하다.
--   보존 기간이 7일을 넘는 정책이라면 카탈로그 없이는 성립하지 않는다.

  2  FROM   dba_segments WHERE owner = 'RCATOWNER'

-- 7-1. rc_maint_crosscheck.sh — 안전장치가 있는 정기 정리
--
-- 고급 실습 03의 gs_maint_obsolete 스크립트를 그대로 돌리면
-- 오류 ②의 사고를 막지 못한다. 실행기에 검사를 넣는다.

[oracle@oel7v9r1 ~]$ cat /home/oracle/rcadm/rc_maint_crosscheck.sh

#!/bin/bash
# 정기 정합성 점검과 공간 회수
# 사용법 : rc_maint_crosscheck.sh <ORACLE_SID>
set -u
SID=$1
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
CATALOG="rcatowner/oracle_4U@rcat"
BKDIR=/backup/$(echo $SID | tr 'a-z' 'A-Z')
LOG=/home/oracle/rcadm/log/maint_${SID}_$(date +%Y%m%d).log
MAILTO="dba-team@example.com"

# --- 안전장치 1 : 마운트와 쓰기 가능 여부 (오류 ② 재발 방지)
if ! mountpoint -q /backup; then
  echo "[ABORT] /backup is not mounted - skipping crosscheck" | tee -a $LOG
  mailx -s "[ABORT] maint skipped - /backup not mounted ($SID)" $MAILTO < $LOG
  exit 2
fi
if ! touch $BKDIR/.mnt_$$ 2>/dev/null; then
  echo "[ABORT] $BKDIR not writable - skipping crosscheck" | tee -a $LOG
  mailx -s "[ABORT] maint skipped - path not writable ($SID)" $MAILTO < $LOG
  exit 2
fi
rm -f $BKDIR/.mnt_$$

# --- 안전장치 2 : 보존 정책이 설정되어 있는가 (오류 ① 재발 방지)
POLICY=$(rman target / catalog $CATALOG << EOF 2>/dev/null | grep 'RETENTION POLICY'
SHOW RETENTION POLICY;
EXIT
EOF
)
if echo "$POLICY" | grep -q 'TO NONE'; then
  echo "[ABORT] retention policy is NONE - fix configuration first" | tee -a $LOG
  mailx -s "[ABORT] retention policy NONE ($SID)" $MAILTO < $LOG
  exit 2
fi

# --- 1단계 : 대조와 목록화 (지우지 않는다)
rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
CROSSCHECK BACKUP;
CROSSCHECK ARCHIVELOG ALL;
LIST EXPIRED BACKUP SUMMARY;
REPORT OBSOLETE;
EXIT
EOF

# --- 안전장치 3 : EXPIRED 가 전체의 50%를 넘으면 멈춘다
TOTAL=$(grep -c 'crosschecked backup piece' $LOG)
EXPCNT=$(grep -c "found to be 'EXPIRED'" $LOG)
if [ $TOTAL -gt 0 ] && [ $((EXPCNT * 100 / TOTAL)) -ge 50 ]; then
  echo "[ABORT] EXPIRED ratio ${EXPCNT}/${TOTAL} too high - manual review" >> $LOG
  mailx -s "[ABORT] abnormal EXPIRED ratio ($SID)" $MAILTO < $LOG
  exit 2
fi

# --- 2단계 : 실제 삭제
rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
DELETE NOPROMPT EXPIRED BACKUP;
DELETE NOPROMPT EXPIRED ARCHIVELOG ALL;
DELETE NOPROMPT OBSOLETE;
EXIT
EOF

# --- 3단계 : 복구 가능성 재확인 (원칙 5)
rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
RESTORE DATABASE PREVIEW SUMMARY;
REPORT NEED BACKUP;
EXIT
EOF

if grep -qE 'RMAN-060(23|26)' $LOG; then
  echo "[FATAL] restore path broken after cleanup" >> $LOG
  mailx -s "[FATAL] restore path broken after cleanup ($SID)" $MAILTO < $LOG
  exit 1
fi

df -h /backup >> $LOG
echo "[OK] maintenance completed for $SID"
exit 0

--
-- 과제 A. EXPIRED 비율 임계값 정하기
--   7-1의 안전장치 3은 50%를 기준으로 삼았다.

--
-- 과제 B. 삭제 이력 추적
--   지난 30일간 어떤 DELETE 작업이 수행되었는지 조회하시오.
--   rc_rman_status 의 operation 컬럼을 사용한다.
--   누가 실행했는지까지 추적하려면 무엇이 추가로 필요한지 서술하시오.
--
-- 과제 C. 테이프로 옮긴 백업의 처리
--   디스크의 백업을 테이프로 옮긴 뒤 디스크에서 지웠다.
--   이때 CROSSCHECK 를 돌리면 EXPIRED 가 되고 DELETE EXPIRED 로 기록이 사라진다.
--   테이프의 백업을 계속 인식시키려면 어떻게 해야 하는지 설계하시오.
--   힌트 : SBT 채널 설정과 CHANGE ... UNAVAILABLE 을 비교 검토한다.
--
-- 과제 D. 보존 정책 두 종류의 비교
--   RECOVERY WINDOW 와 REDUNDANCY 를 같은 DB에 번갈아 적용하고
--   REPORT OBSOLETE 결과가 어떻게 달라지는지 비교하시오.
--   어떤 상황에서 어느 쪽이 적합한지 판단 기준을 정리한다.
--
-- 과제 E. 카탈로그 스키마 증가 예측
--   AL 세그먼트의 증가 속도를 측정하고 1년 뒤 크기를 예측하시오.
--   아카이브 로그 생성량과의 상관관계를 확인한다.
--   테이블스페이스 확장 계획을 제안한다.

-- 7-5. 정리 — 이 실습에서 남는 것
--
--   ① rc_maint_crosscheck.sh : 안전장치 3중을 갖춘 정기 정리
--   ② rc_find_orphan.sh      : 기록 없는 파일 탐지
--   ③ 상태 구분표            : [2-1]의 네 가지 상태
--   ④ 처리 순서와 안전 원칙  : [2-2], [2-3]
--   ⑤ 정리 전후 비교표       : [6-5]
--
-- 다음 예제에서는 이 모든 것의 근간인 카탈로그 자체를 보호한다.

-- 실무 포인트
-- 1) EXPIRED 와 OBSOLETE 는 다른 축이다.
--    EXPIRED 는 파일 부재, OBSOLETE 는 보존 정책이다.
--    공간을 회수하는 것은 DELETE OBSOLETE 이고
--    DELETE EXPIRED 는 기록만 정리한다.
--
-- 2) 보존 정책이 NONE 이면 아무것도 지워지지 않는다.
--    오류 없이 "no obsolete backups found" 로 끝나므로 알아채기 어렵다.
--    출력의 "retention policy is set to" 줄을 반드시 읽는다.
--

-- 4) 정리 작업은 반드시 두 단계로 나눈다.
--    1단계에서 대조와 목록화만 하고, 이상 여부를 판정한 뒤 2단계에서 지운다.
--    한 스크립트에서 CROSSCHECK 와 DELETE 를 연달아 실행하지 않는다.

--    이 확인이 없으면 장애가 나서야 알게 된다.
--
-- 6) 기록 없는 파일은 CATALOG START WITH 로 되찾는다.

--    되찾은 뒤에는 RESTORE ... VALIDATE 로 실제 읽히는지 확인한다.
