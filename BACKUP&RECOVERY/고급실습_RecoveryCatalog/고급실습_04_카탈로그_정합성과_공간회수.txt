================================================================================
 고급 실습 04 : 카탈로그·컨트롤파일 불일치 해소와 백업 공간 회수
 과정      : Oracle Database 19c Backup & Recovery — Recovery Catalog 고급
 환경      : Oracle 19.3.0 / Oracle Linux 7 / oel7v9(운영계) + oel7v9r2(관리계) / ARCHIVELOG
 대상 DB   : orcl, sales (oel7v9) / hrdb (oel7v9r2)
 카탈로그  : rcat @ oel7v9r2
 소요 시간 : 약 2시간 30분
 선행 조건 : 고급 실습 01~03 완료
================================================================================

--------------------------------------------------------------------------------
[1] 실무 상황
--------------------------------------------------------------------------------
-- 백업 파일 시스템이 91% 찼다는 경보가 왔다.
--
-- 담당자가 이미 시도한 것들
--   ① DELETE OBSOLETE 를 돌렸다 → "no obsolete backups found"
--   ② 오래된 파일을 눈으로 골라 rm 으로 지웠다 → 공간은 줄었다
--   ③ 그런데 LIST BACKUP 에는 지운 파일이 그대로 보인다
--   ④ 지난주 테이프로 옮긴 백업이 어떻게 처리되었는지 모른다
--
-- 그리고 더 심각한 것이 하나 있다.
--   지난달 nocatalog 로 받은 백업이 있었는데
--   컨트롤파일에서도 카탈로그에서도 찾을 수 없다.
--   파일은 /backup 아래에 그대로 있다.
--
-- 요구 사항
--   ① 공간을 안전하게 회수한다. 필요한 백업은 절대 지우지 않는다
--   ② 카탈로그 기록과 실제 파일을 일치시킨다
--   ③ 저장소에서 사라진 기록을 되살린다
--   ④ 같은 상황이 반복되지 않도록 정기 작업을 만든다
--
-- 13장 실습 5·6 에서 CROSSCHECK 와 DELETE 를 다뤘다.
-- 이 실습에서는 다중 DB 환경에서 그것을 안전하게 운영하는 절차를 만든다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 네 가지 상태를 구분한다
--
--   상태        | 뜻                              | 판정 명령      | 조치
--   ------------|---------------------------------|----------------|-------------
--   AVAILABLE   | 기록도 있고 파일도 있다         | (기본)         | 없음
--   EXPIRED     | 기록은 있는데 파일이 없다       | CROSSCHECK     | DELETE EXPIRED
--   OBSOLETE    | 보존 정책상 더 이상 필요 없다   | REPORT OBSOLETE| DELETE OBSOLETE
--   UNAVAILABLE | 사람이 일시적으로 제외 표시함   | (수동 지정)    | 확인 후 복원
--
--   가장 흔한 오해
--     EXPIRED 는 "오래되었다"는 뜻이 아니다. "파일이 없다"는 뜻이다.
--     OBSOLETE 는 파일 유무와 무관하다. 보존 정책만 본다.
--     둘은 완전히 다른 축이며 동시에 성립할 수 있다.

-- 2-2. 처리 순서와 그 이유
--
--   ① 보존 정책 확인          — NONE 이면 판정 자체가 거부되고(RMAN-06525), 너무 길면 아무것도 지워지지 않는다
--   ② 저장 장치 마운트 확인    — 안 되어 있으면 CROSSCHECK 가 전량 EXPIRED 로 만든다
--   ③ CROSSCHECK              — 기록과 파일을 대조한다
--   ④ EXPIRED 목록 검토       — 지우기 전에 사람이 본다
--   ⑤ DELETE EXPIRED          — 기록만 지운다. 파일은 이미 없다
--   ⑥ REPORT OBSOLETE         — 지울 대상을 미리 본다
--   ⑦ DELETE OBSOLETE         — 기록과 파일을 함께 지운다
--   ⑧ CATALOG START WITH      — 기록 없는 파일을 되찾는다
--   ⑨ RESTORE PREVIEW 로 검증 — 지운 뒤에도 복구 가능한지 확인
--
--   ②가 이 순서에서 가장 중요하다. 이 단계를 건너뛰면 사고가 난다.

-- 2-3. 안전 원칙
--
--   원칙 1. CROSSCHECK 전에 반드시 마운트 상태를 확인한다
--   원칙 2. DELETE EXPIRED 전에 목록을 사람이 검토한다
--   원칙 3. DELETE OBSOLETE 는 REPORT OBSOLETE 로 먼저 확인한다
--   원칙 4. KEEP 이 걸린 백업은 보존 정책의 대상이 아니다 (실습 06)
--   원칙 5. 작업 후 RESTORE PREVIEW 로 복구 가능성을 재확인한다
--
--   지워도 되는 것과 지우면 안 되는 것을 판별하는 기준은
--   "지금 시점에서 복구 목표 기간까지 되돌아갈 수 있는가"이다.

-- 2-4. 두 저장소의 수명 차이
--
--   컨트롤파일 : CONTROL_FILE_RECORD_KEEP_TIME 일 (기본 7)
--                순환 재사용 영역이므로 오래된 기록이 덮인다
--   카탈로그   : 명시적으로 지울 때까지 유지
--
--   이 차이 때문에 카탈로그가 필요하다.
--   보존 기간이 7일을 넘는 정책이라면 카탈로그 없이는 성립하지 않는다.

#   RMAN 은 "접근 불가"와 "파일 없음"을 구분하지 못한다.
# ---------------------------------------------------------------------------
#   mountpoint 는 BKROOT 가 심볼릭 링크이거나 마운트 안의 하위 디렉터리면 실패한다.
#   대신 "BKROOT 가 루트 파일시스템 위에 있으면 마운트가 빠진 것" 으로 판정한다.
MNT=$(df -P "$BKROOT" 2>/dev/null | awk 'NR==2{print $6}')
if [ -z "$MNT" ] || [ "$MNT" = "/" ]; then
  log "[ABORT] $BKROOT is not on a mounted backup filesystem (mount=${MNT:-none}) - skipping crosscheck"
  mailx -s "[ABORT] maint skipped - not mounted ($SID)" "$MAILTO" < "$LOG"
  exit 2
fi
if [ ! -d "$BKDIR" ] || ! touch "$BKDIR/.mnt_$$" 2>/dev/null; then
  log "[ABORT] $BKDIR not writable - skipping crosscheck"
# ---------------------------------------------------------------------------
# 안전장치 2 : 보존 정책 확인
# ---------------------------------------------------------------------------
POLICY=$(rman target / catalog $CATALOG 2>/dev/null << 'EOF' | grep 'RETENTION POLICY'
SHOW RETENTION POLICY;
EXIT
EOF
# ---------------------------------------------------------------------------
# 1단계 : 대조와 목록화 — 지우지 않는다
# ---------------------------------------------------------------------------
log "=== stage 1 : crosscheck and report ==="
rman target / catalog $CATALOG >> "$LOG" 2>&1 << 'EOF'
CROSSCHECK BACKUP;
CROSSCHECK ARCHIVELOG ALL;
LIST EXPIRED BACKUP SUMMARY;
REPORT OBSOLETE;
EXIT
EOF

# ---------------------------------------------------------------------------
# 안전장치 3 : EXPIRED 비율 이상 감지
# ---------------------------------------------------------------------------
# 2단계 : 실제 삭제
#   DELETE EXPIRED   기록만 정리한다 (파일은 이미 없다)
#   DELETE OBSOLETE  기록과 파일을 함께 지운다 (공간이 회수된다)
# ---------------------------------------------------------------------------
log "=== stage 2 : delete ==="
rman target / catalog $CATALOG >> "$LOG" 2>&1 << 'EOF'
DELETE NOPROMPT EXPIRED BACKUP;
DELETE NOPROMPT EXPIRED ARCHIVELOG ALL;
DELETE NOPROMPT OBSOLETE;
EXIT
EOF
# 3단계 : 복구 가능성 재확인
# ---------------------------------------------------------------------------
log "=== stage 3 : verify restore path ==="
rman target / catalog $CATALOG >> "$LOG" 2>&1 << 'EOF'
RESTORE DATABASE PREVIEW SUMMARY;
REPORT NEED BACKUP;
EXIT

--   테이프의 백업을 계속 인식시키려면 어떻게 해야 하는지 설계하시오.

-- 7-5. 정리 — 이 실습에서 남는 것
--
--   ① rc_maint_crosscheck.sh : 안전장치 3중을 갖춘 정기 정리
--   ② rc_find_orphan.sh      : 기록 없는 파일 탐지
--   ③ 상태 구분표            : [2-1]의 네 가지 상태
--   ④ 처리 순서와 안전 원칙  : [2-2], [2-3]
--   ⑤ 정리 전후 비교표       : [6-5]
--
-- 다음 예제에서는 이 모든 것의 근간인 카탈로그 자체를 보호한다.

-- 실무 포인트
-- 1) EXPIRED 와 OBSOLETE 는 다른 축이다.
--    EXPIRED 는 파일 부재, OBSOLETE 는 보존 정책이다.
--    공간을 회수하는 것은 DELETE OBSOLETE 이고
--    DELETE EXPIRED 는 기록만 정리한다.
--
-- 2) 보존 정책이 NONE 이면 REPORT/DELETE OBSOLETE 가 RMAN-06525 로 멈춘다.
--    조용히 지나가는 쪽은 정책이 너무 긴 경우다. "no obsolete backups found" 로 끝나므로 알아채기 어렵다.
--    출력의 "retention policy is set to" 줄을 반드시 읽는다.
--
-- 3) CROSSCHECK 전에 마운트를 확인한다.
--    RMAN 은 접근 불가와 파일 부재를 구분하지 못한다.
--    NFS 가 잠깐 끊긴 상태에서 정기 작업이 돌면 전량이 EXPIRED 가 된다.
--    CROSSCHECK 는 되돌릴 수 있지만 DELETE EXPIRED 는 되돌릴 수 없다.
--
-- 4) 정리 작업은 반드시 두 단계로 나눈다.
--    1단계에서 대조와 목록화만 하고, 이상 여부를 판정한 뒤 2단계에서 지운다.
--    한 스크립트에서 CROSSCHECK 와 DELETE 를 연달아 실행하지 않는다.
--
-- 5) 정리 후에는 RESTORE PREVIEW 로 복구 경로를 확인한다.
--    지운 것이 정책상 맞더라도 실제로 복원 가능한지는 별개다.
--    이 확인이 없으면 장애가 나서야 알게 된다.
--
-- 6) 기록 없는 파일은 CATALOG START WITH 로 되찾는다.
--    경로 끝의 / 유무에 따라 대상 범위가 달라진다.
--    되찾은 뒤에는 RESTORE ... FROM TAG ... VALIDATE 로 실제 읽히는지 확인한다.
