[1] 실무 상황
--------------------------------------------------------------------------------
-- 새벽 3시 20분. 운영 서버 oel7v9r1 이 응답하지 않는다.
-- 데이터센터에서 연락이 왔다. 해당 랙의 전원 계통 사고로
-- 서버와 로컬 디스크가 모두 손상되었다. 복구 불가 판정이다.
--
-- 사라진 것
--   - oel7v9r1 서버 전체
--   - /u01/app/oracle/oradata/ORCL/ (모든 데이터파일과 컨트롤파일)
--   - /home/oracle/arch1/ (아카이브 로그)
--   - $ORACLE_HOME/dbs/spfileorcl.ora
--   - 온라인 리두 로그
--
-- 남아 있는 것
--   - oel7v9r2 서버 (rcat, hrdb 가 돌고 있다)
--   - /backup (NFS 원본이 oel7v9r2 에 있어 무사하다)
--   - /archive_keep (별도 스토리지, 무사)
--   - Recovery Catalog (rcat)
--
-- 업무 요구
--   "오전 8시 전까지 orcl 을 되살릴 것. 데이터 손실은 최소화."
--
-- 이 상황에서 카탈로그가 하는 일은 결정적이다.
--   - orcl 의 DBID 를 알려 준다
--   - 데이터파일이 몇 개였고 각각 어느 테이블스페이스였는지 알려 준다
--   - 리두 로그 그룹 구성과 크기를 알려 준다
--   - 어떤 백업으로 어디까지 복구할 수 있는지 알려 준다
--
-- 이 정보 없이는 복구 계획조차 세울 수 없다.
--
-- 요구 사항
--   ① 카탈로그에서 복구에 필요한 정보를 모두 수집한다
--   ② 경로가 완전히 다른 서버에 복구한다
--   ③ 데이터 손실 범위를 정확히 산정하고 보고한다
--   ④ 복구 후 백업 체계를 정상화한다
--   ⑤ 소요 시간을 측정해 RTO 산정 근거로 남긴다

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 카탈로그에서 수집해야 할 정보
--
--   정보              | 조회 대상            | 없으면 생기는 문제
--   ------------------|----------------------|--------------------------
--   DBID              | rc_database          | 자동 백업을 찾지 못한다
--   데이터파일 구성   | rc_datafile          | SET NEWNAME 목록을 못 만든다
--   테이블스페이스    | rc_tablespace        | 구조를 파악할 수 없다
--   리두 로그 구성    | rc_redo_log          | LOGFILE 절을 못 만든다
--   마지막 백업 시각  | rc_backup_set        | 손실 범위를 산정할 수 없다
--   마지막 아카이브   | rc_archived_log      | 복구 종점을 모른다
--   백업 조각 경로    | rc_backup_piece      | 매체를 준비할 수 없다
--   CONFIGURE 설정    | rc_rman_configuration| 채널 구성을 재현할 수 없다
--
--   이 중 DBID 하나만 있어도 시작은 할 수 있다.
--   그러나 계획 수립과 시간 산정에는 나머지가 모두 필요하다.

-- 2-2. 경로 매핑 설계
--
--   구분           | 원본 (oel7v9r1)                  | 대상 (oel7v9r2)
--   ---------------|----------------------------------|---------------------
--   데이터파일     | /u01/app/oracle/oradata/ORCL/    | /u02/oradata/ORCL/
--   온라인 리두    | /u01/app/oracle/oradata/ORCL/    | /u02/oradata/ORCL/
--   컨트롤파일     | /u01/app/oracle/oradata/ORCL/    | /u02/oradata/ORCL/
--   아카이브       | /home/oracle/arch1/              | /u02/arch_orcl/
--   FRA            | /u01/app/oracle/fast_recovery_area | /u02/fra
--   감사 로그      | /u01/app/oracle/admin/orcl/adump | /u02/admin/orcl/adump
--
--   경로 변경 수단 두 가지
--     SET NEWNAME + SWITCH        데이터파일 개별 지정. 정밀하다
--     DB_FILE_NAME_CONVERT        일괄 치환. spfile 파라미터
--
--   이 실습에서는 SET NEWNAME 을 쓴다.
--   재해 상황에서는 원본 경로 구조를 그대로 유지할 수 없는 경우가 많고
--   파일별로 다른 위치에 두어야 할 수도 있다.

-- 2-3. 복구 순서
--
--   ① 카탈로그에서 정보 수집          (10분)
--   ② 대상 서버 준비 — 경로, 비밀번호 파일, 최소 pfile  (10분)
--   ③ NOMOUNT 기동                    (2분)
--   ④ spfile 복원                     (3분)
--   ⑤ spfile 수정 후 재기동           (5분)
--   ⑥ 컨트롤파일 복원 후 MOUNT        (5분)
--   ⑦ SET NEWNAME + RESTORE + SWITCH  (40분)
--   ⑧ RECOVER                         (20분)
--   ⑨ OPEN RESETLOGS                  (5분)
--   ⑩ 리스너·tnsnames·검증            (15분)
--   ⑪ 새 인카네이션 전체 백업         (30분)
--
--   추정 합계 약 2시간 25분. 목표 시각(08시)까지 여유가 있다.

-- 2-4. 데이터 손실 산정 방법
--
--   손실 범위 = 마지막으로 백업된 아카이브 이후의 변경
--
--   온라인 리두 로그가 사라졌으므로
--   백업되지 않은 아카이브와 현재 리두의 내용은 복구할 수 없다.
--   이것이 물리 백업 체계에서 RPO 를 결정하는 지점이다.
--
--   산정에 필요한 두 값
--     ① 마지막으로 백업된 아카이브의 종료 SCN 과 시각
--     ② 장애 발생 시각
--   이 둘의 차이가 손실 구간이다.

-- 7-1. dr_collect_info.sql — 재해 시 정보 수집

[oracle@oel7v9r2 ~]$ cat /home/oracle/rcadm/dr_collect_info.sql

-- 재해 복구 정보 수집
-- 실행 : sqlplus -s rc_report/<pw>@rcat @dr_collect_info.sql <DB_NAME>
SET LINESIZE 200 PAGESIZE 200 FEEDBACK OFF VERIFY OFF TRIMSPOOL ON
DEFINE dbname = &1
SPOOL /tmp/dr_info_&dbname..txt

PROMPT ================================================================
PROMPT  재해 복구 정보 : &dbname
PROMPT ================================================================

PROMPT === 1. DBID 와 인카네이션 (가장 먼저 확보) ===
SELECT dbid, name, dbinc_key,
       TO_CHAR(reset_time,'YYYY-MM-DD HH24:MI:SS') AS reset_time
FROM   rc_database WHERE name = UPPER('&dbname');

PROMPT === 2. 데이터파일 구성 ===
SELECT file#, tablespace_name, ROUND(bytes/1024/1024) AS mb, name
FROM   rc_datafile
WHERE  dbinc_key = (SELECT MAX(dbinc_key) FROM rc_database
                    WHERE name = UPPER('&dbname'))
ORDER  BY file#;

PROMPT === 3. SET NEWNAME 구문 생성 (경로는 수정해서 사용) ===
SELECT '  SET NEWNAME FOR DATAFILE ' || file# ||
       ' TO ''<신규경로>/' || SUBSTR(name, INSTR(name,'/',-1)+1) || ''';'
FROM   rc_datafile
WHERE  dbinc_key = (SELECT MAX(dbinc_key) FROM rc_database
                    WHERE name = UPPER('&dbname'))
ORDER  BY file#;

PROMPT === 4. 리두 로그 구성 ===
SELECT group#, thread#, ROUND(bytes/1024/1024) AS mb, members
FROM   rc_redo_log
WHERE  dbinc_key = (SELECT MAX(dbinc_key) FROM rc_database
                    WHERE name = UPPER('&dbname'))
ORDER  BY group#;

PROMPT === 5. 임시 테이블스페이스 ===
SELECT tablespace_name, ROUND(bytes/1024/1024) AS mb
FROM   rc_tempfile
WHERE  dbinc_key = (SELECT MAX(dbinc_key) FROM rc_database
                    WHERE name = UPPER('&dbname'));

PROMPT === 6. 최근 백업 (복원 대상 판단) ===
SELECT bs_key, bck_type, incr_level,
       TO_CHAR(completion_time,'MM-DD HH24:MI') AS done
FROM   rc_backup_set
WHERE  db_name = UPPER('&dbname') AND completion_time > SYSDATE - 7
ORDER  BY completion_time;

PROMPT === 7. 백업 조각 위치 (매체 준비) ===
SELECT DISTINCT SUBSTR(handle, 1, INSTR(handle,'/',-1)) AS directory,
       COUNT(*) AS pieces
FROM   rc_backup_piece
WHERE  db_name = UPPER('&dbname') AND status = 'A'
GROUP  BY SUBSTR(handle, 1, INSTR(handle,'/',-1));

PROMPT === 8. 복구 가능 종점 (손실 산정) ===
SELECT MAX(sequence#) AS last_backed_seq,
       TO_CHAR(MAX(next_time),'YYYY-MM-DD HH24:MI:SS') AS covered_until,
       MAX(next_change#) AS covered_scn
FROM   rc_archived_log a
WHERE  a.db_name = UPPER('&dbname')
AND    EXISTS (SELECT 1 FROM rc_backup_redolog b
               WHERE b.dbinc_key = a.dbinc_key AND b.sequence# = a.sequence#);

PROMPT === 9. CONFIGURE 설정 (재현용) ===
SELECT value FROM rc_rman_configuration
WHERE  db_key = (SELECT db_key FROM rc_database WHERE name = UPPER('&dbname'))
ORDER  BY conf#;

SPOOL OFF

-- 7-2. dr_rebuild.sh — 재구축 실행 보조

[oracle@oel7v9r2 ~]$ cat /home/oracle/rcadm/dr_rebuild.sh

#!/bin/bash
# 타 서버 재구축 보조 스크립트
# 사용법 : dr_rebuild.sh <DB_NAME> <신규 데이터 경로> <신규 아카이브 경로>
# 예    : dr_rebuild.sh ORCL /u02/oradata/ORCL /u02/arch_orcl
#
# 주의 : 이 스크립트는 준비와 구문 생성까지만 한다.
#        실제 RESTORE/RECOVER 는 사람이 확인 후 실행한다.
set -u
DBNAME=$1
DATADIR=$2
ARCHDIR=$3
SID=$(echo $DBNAME | tr 'A-Z' 'a-z')
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
WORK=/tmp/dr_$DBNAME

mkdir -p $WORK $DATADIR $ARCHDIR

echo "=== 1. 카탈로그에서 정보 수집 ==="
sqlplus -s rc_report/oracle_4U@rcat \
  @/home/oracle/rcadm/dr_collect_info.sql $DBNAME > /dev/null
cp /tmp/dr_info_$DBNAME.txt $WORK/
grep -A20 '=== 1\.' $WORK/dr_info_$DBNAME.txt

DBID=$(grep -A3 '=== 1\.' $WORK/dr_info_$DBNAME.txt | tail -1 | awk '{print $1}')
echo "DBID = $DBID"

echo "=== 2. SET NEWNAME 구문 생성 ==="
sqlplus -s rc_report/oracle_4U@rcat << EOF > $WORK/set_newname.txt
SET PAGESIZE 0 FEEDBACK OFF LINESIZE 200 HEADING OFF
SELECT '  SET NEWNAME FOR DATAFILE ' || file# || ' TO ''$DATADIR/' ||
       SUBSTR(name, INSTR(name,'/',-1)+1) || ''';'
FROM   rc_datafile
WHERE  dbinc_key = (SELECT MAX(dbinc_key) FROM rc_database
                    WHERE name = '$DBNAME')
ORDER  BY file#;
EXIT
EOF
cat $WORK/set_newname.txt

echo "=== 3. 복원 스크립트 생성 ==="
{
  echo "RUN {"
  echo "  ALLOCATE CHANNEL c1 DEVICE TYPE DISK;"
  echo "  ALLOCATE CHANNEL c2 DEVICE TYPE DISK;"
  cat $WORK/set_newname.txt
  echo "  RESTORE DATABASE;"
  echo "  SWITCH DATAFILE ALL;"
  echo "  RECOVER DATABASE;"
  echo "  RELEASE CHANNEL c1;"
  echo "  RELEASE CHANNEL c2;"
  echo "}"
} > $WORK/restore.rman

cat $WORK/restore.rman

echo
echo "=== 4. 최소 pfile 생성 ==="
cat > $ORACLE_HOME/dbs/init${SID}.ora << EOF
db_name=$SID
sga_target=2G
db_block_size=8192
compatible=19.0.0
control_files='$DATADIR/control01.ctl'
audit_file_dest='/u02/admin/$SID/adump'
EOF
mkdir -p /u02/admin/$SID/adump
echo "생성됨 : $ORACLE_HOME/dbs/init${SID}.ora"

echo
echo "=== 다음 단계를 수동으로 수행한다 ==="
cat << EOF
1) sqlplus / as sysdba
   STARTUP NOMOUNT PFILE='\$ORACLE_HOME/dbs/init${SID}.ora';
2) rman target / catalog rcatowner@rcat
   RESTORE SPFILE TO '/tmp/spfile_${SID}.ora' FROM AUTOBACKUP;
3) pfile 로 변환해 경로를 수정한 뒤 spfile 재생성, NOMOUNT 재기동
4) rman target / catalog rcatowner@rcat
   RESTORE CONTROLFILE;
   ALTER DATABASE MOUNT;
   @$WORK/restore.rman
5) ALTER DATABASE OPEN RESETLOGS;
6) RESYNC CATALOG; BACKUP DATABASE PLUS ARCHIVELOG;
EOF

-- 7-4. 정리 — 이 실습에서 남는 것
--
--   ① dr_collect_info.sql : 재해 시 정보 수집 (9개 항목)
--   ② dr_rebuild.sh       : 준비와 구문 생성 자동화
--   ③ 경로 매핑 설계표    : [2-2]
--   ④ 복구 순서 11단계    : [2-3]
--   ⑤ RTO 실측 근거표     : [6-7]
--
-- 다음 예제에서는 이 복구 시간을 좌우하는 백업 성능을 다룬다.

-- 실무 포인트
-- 1) 카탈로그가 복구 계획의 출발점이다.
--    DBID 없이는 자동 백업을 찾지 못하고
--    파일 목록 없이는 SET NEWNAME 을 만들 수 없다.
--    dr_collect_info.sql 을 평시에 정기 실행해 결과를 별도 보관한다.
--
-- 2) SET NEWNAME · RESTORE · SWITCH · RECOVER 는 한 묶음이다.
--    하나라도 빠지면 ORA-19504 나 RMAN-06571 로 막힌다.
--    각 명령이 무엇을 바꾸는지 이해하면 순서를 외울 필요가 없다.
--
-- 3) spfile 은 원본 경로를 그대로 담고 있다.
--    복원한 뒤 반드시 pfile 로 변환해 경로를 고치고 다시 만든다.
--    이 단계를 건너뛰면 MOUNT 부터 실패한다.
--
-- 4) 재해 복구는 복제가 아니다.
--    DBID 가 유지되어야 하며 카탈로그의 기존 이력을 이어서 쓴다.
--    17장의 DUPLICATE 는 새 DBID 를 만든다는 점에서 목적이 다르다.
--
-- 5) 손실 범위를 먼저 산정해 보고한다.
--    복구 시작 전에 "어디까지 살릴 수 있는가"를 확정해야
--    업무 측이 수작업 복원 계획을 병행할 수 있다.
--    이 판단이 늦으면 전체 복구 시간이 길어진다.
--
-- 6) 복구 완료는 오픈이 아니라 백업 체계 정상화까지다.
--    RESETLOGS 후 새 기준 백업을 받지 않으면
--    다음 장애에서 인카네이션을 거슬러야 하는 훨씬 어려운 상황이 된다.
