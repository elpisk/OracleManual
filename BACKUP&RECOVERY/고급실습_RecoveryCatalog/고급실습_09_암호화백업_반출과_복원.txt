 환경      : Oracle 19.3.0 / Oracle Linux 7 / oel7v9(운영계) + oel7v9r2(복원 검증) / ARCHIVELOG
 대상 DB   : sales (oel7v9)
 카탈로그  : rcat @ oel7v9r2

--------------------------------------------------------------------------------
[1] 실무 상황
--------------------------------------------------------------------------------
-- 보안 점검에서 두 가지가 지적되었다.
--
--   지적 1
--     "/backup 의 백업 파일에서 평문 고객 데이터가 확인됨.
--      파일 시스템 권한 외에 추가 보호 수단이 없음."
--
--   지적 2
--     "외부 위탁 업체에 전달한 백업 매체의 기밀성 통제 절차가 없음."
--
-- 실제로 확인해 보니 지적이 맞았다.
-- 백업 조각을 strings 로 훑으면 고객명과 전화번호가 그대로 나온다.
--
-- 동시에 다른 요구도 있다.
--   외부 감사 법인이 sales 데이터베이스의 특정 시점 사본을 요구했다.
--   USB 매체로 전달해야 하고 그쪽 서버에서 복원할 수 있어야 한다.
--   그쪽에는 우리 지갑이 없다.
--
-- 요구 사항
--   ① 정기 백업이 암호화되어 저장된다
--   ② 운영 중에는 사람의 개입 없이 암호화·복호화가 이루어진다
--   ③ 외부로 반출하는 백업은 우리 지갑 없이도 복원할 수 있어야 한다
--   ④ 키를 잃었을 때의 영향과 대비책을 명확히 한다
--   ⑤ 어떤 백업이 어떤 방식으로 암호화되었는지 카탈로그에서 조회된다
--
-- 14.6절에서 암호화 세 가지 방식을 다뤘다.
-- 이 실습에서는 그것을 실제 운영과 반출 상황에 적용한다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 세 가지 암호화 방식
--
--   방식        | 키 저장    | 복원 조건            | 용도
--   ------------|------------|----------------------|-------------------
--   투명(지갑)  | 지갑 파일  | 같은 지갑 필요       | 정기 백업
--   비밀번호    | 없음       | 비밀번호 필요        | 외부 반출
--   이중        | 지갑 + 비번| 둘 중 하나로 가능    | 양쪽 겸용
--
--   요구 사항 ②는 투명 방식을, ③은 비밀번호 방식을 가리킨다.
--   이중 방식을 쓰면 하나의 백업으로 둘 다 만족할 수 있다.

-- 2-2. 키 관리 설계
--
--   구분           | 위치                                  | 접근 통제
--   ---------------|---------------------------------------|-------------
--   지갑           | /u01/app/oracle/admin/sales/wallet    | oracle 만
--   지갑 비밀번호  | 사내 비밀번호 관리 시스템             | DBA 2인
--   자동 로그인    | 같은 경로의 cwallet.sso               | oracle 만
--   반출 비밀번호  | 건별 생성, 전달 시 별도 경로로 통보   | 요청자
--
--   절대 원칙
--     지갑과 백업을 같은 매체에 함께 두지 않는다.
--     함께 두면 암호화의 의미가 사라진다.
--     이 원칙은 백업 매체를 외부에 맡길 때 특히 중요하다.

-- 2-3. 지갑을 잃으면 어떻게 되는가 (요구 사항 ④)
--
--   투명 방식으로 암호화된 백업은 그 지갑으로만 열린다.
--   지갑을 잃으면 백업 전체가 무용지물이 된다.
--   되살릴 방법은 없다. 오라클도 열어 줄 수 없다.
--
--   그래서 지갑 자체의 백업이 데이터베이스 백업만큼 중요하다.
--     ① 지갑 파일을 별도 매체에 보관한다
--     ② 마스터 키를 변경할 때마다 지갑을 다시 백업한다
--     ③ 지갑 비밀번호를 잃으면 지갑도 열 수 없다. 별도 관리한다
--
--   이것이 고급 실습 06에서 언급한 "5년 뒤 복원 가능성"의 또 다른 축이다.

-- 2-4. 작업 순서
--
--   ① 지갑 생성과 마스터 키 설정
--   ② 자동 로그인 지갑 생성 (요구 사항 ②)
--   ③ CONFIGURE ENCRYPTION FOR DATABASE ON
--   ④ 정기 백업 수행과 평문 노출 여부 확인
--   ⑤ 반출용 이중 모드 백업
--   ⑥ 지갑 없는 서버에서 복원 검증 (요구 사항 ③)
--   ⑦ 카탈로그 조회로 암호화 현황 확인 (요구 사항 ⑤)
--   ⑧ 지갑 백업 절차 수립

-- WALLET_ROOT 는 재기동이 필요하고(SPFILE 전용) TDE_CONFIGURATION 은 즉시 반영된다.
-- 경로 뒤에 /tde/ 가 자동으로 붙는다. 이 하위 디렉터리는 지갑을 만들 때 생긴다.
-- 아직 지갑 파일이 없으므로 NOT_AVAILABLE 이다.
--
-- 참고 : 이전 방식은 sqlnet.ora 의 ENCRYPTION_WALLET_LOCATION 이다.
--        19c 에서도 동작하지만 WALLET_ROOT 방식이 권장된다.
--        둘을 함께 쓰면 WALLET_ROOT 가 우선한다.

-- 7-1. rc_secure_export.sh — 반출용 백업 생성
--
-- 전문은 운영스크립트/rc_secure_export.sh. 골격은 다음과 같다.

[oracle@oel7v9 ~]$ cat /home/oracle/rcadm/rc_secure_export.sh

#!/bin/bash
# 외부 반출용 암호화 백업 생성
# 사용법 : rc_secure_export.sh <ORACLE_SID> <반출식별자> <보관일수>
# 예     : rc_secure_export.sh sales AUDIT_2025Q3 180
set -u
SID=$1; LABEL=$2; KEEPDAYS=$3
DBNAME=$(echo $SID | tr 'a-z' 'A-Z')
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
CATALOG="rcatowner/oracle_4U@rcat"
OUTDIR=/export/${LABEL}
LOG=/home/oracle/rcadm/log/export_${LABEL}_$(date +%Y%m%d).log
mkdir -p $OUTDIR $(dirname $LOG)
log() { echo "$(date '+%Y-%m-%d %H:%M:%S') $*" | tee -a "$LOG"; }

# --- 사전 점검 1 : 카탈로그 접속 (KEEP 사용을 위해)
echo exit | rman target / catalog $CATALOG >/dev/null 2>&1 \
  || { log "[ABORT] recovery catalog required for KEEP option"; exit 2; }

# --- 사전 점검 2 : 반출 경로가 FRA 밖인가 (ORA-19811 방지)
# --- 사전 점검 3 : 반출 경로에 지갑 파일이 없어야 한다
find $OUTDIR \( -name '*.p12' -o -name '*.sso' -o -name '*wallet*' \) | grep -q . \
  && { log "[ABORT] wallet file found in export directory - refusing"; exit 2; }

# --- 반출 비밀번호 생성 (건별 생성이 원칙)
PW=$(openssl rand -base64 24 | tr -d '/+=' | cut -c1-24)
echo " 반출 비밀번호 : $PW"
echo " 이 값은 화면에만 표시된다. 로그에 남기지 않는다."

# --- 수행 (이중 모드 + KEEP + 복원 지점)
# SET ENCRYPTION ... IDENTIFIED BY 는 RUN 블록 안에 둘 수 없다 (RMAN-03032)
log "=== secure export start : $DBNAME / $LABEL ==="
rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
SET ENCRYPTION ON IDENTIFIED BY "$PW";
RUN {
  ALLOCATE CHANNEL c1 DEVICE TYPE DISK FORMAT '$OUTDIR/%d_${LABEL}_%U';
  BACKUP AS COMPRESSED BACKUPSET DATABASE
    TAG 'EXPORT_${LABEL}'
    KEEP UNTIL TIME 'SYSDATE+${KEEPDAYS}'
    RESTORE POINT ${DBNAME}_${LABEL};
  RELEASE CHANNEL c1;
}
EXIT
EOF
grep -qE 'RMAN-[0-9]{5}|ORA-[0-9]{5}' $LOG && { log "[FATAL] backup failed"; exit 1; }

# --- 검증 1 : 평문 노출이 없는가
log "--- verify : plaintext scan ---"
for f in $OUTDIR/*; do
  strings "$f" | grep -qE '@[a-z]+\.(com|co\.kr)|[0-9]{3}-[0-9]{4}-[0-9]{4}' \
    && { log "[FATAL] plaintext detected in $(basename $f)"; exit 1; }
done
log "plaintext scan passed"

# --- 검증 2 : 반출 비밀번호로 복호화가 되는가
log "--- verify : decryption ---"
rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
SET DECRYPTION IDENTIFIED BY "$PW";
RESTORE DATABASE VALIDATE FROM TAG 'EXPORT_${LABEL}';
EXIT
EOF
grep -qE 'ORA-19913|ORA-19870' $LOG \
  && { log "[FATAL] decryption verification failed"; exit 1; }
log "decryption verification passed"

# --- 인수인계 문서 (비밀번호와 DBID 는 포함하지 않는다. 복원 절차와 조각 수를 적는다)
cat > $OUTDIR/README_${LABEL}.txt << TXT
 ... (전문 참조)
TXT
log "[OK] export created at $OUTDIR"
ls -lh $OUTDIR | tee -a $LOG

#!/bin/bash
# 지갑 상태 점검과 정기 백업
SID=$1
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
CATALOG="rcatowner/oracle_4U@rcat"
WALLET_BK=/backup_wallet/$SID
MAILTO="dba-team@example.com"
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
mkdir -p $WALLET_BK

STATUS=$(sqlplus -s / as sysdba << 'EOF'
SET PAGESIZE 0 FEEDBACK OFF HEADING OFF
SELECT status || '|' || wallet_type || '|' || wrl_parameter
FROM v$encryption_wallet WHERE ROWNUM = 1;
EXIT
EOF
)
WSTATUS=$(echo $STATUS | cut -d'|' -f1)
WTYPE=$(echo $STATUS | cut -d'|' -f2)
WPATH=$(echo $STATUS | cut -d'|' -f3)
echo "wallet: status=$WSTATUS type=$WTYPE path=$WPATH"

# --- 점검 1 : 백업 암호화가 켜져 있는데 지갑이 닫혀 있는가
ENC=$(rman target / catalog $CATALOG << 'EOF' 2>/dev/null | grep 'ENCRYPTION FOR DATABASE'
SHOW ENCRYPTION FOR DATABASE;
EXIT
EOF
)
if echo "$ENC" | grep -q 'ON' && [ "$WSTATUS" != "OPEN" ]; then
  MSG="[CRIT] encryption is ON but wallet is $WSTATUS - backup will fail"
  echo "$MSG"; echo "$MSG" | mailx -s "[CRIT] wallet closed ($SID)" $MAILTO
  exit 1
fi

# --- 점검 2 : 지갑 파일이 실제로 있는가
if [ ! -f "${WPATH}ewallet.p12" ]; then
  MSG="[CRIT] wallet file missing: ${WPATH}ewallet.p12"
  echo "$MSG"; echo "$MSG" | mailx -s "[CRIT] wallet file missing ($SID)" $MAILTO
  exit 1
fi

# --- 지갑 백업 (백업 매체와 다른 위치로)
D=$(date +%Y%m%d)
tar czf $WALLET_BK/wallet_${SID}_${D}.tar.gz -C "$(dirname ${WPATH%/})" \
  "$(basename ${WPATH%/})" 2>/dev/null
chmod 600 $WALLET_BK/wallet_${SID}_${D}.tar.gz

# --- 보관 세대 관리 (30세대)
ls -1t $WALLET_BK/wallet_${SID}_*.tar.gz | tail -n +31 | xargs -r rm -f

echo "[OK] wallet checked and backed up : $WALLET_BK/wallet_${SID}_${D}.tar.gz"

-- 7-3. 확장 과제
--
-- 과제 A. ORCL 과 HRDB 적용
--   같은 절차를 나머지 두 DB에 적용하시오.
--   기존 평문 백업을 어떻게 처리할지 결정하고 그 근거를 서술한다.
--   보존 기간 만료를 기다릴지 즉시 재백업할지 판단한다.
--
-- 과제 B. 마스터 키 교체
--   보안 정책상 마스터 키를 1년마다 교체해야 한다.
--   ADMINISTER KEY MANAGEMENT SET KEY 로 교체한 뒤
--   교체 이전 백업(ENC_TDE)이 여전히 복원되는지 확인하시오.
--   v$encryption_keys 에 키가 두 개 남는 구조를 설명한다.
--
-- 과제 C. 암호화와 압축의 순서
--   RMAN 은 압축과 암호화를 어떤 순서로 수행하는가.
--   순서가 반대라면 무슨 문제가 생기는지 설명하고
--   4-4의 반출 백업(압축+암호화 291MB)과 08의 압축 백업(295MB)을 비교해 확인하시오.
--
-- 과제 D. ONLY 옵션 검토
--   SET ENCRYPTION ON IDENTIFIED BY '...' ONLY 를 쓰면
--   지갑으로도 열리지 않는다.
--   어떤 상황에서 이 옵션이 필요한지 논하고
--   비밀번호 분실 시의 위험을 평가하시오.
--
-- 과제 E. 지갑 재해 복구 훈련
--   지갑과 운영 서버를 함께 잃었다고 가정하고
--   [7-2]의 지갑 백업(tar.gz)으로 복구하는 절차를 수행하시오.
--   고급 실습 07의 절차와 결합해 전체 순서를 만든다.
--   지갑 복구가 어느 단계에 들어가야 하는지 판단한다. 자동백업도 암호화되어
--   있으므로 컨트롤파일 복원보다 앞이어야 한다.

-- 7-4. 정리 — 이 실습에서 남는 것
--
--   ① rc_secure_export.sh   : 반출용 백업 생성 (검증·인수문서 포함)
--   ② rc_wallet_check.sh    : 지갑 상태 점검과 정기 백업
--   ③ 키 관리 설계표        : [2-2]
--   ④ 세 방식 비교표        : [2-1]
--   ⑤ 암호화 현황 조회      : [6-1]
--   ⑥ 외부 서버 복원 절차   : [5] 오류 ② + [6-2]
--
-- 마지막 예제에서는 지금까지 만든 모든 것이 실제로 동작하는지 검증한다.

-- 실무 포인트
-- 1) 백업 파일은 데이터베이스 권한 밖에 있다.
--    strings 명령 하나로 고객 데이터가 노출된다.
--    파일 시스템 권한만으로는 부족하다.
--
-- 2) 정기 백업과 반출 백업을 분리한다.
--    정기 백업은 투명 방식, 반출은 이중 모드로 별도 생성한다.
--    지갑을 외부에 넘기는 순간 모든 정기 백업이 노출된다.
--
-- 3) 지갑 비밀번호와 백업 비밀번호는 다른 것이다.
--    지갑 비밀번호는 지갑 파일을 여는 것이고
--    백업 비밀번호는 백업을 여는 것이다.
--    투명 방식 백업은 SET DECRYPTION 으로 열 수 없다.
--
-- 4) SET ENCRYPTION / SET DECRYPTION 은 RUN 블록 밖에서 실행한다.
--    안에 넣으면 RMAN-03032 로 시작조차 하지 않는다. 스크립트에 넣기 전에 한 번 돌린다.
--
-- 5) 자동 로그인 지갑이 없으면 야간 백업이 실패한다.
--    ORA-19914 와 ORA-28365 가 함께 나오면 지갑 상태를 확인한다.
--    자동 로그인을 못 쓰는 정책이라면 여는 절차를 자동화한다.
--
-- 6) 지갑을 잃으면 정기 백업 전체가 무용지물이다. 자동백업도 포함된다.
--    되살릴 방법이 없다. 오라클도 열어 줄 수 없다.
--    지갑 백업을 데이터베이스 백업과 다른 매체에 보관한다.
--
-- 7) 다른 서버에서 복원할 때는 조각 위치부터 등록한다.
--    복원한 컨트롤파일은 원래 경로만 안다. CATALOG START WITH 가 첫 단계다.
--    리두·임시 파일 경로와 변경 추적 파일도 원본 경로라 열기 전에 정리한다.
--
-- 8) 암호화의 시간 비용은 이 환경에서 측정되지 않았다.
--    CPU 가 놀고 있으면 AES256 도 시간에 나타나지 않는다.
--    백업 창이 빠듯하면 운영 조건에서 다시 재고 그때 알고리즘을 고른다.
