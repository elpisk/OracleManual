[1] 실무 상황
--------------------------------------------------------------------------------
-- 보안 점검에서 두 가지가 지적되었다.
--
--   지적 1
--     "/backup 의 백업 파일에서 평문 고객 데이터가 확인됨.
--      파일 시스템 권한 외에 추가 보호 수단이 없음."
--
--   지적 2
--     "외부 위탁 업체에 전달한 백업 매체의 기밀성 통제 절차가 없음."
--
-- 실제로 확인해 보니 지적이 맞았다.
-- 백업 조각을 strings 로 훑으면 고객명과 전화번호가 그대로 나온다.
--
-- 동시에 다른 요구도 있다.
--   외부 감사 법인이 sales 데이터베이스의 특정 시점 사본을 요구했다.
--   USB 매체로 전달해야 하고 그쪽 서버에서 복원할 수 있어야 한다.
--   그쪽에는 우리 지갑이 없다.
--
-- 요구 사항
--   ① 정기 백업이 암호화되어 저장된다
--   ② 운영 중에는 사람의 개입 없이 암호화·복호화가 이루어진다
--   ③ 외부로 반출하는 백업은 우리 지갑 없이도 복원할 수 있어야 한다
--   ④ 키를 잃었을 때의 영향과 대비책을 명확히 한다
--   ⑤ 어떤 백업이 어떤 방식으로 암호화되었는지 카탈로그에서 조회된다
--
-- 14.6절에서 암호화 세 가지 방식을 다뤘다.
-- 이 실습에서는 그것을 실제 운영과 반출 상황에 적용한다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 세 가지 암호화 방식
--
--   방식        | 키 저장    | 복원 조건            | 용도
--   ------------|------------|----------------------|-------------------
--   투명(지갑)  | 지갑 파일  | 같은 지갑 필요       | 정기 백업
--   비밀번호    | 없음       | 비밀번호 필요        | 외부 반출
--   이중        | 지갑 + 비번| 둘 중 하나로 가능    | 양쪽 겸용
--
--   요구 사항 ②는 투명 방식을, ③은 비밀번호 방식을 가리킨다.
--   이중 방식을 쓰면 하나의 백업으로 둘 다 만족할 수 있다.

-- 2-2. 키 관리 설계
--
--   구분           | 위치                                  | 접근 통제
--   ---------------|---------------------------------------|-------------
--   지갑           | /u01/app/oracle/admin/sales/wallet    | oracle 만
--   지갑 비밀번호  | 사내 비밀번호 관리 시스템             | DBA 2인
--   자동 로그인    | 같은 경로의 cwallet.sso               | oracle 만
--   반출 비밀번호  | 건별 생성, 전달 시 별도 경로로 통보   | 요청자
--
--   절대 원칙
--     지갑과 백업을 같은 매체에 함께 두지 않는다.
--     함께 두면 암호화의 의미가 사라진다.
--     이 원칙은 백업 매체를 외부에 맡길 때 특히 중요하다.

-- 2-3. 지갑을 잃으면 어떻게 되는가 (요구 사항 ④)
--
--   투명 방식으로 암호화된 백업은 그 지갑으로만 열린다.
--   지갑을 잃으면 백업 전체가 무용지물이 된다.
--   되살릴 방법은 없다. 오라클도 열어 줄 수 없다.
--
--   그래서 지갑 자체의 백업이 데이터베이스 백업만큼 중요하다.
--     ① 지갑 파일을 별도 매체에 보관한다
--     ② 마스터 키를 변경할 때마다 지갑을 다시 백업한다
--     ③ 지갑 비밀번호를 잃으면 지갑도 열 수 없다. 별도 관리한다
--
--   이것이 고급 실습 06에서 언급한 "5년 뒤 복원 가능성"의 또 다른 축이다.

-- 2-4. 작업 순서
--
--   ① 지갑 생성과 마스터 키 설정
--   ② 자동 로그인 지갑 생성 (요구 사항 ②)
--   ③ CONFIGURE ENCRYPTION FOR DATABASE ON
--   ④ 정기 백업 수행과 평문 노출 여부 확인
--   ⑤ 반출용 이중 모드 백업
--   ⑥ 지갑 없는 서버에서 복원 검증 (요구 사항 ③)
--   ⑦ 카탈로그 조회로 암호화 현황 확인 (요구 사항 ⑤)
--   ⑧ 지갑 백업 절차 수립

RMAN-03009: failure of backup command on ORA_DISK_1 channel at 08/04/2025 10:22:14
ORA-19914: unable to encrypt backup

-- << 원인 파악 >>
-- CONFIGURE ENCRYPTION FOR DATABASE ON 이므로 모든 백업이 암호화된다.
-- 암호화에는 마스터 키가 필요하고 그 키는 지갑 안에 있다.
-- 지갑이 닫혀 있으면 키를 꺼낼 수 없다.
--
-- 두 오류를 함께 읽어야 한다.
--   ORA-19914 : 백업을 암호화할 수 없다 (결과)
--   ORA-28365 : 지갑이 열려 있지 않다 (원인)
--
-- 이 오류가 야간 정기 백업에서 나면 그날 백업이 통째로 실패한다.
-- 그래서 자동 로그인 지갑을 쓰는 것이다.
--
-- 자동 로그인 지갑을 쓸 수 없는 정책이라면
-- 기동 후 지갑을 여는 절차를 반드시 자동화해야 한다.

-- << 수정 >>

SYS@sales> ADMINISTER KEY MANAGEMENT SET KEYSTORE OPEN
  2    IDENTIFIED BY "Wallet#Sales2025";

keystore altered.

SYS@sales> SELECT status, wallet_type FROM v$encryption_wallet;

STATUS  WALLET_TYPE
------- -----------
OPEN    PASSWORD

RMAN> BACKUP TABLESPACE users TAG 'ENC_CLOSED';

Finished backup at 2025-08-04 10:26:33

-- 7-1. rc_secure_export.sh — 반출용 백업 생성

[oracle@oel7v9r1 ~]$ cat /home/oracle/rcadm/rc_secure_export.sh

#!/bin/bash
# 외부 반출용 암호화 백업 생성
# 사용법 : rc_secure_export.sh <ORACLE_SID> <반출식별자> <보관일수>
# 예     : rc_secure_export.sh sales AUDIT_2025Q3 180
set -u
SID=$1; LABEL=$2; KEEPDAYS=$3
DBNAME=$(echo $SID | tr 'a-z' 'A-Z')
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
OUTDIR=/export/${LABEL}
LOG=/home/oracle/rcadm/log/export_${LABEL}.log
mkdir -p $OUTDIR

# --- 반출 비밀번호 생성 (건별 생성이 원칙)
PW=$(openssl rand -base64 18 | tr -d '/+=' | cut -c1-20)
echo "생성된 반출 비밀번호 : $PW"
echo "이 값은 화면에만 표시된다. 별도 경로로 요청자에게 전달할 것."

# --- 안전장치 1 : 반출 경로에 지갑 파일이 없어야 한다
if find $OUTDIR -name '*.p12' -o -name '*.sso' | grep -q .; then
  echo "[ABORT] wallet file found in export directory" | tee -a $LOG
  exit 2
fi

# --- 안전장치 2 : 카탈로그 접속 (KEEP 사용을 위해)
if ! echo exit | rman target / catalog rcatowner/oracle_4U@rcat >/dev/null 2>&1
then
  echo "[ABORT] recovery catalog required" | tee -a $LOG
  exit 2
fi

# --- 수행 (이중 모드 : 지갑으로도 비밀번호로도 열림)
rman target / catalog rcatowner/oracle_4U@rcat >> $LOG 2>&1 << EOF
RUN {
  ALLOCATE CHANNEL c1 DEVICE TYPE DISK FORMAT '$OUTDIR/%d_${LABEL}_%U';
  SET ENCRYPTION ON IDENTIFIED BY "$PW";
  BACKUP AS COMPRESSED BACKUPSET DATABASE
    TAG 'EXPORT_${LABEL}'
    KEEP UNTIL TIME 'SYSDATE+${KEEPDAYS}'
    RESTORE POINT ${DBNAME}_${LABEL};
  RELEASE CHANNEL c1;
}
EXIT
EOF

# --- 검증 : 평문 노출이 없는지
for f in $OUTDIR/*; do
  if strings "$f" | grep -qE '@example\.com|010-[0-9]{4}'; then
    echo "[FATAL] plaintext detected in $f" | tee -a $LOG
    exit 1
  fi
done

# --- 검증 : 복호화가 되는지 (조각 하나만)
FIRST=$(ls -1 $OUTDIR | head -1)
rman target / catalog rcatowner/oracle_4U@rcat >> $LOG 2>&1 << EOF
SET DECRYPTION IDENTIFIED BY "$PW";
RESTORE DATABASE VALIDATE FROM TAG 'EXPORT_${LABEL}';
EXIT
EOF

if grep -qE 'ORA-19913|ORA-19870' $LOG; then
  echo "[FATAL] decryption verification failed" | tee -a $LOG
  exit 1
fi

# --- 인수인계 문서 생성
cat > $OUTDIR/README_${LABEL}.txt << TXT
반출 백업 정보
  대상 DB     : $DBNAME (DBID 는 별도 통보)
  생성 일시   : $(date '+%Y-%m-%d %H:%M:%S')
  태그        : EXPORT_${LABEL}
  보관 기한   : $(date -d "+${KEEPDAYS} days" '+%Y-%m-%d')
  암호화      : 이중 모드 (AES256)
  복원 절차   :
    1) STARTUP NOMOUNT
    2) rman target /
       SET DBID <별도 통보>;
       SET DECRYPTION IDENTIFIED BY '<별도 통보>';
       RESTORE CONTROLFILE FROM '<컨트롤파일 조각>';
       ALTER DATABASE MOUNT;
       RUN { SET DECRYPTION IDENTIFIED BY '<별도 통보>';
             SET NEWNAME FOR DATABASE TO '<경로>/%b';
             RESTORE DATABASE; SWITCH DATAFILE ALL; RECOVER DATABASE; }
    3) ALTER DATABASE OPEN RESETLOGS;
  주의        : 비밀번호는 이 문서에 포함되지 않는다. 별도 경로로 통보된다.
TXT

echo "[OK] export created at $OUTDIR"
ls -lh $OUTDIR

# 지갑 상태 점검과 정기 백업
SID=$1

ENC=$(rman target / catalog rcatowner/oracle_4U@rcat << 'EOF' 2>/dev/null | grep 'ENCRYPTION FOR DATABASE'
SHOW ENCRYPTION FOR DATABASE;
EXIT
EOF
)
if echo "$ENC" | grep -q 'ON' && [ "$WSTATUS" != "OPEN" ]; then
  echo "[CRIT] encryption is ON but wallet is $WSTATUS" \
    | mailx -s "[CRIT] wallet closed - backup will fail ($SID)" $MAILTO
  exit 1
fi

# --- 점검 2 : 지갑 파일이 실제로 있는가
if [ ! -f "${WPATH}ewallet.p12" ]; then
  echo "[CRIT] wallet file missing: ${WPATH}ewallet.p12" \
    | mailx -s "[CRIT] wallet file missing ($SID)" $MAILTO
  exit 1
fi

# --- 지갑 백업 (백업 매체와 다른 위치로)
D=$(date +%Y%m%d)
tar czf $WALLET_BK/wallet_${SID}_${D}.tar.gz -C "$(dirname ${WPATH%/})" \
  "$(basename ${WPATH%/})" 2>/dev/null
chmod 600 $WALLET_BK/wallet_${SID}_${D}.tar.gz

# --- 보관 세대 관리 (30세대)
ls -1t $WALLET_BK/wallet_${SID}_*.tar.gz | tail -n +31 | xargs -r rm -f

echo "[OK] wallet checked and backed up"

-- 7-4. 정리 — 이 실습에서 남는 것
--
--   ① rc_secure_export.sh   : 반출용 백업 생성 (검증·인수문서 포함)
--   ② rc_wallet_check.sh    : 지갑 상태 점검과 정기 백업
--   ③ 키 관리 설계표        : [2-2]
--   ④ 세 방식 비교표        : [2-1]
--   ⑤ 암호화 현황 조회      : [6-1]
--
-- 마지막 예제에서는 지금까지 만든 모든 것이 실제로 동작하는지 검증한다.

-- 실무 포인트
-- 1) 백업 파일은 데이터베이스 권한 밖에 있다.
--    strings 명령 하나로 고객 데이터가 노출된다.
--    파일 시스템 권한만으로는 부족하다.
--
-- 2) 정기 백업과 반출 백업을 분리한다.
--    정기 백업은 투명 방식, 반출은 이중 모드로 별도 생성한다.
--    지갑을 외부에 넘기는 순간 모든 정기 백업이 노출된다.
--
-- 3) 지갑 비밀번호와 백업 비밀번호는 다른 것이다.
--    지갑 비밀번호는 지갑 파일을 여는 것이고
--    백업 비밀번호는 백업을 여는 것이다.
--    투명 방식 백업은 SET DECRYPTION 으로 열 수 없다.
--
-- 4) 자동 로그인 지갑이 없으면 야간 백업이 실패한다.
--    ORA-19914 와 ORA-28365 가 함께 나오면 지갑 상태를 확인한다.
--    자동 로그인을 못 쓰는 정책이라면 여는 절차를 자동화한다.
--
-- 5) 지갑을 잃으면 백업 전체가 무용지물이다.
--    되살릴 방법이 없다. 오라클도 열어 줄 수 없다.
--    지갑 백업을 데이터베이스 백업과 다른 매체에 보관한다.
--
-- 6) 암호화는 백업 시간을 늘린다.
--    이 환경에서는 AES256 으로 약 48% 증가했다.
--    백업 창에 여유가 있는지 먼저 확인하고 알고리즘을 고른다.
