================================================================================
 고급 실습 01 : Virtual Private Catalog와 DBA 권한 분리
 과정      : Oracle Database 19c Backup & Recovery — Recovery Catalog 고급
 환경      : Oracle 19.3.0 / Oracle Linux 7 / oel7v9r1(운영계) + oel7v9r2(관리계)
 대상 DB   : orcl, sales (oel7v9r1) / hrdb (oel7v9r2)
 카탈로그  : rcat @ oel7v9r2
 소요 시간 : 약 2시간 30분
 선행 조건 : BR 1~19장 이수, 종합 실습 과제 수행

--------------------------------------------------------------------------------
[1] 실무 상황
--------------------------------------------------------------------------------
-- 데이터베이스 세 대를 DBA 세 명이 나눠 맡고 있다.
--   orcl  : 코어 업무 시스템
--   sales : 영업 시스템
--   hrdb  : 인사 시스템
--
-- 세 사람 모두 rcatowner 계정으로 카탈로그에 접속한다.
-- 그래서 다음이 가능하다.
--   - 영업 담당자가 코어 시스템의 백업을 DELETE 할 수 있다
--   - 인사 담당자가 다른 시스템의 백업 이력을 전부 조회할 수 있다
--   - 누가 무엇을 지웠는지 추적할 수 없다
--
-- 실제로 지난 분기 감사에서 지적을 받았다.
--   "백업 저장소에 대한 접근 권한이 담당 범위와 일치하지 않음"
--
-- 요구 사항
--   ① 각 DBA는 자기 담당 DB의 백업만 보고 다룰 수 있어야 한다
--   ② 다른 DB의 백업 이력은 조회조차 되지 않아야 한다
--   ③ 새 DB를 등록할 수 있는 사람은 따로 정한다
--   ④ 기존 백업 이력과 스크립트는 그대로 유지되어야 한다
--
-- 13장에서 만든 카탈로그는 소유자 한 명이 전부를 갖는 구조였다.
-- 이 실습에서는 그 위에 Virtual Private Catalog를 얹어 범위를 나눈다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 설계를 먼저 확정하고 명령을 실행한다.
-- 권한을 나눈 뒤에 되돌리는 것은 가능하지만 혼란이 크다.

-- 2-1. 용어 정리
--
--   기본 카탈로그(Base Catalog)
--     rcatowner 스키마. 실제 데이터가 들어 있는 테이블의 소유자.
--     등록된 모든 DB의 메타데이터를 갖는다.
--
--   가상 사설 카탈로그(Virtual Private Catalog, VPC)
--     별도 사용자 스키마. 기본 카탈로그의 일부만 보이는 뷰와 동의어의 집합.
--     자기에게 부여된 DB만 보인다.
--     데이터를 복제하지 않는다. 접근 범위만 제한한다.

-- 2-2. 권한 매트릭스
--
--   사용자        | 담당 DB | CATALOG FOR DATABASE | REGISTER DATABASE
--   --------------|---------|----------------------|-------------------
--   rcatowner     | 전체    | (소유자)             | (소유자)
--   vpc_core      | orcl    | orcl                 | 없음
--   vpc_sales     | sales   | sales                | 있음
--   vpc_hr        | hrdb    | hrdb                 | 없음
--
--   REGISTER DATABASE 를 vpc_sales 에게만 준 이유
--     영업 시스템은 분기마다 테스트 DB가 늘어난다.
--     매번 기본 카탈로그 소유자를 부르는 것이 비효율적이다.
--     나머지 둘은 DB 수가 고정이므로 등록 권한이 필요 없다.

-- 2-3. 명명 규칙
--
--   VPC 사용자명 : vpc_<업무영역>
--   기본 테이블스페이스 : rcat_data (rcatowner와 동일)
--   임시 : temp
--   비밀번호 정책 : 조직 표준을 따르며 이 실습에서는 oracle_4U

-- 2-4. 되돌리기 계획
--
--   REVOKE CATALOG FOR DATABASE <db> FROM <vpc사용자>;
--   DROP CATALOG;                      -- VPC 사용자로 접속해 실행
--   DROP USER <vpc사용자> CASCADE;
--
--   기본 카탈로그의 데이터는 영향을 받지 않는다.
--   VPC는 뷰와 동의어의 모음이므로 지워도 백업 이력이 사라지지 않는다.

-- vpc_hr 에게는 CATALOG FOR DATABASE hrdb 만 부여되었다.
-- REGISTER DATABASE 권한은 별도이며 부여하지 않았다.
--
-- 두 권한의 차이
--   CATALOG FOR DATABASE : 이미 등록된 특정 DB를 다룰 권한
--   REGISTER DATABASE    : 새 DB를 카탈로그에 등록할 권한
--
-- 설계 단계에서 vpc_sales 에게만 등록 권한을 준 이유가 여기서 드러난다.
-- 등록 권한이 있으면 카탈로그에 새 항목을 계속 만들 수 있어
-- 공간과 관리 범위가 통제를 벗어날 수 있다.

-- << 수정 >> 두 가지 선택지가 있다.

-- 선택지 1 : 기본 카탈로그 소유자가 대신 등록한다 (권장)

[oracle@oel7v9r2 ~]$ rman target / catalog rcatowner@rcat
RMAN> REGISTER DATABASE;
-- 이미 등록되어 있다면 RMAN-20002 가 나온다.

-- 선택지 2 : 등록 권한을 부여한다

[oracle@oel7v9r2 ~]$ rman catalog rcatowner@rcat
RMAN> GRANT REGISTER DATABASE TO vpc_hr;

Grant succeeded.

RMAN> EXIT

-- 권한 부여 후에는 성공한다.
-- 다만 이 실습에서는 설계대로 회수한다.

[oracle@oel7v9r2 ~]$ rman catalog rcatowner@rcat
RMAN> REVOKE REGISTER DATABASE FROM vpc_hr;

Revoke succeeded.

-- 7-1. VPC 구성 스크립트
--
-- 운영스크립트/rc_vpc_setup.sql 로 제공한다.
-- 신규 담당자가 생길 때마다 그대로 실행한다.

[oracle@oel7v9r2 ~]$ cat /home/oracle/rcadm/rc_vpc_setup.sql

-- 사용법 : sqlplus / as sysdba @rc_vpc_setup.sql <VPC사용자> <비밀번호>
DEFINE vpc_user  = &1
DEFINE vpc_pass  = &2

CREATE USER &vpc_user IDENTIFIED BY &vpc_pass
  DEFAULT TABLESPACE rcat_data
  TEMPORARY TABLESPACE temp
  QUOTA UNLIMITED ON rcat_data;

GRANT RECOVERY_CATALOG_OWNER TO &vpc_user;

PROMPT
PROMPT === 다음 단계를 수동으로 수행한다 ===
PROMPT 1) rman catalog rcatowner@rcat
PROMPT    RMAN> GRANT CATALOG FOR DATABASE <db> TO &vpc_user;
PROMPT 2) rman catalog &vpc_user@rcat
PROMPT    RMAN> CREATE VIRTUAL CATALOG;
PROMPT

-- 7-2. 권한 현황 점검 조회
--
-- 운영스크립트/rc_vpc_audit.sql
-- 분기 감사 대응용으로 그대로 제출할 수 있다.

[oracle@oel7v9r2 ~]$ cat /home/oracle/rcadm/rc_vpc_audit.sql

SET LINESIZE 140 PAGESIZE 100
COLUMN vpc_user FORMAT A20
COLUMN visible_databases FORMAT A60

PROMPT === VPC 사용자 목록 ===
SELECT u.username AS vpc_user, u.created, u.account_status
FROM   dba_users u
WHERE  u.username LIKE 'VPC%'
ORDER  BY u.username;

PROMPT === 기본 카탈로그 등록 DB ===
SELECT dbid, name, reset_time FROM rcatowner.rc_database ORDER BY name;

PROMPT === VPC 사용자별 가상 카탈로그 생성 여부 ===
SELECT owner AS vpc_user, COUNT(*) AS synonym_count
FROM   dba_synonyms
WHERE  table_owner = 'RCATOWNER' AND owner LIKE 'VPC%'
GROUP  BY owner ORDER BY owner;

--   vpc_core 에게 orcl 과 hrdb 를 함께 부여하고 동작을 확인하시오.

-- 과제 D. 감사 보고서 작성

-- 7-5. 정리 — 이 실습에서 남는 것
--
--   ① rc_vpc_setup.sql   : 신규 담당자 계정 생성 절차
--   ② rc_vpc_audit.sql   : 분기 감사 대응 조회
--   ③ 권한 매트릭스 표   : [2]의 설계 문서
--   ④ 권한 회수 절차     : 7-3의 4단계
--
-- 다음 예제에서는 이 구조 위에서 세 대의 백업 현황을
-- 한 화면으로 보는 리포팅 체계를 만든다.

-- 실무 포인트
-- 1) VPC는 데이터를 복제하지 않는다.
--    뷰와 동의어의 모음이므로 저장 공간이 거의 들지 않는다.
--    DROP CATALOG 로 지워도 백업 이력은 사라지지 않는다.
--
-- 2) 권한 부여는 RMAN 명령이고 계정 생성은 SQL이다.
--    GRANT CATALOG FOR DATABASE 는 SQL*Plus에서 실행되지 않는다.
--    두 도구를 오가야 한다는 점이 처음에는 혼란스럽다.
--
-- 3) CREATE VIRTUAL CATALOG 를 빠뜨리면 권한이 있어도 보이지 않는다.
--    설정 순서는 계정 생성 → 롤 부여 → 범위 부여 → 가상 카탈로그 생성이다.
--
-- 4) 권한 없는 DB는 "없는 DB"로 취급된다.
--    ORA-01031 이 아니라 RMAN-20001 이 나온다.
--    다른 시스템의 존재 자체가 노출되지 않는 것이 설계 의도다.
--
-- 5) 접속 성공이 권한 충분을 뜻하지 않는다.
--    CREATE SESSION 만 있어도 접속 메시지는 정상적으로 나온다.
--    실제 명령에서야 ORA-01031 로 막힌다.
--
-- 6) 글로벌 스토어드 스크립트는 VPC 경계를 넘어 공유된다.
--    표준 백업 절차를 한 곳에서 관리하고 데이터만 나누는 구성이 가능하다.
--    다만 그 스크립트를 수정할 수 있는 사람은 통제해야 한다.
