================================================================================
 고급 실습 03 : 파라미터화 글로벌 Stored Script 백업 프레임워크
 과정      : Oracle Database 19c Backup & Recovery — Recovery Catalog 고급
 환경      : Oracle 19.3.0 / Oracle Linux 7 / oel7v9r1(운영계) + oel7v9r2(관리계)
 대상 DB   : orcl, sales (oel7v9r1) / hrdb (oel7v9r2)
 카탈로그  : rcat @ oel7v9r2
 소요 시간 : 약 3시간
 선행 조건 : 고급 실습 01~02 완료
================================================================================

--------------------------------------------------------------------------------
[1] 실무 상황
--------------------------------------------------------------------------------
-- 현재 백업 스크립트는 이렇게 흩어져 있다.
--
--   oel7v9r1:/home/oracle/bin/backup_orcl.sh    (작성자 A, 2023년)
--   oel7v9r1:/home/oracle/bin/bk_sales.sh       (작성자 B, 2024년)
--   oel7v9r2:/home/oracle/scripts/hrdb_bkup.sh  (작성자 C, 2024년)
--
-- 세 스크립트의 내용이 조금씩 다르다.
--   - orcl 만 CHECK LOGICAL 을 붙인다
--   - sales 는 PLUS ARCHIVELOG 가 빠져 있다 (고급 실습 02의 그 사고)
--   - hrdb 는 태그를 붙이지 않는다
--
-- 지난달 보존 정책을 14일에서 21일로 늘리라는 지시가 있었다.
-- 세 곳을 고쳐야 했고 한 곳을 빠뜨려 아직도 14일로 돌고 있다.
--
-- 요구 사항
--   ① 백업 절차를 한 곳에서 정의하고 세 DB가 같은 절차를 쓴다
--   ② DB마다 다른 값(태그, 경로, 보존일)은 파라미터로 넘긴다
--   ③ 절차를 고치면 세 DB에 즉시 반영된다
--   ④ 실행 결과가 로그로 남고 실패하면 알림이 간다
--   ⑤ 서버에 셸 스크립트를 배포하지 않아도 절차가 유지된다
--
-- 카탈로그의 글로벌 스토어드 스크립트가 이 요구를 정확히 충족한다.
-- 13.6절에서 다룬 스토어드 스크립트를 다중 DB 환경으로 확장한다.

--------------------------------------------------------------------------------
[2] 사전 설계
--------------------------------------------------------------------------------
-- 2-1. 로컬 스크립트와 글로벌 스크립트
--
--   구분        | 로컬 스크립트           | 글로벌 스크립트
--   ------------|-------------------------|---------------------------
--   생성 명령   | CREATE SCRIPT           | CREATE GLOBAL SCRIPT
--   소속        | 특정 대상 DB            | 카탈로그 전체
--   접속 요건   | 대상 DB에 접속 필요     | 카탈로그만 접속해도 생성 가능
--   가시 범위   | 그 DB에서만             | 등록된 모든 DB에서
--   VPC 사용자  | 자기 DB의 것만          | 모두 보임 (실습 01 6-4)
--   용도        | 그 DB에만 있는 예외 절차| 조직 표준 절차
--
--   이 실습에서는 표준 절차를 글로벌로, 예외를 로컬로 둔다.

-- 2-2. 치환 변수
--
--   스크립트 본문에 &1, &2, &3 형태로 넣는다.
--   실행할 때 USING 절로 값을 넘긴다.
--
--     RUN { EXECUTE GLOBAL SCRIPT gs_backup_ts USING 'users', 'TAG01'; }
--
--   주의할 점
--     - EXECUTE SCRIPT 는 반드시 RUN 블록 안에 있어야 한다
--     - USING 값의 개수와 &n 의 개수가 맞아야 한다
--     - 대화형으로 CREATE 하면 값 입력을 요구할 수 있다.
--       파일에서 만들면 그 문제가 없다.

-- 2-3. 만들 스크립트 목록
--
--   이름                  | 파라미터                    | 용도
--   ----------------------|-----------------------------|-------------------
--   gs_daily_incr         | &1 태그접두어               | 일일 증분 + 아카이브
--   gs_weekly_full        | &1 태그접두어               | 주간 Level 0
--   gs_archive_only       | &1 태그접두어               | 아카이브만 (임시)
--   gs_maint_obsolete     | (없음)                      | 보존 정책 적용 정리
--   gs_validate_full      | (없음)                      | 복구 가능성 검증
--
--   태그 규칙 : <접두어>_<종류>_<YYYYMMDD>
--     예) ORCL_INCR_20250604
--   경로 규칙 : /backup/%d/   ← %d 가 DB 이름으로 치환된다
--               경로를 파라미터로 넘길 필요가 없어진다

-- 2-4. 실행 구조
--
--   crontab (각 서버)
--        └─ rc_backup_framework.sh <DB_SID> <스크립트명> <태그접두어>
--              └─ rman target / catalog rcatowner@rcat
--                    └─ RUN { EXECUTE GLOBAL SCRIPT <스크립트명> USING '<접두어>'; }
--              └─ 로그 저장 · 오류 판정 · 실패 시 메일
--
--   셸 스크립트는 실행기 하나만 배포한다.
--   백업 절차 자체는 카탈로그에 있으므로 서버에 없다.
--   절차를 바꾸면 다음 실행부터 세 DB에 동시에 반영된다.

-- 2-5. 표준 CONFIGURE 설정
--
--   스크립트 안에 넣지 않고 DB별 영구 설정으로 둔다.
--   스크립트는 "무엇을 백업할지", CONFIGURE 는 "어떻게 저장할지"를 맡는다.
--
--     RETENTION POLICY  : RECOVERY WINDOW OF 21 DAYS
--     CONTROLFILE AUTOBACKUP : ON
--     DEVICE TYPE DISK PARALLELISM 2
--     CHANNEL DEVICE TYPE DISK FORMAT '/backup/%d/%U'
--     BACKUP OPTIMIZATION : ON

-- 4-1. 스크립트 본문을 파일로 작성한다
--
-- 대화형으로 CREATE 하면 치환 변수 값을 물어볼 수 있다.
-- 파일에서 만들면 그 문제가 없고 형상 관리도 쉬워진다.

[oracle@oel7v9r2 ~]$ mkdir -p /home/oracle/rcadm/scripts
[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_daily_incr.rman << 'EOF'
{
  BACKUP INCREMENTAL LEVEL 1
    CHECK LOGICAL
    DATABASE
    TAG '&1_INCR'
    PLUS ARCHIVELOG
    TAG '&1_ARCH'
    NOT BACKED UP 1 TIMES;
  BACKUP CURRENT CONTROLFILE TAG '&1_CF';
  DELETE NOPROMPT OBSOLETE;
}
EOF

[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_weekly_full.rman << 'EOF'
{
  BACKUP INCREMENTAL LEVEL 0
    CHECK LOGICAL
    DATABASE
    TAG '&1_FULL'
    PLUS ARCHIVELOG
    TAG '&1_ARCH';
  BACKUP CURRENT CONTROLFILE TAG '&1_CF';
  DELETE NOPROMPT OBSOLETE;
}
EOF

[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_archive_only.rman << 'EOF'
{
  SQL 'ALTER SYSTEM ARCHIVE LOG CURRENT';
  BACKUP ARCHIVELOG ALL TAG '&1_ARCH' NOT BACKED UP 1 TIMES;
}
EOF

[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_validate_full.rman << 'EOF'
{
  RESTORE DATABASE VALIDATE;
  RESTORE ARCHIVELOG ALL VALIDATE;
  BACKUP VALIDATE CHECK LOGICAL DATABASE ARCHIVELOG ALL;
}
EOF

[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_maint_obsolete.rman << 'EOF'
{
  CROSSCHECK BACKUP;
  CROSSCHECK ARCHIVELOG ALL;
  DELETE NOPROMPT EXPIRED BACKUP;
  DELETE NOPROMPT EXPIRED ARCHIVELOG ALL;
  DELETE NOPROMPT OBSOLETE;
  REPORT NEED BACKUP;
}
EOF

-- 4-6. 절차 변경이 즉시 반영되는지 확인
--
-- 요구 사항 ③의 검증이다.
-- 백업 조각 크기를 제한하라는 지시가 내려왔다고 하자.

[oracle@oel7v9r2 ~]$ cat > /home/oracle/rcadm/scripts/gs_daily_incr.rman << 'EOF'
{
  BACKUP INCREMENTAL LEVEL 1
    CHECK LOGICAL
    DATABASE
    TAG '&1_INCR'
    MAXPIECESIZE 2G
    PLUS ARCHIVELOG
    TAG '&1_ARCH'
    NOT BACKED UP 1 TIMES;
  BACKUP CURRENT CONTROLFILE TAG '&1_CF';
  DELETE NOPROMPT OBSOLETE;
}
EOF

-- 7-1. 실행기 — rc_backup_framework.sh
--
-- 서버에 배포하는 유일한 파일이다.
-- 사전 점검, 실행, 판정, 알림을 담당한다.

[oracle@oel7v9r1 ~]$ cat /home/oracle/rcadm/rc_backup_framework.sh

#!/bin/bash
# 사용법 : rc_backup_framework.sh <ORACLE_SID> <글로벌스크립트명> [태그접두어]
# 예     : rc_backup_framework.sh orcl gs_daily_incr ORCL

set -u
SID=$1
SCRIPT=$2
PREFIX=${3:-$(echo $1 | tr 'a-z' 'A-Z')}

export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=$SID
export PATH=$ORACLE_HOME/bin:$PATH
export NLS_DATE_FORMAT='YYYY-MM-DD HH24:MI:SS'

CATALOG="rcatowner/oracle_4U@rcat"
D=$(date +%Y%m%d_%H%M)
LOGDIR=/home/oracle/rcadm/log
LOG=$LOGDIR/${SID}_${SCRIPT}_${D}.log
MAILTO="dba-team@example.com"
mkdir -p $LOGDIR

# --- 사전 점검 1 : 인스턴스가 살아 있는가
if ! ps -ef | grep -q "[o]ra_pmon_${SID}"; then
  echo "[FATAL] instance $SID is not running" | tee -a $LOG
  mailx -s "[FATAL] backup abort - $SID down" $MAILTO < $LOG
  exit 2
fi

# --- 사전 점검 2 : 백업 경로가 있는가 (오류 ② 재발 방지)
DBNAME=$(echo $SID | tr 'a-z' 'A-Z')
if [ ! -d /backup/$DBNAME ]; then
  echo "[FATAL] backup directory /backup/$DBNAME not found" | tee -a $LOG
  mailx -s "[FATAL] backup abort - path missing $DBNAME" $MAILTO < $LOG
  exit 2
fi

# --- 사전 점검 3 : 여유 공간 20% 이상인가
USEPCT=$(df -P /backup | tail -1 | awk '{print $5}' | tr -d '%')
if [ $USEPCT -ge 80 ]; then
  echo "[WARN] /backup usage ${USEPCT}%" | tee -a $LOG
fi

# --- 사전 점검 4 : 카탈로그에 접속되는가
if ! echo "exit" | rman target / catalog $CATALOG > /tmp/cat_$$.log 2>&1; then
  echo "[WARN] recovery catalog unreachable - fallback mode" | tee -a $LOG
  cat /tmp/cat_$$.log >> $LOG
  # 폴백 : 파일 기반 절차로 수행 (오류 ③ 대비)
  if [ -f /home/oracle/rcadm/fallback/${SCRIPT}_${DBNAME}.rman ]; then
    rman target / nocatalog \
      @/home/oracle/rcadm/fallback/${SCRIPT}_${DBNAME}.rman >> $LOG 2>&1
    echo "[INFO] fallback executed - RESYNC required later" >> $LOG
    mailx -s "[WARN] backup ran in fallback mode - $SID" $MAILTO < $LOG
    exit 1
  fi
  mailx -s "[FATAL] catalog down and no fallback - $SID" $MAILTO < $LOG
  exit 2
fi
rm -f /tmp/cat_$$.log

# --- 실행
echo "=== $(date) : $SID / $SCRIPT / prefix=$PREFIX ===" >> $LOG

rman target / catalog $CATALOG >> $LOG 2>&1 << EOF
RUN { EXECUTE GLOBAL SCRIPT $SCRIPT USING '$PREFIX'; }
EXIT
EOF

# --- 판정
if grep -qE 'RMAN-[0-9]+|ORA-[0-9]+' $LOG; then
  echo "[FAIL] errors found in $LOG"
  mailx -s "[FAIL] RMAN backup $SID / $SCRIPT" $MAILTO < $LOG
  exit 1
fi

if ! grep -q 'Finished backup' $LOG; then
  echo "[FAIL] no completion marker in $LOG"
  mailx -s "[FAIL] RMAN backup incomplete $SID / $SCRIPT" $MAILTO < $LOG
  exit 1
fi

echo "[OK] $SID / $SCRIPT completed"
find $LOGDIR -name "${SID}_*.log" -mtime +60 -delete
exit 0

-- 7-5. 확장 과제
--
-- 과제 A. 로컬 스크립트와의 병용
--   sales 에만 필요한 예외 절차가 생겼다.
--   특정 테이블스페이스를 백업에서 제외해야 한다.
--   글로벌 스크립트를 건드리지 않고 처리하는 방법을 설계하고 구현하시오.
--   힌트 : CONFIGURE EXCLUDE FOR TABLESPACE 와 로컬 스크립트를 비교 검토한다.
--
-- 과제 B. 파라미터 두 개 이상
--   태그 접두어 외에 보존일수를 두 번째 파라미터로 받는 스크립트를 만드시오.
--   &1 과 &2 를 함께 쓰고 USING 절에 값 두 개를 넘긴다.
--   보존일수를 스크립트 파라미터로 두는 것이 CONFIGURE 로 두는 것보다
--   나은지 판단하고 근거를 서술하시오.
--
-- 과제 C. 폴백 파일 완성
--   7-3에서 만든 폴백 파일은 치환 변수가 남아 있어 그대로 실행되지 않는다.
--   DB별로 값을 치환한 파일을 생성하도록 스크립트를 개선하시오.
--   sed 로 &1 을 DB 이름으로 바꾸는 방법을 검토한다.
--
-- 과제 D. 실행 이력 추적
--   어떤 스크립트가 언제 실행되었는지 카탈로그에서 확인하는 조회를 만드시오.
--   rc_rman_status 의 operation 과 command_id 를 이용한다.
--   실행기에서 SET COMMAND ID TO 로 식별자를 넣으면 추적이 쉬워진다.
--
-- 과제 E. 스크립트 변경 감지
--   글로벌 스크립트가 승인 없이 바뀌는 것을 막아야 한다.
--   원본 파일의 해시와 카탈로그 내용의 해시를 비교하는 점검을 구현하시오.
--   불일치 시 일일 리포트에 경고를 출력한다.

-- 7-6. 정리 — 이 실습에서 남는 것
--
--   ① 글로벌 스크립트 5종      : 조직 표준 백업 절차
--   ② rc_backup_framework.sh   : 사전 점검·실행·판정·알림 실행기
--   ③ rc_export_scripts.sh     : 폴백 파일 추출기
--   ④ std_configure.rman       : 표준 CONFIGURE 일괄 적용
--   ⑤ 크론 등록 예시           : 서버별 스케줄
--
-- 다음 예제에서는 이 프레임워크가 매일 쌓는 백업과
-- 카탈로그 기록 사이의 불일치를 다룬다.

-- 실무 포인트
-- 1) EXECUTE SCRIPT 는 RUN 블록 안에서만 동작한다.
--    PRINT 와 LIST 는 밖에서 되므로 더 헷갈린다.
--    RMAN-01009 의 "expecting one of" 목록을 읽으면 원인이 바로 보인다.
--
-- 2) 절차는 카탈로그에, 설정은 CONFIGURE 에, 준비는 서버에 둔다.
--    이 세 가지를 섞으면 표준화가 무너진다.
--    /backup 경로 누락 사고가 그 경계를 보여 준다.
--
-- 3) 스토어드 스크립트는 카탈로그가 있어야만 쓸 수 있다.
--    RMAN-06171 이 나오면 카탈로그 접속을 먼저 확인한다.
--    카탈로그 장애 시의 폴백을 반드시 준비해 둔다.
--
-- 4) 스크립트를 파일에서 만든다.
--    대화형 CREATE 는 치환 변수 값을 물어볼 수 있어 자동화에 맞지 않는다.
--    FROM FILE 방식은 형상 관리와도 자연스럽게 이어진다.
--
-- 5) 카탈로그는 스크립트 변경 이력을 남기지 않는다.
--    REPLACE 하면 이전 내용을 되돌릴 수 없다.
--    원본을 형상 관리 도구에 두고 카탈로그는 배포 대상으로만 다룬다.
--
-- 6) 실행기의 판정은 종료 코드가 아니라 로그 내용으로 한다.
--    RMAN 은 일부 실패에도 0으로 끝나는 경우가 있다.
--    ORA- 와 RMAN- 문자열 검사, 완료 표시 검사를 함께 쓴다.
