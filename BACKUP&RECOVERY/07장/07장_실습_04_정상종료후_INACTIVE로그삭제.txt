================================================================================
 실습 7-4 : 정상 종료 후 INACTIVE 리두 로그 삭제
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / NOARCHIVELOG
 소요 시간 : 약 15분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 정상 종료 후 INACTIVE 그룹의 멤버가 모두 삭제되었다.
-- 그 그룹의 리두는 이미 데이터파일에 반영되어 있어 손실이 없다.
-- CLEAR LOGFILE로 그룹을 다시 만들면 RESETLOGS 없이 열린다.
-- 멤버 하나만 손상된 경우와의 차이도 함께 확인한다.
-- 복구 유형 : 복구 불필요(CLEAR 후 정상 오픈)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 리두 로그가 그룹 세 개, 그룹마다 멤버 두 개로 구성되어 있어야 한다.
-- 데이터베이스가 OPEN 상태여야 한다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL member FOR a44

SYS@orcl> !grep -n 'CLOSE NORMAL' \

-- 정상 종료였다. 인스턴스 복구 자체가 필요 없다.

SYS@orcl> SELECT * FROM v$recover_file;

no rows selected

-- 데이터파일은 문제가 없다.

-- 판정
--   ① 멤버 : 그룹 3은 전손, 나머지 그룹은 온전
--   ② 그룹 상태 : INACTIVE → CLEAR 가능
--   ③ 종료 : 정상 → RESETLOGS 불필요
--   → CLEAR LOGFILE GROUP 3 후 OPEN. 손실 없음.

SYS@orcl> !mkdir -p /home/oracle/before_recover_74
SYS@orcl> !cp -p /u01/app/oracle/oradata/ORCL/*.ctl /home/oracle/before_recover_74/

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 그룹을 제거해 보려 한다.

SYS@orcl> ALTER DATABASE DROP LOGFILE GROUP 3;
ALTER DATABASE DROP LOGFILE GROUP 3
*
ERROR at line 1:
ORA-00313: open failed for members of log group 3 of thread 1
ORA-00312: online log 3 thread 1: '/u01/app/oracle/oradata/ORCL/redo03.log'
ORA-27037: unable to obtain file status

-- << 원인 파악 >>
-- DROP LOGFILE 은 그룹을 제거하는 명령이며 파일에 접근할 수 있어야 한다.
-- 파일이 없어졌으므로 제거 자체가 되지 않는다.
-- 필요한 것은 제거가 아니라 재생성이다.
-- CLEAR LOGFILE 은 파일이 없으면 새로 만들어 주므로 이 상황에 맞는 명령이다.

SYS@orcl> !ls /u01/app/oracle/oradata/ORCL/redo03.log
ls: cannot access '/u01/app/oracle/oradata/ORCL/redo03.log': No such file or directory

-- << 수정 >>

SYS@orcl> ALTER DATABASE CLEAR LOGFILE GROUP 3;

Database altered.

SYS@orcl> SELECT group#, sequence#, status FROM v$log WHERE group# = 3;

    GROUP#  SEQUENCE# STATUS
---------- ---------- ----------------
         3          0 UNUSED

SYS@orcl> SELECT member, status FROM v$logfile WHERE group# = 3;

MEMBER                                       STATUS
-------------------------------------------- -------
/u01/app/oracle/oradata/ORCL/redo03.log
/u02/oradata/ORCL/redo03b.log

-- STATUS가 비었다. 멤버 두 개가 모두 다시 만들어졌다.

SYS@orcl> !ls -l /u01/app/oracle/oradata/ORCL/redo03.log /u02/oradata/ORCL/redo03b.log
-rw-r-----. 1 oracle oinstall 209715712 May 10 19:52 redo03.log
-rw-r-----. 1 oracle oinstall 209715712 May 10 19:52 redo03b.log

SYS@orcl> ALTER DATABASE OPEN;

Database altered.

-- RESETLOGS 없이 열렸다.

-- 실무 포인트
-- 1) ORA-00312의 줄 수가 진단의 열쇠다.
--    멤버 수만큼 나오면 그룹 전손이고 ORA-00313이 함께 나온다.
--    한 줄만 나오면 멤버 하나 손상이므로 서비스가 멈추지 않는다.
--
-- 2) DROP LOGFILE 과 CLEAR LOGFILE 은 목적이 다르다.
--    DROP은 그룹을 없애는 명령이라 파일에 접근할 수 있어야 하고,
--    CLEAR는 내용을 비우고 없으면 새로 만드는 명령이라 이 상황에 맞는다.
--
-- 3) 정상 종료 + INACTIVE 조합이면 손실이 없다.
--    그 그룹의 리두가 이미 데이터파일에 반영되어 있기 때문이다.
--    RESETLOGS도 필요 없어 기존 백업본이 계속 유효하다.
--
-- 4) 멤버 하나 손상은 온라인으로 처리한다.
--    스위치와 체크포인트로 대상 그룹을 INACTIVE로 만든 뒤
--    같은 그룹의 멤버를 복사하거나 DROP/ADD MEMBER 를 수행한다.
--
-- 5) CLEAR 후 확인은 네 가지다.
--    v$log의 STATUS, v$logfile의 STATUS, OS 파일 재생성, v$recover_file 공백이다.
--    이 중 하나라도 어긋나면 아직 남은 문제가 있다는 뜻이다.
--
-- 6) 이 실습이 손쉬웠던 이유는 종료 방식과 그룹 상태가 모두 유리했기 때문이다.
--    다음 실습에서 같은 그룹 손상을 비정상 종료 상태에서 다시 본다.

SYS@orcl> EXIT
