================================================================================
 실습 16-3 : spfile 손상 복구 — 자동 백업에서 RESTORE SPFILE
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 25분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- spfile이 사라져 인스턴스를 기동할 수 없다.
-- 최소 내용의 임시 pfile로 인스턴스만 띄운다.
-- SET DBID 후 자동 백업에서 spfile을 복원한다.
-- 복원 후 파라미터 값이 최신인지 확인한다.
-- 복구 유형 : 파라미터 파일 복구, 전면 중단

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------

-- pfile 사본이 없다. 있었다면 그것으로 즉시 기동할 수 있었다.

-- 판정
--   ① spfile과 pfile 모두 부재 → 인스턴스 기동 불가
--   ② 자동 백업 있음, DBID는 파일명에서 확인 가능
--   ③ 순서 : 임시 pfile로 기동 → SET DBID → RESTORE SPFILE
--   → 전면 중단이며 몇 분이면 복구된다.

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 임시 pfile 없이 복원을 시도해 본다.

[oracle@oel7v9r1 ~]$ rman target /

RMAN> SET DBID 1200530011;

executing command: SET DBID

RMAN> RESTORE SPFILE FROM AUTOBACKUP;

RMAN-00571: ===========================================================

RMAN-03002: failure of restore command at 05/18/2025 10:41:02
RMAN-06403: could not obtain a fully authorized session
ORA-01034: ORACLE not available

-- << 원인 파악 >>
-- 인스턴스가 없으면 RMAN이 작업을 수행할 수 없다.
-- 복원 작업도 인스턴스의 서버 프로세스가 하기 때문이다.
-- spfile이 없어 인스턴스를 못 올리고, 인스턴스가 없어 복원을 못 하는 상황이다.
-- 최소한의 pfile로 인스턴스만 먼저 띄워야 한다.

-- << 수정 >>

-- 실무 포인트
-- 1) spfile이 없으면 인스턴스를 올릴 수 없다.
--    ORA-01078과 LRM-00109가 그 신호이며 찾는 순서는
--    spfile<SID>.ora → spfile.ora → init<SID>.ora 다.
--
-- 2) 인스턴스 없이는 RMAN 복원도 불가능하다.
--    RMAN-06403과 ORA-01034가 그 사실을 알려 준다.
--    복원 작업도 인스턴스의 서버 프로세스가 수행하기 때문이다.
--
-- 3) 최소 pfile로 인스턴스만 띄우는 것이 해결의 열쇠다.
--    db_name 한 줄이면 충분하며 기본값으로 작은 인스턴스가 뜬다.
--    복원 작업에는 그것으로 충분하다.
--
-- 4) SET DBID가 필요하다.
--    자동 백업 파일명이 c-DBID-YYYYMMDD-NN 형식이기 때문이다.
--    자동 백업 위치가 기본값이 아니면 FORMAT도 지정한다.
--
-- 5) 복원본은 자동 백업 시점의 내용이다.
--    그 이후 파라미터를 바꿨다면 그 변경은 사라진다.
--    v$parameter 로 isdefault='FALSE' 목록을 확인해 비교한다.
--
-- 6) pfile 사본이 있었다면 이 모든 절차가 한 줄로 끝났다.
--    STARTUP PFILE='...' 로 기동한 뒤 CREATE SPFILE 하면 된다.
--    파라미터를 바꿀 때마다 사본을 남기는 습관이 가장 단순한 대비책이다.
