================================================================================
 실습 16-4 : 파라미터 값 오류로 기동 불가 상황 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 25분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 메모리 파라미터를 SCOPE=SPFILE 로 조정했다가 재기동에 실패했다.
-- spfile은 이진 파일이라 직접 편집할 수 없다.
-- pfile로 변환해 값을 고친 뒤 그 pfile로 기동한다.
-- 이어서 spfile을 다시 만들어 정상 상태로 되돌린다.
-- 복구 유형 : 파라미터 값 수정, 전면 중단

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 16-3까지 완료되어 spfile이 정상이어야 한다.

[oracle@oel7v9 ~]$ sqlplus / as sysdba

SYS@orcl> SHOW PARAMETER spfile

NAME    TYPE   VALUE
------- ------ ------------------------------------------------------------
spfile  string /u01/app/oracle/product/19.3.0/dbhome_1/dbs/spfileorcl.ora

SYS@orcl> !free -g
              total        used        free      shared  buff/cache   available
Mem:              7           1           0           1           6           4
Swap:            15           0          15

-- 서버 메모리는 7GB다.

--------------------------------------------------------------------------------
[3] 초기 상태 확인
--------------------------------------------------------------------------------
SYS@orcl> SHOW PARAMETER sga_target

NAME        TYPE        VALUE
----------- ----------- ------
sga_target  big integer 2G

SYS@orcl> SHOW PARAMETER sga_max_size

NAME          TYPE        VALUE
------------- ----------- ------
sga_max_size  big integer 2G

-- sga_max_size 가 2G로 고정되어 있다. sga_target 은 이 값을 넘을 수 없다.

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
OPEN

--------------------------------------------------------------------------------
[4] 장애 유발 : 과도한 메모리 파라미터 설정
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET sga_target = 40G SCOPE = SPFILE;

System altered.

-- SCOPE=SPFILE 이므로 지금은 아무 일도 일어나지 않는다.
-- 값 검증도 하지 않고 spfile 에 그대로 기록된다. 다음 재기동 때 드러난다.

SYS@orcl> SHOW PARAMETER sga_target

NAME        TYPE        VALUE
----------- ----------- ------
sga_target  big integer 2G

-- 현재 인스턴스는 여전히 2G로 동작한다.

SYS@orcl> SHUTDOWN IMMEDIATE

Database closed.
Database dismounted.
ORACLE instance shut down.

--------------------------------------------------------------------------------
[5] 증상 관찰
--------------------------------------------------------------------------------
SYS@orcl> STARTUP

ORA-00823: Specified value of sga_target greater than sga_max_size
ORA-01078: failure in processing system parameters

-- sga_target(40G)이 sga_max_size(2G)를 넘어 기동 전 검증에서 막혔다.
-- sga_max_size 가 지정되어 있지 않았다면, 대신 서버 메모리를 넘는 순간
-- ORA-00845 나 ORA-27102(out of memory)로 실패했을 것이다. 어느 쪽이든 값이 과하다는 뜻이다.

SYS@orcl> SELECT status FROM v$instance;
SELECT status FROM v$instance
                   *
ERROR at line 1:
ORA-01034: ORACLE not available

-- 인스턴스가 뜨지 않는다.

--------------------------------------------------------------------------------
[6] 진단
--------------------------------------------------------------------------------
SYS@orcl> !ls -l $ORACLE_HOME/dbs/spfileorcl.ora
-rw-r-----. 1 oracle dba 4608 May 18 11:12 spfileorcl.ora

-- spfile은 존재한다. 값이 문제다.

SYS@orcl> !strings $ORACLE_HOME/dbs/spfileorcl.ora | grep -i sga
orcl.__sga_target=1577058304
sga_max_size=2147483648
*.sga_target=42949672960

-- strings 로 내용 일부를 볼 수는 있으나 편집할 수 없다.
-- 이진 파일이므로 직접 수정하면 파일이 깨진다. 42949672960바이트는 40GB다.

SYS@orcl> !ls /home/oracle/backup/init*.ora
/home/oracle/backup/initorcl_20250518.ora

-- 실습 16-3에서 만든 사본이 있다.
-- 사본이 없는 경우를 가정해 pfile 변환 절차를 먼저 수행한다.

-- 판정
--   ① spfile은 존재하나 sga_target 값이 sga_max_size(및 서버 메모리)를 초과
--   ② 이진 파일이라 직접 편집 불가
--   → pfile로 변환 → 값 수정 → 그 pfile로 기동 → spfile 재생성

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 인스턴스가 없는 상태에서도 CREATE PFILE 은 수행된다. spfile 을 읽어 쓰기만 하기 때문이다.

SYS@orcl> CREATE PFILE='/tmp/fix.ora' FROM SPFILE;

File created.

-- 텍스트 파일이 만들어졌다. 값을 고친다. sga_max_size 이하로 맞춘다.

SYS@orcl> !grep -n 'sga_target' /tmp/fix.ora
9:orcl.__sga_target=1577058304
44:*.sga_target=42949672960

SYS@orcl> !sed -i 's/^\*.sga_target=.*/*.sga_target=2147483648/' /tmp/fix.ora

SYS@orcl> !grep -n 'sga_target' /tmp/fix.ora
9:orcl.__sga_target=1577058304
44:*.sga_target=2147483648

-- 고쳤으니 그냥 기동해 본다.

SYS@orcl> STARTUP

ORA-00823: Specified value of sga_target greater than sga_max_size
ORA-01078: failure in processing system parameters

-- << 원인 파악 >>
-- 같은 오류다. STARTUP 은 $ORACLE_HOME/dbs 의 spfile 을 읽지 /tmp/fix.ora 를 읽지 않는다.
-- 고친 파일로 기동하려면 PFILE 을 명시해야 하고, 그 뒤 spfile 을 다시 만들어야
-- 다음 재기동 때 같은 일이 되풀이되지 않는다.

-- << 수정 >>

SYS@orcl> STARTUP PFILE='/tmp/fix.ora';

ORACLE instance started.

Total System Global Area 2147480360 bytes
Fixed Size                  8893224 bytes
Variable Size             536870912 bytes
Database Buffers         1476395008 bytes
Redo Buffers              125321216 bytes
Database mounted.
Database opened.

-- 수정한 pfile로 정상 기동되었다.

SYS@orcl> SHOW PARAMETER spfile

NAME    TYPE   VALUE
------- ------ ------------------------------------------------------------
spfile  string

-- 값이 비어 있다. pfile로 뜬 상태다. 이대로 두면 다음 재기동 때 다시 실패한다.

SYS@orcl> CREATE SPFILE FROM PFILE='/tmp/fix.ora';

File created.

SYS@orcl> SHUTDOWN IMMEDIATE
SYS@orcl> STARTUP

ORACLE instance started.
Database mounted.
Database opened.

-- 사본이 있었다면 STARTUP PFILE='초기사본' 으로 바로 기동할 수 있었다.

SYS@orcl> CREATE PFILE='/home/oracle/backup/initorcl_ok.ora' FROM SPFILE;

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat
RMAN> BACKUP DATABASE TAG 'AFTER_PARAM' PLUS ARCHIVELOG;
RMAN> EXIT

-- 실무 포인트
-- 1) SCOPE=SPFILE 변경은 값 검증 없이 기록되고 다음 재기동 때 적용된다.
--    변경 시점에는 문제가 드러나지 않아 나중에야 발견된다.
--    그래서 변경 후 즉시 재기동해 확인하는 것이 안전하다.
--
-- 2) sga_target 은 sga_max_size 를 넘을 수 없다(ORA-00823).
--    sga_max_size 가 없으면 서버 메모리를 넘는 순간 ORA-00845/ORA-27102 가 난다.
--    어느 쪽이든 "값이 과하다"는 신호이며 대응은 같다.
--
-- 3) spfile은 이진 파일이라 직접 편집할 수 없다.
--    strings 로 내용을 볼 수는 있으나 수정하면 파일이 깨진다.
--    반드시 pfile로 변환해 고쳐야 한다.
--
-- 4) CREATE PFILE FROM SPFILE 은 인스턴스 없이도 수행된다.
--    spfile 을 읽어 텍스트로 쓰기만 하므로 idle 상태에서 바로 쓴다.
--    반대로 STARTUP 은 PFILE 을 명시하지 않으면 늘 spfile 을 읽는다.
--
-- 5) 순서는 pfile 변환 → 값 수정 → pfile로 기동 → CREATE SPFILE 이다.
--    마지막 단계를 빠뜨리면 다음 재기동 때 다시 실패한다.
--    SHOW PARAMETER spfile 로 기동 방식을 확인한다(값이 비어 있으면 pfile로 뜬 것).
--
-- 6) 가장 단순한 대비책은 사본이다.
--    파라미터를 바꾸기 전에 CREATE PFILE 로 사본을 남기면
--    이 실습의 모든 절차가 STARTUP PFILE 한 줄로 대체된다.
