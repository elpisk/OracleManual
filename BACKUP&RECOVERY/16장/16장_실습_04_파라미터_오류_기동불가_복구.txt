================================================================================
 실습 16-4 : 파라미터 값 오류로 기동 불가 상황 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 25분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 메모리 파라미터를 SCOPE=SPFILE 로 조정했다가 재기동에 실패했다.
-- spfile은 이진 파일이라 직접 편집할 수 없다.
-- pfile로 변환해 값을 고친 뒤 그 pfile로 기동한다.
-- 이어서 spfile을 다시 만들어 정상 상태로 되돌린다.
-- 복구 유형 : 파라미터 값 수정, 전면 중단

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 16-3까지 완료되어 spfile이 정상이어야 한다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SHOW PARAMETER spfile

NAME    TYPE   VALUE
------- ------ ------------------------------------------------------------
spfile  string /u01/app/oracle/product/19.3.0/dbhome_1/dbs/spfileorcl.ora

SYS@orcl> !free -g
              total        used        free      shared  buff/cache   available
Mem:              7           2           1           1           3           3

-- 서버 메모리는 7GB다.

-- 이번 실습에서는 사본 없이 진행한다.

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
OPEN

--------------------------------------------------------------------------------
[4] 장애 유발 : 과도한 메모리 파라미터 설정
--------------------------------------------------------------------------------
SYS@orcl> ALTER SYSTEM SET sga_target = 40G SCOPE = SPFILE;

System altered.

-- SCOPE=SPFILE 이므로 지금은 아무 일도 일어나지 않는다.
-- 다음 재기동 때 적용된다.

SYS@orcl> SHOW PARAMETER sga_target

NAME        TYPE        VALUE
----------- ----------- ------
sga_target  big integer 1G

-- 현재 인스턴스는 여전히 1G로 동작한다.

SYS@orcl> SHUTDOWN IMMEDIATE

Database closed.
Database dismounted.
ORACLE instance shut down.

--------------------------------------------------------------------------------
[6] 진단
--------------------------------------------------------------------------------
SYS@orcl> !ls -l $ORACLE_HOME/dbs/spfileorcl.ora
-rw-r-----. 1 oracle oinstall 3584 May 18 11:12 spfileorcl.ora

-- spfile은 존재한다. 값이 문제다.

SYS@orcl> !strings $ORACLE_HOME/dbs/spfileorcl.ora | grep -i sga
*.sga_target=42949672960

-- strings 로 내용 일부를 볼 수는 있으나 편집할 수 없다.
-- 이진 파일이므로 직접 수정하면 파일이 깨진다.

SYS@orcl> !ls /home/oracle/backup/init*.ora
/home/oracle/backup/initorcl_20250518.ora

-- 실습 16-3에서 만든 사본이 있다.
-- 사본이 없는 경우를 가정해 pfile 변환 절차를 먼저 수행한다.

-- 판정
--   ① spfile은 존재하나 sga_target 값이 서버 메모리를 초과
--   ② 이진 파일이라 직접 편집 불가
--   → pfile로 변환 → 값 수정 → 그 pfile로 기동 → spfile 재생성

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 인스턴스가 없는 상태에서 CREATE PFILE 을 시도해 본다.

SYS@orcl> CREATE PFILE='/tmp/fix.ora' FROM SPFILE;
CREATE PFILE='/tmp/fix.ora' FROM SPFILE
*
ERROR at line 1:
ORA-01034: ORACLE not available

-- << 원인 파악 >>
-- 인스턴스가 없어도 CREATE PFILE 은 수행할 수 있어야 하지만
-- 세션이 인스턴스에 붙어 있지 않으면 명령 자체가 거부된다.
-- NOMOUNT 상태의 인스턴스가 필요하다.
-- 그런데 지금은 spfile 때문에 NOMOUNT도 되지 않는다.
-- 임시 pfile로 인스턴스를 먼저 띄우면 두 문제가 한 번에 풀린다.

-- << 수정 >>

SYS@orcl> !echo "db_name=orcl" > /tmp/init_min.ora

SYS@orcl> STARTUP NOMOUNT PFILE='/tmp/init_min.ora';

ORACLE instance started.

Total System Global Area  398458880 bytes

SYS@orcl> CREATE PFILE='/tmp/fix.ora' FROM SPFILE='/u01/app/oracle/product/19.3.0/dbhome_1/dbs/spfileorcl.ora';

File created.

-- 이제 텍스트 파일이 만들어졌다.

SYS@orcl> !grep -n 'sga_target' /tmp/fix.ora
14:*.sga_target=42949672960

SYS@orcl> !sed -i 's/^\*.sga_target=.*/*.sga_target=1073741824/' /tmp/fix.ora

SYS@orcl> !grep -n 'sga_target' /tmp/fix.ora
14:*.sga_target=1073741824

SYS@orcl> SHUTDOWN IMMEDIATE

ORACLE instance shut down.

SYS@orcl> STARTUP PFILE='/tmp/fix.ora';

ORACLE instance started.

Total System Global Area 1073741824 bytes
Database mounted.
Database opened.

-- 수정한 pfile로 정상 기동되었다.

SYS@orcl> CREATE SPFILE FROM PFILE='/tmp/fix.ora';

File created.

SYS@orcl> SHUTDOWN IMMEDIATE
SYS@orcl> STARTUP

ORACLE instance started.
Database opened.

-- 실무 포인트
-- 1) SCOPE=SPFILE 변경은 다음 재기동 때 적용된다.
--    변경 시점에는 문제가 드러나지 않아 나중에야 발견된다.
--    그래서 변경 후 즉시 재기동해 확인하는 것이 안전하다.
--
-- 2) spfile은 이진 파일이라 직접 편집할 수 없다.
--    strings 로 내용을 볼 수는 있으나 수정하면 파일이 깨진다.
--    반드시 pfile로 변환해 고쳐야 한다.
--
-- 3) CREATE PFILE 도 인스턴스가 필요하다.
--    인스턴스가 없으면 ORA-01034로 거부된다.
--    최소 pfile로 NOMOUNT까지 올린 뒤 수행한다.
--
-- 4) 순서는 pfile 변환 → 값 수정 → pfile로 기동 → CREATE SPFILE 이다.
--    마지막 단계를 빠뜨리면 다음 재기동 때 다시 실패한다.
--
-- 5) SHOW PARAMETER spfile 로 기동 방식을 확인한다.
--    값이 비어 있으면 pfile로 뜬 상태이며 spfile 재생성이 필요하다.
--
-- 6) 가장 단순한 대비책은 사본이다.
--    파라미터를 바꾸기 전에 CREATE PFILE 로 사본을 남기면
--    이 실습의 모든 절차가 STARTUP PFILE 한 줄로 대체된다.
