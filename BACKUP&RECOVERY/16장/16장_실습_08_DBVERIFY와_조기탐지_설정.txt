[5] 진행 로그 : 열린 상태에서의 검사
--------------------------------------------------------------------------------
[oracle@oel7v9 ~]$ dbv file=/u01/app/oracle/oradata/orcl/users01.dbf blocksize=8192 \
>   logfile=/tmp/dbv_open.log

[oracle@oel7v9 ~]$ grep -E 'Influx|Corrupt|Examined' /tmp/dbv_open.log
Total Pages Examined         : 12800
Total Pages Marked Corrupt   : 0
Total Pages Influx           : 0

-- Influx는 검사 도중 그 블록이 쓰기로 바뀌면 올라간다.
-- 한가한 파일을 검사하면 대개 0이고, 갱신이 활발한 파일이면 몇 개가 잡힌다.
-- Influx는 손상이 아니라 "검사 순간에 바뀌고 있던 블록"이라는 뜻이다.
-- 정확한 검사가 필요하면 데이터베이스를 내리거나, 정지된 사본·RMAN VALIDATE를 쓴다.

-- 원격지로 옮긴 백업 파일의 무결성을 확인할 때 이 방법을 쓴다.
-- (여기서는 16-7 의 NOLOGGING 흔적이 사본에도 그대로 담겨 Marked Corrupt 1 로 나온다.)
-- 백업 세트는 RMAN 고유 형식이라 dbv로 검사할 수 없고 이미지 카피만 가능하다.

--------------------------------------------------------------------------------
[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- blocksize를 잘못 지정해 본다.

[oracle@oel7v9 ~]$ dbv file=/u01/app/oracle/oradata/orcl/users01.dbf blocksize=4096

DBVERIFY: Release 19.0.0.0.0 - Production

DBVERIFY - Verification starting : FILE = /u01/app/oracle/oradata/orcl/users01.dbf
DBV-00103: Specified BLOCKSIZE (4096) differs from actual (8192)

-- << 원인 파악 >>
-- 파일의 실제 블록 크기와 지정한 값이 다르면 검사할 수 없다.
-- 19c 는 DBV-00103 으로 실제 크기(8192)를 알려 준다.
-- v$datafile 의 BLOCK_SIZE 컬럼으로 확인해야 한다.
-- 기본값은 2048이므로 대부분의 환경에서 반드시 지정해야 한다.

[oracle@oel7v9 ~]$ sqlplus -s / as sysdba
SQL> SELECT DISTINCT block_size FROM v$datafile;

BLOCK_SIZE
----------
      8192

-- << 수정 >>

[oracle@oel7v9 ~]$ dbv file=/u01/app/oracle/oradata/orcl/users01.dbf blocksize=8192 \
>   logfile=/tmp/dbv_fixed.log

[oracle@oel7v9 ~]$ tail -4 /tmp/dbv_fixed.log
Total Pages Marked Corrupt   : 0
Total Pages Influx           : 0
Total Pages Encrypted        : 0
Highest block SCN            : 7760762 (0.7760762)

--------------------------------------------------------------------------------
[8] 검증 및 실무 포인트 — 조기 탐지 설정
--------------------------------------------------------------------------------
[oracle@oel7v9 ~]$ sqlplus / as sysdba

-- 값을 잘못 지정해 본다.

SYS@orcl> ALTER SYSTEM SET db_block_checking = HIGH SCOPE = BOTH;
ALTER SYSTEM SET db_block_checking = HIGH SCOPE = BOTH
*
ERROR at line 1:
ORA-00096: invalid value HIGH for parameter db_block_checking, must be from
among FULL, TRUE, MEDIUM, LOW, OFF, FALSE

-- << 원인 파악 >>
-- db_block_checking 이 받는 값은 OFF(FALSE), LOW, MEDIUM, FULL(TRUE) 이다.
-- db_block_checksum 의 값(OFF, TYPICAL, FULL)과 혼동하기 쉽다.
-- 두 파라미터의 이름이 비슷해 값을 서로 바꿔 쓰는 실수가 흔하다.
-- 오류 메시지가 가능한 값을 모두 알려 주므로 그대로 고르면 된다.

-- << 수정 >>

SYS@orcl> ALTER SYSTEM SET db_block_checksum = FULL SCOPE = BOTH;

System altered.

SYS@orcl> ALTER SYSTEM SET db_block_checking = MEDIUM SCOPE = BOTH;

System altered.

SYS@orcl> SHOW PARAMETER db_block_check

NAME                 TYPE    VALUE
-------------------- ------- --------
db_block_checking    string  MEDIUM
db_block_checksum    string  FULL

-- 정기 검사 스크립트를 만든다.
-- (스크립트 안에 EOF 히어독과 v$ 의 $ 가 있어, 편집기로 직접 작성한다.)

[oracle@oel7v9 ~]$ cat /home/oracle/rman/monthly_check.sh
#!/bin/bash
export ORACLE_HOME=/u01/app/oracle/product/19.3.0/dbhome_1
export ORACLE_SID=orcl
export PATH=$ORACLE_HOME/bin:$PATH
LOG=/home/oracle/rman/log/check_$(date +%Y%m%d).log

rman target / log=$LOG <<EOF
VALIDATE CHECK LOGICAL DATABASE;
EOF

sqlplus -s / as sysdba >> $LOG <<EOF
SELECT file#, block#, blocks, corruption_type
FROM   v\$database_block_corruption;
EOF

if grep -qE 'FAILED|corruption' $LOG; then
  echo "[ORCL] block corruption detected - see $LOG"
  exit 1
fi
echo "[ORCL] monthly check OK"

[oracle@oel7v9 ~]$ chmod 700 /home/oracle/rman/monthly_check.sh
[oracle@oel7v9 ~]$ /home/oracle/rman/monthly_check.sh
[ORCL] monthly check OK

[oracle@oel7v9 ~]$ crontab -l | tail -1
0 3 1 * * /home/oracle/rman/monthly_check.sh >> /home/oracle/rman/log/cron.log 2>&1

-- 매월 1일 새벽 3시에 수행하도록 등록했다.

-- 실무 포인트
-- 1) dbv는 데이터베이스 밖에서 파일을 검사한다.
--    인스턴스가 내려간 상태에서도 쓸 수 있어 백업 파일 검증에 유용하다.
--    다만 백업 세트는 RMAN 고유 형식이라 검사할 수 없고 이미지 카피만 가능하다.
--
-- 2) blocksize를 반드시 지정한다.
--    기본값이 2048이라 대부분의 환경에서 DBV-00103으로 실패한다.
--    19c 는 DBV-00103 으로 실제 블록 크기를 알려 주므로 그 값으로 다시 실행한다.
--
-- 3) Influx는 손상이 아니다.
--    검사 중 변경된 블록의 수이며 열린 상태에서 검사하면 나타난다.
--    확실히 정합적인 검사가 필요하면 이미지 카피나 RMAN VALIDATE를 쓴다.
--
-- 4) DB_BLOCK_CHECKSUM은 체크섬을, DB_BLOCK_CHECKING은 구조 일관성을 검사한다.
--    값이 서로 다르다(checksum: OFF/TYPICAL/FULL, checking: OFF/LOW/MEDIUM/FULL).
--    두 파라미터 모두 CPU 부담을 늘리므로 실제 워크로드로 측정해 판단한다.
--    MEDIUM 정도가 실무에서 무리 없이 쓰이는 값이다.
--
-- 5) 파라미터를 바꿨으면 pfile 사본을 남긴다.
--    복구 후 값을 비교할 근거가 된다.
--
-- 6) 정기 검사를 자동화한다.
--    월 1회 VALIDATE CHECK LOGICAL DATABASE 와 손상 목록 조회를 묶어
--    크론에 등록하고 손상이 발견되면 알림이 가도록 만든다.
