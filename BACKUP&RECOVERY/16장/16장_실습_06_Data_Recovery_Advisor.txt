[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 데이터파일 하나를 삭제해 장애를 만든다.
-- DRA가 그 장애를 감지하고 조치안을 제시하는 과정을 확인한다.
-- REPAIR FAILURE PREVIEW로 스크립트를 먼저 확인한다.
-- 제시안을 검토한 뒤 실행하고 결과를 확인한다.
-- 복구 유형 : DRA 자동 조치, 전면 중단(감지 시점 기준)

[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- ADVISE 없이 REPAIR를 먼저 시도해 본다. (새 세션)

[oracle@oel7v9 ~]$ rman target /

RMAN> REPAIR FAILURE;

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-03002: failure of repair command at 05/18/2025 13:22:41
RMAN-06954: REPAIR command must be preceded by ADVISE command in same session

-- << 원인 파악 >>
-- REPAIR FAILURE는 ADVISE FAILURE의 결과를 사용한다.
-- 같은 세션에서 ADVISE를 먼저 수행해야 한다.
-- 이 제약이 오히려 안전장치가 된다. 조치안을 보지 않고는 실행할 수 없다.

-- << 수정 >>

RMAN> ADVISE FAILURE ALL;

... (자동 조치 옵션 다시 표시) ...
Repair script: /u01/app/oracle/diag/rdbms/orcl/orcl/hm/reco_1260331017.hm

-- ADVISE FAILURE 를 그냥 다시 부르면 RMAN-07211(failure option not specified)이 날 수 있다.
-- 이미 분석 결과가 남아 있어 대상을 명시해야 하기 때문이다. ALL(또는 장애 번호)을 붙인다.

RMAN> REPAIR FAILURE PREVIEW;

Strategy: The repair includes complete media recovery with no data loss
Repair script: /u01/app/oracle/diag/rdbms/orcl/orcl/hm/reco_1260331017.hm

contents of repair script:
   # restore and recover datafile
   restore ( datafile 8 );
   recover datafile 8;
   sql 'alter database datafile 8 online';

-- 스크립트를 확인한다.
--   SET UNTIL 이 없다 → 불완전 복구가 아니다
--   CLEAR UNARCHIVED 가 없다 → 아카이브 연속성에 영향 없다
--   현재 MOUNTED 상태라 offline 단계가 없다(파일이 이미 닫혀 있다).
--   15장에서 배운 절차와 같다
-- 실행해도 안전하다고 판단한다.

RMAN> REPAIR FAILURE NOPROMPT;

Strategy: The repair includes complete media recovery with no data loss
Repair script: /u01/app/oracle/diag/rdbms/orcl/orcl/hm/reco_1260331017.hm

contents of repair script:
   restore ( datafile 8 );
   recover datafile 8;
   sql 'alter database datafile 8 online';

executing repair script

Starting restore at 18-MAY-25
channel ORA_DISK_1: restoring datafile 00008 to /u03/oradata/ORCL/tbs13_01.dbf
channel ORA_DISK_1: restore complete, elapsed time: 00:00:01
Finished restore at 18-MAY-25

Starting recover at 18-MAY-25
starting media recovery
media recovery complete, elapsed time: 00:00:00
Finished recover at 18-MAY-25

sql statement: alter database datafile 8 online
repair failure complete

database opened

-- NOPROMPT 를 붙이면 YES/NO 확인 없이 실행한다. 붙이지 않으면
-- "Do you really want to execute the above repair (enter YES or NO)?" 에 YES로 답한다.
-- MOUNTED 상태에서 시작했으므로 복구가 끝난 뒤 DRA가 데이터베이스를 열어 준다.

     FILE# STATUS
---------- -------
         8 ONLINE

SYS@orcl> SELECT failure_id, status, priority

---------- -------- --------
      9425 CLOSED   HIGH
      9217 CLOSED   HIGH

-- 조치된 장애는 CLOSED로 바뀐다. 이력이 남는다.

SYS@orcl> EXIT

[oracle@oel7v9 ~]$ rman target /

RMAN> LIST FAILURE ALL;

no failures found that match specification

-- ALL을 붙여도 열린 장애가 없다. 모두 CLOSED 되었기 때문이다.

RMAN> EXIT

-- 실무 포인트
-- 1) DRA는 장애를 자동으로 감지해 목록으로 관리한다.
--    부모 장애와 자식 장애로 구조화되어 영향 범위를 함께 보여 준다.
--    심각도는 CRITICAL, HIGH, LOW 세 단계이며 CRITICAL부터 처리한다.
--
-- 2) 리눅스에서는 파일을 지워도 인스턴스가 연 핸들로 계속 읽어 장애가 늦게 드러난다.
--    파일을 다시 열어야(재기동·오프라인/온라인) DRA가 감지한다.
--    재기동 시 OPEN에서 ORA-01157로 멈추고 DB는 MOUNTED로 남는다.
--
-- 3) REPAIR FAILURE는 같은 세션에서 ADVISE FAILURE를 먼저 요구한다(RMAN-06954).
--    ADVISE 를 다시 부를 때 대상을 안 주면 RMAN-07211이 나므로 ALL이나 장애 번호를 붙인다.
--    조치안을 보지 않고는 실행할 수 없게 만든 안전장치다.
--
-- 4) PREVIEW로 스크립트를 반드시 확인한다.
--    SET UNTIL이 있으면 불완전 복구이고 CLEAR UNARCHIVED가 있으면
--    아카이브 연속성이 끊긴다. 둘 중 하나라도 있으면 그대로 실행하지 않는다.
--
-- 5) 제시된 스크립트는 15장에서 배운 절차와 같다.
--    DRA가 특별한 방법을 쓰는 것이 아니라 표준 절차를 자동 구성할 뿐이다.
--    상태(OPEN/MOUNTED)에 따라 offline 단계 유무와 마무리 open 여부만 달라진다.
--
-- 6) 조치된 장애는 CLOSED로 바뀌며 v$ir_failure 에 이력이 남는다.
--    REPAIR FAILURE NOPROMPT 는 확인 없이 실행하므로 PREVIEW로 검토한 뒤에만 쓴다.
