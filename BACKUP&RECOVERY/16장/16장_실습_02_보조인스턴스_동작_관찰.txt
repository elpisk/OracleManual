-- 공간이 부족할 때 어떤 오류가 나는지 재현한다.
-- Memory Script의 내용을 해석한다.
-- 정리가 실패했을 때의 뒷정리 절차를 확인한다.

[2] 사전 조건
--------------------------------------------------------------------------------

-- 공간 부족을 재현하기 위해 작은 디렉터리를 준비한다.

[6] 진단
--------------------------------------------------------------------------------
-- << 원인 파악 >>
-- ORA-19504와 ORA-15041은 공간 부족을 뜻한다.
-- 보조 인스턴스는 SYSTEM·SYSAUX·UNDO와 대상 TS를 모두 복원한다.
-- 복구할 테이블이 50행에 불과해도 약 1.8GB가 필요하다.
-- 300MB 공간으로는 SYSTEM 파일 하나도 복원할 수 없다.

[oracle@oel7v9r1 ~]$ sqlplus -s / as sysdba <<< \
> "SELECT ROUND(SUM(bytes)/1024/1024) AS need_mb FROM dba_data_files
   WHERE tablespace_name IN ('SYSTEM','SYSAUX','UNDOTBS1','USERS');"

   NEED_MB
----------
      1770

-- 실행 전에 이 값을 확인했어야 한다.

-- 실무 포인트
-- 1) 보조 인스턴스는 대상 데이터베이스와 별개의 인스턴스다.
--    임의의 SID가 부여되며 ps 명령으로 확인할 수 있다.
--    작업이 끝나면 자동으로 정리된다.
--
-- 2) 공간 요구는 복구할 테이블 크기와 무관하다.
--    SYSTEM·SYSAUX·UNDO와 대상 TS를 모두 복원하기 때문이다.
--    50행짜리 테이블에도 약 1.8GB가 필요했다.
--
-- 3) 실행 전에 필요량을 계산한다.
--    dba_data_files 에서 네 테이블스페이스의 합을 구하면 된다.
--    여유를 두고 1.5배 정도의 공간을 확보하는 편이 안전하다.
--
-- 4) 실패하면 보조 인스턴스가 남을 수 있다.
--    ps 로 확인하고 ORACLE_SID를 그 값으로 바꿔 SHUTDOWN ABORT 한다.
--    AUXILIARY DESTINATION 의 파일도 함께 지운다.
--
-- 5) 정리하지 않으면 다음 수행 때 공간 부족을 만든다.
--    실패 후에는 반드시 디렉터리를 확인한다.
--
-- 6) Memory Script는 RMAN이 자동 구성한 복구 스크립트다.
--    clone 이 붙은 명령이 보조 인스턴스를 대상으로 한다.
--    15장에서 배운 절차와 같은 내용임을 확인할 수 있다.
