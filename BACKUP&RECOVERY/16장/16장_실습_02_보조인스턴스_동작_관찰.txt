[6] 진단
--------------------------------------------------------------------------------
-- << 원인 파악 >>
-- ORA-27072 의 'No space left on device' 가 공간 부족을 뜻한다.
-- (ASM 이라면 ORA-15041 로, 파일 시스템이라면 이렇게 나온다.)
-- 보조 인스턴스는 SYSTEM·SYSAUX·UNDO와 대상 TS를 모두 복원한다.
-- 복구할 테이블이 50행에 불과해도 그만큼의 공간이 필요하다.
-- 300MB 로는 UNDO 파일 하나도 다 복원하지 못한다.

[oracle@oel7v9 ~]$ sqlplus -s / as sysdba <<< \
> "SELECT ROUND(SUM(bytes)/1024/1024) AS need_mb FROM dba_data_files
   WHERE tablespace_name IN ('SYSTEM','SYSAUX','UNDOTBS1','USERS');"

   NEED_MB
----------
      1770

-- 실행 전에 이 값을 확인했어야 한다.

-- 실무 포인트
-- 1) 보조 인스턴스는 대상 데이터베이스와 별개의 인스턴스다.
--    임의의 SID(sznh 등)가 부여되며 ps 명령으로 확인할 수 있다.
--    작업이 끝나거나 실패하면 19c 는 스스로 내리고 파일을 지운다.
--
-- 2) 공간 요구는 복구할 테이블 크기와 무관하다.
--    SYSTEM·SYSAUX·UNDO와 대상 TS를 모두 복원하기 때문이다.
--    50행짜리 테이블에도 약 1.8GB가 필요했다.
--
-- 3) 실행 전에 필요량을 계산한다.
--    dba_data_files 에서 SYSTEM·SYSAUX·UNDO 와 대상 TS 의 합을 구하면 된다.
--    여유를 두고 1.5배 정도의 공간을 확보하는 편이 안전하다.
--
-- 4) 공간이 부족하면 ORA-19502/ORA-27072 'No space left on device' 가 나온다.
--    RMAN 은 조각을 바꿔 가며 'failover to previous backup' 를 반복하다
--    끝내 RMAN-06026/06023 으로 중단한다.
--
-- 5) 19c 는 실패해도 보조 인스턴스를 자동으로 정리한다.
--    'Removing automatic instance' 뒤에 pmon 이 남지 않고 파일도 지워진다.
--    'could not be removed' 경고가 보여도 tmpfs 를 비운 것은 그 정리 과정이다.
--    (드물게 정리가 실패하면 ps 로 SID 를 찾아 SHUTDOWN ABORT 하고 파일을 지운다.)
--
-- 6) Memory Script는 RMAN이 자동 구성한 복구 스크립트다.
--    clone 이 붙은 명령이 보조 인스턴스를 대상으로 한다.
--    15장에서 배운 절차와 같은 내용임을 확인할 수 있다.
