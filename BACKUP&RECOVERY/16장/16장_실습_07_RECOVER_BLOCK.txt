================================================================================
 실습 16-7 : RECOVER BLOCK으로 손상 블록만 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 30분

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 블록 손상을 다시 만들고 블록 단위로만 복구한다.
-- 복구 중에도 다른 블록에 접근할 수 있음을 확인한다.
-- 파일 복구와 소요 시간을 비교한다.
-- NOLOGGING 블록은 복구되지 않는 것도 확인한다.
-- 복구 유형 : 블록 미디어 복구, 업무 중단 없음

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 16-6까지 완료되어 있어야 한다.
-- 손상 이전 백업이 반드시 필요하다.

[oracle@oel7v9r1 ~]$ rman target / catalog rcatowner@rcat

RMAN> BACKUP DATAFILE 7 TAG 'BASE_167';

Starting backup at 18-MAY-25
Finished backup at 18-MAY-25

RMAN> EXIT

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

-- 실습 16-5에서 만든 테이블이며 손상은 이미 복구되었다.

  2  SELECT LEVEL + 500, RPAD('y', 2000, 'y') FROM dual CONNECT BY LEVEL <= 100;
SYS@orcl> COMMIT;

-- NOLOGGING으로 적재한 테이블도 만들어 둔다.

SYS@orcl> CREATE TABLE hr.blk167_nl NOLOGGING TABLESPACE users
  2  AS SELECT LEVEL AS id, RPAD('z',2000,'z') AS pad
  3     FROM dual CONNECT BY LEVEL <= 100;

Table created.

SYS@orcl> SELECT MIN(DBMS_ROWID.rowid_block_number(ROWID)) AS min_blk
  2  FROM   hr.blk167_nl;

   MIN_BLK
----------
       420

SYS@orcl> EXIT

-- 판정
--   ① 손상 블록 3개 → 블록 복구가 적절 (파일 복구는 과하다)

-- 블록 복구는 3초에 끝났다.
-- 같은 파일을 전체 복구했다면 복원에만 수십 초가 걸렸을 것이다.

[oracle@oel7v9r1 ~]$ rman target / catalog rcatowner@rcat
RMAN> BACKUP DATAFILE 7 TAG 'AFTER_BLOCK';
RMAN> VALIDATE DATAFILE 7;

7    OK     0              380          1280            2717600

RMAN> EXIT

-- 실무 포인트
-- 1) 블록 복구는 손상 블록만 백업에서 꺼내 되돌린다.
--    이 실습에서는 3초에 끝났다. 파일 복구와 비교하면 차이가 크다.
--    파일을 OFFLINE으로 내리지 않아 업무도 멈추지 않는다.
--
-- 2) 같은 파일의 다른 객체는 정상적으로 조회된다.
--    손상 블록을 읽는 세션만 오류를 만난다.
--    이것이 파일 복구와의 가장 큰 차이다.
--
-- 3) RECOVER CORRUPTION LIST 는 목록 전체를 대상으로 한다.
--    복구된 블록은 목록에서 사라지고 실패한 것만 남는다.
--    남은 항목을 확인하는 것이 복구 후 첫 검증이다.
--
-- 4) 백업 이후에 만들어진 객체의 블록은 복구할 수 없다.
--    백업에 그 블록의 내용이 없기 때문이다.
--    RMAN-06023이 그 사실을 알려 준다.
--
-- 5) NOLOGGING으로 적재된 블록도 마찬가지다.
--    리두에 내용이 없어 어떤 방법으로도 되살릴 수 없다.
--    해당 객체를 재생성하거나 재적재하는 수밖에 없다.
--
-- 6) 객체를 지우면 그 블록이 재사용되어 손상 표시가 해소된다.
--    다만 데이터는 잃은 것이므로 재적재 계획이 함께 필요하다.
--    복구 후 VALIDATE로 손상이 없는지 다시 확인한다.
