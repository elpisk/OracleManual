--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- SYSTEM 데이터파일 하나와 컨트롤파일 전부가 손상되었다.
-- 다른 데이터파일과 리두, 아카이브는 온전하다.
-- SYSTEM은 OFFLINE 할 수 없어 데이터베이스 전체가 중단된다.
-- 대신 복원 대상이 하나뿐이므로 복구 시간은 짧다.
-- 복구 유형 : 완전 복구, RESETLOGS 강제

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

-- 백업 매니페스트에 데이터파일 개수를 기록해 둔다.

-- 3단계 : 복원 대상 판별

SYS@orcl> SELECT file#, error, change# FROM v$recover_file ORDER BY file#;

     FILE# ERROR                    CHANGE#
---------- -------------------- -----------
         1 FILE NOT FOUND                 0
         3                          2450300
         4                          2450300
         7                          2450300

-- 1번만 ERROR가 FILE NOT FOUND다. 나머지는 파일이 있고 SCN만 뒤처져 있다.
-- 뒤처진 것은 백업 컨트롤파일의 SCN이 오래되어 그런 것이며 파일 자체는 최신이다.
-- 복원 대상은 1번 하나뿐이다.

SYS@orcl> !cp -p /home/oracle/backup/ch12/*.dbf /u02/oradata/ORCL/

-- << 여기서 판단 착오를 확인한다 >>
-- 전부 복원했다. 편해 보이지만 복구 시간이 늘어난다.

SYS@orcl> SELECT file#, checkpoint_change# FROM v$datafile_header ORDER BY file#;

     FILE# CHECKPOINT_CHANGE#
---------- ------------------
         1            2447100
         3            2447100
         4            2447100
         7            2447100

-- 네 파일 모두 백업 시점으로 돌아갔다.
-- 원래는 3·4·7번이 최신 상태였으므로 그 구간의 아카이브를 다시 적용해야 한다.
-- 복원 대상을 최소화했다면 적용할 아카이브가 훨씬 적었을 것이다.

-- << 수정 >> 실습에서는 판별의 효과를 확인하기 위해 되돌린다.

SYS@orcl> !cp -p /home/oracle/before_recover_122/sysaux01.dbf \
                 /home/oracle/before_recover_122/undotbs01.dbf \
                 /home/oracle/before_recover_122/users01.dbf /u02/oradata/ORCL/

-- 실무 포인트
-- 1) SYSTEM이 포함되면 손상 범위가 좁아도 전면 중단이다.
--    OFFLINE 할 수 없어 부분 처리가 불가능하기 때문이다.
--    대신 복원 대상이 적어 복구 시간은 오히려 짧다.
--
-- 2) 컨트롤파일은 CONTROL_FILES의 모든 경로에 빠짐없이 복사한다.
--    하나만 빠져도 ORA-00205가 다시 나온다. alert log가 어느 파일인지 알려 준다.
--
-- 3) v$recover_file 의 ERROR 컬럼으로 복원 대상을 판별한다.
--    FILE NOT FOUND면 파일이 없는 것이고, 비어 있으면 파일은 있고 SCN만 뒤처진 것이다.
--    후자는 복원 대상이 아니다.
--
-- 4) 멀쩡한 파일까지 되돌리면 그만큼 아카이브를 더 적용해야 한다.
--    이 실습에서 전부 복원했을 때와 하나만 복원했을 때의 SCN 차이가 그 증거다.
--    복원 대상 최소화가 복구 시간 단축의 첫 번째 방법이다.
--
-- 5) OS의 파일 개수와 매니페스트의 개수를 비교하면 손상 범위를 몇 초에 확인할 수 있다.
--    매니페스트를 백업 때마다 갱신해 두는 것이 이 판정을 가능하게 한다.
