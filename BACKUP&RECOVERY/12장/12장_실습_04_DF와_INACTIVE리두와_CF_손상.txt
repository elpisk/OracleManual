================================================================================
 실습 12-4 : 일반 데이터파일 + INACTIVE 리두 + 컨트롤파일 손상
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 30분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 디스크 하나가 손상되어 일반 데이터파일, INACTIVE 리두 그룹, 컨트롤파일이 함께 사라졌다.
-- CURRENT 그룹은 다른 디스크에 있어 살아 있다.
-- 손상된 리두 그룹은 이미 아카이브가 완료되어 사본이 있다.
-- 세 종류가 동시에 손상되었지만 손실은 없다.
-- 복구 유형 : 완전 복구, RESETLOGS 강제

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- ARCHIVELOG 모드이며 실습 직전에 전체 백업과 컨트롤파일 백업을 받는다.
-- 리두는 그룹 세 개, 그룹마다 멤버 두 개이며 두 디스크에 분산되어 있다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL member FOR a44

-- 판정
--   ① 컨트롤파일 수단 : Binary 백업본 있음
--   ② 아카이브 연속 : 22개, 결손 없음
--   ③ CURRENT 리두 : 그룹 4 생존
--   → 완전 복구 가능. 손실 없음.
--   손상된 그룹 1은 INACTIVE이며 아카이브 사본이 있으므로 문제되지 않는다.

-- 0단계 : 남아 있는 파일을 별도 위치로 복사한다.

SYS@orcl> !D=/home/oracle/before_recover_124; mkdir -p $D; \
          cp -p /u02/oradata/ORCL/*.dbf $D/ 2>/dev/null; \
          cp -p /u01/app/oracle/oradata/ORCL/*.log $D/ 2>/dev/null; \
          cp -p /u02/oradata/ORCL/*.log $D/ 2>/dev/null; \
          date > $D/copied_at.txt; ls -l $D >> $D/copied_at.txt

-- 실무 포인트
-- 1) 세 종류가 동시에 손상되어도 손실이 없을 수 있다.
--    손상된 리두가 INACTIVE이고 아카이브가 완료되어 사본이 있었기 때문이다.
--    파일 종류의 개수가 아니라 어느 그룹이 손상되었는지가 결과를 정한다.
--
-- 2) 손상된 INACTIVE 그룹에 대해 CLEAR를 따로 수행할 필요가 없다.
--    RESETLOGS 오픈이 모든 그룹의 파일을 새로 만들기 때문이다.
--
-- 3) ORA-00344와 ORA-27040은 리두를 만들 위치의 문제다.
--    디렉터리 권한, 소유자, 공간을 순서대로 확인한다.
--    복구 도중 권한이 바뀌는 일은 실무에서 드물지 않다.
--
-- 4) 리두 멤버를 두 디스크에 분산했기 때문에 CURRENT 그룹이 살아남았다.
--    같은 디스크에 몰려 있었다면 CURRENT까지 잃어 불완전 복구가 되었을 것이다.
--    다중화의 효과가 가장 직접적으로 드러나는 사례다.
--
-- 5) 복구 후 v$logfile 의 STATUS가 비어 있는지 확인한다.
--    INVALID가 남아 있으면 파일이 제대로 만들어지지 않은 것이다.
