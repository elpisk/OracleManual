================================================================================
 실습 3-1 : Cold Backup 수행
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 12분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- 데이터베이스를 정상 종료하고 모든 파일을 복사해 일관성 있는 백업본을 만든다.
-- 종료 전후로 SCN 과 FUZZY 를 확인해 백업본이 유효한지 검증한다.
-- 여기서 만든 백업본은 4~7장 NOARCHIVELOG 시나리오의 출발점이 되므로 삭제하지 않는다.
-- 복구 유형 : 해당 없음(백업 작업)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태이고 다른 사용자가 접속하지 않은 개별 환경이어야 한다.
-- 백업 디스크에 데이터베이스 전체 크기 이상의 여유가 있어야 한다.
-- 2장에서 리두 로그 멤버를 /u02 에도 만들었으므로 복사 경로가 두 곳이다.

[oracle@oel7v9r1 ~]$ df -h /home/oracle
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda3        20G  4.2G   16G  22% /home

[oracle@oel7v9r1 ~]$ mkdir -p /home/oracle/backup/cold/20250509
[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL name FOR a52

[4] 작업 수행 : 정상 종료와 일관성 확인
--------------------------------------------------------------------------------

Database dismounted.
ORACLE instance shut down.

-- 복사 전에 백업본이 일관성 있는 상태인지 확인한다.

SYS@orcl> STARTUP MOUNT

Total System Global Area 1140849904 bytes

SYS@orcl> SELECT file#, checkpoint_change#, fuzzy, status FROM v$datafile_header ORDER BY file#;

     FILE# CHECKPOINT_CHANGE# FUZ STATUS
---------- ------------------ --- -------
         1            2341598 NO  ONLINE
         3            2341598 NO  ONLINE
         4            2341598 NO  ONLINE

-- FUZZY 가 모두 NO 이고 SCN 이 일치한다. 일관성 있는 상태다.
-- 이 상태에서 복사한 백업본은 복원 후 리두 적용 없이 그대로 열린다.

SYS@orcl> SHUTDOWN IMMEDIATE
ORA-01109: database not open

Database dismounted.
ORACLE instance shut down.

-- ORA-01109 는 오류가 아니라 안내 메시지다. MOUNT 상태에서 내렸으므로 정상이다.

--------------------------------------------------------------------------------
[5] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 데이터 파일과 제어 파일만 복사하고 리두 로그를 빠뜨려 본다.

[oracle@oel7v9r1 ~]$ BKP=/home/oracle/backup/cold/20250509
[oracle@oel7v9r1 ~]$ cp -pv /u01/app/oracle/oradata/ORCL/*.dbf $BKP/
'/u01/app/oracle/oradata/ORCL/sysaux01.dbf' -> '.../sysaux01.dbf'
'/u01/app/oracle/oradata/ORCL/system01.dbf' -> '.../system01.dbf'
'/u01/app/oracle/oradata/ORCL/temp01.dbf' -> '.../temp01.dbf'
'/u01/app/oracle/oradata/ORCL/undotbs01.dbf' -> '.../undotbs01.dbf'
'/u01/app/oracle/oradata/ORCL/users01.dbf' -> '.../users01.dbf'

[oracle@oel7v9r1 ~]$ cp -pv /u01/app/oracle/oradata/ORCL/*.ctl $BKP/

[oracle@oel7v9r1 ~]$ ls $BKP/ | wc -l
7

-- << 오류 발생 >>
-- 조회로 확인한 대상은 13개인데 7개만 복사되었다.

[oracle@oel7v9r1 ~]$ ls $BKP/
control01.ctl  control02.ctl  sysaux01.dbf  system01.dbf  temp01.dbf  undotbs01.dbf  users01.dbf

-- << 원인 파악 >>
-- 두 가지 문제가 있다.
--   1) 리두 로그(*.log)를 복사하지 않았다. Cold Backup 에서는 반드시 포함해야 한다.
--   2) /u02 경로의 제어 파일과 리두 멤버가 빠졌다. 와일드카드가 /u01 만 대상으로 했다.
--   3) 반대로 temp01.dbf 는 백업 대상이 아닌데 *.dbf 에 걸려 들어왔다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ rm -f $BKP/temp01.dbf
[oracle@oel7v9r1 ~]$ cp -pv /u01/app/oracle/oradata/ORCL/*.log $BKP/
[oracle@oel7v9r1 ~]$ cp -pv /u02/oradata/ORCL/*.ctl /u02/oradata/ORCL/*.log $BKP/

[oracle@oel7v9r1 ~]$ ls $BKP/ | wc -l
13

[oracle@oel7v9r1 ~]$ ls $BKP/
control01.ctl  control03.ctl  redo01b.log  redo03b.log  redo04b.log  sysaux01.dbf  undotbs01.dbf
control02.ctl  redo01.log     redo03.log   redo04.log   system01.dbf users01.dbf

-- 13개가 모두 갖춰졌다. temp01.dbf 는 제외되었다.

--------------------------------------------------------------------------------
[6] 진단 : 왜 손으로 적으면 안 되는가
--------------------------------------------------------------------------------
-- 경로가 /u01 과 /u02 두 곳으로 나뉘어 있어 와일드카드 하나로는 전부 잡히지 않는다.
-- 데이터 파일이 추가되거나 리두 멤버가 늘어나면 스크립트를 매번 고쳐야 한다.
-- 조회 결과에서 복사 명령을 생성하면 이런 누락이 생기지 않는다.
-- 실습 1-4 에서 만든 방식을 그대로 쓴다.

SYS@orcl> STARTUP MOUNT
SYS@orcl> SET PAGESIZE 0 FEEDBACK OFF HEADING OFF ECHO OFF TRIMSPOOL ON
SYS@orcl> SPOOL /tmp/cold_copy.sh

SYS@orcl> SELECT 'cp -p ' || name || ' /home/oracle/backup/cold/20250509/' FROM v$datafile
  2  UNION ALL
  3  SELECT 'cp -p ' || name || ' /home/oracle/backup/cold/20250509/' FROM v$controlfile
  4  UNION ALL
  5  SELECT 'cp -p ' || member || ' /home/oracle/backup/cold/20250509/' FROM v$logfile;

SYS@orcl> SPOOL OFF
SYS@orcl> SET PAGESIZE 100 FEEDBACK ON HEADING ON

SYS@orcl> !grep -c '^cp' /tmp/cold_copy.sh
13

-- 13줄이 생성되었다. TEMP 파일은 v$datafile 에 없으므로 자동으로 제외된다.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) 종료 방식이 전부다. NORMAL·IMMEDIATE·TRANSACTIONAL 중 하나여야 한다.
--    세 방식 모두 종료 전 체크포인트를 완료해 파일 간 SCN 을 일치시킨다.
--
-- 2) 복사 전에 MOUNT 상태에서 FUZZY 를 확인하는 습관을 들인다.
--    FUZZY 가 YES 이면 일관성 없는 백업본이 되며, 그 사실을 장애 때 알게 되면 늦다.
--
-- 3) 복사 대상은 조회 결과에서 생성한다.
--    경로가 여러 곳으로 나뉘면 와일드카드 하나로는 반드시 빠뜨린다.
--
-- 4) TEMP 파일은 백업 대상이 아니다. *.dbf 로 복사하면 함께 들어오므로 제외한다.
--    포함해도 해가 되지는 않지만 공간만 차지한다.
--
-- 5) Cold Backup 에서는 온라인 리두 로그를 반드시 포함한다.
--    데이터 파일과 SCN 이 일치하므로 함께 되돌리면 그대로 열린다.
--    Hot Backup(실습 3-3)에서는 반대로 제외한다는 점을 대비해 기억한다.
--
-- 6) 이 백업본은 4~7장 시나리오에서 사용한다. 날짜 디렉터리째 보관한다.

SYS@orcl> EXIT
