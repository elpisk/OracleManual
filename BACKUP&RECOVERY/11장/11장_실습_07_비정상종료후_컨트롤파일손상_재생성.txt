--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- SHUTDOWN ABORT 뒤 컨트롤파일이 전손되었다.
-- 적용할 리두가 남아 있어 재생성만으로는 열리지 않는다.
-- 재생성한 컨트롤파일은 온라인 리두의 현재 위치를 알고 있으므로
-- RECOVER DATABASE 가 아카이브와 온라인 리두를 이어서 적용하고 그대로 열린다.
-- 실습 11-5의 백업 컨트롤파일(USING BACKUP CONTROLFILE, RESETLOGS)과 대비된다.
-- 복구 유형 : 완전 복구(RESETLOGS 불필요)

-- 실무 포인트
-- 1) 컨트롤파일 생성 성공과 오픈 가능은 다른 문제다.
--    비정상 종료 상태에서는 적용할 리두가 남아 ORA-01113으로 막힌다.
--    실습 11-6에서는 FUZZY가 NO여서 그대로 열렸다.
--
-- 2) 재생성한 컨트롤파일은 백업 컨트롤파일이 아니다.
--    온라인 리두 헤더에서 현재 시퀀스를 읽어 오므로 RECOVER DATABASE 만으로
--    아카이브와 온라인 리두를 끝까지 적용한다. USING BACKUP CONTROLFILE 도,
--    온라인 리두 파일명을 손으로 주는 일도 없다.
--
-- 3) 그래서 RESETLOGS 가 강제되지 않는다.
--    형식(NORESETLOGS)과 오픈 방식이 일치한다. 인카네이션도 그대로다.
--    백업 컨트롤파일로 복구하면(11-5, 11-8) 예외 없이 RESETLOGS 다.
--
-- 4) 데이터 손실은 없다.
--    아카이브와 온라인 리두가 모든 구간을 담당했기 때문이다.
--    손실을 만드는 것은 CURRENT 리두 자체의 손상뿐이다.
--
-- 5) trace 재생성이므로 TEMP를 추가해야 한다.
--    복구 후 확인 항목에 UNNAMED 유무와 TEMP, 사본 수를 포함한다.
