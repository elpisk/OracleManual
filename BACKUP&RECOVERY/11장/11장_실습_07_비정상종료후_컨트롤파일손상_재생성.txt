[1] 시나리오 개요
--------------------------------------------------------------------------------
-- SHUTDOWN ABORT 뒤 컨트롤파일이 전손되었다.
-- 적용할 리두가 남아 있어 재생성만으로는 열리지 않는다.
-- USING BACKUP CONTROLFILE 로 복구한 뒤 RESETLOGS로 연다.
-- 아카이브와 온라인 리두를 함께 써서 완전 복구를 달성한다.
-- 복구 유형 : 완전 복구(RESETLOGS 강제)

-- 실무 포인트
-- 1) 컨트롤파일 생성 성공과 오픈 가능은 다른 문제다.
--    비정상 종료 상태에서는 적용할 리두가 남아 ORA-01113으로 막힌다.
--    실습 11-6에서는 FUZZY가 NO여서 그대로 열렸다.
--
-- 2) 새로 만든 컨트롤파일도 백업 컨트롤파일이다.
--    RECOVER DATABASE 만 쓰면 ORA-01610이 나온다.
--    리두 적용 이력이 없어 어디까지 복구되었는지 알 수 없기 때문이다.
--
-- 3) NORESETLOGS 형식으로 만들었어도 RESETLOGS가 강제된다.
--    형식 선택과 최종 오픈 방식은 별개의 문제다.
--    USING BACKUP CONTROLFILE 로 복구했다면 예외 없이 RESETLOGS다.
--
-- 4) 아카이브가 자동 적용되고 마지막 구간만 수동이다.
--    CURRENT 그룹의 리두는 아직 아카이브되지 않아 ORA-00308로 멈춘다.
--    AUTORECOVERY를 끄고 그 그룹의 멤버 경로를 입력하면 완전 복구가 된다.
--
-- 5) 데이터 손실은 없다.
--    아카이브와 온라인 리두가 모든 구간을 담당했기 때문이다.
--    손실을 만드는 것은 CURRENT 리두 자체의 손상뿐이다.
--
-- 6) trace 재생성이므로 TEMP를 추가해야 한다.
--    복구 후 확인 항목에 UNNAMED 유무와 TEMP, 사본 수를 포함한다.

SYS@orcl> EXIT
