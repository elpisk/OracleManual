 실습 1-1 : 백업 대상 파일 확인
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 10분

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- 복구 작업은 "무엇이 없어졌는가"를 아는 데서 시작한다.
-- 그러려면 먼저 "무엇이 있어야 하는가"를 알아야 한다.
-- 이 실습은 백업 대상이 되는 물리 파일 전체를 한 목록으로 뽑고,
-- 다중화 상태를 점검하며, 백업 대상에서 제외되는 파일을 확인한다.
-- 복구 유형 : 해당 없음(확인 실습)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태여야 한다.
-- SYSDBA 권한으로 접속한다.
-- 이 실습은 조회만 수행하므로 데이터베이스를 손상시키지 않는다.

--------------------------------------------------------------------------------

SYS@orcl> SELECT instance_name, status, database_status FROM v$instance;

---------------- ------------ -----------------
orcl             OPEN         ACTIVE

SYS@orcl> SELECT name, open_mode, log_mode, checkpoint_change# FROM v$database;

NAME      OPEN_MODE            LOG_MODE     CHECKPOINT_CHANGE#

-- LOG_MODE가 NOARCHIVELOG다.
-- 이 상태에서는 아카이브 로그가 생성되지 않으며 복구 가능 범위가 제한된다.
-- ARCHIVELOG 전환은 2장에서 다룬다.

--------------------------------------------------------------------------------
[4] 작업 수행 : 백업 대상 파일 통합 조회
--------------------------------------------------------------------------------
-- 데이터 파일

SYS@orcl> SELECT file#, name, bytes/1024/1024 AS mb, status
  2  FROM   v$datafile ORDER BY file#;

     FILE# NAME                                                        MB STATUS
---------- ---------------------------------------------------- --------- -------
         1 /u01/app/oracle/oradata/ORCL/system01.dbf                  900 SYSTEM
         3 /u01/app/oracle/oradata/ORCL/sysaux01.dbf                  560 ONLINE
         4 /u01/app/oracle/oradata/ORCL/undotbs01.dbf                 105 ONLINE
         7 /u01/app/oracle/oradata/ORCL/users01.dbf                     5 ONLINE

-- FILE# 이 1,3,4,7 로 건너뛴다. 2와 5,6은 과거에 삭제된 파일 번호이며 정상이다.
-- STATUS 가 SYSTEM 인 1번은 OFFLINE 할 수 없는 파일이다. 이 차이가 복구 절차를 가른다.

-- 제어 파일

[6] 백업 대상에서 제외되는 파일 확인
--------------------------------------------------------------------------------
-- TEMP 파일은 v$datafile 에 나타나지 않는다. 별도 뷰로 조회한다.

SYS@orcl> SELECT file#, name, bytes/1024/1024 AS mb, status FROM v$tempfile;

     FILE# NAME                                                        MB STATUS
---------- ---------------------------------------------------- --------- -------
         1 /u01/app/oracle/oradata/ORCL/temp01.dbf                     60 ONLINE

-- TEMP 파일은 정렬·해시 조인에 쓰이는 임시 데이터만 담는다.
-- 유실되어도 재생성으로 끝나므로 백업 대상이 아니다. 재생성 절차는 5장에서 다룬다.

-- 파라미터 파일은 어느 뷰에도 나오지 않지만 백업 대상이다.

SYS@orcl> SHOW PARAMETER spfile

NAME    TYPE     VALUE
------- -------- ---------------------------------------------------------
spfile  string   /u01/app/oracle/product/19.3.0/dbhome_1/dbs/spfileorcl.ora

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) 제어 파일 두 개가 모두 /u01 아래에 있다. 이것은 다중화가 아니다.
--    /u01 디스크가 손상되면 두 파일이 함께 사라진다.
--    운영 환경에서는 서로 다른 물리 디스크에 배치한다. 구성 절차는 2장에서 다룬다.
--
-- 2) v$log 의 MEMBERS 가 모두 1이다. 그룹마다 사본이 하나뿐이라는 뜻이다.
--    CURRENT 그룹(여기서는 2번)의 유일한 멤버가 손상되면 완전 복구가 불가능해진다.
--
-- 3) 백업 대상에서 가장 자주 빠뜨리는 것이 파라미터 파일이다.
--    데이터 파일만 백업하면 복원은 되지만 인스턴스를 기동할 수 없다.
--
-- 4) 이 조회 결과는 실습 1-4에서 백업 스크립트를 자동 생성하는 입력으로 그대로 쓴다.

SYS@orcl> EXIT
