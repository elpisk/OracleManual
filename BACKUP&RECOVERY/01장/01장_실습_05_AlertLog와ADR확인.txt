================================================================================
 실습 1-5 : Alert Log와 ADR 확인
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 10분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- 복구 명령을 아무리 잘 알아도 무엇이 잘못됐는지 못 찾으면 쓸 수 없다.
-- ADR 의 구조를 확인하고, adrci 로 alert log 를 필터링해 조회하는 절차를 익힌다.
-- 4장 이후 모든 시나리오의 "증상 관찰" 단계에서 이 절차를 반복 사용한다.
-- 복구 유형 : 해당 없음(진단 실습)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태여야 한다.
-- oracle OS 계정으로 셸에 접근할 수 있어야 한다.
-- 실습 1-2 를 먼저 수행했다면 alert log 에 crash recovery 기록이 남아 있어 조회 결과가 풍부하다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL name FOR a24
SYS@orcl> COL value FOR a60

[5] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- home 을 지정하지 않고 바로 조회를 시도한다.

adrci> SHOW ALERT -TAIL 20
DIA-48449: Tail alert can only apply to single ADR home

-- << 원인 파악 >>
-- ADR home 이 두 개인데 대상을 지정하지 않아 adrci 가 어느 쪽을 볼지 결정하지 못했다.
-- SHOW HOMES 결과가 하나뿐이면 이 오류가 나지 않는다.

-- << 수정 >>

adrci> SET HOME diag/rdbms/orcl/orcl

adrci> SHOW HOMES

[6] ORA 오류만 필터링해서 보기
--------------------------------------------------------------------------------
-- -P 옵션에 조건을 주면 조건에 맞는 줄만 나온다. -TERM 은 편집기를 열지 않고 화면에 출력한다.

adrci> SHOW ALERT -P "MESSAGE_TEXT LIKE '%ORA-%'" -TERM

ADR Home = /u01/app/oracle/diag/rdbms/orcl/orcl:
*************************************************************************
2025-05-06 08:41:12.336000 +09:00
ORA-01110: data file 7: '/u01/app/oracle/oradata/ORCL/users01.dbf'
ORA-01157: cannot identify/lock data file 7 - see DBWR trace file
2025-05-06 08:44:57.201000 +09:00
ORA-00312: online log 2 thread 1: '/u01/app/oracle/oradata/ORCL/redo02.log'

-- 시간 범위로 좁힐 수도 있다.

adrci> SHOW ALERT -P "ORIGINATING_TIMESTAMP > systimestamp - 1" -TERM

-- 인시던트와 문제 목록을 확인한다.

adrci> SHOW INCIDENT

ADR Home = /u01/app/oracle/diag/rdbms/orcl/orcl:
*************************************************************************
0 rows fetched

adrci> SHOW PROBLEM

ADR Home = /u01/app/oracle/diag/rdbms/orcl/orcl:
*************************************************************************
0 rows fetched

-- 인시던트가 0건이면 심각한 내부 오류(ORA-600, ORA-7445 등)가 없었다는 뜻이다.

adrci> EXIT

--------------------------------------------------------------------------------
[7] 검증 : SQL 로도 같은 내용을 확인
--------------------------------------------------------------------------------
[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL message_text FOR a76

SYS@orcl> SELECT TO_CHAR(originating_timestamp,'MM-DD HH24:MI:SS') AS ts, message_text
  2  FROM   v$diag_alert_ext
  3  WHERE  message_text LIKE 'ORA-%'
  4  AND    originating_timestamp > SYSTIMESTAMP - 1
  5  ORDER  BY originating_timestamp;

TS              MESSAGE_TEXT
--------------- ----------------------------------------------------------------------------
05-06 08:41:12  ORA-01110: data file 7: '/u01/app/oracle/oradata/ORCL/users01.dbf'
05-06 08:41:12  ORA-01157: cannot identify/lock data file 7 - see DBWR trace file
05-06 08:44:57  ORA-00312: online log 2 thread 1: '/u01/app/oracle/oradata/ORCL/redo02.log'

3 rows selected.

-- adrci 와 v$diag_alert_ext 는 같은 XML alert log 를 읽으므로 결과가 일치한다.

-- 텍스트 alert log 를 직접 읽어도 된다. 복구 작업 중에는 이 방식이 편하다.

SYS@orcl> !tail -f /u01/app/oracle/diag/rdbms/orcl/orcl/trace/alert_orcl.log
(Ctrl+C 로 종료)

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) ADR home 이 여러 개일 때는 SET HOME 으로 대상을 먼저 지정한다.
--    지정하지 않으면 DIA-48449 가 발생한다.
--
-- 2) 장애 분석은 발생 시각 전후 10분 구간만 본다. 그 앞뒤는 대개 무관한 정보다.
--
-- 3) ORA 오류가 여러 개 연달아 기록되면 먼저 기록된 쪽이 근본 원인인 경우가 많다.
--    위 결과에서 ORA-01157(파일 식별 불가)이 원인이고 ORA-01110 은 대상을 알려 주는 보조 정보다.
--
-- 4) 'Errors in file /u01/.../trace/orcl_dbw0_1234.trc' 같은 줄이 보이면
--    그 트레이스 파일에 상세 정보가 있다. 반드시 함께 확인한다.
--
-- 5) 복구를 수행하는 동안 별도 터미널에서 tail -f 로 alert log 를 열어 두면
--    RECOVER 진행 상황과 실패 원인을 실시간으로 볼 수 있다.
--
-- 6) ADR 은 자동으로 정리되지 않아 장기 운영 시 용량이 커진다.
--    adrci 의 PURGE 명령으로 보관 기간을 관리한다.
--    예) adrci> PURGE -AGE 43200 -TYPE ALERT   (30일 이전 alert 정리)

SYS@orcl> EXIT
