================================================================================
 실습 2-7 : 파라미터 파일과 제어 파일 백업
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 12분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- 데이터 파일만 백업해 두면 복원은 되지만 인스턴스를 기동할 수 없다.
-- 구성 자체를 백업하는 세 가지 산출물을 만든다.
--   파라미터 파일 텍스트 사본 / 제어 파일 바이너리 백업 / 제어 파일 트레이스 백업
-- 마지막으로 RMAN 자동 백업을 설정해 이후 장의 준비를 마친다.
-- 복구 유형 : 해당 없음(백업 준비)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태여야 한다.
-- /home/oracle/backup 디렉터리를 만들 수 있어야 한다.
-- 실습 2-1~2-6 에서 구성을 여러 번 바꿨으므로 지금이 백업을 새로 받을 시점이다.

[oracle@oel7v9r1 ~]$ mkdir -p /home/oracle/backup /home/oracle/backup/autobackup
[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200

--------------------------------------------------------------------------------
[5] 작업 수행 : 제어 파일 백업 두 가지
--------------------------------------------------------------------------------
-- 바이너리 백업 : 제어 파일을 그대로 복사한 것. SCN 정보를 갖는다.

SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO
  2    '/home/oracle/backup/control_20250509.ctl' REUSE;

Database altered.

-- 트레이스 백업 : CREATE CONTROLFILE 스크립트. 최신 구조를 갖는다.

SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO TRACE
  2    AS '/home/oracle/backup/control_orcl.txt' REUSE;

Database altered.

SYS@orcl> !grep -c 'CREATE CONTROLFILE' /home/oracle/backup/control_orcl.txt
2

SYS@orcl> !grep 'CREATE CONTROLFILE' /home/oracle/backup/control_orcl.txt
CREATE CONTROLFILE REUSE DATABASE "ORCL" NORESETLOGS  ARCHIVELOG
CREATE CONTROLFILE REUSE DATABASE "ORCL" RESETLOGS  ARCHIVELOG

-- 두 버전이 들어 있다.
--   NORESETLOGS : 온라인 리두 로그가 온전할 때 사용
--   RESETLOGS   : 온라인 리두 로그가 유실되었을 때 사용
-- 선택 기준은 6장과 11장에서 다룬다.

SYS@orcl> !sed -n '/NORESETLOGS/,/CHARACTER SET/p' /home/oracle/backup/control_orcl.txt
CREATE CONTROLFILE REUSE DATABASE "ORCL" NORESETLOGS  ARCHIVELOG

-- 트레이스 백업이 최신 구조를 갖는다는 것이 이런 뜻이다.

--------------------------------------------------------------------------------
[6] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 같은 경로로 트레이스 백업을 다시 받아 본다.

SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO TRACE
  2    AS '/home/oracle/backup/control_orcl.txt';
ALTER DATABASE BACKUP CONTROLFILE TO TRACE
*
ERROR at line 1:
ORA-27038: created file already exists
ORA-06512: at line 1
Additional information: 1

-- << 원인 파악 >>
-- 대상 파일이 이미 있으면 덮어쓰지 않고 오류를 낸다.
-- 실수로 기존 백업을 지우는 것을 막기 위한 동작이다.

-- << 수정 >>
-- 덮어쓰려면 REUSE 를 붙이고, 이력을 남기려면 파일명에 날짜를 넣는다.

SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO TRACE
  2    AS '/home/oracle/backup/control_orcl_20250509.txt';

Database altered.

-- REUSE 없이 날짜를 붙이는 쪽이 안전하다. 구조 변경 이력이 남기 때문이다.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) 세 산출물은 구조가 바뀔 때마다 새로 받는다.
--    데이터 파일 추가, 테이블스페이스 생성, 리두 그룹 변경, 제어 파일 경로 변경이 그 시점이다.
--    이 실습에서도 2-4·2-5 의 변경이 반영된 것을 확인했다.
--
-- 2) 파일명에 날짜를 붙이면 구조 변경 이력이 남는다.
--    REUSE 로 덮어쓰면 직전 상태를 잃는다. 디스크 여유가 있으면 날짜 방식을 권한다.
--
-- 3) SPFILE 을 잃어도 데이터는 무사하다.
--    STARTUP PFILE='경로' 로 기동한 뒤 CREATE SPFILE FROM PFILE 로 되살리고 재기동한다.
--    PFILE 도 없으면 alert log 의 기동 시 파라미터 목록으로 재작성할 수 있다.
--
-- 4) PFILE 로 기동한 상태에서는 ALTER SYSTEM ... SCOPE=spfile 이 동작하지 않는다.
--    SPFILE 을 만든 뒤 반드시 재기동해야 그때부터 SPFILE 로 동작한다.
--
-- 5) DBID 는 별도로 기록해 둔다.
--    제어 파일을 모두 잃으면 RMAN 이 카탈로그를 읽지 못하므로
--    SET DBID 로 자동 백업을 찾아야 한다. 15·16장에서 실제로 사용한다.
--
-- 6) 이 장의 구성 변경이 끝났으므로 3장에서 전체 백업을 새로 받는다.
--    ARCHIVELOG 전환 이전 백업은 아카이브와 계보가 이어지지 않아 쓸 수 없다.
