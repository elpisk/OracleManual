================================================================================
 실습 2-4 : 제어 파일 다중화
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 12분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- 제어 파일에 세 번째 사본을 다른 디스크에 추가한다.
-- CONTROL_FILES 는 정적 파라미터라 재기동이 필요하며, 복사 시점을 틀리면 문제가 생긴다.
-- 복사를 빠뜨렸을 때의 ORA-00205 를 재현하고 해소한다.
-- 복구 유형 : 해당 없음(구성 작업)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태이고 다른 사용자가 접속하지 않은 개별 환경이어야 한다.
-- /u02 파일시스템이 있고 oracle 계정에 쓰기 권한이 있어야 한다.

[oracle@oel7v9r1 ~]$ df -h /u02
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdc1        20G  1.2G   19G   7% /u02

[oracle@oel7v9r1 ~]$ mkdir -p /u02/oradata/ORCL
[oracle@oel7v9r1 ~]$ ls -ld /u02/oradata/ORCL
drwxr-xr-x. 2 oracle oinstall 6 May  9 10:02 /u02/oradata/ORCL

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL name FOR a52

--------------------------------------------------------------------------------
[4] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 무중단으로 적용하고 싶어 SCOPE=both 를 시도해 본다.

SYS@orcl> ALTER SYSTEM SET control_files =
  2    '/u01/app/oracle/oradata/ORCL/control01.ctl',
  3    '/u01/app/oracle/oradata/ORCL/control02.ctl',
  4    '/u02/oradata/ORCL/control03.ctl' SCOPE=both;
ALTER SYSTEM SET control_files =
*
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

-- << 원인 파악 >>
-- CONTROL_FILES 는 정적 파라미터다.
-- 인스턴스가 기동될 때 읽어 제어 파일을 여는 데 쓰이므로 운영 중 바꿀 수 없다.
-- SCOPE=spfile 로만 설정할 수 있고 재기동해야 적용된다.

SYS@orcl> SELECT name, issys_modifiable FROM v$parameter WHERE name = 'control_files';

NAME            ISSYS_MODIFIABLE
--------------- ----------------
control_files   FALSE

-- << 수정 >>

SYS@orcl> ALTER SYSTEM SET control_files =
  2    '/u01/app/oracle/oradata/ORCL/control01.ctl',
  3    '/u01/app/oracle/oradata/ORCL/control02.ctl',
  4    '/u02/oradata/ORCL/control03.ctl' SCOPE=spfile;

System altered.

--------------------------------------------------------------------------------

ORACLE instance shut down.

SYS@orcl> STARTUP

Total System Global Area 1140849904 bytes
Fixed Size                  8895728 bytes

ORA-00205: error in identifying control file, check alert log for more info

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
STARTED

-- << 원인 파악 >>
-- CONTROL_FILES 목록에 있는 세 번째 경로에 실제 파일이 없다.
-- 인스턴스는 기동되었으나 마운트에 실패해 NOMOUNT(STARTED) 상태에 머문다.

SYS@orcl> !tail -6 /u01/app/oracle/diag/rdbms/orcl/orcl/trace/alert_orcl.log
ORA-00202: control file: '/u02/oradata/ORCL/control03.ctl'

Linux-x86_64 Error: 2: No such file or directory
Additional information: 7
ORA-205 signalled during: ALTER DATABASE   MOUNT...

-- << 수정 >>
-- 인스턴스를 내리고 정상 사본을 복사한 뒤 다시 기동한다.

SYS@orcl> SHUTDOWN IMMEDIATE
ORA-01507: database not mounted
ORACLE instance shut down.

SYS@orcl> !cp -v /u01/app/oracle/oradata/ORCL/control01.ctl /u02/oradata/ORCL/control03.ctl
'/u01/app/oracle/oradata/ORCL/control01.ctl' -> '/u02/oradata/ORCL/control03.ctl'

ORACLE instance started.
Database mounted.
Database opened.

--------------------------------------------------------------------------------
[6] 진단 : 왜 종료 후에 복사해야 하는가
--------------------------------------------------------------------------------
-- 데이터베이스가 열려 있는 동안 제어 파일은 계속 갱신된다.
-- 체크포인트, 로그 스위치, 아카이브 생성 때마다 내용이 바뀐다.
-- 열린 상태에서 복사하면 그 사본은 기동 시점에 이미 낡아 있고,
-- 세 사본의 내용이 달라 마운트에 실패하거나 이후 불일치가 생긴다.

SYS@orcl> SELECT name FROM v$controlfile;

NAME
----------------------------------------------------
/u01/app/oracle/oradata/ORCL/control01.ctl
/u01/app/oracle/oradata/ORCL/control02.ctl
/u02/oradata/ORCL/control03.ctl

--------------------------------------------------------------------------------
[7] 검증 : 실제로 동시 기록되는가
--------------------------------------------------------------------------------
-- v$controlfile 조회는 파라미터에 무엇이 적혀 있는지만 보여 준다.
-- 실제 동시 기록 여부는 OS 에서 확인해야 한다.

SYS@orcl> !ls -l --time-style=+%H:%M:%S /u01/app/oracle/oradata/ORCL/control0*.ctl /u02/oradata/ORCL/control03.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:14:03 /u01/app/oracle/oradata/ORCL/control01.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:14:03 /u01/app/oracle/oradata/ORCL/control02.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:14:03 /u02/oradata/ORCL/control03.ctl

SYS@orcl> ALTER SYSTEM CHECKPOINT;

System altered.

SYS@orcl> !ls -l --time-style=+%H:%M:%S /u01/app/oracle/oradata/ORCL/control0*.ctl /u02/oradata/ORCL/control03.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:15:41 /u01/app/oracle/oradata/ORCL/control01.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:15:41 /u01/app/oracle/oradata/ORCL/control02.ctl
-rw-r-----. 1 oracle oinstall 10600448 10:15:41 /u02/oradata/ORCL/control03.ctl

-- 세 파일의 크기와 갱신 시각이 함께 움직였다. 동시 기록이 확인되었다.
-- 한 파일만 시각이 오래되었다면 그 경로는 실제로 쓰이지 않는 상태다.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) 절차 순서가 전부다.
--    SCOPE=spfile 설정 → SHUTDOWN IMMEDIATE → OS 복사 → STARTUP.
--    복사를 종료 전에 하면 뒤처진 사본이 되고, 빠뜨리면 ORA-00205 가 발생한다.
--
-- 2) ORA-00205 는 데이터 손실 장애가 아니다.
--    파일을 복사해 채우거나 CONTROL_FILES 에서 그 경로를 제거하면 즉시 해소된다.
--    당황해서 제어 파일을 재생성할 일이 아니다.
--
-- 3) 다중화는 "하나가 깨져도 계속 동작한다"가 아니다.
--    제어 파일 중 하나라도 읽을 수 없으면 마운트되지 않는다.
--    다중화의 실제 의미는 정상 사본이 남아 있어 그것으로 채우고 재기동할 수 있다는 것이다.
--
-- 4) 경로는 반드시 서로 다른 물리 디스크에 둔다.
--    같은 디스크에 세 개를 두면 그 디스크 손상 시 모두 사라진다.
--
-- 5) 다중화는 구축 시점, 서비스 개시 전에 해 두는 것이 좋다.
--    운영 중에는 재기동 일정을 잡기 어려워 미루다 그대로 몇 년을 가는 경우가 흔하다.

SYS@orcl> EXIT
