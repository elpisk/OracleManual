================================================================================
 실습 2-3 : Fast Recovery Area 구성과 공간 확인
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 10분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- Fast Recovery Area 를 구성하고 공간 사용량을 조회한다.
-- 파라미터 설정 순서가 강제되어 있으므로 순서를 바꿔 오류를 확인한 뒤 바로잡는다.
-- FRA 는 13~16장의 RMAN 실습에서 백업 저장소로 사용한다.
-- 복구 유형 : 해당 없음(구성 작업)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태여야 한다.
-- /u01 파일시스템에 최소 5GB 이상의 여유가 있어야 한다.
-- 두 파라미터 모두 동적이므로 재기동이 필요 없다.

[oracle@oel7v9r1 ~]$ df -h /u01
Filesystem      Size  Used Avail Use% Mounted on
/dev/sdb1        50G   18G   30G  38% /u01

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL name FOR a40

--------------------------------------------------------------------------------
[3] 초기 상태 확인
--------------------------------------------------------------------------------
SYS@orcl> SHOW PARAMETER db_recovery_file_dest

NAME                          TYPE        VALUE
----------------------------- ----------- -------
db_recovery_file_dest         string
db_recovery_file_dest_size    big integer 0

-- 둘 다 비어 있다. FRA 가 구성되지 않은 상태다.

SYS@orcl> SELECT * FROM v$recovery_file_dest;

no rows selected

SYS@orcl> SELECT dest_id, status, destination FROM v$archive_dest WHERE dest_id = 10;

   DEST_ID STATUS    DESTINATION
---------- --------- ------------------------------
        10 INACTIVE

-- DEST_10 은 FRA 전용 슬롯이다. FRA 를 지정하면 자동으로 활성화된다.

--------------------------------------------------------------------------------
[4] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 경로를 먼저 설정해 본다.

SYS@orcl> ALTER SYSTEM SET db_recovery_file_dest = '/u01/app/oracle/fast_recovery_area' SCOPE=both;
ALTER SYSTEM SET db_recovery_file_dest = '/u01/app/oracle/fast_recovery_area' SCOPE=both
*
ERROR at line 1:
ORA-02097: parameter cannot be modified because specified value is invalid
ORA-32001: write to SPFILE requested but no SPFILE is in use

-- 위 메시지가 나오는 경우도 있으나, SPFILE 로 기동한 환경에서는 다음과 같이 나온다.

ORA-02097: parameter cannot be modified because specified value is invalid
ORA-19802: cannot use DB_RECOVERY_FILE_DEST without DB_RECOVERY_FILE_DEST_SIZE

-- << 원인 파악 >>
-- FRA 는 논리적 상한으로 관리되는 영역이다.
-- 상한이 정해지지 않은 상태에서는 영역 자체를 정의할 수 없다.
-- 따라서 크기를 먼저 설정해야 한다.

-- << 수정 >>

SYS@orcl> ALTER SYSTEM SET db_recovery_file_dest_size = 4G SCOPE=both;

System altered.

SYS@orcl> ALTER SYSTEM SET db_recovery_file_dest = '/u01/app/oracle/fast_recovery_area' SCOPE=both;

System altered.

SYS@orcl> SHOW PARAMETER db_recovery_file_dest

NAME                          TYPE        VALUE
----------------------------- ----------- -----------------------------------
db_recovery_file_dest         string      /u01/app/oracle/fast_recovery_area
db_recovery_file_dest_size    big integer 4G

--------------------------------------------------------------------------------
[5] 작업 수행 : FRA 동작 확인
--------------------------------------------------------------------------------
-- FRA 를 지정하면 DEST_10 이 자동으로 FRA 를 가리킨다.

SYS@orcl> SELECT dest_id, status, destination FROM v$archive_dest WHERE dest_id = 10;

   DEST_ID STATUS    DESTINATION
---------- --------- ------------------------------
        10 VALID     USE_DB_RECOVERY_FILE_DEST

-- 로그 스위치를 일으켜 FRA 에도 아카이브가 생성되는지 본다.

SYS@orcl> ALTER SYSTEM ARCHIVE LOG CURRENT;
System altered.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) DB_RECOVERY_FILE_DEST_SIZE 는 실제 디스크 용량과 무관한 논리적 상한이다.
--    디스크에 여유가 있어도 이 값을 넘으면 아카이브가 멈춘다.
--    디스크를 늘렸다면 이 파라미터도 함께 올려야 한다.
--
-- 2) FRA 의 자동 삭제는 RMAN 이 관리하는 파일에만 적용된다.
--    OS 명령으로 FRA 안에 복사해 둔 파일은 Oracle 이 인식하지 않아 자동 삭제 대상이 아니다.
--    이 오해 때문에 FRA 를 켜 두고도 디스크가 가득 차는 경우가 있다.
--
-- 3) SPACE_RECLAIMABLE 이 핵심 지표다.
--    사용률이 높아도 회수 가능량이 크면 여유가 있고,
--    회수 가능량이 0 에 가까운데 사용률이 높으면 곧 정지한다.
--
-- 4) FRA 안의 파일명은 Oracle Managed Files 규칙을 따르므로 LOG_ARCHIVE_FORMAT 이 적용되지 않는다.
--    복구 시 파일명을 직접 지정할 일이 거의 없으므로 문제가 되지 않는다.
--
-- 5) FRA 를 쓸지 LOG_ARCHIVE_DEST_n 만 쓸지는 RMAN 사용 여부로 갈린다.
--    RMAN 을 주로 쓰면 FRA 가 유리하고, OS 복사 기반이면 자동 관리 이점을 못 누린다.
--    이 과정은 4~12장에서 OS 디렉터리를, 13~16장에서 FRA 를 주로 사용한다.

SYS@orcl> EXIT
