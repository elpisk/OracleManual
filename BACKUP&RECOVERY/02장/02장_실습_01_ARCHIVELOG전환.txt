================================================================================
 실습 2-1 : ARCHIVELOG 모드 전환
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 15분
================================================================================

--------------------------------------------------------------------------------
[1] 실습 개요
--------------------------------------------------------------------------------
-- NOARCHIVELOG 로 운영 중인 데이터베이스를 ARCHIVELOG 로 전환한다.
-- 이 전환 하나로 복구 가능 범위가 "백업 시점 복귀"에서 "완전 복구"로 바뀐다.
-- 8~12장 시나리오의 전제가 되는 구성이므로 실습 후 되돌리지 않는다.
-- 복구 유형 : 해당 없음(구성 작업)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 데이터베이스가 OPEN 상태이고 다른 사용자가 접속하지 않은 개별 환경이어야 한다.
-- 이 실습은 재기동을 두 번 수행한다.
-- oracle 계정이 /home/oracle 아래에 디렉터리를 만들 수 있어야 한다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> SELECT COUNT(*) AS other_sessions FROM v$session
  2  WHERE  type = 'USER' AND username IS NOT NULL
  3  AND    sid <> SYS_CONTEXT('USERENV','SID');

OTHER_SESSIONS
--------------
             0

--------------------------------------------------------------------------------
[3] 초기 상태 확인
--------------------------------------------------------------------------------
SYS@orcl> SELECT name, log_mode, open_mode FROM v$database;

NAME      LOG_MODE     OPEN_MODE
--------- ------------ --------------------
ORCL      NOARCHIVELOG READ WRITE

SYS@orcl> ARCHIVE LOG LIST
Database log mode              No Archive Mode
Automatic archival             Disabled
Archive destination            /u01/app/oracle/product/19.3.0/dbhome_1/dbs/arch
Oldest online log sequence     22
Current log sequence           24

-- Archive destination 이 $ORACLE_HOME/dbs/arch 로 되어 있다.
-- 이것은 LOG_ARCHIVE_DEST_n 이 설정되지 않았을 때의 기본값이며 권장되지 않는다.

SYS@orcl> !ps -ef | grep ora_arc | grep -v grep

-- 아무것도 출력되지 않는다. NOARCHIVELOG 모드에서는 ARCn 이 기동되지 않는다.

--------------------------------------------------------------------------------
[4] 작업 수행 : 대상 디렉터리와 파라미터 설정
--------------------------------------------------------------------------------
SYS@orcl> !mkdir -p /home/oracle/arch1 /home/oracle/arch2

SYS@orcl> !ls -ld /home/oracle/arch1 /home/oracle/arch2
drwxr-xr-x. 2 oracle oinstall 6 May  9 09:12 /home/oracle/arch1
drwxr-xr-x. 2 oracle oinstall 6 May  9 09:12 /home/oracle/arch2

SYS@orcl> ALTER SYSTEM SET log_archive_dest_1 = 'location=/home/oracle/arch1 mandatory' SCOPE=spfile;

System altered.

SYS@orcl> ALTER SYSTEM SET log_archive_dest_2 = 'location=/home/oracle/arch2 optional' SCOPE=spfile;

System altered.

-- 파일명 형식 확인 후 변경

SYS@orcl> SHOW PARAMETER log_archive_format

NAME                 TYPE     VALUE
-------------------- -------- --------------
log_archive_format   string   %t_%s_%r.dbf

SYS@orcl> ALTER SYSTEM SET log_archive_format = 'arch_%t_%s_%r.arc' SCOPE=spfile;

System altered.

-- %r 이 포함되어 있는지 반드시 확인한다.
-- 빠지면 RESETLOGS 전후의 아카이브가 같은 이름으로 겹쳐 덮어쓰인다.

--------------------------------------------------------------------------------
[5] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 종료하지 않고 바로 전환을 시도해 본다.

SYS@orcl> ALTER DATABASE ARCHIVELOG;
ALTER DATABASE ARCHIVELOG
*
ERROR at line 1:
ORA-01126: database must be mounted in this instance and not open in any instance

-- << 원인 파악 >>
-- 로그 모드는 제어 파일에 기록되는 속성이다.
-- 제어 파일은 읽었지만 데이터 파일은 아직 열지 않은 MOUNT 단계에서만 변경할 수 있다.

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
OPEN

-- << 수정 >>
-- 정상 종료 후 MOUNT 까지만 올린다.

SYS@orcl> SHUTDOWN IMMEDIATE
Database closed.
Database dismounted.
ORACLE instance shut down.

SYS@orcl> STARTUP MOUNT
ORACLE instance started.

Total System Global Area 1140849904 bytes
Fixed Size                  8895728 bytes
Variable Size             754974720 bytes
Database Buffers          369098752 bytes
Redo Buffers                7880704 bytes
Database mounted.

SYS@orcl> SELECT status FROM v$instance;

STATUS
------------
MOUNTED

SYS@orcl> ALTER DATABASE ARCHIVELOG;

Database altered.

SYS@orcl> ALTER DATABASE OPEN;

Database altered.

[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1) 전환 직후 전체 백업을 새로 받아야 한다.
--    전환 이전 백업은 아카이브 로그와 계보가 이어지지 않아 완전 복구의 출발점이 될 수 없다.
--    실제 백업은 3장에서 수행한다.
--
-- 2) SHUTDOWN ABORT 로 내린 뒤 전환하면 안 된다.
--    체크포인트가 완료되지 않아 SCN 이 어긋난 상태이며, 전환이나 이후 오픈에서 문제가 생긴다.
--
-- 3) 기본 아카이브 대상($ORACLE_HOME/dbs/arch)을 그대로 쓰지 않는다.
--    ORACLE_HOME 이 있는 디스크가 가득 차면 데이터베이스가 멈춘다.
--
-- 4) LOG_ARCHIVE_FORMAT 에 %r 을 반드시 포함한다.
--    소문자는 값 그대로, 대문자(%T·%S·%R)는 앞을 0으로 채운 고정 폭으로 생성된다.
--
-- 5) 이 구성은 8장부터 다시 사용한다.
--    4~7장의 NOARCHIVELOG 시나리오를 위해 잠시 되돌릴 때는
--    같은 절차로 ALTER DATABASE NOARCHIVELOG 를 수행하고, 8장 전에 다시 전환한다.

SYS@orcl> EXIT
