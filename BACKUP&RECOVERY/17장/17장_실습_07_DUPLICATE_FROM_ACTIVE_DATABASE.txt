================================================================================
 실습 17-7 : DUPLICATE TARGET DATABASE FROM ACTIVE DATABASE
 과정      : Oracle Database 19c Backup & Recovery

 소요 시간 : 약 35분

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 원본에서 직접 읽어 복제본을 만든다.
-- Memory Script를 해석하며 진행 단계를 확인한다.
-- 17.2절의 수동 절차와 같은 구조임을 확인한다.
-- 완료 후 DBID와 경로를 검증한다.
-- 작업 유형 : 복제 수행(장애 복구 아님)

-- << 원인 파악 >>
-- 복제본이 이미 열려 있는 상태다.
-- DUPLICATE는 auxiliary가 NOMOUNT 상태일 것을 요구한다.
-- 열린 복제본을 덮어쓰려면 명시적으로 내려야 한다.

RMAN> EXIT

-- << 수정 >> 복제본을 NOMOUNT로 내린 뒤 재수행한다.

-- 실무 포인트
-- 1) ACTIVE DUPLICATE는 명령 하나로 끝난다.
--    17.2절의 여러 단계가 Memory Script로 자동 실행된다.
--    수동 복제를 먼저 해 보면 이 로그가 훨씬 잘 읽힌다.
--
-- 2) Memory Script는 다섯 구간으로 나뉜다.
--    spfile 생성과 재기동, 컨트롤파일 복원과 MOUNT,
--    데이터파일 복원, SWITCH, 복구와 RESETLOGS 오픈이다.
--    clone 이 붙은 명령이 복제본을 대상으로 한다.
--
-- 3) DBID가 자동으로 새로 부여된다.
--    수동 복제에서 SET DATABASE 절이 하던 일이다.
--    복제 후 반드시 확인한다.
--
-- 4) db_create_file_dest 를 지정하면 OMF 이름으로 파일이 만들어진다.
--    경로 변환 규칙이 필요 없어 실수 여지가 줄어든다.
--    다만 파일명이 알아보기 어려워지므로 운영 환경에서는 판단이 필요하다.
--
-- 5) 임시 파일도 자동으로 만들어진다.
--    수동 복제에서 직접 추가하던 단계가 사라진다.
--
-- 6) 복제본이 열려 있으면 DUPLICATE를 다시 할 수 없다.
--    RMAN-05537과 RMAN-05001이 함께 나온다.
--    NOMOUNT로 내린 뒤 재수행해야 한다.
