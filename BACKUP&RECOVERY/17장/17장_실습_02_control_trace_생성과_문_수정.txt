--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 원본의 컨트롤파일 trace 백업을 만든다.
-- RESETLOGS 형식 부분을 가져와 복제본용으로 수정한다.
-- REUSE DATABASE를 SET DATABASE로 바꾸고 모든 경로를 치환한다.
-- 원본 경로가 남아 있는지 검증하는 절차를 익힌다.
-- 작업 유형 : 복제 준비(장애 복구 아님)

[4] 작업 수행 : trace 백업 생성
--------------------------------------------------------------------------------
SYS@orcl> ALTER DATABASE BACKUP CONTROLFILE TO TRACE
  2    AS '/tmp/cf_orcl.sql' REUSE;

Database altered.

SYS@orcl> !grep -n 'CREATE CONTROLFILE' /tmp/cf_orcl.sql
41:CREATE CONTROLFILE REUSE DATABASE "ORCL" NORESETLOGS  ARCHIVELOG
98:CREATE CONTROLFILE REUSE DATABASE "ORCL" RESETLOGS  ARCHIVELOG

-- 리두 파일을 복사하지 않았으므로 NORESETLOGS 형식은 쓸 수 없다.

[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 치환을 하나 빠뜨린 상황을 재현한다.

[oracle@oel7v9r1 ~]$ sed -n '98,150p' /tmp/cf_orcl.sql > /tmp/cf_bad.sql
[oracle@oel7v9r1 ~]$ sed -i 's|REUSE DATABASE "ORCL"|SET DATABASE "CLONE"|' /tmp/cf_bad.sql
[oracle@oel7v9r1 ~]$ sed -i 's|/u03/oradata/ORCL/|/u04/clone/CLONE/|g' /tmp/cf_bad.sql
[oracle@oel7v9r1 ~]$ sed -i 's|/u01/app/oracle/oradata/ORCL/|/u04/clone/CLONE/|g' /tmp/cf_bad.sql

-- /u02 치환을 빠뜨렸다.

[oracle@oel7v9r1 ~]$ grep -n '/u02/oradata/ORCL' /tmp/cf_bad.sql
10:    '/u02/oradata/ORCL/redo01b.log',
15:    '/u02/oradata/ORCL/redo03b.log',
20:    '/u02/oradata/ORCL/redo04b.log'

-- << 원인 파악 >>
-- 리두 멤버 세 개가 원본 경로를 가리킨다.
-- 이 문을 실행하면 복제본이 원본의 리두 파일을 자기 것으로 인식한다.
-- 복제본을 RESETLOGS로 열면 그 파일을 새로 만들면서 원본의 리두를 덮어쓴다.
-- 원본이 운영 중이라면 즉시 장애가 발생한다.
-- 경로가 여러 갈래일 때 하나를 빠뜨리는 것이 가장 흔한 실수다.

-- 이 문을 그대로 실행하면 다음과 같이 진행된다.

SYS@CLONE> @/tmp/cf_bad.sql

CREATE CONTROLFILE SET DATABASE "CLONE" RESETLOGS  ARCHIVELOG
*
ERROR at line 1:
ORA-01503: CREATE CONTROLFILE failed
ORA-00200: control file could not be created
ORA-00202: control file: '/u04/clone/CLONE/control01.ctl'
ORA-27038: created file already exists

-- 이번에는 컨트롤파일이 이미 있어 막혔지만
-- 없는 상태였다면 그대로 만들어져 원본 리두를 가리켰을 것이다.
-- 오류로 막히는 것에 기대면 안 된다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ sed -i 's|/u02/oradata/ORCL/|/u04/clone/CLONE/|g' /tmp/cf_bad.sql
[oracle@oel7v9r1 ~]$ grep -c '/u02/oradata/ORCL' /tmp/cf_bad.sql
0

[oracle@oel7v9r1 ~]$ diff /tmp/cf_clone.sql /tmp/cf_bad.sql
[oracle@oel7v9r1 ~]$ echo $?
0

-- 두 파일이 같아졌다. 치환이 완전히 끝났다.

[oracle@oel7v9r1 ~]$ rm -f /tmp/cf_bad.sql

--------------------------------------------------------------------------------
[8] 검증 및 실무 포인트
--------------------------------------------------------------------------------
-- 최종 검증 스크립트를 만들어 둔다.

[oracle@oel7v9r1 ~]$ cat > /tmp/check_clone_sql.sh <<'EOS'
#!/bin/bash
F=$1
SRC="/u01/app/oracle/oradata/ORCL|/u02/oradata/ORCL|/u03/oradata/ORCL"
echo "== 원본 경로 검사 =="
if grep -nE "$SRC" $F; then
  echo "!! 원본 경로가 남아 있다. 실행 금지"
  exit 1
fi
echo "OK - 원본 경로 없음"
echo "== SET DATABASE 확인 =="
grep -n 'SET DATABASE' $F || { echo "!! SET DATABASE 없음"; exit 1; }
echo "== 파일 개수 =="
echo "문: $(grep -c 'dbf' $F)  실제: $(ls /u04/clone/CLONE/*.dbf | wc -l)"
EOS

[oracle@oel7v9r1 ~]$ chmod 700 /tmp/check_clone_sql.sh
[oracle@oel7v9r1 ~]$ /tmp/check_clone_sql.sh /tmp/cf_clone.sql

== 원본 경로 검사 ==
OK - 원본 경로 없음
== SET DATABASE 확인 ==
1:CREATE CONTROLFILE SET DATABASE "CLONE" RESETLOGS  ARCHIVELOG
== 파일 개수 ==
문: 5  실제: 5

-- 실무 포인트
-- 1) 복제에는 RESETLOGS 형식을 쓴다.
--    리두 파일을 복사하지 않았으므로 NORESETLOGS 형식은 성립하지 않는다.
--    6장에서 다룬 형식 선택 기준이 그대로 적용된다.
--
-- 2) REUSE DATABASE를 SET DATABASE로 바꾼다.
--    REUSE는 같은 이름과 DBID를 유지하므로 복제본이 되지 못한다.
--    SET DATABASE는 새 이름을 지정하며 DBID도 새로 만들어진다.
--
-- 3) 경로가 여러 갈래면 치환도 그만큼 필요하다.
--    이 환경에서는 데이터파일 /u03, 리두 /u01과 /u02로 세 갈래였다.
--    하나를 빠뜨리는 것이 가장 흔한 실수다.
--
-- 4) 원본 경로가 남으면 원본이 손상될 수 있다.
--    복제본이 원본의 리두를 자기 것으로 인식해 덮어쓰게 된다.
--    운영 중이라면 즉시 장애가 발생한다.
--
-- 5) 실행 전 검증을 스크립트로 만들어 둔다.
--    원본 경로 검사, SET DATABASE 확인, 파일 개수 대조 세 가지면 충분하다.
--    몇 초면 끝나지만 가장 큰 사고를 막아 준다.
--
-- 6) 문에 나열된 파일 개수와 실제 파일 개수를 대조한다.
--    빠진 파일이 있으면 복구 후 UNNAMED로 나타난다.
