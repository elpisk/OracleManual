[4] 작업 수행 : 디렉터리와 pfile
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ mkdir -p /u04/newdb
[oracle@oel7v9 ~]$ mkdir -p /u04/newdb/arch

[oracle@oel7v9 ~]$ cat > $ORACLE_HOME/dbs/initNEWDB.ora <<EOS
db_name=NEWDB
db_unique_name=NEWDB
db_block_size=8192
sga_target=512M
audit_file_dest='/u01/app/oracle/admin/NEWDB/adump'
db_create_file_dest='/u04/newdb'
db_recovery_file_dest_size=4G
compatible=19.0.0
EOS

[oracle@oel7v9 ~]$ cat $ORACLE_HOME/dbs/initNEWDB.ora
db_name=NEWDB
db_unique_name=NEWDB
db_block_size=8192
sga_target=512M
audit_file_dest='/u01/app/oracle/admin/NEWDB/adump'
db_create_file_dest='/u04/newdb'
db_recovery_file_dest_size=4G
compatible=19.0.0

-- 최소한의 값만 넣었다. NOMOUNT 로 띄우는 데 필요한 것뿐이다.
-- DUPLICATE 의 SPFILE 절을 쓰면 이 파일은 기동용으로만 쓰이고, 복제본의 spfile 은
-- 원본의 spfile 을 복사해 만들어진다. 즉 여기 적은 값이 그대로 남지 않는다(17-7 에서 확인).

[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 인스턴스를 띄우지 않은 채 접속을 시도해 본다.

[oracle@oel7v9 ~]$ sqlplus sys/oracle_4U@NEWDB as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production on Mon May 19 11:25:02 2025

ERROR:
ORA-01034: ORACLE not available
Process ID: 0
Session ID: 0 Serial number: 0

-- << 원인 파악 >>
-- 리스너는 정적 등록으로 서비스를 알고 있어 접속을 받아 서버 프로세스를 띄운다.
-- 그 서버 프로세스가 붙을 인스턴스(SGA)가 없어 ORA-01034 로 끝난다.
-- 동적 등록만 있는 서비스라면 리스너 단계에서 ORA-12514(서비스를 모름)가 나온다.
-- 정적 등록의 뜻이 바로 이것이다. 인스턴스가 없어도 접속을 받아 주므로 NOMOUNT 로 띄우고
-- 원격에서 붙을 수 있다. DUPLICATE 가 이 성질을 쓴다.

-- << 수정 >>

[oracle@oel7v9 ~]$ lsnrctl status | grep -A 2 'Service "NEWDB"'
Service "NEWDB" has 2 instance(s).
  Instance "NEWDB", status UNKNOWN, has 1 handler(s) for this service...
  Instance "NEWDB", status BLOCKED, has 1 handler(s) for this service...

-- 인스턴스가 뜨자 같은 이름이 둘 보인다. UNKNOWN 은 정적 등록, BLOCKED 는 NOMOUNT 인스턴스가
-- 스스로 한 동적 등록이다. BLOCKED 는 열리지 않아 일반 접속을 막는다는 뜻이고,
-- SYSDBA 접속은 정적 등록 쪽으로 들어가므로 된다.

-- 실무 포인트
-- 1) 복제본은 정적 등록이 필요하다.
--    NOMOUNT 상태에서 접속을 받아야 하는데 동적 등록은 BLOCKED 로만 이루어진다.
--    정적 등록의 status가 UNKNOWN으로 표시되는 것은 정상이다.
--
-- 2) 정적 등록만으로는 부족하다.
--    인스턴스가 없으면 ORA-01034 가 나온다(등록은 됐고 붙을 SGA 가 없다는 뜻).
--    NOMOUNT로 먼저 띄운 뒤 접속을 확인한다.
--
-- 3) 패스워드 파일은 원본 것을 복사하는 방법이 가장 확실하다.
--    orapwd 로 새로 만들 때는 비밀번호를 정확히 맞춰야 하고 19c 복잡도 규칙도 통과해야 한다(17-8).
--    다르면 ORA-01017로 DUPLICATE가 시작되지 않는다.
--
-- 4) 복제본 pfile은 최소한만 있으면 된다. 단, 기동용일 뿐이다.
--    SPFILE 절을 쓰면 복제본의 실제 파라미터는 원본 spfile 을 복사한 것이 된다.
--    여기 적은 audit_file_dest 같은 값이 그대로 남을 거라고 믿으면 안 된다(17-7).
--
-- 5) db_create_file_dest 를 지정하면 데이터파일·리두·임시 파일의 경로 변환 규칙이 필요 없다.
--    OMF 방식으로 그 아래에 파일이 자동 배치된다.
--    다만 컨트롤파일 경로는 spfile 의 control_files 를 따르므로 따로 SET 해야 한다(17-7).
--
-- 6) 설정 파일은 수정 전에 사본을 남긴다.
--    listener.ora의 괄호 하나만 어긋나도 리스너가 기동되지 않는다.
--    실습이 끝나면 되돌린다. DROP DATABASE 는 이 파일들을 건드리지 않는다.
