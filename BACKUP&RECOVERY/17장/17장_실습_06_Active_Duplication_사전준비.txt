[1] 시나리오 개요
--------------------------------------------------------------------------------

-- 복제본 인스턴스를 NOMOUNT로 기동한다.

-- 작업 유형 : 복제 준비(장애 복구 아님)

[oracle@oel7v9r1 ~]$ cat $ORACLE_HOME/dbs/initNEWDB.ora

db_unique_name=NEWDB
db_block_size=8192
sga_target=512M
audit_file_dest='/u01/app/oracle/admin/NEWDB/adump'
db_create_file_dest='/u04/newdb'
db_recovery_file_dest_size=4G
compatible=19.0.0

[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 인스턴스를 띄우지 않은 채 접속을 시도해 본다.

[oracle@oel7v9r1 ~]$ sqlplus sys/oracle_4U@NEWDB as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production

ERROR:
ORA-12528: TNS:listener: all appropriate instances are blocking new connections

-- << 원인 파악 >>
-- 리스너는 서비스를 알고 있지만 인스턴스가 없다.
-- 정적 등록된 서비스에 인스턴스가 없으면 이 오류가 나온다.
-- 복제본 인스턴스를 NOMOUNT로 먼저 띄워야 한다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ export ORACLE_SID=NEWDB
[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

-- 실무 포인트
-- 1) 복제본은 정적 등록이 필요하다.
--    NOMOUNT 상태에서 접속을 받아야 하는데 동적 등록은 오픈 후에 이루어진다.
--    정적 등록의 status가 UNKNOWN으로 표시되는 것은 정상이다.
--
-- 2) 정적 등록만으로는 부족하다.
--    인스턴스가 없으면 ORA-12528이 나온다.
--    NOMOUNT로 먼저 띄운 뒤 접속을 확인한다.
--
-- 3) 패스워드 파일은 원본 것을 복사하는 방법이 가장 확실하다.
--    orapwd 로 새로 만들 때는 비밀번호를 정확히 맞춰야 한다.
--    다르면 ORA-01017로 DUPLICATE가 시작되지 않는다.
--
-- 4) 복제본 pfile은 최소한만 있으면 된다.
--    db_name, db_block_size, sga_target, audit_file_dest 정도다.
--    나머지는 DUPLICATE가 원본에서 가져오거나 SET 절로 지정한다.
--
-- 5) db_create_file_dest 를 지정하면 경로 변환 규칙이 필요 없다.
--    OMF 방식으로 그 아래에 파일이 자동 배치된다.
--    경로가 여러 갈래인 환경에서 실수 여지를 크게 줄여 준다.
--
-- 6) 설정 파일은 수정 전에 사본을 남긴다.
--    listener.ora의 괄호 하나만 어긋나도 리스너가 기동되지 않는다.
