-- 파일은 있는데 컨트롤파일이 그 이름을 모른다.
-- RENAME FILE 로 이름을 알려 주는 길은 그 파일이 READ ONLY 또는 OFFLINE NORMAL
-- 상태로 남겨진 것일 때만 통한다. 이 파일은 미디어 복구가 필요한 상태인데
-- RESETLOGS 를 지나 그 복구가 막혔다. 그대로 두면 USERS 를 지우는 수밖에 없다.

-- 판정
--   ① 컨트롤파일 문에서 파일 하나가 빠졌다
--   ② 이미 RESETLOGS로 열었으므로 7번을 살릴 수 없다
--   → 컨트롤파일을 다시 만들어야 한다. 처음부터 재수행한다.

-- 실무 포인트
-- 1) CREATE CONTROLFILE 은 파일 헤더의 절대 번호를 그대로 쓴다.
--    나열 순서와 무관하게 원본의 번호가 유지된다. 11-8 과 같다.
--
-- 2) 파일이 빠져도 문법 오류가 아니므로 그대로 만들어진다.
--    실행 전에 파일 개수를 대조해야 하는 이유가 여기에 있다.
--
-- 3) 빠진 파일은 열 때 MISSINGnnnnn 자리표시자로 등록된다.
--    데이터 사전과 컨트롤파일을 대조한 결과이며 OFFLINE·복구 필요 상태다.
--    READ ONLY 나 OFFLINE NORMAL 이던 파일만 RENAME FILE 로 되살릴 수 있다.
--    6장의 UNNAMED(등록은 됐으나 이름을 모름)와는 성격이 다르다.
--
-- 4) RESETLOGS로 연 뒤에는 되돌릴 수 없다.
--    컨트롤파일을 다시 만들고 데이터파일도 백업본에서 다시 복사해야 한다.
--
-- 5) SET DATABASE 절이 이름과 DBID를 모두 바꾼다.
--    DBID가 원본과 다른지 반드시 확인한다. 같으면 복제본이 아니다.
--
-- 6) 생성 직후 파일 목록을 전수 확인한다.
--    v$datafile, v$logfile, v$controlfile 세 뷰를 모두 조회한다.
--    하나라도 원본 경로가 있으면 즉시 중단하고 바로잡는다.
