 과정      : Oracle Database 19c Backup & Recovery

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- SYSTEM 데이터파일이 손상되었다.
-- SYSTEM은 OFFLINE으로 내릴 수 없어 무중단 복구가 불가능하다.
-- MOUNT 상태로 내려 복구한 뒤 다시 연다.
-- 손상된 파일만 복원해 복구 시간을 줄인다.
-- 복구 유형 : 완전 복구, 전면 중단, 손실 없음

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 열린 상태로 복구할 수 있는지 먼저 시도해 본다.

RMAN> ALTER DATABASE OPEN;

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-03002: failure of sql statement command at 05/16/2025 11:41:02
ORA-01157: cannot identify/lock data file 1 - see DBWR trace file
ORA-01110: data file 1: '/u02/oradata/ORCL/system01.dbf'

-- << 원인 파악 >>
-- SYSTEM 데이터파일이 없으면 데이터베이스를 열 수 없다.
-- 데이터 사전이 그 안에 있어 오픈 과정에서 반드시 필요하다.
-- OFFLINE으로 내려 두고 여는 방법도 통하지 않는다.

RMAN> SQL 'ALTER DATABASE DATAFILE 1 OFFLINE';

RMAN-03009: failure of sql command
ORA-01541: system tablespace cannot be brought offline; shut down if necessary

-- SYSTEM은 OFFLINE 대상이 아니라는 것이 명시적으로 나온다.
-- 전면 중단이 불가피하다.

-- << 수정 >> MOUNT 상태에서 복구한다.

RMAN> RESTORE DATAFILE 1;

Starting restore at 16-MAY-25
channel ORA_DISK_1: starting datafile backup set restore

Finished restore at 16-MAY-25

-- 1번만 복원했다. 다른 파일은 그대로 두어 적용할 아카이브를 줄인다.

RMAN> RECOVER DATAFILE 1;

[oracle@oel7v9r1 ~]$ sqlplus -s / as sysdba <<< \
> "SELECT operation, status, TO_CHAR(start_time,'HH24:MI:SS') AS s,
   TO_CHAR(end_time,'HH24:MI:SS') AS e FROM v\$rman_status
   WHERE start_time > SYSDATE-1/24 ORDER BY start_time;"

OPERATION  STATUS     S        E
---------- ---------- -------- --------
RESTORE    COMPLETED  11:44:12 11:44:53
RECOVER    COMPLETED  11:44:55 11:44:58

-- 복원 41초, 복구 3초다. 복원이 시간의 대부분을 차지한다.

-- 실무 포인트
-- 1) SYSTEM 손상은 무중단 복구가 불가능하다.
--    ORA-01541이 그 사실을 명시적으로 알려 준다.
--    진단 직후 전면 중단임을 현업에 통보하는 것이 첫 조치다.
--
-- 2) SYSTEM이 없으면 데이터베이스를 열 수 없다.
--    데이터 사전이 그 안에 있어 오픈 과정에서 반드시 필요하기 때문이다.
--    ORA-01157은 그 파일을 찾거나 잠글 수 없다는 뜻이다.
--
-- 3) MOUNT 상태에서는 컨트롤파일을 읽으므로 진단 뷰를 쓸 수 있다.
--    v$recover_file 로 손상 범위를 확인한 뒤 복구를 시작한다.
--
-- 4) 손상된 파일만 복원한다.
--    RESTORE DATABASE 를 쓰면 멀쩡한 파일까지 되돌려 적용할 아카이브가 늘어난다.
--    이 실습에서는 1번만 복원해 복구 시간을 41초로 줄였다.
--
-- 5) 현재 컨트롤파일을 썼으므로 RESETLOGS가 필요 없다.
--    인카네이션이 유지되어 이전 백업도 그대로 유효하다.
--
-- 6) 복구 시간은 v$rman_status 로 확인해 보고에 포함한다.
--    복원과 복구의 비중을 알면 다음 개선 지점이 드러난다.
