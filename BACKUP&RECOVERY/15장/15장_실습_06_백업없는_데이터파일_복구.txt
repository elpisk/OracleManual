================================================================================
 실습 15-6 : 백업받지 않은 테이블스페이스의 데이터파일 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 30분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 테이블스페이스를 만들고 백업하기 전에 데이터파일이 손상되었다.
-- 백업이 없으므로 복원할 백업 조각이 없다.
-- 빈 파일을 만들고 아카이브를 처음부터 적용해 복구한다. RMAN 은 이 과정을 RESTORE 안에서 대신한다.
-- NOLOGGING으로 적재한 데이터가 복구되지 않는 것도 확인한다.
-- 복구 유형 : 파일 재생성 후 완전 복구, 무중단

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 15-5까지 완료되어 있어야 한다.
-- 아카이브가 연속이어야 이 복구가 성립한다.

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat

RMAN> BACKUP DATABASE TAG 'BASE_156' PLUS ARCHIVELOG;
RMAN> EXIT

-- 백업이 없다는 오류 대신 "will be created automatically" 가 나온다.
-- 파일을 만든 기록(CREATE TABLESPACE)이 아카이브 안에 있으면 RMAN 이 빈 파일을 만들고
-- 그 뒤의 리두를 적용한다. 8-4 의 ALTER DATABASE CREATE DATAFILE 을 대신하는 것이다.
-- 파일 생성 직후의 시퀀스 27 은 이미 백업에 들어가 목록에는 28 만 보인다.

-- 판정
--   ① 백업 없음 → 조각 복원은 불가
--   ② 파일 생성 시점부터 아카이브 연속 → RMAN 이 파일을 만들고 복구 가능
--   ③ NOLOGGING 적재분은 복구되지 않는다 → 재적재 필요
--   → 대상을 내리고 RESTORE → RECOVER

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 대상을 먼저 내리려 한다. 8-4 와 같은 순서다.

RMAN> EXIT
[oracle@oel7v9 ~]$ sqlplus / as sysdba

SYS@orcl> ALTER TABLESPACE tbs_nb OFFLINE NORMAL;
ALTER TABLESPACE tbs_nb OFFLINE NORMAL
*
ERROR at line 1:
ORA-01116: error in opening database file 9
ORA-01110: data file 9: '/u01/app/oracle/oradata/orcl/tbs_nb01.dbf'
ORA-27041: unable to open file
Linux-x86_64 Error: 2: No such file or directory
Additional information: 3

-- << 원인 파악 >>
-- OFFLINE NORMAL 은 체크포인트를 위해 파일을 열어야 하는데 파일이 없어 수행할 수 없다.
-- 손상된 파일에는 OFFLINE IMMEDIATE 를 쓴다.

-- << 수정 >>

SYS@orcl> ALTER TABLESPACE tbs_nb OFFLINE IMMEDIATE;

Tablespace altered.

SYS@orcl> EXIT

RMAN> RESTORE TABLESPACE tbs_nb;

-- 실무 포인트
-- 1) 백업이 없어도 아카이브가 연속이면 복구할 수 있다.
--    파일을 만든 리두가 아카이브에 있으면 RMAN 의 RESTORE 가 빈 파일을 만들고
--    ("creating datafile") RECOVER 가 그 뒤의 변경을 적용한다.
--    User Managed 의 ALTER DATABASE CREATE DATAFILE 과 같은 일이다.
--
-- 2) 조건은 아카이브가 하나도 빠지지 않는 것이다.
--    중간에 결손이 있으면 그 지점까지만 복구되어 파일을 열 수 없다.
--
-- 3) NOLOGGING으로 적재된 데이터는 복구되지 않는다.
--    조회 시 ORA-01578과 ORA-26040이 함께 나온다.
--    블록 손상이 아니라 내용이 없는 상태이므로 재적재가 답이다.
--
-- 4) REPORT UNRECOVERABLE 이 이 상황을 미리 알려 준다.
--    NOLOGGING 작업 직후 이 목록에 파일이 나타나므로
--    정기 점검 항목으로 넣어 두면 즉시 백업할 근거가 된다.
--
-- 5) 구조를 바꾸면 즉시 백업한다.
--    테이블스페이스를 만들고 백업을 미루면 이 상황이 만들어진다.
--    복구는 되지만 시간이 오래 걸리고 NOLOGGING 부분은 잃는다.
--
-- 6) 대량 적재에 NOLOGGING을 쓴다면 직후 백업을 절차에 넣는다.
--    적재 스크립트 마지막에 BACKUP TABLESPACE 를 붙이는 방식이 확실하다.
