--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 데이터 디스크 전체를 쓸 수 없어 새 디스크로 옮기며 복구한다.
-- SET NEWNAME FOR DATABASE 로 여러 파일을 한 번에 지정한다.
-- SWITCH DATAFILE ALL 로 컨트롤파일의 경로를 일괄 갱신한다.
-- 치환 문자 %b 의 동작을 확인한다.
-- 복구 유형 : 완전 복구, 전면 중단, 전체 경로 변경

-- 실무 포인트
-- 1) SET NEWNAME FOR DATABASE 로 여러 파일을 한 번에 지정한다.
--    파일마다 SET NEWNAME 을 쓰지 않아도 되므로 명령이 크게 줄어든다.
--
-- 2) 디렉터리만 지정하면 RMAN-06970으로 거부된다.
--    파일명을 만들 치환 문자가 필요하기 때문이다.
--    %b 는 원래 파일명, %f 는 파일 번호, %U 는 고유 이름으로 치환된다.
--
-- 3) 원래 이름을 유지하려면 %b 를 쓴다.
--    %U 를 쓰면 이름이 알아보기 어려운 형태로 바뀌어 운영에 불편하다.
--
-- 4) SWITCH DATAFILE ALL 로 모든 경로를 한 번에 갱신한다.
--    SET NEWNAME 으로 지정한 파일 중 경로가 실제로 바뀐 것만 처리된다.
--
-- 5) 임시 파일은 SET NEWNAME 으로 옮겨지지 않는다.
--    RESTORE 대상이 아니어서 OPEN 때 원래 경로에 다시 만들어진다.
--    함께 옮기려면 ADD 뒤 DROP 으로 처리하고 v$tempfile 을 반드시 확인한다.
--
-- 6) 경로가 바뀌면 백업과 문서를 함께 갱신한다.
--    복구 절차서의 경로 목록, 백업 스크립트, 매니페스트가 대상이다.
--    이 작업을 미루면 다음 장애에서 옛 경로를 찾다가 시간을 낭비한다.
