-- 채널을 늘려 복원 시간을 줄이고 진행률을 확인한다.
-- 9장의 User Managed 절차와 명령 수를 비교한다.
-- 복구 유형 : 완전 복구, 전면 중단, RESETLOGS 불필요

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat
RMAN> BACKUP DATABASE TAG 'AFTER_FULL_RESTORE' PLUS ARCHIVELOG;

-- 9장의 User Managed 절차와 비교
--   User Managed : 백업본 경로 확인 → 파일별 cp → MOUNT → RECOVER →
--                  아카이브 경로 입력 반복 → OPEN → ADD TEMPFILE   (다단계)
--   RMAN        : STARTUP MOUNT → RESTORE DATABASE → RECOVER DATABASE →
--                  ALTER DATABASE OPEN                              (4단계)

-- 실무 포인트
-- 1) 컨트롤파일이 온전하면 MOUNT까지 올라간다.
--    진단 뷰를 쓸 수 있어 손상 범위를 즉시 확인할 수 있다.
--    컨트롤파일까지 손상되면 NOMOUNT에서 시작해야 한다.
--
-- 2) 복원은 컨트롤파일에 기록된 경로로 진행된다.
--    디렉터리가 없으면 RMAN 이 만들어 준다. 그러나 마운트 지점 자체가 없으면
--    루트 파일시스템에 만들어 버리므로 파일을 옮긴 이력이 있으면 복구 전에 경로를 확인한다.
--
-- 3) 채널을 늘리면 여러 파일을 동시에 복원한다.
--    다만 백업 세트 수가 병렬도의 상한이고, 백업 위치와 복원 대상이 같은 디스크면 효과가 없다.
--
-- 4) 순서는 RESTORE → RECOVER 다. 거꾸로 하면 RMAN-06094 로 막힌다.
--
-- 5) 현재 컨트롤파일로 복구했으므로 RESETLOGS가 필요 없다.
--    인카네이션이 유지되어 이전 백업도 계속 유효하다.
--
-- 6) 임시 파일이 자동으로 만들어진다.
--    9장에서 매번 수행하던 ADD TEMPFILE 단계가 사라진다.
--
-- 7) 명령이 네 줄로 끝나지만 내부에서 하는 일은 9장과 같다.
--    복원 대상 판별과 아카이브 탐색이 자동화되었을 뿐이다.
