 실습 15-2 : 일반 테이블스페이스를 다른 위치로 복구 — SET NEWNAME / SWITCH

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 데이터파일이 있던 디스크를 더 이상 쓸 수 없다.
-- 다른 디스크로 복원하고 그 위치를 정식 경로로 등록한다.
-- SET NEWNAME과 SWITCH를 짝으로 사용한다.
-- SWITCH를 빠뜨렸을 때 무슨 일이 생기는지 확인한다.
-- 복구 유형 : 완전 복구, 무중단, 파일 위치 변경

--   ② 원래 위치 사용 불가 → 새 위치로 복원해야 한다
--   ③ 백업과 아카이브는 있다
--   → SET NEWNAME → RESTORE → SWITCH → RECOVER

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 먼저 SWITCH를 빠뜨린 채 진행해 본다.

RMAN> RUN {
  2>   SQL 'ALTER TABLESPACE tbs13 OFFLINE IMMEDIATE';
  3>   SET NEWNAME FOR DATAFILE 8 TO '/u03/oradata/ORCL/tbs13_01.dbf';
  4>   RESTORE TABLESPACE tbs13;
  5>   RECOVER TABLESPACE tbs13;
  6> }

-- << 원인 파악 >>
-- 복원은 /u03 에 성공했다. 파일도 실제로 존재한다.

RMAN> EXIT
[oracle@oel7v9r1 ~]$ ls -l /u03/oradata/ORCL/
-rw-r-----. 1 oracle oinstall 20979712 May 16 11:04 tbs13_01.dbf

[oracle@oel7v9r1 ~]$ sqlplus -s / as sysdba <<< \
> "SELECT file#, name FROM v\$datafile WHERE file#=8;"

     FILE# NAME
---------- ------------------------------------------
         8 /u02/oradata/ORCL/tbs13_01.dbf

-- 컨트롤파일은 여전히 옛 경로를 가리킨다.
-- SET NEWNAME은 복원 위치만 바꿀 뿐 컨트롤파일을 갱신하지 않는다.
-- RECOVER는 컨트롤파일이 가리키는 경로를 대상으로 하므로 파일이 없다고 판단한다.
-- SWITCH가 그 경로를 새 위치로 바꿔 주는 명령이다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ rman target / catalog rcatowner@rcat

RMAN> RUN {
  2>   SET NEWNAME FOR DATAFILE 8 TO '/u03/oradata/ORCL/tbs13_01.dbf';
  3>   SWITCH DATAFILE ALL;
  4>   RECOVER TABLESPACE tbs13;
  5>   SQL 'ALTER TABLESPACE tbs13 ONLINE';
  6> }

-- 새 위치에서 정상적으로 쓰기가 된다.

SYS@orcl> EXIT

[oracle@oel7v9r1 ~]$ rman target / catalog rcatowner@rcat

RMAN> BACKUP TABLESPACE tbs13 TAG 'AFTER_MOVE';

-- 경로가 바뀌었으므로 백업을 다시 받고 매니페스트도 갱신한다.

RMAN> EXIT

-- 실무 포인트
-- 1) SET NEWNAME은 복원 위치만 지정한다.
--    컨트롤파일에는 여전히 원래 경로가 기록되어 있다.
--    SWITCH로 그 경로를 갱신해야 데이터베이스가 새 파일을 인식한다.
--
-- 2) SWITCH를 빠뜨리면 RMAN-06094가 나온다.
--    파일은 새 위치에 있는데 컨트롤파일은 옛 경로를 보고 있어
--    복원되지 않았다고 판단하는 것이다.
--
-- 3) 올바른 순서는 SET NEWNAME → RESTORE → SWITCH → RECOVER 다.
--    RECOVER를 SWITCH보다 먼저 하면 옛 경로를 대상으로 삼아 실패한다.
--
-- 4) SET NEWNAME은 RUN 블록 안에서만 쓸 수 있다.
--    프롬프트에서 단독으로 실행하면 구문 오류가 난다.
--
-- 5) 여러 파일을 한꺼번에 옮길 때는 다음 형태를 쓴다.
--    SET NEWNAME FOR DATABASE TO '/u03/oradata/ORCL/%b';
--    %b 는 원래 파일명만 남기는 치환 문자다.
--
-- 6) 경로가 바뀌었으므로 백업을 다시 받고 문서를 갱신한다.
--    복구 절차서의 경로 목록이 옛 값이면 다음 장애에서 혼란을 만든다.
