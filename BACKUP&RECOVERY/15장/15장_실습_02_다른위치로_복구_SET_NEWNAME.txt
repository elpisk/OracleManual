[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 데이터파일이 있던 디스크를 더 이상 쓸 수 없다.
-- 다른 디스크로 복원하고 그 위치를 정식 경로로 등록한다.
-- SET NEWNAME과 SWITCH를 짝으로 사용한다.

-- 복구 유형 : 완전 복구, 무중단, 파일 위치 변경

RMAN> RUN {
  2>   SET NEWNAME FOR DATAFILE 8 TO '/u03/oradata/ORCL/tbs13_01.dbf';
  3>   SWITCH DATAFILE ALL;
  4>   RECOVER TABLESPACE tbs13;
  5>   SQL 'ALTER TABLESPACE tbs13 ONLINE';
  6> }

-- 실무 포인트
-- 1) SET NEWNAME은 복원 위치만 지정한다.
--    컨트롤파일에는 여전히 원래 경로가 기록되어 있다.
--    SWITCH로 그 경로를 갱신해야 데이터베이스가 새 파일을 인식한다.
--
-- 2) SWITCH를 빠뜨리면 RECOVER 가 옛 경로를 찾다 ORA-01157 로 실패한다.
--    파일은 새 위치에 있는데 컨트롤파일은 옛 경로를 보고 있기 때문이다.
--
-- 3) 올바른 순서는 SET NEWNAME → RESTORE → SWITCH → RECOVER 다.
--    RECOVER를 SWITCH보다 먼저 하면 옛 경로를 대상으로 삼아 실패한다.
--
-- 4) SET NEWNAME은 RUN 블록 안에서만 쓸 수 있다.
--    프롬프트에서 단독으로 실행하면 구문 오류가 난다.
--
-- 5) 여러 파일을 한꺼번에 옮길 때는 다음 형태를 쓴다.
--    SET NEWNAME FOR DATABASE TO '/u03/oradata/ORCL/%b';
--    %b 는 원래 파일명만 남기는 치환 문자다.
--
-- 6) 경로가 바뀌었으므로 백업을 다시 받고 문서를 갱신한다.
--    복구 절차서의 경로 목록이 옛 값이면 다음 장애에서 혼란을 만든다.
