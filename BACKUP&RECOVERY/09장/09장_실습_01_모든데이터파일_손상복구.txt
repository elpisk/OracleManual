================================================================================
 실습 9-1 : 모든 데이터파일 손상 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 25분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 데이터파일이 놓인 디스크가 손상되어 모든 데이터파일이 유실되었다.
-- 컨트롤파일과 리두 로그, 아카이브는 다른 디스크에 있어 온전하다.
-- MOUNT 상태에서 전체 복원 후 RECOVER DATABASE 로 일괄 처리한다.
-- 아카이브가 연속이면 파일이 전부 없어져도 손실이 없다.
-- 복구 유형 : 완전 복구(전면 중단)

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

SYS@orcl> SELECT MIN(sequence#) AS oldest, MAX(sequence#) AS newest, COUNT(*) AS cnt,

  3  FROM   v$archived_log WHERE status = 'A';

-- CNT와 EXPECTED가 같다. 아카이브가 연속이다.

-- 판정
--   ① 컨트롤파일·리두 : 온전
--   ② 백업본 : 일곱 개 모두 보유
--   ③ 아카이브 : 연속 보유
--   → 완전 복구 가능. MOUNT 상태에서 전체 복원 후 RECOVER DATABASE.

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- MOUNT 상태에서 바로 복구를 시도한다.

SYS@orcl> SET AUTORECOVERY ON
SYS@orcl> RECOVER DATABASE;
ORA-00283: recovery session canceled due to errors
ORA-01110: data file 1: '/u01/app/oracle/oradata/ORCL/system01.dbf'
ORA-01157: cannot identify/lock data file 1 - see DBWR trace file

-- << 원인 파악 >>
-- 복구는 파일에 리두를 적용하는 작업이다. 적용할 대상 파일이 있어야 한다.
-- 파일이 하나도 없는 상태에서는 복구를 시작할 수 없다.
-- 복원이 먼저이고 복구가 나중이다. 순서를 뒤집을 수 없다.

SYS@orcl> !ls /u01/app/oracle/oradata/ORCL/*.dbf 2>/dev/null
[oracle@oel7v9r1 ~]$

-- << 수정 >>

SYS@orcl> !cp -p /home/oracle/backup/ch09/*.dbf /u01/app/oracle/oradata/ORCL/

SYS@orcl> !ls /u01/app/oracle/oradata/ORCL/*.dbf | wc -l
7

-- 아카이브가 정상 생성되고 여유 공간도 충분하다.

-- 실무 포인트
-- 1) 아카이브가 연속이면 데이터파일이 전부 없어져도 손실이 없다.
--    NOARCHIVELOG 환경에서 같은 상황은 백업 시점 복귀와 큰 손실로 끝났다.
--    아카이브 모드 전환의 가치가 가장 크게 드러나는 장면이다.
--
-- 2) 복원이 먼저이고 복구가 나중이다.
--    파일이 없는 상태에서 RECOVER 를 시도하면 ORA-01157로 막힌다.
--    복구는 존재하는 파일에 리두를 적용하는 작업이기 때문이다.
--
-- 3) 오류 메시지는 첫 파일만 알려 준다.
--    전체 목록은 MOUNT 상태에서 v$recover_file 로 확인해야 한다.
--    ERROR 컬럼이 FILE NOT FOUND 에서 공백으로 바뀌면 복원이 끝났다는 뜻이다.
--
-- 4) 복구 전 아카이브 연속성을 점검한다.
--    개수와 기대값을 비교하는 조회 하나로 확인할 수 있다.
--    빠진 구간이 있으면 그 지점이 복구 한계이므로 계획을 다시 세워야 한다.
--
-- 5) 복구가 길어지면 v$recovery_progress 로 진행 상황을 확인한다.
--    현업에 예상 시간을 안내할 수 있어 대응이 매끄러워진다.
--
-- 6) 백업본과 아카이브는 데이터 디스크와 다른 물리 장치에 둔다.
--    이 실습이 성립한 이유가 바로 그 배치다. 같은 디스크였다면 함께 사라졌다.

SYS@orcl> EXIT
