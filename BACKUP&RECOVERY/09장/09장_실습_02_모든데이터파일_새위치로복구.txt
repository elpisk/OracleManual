 실습 9-2 : 모든 데이터파일을 새 위치로 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 25분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 모든 데이터파일이 유실되었고 원래 디스크를 더 이상 쓸 수 없다.
-- 백업본을 새 위치로 복원하고 파일마다 RENAME FILE 을 수행한다.
-- 파일이 많으므로 조회 결과로 RENAME 스크립트를 생성해 일괄 적용한다.
-- TEMP 파일 이전과 후속 작업까지 함께 다룬다.
-- 복구 유형 : 완전 복구(경로 변경, 전면 중단)

-- << 원인 파악 >>
-- 파일은 /u02에 복원했는데 컨트롤파일은 여전히 /u01 경로를 알고 있다.
-- 복구는 컨트롤파일이 아는 경로의 파일을 대상으로 한다.
-- 복원 위치가 달라졌으면 RENAME FILE 로 그 사실을 먼저 알려야 한다.
-- 파일이 일곱 개이므로 손으로 입력하면 오타가 나기 쉽다.

SYS@orcl> SELECT file#, name FROM v$datafile WHERE file# = 1;

     FILE# NAME
---------- ------------------------------------------
         1 /u01/app/oracle/oradata/ORCL/system01.dbf

-- << 수정 >>
-- 조회 결과로 RENAME 스크립트를 생성한다.

SYS@orcl> SET LINESIZE 200 PAGESIZE 0 FEEDBACK OFF
SYS@orcl> SPOOL /home/oracle/backup/rename.sql
SYS@orcl> SELECT 'ALTER DATABASE RENAME FILE ''' || name || '''' ||
  2         ' TO ''' || REPLACE(name, '/u01/app/oracle/oradata/ORCL',
  3         '/u02/oradata/ORCL') || ''';'
  4  FROM   v$datafile ORDER BY file#;
SYS@orcl> SPOOL OFF
SYS@orcl> SET PAGESIZE 50 FEEDBACK ON

SYS@orcl> !grep -c 'RENAME FILE' /home/oracle/backup/rename.sql

-- 백업 스크립트의 경로 목록도 이 결과로 갱신한다.

-- 실무 포인트
-- 1) 복원 위치가 달라지면 RENAME FILE 이 반드시 필요하다.
--    컨트롤파일이 아는 경로의 파일이 복구 대상이 되기 때문이다.
--    RENAME 없이 복구하면 예전 경로를 찾다 ORA-01157로 막힌다.
--
-- 2) 파일이 많으면 스크립트를 생성한다.
--    v$datafile 조회 결과에 REPLACE 를 적용하면 한 번에 만들어진다.
--    이 쿼리를 복구 절차서에 넣어 두면 장애 시 바로 쓸 수 있다.
--
-- 3) 생성한 스크립트는 실행 전에 눈으로 확인한다.
--    SPOOL 파일에 프롬프트나 머리글이 섞이면 실행이 실패한다.
--    PAGESIZE 0 과 FEEDBACK OFF 로 불필요한 출력을 줄인다.
--
-- 4) TEMP 파일은 RENAME 대상에 포함되지 않는다.
--    v$datafile 조회로 만든 스크립트에는 TEMP가 없기 때문이다.
--    ADD TEMPFILE 로 새 위치에 추가하고 예전 것을 DROP 한다.
--
-- 5) 경로가 바뀌면 후속 작업이 따라온다.
--    백업 스크립트, 매니페스트, 모니터링 대상을 모두 갱신하고
--    컨트롤파일 백업을 새로 받는다.
--
-- 6) 갱신을 빠뜨리면 다음 백업이 조용히 실패한다.
--    그 사실이 다음 장애에서야 드러나므로 경로 변경 후 점검이 중요하다.

SYS@orcl> EXIT
