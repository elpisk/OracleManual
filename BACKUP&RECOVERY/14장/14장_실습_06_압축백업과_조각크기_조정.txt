--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 같은 대상을 압축 없이와 압축으로 백업해 크기와 시간을 비교한다.
-- MAXPIECESIZE로 조각 크기를 제한한다.
-- SECTION SIZE로 큰 파일을 나눠 병렬 처리한다.
-- MAXSETSIZE를 잘못 설정했을 때의 실패를 확인한다.
-- 작업 유형 : 백업 최적화(장애 복구 아님)

-- 파일 하나를 블록 범위로 나눠 두 채널이 동시에 처리했다.
-- MAXPIECESIZE는 결과 파일을 나누고 SECTION SIZE는 작업 자체를 나눈다.
-- 큰 데이터파일 하나가 백업 시간을 지배할 때 효과가 크다.

--------------------------------------------------------------------------------
[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- MAXSETSIZE를 데이터파일보다 작게 설정해 본다.

RMAN> CONFIGURE MAXSETSIZE TO 100 M;

new RMAN configuration parameters:
CONFIGURE MAXSETSIZE TO 100 M;
new RMAN configuration parameters are successfully stored

RMAN> BACKUP DATAFILE 1;

Starting backup at 15-MAY-25
channel ORA_DISK_1: starting full datafile backup set
RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-03002: failure of backup command at 05/15/2025 12:22:41
RMAN-06183: datafile or datafile copy larger than MAXSETSIZE:
 file# 1 /u02/oradata/ORCL/system01.dbf

-- << 원인 파악 >>
-- MAXSETSIZE는 백업 세트 하나의 최대 크기다.
-- 데이터파일 하나가 그 값보다 크면 세트를 만들 수 없어 백업이 실패한다.
-- 조각 크기를 제한하려던 것이라면 MAXPIECESIZE를 썼어야 한다.
-- 두 옵션의 이름이 비슷해 혼동하기 쉽다.

-- << 수정 >>

RMAN> CONFIGURE MAXSETSIZE CLEAR;

RMAN configuration parameters are successfully reset to default value

RMAN> SHOW MAXSETSIZE;

CONFIGURE MAXSETSIZE TO UNLIMITED; # default

RMAN> BACKUP DATAFILE 1 TAG 'AFTER_FIX';

Starting backup at 15-MAY-25
Finished backup at 15-MAY-25

-- 정리
[oracle@oel7v9r1 ~]$ rman target /
RMAN> DELETE NOPROMPT BACKUP TAG 'PIECES';
RMAN> DELETE NOPROMPT BACKUP TAG 'SECTION';

-- 실무 포인트
-- 1) 압축 없이도 백업 세트는 원본보다 작다.
--    빈 블록을 건너뛰기 때문이며 이 실습에서 890MB가 712MB가 되었다.
--    압축을 적용하면 179MB까지 줄었지만 시간이 36초에서 84초로 늘었다.
--
-- 2) 압축은 디스크와 CPU를 맞바꾸는 선택이다.
--    백업 창이 빠듯하면 압축이 오히려 문제가 될 수 있다.
--    compression_ratio 컬럼으로 효과를 정량적으로 확인한다.
--
-- 3) MAXPIECESIZE는 결과 파일을 나눈다.
--    하나의 백업 세트가 여러 조각이 되며 미디어 크기 제한에 대응한다.
--
-- 4) SECTION SIZE는 작업 자체를 나눈다.
--    파일 하나를 블록 범위로 쪼개 여러 채널이 동시에 처리한다.
--    큰 데이터파일 하나가 백업 시간을 지배할 때 효과가 크다.
--
-- 5) MAXSETSIZE는 백업 세트의 최대 크기다.
--    데이터파일보다 작게 설정하면 RMAN-06183으로 백업이 실패한다.
--    조각 크기 제한이 목적이라면 MAXPIECESIZE를 써야 한다.
--
-- 6) 설정 실수는 CLEAR로 되돌린다.
--    SHOW로 기본값 복귀를 확인한 뒤 백업을 다시 시도한다.
