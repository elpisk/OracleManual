-- 작업 유형 : 백업 최적화(장애 복구 아님)

SYS@orcl> SELECT bs.recid, bs.pieces, MAX(bp.compressed) AS com,
  2         ROUND(SUM(bp.bytes)/1024/1024) AS mb, MAX(bp.tag) AS tag
  3  FROM   v$backup_set bs, v$backup_piece bp
  4  WHERE  bs.set_stamp = bp.set_stamp AND bs.set_count = bp.set_count
  5  AND    bp.tag IN ('NOCOMP','COMP','PIECES','SECTION','AFTER_FIX') AND bp.status = 'A'
  6  GROUP  BY bs.recid, bs.pieces ORDER BY bs.recid;

     RECID     PIECES COM         MB TAG
---------- ---------- --- ---------- ----------
       118          1 NO         782 NOCOMP
       120          1 YES        235 COMP
       122          4 NO         782 PIECES
       124          5 NO         782 SECTION
       126          1 NO         782 AFTER_FIX

-- (압축 여부와 크기는 v$backup_set 이 아니라 v$backup_piece 에 있다.)
-- 압축본이 235MB로 가장 작다.
-- MAXPIECESIZE(122)도 SECTION SIZE(124)도 세트는 하나이고 조각만 나뉜다.
-- 122 는 결과 파일을 200MB 씩 자른 것이고 124 는 작업 구간을 나눈 것이다.

SYS@orcl> SELECT TO_CHAR(start_time,'HH24:MI') AS started, elapsed_seconds AS secs,
  2         ROUND(output_bytes/1024/1024) AS out_mb
  3  FROM   v$rman_backup_job_details
  4  ORDER  BY start_time DESC FETCH FIRST 4 ROWS ONLY;

STARTED       SECS     OUT_MB
------- ---------- ----------
12:19           15        782
12:14           58       1563
12:07           18        235
12:04           27        782

-- 12:14 행은 PIECES 와 AFTER_FIX 가 한 세션이라 합쳐진 값(1,563MB)이다.
-- 다중 섹션(12:19)은 채널 둘이 나눠 15초, 단일 채널(12:04)은 27초다.
-- 목표가 공간이면 압축, 시간이면 다중 섹션이 답이다.

-- 정리
[oracle@oel7v9 ~]$ rman target /
RMAN> DELETE NOPROMPT BACKUP TAG 'PIECES';
RMAN> DELETE NOPROMPT BACKUP TAG 'SECTION';

-- 실무 포인트
-- 1) 압축 없이도 백업 세트는 원본보다 작다.
--    빈 블록을 건너뛰기 때문이며 이 실습에서 890MB가 782MB가 되었다.
--    압축을 적용하면 235MB까지 줄었다.
--
-- 2) 압축은 디스크·I/O 와 CPU 를 맞바꾸는 선택이다.
--    I/O 가 병목이면 이 실습처럼 오히려 빨라지고, CPU 가 병목이면 느려진다.
--    compression_ratio 와 elapsed_seconds 를 자기 서버에서 재어 정한다.
--
-- 3) MAXPIECESIZE는 결과 파일을 나눈다.
--    하나의 백업 세트가 여러 조각이 되며 미디어 크기 제한에 대응한다.
--    같은 세션에서 SECTION SIZE 와 섞어 쓰면 RMAN-06808 이 난다.
--
-- 4) SECTION SIZE는 작업 자체를 나눈다.
--    파일 하나를 블록 범위로 쪼개 여러 채널이 동시에 처리한다.
--    큰 데이터파일 하나가 백업 시간을 지배할 때 효과가 크다.
--
-- 5) MAXSETSIZE는 백업 세트의 최대 크기다.
--    데이터파일보다 작게 설정하면 RMAN-06183으로 백업이 실패한다.
--    조각 크기 제한이 목적이라면 MAXPIECESIZE를 써야 한다.
--
-- 6) 설정 실수는 CLEAR로 되돌린다.
--    SHOW로 기본값 복귀를 확인한 뒤 백업을 다시 시도한다.
--    v$rman_backup_job_details 는 세션 단위로 모이므로 명령별 비교는 세션을 나눈다.
