================================================================================
 실습 14-5 : Image Copy(BACKUP AS COPY)와 SWITCH를 이용한 즉시 복구
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 35분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 이미지 카피를 만들고 백업 세트와 크기를 비교한다.
-- 데이터파일을 손상시킨 뒤 SWITCH로 즉시 전환해 복구한다.
-- 복원 단계가 사라지는 것을 시간으로 확인한다.
-- 전환 후 데이터파일 위치가 바뀐다는 점과 그 뒷정리를 확인한다.
-- 복구 유형 : 이미지 카피 전환 복구, 손실 없음

[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- OFFLINE 하지 않고 바로 SWITCH를 시도해 본다.

RMAN> SWITCH DATAFILE 8 TO COPY;

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-03002: failure of switch to copy command at 05/15/2025 11:14:02
RMAN-06572: database is open and datafile 8 is not offline

-- << 원인 파악 >>
-- 파일이 ONLINE 상태이면 전환할 수 없다.
-- 데이터베이스가 그 파일을 열어 두고 있기 때문이다.
-- 먼저 OFFLINE으로 내려야 한다.

-- 원래 위치로 돌아왔다.

-- 실무 포인트
-- 1) 이미지 카피는 원본과 크기가 같다.
--    백업 세트는 빈 블록을 건너뛰어 작지만 카피는 그대로 복사한다.
--    디스크 요구량이 100%라는 점이 이 방식의 대가다.
--
-- 2) SWITCH는 파일을 옮기지 않는다.
--    컨트롤파일에 기록된 경로를 바꾸는 동작이므로 크기와 무관하게 즉시 끝난다.
--    500GB 데이터베이스에서 40분 걸리던 복원이 수 초로 줄어드는 이유다.
--
-- 3) SWITCH 전에 해당 파일을 OFFLINE으로 내려야 한다.
--    ONLINE 상태에서는 RMAN-06572로 거부된다.
--    전체를 전환할 때는 MOUNT 상태에서 SWITCH DATABASE TO COPY 를 쓴다.
--
-- 4) 열린 파일을 지우면 곧바로 오류가 나지 않는다.
--    핸들이 살아 있는 동안은 조회도 되고 v$recover_file 도 비어 있다.
--    OFFLINE/ONLINE 이나 재기동처럼 이름으로 다시 열 때 ORA-01157 로 드러난다.
--
-- 5) SWITCH 후에도 RECOVER는 필요하다.
--    카피를 만든 시점 이후의 변경은 아카이브로 채워야 하기 때문이다.
--    이 단계는 백업 세트 복구와 동일하다.
--
-- 6) 전환 후 카피가 있던 경로가 정식 데이터파일 위치가 된다.
--    백업용 저성능 디스크라면 성능이 떨어지므로 반드시 뒷정리를 계획한다.
--    되돌릴 때는 원래 경로로 카피를 만들고 다시 SWITCH 한다.
--
-- 7) 이 방식은 복구 시간과 디스크를 맞바꾸는 선택이다.
--    증분 갱신 백업과 결합하면 카피를 항상 최신에 가깝게 유지할 수 있다.
