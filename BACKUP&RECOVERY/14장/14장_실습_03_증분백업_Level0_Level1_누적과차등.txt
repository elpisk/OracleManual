--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- Level 0을 기준점으로 삼고 Level 1을 여러 번 받는다.
-- 차등과 누적의 크기 차이를 같은 변경량으로 비교한다.
-- FULL을 기준점으로 삼으려 할 때 무슨 일이 생기는지 확인한다.
-- 증분 백업의 복원 동작을 PREVIEW로 확인한다.
-- 작업 유형 : 백업 수행(장애 복구 아님)

[oracle@oel7v9 ~]$ sqlplus / as sysdba

SYS@orcl> SET LINESIZE 200
SYS@orcl> COL tag FOR a14
SYS@orcl> SELECT bp.recid, bd.incremental_level AS lv,
  2         DECODE(bd.incremental_change#, 0, 'BASE',
  3                TO_CHAR(bd.incremental_change#)) AS from_scn,
  4         ROUND(bp.bytes/1024/1024, 1) AS mb, bd.blocks, bd.blocks_read, bp.tag
  5  FROM   v$backup_piece bp, v$backup_datafile bd
  6  WHERE  bp.set_stamp = bd.set_stamp AND bp.set_count = bd.set_count
  7  AND    bd.file# = 8 AND bp.status = 'A' AND bp.recid >= 71
  8  ORDER  BY bp.recid;

---------- ---------- ------------ ---------- ---------- ----------- --------------

        73          1 2561951             6.5        833         896 L1_AFTER_FULL
        75          0 BASE                6.6        836         896 L0_WEEKLY
        89          1 2570926             1.1        136         896 L1_DIFF_MON

-- (v$backup_set 에는 bytes 열이 없다. 크기는 v$backup_piece 에서 본다.)
-- RECID 73 : Level 0 없이 받은 Level 1. from_scn 이 파일 생성 SCN 이고 833 블록으로
--            사실상 전체다. Level 1 이란 이름만 붙은 FULL 이다.
-- RECID 93 이 차등, 95 가 누적이다.
-- 차등은 직전 Level 1 이후 변경분만 담아 135 블록(1.1MB)이다.
-- 누적은 Level 0 이후 전체 변경분을 담아 402 블록(3.2MB), 차등 세 개의 합과 같다.
-- from_scn 값이 그 차이를 보여 준다. 누적은 Level 0의 SCN(2570926)을 기준으로 한다.
-- BLOCKS_READ 는 모두 896(파일 전체)이다. 담는 양은 줄어도 읽는 양은 그대로다(14-4).

-- 복구 시 적용 대상
--   차등 → L0 + 월 + 화 + 수  (4개)
--   누적 → L0 + 누적 수요일   (2개)

-- 실무 포인트
-- 1) FULL은 증분의 기준점이 되지 못한다.
--    Level 0 없이 Level 1을 받으면 오류 없이 파일 전체를 담은 "Level 1" 이 만들어진다.
--    LIST 의 LV 만 보면 모르고, v$backup_datafile 의 blocks 와 from_scn 을 봐야 드러난다.
--
-- 2) 차등과 누적의 차이는 from_scn 으로 확인할 수 있다.
--    차등은 직전 백업의 SCN, 누적은 Level 0의 SCN을 기준으로 한다.
--    같은 변경량에서 누적이 약 세 배 컸다.
--
-- 3) 복구 관점에서는 반대다.
--    차등은 Level 0과 모든 Level 1을 순서대로 적용해야 하고
--    누적은 Level 0과 마지막 하나만 적용하면 된다. PREVIEW 가 그 조합을 보여 준다.
--
-- 4) 증분 레벨은 0과 1만 쓴다.
--    Level 2~4 는 구문은 통하지만 뒤의 Level 1 이 부모로 삼지 않아 버려지는 백업이 된다.
--
-- 5) RESTORE PREVIEW 로 복원에 필요한 백업을 미리 확인한다.
--    목록이 길어지면 Level 0 주기를 짧게 조정할 근거가 된다.
--
-- 6) 백업 크기만 보고 판단하지 않는다.
--    BLOCKS_READ 가 파일 전체인 것을 보았다. 다음 실습에서 BCT 로 읽는 양을 줄인다.
