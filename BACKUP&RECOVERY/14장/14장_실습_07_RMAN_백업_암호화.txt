================================================================================
 실습 14-7 : RMAN 백업 암호화 — SET ENCRYPTION ON
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 30분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 외부 반출용 백업을 비밀번호 방식으로 암호화한다.
-- 암호화 여부를 v$backup_piece 로 확인한다.
-- 비밀번호 없이 복원을 시도해 실패를 확인한다.
-- 복호화 키를 지정한 뒤 복원이 되는 것을 확인한다.
-- 작업 유형 : 백업 보호(장애 복구 아님)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 실습 14-6까지 완료되어 있어야 한다.

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat

CONFIGURE ENCRYPTION FOR DATABASE OFF; # default

-- 기본은 꺼져 있고 알고리즘은 AES128이다.

[5] 진행 로그 : 비밀번호 방식 암호화
--------------------------------------------------------------------------------
RMAN> SET ENCRYPTION ON IDENTIFIED BY 'Backup#2025' ONLY;

executing command: SET encryption

-- ONLY를 붙이면 비밀번호로만 열 수 있다.
-- 붙이지 않으면 지갑과 비밀번호 둘 다로 열 수 있는 이중 방식이 된다.

-- 여러 세션에서 반복 사용할 백업이라면 스크립트에 키를 넣어야 한다.

[oracle@oel7v9 ~]$ cat > /home/oracle/rman/export_backup.rmn <<'EOS'
SET ENCRYPTION ON IDENTIFIED BY '&1' ONLY;
BACKUP AS COMPRESSED BACKUPSET DATABASE
  FORMAT '/home/oracle/rmanbk/export_%U' TAG 'ENC_EXPORT';
EOS

[oracle@oel7v9 ~]$ chmod 600 /home/oracle/rman/export_backup.rmn

-- 비밀번호를 파일에 직접 넣지 않고 치환 변수로 받는다.
-- 스크립트에 평문으로 넣으면 암호화의 의미가 크게 줄어든다.

-- 실무 포인트
-- 1) 암호화 방식은 세 가지다.
--    투명 방식은 지갑을 사용하며 복원 시 자동으로 열린다.
--    비밀번호 방식은 복원 시 같은 비밀번호가 필요하다.
--    이중 방식은 둘 다로 열 수 있으며 ONLY를 붙이지 않으면 이 방식이 된다.
--
-- 2) 지갑이 없으면 투명 방식은 ORA-28365로 실패한다.
--    운영에서 상시 암호화를 쓰려면 지갑 구성이 선행되어야 한다.
--
-- 3) SET ENCRYPTION 은 세션 단위 설정이며 그 세션의 자동 백업까지 암호화한다.
--    새 세션에는 남아 있지 않으므로 복원 시 SET DECRYPTION 을 다시 지정한다.
--    암호화된 자동 백업으로 컨트롤파일을 복원할 때도 비밀번호가 필요하다.
--
-- 4) 비밀번호를 모르면 ORA-19913으로 막히며 우회 방법이 없다.
--    담당자 퇴사로 비밀번호가 사라져 백업을 열지 못한 사례가 실제로 있다.
--    암호화는 복원 절차의 일부이므로 비밀번호 보관 위치를 절차서에 남긴다.
--
-- 5) 암호화하지 않은 백업 조각에서는 문자열이 그대로 보인다.
--    외부 반출이나 원격 보관 시 암호화가 필요한 이유다.
--    암호화 여부는 v$backup_piece.encrypted 로 확인한다(LIST 에는 안 나온다).
--
-- 6) 스크립트에 비밀번호를 평문으로 넣지 않는다.
--    치환 변수로 받거나 지갑 기반 투명 방식으로 전환한다.
