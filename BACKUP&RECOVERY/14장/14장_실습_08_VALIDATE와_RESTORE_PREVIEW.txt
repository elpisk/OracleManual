[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 세 검증 명령의 역할 차이를 확인한다.
-- VALIDATE는 대상을, BACKUP VALIDATE는 백업 가능성을 검사한다.
-- RESTORE PREVIEW는 복원 계획을, RESTORE VALIDATE는 백업본 가용성을 확인한다.
-- 백업 조각을 손상시켜 검증이 실패를 잡아내는지 확인한다.
-- 작업 유형 : 검증(장애 복구 아님)

-- << 원인 파악 >>
-- ORA-19612는 백업 조각이 없거나 손상되었다는 뜻이다.
-- CROSSCHECK는 통과했으므로 파일은 존재한다. 내용이 깨진 것이다.
-- 파일 존재 확인과 내용 검증은 다른 명령이 담당한다.
-- CROSSCHECK만 정기 작업에 넣어 두면 이런 손상을 발견하지 못한다.

RMAN> LIST BACKUP TAG 'NOCOMP';

52      Full    712.44M    DISK        00:00:36     15-MAY-25
        BP Key: 52   Status: AVAILABLE  Tag: NOCOMP

-- 상태는 여전히 AVAILABLE이다.

-- << 수정 >> 손상된 백업을 리포지터리에서 제외하고 다른 백업으로 대체한다.

-- 실무 포인트
-- 1) 세 명령의 검사 대상이 다르다.
--    VALIDATE는 운영 중인 데이터파일의 블록을 검사한다.
--    BACKUP VALIDATE는 백업이 가능한 상태인지 흉내 내어 확인한다.
--    RESTORE VALIDATE는 백업본이 실제로 읽히는지 확인한다.
--
-- 2) BACKUP VALIDATE는 백업 조각을 만들지 않는다.
--    LIST 목록이 늘지 않는 것으로 확인할 수 있다.
--    야간 백업 전 사전 점검에 쓰면 실패를 미리 줄일 수 있다.
--
-- 3) RESTORE PREVIEW는 복구 계획을 세울 때 가장 먼저 쓴다.
--    어느 백업과 아카이브가 쓰일지, 어느 SCN을 넘어야 하는지 알려 준다.
--    테이프에서 가져와야 할 것이 있는지도 여기서 드러난다.
--
-- 4) CROSSCHECK는 파일 존재만 확인하며 내용 손상은 잡지 못한다.
--    손상된 조각도 AVAILABLE로 남는다.
--    내용 검증은 RESTORE ... VALIDATE 가 담당한다.
--
-- 5) 두 명령을 모두 정기 점검에 넣어야 한다.
--    CROSSCHECK는 주 1회, RESTORE VALIDATE도 주 1회를 권한다.
--
-- 6) 손상된 백업은 CHANGE ... UNAVAILABLE 로 선택 대상에서 제외한다.
--    복구 중이라면 이 조치로 다른 백업을 즉시 쓸 수 있다.
--    원인을 해결한 뒤 AVAILABLE 로 되돌린다.
