[5] 진행 로그 해석
--------------------------------------------------------------------------------
-- 로그를 여섯 구간으로 나눠 읽는다.
--   ① current log archived        : 백업 전 로그 스위치
--   ② archived log backup set     : 그때까지의 아카이브 백업
--   ③ full datafile backup set    : 데이터파일 백업 (채널 2개)
--   ④ current log archived        : 백업 구간 리두를 아카이브
--   ⑤ archived log backup set     : 시퀀스 11 백업
--   ⑥ Control File and SPFILE Autobackup
--
-- ④와 ⑤가 핵심이다.
-- 데이터파일 백업 구간의 리두가 확보되어 이 백업만으로 일관성 복구가 가능해진다.

RMAN> LIST BACKUP SUMMARY;

Key     TY LV S Device Type Completion Time #Pieces #Copies Compressed Tag
------- -- -- - ----------- --------------- ------- ------- ---------- ----------
24      B  A  A DISK        14-MAY-25       1       1       NO         TAG2025...
25      B  F  A DISK        14-MAY-25       1       1       NO         FULL_DAILY
26      B  F  A DISK        14-MAY-25       1       1       NO         FULL_DAILY
27      B  A  A DISK        14-MAY-25       1       1       NO         TAG2025...
28      B  F  A DISK        14-MAY-25       1       1       NO         TAG2025...

-- TY 컬럼 : B는 백업 세트, A는 아카이브 로그 백업, F는 전체를 뜻한다.
-- 데이터파일 백업이 두 세트로 나뉜 것은 채널이 두 개였기 때문이다.

-- 실무 포인트
-- 1) PLUS ARCHIVELOG 는 백업 전후로 로그 스위치를 건다.
--    ④단계의 스위치로 데이터파일 백업 구간의 리두가 확보된다.
--    그 결과 이 백업 세트만으로 일관성 있는 복구가 가능해진다.
--
-- 2) 채널 수만큼 백업 세트가 나뉜다.
--    로그에서 allocated channel 줄의 개수로 병렬도 반영을 확인한다.
--    데이터파일이 채널에 분배되는 방식은 RMAN이 크기를 고려해 정한다.
--
-- 3) 마지막에 자동 백업 구간이 보이지 않으면 설정이 꺼진 것이다.
--    매 백업 로그에서 이 구간을 확인하는 습관을 들인다.
--
-- 4) 압축 없이도 출력이 입력보다 작다.
--    빈 블록을 건너뛰기 때문이며 User Managed 백업과의 대표적 차이다.
--
-- 5) 오류 스택은 아래부터 읽는다.
--    ORA-27040 + Error 13은 권한, Error 28은 공간 부족이다.
--    두 경우의 조치가 다르므로 반드시 구분한다.
--
-- 6) 백업 후 REPORT NEED BACKUP 이 비었는지 확인한다.
--    비어 있어야 보존 정책 요건이 충족된 상태다.
