[5] 진행 로그 해석
--------------------------------------------------------------------------------
-- 로그를 여섯 구간으로 나눠 읽는다.
--   ① current log archived        : 백업 전 로그 스위치 (시퀀스 6 생성)
--   ② archived log backup set     : 그때까지의 아카이브 백업 (5, 6 — 채널 둘이 나눠 맡음)
--   ③ full datafile backup set    : 데이터파일 백업 (채널 2개, 세트 2개)
--   ④ current log archived        : 백업 구간 리두를 아카이브 (시퀀스 7 생성)
--   ⑤ archived log backup set     : 시퀀스 7 백업
--   ⑥ Control File and SPFILE Autobackup
--
-- ④와 ⑤가 핵심이다.
-- 데이터파일 백업 구간의 리두가 확보되어 이 백업만으로 일관성 복구가 가능해진다.
--
-- TAG 의 위치에 주의한다. TAG 는 바로 앞의 백업 대상(DATABASE)에만 붙는다.
-- ②·⑤의 아카이브 세트는 기본 태그(TAG날짜시각)를 받았다.
-- `BACKUP DATABASE PLUS ARCHIVELOG TAG 'FULL_DAILY'` 처럼 뒤에 쓰면 반대로
-- 아카이브 세트에만 붙고 데이터파일 세트는 기본 태그가 된다(실측).

-- 실무 포인트
-- 1) PLUS ARCHIVELOG 는 백업 전후로 로그 스위치를 건다.
--    ④단계의 스위치로 데이터파일 백업 구간의 리두가 확보된다.
--    그 결과 이 백업 세트만으로 일관성 있는 복구가 가능해진다.
--
-- 2) TAG 는 바로 앞의 백업 대상에만 붙는다.
--    BACKUP DATABASE TAG '…' PLUS ARCHIVELOG 로 써야 데이터파일 세트에 태그가 남는다.
--    뒤에 쓰면 아카이브 세트에만 붙어 나중에 FROM TAG 로 찾을 수 없다.
--
-- 3) 채널 수만큼 백업 세트가 나뉜다.
--    로그에서 allocated channel 줄의 개수로 병렬도 반영을 확인한다.
--    아카이브 백업도 채널이 나눠 맡는다. 한 채널이 실패하면 다른 채널로 넘긴다.
--
-- 4) 마지막에 자동 백업 구간이 보이지 않으면 설정이 꺼진 것이다.
--    매 백업 로그에서 이 구간을 확인하는 습관을 들인다.
--
-- 5) 압축 없이도 출력이 입력보다 조금 작다.
--    빈 블록을 건너뛰기 때문이며 User Managed 백업과의 대표적 차이다.
--    크게 줄이려면 14-6 의 압축을 쓴다.
--
-- 6) 오류 스택은 아래부터 읽는다.
--    ORA-27040 + Error 13은 권한, Error 28은 공간 부족이다.
--    두 경우의 조치가 다르므로 반드시 구분한다.
