================================================================================
 실습 4-6 : SYSTEM 데이터파일 손상 — 리두 없음
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL
 소요 시간 : 약 15분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- SYSTEM 데이터 파일이 유실되었고 리두도 덮어써졌다.
-- SYSTEM은 버릴 수 없으므로 전체를 백업 시점으로 되돌리는 것 외에 방법이 없다.
-- 이 장에서 손실 규모가 가장 큰 시나리오다.
-- 복구 유형 : 불완전 복구(백업 시점 복귀, 전체 데이터 손실)

--------------------------------------------------------------------------------

-- 판정
--   1단계 : 손상 파일이 SYSTEM이다 → 데이터베이스를 내리고 MOUNT에서 처리
--   2단계 : 백업본에 존재한다 → 복원 가능
--   3단계 : 백업본 SCN(2356402) < 최소 리두 SCN(2358140) → 리두 부족
--   4단계 : SYSTEM이므로 전체 복원 외에 방법이 없다

SYS@orcl> !mkdir -p /home/oracle/before_recover_46
SYS@orcl> !cp -p /u01/app/oracle/oradata/ORCL/*.ctl /u01/app/oracle/oradata/ORCL/*.log \
                 /home/oracle/before_recover_46/

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정

SYS@orcl> SHUTDOWN ABORT

SYS@orcl> !cp -p /home/oracle/backup/ch04/system01.dbf /u01/app/oracle/oradata/ORCL/

SYS@orcl> STARTUP MOUNT

SYS@orcl> SET AUTORECOVERY OFF
SYS@orcl> RECOVER DATABASE;

SYS@orcl> SELECT COUNT(*) FROM hr.emp1;

  COUNT(*)
----------
         2

-- 다른 테이블스페이스의 데이터도 백업 시점으로 함께 되돌아갔다.
-- 실습 4-4와 달리 부분 포기가 불가능해 전체가 영향을 받았다.

SYS@orcl> SELECT SCN_TO_TIMESTAMP(2356402) FROM dual;

SCN_TO_TIMESTAMP(2356402)
---------------------------------------------------------
09-MAY-25 06.11.02.000000000 PM

-- 이 시각 이후의 모든 업무를 재처리해야 한다. 현업에 통보할 정보다.

-- 실무 포인트
-- 1) SYSTEM 손상 + 리두 부족은 이 장에서 손실이 가장 큰 조합이다.
--    일반 테이블스페이스라면 그것만 버리고 나머지를 최신으로 살릴 수 있었으나,
--    SYSTEM은 그 우회로가 없어 전체가 백업 시점으로 되돌아간다.
--
-- 2) ORA-01541이 나오는 순간 판정이 끝난다.
--    "이 파일은 떼어 낼 수 없다"는 뜻이므로 전체 복원 외에 선택지가 없다.
--
-- 3) 손실 규모를 정확히 산출해 통보한다.
--    SCN_TO_TIMESTAMP로 복구 지점을 환산하고, 그 시각 이후 업무를 재처리하도록 안내한다.
--
-- 4) 예방책은 세 가지다.
--    SYSTEM 파일을 다중화된 디스크에 배치, 백업 주기 단축,
--    그리고 근본적으로는 ARCHIVELOG 전환이다.
--    ARCHIVELOG였다면 아카이브로 시퀀스 58 이후를 적용해 완전 복구가 가능했다.
--
-- 5) 이 실습이 4~7장에서 NOARCHIVELOG를 다루는 이유를 가장 분명하게 보여 준다.
--    같은 장애가 8장 이후 ARCHIVELOG 환경에서는 데이터 손실 없이 끝난다.

SYS@orcl> EXIT
