# 장애 주입 스크립트 (강사 전용 · 학생 노출 금지)

B&R 수료 점검 1일 실습(최상급)의 **장애 상황을 강사가 주입**하기 위한 스크립트다.
학생 배포자료에는 장애의 실제 원인·명령이 들어 있지 않다 — 학생은 **증상만 보고 스스로 진단·복구**한다.

## 파일
| 스크립트 | 시나리오 | 주입하는 장애(요약) |
|---|---|---|
| `fault_p1_block.sh` | 개인 1 | 은폐형 블록 손상(표+인덱스) + 아카이브 비표준 경로 이동 |
| `fault_p2_logical.sh` | 개인 2 | 정상 트랜잭션에 묻힌 오염 커밋 + Flashback 봉쇄(LogMiner/RECOVER TABLE 유도) |
| `fault_t1_multi.sh` | 조별 1 | CURRENT 리두+컨트롤파일 상실 + 손상 백업피스 + 아카이브 갭 + SYSTEM 블록 손상 |
| `fault_t2_dr.sh` | 조별 2 | 서버 소실 + DBID 미상 + 백업 분산 + TS 논리오염(TSPITR) + 스키마 이관 |
| `_lab_env.sh` | 공통 | 경로·SID·업무 스키마 설정(기본 SID=orcl, BIZ_USER=HR), 안전 가드 |
| `_preflight.sh` | 공통 | **비파괴 사전 점검** — 실경로·모드·백업·공간·스키마·보조 디렉터리 확인 |

## 사용법
1. `_lab_env.sh` 를 랩 환경(경로·SID·스키마)에 맞게 수정한다. 기본값은 SID=orcl, BIZ_USER=HR.
2. **먼저 `./_preflight.sh` 를 돌려** 실경로(특히 데이터파일 dir)·모드·백업·공간·HR 스키마·`/u01/aux`·`/backup2`·`DP` 디렉터리를 확인하고, `[!!]` 항목을 해소한다.
3. **반드시 복원 가능한 스냅숏을 먼저 뜬다.** 각 시나리오 시작 상태로 되돌릴 수 있어야 재실행·다음 조 진행이 가능하다.
4. 학생이 보지 않는 콘솔에서 실행한다. **fault_*.sh 는 DB 를 의도적으로 손상시킨다 — 되돌림은 오직 시작 스냅숏 복원뿐이다.**
   확인 게이트가 걸려 있다:
   ```bash
   ./fault_t1_multi.sh              # 대화형: 경고 배너 후 SID(orcl)를 직접 타이핑해야 진행
   DRYRUN=YES ./fault_t1_multi.sh   # 미리보기: 대상 SID/DBID 만 확인하고 변경 없이 종료
   SNAP_TAKEN=YES CONFIRM_DESTROY=YES ./fault_t1_multi.sh   # 비대화형(자동화)에서만
   ```
   `SNAP_TAKEN` 은 '스스로 선언'일 뿐 스냅숏 존재를 검증하지 못한다. 대화형 실행 시에는 SID 재입력이 실제 사람 확인 게이트다.
5. 스크립트가 출력하는 `[주입·비공개]`/`[참고·강사]` 값(오염 SCN, DBID 등)은 **채점·힌트 통제용**이며 학생에게 알리지 않는다.
6. 학생에게는 스크립트 헤더의 "학생 안내(구두)" 한 줄만 전달한다(예: "기동 실패가 보고되었다. 복구하라").

## 주의
- 스크립트는 **파괴적**이며 그 자체가 목적이다(장애 주입). **원복 기능은 없다** — 되돌리려면 실습 시작 상태의 VM/스토리지 스냅숏을 복원한다. DB/RMAN 레벨로는 못 되돌리는 손상(블록·컨트롤파일·서버 소실)이 포함된다.
- 진행 순서(권장): `_preflight.sh` → **VM/스토리지 스냅숏 생성** → `DRYRUN=YES` 로 대상 확인 → 실제 주입 → 실습 → **스냅숏 복원으로 다음 조 준비**.
- 운영 DB 에서 절대 실행하지 않는다. 개인 실습용 orcl 랩 전용.
- 경로·백업 위치·리두/컨트롤파일 구성은 랩마다 다르므로, 최초 1회는 강사가 직접 값을 확인하며 리허설한다.
- 조별 2 는 '새 호스트' 자원(빈 ORACLE_HOME·디렉터리)과 분산 백업 접근이 사전 준비돼야 한다.
- 파일 끝 줄은 각 스크립트의 "모범 복구" 요약이며, 상세 절차·채점은 `BR_수료점검_1일실습_진행안.docx` 를 따른다.
