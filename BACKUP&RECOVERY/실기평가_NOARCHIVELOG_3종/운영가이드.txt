================================================================================
 ■ NOARCHIVELOG 복구 실기평가 — 운영 가이드
   감독관 진행 순서 · 응시자 개인 PC 작업 · 채점과 정리
================================================================================

--------------------------------------------------------------------------------
 0. 전제
--------------------------------------------------------------------------------
 응시자는 각자 자기 PC 의 VM 에서 자기 ORCL 을 깨고 복구한다.
 공용 데이터베이스 하나를 여럿이 쓰는 방식이 아니다. 장애를 실제로 일으키므로
 공용 환경에서는 성립하지 않는다.

 감독관은 준비물 배포와 시간 관리, 채점을 맡는다.
 응시자 PC 에 원격 접속할 필요는 없다. 제출물은 텍스트 파일로 받는다.

 배포 대상 5개 스크립트
   exam_prep.sh    준비 (기준선 · Cold Backup 두 벌 · 확인용 테이블)
   exam_reset.sh   복원 (감독자 복원점으로 되돌리기)
   exam_break1.sh  시나리오 1 장애 유발   인자 1|2|3|4
   exam_break2.sh  시나리오 2 장애 유발   인자 1|2|3
   exam_break3.sh  시나리오 3 장애 유발   인자 1|2|3

================================================================================
 1. 감독관 — 시험 전날
================================================================================
 1-1. 응시자 VM 이 아래 조건을 만족하는지 확인한다. 하나라도 다르면 문제지의
      경로가 맞지 않아 그대로 진행할 수 없다.

      [oracle@oel7v9 ~]$ sqlplus / as sysdba
      SYS@orcl> SELECT name, log_mode, open_mode FROM v$database;
      SYS@orcl> SELECT file#, name FROM v$datafile ORDER BY file#;
      SYS@orcl> SELECT name FROM v$controlfile;
      SYS@orcl> SELECT group#, member FROM v$logfile ORDER BY group#, member;

      확인 항목
        · ORCL / READ WRITE / NOARCHIVELOG
        · 데이터파일과 TEMP 가 /u02/oradata/orcl/ 에 있다
        · 컨트롤파일 3개 — 01·03 은 /u02/oradata/orcl, 02 는 /fra/oradata/ORCL
        · 리두 3그룹 × 2멤버 — a멤버 /u02/oradata/orcl, b멤버 /fra/oradata/ORCL
        · $ORACLE_HOME 은 /u01/app/oracle/product/19.3.0/dbhome_1
        · hr 계정이 존재하고 기본 테이블스페이스가 USERS

 1-2. 디스크 여유를 본다. Cold Backup 을 두 벌 받으므로 데이터파일 총량의
      두 배가 필요하다. 이 랩 기준 약 11GB 다.

      $ df -h /home/oracle /u01 /u02

 1-3. 스크립트 5개를 각 응시자 VM 의 /home/oracle/exam/ 에 배포한다.

      $ mkdir -p /home/oracle/exam
      $ cp exam_*.sh /home/oracle/exam/
      $ chmod +x /home/oracle/exam/*.sh
      $ chown -R oracle:dba /home/oracle/exam

 1-4. VM 스냅숏을 하나 떠 둔다. 응시자가 복구에 실패하고 exam_reset.sh 로도
      돌아오지 못하는 경우의 마지막 보루다. 정지 상태에서 뜬다.

 1-5. 문제지를 인쇄하거나 파일로 준비한다. 모범답안은 배포하지 않는다.

================================================================================
 2. 감독관 — 시험 당일, 각 시나리오 시작 전
================================================================================
 2-1. 응시자에게 준비 스크립트를 실행시킨다. 이것은 시험 시간에 포함하지 않는다.
      약 3~5분 걸린다.

      $ /home/oracle/exam/exam_prep.sh

      정상 종료 시 마지막에 이렇게 나온다.
        준비 완료.
          응시자용 백업 : /home/oracle/backup/exam_nolog
          감독자 복원점 : /home/oracle/backup/_proctor
          기준선        : /home/oracle/exam/baseline.txt

      "중단:" 으로 끝나면 데이터베이스가 READ WRITE 가 아니거나 ARCHIVELOG 다.
      그 상태를 먼저 고친 뒤 다시 실행시킨다. 이 스크립트는 중단될 때
      백업을 건드리지 않으므로 반복 실행해도 안전하다.

 2-2. 기준선을 응시자가 직접 읽게 한다. 이후 모든 판정의 출발점이다.

      $ cat /home/oracle/exam/baseline.txt

      특히 아래 두 값을 각자 종이에 적게 한다.
        · CHECKPOINT_CHANGE#            백업 시점의 SCN
        · MIN_FIRST_CHANGE              온라인 리두가 담고 있는 가장 오래된 SCN
      시나리오 1 의 판정이 이 두 값의 대소로 갈린다.

 2-3. 시간을 알린다. 시나리오당 50분이며 장애 유발 시각부터 센다.

 2-4. 금지 사항을 고지한다.
      · /home/oracle/backup/_proctor 는 손대지 않는다  (건드리면 자동 불합격)
      · 지시하지 않은 시나리오의 장애 스크립트를 미리 돌리지 않는다
      · 모범답안·인터넷 검색 허용 여부는 감독관이 정해 사전 고지한다

================================================================================
 3. 응시자 — 개인 PC 에서 하는 일
================================================================================
 3-0. 시작 전 준비

      · SSH 또는 콘솔로 자기 VM 에 접속한다.
      · 창을 두 개 연다. 하나는 SQL*Plus, 하나는 셸(alert log 감시용)이다.
        답안 작성에 alert log 인용이 반복해서 필요하다.

        [창 A]  $ sqlplus / as sysdba
        [창 B]  $ tail -f /u01/app/oracle/diag/rdbms/orcl/orcl/trace/alert_orcl.log

      · 출력을 파일로 남긴다. 답안 제출물이 된다.
        SYS@orcl> SPOOL /home/oracle/answer_s1.txt
        (시나리오가 끝나면 SPOOL OFF)

      · 화면 폭을 맞춘다.
        SYS@orcl> SET LINESIZE 200 PAGESIZE 100
        SYS@orcl> COL name FOR a50
        SYS@orcl> COL member FOR a46

 3-0b. 케이스는 하나씩 주입한다

      한 시나리오에 과제가 3~4개 있지만 한꺼번에 깨지지 않는다.
      장애 스크립트는 인자로 케이스를 지정한다.

        $ /home/oracle/exam/exam_break1.sh 1     ← 1-1 만 깨진다
          (진단 → 복구 → 검증 → 답안 작성)
        $ /home/oracle/exam/exam_break1.sh 2     ← 1-2 만 깨진다
          ...

      ★ 앞 케이스를 복구해야 다음 케이스를 주입할 수 있다.
        각 스크립트는 시작할 때 hr.exam_log 에 표식 행을 넣으므로
        데이터베이스가 READ WRITE 여야 한다.
        복구가 끝나지 않은 상태에서 실행하면 아래처럼 막고 종료한다.

          ==============================================================
           중단 : 데이터베이스가 READ WRITE 가 아니다 (현재: MOUNTED)

           앞 케이스의 복구가 끝나지 않았다.
             · 복구를 계속하려면 이 스크립트를 실행하지 말 것
             · 포기하고 다음 케이스로 넘어가려면 감독관이 아래를 실행한 뒤
               다시 이 스크립트를 실행한다
                 /home/oracle/exam/exam_reset.sh
          ==============================================================

        이 메시지가 나오면 장애는 주입되지 않은 것이다. 데이터베이스 상태는
        그대로이므로 복구를 이어서 해도 된다.

 3-1. 각 과제의 진행 순서 — 네 걸음을 반드시 지킨다

      ① 장애를 일으킨다
         $ /home/oracle/exam/exam_break1.sh 1
         화면에 나온 오류를 그대로 답안에 붙여 넣는다.

      ② 판정한다  ← 여기서 점수가 갈린다
         명령을 치기 전에 조회부터 한다. 무엇이 손상되었고, 백업본에 있고,
         필요한 리두가 살아 있고, 떼어 낼 수 있는가를 순서대로 확인한다.
         각 조회의 결과를 답안에 남기고 "그래서 어느 경로를 택했다" 를 한 줄 적는다.

      ③ 되돌릴 수 없는 명령 전에 사본을 확보한다
         $ mkdir -p /home/oracle/before_<과제번호>
         $ cp -p <건드릴 파일> /home/oracle/before_<과제번호>/
         이 기록이 없으면 감점한다.

      ④ 복구하고 검증한다
         복구 명령만 적고 끝내지 않는다. 무엇으로 복구를 확인했는지 적는다.
         hr.exam_log 의 행 수와 내용, v$recover_file 이 비었는지,
         v$database 의 open_mode 를 함께 남긴다.

 3-2. 막혔을 때

      · 오류가 나는 것은 감점 사유가 아니다. 오류와 그때의 판단을 적으면 된다.
      · 인스턴스가 죽어 ORA-03113 / ORA-01034 가 나오면 당황하지 말고
        STARTUP MOUNT 로 올려 MOUNT 상태에서 조회한다.
      · STARTUP 을 이미 한 뒤에 다시 STARTUP 하면 ORA-01081 이 난다.
        그때는 ALTER DATABASE MOUNT 를 쓴다.
      · 30분이 지나도 진전이 없으면 감독관에게 알린다. 감독관이
        exam_reset.sh 로 되돌려 주고, 그 시나리오는 부분 점수로 처리한다.

 3-3. 시나리오가 끝나면

      SYS@orcl> SPOOL OFF
      제출 파일 : /home/oracle/answer_s1.txt (시나리오별로 하나씩)

      감독관이 지시할 때까지 다음 시나리오의 장애 스크립트를 실행하지 않는다.

================================================================================
 4. 감독관 — 시나리오 사이
================================================================================
 4-1. 응시자 답안 파일을 수거한다.

 4-1b. 한 케이스에서 응시자가 복구에 실패했을 때

      그 케이스만 포기시키고 다음 케이스로 넘긴다. 시나리오 전체를 버리지 않는다.

        ① 응시자에게 그때까지의 판정·시도 기록을 답안에 남기게 한다
           (복구 실패 자체보다 판정을 했는지가 배점의 절반이다)
        ② 감독관이 되돌린다
           $ /home/oracle/exam/exam_reset.sh
        ③ 다음 케이스의 장애 스크립트를 실행하게 한다

      되돌리면 hr.exam_log 가 BASE 한 행으로 초기화된다. 각 케이스의 표식은
      그 케이스의 장애 스크립트가 다시 넣으므로 손실 판정에는 영향이 없다.

 4-2. 다음 시나리오를 위해 랩을 되돌린다. 응시자가 복구에 성공했든 실패했든
      항상 실행한다. 앞 시나리오의 잔재가 다음 판정을 오염시키기 때문이다.

      $ /home/oracle/exam/exam_reset.sh

      약 2~3분 걸린다. 마지막에 "복원 완료. 다음 시나리오를 시작할 수 있다." 가
      나와야 한다. 컨트롤파일까지 통째로 되돌리므로 별도 복구 명령이 필요 없다.

 4-3. 되돌아온 상태를 확인한다.
      · ORCL / READ WRITE / NOARCHIVELOG
      · 데이터파일 8개, TEMP 1개
      · 컨트롤파일 3개
      · 리두 3그룹
      · hr.exam_log 1행 (BASE 만)

 4-4. exam_reset.sh 로도 살아나지 않으면 1-4 의 VM 스냅숏으로 되돌린 뒤
      exam_prep.sh 부터 다시 시작한다.

================================================================================
 5. 감독관 — 시험 후
================================================================================
 5-1. 채점은 모범답안의 【판정】【수행】【검증】 세 축으로 한다.
      명령이 맞았는지보다 판정을 했는지를 먼저 본다.

 5-2. 특히 아래 세 가지를 본다.
      ① 복구를 시작하기 전에 판정했는가
      ② 지킬 수 있는 데이터를 스스로 버리지 않았는가
      ③ 잃은 것을 업무 언어로 보고할 수 있는가

      ②의 대표 사례가 과제 1-1 이다. 온라인 리두가 살아 있어 손실 없이 복구할 수
      있는데 전체 복원이나 OFFLINE DROP 으로 간 답안은 데이터베이스를 열었더라도
      크게 감점한다. 열었다는 사실만으로 점수를 주지 않는다.

 5-3. 정리
      $ /home/oracle/exam/exam_reset.sh
      $ rm -rf /home/oracle/backup/exam_nolog /home/oracle/backup/_proctor
      $ rm -rf /home/oracle/before_*
      백업 두 벌이 약 11GB 를 차지하므로 반드시 지운다.
      exam_prep.sh 가 만든 exam_tbs 테이블스페이스와 hr.exam_log,
      hr.exam_t2 도 필요 없으면 함께 정리한다.

      SYS@orcl> DROP TABLESPACE exam_tbs INCLUDING CONTENTS AND DATAFILES;
      SYS@orcl> DROP TABLE hr.exam_log PURGE;

================================================================================
 6. 시간 배분 (시나리오당 50분)
================================================================================
  0~5분    문제 읽기, 기준선 확인
  5~15분   장애 유발과 증상 관찰, 오류 기록
  15~25분  판정 (조회 중심). 여기서 서두르면 뒤가 전부 틀어진다
  25~40분  복구 수행
  40~48분  검증과 손실 산정
  48~50분  SPOOL OFF, 제출

  과제가 여러 개인 시나리오는 배점 비율로 시간을 나눈다.
  예: 시나리오 1 은 1-1(30점) 15분, 1-2(30점) 15분, 1-3(25점) 12분, 1-4(15점) 8분.
