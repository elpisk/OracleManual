================================================================================
 ■ ARCHIVELOG 복구 실기평가 — 운영 가이드
   감독관 진행 순서 · 응시자 개인 PC 작업 · 채점과 정리
================================================================================

--------------------------------------------------------------------------------
 0. 전제
--------------------------------------------------------------------------------
 응시자는 각자 자기 PC 의 VM 에서 자기 ORCL 을 깨고 복구한다.
 공용 데이터베이스 하나를 여럿이 쓰는 방식이 아니다. 장애를 실제로 일으키므로
 공용 환경에서는 성립하지 않는다.

 감독관은 준비물 배포와 시간 관리, 채점을 맡는다.
 응시자 PC 에 원격 접속할 필요는 없다. 제출물은 텍스트 파일로 받는다.

 배포 대상 6개 스크립트 (같은 디렉터리에 있어야 한다. 나머지가 exam_env.sh 를 읽는다)
   exam_env.sh     공통 (경로를 v$ 뷰에서 읽는다. 직접 실행하지 않는다)
   exam_prep.sh    준비 (기준선 · Hot Backup · 확인용 테이블 · 감독자 복원점)
   exam_reset.sh   복원 (감독자 복원점으로 되돌리기)
   exam_break1.sh  시나리오 1 장애 유발   인자 1|2|3
   exam_break2.sh  시나리오 2 장애 유발   인자 1|2|3
   exam_break3.sh  시나리오 3 장애 유발   인자 1|2|3

 스크립트는 경로를 고정하지 않는다. 데이터파일·컨트롤파일·리두·아카이브 위치를
 실행 시점의 v$datafile / v$controlfile / v$logfile / v$archive_dest 에서 읽으므로
 교안 기준 배치가 아닌 VM 에서도 동작한다. 문제지의 경로 표기만 다를 뿐이다.
 이 가이드는 SID sales, 백업 위치 /arch/exam, 데이터파일 /u03/oradata/SALES 인
 별도 랩에서 세 시나리오 전부를 실행해 검증했다.

 바꿀 수 있는 값 (환경변수로 준다. 보통은 건드리지 않는다)
   EXAM_SID    대상 SID                 기본 orcl
   EXAM_BASE   백업 보관 상위 디렉터리  기본 /home/oracle/backup
   EXAM_DIR    스크립트·기준선 디렉터리 기본 /home/oracle/exam
   예 : $ EXAM_BASE=/arch/exam /home/oracle/exam/exam_prep.sh

================================================================================
 1. 감독관 — 시험 전날
================================================================================
 1-1. 응시자 VM 이 아래 조건을 만족하는지 확인한다.

      [oracle@oel7v9 ~]$ sqlplus / as sysdba
      SYS@orcl> SELECT name, log_mode, open_mode FROM v$database;
      SYS@orcl> SELECT file#, name FROM v$datafile ORDER BY file#;
      SYS@orcl> SELECT name FROM v$controlfile;
      SYS@orcl> SELECT group#, member FROM v$logfile ORDER BY group#, member;
      SYS@orcl> SELECT dest_id, destination, status FROM v$archive_dest WHERE dest_id = 1;
      SYS@orcl> SHOW PARAMETER log_archive_format

      확인 항목
        · ORCL / READ WRITE / ARCHIVELOG
        · LOG_ARCHIVE_DEST_1 이 디렉터리(location=)이고 VALID 다. 아카이브 대상은 하나다
          (둘 이상이면 RECOVER 의 suggestion 이 번호가 큰 대상을 가리켜 화면이 어긋난다)
        · 데이터파일이 모두 같은 디렉터리에 있다 (exam_nobk, exam_new 를 그 디렉터리에 만든다)
        · 리두 그룹이 3개 이상이다 (과제 2-1 이 결손 시퀀스를 덮으려고 스위치를 돌린다)
        · $ORACLE_HOME 은 /u01/app/oracle/product/19.3.0/dbhome_1
        · hr 계정이 존재한다 (USERS 쿼터는 스크립트가 준다)
        · 8~12장 실습이 남긴 exam_* 이름의 테이블스페이스·테이블이 없다
          (있으면 exam_prep.sh 가 지운다. 지워도 되는 것인지 미리 확인한다)

 1-2. 아카이브 디렉터리를 정리한다. exam_prep.sh 는 아카이브 대상 1번의 파일을 전부
      감독자 복원점에 복사하므로, 실습으로 쌓인 아카이브가 많으면 시간과 공간을 낭비한다.
      최근 백업과 무관한 오래된 아카이브는 지운다.

      $ ls /home/oracle/arch1 | wc -l ; du -sh /home/oracle/arch1

 1-3. 디스크 여유를 본다. Hot Backup, Cold 복원점, Hot Backup 사본 — 데이터파일 총량의
      세 배가 필요하다. 교안 기준 랩(데이터파일 약 2GB)에서 약 6GB 다.

      $ df -h /home/oracle /u01 /u02

 1-4. 스크립트 6개를 각 응시자 VM 의 /home/oracle/exam/ 에 배포한다.
      (NOARCHIVELOG 평가의 스크립트가 같은 이름으로 남아 있다면 먼저 치운다)

      $ mkdir -p /home/oracle/exam
      $ cp exam_*.sh /home/oracle/exam/
      $ chmod +x /home/oracle/exam/*.sh
      $ chown -R oracle:dba /home/oracle/exam

 1-5. VM 스냅숏을 하나 떠 둔다. 응시자가 복구에 실패하고 exam_reset.sh 로도
      돌아오지 못하는 경우의 마지막 보루다. 정지 상태에서 뜬다.

 1-6. 문제지를 인쇄하거나 파일로 준비한다. 모범답안은 배포하지 않는다.

================================================================================
 2. 감독관 — 시험 당일, 각 시나리오 시작 전
================================================================================
 2-1. 응시자에게 준비 스크립트를 실행시킨다. 이것은 시험 시간에 포함하지 않는다.
      데이터파일 2GB 기준 3~5분, 디스크가 느리면 15분 이상 걸린다 (검증 랩에서 17분).

      $ /home/oracle/exam/exam_prep.sh

      정상 종료 시 마지막에 이렇게 나온다.
        준비 완료.
          응시자용 백업 : /home/oracle/backup/exam_arch
          감독자 복원점 : /home/oracle/backup/_proctor_arch   (되돌리려면 exam_reset.sh)
          기준선        : /home/oracle/exam/baseline.txt

      "중단:" 으로 끝나면 데이터베이스가 READ WRITE 가 아니거나 NOARCHIVELOG 이거나
      아카이브 대상 1번을 읽지 못한 것이다. 그 상태를 먼저 고친 뒤 다시 실행시킨다.
      이 스크립트는 중단될 때 백업을 건드리지 않으므로 반복 실행해도 안전하다.

 2-2. 기준선을 응시자가 직접 읽게 한다. 이후 모든 판정의 출발점이다.

      $ cat /home/oracle/exam/baseline.txt
      $ cat /home/oracle/backup/exam_arch/backup_info.txt

      특히 아래 값을 각자 종이에 적게 한다.
        · RESETLOGS_CHANGE#           인카네이션이 바뀌면 이 값이 바뀐다
        · LAST_ARCHIVED               지금까지의 마지막 아카이브 시퀀스
        · backup_info.txt 의 seq_begin/seq_end   Hot Backup 구간의 시퀀스
      시나리오 2 의 "어디까지 되살릴 수 있는가" 가 이 값들로 갈린다.

 2-3. 시간을 알린다. 시나리오당 60분이며 첫 장애 유발 시각부터 센다.
      장애 스크립트가 새 Hot Backup 을 받는 시간(2-2, 2-3, 3-2, 3-3 의 앞부분)은 시험 시간에서 뺀다.

 2-4. 금지 사항을 고지한다.
      · /home/oracle/backup/_proctor_arch 는 손대지 않는다  (건드리면 자동 불합격)
      · 지시하지 않은 시나리오의 장애 스크립트를 미리 돌리지 않는다
      · RMAN 을 쓰지 않는다 (이 평가는 사용자 관리 복구다)
      · 모범답안·인터넷 검색 허용 여부는 감독관이 정해 사전 고지한다

================================================================================
 3. 응시자 — 개인 PC 에서 하는 일
================================================================================
 3-0. 시작 전 준비

      · SSH 또는 콘솔로 자기 VM 에 접속한다.
      · 창을 두 개 연다. 하나는 SQL*Plus, 하나는 셸(alert log 감시·파일 복사용)이다.
        답안 작성에 alert log 인용이 반복해서 필요하다.

        [창 A]  $ sqlplus / as sysdba
        [창 B]  $ tail -f /u01/app/oracle/diag/rdbms/orcl/orcl/trace/alert_orcl.log

      · 출력을 파일로 남긴다. 답안 제출물이 된다.
        SYS@orcl> SPOOL /home/oracle/answer_s1.txt
        (시나리오가 끝나면 SPOOL OFF)

      · 화면 폭과 날짜 형식을 맞춘다. RECOVER 의 시각 표기와 UNTIL TIME 입력에 필요하다.
        SYS@orcl> SET LINESIZE 200 PAGESIZE 100
        SYS@orcl> COL name FOR a50
        SYS@orcl> COL member FOR a50
        SYS@orcl> ALTER SESSION SET NLS_DATE_FORMAT = 'YYYY-MM-DD HH24:MI:SS';

 3-0b. 케이스는 하나씩 주입한다

      한 시나리오에 과제가 3개 있지만 한꺼번에 깨지지 않는다.
      장애 스크립트는 인자로 케이스를 지정한다.

        $ /home/oracle/exam/exam_break1.sh 1     ← 1-1 만 깨진다
          (진단 → 복구 → 검증 → 답안 작성)
        $ /home/oracle/exam/exam_break1.sh 2     ← 1-2 만 깨진다
          ...

      ★ 앞 케이스를 복구해야 다음 케이스를 주입할 수 있다.
        각 스크립트는 시작할 때 hr.exam_log 에 표식 행을 넣으므로
        데이터베이스가 READ WRITE 여야 한다.
        복구가 끝나지 않은 상태에서 실행하면 아래처럼 막고 종료한다.

          ==============================================================
           중단 : 데이터베이스가 READ WRITE 가 아니다 (현재: MOUNTED)

           앞 케이스의 복구가 끝나지 않았다.
             · 복구를 계속하려면 이 스크립트를 실행하지 말 것
             · 포기하고 다음 케이스로 넘어가려면 감독관이 아래를 실행한 뒤
               다시 이 스크립트를 실행한다
                 /home/oracle/exam/exam_reset.sh
          ==============================================================

        이 메시지가 나오면 장애는 주입되지 않은 것이다. 데이터베이스 상태는
        그대로이므로 복구를 이어서 해도 된다.

      ★ 앞 케이스가 RESETLOGS 나 CLEAR UNARCHIVED 로 끝났다면, 다음 장애 스크립트는
        먼저 새 Hot Backup 을 받는다. 화면에 "새 Hot Backup 을 받는다" 또는
        "정기 Hot Backup" 이 표시되고 backup_info.txt 가 새로 써진다.
        그때부터 백업 디렉터리의 파일은 새 것이다. 이전 백업 시점을 전제로 판정하면 틀린다.

 3-1. 각 과제의 진행 순서 — 네 걸음을 반드시 지킨다

      ① 장애를 일으킨다
         $ /home/oracle/exam/exam_break1.sh 1
         화면에 나온 오류를 그대로 답안에 붙여 넣는다.

      ② 판정한다  ← 여기서 점수가 갈린다
         명령을 치기 전에 조회부터 한다. 무엇이 손상되었고, 백업본에 있고,
         필요한 리두가 아카이브와 온라인 리두에 이어져 있는가를 순서대로 확인한다.
         각 조회의 결과를 답안에 남기고 "그래서 어느 경로를 택했다" 를 한 줄 적는다.

      ③ 되돌릴 수 없는 명령 전에 사본을 확보한다
         $ mkdir -p /home/oracle/before_<과제번호>
         $ cp -p <건드릴 파일> /home/oracle/before_<과제번호>/
         RESETLOGS 나 CLEAR UNARCHIVED 앞에서는 컨트롤파일과 남은 리두 멤버를 복사한다.
         이 기록이 없으면 감점한다.

      ④ 복구하고 검증한다
         복구 명령만 적고 끝내지 않는다. 무엇으로 복구를 확인했는지 적는다.
         hr.exam_log 의 행 수와 내용(step, reg_time), v$recover_file 이 비었는지,
         v$database 의 open_mode 와 resetlogs_change# 를 함께 남긴다.

 3-2. 막혔을 때

      · 오류가 나는 것은 감점 사유가 아니다. 오류와 그때의 판단을 적으면 된다.
      · 인스턴스가 죽어 ORA-03113 / ORA-01034 가 나오면 당황하지 말고
        STARTUP MOUNT 로 올려 MOUNT 상태에서 조회한다. (과제 3-1 은 원래 그렇게 죽는다)
      · STARTUP 을 이미 한 뒤에 다시 STARTUP 하면 ORA-01081 이 난다.
        그때는 ALTER DATABASE MOUNT 를 쓴다.
      · RECOVER 프롬프트에서 제안된 파일이 없으면 ORA-00308 로 세션이 끝난다.
        RECOVER 를 다시 실행하면 실패한 시퀀스부터 다시 묻는다. 그때 다른 경로를
        입력하거나 CANCEL 한다. 엔터 연타는 없는 파일을 계속 찾는다.
      · 30분이 지나도 진전이 없으면 감독관에게 알린다. 감독관이
        exam_reset.sh 로 되돌려 주고, 그 시나리오는 부분 점수로 처리한다.

 3-3. 시나리오가 끝나면

      SYS@orcl> SPOOL OFF
      제출 파일 : /home/oracle/answer_s1.txt (시나리오별로 하나씩)

      감독관이 지시할 때까지 다음 시나리오의 장애 스크립트를 실행하지 않는다.

================================================================================
 4. 감독관 — 시나리오 사이
================================================================================
 4-1. 응시자 답안 파일을 수거한다.

 4-1b. 한 케이스에서 응시자가 복구에 실패했을 때

      그 케이스만 포기시키고 다음 케이스로 넘긴다. 시나리오 전체를 버리지 않는다.

        ① 응시자에게 그때까지의 판정·시도 기록을 답안에 남기게 한다
           (복구 실패 자체보다 판정을 했는지가 배점의 절반이다)
        ② 감독관이 되돌린다
           $ /home/oracle/exam/exam_reset.sh
        ③ 다음 케이스의 장애 스크립트를 실행하게 한다

      되돌리면 hr.exam_log 가 BASE·SAFE 두 행으로 초기화된다. 각 케이스의 표식은
      그 케이스의 장애 스크립트가 다시 넣으므로 손실 판정에는 영향이 없다.

 4-2. 다음 시나리오를 위해 랩을 되돌린다. 응시자가 복구에 성공했든 실패했든
      항상 실행한다. 앞 시나리오의 잔재(새 인카네이션, 끊긴 아카이브 사슬, 새 백업)가
      다음 판정을 오염시키기 때문이다. 시나리오 2 와 3 은 이전 시나리오의 백업으로는
      풀 수 없으므로 이 단계를 빼먹으면 시험이 성립하지 않는다.

      $ /home/oracle/exam/exam_reset.sh

      약 1~3분 걸린다. 마지막에 "복원 완료. 다음 시나리오를 시작할 수 있다." 가
      나와야 한다. 컨트롤파일까지 통째로 되돌리므로 별도 복구 명령이 필요 없다.
      되돌리는 것 : 데이터파일·TEMP·컨트롤파일·리두·spfile·패스워드 파일,
      아카이브 디렉터리(복원점 이후 것 삭제, 지워진 것 복원), 응시자용 백업(원래 Hot Backup 으로),
      과제가 만든 exam_nobk·exam_new 데이터파일.

 4-3. 되돌아온 상태를 확인한다. 스크립트 끝의 "=== 확인 ===" 출력으로 본다.
      · ORCL / READ WRITE / ARCHIVELOG / RESETLOGS_CHANGE# 가 기준선과 같다
      · 데이터파일 수가 기준선과 같다, TEMP 1개
      · 컨트롤파일 3개, 리두 3그룹, LAST_ARCHIVED 가 기준선과 같다
      · hr.exam_log 2행 (BASE, SAFE), hr.exam_orders 2000행

 4-4. exam_reset.sh 로도 살아나지 않으면 1-5 의 VM 스냅숏으로 되돌린 뒤
      exam_prep.sh 부터 다시 시작한다.

================================================================================
 5. 감독관 — 시험 후
================================================================================
 5-1. 채점은 모범답안의 【판정】【수행】【검증】 세 축으로 한다.
      명령이 맞았는지보다 판정을 했는지를 먼저 본다.

 5-2. 특히 아래 네 가지를 본다.
      ① 복구를 시작하기 전에 판정했는가 (리두가 이어지는지 조회로 확인했는가)
      ② 지킬 수 있는 데이터를 스스로 버리지 않았는가
      ③ 잃은 것을 업무 언어로 보고할 수 있는가
      ④ RESETLOGS / CLEAR UNARCHIVED 뒤에 "즉시 전체 백업" 을 적었는가

      ②의 대표 사례가 과제 1-1 과 1-3 이다. 아카이브와 온라인 리두로 완전 복구가 되는데
      불완전 복구나 OFFLINE DROP 으로 간 답안은 데이터베이스를 열었더라도 크게 감점한다.
      과제 2-2 에서 신고 시각보다 훨씬 앞으로 되돌려 정상 업무까지 버린 답안도 같다.
      열었다는 사실만으로 점수를 주지 않는다.

 5-3. 정리
      $ /home/oracle/exam/exam_reset.sh
      $ rm -rf /home/oracle/backup/exam_arch /home/oracle/backup/_proctor_arch
      $ rm -rf /home/oracle/before_*
      백업 세 벌이 약 6GB 를 차지하므로 반드시 지운다.
      exam_prep.sh 와 장애 스크립트가 만든 객체도 필요 없으면 함께 정리한다.

      SYS@orcl> DROP TABLESPACE exam_nobk INCLUDING CONTENTS AND DATAFILES;
      SYS@orcl> DROP TABLESPACE exam_new INCLUDING CONTENTS AND DATAFILES;
      SYS@orcl> DROP TABLE hr.exam_log PURGE;
      SYS@orcl> DROP TABLE hr.exam_orders PURGE;
      (exam_reset.sh 뒤에는 exam_nobk·exam_new 가 컨트롤파일에 없으므로 DROP 이 ORA-00959 로
       실패한다. 그때는 데이터파일이 이미 지워진 것이니 무시한다)

 6. 시간 배분 (시나리오당 60분)
================================================================================
  0~5분    문제 읽기, 기준선·backup_info.txt 확인
  5~15분   장애 유발과 증상 관찰, 오류 기록
  15~25분  판정 (조회 중심). 여기서 서두르면 뒤가 전부 틀어진다
  25~45분  복구 수행 (전체 복원은 복사 시간이 든다. 복사 중에 판정 기록을 정리한다)
  45~55분  검증과 손실 산정
  55~60분  SPOOL OFF, 제출

  과제가 여러 개인 시나리오는 배점 비율로 시간을 나눈다.
  예: 시나리오 1 은 1-1(25점) 15분, 1-2(30점) 18분, 1-3(45점) 27분.

 7. 자주 나오는 상황과 감독관 대응
================================================================================
 상황                                   대응
 ------------------------------------   --------------------------------------
 exam_prep.sh 가 "중단:" 으로 끝남       DB 를 READ WRITE / ARCHIVELOG 로 맞추고
                                        아카이브 대상 1번을 확인한 뒤 재실행
 exam_prep.sh 가 오래 걸림               데이터파일 복사가 두 번, 사본이 한 번이다.
                                        디스크가 느린 VM 은 15분 이상. 기다린다
 ORA-03113 으로 인스턴스가 죽음          정상이다 (3-1). STARTUP MOUNT 로 올려
                                        MOUNT 에서 진행하라고 안내
 ORA-01081                              STARTUP 을 두 번 한 것이다.
                                        ALTER DATABASE MOUNT 를 쓰라고 안내
 RECOVER 가 ORA-00308 로 끝남             정상이다. RECOVER 를 다시 실행하면 그 시퀀스부터
                                        다시 묻는다. 경로 입력 또는 CANCEL 안내
 RESETLOGS 가 ORA-01152 / ORA-01195       아카이브를 덜 적용했다. RECOVER 를 더 하라고 안내.
                                        exam_arch/arch 의 사본을 쓰게 한다 (2-3)
 RESETLOGS 뒤 ORA-00376 (파일 OFFLINE)   2-1 에서 OFFLINE 한 파일을 ONLINE 하지 않은 것.
                                        RECOVER DATAFILE n → ONLINE 안내 (모범답안 2-1.7)
 장애 스크립트가 "새 Hot Backup" 을 받음  정상이다. 앞 과제가 RESETLOGS/CLEAR UNARCHIVED 로
                                        끝났기 때문. 그 시간은 시험 시간에서 뺀다
 응시자가 _proctor_arch 를 건드림        자동 불합격 처리. 그 VM 은 스냅숏으로 복원
 응시자가 RMAN 으로 복구함               자동 불합격. 이 평가는 사용자 관리 복구다
 시간 내 복구 실패                       exam_reset.sh 로 되돌리고 부분 점수 처리.
                                        판정과 시도 기록에 점수를 준다
