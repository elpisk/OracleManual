[6] 확인 : 로그를 읽는다
--------------------------------------------------------------------------------
-- Processing object type 줄 : 어떤 종류의 객체를 처리했는지
-- . . exported 줄            : 실제 데이터가 담긴 테이블과 행 수
-- Master table 줄            : 작업 기록 테이블이 덤프에 기록됨
-- Dump file set 줄           : 만들어진 파일의 실제 경로
-- 마지막 Job 줄              : 성공 여부와 완료 시각, 소요 시간

[oracle@oel7v9 ~]$ grep '\. \. exported' /u03/dpdump/hr_full_exp.log \
>   | awk '{print $4, $(NF-1)}'

"HR"."EMPLOYEES" 107
"HR"."LOCATIONS" 23
"HR"."JOB_HISTORY" 10
"HR"."JOBS" 19
"HR"."DEPARTMENTS" 27
"HR"."COUNTRIES" 25
"HR"."REGIONS" 4

-- 줄 구조는 ". . exported <이름> <크기> KB <행수> rows" 이다.
-- 앞의 점 두 개가 각각 한 필드라 이름은 네 번째 필드($4)다.
-- 이 행 수가 이후 반입 검증의 기준이 된다.

[oracle@oel7v9 ~]$ ls -lh /u03/dpdump/hr_full.dmp

-rw-r-----. 1 oracle dba 708K May 21 10:06 /u03/dpdump/hr_full.dmp

-- 추정 448KB, 실제 파일 708KB. 추정은 테이블 데이터만 계산한 값이고
-- 덤프 파일에는 메타데이터(DDL)와 마스터 테이블이 함께 담긴다.
-- hr처럼 데이터가 작은 스키마는 파일 대부분이 메타데이터다.
-- 실제 내보낸 데이터는 . . exported 줄을 합친 59KB 남짓이다.

UDE-00011: parameter include is incompatible with parameter exclude

-- << 원인 파악 >>
-- INCLUDE와 EXCLUDE는 한 작업에서 동시에 지정할 수 없다.
-- 클라이언트(expdp)가 파라미터를 검사하는 단계에서 UDE-00011로 거부한다.
-- 접속은 됐지만 작업(Job)은 아예 만들어지지 않는다.
-- INCLUDE로 포함 목록을 정하면 나머지는 자동으로 제외된다.
-- 원하는 것이 "테이블만"이라면 INCLUDE 하나로 충분하다.

-- << 수정 >>

SYS@orcl> SELECT job_name, state FROM dba_datapump_jobs;

no rows selected

-- 모든 작업이 정상 종료되어 마스터 테이블이 남지 않았다.

-- 실무 포인트
-- 1) 마지막 Job 줄을 반드시 확인한다.
--    successfully completed 와 completed with N error(s) 는 다르다.
--    후자는 일부 객체가 빠졌다는 뜻이며 종료 코드만으로는 구분되지 않는다.
--
-- 2) 행 수가 찍히는 줄을 기록해 둔다.
--    반입 후 대조할 근거가 된다.
--    grep으로 뽑아 파일로 남기면 검증 절차를 자동화할 수 있다.
--
-- 3) ESTIMATE 방식에 따라 값이 크게 다르다.
--    BLOCKS는 할당 블록 기준이라 과대 추정된다.
--    STATISTICS는 정확하지만 통계가 오래되면 반대로 어긋난다.
--    두 방식 모두 테이블 데이터만 계산한다. 메타데이터 크기는 포함되지 않는다.
--
-- 4) INCLUDE와 EXCLUDE는 함께 쓸 수 없다.
--    지정하면 UDE-00011로 거부되고 작업 자체가 만들어지지 않는다.
--    INCLUDE=TABLE은 인덱스·제약·트리거 같은 종속 객체를 함께 가져온다.
--    특정 객체만 빼려면 EXCLUDE 하나로 쓴다.
--
-- 5) 따옴표가 들어가는 옵션은 PARFILE로 관리한다.
--    QUERY와 INCLUDE의 조건절이 대표적이다.
--    셸 이스케이프 문제가 사라지고 이력 관리도 쉬워진다.
--
-- 6) CONTENT=METADATA_ONLY 덤프를 형상 관리용으로 정기 생성해 두면 유용하다.
--    구조 변경 이력을 남기는 데 쓸 수 있다.
--    크기가 작아지는 정도는 데이터 양에 달렸다.
