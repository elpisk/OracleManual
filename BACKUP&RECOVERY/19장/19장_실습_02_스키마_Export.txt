--------------------------------------------------------------------------------
[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 특정 테이블만 골라 내보내면서 인덱스는 빼려고 한다.

[oracle@oel7v9r1 ~]$ expdp system/oracle_4U directory=dp_dir \
>   dumpfile=hr_sel.dmp logfile=hr_sel.log schemas=hr \
>   include=TABLE exclude=INDEX

ORA-39071: Value for EXCLUDE is badly formed.
ORA-39041: Filter "EXCLUDE" either identifies all object types or no object
types.

-- << 원인 파악 >>
-- INCLUDE와 EXCLUDE는 한 작업에서 동시에 지정할 수 없다.
-- INCLUDE로 포함 목록을 정하면 나머지는 자동으로 제외된다.
-- 두 지시가 충돌하므로 필터가 성립하지 않는다.
-- 원하는 것이 "테이블만"이라면 INCLUDE 하나로 충분하다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ expdp system/oracle_4U directory=dp_dir \
>   dumpfile=hr_sel.dmp logfile=hr_sel.log schemas=hr \
>   include=TABLE

Processing object type SCHEMA_EXPORT/TABLE/TABLE
. . exported "HR"."EMPLOYEES"                17.05 KB     107 rows
...
Job "SYSTEM"."SYS_EXPORT_SCHEMA_01" successfully completed at 10:11:20

-- 인덱스와 제약은 처리되지 않았다.

-- 조건을 가진 테이블 목록으로 좁혀 본다.

[oracle@oel7v9r1 ~]$ cat > /home/oracle/dp/sel.par << 'EOF'
directory=dp_dir
dumpfile=hr_two.dmp
logfile=hr_two.log
schemas=hr
include=TABLE:"IN ('EMPLOYEES','DEPARTMENTS')"
EOF

[oracle@oel7v9r1 ~]$ expdp system/oracle_4U parfile=/home/oracle/dp/sel.par

. . exported "HR"."EMPLOYEES"                17.05 KB     107 rows
. . exported "HR"."DEPARTMENTS"               7.12 KB      27 rows
Job "SYSTEM"."SYS_EXPORT_SCHEMA_01" successfully completed at 10:13:05

-- 따옴표가 들어가는 조건은 PARFILE에 넣는 편이 안전하다.
-- 셸에서 직접 쓰면 이스케이프 때문에 실수하기 쉽다.

SYS@orcl> SELECT job_name, state FROM dba_datapump_jobs;

no rows selected

-- 모든 작업이 정상 종료되어 마스터 테이블이 남지 않았다.

-- 실무 포인트
-- 1) 마지막 Job 줄을 반드시 확인한다.
--    successfully completed 와 completed with N error(s) 는 다르다.
--    후자는 일부 객체가 빠졌다는 뜻이며 종료 코드만으로는 구분되지 않는다.
--
-- 2) 행 수가 찍히는 줄을 기록해 둔다.
--    반입 후 대조할 근거가 된다.
--    grep으로 뽑아 파일로 남기면 검증 절차를 자동화할 수 있다.
--
-- 3) ESTIMATE 방식에 따라 값이 크게 다르다.
--    BLOCKS는 할당 블록 기준이라 과대 추정된다.
--    STATISTICS는 정확하지만 통계가 오래되면 반대로 어긋난다.
--    실제 크기는 압축 여부에 따라 또 달라진다.
--
-- 4) INCLUDE와 EXCLUDE는 함께 쓸 수 없다.
--    지정하면 ORA-39071로 거부된다.
--    포함 목록을 정하면 나머지는 자동 제외이므로 하나면 충분하다.
--
-- 5) 따옴표가 들어가는 옵션은 PARFILE로 관리한다.
--    QUERY와 INCLUDE의 조건절이 대표적이다.
--    셸 이스케이프 문제가 사라지고 이력 관리도 쉬워진다.
--
-- 6) CONTENT=METADATA_ONLY 덤프를 형상 관리용으로 정기 생성해 두면 유용하다.
--    크기가 작고 구조 변경 이력을 남기는 데 쓸 수 있다.
