[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 운영 hr 스키마를 개발용 hr_dev로 옮긴다.
-- 대상 환경은 테이블스페이스 이름이 다르고 공간도 넉넉하지 않다.
-- REMAP 계열로 이름을 바꾸고 TRANSFORM으로 저장 속성을 무시한다.
-- 반입 후 권한 누락을 확인하고 보완한다.
-- 작업 유형 : 스키마 이관

[7] 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- << 원인 파악 >>
-- 두 종류의 메시지가 섞여 있으므로 나누어 본다.
--
-- ORA-31684 : 사용자가 이미 있다는 뜻이다.
--   덤프에 CREATE USER 문이 담겨 있는데 대상에 이미 만들어 두었기 때문이다.
--   미리 만들어 둔 것이 의도한 바이므로 무시해도 되는 경고에 가깝다.
--
-- ORA-01950 : 테이블스페이스 할당량이 없다는 뜻이다.
--   DEV_DATA는 존재하지만 HR_DEV에게 QUOTA를 주지 않았다.
--   RESOURCE 롤에는 UNLIMITED TABLESPACE가 포함되지 않는다.
--   원본 HR은 UNLIMITED TABLESPACE 시스템 권한을 따로 가지고 있었다.

SYS@orcl> SELECT tablespace_name, max_bytes FROM dba_ts_quotas
  2  WHERE  username = 'HR_DEV';

no rows selected

SYS@orcl> SELECT COUNT(*) FROM dba_tables WHERE owner = 'HR_DEV';

  COUNT(*)
----------
         0

-- 테이블이 하나도 만들어지지 않았다.

-- << 수정 >> 할당량을 부여하고 다시 반입한다.

SYS@orcl> ALTER USER hr_dev QUOTA UNLIMITED ON dev_data;

User altered.

SYS@orcl> SELECT tablespace_name, max_bytes FROM dba_ts_quotas
  2  WHERE  username = 'HR_DEV';

TABLESPACE_NAME   MAX_BYTES
----------------- ---------
DEV_DATA                 -1

-- -1은 무제한을 뜻한다.

-- 실무 포인트
-- 1) 반입 전 SQLFILE로 DDL을 확인한다.
--    참조하는 테이블스페이스를 모두 알 수 있어 준비 누락을 막는다.
--    저장 절이 얼마나 큰지도 여기서 보인다.
--
-- 2) REMAP_TABLESPACE는 대상을 만들어 주지 않는다.
--    없으면 ORA-00959, 있어도 QUOTA가 없으면 ORA-01950이다.
--    두 오류는 다른 문제이므로 구분해서 대응한다.
--
-- 3) RESOURCE 롤에 UNLIMITED TABLESPACE는 포함되지 않는다.
--    11g 이후 분리되었으므로 QUOTA를 명시적으로 부여해야 한다.
--    오래된 절차서를 그대로 쓰면 이 지점에서 막힌다.
--
-- 4) TRANSFORM=SEGMENT_ATTRIBUTES:N 은 개발 환경 이관의 기본 옵션에 가깝다.
--    운영의 큰 저장 절이 따라오면 개발 서버 공간이 금방 바닥난다.
--    대상의 기본값을 쓰게 하면 실제 데이터 양에 맞게 잡힌다.
--
-- 5) 권한은 별도로 대조한다.
--    MINUS 연산으로 원본과 대상의 차이를 뽑으면 누락을 바로 찾는다.
--    dba_sys_privs, dba_role_privs, dba_tab_privs 세 가지를 모두 본다.
--
-- 6) ORA-31684는 대개 무시해도 되는 항목이다.
--    사용자를 미리 만들어 둔 경우에 나온다.
--    completed with N error(s) 를 볼 때 이런 항목을 걸러 낼 줄 알아야 한다.
