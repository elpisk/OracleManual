--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 운영 hr 스키마를 개발용 hr_dev로 옮긴다.
-- 대상 환경은 테이블스페이스 이름이 다르고 공간도 넉넉하지 않다.
-- REMAP 계열로 이름을 바꾸고 TRANSFORM으로 저장 속성을 무시한다.
-- 반입 후 권한 누락을 확인하고 보완한다.
-- 작업 유형 : 스키마 이관

-- new object type path: SCHEMA_EXPORT/TABLESPACE_QUOTA
DECLARE
  TEMP_COUNT NUMBER;
  SQLSTR VARCHAR2(200);
BEGIN
  SQLSTR := 'ALTER USER "HR_DEV" QUOTA UNLIMITED ON "DEV_DATA"';
  EXECUTE IMMEDIATE SQLSTR;

-- 스키마 모드 덤프는 CREATE USER 와 함께 시스템 권한 7개, 롤, 테이블스페이스 할당량까지 담는다.
-- REMAP_SCHEMA 는 이것들의 대상도 HR_DEV 로, REMAP_TABLESPACE 는 할당량의 대상도 DEV_DATA 로 바꾼다.
-- 그대로 반입하면 운영 계정의 권한이 통째로 개발 계정에 넘어간다.
-- 정책대로 SYSTEM_GRANT, ROLE_GRANT, TABLESPACE_QUOTA 세 경로를 EXCLUDE 하기로 한다.

-- << 원인 파악 >>
-- 87건이지만 종류는 넷이다. 근본 원인은 하나고 나머지는 연쇄다.
--
-- ORA-31684 : 사용자가 이미 있다는 뜻이다.
--   덤프에 CREATE USER 문이 담겨 있는데 대상에 이미 만들어 두었기 때문이다.
--   미리 만들어 둔 것이 의도한 바이므로 무시해도 되는 경고에 가깝다.
--
-- ORA-39083 + ORA-01950 : 테이블 7개가 모두 만들어지지 못했다(근본 원인).
--   DEV_DATA는 존재하지만 HR_DEV에게 QUOTA가 없다.
--   RESOURCE 롤에는 UNLIMITED TABLESPACE가 포함되지 않는다.
