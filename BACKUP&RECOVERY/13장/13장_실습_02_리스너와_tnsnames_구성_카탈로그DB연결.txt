-- 새로 만든 RCAT 은 이미 리스너에 보인다. 인스턴스의 PMON(LREG)이 기본 포트 1521 의
-- 리스너에 스스로 등록하는 동적 등록이다. status READY 가 그 표시다.
-- 동적 등록은 인스턴스가 내려가면 서비스도 사라진다. 그러면 원격에서
-- sqlplus sys@rcat as sysdba 로 접속해 STARTUP 할 수 없다.
-- 카탈로그처럼 항상 접속 가능해야 하는 대상은 정적 등록을 함께 둔다.

[oracle@oel7v9 ~]$ cat $ORACLE_HOME/network/admin/listener.ora
LISTENER =
  (DESCRIPTION_LIST =
    (DESCRIPTION =
      (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521))
      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )
  )

  )

-- 같은 인스턴스가 두 줄로 보인다. UNKNOWN 이 정적 등록, READY 가 동적 등록이다.
-- 정적 등록은 리스너가 인스턴스 상태를 확인하지 않고 설정만 믿으므로 UNKNOWN 이 정상이다.
-- 인스턴스를 내리면 READY 줄만 사라지고 UNKNOWN 줄은 남아 접속 경로가 유지된다.

ERROR:
ORA-12154: TNS:could not resolve the connect identifier specified


Enter user-name: ^D

-- << 원인 파악 >>
-- ORA-12154는 이름 해석 실패다. tnsnames.ora에 그 이름이 없다는 뜻이다.
-- 네트워크나 리스너 문제가 아니라 이름 문제다.
-- 리스너가 죽어 있으면 ORA-12541, 서비스가 없으면 ORA-12514가 나온다.
-- 세 오류를 구분하면 원인을 빠르게 좁힐 수 있다.
-- (접속 실패 뒤 사용자 이름을 다시 묻는 프롬프트는 Ctrl-D 로 빠져나온다.)

[oracle@oel7v9 ~]$ grep -n '^RCAT' $ORACLE_HOME/network/admin/tnsnames.ora
12:RCAT =

-- 등록된 이름은 RCAT이다.

-- 실무 포인트
-- 1) 인스턴스는 기본 포트의 리스너에 스스로 등록한다(동적 등록, READY).
--    그러나 인스턴스가 내려가면 서비스도 사라져 원격 STARTUP 경로가 없어진다.
--    카탈로그처럼 항상 접속 가능해야 하는 대상은 정적 등록(UNKNOWN)을 함께 둔다.
--
-- 2) 설정 파일은 수정 전에 사본을 남긴다.
--    listener.ora의 괄호 하나만 어긋나도 리스너가 기동되지 않는다.
--
-- 3) 접속 문제는 세 오류로 원인을 좁힌다.
--    ORA-12154는 이름 해석 실패, ORA-12541은 리스너 부재,
--    ORA-12514는 리스너는 있으나 그 서비스가 등록되지 않은 경우다.
--
-- 4) tnsping은 리스너까지만 확인한다.
--    인스턴스 상태는 알려 주지 않으므로 sqlplus 접속으로 최종 확인한다.
--
-- 5) sqlplus 접속을 먼저 확인한 뒤 RMAN을 시도한다.
--    sqlplus가 안 되면 RMAN도 안 되므로 원인을 좁히기 쉽다.
--
-- 6) 카탈로그 소유자에게는 RECOVERY_CATALOG_OWNER 롤만 준다.
--    DBA 롤을 주는 구성이 실무에서 자주 발견되지만 필요하지 않다.
--
-- 7) 카탈로그 DB 는 대상과 다른 인스턴스, 가능하면 다른 서버에 둔다.
--    실습은 한 서버에 두지만 대상 서버를 잃으면 카탈로그도 잃는 구성이다.
