 실습 13-2 : listener.ora / tnsnames.ora 구성과 카탈로그 DB 연결
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL + RCAT
 소요 시간 : 약 30분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 카탈로그용 인스턴스 RCAT에 접속할 수 있도록 네트워크를 구성한다.
-- 리스너가 두 SID를 모두 서비스하도록 정적 등록을 추가한다.
-- tnsnames.ora에 접속 이름을 만들고 tnsping과 sqlplus로 확인한다.
-- 카탈로그 소유자를 만들고 접속까지 확인한다.
-- 작업 유형 : 환경 구성(장애 복구 아님)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- 카탈로그용 인스턴스 RCAT이 생성되어 있어야 한다.
-- 리스너가 기동 중이어야 한다.

[oracle@oel7v9r1 ~]$ ps -ef | grep [p]mon

oracle    4188     1  0 08:52 ?        00:00:00 ora_pmon_rcat

--------------------------------------------------------------------------------
[3] 초기 상태 확인
--------------------------------------------------------------------------------
-- RCAT이 리스너에 등록되어 있지 않다.

[oracle@oel7v9r1 ~]$ lsnrctl status | grep -i rcat
[oracle@oel7v9r1 ~]$

-- 동적 등록이 되려면 LOCAL_LISTENER 설정과 인스턴스 기동 순서가 맞아야 한다.
-- 카탈로그처럼 항상 접속 가능해야 하는 대상은 정적 등록이 안전하다.

[oracle@oel7v9r1 ~]$ cat $ORACLE_HOME/network/admin/listener.ora
LISTENER =
  (DESCRIPTION_LIST =
    (DESCRIPTION =
      (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9r1)(PORT = 1521))
      (ADDRESS = (PROTOCOL = IPC)(KEY = EXTPROC1521))
    )
  )

--------------------------------------------------------------------------------
[4] 작업 수행 : 리스너 정적 등록
--------------------------------------------------------------------------------
[oracle@oel7v9r1 ~]$ cp -p $ORACLE_HOME/network/admin/listener.ora \
>   $ORACLE_HOME/network/admin/listener.ora.bak

-- 수정 전 사본을 남긴다.

[oracle@oel7v9r1 ~]$ vi $ORACLE_HOME/network/admin/listener.ora

-- 아래 내용을 추가한다.

SID_LIST_LISTENER =
  (SID_LIST =
    (SID_DESC =
      (GLOBAL_DBNAME = rcat)
      (ORACLE_HOME = /u01/app/oracle/product/19.3.0/dbhome_1)
      (SID_NAME = rcat)
    )
  )

[oracle@oel7v9r1 ~]$ lsnrctl reload

Connecting to (DESCRIPTION=(ADDRESS=(PROTOCOL=IPC)(KEY=EXTPROC1521)))
The command completed successfully

[oracle@oel7v9r1 ~]$ lsnrctl status | grep -A 1 'Service "rcat"'
Service "rcat" has 1 instance(s).
  Instance "rcat", status UNKNOWN, has 1 handler(s) for this service...

-- 정적 등록은 status가 UNKNOWN으로 표시된다. 정상이다.
-- 리스너가 인스턴스 상태를 직접 확인하지 않고 설정만 믿기 때문이다.

--------------------------------------------------------------------------------
[5] 진행 로그 : tnsnames.ora 구성
--------------------------------------------------------------------------------
[oracle@oel7v9r1 ~]$ vi $ORACLE_HOME/network/admin/tnsnames.ora

RCAT =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9r1)(PORT = 1521))
    (CONNECT_DATA =
      (SERVER = DEDICATED)
      (SERVICE_NAME = rcat)
    )
  )

[oracle@oel7v9r1 ~]$ tnsping rcat

TNS Ping Utility for Linux: Version 19.0.0.0.0 - Production

Used parameter files:

Attempting to contact (DESCRIPTION = (ADDRESS = (PROTOCOL = TCP)
(HOST = oel7v9r1)(PORT = 1521)) (CONNECT_DATA = (SERVER = DEDICATED)

-- 이름 해석과 리스너 도달까지 확인되었다.
-- tnsping은 리스너까지만 확인한다. 인스턴스 상태는 알려 주지 않는다.

--------------------------------------------------------------------------------
[7] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 접속 이름을 잘못 입력해 본다.

[oracle@oel7v9r1 ~]$ sqlplus rcatowner/oracle_4U@rcatalog

SQL*Plus: Release 19.0.0.0.0 - Production

ERROR:
ORA-12154: TNS:could not resolve the connect identifier specified

-- << 원인 파악 >>
-- ORA-12154는 이름 해석 실패다. tnsnames.ora에 그 이름이 없다는 뜻이다.
-- 네트워크나 리스너 문제가 아니라 이름 문제다.
-- 리스너가 죽어 있으면 ORA-12541, 서비스가 없으면 ORA-12514가 나온다.
-- 세 오류를 구분하면 원인을 빠르게 좁힐 수 있다.

[oracle@oel7v9r1 ~]$ grep -n '^RCAT' $ORACLE_HOME/network/admin/tnsnames.ora
12:RCAT =

-- 등록된 이름은 RCAT이다.

-- << 수정 >>

[oracle@oel7v9r1 ~]$ sqlplus rcatowner/oracle_4U@rcat

SQL*Plus: Release 19.0.0.0.0 - Production
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

RCATOWNER@rcat> SELECT USER FROM dual;

USER
------------------------------
RCATOWNER

RCATOWNER@rcat> SELECT default_tablespace FROM user_users;

DEFAULT_TABLESPACE
------------------------------
RCAT_TS

RCATOWNER@rcat> EXIT

RMAN> EXIT

-- 실무 포인트
-- 1) 카탈로그처럼 항상 접속 가능해야 하는 대상은 정적 등록이 안전하다.
--    동적 등록은 인스턴스가 내려가면 서비스도 사라진다.
--    정적 등록의 status가 UNKNOWN으로 표시되는 것은 정상이다.
--
-- 2) 설정 파일은 수정 전에 사본을 남긴다.
--    listener.ora의 괄호 하나만 어긋나도 리스너가 기동되지 않는다.
--
-- 3) 접속 문제는 세 오류로 원인을 좁힌다.
--    ORA-12154는 이름 해석 실패, ORA-12541은 리스너 부재,
--    ORA-12514는 리스너는 있으나 그 서비스가 등록되지 않은 경우다.
--
-- 4) tnsping은 리스너까지만 확인한다.
--    인스턴스 상태는 알려 주지 않으므로 sqlplus 접속으로 최종 확인한다.
--
-- 5) sqlplus 접속을 먼저 확인한 뒤 RMAN을 시도한다.
--    sqlplus가 안 되면 RMAN도 안 되므로 원인을 좁히기 쉽다.
--
-- 6) 카탈로그 소유자에게는 RECOVERY_CATALOG_OWNER 롤만 준다.
--    DBA 롤을 주는 구성이 실무에서 자주 발견되지만 필요하지 않다.
