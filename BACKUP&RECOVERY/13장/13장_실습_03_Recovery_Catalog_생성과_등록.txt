[4] 작업 수행 : 카탈로그 생성
--------------------------------------------------------------------------------
-- 먼저 대상에 접속한 상태로 CREATE CATALOG를 시도해 본다.

[oracle@oel7v9 ~]$ rman target /

RMAN> CREATE CATALOG;

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-06002: command not allowed when not connected to a recovery catalog

-- << 원인 파악 >>
-- 카탈로그에 접속하지 않은 상태다. nocatalog 모드에서는 만들 대상이 없다.
-- CREATE CATALOG는 카탈로그 접속 상태에서 수행해야 한다.
-- 대상 접속 여부는 관계없다.

RMAN> EXIT

-- << 수정 >>

[oracle@oel7v9 ~]$ rman catalog rcatowner@rcat

recovery catalog database Password:
connected to recovery catalog database

RMAN> CREATE CATALOG;

recovery catalog created

RMAN> EXIT

  2  FROM   user_segments;

-- 대상 수와 백업 빈도에 비례해 늘어나므로 주기적으로 확인한다.

RCATOWNER@rcat> EXIT

-- 실무 포인트
-- 1) CREATE CATALOG는 카탈로그 접속 상태에서 수행한다.
--    대상만 접속한 상태에서는 RMAN-06002가 나온다.
--    REGISTER DATABASE는 대상과 카탈로그에 모두 접속한 상태여야 한다.
--
-- 2) 등록 시 컨트롤파일의 기존 메타데이터가 카탈로그로 복사된다.
--    등록 전에 받은 백업 정보와 인카네이션 이력이 함께 들어온다.
--    다만 기록 수명이 지나 이미 사라진 정보는 들어오지 않는다.
--
-- 3) 이미 등록된 대상을 다시 등록하면 RMAN-20002가 나온다.
--    DBID를 기준으로 판단하므로 중복 등록은 일어나지 않는다.
--    다만 그 세션은 RMAN-20020 으로 더 진행되지 않으므로 다시 접속한다.
--
-- 4) RC_ 뷰로 카탈로그 내용을 직접 조회할 수 있다.
--    LIST 명령이 조회하는 원본이 이 뷰들이며 SQL로 보고서를 만들 때 쓴다.
--    카탈로그 접속에서 LIST 가 보여 주는 Key 는 컨트롤파일 RECID 가 아니라 카탈로그 키다.
--
-- 5) 카탈로그 버전은 rcver 테이블로 확인한다.
--    대상을 상위 버전으로 올리면 UPGRADE CATALOG가 필요할 수 있다.
--
-- 6) 카탈로그 데이터베이스 자체를 백업 대상에 포함한다.
--    이 데이터베이스를 잃으면 모든 대상의 백업 이력을 함께 잃는다.
--    다만 컨트롤파일 기록이 남아 있어 복구 자체는 nocatalog로 가능하다.
