 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL + RCAT / ARCHIVELOG

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 운영 표준에 맞춰 RMAN 영구 설정을 적용한다.
-- 자동 백업 위치, 보존 정책, 채널 FORMAT, 병렬도를 설정한다.
-- 설정 전후를 SHOW ALL로 비교한다.
-- CLEAR로 되돌리는 절차와 설정을 파일로 남기는 방법을 확인한다.
-- 작업 유형 : 환경 구성(장애 복구 아님)

[4] 작업 수행 : 설정 적용

[oracle@oel7v9 ~]$ rman target / catalog rcatowner@rcat

CONFIGURE CONTROLFILE AUTOBACKUP ON;
new RMAN configuration parameters are successfully stored
starting full resync of recovery catalog
full resync complete

-- 19c 의 기본값과 같은 값이지만 명시하면 # default 가 떨어지고 v$rman_configuration 에
-- 기록된다. 운영 표준을 파일로 남길 때 "기본값에 기댄 항목" 이 없도록 하는 뜻이다.

-- 실무 포인트
-- 1) CONFIGURE 설정은 컨트롤파일과 카탈로그에 저장되어 접속을 넘어 유지된다.
--    RUN 블록 안의 설정은 블록이 끝나면 사라진다. 둘을 혼동하지 않는다.
--
-- 2) 자동 백업은 켜 두고(19c 기본 ON) FORMAT에 %F 를 포함한 위치를 지정한다.
--    파일명에 DBID가 들어가야 컨트롤파일을 모두 잃어도 찾을 수 있다.
--    백업이 끝나면 자동 백업이 이어서 수행되는 것을 로그로 확인할 수 있다.
--
-- 3) 기록 수명은 보존 정책보다 크게 잡는다.
--    보존 7일에 기록 수명 31일이면 여유가 충분하다.
--    반대로 되어 있으면 삭제 대상을 찾지 못해 백업 파일만 쌓인다.
--
-- 4) 설정 값은 저장 시 검증되지 않는다.
--    없는 경로를 지정해도 그대로 저장되며 백업 시점에 실패한다.
--    설정 후 반드시 시험 백업으로 확인한다.
--
-- 5) ORA-01580(스냅샷 생성 실패)은 자동 백업 단계에서 난다.
--    데이터파일 백업은 이미 끝난 뒤라 성공한 것처럼 보이기 쉽다. 로그 끝까지 읽는다.
--    RAC에서는 이 경로가 공유 위치여야 한다.
--
-- 6) SHOW ALL 출력을 파일로 저장해 형상 관리에 포함한다.
--    컨트롤파일 재생성 후 같은 설정을 다시 넣어야 스크립트가 그대로 동작한다.
