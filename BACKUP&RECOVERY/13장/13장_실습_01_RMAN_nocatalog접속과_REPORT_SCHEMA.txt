================================================================================
 실습 13-1 : RMAN nocatalog 접속과 REPORT SCHEMA 확인
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG
 소요 시간 : 약 20분
================================================================================

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- RMAN에 처음 접속해 환경을 파악한다.
-- 별도 설정 없이 접속하면 컨트롤파일이 리포지터리가 된다.
-- 접속 시 표시되는 DBID와 SHOW ALL의 첫 줄을 확인한다.
-- REPORT SCHEMA로 대상의 구조를 확인한다.
-- 작업 유형 : 환경 파악(장애 복구 아님)

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- ORCL 인스턴스가 OPEN 상태여야 한다.
-- 환경 변수가 설정되어 있어야 한다.

[oracle@oel7v9r1 ~]$ echo $ORACLE_SID
orcl
[oracle@oel7v9r1 ~]$ echo $ORACLE_HOME
/u01/app/oracle/product/19.3.0/dbhome_1

[oracle@oel7v9r1 ~]$ sqlplus -s / as sysdba <<< "SELECT status FROM v\$instance;"

STATUS
------------
OPEN

[4] 작업 수행 : RMAN 접속
--------------------------------------------------------------------------------
-- 먼저 접속을 잘못 시도해 본다.

[oracle@oel7v9r1 ~]$ rman target sys/wrongpw@orcl

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-04005: error from target database:
ORA-01017: invalid username/password; logon denied

-- << 원인 파악 >>
-- 비밀번호가 틀렸다. RMAN 오류 스택의 맨 아래에 실제 원인이 나온다.
-- RMAN-04005는 대상 데이터베이스에서 온 오류라는 뜻이며
-- 그 아래 ORA- 오류가 실제 원인이다. 항상 아래부터 읽는다.

-- << 수정 >> OS 인증으로 접속한다.

[oracle@oel7v9r1 ~]$ rman target /

[7] 진행 로그 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
-- 명령 하나를 잘못 입력해 본다.

RMAN> REPORT SCHEME;

RMAN-00571: ===========================================================
RMAN-00569: =============== ERROR MESSAGE STACK FOLLOWS ===============
RMAN-00571: ===========================================================
RMAN-00558: error encountered while parsing input commands
RMAN-01009: syntax error: found "identifier": expecting one of:
"need, obsolete, schema, unrecoverable"
RMAN-01008: the bad identifier was: SCHEME

-- << 원인 파악 >>
-- RMAN-01009는 구문 오류이며 기대하는 키워드 목록을 함께 보여 준다.
-- RMAN-01008이 잘못 입력한 식별자를 지목한다.
-- REPORT 뒤에 올 수 있는 키워드는 need, obsolete, schema, unrecoverable 넷이다.

-- << 수정 >>

RMAN> REPORT NEED BACKUP;

[8] 검증 및 실무 포인트
--------------------------------------------------------------------------------
RMAN> EXIT

Recovery Manager complete.

-- v$ 뷰로 같은 내용을 확인해 본다.

[oracle@oel7v9r1 ~]$ sqlplus / as sysdba

SYS@orcl> SELECT dbid, name, log_mode FROM v$database;

      DBID NAME      LOG_MODE
---------- --------- ------------
1200530011 ORCL      ARCHIVELOG

-- RMAN 접속 시 표시된 DBID와 같다.

SYS@orcl> SELECT COUNT(*) FROM v$backup_piece;

  COUNT(*)
----------
         0

SYS@orcl> SELECT * FROM v$rman_configuration;

no rows selected

-- 아직 명시적으로 바꾼 설정이 없어 비어 있다.
-- SHOW ALL에서 # default 로 표시되던 항목들은 이 뷰에 나오지 않는다.

SYS@orcl> SHOW PARAMETER control_file_record_keep_time

NAME                            TYPE        VALUE
------------------------------- ----------- -----
control_file_record_keep_time   integer     7

-- 백업 기록이 7일간 유지된다. 보존 정책을 정할 때 함께 고려한다.

-- 실무 포인트
-- 1) 접속 시 표시되는 DBID를 반드시 기록한다.
--    컨트롤파일과 spfile을 모두 잃으면 이 값이 복구의 출발점이 된다.
--    백업 매니페스트에 DBID를 넣는 이유가 여기에 있다.
--
-- 2) SHOW ALL 첫 줄로 리포지터리 종류를 확인한다.
--    'using target database control file instead of recovery catalog' 가
--    nocatalog 모드를 뜻한다. 카탈로그를 쓰기로 해 놓고 nocatalog로
--    동작하는 환경이 실무에서 발견되므로 인수인계 시 반드시 확인한다.
--
-- 3) RMAN 오류 스택은 아래부터 읽는다.
--    RMAN- 번호는 어느 단계에서 실패했는지를 알려 주고
--    맨 아래의 ORA- 오류가 실제 원인이다.
--
-- 4) RMAN-01009 구문 오류는 기대하는 키워드 목록을 함께 보여 준다.
--    명령을 외우지 않아도 이 목록으로 확인할 수 있다.
--
-- 5) REPORT SCHEMA에 임시 파일이 표시되지만 백업 대상은 아니다.
--    복구 후 자동으로 다시 만들어지므로 ADD TEMPFILE 단계가 사라진다.
--
-- 6) 자동 백업이 기본 OFF라는 점을 확인했다.
--    운영 환경에서 끄고 쓸 이유가 없으므로 실습 13-4에서 켠다.
