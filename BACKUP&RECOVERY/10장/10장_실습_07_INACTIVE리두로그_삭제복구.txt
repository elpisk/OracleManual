 실습 10-7 : INACTIVE 리두 로그 삭제 — 정상 종료 후와 운영 중
 과정      : Oracle Database 19c Backup & Recovery
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / ARCHIVELOG

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- INACTIVE 리두 로그 그룹이 전손된 두 경우를 비교한다.
--   정상 종료 후 유실 → 아카이브 완료 상태, CLEAR로 손실 없이 처리
--   운영 중 유실, 아카이브 미완료 → ORA-00350, 원인 확인이 먼저
-- ARCHIVED 컬럼 확인이 판단의 출발점임을 확인한다.
-- 복구 유형 : 복구 불필요(CLEAR) 또는 리두 구간 손실

SYS@orcl> SELECT group#, sequence#, archived, status FROM v$log ORDER BY group#;

    GROUP#  SEQUENCE# ARC STATUS
---------- ---------- --- ----------------
         1          3 YES INACTIVE
         3          4 YES CURRENT
         4          2 YES INACTIVE

-- 그룹 4는 INACTIVE이고 ARCHIVED가 YES다.
-- 그 내용이 아카이브에 남아 있으므로 CLEAR 해도 잃을 것이 없다.

SYS@orcl> SELECT sequence#, name FROM v$archived_log WHERE sequence# = 2;

---------- ----------------------------------------
         2 /u02/arch1/1_2_1200562204.dbf

SYS@orcl> ALTER DATABASE CLEAR LOGFILE GROUP 4;

Database altered.

SYS@orcl> SELECT group#, sequence#, status FROM v$log WHERE group# = 4;

    GROUP#  SEQUENCE# STATUS
---------- ---------- ----------------

/u01/app/oracle/oradata/ORCL/redo04.log

--------------------------------------------------------------------------------
[7] 복구 절차 : 오류 발생 → 원인 파악 → 수정
--------------------------------------------------------------------------------
SYS@orcl> ALTER DATABASE CLEAR LOGFILE GROUP 3;
ALTER DATABASE CLEAR LOGFILE GROUP 3
*
ERROR at line 1:
ORA-00350: log 3 of instance orcl (thread 1) needs to be archived
ORA-00312: online log 3 thread 1: '/u01/app/oracle/oradata/ORCL/redo03.log'

-- << 원인 파악 >>
-- ARCHIVED가 NO이므로 그 내용이 아카이브에 남아 있지 않다.
-- 여기서 습관적으로 UNARCHIVED를 붙이면 그 구간의 리두를 버리게 된다.
-- 먼저 NO인 이유를 확인해야 한다.
-- 파일이 없어서인지, 아카이브 대상에 문제가 있어서인지 구분해야 한다.

SYS@orcl> SELECT dest_id, destination, status, error FROM v$archive_dest
  2  WHERE  destination IS NOT NULL;

   DEST_ID DESTINATION      STATUS  ERROR
---------- ---------------- ------- --------------------------------
         1 /u02/arch1       ERROR   ORA-19504: failed to create file

SYS@orcl> !ls -ld /u02/arch1
dr-x------. 2 oracle oinstall 4096 May 12 15:02 /u02/arch1

-- 대상 디렉터리에 쓸 수 없다. 이것이 아카이브가 밀린 원인이다.
-- 그룹 4와 1은 파일이 멀쩡하므로 대상을 고치면 아카이브할 수 있다.
-- 그룹 3은 파일이 이미 없어 아카이브할 원본이 없다.

-- << 수정 >>
-- 먼저 대상을 고치고 밀린 아카이브를 처리한다.

SYS@orcl> !chmod 700 /u02/arch1

SYS@orcl> ALTER SYSTEM ARCHIVE LOG ALL;
ALTER SYSTEM ARCHIVE LOG ALL
*
ERROR at line 1:
ORA-16038: log 3 sequence# 4 cannot be archived
ORA-00312: online log 3 thread 1: '/u01/app/oracle/oradata/ORCL/redo03.log'

-- 그룹 3은 파일이 없어 아카이브할 수 없다. 나머지는 처리되었다.

SYS@orcl> SELECT group#, sequence#, archived, status FROM v$log ORDER BY group#;

    GROUP#  SEQUENCE# ARC STATUS
---------- ---------- --- ----------------
         1          6 YES CURRENT
         3          4 NO  INACTIVE
         4          5 YES INACTIVE

-- 그룹 3만 NO로 남았다. 이 경우에만 UNARCHIVED가 정당하다.

SYS@orcl> ALTER DATABASE CLEAR UNARCHIVED LOGFILE GROUP 3;

Database altered.

SYS@orcl> SELECT group#, sequence#, archived, status FROM v$log ORDER BY group#;

    GROUP#  SEQUENCE# ARC STATUS
---------- ---------- --- ----------------
         1          6 YES CURRENT
         3          0 YES UNUSED
         4          5 YES INACTIVE

SYS@orcl> SELECT MIN(sequence#), MAX(sequence#), COUNT(*),
  2         MAX(sequence#) - MIN(sequence#) + 1 AS expected
  3  FROM   v$archived_log WHERE status = 'A';

-------------- -------------- ---------- ----------
             1              6          5          6

-- 시퀀스 4가 빠졌다. 버린 구간이다.
-- 이 시점 이전의 백업본은 사실상 무효가 되었다.

SYS@orcl> ALTER SYSTEM SWITCH LOGFILE;
SYS@orcl> ALTER SYSTEM SWITCH LOGFILE;
SYS@orcl> SELECT group#, sequence#, status FROM v$log ORDER BY group#;

    GROUP#  SEQUENCE# STATUS
---------- ---------- ----------------
         1          6 INACTIVE
         3          8 CURRENT
         4          7 INACTIVE

-- 그룹 3이 순환에 복귀했다.

-- 버린 구간이 있으므로 즉시 전체 백업을 받는다.

SYS@orcl> SHUTDOWN IMMEDIATE
SYS@orcl> !rm -rf /home/oracle/backup/ch10 && mkdir -p /home/oracle/backup/ch10
SYS@orcl> !cp -p /u02/oradata/ORCL/*.dbf /home/oracle/backup/ch10/
SYS@orcl> !rm -f /home/oracle/backup/ch10/temp01.dbf
SYS@orcl> STARTUP

-- 실무 포인트
-- 1) 판단의 출발점은 v$log의 ARCHIVED 컬럼이다.
--    YES이면 CLEAR LOGFILE 로 손실 없이 처리된다.
--    NO이면 UNARCHIVED가 필요하며 그 구간의 리두를 잃는다.
--
-- 2) ARCHIVED가 NO인 이유를 먼저 확인한다.
--    아카이브 대상 문제로 밀린 것이라면 대상을 고치고 처리하면 손실이 없다.
--    파일이 이미 없어 아카이브할 수 없는 경우에만 UNARCHIVED를 쓴다.
--
-- 3) 이 실습에서 대상을 고친 뒤 세 그룹 중 두 그룹이 아카이브되었다.
--    확인 없이 세 그룹 모두 UNARCHIVED로 처리했다면 불필요한 손실이 생겼을 것이다.
--
-- 4) ORA-00350과 ORA-01624를 구분한다.
--    전자는 아카이브가 완료되지 않았다는 뜻이고,
--    후자는 인스턴스 복구에 필요한 그룹이라는 뜻이다.
--
-- 5) UNARCHIVED로 비운 뒤에는 시퀀스가 빠진다.
--    연속성 점검에서 개수와 기대값이 달라지며 그 이전 백업본이 무효가 된다.
--    즉시 전체 백업을 받아야 한다.
--
-- 6) 커밋된 데이터는 사라지지 않는다.
--    이 실습에서 3번 행이 그대로 남아 있다.
--    리두를 버리는 것은 미래의 복구 수단을 잃는 것이지 현재 데이터를 잃는 것이 아니다.

SYS@orcl> EXIT
