 파티셔닝 실습 03 : INTERVAL 파티션 — 파티션을 자동으로 만든다
 과정      : Oracle Database 19c 파티셔닝 실습
 환경      : Oracle 19.3.0 / Oracle Linux 7 / non-CDB ORCL / AL32UTF8 / 8K 블록
 계정      : SYS (대상 스키마 HR)
 소요 시간 : 약 45분

--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- RANGE 파티션의 가장 큰 운영 부담은 "미래 파티션을 누가 만들어 주는가" 다.
-- 안 만들어 두면 ORA-14400 으로 배치가 죽고, MAXVALUE 를 두면 그 하나가 계속 커진다.
-- INTERVAL 파티션(11g 도입)은 값이 들어올 때 파티션을 자동으로 만든다.
--
-- 목표
--   (1) RANGE 테이블을 INTERVAL 로 바꾸려다 실패하는 이유를 본다 (MAXVALUE 와 공존 불가)
--   (2) INTERVAL 파티션을 만들고 자동 생성되는 SYS_P 파티션을 관찰한다
--   (3) partition_count 가 1048575 로 보이는 이유를 이해한다
--   (4) 자동 생성된 이름을 의미 있는 이름으로 바꾼다 (RENAME PARTITION FOR)
--   (5) INTERVAL 을 해제하면 어떻게 되는지 확인한다
-- 작업 유형 : 구조 변경

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- · 실습 02 의 hr.emp_yr 이 RANGE 4파티션(p2004/p2005/p2006/pmax) 으로 있다
-- · NLS_DATE_FORMAT 이 YYYY-MM-DD HH24:MI:SS 로 설정돼 있다
--   (아니면 TO_DATE 결과 표시가 달라 보인다)
-- · INTERVAL 파티션은 숫자·날짜 등 산술이 가능한 단일 키에만 쓸 수 있다

[3] 초기 상태 확인 — 간격을 만드는 함수
--------------------------------------------------------------------------------
-- INTERVAL 절에는 "간격" 을 나타내는 식을 쓴다. 날짜라면 다음 두 함수다.
--   NUMTOYMINTERVAL(n,'YEAR'|'MONTH')   연·월 간격
--   NUMTODSINTERVAL(n,'DAY'|'HOUR'|...) 일·시 간격
-- 숫자 키라면 그냥 상수를 쓴다 : INTERVAL (10000)

SYS@orcl> COL d FORMAT a20
SYS@orcl> SELECT TO_CHAR(DATE '2026-01-01' + NUMTOYMINTERVAL(1,'year'),'YYYY-MM-DD') AS plus_1y,
  2         TO_CHAR(DATE '2026-01-01' + NUMTOYMINTERVAL(1,'month'),'YYYY-MM-DD') AS plus_1m,
  3         TO_CHAR(DATE '2026-01-01' + NUMTODSINTERVAL(7,'day'),'YYYY-MM-DD') AS plus_7d
  4  FROM   dual;

PLUS_1Y    PLUS_1M    PLUS_7D
---------- ---------- ----------
2027-01-01 2026-02-01 2026-01-08

[4] 작업 수행 — 기존 테이블을 바꿔 보고, 새로 만든다
--------------------------------------------------------------------------------
-- 먼저 실습 02 의 테이블을 그대로 INTERVAL 로 바꿔 본다.

SYS@orcl> ALTER TABLE hr.emp_yr SET INTERVAL (NUMTOYMINTERVAL(1,'year'));
ALTER TABLE hr.emp_yr SET INTERVAL (NUMTOYMINTERVAL(1,'year'))
*
ERROR at line 1:
ORA-14759: SET INTERVAL is not legal on this table.

-- ORA-14759: SET INTERVAL is not legal on this table.
--   원인은 pmax(MAXVALUE) 파티션이다.
--   INTERVAL 은 "마지막 파티션 뒤로 간격을 이어 붙이는" 방식이므로
--   끝이 MAXVALUE 로 막혀 있으면 이어 붙일 자리가 없다.
--   바꾸려면 먼저 MAXVALUE 파티션을 DROP 하거나 SPLIT 해야 한다.

-- 그래서 새로 만든다. MAXVALUE 파티션을 두지 않는다.

SYS@orcl> DROP TABLE hr.emp_yr PURGE;

Table dropped.

SYS@orcl> CREATE TABLE hr.emp_yr
  2  PARTITION BY RANGE (hire_date) INTERVAL (NUMTOYMINTERVAL(1,'year'))
  3  (PARTITION p2004 VALUES LESS THAN (TO_DATE('2005-01-01','YYYY-MM-DD')),
  4   PARTITION p2005 VALUES LESS THAN (TO_DATE('2006-01-01','YYYY-MM-DD')),
  5   PARTITION p2006 VALUES LESS THAN (TO_DATE('2007-01-01','YYYY-MM-DD')))
  6  TABLESPACE users
  7  AS SELECT employee_id, last_name, salary, hire_date, department_id FROM hr.employees;

Table created.

--   · 정의할 때 3개만 썼는데 5개가 됐다.
--     CTAS 가 2007년·2008년 데이터를 넣으면서 SYS_P612 · SYS_P613 을 자동으로 만들었다.
--   · interval 컬럼(IS_INTERVAL) 이 구분을 알려 준다.

[7] 정리

-- 실습 04 는 새 테이블(emp_hash · emp_list) 을 쓴다. emp_yr 은 여기서 지운다.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1. INTERVAL 파티션은 "미래 파티션 관리" 문제를 없앤다.
--    월별 파티션 테이블의 대부분은 INTERVAL 로 만드는 것이 맞다.
--    대신 파티션 이름을 예측할 수 없으므로 운영 스크립트는
--    PARTITION FOR (값) 표기나 dba_tab_partitions 조회로 이름을 찾아 써야 한다.
--
-- 2. MAXVALUE 와 INTERVAL 은 공존할 수 없다(ORA-14759).
--    둘 중 하나를 고르는 것이고, 실무에서는 INTERVAL 이 거의 항상 낫다.
--
-- 3. partition_count = 1048575 를 실제 개수로 착각하지 않는다.
--    모니터링 쿼리는 SELECT COUNT(*) FROM dba_tab_partitions 로 센다.
--
-- 4. 간격은 데이터 유입 속도에 맞춘다.
--    파티션 하나가 8MB 를 먼저 잡으므로(실습 02) 하루 몇 건 들어오는 테이블에
--    일별 간격을 주면 낭비가 크다. 월별·분기별부터 검토한다.
--
-- 5. 이력 보관 정책과 함께 설계한다.
--    자동 생성은 편하지만 자동 삭제는 없다.
--    오래된 파티션을 DROP 하거나 EXCHANGE 로 떼어 내는 작업(실습 06·07)은 여전히 필요하다.
