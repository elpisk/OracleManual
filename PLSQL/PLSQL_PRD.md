좋습니다. 기존 PRD를 기반으로 하되, **확장 옵션을 단순 나열하지 않고 정식 요구사항으로 편입**해서, 향후 실제 교안·실습·SQL 파일·평가·DBA 자동화 프로젝트까지 일관되게 제작할 수 있는 형태로 다시 구성하겠습니다.

특히 DBA 대상이라는 점을 반영하여 **HR 스키마 실습 + DBA 권한 환경 + Data Dictionary + DBMS_SCHEDULER + 운영 자동화**를 하나의 교육 체계로 연결하겠습니다.

# 1. Product Vision

## 1.1 제품명

**Oracle PL/SQL 7-Day Practical & DBA Automation Training**

## 1.2 핵심 비전

본 과정은 PL/SQL 문법을 단순하게 학습하는 과정이 아니다.

교육생이 다음 단계로 성장하도록 설계한다.

```text

   ↓
PL/SQL 입문자
   ↓
PL/SQL 프로그램 개발자
   ↓
Stored Program 개발자
   ↓
DB 운영 자동화 개발자
   ↓
Oracle DBA Automation Engineer
```

최종적으로 교육생이 다음과 같은 업무 요구사항을 받았을 때 스스로 PL/SQL 프로그램을 설계하고 구현할 수 있도록 한다.

> "매일 반복되는 DB 점검 업무를 자동화하고, 성공/실패 여부와 오류 내용을 로그로 남겨라."

# 25. Transaction 설계 교육

단순히 COMMIT을 사용하는 것을 가르치는 것이 아니라 다음을 교육한다.

```text
작업 시작
   ↓
SAVEPOINT
   ↓
작업 수행
   ↓
성공?
 ┌─┴─┐
YES  NO
 ↓    ↓
COMMIT ROLLBACK
       ↓
      LOG
```

운영 자동화에서 Transaction Boundary를 설계하는 방법을 포함한다.

# 47. 최종 성공 기준

본 프로젝트는 단순히 "교안과 문제를 만들었다"를 성공으로 판단하지 않는다.

다음 조건을 모두 만족해야 한다.

### 교육생 관점

```text
SQL
 ↓
PL/SQL
 ↓
Stored Program
 ↓
Exception
 ↓
Dynamic SQL
 ↓
DBA Automation
 ↓
Scheduler
```

과정을 혼자 수행할 수 있어야 한다.

### 실습 관점

**100개 문제 모두 실제 PL/SQL 작성 문제**

### 코드 관점

**모든 정답 코드는 실제 Oracle 환경에서 실행 가능해야 함**

### DBA 관점

교육생이 다음 요구사항을 독립적으로 구현할 수 있어야 한다.

> "매일 새벽 DB 상태를 점검하고, 이상 항목을 기록하고, 작업 결과를 로그로 남기고, 실패하면 오류 정보를 기록하는 자동화 프로그램을 작성하시오."

### 최종 목표

**PL/SQL 문법 교육 → DBA 업무 자동화 역량 교육**

으로 연결되는 것이 본 제품의 최종 성공 기준이다.

이 버전에서는 기존의 "향후 확장 가능" 항목을 **실제 PRD의 정식 요구사항**으로 승격했습니다. 특히 핵심적인 변경점은 **DBMS_SCHEDULER + Data Dictionary + Logging + Monitoring + Bulk Processing + 성능 + 자동채점 + 실습환경 초기화 + 강사용 패키지 + Workbook + 최종 Automation Framework**까지 전체 제품 범위에 포함한 것입니다.

다음 단계에서는 이 PRD를 바탕으로 **「7일 × 시간대별 상세 커리큘럼 + Chapter별 세부 목차 + 70개 실습문제 제목/난이도 + 최종 30문제 구성표」**를 먼저 확정하면, 이후 실제 교안과 100개 PL/SQL 문제를 체계적으로 제작하기 좋습니다.
