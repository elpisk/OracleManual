 정리
--------------------------------------------------------------------------------
 1. 패키지 스펙에 선언한 서브프로그램을 바디에 정의하지 않으면 PLS-00323 이다.
    오류 위치가 바디의 마지막 END 로 표시되는 점에 주의한다.
 2. 바디가 INVALID 이면 어떤 프로시저를 호출해도 ORA-04063 / ORA-06508 이 난다.
    패키지는 스펙과 바디가 별개의 객체이므로 각각 상태를 확인한다.
 3. 개별 점검을 예외 처리 없이 순차 호출하면 첫 실패가 나머지 전부를 막는다.
    로그조차 남지 않아 "아무 일도 없었던 것"과 구분되지 않는다.
 4. 각 호출을 개별 BEGIN … EXCEPTION … END 로 감싸면 부분 실패를 흡수한다.
    실패한 점검만 ERROR 로 기록되고 나머지는 정상 수행된다.
 5. 마지막에 RAISE_APPLICATION_ERROR 로 재전파해야 스케줄러가 FAILED 로 인지한다.
    삼키기만 하면 이력이 SUCCEEDED 가 되어 알림도 울리지 않는다.
 6. 권한 요건이 다른 점검은 동적 SQL 로 컴파일 의존성을 끊으면
    권한 회수 시에도 패키지 전체가 INVALID 가 되지 않는다.
 7. 스케줄러에 노출하는 진입점은 RUN_ALL_CHECK 하나면 충분하다.
    job_action 은 'PKG_DBA_AUTOMATION.RUN_ALL_CHECK' 한 줄이다.
