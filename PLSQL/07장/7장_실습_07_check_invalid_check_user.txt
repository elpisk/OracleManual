 정리
--------------------------------------------------------------------------------
 1. 점검 프로시저의 첫 번째 규칙은 대상 범위를 명시적으로 좁히는 것이다.
    owner 조건을 빠뜨리면 PUBLIC·SYS 객체까지 잡혀 결과가 폭증한다.
 2. ALL_OBJECTS 는 접근 가능한 객체만 보여 주므로 추가 권한 없이 동작한다.
    관리자 권한이 있다면 그때 DBA_OBJECTS 로 바꾼다.
 3. 정적 SQL 은 컴파일 시점에 객체 존재와 권한을 검사한다.
    권한이 없으면 "Warning: Procedure created with compilation errors" 가 뜨고
    SHOW ERRORS 에 PL/SQL: ORA-00942 가 나오며 객체는 INVALID 로 남는다.
 4. 정의자 권한 프로그램의 정적 SQL 은 롤로 받은 권한을 무시한다.
    SELECT_CATALOG_ROLE 을 줘도 컴파일되지 않으며, 직접 GRANT 해야 한다.
 5. 최소 권한 원칙에 따라 롤 전체가 아니라 필요한 뷰만 직접 부여한다.
 6. DBA_USERS 의 ORACLE_MAINTAINED = 'N' 조건으로 오라클 기본 계정을 걸러 내면
    점검 결과의 잡음이 크게 줄어든다.
 7. 점검 프로시저를 순차 호출하기만 하면 첫 실패가 나머지를 막는다.
    이 문제는 실습 08 의 패키지에서 개별 예외 블록으로 해결한다.
