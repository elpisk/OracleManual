[7] (오류 재현 2) ORA-27367 — Program 을 활성화하지 않았다
--------------------------------------------------------------------------------

-- 원인 파악
--   ORA-27476 과 헷갈리기 쉽지만 의미가 다르다.
--     ORA-27476 : 그 이름을 찾을 수 없다 (오타 · 미생성)
--     ORA-27367 : 이름은 찾았으나 그 Program 이 비활성 상태다
--   Program 의 enabled 기본값도 FALSE 이므로 별도로 켜야 한다.

SQL> SELECT program_name, enabled FROM user_scheduler_programs;

PROGRAM_NAME       ENABLED
------------------ --------
PRG_DEPT_REPORT    FALSE

-- 수정 : Program 을 ENABLE 한다.
--        인자가 이미 정의되어 있으므로 지금은 켤 수 있다.

SQL> EXEC DBMS_SCHEDULER.ENABLE('PRG_DEPT_REPORT');

SQL> SELECT program_name, enabled FROM user_scheduler_programs;

-- 이 Job 은 부서 60을 대상으로 하려 하므로 명시한다.

 정리
--------------------------------------------------------------------------------
 1. Program 은 "무엇을 실행할 것인가", Schedule 은 "언제 실행할 것인가"를
    담은 독립 객체다. Job 은 둘을 이름으로 엮기만 한다.
 2. 없는 Program·Schedule 을 참조하면 ORA-27476 does not exist 가 발생한다.
    이름 오타 · 미생성 · 스키마 수식 누락 셋을 순서대로 확인한다.
 3. 비활성 Program 을 참조하는 Job 을 ENABLE 하면 ORA-27367 이 발생한다.
    ORA-27476 과 달리 "이름은 찾았지만 꺼져 있다"는 뜻이다.
 4. Program 의 enabled 기본값도 FALSE 다. 인자를 정의한 뒤 ENABLE 한다.
    순서는 CREATE_PROGRAM → DEFINE_PROGRAM_ARGUMENT → ENABLE 이다.
 5. Job 의 인자는 SET_JOB_ARGUMENT_VALUE 로 지정하며 Program 의 기본값을
    Job 단위로 덮어쓴다. 이것이 재사용성의 핵심이다.
 6. 캘린더 표현식은 EVALUATE_CALENDAR_STRING 으로 반드시 사전 검증한다.
 7. Schedule 객체를 고치면 이를 참조하는 모든 Job 의 다음 실행 시각이
    함께 재계산된다. 두 개 이상의 Job 이 시각을 공유하면 분리가 이득이다.
