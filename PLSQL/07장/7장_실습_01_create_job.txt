================================================================================
 제7장 실습 01 — DBMS_SCHEDULER.CREATE_JOB 으로 Job 생성
--------------------------------------------------------------------------------
 대상 스키마 : HR (EMPLOYEES / DEPARTMENTS / JOBS / JOB_HISTORY /
                   LOCATIONS / COUNTRIES / REGIONS)
 실행 환경   : Oracle Database 19c (19.3) / SQL*Plus
 학습 목표   : 1) HR 계정에 CREATE JOB 권한을 부여하고 ORA-27486 을 재현한다
               2) 이후 실습에서 공통으로 쓸 로그 테이블 두 개를 만든다
               3) job_type 문자열 오타로 ORA-27465 를 재현하고 고친다
               4) enabled 기본값 FALSE 때문에 Job 이 돌지 않는 상황을 확인한다
               5) 같은 이름으로 다시 만들어 ORA-27477 을 재현하고 고친다
               6) auto_drop 기본값 TRUE 때문에 Job 이 사라지는 것을 확인한다
 사전 준비   : 없음. 이 실습에서 만드는 plsql_job_log · dba_check_result 테이블과
               PR_JOB_DEMO 프로시저를 실습 02~08 에서 계속 사용합니다.

--   job_type 은 정해진 문자열 목록 중 하나여야 한다.

 정리
--------------------------------------------------------------------------------
 1. 스케줄러 권한 부족은 ORA-01031 이 아니라 ORA-27486 으로 나타난다.
    자기 스키마용 최소 권한은 CREATE JOB 하나면 충분하다.
 2. job_type 문자열이 목록에 없으면 ORA-27465 로 CREATE_JOB 자체가 실패한다.
    즉시 발견되므로 오히려 안전한 오류다.
 3. enabled 기본값은 FALSE 다. 명시하지 않으면 STATE 가 DISABLED 로 남아
    예정 시각이 되어도 실행되지 않는다.
 4. auto_drop 기본값은 TRUE 다. repeat_interval 이 없는 일회성 작업은
    실행 후 스스로 사라진다. 실행 여부는 JOB_RUN_DETAILS 로 확인한다.
 5. 같은 이름이 이미 있으면 ORA-27477 이다. 재실행 가능한 스크립트를 만들려면
    PRAGMA EXCEPTION_INIT 으로 ORA-27475 를 처리한 뒤 DROP → CREATE 한다.
 6. job_action 형식 오류는 생성 시점에 검사되지 않고 실행 시점에 드러난다.
    Job 을 만든 뒤 반드시 RUN_JOB 으로 한 번 수동 검증한다.
 7. Job 생성 직후 확인할 세 컬럼은 ENABLED · STATE · NEXT_RUN_DATE 다.
================================================================================
