[3] Bind Variable 을 사용한 Dynamic DML
--------------------------------------------------------------------------------

SQL> DECLARE
  2     v_dept   NUMBER := 60;
  3     v_pct    NUMBER := 0.05;
  4  BEGIN
  5     EXECUTE IMMEDIATE 'UPDATE emp_copy SET commission_pct = :pct
  6                         WHERE department_id = :dept'
  7        USING v_pct, v_dept;
  8     DBMS_OUTPUT.PUT_LINE('처리 건수 : ' || SQL%ROWCOUNT);
  9  END;
 10  /
처리 건수 : 5

PL/SQL procedure successfully completed.

-- USING 인자의 순서가 플레이스홀더의 등장 순서와 일치해야 한다.
-- :pct 가 먼저이므로 v_pct 를 먼저 넘겼다.

SQL> ROLLBACK;

Rollback complete.

-- 원인 파악
--   SQL 문장을 동적으로 실행할 때 플레이스홀더와 USING 인자는
--   이름이 아니라 위치(순서)로 대응된다. 이름은 사람이 읽기 위한 표시일 뿐이다.

--   인자를 하나만 넘겼으므로 두 번째 자리가 비어 ORA-01008 이 발생했다.

-- 수정 : 등장 횟수만큼 인자를 넘긴다.

SQL> DECLARE

[7] 문자열 결합 방식과 Bind Variable 방식의 비교
--------------------------------------------------------------------------------

-- 같은 작업을 두 방식으로 27개 부서에 대해 반복한다고 가정한다.

SQL> CREATE OR REPLACE PROCEDURE upd_bad(p_dept IN NUMBER) IS
  2  BEGIN
  3     -- 값을 문자열로 결합 : 부서마다 다른 문장이 만들어진다
  4     EXECUTE IMMEDIATE 'UPDATE emp_copy SET commission_pct = 0.1
  5                         WHERE department_id = ' || p_dept;
  6  END;
  7  /

Procedure created.

SQL> CREATE OR REPLACE PROCEDURE upd_good(p_dept IN NUMBER) IS
  2  BEGIN
  3     -- 값을 바인딩 : 문장 텍스트가 언제나 동일하다
  4     EXECUTE IMMEDIATE 'UPDATE emp_copy SET commission_pct = 0.1
  5                         WHERE department_id = :d'
  6        USING p_dept;
  7  END;
  8  /

Procedure created.

-- 라이브러리 캐시에 어떤 문장이 쌓였는지 확인한다.
-- (V$SQL 조회 권한이 없으면 이 단계는 SYSTEM 계정에서 확인한다.)

SQL> SELECT COUNT(*) AS stmt_cnt
  2    FROM v$sql
  3   WHERE sql_text LIKE 'UPDATE emp_copy SET commission_pct = 0.1%'
  4     AND sql_text NOT LIKE '%:d%';

  STMT_CNT
----------
        27

SQL> SELECT COUNT(*) AS stmt_cnt
  2    FROM v$sql
  3   WHERE sql_text LIKE 'UPDATE emp_copy SET commission_pct = 0.1%'
  4     AND sql_text LIKE '%:d%';

  STMT_CNT
----------
         1

-- 문자열 결합 방식은 27개의 서로 다른 문장을 만들어 캐시를 오염시켰다.
-- 바인딩 방식은 문장이 하나뿐이다. 이것이 하드 파스와 소프트 파스의 차이다.

 10  END;

================================================================================
 정리
--------------------------------------------------------------------------------
 1. Dynamic DML 은 EXECUTE IMMEDIATE 와 USING 절로 실행하며
    처리 건수는 SQL%ROWCOUNT 로 확인한다(직후에 읽어야 한다).
 2. SQL 문장에서 플레이스홀더와 USING 인자는 위치로 대응된다.
    같은 이름이 두 번 나오면 인자도 두 번 넘겨야 한다. 아니면 ORA-01008.
 3. 인자가 남으면 ORA-01006 이 발생한다. 두 오류는 방향만 다른 짝이다.
 4. PL/SQL 블록 문자열에서는 이름으로 대응되므로 중복 등장해도 인자는 하나다.
 5. 값을 문자열로 결합하면 실행마다 다른 문장이 되어 하드 파스가 반복된다.
 6. RETURNING INTO 는 USING 목록의 OUT 인자로 결과를 받는다.
    여러 행이면 RETURNING ... BULK COLLECT INTO 를 사용한다.
