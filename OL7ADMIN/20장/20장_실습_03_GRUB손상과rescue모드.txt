 제20장 실습 03 — GRUB 손상과 rescue 모드
 대상   : ol7a (직렬 콘솔 ttyS0 으로 진행)
 목표   : 반쯤 지워진 grub.cfg 로 GRUB 셸에 떨어진 상태에서 linux16·initrd16·boot 로
          손수 부팅하고 grub2-mkconfig 로 되살린다. 기본 커널의 initramfs 가 사라져
          패닉이 나는 서버를 rescue 커널 항목으로 살려 dracut 으로 고친다
 배경   : BIOS 의 GRUB 2 는 MBR → core.img → /boot/grub2 의 모듈과 grub.cfg 순서로
          올라온다. grub.cfg 에 부팅 항목이 없으면 grub> 셸을 준다. 셸에서 쓰는 경로는
          GRUB 의 root 장치(/boot 파티션) 기준이라 /boot 접두어가 없다. 7.9 는 설치 때
          어느 하드웨어에서나 뜨는 rescue 커널 항목(0-rescue)을 만들어 둔다. 디스크로
          아무것도 안 뜨면 설치 매체의 rescue 모드(/mnt/sysimage)를 쓴다 (본문 20.5)
 소요   : 약 40분
 선행   : pre-break 스냅샷
 계정   : root
 주의   : /boot 의 파일 이름을 바꾼다. 전원을 강제로 끄는 단계가 있다
 되돌림 : grub.cfg 가 원본과 같음, 기본 커널 initramfs 복구, UEK 로 부팅
          → diff /root/grub.cfg.orig /boot/grub2/grub.cfg (출력 없음), uname -r

ls

(hd0) (hd0,msdos2) (hd0,msdos1) (hd1) (hd2) (hd3) (hd4) 
-- ls : GRUB 이 보는 디스크와 파티션.
-- hd0 은 BIOS 가 첫 번째로 넘긴 디스크(sda), 파티션 둘.
-- hd1~hd4 는 빈 실습 디스크 sdb~sde 다.

echo root=$root prefix=$prefix

root=hd0,msdos1 prefix=(hd0,msdos1)/grub2
-- root : 파일을 찾는 기본 장치. hd0 의 첫 파티션, 즉 /boot 파티션이다.
-- prefix : 모듈과 grub.cfg 를 읽는 경로.
-- 리눅스에서 /boot/grub2 인 곳이 GRUB 에서는 /grub2 다.

grub> 
ls /grub2/

device.map i386-pc/ locale/ fonts/ grubenv grub.cfg grub.cfg.1794395718.rpmsave
-- ls /grub2/ 가 바로 보인다.

-- grubenv 는 saved_entry 를 담는 파일.


grub>

 [4] 오류 흐름 — linux16 경로를 /boot 부터 씀
--------------------------------------------------------------------------------

-- 콘솔 한 줄이 80자를 넘으면 GRUB 의 줄 편집기가 줄을 접어 화면이 어지러워진다.
-- 커널 버전을 변수 k 에 담아 짧게 친다.
set k=5.4.17-2136.338.4.2.el7uek.x86_64

grub> 
linux16 /boot/vmlinuz-$k root=/dev/mapper/ol-root ro

error: file `/boot/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64' not found.
-- 리눅스에서 쓰던 대로 /boot 를 붙였더니 파일이 없다.
-- GRUB 의 root 가 이미 /boot 파티션이라 /boot/vmlinuz… 는 /boot/boot/vmlinuz… 를 찾은 셈이다.
-- $k 는 오류 메시지에서 실제 버전으로 펼쳐져 보인다.
-- 증상   : linux16 /boot/vmlinuz-$k … → "error: file … not found."
-- 원인   : /boot 가 별도 파티션이고 GRUB 의 root=hd0,msdos1 이 그 파티션이라 경로에 /boot 가 없어야 한다
-- 조치   : linux16 /vmlinuz-$k root=/dev/mapper/ol-root ro
-- 재확인 : 오류 없이 grub> 로 돌아오고, boot 뒤 /proc/cmdline 의 BOOT_IMAGE=/vmlinuz-…

grub> 

--------------------------------------------------------------------------------
 [5] 손으로 부팅 — linux16 · initrd16 · boot
--------------------------------------------------------------------------------

-- rd.lvm.lv 를 빼면 dracut 은 찾은 LV 를 모두 켠다.
-- console= 을 넣지 않았으니 이번 부팅의 메시지는 직렬 콘솔이 아니라 VGA 화면에만 나간다.
-- 부팅 결과는 SSH 로 확인한다.
linux16 /vmlinuz-$k root=/dev/mapper/ol-root ro

grub> 
-- 오류 없이 프롬프트로 돌아왔다.
-- 커널이 메모리에 올라갔다.
initrd16 /initramfs-$k.img

grub> 
-- initramfs 도 올라갔다.
boot
-- boot 로 커널을 실행한다.
-- console= 이 없어 직렬 콘솔에는 더 찍히지 않았다.
-- 러너가 SSH 가 열리기를 기다렸다가 접속했다.

[root@ol7a ~]# cat /proc/cmdline; uptime
BOOT_IMAGE=/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64 root=/dev/mapper/ol-root ro
 22:00:43 up 1 min,  0 users,  load average: 0.00, 0.00, 0.00
-- BOOT_IMAGE 뒤가 직접 친 파라미터 그대로다.
-- rhgb quiet, crashkernel,
-- rd.lvm.lv, console= 이 모두 빠졌다.
-- crashkernel 이 없으니 이번 부팅에서는 kdump 가 동작하지 않는다.
[root@ol7a ~]# swapon --show; lvs --noheadings -o lv_name,lv_active ol
NAME      TYPE      SIZE USED PRIO
/dev/dm-0 partition 3.9G   0B   -2
  root active
  swap active
-- swapon : 스왑 장치 dm-0(ol-swap) 3.9G, 사용 0B.
-- lvs : root·swap 모두 active.
-- rd.lvm.lv 를 빼도 dracut 이 VG 의 LV 를 다 켰다.

[root@ol7a ~]# mv /boot/initramfs-5.4.17-2136.338.4.2.el7uek.x86_64.img /root/; ls /boot | grep -E '^initramfs'
initramfs-0-rescue-b8658360b45f49fe8174bcd0b610ae6e.img

-- 재부팅하면 메뉴의 첫 항목(기본)으로 부팅한다.
-- 콘솔 출력의 마지막 8줄.
[    0.674705]  prepare_namespace+0x141/0x17d
[    0.675431]  kernel_init_freeable+0x27c/0x2a7
[    0.676112]  ? loglevel+0x5d/0x5d
[    0.676637]  ? rest_init+0xb0/0xb0
[    0.677181]  kernel_init+0xe/0x123
[    0.677719]  ret_from_fork+0x24/0x36
[    0.678351] Kernel Offset: 0x32c00000 from 0xffffffff81000000 (relocation range: 0xffffffff80000000-0xffffffffbfffffff)
[    0.680003] ---[ end Kernel panic - not syncing: VFS: Unable to mount root fs on unknown-block(0,0) ]---
-- 마지막 줄이 이유다.
-- VFS: Unable to mount root fs on unknown-block(0,0).
-- 0.68초 만에 패닉했다.
-- 루트 장치를 열 initramfs 가 없었다.

-- prepare_namespace 에서 루트를 찾다 멈췄다.

 [8] rescue 커널 항목으로 부팅
--------------------------------------------------------------------------------

-- 패닉 뒤에는 응답이 없다.
-- 전원을 강제로 끈다 (vmrun stop hard).
-- 메뉴의 다섯 번째 항목이 rescue 커널이다.
-- 아래 화살표 네 번 후 Enter.



      Oracle Linux Server 7.9, with Unbreakable Enterprise Kernel 5.4.17-2136.>
      Oracle Linux Server 7.9, with Unbreakable Enterprise Kernel 5.4.17-2102.>
      Oracle Linux Server 7.9, with Linux 3.10.0-1160.119.1.0.5.el7.x86_64
      Oracle Linux Server 7.9, with Linux 3.10.0-1160.el7.x86_64
      Oracle Linux Server 7.9, with Linux 0-rescue-b8658360b45f49fe8174bcd0b61>
-- GRUB 메뉴 다섯 항목.
-- 화면 폭에서 잘린 제목은 > 로 끝난다.
-- 직렬 화면 재구성이라 선택 막대(반전 표시)는 보이지 않는다.
Oracle Linux Server 7.9
Kernel 3.10.0-1160.el7.x86_64 on an x86_64
ol7a login:
-- 3.10.0-1160.el7 커널로 로그인 프롬프트까지 왔다.
[root@ol7a ~]# uname -r; cat /proc/cmdline | cut -c1-80
3.10.0-1160.el7.x86_64
BOOT_IMAGE=/vmlinuz-0-rescue-b8658360b45f49fe8174bcd0b610ae6e root=/dev/mapper/o
-- 실행 중인 커널 이름은 3.10.0-1160.el7.x86_64.
-- 부팅한 파일은 vmlinuz-0-rescue-….
-- 80자에서 잘랐다.
[root@ol7a ~]# ls -l /boot/vmlinuz-0-rescue-* /boot/vmlinuz-3.10.0-1160.el7.x86_64 | cut -c24-; cmp /boot/vmlinuz-0-rescue-* /boot/vmlinuz-3.10.0-1160.el7.x86_64 && echo same
 6771656 Nov 11 19:47 /boot/vmlinuz-0-rescue-b8658360b45f49fe8174bcd0b610ae6e
 6771656 Oct  2  2020 /boot/vmlinuz-3.10.0-1160.el7.x86_64
same
-- 두 파일 크기 6771656 으로 같고 cmp 도 같다고 한다.
-- rescue 커널은 설치 매체의 3.10.0-1160 커널을 복사한 것이다.
-- initramfs 는 모든 드라이버를 담은 범용판이라 어느 하드웨어에서도 뜬다(68MB).

 [9] 오류 흐름 — 버전 없이 dracut -f
--------------------------------------------------------------------------------
