================================================================================
 제20장 실습 05 — dmesg 로 디스크 오류 읽기
 대상   : ol7a
 목표   : 실습 디스크를 SCSI 계층에서 offline 으로 만들어 I/O 오류를 일으키고, dmesg -T·
          journalctl -k 의 메시지를 장치 이름 → 마운트 지점으로 이어 읽는다. ext4 가
          읽기 전용으로 다시 마운트되는 과정과 XFS 가 스스로 멈추는 과정을 비교한다
 배경   : 디스크 오류는 아래층부터 위층 순서로 커널 로그에 찍힌다. SCSI(sd H:C:T:L)
          → 블록 계층(blk_update_request, dev sdX) → 파일 시스템(EXT4-fs (sdX1), XFS
          (dm-N)). 메시지마다 장치를 부르는 이름이 다르다. LVM 위의 파일 시스템은
          dm-N 으로 찍혀 lsblk·dmsetup 으로 이어 줘야 한다. VM 에서 디스크를 떼는 대신
          /sys/block/sdX/device/state 에 offline 을 써서 같은 증상을 만든다 (본문 20.2·20.4)
 소요   : 약 30분
 선행   : storage-clean 스냅샷 (sdb~sde 비어 있음)
 계정   : root
 주의   : sdb·sdc·sdd 의 내용을 지운다. OS 디스크(sda, 2:0:0:0)는 건드리지 않는다
 되돌림 : 마운트·LV·VG·PV 제거, 디스크 서명 지움, 모든 장치 state=running
          → lsblk 가 [0] 과 같고 /sys/block/sd?/device/state 가 모두 running

 [0] 시작 전 상태 기록
--------------------------------------------------------------------------------

-- 지울 디스크가 빈 실습 디스크인지부터 본다.
-- HCTL = Host:Channel:Target:Lun, SCSI 주소다.
[root@ol7a ~]# lsblk -o NAME,HCTL,SIZE,TYPE,FSTYPE,MOUNTPOINT
NAME        HCTL        SIZE TYPE FSTYPE      MOUNTPOINT
sdd         2:0:3:0      10G disk             
sdb         2:0:2:0      10G disk             
sr0         1:0:0:0     4.5G rom  iso9660     
sde         2:0:4:0      10G disk             
sdc         2:0:1:0      10G disk             
sda         2:0:0:0      40G disk             
├─sda2                   39G part LVM2_member 
│ ├─ol-swap             3.9G lvm  swap        [SWAP]
│ └─ol-root            35.1G lvm  xfs         /
└─sda1                    1G part xfs         /boot
-- 열은 이름·주소·크기·종류·파일 시스템·마운트 지점 순.
-- OS 디스크는 sda(2:0:0:0).
-- / 와 /boot 가 여기 있다.
-- sdb~sde 는 FSTYPE·MOUNTPOINT 가 비었다.
-- sr0(1:0:0:0)은 설치 ISO 다.
-- 이번 부팅에서 sdb 가 2:0:2:0,
-- sdc 가 2:0:1:0 이다.
-- 이름 순서와 SCSI 주소 순서가 어긋났다.
-- 이름만 보고 주소를 짐작하면 틀린다.
-- 이름이 sdd, sdb,
-- sr0 … 순으로 찍힌 것은 lsblk 가 sysfs 순서로 읽기 때문이다.
-- wipefs -n : 지우지 않고 서명만 본다(no-act).
[root@ol7a ~]# wipefs -n /dev/sdb /dev/sdc /dev/sdd; echo "rc=$?"
rc=0
-- 출력 없이 rc=0.
-- 세 디스크 모두 서명이 없다.
[root@ol7a ~]# grep . /sys/block/sd[a-e]/device/state
/sys/block/sda/device/state:running
/sys/block/sdb/device/state:running
/sys/block/sdc/device/state:running
/sys/block/sdd/device/state:running
/sys/block/sde/device/state:running
-- 다섯 디스크 모두 running.
-- [3] 에서 이 값을 바꾼다.
-- 커널 메시지 줄 수와,
-- 이번 부팅의 err 이상 개수.
[root@ol7a ~]# dmesg | wc -l; journalctl -k -b -p err --no-pager -q | wc -l
1313
7
-- 링 버퍼 1313줄, err 이상 7줄.
-- 7줄은 부팅 때부터 있던 것이다(실습 06 [2] 에서 내용을 본다).
-- 기준값을 먼저 잡아야 실습이 만든 오류만 셀 수 있다.

 [1] 실습 파일 시스템 두 개 만들기
--------------------------------------------------------------------------------

-- sdb 는 LVM 위 XFS, sdc 는 파티션 위 ext4.
-- 오류 메시지의 장치 이름을 비교하려는 배치다.
-- -q 는 진행 메시지를 줄인다.
[root@ol7a ~]# pvcreate -q /dev/sdb; vgcreate -q vgt /dev/sdb; lvcreate -q -L 2G -n lvx vgt; mkfs.xfs -q /dev/vgt/lvx; mkdir -p /data1; mount /dev/vgt/lvx /data1
  Physical volume "/dev/sdb" successfully created.
  Volume group "vgt" successfully created
  Logical volume "lvx" created.
-- PV → VG → LV 순서로 세 줄.
-- mkfs.xfs -q 는 조용하다.
[root@ol7a ~]# parted -s /dev/sdc mklabel msdos mkpart primary 1MiB 2GiB; mkfs.ext4 -q /dev/sdc1; mkdir -p /data2
-- ext4 의 오류 동작은 슈퍼블록 값과 마운트 옵션 errors= 로 정한다.
[root@ol7a ~]# tune2fs -l /dev/sdc1 | grep -i 'errors behavior'
Errors behavior:          Continue
-- 슈퍼블록 기본값은 Continue.
-- 오류가 나도 계속 쓴다.
-- errors=remount-ro 를 명시한다.
-- 오류가 나면 쓰기를 막는다.
[root@ol7a ~]# mount -o errors=remount-ro /dev/sdc1 /data2; findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS /data1 /data2
-- findmnt 가 아무것도 찍지 않았다.
-- 인자를 둘 주면 findmnt 는 "원본 장치, 마운트 지점" 한 쌍으로 읽는다.
-- /data1 을 원본으로 하는 /data2 마운트는 없으니 빈 출력이다.
-- 마운트 지점은 하나씩 주어야 한다([4] 에서 그렇게 한다).
[root@ol7a ~]# for d in /data1 /data2; do dd if=/dev/urandom of=$d/base.dat bs=1M count=20 status=none; done; sync; ls -l /data1 /data2
/data1:
total 20480
-rw-r--r--. 1 root root 20971520 Nov 16 22:05 base.dat

/data2:
total 20496
-rw-r--r--. 1 root root 20971520 Nov 16 22:05 base.dat
drwx------. 2 root root    16384 Nov 16 22:05 lost+found
-- 두 곳에 20MB 파일 하나씩.
-- ext4 에는 lost+found 가 미리 있다.

 [3] sdc 를 offline 으로 — ext4 쪽 오류
--------------------------------------------------------------------------------

-- 디스크가 응답하지 않는 상황을 흉내 낸다.
-- offline 이면 SCSI 중간층이 I/O 를 거절한다.
[root@ol7a ~]# echo offline > /sys/block/sdc/device/state; cat /sys/block/sdc/device/state
offline
-- 즉시 바뀐다. 파일 시스템은 아직 모른다.
-- oflag=direct : 페이지 캐시를 거치지 않는 직접 I/O.
[root@ol7a ~]# dd if=/dev/zero of=/data2/new.dat bs=1M count=10 oflag=direct; echo "rc=$?"
dd: error writing ‘/data2/new.dat’: Input/output error
1+0 records in
0+0 records out
0 bytes (0 B) copied, 0.00519574 s, 0.0 kB/s
-- 첫 1MB 블록에서 바로 Input/output error.
-- 1+0 records in : 1MB 를 읽었고,
-- 0+0 out : 하나도 못 썼다.
rc=1
-- 저널 커밋 주기(기본 5초)를 기다리며 메타데이터를 건드린다.
[root@ol7a ~]# touch /data2/a; sync; sleep 7; touch /data2/b; echo "rc=$?"
touch: cannot touch ‘/data2/b’: Read-only file system
-- 첫 touch 는 조용히 지나갔고 7초 뒤의 touch 가 막혔다.
-- 오류가 I/O error 가 아니라 Read-only file system 이다.
-- 그사이 ext4 가 스스로 읽기 전용이 된 것이다.
rc=1

 [4] 오류 흐름 — 메시지의 장치 이름과 마운트 지점 연결
--------------------------------------------------------------------------------

-- 메시지의 이름은 sd 2:0:1:0, sdc, sdc1 셋.
-- 어느 마운트 지점인가.
[root@ol7a ~]# lsblk -o NAME,HCTL,MOUNTPOINT /dev/sdc
NAME   HCTL       MOUNTPOINT
sdc    2:0:1:0    
└─sdc1            /data2
-- 2:0:1:0 = sdc, 그 파티션 sdc1 이 /data2.
[root@ol7a ~]# findmnt -S /dev/sdc1 -o TARGET,SOURCE,OPTIONS
TARGET SOURCE    OPTIONS
/data2 /dev/sdc1 ro,relatime,seclabel,errors=remount-ro
-- -S 는 원본 장치로 찾는다.
-- 옵션 첫머리가 ro 다.
-- by-path 이름에도 HCTL 이 들어 있다.
-- 이 grep 은 지난 실측(sdc=2:0:2:0)을 보고 짠 것이다.
[root@ol7a ~]# ls -l /dev/disk/by-path | grep -E '0:2:0($| )|0:2:0-part'
lrwxrwxrwx. 1 root root  9 Nov 16 22:05 pci-0000:00:10.0-scsi-0:0:2:0 -> ../../sdb
-- scsi-0:0:2:0 이 sdb 를 가리킨다.
-- 오류가 난 sdc 가 아니다.
-- 이번 부팅에서 sdc 는 2:0:1:0 이다.
-- 주소를 기억에 기대 고르면 엉뚱한 디스크를 짚는다.
-- 메시지의 HCTL(2:0:1:0)을 그대로 써야 한다.
-- pci-0000:00:10.0 은 SCSI 컨트롤러 주소.
-- by-path 는 슬롯이 같으면 부팅마다 같지만 sd 이름은 바뀔 수 있다.
-- 장치 단위 I/O 계수. 16진수다.
[root@ol7a ~]# grep . /sys/block/sdc/device/{ioerr_cnt,iodone_cnt}
/sys/block/sdc/device/ioerr_cnt:0x6
/sys/block/sdc/device/iodone_cnt:0x209
-- ioerr_cnt 0x6 = 6건, iodone_cnt 0x209 = 521건.
-- dmesg 의 rejecting 줄 수와 같은 6이다.
-- 증상   : "EXT4-fs (sdc1): Remounting filesystem read-only" — 어느 디스크·어느 마운트인지 메시지만으론 모름
-- 원인   : SCSI 는 2:0:1:0, 블록은 sdc, ext4 는 sdc1 로 부르고, sd 이름과 주소의 짝은 부팅마다 바뀔 수 있다
-- 조치   : lsblk -o NAME,HCTL,MOUNTPOINT, findmnt -S /dev/sdc1, by-path 로 잇는다
-- 재확인 : 2:0:1:0 → sdc → sdc1 → /data2, ioerr_cnt 0x6

--------------------------------------------------------------------------------
 [5] 오류 흐름 — 읽기 전용으로 다시 마운트된 ext4
--------------------------------------------------------------------------------

-- 새 파일을 만들어 본다.
[root@ol7a ~]# touch /data2/c; echo "rc=$?"; findmnt -n -o OPTIONS /data2
touch: cannot touch ‘/data2/c’: Read-only file system
rc=1
ro,relatime,seclabel,errors=remount-ro
-- 마운트 옵션이 ro.
-- 응용은 Read-only file system 만 본다.
-- 장치를 되살리면 파일 시스템도 돌아올까.
[root@ol7a ~]# echo running > /sys/block/sdc/device/state; touch /data2/c; echo "rc=$?"
touch: cannot touch ‘/data2/c’: Read-only file system
rc=1
-- 장치는 running 인데 파일 시스템은 ro 그대로다.
-- 저널이 중단(abort)된 ext4 는 스스로 rw 로 돌아오지 않는다.
-- remount,rw 로 바로 올려 본다.
[root@ol7a ~]# mount -o remount,rw /data2; echo "rc=$?"; dmesg | tail -2
mount: cannot remount /dev/sdc1 read-write, is write-protected
rc=32
[   19.715839] EXT4-fs (sdc1): I/O error while writing superblock
[   20.121029] EXT4-fs error (device sdc1): ext4_remount:5462: Abort forced by user
-- 마운트가 write-protected 라며 거부했다(rc=32).
-- 커널은 "Abort forced by user" 를 남겼다.
-- 중단된 저널은 remount 로 못 살린다.
-- 증상   : "touch: cannot touch ‘/data2/c’: Read-only file system", remount,rw 는 "is write-protected"
-- 원인   : I/O 오류로 저널이 중단되자 errors=remount-ro 가 ro 로 바꿨다. 장치를 살려도 그대로다
-- 조치   : umount → e2fsck -fy /dev/sdc1 → 다시 mount
-- 재확인 : touch rc=0, findmnt 옵션 rw
-- 떼고, 검사하고, 다시 붙인다.
-- -f 는 깨끗해 보여도 강제 검사,
-- -y 는 모든 질문에 yes.
-- e2fsck 가 결과 줄 앞뒤에 찍는 별표 다섯 개는 교안 형식과 겹쳐 sed 로 하나로 줄인다.
-- 종료 코드는 PIPESTATUS 로 e2fsck 것을 본다.
[root@ol7a ~]# umount /data2; e2fsck -fy /dev/sdc1 2>&1 | sed 's/\*\{2,\}/*/g'; echo "rc=${PIPESTATUS[0]}"
e2fsck 1.45.4 (23-Sep-2019)
