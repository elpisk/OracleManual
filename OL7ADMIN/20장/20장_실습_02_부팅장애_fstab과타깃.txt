================================================================================
 제20장 실습 02 — 부팅 장애: fstab 과 기본 타깃
 대상   : ol7a (직렬 콘솔 ttyS0 으로 진행)
 목표   : 마운트할 수 없는 fstab 줄, 망가진 기본 타깃 링크, 끝나지 않는 서비스를 하나씩
          걸고 부팅이 각각 어디서 멈추는지(emergency·rescue·멈춤) 구분한다. GRUB 에서
          systemd.unit= 으로 들어간 셸에서 읽기 전용 루트를 다시 마운트해 고친다
 배경   : local-fs.target 이 실패하면 systemd 는 emergency.target 으로 간다. 기본
          타깃을 쓸 수 없으면 rescue.target 을 대신 올린다. 둘 다 sulogin 이 root 암호를
          묻지만 올라와 있는 것이 다르다. emergency 는 루트 하나만(요청해서 들어가면
          읽기 전용), rescue 는 로컬 파일 시스템 전부를 올린다. 둘 다 네트워크와 sshd 는
          없다 (본문 20.5, 3장)
 소요   : 약 50분
 선행   : pre-break 스냅샷(sdb 는 빈 디스크). 직렬 콘솔 캡처 설정이 기준 상태에 있다
 계정   : root (콘솔의 sulogin 도 root 암호 oracle)
 주의   : SSH 가 끊긴 동안의 작업은 모두 직렬 콘솔에서 한다. 전원을 강제로 끄는 단계가 있다
 되돌림 : fstab 원본, 기본 타깃 multi-user.target, license-wait 유닛 제거
          → systemctl get-default, diff /root/fstab.orig /etc/fstab (출력 없음)

 [1] 먼저 — 없는 UUID 를 가리키는 fstab 줄
--------------------------------------------------------------------------------

-- 디스크를 바꿔 UUID 가 달라진 상황이다.
-- nofail 이 없다.
-- 9장 실습 04 에서 본 경우를 부팅 장애 관점에서 다시 본다.
[root@ol7a ~]# mkdir -p /data; echo 'UUID=0e0e0e0e-dead-beef-0000-000000000001 /data xfs defaults 0 0' >> /etc/fstab; diff /root/fstab.orig /etc/fstab
11a12
> UUID=0e0e0e0e-dead-beef-0000-000000000001 /data xfs defaults 0 0
[root@ol7a ~]# systemctl daemon-reload; systemctl show data.mount -p What -p RequiredBy | cut -c1-120
What=/dev/disk/by-uuid/0e0e0e0e-dead-beef-0000-000000000001
RequiredBy=remote-fs.target
-- RequiredBy=remote-fs.target. local-fs 가 아니다.
-- 7.9 의 systemd-219 는 부팅 초기에 없는 장치를
-- 가리키는 줄을 원격 쪽(remote-fs)에 건다.
-- 그러면 이 마운트가 실패해도 emergency 로 가지 않는다.
-- 9장에서 본 것과 같은 동작이다.
-- 재부팅. SSH 가 돌아오는지 본다.
[root@ol7a ~]# uptime; systemctl is-system-running; findmnt /data; echo "findmnt rc=$?"

starting
findmnt rc=1
-- SSH 로 들어왔다.
-- up 0 min, 상태 starting.
-- 부팅이 아직 끝나지 않았다.
-- /data 는 없다(findmnt rc=1).
[root@ol7a ~]# journalctl -b -q --no-pager | grep -E 'Timed out|Dependency failed' | cut -c17-140
-- 아직 아무 줄도 없다.
-- 장치 대기 90초가 다 지나지 않았다.
[root@ol7a ~]# systemd-analyze | cut -c1-120
Bootup is not yet finished. Please try again later.
-- systemd-analyze 도 부팅이 끝나지 않았다고 한다.
-- sshd 는 이미 떴지만 시스템은 뒤에서 장치를 기다리는 중이다.
-- 이런 서버는 "접속은 되는데 느리게 뜬다"로 신고된다.
-- emergency 화면은 없다.

 [2] 장애 A 심기 — 빈 디스크를 가리키는 fstab 줄
--------------------------------------------------------------------------------

-- 장애 A. UUID 대신 장치 이름을 썼고,
-- 그 디스크는 교체돼 비어 있다.
[root@ol7a ~]# sed -i '/0e0e0e0e/d' /etc/fstab; echo '/dev/sdb /data xfs defaults 0 0' >> /etc/fstab; diff /root/fstab.orig /etc/fstab
11a12
> /dev/sdb /data xfs defaults 0 0
[root@ol7a ~]# systemctl daemon-reload; systemctl show data.mount -p What -p RequiredBy | cut -c1-120; blkid /dev/sdb; echo "blkid rc=$?"
What=/dev/sdb
RequiredBy=local-fs.target
blkid rc=2
-- 이번에는 RequiredBy=local-fs.target.
-- /dev/sdb 는 부팅 초기에 이미 있는 장치다.
-- 커널이 만든 장치 파일이라 udev 를 기다리지 않는다.
-- blkid rc=2 : sdb 에 파일 시스템이 없다.
-- 마운트는 실패할 것이다.

 [11] 오류 흐름 — emergency 와 rescue 를 구분하지 못함
--------------------------------------------------------------------------------
-- 세 번의 셸을 나란히 놓는다.
--
--  항목             장애 A(자동 emergency)  [9](요청 emergency)  B'·[변형](rescue)
--  화면 첫 줄       Welcome to emergency    Welcome to emerg…    Welcome to rescue
--  루트             rw                      ro                   rw
--  /boot            붙음                    안 붙음              붙음
--  local-fs.target  없음(실패)              없음                 active
--  sshd·network     inactive                -                    inactive
--  활성 타깃 수     17                      -                    6
--
-- 자동 emergency 는 local-fs 단계에서 실패했다.
-- 그래서 루트가 이미 rw 였다.
-- 요청한 emergency 는 루트를 ro 로만 붙인다.
-- 고치려면 remount 가 먼저다.
-- 증상   : 콘솔에 "Give root password for maintenance" 가 떴다는 것만 보고 같은 상황으로 판단
-- 원인   : emergency 와 rescue 는 sulogin 화면이 같아 첫 줄을 놓치면 구분이 안 된다
-- 조치   : 첫 줄(Welcome to …)과 findmnt -no OPTIONS /, list-units -t target 으로 확인
-- 재확인 : emergency 는 local-fs.target 이 없고, rescue 는 local-fs.target 이 active
