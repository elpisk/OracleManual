================================================================================
 제20장 실습 01 — root 암호 분실 복구 (rd.break)
 대상   : ol7a (직렬 콘솔 ttyS0 으로 진행)
 목표   : root 암호를 모르는 상태를 만들고, GRUB 에서 rd.break 를 붙여 initramfs 셸로
          들어가 /sysroot 를 쓰기 가능으로 다시 마운트·chroot 해 암호를 바꾼다.
          .autorelabel 을 빠뜨렸을 때 무엇이 막히는지 보고 다시 고친다
 배경   : rd.break 는 dracut 이 실제 루트로 넘어가기(switch_root) 직전에 셸을 준다. 이
          시점의 실제 루트는 /sysroot 에 읽기 전용으로 붙어 있고 systemd 는 아직 뜨지
          않았다. 그래서 root 암호를 묻지 않는다. 대신 SELinux 정책도 아직 올라오지
          않아 이때 새로 쓴 /etc/shadow 에는 보안 레이블이 붙지 않는다. 기본 상태
          (enforcing)를 그대로 둔 서버라 다음 부팅에서 전체 레이블을 다시 붙이는
          /.autorelabel 이 필요하다 (본문 20.5)
 소요   : 약 30분
 선행   : pre-break 스냅샷. 직렬 콘솔 캡처 설정(console=ttyS0,115200)이 기준 상태에 있다
 계정   : root
 주의   : root 암호를 한 번 임의 값으로 바꾼다(분실 상황 흉내). 끝에서 oracle 로 되돌린다
 되돌림 : root 암호 oracle, /.autorelabel 없음 → SSH 로 root/oracle 접속,
          ls -Z /etc/shadow 의 형식이 [0] 과 같음

--------------------------------------------------------------------------------
 [0] 시작 전 상태 기록
--------------------------------------------------------------------------------

-- shadow 의 root 줄에서 해시 앞부분만 본다.
-- cut -c1-24 로 24자에서 잘랐다.
-- 해시 전체를 화면에 남기지 않는다.
[root@ol7a ~]# grep '^root:' /etc/shadow | cut -c1-24; chage -l root | head -1
root:$6$5Cdlp2/WVWJJT7nO
-- 필드는 콜론으로 나뉜다.
-- 이름 : 해시 : 마지막 변경일 …
-- $6$ 는 SHA-512 해시.
-- 다음 $ 까지가 솔트(5Cdlp2/WVWJJT7nO).
Last password change                                    : never
-- 설치 때 넣은 암호라 변경일 기록이 never 다.
-- ls -Z 의 네 번째 열이 보안 레이블이다.
-- 이 실습은 레이블을 다루지 않는다.
-- 복구가 맞게 됐는지 보는 기준으로만 쓴다.
[root@ol7a ~]# ls -Z /etc/shadow; getenforce; ls -la /.autorelabel 2>&1
----------. root root system_u:object_r:shadow_t:s0    /etc/shadow
Enforcing
ls: cannot access /.autorelabel: No such file or directory
-- 권한 열이 모두 - 다.
-- 누구에게도 권한이 없고 root 만 예외로 읽는다.
-- 레이블 열은 system_u:object_r:shadow_t:s0.
-- 끝의 점(.)은 레이블이 붙은 파일 표시.
-- 기본 상태 그대로 Enforcing,
-- /.autorelabel 은 없다.
-- console=tty0 console=ttyS0,115200 은 랩 콘솔 캡처용 설정이다.
-- 마지막 console= 이 /dev/console 이 되므로 rd.break 셸이 ttyS0 에 뜬다.
[root@ol7a ~]# cat /proc/cmdline
BOOT_IMAGE=/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64 root=/dev/mapper/ol-root ro crashkernel=auto rd.lvm.lv=ol/root rd.lvm.lv=ol/swap rhgb quiet console=tty0 console=ttyS0,115200 scsi_mod.scan=sync
-- 볼 것은 root=/dev/mapper/ol-root ro.
-- 루트는 처음에 읽기 전용으로 붙는다.
-- rd.lvm.lv 두 개는 initramfs 가 켤 LV 이름이다.

-- 프롬프트 switch_root:/# 가 rd.break 셸이다.
-- dracut 은 이 셸을 emergency mode 라고 부른다.
-- root 암호를 묻지 않았다.
-- rdsosreport.txt 는 dracut 의 진단 자료다.
-- 장애 보고 때 붙인다.
-- 지금 / 는 initramfs(메모리)다.
-- 실제 루트는 /sysroot 에 있다.
cat /proc/cmdline | tr ' ' '\n' | tail -2
sh: tail: command not found
-- initramfs 에는 꼭 필요한 명령만 들어 있다.
-- tail 이 없다.
-- 이 셸에서는 cat·mount·ls·chroot 정도만 믿는다.
switch_root:/# 
mount | grep -E ' /sysroot | / '
none on / type rootfs (rw)
/dev/mapper/ol-root on /sysroot type xfs (ro,relatime,attr2,inode64,logbufs=8,logbsize=32k,noquota)

-- 실제 루트 ol-root 는 /sysroot 에 ro 로 붙어 있다.
-- 옵션의 첫 단어 ro 가 [5] 오류의 원인이다.
switch_root:/#

 [5] 오류 흐름 — 읽기 전용 /sysroot 에서 passwd
--------------------------------------------------------------------------------

-- 바로 chroot 해서 암호를 바꿔 본다.
-- chroot /sysroot 는 /sysroot 를 / 로 삼는 셸을 연다.
-- 디스크의 passwd 를 쓰려는 것이다.
-- passwd --stdin 은 표준 입력에서 새 암호를 읽는다(콘솔 자동화용).
chroot /sysroot
sh-4.2# 
echo oracle | passwd --stdin root
Changing password for user root.
passwd: Authentication token manipulation error
-- 메시지만으로는 원인이 보이지 않는다.
sh-4.2# 
touch /etc/x; exit
touch: cannot touch ‘/etc/x’: Read-only file system
-- touch 로 확인하니 Read-only file system 이다.
-- passwd 는 /etc/nshadow 를 만든 뒤 바꿔치기하는데 그 쓰기가 막혔다.
-- 증상   : "passwd: Authentication token manipulation error"
-- 원인   : /sysroot 가 ro 로 붙어 있어 /etc/shadow 를 새로 쓸 수 없다(touch 가 Read-only file system)
-- 조치   : chroot 를 나와 mount -o remount,rw /sysroot 뒤 다시 chroot 해서 passwd
-- 재확인 : passwd 가 all authentication tokens updated successfully, 해시의 솔트가 바뀜
exit
switch_root:/#

 [변형] passwd 대신 chpasswd 로 다시 설정

-- 같은 chroot 안에서 chpasswd 로 한 번 더 바꾼다.
-- 이름:암호 형식은 [1] 과 같다.
-- 여러 계정을 한 번에 바꿀 때 쓴다.
grep '^root:' /etc/shadow | cut -c1-24; echo 'root:oracle' | chpasswd; g 
rep '^root:' /etc/shadow | cut -c1-24
-- 명령이 g 와 rep 사이에서 끊겨 보인다.
-- 콘솔이 80자에서 줄을 바꿔 되돌려 보낸 화면이다.
-- 실행된 명령은 한 줄이다.

root:$6$AWgmM/HFge5/bU2$
-- 위가 passwd 의 결과(솔트 8자 TZYpVWOS),
-- 아래가 chpasswd 결과.
-- 둘 다 $6$(SHA-512).
-- chpasswd 쪽 솔트가 16자(AWgmM/HFge5/bU2)로 더 길다.
-- 형식이 같으니 로그인에는 차이가 없다.
