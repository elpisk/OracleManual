================================================================================
 제11장 실습 05 — xfsdump 와 xfsrestore
 대상   : ol7a
 목표   : 레벨 0·1 덤프를 파일로 뜨고 인벤토리(xfsdump -I)를 읽는다. 파일 시스템을
          새로 만든 뒤 레벨 0 → 1 순서로 누적 복원(-r)하고, 레벨 1 만으로 복원하면
          무엇이 빠지는지 본다. 파일 하나 복원(-s)과 대화형 복원(-i)도 해 본다
 배경   : xfsdump 는 XFS 를 inode 순서로 읽어 덤프 스트림을 만든다. 레벨 0 은 전체,
          레벨 N 은 그보다 낮은 마지막 레벨 이후 바뀐 것만 담는다. 어떤 덤프를
          언제 떴는지는 /var/lib/xfsdump/inventory 에 남는다. 덤프는 마운트된
          파일 시스템에서 뜬다 (본문 11.7)
 소요   : 약 25분
 선행   : storage-clean 스냅샷. 인터넷(yum.oracle.com) — xfsdump 가 없으면 설치
 계정   : root
 주의   : [7] 에서 원본 파일 시스템을 mkfs 로 지운다. 덤프 파일이 다른 디스크(sdc)에
          있는지 먼저 확인한다
 되돌림 : 마운트 해제, wipefs, 인벤토리 디렉터리 삭제.
          lsblk -f /dev/sdb /dev/sdc 가 비어 있고 xfsdump -I 가 빈 목록이면 끝
================================================================================

 [1] 원본과 백업 장소 준비

-- 원본은 sdb 의 /src, 덤프 파일은 다른 디스크 sdc 의 /backup 에 둔다.
-- 원본을 지우는 실습이라 같은 디스크에 두면 덤프도 같이 사라진다.
[root@ol7a ~]# mkfs.xfs -q -L src /dev/sdb; mkfs.xfs -q -L backup /dev/sdc; mkdir -p /src /backup; mount /dev/sdb /src; mount /dev/sdc /backup

 [2] 레이블 없이 덤프 — 오류 ①
--------------------------------------------------------------------------------

-- 덤프에는 세션 레이블(-L)과 미디어 레이블(-M)이 있다. 둘 다 주지 않고 친다.
--   -l 0  레벨 0(전체)
--   -f    덤프 대상(파일·테이프 장치)
-- 먼저 cron 처럼 터미널 없이 돌린다. 표준 입력은 /dev/null 이다.
[root@ol7a ~]# timeout 60 xfsdump -l 0 -f /backup/nolabel.dump /src 2>&1 | grep -i -E 'label|warning|Status'; echo "rc=${PIPESTATUS[0]}"
 ============================= dump label dialog ==============================
please enter label for this dump session (timeout in 300 sec)
session label entered: ""
xfsdump: WARNING: no session label specified
xfsdump: session label: ""
 ============================= media label dialog =============================
please enter label for media in drive 0 (timeout in 300 sec)
media label entered: ""
xfsdump: WARNING: no media label specified
xfsdump:   stream 0 /backup/nolabel.dump OK (success)
xfsdump: Dump Status: SUCCESS
rc=0
-- 터미널이 없으니 질문 상자를 띄우고 바로 빈 값을 받았다
--   dump label dialog → session label entered: ""
--   media label dialog → media label entered: ""
-- WARNING 두 줄을 남기고 덤프는 SUCCESS
-- cron 에서 돌면 이렇게 빈 레이블 덤프가 쌓인다

-- 이번에는 사람이 터미널에서 치는 경우다. script 가 가상 터미널(pty)을 만들어 준다.
-- 질문이 나오면 답할 줄 두 개를 미리 넣고, 10초 동안 입력을 열어 둔다.
[root@ol7a ~]# (printf 'tty_session\ntty_media\n'; sleep 10) | timeout 60 script -qc 'xfsdump -l 0 -f /backup/tty.dump /src' /dev/null | tr -d '\r' | grep -i -E 'please enter|label|Status' | cut -c1-110
[ol7lab: 120초 시간 제한 초과]
-- 증상   : 터미널(pty)에서는 질문을 띄우고 기다린다. 120초 안에 끝나지 않았다
-- 원인   : -L·-M 이 없어 xfsdump 가 레이블을 묻는다. 질문마다 timeout in 300 sec
--          미리 넣은 답 가운데 세션 레이블만 받아들이고 미디어 질문에서 멈췄다
-- 조치   : 덤프마다 -L 세션레이블 -M 미디어레이블 을 준다([3])
-- 재확인 : [3] 이 질문 없이 Dump Status: SUCCESS 로 끝난다
-- 이 줄은 러너의 시간 제한 표시다. 남은 xfsdump 는 pkill 로 정리했다
[root@ol7a ~]# ls -l /backup/; xfsdump -I | grep -E 'session label|media label'
total 48428
-rw-r--r--. 1 root root 49586288 Nov 16 15:49 nolabel.dump
-rw-r--r--. 1 root root        0 Nov 16 15:49 tty.dump
                session label:  ""
                                media label:    ""
                session label:  "tty_session
-- nolabel.dump 는 49586288 바이트로 완성
-- tty.dump 는 0 바이트. 덤프가 시작도 못 했다
-- 인벤토리에는 빈 레이블 세션과
--   tty_session 세션이 남았다(따옴표가 닫히지 않은 채)
-- 다음 단계 첫 명령이 이 흔적을 모두 지운다

 [9] 누적 복원 — 레벨 0 다음 레벨 1

 [10] 파일 하나만 — -s 와 대화형 -i

-- -s 는 덤프 안의 상대 경로 하나만 꺼낸다. 원래 자리가 아니라 /tmp/one 에 푼다.
[root@ol7a ~]# mkdir -p /tmp/one; xfsrestore -f /backup/src_L0.dump -s etc/hosts /tmp/one 2>&1 | tail -2; find /tmp/one -type f
xfsrestore:   stream 0 /backup/src_L0.dump OK (success)
xfsrestore: Restore Status: SUCCESS
/tmp/one/etc/hosts
