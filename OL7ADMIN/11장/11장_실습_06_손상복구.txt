 제11장 실습 06 — 손상 복구
 대상   : ol7a
 목표   : 언마운트 상태에서 xfs_repair -n 으로 검사하고, xfs_db 로 디렉터리 inode 와
          주 슈퍼블록을 일부러 망가뜨린 뒤 xfs_repair 로 고친다. 로그가 더러운
          파일 시스템에서 xfs_repair 가 거부하는 이유와 -L 이 무엇을 버리는지
          본다. xfs_fsr 로 조각난 파일을 모은다
 배경   : XFS 는 마운트할 때 로그를 재생해 일관성을 맞춘다. 그래서 부팅 때 fsck
          단계가 사실상 없다(fsck.xfs 는 -f 없이는 검사하지 않는다). 메타데이터 자체가
          깨졌을 때만 xfs_repair 를 언마운트 상태에서 돌린다. 로그를 재생할 수 없으면
          -L 로 로그를 지우는데, 그 안의 변경은 사라진다 (본문 11.8)
 소요   : 약 30분
 선행   : storage-clean 스냅샷
 계정   : root
 주의   : xfs_db -x 는 실습 디스크 sdb·sdc 에서만 쓴다. sda(OS 디스크, VG ol)의
          장치 이름을 절대 넣지 않는다. 명령마다 장치 이름을 두 번 확인한다
 되돌림 : 마운트 해제, wipefs. lsblk -f /dev/sdb /dev/sdc 가 비어 있으면 끝

--------------------------------------------------------------------------------
 [4] 디렉터리 inode 망가뜨리기 — xfs_db -x
--------------------------------------------------------------------------------

-- xfs_db 는 XFS 디버거다. -r 은 읽기 전용, -x 는 쓰기를 허용하는 전문가 모드다.
-- 먼저 -r 로 dir1 의 inode 를 읽어 core.magic 과 core.mode 를 본다.
[root@ol7a ~]# mount /dev/sdb1 /rep; ls -di /rep/dir1 | tee /root/dir1.ino; umount /rep
131 /rep/dir1
[root@ol7a ~]# xfs_db -r -c "inode $(awk '{print $1}' /root/dir1.ino)" -c 'print core.magic core.mode core.nlinkv2 core.size' /dev/sdb1
core.magic = 0x494e
core.mode = 040755
core.nlinkv2 = 2
core.size = 76
-- core.magic 0x494e = "IN"(inode 표시)
-- mode 040755: 디렉터리, 권한 755
-- nlinkv2 2: . 과 부모의 항목
-- size 76: 짧은 디렉터리(inode 안에 항목)

-- magic(IN 을 뜻하는 0x494e)을 0 으로 덮어쓴다. inode 가 inode 로 보이지 않게 된다.
[root@ol7a ~]# xfs_db -x -c "inode $(awk '{print $1}' /root/dir1.ino)" -c 'write core.magic 0' /dev/sdb1
core.magic = 0
-- -x 쓰기 모드에서 magic 을 0 으로 썼다
-- 실제 장애라면 디스크·컨트롤러 오류다

 [8] 더러운 로그 — 오류 ②
--------------------------------------------------------------------------------

-- 전원이 갑자기 나간 상황을 흉내 낸다. xfs_io 의 shutdown 은 파일 시스템을
-- 즉시 멈춰 그 뒤로 어떤 쓰기도 디스크에 가지 않게 한다. -f 를 주지 않으면
-- 로그를 먼저 비우지 않는다.
-- 표본: before.txt 는 sync 로 확실히 내리고, after 파일 20개는 만든 직후 로그만
-- 디스크에 강제(sync)한 뒤 곧바로 멈춘다.
[root@ol7a ~]# echo before > /rep/before.txt; sync; sleep 35; mkdir /rep/after; for i in $(seq 1 20); do echo $i > /rep/after/a$i; done; sync; xfs_io -x -c shutdown /rep; echo "rc=$?"
rc=0
-- 마지막 동기화 뒤의 변경은 없다
-- shutdown: 파일 시스템을 강제 정지
--   로그를 디스크에 내리지 않고 멈춘다
--   전원이 나간 것과 비슷한 상태
-- 두 번째 sync 는 로그를 디스크에 썼다
--   제자리 반영(체크포인트)은 아직이다
-- 그래서 로그 재생이 필요한 상태가 된다
[root@ol7a ~]# ls /rep; echo "rc=$?"; dmesg | tail -3

-- 조각난 파일을 일부러 만든다. 두 파일에 4KB 씩 번갈아, 뒤에서부터 쓰고 매번 fsync 한다.
[root@ol7a ~]# for i in $(seq 200 -1 1); do xfs_io -f -c "pwrite -q $((i*4))k 4k" -c fsync /rep/frag1; xfs_io -f -c "pwrite -q $((i*4))k 4k" -c fsync /rep/frag2; done; ls -l /rep/frag1

--   0 번 블록은 쓰지 않아 구멍
[root@ol7a ~]# xfs_bmap /rep/frag1 | wc -l; xfs_bmap -v /rep/frag1 | head -6
