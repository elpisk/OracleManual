================================================================================
 제13장 실습 01 — 현재 네트워크 구성 읽기
 대상   : ol7a
 목표   : ip·nmcli 출력과 ifcfg·hosts·resolv.conf·nsswitch.conf 를 한 줄씩 읽어
          "지금 이 서버의 네트워크가 어떻게 잡혀 있는가"를 설명할 수 있게 한다
 배경   : OL 7.9 의 네트워크 구성은 세 층으로 나뉜다. 커널이 실제로 쓰는 값(ip),
          NetworkManager 가 관리하는 연결 프로필(nmcli), 그 프로필이 저장되는
          /etc/sysconfig/network-scripts/ifcfg-* 파일이다. 이름 해석은 nsswitch.conf
          가 순서를 정하고 /etc/hosts·resolv.conf 가 실제 값을 준다 (본문 13.2·13.3·13.5)
 소요   : 약 30분
 선행   : ol7-base 스냅샷
 계정   : root
 주의   : [8] 에서 net-tools 를 지웠다 다시 설치하고 [10] 에서 resolv.conf 를 고친다. 끝에서 모두 되돌린다
 되돌림 : net-tools 설치 상태, resolv.conf 원래 내용 → rpm -q net-tools, md5sum /etc/resolv.conf

--------------------------------------------------------------------------------
 [1] 장치 목록 — ip link
--------------------------------------------------------------------------------

-- ip link 는 L2(링크) 계층만 본다. 주소는 나오지 않는다.
-- 장치가 몇 개인지, 링크가 살아 있는지, MAC 이 무엇인지 확인하는 첫 명령이다.
[root@ol7a ~]# ip link show
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN mode DEFAULT group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
2: ens32: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 00:0c:29:ac:5e:a0 brd ff:ff:ff:ff:ff:ff
3: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP mode DEFAULT group default qlen 1000
    link/ether 00:0c:29:ac:5e:aa brd ff:ff:ff:ff:ff:ff
-- 장치마다 두 줄이다. 첫 줄의 필드
--   2:                 장치 번호(ifindex). 부팅 때 생긴 순서
--   ens32:             장치 이름
--   <...UP,LOWER_UP>   플래그. UP 은 관리자가 올린 상태, LOWER_UP 은 물리 링크(반송파)가 살아 있는 상태
--   mtu 1500           한 번에 보낼 수 있는 최대 프레임 크기
--   qdisc pfifo_fast   송신 대기열 방식
--   state UP           링크 상태. lo 는 UNKNOWN 으로 나오는 것이 정상이다
--   qlen 1000          송신 대기열 길이
-- 둘째 줄 link/ether 는 MAC 주소, brd 는 브로드캐스트 주소다
-- ens32 의 MAC 은 …5e:a0, ens33 은 …5e:aa. 실습 04 에서 본드가 이 둘 중 하나를 쓴다
-- ens33 도 UP,LOWER_UP 이다. 주소가 없을 뿐 링크는 살아 있다

--------------------------------------------------------------------------------
 [2] 주소 — ip addr
--------------------------------------------------------------------------------

-- ip addr 는 ip link 의 내용에 L3(주소) 줄을 더한다.
-- -4 는 IPv4 줄만, 장치 이름을 붙이면 그 장치만 보인다.
[root@ol7a ~]# ip addr show ens32
2: ens32: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP group default qlen 1000
    link/ether 00:0c:29:ac:5e:a0 brd ff:ff:ff:ff:ff:ff
    inet 172.16.225.61/24 brd 172.16.225.255 scope global noprefixroute ens32
       valid_lft forever preferred_lft forever
    inet6 fe80::87f4:d993:7b43:e0c1/64 scope link noprefixroute 
       valid_lft forever preferred_lft forever
-- inet 줄의 필드
--   172.16.225.61/24      주소와 접두사 길이(넷마스크 255.255.255.0)
--   brd 172.16.225.255    브로드캐스트 주소
--   scope global          밖으로 쓰는 주소. 링크 로컬은 scope link
--   noprefixroute         커널이 이 주소로 연결 경로를 자동으로 만들지 않음. NetworkManager 가 경로를 따로 넣는다
-- valid_lft·preferred_lft forever 는 고정 주소라는 뜻이다. DHCP 주소는 남은 초가 나온다(실습 02 [변형])
-- inet6 fe80:: 는 IPv6 링크 로컬 주소다. ifcfg 의 IPV6INIT=yes 때문에 생겼다

[root@ol7a ~]# ip addr show ens33
3: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP group default qlen 1000
    link/ether 00:0c:29:ac:5e:aa brd ff:ff:ff:ff:ff:ff
-- ens33 은 inet 줄이 없다. 두 줄로 끝난다

-- -br(brief) 는 한 장치를 한 줄로 줄인다. 장치가 많을 때 먼저 친다.
[root@ol7a ~]# ip -br link; ip -br addr
lo               UNKNOWN        00:00:00:00:00:00 <LOOPBACK,UP,LOWER_UP> 
ens32            UP             00:0c:29:ac:5e:a0 <BROADCAST,MULTICAST,UP,LOWER_UP> 
ens33            UP             00:0c:29:ac:5e:aa <BROADCAST,MULTICAST,UP,LOWER_UP> 
-- 열은 이름, 상태, (link 는 MAC·플래그) / (addr 는 주소 목록) 순이다
-- 위 세 줄이 ip -br link, 아래 세 줄이 ip -br addr 이다. ens33 의 주소 칸이 비어 있다
lo               UNKNOWN        127.0.0.1/8 ::1/128 
ens32            UP             172.16.225.61/24 fe80::87f4:d993:7b43:e0c1/64 
ens33            UP             

--------------------------------------------------------------------------------
 [3] 경로 — ip route
--------------------------------------------------------------------------------

-- 기본 경로(default)가 없으면 같은 서브넷 밖으로 나가지 못한다. 실습 05 의 주제다.
[root@ol7a ~]# ip route show
default via 172.16.225.2 dev ens32 proto static metric 100 
172.16.225.0/24 dev ens32 proto kernel scope link src 172.16.225.61 metric 100 
-- 두 줄의 필드
--   default via 172.16.225.2   기본 경로. 다른 경로에 걸리지 않는 모든 목적지는 게이트웨이 .2 로
--   dev ens32                  내보낼 장치
--   proto static               NetworkManager 가 고정 설정(GATEWAY)으로 넣은 경로
--   proto kernel scope link    같은 서브넷으로 가는 연결 경로. 게이트웨이 없이 바로 보낸다
--   src 172.16.225.61          이 경로로 나갈 때의 출발 주소
--   metric 100                 같은 목적지 경로가 여럿일 때 작은 값이 우선. NetworkManager 이더넷 기본값

-- ip route get 은 "이 목적지로 보내면 어느 장치·어느 출발 주소를 쓰는가"를 커널에 묻는다.
-- 경로 표를 눈으로 따라가는 대신 커널의 판단을 그대로 본다.
[root@ol7a ~]# ip route get 172.16.225.62; ip route get 8.8.8.8
172.16.225.62 dev ens32 src 172.16.225.61 uid 0 
    cache 
8.8.8.8 via 172.16.225.2 dev ens32 src 172.16.225.61 uid 0 
    cache 
-- 같은 서브넷인 ol7b(.62)는 via 없이 ens32 로 바로, 8.8.8.8 은 via 172.16.225.2 로 나간다
-- uid 0 은 이 질의를 root 가 했다는 표시다

--------------------------------------------------------------------------------
 [4] NetworkManager 가 보는 장치 — nmcli device
--------------------------------------------------------------------------------

-- nmcli general 은 NetworkManager 자체의 상태다. 데몬이 떠 있지 않으면 이후 nmcli 명령이 모두 실패한다.
[root@ol7a ~]# systemctl is-active NetworkManager; nmcli general status
active
STATE      CONNECTIVITY  WIFI-HW  WIFI     WWAN-HW  WWAN    
connected  full          enabled  enabled  enabled  enabled 
-- STATE connected 는 활성 연결이 하나 이상 있다는 뜻이다
-- CONNECTIVITY full 은 인터넷까지 닿는다는 판정이다. 게이트웨이가 없으면 limited 나 none 이 된다
-- WIFI·WWAN 열은 이 서버에 무선 장치가 없어 의미가 없다

-- nmcli device 는 커널 장치를 NetworkManager 의 눈으로 다시 본 것이다.
[root@ol7a ~]# nmcli device status
DEVICE  TYPE      STATE         CONNECTION 
ens32   ethernet  connected     ens32      
ens33   ethernet  disconnected  --         
lo      loopback  unmanaged     --         
-- ens32 connected(연결 ens32 가 걸림), ens33 disconnected(관리하지만 연결 없음), lo unmanaged(관리 안 함)
-- ens33 이 disconnected 인 이유는 프로필 ens33 의 ONBOOT=no 다. [7] 에서 확인한다

--------------------------------------------------------------------------------
 [5] 연결 프로필 — nmcli connection
--------------------------------------------------------------------------------

-- 장치(device)와 연결(connection)은 다르다. 연결은 "이 장치에 이 설정을 입힌다"는 프로필이다.
-- 한 장치에 연결 여러 개를 만들어 두고 골라 쓸 수 있다.
[root@ol7a ~]# nmcli connection show
NAME   UUID                                  TYPE      DEVICE 
ens32  987096e5-6a52-4e8e-bce9-5978c9bb9f51  ethernet  ens32  
ens33  09e33476-a93c-4005-a933-74479920bb5b  ethernet  --     
-- NAME 은 프로필 이름, UUID 는 프로필 고유 ID, DEVICE 는 지금 걸린 장치다
-- 프로필 ens33 은 있지만 DEVICE 가 -- 다. 프로필이 있는 것과 활성화된 것은 다르다

-- 특정 연결의 속성 전체는 200줄이 넘는다. -f 로 ipv4 와 connection 묶음만 고른다.
-- -f(fields) 는 보고 싶은 속성 묶음이나 속성 이름을 쉼표로 준다.
[root@ol7a ~]# nmcli -f connection.id,connection.uuid,connection.interface-name,connection.autoconnect,ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns,ipv4.never-default connection show ens32
connection.id:                          ens32
connection.uuid:                        987096e5-6a52-4e8e-bce9-5978c9bb9f51
connection.interface-name:              ens32
connection.autoconnect:                 yes
ipv4.method:                            manual
ipv4.addresses:                         172.16.225.61/24
ipv4.gateway:                           172.16.225.2
ipv4.dns:                               172.16.225.2
ipv4.never-default:                     no
-- 소문자 속성은 프로필에 저장된 설정값이다. 지금 장치에 걸린 값은 대문자 IP4.* 묶음이다
-- connection.interface-name ens32 가 이 프로필을 장치 ens32 에 묶는다
-- ipv4.method manual 은 고정 주소. DHCP 면 auto 다
-- ipv4.never-default no 는 이 연결의 게이트웨이를 기본 경로로 쓴다는 뜻이다(ifcfg 의 DEFROUTE=yes)

--------------------------------------------------------------------------------
 [6] 연결 프로필이 저장된 파일 — ifcfg-ens32
--------------------------------------------------------------------------------

-- OL 7.9 의 NetworkManager 는 ifcfg-rh 플러그인으로 /etc/sysconfig/network-scripts 의 ifcfg 파일을 읽고 쓴다.
-- [5] 의 nmcli 값과 이 파일의 키가 짝을 이룬다.
[root@ol7a ~]# grep -v '^#' /etc/NetworkManager/NetworkManager.conf | grep -v '^$'
[main]
[logging]
-- NetworkManager.conf 에는 묶음 이름 두 줄뿐이다. 나머지는 모두 기본값이다
-- 기본값 전체는 NetworkManager --print-config 로 본다(실습 03 [1]). plugins=ifcfg-rh 가 거기 있다
[root@ol7a ~]# ls -l /etc/sysconfig/network-scripts/ifcfg-*
-rw-r--r--. 1 root root 366 Nov 11 19:49 /etc/sysconfig/network-scripts/ifcfg-ens32
-rw-r--r--. 1 root root 279 Nov 11 19:49 /etc/sysconfig/network-scripts/ifcfg-ens33
-rw-r--r--. 1 root root 254 May 22  2020 /etc/sysconfig/network-scripts/ifcfg-lo
-- 장치마다 ifcfg 파일 하나. lo 파일의 날짜는 initscripts 패키지 시각이고, ens32·ens33 은 설치한 날이다

[root@ol7a ~]# cat /etc/sysconfig/network-scripts/ifcfg-ens32
TYPE=Ethernet
PROXY_METHOD=none
BROWSER_ONLY=no
BOOTPROTO=none
DEFROUTE=yes
IPV4_FAILURE_FATAL=no
IPV6INIT=yes
IPV6_AUTOCONF=yes
IPV6_DEFROUTE=yes
IPV6_FAILURE_FATAL=no
IPV6_ADDR_GEN_MODE=stable-privacy
NAME=ens32
UUID=987096e5-6a52-4e8e-bce9-5978c9bb9f51
DEVICE=ens32
ONBOOT=yes
IPADDR=172.16.225.61
PREFIX=24
GATEWAY=172.16.225.2
DNS1=172.16.225.2
IPV6_PRIVACY=no
-- 20개 키 가운데 이 실습에서 볼 것
--   BOOTPROTO=none            고정 주소 ↔ ipv4.method manual
--   DEFROUTE=yes              기본 경로로 씀 ↔ ipv4.never-default no
--   NAME / UUID / DEVICE      ↔ connection.id / connection.uuid / connection.interface-name
--   ONBOOT=yes                ↔ connection.autoconnect yes
--   IPADDR / PREFIX           ↔ ipv4.addresses 172.16.225.61/24
--   GATEWAY / DNS1            ↔ ipv4.gateway / ipv4.dns
-- PROXY_METHOD·BROWSER_ONLY·IPV6_* 는 NetworkManager 가 쓴 기본값이다
-- HWADDR 키는 없다. 이 프로필은 MAC 이 아니라 이름(DEVICE)으로 장치를 찾는다(실습 07)

--------------------------------------------------------------------------------
 [7] 쉬고 있는 두 번째 NIC — ifcfg-ens33
--------------------------------------------------------------------------------

-- 두 파일을 나란히 비교한다. --suppress-common-lines 는 같은 줄을 숨긴다.
[root@ol7a ~]# diff -y -W 90 --suppress-common-lines /etc/sysconfig/network-scripts/ifcfg-ens32 /etc/sysconfig/network-scripts/ifcfg-ens33
BOOTPROTO=none                              |   BOOTPROTO=dhcp
NAME=ens32                                  |   NAME=ens33
UUID=987096e5-6a52-4e8e-bce9-5978c9bb9f51   |   UUID=09e33476-a93c-4005-a933-74479920bb5b
DEVICE=ens32                                |   DEVICE=ens33
ONBOOT=yes                                  |   ONBOOT=no
IPADDR=172.16.225.61                        <
PREFIX=24                                   <
GATEWAY=172.16.225.2                        <
DNS1=172.16.225.2                           <
IPV6_PRIVACY=no                             <
-- | 는 양쪽이 다른 줄, < 는 왼쪽(ens32)에만 있는 줄이다
-- ens33 은 BOOTPROTO=dhcp, ONBOOT=no. 설치 때 두 번째 NIC 를 켜지 않아 기본값 그대로 남았다
-- 주소·게이트웨이·DNS 키가 ens33 에는 없다. DHCP 라 받을 값이기 때문이다

--------------------------------------------------------------------------------
 [8] ifconfig 를 찾는 사람에게 — net-tools
--------------------------------------------------------------------------------

-- 예전 문서와 스크립트는 ifconfig·netstat·route 를 쓴다. 기준 VM 에는 net-tools 가 이미 있다([0] 의 rpm -q).
-- 최소 설치로 만든 서버를 흉내 내려고 패키지를 지운 뒤 같은 명령을 친다.
[root@ol7a ~]# yum -y -q remove net-tools; rpm -q net-tools
package net-tools is not installed
[root@ol7a ~]# ifconfig ens32
/tmp/_ol7lab_root.sh: line 1: ifconfig: command not found
-- 앞의 /tmp/_ol7lab_root.sh: line 1: 은 이 실습 러너가 명령을 스크립트로 넘겨 실행해서 붙은 접두어다
-- 터미널에서 직접 치면 bash: ifconfig: command not found 로 나온다
-- 오류 흐름
-- 증상   : ifconfig ens32 → ifconfig: command not found
-- 원인   : net-tools 패키지가 없다. 7.9 최소 설치에는 들어 있지 않고, 기본 도구는 iproute 의 ip 다
-- 조치   : yum provides 로 패키지를 찾고 yum install net-tools. 새 스크립트는 ip·ss 로 쓴다
-- 재확인 : rpm -q net-tools 가 버전을 찍고 ifconfig ens32 가 inet 172.16.225.61 을 보인다

-- 어느 패키지가 이 명령을 주는지 yum 에 묻는다. 경로에 와일드카드를 쓰면 bin·sbin 어디에 있든 찾는다.
[root@ol7a ~]# yum -q provides '*/sbin/ifconfig' 2>&1 | grep -E '^net-tools' | tail -2
net-tools-2.0-0.24.20131004git.el7.x86_64 : Basic networking tools
net-tools-2.0-0.25.20131004git.el7.x86_64 : Basic networking tools
-- 저장소에 판이 여럿 있어 tail -2 로 마지막 둘만 봤다. 0.25 가 최신이다

[root@ol7a ~]# yum -y -q install net-tools; rpm -q net-tools
net-tools-2.0-0.25.20131004git.el7.x86_64
-- -q 라 설치 과정은 찍히지 않았다. rpm -q 가 [0] 과 같은 0.25 를 보인다

-- ifconfig 는 9줄짜리 블록을 보인다. 앞 세 줄만 본다.
[root@ol7a ~]# ifconfig ens32 | head -3; route -n
ens32: flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  mtu 1500
        inet 172.16.225.61  netmask 255.255.255.0  broadcast 172.16.225.255
        inet6 fe80::87f4:d993:7b43:e0c1  prefixlen 64  scopeid 0x20<link>
Kernel IP routing table
Destination     Gateway         Genmask         Flags Metric Ref    Use Iface
0.0.0.0         172.16.225.2    0.0.0.0         UG    100    0        0 ens32
172.16.225.0    0.0.0.0         255.255.255.0   U     100    0        0 ens32
-- ifconfig 는 9줄짜리 블록 가운데 head -3 으로 세 줄만 봤다
--   flags=4163<UP,BROADCAST,RUNNING,MULTICAST>  RUNNING 이 ip 의 LOWER_UP 에 해당한다
--   inet ... netmask 255.255.255.0             ip 는 /24, ifconfig 는 넷마스크로 적는다
-- route -n 은 ip route 와 같은 표다. Flags U 는 쓸 수 있음, G 는 게이트웨이 경유
-- ifconfig 가 못 보여 주는 것도 있다
--   ip addr 의 noprefixroute·dynamic 같은 꼬리표
--   레이블 없이 넣은 보조 주소(ifconfig 는 ens33:1 같은 별칭만 보인다)
-- net-tools 는 2013년 스냅숏(20131004git)에서 멈춘 패키지다. 새 기능은 iproute 에만 들어간다

-- 같은 정보를 ip 로 보면 다음과 같다.
-- 대응표
--   ifconfig            → ip addr / ip -s link
--   ifconfig ens33 up   → ip link set ens33 up
--   route -n            → ip route
--   netstat -tlnp       → ss -tlnp

[root@ol7a ~]# ss -tlnp | head -4; ip neigh show dev ens32

 [9] 이름 해석 — nsswitch.conf, hosts, resolv.conf

-- 이름을 주소로 바꿀 때 어디를 어떤 순서로 볼지는 nsswitch.conf 의 hosts 줄이 정한다.
[root@ol7a ~]# grep -E '^hosts' /etc/nsswitch.conf
hosts:      files dns myhostname
-- files(/etc/hosts) → dns(resolv.conf 의 서버) → myhostname(자기 이름) 순서로 묻는다

[root@ol7a ~]# cat /etc/hosts
127.0.0.1   localhost localhost.localdomain localhost4 localhost4.localdomain4

-- 한 줄에 주소, 정식 이름, 별칭 순이다. 두 노드 이름은 DNS 서버가 아니라 이 파일에만 있다

[root@ol7a ~]# cat /etc/resolv.conf
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
-- 첫 줄 Generated by NetworkManager 가 이 파일을 누가 썼는지 알려 준다
-- search example.com 은 점 없는 이름 뒤에 붙여 볼 도메인, nameserver 는 DNS 서버(최대 3개)다

-- /etc/sysconfig/network 는 시스템 전체 네트워크 설정이다. 7.9 에서는 거의 비어 있다.
[root@ol7a ~]# cat /etc/sysconfig/network; hostnamectl status | grep -i hostname

-- getent hosts 는 nsswitch.conf 순서를 그대로 따라 해석한다. 응용 프로그램이 보는 결과와 같다.
[root@ol7a ~]# getent hosts ol7b; getent hosts yum.oracle.com

-- ol7b 는 /etc/hosts(files)에서, yum.oracle.com 은 DNS 에서 풀렸다
-- yum.oracle.com 은 IPv6 주소 둘이 나왔다. getent hosts 는 IPv6 를 먼저 묻는다
-- 두 번째 열은 CNAME 을 따라간 최종 이름(akamaiedge), 나머지는 별칭이다. 대소문자(.NET)는 DNS 응답 그대로다

--------------------------------------------------------------------------------
 [10] resolv.conf 를 손으로 고치면
--------------------------------------------------------------------------------

-- DNS 서버를 하나 더 넣고 싶어 resolv.conf 를 직접 고친 상황이다.
[root@ol7a ~]# cp -p /etc/resolv.conf /root/resolv.conf.orig
[root@ol7a ~]# echo 'nameserver 8.8.8.8' >> /etc/resolv.conf; cat /etc/resolv.conf
-- 파일 끝에 nameserver 8.8.8.8 이 붙었다. 이 순간부터 리졸버는 이 줄을 쓴다
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
nameserver 8.8.8.8

-- 연결을 다시 올린다. 운영 중에도 자주 일어나는 일이다(장애 조치, 재부팅, 케이블 재연결).
-- nmcli device reapply 는 IP 를 내리지 않고 프로필을 다시 적용한다. SSH 가 끊기지 않는다.
[root@ol7a ~]# nmcli device reapply ens32; sleep 2; cat /etc/resolv.conf
Connection successfully reapplied to device 'ens32'.
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
nameserver 8.8.8.8

[root@ol7a ~]# diff /root/resolv.conf.orig /etc/resolv.conf && echo SAME
3a4
> nameserver 8.8.8.8
-- reapply 뒤에도 손으로 넣은 줄이 살아 있다. reapply 는 DNS 설정이 바뀌지 않으면 파일을 다시 쓰지 않았다

-- NetworkManager 를 다시 시작한다. 패키지 업데이트나 재부팅 때마다 일어나는 일이다.
-- NetworkManager 재시작은 이미 걸린 IP 를 내리지 않는다(SSH 가 유지된다).
[root@ol7a ~]# systemctl restart NetworkManager; sleep 3; cat /etc/resolv.conf
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
[root@ol7a ~]# diff /root/resolv.conf.orig /etc/resolv.conf && echo SAME
-- 재시작 뒤 resolv.conf 가 원본과 같아졌다. 손으로 넣은 줄이 사라졌다
-- 오류 흐름
-- 증상   : resolv.conf 에 넣은 nameserver 8.8.8.8 이 systemctl restart NetworkManager 뒤 사라짐
-- 원인   : NetworkManager 가 활성 연결의 DNS(ipv4.dns=172.16.225.2)로 파일을 새로 썼다
-- 조치   : 프로필에 넣는다(nmcli connection modify ens32 +ipv4.dns 8.8.8.8). 손으로 관리하려면 [main] dns=none
-- 재확인 : 재시작·reapply 뒤에도 resolv.conf 에 8.8.8.8, ifcfg-ens32 에 DNS2=8.8.8.8
SAME

-- 영구적으로 넣으려면 프로필에 넣는다. ipv4.dns 는 ifcfg 의 DNS1·DNS2 키가 된다.
[root@ol7a ~]# nmcli connection modify ens32 +ipv4.dns 8.8.8.8
[root@ol7a ~]# nmcli device reapply ens32; sleep 2; cat /etc/resolv.conf; grep DNS /etc/sysconfig/network-scripts/ifcfg-ens32
Connection successfully reapplied to device 'ens32'.
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
nameserver 8.8.8.8
DNS1=172.16.225.2
DNS2=8.8.8.8
-- 이번에는 프로필에 들어갔다. resolv.conf 에 두 줄, ifcfg 에 DNS1·DNS2 가 생겼다
-- + 는 목록에 더하기다. + 없이 ipv4.dns 8.8.8.8 이라고 쓰면 172.16.225.2 가 지워진다

-- 원래대로. -ipv4.dns 로 그 값만 뺀다.
[root@ol7a ~]# nmcli connection modify ens32 -ipv4.dns 8.8.8.8; nmcli device reapply ens32; sleep 2; cat /etc/resolv.conf; grep DNS /etc/sysconfig/network-scripts/ifcfg-ens32
Connection successfully reapplied to device 'ens32'.
# Generated by NetworkManager
search example.com
nameserver 172.16.225.2
DNS1=172.16.225.2
-- - 로 그 값만 뺐다. DNS2 키가 없어지고 resolv.conf 도 원래 한 줄로 돌아왔다

-- 커널은 장치 정보를 /sys/class/net 아래 파일로도 내놓는다. 도구가 없어도 읽을 수 있다.
[root@ol7a ~]# for d in ens32 ens33; do echo "$d $(cat /sys/class/net/$d/address) operstate=$(cat /sys/class/net/$d/operstate) carrier=$(cat /sys/class/net/$d/carrier) mtu=$(cat /sys/class/net/$d/mtu)"; done
ens32 00:0c:29:ac:5e:a0 operstate=up carrier=1 mtu=1500
ens33 00:0c:29:ac:5e:aa operstate=up carrier=1 mtu=1500
-- /sys/class/net/장치/ 아래 address·operstate·carrier·mtu 파일이 ip link 의 값과 같다
-- carrier=1 이 LOWER_UP 에 해당한다. 도구가 하나도 없는 응급 셸에서도 읽을 수 있다
