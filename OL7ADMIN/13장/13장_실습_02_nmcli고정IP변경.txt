================================================================================
 제13장 실습 02 — nmcli 로 고정 IP 변경
 대상   : ol7a (ens33 에서 실험, 마지막에 ens32), ol7b (밖에서 확인)
 목표   : nmcli connection modify 로 고정 IP·자동 연결·보조 IP 를 넣고, ifcfg 파일이
          어떻게 바뀌는지 diff 로 본다. modify 만으로는 반영되지 않는다는 것과
          up·reapply 의 차이, SSH 가 붙은 인터페이스를 바꿨을 때의 복구를 확인한다
 배경   : nmcli connection modify 는 연결 프로필(디스크의 ifcfg 파일)만 바꾼다.
          커널에 적용하려면 nmcli connection up(연결을 다시 활성화) 이나
          nmcli device reapply(활성 상태를 유지한 채 다시 적용)가 필요하다. ip addr add 로
          넣은 주소는 프로필에 없으므로 다음 활성화 때 사라진다 (본문 13.3·13.4)
 소요   : 약 40분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : root
 주의   : [10] 에서 ens32 의 주소를 바꿔 SSH 가 끊긴다. 직렬 콘솔로 복구한다
 되돌림 : ifcfg-ens33 원본(ONBOOT=no, 주소 없음), ens32 172.16.225.61
          → md5sum ifcfg-ens3?, ip -br addr

--------------------------------------------------------------------------------
 [1] ens33 프로필의 현재 IPv4 설정
--------------------------------------------------------------------------------

-- 소문자 속성(ipv4.*)은 프로필에 저장된 설정값,
-- 대문자 속성(IP4.*)은 지금 장치에 적용된 값이다.
-- 연결이 활성화돼 있지 않으면 대문자 묶음은 나오지 않는다.
[root@ol7a ~]# nmcli -f connection.autoconnect,ipv4.method,ipv4.addresses,ipv4.gateway,ipv4.dns connection show ens33
connection.autoconnect:                 no
ipv4.method:                            auto
ipv4.addresses:                         --
ipv4.gateway:                           --
ipv4.dns:                               --
-- autoconnect no 가 ifcfg 의 ONBOOT=no,
-- ipv4.method auto 가 BOOTPROTO=dhcp 다
-- 주소·게이트웨이·DNS 는 비어 있다(--). DHCP 로 받을 값이기 때문이다
[root@ol7a ~]# nmcli -f GENERAL.STATE,IP4 connection show ens33
-- 아무것도 나오지 않았다. 연결이 활성화돼 있지 않으면 GENERAL·IP4 묶음은 없다

--------------------------------------------------------------------------------
 [2] 고정 IP 로 바꾼다 — connection modify
--------------------------------------------------------------------------------

-- ipv4.method manual 은 BOOTPROTO=none(고정)에 해당한다
-- 주소는 접두사 길이(/24)와 함께 준다.
-- 한 명령에 속성을 여러 개 이어 쓸 수 있다.
[root@ol7a ~]# nmcli connection modify ens33 ipv4.method manual ipv4.addresses 172.16.225.71/24

[root@ol7a ~]# diff /root/ifcfg-ens33 /etc/sysconfig/network-scripts/ifcfg-ens33
4c4
< BOOTPROTO=dhcp
---
> BOOTPROTO=none
15a16,17
> IPADDR=172.16.225.71
> PREFIX=24
-- modify 는 출력 없이 끝난다. 그 대신 ifcfg 가 바로 고쳐졌다
--   4c4       BOOTPROTO 가 dhcp → none
--   15a16,17  파일 끝에 IPADDR·PREFIX 두 줄 추가
-- NetworkManager 메모리와 디스크는 이미 새 값이다. 남은 것은 커널이다

--------------------------------------------------------------------------------
 [3] 오류 ① — 고쳤는데 주소가 없다
--------------------------------------------------------------------------------

[root@ol7a ~]# ip -4 addr show ens33; nmcli -f ipv4.addresses connection show ens33
ipv4.addresses:                         172.16.225.71/24
-- ip -4 addr show ens33 은 아무것도 찍지 않았다
-- 장치에는 IPv4 주소가 없다
-- 프로필 값은 172.16.225.71/24 다. 두 층이 어긋나 있다
[root@ol7a ~]# ping -c 2 -W 2 -I ens33 172.16.225.2
ping: Warning: source address might be selected on device other than ens33.
PING 172.16.225.2 (172.16.225.2) from 172.16.225.61 ens33: 56(84) bytes of data.

--- 172.16.225.2 ping statistics ---
2 packets transmitted, 0 received, 100% packet loss, time 1053ms
-- 경고 줄 source address might be selected on device other than ens33 이 핵심이다
-- -I ens33 은 장치만 묶을 뿐 출발 주소는 경로표로 고른다
-- 출발 주소가 172.16.225.61(ens32 의 것)이 됐다
-- ens33 에 주소가 없으니 어차피 응답을 받을 수 없다
-- 오류 흐름
-- 증상   : modify 뒤 ip -4 addr show ens33 이 비어 있고 ping -I ens33 이 100% packet loss
-- 원인   : nmcli connection modify 는 프로필·ifcfg 만 고친다. 장치에 반영하는 단계가 빠졌다
-- 조치   : nmcli connection up ens33 (또는 활성 연결이면 nmcli device reapply ens33)
-- 재확인 : ip -4 addr 에 inet 172.16.225.71/24, nmcli 의 GENERAL.STATE activated·IP4.ADDRESS[1]

--------------------------------------------------------------------------------
 [4] 반영 — connection up
--------------------------------------------------------------------------------

[root@ol7a ~]# nmcli connection up ens33
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/2)
[root@ol7a ~]# ip -4 addr show ens33; nmcli -f GENERAL.STATE,IP4.ADDRESS connection show ens33
3: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP group default qlen 1000
    inet 172.16.225.71/24 brd 172.16.225.255 scope global noprefixroute ens33
       valid_lft forever preferred_lft forever
GENERAL.STATE:                          activated
IP4.ADDRESS[1]:                         172.16.225.71/24
-- 장치에 172.16.225.71/24 가 걸렸다
-- noprefixroute 는 NetworkManager 가 넣은 주소라는 표시다
-- 대문자 묶음이 이제 보인다. GENERAL.STATE activated, IP4.ADDRESS[1] 이 프로필 값과 같다
[root@ol7a ~]# ping -c 2 -W 2 -I ens33 172.16.225.2 | tail -2
2 packets transmitted, 0 received, 100% packet loss, time 1031ms
-- 주소가 있는데도 -I ens33 ping 은 여전히 실패한다
-- 출발 주소가 여전히 .61 로 골라지기 때문이다
-- 같은 서브넷에 NIC 가 둘이면 응답이 어느 장치로 돌아오는지가 꼬인다
-- ping -I 172.16.225.71 처럼 주소로 지정해야 정확하다
-- 그래서 확인은 밖(ol7b)에서 한다

-- 같은 서브넷에 NIC 두 개가 붙었다. 경로 표를 본다.
[root@ol7a ~]# ip route
default via 172.16.225.2 dev ens32 proto static metric 100 
172.16.225.0/24 dev ens32 proto kernel scope link src 172.16.225.61 metric 100 
172.16.225.0/24 dev ens33 proto kernel scope link src 172.16.225.71 metric 101 
-- 같은 172.16.225.0/24 로 가는 연결 경로가 둘이다
-- metric 100(ens32)이 101(ens33)보다 우선한다
-- 기본 경로는 ens32 하나뿐이다. ens33 프로필에는 게이트웨이가 없다

-- 밖(ol7b)에서 새 주소가 보이는지 확인한다.
[root@ol7b ~]# ping -c 2 -W 2 172.16.225.71 | tail -2; ip neigh show 172.16.225.71
2 packets transmitted, 1 received, 50% packet loss, time 1006ms
rtt min/avg/max/mdev = 0.318/0.318/0.318/0.000 ms
172.16.225.71 dev ens32 lladdr 00:0c:29:ac:5e:aa DELAY
-- ol7b 에서는 응답이 왔다. 첫 패킷은 ARP 를 묻는 동안 사라져 50% 다

-- .71 은 ens33 이 대답하고 있다
-- 뒤의 dev ens32 는 ol7b 쪽 장치 이름이다(ol7b 도 NIC 가 ens32 다)

 [5] 부팅 때 자동 활성화 — connection.autoconnect
--------------------------------------------------------------------------------

-- 지금은 수동으로 올렸다. 재부팅하면 ONBOOT=no 라 다시 꺼진 채 올라온다.
[root@ol7a ~]# nmcli connection modify ens33 connection.autoconnect yes
[root@ol7a ~]# diff /root/ifcfg-ens33 /etc/sysconfig/network-scripts/ifcfg-ens33
4c4
< BOOTPROTO=dhcp
---
> BOOTPROTO=none
15c15,17
< ONBOOT=no
---
> ONBOOT=yes
> IPADDR=172.16.225.71
> PREFIX=24
-- 15c15,17 로 바뀌었다. ONBOOT=no 가 yes 로 바뀐 줄이 diff 에 더해졌다
-- 이 값은 지금 상태에 영향이 없다
-- 다음 부팅이나 NetworkManager 재시작 때 자동으로 올릴지만 정한다

--------------------------------------------------------------------------------
 [6] 보조 IP — +ipv4.addresses
--------------------------------------------------------------------------------

-- 속성 이름 앞의 + 는 목록에 추가, - 는 목록에서 제거다
-- + 없이 쓰면 목록 전체를 바꾼다.
[root@ol7a ~]# nmcli connection modify ens33 +ipv4.addresses 172.16.225.72/24
[root@ol7a ~]# nmcli -g ipv4.addresses connection show ens33
172.16.225.71/24, 172.16.225.72/24
-- -g 는 값만 쉼표로 이어 보인다. 주소 목록에 두 개가 들어 있다
[root@ol7a ~]# diff /root/ifcfg-ens33 /etc/sysconfig/network-scripts/ifcfg-ens33
4c4
< BOOTPROTO=dhcp
---
> BOOTPROTO=none
15c15,19
< ONBOOT=no
---
> ONBOOT=yes
> IPADDR=172.16.225.71
> PREFIX=24
> IPADDR1=172.16.225.72
> PREFIX1=24
-- 보조 주소는 별칭 파일(ifcfg-ens33:0)이 아니라 같은 파일의 번호 붙은 키 IPADDR1·PREFIX1 로 들어간다

-- 이번에는 up 대신 reapply 로 반영한다. 활성 연결을 내리지 않고 바뀐 값만 적용한다.
[root@ol7a ~]# nmcli device reapply ens33; ip -4 addr show ens33
Connection successfully reapplied to device 'ens33'.
3: ens33: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc pfifo_fast state UP group default qlen 1000
    inet 172.16.225.71/24 brd 172.16.225.255 scope global noprefixroute ens33
       valid_lft forever preferred_lft forever
    inet 172.16.225.72/24 brd 172.16.225.255 scope global secondary noprefixroute ens33
       valid_lft forever preferred_lft forever
-- reapply 는 Connection successfully reapplied 한 줄로 끝났다
-- 연결 번호를 새로 받지 않았다
-- .72 줄에 secondary 가 붙었다
-- 같은 서브넷의 두 번째 주소라는 뜻이다. .71 은 내려가지 않았다

[root@ol7b ~]# ping -c 1 -W 2 172.16.225.72 | tail -2
1 packets transmitted, 1 received, 0% packet loss, time 0ms
rtt min/avg/max/mdev = 0.344/0.344/0.344/0.000 ms
-- 이번에는 ARP 가 이미 알려져 있어 첫 패킷부터 응답했다(0% packet loss)

--------------------------------------------------------------------------------
 [7] 런타임으로만 넣은 주소 — ip addr add
--------------------------------------------------------------------------------

-- ip addr add 는 커널에만 넣는다. 프로필과 ifcfg 파일은 모른다.
[root@ol7a ~]# ip addr add 172.16.225.73/24 dev ens33; ip -4 addr show ens33 | grep inet
    inet 172.16.225.71/24 brd 172.16.225.255 scope global noprefixroute ens33
    inet 172.16.225.72/24 brd 172.16.225.255 scope global secondary noprefixroute ens33
    inet 172.16.225.73/24 scope global secondary ens33
-- .73 줄에는 brd 와 noprefixroute 가 없다
-- 손으로 넣은 주소와 NetworkManager 가 넣은 주소가 꼬리표로 구분된다
[root@ol7a ~]# nmcli -g ipv4.addresses connection show ens33; grep -c 172.16.225.73 /etc/sysconfig/network-scripts/ifcfg-ens33
172.16.225.71/24, 172.16.225.72/24
0
-- 프로필 목록에는 .71·.72 뿐이고 ifcfg 에는 .73 이 한 번도 없다(grep -c 가 0)

-- 연결을 다시 올리면 NetworkManager 가 프로필대로 다시 맞춘다.
[root@ol7a ~]# nmcli connection up ens33 >/dev/null; ip -4 addr show ens33 | grep inet
    inet 172.16.225.71/24 brd 172.16.225.255 scope global noprefixroute ens33
    inet 172.16.225.72/24 brd 172.16.225.255 scope global secondary noprefixroute ens33
-- connection up 한 번에 .73 이 사라졌다
-- NetworkManager 는 장치를 프로필대로 다시 맞춘다
-- 서비스 주소를 ip addr add 로만 걸어 두면 링크 재연결·재부팅·NetworkManager 의 재활성화 때 조용히 없어진다

 [8] 보조 IP 빼기 — -ipv4.addresses

-- IPADDR1·PREFIX1 키가 파일에서 사라졌다

--------------------------------------------------------------------------------
 [9] up 과 reapply 는 무엇이 다른가
--------------------------------------------------------------------------------

-- 연결이 활성화된 시각은 GENERAL.STATE 가 아니라 장치의 이벤트로 본다
-- 두 명령 직후의 로그를 비교한다.
[root@ol7a ~]# journalctl -u NetworkManager --since '-2min' --no-pager | grep 'device (ens33)' | grep -oE '(state change: [a-z-]+ -> [a-z-]+|reapply.*)' | tail -9
state change: secondaries -> activated
-- grep -oE 로 상태 변화 부분만 잘랐고 tail -9 로 마지막 아홉 줄만 봤다
-- [7] 의 connection up 이 남긴 기록이다
-- up 은 activated → deactivating → disconnected 로 한 번 내려갔다가 prepare → config → ip-config → ip-check → secondaries → activated 로 다시 올라온다
-- [6]·[8] 의 reapply 는 상태 변화 줄을 하나도 남기지 않았다
-- 장치가 activated 상태를 벗어나지 않았다
-- 운영 중에 주소 하나를 더하거나 뺄 때 reapply 가 덜 거친 이유다
state change: activated -> deactivating
state change: deactivating -> disconnected
state change: disconnected -> prepare
state change: prepare -> config
state change: config -> ip-config
state change: ip-config -> ip-check
state change: ip-check -> secondaries
state change: secondaries -> activated

-- 같은 ens33 에 DHCP 로 주소를 받는 프로필을 하나 더 만든다
-- 장치는 한 번에 한 프로필만 쓴다.
-- type ethernet 은 유선 프로필,
-- ifname 은 묶을 장치, con-name 은 프로필 이름이다.
-- ipv4.method auto 가 BOOTPROTO=dhcp 에 해당한다
-- autoconnect no 로 저절로 올라오지 않게 한다.
[root@ol7a ~]# nmcli connection add type ethernet ifname ens33 con-name ens33-dhcp ipv4.method auto connection.autoconnect no
Connection 'ens33-dhcp' (ae292b0d-6057-4044-8054-afdde15c5309) successfully added.
[root@ol7a ~]# grep -E '^(BOOTPROTO|ONBOOT|DEVICE|NAME)=' /etc/sysconfig/network-scripts/ifcfg-ens33-dhcp
BOOTPROTO=dhcp
NAME=ens33-dhcp
DEVICE=ens33
ONBOOT=no
-- 파일 이름은 con-name 을 따라 ifcfg-ens33-dhcp 다
-- DEVICE=ens33 으로 같은 장치에 묶였다
-- BOOTPROTO=dhcp, ONBOOT=no. 한 장치에 프로필 두 개가 생겼다

-- DHCP 프로필로 바꿔 올린다. VMware NAT 의 DHCP 서버가 주소를 준다.
[root@ol7a ~]# nmcli connection up ens33-dhcp; nmcli -f NAME,DEVICE connection show --active; ip -4 addr show ens33 | grep inet
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/6)
NAME        DEVICE 
ens32       ens32  
ens33-dhcp  ens33  
    inet 172.16.225.132/24 brd 172.16.225.255 scope global dynamic noprefixroute ens33
-- ens33 의 활성 연결이 ens33 에서 ens33-dhcp 로 바뀌었다
-- 장치는 한 번에 프로필 하나만 쓴다
-- 172.16.225.132 는 VMware NAT 의 DHCP 범위(.128~.254)에서 받은 주소다
-- dynamic 이 임대 주소 표시다

-- DHCP4 묶음은 서버에게서 받은 값 전체다
-- 임대 시간·서버 주소·게이트웨이·DNS 를 본다.
[root@ol7a ~]# nmcli -f DHCP4 connection show ens33-dhcp | grep -E ' (dhcp_lease_time|dhcp_server_identifier|ip_address|routers|domain_name_servers) ='
DHCP4.OPTION[2]:                        dhcp_lease_time = 1800
DHCP4.OPTION[4]:                        dhcp_server_identifier = 172.16.225.254
DHCP4.OPTION[6]:                        domain_name_servers = 172.16.225.2
DHCP4.OPTION[8]:                        ip_address = 172.16.225.132
DHCP4.OPTION[29]:                       routers = 172.16.225.2
-- DHCP4.OPTION 은 서버가 준 옵션이다. 번호는 목록 순서일 뿐 의미가 없다
--   dhcp_lease_time = 1800          임대 30분
--   dhcp_server_identifier          DHCP 서버는 172.16.225.254(VMware 의 DHCP 서비스)
--   domain_name_servers / routers   DNS 와 게이트웨이 모두 172.16.225.2

-- 7.9 의 NetworkManager 는 DHCP 를 dhclient 프로세스에 맡긴다. 임대 파일도 남는다.
[root@ol7a ~]# pgrep -a dhclient | grep -oE '^[0-9]+ [^ ]+|-lf [^ ]+'
2930 /sbin/dhclient
-lf /var/lib/NetworkManager/dhclient-ae292b0d-6057-4044-8054-afdde15c5309-ens33.lease
-- PID 2930 의 /sbin/dhclient 가 떠 있다
-- -lf 는 임대 파일 경로다. 파일 이름에 프로필 UUID 와 장치 이름이 들어간다
-- [OL8/9] OL 8 부터는 NetworkManager 내장 DHCP 클라이언트가 기본이라 dhclient 프로세스가 보이지 않는다
-- 공식 문서(NET-2)는 임대 정보가 /var/lib/dhclient 에 남는다고 적는다
-- NetworkManager 가 띄운 dhclient 는 다른 곳에 쓴다.
[root@ol7a ~]# ls /var/lib/dhclient/; ls /var/lib/NetworkManager/ | grep -i lease
dhclient-ae292b0d-6057-4044-8054-afdde15c5309-ens33.lease
-- /var/lib/dhclient 는 비어 있다
-- 문서가 말하는 위치는 network 서비스가 dhclient 를 띄울 때의 것이다
[root@ol7a ~]# grep -E 'fixed-address|routers|lease-time|server-identifier|renew|expire' /var/lib/NetworkManager/dhclient-*-ens33.lease
  fixed-address 172.16.225.132;
  option routers 172.16.225.2;
  option dhcp-lease-time 1800;
  option dhcp-server-identifier 172.16.225.254;
  renew 1 2026/11/16 02:00:31;
  expire 1 2026/11/16 02:15:33;
-- renew·expire 시각은 UTC 다(서버 시계는 KST). 숫자 1 은 요일(월요일)이다
-- renew 는 임대 절반쯤 지난 시각, expire 는 임대가 끝나는 시각이다
-- dhclient 가 그 전에 갱신한다

-- DHCP 가 준 게이트웨이와 DNS 가 경로표와 resolv.conf 에 더해졌는지 본다.
