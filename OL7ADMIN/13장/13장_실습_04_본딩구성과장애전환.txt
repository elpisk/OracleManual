================================================================================
 제13장 실습 04 — 본딩 구성과 장애 전환
 대상   : ol7a (NIC 두 개 ens32·ens33)
 목표   : active-backup 본드 bond0 를 nmcli 로 만들고 SSH 가 붙은 172.16.225.61 을
          bond0 로 옮긴다. /proc/net/bonding/bond0 를 읽고, 슬레이브 링크를 내려
          전환과 패킷 손실을 잰다. 같은 이중화를 팀(teamd)으로도 만든다
 배경   : bonding 모듈은 NIC 여러 개를 논리 장치 하나로 묶는다. active-backup(mode 1)
          은 슬레이브 하나만 쓰고 MII 감시(miimon)로 링크 끊김을 알면 대기 슬레이브로
          넘긴다. 스위치 설정이 필요 없어 DB 서버 공용망에 가장 흔하다. NetworkManager
          에서는 본드 연결 하나 + 슬레이브 연결 여러 개로 만든다 (본문 13.6)
 소요   : 약 45분
 선행   : ol7-base 스냅샷 (⚠ ens32 의 주소를 본드로 옮긴다)
 계정   : root
 주의   : [7] 과 [변형] 에서 접속 주소가 다른 장치로 옮겨 간다. 옮기는 스크립트에
          180초 되돌림 타이머를 넣는다. 링크 끊기는 게스트 안의 ip link set down 으로 한다
 되돌림 : 본드·팀 연결 삭제, ens32 에 172.16.225.61, ifcfg 원본
          → nmcli connection show, md5sum ifcfg-ens3?

-- 본딩 드라이버가 어느 커널 파일인지,
-- 어떤 옵션을 받는지 먼저 본다
[root@ol7a ~]# modinfo bonding | grep -E '^(filename|description)'
filename:       /lib/modules/5.4.17-2136.338.4.2.el7uek.x86_64/kernel/drivers/net/bonding/bonding.ko.xz
description:    Ethernet Channel Bonding Driver, v3.7.1
[root@ol7a ~]# modinfo -p bonding | grep -E '^(mode|miimon|primary|fail_over_mac):' | cut -c1-110
miimon:Link check interval in milliseconds (int)
mode:Mode of operation; 0 for balance-rr, 1 for active-backup, 2 for balance-xor, 3 for broadcast, 4 for 802.3
primary:Primary network device to use (charp)
fail_over_mac:For active-backup, do not set all slaves to the same MAC; 0 for none (default), 1 for active, 2 
-- cut -c1-110 으로 긴 설명 줄을 잘랐다
-- 이 실습에서 쓰는 네 옵션이다
--  mode  0~6 또는 이름. active-backup 은 1
--  miimon  링크 확인 주기(ms). 0 이면 감시하지 않아 전환이 일어나지 않는다
--  primary  링크가 살아 있으면 늘 쓸 슬레이브
--  fail_over_mac  active-backup 에서 슬레이브 MAC 을 어떻게 둘지. 0 none(기본, 모두 같은 MAC), 1 active, 2 follow

 [2] 오류 ② — 모드 이름 오타

-- 본드 연결을 만든다. 모드 이름을 한 글자 틀리게 쓴 경우다.
[root@ol7a ~]# nmcli connection add type bond con-name bond0 ifname bond0 bond.options "mode=active-bakcup,miimon=100" ipv4.method manual ipv4.addresses 172.16.225.71/24
Error: failed to modify bond.options: 'active-bakcup' not among [balance-rr, active-backup, balance-xor, broadcast, 802.3ad, balance-tlb, balance-alb].
-- 오류 문구가 허용되는 모드 이름 일곱 개를 그대로 알려 준다
-- 숫자(1)로 써도 된다
[root@ol7a ~]# nmcli connection show | grep -c bond0
-- 연결이 만들어지지 않았다(grep -c 0)
-- 잘못된 옵션은 파일에 남지 않는다
--
--
-- 오류 흐름
-- 증상   : nmcli connection add … mode=active-bakcup → Error: failed to modify bond.options: 'active-bakcup' not among [...]
-- 원인   : bond.options 의 mode 값 오타. nmcli 가 생성 전에 값을 검사한다
-- 조치   : mode=active-backup(또는 mode=1)으로 다시 add
-- 재확인 : Connection 'bond0' (...) successfully added., ifcfg-bond0 의 BONDING_OPTS
0

-- 바르게 다시 만든다. 주소는 일단 임시 주소 .71 이다.
[root@ol7a ~]# nmcli connection add type bond con-name bond0 ifname bond0 bond.options "mode=active-backup,miimon=100,fail_over_mac=active" ipv4.method manual ipv4.addresses 172.16.225.71/24
Connection 'bond0' (8d619e07-f73f-4d09-b93d-e648253dba3d) successfully added.
-- 이번에는 fail_over_mac=active 를 함께 줬다
-- 이 랩의 첫 실측(기본값 none)에서 전환 직후 SSH 세션이 끊겼기 때문이다
-- none 은 모든 슬레이브에 같은 MAC 을 입힌다
-- 가상 스위치가 MAC 을 포트에 묶어 두면 전환한 슬레이브로 프레임이 가지 않는다

 [6] 옮기기 전 준비 — 되돌림 스크립트와 타이머
--------------------------------------------------------------------------------

-- 원래 구성으로 돌리는 스크립트를 먼저 만든다
-- 타이머와 [되돌림] 이 함께 쓴다.
[root@ol7a ~]# cat > /root/tobase.sh <<'EOF'
-- tobase.sh 는 본드·팀 연결을 모두 지우고 원본 ifcfg 를 덮은 뒤 ens32 를 올린다
-- 연결이 없으면 delete 가 오류를 내므로 2>/dev/null 로 버렸다
-- [되돌림] 과 타이머가 이 스크립트를 함께 쓴다
#!/bin/bash
for c in bond0-ens32 bond0-ens33 bond0 team0-ens32 team0-ens33 team0; do nmcli connection delete $c 2>/dev/null; done
cp -p /root/ifcfg-ens32 /root/ifcfg-ens33 /etc/sysconfig/network-scripts/
nmcli connection reload; nmcli connection up ens32
EOF
-- 접속 주소를 본드로 옮기는 스크립트
-- 180초 안에 /root/bond.ok 가 생기지 않으면 tobase.sh 를 부른다.
[root@ol7a ~]# cat > /root/tobond.sh <<'EOF'
#!/bin/bash
nmcli connection modify bond0 ipv4.addresses 172.16.225.61/24 ipv4.gateway 172.16.225.2 ipv4.dns 172.16.225.2
nmcli connection modify ens32 connection.autoconnect no
nmcli connection modify bond0-ens32 connection.autoconnect yes
nmcli connection up bond0-ens32; nmcli device reapply bond0
sleep 180; [ -f /root/bond.ok ] || /root/tobase.sh
EOF
[root@ol7a ~]# chmod +x /root/tobase.sh /root/tobond.sh; rm -f /root/bond.ok; bash -n /root/tobond.sh && echo "syntax ok"
--
-- tobond.sh 의 순서
--  1. bond0 프로필에 .61·게이트웨이·DNS 를 넣는다(아직 반영 안 됨)
--  2. ens32 프로필의 자동 연결을 끈다. 재부팅해도 ens32 가 본드에서 빠져나가지 않게
--  3. bond0-ens32 를 자동 연결로 바꾸고 올린다. 이때 ens32 의 .61 이 빠진다
--  4. reapply 로 bond0 에 .61 이 걸린다
--  5. 180초 뒤 /root/bond.ok 가 없으면 tobase.sh 로 원상 복구
-- bash -n 은 문법만 검사하고 실행하지 않는다
-- 원격에서 돌리기 전에 반드시 한 번 친다
syntax ok

-- 팀에 필요한 두 패키지가 기준 VM 에 이미 있다
-- 없으면 yum install 뒤 NetworkManager 를 다시 시작해야 team 연결 종류가 생긴다
-- 본드를 지우고 팀을 만든다
-- 접속 주소가 다시 옮겨 가므로 같은 타이머 방식을 쓴다.
[root@ol7a ~]# cat > /root/toteam.sh <<'EOF'
-- 팀 연결은 team.runner 로 방식을 정한다
-- activebackup 이 본딩의 active-backup 이다
-- team.runner-hwaddr-policy by_active 는 본딩의 fail_over_mac=active 에 해당한다
-- 포트 연결(team-slave)은 for 로 두 개를 만들고 바로 올린다
#!/bin/bash
for c in bond0-ens32 bond0-ens33 bond0; do nmcli connection delete $c; done
nmcli connection add type team con-name team0 ifname team0 team.runner activebackup team.runner-hwaddr-policy by_active ipv4.method manual ipv4.addresses 172.16.225.61/24 ipv4.gateway 172.16.225.2 ipv4.dns 172.16.225.2
for p in ens32 ens33; do nmcli connection add type team-slave con-name team0-$p ifname $p master team0; nmcli connection up team0-$p; done
sleep 180; [ -f /root/team.ok ] || /root/tobase.sh
-- 로그에서 성공 줄 수만 셌다
-- 삭제 3(본드 연결) + 추가 3(팀·포트 둘) + 활성화 2 = 8
EOF
[root@ol7a ~]# chmod +x /root/toteam.sh; rm -f /root/team.ok; nohup /root/toteam.sh >/tmp/toteam.log 2>&1 </dev/null &
