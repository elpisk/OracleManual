================================================================================
 제13장 실습 07 — 인터페이스 이름 규칙
 대상   : ol7a
 목표   : ens32·ens33 이라는 이름이 어디서 왔는지 udev 의 근거로 확인하고,
          net.ifnames=0 으로 이름 체계를 바꿨을 때 ifcfg 파일과 어긋나 연결이
          안 되는 상황을 직렬 콘솔에서 복구한다. MAC 기준 이름 고정도 해 본다
 배경   : 커널은 NIC 를 eth0·eth1 로 먼저 만든다. 부팅 중 udev 가 펌웨어·PCI 슬롯·
          경로·MAC 정보로 새 이름을 정해 바꾼다(예측 가능한 이름). 슬롯 정보가 있으면
          ens<슬롯>, 없으면 enp<버스>s<슬롯> 이다. ifcfg 파일과 NetworkManager 연결은
          이 이름(DEVICE)이나 MAC(HWADDR)으로 장치를 찾는다 (본문 13.1)
 소요   : 약 40분 (재부팅 4회)
 선행   : ol7-base 스냅샷 (⚠ 부트 파라미터와 ifcfg 를 바꾼다)
 계정   : root
 주의   : [7]~[9] 동안 SSH 로 접속할 수 없다. 직렬 콘솔로 작업한다
 되돌림 : 부트 파라미터·ifcfg 원래대로, 재부팅 후 ens32/ens33 → ip -br link, cat /proc/cmdline

 [1] 커널이 처음 붙인 이름 — eth0 에서 ens32 로
--------------------------------------------------------------------------------

-- 부팅 로그에서 이름이 바뀐 기록을 찾는다.
[root@ol7a ~]# journalctl -b -k | grep -E 'eth[01]: \(PCI|renamed' | cut -c17-
ol7a.example.com kernel: e1000 0000:02:00.0 eth0: (PCI:66MHz:32-bit) 00:0c:29:ac:5e:a0
ol7a.example.com kernel: e1000 0000:02:01.0 eth1: (PCI:66MHz:32-bit) 00:0c:29:ac:5e:aa
ol7a.example.com kernel: e1000 0000:02:01.0 ens33: renamed from eth1
ol7a.example.com kernel: e1000 0000:02:00.0 ens32: renamed from eth0
-- cut -c17- 로 앞의 날짜·시각을 잘랐다
-- e1000 드라이버가 PCI 0000:02:00.0 을 eth0,
-- 0000:02:01.0 을 eth1 로 먼저 만들었다
-- 곧바로 udev 가 eth1 → ens33, eth0 → ens32 로 바꿨다
-- 바꾼 순서는 udev 가 처리한 순서일 뿐이다
-- 커널이 붙이는 ethN 은 장치를 찾은 순서다
-- 드라이버가 둘이거나 NIC 를 추가하면 순서가 바뀔 수 있다

--------------------------------------------------------------------------------
 [2] udev 가 계산한 이름 후보 — ID_NET_NAME_*
--------------------------------------------------------------------------------

-- udevadm info 는 udev 데이터베이스에 저장된 장치 속성을 보인다.
[root@ol7a ~]# udevadm info /sys/class/net/ens32 | grep -E 'ID_NET_NAME|ID_PATH=|INTERFACE=|ID_NET_DRIVER'
E: ID_NET_DRIVER=e1000
E: ID_NET_NAME_MAC=enx000c29ac5ea0
E: ID_NET_NAME_PATH=enp2s0
E: ID_NET_NAME_SLOT=ens32
E: ID_PATH=pci-0000:02:00.0
E: INTERFACE=ens32
-- E: 로 시작하는 줄은 udev 가 장치에 붙여 둔 속성(환경 변수)이다
--   ID_NET_DRIVER=e1000           드라이버
--   ID_NET_NAME_MAC=enx000c29ac5ea0  MAC 기준 후보 (enx + MAC)
--   ID_NET_NAME_PATH=enp2s0       PCI 경로 기준 후보 (버스 2, 슬롯 0)
--   ID_NET_NAME_SLOT=ens32        핫플러그 슬롯 기준 후보 (슬롯 32)
--   INTERFACE=ens32               실제로 고른 이름
-- 내장 포트 후보(ID_NET_NAME_ONBOARD, eno1 형식)는 없다
-- VMware 가 내장 포트 번호를 알려 주지 않는다

-- 후보 가운데 무엇을 고를지는 udev 규칙이 정한다
-- 7.9 는 80-net-name-slot.rules 에 순서가 적혀 있다.
-- grep -v 로 주석과 빈 줄을 뺐다.
[root@ol7a ~]# ls /usr/lib/udev/rules.d/ | grep -E 'net|biosdev'
60-net.rules
71-biosdevname.rules
75-net-description.rules
80-net-name-slot.rules
80-net-setup-link.rules
-- 이름과 관련된 규칙 다섯 개다. 앞 번호가 먼저 돈다
--   60-net.rules            ifcfg 의 HWADDR·DEVICE 로 이름을 정함([10])
--   71-biosdevname.rules    biosdevname 이름([4])
--   75-net-description.rules 장치 설명 속성
--   80-net-name-slot.rules  예측 가능한 이름(아래)
--   80-net-setup-link.rules .link 파일 처리
[root@ol7a ~]# grep -v '^#' /usr/lib/udev/rules.d/80-net-name-slot.rules | grep -v '^$'
ACTION!="add", GOTO="net_name_slot_end"
SUBSYSTEM!="net", GOTO="net_name_slot_end"
NAME!="", GOTO="net_name_slot_end"
IMPORT{cmdline}="net.ifnames"
ENV{net.ifnames}=="0", GOTO="net_name_slot_end"
NAME=="", ENV{ID_NET_NAME_ONBOARD}!="", NAME="$env{ID_NET_NAME_ONBOARD}"
NAME=="", ENV{ID_NET_NAME_SLOT}!="", NAME="$env{ID_NET_NAME_SLOT}"
NAME=="", ENV{ID_NET_NAME_PATH}!="", NAME="$env{ID_NET_NAME_PATH}"
LABEL="net_name_slot_end"
-- 줄마다 읽으면
--   NAME!="" 이면 끝       앞 규칙이 이미 이름을 정했으면 건드리지 않는다
--   IMPORT{cmdline}         커널 인자 net.ifnames 를 읽는다
--   net.ifnames==0 이면 끝  [6] 에서 이 줄을 탄다. 이름을 바꾸지 않아 ethN 이 남는다
--   ONBOARD → SLOT → PATH   먼저 있는 후보를 이름으로 쓴다
-- ens32 는 ONBOARD 후보가 없고 SLOT 후보가 있어 ens32 가 됐다
-- MAC 후보는 이 규칙에 없다

 [3] 슬롯 번호 32 는 어디서 왔나
--------------------------------------------------------------------------------

[root@ol7a ~]# ethtool -i ens32 | grep bus-info; ethtool -i ens33 | grep bus-info
bus-info: 0000:02:00.0
bus-info: 0000:02:01.0
-- 두 NIC 의 PCI 주소다. 버스 02, 장치 00·01

-- 펌웨어(ACPI)가 알려 준 PCI 핫플러그 슬롯 목록이다
-- 디렉터리 이름이 슬롯 번호, address 가 그 슬롯의 PCI 주소다.
[root@ol7a ~]# for s in 32 33; do echo "slot $s -> $(cat /sys/bus/pci/slots/$s/address)"; done
slot 32 -> 0000:02:00
slot 33 -> 0000:02:01
-- /sys/bus/pci/slots/32 의 주소가 0000:02:00 이다
-- ens32 의 bus-info 와 같다
-- 슬롯 번호 32·33 은 VMware 가상 하드웨어가 ACPI 로 알려 준 값이다
-- 이 번호가 이름에 들어갔다
-- VirtualBox 처럼 슬롯 정보를 주지 않는 하이퍼바이저에서는 SLOT 후보가 없어 PATH 후보(enp0s3)가 이름이 된다

-- net_id 빌트인을 직접 돌려 계산 과정을 본다.
[root@ol7a ~]# udevadm test-builtin net_id /sys/class/net/ens33 2>/dev/null | grep ID_NET_NAME
ID_NET_NAME_MAC=enx000c29ac5eaa
ID_NET_NAME_PATH=enp2s1
ID_NET_NAME_SLOT=ens33
-- 2>/dev/null 로 디버그 출력을 버리고 결과만 봤다
-- ens33 의 후보도 같은 방식으로 계산된다

--------------------------------------------------------------------------------
 [5] 오류 ② — MAC 이 바뀐 NIC (VM 복제 상황 흉내)
--------------------------------------------------------------------------------

-- VM 을 복제하면 NIC 의 MAC 이 새로 생긴다
-- ifcfg 에 HWADDR 가 박혀 있으면 프로필이 장치를 찾지 못한다.
-- ens33 의 ifcfg 에 다른 MAC 을 넣어 같은 상황을 만든다
-- SSH 가 붙은 ens32 는 건드리지 않는다.
[root@ol7a ~]# cat /sys/class/net/ens33/address
00:0c:29:ac:5e:aa
-- ens33 의 실제 MAC 이다
[root@ol7a ~]# echo 'HWADDR=00:0C:29:AA:BB:CC' >> /etc/sysconfig/network-scripts/ifcfg-ens33; nmcli connection reload
[root@ol7a ~]# nmcli connection up ens33
Error: Connection activation failed: No suitable device found for this connection (device ens32 not available because profile is not compatible with device (mismatching interface name)).
-- 오류 문구 안의 mismatching interface name 은 ens32 가 거절된 이유다(줄이 길어 잘림)
-- NetworkManager 는 모든 장치를 후보로 따져 보고,
-- 맞는 장치가 하나도 없다고 답했다

[root@ol7a ~]# nmcli -f GENERAL.DEVICE,GENERAL.HWADDR device show ens33; nmcli -g 802-3-ethernet.mac-address connection show ens33
GENERAL.DEVICE:                         ens33
GENERAL.HWADDR:                         00:0C:29:AC:5E:AA
00\:0C\:29\:AA\:BB\:CC
-- 장치의 GENERAL.HWADDR 은 00:0C:29:AC:5E:AA,
-- 프로필의 802-3-ethernet.mac-address 는 00:0C:29:AA:BB:CC 다
-- -g 출력의 \: 는 콜론을 구분자와 헷갈리지 않게 이스케이프한 것이다
-- 오류 흐름
-- 증상   : nmcli connection up ens33 → Error: Connection activation failed: No suitable device found for this connection
-- 원인   : ifcfg 의 HWADDR(00:0C:29:AA:BB:CC)와 장치의 실제 MAC(00:0c:29:ac:5e:aa)이 다르다. 프로필이 붙을 장치가 없다
-- 조치   : HWADDR 를 실제 MAC 으로 고치거나 지우고 reload
-- 재확인 : nmcli connection up ens33 이 activated
-- VM 을 복제하거나 NIC 를 교체한 뒤 네트워크가 안 올라오는 경우가 이것이다
-- 템플릿 VM 의 ifcfg 에서는 HWADDR·UUID 를 지워 둔다

-- 고친다. 실제 MAC 으로 바꾸거나 HWADDR 줄을 지운다
-- 여기서는 실제 MAC 으로 바꾼다.
[root@ol7a ~]# sed -i "s/^HWADDR=.*/HWADDR=$(cat /sys/class/net/ens33/address)/" /etc/sysconfig/network-scripts/ifcfg-ens33; nmcli connection reload
[root@ol7a ~]# nmcli connection up ens33; nmcli -g GENERAL.STATE connection show ens33
Connection successfully activated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/2)
-- 실제 MAC 으로 고치자 바로 활성화됐다
-- HWADDR 는 대소문자를 가리지 않는다(파일에는 소문자를 넣었다)
activated
[root@ol7a ~]# nmcli connection down ens33; cp -p /root/net0/ifcfg-ens33 /etc/sysconfig/network-scripts/; nmcli connection reload
Connection 'ens33' successfully deactivated (D-Bus active path: /org/freedesktop/NetworkManager/ActiveConnection/2)
-- 원본 ifcfg-ens33 으로 되돌렸다
-- 다음 단계는 HWADDR 가 없는 원래 상태에서 시작한다

-- 7.9 의 udev 는 이름을 고르기 전에 60-net.rules 를 먼저 거친다.
-- 이 규칙은 rename_device 도우미로 ifcfg 파일들의 HWADDR 를 뒤져,
-- MAC 이 맞는 파일의 DEVICE 로 이름을 붙인다.
[root@ol7a ~]# grep -v '^#' /usr/lib/udev/rules.d/60-net.rules | grep -v '^$'
ACTION=="add", SUBSYSTEM=="net", PROGRAM="/lib/udev/detect_failover", RESULT=="?*", ENV{NET_FAILOVER}="$result"
ACTION=="add", SUBSYSTEM=="net", DRIVERS=="?*", ATTR{type}=="1", ENV{NET_FAILOVER}=="[01]*", PROGRAM="/lib/udev/rename_device", RESULT=="?*", NAME="$result"
-- 두 줄 모두 장치 추가(add) 때 돈다
--   detect_failover  가상 장애 조치 NIC 인지 검사(여기서는 해당 없음)
--   rename_device    ifcfg 를 뒤져 이름을 정하고, 결과가 있으면 NAME 에 넣는다
-- NAME 이 정해지면 80-net-name-slot.rules 의 NAME!="" 줄에 걸려 슬롯 이름을 붙이지 않는다

-- lan33 프로필을 lan1 로 바꾸고 DEVICE=lan1 을 적는다
-- HWADDR 는 [변형]에서 넣은 eth1 의 MAC 이다.
-- 이 파일 하나에 MAC(HWADDR)과 원하는 이름(DEVICE=lan1)이 함께 있다
[root@ol7a ~]# cd /etc/sysconfig/network-scripts; mv ifcfg-lan33 ifcfg-lan1; sed -i 's/^NAME=.*/NAME=lan1/' ifcfg-lan1; echo 'DEVICE=lan1' >> ifcfg-lan1; grep -E '^(NAME|DEVICE|HWADDR)=' ifcfg-lan1
