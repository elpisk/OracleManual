================================================================================
 제15장 실습 02 — 키 생성과 배포
 대상   : ol7a (student, oracle), ol7b (student, oracle)
 목표   : ssh-keygen 으로 RSA·ECDSA 키 쌍을 만들고(암호문 유무), ssh-copy-id 로
          공개 키를 배포해 암호 없이 접속한다. 서버 로그에서 어떤 키로 들어왔는지
          확인하고, oracle 사용자끼리 양방향 동등성(RAC 설치 전제)을 구성한다
 배경   : 공개 키 인증은 개인 키(클라이언트에만 있음)로 만든 서명을 서버가
          ~/.ssh/authorized_keys 의 공개 키로 검증하는 방식이다. 암호가 네트워크로
          가지 않고, 키마다 따로 회수할 수 있다. 개인 키에 암호문을 걸면 파일이
          새어 나가도 바로 쓰이지 않는다 (본문 15.4)
 소요   : 약 35분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : student, oracle (만들어서 씀), root (확인·정리)
 주의   : 없음. 끝에서 키와 oracle 사용자를 지운다
 되돌림 : 두 노드의 /home/student/.ssh 삭제, oracle 사용자 삭제
          → ls -ld /home/student/.ssh, id oracle
================================================================================

-- 이 랩은 터미널 없이 실행되므로 ssh 가 묻는 질문(yes/no, 암호, 암호문)에는
-- SSH_ASKPASS 도우미(/usr/local/bin/ask)가 답하고, 질문 문구는 /tmp/ask.log 에 남는다.
-- 수업에서는 SSH_ASKPASS·DISPLAY 를 빼고 같은 명령을 친 뒤 키보드로 답한다.

ls: cannot access /home/student/.ssh: No such file or directory
uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
id: oracle: no such user

-- 이 실습의 클라이언트는 ol7a 의 student, 서버는 ol7b 의 student 다.
[root@ol7b ~]# ls -ld /home/student/.ssh; grep -E '^#?(PubkeyAuthentication|AuthorizedKeysFile|PasswordAuthentication)' /etc/ssh/sshd_config
ls: cannot access /home/student/.ssh: No such file or directory
#PubkeyAuthentication yes

-- 주석(#) 줄은 기본값 안내. 살아 있는 줄은 AuthorizedKeysFile 과 PasswordAuthentication yes.

--------------------------------------------------------------------------------
 [1] RSA 키 쌍 만들기 — 암호문 없이
--------------------------------------------------------------------------------

-- -t rsa : 키 종류, -b 3072 : 길이(7.4 의 기본은 2048), -N '' : 암호문 없음,
-- -f : 저장할 파일, -C : 공개 키 끝에 붙는 주석(누구의 키인지 표시)
[student@ol7a ~]$ ssh-keygen -t rsa -b 3072 -N '' -C 'student@ol7a rsa' -f ~/.ssh/id_rsa
Generating public/private rsa key pair.
Created directory '/home/student/.ssh'.
-- ~/.ssh 가 없어서 ssh-keygen 이 700 으로 만들었다.
-- -N '' 을 주었으므로 암호문 질문이 없다. -f 를 주면 파일 이름 질문도 없다.
Your identification has been saved in /home/student/.ssh/id_rsa.
Your public key has been saved in /home/student/.ssh/id_rsa.pub.
The key fingerprint is:
SHA256:Xh45lvoBcfMex5mLh5tOI+Ps0G5OumTprCppdBL4V+U student@ol7a rsa
-- 지문 뒤의 student@ol7a rsa 는 -C 로 준 주석.
-- -C 를 생략하면 사용자@호스트(student@ol7a.example.com)가 들어간다.
The key's randomart image is:
+---[RSA 3072]----+
|                 |
|        .        |
| .     o. o      |
|. .   . Eo = . o |
| . . .  S B o =  |
|  + o  . O + = . |
| . =    B B * o  |
|  +    = O.= =   |
| . .....==B.+    |
+----[SHA256]-----+
-- randomart: 지문을 그림으로. 사람이 두 키를 눈으로 비교하라고 만든 것.
-- 머리의 [RSA 3072] 가 종류와 길이. 7.4 의 -t rsa 기본은 2048 이다.
-- 지금 권고는 RSA 3072 이상 또는 Ed25519. 2048 은 아직 허용되지만 여유가 적다.
-- [OL8/9] OL10 은 -t 없이 Ed25519 를 만든다.
[student@ol7a ~]$ ls -la ~/.ssh
total 8
drwx------. 2 student student   38 Nov 16 12:42 .
drwx------. 3 student student   74 Nov 16 12:42 ..
-rw-------. 1 student student 2455 Nov 16 12:42 id_rsa
-rw-r--r--. 1 student student  570 Nov 16 12:42 id_rsa.pub
-- 개인 키 600(2455바이트), 공개 키 644(570바이트). 디렉터리 700.
-- ssh-keygen 이 만든 권한이 곧 권장 권한이다. 손으로 바꾸지 않는다.
-- 백업에서 복원하거나 scp 로 옮길 때 이 권한이 깨지기 쉽다([8]).

--------------------------------------------------------------------------------
 [2] 키 파일 들여다보기
--------------------------------------------------------------------------------

-- 개인 키의 첫 줄과 끝 줄. 가운데 Base64 본문은 보이지 않게 자른다.
[student@ol7a ~]$ head -1 ~/.ssh/id_rsa; tail -1 ~/.ssh/id_rsa; wc -l ~/.ssh/id_rsa
-----BEGIN RSA PRIVATE KEY-----
-----END RSA PRIVATE KEY-----
-- PEM 형식. 머리줄 사이에 Base64 본문 37줄, 모두 39줄이다.
-- 첫 줄에 ENCRYPTED 표시가 없으니 암호문 없는 키다. 파일만 있으면 누구나 쓴다.
39 /home/student/.ssh/id_rsa
-- [OL8/9] OpenSSH 7.8 부터는 기본 형식이 "BEGIN OPENSSH PRIVATE KEY" 다. 7.4 는 PEM.
-- 공개 키는 한 줄: 종류, Base64 본문, 주석
[student@ol7a ~]$ awk '{print $1, substr($2,1,30)"...", length($2)"자", $3, $4}' ~/.ssh/id_rsa.pub
ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQ... 544자 student@ol7a rsa
-- 1필드 ssh-rsa(종류), 2필드 Base64 544자, 3필드부터 주석.
-- 주석은 공백을 포함할 수 있어 $3, $4 두 필드로 찍혔다.
-- authorized_keys 에 들어가는 것이 이 한 줄이다.
-- 공개 키는 남에게 보여도 된다. 메일·티켓에 붙여 배포하는 것도 이 파일이다.
[student@ol7a ~]$ ssh-keygen -lf ~/.ssh/id_rsa.pub
3072 SHA256:Xh45lvoBcfMex5mLh5tOI+Ps0G5OumTprCppdBL4V+U student@ol7a rsa (RSA)
-- [1] 의 지문과 같다. 이 지문이 [7] 의 서버 로그에 다시 나온다.
-- 개인 키에서 공개 키를 다시 뽑을 수 있다(-y). .pub 를 잃어버려도 복구된다.
[student@ol7a ~]$ ssh-keygen -y -f ~/.ssh/id_rsa | cut -c1-40; ssh-keygen -y -f ~/.ssh/id_rsa | diff - <(cut -d' ' -f1,2 ~/.ssh/id_rsa.pub) && echo same
ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQC4
same
-- -y 로 뽑은 공개 키가 .pub 의 앞 두 필드와 같다. 주석은 개인 키에 없다.

--------------------------------------------------------------------------------
 [3] ECDSA 키 쌍 — 암호문을 걸어서
--------------------------------------------------------------------------------

-- -b 521 : ECDSA 는 256·384·521 중 하나. 암호문은 개인 키 파일을 암호화한다.
[student@ol7a ~]$ ssh-keygen -t ecdsa -b 521 -N 'Lab15-pass' -C 'student@ol7a ecdsa' -f ~/.ssh/id_ecdsa | head -4
Generating public/private ecdsa key pair.
Your identification has been saved in /home/student/.ssh/id_ecdsa.
Your public key has been saved in /home/student/.ssh/id_ecdsa.pub.
The key fingerprint is:
-- head -4 로 randomart 는 잘랐다.
-- -b 521 은 오타가 아니다. ECDSA 곡선 이름이 nistp521 이다.
[student@ol7a ~]$ head -4 ~/.ssh/id_ecdsa
-----BEGIN EC PRIVATE KEY-----
Proc-Type: 4,ENCRYPTED
-- 암호문을 걸면 PEM 머리에 Proc-Type 과 DEK-Info 가 붙는다.
DEK-Info: AES-128-CBC,5927E1E7DF9253063E2D4E81389EBB2F
-- AES-128-CBC 로 본문을 암호화했다. 뒤의 16진수는 IV.
-- 이 파일을 훔쳐도 Lab15-pass 를 모르면 서명을 만들 수 없다.
-- 암호문 없는 id_rsa 에는 이 두 줄이 없다.
[student@ol7a ~]$ ls -l ~/.ssh
total 16
-rw-------. 1 student student  444 Nov 16 12:42 id_ecdsa
-rw-r--r--. 1 student student  272 Nov 16 12:42 id_ecdsa.pub
-rw-------. 1 student student 2455 Nov 16 12:42 id_rsa
-rw-r--r--. 1 student student  570 Nov 16 12:42 id_rsa.pub
-- ECDSA 521 은 개인 키 444, 공개 키 272바이트. RSA 3072 보다 훨씬 작다.

 [4] 상대 호스트 키 먼저 등록
--------------------------------------------------------------------------------

[student@ol7a ~]$ ssh-keyscan -t ecdsa ol7b 2>/dev/null >> ~/.ssh/known_hosts; ssh-keygen -lf ~/.ssh/known_hosts
256 SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo ol7b (ECDSA)
-- 01 에서 확인한 ol7b 의 지문과 같다. 이 단계를 빼면 ssh-copy-id 가 yes/no 를 묻는다.

--------------------------------------------------------------------------------
 [5] ssh-copy-id 로 공개 키 배포
--------------------------------------------------------------------------------

-- -i : 보낼 공개 키. 이 단계에서만 student 의 암호를 한 번 묻는다.
[student@ol7a ~]$ SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh-copy-id -i ~/.ssh/id_rsa.pub ol7b
/bin/ssh-copy-id: INFO: Source of key(s) to be installed: "/home/student/.ssh/id_rsa.pub"
-- 1단계: 보낼 키 확인.
-- -i 를 생략하면 ~/.ssh/id_*.pub 중 가장 최근 것을 고른다.
/bin/ssh-copy-id: INFO: attempting to log in with the new key(s), to filter out any that are already installed
-- 2단계: 새 키로 먼저 들어가 본다. 이미 등록된 키면 여기서 걸러진다.
/bin/ssh-copy-id: INFO: 1 key(s) remain to be installed -- if you are prompted now it is to install the new keys
-- 3단계: 남은 키를 넣으려고 암호로 접속한다.
-- 원격에서 mkdir -p ~/.ssh; cat >> authorized_keys 와 권한 조정, restorecon 을 실행한다.

Number of key(s) added: 1

Now try logging into the machine, with:   "ssh 'ol7b'"
and check to make sure that only the key(s) you wanted were added.
-- 경로가 /bin/ssh-copy-id 로 찍힌다. 7.9 는 /bin 이 /usr/bin 의 링크다.
[root@ol7a ~]# cat /tmp/ask.log
student@ol7b's password: 
-- 질문은 암호 하나뿐. 호스트 키는 [4] 에서 미리 넣어 두어 묻지 않았다.
-- 암호 인증이 꺼진 서버라면 이 단계가 불가능하다. 그때는 콘솔이나 다른 키로 넣는다.

--------------------------------------------------------------------------------
 [7] 암호 없는 접속과 서버 로그
--------------------------------------------------------------------------------

-- BatchMode=yes 로 묻는 것을 막은 채 들어가지면 키 인증이 된 것이다.
[student@ol7a ~]$ ssh -o BatchMode=yes ol7b 'hostname; id -un; echo $SSH_CONNECTION'
ol7b.example.com
student
172.16.225.61 52632 172.16.225.62 22
-- 암호 질문 없이 들어갔다. SSH_CONNECTION: 출발지 IP·포트, 도착지 IP·포트.
-- BatchMode=yes 로도 성공했으니 cron·스크립트에서도 같은 접속이 된다.
-- 서버의 /var/log/secure 에는 어떤 키(지문)로 들어왔는지 남는다.
[root@ol7b ~]# grep 'Accepted' /var/log/secure | tail -2
Nov 16 12:42:52 ol7b sshd[2776]: Accepted password for student from 172.16.225.61 port 52622 ssh2
-- 윗줄: [5] 의 ssh-copy-id 가 암호로 들어온 기록.
Nov 16 12:42:52 ol7b sshd[3310]: Accepted publickey for student from 172.16.225.61 port 52632 ssh2: RSA SHA256:Xh45lvoBcfMex5mLh5tOI+Ps0G5OumTprCppdBL4V+U
-- 아랫줄: 이번 접속. publickey 와 키 종류·지문(Xh45lvoB...)이 남는다.
-- 지문이 [2] 의 ssh-keygen -lf 값과 같다. 누구의 키로 들어왔는지 이것으로 가린다.
-- 포트 52632 가 위 SSH_CONNECTION 의 출발 포트와 같다.
-- 키를 회수했는데도 누가 들어온다면, 이 지문으로 남은 키를 찾는다.
-- -v 로 클라이언트가 어떤 키를 내밀었는지 본다.
[student@ol7a ~]$ ssh -v -o BatchMode=yes ol7b true 2>&1 | grep -E 'Offering|Server accepts|Authentication succeeded|Authentications that'
debug1: Authentications that can continue: publickey,gssapi-keyex,gssapi-with-mic,password
debug1: Offering RSA public key: /home/student/.ssh/id_rsa
-- 클라이언트는 공개 키를 먼저 내밀어 받아 줄지 묻는다.
-- 이 시점에는 아직 개인 키를 쓰지 않는다.
debug1: Server accepts key: pkalg rsa-sha2-512 blen 407
-- 서버가 받겠다고 하면 그때 개인 키로 서명한다. 서명 알고리즘은 rsa-sha2-512.
-- id_ecdsa 는 내밀기 전에 id_rsa 로 끝났다. 기본 키 파일 순서가 rsa 먼저다.
-- blen 407 은 공개 키 블롭 길이(바이트). Base64 544자를 풀면 407바이트다.
debug1: Authentication succeeded (publickey).

 [8] 오류 ① — 개인 키 권한이 넓다
--------------------------------------------------------------------------------

[student@ol7a ~]$ chmod 644 ~/.ssh/id_rsa; ls -l ~/.ssh/id_rsa
-rw-r--r--. 1 student student 2455 Nov 16 12:42 /home/student/.ssh/id_rsa
-- 개인 키를 644 로 넓혔다. 다른 사용자가 읽을 수 있는 상태.
-- tar 로 홈을 옮기거나 Windows 공유를 거쳐 복사하면 흔히 이렇게 된다.
[student@ol7a ~]$ ssh -o BatchMode=yes ol7b hostname; echo rc=$?
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@         WARNING: UNPROTECTED PRIVATE KEY FILE!          @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
Permissions 0644 for '/home/student/.ssh/id_rsa' are too open.
It is required that your private key files are NOT accessible by others.
This private key will be ignored.
Load key "/home/student/.ssh/id_rsa": bad permissions
-- 클라이언트 쪽 검사다. 서버에는 아무 기록도 남지 않는다.
-- 경고 여섯 줄 다음의 Load key 줄이 결론이다. 키 이름과 이유(bad permissions).
-- id_rsa 를 버린 뒤 id_ecdsa 로 넘어갔지만 BatchMode 라 암호문을 못 물어 그것도 실패.
Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password).
rc=255

-- 증상   : "WARNING: UNPROTECTED PRIVATE KEY FILE!", "Permissions 0644 ... are too open."
-- 원인   : 개인 키가 다른 사용자에게 읽힘. ssh 가 그 키를 무시("This private key will be ignored.")
-- 조치   : chmod 600 ~/.ssh/id_rsa
-- 재확인 : 같은 BatchMode 접속이 ol7b.example.com, rc=0
[student@ol7a ~]$ chmod 600 ~/.ssh/id_rsa; ssh -o BatchMode=yes ol7b hostname; echo rc=$?
ol7b.example.com
rc=0
-- 권한만 되돌리면 바로 된다. 키 파일은 바뀌지 않았다.
-- 그룹 읽기만 연 640 도 같은 경고를 낸다(03 [9]). 600 또는 400 만 통과.

--------------------------------------------------------------------------------
 [9] 오류 ② — 손으로 붙여 넣다 줄이 끊긴 공개 키
--------------------------------------------------------------------------------

-- 터미널에서 복사·붙여넣기를 하면 긴 줄이 화면 폭에서 끊겨 줄바꿈이 끼어드는 일이 흔하다.
-- fold -w 70 으로 그 상황을 만든다. 배달은 이미 되는 RSA 키 접속으로 한다.
[student@ol7a ~]$ fold -w 70 ~/.ssh/id_ecdsa.pub | ssh -o BatchMode=yes ol7b 'cat >> ~/.ssh/authorized_keys'
-- 출력이 없다. 원격 cat 이 표준 입력을 그대로 덧붙였다.
-- 키 접속이 하나 있으면 이렇게 다른 키를 배달할 수 있다. 손 복사의 축소판이다.
[root@ol7b ~]# awk '{print NR": "length($0)"자 "substr($0,1,24)}' /home/student/.ssh/authorized_keys
1: 569자 ssh-rsa AAAAB3NzaC1yc2EA
2: 70자 ecdsa-sha2-nistp521 AAAA
3: 70자 CFBAEPwA5zvsHcJci0SeTVJq
4: 70자 apTuyRSY6oUOIYjP3wV8pwHP
5: 61자 IAmozayEgf3TJk7fRzbTQUvF
-- 1번 줄은 RSA 키(569자, 줄바꿈 빼고). 2~5번이 ECDSA 키 하나가 네 줄로 끊긴 것.
-- sshd 는 줄 단위로 읽으므로 2번 줄은 본문이 잘린 키, 3~5번 줄은 쓰레기다.
-- 70+70+70+61 = 271자. 원래 키는 272바이트(줄바꿈 포함) 한 줄이다.
-- ECDSA 키만 쓰도록(-i, IdentitiesOnly) 하고 공개 키 인증만 시도(PreferredAuthentications)
[student@ol7a ~]$ SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh -i ~/.ssh/id_ecdsa -o IdentitiesOnly=yes -o PreferredAuthentications=publickey ol7b hostname; echo rc=$?
Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password).
rc=255
[root@ol7a ~]# cat /tmp/ask.log
-- 질문 기록이 비었다. 암호문을 묻지도 않았다.
-- 서버가 공개 키를 받지 않으면 개인 키를 열 필요가 없어서다([7] 의 순서).
-- 그래서 "암호문을 묻지 않고 실패"하면 서버 쪽 authorized_keys 부터 의심한다.
[root@ol7b ~]# ssh-keygen -lf /home/student/.ssh/authorized_keys
3072 SHA256:Xh45lvoBcfMex5mLh5tOI+Ps0G5OumTprCppdBL4V+U student@ol7a rsa (RSA)
-- 지문을 뽑으면 RSA 한 줄만 나온다. 끊긴 줄들은 말없이 건너뛴다.
-- 경고도 오류도 없다. 줄 길이를 직접 세어 보기 전에는 드러나지 않는다.

-- 증상   : ECDSA 키 접속이 "Permission denied (publickey,...)" rc=255, 암호문 질문도 없음
-- 원인   : authorized_keys 의 키가 70자마다 끊겨 네 줄. 줄 길이(awk)로 확인
-- 조치   : 끊긴 2~5번 줄 삭제 후 ssh-copy-id -i ~/.ssh/id_ecdsa.pub ol7b
-- 재확인 : 같은 접속이 rc=0, 질문 기록은 암호문 하나
-- 조치: 끊긴 줄(2~)을 지우고 ssh-copy-id 로 다시 넣는다.
[root@ol7b ~]# sed -i '2,$d' /home/student/.ssh/authorized_keys; wc -l /home/student/.ssh/authorized_keys
1 /home/student/.ssh/authorized_keys
-- RSA 키 한 줄만 남았다.
-- '2,$d' 는 2번 줄부터 끝까지 지우는 sed 명령.
[student@ol7a ~]$ SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh-copy-id -i ~/.ssh/id_ecdsa.pub ol7b 2>&1 | grep -E 'Number|WARNING|ERROR'
Number of key(s) added: 1
-- ssh-copy-id 는 RSA 키(이미 있음)는 건드리지 않고 ECDSA 만 넣었다.
-- -i 로 ECDSA 공개 키만 지정했기 때문이기도 하다.
[student@ol7a ~]$ SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh -i ~/.ssh/id_ecdsa -o IdentitiesOnly=yes -o PreferredAuthentications=publickey ol7b hostname; echo rc=$?
ol7b.example.com
rc=0
[root@ol7a ~]# cat /tmp/ask.log
Enter passphrase for key '/home/student/.ssh/id_ecdsa': 
-- 이번에는 서버가 키를 받아 주었으므로 개인 키를 열려고 암호문을 물었다.
-- 암호문은 서버로 가지 않는다. 클라이언트에서 파일을 복호화할 때만 쓴다.
-- 접속마다 암호문을 치는 불편은 04 의 ssh-agent 로 없앤다.

 [10] authorized_keys 옵션 — 키 하나의 권한 줄이기
--------------------------------------------------------------------------------

-- 줄 앞에 옵션을 붙이면 그 키로 들어온 접속을 제한한다. from= : 허용할 출발지,
-- command= : 무엇을 치든 이 명령만 실행. 백업 스크립트용 키에 쓴다.
[root@ol7b ~]# sed -i '1s/^/from="172.16.225.61",command="\/usr\/bin\/uptime",no-pty /' /home/student/.ssh/authorized_keys; cut -c1-70 /home/student/.ssh/authorized_keys | head -1
-- 옵션은 키 종류(ssh-rsa) 앞에 쉼표로 이어 붙인다. 공백은 마지막에 한 칸.
from="172.16.225.61",command="/usr/bin/uptime",no-pty ssh-rsa AAAAB3Nz
[student@ol7a ~]$ ssh -o BatchMode=yes -o IdentitiesOnly=yes -i ~/.ssh/id_rsa ol7b hostname
 12:42:55 up 0 min,  0 users,  load average: 0.46, 0.10, 0.03
-- hostname 을 요청했는데 uptime 결과가 왔다. command= 가 요청을 무시한다.
-- 요청한 명령은 SSH_ORIGINAL_COMMAND 변수로 넘어가 스크립트가 검사할 수 있다.
-- from= 이 172.16.225.61 이라 ol7a 에서는 통과. 다른 곳에서 오면 이 키는 거부된다.
-- no-pty 는 터미널 할당을 막는다. 대화형 셸을 못 쓰게 하는 장치.
-- 백업 스크립트용 무암호 키에는 from·command 를 함께 거는 것이 좋다.
[root@ol7b ~]# sed -i '1s/^from="172.16.225.61",command="\/usr\/bin\/uptime",no-pty //' /home/student/.ssh/authorized_keys; cut -c1-30 /home/student/.ssh/authorized_keys | head -1
ssh-rsa AAAAB3NzaC1yc2EAAAADAQ
-- 옵션을 지워 원래 줄로 되돌렸다.
-- authorized_keys 는 접속할 때마다 새로 읽는다. 옵션을 넣고 빼는 데 reload 가 필요 없다.

 [11] oracle 사용자 동등성 — 두 노드 양방향
--------------------------------------------------------------------------------

-- RAC·Data Guard 설치는 oracle 이 모든 노드(자기 자신 포함)로 암호 없이 들어갈 수 있어야 한다.
[root@ol7a ~]# id oracle; ssh-keyscan -t ecdsa ol7a ol7b ol7a.example.com ol7b.example.com 2>/dev/null > /tmp/kh; wc -l /tmp/kh
uid=1001(oracle) gid=1001(oracle) groups=1001(oracle)
4 /tmp/kh
-- 두 노드 × 짧은 이름·FQDN, 네 줄. 오라클 사용자마다 같은 known_hosts 를 쓴다.
-- oracle 은 이 단계 직전에 두 노드에 만들었다(실행 줄은 생략). 암호는 수업용 값.
-- 두 노드에서 키를 만들고 known_hosts 를 같은 내용으로 맞춘다.
[oracle@ol7a ~]$ ssh-keygen -t rsa -N '' -f ~/.ssh/id_rsa -q; cp /tmp/kh ~/.ssh/known_hosts; ls ~/.ssh
id_rsa
id_rsa.pub
known_hosts
-- -q 는 randomart 등 출력을 끈다. 스크립트에서 키를 만들 때 쓴다.
-- known_hosts 는 /tmp/kh 를 복사해 두 노드 모두 같은 네 줄을 갖는다.
[root@ol7b ~]# ssh-keyscan -t ecdsa ol7a ol7b ol7a.example.com ol7b.example.com 2>/dev/null > /tmp/kh
[oracle@ol7b ~]$ ssh-keygen -t rsa -N '' -f ~/.ssh/id_rsa -q; cp /tmp/kh ~/.ssh/known_hosts; ls ~/.ssh
id_rsa
id_rsa.pub
known_hosts
-- 각 노드가 자기 키를 두 노드 모두에 배포한다(자기 자신에게도).
[oracle@ol7a ~]$ for h in ol7a ol7b; do SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh-copy-id $h 2>&1 | grep Number; done
Number of key(s) added: 1
Number of key(s) added: 1
-- ol7a 의 oracle 키가 ol7a(자기 자신)와 ol7b 두 곳에 들어갔다.
-- 자기 자신에게도 넣는 이유: 설치 도구가 로컬 노드에도 ssh 로 명령을 보낸다.
[oracle@ol7b ~]$ for h in ol7a ol7b; do SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh-copy-id $h 2>&1 | grep Number; done
Number of key(s) added: 1
Number of key(s) added: 1
-- ol7b 쪽도 같다. 이제 각 노드의 authorized_keys 에 두 노드 키가 모두 있다.
-- 확인은 이름 네 가지로 모두 해 본다. 하나라도 질문이 뜨면 설치 도구가 멈춘다.
[oracle@ol7a ~]$ for h in ol7a ol7b ol7a.example.com ol7b.example.com; do ssh -o BatchMode=yes $h 'echo $(hostname) $(date +%T)'; done
ol7a.example.com 12:42:58
ol7b.example.com 12:42:59
ol7a.example.com 12:42:59
ol7b.example.com 12:42:59
-- 네 이름 모두 질문 없이 들어갔다. 시각이 1초 안에 맞는 것도 chrony 덕분이다.
-- ol7a → ol7a 도 ssh 로 들어간 것이다(로컬 셸이 아님).
[oracle@ol7b ~]$ for h in ol7a ol7b ol7a.example.com ol7b.example.com; do ssh -o BatchMode=yes $h 'echo $(hostname) $(date +%T)'; done
ol7a.example.com 12:42:59
ol7b.example.com 12:42:59
ol7a.example.com 12:43:00
ol7b.example.com 12:43:00
-- 반대 방향도 네 번 모두 성공. 2 노드 × 4 이름 = 8 조합.
-- 하나라도 질문이 뜨거나 암호를 물으면 cluvfy 의 사용자 동등성 검사가 실패한다.
-- RAC 설치의 sshUserSetup.sh 나 OUI 의 SSH 연결 설정이 하는 일이 이것이다.

 [변형] Ed25519 키와 ssh-keygen 의 다른 쓰임
--------------------------------------------------------------------------------

-- Ed25519 는 OpenSSH 6.5 부터. 7.4 에서도 쓸 수 있고 키가 가장 짧다. 개인 키는 처음부터 새 형식.
[student@ol7a ~]$ ssh-keygen -t ed25519 -N '' -C 'student@ol7a ed25519' -f ~/.ssh/id_ed25519 -q; head -1 ~/.ssh/id_ed25519
-----BEGIN OPENSSH PRIVATE KEY-----
-- Ed25519 는 7.4 에서도 새 형식으로만 저장된다.
-- 옛 도구(일부 백업 에이전트, 옛 paramiko)는 이 형식을 못 읽을 수 있다.
[student@ol7a ~]$ for f in ~/.ssh/id_*.pub; do ssh-keygen -lf $f; done
521 SHA256:SbU0iu6M/aFeLG+QSkotJtzfiimLLk+s2dxq0Jin+4o student@ol7a ecdsa (ECDSA)
256 SHA256:WN3FmucCizUPqoGaH+8APqVwgm7wMyYQ7zEh8Jy06Yw student@ol7a ed25519 (ED25519)
3072 SHA256:Xh45lvoBcfMex5mLh5tOI+Ps0G5OumTprCppdBL4V+U student@ol7a rsa (RSA)
-- 비트 수가 종류마다 다르다. ECDSA 521, Ed25519 256(고정), RSA 3072.
-- 한 사용자가 키 여러 개를 가져도 된다. ssh 는 기본 파일 이름 순서로 내민다.
[student@ol7a ~]$ wc -c ~/.ssh/id_rsa.pub ~/.ssh/id_ecdsa.pub ~/.ssh/id_ed25519.pub
570 /home/student/.ssh/id_rsa.pub
272 /home/student/.ssh/id_ecdsa.pub
102 /home/student/.ssh/id_ed25519.pub
944 total
-- 공개 키 크기: RSA 570, ECDSA 272, Ed25519 102바이트. 붙여 넣기에는 짧은 키가 유리하다.
-- 지문은 종류와 상관없이 SHA256 43자로 같은 길이다.
-- 암호문 바꾸기(-p). -P 옛 암호문, -N 새 암호문.
[student@ol7a ~]$ ssh-keygen -p -P 'Lab15-pass' -N 'Lab15-new' -f ~/.ssh/id_ecdsa; ssh-keygen -y -P 'Lab15-pass' -f ~/.ssh/id_ecdsa; echo rc=$?
Your identification has been saved with the new passphrase.
-- 암호문을 Lab15-new 로 바꿨다. 파일만 다시 암호화되고 키 자체는 그대로다.
-- 그래서 공개 키와 지문도 바뀌지 않는다.
Load key "/home/student/.ssh/id_ecdsa": incorrect passphrase supplied to decrypt private key
-- 옛 암호문으로는 더 이상 열리지 않는다. 서버의 authorized_keys 는 고칠 필요가 없다.
-- -y 는 개인 키를 열어야 하므로 암호문이 틀리면 rc=255 로 끝난다.
rc=255
