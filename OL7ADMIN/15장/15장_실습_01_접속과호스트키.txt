================================================================================
 제15장 실습 01 — 첫 접속과 호스트 키
 대상   : ol7a (클라이언트), ol7b (서버)
 목표   : 첫 접속에서 묻는 호스트 키 지문을 서버 쪽 값과 대조하고, known_hosts
          한 줄의 형식, ssh-keyscan 으로 미리 모으는 방법, ssh -v 출력의 단계를
          읽는다. 서버 호스트 키가 바뀌었을 때의 경고를 재현하고 원인을 확인한 뒤
          ssh-keygen -R 로 정리한다
 배경   : SSH 는 사용자를 인증하기 전에 서버를 먼저 인증한다. 서버는 호스트 키
          (/etc/ssh/ssh_host_*_key)로 서명하고, 클라이언트는 그 공개 키를
          ~/.ssh/known_hosts 에 적어 두었다가 다음 접속부터 대조한다. 첫 접속의
          yes 한 번이 이후 모든 접속의 신뢰 기준이 된다 (본문 15.1, 15.4)
 소요   : 약 30분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : root (ol7a·ol7b)
 주의   : [8] 에서 ol7b 의 ECDSA 호스트 키를 새로 만든다. 원본은 백업해 두고
          [11] 에서 되돌린다
 되돌림 : ol7b 호스트 키 원본 복구(지문 비교), ol7a 의 /root/.ssh 삭제
          → ssh-keygen -lf /etc/ssh/ssh_host_ecdsa_key.pub, ls -ld /root/.ssh
================================================================================

-- 이 랩의 명령은 터미널(tty) 없이 실행된다. ssh 가 yes/no 나 암호를 물으면 키보드
-- 대신 SSH_ASKPASS 도우미(/usr/local/bin/ask)가 답한다. 도우미는 받은 질문 문구를
-- /tmp/ask.log 에 남기므로, 수업에서 화면에 뜨는 질문을 그 파일로 그대로 볼 수 있다.
-- SSH_ASKPASS 는 DISPLAY 변수가 있고 터미널이 없을 때만 쓰인다. 수업에서는 이 두
-- 변수를 빼고 같은 명령을 친 뒤 키보드로 답한다.

[root@ol7a ~]# ls -ld /root/.ssh; ls /etc/ssh
ls: cannot access /root/.ssh: No such file or directory

moduli

ssh_host_rsa_key.pub

-- ssh_config(클라이언트)와 sshd_config(서버)가 같은 디렉터리에 있다.
[root@ol7b ~]# systemctl is-active sshd; ss -ltnp | grep sshd

--------------------------------------------------------------------------------
 [1] 서버 쪽 호스트 키와 지문
--------------------------------------------------------------------------------

-- 호스트 키는 sshd 가 처음 시작될 때 sshd-keygen 이 만든다. 종류마다 개인 키와 .pub 한 쌍.
[root@ol7b ~]# ls -l /etc/ssh/ssh_host_*
-rw-r-----. 1 root ssh_keys  227 Nov 12 05:11 /etc/ssh/ssh_host_ecdsa_key
-rw-r--r--. 1 root root      162 Nov 12 05:11 /etc/ssh/ssh_host_ecdsa_key.pub
-rw-r-----. 1 root ssh_keys  387 Nov 12 05:11 /etc/ssh/ssh_host_ed25519_key
-rw-r--r--. 1 root root       82 Nov 12 05:11 /etc/ssh/ssh_host_ed25519_key.pub
-rw-r-----. 1 root ssh_keys 1679 Nov 12 05:11 /etc/ssh/ssh_host_rsa_key
-rw-r--r--. 1 root root      382 Nov 12 05:11 /etc/ssh/ssh_host_rsa_key.pub
-- 개인 키는 640 root:ssh_keys. sshd-keygen 이 ssh_keys 그룹에 읽기를 준다.
-- 공개 키는 644. 크기는 ecdsa 162, ed25519 82, rsa 382 바이트.
-- 날짜 Nov 12 05:11 은 ol7b 를 설치하고 sshd 가 처음 뜬 시각.
-- -l : 지문 출력, -f : 키 파일. 기본 해시는 SHA256(Base64). -E md5 는 옛 형식(콜론 16진수).
[root@ol7b ~]# for k in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf $k; done
256 SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo no comment (ECDSA)
256 SHA256:WcmhzTiTnVeFE/EGCtMx+daNIC0BIW0a1S0v2l2FDUA no comment (ED25519)
2048 SHA256:oMhuTRh5Cyo5LTPzM0ZGY5vx7rShonjkdjOHzHdlDNE no comment (RSA)
-- 열: 비트 수, 지문(SHA256:Base64), 주석, (종류).
-- 호스트 키에는 주석이 없어 no comment 로 나온다.
-- 이 실습에서 볼 값은 ECDSA 의 SHA256:MrVOo4BJ... 이다.
-- 이 값을 서버 관리자에게서 따로(문서·전화) 받아 두는 것이 원칙.
[root@ol7b ~]# ssh-keygen -E md5 -lf /etc/ssh/ssh_host_ecdsa_key.pub
256 MD5:65:b2:0d:b9:fd:c7:2b:7e:af:fe:4d:17:dc:65:25:fe no comment (ECDSA)
-- 옛 클라이언트(PuTTY 옛 판 등)가 보여 주는 형식. 같은 키의 다른 표기다.
-- 이 지문을 서버 관리자에게서 따로(전화·문서) 받아 첫 접속 때 대조하는 것이 원칙이다.
[root@ol7b ~]# cp -p /etc/ssh/ssh_host_ecdsa_key /etc/ssh/ssh_host_ecdsa_key.pub /root/
-- [8] 에서 키를 새로 만들기 전에 원본을 남긴다. -p 는 권한·시각 보존.

--------------------------------------------------------------------------------
 [2] 오류 ② — 터미널 없는 첫 접속
--------------------------------------------------------------------------------

-- 스크립트·cron 처럼 답할 사람이 없는 곳에서 처음 보는 서버에 접속하면 어떻게 되나.
-- BatchMode=yes : 암호·질문을 일절 묻지 않고 실패로 처리(스크립트용 옵션).
-- 아래부터 클라이언트 ol7a 쪽이다.
[root@ol7a ~]# ssh -o BatchMode=yes ol7b hostname; echo rc=$?
Host key verification failed.
-- 질문할 수 없으니 호스트 키 확인 단계에서 바로 실패. rc=255 는 ssh 자체의 실패.
-- 기본값 ask 는 터미널이 있어야 물을 수 있다.
-- cron·스크립트에서 처음 보는 서버에 붙으면 이렇게 끝난다.
rc=255
-- StrictHostKeyChecking=yes : known_hosts 에 없는 호스트는 묻지도 않고 거부.
[root@ol7a ~]# ssh -o StrictHostKeyChecking=yes ol7b hostname; echo rc=$?
No ECDSA host key is known for ol7b and you have requested strict checking.
-- known_hosts 에 없으면 묻지도 않고 거부한다는 뜻을 그대로 말한다.
-- 클라이언트가 고른 키 종류가 ECDSA 라는 것도 이 줄에서 보인다.
Host key verification failed.
rc=255
-- [OL8/9] OpenSSH 7.6 부터 accept-new(새 호스트만 자동 등록) 값이 있다. 7.4 에서는:
[root@ol7a ~]# ssh -o StrictHostKeyChecking=accept-new ol7b hostname; echo rc=$?
command-line line 0: unsupported option "accept-new".
-- 7.4 는 yes·no·ask 만 안다. 옵션 이름은 맞고 값이 틀렸다는 메시지.
-- 7.9 에서 비슷한 효과를 내려면 [6] 처럼 keyscan 으로 미리 넣는다.
rc=255
[root@ol7a ~]# ls -l /root/.ssh
total 0
-- 세 번 실패하는 동안 ssh 가 빈 ~/.ssh(700)를 만들어 두었다.

-- 증상   : ssh -o BatchMode=yes ol7b → "Host key verification failed.", rc=255
-- 원인   : known_hosts 에 ol7b 가 없고, 확인 질문에 답할 터미널이 없다
-- 조치   : 서버 지문을 따로 확인한 뒤 [3] 처럼 한 번 접속하거나 [6] 의 keyscan 으로 등록
-- 재확인 : [11] 에서 BatchMode 접속이 호스트 키 단계를 통과(인증 단계에서 멈춤)

--------------------------------------------------------------------------------
 [3] 첫 접속 — 지문 확인 질문에 yes
--------------------------------------------------------------------------------

[root@ol7a ~]# SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh ol7b hostname; echo rc=$?
Warning: Permanently added 'ol7b,172.16.225.62' (ECDSA) to the list of known hosts.
-- 도우미가 yes 와 root 암호를 대신 넣었다. 이름과 IP 가 한 줄로 등록된다.
-- Warning 은 stderr, ol7b.example.com 은 원격 hostname 의 출력.
ol7b.example.com
rc=0
-- ssh 가 물은 질문 두 개(호스트 키 확인, root 암호)를 그대로 본다.
[root@ol7a ~]# cat /tmp/ask.log
The authenticity of host 'ol7b (172.16.225.62)' can't be established.
ECDSA key fingerprint is SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo.
ECDSA key fingerprint is MD5:65:b2:0d:b9:fd:c7:2b:7e:af:fe:4d:17:dc:65:25:fe.
-- 7.4 는 질문에 SHA256 과 MD5 두 형식을 모두 보여 준다.
-- [1] 에서 ol7b 가 보여 준 SHA256:MrVOo4BJ... 와 같다. 여기서 yes 가 맞다.
Are you sure you want to continue connecting (yes/no)? 
-- [OL8/9] 8.x 의 질문은 (yes/no/[fingerprint]) 다. 지문을 붙여 넣어 답할 수 있다.
root@ol7b's password: 
-- 호스트 키 다음에야 암호를 묻는다. 서버를 먼저 믿고 사용자를 나중에 인증한다.
-- 질문 문구의 ol7b 는 명령줄에 쓴 이름 그대로다.

 [4] known_hosts 한 줄의 형식
--------------------------------------------------------------------------------

[root@ol7a ~]# ls -l /root/.ssh/known_hosts; wc -l /root/.ssh/known_hosts
-rw-r--r--. 1 root root 180 Nov 16 10:39 /root/.ssh/known_hosts
1 /root/.ssh/known_hosts
-- 권한 644, 180바이트, 한 줄. 사용자 파일이라 소유자는 root.
-- 공개 키 본문이 길어서 앞 90자만 자른다.
[root@ol7a ~]# cut -c1-90 /root/.ssh/known_hosts
ol7b,172.16.225.62 ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTYAAAAIbmlzdHAyNTYAAAB
[root@ol7a ~]# awk '{print "1열(호스트):", $1; print "2열(키 종류):", $2; print "3열(키) 길이:", length($3)}' /root/.ssh/known_hosts
1열(호스트): ol7b,172.16.225.62
2열(키 종류): ecdsa-sha2-nistp256
3열(키) 길이: 140
-- 1열: 접속에 쓴 이름과 IP. CheckHostIP yes(기본)라 IP 도 같이 적는다.
-- 2열: 키 종류. ecdsa-sha2-nistp256 은 256비트 ECDSA.
-- 3열: 공개 키 Base64 본문. RSA 2048 이면 372자쯤 된다.
-- 줄 끝에 주석 필드를 더 붙여도 된다. ssh 는 무시한다.
-- known_hosts 에 적힌 키의 지문을 뽑아 [1] 의 서버 값과 비교한다.
[root@ol7a ~]# ssh-keygen -lf /root/.ssh/known_hosts
256 SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo ol7b,172.16.225.62 (ECDSA)
-- known_hosts 에 적힌 키의 지문이 서버의 값과 같다. 손으로 대조할 때 이 명령을 쓴다.
-- -F : known_hosts 에서 호스트 찾기. 이름·IP 어느 쪽으로도 찾힌다.
[root@ol7a ~]# ssh-keygen -F ol7b | cut -c1-80; ssh-keygen -F 172.16.225.62 | cut -c1-80
# Host ol7b found: line 1 
ol7b,172.16.225.62 ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTYAAAAIbmlzd
# Host 172.16.225.62 found: line 1 
-- 이름으로도 IP 로도 같은 1번 줄이 찾힌다.
ol7b,172.16.225.62 ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTYAAAAIbmlzd

 [5] 두 번째 접속 — 묻지 않는다
--------------------------------------------------------------------------------

[root@ol7a ~]# SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh ol7b hostname; cat /tmp/ask.log
ol7b.example.com
root@ol7b's password: 
-- 두 번째 접속: 질문 기록에 호스트 키 확인이 없고 암호 질문 하나뿐이다.
-- 키 인증을 아직 만들지 않았으므로 암호는 계속 묻는다(02 에서 해결).
-- 다른 이름(FQDN)으로 접속하면 known_hosts 에는 그 이름이 없다.
[root@ol7a ~]# SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh ol7b.example.com hostname; cat /tmp/ask.log
Warning: Permanently added 'ol7b.example.com' (ECDSA) to the list of known hosts.
ol7b.example.com
The authenticity of host 'ol7b.example.com (172.16.225.62)' can't be established.
ECDSA key fingerprint is SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo.
ECDSA key fingerprint is MD5:65:b2:0d:b9:fd:c7:2b:7e:af:fe:4d:17:dc:65:25:fe.
Are you sure you want to continue connecting (yes/no)? 
root@ol7b.example.com's password: 
-- FQDN 으로 접속하자 같은 지문인데도 다시 물었다. 대조는 이름 기준이다.
-- 이번에는 IP 가 이미 있어서 이름만 새 줄로 등록됐다.
[root@ol7a ~]# cut -c1-60 /root/.ssh/known_hosts
ol7b,172.16.225.62 ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItb
ol7b.example.com ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbml
-- 같은 키가 두 줄에 있다. RAC 처럼 이름 여러 개를 쓰는 환경은 모두 등록해야 한다.
-- 짧은 이름, FQDN, IP 세 가지가 이제 모두 known_hosts 에 있다.

--------------------------------------------------------------------------------
 [6] ssh-keyscan — 접속하지 않고 호스트 키 모으기
--------------------------------------------------------------------------------

-- -t : 받을 키 종류. 출력의 # 줄은 stderr 로 나오는 서버 배너다.
[root@ol7a ~]# ssh-keyscan -t rsa,ecdsa,ed25519 ol7b 2>&1 | cut -c1-80
# ol7b:22 SSH-2.0-OpenSSH_7.4
# ol7b:22 SSH-2.0-OpenSSH_7.4
# ol7b:22 SSH-2.0-OpenSSH_7.4
ol7b ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABAQDH29JdjaRXkgH8DYXPu9hPRbAmFcrlLpeQ071
ol7b ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTYAAAAIbmlzdHAyNTYAAABBBFq
ol7b ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDOlAqfsRMNeOBWn+d5zdu6OTXWrOUWdF7+Tnc3
-- # 줄: 서버 배너(stderr). 키 종류마다 한 번씩 접속해서 세 번 나온다.
-- 나머지: known_hosts 형식 그대로. 다만 이름만 있고 IP 는 붙지 않는다.
-- 받은 키의 지문을 바로 계산한다(-f - 는 표준 입력).
[root@ol7a ~]# ssh-keyscan -t ecdsa ol7b 2>/dev/null | ssh-keygen -lf -
256 SHA256:MrVOo4BJEDHvlQH0owC4B+OrcIa7JonZUKBXOrS/GVo ol7b (ECDSA)
-- 받은 키의 지문을 바로 계산했다. keyscan 은 검증을 하지 않으므로 이 대조가 필수다.
-- -f - 는 표준 입력에서 읽으라는 뜻.
-- 여러 노드를 미리 등록할 때(RAC 노드 간 동등성 준비 등) 이렇게 모은다.
[root@ol7a ~]# ssh-keyscan -t ecdsa ol7a ol7a.example.com 172.16.225.61 2>/dev/null >> /root/.ssh/known_hosts; wc -l /root/.ssh/known_hosts
5 /root/.ssh/known_hosts
-- ol7a 자신의 키를 이름 셋으로 넣었다. 2줄 → 5줄.
-- 자기 자신에게 ssh 하는 도구(RAC 설치)를 위한 준비와 같다.

--------------------------------------------------------------------------------
 [7] ssh -v — 접속 단계 읽기
--------------------------------------------------------------------------------

-- -v 는 debug1 수준. 줄이 100줄 넘게 나오므로 단계를 보여 주는 줄만 골라낸다.
[root@ol7a ~]# SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh -v ol7b true 2>&1 | grep -E 'debug1: (Reading|Connecting|Connection est|Local version|Remote protocol|Authenticating|SSH2_MSG_KEXINIT sent|kex: algorithm|kex: host key|kex: server->client|Server host key|Host .ol7b. is known|Authentications that|Next authentication|Authentication succeeded|Sending command|Exit status)'
debug1: Reading configuration data /etc/ssh/ssh_config
-- 단계 1: 설정 읽기. ~/.ssh/config 가 없어 전역 파일만 읽었다.

[root@ol7a ~]# ssh -o BatchMode=yes ol7b true; echo rc=$?; ssh-keygen -lF ol7b

-- -lF 는 찾은 줄을 지문으로 보여 준다. 5번 줄이 원본 지문으로 돌아왔다.
