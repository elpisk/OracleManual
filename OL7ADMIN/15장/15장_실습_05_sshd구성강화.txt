================================================================================
 제15장 실습 05 — sshd 구성 강화
 대상   : ol7b (서버 설정을 바꿈), ol7a (root, 클라이언트)
 목표   : PermitRootLogin·PasswordAuthentication·AllowUsers 를 바꿔 접속 결과가
          어떻게 달라지는지 네 가지 조합으로 확인한다. 바꿀 때마다 sshd -t 로 문법을,
          sshd -T 로 실제 적용값을 본다. sshd 를 다시 시작해도 이미 열린 세션은
          유지된다는 것을 확인하고, 검증 없이 재시작해 sshd 가 못 뜬 상황을
          직렬 콘솔로 복구한다
 배경   : sshd_config 는 같은 키워드가 여러 번 나오면 처음 값이 이긴다. 파일을 고쳐도
          sshd 가 다시 읽기(reload·restart) 전에는 반영되지 않는다. OL7 의
          sshd.service 는 KillMode=process 라 재시작해도 기존 세션 프로세스는 남는다.
          그래서 원격 작업 중에는 세션 하나를 열어 둔 채 바꾸고 새 접속으로 확인한다
          (본문 15.2)
 소요   : 약 40분
 선행   : ol7-base, ol7b-base 스냅샷 (⚠ 설정을 잘못 두면 원격 접속이 끊기므로 스냅샷 필수)
 계정   : root (두 노드), student (접속 대상)
 주의   : [10] 에서 ol7b 의 sshd 가 기동에 실패한다. 직렬 콘솔로 복구한다
 되돌림 : sshd_config 원본 복구 → diff, sshd -T, try 결과가 [2] 와 같음
================================================================================

 [1] 준비 — root 키를 ol7b 의 root·student 에 배포
--------------------------------------------------------------------------------

[root@ol7a ~]# ssh-keygen -t ecdsa -N '' -f /root/.ssh/id_ecdsa -q; ssh-keyscan -t ecdsa ol7b 2>/dev/null > /root/.ssh/known_hosts
[root@ol7a ~]# for u in root student; do SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 ssh-copy-id $u@ol7b 2>&1 | grep Number; done
Number of key(s) added: 1
Number of key(s) added: 1
-- root@ol7b, student@ol7b 두 계정에 같은 root@ol7a 의 키를 넣었다.
-- 암호는 두 번 물었다(계정마다).
-- 이제 ol7a 의 root 는 두 계정 모두 키로 들어간다.
[root@ol7a ~]# cat /usr/local/bin/try
#!/bin/bash
# root·student 두 계정 × 공개 키·암호 두 방식으로 ol7b 에 접속해 본 결과를 한 줄씩
for u in root student; do
  for m in publickey password; do
    r=$(SSH_ASKPASS=/usr/local/bin/ask DISPLAY=:0 timeout 20 ssh -o PreferredAuthentications=$m -o ConnectTimeout=5 $u@ol7b 'echo OK' 2>&1 | tail -1)
    printf '%-8s %-10s %s\n' $u $m "$r"
  done
done
-- try 는 PreferredAuthentications 로 방식을 하나만 쓰게 해서 네 조합을 따로 본다.
-- tail -1 로 마지막 줄(OK 또는 오류 메시지)만 남긴다. timeout 20 은 걸림 방지.
-- 열: 계정, 방식, 결과.

 [3] root 는 키로만 — PermitRootLogin prohibit-password
--------------------------------------------------------------------------------

-- 7.4 의 값: yes(기본) / prohibit-password(=without-password) / forced-commands-only / no
[root@ol7b ~]# sed -i 's/^#PermitRootLogin yes/PermitRootLogin prohibit-password/' /etc/ssh/sshd_config; diff /root/sshd_config.orig /etc/ssh/sshd_config
38c38
< #PermitRootLogin yes
---
> PermitRootLogin prohibit-password
-- 주석 줄을 고쳤다. 38번 줄. diff 의 38c38 은 38번 줄이 바뀌었다는 뜻.
-- < 는 원본, > 는 새 파일.
-- 파일만 고친 상태. sshd 는 아직 옛 설정으로 돈다.
[root@ol7a ~]# try
root     publickey  OK
root     password   OK
student  publickey  OK
student  password   OK
-- 파일을 고쳤지만 결과는 그대로. 실행 중인 sshd 는 아직 옛 설정이다.
-- 즉시 반영되지 않는다.
-- sshd -T 를 쳤다면 이미 새 값이 보였을 것이다(파일 기준).
-- -t : 문법 검사(출력 없고 종료 코드 0 이면 통과). 그다음 reload 로 다시 읽게 한다.
[root@ol7b ~]# sshd -t; echo rc=$?; systemctl reload sshd
rc=0
-- sshd -t 는 통과하면 아무 말도 없다. rc=0 이 유일한 신호.
-- reload 는 sshd 에 HUP 을 보낸다(ExecReload, [6]). 출력이 없다.
-- 이번 세션은 끊기지 않는다.
[root@ol7a ~]# try
root     publickey  OK
root     password   Permission denied (publickey,gssapi-keyex,gssapi-with-mic,password).
-- root 암호만 막혔다. 서버가 받는 방식 목록에는 password 가 여전히 있다.
-- 다른 계정은 암호를 써도 되기 때문이다. root 에게만 암호가 거부된다.
-- 바뀐 줄: root password 하나.
-- root 키 접속은 그대로 OK.
student  publickey  OK
student  password   OK

ol7b sshd[10286]: Accepted publickey for student from 172.16.225.61 port 37462 ssh2: ECDSA SHA256:EVF+V0TM+kb1lcYKW2nzR4QTlUh9GbPrSmZU5oXDZF0
ol7b sshd[10300]: Accepted password for student from 172.16.225.61 port 37478 ssh2
-- tail -2 에는 마지막 두 접속(student 키·암호)만 보였다. root 의 거부는 그 앞에 있다.

 [4] 같은 키워드가 두 번 — 처음 값이 이긴다
--------------------------------------------------------------------------------

-- 흔한 실수: 기본 파일에 이미 PasswordAuthentication yes 가 있는데 끝에 no 를 덧붙인다.
[root@ol7b ~]# grep -n '^PasswordAuthentication' /etc/ssh/sshd_config
65:PasswordAuthentication yes
-- 65번 줄에 살아 있는 yes 가 있다.
-- -n: 줄 번호.
[root@ol7b ~]# echo 'PasswordAuthentication no' >> /etc/ssh/sshd_config; grep -n '^PasswordAuthentication' /etc/ssh/sshd_config
65:PasswordAuthentication yes
140:PasswordAuthentication no
-- 파일 끝(140번 줄)에 no 를 덧붙였다. 같은 키워드가 두 번.
-- 셸 설정처럼 뒤가 이긴다고 생각하기 쉽다.
[root@ol7b ~]# sshd -t; echo rc=$?; sshd -T | grep '^passwordauthentication'
rc=0
passwordauthentication yes
-- 문법은 통과(rc=0), 적용값은 yes. 처음 나온 65번 줄이 이겼다.
-- reload 했다면 암호 인증이 꺼진 줄 알고 넘어갔을 것이다. sshd -T 로만 잡힌다.
-- 이 단계에서는 reload 하지 않았다.
-- [OL8/9] OL8 이후는 sshd_config.d/*.conf 가 앞에서 include 되어 그쪽 값이 이긴다.

permitrootlogin without-password

--------------------------------------------------------------------------------
 [6] 재시작해도 기존 세션은 남는다
--------------------------------------------------------------------------------

-- 지금 ol7b 의 sshd 프로세스: 리스너(-D) 하나와 세션마다 하나씩
[root@ol7b ~]# ps -o pid,ppid,etime,args -C sshd
  PID  PPID     ELAPSED COMMAND
 1352     1       00:19 /usr/sbin/sshd -D
 4837  1352       00:13 sshd: root@notty
-- PID 1352 가 리스너(-D, 부모는 systemd). 4837 이 이 랩을 돌리는 root 세션(notty).
-- 세션 프로세스의 부모(PPID)가 리스너다.
-- ELAPSED 는 시작 뒤 경과 시간.
[root@ol7b ~]# systemctl show sshd -p KillMode -p Restart -p RestartUSec -p ExecReload
Restart=on-failure
RestartUSec=42s
ExecReload={ path=/bin/kill ; argv[]=/bin/kill -HUP $MAINPID ; ignore_errors=no ; start_time=[Mon 2026-11-16 12:50:18 KST] ; stop_time=[Mon 2026-11-16 12:50:18 KST] ; pid=10434 ; code=exited ; status=0 }
KillMode=process
-- KillMode=process: 멈출 때 주 프로세스(리스너)만 죽인다. 세션 프로세스는 남는다.
-- Restart=on-failure, 42초: 비정상 종료하면 42초 뒤 다시 띄운다([10] 에서 보인다).
-- ExecReload 는 kill -HUP $MAINPID. [3]·[5] 의 reload 기록이 status=0 으로 남았다.
-- 볼 값: KillMode, Restart, RestartUSec.
[root@ol7b ~]# systemctl restart sshd; ps -o pid,ppid,etime,args -C sshd
  PID  PPID     ELAPSED COMMAND
 4837     1       00:13 sshd: root@notty
10532     1       00:00 /usr/sbin/sshd -D
-- 리스너는 새 PID 10532(경과 00:00). 세션 4837 은 그대로이고 부모가 1(systemd)로 바뀌었다.
-- 옛 리스너가 죽어 고아가 되었기 때문이다. 세션은 끊기지 않았다.
-- restart 는 출력이 없다.
-- 이 명령이 실행된다는 것 자체가 기존 세션이 살아 있다는 증거다.
[root@ol7b ~]# echo "still here: $(date +%T)"
still here: 12:50:20
-- 같은 세션으로 다음 명령이 돈다. 세션이 옛 설정으로 살아 있다는 것은 새 설정의 증거가 아니다.

--------------------------------------------------------------------------------
 [7] 접속 계정 제한 — AllowUsers
--------------------------------------------------------------------------------

-- 공백으로 여러 명. user@host 형식으로 출발지도 제한할 수 있다.
[root@ol7b ~]# echo 'AllowUsers student' >> /etc/ssh/sshd_config; sshd -t && systemctl reload sshd; sshd -T | grep -E '^allowusers'
allowusers student
-- AllowUsers 는 기본 파일에 없어서 덧붙여도 된다. 적용값 확인.
-- 목록에 없는 계정은 모두 거부.
[root@ol7a ~]# try
root     publickey  Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
root     password   Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
student  publickey  OK
student  password   Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
-- root 는 키까지 막혔다. student 키만 OK. 암호는 [5] 부터 꺼져 있다.
-- 바뀐 줄: root publickey.
[root@ol7b ~]# grep 'not allowed' /var/log/secure | tail -1 | cut -c17-
ol7b sshd[10647]: User root from ol7a.example.com not allowed because not listed in AllowUsers
-- 이유가 명확히 남는다. 출발지는 IP 대신 이름(UseDNS yes 의 역할).
-- 이 거부는 키 검증보다 먼저 일어난다. 키가 맞는지 보지도 않는다.
-- 클라이언트에는 이유가 안 보인다.

--------------------------------------------------------------------------------
 [8] 오류 ② — AllowUsers 에서 자기 계정을 빼 버림
--------------------------------------------------------------------------------

-- 관리자는 student 로 들어와 sudo 를 쓰는 운영 규칙이라고 하자. oracle 만 허용하도록
-- 바꾸면서 student 를 빠뜨린다. sshd -t 는 문법만 보므로 통과한다.
[root@ol7b ~]# sed -i 's/^AllowUsers student/AllowUsers oracle/' /etc/ssh/sshd_config; sshd -t; echo rc=$?; systemctl reload sshd
rc=0
-- sshd -t 는 rc=0. oracle 이 이 서버에 없다는 것도, student 가 빠졌다는 것도 모른다.
-- 문법만 본다.
-- 계정 존재 여부는 모른다.
[root@ol7a ~]# try
root     publickey  Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
root     password   Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
student  publickey  Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
student  password   Permission denied (publickey,gssapi-keyex,gssapi-with-mic).
-- 네 줄 모두 거부. 관리자 계정 student 도 새 접속으로는 못 들어온다.
-- 이 root 세션만 살아 있다.
[root@ol7b ~]# grep 'not allowed' /var/log/secure | tail -2 | cut -c17-
ol7b sshd[10713]: User student from ol7a.example.com not allowed because not listed in AllowUsers
ol7b sshd[10715]: User student from ol7a.example.com not allowed because not listed in AllowUsers

-- 증상   : try 네 줄 모두 "Permission denied". secure "User student ... not listed in AllowUsers"
-- 원인   : AllowUsers 를 oracle 로 바꾸며 관리자 계정 student 를 뺌. sshd -t 는 rc=0 으로 통과
-- 조치   : 열어 둔 root 세션에서 AllowUsers student oracle 로 고치고 sshd -t, reload
-- 재확인 : 새 접속 try 에서 student publickey OK (아래)
-- 열어 둔 세션(이 root 세션)에서 바로 고친다. 이 세션까지 닫았다면 콘솔로 가야 한다.
[root@ol7b ~]# sed -i 's/^AllowUsers oracle/AllowUsers student oracle/' /etc/ssh/sshd_config; sshd -t && systemctl reload sshd; sshd -T | grep '^allowusers'
allowusers student
allowusers oracle

 [9] 그 밖의 권장 설정
--------------------------------------------------------------------------------

-- 실습에서 계속 쓰려면 AllowUsers 는 뺀다. 나머지는 운영 서버에서 흔히 쓰는 값.
[root@ol7b ~]# sed -i '/^AllowUsers/d' /etc/ssh/sshd_config; grep -c AllowUsers /etc/ssh/sshd_config
0
-- AllowUsers 줄을 모두 지웠다(0개).
-- 이후 단계는 계정 제한 없이 진행.
[root@ol7b ~]# cat >> /etc/ssh/sshd_config <<'EOF'
MaxAuthTries 3
LoginGraceTime 30
ClientAliveInterval 300
ClientAliveCountMax 2
Banner /etc/issue.net
EOF
-- 다섯 키워드 모두 기본 파일에 살아 있는 줄이 없어서 덧붙여도 적용된다.
-- X11Forwarding 은 살아 있는 줄이라 sed 로 고쳤다.
[root@ol7b ~]# sed -i 's/^X11Forwarding yes/X11Forwarding no/' /etc/ssh/sshd_config; sshd -t && systemctl reload sshd
[root@ol7b ~]# sshd -T | grep -E '^(maxauthtries|logingracetime|clientaliveinterval|clientalivecountmax|x11forwarding|banner|allowusers) '
logingracetime 30
maxauthtries 3
clientaliveinterval 300
clientalivecountmax 2
x11forwarding no
banner /etc/issue.net
-- 인증 3회, 대기 30초, 300초마다 생존 확인 2회 무응답이면 끊음, X11 끔, 배너.
-- allowusers 줄이 없다. 지운 것이 반영됐다.
-- 모두 [0] 과 다른 값이다.
[root@ol7b ~]# cat /etc/issue.net
\S
Kernel \r on an \m
-- /etc/issue.net 의 \S·\r·\m 은 agetty 가 콘솔에서 바꿔 주는 이스케이프다.
-- Banner 는 인증 전에 보내진다. 클라이언트는 stderr 로 출력한다.
[root@ol7a ~]# ssh -o BatchMode=yes student@ol7b hostname
\S
Kernel \r on an \m
ol7b.example.com
-- sshd 는 이스케이프를 풀지 않고 그대로 보낸다. 배너 파일은 따로 평문으로 만든다.
-- 배너는 stderr 로 나온다. 스크립트가 stdout 만 읽으면 영향이 없다.
-- 법적 고지 문구를 넣는 자리.

 [변형] Match 블록 — 출발지에 따라 다른 설정
--------------------------------------------------------------------------------

-- 내부망(172.16.225.0/24)에서는 암호 인증을 허용하고 나머지는 키만. Match 는 파일 끝에 둔다.
[root@ol7b ~]# printf 'Match Address 172.16.225.0/24\n    PasswordAuthentication yes\n' >> /etc/ssh/sshd_config; sshd -t && systemctl reload sshd; tail -3 /etc/ssh/sshd_config
Banner /etc/issue.net
Match Address 172.16.225.0/24
    PasswordAuthentication yes
-- Match 는 파일 끝, 조건 아래 줄은 들여 써서 구분한다(들여쓰기는 문법이 아니라 관례).
-- -C : 가상의 접속 조건(user, host, addr)으로 sshd -T 를 계산해 본다.
[root@ol7b ~]# sshd -T -C user=student,host=ol7a,addr=172.16.225.61 | grep '^passwordauthentication'
passwordauthentication yes
-- 내부망 주소로 가정하면 암호 인증 yes.
-- 전역값은 [5] 의 no.
[root@ol7b ~]# sshd -T -C user=student,host=x,addr=10.1.1.5 | grep '^passwordauthentication'
passwordauthentication no
-- 바깥 주소로 가정하면 전역값 no. 접속하지 않고 Match 효과를 미리 계산했다.
-- -C 에는 user·host·addr 세 값을 모두 준다. 하나라도 빠지면 오류가 난다.
[root@ol7a ~]# try
root     publickey  OK
root     password   Authentication failed.
-- root 암호: PermitRootLogin 은 prohibit-password 그대로라 거부.
-- 메시지가 다르다. MaxAuthTries 3 을 넘겨 서버가 끊었다(시도 세 번 × 실패).
student  publickey  OK
student  password   OK
-- student 암호는 내부망 Match 덕분에 OK. 출발지 172.16.225.61 이 조건에 맞았다.
-- 키 두 줄은 그대로 OK.
