================================================================================
 제18장 실습 06 — 소켓 상태와 tcpdump 로 ol7a ↔ ol7b 통신 보기
 대상   : ol7a, ol7b
 목표   : ss -tanp·ss -s·netstat -s 로 소켓과 TCP 카운터를 읽고, ol7a 에서
          ol7b 로 가는 연결을 tcpdump 로 캡처해(-i, -nn, 호스트·포트 필터,
          -w/-r) 3-way handshake·데이터·종료 패킷의 플래그를 읽는다. 방화벽에
          막힌 연결이 패킷으로 어떻게 보이는지도 본다
 배경   : ss 는 커널의 소켓 표를 netlink 로 바로 읽고 netstat 은 /proc/net 파일을
          읽는다. 7.9 에는 둘 다 있다. tcpdump 는 한 인터페이스의 패킷을 BPF 필터로
          골라 찍는다. -i 를 빼면 첫 번째 인터페이스 하나만 보고, -n 을 빼면 주소마다
          이름 조회를 한다. TCP 연결은 SYN → SYN-ACK → ACK 로 열리고 FIN 으로
          닫힌다(본문 18.5)
 소요   : 약 30분
 선행   : ol7-base, ol7b-base 스냅샷. ol7b 를 켠다
 계정   : root (두 노드)
 주의   : ol7b 의 firewalld 에 런타임 규칙을 하나 더한다(재시작하면 사라짐).
          두 노드에 nmap-ncat 을 설치하고 끝에서 지운다
 되돌림 : ol7b 런타임 규칙 제거, ncat 프로세스 0개, nmap-ncat 제거, 캡처 파일 삭제.
          확인은 firewall-cmd --list-ports(빈 줄) · rpm -q nmap-ncat

-- 열 해설
--   State   : LISTEN(연결 대기), ESTAB(연결됨), TIME-WAIT(닫힌 뒤 대기) 등
--   Recv-Q  : ESTAB 에서는 받았지만 프로그램이 아직 안 읽은 바이트, LISTEN 에서는 대기 중인 연결 수
--   Send-Q  : ESTAB 에서는 보냈지만 상대가 확인 안 한 바이트, LISTEN 에서는 백로그 크기(128·100)
--   Local·Peer Address:Port, Process : 소켓을 가진 프로세스 이름·PID·fd
-- 대기 중: rpcbind 111, sshd 22, postfix master 25(127.0.0.1 만).
-- IPv4·IPv6 가 따로 한 줄씩
-- ESTAB 한 줄은 이 러너의 접속(호스트 172.16.225.1 → 22, sshd
-- 1984)이다
-- 대기 소켓만: -l. 줄 하나가 "이 주소·포트로 들어오는 연결을 받는
-- 프로그램" 이다.

-- -D : tcpdump 가 캡처할 수 있는 장치 목록. 번호 순서가 기본 선택
-- 순서다.

2.nfqueue (Linux netfilter queue (NFQUEUE) interface)
3.ens32
4.ens33
5.any (Pseudo-device that captures on all interfaces)
6.lo [Loopback]
-- 목록 1·2 번이 nflog·nfqueue 다. 이 버전의 tcpdump 는 -i 가
-- 없으면 이 목록의 1번을 고른다
-- 자기 자신(127.0.0.1:7000)에 연결하는 프로그램의 패킷을 잡으려
-- 한다. -i 없이.
[root@ol7a ~]# nohup timeout 90 ncat -lk 127.0.0.1 7000 >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# nohup timeout 8 tcpdump -nn -c 6 port 7000 >/tmp/td1.log 2>&1 </dev/null &
[root@ol7a ~]# sleep 1; echo hi | ncat --send-only 127.0.0.1 7000; sleep 8; cat /tmp/td1.log
tcpdump: NFLOG link-layer type filtering not implemented
-- 증상   : tcpdump -nn -c 6 port 7000 이 패킷 하나 없이 "tcpdump:
--          NFLOG
--          link-layer type filtering not implemented" 를 찍고 끝났다
-- 원인   : -i 를 주지 않아 tcpdump -D 의 첫 장치 nflog 를 골랐고,

 [4] ol7b 로 연결 — 방화벽에 막히면 패킷이 어떻게 보이나
--------------------------------------------------------------------------------
-- ol7b 에 5555 포트 수신기를 띄운다. -k 는 연결이 끝나도 계속
-- 받는다.
[root@ol7b ~]# nohup timeout 600 ncat -lk 5555 >/tmp/recv.txt 2>&1 </dev/null &
[root@ol7b ~]# ss -tlnp | grep 5555
LISTEN 0      10           0.0.0.0:5555      0.0.0.0:*    users:(("ncat",pid=10175,fd=4))  
LISTEN 0      10              [::]:5555         [::]:*    users:(("ncat",pid=10175,fd=3))  
-- ol7b 의 ncat(PID 10175)이 IPv4·IPv6 5555 에서 기다린다. 백로그
-- 10
-- ol7a 에서 캡처를 걸고 보낸다.
--   -i ens32 : 인터페이스  -nn : 주소·포트 모두 숫자  -w : 해석하지 않고 파일로  host·port : BPF 필터
[root@ol7a ~]# nohup timeout 10 tcpdump -i ens32 -nn -w /tmp/fw.pcap host 172.16.225.62 and port 5555 >/tmp/td3.log 2>&1 </dev/null &
[root@ol7a ~]# sleep 1; echo hello | ncat --send-only ol7b 5555; echo "ncat exit=$?"
Ncat: No route to host.
ncat exit=1
-- 증상   : ol7a → ol7b 5555 연결에서 Ncat: No route to host.,
--          exit 1
-- 원인   : 경로 문제가 아니다. 같은 서브넷이고 ping·ssh 는 된다.
--          ol7b 의 firewalld(public 영역)가
--          5555 를 허용하지 않아 SYN 을 버리고 ICMP host-prohibited(형식 3)로 거부했다.
--          커널이 그 ICMP 를 EHOSTUNREACH 로 바꾸고, ncat 은 그것을 No route to host 로 찍는다
-- 조치   : ol7b 에서 firewall-cmd --add-port=5555/tcp (런타임)
-- 재확인 : [5] 에서 같은 명령이 exit 0, ol7b 의 recv.txt 에 hello
[root@ol7a ~]# sleep 10; cat /tmp/td3.log; tcpdump -nn -r /tmp/fw.pcap
tcpdump: listening on ens32, link-type EN10MB (Ethernet), capture size 262144 bytes
1 packet captured
1 packet received by filter
0 packets dropped by kernel
reading from file /tmp/fw.pcap, link-type EN10MB (Ethernet)
17:39:14.158486 IP 172.16.225.61.37654 > 172.16.225.62.5555: Flags [S], seq 2754682205, win 64240, options [mss 1460,sackOK,TS val 2414490428 ecr 0,nop,wscale 7], length 0
-- 잡힌 것은 나가는 SYN 하나뿐(1 packet captured). SYN-ACK 가 없다
-- 거부 응답은 ICMP 패킷이라 TCP 포트가 없다. port 5555 필터에
-- 걸리지 않아 캡처에서 빠졌다
-- 거부 응답(ICMP)이 이 캡처에 들어 있는지 icmp 만 따로 걸러 본다.
[root@ol7a ~]# tcpdump -nn -v -r /tmp/fw.pcap icmp 2>/dev/null | head -4
-- 출력 없음. 이 파일에는 ICMP 가 없다. 거부를 보려면 필터를 'host
-- 172.16.225.62 and (port 5555 or icmp)' 로 짠다
-- 대신 [8] 의 netstat -s 차이에서 InType3 3 → 4 로 ICMP 수신 한
-- 건이 확인된다
-- ol7b 에 런타임 규칙만 더한다(--permanent 없음 → 재시작하면
-- 사라짐).
[root@ol7b ~]# firewall-cmd --add-port=5555/tcp; firewall-cmd --list-ports
-- success 와 함께 5555/tcp 가 목록에 생겼다. --permanent 가 없어
-- firewalld 재시작·재부팅 때 사라진다
success
