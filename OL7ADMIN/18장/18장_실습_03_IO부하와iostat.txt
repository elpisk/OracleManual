================================================================================
 제18장 실습 03 — I/O 부하와 iostat -x 열 읽기
 대상   : ol7a (OS 디스크 sda, VG ol 위의 XFS 루트)
 목표   : dd 로 쓰기·읽기 부하를 만들어 iostat -x 의 r/s·w/s·rkB/s·wkB/s·
          avgqu-sz·await·%util 을 읽고, iotop·pidstat -d 로 I/O 를 만든
          프로세스를 지목한다. 페이지 캐시가 읽기 부하를 가리는 모습과
          %util 100% 가 곧 디스크 한계는 아니라는 것을 숫자로 본다
 배경   : 블록 장치 통계는 /proc/diskstats 의 누적 카운터이고 iostat 은 두
          시점의 차이를 초당 값으로 바꿔 보여 준다. 첫 보고서는 부팅 이후
          평균이다. 읽기는 페이지 캐시에 있으면 디스크까지 가지 않는다.
          %util 은 "장치에 처리 중인 요청이 하나라도 있던 시간 비율"이라
          병렬 처리가 되는 장치에서는 100% 여도 여유가 있을 수 있다(본문 18.4)
 소요   : 약 25분
 선행   : ol7-base 스냅샷
 계정   : root
 주의   : /var/tmp 에 1.5GB 파일을 만들고 끝에서 지운다
 되돌림 : 시험 파일 삭제, dd 프로세스 0개. 확인은 ls /var/tmp · df -h /

 [2] 버퍼 쓰기와 fdatasync
--------------------------------------------------------------------------------
-- 버퍼 쓰기: dd 는 페이지 캐시에 쓰고 바로 끝난다. 디스크에는
-- 나중에 내려간다.
-- conv=fdatasync 를 붙이면 끝나기 전에 디스크까지 내린 시간이
-- 속도에 포함된다.
[root@ol7a ~]# dd if=/dev/zero of=/var/tmp/big.dat bs=1M count=1500 2>&1 | tail -1
1572864000 bytes (1.6 GB) copied, 4.28571 s, 367 MB/s
-- bs=1M count=1500 = 1572864000 바이트. 367 MB/s 는 캐시에 쓴
-- 속도다
-- 2>&1 | tail -1 : dd 는 통계를 표준 오류로 찍는다. 마지막
-- 줄(크기·시간·속도)만 남겼다
-- 이 VM 의 메모리가 넉넉해 1.5GB 가 거의 다 캐시에 들어갔다
[root@ol7a ~]# grep -E '^(Dirty|Writeback):' /proc/meminfo; sync; grep -E '^(Dirty|Writeback):' /proc/meminfo
Dirty:            204116 kB
Writeback:             0 kB
-- dd 가 끝난 직후 Dirty 204116 kB(약 200MB)가 아직 디스크에 안
-- 내려갔다
-- sync 뒤 Dirty 0. 버퍼 쓰기의 "끝났다" 는 "캐시에 넣었다" 이다
Dirty:                 0 kB
Writeback:             0 kB
[root@ol7a ~]# dd if=/dev/zero of=/var/tmp/big.dat bs=1M count=1500 conv=fdatasync 2>&1 | tail -1
1572864000 bytes (1.6 GB) copied, 19.7245 s, 79.7 MB/s
-- conv=fdatasync 를 붙이자 79.7 MB/s. 같은 1.5GB 인데 숫자가
-- 4.6배 차이 난다
-- 기존 파일을 지우고 다시 만드는(truncate) 비용과 디스크까지 내린
-- 시간이 함께 들어갔다

--------------------------------------------------------------------------------
 [5] 캐시를 비운 읽기와 iflag=direct
--------------------------------------------------------------------------------
-- 캐시를 비우고 같은 읽기를 한다.
[root@ol7a ~]# sync; echo 3 > /proc/sys/vm/drop_caches; free -m | head -2
              total        used        free      shared  buff/cache   available
Mem:           3629         161        3398           8          69        3311
-- buff/cache 1668 → 69. 이제 파일 내용은 캐시에 없다
-- 운영 서버라면 이 drop_caches 는 하지 않는다. 실습이라 캐시
-- 효과를 보이려고 썼다
[root@ol7a ~]# nohup dd if=/var/tmp/big.dat of=/dev/null bs=1M >/tmp/ddr.log 2>&1 </dev/null &
[root@ol7a ~]# iostat -dxky sda 1 2
Linux 5.4.17-2136.338.4.2.el7uek.x86_64 (ol7a.example.com)      11/16/2026      _x86_64_        (2 CPU)

Device:         rrqm/s   wrqm/s     r/s     w/s    rkB/s    wkB/s avgrq-sz avgqu-sz   await r_await w_await  svctm  %util
sda               0.00     0.00 1442.00    1.00 1472540.00     4.00  2040.95     0.89    0.62    0.62    0.00 0.3929  56.70

Device:         rrqm/s   wrqm/s     r/s     w/s    rkB/s    wkB/s avgrq-sz avgqu-sz   await r_await w_await  svctm  %util
sda               0.00     0.00    2.00    0.00    12.00     0.00    12.00     0.00    0.50    0.50    0.00 1.0000   0.20
-- 첫 1초: r/s 1442, rkB/s 1472540(≈1.4 GB/s), avgrq-sz 2040.95
-- 섹터(≈1MB), %util 56.70
-- 둘째 1초에는 이미 dd 가 끝나 거의 0
[root@ol7a ~]# while pgrep -x dd >/dev/null; do sleep 1; done; tail -1 /tmp/ddr.log
1572864000 bytes (1.6 GB) copied, 0.666609 s, 2.4 GB/s
-- 캐시를 비운 뒤 2.4 GB/s. VMware 가상 디스크라 호스트 OS 쪽
-- 캐시가 한 겹 더 있어 여전히 빠르다
-- 게스트 안의 캐시는 피했지만 호스트 캐시는 게스트에서 보이지
-- 않는다. 가상 환경 성능 측정의 한계다
-- 캐시를 비우지 않고 캐시를 피하는 방법: iflag=direct. 운영 중인
-- 서버에서는 drop_caches 보다 이쪽이 낫다.
[root@ol7a ~]# dd if=/var/tmp/big.dat of=/dev/null bs=1M iflag=direct 2>&1 | tail -1
1572864000 bytes (1.6 GB) copied, 0.829124 s, 1.9 GB/s
-- iflag=direct 로 1.9 GB/s. 캐시를 버리지 않고 같은 효과를 냈다
-- drop_caches 는 서버의 다른 프로그램 캐시까지 버리므로 운영
-- 서버에서는 이 방법을 쓴다

 [6] iotop — I/O 를 만든 프로세스 지목
--------------------------------------------------------------------------------
-- iotop 은 기본 설치에 없을 수 있다. 있으면 yum 이 "already
-- installed" 라고 한다.
[root@ol7a ~]# yum -y -q install iotop 2>&1 | tail -3; rpm -q iotop
iotop-0.6-4.el7.noarch
-- 기준 상태에 없던 iotop 0.6 이 ol7_latest 에서 설치됐다(yum -q
-- 라 진행 줄은 없다)
-- iotop 은 커널의 작업별 I/O 통계(taskstats)를 읽으므로 root 로
-- 돌린다
-- 직접 읽기를 60초 걸어 두고 iotop 으로 본다.
--   -b : 배치  -o : I/O 가 있는 프로세스만  -n 3 : 세 번  -d 2 : 2초 간격  -k : KB/s
[root@ol7a ~]# nohup timeout 60 sh -c 'while :; do dd if=/var/tmp/big.dat of=/dev/null bs=64k iflag=direct; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# iotop -b -o -k -n 3 -d 2 | grep -v '^$' | cut -c1-110

Actual DISK READ:  988496.45 K/s | Actual DISK WRITE:       0.00 K/s

-- 머리 두 줄: Total 은 프로세스가 요청한 양, Actual 은 실제
-- 장치에 간 양
