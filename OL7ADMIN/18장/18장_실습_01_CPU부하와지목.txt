================================================================================
 제18장 실습 01 — CPU 부하를 걸고 원인 프로세스 지목하기
 대상   : ol7a (2 vCPU)
 목표   : 셸 루프와 다중 스레드 압축으로 CPU 부하를 만들고 top 헤더 다섯 줄과
          %CPU 열, mpstat -P ALL 의 CPU 별 값, vmstat 의 r·us·sy·id·wa 를
          읽어 부하를 만든 프로세스를 지목한다. 부하 평균과 CPU 사용률이
          서로 다른 값이라는 것을 숫자로 확인한다
 배경   : CPU 가 바쁜지는 사용률(us+sy)과 대기열 길이(r, 부하 평균) 두 쪽으로
          본다. 사용률은 "쓰고 있는 시간의 비율"이고 부하 평균은 "실행 중이거나
          실행을 기다리는(그리고 D 상태인) 작업 수의 평균"이다. CPU 가 2개면
          부하 2 가 꽉 찬 상태다. top 의 %CPU 는 CPU 한 개를 100 으로 친다
          (본문 18.1, 18.2)
 소요   : 약 25분
 선행   : ol7-base 스냅샷
 계정   : root
 주의   : 부하 프로세스는 모두 timeout 으로 시간이 정해져 있다. /var/tmp 에
          1GB 파일을 잠깐 만들고 지운다
 되돌림 : 부하 프로세스 0개, 부하 평균이 내려가는 중, /var/tmp 의 시험 파일 없음.
          확인은 pgrep -c -f '^sh -c while' · ls /var/tmp

 [7] 부하 넷 — 부하 평균을 키운다
--------------------------------------------------------------------------------
-- 루프를 세 개 더 띄워 CPU 2개에 일거리 4개를 준다.
[root@ol7a ~]# nohup timeout 200 sh -c 'while :; do :; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# nohup timeout 200 sh -c 'while :; do :; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# nohup timeout 200 sh -c 'while :; do :; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# pgrep -c -f '^sh -c while'
4
-- timeout 아래의 sh 4개. pgrep -f '^sh -c while' 로 timeout 프로세스는
-- 세지 않았다
-- 1분 부하 평균은 지수 이동 평균이라 바로 오르지 않는다. 75초 동안
-- 15초마다 찍는다.
[root@ol7a ~]# for i in 1 2 3 4 5 6; do cat /proc/loadavg; sleep 15; done
0.63 0.15 0.05 5/193 2302
1.53 0.37 0.12 5/193 2304
2.22 0.58 0.20 5/193 2306
2.76 0.78 0.27 5/193 2308
3.11 0.95 0.33 5/193 2316
3.38 1.12 0.40 5/193 2318
-- 15초마다 1분 평균이 0.63 → 1.53 → 2.22 → 2.76 → 3.11 → 3.38. 4 를
-- 향해 천천히 오른다
-- 4번째 필드 5/193 : 실행 가능 작업 5개(루프 4 + cat 1)
-- 1분 평균은 지수 이동 평균이다. 부하가 바뀐 뒤 1분이 지나도 목표의 63%
-- 쯤만 따라간다
-- 증상   : 부하 평균 3.38 을 보고 "CPU 를 338% 쓴다", "CPU 가 4개는
--          있어야 한다" 고 읽는다
-- 원인   : 부하 평균은 사용률이 아니라 실행 가능(R)·D 상태 작업 수의
--          평균이다
--          CPU 2개에 일거리 4개면 둘은 늘 기다린다. 사용률은 100% 에서 멈춘다
-- 조치   : CPU 개수(nproc 2)로 나눠 읽고, 사용률은 vmstat·mpstat 으로
--          따로 본다
-- 재확인 : 아래 vmstat 에서 us 99~100, r 4~5 — 사용률은 100, 대기열은
--          CPU 의 두 배
[root@ol7a ~]# vmstat 2 3
procs -----------memory---------- ---swap-- -----io---- -system-- ------cpu-----

 5  0      0 3364076   2116 174624    0    0     0     0 1236  330 99  1  0  0  0
-- r 4~5 : 루프 4개 + 가끔 다른 작업. CPU 2개보다 큰 값이 이어지면
-- 포화다
-- us 100, id 0. 루프 하나일 때(us 39)와 비교하면 사용률은 두 배 반이
-- 됐을 뿐이다

 [변형] CPU 는 놀고 부하 평균만 오르는 경우 — D 상태

-- 부하 평균에는 디스크를 기다리는 D(uninterruptible) 상태 작업도
-- 들어간다.
-- oflag=direct : 페이지 캐시를 거치지 않고 디스크에 바로 쓴다. 두 개를
-- 같이 돌린다(합계 1GB).
[root@ol7a ~]# cat /proc/loadavg
2.69 1.44 0.57 1/185 2614
-- 앞 단계 부하가 남아 1분 평균 2.69 에서 출발한다. 실행 중 작업 1/185
[root@ol7a ~]# nohup dd if=/dev/zero of=/var/tmp/io1 bs=64k count=8000 oflag=direct >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# nohup dd if=/dev/zero of=/var/tmp/io2 bs=64k count=8000 oflag=direct >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# sleep 2; ps -eo pid,stat,pcpu,wchan:22,comm | awk 'NR==1 || $NF=="dd"'
  PID STAT %CPU WCHAN                  COMMAND
 2650 D     4.8 iomap_dio_rw           dd

-- 기다리는 커널 함수
-- 이 순간 ps 에 dd 는 하나뿐이었다. 끝의 ls 로 보면 두 파일 모두 500MB
-- 를 다 썼다
