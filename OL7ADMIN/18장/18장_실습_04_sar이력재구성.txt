================================================================================
 제18장 실습 04 — sar 로 지난 시간대 재구성하기
 대상   : ol7a
 목표   : sysstat 의 수집 구조(cron 의 sa1·sa2, /var/log/sa 의 일별 파일,
          /etc/sysconfig/sysstat)를 확인하고, 수집 간격을 줄여 몇 분 동안
          CPU·디스크·네트워크 부하를 시각을 정해 남긴 뒤 sar -u/-q/-r/-b/-n DEV
          와 -s·-e 로 그 시간대를 다시 읽는다
 배경   : sar 는 두 가지로 쓴다. 인자에 간격을 주면 지금 값을 찍고, 간격이 없으면
          /var/log/sa/saDD(DD = 일) 에 쌓인 이력을 읽는다. 이력은 cron 이 10분마다
          부르는 sa1 이 쌓고, 하루 끝에 sa2 가 텍스트 요약 sarDD 를 만든다.
          보관 일수는 /etc/sysconfig/sysstat 의 HISTORY 다(본문 18.6)
 소요   : 약 25분 (기다리는 시간 약 6분 포함)
 선행   : ol7-base 스냅샷
 계정   : root
 주의   : /etc/cron.d/sysstat 를 잠시 고친다. /var/tmp 에 1GB 파일을 만들고 지운다
 되돌림 : /etc/cron.d/sysstat 원래대로(diff 무출력), 시험 파일 삭제.
          확인은 diff /root/sysstat.cron.orig /etc/cron.d/sysstat

 [1] 수집은 누가 하는가 — cron 과 sysstat.service
--------------------------------------------------------------------------------
-- 수집 일정은 /etc/cron.d/sysstat 한 파일이다. 다섯 칸 시간
-- 필드 뒤에 실행 계정(root)이 온다.
[root@ol7a ~]# cat /etc/cron.d/sysstat
# Run system activity accounting tool every 10 minutes
*/10 * * * * root /usr/lib64/sa/sa1 1 1
# 0 * * * * root /usr/lib64/sa/sa1 600 6 &
# Generate a daily summary of process accounting at 23:53
53 23 * * * root /usr/lib64/sa/sa2 -A
-- 2줄 : 10분마다(*/10) root 로 sa1 1 1 — 1초 간격 표본 1개를
-- 오늘 파일에 더한다
-- 3줄 : 주석 처리된 대안. 매시 정각에 600초 간격 6개를 모으는
-- 방식
-- 5줄 : 매일 23:53 sa2 -A — 하루치를 텍스트 요약 sarDD 로
-- 만들고 오래된 파일을 정리한다
-- 시간 필드 다섯 칸(분 시 일 월 요일) 뒤에 실행 계정이 오는
-- 것은 /etc/cron.d 형식이다
-- sysstat.service 는 상주하지 않는다. 부팅 때 "LINUX RESTART"
-- 표시 한 줄만 남기고 끝난다.
[root@ol7a ~]# systemctl cat sysstat | grep -E '^(Type|ExecStart|RemainAfterExit)'
Type=oneshot
RemainAfterExit=yes
ExecStart=/usr/lib64/sa/sa1 --boot
-- Type=oneshot : 한 번 실행하고 끝. RemainAfterExit=yes 라 끝난
-- 뒤에도 active 로 보인다
-- sa1 --boot : 오늘 파일에 LINUX RESTART 표시를 남긴다. 그 뒤
-- 수집은 하지 않는다
-- 보관과 압축 설정. 주석과 빈 줄은 뺐다.
[root@ol7a ~]# grep -v '^#' /etc/sysconfig/sysstat | grep -v '^$'
HISTORY=28
COMPRESSAFTER=31
SADC_OPTIONS="-S DISK"
ZIP="bzip2"
-- HISTORY=28 : 28일 보관. 28 을 넘기면 /var/log/sa/YYYYMM
-- 디렉터리로 나눠 보관한다
-- COMPRESSAFTER=31 : 31일 지난 파일을 압축. HISTORY 보다 커서
-- 이 설정에서는 압축할 일이 없다
-- SADC_OPTIONS="-S DISK" : 디스크 통계도 모은다(sar -d 가 이
-- 덕에 나온다)
-- ZIP="bzip2" : 압축 도구

 [2] 설치돼 있는데 sar 가 비어 있다
--------------------------------------------------------------------------------
-- 오늘 파일을 읽는다(-f 생략 = 오늘 파일).
[root@ol7a ~]# sar -u
Linux 5.4.17-2136.338.4.2.el7uek.x86_64 (ol7a.example.com)      11/16/2026      _x86_64_        (2 CPU)

05:31:40 PM       LINUX RESTART
-- 첫 줄은 커널 버전·호스트·날짜·CPU 수. 데이터 줄은
-- RESTART(05:31:40 PM) 하나뿐이다

-- 읽었다
-- RESTART 줄은 재부팅 시각의 표시다. 장애 뒤 "언제 재부팅됐나"
-- 를 확인할 때도 쓴다
-- 오늘 파일에 실제로 몇 번 기록됐는지 cron 로그로 본다.
[root@ol7a ~]# grep -c 'sa1 1 1' /var/log/cron; grep 'sa1' /var/log/cron | tail -2
3
Nov 11 20:30:01 ol7a CROND[10190]: (root) CMD (/usr/lib64/sa/sa1 1 1)
Nov 11 20:40:01 ol7a CROND[10386]: (root) CMD (/usr/lib64/sa/sa1 1 1)
-- /var/log/cron 의 sa1 실행 기록 3번은 전부 11월 11일 것이다.
-- 오늘은 한 번도 돌지 않았다
-- 증상   : sysstat 이 설치·enabled 인데 sar -u 가 LINUX RESTART
--          한 줄만 보여 준다
-- 원인   : 값은 sa1 이 남긴 두 표본의 차이로 계산된다. 부팅
--          직후라 cron 의 sa1 이
--          아직 한 번도 돌지 않았다. 10분 간격이면 첫 데이터 줄까지 길게는 20분
-- 조치   : 기다리거나, 간격을 줄이거나([4]), 지금 상황은 sar -u
--          1 5 처럼 간격을 주어 실시간으로 본다
-- 재확인 : [6] 에서 sa1 이 매분 돈 뒤 sar -u 에 05:33:01 부터
--          데이터 줄이 생겼다

 [3] 지난 날짜 파일 — 파일 이름은 "일" 만 담는다
--------------------------------------------------------------------------------
-- 어제 파일을 열어 본다. date -d yesterday +%d 는 어제의 일(두
-- 자리)이다.
[root@ol7a ~]# date -d yesterday +%d; sar -u -f /var/log/sa/sa$(date -d yesterday +%d)
15
Cannot open /var/log/sa/sa15: No such file or directory
-- 증상   : 어제 기록을 보려고 sa15 를 열자 Cannot open
--          /var/log/sa/sa15: No such file or directory
-- 원인   : 어제는 VM 이 꺼져 있어 파일이 없다. 운영 서버라면
--          sysstat 설치 전, HISTORY 를
--          넘겨 지워졌거나, 날짜를 잘못 계산한 경우다
-- 조치   : ls -l /var/log/sa 로 실제 있는 파일과 수정 시각부터
--          확인하고 그 파일을 지정한다
-- 재확인 : 아래 for 루프에서 sa11·sa16 의 머리 줄 날짜가 나왔다
-- 남아 있는 다른 날짜 파일의 머리 줄. 어느 달의 그 날인지는
-- 파일 안의 날짜로만 안다.
[root@ol7a ~]# for f in /var/log/sa/sa[0-9]*; do echo "== $f"; sar -u -f $f | head -1; done
== /var/log/sa/sa11
Linux 5.4.17-2102.201.3.el7uek.x86_64 (ol7a.example.com)        11/11/2026      _x86_64_        (2 CPU)
== /var/log/sa/sa16
Linux 5.4.17-2136.338.4.2.el7uek.x86_64 (ol7a.example.com)      11/16/2026      _x86_64_        (2 CPU)
-- sa11 의 머리 줄은 11/11/2026, 커널 2102.201.3(업데이트 전).
-- sa16 은 11/16/2026, 커널 2136.338.4.2
-- 같은 sa11 이라도 다음 달이면 12월 11일 내용으로 덮인다.
-- 날짜는 머리 줄로 확인한다
-- 커널 버전이 바뀐 것도 이 줄에서 보인다. 패치 전후 성능 비교의
-- 단서가 된다
-- sarDD 는 sa2 가 만든 텍스트 요약이다. sar -f 로 읽는 파일이
-- 아니다.
[root@ol7a ~]# sar -u -f /etc/hosts
Invalid system activity file: /etc/hosts
-- sar 바이너리 파일이 아니면 Invalid system activity file 로
-- 거부한다. sarDD(텍스트)를 -f 로 줘도 같다
-- sarDD 는 cat·less 로 읽는다. 하루가 끝나야(23:53) 생기므로
-- 오늘 것은 아직 없다

 [4] 수집 간격을 1분으로 줄인다
--------------------------------------------------------------------------------
[root@ol7a ~]# cp -p /etc/cron.d/sysstat /root/sysstat.cron.orig
[root@ol7a ~]# sed -i 's#^\*/10 \* \* \* \* root#*/1 * * * * root#' /etc/cron.d/sysstat
[root@ol7a ~]# diff /root/sysstat.cron.orig /etc/cron.d/sysstat
2c2
< */10 * * * * root /usr/lib64/sa/sa1 1 1
---
> */1 * * * * root /usr/lib64/sa/sa1 1 1
-- */10 → */1. 매분 1초짜리 표본을 하나씩 남기게 했다
-- 원본은 /root/sysstat.cron.orig 로 떠 두었다(cp -p 로
-- 권한·시각 보존)
-- sed 의 s#...#...# : 구분자로 # 를 써서 */ 를 이스케이프 없이
-- 다뤘다. ^ 는 줄 처음, \* 는 글자 * 이다
-- 운영 서버에서 1분 간격은 파일이 10배 커진다. 장애 조사
-- 기간에만 쓰고 되돌린다
-- crond 는 매분 /etc/cron.d 의 변경 시각을 보고 다시 읽는다.
-- 재시작이 필요한지 로그로 확인한다.
-- 부하 재료로 1GB 파일을 미리 만든다(디스크 부하 단계에서
-- 읽기만 한다).
[root@ol7a ~]# dd if=/dev/zero of=/var/tmp/sar.dat bs=1M count=1000 conv=fdatasync status=none; ls -l /var/tmp/sar.dat
-rw-r--r--. 1 root root 1048576000 Nov 16 17:31 /var/tmp/sar.dat
-- 디스크 부하용 1GB 파일. conv=fdatasync 로 디스크까지 내렸다
[root@ol7a ~]# date '+%T'; grep -E 'RELOAD|sysstat' /var/log/cron | tail -3
17:32:02
Nov 16 17:32:01 ol7a crond[1028]: (*system*) RELOAD (/etc/cron.d/sysstat)
-- 17:32:01 에 crond 가 바뀐 /etc/cron.d/sysstat 을 스스로 다시
-- 읽었다(RELOAD). 재시작하지 않았다
-- crond 는 매분 cron 디렉터리의 수정 시각을 확인한다. 고친
-- 내용은 다음 분부터 반영된다

 [5] 시각을 정해 부하를 남긴다 — CPU, 디스크, 네트워크
--------------------------------------------------------------------------------
-- 각 부하의 시작 시각을 파일에 적어 두고 나중에 sar -s 로 그
-- 시간대를 찾는다.
-- CPU : 루프 두 개(2 vCPU 를 가득) 110초
[root@ol7a ~]# date '+%H:%M:%S' | tee /tmp/t.cpu; date -d '+2 min' '+%H:%M:%S' > /tmp/t.cpu.end
17:32:02
-- CPU 부하 시작 17:32:02. 끝 시각(2분 뒤)은 /tmp/t.cpu.end 에
-- 적어 두었다
-- date -d '+2 min' : 지금부터 2분 뒤 시각. 끝 시각을 함께 남겨
-- 두면 -e 에 그대로 쓴다
[root@ol7a ~]# nohup timeout 110 sh -c 'while :; do :; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# nohup timeout 110 sh -c 'while :; do :; done' >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# grep 'sa1' /var/log/cron | tail -3

Nov 16 17:33:01 ol7a CROND[2388]: (root) CMD (/usr/lib64/sa/sa1 1 1)
-- 17:32:01·17:33:01 에 sa1 이 돌았다. 1분 간격 수집이 시작됐다

-- 디스크 : 1GB 파일 직접 읽기를 50초 동안 반복
[root@ol7a ~]# date '+%H:%M:%S' | tee /tmp/t.disk

 [7] -s·-e — 시간대 잘라 보기
--------------------------------------------------------------------------------
-- [5] 에서 적어 둔 CPU 부하 시작 시각부터 2분만 본다. -s 시작,
-- -e 끝(HH:MM:SS)

17:34:02

05:33:01 PM     CPU     %user     %nice   %system   %iowait    %steal     %idle
05:34:01 PM     all     77.98      0.00      7.49      1.12      0.00     13.40
Average:        all     77.98      0.00      7.49      1.12      0.00     13.40
-- 증상   : 부하 시작 시각(17:32:02)부터 잘랐는데 정작 루프가
--          가장 바빴던 05:33:01 줄이 빠졌다
