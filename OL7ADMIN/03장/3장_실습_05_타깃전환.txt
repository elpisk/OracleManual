================================================================================
 제3장 실습 05 — 타깃 전환
 대상   : ol7a (원격 SSH 세션 + 직렬 콘솔 ttyS0)
 목표   : get-default·set-default 로 기본 타깃을 바꾸고, isolate 로 지금 타깃을
          바꿔 두 명령의 지속 범위를 비교한다. 원격 세션에서 rescue.target 으로
          isolate 했을 때 접속이 끊기는 것을 보고 직렬 콘솔로 되살린다
 배경   : 타깃은 여러 유닛을 묶어 "시스템이 도달할 상태"를 정의하는 유닛이다.
          default.target 심볼릭 링크가 부팅 때 갈 곳을 정하고(set-default),
          isolate 는 지금 이 순간의 상태를 바꾼다. 런레벨 0~6 은 runlevelN.target
          이라는 별칭 링크로 남아 있다 (본문 3.6)
 소요   : 약 30분 (재부팅 두 번 포함)
 선행   : pre-break 스냅샷(= ol7-base). 직렬 콘솔은 랩 기준 설정(console=ttyS0,115200)으로 켜져 있음
 계정   : root
 주의   : [6] 에서 SSH 접속이 끊긴다. 콘솔 없이 운영 서버에서 따라 하면 안 된다
 되돌림 : 기본 타깃 multi-user.target, 현재 타깃 multi-user.target.
          확인은 systemctl get-default, runlevel

 [3] isolate 할 수 있는 타깃, 없는 타깃
--------------------------------------------------------------------------------

-- yes 인 것만 isolate 할 수 있다.
-- 속성 하나로 판별한다.
-- isolate 는 AllowIsolate=yes 인 유닛에만 허용된다.
-- 유닛 다섯 개를 주면 순서대로 한 줄씩 나온다.
[root@ol7a ~]# systemctl show -p AllowIsolate multi-user.target rescue.target graphical.target network.target sshd.service
AllowIsolate=yes

AllowIsolate=yes

AllowIsolate=yes

AllowIsolate=no

AllowIsolate=no
-- 순서대로 multi-user yes, rescue yes, graphical yes, network no, sshd no.
-- 서비스는 isolate 대상이 아니다. 타깃 중에서도 "도착지" 역할을 하는 것만 yes 다.

--------------------------------------------------------------------------------
 [4] set-default — 다음 부팅의 목적지만 바꾼다
--------------------------------------------------------------------------------

-- 바꾼 뒤 get-default, runlevel, is-active 셋을 본다.
-- 링크만 바뀌는지 본다.
-- 기본 타깃을 graphical.target 으로 바꾼다. 출력에 링크를 지우고 다시 만드는 과정이 찍힌다.
[root@ol7a ~]# systemctl set-default graphical.target
Removed symlink /etc/systemd/system/default.target.
Created symlink from /etc/systemd/system/default.target to /usr/lib/systemd/system/graphical.target.
-- set-default 는 링크를 지우고(Removed) 새로 만든다(Created). 하는 일은 이 두 줄이 전부다.
-- 링크를 다시 본다.
[root@ol7a ~]# ls -l /etc/systemd/system/default.target
lrwxrwxrwx. 1 root root 40 Nov 12 19:19 /etc/systemd/system/default.target -> /usr/lib/systemd/system/graphical.target
-- 새 링크는 /usr/lib 경로로 만들어졌다. 설치 때의 /lib 경로와 다르지만 같은 파일이다.

-- 링크는 바뀌었지만 지금 상태도 바뀌었을까.
[root@ol7a ~]# systemctl get-default; runlevel; systemctl is-active graphical.target
graphical.target
N 3
inactive
-- get-default 는 graphical 로 바뀌었는데 runlevel 은 N 3, graphical.target 은 inactive.
-- set-default 는 지금 상태를 건드리지 않는다.

--------------------------------------------------------------------------------
 [5] 오류 흐름 — set-default 와 isolate 를 혼동
--------------------------------------------------------------------------------

-- 순서: 재부팅 → isolate → 확인 → 재부팅 → 확인.
-- 기본 타깃이 graphical 인 상태로 재부팅한다.
-- 재부팅 (systemctl reboot 후 SSH 재접속)
-- 기본값, 런레벨, 두 타깃.
[root@ol7a ~]# systemctl get-default; runlevel; systemctl is-active graphical.target multi-user.target
graphical.target
N 5
active
active

-- GUI 가 없으니 graphical 을 쓸 이유가 없다. isolate 로 multi-user 로 내린다.
-- 재부팅 뒤 runlevel 은 N 5, graphical 과 multi-user 가 모두 active.
-- graphical 은 multi-user 를 Requires 로 끌어오므로 둘 다 active 다.
[root@ol7a ~]# systemctl isolate multi-user.target
-- 같은 확인을 반복한다.
[root@ol7a ~]# runlevel; systemctl is-active graphical.target multi-user.target
5 3
inactive
active

-- 이전 5, 지금 3. isolate 가 graphical 을 내리고 multi-user 만 남겼다.
-- isolate 로 내렸으니 다음 부팅도 multi-user 일 것이라고 생각하기 쉽다. 재부팅해서 확인한다.
[root@ol7a ~]# systemctl get-default; runlevel; systemctl is-active graphical.target
graphical.target
N 5
active
-- 재부팅하니 다시 N 5. isolate 로 바꾼 것은 그 부팅에서만 유효했다.
-- 증상   : isolate multi-user.target 으로 내렸는데 재부팅 뒤 runlevel 이 N 5, graphical.target active
-- 원인   : isolate 는 지금 활성 유닛 집합만 바꾼다. 부팅 목적지는 default.target 링크(get-default)가 정한다
-- 조치   : systemctl set-default multi-user.target
-- 재확인 : get-default 가 multi-user.target, default.target 링크 대상이 multi-user.target, 재부팅 뒤 runlevel N 3

-- 기본값을 고치는 것은 set-default 다.
[root@ol7a ~]# systemctl set-default multi-user.target
Removed symlink /etc/systemd/system/default.target.
Created symlink from /etc/systemd/system/default.target to /usr/lib/systemd/system/multi-user.target.
-- 결과 확인.
[root@ol7a ~]# systemctl get-default; ls -l /etc/systemd/system/default.target
multi-user.target
lrwxrwxrwx. 1 root root 41 Nov 12 19:20 /etc/systemd/system/default.target -> /usr/lib/systemd/system/multi-user.target
-- 링크가 multi-user 로 바뀌었다. 재부팅 확인은 [되돌림 확인] 의 runlevel 대신 [0] 과 같은 get-default 로 한다.

--------------------------------------------------------------------------------
 [6] 오류 흐름 — 원격 세션에서 isolate rescue.target
--------------------------------------------------------------------------------

-- 콘솔 출력은 러너가 받아 붙였다.
-- 운영에서 생기는 상황: "단일 사용자 모드로 내려서 점검하라"는 지시를
-- SSH 세션에서 그대로 따른 경우다.
-- 예상: 세션이 끊긴다. 확인은 직렬 콘솔로 한다.
-- 콘솔이 있는 랩에서만 한다.
-- rescue.target 은 기본 파일 시스템만 마운트하고 네트워크와 대부분의 서비스를 내린다.
-- 무엇이 남는지 먼저 본다.
-- 의존 트리, 앞 20줄.
[root@ol7a ~]# systemctl list-dependencies rescue.target --no-pager | head -20

-- rescue.target 이 끌어오는 것은 rescue.service, utmp 기록, sysinit.target 셋이다(앞 20줄만 봤다).
-- sysinit 아래는 파일 시스템·LVM·udev 같은 기초 유닛뿐이다. sshd 도 network 도 없다.

-- 지금 이 세션은 SSH 다. 그대로 isolate 한다.
-- (러너가 콘솔 출력을 미리 받기 시작하도록 직렬 콘솔을 먼저 연다)

-- isolate 는 rescue.target 이 끌어오지 않는 유닛을 모두 정지한다. sshd 도 그 안에 있다.
[root@ol7a ~]# systemctl isolate rescue.target
-- SSH 쪽 출력이 없다. sshd 가 정지되며 세션이 끊겨 명령의 결과를 받지 못했다.

-- 직렬 콘솔(ttyS0)을 본다. rescue.service 가 root 암호를 묻는다.
Welcome to rescuGive root password for maintenance
(or press Control-D to continue): 
-- 여기부터 직렬 콘솔 화면이다. 첫 줄의 Welcome to rescu… 는 환영 문구가 암호 프롬프트에 덮어써지며 잘린 것이다.
-- 콘솔에 root 암호(oracle)를 넣었다. 입력은 화면에 찍히지 않는다. 그 뒤 프롬프트가 떴다.

 [7] 콘솔에서 multi-user 로 되돌리기

-- systemctl default 대신 Ctrl-D 로 셸을 나가도 된다.
-- rescue.service 가 셸이 끝나면 default 로 다시 간다.
-- 콘솔 셸에서 친다.
-- systemctl default 는 isolate default.target 과 같다.

[root@ol7a ~]# ls -l /usr/sbin/telinit /usr/sbin/init

-- 종료 코드는 찍지 않았다.
-- 오류 문구를 그대로 기록해 둔다.
-- [3] 의 no 를 실제로.
-- AllowIsolate=no 인 network.target 으로 isolate 해 본다.
[root@ol7a ~]# systemctl isolate network.target
Failed to start network.target: Operation refused, unit network.target may be requested by dependency only (it is configured to refuse manual start/stop).

-- 실패해도 지금 상태는 그대로다.
-- 증상   : "Operation refused, unit network.target may be requested by dependency only"
-- 원인   : network.target 은 AllowIsolate=no 이고 RefuseManualStart=yes 다. 다른 유닛이 끌어올 때만 쓰인다
-- 조치   : 도착지 타깃(multi-user, graphical, rescue, emergency) 중에서 고른다
-- 재확인 : systemctl show -p AllowIsolate 대상 이 yes 인지 먼저 본다([3])

--------------------------------------------------------------------------------
 [10] rescue.target 과 emergency.target 의 차이 — 정의로 비교
--------------------------------------------------------------------------------

-- 비교할 것: Requires 에 sysinit.target 이 있는가.
-- 그 차이가 마운트·swap·udev 가 서는지를 가른다.
-- 정의만 본다.
-- 두 타깃은 모두 root 암호를 묻는 셸을 주지만 올리는 범위가 다르다. 들어가 보는 것은 20장에서 한다.
-- 주석 줄은 뺀다.
[root@ol7a ~]# systemctl cat rescue.target | grep -v '^#'

[Unit]
Description=Rescue Mode
Documentation=man:systemd.special(7)
Requires=sysinit.target rescue.service
After=sysinit.target rescue.service
AllowIsolate=yes

[Install]
Alias=kbrequest.target
-- rescue.target 은 sysinit.target 을 Requires 로 끌어온다. 파일 시스템 마운트, swap, udev 가 모두 선다.
-- [Install] 의 Alias=kbrequest.target : 콘솔에서 Alt+위 화살표(kbrequest)를 누르면 rescue 로 간다.
-- 같은 방법으로 emergency.
[root@ol7a ~]# systemctl cat emergency.target | grep -v '^#'

[Unit]
Description=Emergency Mode
Documentation=man:systemd.special(7)
Requires=emergency.service
After=emergency.service
AllowIsolate=yes
-- emergency.target 은 sysinit 없이 emergency.service 만 끌어온다.
-- 두 트리의 줄 수.
[root@ol7a ~]# systemctl list-dependencies rescue.target --no-pager | wc -l; systemctl list-dependencies emergency.target --no-pager | wc -l
50
2
-- 의존 트리 줄 수가 rescue 50, emergency 2. 올리는 범위의 차이가 숫자로 보인다.
-- 셸을 띄우는 서비스 쪽.
[root@ol7a ~]# systemctl cat emergency.service | grep -E '^(ExecStart|ExecStartPre|Before|After|DefaultDependencies)'
DefaultDependencies=no
Before=shutdown.target
ExecStartPre=-/bin/plymouth quit
ExecStartPre=-/bin/echo -e 'Welcome to emergency mode! After logging in, type "journalctl -xb" to view\\nsystem logs, "systemctl reboot" to reboot, "systemctl default" or ^D to\\ntry again to boot into default mode.'
ExecStart=-/bin/sh -c "/usr/sbin/sulogin; /usr/bin/systemctl --fail --no-block default"
-- DefaultDependencies=no : 기본 의존(sysinit 등)을 붙이지 않는다. 그래서 거의 아무것도 없이 뜬다
-- ExecStartPre 의 echo : emergency 진입 때 보이는 안내 문구다(20장에서 화면으로 본다)
-- ExecStart : sulogin 으로 root 암호를 묻고, 셸을 나오면 systemctl default 로 정상 부팅을 다시 시도한다
-- 앞의 - 는 실패해도 무시하라는 뜻이다.

--------------------------------------------------------------------------------
 [변형] set-default 대신 링크를 직접 바꾸기
--------------------------------------------------------------------------------

-- 그다음 별칭 이름(runlevel5)을 set-default 에 준다.
-- 링크 하나라는 것을 손으로 확인.
-- set-default 가 하는 일은 링크 하나다. ln -sf 로 직접 해도 결과가 같은지 본다.
[root@ol7a ~]# ln -sf /usr/lib/systemd/system/graphical.target /etc/systemd/system/default.target; systemctl get-default
graphical.target
-- 링크만 바꿨다.
-- ln -sf 로 링크만 바꿔도 get-default 가 바로 따라온다. daemon-reload 도 필요 없다.
[root@ol7a ~]# ln -sf /usr/lib/systemd/system/multi-user.target /etc/systemd/system/default.target; systemctl get-default
multi-user.target

-- runlevel5.target 처럼 별칭 이름을 set-default 에 주면 무엇이 기록되는지 본다.
[root@ol7a ~]# systemctl set-default runlevel5.target; ls -l /etc/systemd/system/default.target; systemctl get-default
Removed symlink /etc/systemd/system/default.target.
Created symlink from /etc/systemd/system/default.target to /usr/lib/systemd/system/graphical.target.
lrwxrwxrwx. 1 root root 40 Nov 12 19:22 /etc/systemd/system/default.target -> /usr/lib/systemd/system/graphical.target
graphical.target
-- runlevel5.target 을 주었는데 링크는 graphical.target 으로 만들어졌다. set-default 가 별칭을 실제 이름으로 풀었다.
[root@ol7a ~]# systemctl set-default multi-user.target
Removed symlink /etc/systemd/system/default.target.
Created symlink from /etc/systemd/system/default.target to /usr/lib/systemd/system/multi-user.target.
-- 이제 [0] 과 같은 목적지.

--------------------------------------------------------------------------------
 [되돌림 확인]
--------------------------------------------------------------------------------

-- runlevel 의 첫 값은 무시한다.
-- 기본 타깃과 현재 상태를 [0] 과 비교한다.
-- 세 값.
[root@ol7a ~]# systemctl get-default; ls -l /etc/systemd/system/default.target; runlevel
multi-user.target
lrwxrwxrwx. 1 root root 41 Nov 12 19:22 /etc/systemd/system/default.target -> /usr/lib/systemd/system/multi-user.target
1 3
-- [0] 과 같은 multi-user.target. 링크 대상 경로는 /lib 에서 /usr/lib 로 바뀌었다(같은 파일).
-- runlevel 의 이전 값이 1 인 것은 이 부팅에서 rescue 를 거쳤기 때문이다. 재부팅하면 N 3 으로 돌아간다.

--------------------------------------------------------------------------------
 [정리] 관찰 요약
--------------------------------------------------------------------------------

-- graphical 열은 is-active 값이다.
-- [6] 의 get-default 는 [5] 에서 되돌린 값이다.
-- 아래 표의 SSH 열은 원격 접속 가능 여부다.
--  시점                       get-default        runlevel   graphical  SSH
--  [0] 시작 전                multi-user         N 3        inactive   됨
--  [4] set-default graphical  graphical          N 3        inactive   됨
--  [5] 재부팅 뒤              graphical          N 5        active     됨
--  [5] isolate multi-user     graphical          5 3        inactive   됨
--  [5] 재부팅 뒤              graphical          N 5        active     됨
--  [6] isolate rescue         multi-user         5 1        inactive   끊김
--  [7] systemctl default      multi-user         1 3        inactive   됨
--  되돌린 뒤                  multi-user         1 3        inactive   됨
--
--  · set-default = 링크 하나(다음 부팅), isolate = 지금 활성 유닛 집합
--  · rescue 로 isolate 하면 sshd·네트워크가 내려간다. 콘솔 없이 치면 안 된다
--  · rescue 는 sysinit 까지, emergency 는 그것도 없이 셸만(의존 트리 50줄 대 2줄)
--  · isolate 는 AllowIsolate=yes 인 도착지 타깃에만 된다
