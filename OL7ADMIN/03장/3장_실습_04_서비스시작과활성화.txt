================================================================================
 제3장 실습 04 — 서비스 시작과 활성화
 대상   : ol7a
 목표   : start 와 enable 이 서로 다른 것을 바꾼다는 사실을 재부팅 전후로 확인한다.
          is-active·is-enabled 로 두 상태를 따로 읽고, mask 로 서비스를 완전히
          막았다가 푼다
 배경   : start/stop 은 지금 돌고 있는가(active)를, enable/disable 은 부팅 때
          올라오는가(.wants 링크)를 바꾼다. 둘은 독립이다. mask 는 유닛 이름을
          /dev/null 로 가려 수동 start 까지 막는다. 실습 대상은 rsync 패키지의
          rsyncd 서비스(TCP 873)다 (본문 3.7)
 소요   : 약 25분 (재부팅 두 번 포함)
 선행   : ol7-base
 계정   : root
 주의   : 없음. rsyncd 는 기본 설정 그대로 띄우며 방화벽은 열지 않는다
 되돌림 : rsyncd inactive·disabled, mask 없음. 확인은
          systemctl is-active rsyncd; systemctl is-enabled rsyncd
================================================================================

--------------------------------------------------------------------------------
 [0] 시작 전 상태 기록
--------------------------------------------------------------------------------

-- 이 실습의 대상은 rsync 데몬(rsyncd)이다. DB 와 무관한 가벼운 서비스라 켜고 꺼도 다른 실습에 영향이 없다.
-- 대상 패키지가 있는지, 서비스 두 상태가 무엇인지 먼저 남긴다.
-- rpm -q   : 패키지가 설치돼 있으면 이름-버전-릴리스를 찍는다
[root@ol7a ~]# rpm -q rsync
rsync-3.1.2-12.el7_9.x86_64
-- rsync 3.1.2. 기본 설치에 들어 있다. 서비스 유닛 파일도 이 패키지가 준다.
-- is-active  : 지금 상태 한 단어(active, inactive, failed, …)
-- is-enabled : 부팅 때 기동 여부 한 단어(enabled, disabled, static, masked, …)
[root@ol7a ~]# systemctl is-active rsyncd; systemctl is-enabled rsyncd
unknown
disabled
-- is-active 가 inactive 가 아니라 unknown 이다. 219 는 한 번도 로드되지 않은 유닛을 unknown 으로 답한다.
-- 유닛을 한 번이라도 다룬 뒤에는 inactive 로 바뀐다([4]). 둘 다 "돌고 있지 않다"는 뜻이다.
-- is-enabled 는 disabled. 패키지 기본값이 꺼짐이다.

-- TCP 873 에서 듣는 프로세스가 있는지 본다.
-- ss -l : LISTEN 소켓만, -t : TCP, -n : 포트를 숫자로, -p : 프로세스 이름
[root@ol7a ~]# ss -ltnp '( sport = :873 )'
State Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
-- 머리 줄만 있고 소켓이 없다. 873 을 아무도 듣지 않는다.

--------------------------------------------------------------------------------
 [1] 유닛 파일과 status 읽기 — 꺼진 상태
--------------------------------------------------------------------------------

-- 서비스가 꺼진 상태의 status 모양을 먼저 기억해 둔다.
-- systemctl cat : 유닛 파일 내용을 출처 경로와 함께 보여 준다. drop-in 이 있으면 이어서 붙는다
[root@ol7a ~]# systemctl cat rsyncd --no-pager
# /usr/lib/systemd/system/rsyncd.service
[Unit]
Description=fast remote file copy program daemon
ConditionPathExists=/etc/rsyncd.conf

[Service]
EnvironmentFile=/etc/sysconfig/rsyncd
ExecStart=/usr/bin/rsync --daemon --no-detach "$OPTIONS"
-- $OPTIONS 는 EnvironmentFile 에서 온 변수다. 기본 파일에는 OPTIONS="" 만 있다.

[Install]
WantedBy=multi-user.target
-- 첫 줄 주석이 파일 위치다. /usr/lib/systemd/system 이라 패키지 원본이다.
-- ConditionPathExists : /etc/rsyncd.conf 가 없으면 시작 조건이 맞지 않아 건너뛴다(실패가 아님)
-- EnvironmentFile     : /etc/sysconfig/rsyncd 의 OPTIONS 변수를 읽어 ExecStart 에 넣는다
-- --no-detach         : rsync 가 백그라운드로 빠지지 않게 한다. Type 이 없어 기본 simple 이라 이 옵션이 필요하다
-- WantedBy            : enable 하면 multi-user.target.wants 에 링크가 생긴다
-- --no-pager : less 로 넘기지 않고 그대로 출력한다
[root@ol7a ~]# systemctl status rsyncd --no-pager
● rsyncd.service - fast remote file copy program daemon
   Loaded: loaded (/usr/lib/systemd/system/rsyncd.service; disabled; vendor preset: disabled)
   Active: inactive (dead)
-- 첫 줄 ● 뒤에 유닛 이름과 Description.
-- Loaded 괄호 : 유닛 파일 경로; is-enabled 값; vendor preset(배포판 기본값)
-- Active : inactive (dead). 한 번도 돈 적이 없어 로그 줄이 없다.

--------------------------------------------------------------------------------
 [2] start — 지금만 켠다
--------------------------------------------------------------------------------

-- [0] 의 세 명령(is-active, is-enabled, ss)을 start 뒤에 다시 쳐서 바뀐 것만 찾는다.
-- 서비스를 다루는 모든 실습에서 이 세 가지를 짝으로 확인한다.
-- start 는 지금 띄운다. 부팅 설정은 건드리지 않는다. 성공하면 아무것도 찍지 않는다.
[root@ol7a ~]# systemctl start rsyncd
-- 두 상태를 따로 확인한다.
[root@ol7a ~]# systemctl is-active rsyncd; systemctl is-enabled rsyncd
active
disabled
-- active 인데 disabled. 지금은 돌지만 부팅 때는 뜨지 않는 조합이다.
-- start 직후 status 를 다시 본다. [1] 과 달라진 줄을 찾는다.
[root@ol7a ~]# systemctl status rsyncd --no-pager
● rsyncd.service - fast remote file copy program daemon
   Loaded: loaded (/usr/lib/systemd/system/rsyncd.service; disabled; vendor preset: disabled)
   Active: active (running) since Thu 2026-11-12 19:00:27 KST; 122ms ago
 Main PID: 2102 (rsync)
   CGroup: /system.slice/rsyncd.service
           └─2102 /usr/bin/rsync --daemon --no-detach

Nov 12 19:00:27 ol7a.example.com systemd[1]: Started fast remote file copy program daemon.
Nov 12 19:00:27 ol7a.example.com rsyncd[2102]: rsyncd version 3.1.2 starting, listening on port 873
-- 바뀐 줄만 짚는다.
-- Active   : active (running) since … ; 122ms ago — 막 떴다
-- Main PID : 2102. rsync 프로세스 하나가 서비스의 본체다
-- CGroup   : /system.slice/rsyncd.service 아래에 그 프로세스가 있다
-- 맨 아래 두 줄은 이 유닛의 journal. systemd 가 Started 를, rsyncd 자신이 포트 873 을 찍었다
-- Loaded 줄은 여전히 disabled. start 는 enable 상태를 바꾸지 않는다.
-- 포트 873 을 정말 듣고 있는지 확인한다.
[root@ol7a ~]# ss -ltnp '( sport = :873 )'
State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess                         
LISTEN 0      5            0.0.0.0:873       0.0.0.0:*    users:(("rsync",pid=2102,fd=4))
LISTEN 0      5               [::]:873          [::]:*    users:(("rsync",pid=2102,fd=5))
-- State LISTEN, Send-Q 5 는 대기열 길이(backlog), Local Address 0.0.0.0:873 과 [::]:873 은 IPv4·IPv6 모두.
-- Process 열에 rsync, pid 2102 — status 의 Main PID 와 같다. 방화벽은 열지 않았으니 바깥에서는 못 붙는다.

--------------------------------------------------------------------------------
 [3] 재부팅하면 — start 의 지속 범위
--------------------------------------------------------------------------------

-- 기대: 꺼짐. 873 비어 있음.
-- start 만 한 상태로 재부팅한다. enable 하지 않았으니 부팅 때 뜨지 않을 것으로 예상한다.
-- 재부팅 (systemctl reboot 후 SSH 재접속)
[root@ol7a ~]# systemctl is-active rsyncd; systemctl is-enabled rsyncd
unknown
disabled
-- 예상대로 꺼져 있다. 다시 unknown 인 것은 재부팅으로 systemd 가 새로 떠서 유닛을 아직 로드하지 않았기 때문이다.
[root@ol7a ~]# ss -ltnp '( sport = :873 )'
State Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
-- 873 도 비었다. start 의 효과는 그 부팅이 끝나면 사라진다.

--------------------------------------------------------------------------------
 [4] 오류 흐름 — enable 만 하고 start 하지 않음
--------------------------------------------------------------------------------

-- 출력에서 볼 것: is-enabled 와 is-active 가 서로 다른 값을 내는가.
-- "부팅 때 뜨게 해 두라"는 요청을 받고 enable 만 친 상황이다. 지금 바로 서비스가 필요하다면 이것은 실수다.
-- 링크를 만드는 명령이다. 지금 띄우지는 않는다.
[root@ol7a ~]# systemctl enable rsyncd
Created symlink from /etc/systemd/system/multi-user.target.wants/rsyncd.service to /usr/lib/systemd/system/rsyncd.service.
-- enable 이 한 일은 이 한 줄이 전부다. 링크 하나를 만들었다.
-- 순서를 바꿔 is-enabled 를 먼저 본다.
[root@ol7a ~]# systemctl is-enabled rsyncd; systemctl is-active rsyncd
enabled
inactive
-- enabled 인데 inactive. 둘은 따로 움직인다. 이번에는 unknown 대신 inactive 가 나왔다 — enable 이 유닛을 로드했기 때문이다.
-- enable 이 만든 링크를 눈으로 확인한다.
[root@ol7a ~]# ls -l /etc/systemd/system/multi-user.target.wants/ | grep rsync
lrwxrwxrwx. 1 root root 38 Nov 12 19:00 rsyncd.service -> /usr/lib/systemd/system/rsyncd.service
-- 링크는 /etc 쪽에 있고 대상은 /usr/lib 의 원본이다. 원본을 옮기지 않는다.
-- 포트는 비어 있을 것이다.
[root@ol7a ~]# ss -ltnp '( sport = :873 )'
State Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
-- 증상   : is-enabled 는 enabled 인데 873 을 듣는 프로세스가 없음, is-active 는 inactive
-- 원인   : enable 은 다음 부팅을 위한 링크만 만든다. 지금 띄우는 것은 start 다
-- 조치   : systemctl start rsyncd (처음부터라면 enable --now)
-- 재확인 : is-active 가 active, ss 에 rsync 가 873 LISTEN

-- 지금 띄우려면 start 를 따로 친다.
-- start 를 따로 친다.
[root@ol7a ~]# systemctl start rsyncd; systemctl is-active rsyncd
active
-- active. 같은 결과를 한 번에 얻는 방법이 [5] 의 --now 다.

--------------------------------------------------------------------------------
 [5] enable --now — 두 일을 한 번에
--------------------------------------------------------------------------------

-- [4] 의 enable·start 를 먼저 모두 되돌린 뒤 시작한다.
-- 운영에서는 "켜고, 부팅 때도 켜지게"가 대부분이다. 명령 하나로 하는 방법을 확인한다.
-- 먼저 둘 다 되돌린다. disable 과 stop 을 각각.
-- 명령 네 개를 ; 로 이어 한 줄에 쳤다. 앞 명령이 실패해도 다음이 실행된다.
[root@ol7a ~]# systemctl disable rsyncd; systemctl stop rsyncd; systemctl is-enabled rsyncd; systemctl is-active rsyncd
Removed symlink /etc/systemd/system/multi-user.target.wants/rsyncd.service.
disabled
unknown
-- disable 은 링크를 지운다. Removed symlink 한 줄이 enable 의 반대다.

-- --now : enable 과 함께 start 까지 (disable 과 함께 쓰면 stop 까지)
-- echo "rc=$?" 는 바로 앞 명령의 종료 코드다. 0 이 성공.
[root@ol7a ~]# systemctl enable --now rsyncd; echo "rc=$?"
Created symlink from /etc/systemd/system/multi-user.target.wants/rsyncd.service to /usr/lib/systemd/system/rsyncd.service.
rc=0
-- 7.9 의 systemctl(219)도 --now 를 받는다. 링크를 만든 뒤 바로 start 까지 했다.
[root@ol7a ~]# systemctl is-enabled rsyncd; systemctl is-active rsyncd
enabled
active
-- enabled 와 active 가 함께 나왔다.

--------------------------------------------------------------------------------
 [6] 재부팅하면 — enable 의 지속 범위
--------------------------------------------------------------------------------

-- 기대: active, enabled, Main PID 가 작은 번호.
-- 이번에는 enable 한 상태로 재부팅한다.
-- 재부팅 (systemctl reboot 후 SSH 재접속)
[root@ol7a ~]# systemctl is-active rsyncd; systemctl is-enabled rsyncd
active
enabled
-- 부팅 때 떴다. 순서가 [5] 와 반대(is-active 먼저)라 active, enabled 순서다.
-- status 의 앞 네 줄만 본다.
[root@ol7a ~]# systemctl status rsyncd --no-pager | head -4
● rsyncd.service - fast remote file copy program daemon
   Loaded: loaded (/usr/lib/systemd/system/rsyncd.service; enabled; vendor preset: disabled)
   Active: active (running) since Thu 2026-11-12 19:01:05 KST; 13s ago
 Main PID: 992 (rsync)
-- Loaded 괄호의 첫 값이 enabled 로 바뀌었다. vendor preset 은 여전히 disabled — 배포판 기본값과 다르게 켰다는 표시다.
-- Main PID 992. [2] 의 2102 보다 훨씬 작다. 부팅 초반에 systemd 가 띄웠기 때문이다.
-- since 19:01:05; 13s ago — 이 부팅의 시작 시각과 거의 같다.
-- 이번 부팅에서 rsyncd 가 남긴 로그.
[root@ol7a ~]# journalctl -b -u rsyncd --no-pager
-- Logs begin at Thu 2026-11-12 19:01:03 KST, end at Thu 2026-11-12 19:01:19 KST. --
Nov 12 19:01:05 ol7a.example.com systemd[1]: Started fast remote file copy program daemon.
Nov 12 19:01:05 ol7a.example.com rsyncd[992]: rsyncd version 3.1.2 starting, listening on port 873
-- -b -u : 이번 부팅에서 이 유닛의 로그만. 맨 위 "-- Logs begin" 줄은 journalctl 의 머리말이다.
-- [2] 의 로그(19:00:27)는 없다. 재부팅으로 휘발성 journal 이 지워졌다(실습 01).

--------------------------------------------------------------------------------
 [7] is-enabled 의 여러 값
--------------------------------------------------------------------------------

-- 값마다 뜻은 본문 3.7.3 의 표를 본다.
-- for 문으로 유닛 일곱 개의 is-enabled 값을 한 줄씩 찍는다. printf '%-20s' 는 20칸 왼쪽 정렬이다.
-- enabled·disabled 말고도 값이 더 있다. [Install] 절이 없는 유닛, 인스턴스 유닛 등을 함께 본다.
-- 2>&1 은 오류 메시지도 값 자리에 찍히게 한다. 없는 유닛이면 오류 문구가 보인다.
[root@ol7a ~]# for u in sshd rsyncd nfs-server systemd-journald getty@tty1 rsyncd.socket tmp.mount; do printf '%-20s %s\n' $u "$(systemctl is-enabled $u 2>&1)"; done
sshd                 enabled
rsyncd               enabled
nfs-server           disabled
systemd-journald     static
getty@tty1           enabled
rsyncd.socket        disabled
tmp.mount            disabled
-- sshd 와 getty@tty1 은 설치 때부터 enabled. systemd-journald 는 static — [Install] 이 없어 enable 대상이 아니다.
-- getty@tty1 은 getty@.service 의 인스턴스다. @ 뒤 tty1 이 인스턴스 이름이다.
-- rsyncd.socket 은 서비스와 별개로 disabled. 소켓도 따로 enable 상태를 가진다.
-- tmp.mount 는 /tmp 를 tmpfs 로 붙이는 유닛이다. 7.9 는 기본으로 쓰지 않는다(/tmp 는 루트 파일 시스템의 디렉터리).

-- 상태별 유닛 파일 개수
-- --no-legend 로 머리·꼬리 줄을 빼고 두 번째 열(STATE)만 센다.
[root@ol7a ~]# systemctl list-unit-files --no-legend | awk '{print $2}' | sort | uniq -c
     61 disabled
     63 enabled
      2 indirect
    182 static
-- 유닛 파일 308개 중 static 이 182개로 가장 많다. 다른 유닛이 필요할 때 끌어오는 부품들이다.
-- indirect 2개는 자신은 링크가 없고 Also= 로 묶인 다른 유닛이 enable 된 경우다.

--------------------------------------------------------------------------------
 [8] 오류 흐름 — mask 된 서비스를 start
--------------------------------------------------------------------------------

-- 순서: disable --now → mask → 확인 → start(실패) → enable(실패) → status → unmask.
-- disable 은 부팅 때 자동 기동만 막는다. 다른 유닛이 Wants= 로 끌어오거나 사람이 start 하면 뜬다.
-- 절대 뜨면 안 되는 서비스(같은 포트를 쓰는 다른 데몬 등)는 mask 로 막는다.
-- 끄고, 부팅 때 안 올라오게 하고, 손으로도 못 띄우게 막는다.
-- 끄고 링크도 지운다.
[root@ol7a ~]# systemctl disable --now rsyncd; systemctl is-active rsyncd
Removed symlink /etc/systemd/system/multi-user.target.wants/rsyncd.service.
unknown
-- disable --now : 링크를 지우고 stop 까지 했다. 다시 unknown — stop 뒤 유닛이 메모리에서 내려갔다.
-- 손으로도 못 띄우게 가린다.
[root@ol7a ~]# systemctl mask rsyncd
Created symlink from /etc/systemd/system/rsyncd.service to /dev/null.
-- 출력 형식이 enable 때와 같다. "from 무엇 to 무엇".
-- mask 는 /etc/systemd/system 에 같은 이름으로 /dev/null 링크를 만든다. /etc 가 /usr/lib 보다 우선이라 원본이 가려진다.
-- 가림의 실체를 본다.
[root@ol7a ~]# ls -l /etc/systemd/system/rsyncd.service; systemctl is-enabled rsyncd
lrwxrwxrwx. 1 root root 9 Nov 12 19:01 /etc/systemd/system/rsyncd.service -> /dev/null
masked
-- 링크 크기 9 = "/dev/null" 9글자.

-- 가린 서비스를 띄워 본다. 종료 코드도 같이 찍는다.
[root@ol7a ~]# systemctl start rsyncd; echo "rc=$?"
Failed to start rsyncd.service: Unit is masked.
rc=1
-- 증상   : "Failed to start rsyncd.service: Unit is masked." 종료 코드 1
-- 원인   : mask 로 유닛 이름이 /dev/null 을 가리킨다. 사람이 start 해도, 다른 유닛이 끌어와도 뜨지 않는다
-- 조치   : systemctl unmask rsyncd 로 링크를 지운 뒤 start
-- 재확인 : is-enabled 가 masked 가 아닌 값(disabled), /etc/systemd/system/rsyncd.service 가 없음
-- enable 은 될까.
[root@ol7a ~]# systemctl enable rsyncd; echo "rc=$?"
Failed to execute operation: Cannot send after transport endpoint shutdown
rc=1
-- enable 도 거부됐다. 메시지는 "Cannot send after transport endpoint shutdown" — 219 의 엉뚱한 문구다.
-- 원인을 말해 주지 않는 메시지라 is-enabled 로 masked 인지 먼저 확인하는 습관이 필요하다.
-- masked 상태의 status 화면.
[root@ol7a ~]# systemctl status rsyncd --no-pager
● rsyncd.service
   Loaded: masked (/dev/null; bad)
   Active: inactive (dead)

--------------------------------------------------------------------------------
 [9] 소켓 활성화 — rsyncd.socket
--------------------------------------------------------------------------------

-- 순서: 유닛 목록 → 소켓 파일 → 소켓만 켜기 → 접속 → journal → Conflicts.
-- 소켓 유닛은 inetd 의 역할을 systemd 가 맡은 것이다. 연결이 드문 서비스에 쓰면 평소 프로세스가 없다.
-- rsync 패키지에는 서비스 말고 소켓 유닛도 들어 있다. 소켓은 systemd 가 대신 듣고 있다가
-- 연결이 오면 그때 서비스(rsyncd@.service 인스턴스)를 띄운다.
-- 이름 패턴으로 rsyncd 관련 유닛 파일만 고른다.
[root@ol7a ~]# systemctl list-unit-files 'rsyncd*' --no-pager
UNIT FILE       STATE   
rsyncd.service  disabled
rsyncd@.service static  
rsyncd.socket   disabled

3 unit files listed.
-- rsyncd@.service 가 static 인 인스턴스 템플릿이다. 소켓이 연결마다 이 템플릿으로 인스턴스를 만든다.
-- 소켓 유닛 파일. 첫 줄의 경로 주석은 grep 으로 뺐다.
[root@ol7a ~]# systemctl cat rsyncd.socket --no-pager | grep -v '^#'
[Unit]
Description=Rsync Server Socket
Conflicts=rsyncd.service

[Socket]
ListenStream=873
Accept=yes

[Install]
WantedBy=sockets.target 
-- Conflicts=rsyncd.service : 소켓을 켜면 서비스가 내려간다. 둘이 같은 873 을 두고 다투지 않게 막는다
-- ListenStream=873         : TCP 873 을 systemd 가 연다
-- Accept=yes               : 연결마다 서비스 인스턴스를 새로 띄운다(inetd 방식)
-- WantedBy=sockets.target  : enable 하면 부팅 초반 소켓 단계에서 열린다
-- 소켓만 켜고 누가 873 을 듣는지 본다.
[root@ol7a ~]# systemctl start rsyncd.socket; ss -ltnp '( sport = :873 )'
State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
LISTEN 0      128                *:873             *:*    users:(("systemd",pid=1,fd=28))
-- 873 을 듣는 프로세스가 rsync 가 아니라 systemd(pid 1) 다. 대기열도 128 로 [2] 의 5 와 다르다.
-- 아직 rsync 프로세스는 하나도 없다.

-- 접속을 하나 만들어 본다. 모듈이 없으니 목록은 비어 있다.
-- rsync://호스트/ 는 데몬에 붙어 모듈 목록을 달라고 한다. 이 접속이 소켓을 깨운다.
-- 이 접속은 IPv6 localhost(::1)로 간다.
[root@ol7a ~]# rsync rsync://localhost/; echo "rc=$?"
rc=0
-- 모듈이 하나도 없어 목록은 비었고 클라이언트 종료 코드는 0.
-- 접속 뒤 무엇이 떴다 사라졌는지 journal 에서 본다.
[root@ol7a ~]# journalctl -b --no-pager | grep -E 'rsyncd@|rsync' | tail -4
Nov 12 19:01:21 ol7a.example.com rsyncd[2338]: module-list request from localhost (::1)
Nov 12 19:01:21 ol7a.example.com systemd[1]: rsyncd@0-::1:873-::1:44624.service: main process exited, code=exited, status=255/n/a
Nov 12 19:01:21 ol7a.example.com systemd[1]: Unit rsyncd@0-::1:873-::1:44624.service entered failed state.
Nov 12 19:01:21 ol7a.example.com systemd[1]: rsyncd@0-::1:873-::1:44624.service failed.
-- 연결 하나에 인스턴스 rsyncd@0-::1:873-::1:44624.service 가 떴다. 이름에 번호, 로컬 주소·포트, 상대 주소·포트가 들어간다.
-- 인스턴스는 목록 요청을 처리한 뒤 status=255 로 끝나 failed 로 남았다. rsync 데몬이 inetd 방식에서 내는 종료 코드라
-- 클라이언트 쪽 결과(rc=0)와 무관하다. 소켓 활성화 서비스를 볼 때 인스턴스의 failed 를 장애로 오판하기 쉽다.

-- 서비스와 소켓이 같은 포트를 두고 부딪치는 관계인지 확인한다.
-- show -p 로 속성 하나만 본다. 유닛 두 개를 주면 차례로 찍는다.
[root@ol7a ~]# systemctl show -p Conflicts rsyncd.socket rsyncd.service
Conflicts=shutdown.target rsyncd.service

Conflicts=shutdown.target
-- Conflicts 는 소켓 쪽에만 rsyncd.service 가 있다. 서비스 쪽에는 없다. 한쪽에만 써도 양방향으로 작동한다.
-- shutdown.target 은 모든 유닛에 기본으로 붙는다. 종료 때 함께 내려가라는 뜻이다.
-- 소켓을 닫는다.
[root@ol7a ~]# systemctl stop rsyncd.socket

--------------------------------------------------------------------------------
 [변형] enable 을 링크로 직접
--------------------------------------------------------------------------------

-- 마지막에 preset 으로 배포판 기본값으로 돌린다.
-- 스크립트나 설정 관리 도구가 링크를 직접 만드는 경우도 있다. systemctl 이 그것을 enable 로 인정하는지 본다.
-- enable 이 하는 일은 [Install] 의 WantedBy 를 읽어 링크 하나를 만드는 것이다. 손으로 해 본다.
-- 소켓을 멈췄다. 이제 enable 이 만드는 링크를 ln -s 로 똑같이 만든다.
[root@ol7a ~]# ln -s /usr/lib/systemd/system/rsyncd.service /etc/systemd/system/multi-user.target.wants/rsyncd.service
-- 링크만으로 enabled 로 보이는지 본다.
[root@ol7a ~]# systemctl is-enabled rsyncd
enabled
-- is-enabled 는 링크만 보고 판단한다. systemctl enable 로 만든 것과 구별하지 않는다.

-- preset 은 배포판이 정한 기본값(vendor preset)으로 되돌린다.
-- preset 파일에서 rsync 줄과 기본 규칙을 찾는다.
[root@ol7a ~]# grep -rh -E 'rsync|^disable \*' /usr/lib/systemd/system-preset/
disable *
-- preset 파일에 rsync 관련 줄이 없고, 마지막 기본 규칙이 disable * 다. 그래서 vendor preset 이 disabled 였다.
-- 기본값 규칙을 적용한다.
[root@ol7a ~]# systemctl preset rsyncd; systemctl is-enabled rsyncd
Removed symlink /etc/systemd/system/multi-user.target.wants/rsyncd.service.
disabled
-- preset 은 그 규칙대로 링크를 지웠다. 많은 서비스를 배포판 기본값으로 한꺼번에 되돌릴 때 systemctl preset-all 을 쓴다.

-- 과제 3 은 --runtime 이라 재부팅 뒤 masked 가 풀려야 정상이다.
-- 과제 2 를 하면 rsyncd.socket 이 enabled 로 남는다. 끝나면 disable --now 로 끈다.
-- 과제마다 시작 전 상태를 [0] 의 세 명령으로 먼저 기록해 둔다.
-- 1. /etc/rsyncd.conf 를 지우거나 이름을 바꾼 뒤 systemctl start rsyncd 를 쳐 본다. ConditionPathExists 때문에
--    실패가 아니라 "조건 불충족"으로 건너뛴다. status 의 Active 줄 문구로 확인한다.
-- 2. systemctl enable --now rsyncd.socket 뒤 재부팅하고, 부팅 직후 ss 로 873 의 주인이 누구인지 본다.
--    rsync 로 한 번 접속한 뒤 systemctl list-units 'rsyncd@*' --all 로 인스턴스 이름을 확인한다.
-- 3. systemctl mask --runtime rsyncd 로 가린 뒤 링크가 어디에 생겼는지(/run/systemd/system) 보고, 재부팅 뒤에도 masked 인지 본다.
-- 끝나면 [되돌림 확인] 의 명령으로 서비스와 소켓이 모두 disabled·unknown 인지 확인한다.
