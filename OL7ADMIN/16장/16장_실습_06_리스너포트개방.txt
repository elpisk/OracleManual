================================================================================
 제16장 실습 06 — 리스너 포트 1521 개방
 대상   : ol7a(DB 서버 역할), ol7b(클라이언트 역할)
 목표   : Oracle Net 리스너 포트 1521 을 firewalld 에 여는 세 가지 방법(포트, 직접 만든
          서비스, 출발지 제한 rich rule)을 비교한다. 클라이언트에서 보이는 세 가지 실패
          메시지(No route to host, Connection refused, Connection timed out)가 각각
          무엇을 뜻하는지 구분하고, ss 로 리스너가 어느 주소에 묶였는지 확인한다
 배경   : 접속 실패는 방화벽이 거부(REJECT)했는지, 버렸는지(DROP), 방화벽은 통과했는데
          그 포트를 듣는 프로세스가 없는지에 따라 클라이언트 메시지가 다르다. DB 접속
          장애를 볼 때 이 구분이 첫 단계다. 실제 리스너 대신 ncat 이 1521 을 듣게
          한다(본문 16.4·16.5, 17장 리스너 준비와 이어짐)
 소요   : 약 25분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : root
 주의   : drop 영역에 ol7b 주소를 넣는 단계가 있다. ol7b → ol7a 만 영향받고 강사 PC 의
          접속은 그대로다. 끝나면 반드시 뺀다
 되돌림 : public 영역 [0] 과 같음, oracledb 서비스 정의 삭제, 1521 리스너 없음.
          확인: firewall-cmd --list-all, ls /etc/firewalld/services, ss -ltn

[root@ol7a ~]# ss -ltn
State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
LISTEN 0      128          0.0.0.0:111       0.0.0.0:*          
LISTEN 0      128          0.0.0.0:22        0.0.0.0:*          
LISTEN 0      100        127.0.0.1:25        0.0.0.0:*          
LISTEN 0      128             [::]:111          [::]:*          
LISTEN 0      128             [::]:22           [::]:*          
LISTEN 0      100            [::1]:25           [::]:*          
-- 열: State · Recv-Q · Send-Q · Local Address:Port · Peer Address:Port · Process(-p 없어 빈칸)
--   111  rpcbind, 모든 주소(0.0.0.0·[::])
--   22   sshd, 모든 주소

-- 1521 을 듣는 프로세스는 없다. Send-Q 는 대기 큐 한도(128·100)
-- -l 대기, -t TCP, -n 숫자. -u 를 빼서 UDP 는 보지 않았다
-- 이 목록이 [11] 끝에서 다시 같아야 한다
-- 111(rpcbind) 은 방화벽에 열려 있지 않아 바깥에서는 닿지 않는다

 [2] 실패 메시지 ① — 방화벽 거부

-- -v : 연결 과정 출력, -w 3 : 3초 제한. </dev/null : 보낼 것 없음
[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: No route to host.
rc=1
-- 메시지 ① No route to host. ol7b 의 ncat 은 Version 7.50 으로 나온다(패키지 이름은 6.40-19)
-- -v 로 연결 과정을 보였다. 거부 응답이 바로 와서 3초를 기다리지 않았다
-- firewalld 기본 거부(icmp-host-prohibited)다. 이 서버의 1521 은 아직 방화벽에서 막혀 있다
-- rc=1 은 ncat 의 연결 실패. 세 메시지 모두 rc=1 이라 rc 로는 구별되지 않는다

 [3] 오류 재현 ① — 포트는 열렸는데 리스너가 없음
--------------------------------------------------------------------------------

[root@ol7a ~]# firewall-cmd --add-port=1521/tcp; firewall-cmd --list-ports
success
1521/tcp
-- runtime 에 1521/tcp 를 열었다
-- reload 하면 사라지는 runtime 개방이다. [7] 의 reload 에서 실제로 사라진다
[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connection refused.
rc=1
-- 증상   : 방화벽을 열었는데 ol7b 는 "Ncat: Connection refused."
-- 원인   : 1521 을 듣는 프로세스가 없다(아래 ss 결과가 머리 줄뿐). 커널이 RST 를 돌려보냈다
-- 조치   : [5] 에서 리스너를 띄운다
-- 재확인 : [5] 의 ncat 이 Connected to 172.16.225.61:1521
-- 메시지가 No route to host 에서 Connection refused 로 바뀌었다. 방화벽 단계는 지났다는 뜻
-- 응답이 즉시 왔다. 서버가 살아 있고 경로도 정상이다
-- 방화벽은 지났고 프로세스가 없다

-- 듣는 프로세스가 있는지 서버에서 본다
[root@ol7a ~]# ss -ltn '( sport = :1521 )'
State Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
-- 머리 줄만 있다. 필터 '( sport = :1521 )' 에 맞는 대기 소켓이 없다
-- DB 로 치면 리스너가 내려가 있거나 다른 포트를 듣는 상황이다
-- Oracle 이라면 lsnrctl status 로 리스너 상태와 듣는 주소를 함께 본다(17장)

 [4] 실패 메시지 ③ — 패킷을 버리는 drop 영역
--------------------------------------------------------------------------------

-- ol7b 주소를 drop 영역에 묶는다. 출발지 영역이 먼저 평가된다(실습 03)
[root@ol7a ~]# firewall-cmd --zone=drop --add-source=172.16.225.62/32; firewall-cmd --get-active-zones
success
drop
  sources: 172.16.225.62/32
public
  interfaces: ens32
-- drop 영역이 sources 172.16.225.62/32 로 활성이 됐다. 출발지 영역이 먼저다
-- runtime 에만 넣었다. 강사 PC 의 접속은 영향이 없다
[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connection timed out.
rc=1
-- 메시지 ③ Connection timed out. -w 3 만큼 기다렸다. drop 은 응답을 보내지 않는다
-- -w 를 주지 않으면 TCP 재전송 한도(1분 이상)까지 기다린다
-- 응용 프로그램의 접속 제한 시간이 길면 화면이 멈춘 것처럼 보인다
[root@ol7b ~]# ping -c 1 -W 2 ol7a | tail -2
1 packets transmitted, 0 received, 100% packet loss, time 0ms
-- ping 도 응답 없음. drop 영역은 ICMP 까지 버린다
-- 클라이언트에서 보면 "서버가 꺼졌다" 와 구별되지 않는다. 장애 대응 시간이 길어진다
-- tail -2 로 통계 두 줄만 남겼다. 마지막 rtt 줄은 응답이 없어 출력되지 않았다
[root@ol7a ~]# firewall-cmd --zone=drop --remove-source=172.16.225.62/32
success
-- ol7b 를 drop 에서 뺐다
-- 세 메시지를 표로 다시 정리하면 [정리] 와 같다

[root@ol7a ~]# sleep 1; ss -ltnp '( sport = :1521 )'

[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"

Connected to ol7a.
Escape character is '^]'.

-- rc=1 이지만 연결은 성공했다. telnet 의 rc 로 판정하지 말고 Connected 줄을 본다
[root@ol7a ~]# cat /tmp/l1521.log
-- 리스너 로그는 비었다. telnet 은 입력을 보내기 전에 EOF 로 끝나 PING 이 도착하지 않았다
-- 연결 확인만 하려면 ncat -v 쪽이 판정이 분명하다
-- Windows 클라이언트라면 Test-NetConnection 이 같은 역할을 한다

 [6] 루프백에만 묶인 리스너
--------------------------------------------------------------------------------

-- 리스너가 localhost 에만 묶이는 실수(listener.ora 의 HOST=localhost 와 같은 상황)를 1522 로 재현
[root@ol7a ~]# nohup ncat -lk 127.0.0.1 1522 >/dev/null 2>&1 </dev/null &
[root@ol7a ~]# firewall-cmd --add-port=1522/tcp; sleep 1; ss -ltn '( sport = :1521 or sport = :1522 )'
success
State  Recv-Q Send-Q Local Address:Port Peer Address:PortProcess
LISTEN 0      10           0.0.0.0:1521      0.0.0.0:*          
LISTEN 0      10         127.0.0.1:1522      0.0.0.0:*          
LISTEN 0      10              [::]:1521         [::]:*          
-- 1521 은 0.0.0.0, 1522 는 127.0.0.1 에만 묶였다. 1522 의 IPv6 소켓도 없다
-- ncat -l 127.0.0.1 1522 처럼 주소를 주면 그 주소에만 묶인다
-- 필터에 or 를 써서 두 포트를 한 번에 봤다
[root@ol7b ~]# ncat -v -w 3 ol7a 1522 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connection refused.
rc=1
-- 방화벽에서 1522 를 열었는데도 Connection refused. 바깥 주소에서 듣는 소켓이 없다
-- [3] 의 리스너 없음과 같은 메시지다. 서버에서 ss 로 주소를 봐야 둘이 구별된다
[root@ol7a ~]# ncat -v -w 3 127.0.0.1 1522 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connected to 127.0.0.1:1522.
Ncat: 0 bytes sent, 0 bytes received in 0.01 seconds.
rc=0
-- 서버 자신(127.0.0.1)에서는 연결된다
-- 증상   : 포트는 열었는데 ol7b 에서만 Connection refused, 서버 안에서는 됨
-- 원인   : 리스너가 127.0.0.1 에 묶였다(ss 의 Local Address)
-- 조치   : 리스너를 0.0.0.0 이나 서버 주소에 묶는다. Oracle 이면 listener.ora 의 HOST 를 호스트 이름으로
-- 재확인 : ss 의 Local Address 가 0.0.0.0:포트 또는 172.16.225.61:포트
[root@ol7a ~]# pkill -f 'ncat -lk 127.0.0.1 1522'; firewall-cmd --remove-port=1522/tcp
success
-- 1522 리스너와 포트를 정리했다
-- 1522 는 이 단계에서만 썼다
-- pkill -f 는 명령줄 전체로 프로세스를 고른다. 1521 리스너는 살아 있다

--------------------------------------------------------------------------------
 [7] 서비스 정의 파일 만들기
--------------------------------------------------------------------------------

-- 포트 번호 대신 이름으로 관리하려고 oracledb 서비스를 만든다
-- 방법 A : firewall-cmd 로 만든다. 새 서비스는 permanent 로만 만들 수 있다
[root@ol7a ~]# firewall-cmd --permanent --new-service=oracledb
success
-- --new-service 는 permanent 전용. /etc/firewalld/services/oracledb.xml 이 생긴다
-- 이름은 소문자·숫자·하이픈. 영역 이름과 같은 규칙
[root@ol7a ~]# firewall-cmd --permanent --service=oracledb --set-short="Oracle Net Listener"; firewall-cmd --permanent --service=oracledb --set-description="Oracle Database listener (TNS) 1521/tcp"; firewall-cmd --permanent --service=oracledb --add-port=1521/tcp
success
success
success
-- short·description·port 세 속성을 넣었다. 셋 다 success
-- 명령 줄이 길어 화면에서 잘렸다. 세 번째는 --add-port=1521/tcp
[root@ol7a ~]# cat /etc/firewalld/services/oracledb.xml
<?xml version="1.0" encoding="utf-8"?>
<service>
  <short>Oracle Net Listener</short>
  <description>Oracle Database listener (TNS) 1521/tcp</description>
  <port protocol="tcp" port="1521"/>
</service>
-- 직접 쓴 XML 과 같은 형식이다. short 는 GUI 에 보이는 이름, port 가 실제 규칙
-- 이 파일 하나를 다른 서버의 같은 자리에 복사하면 같은 서비스가 생긴다

-- reload 전에는 runtime 이 이 서비스를 모른다
[root@ol7a ~]# firewall-cmd --info-service=oracledb; echo "rc=$?"
Error: INVALID_SERVICE: oracledb
rc=101
-- reload 전에는 runtime 이 이 서비스를 모른다. 원문: Error: INVALID_SERVICE: oracledb
-- rc 101 은 INVALID_SERVICE 의 오류 코드
[root@ol7a ~]# firewall-cmd --reload; firewall-cmd --info-service=oracledb
success
oracledb
  ports: 1521/tcp
  protocols: 
  source-ports: 
  modules: 
  destination: 
-- reload 뒤 --info-service 가 ports 1521/tcp 를 보였다. modules·destination 은 빈칸
-- protocols·source-ports 도 빈칸. 포트 하나짜리 단순한 서비스다

--------------------------------------------------------------------------------
 [8] 오류 재현 ② — 다른 영역에 연 경우
--------------------------------------------------------------------------------

-- reload 로 [3] 의 runtime 포트가 사라졌다. 이제 서비스로 연다. 그런데 영역을 잘못 골랐다
[root@ol7a ~]# firewall-cmd --list-ports; firewall-cmd --zone=internal --add-service=oracledb

success
-- reload 로 [3] 의 runtime 1521/tcp 가 사라졌다(--list-ports 빈 줄). 그 상태에서 internal 에 넣었다
-- --zone=internal 은 runtime 변경이다. 실수해도 reload 로 되돌릴 수 있다
[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: No route to host.
rc=1
-- 증상   : oracledb 를 열었다(success)는데 ol7b 는 No route to host
-- 원인   : internal 영역에 넣었다. ens32 는 public 에 묶여 있다(아래 --get-active-zones)
-- 조치   : --zone=internal --remove-service, --zone=public --add-service(두 벌 모두)
-- 재확인 : ncat 이 Connected, --list-services 와 --permanent --list-services 에 oracledb

[root@ol7a ~]# firewall-cmd --get-active-zones; firewall-cmd --zone=internal --list-services
public
  interfaces: ens32
dhcpv6-client mdns oracledb samba-client ssh
-- 활성 영역은 public 하나. internal 은 묶인 것이 없어 목록에 없다

 [9] 서버에서 본 연결

-- ol7b 에서 20초짜리 연결을 하나 띄우고 ol7a 에서 그 연결을 본다
[root@ol7b ~]# nohup sh -c 'sleep 20 | ncat ol7a 1521' >/dev/null 2>&1 </dev/null &

-- state established 필터로 대기 소켓은 빼고 맺어진 연결만 보았다
-- ol7b 의 sleep 20 이 끝나면 이 연결도 닫힌다

 [10] 출발지를 제한해 열기
--------------------------------------------------------------------------------

-- 운영에서는 1521 을 응용 서버 대역에만 연다. 서비스를 빼고 rich rule 로 바꾼다
[root@ol7a ~]# firewall-cmd --remove-service=oracledb; firewall-cmd --add-rich-rule='rule family="ipv4" source address="172.16.225.62/32" service name="oracledb" accept'
success
success
[root@ol7a ~]# firewall-cmd --list-rich-rules
rule family="ipv4" source address="172.16.225.62/32" service name="oracledb" accept
-- runtime 에서 서비스를 빼고 rich rule 로 바꿨다. 이제 ol7b 만 1521 에 닿는다
-- 서비스를 빼고 넣는 사이는 짧지만 그 순간 새 연결은 거부된다
[root@ol7b ~]# ncat -v -w 3 ol7a 1521 </dev/null; echo "rc=$?"
Ncat: Version 7.50 ( https://nmap.org/ncat )
Ncat: Connected to 172.16.225.61:1521.
Ncat: 0 bytes sent, 0 bytes received in 0.00 seconds.
rc=0
-- ol7b 는 계속 Connected
-- 결과는 같고 범위만 좁아졌다

-- 출발지가 다르면? ol7a 자기 주소는 lo 로 들어가 방화벽과 무관하니, 판정은 iptables 규칙으로 본다
[root@ol7a ~]# iptables -S IN_public_allow | grep 1521
-A IN_public_allow -s 172.16.225.62/32 -p tcp -m tcp --dport 1521 -m conntrack --ctstate NEW,UNTRACKED -j ACCEPT
-- 서비스 이름 oracledb 가 포트 1521 로 풀려 들어갔다. -s 로 출발지 조건이 붙었다
-- 다른 주소는 이 줄에 맞지 않아 기본 거부(No route to host)를 받는다
-- 응용 서버가 여러 대면 source address 에 대역(/24)을 쓰거나 규칙을 서버마다 둔다
-- 이 rich rule 은 runtime 에만 있다. [변형] 의 reload 에서 사라지고 permanent 의 서비스 개방이 돌아온다
