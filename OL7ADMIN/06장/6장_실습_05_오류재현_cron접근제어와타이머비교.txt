 제6장 실습 05 — 오류 재현: cron 접근 제어와 systemd 타이머 비교
 대상   : ol7a
 목표   : cron.deny·cron.allow 를 만들어 누가 crontab 을 쓸 수 있는지 바꾸고,
          이미 등록된 crontab 이 그 뒤에도 실행되는지 확인한다. 같은 작업을
          systemd 타이머로 만들어 list-timers 와 journalctl 로 cron 과 비교한다
 배경   : crontab 명령은 /etc/cron.allow 가 있으면 거기 적힌 사용자만,
          없으면 /etc/cron.deny 에 없는 사용자만 허용한다. OL7 기본은 빈 cron.deny
          하나라 모든 사용자가 쓸 수 있다. systemd 타이머는 .timer 유닛이 같은 이름의
          .service 유닛을 시각에 맞춰 띄우는 방식이다 (본문 6.4·6.7 절)
 소요   : 약 15분 (분 경계 대기 세 번)
 선행   : ol7-base 스냅샷
 계정   : root, student
 주의   : 없음. 만든 유닛 파일과 접근 제어 파일은 [10] 에서 지운다
 되돌림 : /etc/cron.allow 없음, /etc/cron.deny 빈 파일, student crontab 없음,
          lab-report 타이머·서비스 없음. 확인은 ls -l /etc/cron.*, list-timers

 [4] 오류 흐름 ① — cron.allow 를 만들자 student 가 막힌다
--------------------------------------------------------------------------------

-- deny 를 비우고, 이번에는 '허용 목록' 방식으로 바꾼다.
-- 운영 담당자 계정 하나만 쓰게 하려는 의도로 cron.allow 에 root 만 적는다
[root@ol7a ~]# sed -i '/^student$/d' /etc/cron.deny; echo root > /etc/cron.allow; ls -l /etc/cron.allow /etc/cron.deny
-rw-r--r--. 1 root root 5 Nov 12 18:28 /etc/cron.allow
-rw-------. 1 root root 0 Nov 12 18:28 /etc/cron.deny
-- cron.allow: 5 바이트(root + 줄바꿈), 권한 644
-- cron.deny: 다시 0 바이트. 이제 판정은 cron.allow 만 본다
[student@ol7a ~]$ crontab -l; echo rc=$?
You (student) are not allowed to use this program (crontab)
See crontab(1) for more information
rc=1
-- cron.deny 에는 student 가 없는데도 거부됐다. cron.allow 에 없기 때문이다
[root@ol7a ~]# crontab -l -u student; echo rc=$?
* * * * * date +\%T >> /home/student/acl-test.log
rc=0
-- root 는 -u 로 student 의 crontab 을 볼 수 있다. 접근 제어는 root 를 막지 않는다
[root@ol7a ~]# sleep $((62 - 10#$(date +%S))); date '+%T'; tail -2 /home/student/acl-test.log
18:29:02
18:28:01
18:29:01
[root@ol7a ~]# grep -E 'student' /var/log/cron | tail -3
Nov 12 18:28:02 ol7a crontab[2279]: (student) AUTH (crontab command not allowed)
Nov 12 18:28:02 ol7a crontab[2297]: (root) LIST (student)
Nov 12 18:29:01 ol7a CROND[2319]: (student) CMD (date +%T >> /home/student/acl-test.log)
-- 18:29:01 에도 실행. 허용 목록 방식으로 바꿔도 결과가 같다
-- 로그 둘째 줄 (root) LIST (student) 는 위에서 root 가 -u 로 조회한 기록
--
-- 증상   : cron.allow 에 root 만 적자 student 의 crontab -l 이
--          'You (student) are not allowed to use this program (crontab)', rc=1.
--          그런데 student 의 매 분 작업은 18:28:01, 18:29:01 에 계속 실행
-- 원인   : cron.allow 가 있으면 거기 없는 사용자는 crontab 명령을 못 쓴다.
--          접근 제어는 crontab 명령에만 걸리고, /var/spool/cron 에 이미 있는
--          작업은 crond 가 그대로 실행했다
-- 조치   : 허용할 사용자는 cron.allow 에 추가(아래). 작업 자체를 멈추려면
--          crontab -r -u student 로 지워야 한다
-- 재확인 : student 의 crontab -l 이 작업 줄을 보여 줌

-- 조치: student 를 cron.allow 에 넣는다
[root@ol7a ~]# echo student >> /etc/cron.allow; cat /etc/cron.allow
root
student
-- cron.allow 가 root, student 두 줄
[student@ol7a ~]$ crontab -l
* * * * * date +\%T >> /home/student/acl-test.log
-- student 의 crontab -l 이 다시 동작한다

[root@ol7a ~]# echo student >> /etc/cron.deny; head -v /etc/cron.allow /etc/cron.deny
==> /etc/cron.allow <==
root

==> /etc/cron.deny <==

-- 두 파일 모두에 student 가 있다

[student@ol7a ~]$ crontab -l; echo rc=$?
* * * * * date +\%T >> /home/student/acl-test.log

-- cron.allow 가 이겼다. cron.allow 가 있으면 cron.deny 는 보지 않는다
[root@ol7a ~]# rm -f /etc/cron.allow; sed -i '/^student$/d' /etc/cron.deny; wc -c /etc/cron.deny

-- cron.allow 를 지우고 cron.deny 를 0 바이트로 되돌렸다
[student@ol7a ~]$ crontab -r; crontab -l
no crontab for student
-- 이번에는 student 가 직접 crontab -r. 매 분 작업이 사라졌다

Description=Cleanup of Temporary Directories
Documentation=man:tmpfiles.d(5) man:systemd-tmpfiles(8)
DefaultDependencies=no
Conflicts=shutdown.target
After=systemd-readahead-collect.service systemd-readahead-replay.service local-fs.target time-sync.target
Before=shutdown.target
[Service]
Type=oneshot
ExecStart=/usr/bin/systemd-tmpfiles --clean
IOSchedulingClass=idle
-- 짝 서비스는 이름이 같은 systemd-tmpfiles-clean.service
--   Type=oneshot : 한 번 실행하고 끝나는 작업
--   ExecStart    : 실제 명령 systemd-tmpfiles --clean
--   IOSchedulingClass=idle : 디스크 I/O 를 다른 작업이 쉴 때만
-- cron 작업과 달리 유닛 지시어로 우선순위·의존성(After=)을 줄 수 있다

--------------------------------------------------------------------------------
 [7] 타이머 만들기 — 오류 흐름 ② 이름이 다른 서비스
--------------------------------------------------------------------------------

-- 실습 01 의 '열린 포트 수 기록' 을 타이머로 옮긴다. 스크립트와 서비스 유닛
[root@ol7a ~]# printf '#!/bin/bash\necho "$(date +%%T) listen=$(ss -tln | tail -n +2 | wc -l)"\n' > /usr/local/bin/lab-report.sh; chmod 755 /usr/local/bin/lab-report.sh; /usr/local/bin/lab-report.sh
18:29:03 listen=6
-- 직접 실행은 정상. 열린 리슨 소켓 6 개
-- 타이머로 돌 때의 PATH 는 systemd 의 기본값이라 /usr/sbin 이 들어 있다.
-- cron 과 달리 ss 를 찾지 못하는 문제가 없다([8] 의 listen=6 이 증거)
-- root 의 PATH 에 /usr/sbin 이 있어 ss 를 찾았다
[root@ol7a ~]# cat > /etc/systemd/system/lab-reporter.service <<'EOF'
[Unit]
Description=Lab listen-port report
[Service]
Type=oneshot
ExecStart=/usr/local/bin/lab-report.sh
EOF
-- 서비스 이름은 lab-reporter.service. 타이머와 이름을 일부러 다르게 했다
-- [Install] 이 없다. 타이머가 깨우는 서비스라 enable 할 필요가 없다

-- 타이머 유닛. OnCalendar=*:*:00 은 매 분 0초.
--   AccuracySec=1s : 기본 1분의 오차 범위를 1초로 줄임 (관찰용)
[root@ol7a ~]# cat > /etc/systemd/system/lab-report.timer <<'EOF'
[Unit]
Description=Run lab report every minute
[Timer]
OnCalendar=*:*:00
AccuracySec=1s
[Install]
WantedBy=timers.target
EOF
-- 타이머 이름은 lab-report.timer. Unit= 지정이 없다
-- [Install] 의 WantedBy=timers.target : enable 하면 부팅 때 타이머가 켜짐
[root@ol7a ~]# systemctl daemon-reload; systemctl start lab-report.timer; echo rc=$?
Job for lab-report.timer failed. See "systemctl status lab-report.timer" and "journalctl -xe" for details.
rc=1
-- 시작이 실패했다. 메시지는 status 와 journalctl -xe 를 보라는 안내뿐
-- daemon-reload 는 새 유닛 파일 둘을 systemd 에 읽히는 단계다
-- 이번 실패는 그 뒤의 일이다. status 의 Loaded: loaded 가 파일을 읽었다는 증거
-- 원인은 status 머리에 나오지 않으므로 유닛 짝부터 의심한다
[root@ol7a ~]# systemctl status lab-report.timer | head -4; systemctl list-timers lab-report.timer
● lab-report.timer - Run lab report every minute
   Loaded: loaded (/etc/systemd/system/lab-report.timer; disabled; vendor preset: disabled)
   Active: inactive (dead)

0 timers listed.
Pass --all to see loaded but inactive timers, too.
-- status 머리 세 줄
--   Loaded: loaded (...; disabled; ...) : 파일은 읽혔다. 문법 문제가 아니다
--   Active: inactive (dead) : 타이머가 켜지지 않았다
-- list-timers 에는 0 timers. 실패한 타이머는 목록에 없다
--
-- 증상   : systemctl start lab-report.timer 가 'Job for lab-report.timer failed.'
--          로 rc=1, 타이머는 inactive (dead)
-- 원인   : Unit= 이 없는 타이머는 이름이 같은 lab-report.service 를 깨운다.
--          그런 서비스가 없다. 만든 것은 lab-reporter.service 다
-- 조치   : [Timer] 에 Unit=lab-reporter.service 를 넣고 daemon-reload
-- 재확인 : enable --now 뒤 is-active → active, list-timers 의 ACTIVATES 열

-- 조치: 타이머 쪽에 Unit= 으로 서비스 이름을 지정한다.
-- (서비스 파일 이름을 lab-report.service 로 바꾸는 방법도 있다)
[root@ol7a ~]# sed -i '/^AccuracySec/a Unit=lab-reporter.service' /etc/systemd/system/lab-report.timer; grep -A4 '^\[Timer\]' /etc/systemd/system/lab-report.timer
[Timer]
OnCalendar=*:*:00
AccuracySec=1s
Unit=lab-reporter.service
[Install]
-- sed 의 a 명령 : AccuracySec 줄 다음에 한 줄 추가. grep -A4 로 [Timer] 절 확인
[root@ol7a ~]# systemctl daemon-reload; systemctl enable --now lab-report.timer; systemctl is-active lab-report.timer; systemctl is-enabled lab-report.timer
Created symlink from /etc/systemd/system/timers.target.wants/lab-report.timer to /etc/systemd/system/lab-report.timer.
active
enabled
-- enable --now : enable(부팅 때 켜짐)과 start 를 한 번에
-- 심볼릭 링크가 timers.target.wants 에 생겼다. active, enabled

--------------------------------------------------------------------------------
--  항목                     시작 전         변경 후                          되돌린 뒤
--  /etc/cron.deny           0 바이트        student → crontab 거부(rc=1)     0 바이트
--  /etc/cron.allow          없음            root 만 → student 거부           없음

--  list-timers --all        2 개            3 개                             3 개(lab-once 일시)
--
-- 확인한 사실
--   cron.allow·cron.deny 는 crontab 명령을 막는다. 이미 등록된 작업은 crond 가 계속 돌린다
