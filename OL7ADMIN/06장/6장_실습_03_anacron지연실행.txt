 제6장 실습 03 — anacron: 꺼져 있던 동안 밀린 작업이 켜진 뒤 실행되는 과정
 대상   : ol7a
 목표   : /etc/anacrontab 의 필드와 변수, /var/spool/anacron 타임스탬프를 읽고,
          VM 을 껐다 켠 뒤 밀린 작업이 지연 시간만큼 기다렸다 실행되는 것을
          /var/log/cron 으로 추적한다. START_HOURS_RANGE 와 타임스탬프 때문에
          작업이 돌지 않는 두 경우를 재현한다
 배경   : anacron 은 '며칠마다 한 번'만 보장한다. 작업마다 마지막 실행 날짜를
          /var/spool/anacron/작업ID 에 YYYYMMDD 로 적어 두고, 주기가 지났으면 지연
          시간(분)만큼 기다린 뒤 실행한다. anacron 은 상주하지 않는다. OL7 에서는
          crond 가 매시 01분에 /etc/cron.hourly/0anacron 을 부르고, 그 스크립트가
          anacron -s 를 띄운다 (본문 6.5 절)
 소요   : 약 20분 (전원 끄고 켜기, 지연 대기 포함)
 선행   : ol7-base 스냅샷
 계정   : root
 주의   : 꺼져 있던 '며칠'은 타임스탬프 파일을 과거 날짜로 바꿔 흉내 낸다.
          시계를 date -s 로 돌리면 chronyd 가 곧 되돌린다(4장). 시계는 건드리지 않는다.
          0hourly 를 [6]~[8] 동안만 매 분 실행으로 바꾼다
 되돌림 : /etc/anacrontab·/etc/cron.d/0hourly 원래대로(md5sum 비교), 타임스탬프
          파일 셋을 [0] 의 값으로, lab.daily 타임스탬프와 스크립트 삭제

 [1] /etc/anacrontab — 변수 다섯 개와 작업 세 줄
--------------------------------------------------------------------------------

[root@ol7a ~]# cat /etc/anacrontab
# /etc/anacrontab: configuration file for anacron

# See anacron(8) and anacrontab(5) for details.

SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
# the maximal random delay added to the base delay of the jobs
RANDOM_DELAY=45
# the jobs will be started during the following hours only
START_HOURS_RANGE=3-22

#period in days   delay in minutes   job-identifier   command
1       5       cron.daily              nice run-parts /etc/cron.daily
7       25      cron.weekly             nice run-parts /etc/cron.weekly
@monthly 45     cron.monthly            nice run-parts /etc/cron.monthly
-- 변수 다섯 줄
--   SHELL·PATH·MAILTO : 작업 실행 환경과 출력 메일 수신자
--   RANDOM_DELAY=45   : delay 에 0~45분을 무작위로 더함
--   START_HOURS_RANGE=3-22 : 3시~22시 사이에만 작업 시작
-- 작업 줄 네 필드: period(일) delay(분) job-identifier command
--   cron.daily   : 1일마다, 5분 지연
--   cron.weekly  : 7일마다, 25분 지연
--   cron.monthly : @monthly(달이 바뀌면), 45분 지연
-- 명령의 nice 는 정비 작업의 CPU 우선순위를 낮춘다

-- -T : 문법만 검사하고 끝남. 오류가 없으면 아무것도 출력하지 않는다
[root@ol7a ~]# anacron -T; echo rc=$?; rpm -qf /usr/sbin/anacron
rc=0
cronie-anacron-1.4.11-25.el7_9.x86_64
-- 출력 없이 rc=0 → 문법 정상.
-- anacron 은 cronie-anacron 패키지
-- 상주 서비스가 아니라 systemctl 목록에는 없다

--------------------------------------------------------------------------------
 [2] 누가 anacron 을 부르나 — 0hourly 와 0anacron
--------------------------------------------------------------------------------

[root@ol7a ~]# cat /etc/cron.d/0hourly
# Run the hourly jobs
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
01 * * * * root run-parts /etc/cron.hourly
-- 매시 01분에 root 로 run-parts /etc/cron.hourly.
-- 그 안에 0anacron 이 있다
[root@ol7a ~]# cat /etc/cron.hourly/0anacron
#!/bin/sh
# Check whether 0anacron was run today already
if test -r /var/spool/anacron/cron.daily; then
    day=`cat /var/spool/anacron/cron.daily`
fi
if [ `date +%Y%m%d` = "$day" ]; then
    exit 0;
fi

# Do not run jobs when on battery power
if test -x /usr/bin/on_ac_power; then
    /usr/bin/on_ac_power >/dev/null 2>&1
    if test $? -eq 1; then
    exit 0
    fi
fi
/usr/sbin/anacron -s
-- 0anacron 이 anacron 을 부르기 전 검사 둘
--   3~8행  : cron.daily 타임스탬프가 오늘이면 exit 0
--   11~16행: on_ac_power 가 1(배터리)이면 exit 0
-- 둘 다 아니면 anacron -s.
-- -s 는 작업을 하나씩 차례로(serialize)
-- 첫 검사가 cron.daily 만 본다는 점이 [4] 의 오류로 이어진다

-- 지금까지 anacron 이 남긴 기록
[root@ol7a ~]# grep -E 'anacron' /var/log/cron | tail -8
-- 출력 없음. 부팅 뒤 아직 01분을 지나지 않았다
-- 기준 상태에서 anacron 이 돈 흔적이 없다는 [0] 의 관찰과 맞다

-- 작업 스크립트: 실행 시각을 /var/log/lab-anacron.log 에 남긴다
[root@ol7a ~]# printf '#!/bin/bash\necho "$(date "+%%F %%T") lab.daily ran" >> /var/log/lab-anacron.log\n' > /usr/local/bin/lab-daily.sh; chmod 755 /usr/local/bin/lab-daily.sh; cat /usr/local/bin/lab-daily.sh
#!/bin/bash

-- printf 의 %% 가 % 로 들어갔다.
-- 실행 시각을 한 줄씩 남기는 스크립트

-- anacrontab 에 세 가지를 바꾼다.
--   RANDOM_DELAY=0          관찰하기 쉽게 무작위 지연을 없앰 (기본 45분까지)
--   START_HOURS_RANGE=0-24  실습 시각과 상관없이 실행되게 (기본 3-22)
--   1 2 lab.daily ...       하루 주기, 지연 2분
[root@ol7a ~]# sed -i -e 's/^RANDOM_DELAY=.*/RANDOM_DELAY=0/' -e 's/^START_HOURS_RANGE=.*/START_HOURS_RANGE=0-24/' /etc/anacrontab
[root@ol7a ~]# echo '1	2	lab.daily		/usr/local/bin/lab-daily.sh' >> /etc/anacrontab; diff /root/anacrontab /etc/anacrontab; anacron -T; echo rc=$?

 [9] 오류 흐름 ② — START_HOURS_RANGE 밖
--------------------------------------------------------------------------------

-- 이번에는 0anacron 을 거치지 않고 anacron 을 직접 앞에서 돌린다.
--   -d : 데몬으로 갈라지지 않고 메시지를 표준 오류로
--   lab.daily : 이 작업만 대상으로
-- 지금 시각이 들어가지 않는 범위(지금+2 ~ 지금+3시)로 바꾸고 타임스탬프를 사흘 전으로.
-- 범위 검사를 통과하면 지연 2분을 기다리게 되므로 timeout 30 으로 묶어 둔다
[root@ol7a ~]# man anacron 2>/dev/null | col -b | grep -B1 -A3 -E '^ +-n'

       -n     Runs  jobs  immediately  and ignores the specified delays in the
              /etc/anacrontab file.  This options implies -s.
-- man 의 -n 설명: 지연을 무시하고 바로 실행, -s 를 포함
-- 시간대(START_HOURS_RANGE) 이야기는 없다. 아래에서 직접 확인

       -d     Does not fork Anacron to the background.  In this mode,  Anacron
[root@ol7a ~]# H=$(date +%-H); S=$(( (H+2) % 24 )); sed -i "s/^START_HOURS_RANGE=.*/START_HOURS_RANGE=$S-$((S+1))/" /etc/anacrontab; grep START /etc/anacrontab; date '+%H:%M'

[root@ol7a ~]# date -d '3 days ago' +%Y%m%d > /var/spool/anacron/lab.daily; timeout 30 anacron -d lab.daily; echo rc=$?; cat /var/spool/anacron/lab.daily; tail -1 /var/log/lab-anacron.log
