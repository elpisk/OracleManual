 제8장 실습 01 — 사용자 생성과 계정 파일의 변화
 대상   : ol7a
 목표   : useradd 한 번이 passwd·shadow·group·gshadow·홈·메일 스풀 여섯 곳을
          어떻게 바꾸는지 diff 로 확인하고, 그 값이 어디서 왔는지(useradd -D,
          /etc/default/useradd, /etc/login.defs, /etc/skel) 따라간다
 배경   : 로컬 계정은 /etc 아래 네 파일의 한 줄씩으로 이루어진다. passwd 는 누구나
          읽는 공개 정보, shadow 는 root 만 읽는 암호 해시와 만료 정보, group·gshadow 는

          /etc/login.defs 의 기본값으로 이 네 줄과 홈 디렉터리를 만든다(본문 8.1~8.3)
 소요   : 약 25분
 선행   : ol7-base 스냅샷(student UID 1000 만 있는 상태)
 계정   : root (확인용으로 user1·user4 전환)
 주의   : 없음. 만든 계정은 끝에서 모두 지운다
 되돌림 : user1~user6·svc1 삭제, 네 파일이 [0] 의 사본과 같음(diff 무출력)

 [1] useradd 의 기본값 — useradd -D 와 /etc/default/useradd
--------------------------------------------------------------------------------

-- 옵션 없이 useradd 를 치면 무엇이 정해지는지부터 본다.
-- -D 는 "기본값 표시". 인자가 없으면 표시만 하고 아무것도 바꾸지 않는다.
[root@ol7a ~]# useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
-- 일곱 값의 뜻
--   GROUP=100      users 그룹. UPG 를 쓰므로 실제로는 쓰이지 않음
--   HOME=/home     홈의 상위 경로. 홈 = HOME/이름
--   INACTIVE=-1    암호 만료 뒤에도 잠그지 않음
--   EXPIRE=        계정 만료일 없음
--   SHELL·SKEL     로그인 셸과 홈 원본 위치
--   CREATE_MAIL_SPOOL=yes  /var/spool/mail/이름 생성

-- 같은 값이 파일로 저장돼 있다. useradd -D -s 같은 변경도 이 파일을 고친다.
[root@ol7a ~]# cat /etc/default/useradd
# useradd defaults file
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
-- 첫 줄만 주석이고 나머지 일곱 줄은 useradd -D 출력과 글자까지 같다

 [2] /etc/login.defs — UID 범위, 홈 생성, 암호 기본값
--------------------------------------------------------------------------------

-- login.defs 는 shadow-utils 전체(useradd·groupadd·passwd·chage 등)가 읽는 설정이다.
-- 주석과 빈 줄을 빼면 실제로 설정된 줄만 남는다.
-- grep -v '^#' : #으로 시작하는 줄 제외, grep -v '^$' : 빈 줄 제외
[root@ol7a ~]# grep -v '^#' /etc/login.defs | grep -v '^$'
MAIL_DIR        /var/spool/mail
PASS_MAX_DAYS   99999
PASS_MIN_DAYS   0
PASS_MIN_LEN    5
PASS_WARN_AGE   7
UID_MIN                  1000
UID_MAX                 60000
SYS_UID_MIN               201
SYS_UID_MAX               999
GID_MIN                  1000
GID_MAX                 60000
SYS_GID_MIN               201
SYS_GID_MAX               999
CREATE_HOME     yes
UMASK           077
USERGROUPS_ENAB yes
ENCRYPT_METHOD SHA512
-- 주석을 걷어 내면 17줄이 남는다
--   MAIL_DIR       메일 스풀 위치
--   PASS_MAX_DAYS 99999 / MIN 0 / WARN 7 → 사실상 만료 없음
--   PASS_MIN_LEN 5 는 7.9 에서 쓰이지 않는다. 길이는 pwquality 가 본다
--   UID_MIN 1000 ~ UID_MAX 60000      일반 사용자
--   SYS_UID_MIN 201 ~ SYS_UID_MAX 999 시스템 계정(-r)
--   GID 범위도 같은 값
--   CREATE_HOME yes  -m 없이도 홈을 만든다(이 실습의 [4])
--   UMASK 077        새 홈의 권한 700
--   USERGROUPS_ENAB yes  UPG 생성, userdel 때 UPG 정리
--   ENCRYPT_METHOD SHA512  chpasswd·newusers 의 해시

-- 이 파일이 UID 범위를 정한다는 것을 숫자로 확인한다. student 의 UID 가 범위의 첫 값인지 본다.
[root@ol7a ~]# id student
uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
-- student 의 UID 1000 = UID_MIN.
-- 처음 만든 일반 사용자라 범위의 첫 값을 받았다
-- groups 의 10(wheel) 은 설치 화면에서 관리자로 지정한 결과다

 [4] useradd user1 — 옵션 없이 만들고 네 파일의 diff 보기
--------------------------------------------------------------------------------

-- 옵션을 하나도 주지 않는다. 기본값이 무엇을 만드는지 그대로 본다.
-- useradd 는 성공하면 아무것도 출력하지 않는다. 종료 코드로 확인한다.
[root@ol7a ~]# useradd user1; echo "exit=$?"
exit=0
-- 출력 없이 exit=0. useradd 는 성공하면 말이 없다

-- diff 의 '>' 줄이 새로 생긴 줄이다. 네 파일 모두 한 줄씩 늘어야 한다.
[root@ol7a ~]# for f in passwd shadow group gshadow; do echo "== $f"; diff /root/b08/$f /etc/$f; done
== passwd
28a29
> user1:x:1001:1001::/home/user1:/bin/bash
== shadow
28a29
> user1:!!:20773:0:99999:7:::
== group
51a52
> user1:x:1001:
== gshadow
51a52
> user1:!::
-- 네 파일 모두 '>' 한 줄씩.
-- diff 의 28a29 는 "28번 줄 뒤에 29번 줄 추가"
--   passwd   user1:x:1001:1001::/home/user1:/bin/bash
--            UID 1001 = student 다음 번호, GID 도 1001(UPG)
--   shadow   user1:!!:20773:0:99999:7:::
--            !! 는 암호 없음(잠김), 20773 은 오늘의 일수
--   group    user1:x:1001:    구성원 칸이 빈 UPG
--   gshadow  user1:!::        그룹 암호 없음

 [5] /etc/passwd 의 일곱 필드
--------------------------------------------------------------------------------

-- getent 는 /etc/passwd 를 직접 읽지 않고 NSS(nsswitch.conf)를 거쳐 조회한다.
-- 나중에 LDAP 를 붙여도 같은 명령으로 볼 수 있어 스크립트에서는 getent 가 낫다.
[root@ol7a ~]# getent passwd user1
user1:x:1001:1001::/home/user1:/bin/bash

-- 콜론으로 나눈 필드를 번호와 함께 찍는다.
[root@ol7a ~]# getent passwd user1 | awk -F: '{for(i=1;i<=NF;i++) printf "%d %s\n", i, $i}'
1 user1
2 x
3 1001
4 1001
5 
6 /home/user1
7 /bin/bash
-- 1 이름  2 x(해시는 shadow 에)  3 UID  4 기본 GID
-- 5 GECOS 는 빈 칸. -c 를 주지 않았다
-- 6 홈 = HOME(/home) + 이름, 7 셸 = SHELL 기본값

-- 권한도 본다. passwd 는 누구나 읽어야 하므로(ls -l 이 사용자 이름을 찾는 데 쓴다) 644 다.
[root@ol7a ~]# ls -l /etc/passwd /etc/shadow /etc/group /etc/gshadow
-rw-r--r--. 1 root root  693 Nov 16 10:48 /etc/group
----------. 1 root root  555 Nov 16 10:48 /etc/gshadow
-rw-r--r--. 1 root root 1426 Nov 16 10:48 /etc/passwd
----------. 1 root root  927 Nov 16 10:48 /etc/shadow
-- 크기가 늘었다. passwd 1385 → 1426, shadow 899 → 927
-- 권한은 그대로 644·000. useradd 는 권한을 바꾸지 않고 내용만 고친다

 [8] 암호 설정 — 잠긴 계정 풀기
--------------------------------------------------------------------------------

-- 대화형 passwd 대신 chpasswd 로 넣는다. 형식은 "이름:암호" 한 줄.
-- 스크립트에서 여러 계정에 암호를 줄 때 쓰는 방법이다.
[root@ol7a ~]# echo 'user1:Ol7#Pass2026' | chpasswd; echo "exit=$?"
exit=0

-- 두 번째 필드가 어떻게 바뀌었는지 본다. 해시는 길어서 앞 20자만 자른다.
[root@ol7a ~]# grep '^user1:' /etc/shadow | cut -d: -f1-3 | cut -c1-40; passwd -S user1
user1:$6$Yz6.t/5U$rRtKWBkZrcT0XJwEGuRfOJ
user1 PS 2026-11-16 0 99999 7 -1 (Password set, SHA512 crypt.)
-- 2번 필드가 !! 에서 $6$Yz6.t/5U$... 로 바뀌었다
--   $6$ = SHA-512, 다음 $ 까지 Yz6.t/5U 가 소금(salt)
-- passwd -S 는 LK → PS(Password set), 해시 방식까지 알려 준다
-- chpasswd 는 login.defs 의 ENCRYPT_METHOD SHA512 를 따랐다
[root@ol7a ~]# diff /root/b08/shadow /etc/shadow | cut -c1-60
28a29
> user1:$6$Yz6.t/5U$rRtKWBkZrcT0XJwEGuRfOJTaRC98lG3TqLrEjLSS
-- [4] 의 diff 와 다른 점은 2번 필드뿐. 다른 칸은 그대로다

--------------------------------------------------------------------------------
 [9] 옵션으로 기본값 바꾸기 — 오류 ①: 이미 있는 UID
--------------------------------------------------------------------------------

-- DBA 가 여러 서버에서 같은 사용자를 같은 UID 로 맞추려 할 때 -u 를 쓴다(NFS 공유 때문).
-- 의도는 user2 를 UID 1000 으로 만드는 것이지만 1000 은 이미 student 다.
-- -u UID, -c 설명(GECOS), -s 로그인 셸
[root@ol7a ~]# useradd -u 1000 -c 'DB operator' -s /bin/bash user2; echo "exit=$?"
useradd: UID 1000 is not unique
exit=4
-- 증상   : useradd -u 1000 이 'useradd: UID 1000 is not unique' 로 거부, exit=4
-- 원인   : 1000 은 student 가 쓰고 있다. useradd 는 UID 중복을 막는다
--          종료 코드 4 는 useradd(8) 의 "UID already in use"
-- 조치   : 비어 있는 번호를 확인해 다시 지정(아래 getent passwd 1500)
-- 재확인 : useradd -u 1500 뒤 id user2 → uid=1500(user2)

-- 어떤 계정이 그 UID 를 쓰는지 확인한다. getent passwd 에 UID 를 주면 역조회가 된다.
[root@ol7a ~]# getent passwd 1000; getent passwd 1500 || echo "1500 비어 있음"
-- getent passwd 숫자 는 UID 로 역조회한다.
-- 결과가 없으면 rc=2 라 || 뒤가 실행됐다
student:x:1000:1000:lab student:/home/student:/bin/bash
1500 비어 있음

[root@ol7a ~]# useradd -u 1500 -c 'DB operator' -s /bin/bash user2; echo "exit=$?"; id user2
exit=0
uid=1500(user2) gid=1500(user2) groups=1500(user2)
-- GID 도 1500. UPG 는 가능하면 UID 와 같은 번호를 GID 로 쓴다

-- -o(non-unique)를 붙이면 중복 UID 를 강제로 만들 수 있다. 확인만 하고 쓰지 않는다.
[root@ol7a ~]# useradd --help | grep -E '^ +-o|^ +-u'
  -o, --non-unique              allow to create users with duplicate
  -u, --uid UID                 user ID of the new account
-- -o 의 도움말은 'allow to create users with duplicate' 에서 줄이 넘어간다
-- grep 이 첫 줄만 잡았다. 중복 UID 는 파일 소유가 섞이므로 쓰지 않는다

-- UID 1500 다음 사용자는 몇 번을 받는가. 비어 있는 가장 작은 값이 아니라 "가장 큰 값 + 1" 이다.
[root@ol7a ~]# useradd user3; id user3
uid=1501(user3) gid=1501(user3) groups=1501(user3)
-- 1001 이 이미 user1 이고 1002~1499 는 비었지만 1501 을 받았다
-- 규칙은 "가장 큰 UID + 1". 중간의 빈 번호는 채우지 않는다

--------------------------------------------------------------------------------
 [10] 홈 없이 만들기 — 오류 ②: -M 으로 만든 계정의 로그인
--------------------------------------------------------------------------------

-- 7.9 의 login.defs 는 CREATE_HOME yes 다. 그래서 -m 없이도 홈이 생긴다([4]).
-- 반대로 -M(--no-create-home)을 주면 홈 없이 계정만 생긴다.
-- 배치 계정을 만들며 습관적으로 -M 을 주고 나중에 그 계정으로 로그인시키는 경우가 있다.
[root@ol7a ~]# useradd -M user4; echo "exit=$?"; ls -ld /home/user4; grep '^user4:' /etc/passwd
exit=0
ls: cannot access /home/user4: No such file or directory
user4:x:1502:1502::/home/user4:/bin/bash
-- passwd 에는 홈이 /home/user4 로 적혔지만 디렉터리는 없다
-- -M 은 "만들지 않음" 일 뿐 홈 경로 칸은 그대로 채운다
[user4@ol7a ~]$ pwd; ls -a
su: warning: cannot change directory to /home/user4: No such file or directory
/root
ls: cannot open directory .: Permission denied
-- 증상   : 'su: warning: cannot change directory to /home/user4:
--          No such file or directory', 작업 위치가 /root 로 남고
--          ls 는 'Permission denied'
-- 원인   : -M 으로 만들어 홈이 없다. su 는 홈으로 못 가자 원래 위치에
--          남았고, /root 는 user4 가 읽을 수 없다. 프로파일도 못 읽었다
-- 조치   : mkhomedir_helper user4 로 skel 을 복사해 홈 생성(아래)
-- 재확인 : 다시 들어가면 pwd 가 /home/user4,
-- ls -a 에 skel 파일 넷

-- 홈을 skel 로 직접 만들어 준다. mkhomedir_helper 는 pam 패키지에 들어 있는 도구로
-- skel 복사·소유자·권한(UMASK)을 한 번에 처리한다.
[root@ol7a ~]# rpm -qf /usr/sbin/mkhomedir_helper; mkhomedir_helper user4; ls -la /home/user4
pam-1.1.8-23.0.1.el7.x86_64
total 16
drwxr-xr-x. 2 user4 user4  85 Nov 16 10:48 .
drwxr-xr-x. 7 root  root   73 Nov 16 10:48 ..
-rw-r--r--. 1 user4 user4  18 Nov 16 10:48 .bash_logout
-rw-r--r--. 1 user4 user4 193 Nov 16 10:48 .bash_profile
-rw-r--r--. 1 user4 user4 231 Nov 16 10:48 .bashrc
-rw-r--r--. 1 user4 user4  17 Nov 16 10:48 .ol7lab_profile
-- mkhomedir_helper 는 pam 패키지(1.1.8-23.0.1) 소속
-- 만든 홈의 권한이 drwxr-xr-x(755) 다. useradd 의 700 과 다르다
--   mkhomedir_helper 의 기본 umask 는 0022. 인자로 umask 를 줄 수 있다
-- 파일 시각이 오늘(Nov 16)이다. useradd 와 달리 원본 시각을 보존하지 않았다
[user4@ol7a ~]$ pwd; ls -a
/home/user4
.
..
.bash_logout
.bash_profile
.bashrc
.ol7lab_profile
-- 이번에는 경고 없이 홈에서 시작했다

--------------------------------------------------------------------------------
 [11] 시스템 계정 — useradd -r
--------------------------------------------------------------------------------

-- 서비스용 계정은 -r 로 만든다. UID 를 SYS_UID_MIN~SYS_UID_MAX 범위에서 위에서부터 받는다.
-- -s /sbin/nologin 로 로그인 셸을 막는다.
[root@ol7a ~]# useradd -r -s /sbin/nologin -c 'lab service' svc1; id svc1; grep '^svc1:' /etc/passwd /etc/shadow
uid=996(svc1) gid=992(svc1) groups=992(svc1)
/etc/passwd:svc1:x:996:992:lab service:/home/svc1:/sbin/nologin
/etc/shadow:svc1:!!:20773::::::
-- UID 996, GID 992. 999 부터 아래로 내려가며 비어 있는 번호를 받았다
-- shadow 의 4~7번 칸이 비어 있다. 시스템 계정에는 암호 노화를 걸지 않는다
[root@ol7a ~]# ls -ld /home/svc1 /var/spool/mail/svc1
ls: cannot access /home/svc1: No such file or directory
ls: cannot access /var/spool/mail/svc1: No such file or directory
-- -r 은 홈도 메일 스풀도 만들지 않는다.
-- passwd 에 /home/svc1 이 적혀 있을 뿐이다

-- 셸이 nologin 이면 su 로도 들어가지 못한다.
[root@ol7a ~]# su - svc1 -c id; echo "exit=$?"
su: warning: cannot change directory to /home/svc1: No such file or directory
This account is currently not available.
exit=1
-- 'This account is currently not available.' 은 /sbin/nologin 이 찍는 문구
-- su 의 인증은 root 라 통과했고,
-- 셸 대신 nologin 이 실행돼 rc=1 로 끝났다

--------------------------------------------------------------------------------
 [12] 만든 뒤 바꾸기 — usermod
--------------------------------------------------------------------------------

-- 설명·셸·홈 위치를 바꾼다. -d 새 홈 경로, -m 은 기존 홈의 내용을 새 경로로 옮김.
-- -m 없이 -d 만 주면 /etc/passwd 의 경로만 바뀌고 파일은 옛 자리에 남는다.
[root@ol7a ~]# usermod -c 'Batch user' -d /home/batch3 -m user3; grep '^user3:' /etc/passwd; ls -ld /home/user3 /home/batch3
user3:x:1501:1501:Batch user:/home/batch3:/bin/bash
ls: cannot access /home/user3: No such file or directory
drwx------. 2 user3 user3 85 Nov 16 10:48 /home/batch3
-- -m 이 있어 /home/user3 은 사라지고 /home/batch3 로 옮겨졌다
-- GECOS 칸이 Batch user 로 채워졌다

-- 사용자 이름 자체도 바꿀 수 있다. -l 새이름. UID 는 그대로라 파일 소유는 따라간다.
-- 그룹 이름(UPG)은 바뀌지 않는다는 점을 본다.
[root@ol7a ~]# usermod -l batch3 user3; id batch3; ls -ld /home/batch3; getent group user3 batch3
uid=1501(batch3) gid=1501(user3) groups=1501(user3)
drwx------. 2 batch3 user3 85 Nov 16 10:48 /home/batch3
user3:x:1501:
-- 이름은 batch3, UID 1501 그대로.
-- 홈의 소유자 표시도 batch3 로 바뀌었다
-- 기본 그룹은 여전히 user3. getent group batch3 는 결과가 없다
-- usermod -l 은 UPG 이름을 바꾸지 않는다

--------------------------------------------------------------------------------
 [변형] newusers 로 여러 계정을 한 번에
--------------------------------------------------------------------------------

-- newusers 는 passwd 형식(이름:암호:UID:GID:GECOS:홈:셸)의 파일을 읽어 한꺼번에 만든다.
-- UID·GID 칸을 비우면 useradd 처럼 다음 번호를 받는다. 암호는 평문으로 주면 해시해서 넣는다.
[root@ol7a ~]# printf 'user5:Ol7#Pass2026:::Batch five:/home/user5:/bin/bash\nuser6:Ol7#Pass2026:::Batch six:/home/user6:/bin/bash\n' > /root/nu.txt; cat /root/nu.txt
user5:Ol7#Pass2026:::Batch five:/home/user5:/bin/bash
user6:Ol7#Pass2026:::Batch six:/home/user6:/bin/bash

[root@ol7a ~]# newusers /root/nu.txt; echo "exit=$?"; id user5; id user6
exit=0
uid=1503(user5) gid=1503(user5) groups=1503(user5)
uid=1504(user6) gid=1504(user6) groups=1504(user6)
-- 1503·1504. newusers 도 "가장 큰 UID + 1" 규칙을 따른다

-- useradd 로 만든 user1 과 무엇이 다른지 홈과 shadow 를 나란히 본다.
[root@ol7a ~]# ls -la /home/user5; grep -E '^(user1|user5):' /etc/shadow | cut -d: -f1,3-9; ls -l /var/spool/mail
total 0
drwx------. 2 user5 user5   6 Nov 16 10:48 .
drwxr-xr-x. 9 root  root  100 Nov 16 10:48 ..
user1:20773:0:99999:7:::
user5:20773:0:99999:7:::
total 0
-rw-rw----. 1 batch3  mail 0 Nov 16 10:48 batch3
-rw-rw----. 1 rpc     mail 0 Nov 11 19:45 rpc
-rw-rw----. 1 student mail 0 Nov 11 19:49 student
-rw-rw----. 1 user1   mail 0 Nov 16 10:48 user1
-rw-rw----. 1 user2   mail 0 Nov 16 10:48 user2
-rw-rw----. 1 user4   mail 0 Nov 16 10:48 user4
-- newusers 가 만든 user5 의 홈은 비어 있다(크기 6).
-- skel 을 복사하지 않았다
-- shadow 의 노화 칸은 user1 과 같다(20773:0:99999:7)
-- 메일 스풀 목록에 user5·user6 이 없다.
-- newusers 는 스풀도 만들지 않는다
-- 이름을 바꾼 user3 의 스풀은 batch3 으로 바뀌어 있다.
-- usermod -l 이 옮겼다

 되돌림

-- userdel -r 은 홈과 메일 스풀까지 지운다. batch3 은 이름이 바뀐 user3 이다.
-- user3 의 UPG(user3 그룹)는 이름이 다르므로 userdel 이 지우는지 따로 확인한다.
[root@ol7a ~]# for u in user1 user2 batch3 user4 user5 user6 svc1; do userdel -r $u; done; getent group user3 || echo "user3 그룹 없음"
userdel: user5 mail spool (/var/spool/mail/user5) not found

user3:x:1501:

--   user5·user6 은 newusers 로, svc1 은 -r 로 만들어 스풀이 없었다
--   svc1 은 홈도 없었다. 경고일 뿐 계정 삭제는 끝까지 진행됐다
-- user3 그룹이 남았다. batch3 을 지울 때 이름이 다른 UPG 는 지우지 않았다

-- 이름을 바꾼 계정이 남긴 것을 따로 찾는다. 메일 스풀과 UPG 는 옛 이름 그대로다.
[root@ol7a ~]# ls -l /var/spool/mail; getent group user3 && groupdel user3; rm -f /var/spool/mail/user3; echo "exit=$?"

user3:x:1501:
exit=0

-- groupdel user3 로 지웠다. rm -f 는 대상이 없어도 exit=0
[root@ol7a ~]# rm -f /etc/skel/.ol7lab_profile /root/nu.txt; for f in passwd shadow group gshadow; do diff /root/b08/$f /etc/$f >/dev/null && echo "$f 같음" || echo "$f 다름"; done

 [정리] 관찰 요약
--------------------------------------------------------------------------------
--  항목                  시작 전        변경 후(실습 중)              되돌린 뒤
--  passwd·shadow 줄 수   28             +1 (useradd 마다)            28 (diff 같음)
--  새 계정 shadow 2번    -              !! → chpasswd 뒤 $6$         -
--  passwd -S             -              LK → PS                     -
--  user1 UID/GID         -              1001/1001                   -
--  -u 1000               -              not unique, exit=4          -
--  -u 1500 다음 UID      -              1501 (빈 번호 건너뜀)        -
--  -M 계정 홈            -              없음 → mkhomedir_helper 755  -
--  useradd 홈 권한       -              700 (UMASK 077)             -
--  -r 계정               -              UID 996, 홈·스풀 없음        -
--  usermod -l 뒤         -              UPG user3 남음, 스풀 이동    groupdel
--  newusers 홈           -              빈 디렉터리, 스풀 없음       -
--  /etc/skel             파일 3         4                           3
-- 확인한 사실
--   useradd 는 네 파일 + 홈 + 메일 스풀을 만든다. newusers 는 홈만 비어 있게
--   UID 는 가장 큰 값 + 1. 빈 번호는 채우지 않는다
--   usermod -l 은 스풀은 옮기지만 UPG 이름은 남긴다
