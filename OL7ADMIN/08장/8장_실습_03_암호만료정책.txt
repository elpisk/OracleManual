 제8장 실습 03 — 암호 만료 정책과 암호 강도 규칙
 대상   : ol7a
 목표   : chage -l 의 일곱 줄이 /etc/shadow 의 어느 필드인지 짚고, 최소·최대
          사용 기간, 경고, 비활성, 계정 만료를 걸어 각각 어떤 메시지로 막히는지
          본다. pwquality.conf 로 강도 규칙을 바꾸고 즉시 반영되는지 확인한다
 배경   : 암호 정책은 두 군데서 온다. 만료 날짜는 shadow 의 3~8번 필드(날짜는
          1970-01-01 부터 센 일수)이고 chage 가 고친다. 강도 규칙은 PAM 모듈
          pam_pwquality 가 /etc/security/pwquality.conf 를 읽어 암호를 바꾸는
          순간에 검사한다. login.defs 의 PASS_* 값은 새로 만드는 계정에만
          들어간다(본문 8.5·8.6)
 소요   : 약 30분
 선행   : ol7-base 스냅샷
 계정   : root, student(su 로그인 시험용), user1·user2(실습용)
 주의   : 없음. pwquality.conf·login.defs 는 [0] 의 사본으로 되돌린다
 되돌림 : user1·user2 삭제, 두 설정 파일의 md5sum 이 [0] 과 같음

--------------------------------------------------------------------------------
 [0] 시작 전 상태 기록
--------------------------------------------------------------------------------

-- 바꿀 파일 두 개의 지문을 남기고 사본을 떠 둔다. 끝에서 md5sum 으로 비교한다.
[root@ol7a ~]# mkdir -p /root/b08 && cp -a /etc/security/pwquality.conf /etc/login.defs /root/b08/ && md5sum /etc/security/pwquality.conf /etc/login.defs
ed05f4f0bdd01c1b70acd769929e8e70  /etc/security/pwquality.conf
871bc72fe80572425a9529c6d39166d1  /etc/login.defs
-- md5 두 값을 되돌림에서 다시 비교한다. 한 글자만 달라도 값이 바뀐다

-- login.defs 의 암호 관련 줄. PASS_ 로 시작하는 넷과 해시 방식
[root@ol7a ~]# grep -E '^(PASS_|ENCRYPT_METHOD)' /etc/login.defs
PASS_MAX_DAYS   99999
PASS_MIN_DAYS   0
PASS_MIN_LEN    5
PASS_WARN_AGE   7
ENCRYPT_METHOD SHA512
-- 기본값: 최대 99999일, 최소 0일, 경고 7일. 사실상 만료가 없다
-- PASS_MIN_LEN 5 는 7.9 에서 쓰이지 않는다.
-- 길이 검사는 pam_pwquality 가 한다

-- pwquality.conf 에 주석이 아닌 줄이 몇 개인지 센다. 0 이면 모두 기본값이다.
[root@ol7a ~]# grep -c '^[^#]' /etc/security/pwquality.conf; grep -c '' /etc/security/pwquality.conf
0
50
-- 50줄 전부가 주석. pwquality 는 내장 기본값(minlen 9,
-- difok 5 등)으로 돈다

-- pam_pwquality 를 부르는 곳. passwd 명령은 /etc/pam.d/passwd 가 system-auth 를 포함한다.
[root@ol7a ~]# grep -n pwquality /etc/pam.d/system-auth; grep -v '^#' /etc/pam.d/passwd
16:password    requisite     pam_pwquality.so try_first_pass local_users_only retry=3 authtok_type=
auth       include      system-auth
account    include      system-auth
password   substack     system-auth
-password   optional    pam_gnome_keyring.so use_authtok
password   substack     postlogin
-- system-auth 16행: password 단계, requisite 제어
--   requisite        실패하면 그 자리에서 끝냄(뒤의 pam_unix 를 부르지 않음)
--   local_users_only /etc/passwd 의 계정에만 적용
--   retry=3          새 암호를 세 번까지 다시 묻는다
-- /etc/pam.d/passwd 는 password 단계를 substack 으로 system-auth 에 맡긴다
-- 앞의 - 는 "모듈이 없어도 기록하지 않음".
-- gnome_keyring 은 설치돼 있지 않다

-- 오늘 날짜와, 1970-01-01 부터 센 오늘의 일수. shadow 의 날짜 필드는 이 단위다.
[root@ol7a ~]# date +%F; echo $(( $(date +%s) / 86400 ))
2026-11-16
20773
-- 2026-11-16 은 1970-01-01 부터 20773 일째.
-- 이 숫자가 shadow 에 들어간다

--------------------------------------------------------------------------------
 [1] 새 계정의 기본 만료 정보 — chage -l
--------------------------------------------------------------------------------

-- 실습용 계정을 만들고 암호를 준다. chpasswd 는 root 가 쓰므로 강도 검사를 하지 않는다.
[root@ol7a ~]# useradd user1 && echo 'user1:Ol7#Pass2026' | chpasswd && getent shadow user1 > /root/b08/user1.shadow0; echo "exit=$?"
exit=0
-- && 로 묶어 세 명령이 모두 성공했다. shadow 줄은 [4] 비교용으로 남겼다

-- -l(list)은 읽기만 한다. root 가 아니면 자기 계정만 볼 수 있다.
[root@ol7a ~]# chage -l user1
Last password change                                    : Nov 16, 2026
Password expires                                        : never
Password inactive                                       : never
Account expires                                         : never
Minimum number of days between password change          : 0
Maximum number of days between password change          : 99999
Number of days of warning before password expires       : 7
-- 일곱 줄과 shadow 필드의 짝
--   Last password change   3번(마지막 변경일)
--   Password expires       3번 + 5번으로 계산. 99999 라 never
--   Password inactive      만료일 + 7번. 7번이 비어 never
--   Account expires        8번. 비어 never
--   Minimum / Maximum / warning   4·5·6번

-- 같은 값이 shadow 의 어느 칸인지 본다. 해시(2번)는 길어서 빼고 3~9번만 찍는다.
[root@ol7a ~]# getent shadow user1 | cut -d: -f3- | awk -F: '{for(i=1;i<=NF;i++) printf "%d [%s]\n", i+2, $i}'
3 [20773]
4 [0]
5 [99999]
6 [7]
7 []
8 []
9 []
-- 3 [20773]  4 [0]  5 [99999]  6 [7]  7·8·9 빈 칸
-- 4~6 이 login.defs 의 PASS_MIN_DAYS·MAX_DAYS·WARN_AGE 와 같다

--------------------------------------------------------------------------------
 [2] 날짜 필드 읽기 — 일수를 날짜로
--------------------------------------------------------------------------------

-- 3번 필드(마지막 변경일)를 날짜로 바꿔 본다. date -d 는 "기준일 + N days" 식을 계산한다.
[root@ol7a ~]# d=$(getent shadow user1 | cut -d: -f3); echo "필드3=$d"; date -u -d "1970-01-01 +$d days" +%F
필드3=20773
2026-11-16
-- 20773 일 = 2026-11-16.
-- chage -l 의 Nov 16, 2026 과 같다
-- -u(UTC)를 쓴 이유: 지역 시각으로 계산하면 자정 근처에서 하루가 어긋날 수 있다

-- 반대로 날짜를 일수로. chage -E 에 날짜 대신 일수를 줘도 되는 이유가 이것이다.
[root@ol7a ~]# echo $(( $(date -u -d 2027-06-30 +%s) / 86400 ))
20999
-- 2027-06-30 은 20999.
-- [6] 에서 -E 2027-06-30 을 주면 8번 필드에 이 숫자가 들어간다

--------------------------------------------------------------------------------
 [3] 강도 규칙 — 기본값에서 약한 암호 바꾸기 (오류 ①)
--------------------------------------------------------------------------------

-- pwscore 는 pwquality 규칙으로 점수를 매긴다(0~100). 규칙 위반이면 이유를 출력한다.
[root@ol7a ~]# for p in abc password Oracle2026 'Xk9#mq2Lw!'; do printf '%-12s ' "$p"; echo "$p" | pwscore 2>&1; done
abc          Password quality check failed:
 The password is shorter than 8 characters
password     Password quality check failed:
 The password fails the dictionary check - it is based on a dictionary word
Oracle2026   38
Xk9#mq2Lw!   55
-- abc        'shorter than 8 characters' — minlen 9 에서 문자 종류 credit 1 을 뺀 값
-- password   'fails the dictionary check' — cracklib 사전에 있는 단어
-- Oracle2026 38점, Xk9#mq2Lw! 55점. 통과한 암호만 점수가 나온다

-- user1 이 자기 암호를 'abc' 로 바꾸려 한다. 일반 사용자의 passwd 는
-- 현재 암호 → 새 암호 → 재입력 순으로 묻는다. 입력은 printf 로 준다.
-- 'abc' 를 세 번 주는 것은 system-auth 의 retry=3 때문이다.
[user1@ol7a ~]$ printf 'Ol7#Pass2026\nabc\nabc\nabc\n' | passwd; echo "exit=$?"
(current) UNIX password: New password: BAD PASSWORD: The password is shorter than 8 characters
New password: BAD PASSWORD: The password is shorter than 8 characters
New password: BAD PASSWORD: The password is shorter than 8 characters
passwd: Have exhausted maximum number of retries for service
Changing password for user user1.
Changing password for user1.
exit=1
-- passwd 의 출력은 줄 순서가 섞여 보인다. 프롬프트는 표준 오류로 즉시,
-- Changing password ... 두 줄은 표준 출력 버퍼로 나중에 나왔다
-- 증상   : 'BAD PASSWORD: The password is shorter than 8 characters' 세 번 뒤
--          'passwd: Have exhausted maximum number of retries for service', exit=1
-- 원인   : pam_pwquality(requisite)가 새 암호를 거부했다. retry=3 을 다 썼다
-- 조치   : 규칙에 맞는 암호를 쓴다(12자 이상·3종류는 [5] 에서 통과)
-- 재확인 : passwd 가 'all authentication tokens updated successfully', exit=0
[root@ol7a ~]# getent shadow user1 | cut -d: -f3; tail -3 /var/log/secure | cut -c17-
20773
ol7a useradd[2111]: new user: name=user1, UID=1001, GID=1001, home=/home/user1, shell=/bin/bash
ol7a su: pam_unix(su-l:session): session opened for user user1 by (uid=0)
ol7a su: pam_unix(su-l:session): session closed for user user1
-- 3번 필드가 20773 그대로다. 암호는 바뀌지 않았다
-- secure 에는 useradd 기록과 러너의 su 세션 열고 닫음만 있다
-- pwquality 의 거부는 secure 에 남지 않는다. 사용자 화면에만 보인다

--------------------------------------------------------------------------------
 [4] root 가 바꾸면 — 경고만 하고 넣는다
--------------------------------------------------------------------------------

-- --stdin 은 root 전용 옵션. 표준 입력의 첫 줄을 새 암호로 쓴다.
[root@ol7a ~]# echo abc | passwd --stdin user1; echo "exit=$?"
Changing password for user user1.
passwd: all authentication tokens updated successfully.
exit=0
-- root 의 --stdin 은 BAD PASSWORD 경고조차 찍지 않고 abc 를 넣었다
-- 7.9 의 passwd 는 root 가 바꿀 때 강도 검사 결과를 강제하지 않는다

-- 2번 필드(해시)가 바뀌었는지 앞부분만 본다. $6$ 뒤 소금(salt)이 달라졌으면 새 암호다.
[root@ol7a ~]# diff <(cut -d: -f2 /root/b08/user1.shadow0 | cut -c1-20) <(getent shadow user1 | cut -d: -f2 | cut -c1-20)
1c1
< $6$54EwoLh2D/MR$XC1q
---
> $6$U7rGrmch$dfDKuvIg
-- 소금이 54EwoLh2D/MR 에서 U7rGrmch 로 바뀌었다. 새 해시다
-- chpasswd 의 소금은 16자, passwd 는 8자. 해시를 만든 도구가 다르다

--------------------------------------------------------------------------------
 [5] pwquality.conf 로 규칙 강화 — 바로 반영되는가
--------------------------------------------------------------------------------

-- 최소 길이 12, 문자 종류(대문자·소문자·숫자·특수) 3가지 이상을 요구한다.
-- 데몬이 없는 설정이라 재시작할 대상이 없다. 다음 passwd 실행부터 읽는다.
[root@ol7a ~]# printf 'minlen = 12\nminclass = 3\n' >> /etc/security/pwquality.conf; grep -v '^#' /etc/security/pwquality.conf | grep -v '^$'
minlen = 12
minclass = 3

-- 주석이 아닌 줄이 두 개 생겼다
[root@ol7a ~]# diff /root/b08/pwquality.conf /etc/security/pwquality.conf
50a51,52
> minlen = 12
> minclass = 3
-- 50a51,52: 파일 끝(50행) 뒤에 두 줄

-- 첫 새 암호는 소문자만(1종류), 둘째는 12자 이상·4종류. 현재 암호는 [4] 의 abc.
[user1@ol7a ~]$ printf 'abc\noraclelinux7\nOl7#Strong2026\nOl7#Strong2026\n' | passwd; echo "exit=$?"
(current) UNIX password: New password: BAD PASSWORD: The password contains less than 3 character classes
New password: Retype new password: Changing password for user user1.
Changing password for user1.
passwd: all authentication tokens updated successfully.
exit=0
-- 첫 시도 oraclelinux7 은 'contains less than 3 character classes' 로 거부
--   소문자·숫자 2종류. 12자라 길이는 통과했다
-- 두 번째 Ol7#Strong2026 은 14자·4종류로 통과,
-- Retype 까지 가서 성공
-- 재시작 없이 바로 새 규칙(minclass 3)이 적용됐다
[root@ol7a ~]# for p in oraclelinux7 Ol7pass2026 'Ol7#Strong2026'; do printf '%-15s ' "$p"; echo "$p" | pwscore 2>&1; done
oraclelinux7    Password quality check failed:
 The password contains less than 3 character classes
Ol7pass2026     20
Ol7#Strong2026  54
-- Ol7pass2026 은 3종류·11자인데 20점으로 통과
--   credit 이 문자 종류마다 길이를 1씩 더 쳐 줘서 minlen 12 를 넘겼다
-- 길이를 엄격히 하려면 dcredit=0 ucredit=0 같은 값도 함께 정한다

--------------------------------------------------------------------------------
 [6] 만료 정책 걸기 — chage -M -m -W -I -E
--------------------------------------------------------------------------------

-- -M 최대 사용 일수, -m 최소 사용 일수, -W 만료 전 경고 일수,
-- -I 만료 뒤 비활성까지의 유예 일수, -E 계정 자체의 만료일
[root@ol7a ~]# getent shadow user1 > /root/b08/user1.shadow1; chage -M 90 -m 1 -W 7 -I 14 -E 2027-06-30 user1; echo "exit=$?"
exit=0
-- chage 도 성공하면 말이 없다
[root@ol7a ~]# chage -l user1
Last password change                                    : Nov 16, 2026
Password expires                                        : Feb 14, 2027
Password inactive                                       : Feb 28, 2027
Account expires                                         : Jun 30, 2027
Minimum number of days between password change          : 1
Maximum number of days between password change          : 90
Number of days of warning before password expires       : 7
-- Password expires  Feb 14, 2027 = 11-16 + 90일
-- Password inactive Feb 28, 2027 = 만료일 + 14일
-- Account expires   Jun 30, 2027 = -E 값
-- Minimum 1, Maximum 90

-- 바뀐 칸만 보이도록 해시를 뺀 나머지를 비교한다.
[root@ol7a ~]# diff <(cut -d: -f1,3- /root/b08/user1.shadow1) <(getent shadow user1 | cut -d: -f1,3-)
1c1
< user1:20773:0:99999:7:::
---
> user1:20773:1:90:7:14:20999:
-- 해시를 뺀 줄의 4~8번이 1:90:7:14:20999 로 바뀌었다
-- 3번(20773)은 그대로. chage 는 변경일을 건드리지 않았다

--------------------------------------------------------------------------------
 [9] 다음 로그인 때 변경 강제 — chage -d 0 (오류 ②)
--------------------------------------------------------------------------------

-- -d 0 은 마지막 변경일을 1970-01-01 로 만든다. 새로 발급한 임시 암호에 쓴다.
[root@ol7a ~]# chage -d 0 user1; chage -l user1 | head -3
Last password change                                    : password must be changed
Password expires                                        : password must be changed
Password inactive                                       : password must be changed
-- 3번 필드가 0. 날짜 대신 'password must be changed' 가 세 줄에 찍힌다

-- student 가 su 로 user1 에 들어가 본다. 로그인 암호 한 줄만 준다.
[student@ol7a ~]$ printf 'Ol7#Strong2026\n' | su - user1 -c id; echo "exit=$?"
Password: You are required to change your password immediately (root enforced)
(current) UNIX password: su: Authentication token manipulation error
Changing password for user1.
exit=1
-- 증상   : su 가 'You are required to change your password immediately
--          (root enforced)' 뒤 '(current) UNIX password:' 에서
--          'su: Authentication token manipulation error', exit=1
-- 원인   : 로그인 암호는 맞았지만 account 단계가 변경을 요구했다.
--          입력이 한 줄뿐이라 현재 암호를 받지 못해 변경이 실패했다
-- 조치   : 현재 암호와 새 암호 두 번을 이어서 준다(아래)
-- 재확인 : id 가 실행되고 chage -l 의 첫 줄이 Nov 16, 2026

-- 이번에는 로그인 암호, 현재 암호, 새 암호 두 번을 차례로 준다.
[student@ol7a ~]$ printf 'Ol7#Strong2026\nOl7#Strong2026\nOl7#Fresh2026xy\nOl7#Fresh2026xy\n' | su - user1 -c id; echo "exit=$?"
Password: You are required to change your password immediately (root enforced)
(current) UNIX password: New password: Retype new password: uid=1001(user1) gid=1001(user1) groups=1001(user1) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
Changing password for user1.
exit=0
-- 네 줄을 차례로 썼다: 로그인 암호, 현재 암호, 새 암호, 재입력
-- 변경이 끝난 뒤에야 -c id 가 실행됐다
[root@ol7a ~]# chage -l user1 | head -3
Last password change                                    : Nov 16, 2026
Password expires                                        : Feb 14, 2027
Password inactive                                       : Feb 28, 2027
-- 3번 필드가 오늘(20773)로 돌아왔고 만료·비활성도 다시 계산됐다

--------------------------------------------------------------------------------
 [10] 계정 만료와 비활성
--------------------------------------------------------------------------------

-- -E 에 어제 날짜를 주면 계정이 만료된다. 암호가 맞아도 들어가지 못한다.
[root@ol7a ~]# chage -E $(date -d yesterday +%F) user1; chage -l user1 | sed -n '4p'
Account expires                                         : Nov 15, 2026
-- 어제 날짜가 8번에 들어갔다
[student@ol7a ~]$ printf 'Ol7#Fresh2026xy\n' | su - user1 -c id; echo "exit=$?"
Password: Your account has expired; please contact your system administrator
su: User account has expired
exit=1
-- 'Your account has expired; please contact your system administrator',
-- 'su: User account has expired'.
-- 암호는 맞았다. account 단계에서 막혔다

-- 비활성: 암호가 만료된 뒤 -I 일이 지나면 잠긴다. 마지막 변경을 60일 전으로 돌려 재현한다.
[root@ol7a ~]# chage -E -1 -d $(date -d '-60 days' +%F) -M 30 -I 7 user1; chage -l user1 | head -4
Last password change                                    : Sep 17, 2026
Password expires                                        : Oct 17, 2026
Password inactive                                       : Oct 24, 2026
Account expires                                         : never
-- 60일 전 변경 + 최대 30일 → 10월 17일 만료,
-- + 비활성 7일 → 10월 24일
-- 오늘(11-16)은 비활성 기한도 지났다
[student@ol7a ~]$ printf 'Ol7#Fresh2026xy\n' | su - user1 -c id; echo "exit=$?"
Password: Your account has expired; please contact your system administrator
su: Authentication token expired
exit=1
-- 메시지 첫 줄은 계정 만료와 같다.
-- 둘째 줄이 'su: Authentication token expired'
-- 계정 만료(-E)와 비활성(-I)은 사용자 화면에서 구분이 잘 안 된다
[root@ol7a ~]# grep 'user1' /var/log/secure | tail -4 | cut -c17-
ol7a chage[2782]: changed password expiry for user1
ol7a su: pam_unix(su-l:account): account user1 has expired (account expired)
ol7a chage[2843]: changed password expiry for user1
ol7a su: pam_unix(su-l:account): account user1 has expired (failed to change password)
-- secure 에서는 괄호 안이 다르다
--   (account expired)            8번 필드 만료
--   (failed to change password)  비활성 기한 지남
-- 어느 쪽인지는 secure 를 보고 판단한다

--------------------------------------------------------------------------------
 [11] 해시 알고리즘 — sha512
--------------------------------------------------------------------------------

-- authconfig --test 는 현재 인증 설정을 바꾸지 않고 출력만 한다.
[root@ol7a ~]# authconfig --test | grep -E 'hashing|pwquality|faillock'
 password hashing algorithm is sha512
pam_pwquality is enabled (try_first_pass local_users_only retry=3 authtok_type=)
pam_faillock is disabled (deny=4 unlock_time=1200)
-- password hashing algorithm is sha512
-- pam_pwquality 는 켜져 있고 인자는 system-auth 16행과 같다
-- faillock 은 꺼져 있다.
-- 괄호 안은 authconfig 의 기본 인자(실습 06 에서 바꿔 켬)

-- 해시 문자열의 머리 $6$ 이 sha512 표시다. $1$ 은 MD5, $5$ 는 sha256.
[root@ol7a ~]# getent shadow user1 user2 student | cut -d: -f1,2 | cut -c1-24
user1:$6$PNuoC17t$GYbvnQ
user2:$6$L01qO/W3Xn$JSNx
student:$6$z7uEaT.ktqWGA
-- 세 계정 모두 $6$. 소금 길이는 user1 8자,
-- user2·student 는 더 길다
--   user1 은 [9] 의 su 화면에서 passwd 가, user2 는 chpasswd 가 만들었다

-- pam_unix 줄의 sha512 와 login.defs 의 ENCRYPT_METHOD 가 같은 값을 가리켜야 한다.
[root@ol7a ~]# grep -n 'pam_unix.so.*sha512' /etc/pam.d/system-auth; grep '^ENCRYPT_METHOD' /etc/login.defs
17:password    sufficient    pam_unix.so sha512 shadow nullok try_first_pass use_authtok
ENCRYPT_METHOD SHA512
-- pam_unix 의 sha512 는 passwd·su 의 변경에,
-- ENCRYPT_METHOD 는 chpasswd 에 쓰인다
-- 두 값이 다르면 만든 도구에 따라 해시 방식이 섞인다

--------------------------------------------------------------------------------
 [변형] passwd 의 옵션으로 같은 정책 걸기
--------------------------------------------------------------------------------

-- passwd 에도 -n(최소) -x(최대) -w(경고) -i(비활성) 가 있다. chage 와 같은 칸을 고친다.
[root@ol7a ~]# passwd -n 2 -x 60 -w 10 -i 5 user2; chage -l user2 | sed -n '5,7p'; getent shadow user2 | cut -d: -f4-7
Adjusting aging data for user user2.
passwd: Success
Minimum number of days between password change          : 2
Maximum number of days between password change          : 60
Number of days of warning before password expires       : 10
2:60:10:5
-- 'Adjusting aging data for user user2.' 뒤 Success
-- shadow 4~7번이 2:60:10:5.
-- chage -M -m -W -I 와 같은 칸이다

-- passwd -S 는 한 줄 요약. 날짜 뒤 숫자 넷이 최소·최대·경고·비활성이다.
[root@ol7a ~]# passwd -S user2; passwd -S user1
user2 PS 2026-11-16 2 60 10 5 (Password set, SHA512 crypt.)
user1 PS 2026-09-17 1 30 7 7 (Password set, SHA512 crypt.)
-- user2: 2026-11-16 2 60 10 5.
-- user1: 2026-09-17(60일 전으로 돌림) 1 30 7 7

-- -e(expire)는 chage -d 0 과 같은 효과다.
[root@ol7a ~]# passwd -e user2; getent shadow user2 | cut -d: -f3
Expiring password for user user2.
passwd: Success
0

-- 3번 필드가 0. passwd -e 는 chage -d 0 과 같은 일을 한다
