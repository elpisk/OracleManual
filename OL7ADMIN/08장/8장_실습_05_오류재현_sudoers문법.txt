 제8장 실습 05 — 오류 재현: sudoers 문법 오류와 visudo  [오류 재현]
 대상   : ol7a
 목표   : 문법이 틀린 sudoers 를 visudo 로 저장하려 할 때 무엇이 막히는지,
          visudo 를 거치지 않고 sudoers.d 에 넣으면 무엇이 멈추는지,
          파일 권한·파일 이름 때문에 규칙이 조용히 무시되는 경우를 재현한다
 배경   : sudo 는 실행할 때마다 /etc/sudoers 와 #includedir 로 읽는 /etc/sudoers.d/*
          를 해석한다. 어느 한 파일이라도 문법이 틀리면 sudo 전체가 정책을 세우지
          못하고 멈춘다. visudo 는 임시 사본을 편집하게 한 뒤 저장 전에 문법을 검사해
          이 사고를 막는다. -c 는 검사만, -f 는 대상 파일 지정(본문 8.7)
 소요   : 약 25분
 선행   : ol7-base 스냅샷
 계정   : root, student(wheel, sudo 영향 확인용), user1
 주의   : /etc/sudoers 본문은 건드리지 않는다. 오류는 /tmp 사본과 /etc/sudoers.d 의
          별도 파일로만 재현한다. sudo 가 멈춰도 root SSH 는 되므로 복구할 수 있다
 되돌림 : /etc/sudoers.d 비움, user1 삭제, visudo -c 통과, md5sum 이 [0] 과 같음

 [1] visudo -c — 검사만 하기
--------------------------------------------------------------------------------

-- -c(check) 는 편집기를 열지 않고 문법과 권한만 검사한다. 포함 파일까지 모두 본다.
[root@ol7a ~]# visudo -c; echo "exit=$?"
/etc/sudoers: parsed OK
exit=0
-- 포함 파일이 없어서 /etc/sudoers 한 줄만 보고했다

-- -q(quiet) 를 붙이면 정상일 때 아무것도 출력하지 않는다. 스크립트에서 종료 코드만 볼 때 쓴다.
-- -s(strict) 는 정의되지 않은 별칭 같은 것까지 오류로 본다.
[root@ol7a ~]# visudo -cq; echo "exit=$?"; visudo -cs; echo "exit=$?"
exit=0
/etc/sudoers: parsed OK
exit=0
-- -cq 는 정상일 때 아무것도 찍지 않고 exit=0
-- -cs 는 parsed OK. 기본 sudoers 는 엄격 검사도 통과한다

--------------------------------------------------------------------------------
 [2] 오류 ① — 문법이 틀린 줄을 visudo 로 저장하려 하면
--------------------------------------------------------------------------------

-- 실제 /etc/sudoers 대신 사본으로 한다. visudo -f 는 지정한 파일을 같은 방식으로 다룬다.
[root@ol7a ~]# cp -a /etc/sudoers /tmp/sudoers.test; md5sum /tmp/sudoers.test
1b134d95a4618029ff962a63b021e1ca  /tmp/sudoers.test
-- 사본의 md5 가 /etc/sudoers 와 같다.
-- cp -a 라 권한 0440 도 같다

-- visudo 는 $EDITOR 로 편집기를 고른다. 사람이 vi 에서 실수하는 장면 대신,
-- 파일 끝에 괄호를 닫지 않은 줄을 덧붙이는 작은 스크립트를 편집기로 쓴다.
-- visudo 는 편집기를 '편집기 -- 파일' 로 부르므로 마지막 인자를 파일로 잡는다(for f; do :; done).
[root@ol7a ~]# printf '#!/bin/sh\nfor f; do :; done\necho "user1 ALL=(root /usr/bin/id" >> "$f"\n' > /root/bad_editor.sh; chmod 700 /root/bad_editor.sh; cat /root/bad_editor.sh
#!/bin/sh
for f; do :; done
echo "user1 ALL=(root /usr/bin/id" >> "$f"

-- 세 줄짜리 편집기. 받은 인자를 다 돌고 난 f 가 마지막 인자(파일)다
-- (root 뒤에 ) 가 없다. 이 한 글자가 문법 오류다
-- visudo 가 "What now?" 로 물으면 x(저장하지 않고 끝내기)를 준다. 표준 입력으로 답을 넘긴다.
[root@ol7a ~]# echo x | EDITOR=/root/bad_editor.sh visudo -f /tmp/sudoers.test; echo "exit=$?"
>>> /tmp/sudoers.test: syntax error near line 121 <<<
What now? exit=0
-- visudo 가 편집 뒤 검사에서 '>>> /tmp/sudoers.test: syntax error near line 121 <<<'
-- 121 행은 원래 120행 끝에 덧붙은 줄이다
-- 'What now?' 에 x 를 받아 저장하지 않고 끝냈다.
-- 답 뒤에 줄바꿈이 없어 exit=0 이 이어 붙었다
-- 증상   : 편집을 마치자 '>>> /tmp/sudoers.test: syntax error near line 121 <<<'
--          와 'What now?' 프롬프트
-- 원인   : 괄호를 닫지 않은 (root 때문에 해석 실패. visudo 는 임시 파일
--          sudoers.test.tmp 를 편집시키고 저장 전에 검사한다
-- 조치   : e 로 다시 편집하거나 x 로 버린다(여기서는 x)
-- 재확인 : md5sum 이 [2] 처음 값과 같다(아래)

-- 사본은 바뀌었는가. md5 가 [2] 처음 값과 같으면 저장되지 않은 것이다.
[root@ol7a ~]# md5sum /tmp/sudoers.test; tail -2 /tmp/sudoers.test
1b134d95a4618029ff962a63b021e1ca  /tmp/sudoers.test
## Read drop-in files from /etc/sudoers.d (the # here does not mean a comment)
#includedir /etc/sudoers.d
-- md5 가 1b134d...
-- 그대로, 끝 두 줄도 원래대로. 저장되지 않았다
-- 둘째 줄의 # 은 주석이 아니라는 설명이 파일 안에 적혀 있다

-- visudo 가 편집하던 임시 파일은 남지 않는다.
[root@ol7a ~]# ls -la /tmp | grep -i sudoers
-r--r-----.  1 root root 4328 Jan 24  2023 sudoers.test
-- sudoers.test.tmp 가 없다. visudo 가 정리했다

--------------------------------------------------------------------------------
 [3] 다른 답 — Q 로 강제 저장하면
--------------------------------------------------------------------------------

-- "What now?" 의 보기 셋: e 다시 편집, x 버리고 끝냄, Q 그대로 저장(DANGER).
-- Q 를 고르면 틀린 내용이 그대로 저장된다. 사본이니 해 본다.
[root@ol7a ~]# echo Q | EDITOR=/root/bad_editor.sh visudo -f /tmp/sudoers.test; echo "exit=$?"
>>> /tmp/sudoers.test: syntax error near line 121 <<<
What now? exit=0
-- 같은 오류, 같은 프롬프트. 이번 답은 Q
[root@ol7a ~]# tail -1 /tmp/sudoers.test; visudo -cf /tmp/sudoers.test; echo "exit=$?"
user1 ALL=(root /usr/bin/id
>>> /tmp/sudoers.test: syntax error near line 121 <<<
parse error in /tmp/sudoers.test near line 121
exit=1
-- 마지막 줄에 틀린 줄이 그대로 저장됐다.
-- 다시 검사하면 parse error, exit=1
-- 진짜 /etc/sudoers 에서 Q 를 고르면 그 순간 서버의 sudo 가 모두 멈춘다
-- visudo 의 exit=0 은 "편집이 끝났다"는 뜻일 뿐 문법이 맞다는 뜻이 아니다

--------------------------------------------------------------------------------
 [4] visudo 를 거치지 않으면 — sudoers.d 에 틀린 파일을 바로 넣기
--------------------------------------------------------------------------------

-- 자동화 스크립트가 echo 로 규칙 파일을 바로 써 넣는 경우를 흉내 낸다.
[root@ol7a ~]# echo 'user1 ALL=(root /usr/bin/id' > /etc/sudoers.d/ops; chmod 0440 /etc/sudoers.d/ops; ls -l /etc/sudoers.d
total 4
-r--r-----. 1 root root 28 Nov 16 11:05 ops
-- 권한·소유자는 맞다(0440 root:root). 내용만 틀렸다

-- 규칙과 상관없는 student 의 sudo 부터 본다.
[student@ol7a ~]$ echo student | sudo -S whoami; echo "exit=$?"
>>> /etc/sudoers.d/ops: syntax error near line 1 <<<
sudo: parse error in /etc/sudoers.d/ops near line 1
sudo: no valid sudoers sources found, quitting
sudo: unable to initialize policy plugin
exit=1
-- student 는 ops 와 상관없는 wheel 사용자인데도 멈췄다
--   syntax error near line 1 → parse error → no valid sudoers sources found
--   → unable to initialize policy plugin, exit=1
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S -l; echo "exit=$?"
>>> /etc/sudoers.d/ops: syntax error near line 1 <<<
sudo: parse error in /etc/sudoers.d/ops near line 1
sudo: no valid sudoers sources found, quitting
sudo: unable to initialize policy plugin
exit=1
-- user1 의 sudo -l 도 같은 네 줄.
-- 정책을 세우지 못하면 허용 목록도 못 보인다

-- 이 상태에서 root 는 sudo 가 필요 없으므로 고칠 수 있다. 원인 파일을 찾는다.
[root@ol7a ~]# visudo -c; echo "exit=$?"
>>> /etc/sudoers.d/ops: syntax error near line 1 <<<
parse error in /etc/sudoers.d/ops near line 1
exit=1
-- 증상   : 모든 사용자의 sudo 가 'sudo: no valid sudoers sources found, quitting'
--          'sudo: unable to initialize policy plugin' 으로 exit=1
-- 원인   : sudo 는 실행할 때마다 sudoers 와 sudoers.d 를 모두 해석한다.
--          visudo 를 거치지 않은 ops 의 1행이 틀렸다(visudo -c 가 위치를 알려 줌)
-- 조치   : root 로 ops 를 고친다(아래 [5]). root 로 들어갈 길이 없으면
--          복구 모드 부팅이 필요하다
-- 재확인 : visudo -c 가 두 파일 모두 parsed OK,
-- student·user1 의 sudo 성공

--------------------------------------------------------------------------------
 [6] 오류 ② — 권한이 너무 넓은 sudoers.d 파일
--------------------------------------------------------------------------------

-- 0644 로 바꾼다. 다른 사용자도 읽을 수 있을 뿐 쓸 수는 없다.
[root@ol7a ~]# chmod 0644 /etc/sudoers.d/ops; ls -l /etc/sudoers.d/ops; visudo -c; echo "exit=$?"
-rw-r--r--. 1 root root 29 Nov 16 11:05 /etc/sudoers.d/ops
/etc/sudoers.d/ops: bad permissions, should be mode 0440
/etc/sudoers: parsed OK
exit=1
-- visudo -c 는 'bad permissions,
-- should be mode 0440' 으로 exit=1
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S id; echo "exit=$?"
[sudo] password for user1: uid=0(root) gid=0(root) groups=0(root) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
exit=0
-- 그런데 sudo 는 0644 파일을 그대로 읽었다.
-- user1 의 id 가 root 로 실행
-- 남이 읽을 수만 있는 권한은 sudo 가 막지 않는다.
-- visudo 만 경고한다

-- 0666(누구나 쓰기)이면 누구든 자기에게 ALL 을 줄 수 있다. sudo 는 이 파일을 어떻게 다루는가.
[root@ol7a ~]# chmod 0666 /etc/sudoers.d/ops; ls -l /etc/sudoers.d/ops; visudo -c; echo "exit=$?"
-rw-rw-rw-. 1 root root 29 Nov 16 11:05 /etc/sudoers.d/ops
/etc/sudoers.d/ops: bad permissions, should be mode 0440
/etc/sudoers: parsed OK
exit=1
-- 0666 도 visudo 는 같은 문구로 exit=1
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S id; echo "exit=$?"
sudo: /etc/sudoers.d/ops is world writable
[sudo] password for user1: user1 is not in the sudoers file.  This incident will be reported.
exit=1
-- 증상   : sudo 가 'sudo: /etc/sudoers.d/ops is world writable' 을 찍은 뒤
--          user1 에게 'user1 is not in the sudoers file.', exit=1
-- 원인   : 누구나 쓸 수 있는 파일은 sudo 가 믿지 않고 건너뛴다. 규칙이 그
--          파일에만 있던 user1 은 규칙이 없는 사용자가 됐다
-- 조치   : chmod 0440 /etc/sudoers.d/ops (아래에서 0440 으로 되돌림)
-- 재확인 : visudo -c 의 parsed OK,
-- user1 의 sudo id 성공
[student@ol7a ~]$ echo student | sudo -S whoami; echo "exit=$?"
sudo: /etc/sudoers.d/ops is world writable
[sudo] password for student: root
exit=0
-- student 는 같은 경고 뒤 root.
-- 문법 오류와 달리 그 파일 하나만 빠졌다

-- 소유자가 root 가 아닌 경우.
[root@ol7a ~]# chmod 0440 /etc/sudoers.d/ops; chown user1 /etc/sudoers.d/ops; ls -l /etc/sudoers.d/ops; visudo -c; echo "exit=$?"
-r--r-----. 1 user1 root 29 Nov 16 11:05 /etc/sudoers.d/ops
/etc/sudoers.d/ops: wrong owner (uid, gid) should be (0, 0)
/etc/sudoers: parsed OK
exit=1
-- 소유자 user1 이면 visudo 는 'wrong owner (uid,
-- gid) should be (0, 0)'
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S id; echo "exit=$?"
sudo: /etc/sudoers.d/ops is owned by uid 1001, should be 0
[sudo] password for user1: user1 is not in the sudoers file.  This incident will be reported.
exit=1
-- sudo 는 'is owned by uid 1001,
-- should be 0' 을 찍고 그 파일을 건너뛰었다
-- user1 이 자기 규칙 파일을 고칠 수 있으면 스스로 ALL 을 줄 수 있기 때문이다
[root@ol7a ~]# chown root /etc/sudoers.d/ops; visudo -c
/etc/sudoers: parsed OK
/etc/sudoers.d/ops: parsed OK
-- 소유자를 root 로 되돌리자 정상
-- 권한·소유자 검사는 0440 root:root 하나로 맞추면 된다.
-- install -m 0440 -o root -g root

--------------------------------------------------------------------------------
 [7] 조용히 무시되는 파일 — 이름에 점이 있으면
--------------------------------------------------------------------------------

-- #includedir 는 이름이 ~ 로 끝나거나 . 을 포함한 파일을 읽지 않는다(sudoers(5)).
-- 편집기 백업 파일(ops~)이나 rpm 이 남기는 ops.rpmsave 가 규칙으로 읽히지 않게 하려는 규칙이다.
-- 관리자가 습관적으로 .conf 를 붙이면 그 규칙도 읽히지 않는다.
[root@ol7a ~]# mv /etc/sudoers.d/ops /etc/sudoers.d/ops.conf; ls -l /etc/sudoers.d; visudo -c; echo "exit=$?"
total 4
-r--r-----. 1 root root 29 Nov 16 11:05 ops.conf
/etc/sudoers: parsed OK
exit=0
-- ls 에 ops.conf.
-- visudo -c 는 /etc/sudoers 하나만 검사하고 OK
-- ops.conf 는 검사 대상에서도 빠졌다. 아무 경고도 없다
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S id; echo "exit=$?"
[sudo] password for user1: user1 is not in the sudoers file.  This incident will be reported.
exit=1
-- user1 은 다시 'not in the sudoers file'.
-- 규칙이 사라진 것과 같다
[root@ol7a ~]# sudo -l -U user1
User user1 is not allowed to run sudo on ol7a.
-- root 의 sudo -l -U 로도 확인된다.
-- 원인을 찾으려면 ls /etc/sudoers.d 의 이름을 본다
[root@ol7a ~]# mv /etc/sudoers.d/ops.conf /etc/sudoers.d/ops; sudo -l -U user1 | tail -2
User user1 may run the following commands on ol7a:
    (root) /usr/bin/id
-- 이름을 ops 로 되돌리자 규칙이 돌아왔다

--------------------------------------------------------------------------------
 [8] 문법은 맞지만 뜻이 틀린 줄 — 정의하지 않은 별칭
--------------------------------------------------------------------------------

-- 별칭 이름은 대문자로 쓴다. 정의하지 않은 별칭을 쓰면 visudo 는 어떻게 보는가.
[root@ol7a ~]# echo 'user1 ALL=(root) LOGCMDS' > /tmp/alias.test; visudo -cf /tmp/alias.test; echo "exit=$?"; visudo -csf /tmp/alias.test; echo "exit=$?"
Warning: /tmp/alias.test:1 Cmnd_Alias "LOGCMDS" referenced but not defined
/tmp/alias.test: parsed OK
exit=0
Error: /tmp/alias.test:1 Cmnd_Alias "LOGCMDS" referenced but not defined
exit=1
-- -c(경고)만 주면 'Warning: ... Cmnd_Alias "LOGCMDS" referenced but not defined' 뒤 parsed OK, exit=0
-- -s(엄격)를 더하면 같은 내용이 Error 가 되고 exit=1
-- 오타 난 별칭은 문법상 맞아서 그냥 통과할 수 있다.
-- 검사에는 -s 를 쓴다

-- 소문자로 쓰면 별칭이 아니라 명령으로 읽힌다. 명령은 / 로 시작해야 한다.
[root@ol7a ~]# echo 'user1 ALL=(root) logcmds' > /tmp/alias.test; visudo -cf /tmp/alias.test; echo "exit=$?"
>>> /tmp/alias.test: syntax error near line 1 <<<
parse error in /tmp/alias.test near line 1
exit=1
-- 소문자 logcmds 는 별칭도 경로도 아니라 syntax error
-- 명령은 / 로 시작하는 절대 경로, 별칭은 대문자.
-- 이 규칙 덕분에 둘을 구분한다

--------------------------------------------------------------------------------
 [9] 줄 순서 — 마지막에 맞는 규칙이 이긴다
--------------------------------------------------------------------------------

-- 한 사용자에게 여러 줄이 맞으면 sudo 는 마지막으로 맞은 줄을 쓴다.
-- "다 허용하고 su 만 금지" 를 순서만 바꿔 두 번 써 본다. ! 는 부정이다.
[root@ol7a ~]# printf 'user1 ALL=(root) !/usr/bin/su\nuser1 ALL=(root) /usr/bin/id, /usr/bin/su\n' > /etc/sudoers.d/ops; visudo -c >/dev/null && cat /etc/sudoers.d/ops
user1 ALL=(root) !/usr/bin/su
user1 ALL=(root) /usr/bin/id, /usr/bin/su

-- 첫 번째 배치: 거부가 위, 허용이 아래
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S su -c id; echo "exit=$?"
[sudo] password for user1: uid=0(root) gid=0(root) groups=0(root) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
exit=0
-- su -c id 가 uid=0(root) 로 실행됐다.
-- 아래 줄(허용)이 마지막으로 맞았다
[root@ol7a ~]# printf 'user1 ALL=(root) /usr/bin/id, /usr/bin/su\nuser1 ALL=(root) !/usr/bin/su\n' > /etc/sudoers.d/ops; visudo -c >/dev/null && cat /etc/sudoers.d/ops
user1 ALL=(root) /usr/bin/id, /usr/bin/su
user1 ALL=(root) !/usr/bin/su

-- 두 번째 배치: 허용이 위, 거부가 아래
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S su -c id; echo "exit=$?"
[sudo] password for user1: Sorry, user user1 is not allowed to execute '/bin/su -c id' as root on ol7a.example.com.
exit=1
-- 이번에는 'not allowed to execute '/bin/su -c id''. 마지막에 맞은 거부가 이겼다
-- ! 로 막는 방식은 cp /usr/bin/su /tmp/x 처럼 우회되기 쉽다. 허용만 적는 쪽이 낫다

--------------------------------------------------------------------------------
 [10] 안전한 반영 순서 — 검사 → 설치 → 전체 검사
--------------------------------------------------------------------------------

-- 앞의 사고를 모두 피하는 순서다. 임시 파일에 쓰고, -cf 로 검사하고,
-- install 로 이름·권한·소유자를 맞춰 넣고, 마지막에 -c 로 전체를 다시 본다.
-- && 로 묶어 앞 단계가 실패하면 뒤로 가지 않게 한다.
[root@ol7a ~]# echo 'user1 ALL=(root) /usr/bin/id' > /tmp/ops.new && visudo -cqf /tmp/ops.new && install -m 0440 -o root -g root /tmp/ops.new /etc/sudoers.d/ops && visudo -c; echo "exit=$?"
/etc/sudoers: parsed OK
/etc/sudoers.d/ops: parsed OK
exit=0
-- 네 단계가 모두 통과해 설치됐다. -cqf 는 정상이면 말이 없다

-- 같은 순서에 틀린 파일을 넣으면 첫 검사에서 멈추고 설치하지 않는다.
[root@ol7a ~]# echo 'user1 ALL=(root /usr/bin/id' > /tmp/ops.new && visudo -cqf /tmp/ops.new && install -m 0440 -o root -g root /tmp/ops.new /etc/sudoers.d/ops && visudo -c; echo "exit=$?"; cat /etc/sudoers.d/ops
exit=1
user1 ALL=(root) /usr/bin/id
-- 틀린 파일은 -cqf 에서 exit=1.
-- && 때문에 install 과 -c 는 실행되지 않았다
-- ops 의 내용은 앞의 맞는 줄 그대로다. 사고가 설치 전에 멈췄다

--------------------------------------------------------------------------------
 [변형] visudo 로 sudoers.d 파일을 직접 편집하기
--------------------------------------------------------------------------------

-- 임시 파일 대신 visudo -f 로 sudoers.d 의 파일을 바로 연다. 저장 전 검사는 [2] 와 같고,
-- 새 파일이면 visudo 가 0440 root:root 로 만든다. 편집기 대신 줄을 덧붙이는 스크립트를 쓴다.
[root@ol7a ~]# printf '#!/bin/sh\nfor f; do :; done\necho "user1 ALL=(root) /usr/bin/uptime" >> "$f"\n' > /root/good_editor.sh; chmod 700 /root/good_editor.sh

[root@ol7a ~]# EDITOR=/root/good_editor.sh visudo -f /etc/sudoers.d/uptime; echo "exit=$?"; ls -l /etc/sudoers.d; cat /etc/sudoers.d/uptime
exit=0
total 8
-r--r-----. 1 root root 29 Nov 16 11:05 ops
-r--r-----. 1 root root 33 Nov 16 11:05 uptime
user1 ALL=(root) /usr/bin/uptime

-- 새 파일 uptime 이 0440 root:root, 33바이트로 생겼다.
-- visudo 가 권한까지 맞췄다
-- 'unchanged' 메시지 없이 exit=0. 검사를 통과해 저장됐다
-- 틀린 줄을 덧붙이는 편집기로 같은 일을 하면 이번에도 "What now?" 에서 멈춘다.
[root@ol7a ~]# echo x | EDITOR=/root/bad_editor.sh visudo -f /etc/sudoers.d/uptime; echo "exit=$?"; cat /etc/sudoers.d/uptime
>>> /etc/sudoers.d/uptime: syntax error near line 2 <<<
What now? exit=0
user1 ALL=(root) /usr/bin/uptime
-- syntax error near line 2 → What now? → x. 파일은 첫 줄 그대로다
-- 기존 sudoers.d 파일을 고칠 때도 visudo -f 를 쓰면 같은 보호를 받는다

--------------------------------------------------------------------------------
 [정리] 관찰 요약
--------------------------------------------------------------------------------
--  상황                         visudo -c                      sudo 동작
--  사본에 틀린 줄 + x            syntax error → What now?      (저장 안 됨, md5 같음)
--  사본에 틀린 줄 + Q            저장됨, 다시 검사 시 exit=1    (진짜면 전체 정지)
--  sudoers.d 에 틀린 파일        parse error, exit=1           모든 사용자 정지
--  0644                          bad permissions, exit=1       그대로 읽음(실행됨)
--  0666                          bad permissions, exit=1       world writable → 그 파일만 무시
--  소유자 user1                  wrong owner, exit=1           owned by uid 1001 → 무시
--  이름 ops.conf                 검사 목록에서 빠짐, OK        경고 없이 무시
--  정의 안 된 별칭               Warning(-c) / Error(-cs)      -
--  거부 줄이 위                  OK                            허용이 이김
--  거부 줄이 아래                OK                            거부가 이김
--  항목                 시작 전     되돌린 뒤
--  /etc/sudoers md5     1b134d…     1b134d…
--  /etc/sudoers.d       비어 있음    비어 있음
-- 확인한 사실
--   문법 오류는 sudo 전체를, 권한·소유자 문제는 그 파일만 멈춘다
--   이름에 점이 있는 파일은 sudo 도 visudo 도 보지 않는다
--   임시 파일 → visudo -cqf → install -m 0440 → visudo -c 순서면 사고가 설치 전에 멈춘다
