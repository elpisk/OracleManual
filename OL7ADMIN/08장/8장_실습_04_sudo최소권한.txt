================================================================================
 제8장 실습 04 — sudo 최소 권한
 대상   : ol7a
 목표   : 운영자 계정에 "필요한 명령만" root 권한으로 허용하는 sudoers 규칙을 만들고,
          sudo -l 로 확인하고, 허용하지 않은 명령이 어떻게 거부·기록되는지 본다.
          와일드카드 하나가 허용 범위를 얼마나 넓히는지도 직접 확인한다
 배경   : sudoers 한 줄은 "누가 어느 호스트에서 = (누구로서) 무엇을" 이다.
          wheel 그룹처럼 ALL 을 주면 root 와 다를 바 없다. DB 서버에서는 운영자에게
          서비스 상태 확인·재시작처럼 정해진 명령만 열어 두고, 모든 실행은 /var/log/secure
          에 남긴다. 규칙 파일은 /etc/sudoers.d 아래에 따로 두고 visudo 로 검사한다
          (본문 8.7)
 소요   : 약 30분
 선행   : ol7-base 스냅샷
 계정   : root, user1(운영자 역할), user2(비교용)
 주의   : /etc/sudoers 본문은 고치지 않는다. 규칙은 /etc/sudoers.d/ops 하나에만 둔다
 되돌림 : /etc/sudoers.d/ops 삭제, user1·user2 삭제, visudo -c 통과

 [2] 규칙 작성 — 임시 파일에 쓰고 visudo 로 검사한 뒤 설치
--------------------------------------------------------------------------------

-- 바로 /etc/sudoers.d 에 쓰지 않는다. 문법이 틀린 파일이 그 자리에 들어가는 순간
-- 모든 사용자의 sudo 가 멈춘다(실습 05). 그래서 /tmp 에서 먼저 검사한다.
-- 규칙: user1 은 root 로서 chronyd 의 상태 확인·재시작, 시간 동기 상태 확인만 할 수 있다.
-- 명령은 절대 경로로 쓴다. sudoers 는 PATH 를 믿지 않는다.
[root@ol7a ~]# cat > /tmp/ops <<'EOF'
# 운영자 user1 — chronyd 관리만
user1  ALL=(root)  /usr/bin/systemctl status chronyd, /usr/bin/systemctl restart chronyd, /usr/bin/chronyc tracking
EOF

-- visudo -c 검사만, -f 파일 지정. /etc/sudoers 가 아닌 파일도 같은 문법으로 검사한다.
[root@ol7a ~]# visudo -cf /tmp/ops; echo "exit=$?"
/tmp/ops: parsed OK
exit=0
-- 'parsed OK', exit=0.
-- 아직 /etc/sudoers.d 에는 아무것도 없다

-- install 로 복사하면서 소유자·모드를 한 번에 맞춘다. sudoers 파일은 0440 root:root 가 기본이다.
[root@ol7a ~]# install -m 0440 -o root -g root /tmp/ops /etc/sudoers.d/ops; ls -l /etc/sudoers.d; visudo -c
total 4
-r--r-----. 1 root root 156 Nov 16 11:05 ops
/etc/sudoers: parsed OK
/etc/sudoers.d/ops: parsed OK
-- -r--r----- = 0440 root:root, 156바이트.
-- 전체 검사에서 두 파일 모두 OK

 [6] 별칭 — User_Alias, Cmnd_Alias 와 그룹 규칙

-- 사람이 늘면 사람마다 줄을 쓰는 대신 별칭이나 그룹(%이름)으로 묶는다.
-- 별칭 이름은 대문자로 시작해야 한다. 그룹은 % 를 붙인다.
[root@ol7a ~]# groupadd opsgrp; usermod -aG opsgrp user2; cat > /tmp/ops <<'EOF'
Cmnd_Alias  CHRONY = /usr/bin/systemctl status chronyd, /usr/bin/systemctl restart chronyd, /usr/bin/chronyc tracking
Cmnd_Alias  NETVIEW = /usr/sbin/ip addr show, /usr/bin/firewall-cmd --list-all
User_Alias  OPERATORS = user1
OPERATORS   ALL=(root)  CHRONY
%opsgrp     ALL=(root)  CHRONY, NETVIEW
EOF

 [7] NOPASSWD — 암호를 묻지 않는 규칙
--------------------------------------------------------------------------------

-- 감시 스크립트가 cron 에서 sudo 를 쓰려면 암호를 물으면 안 된다. 그 명령에만 NOPASSWD 를 붙인다.
-- 먼저 지금 상태에서 -n(non-interactive, 암호가 필요하면 묻지 말고 실패) 으로 친다.
[user2@ol7a ~]$ sudo -n /usr/bin/chronyc tracking; echo "exit=$?"
sudo: a password is required
exit=1
-- -n 은 암호가 필요하면 묻지 않고 'a password is required' 로 끝낸다
[root@ol7a ~]# sed -i 's|^%opsgrp .*|%opsgrp     ALL=(root)  CHRONY, NOPASSWD: NETVIEW|' /etc/sudoers.d/ops; visudo -c; tail -1 /etc/sudoers.d/ops
/etc/sudoers: parsed OK
/etc/sudoers.d/ops: parsed OK
%opsgrp     ALL=(root)  CHRONY, NOPASSWD: NETVIEW

-- sed -i 로 고친 직후에도 visudo -c 를 다시 돌렸다.
-- 고친 뒤 검사는 빠뜨리지 않는다
-- NOPASSWD: 는 그 뒤의 명령(NETVIEW)에만 붙는다.
-- CHRONY 는 여전히 암호
-- 파일을 고친 즉시 적용되는지 본다. sudo 는 데몬이 아니라 실행할 때마다 sudoers 를 읽는다.
[user2@ol7a ~]$ sudo -n /usr/sbin/ip addr show | head -3; sudo -n /usr/bin/chronyc tracking; echo "exit=$?"
1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
sudo: a password is required
exit=1
-- ip addr show 는 암호 없이 실행됐다(lo 줄 셋, head -3)
-- chronyc tracking 은 'a password is required', exit=1
-- 파일을 고친 즉시 반영됐다.
-- sudo 는 실행할 때마다 sudoers 를 읽는다

-- 규칙의 명령은 'ip addr show' 로 인자까지 정해져 있다. 인자를 하나 더 붙이면 맞지 않는다.
[user2@ol7a ~]$ sudo -n /usr/sbin/ip addr show ens32; echo "exit=$?"
sudo: a password is required
exit=1
-- 인자 ens32 를 붙이니 규칙 'ip addr show' 와 맞지 않았다
-- 맞는 규칙이 없을 때도 sudo 는 먼저 암호를 요구한다.
-- -n 이라 그 자리에서 끝났다

-- 볼 파일을 정확히 적는다. 로그 확인용으로는 tail 처럼 쓰기 기능이 없는 명령이 낫다.

 [10] 다른 사용자로 실행 — (runas) 부분
--------------------------------------------------------------------------------

-- 괄호 안은 "누구로서" 다. DBA 작업을 root 가 아니라 특정 계정으로 하게 할 때 쓴다.
-- 여기서는 user1 이 student 로서 id 명령만 실행하게 한다. -u 로 대상 사용자를 고른다.
[root@ol7a ~]# echo 'user1  ALL=(student)  /usr/bin/id' >> /etc/sudoers.d/logview; visudo -c
/etc/sudoers: parsed OK
/etc/sudoers.d/logview: parsed OK
/etc/sudoers.d/ops: parsed OK
-- >> 로 덧붙인 뒤 전체 검사. 파일 셋 모두 OK
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S -u student id; echo "exit=$?"
[sudo] password for user1: uid=1000(student) gid=1000(student) groups=1000(student),10(wheel) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
exit=0
-- (runas) 에 적은 계정으로만 바꿀 수 있다
-- -u student 로 실행. uid=1000(student).
-- root 가 아니라 student 권한이다

-- 대상 계정을 지정하지 않으면 root 로 실행하려 하므로 거부된다.
[user1@ol7a ~]$ echo 'Ol7#Pass2026' | sudo -S id; echo "exit=$?"
[sudo] password for user1: Sorry, user user1 is not allowed to execute '/bin/id' as root on ol7a.example.com.
exit=1
-- -u 를 빼면 대상은 root.
-- 규칙의 (student) 와 맞지 않아 거부
-- DBA 에게 oracle 계정 권한만 주는 규칙이 이 형태다: (oracle) 명령

-- 7.9 의 기본 sudoers 에는 "%wheel ALL=(ALL) ALL" 이 켜져 있다. 그룹에 넣기만 하면 된다.

-- wheel 은 sudo 만이 아니라 su 에도 쓰인다. pam_wheel 줄은 기본값으로 주석 처리돼 있다.
[root@ol7a ~]# grep -n wheel /etc/pam.d/su

 [정리] 관찰 요약
--------------------------------------------------------------------------------
--  항목                      시작 전      변경 후                        되돌린 뒤
--  /etc/sudoers.d            비어 있음    ops, logview                   비어 있음
--  /etc/sudoers md5          1b134d…      1b134d…                        1b134d…
--  user1 규칙 없음            -           not in the sudoers file        -
--  user1 stop chronyd         -           command not allowed            -
--  NOPASSWD ip addr show      -           암호 없이 실행                 -

--  cat /var/log/* → shadow    -           허용(rc=0)                     -
--  나열형 규칙 → shadow       -           not allowed(rc=1)              -
--  (student) id               -           -u student 만 허용             -
--  user2 + wheel              -           (ALL) ALL, shadow 30줄         삭제
-- 확인한 사실
--   sudoers 는 실행 때마다 읽는다. 재시작 없음
