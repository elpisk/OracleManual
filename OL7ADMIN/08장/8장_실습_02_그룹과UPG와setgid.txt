 제8장 실습 02 — 그룹, 사용자 전용 그룹(UPG), setgid 공유 디렉터리
 대상   : ol7a
 목표   : 보조 그룹을 붙이고 떼는 방법(usermod -aG, gpasswd), 그룹 변경이 이미 떠 있는
          세션에 반영되지 않는 이유, UPG 와 umask 002 의 관계, setgid 와 삭제 제한 비트로
          팀 공유 디렉터리를 만드는 과정을 확인한다
 배경   : 7.9 의 useradd 는 사용자마다 같은 이름의 그룹(UPG)을 만들어 기본 그룹으로 준다.
          /etc/bashrc 와 /etc/profile 은 "기본 그룹 이름 = 사용자 이름"이면 umask 를
          002 로 둔다. 혼자 쓰는 그룹이라 그룹 쓰기를 열어도 새는 곳이 없기 때문이다.
          여럿이 쓰는 디렉터리는 setgid 로 그룹을 물려주고, +t 로 남의 파일 삭제를
          막는다(본문 8.4)
 소요   : 약 30분
 선행   : ol7-base 스냅샷
 계정   : root, user1, user2, user3
 주의   : 없음
 되돌림 : 사용자 셋·그룹 둘·/srv/proj 삭제, group·gshadow 가 [0] 사본과 같음

--------------------------------------------------------------------------------
 [1] umask 를 정하는 곳 — /etc/bashrc
--------------------------------------------------------------------------------

-- umask 는 로그인 셸이 /etc/profile 과 /etc/bashrc 를 읽으며 정한다. 두 파일에 같은 조건문이 있다.
-- grep -n 으로 줄 번호와 함께, -A4 로 뒤 네 줄까지 본다.
[root@ol7a ~]# grep -n -A4 'id -gn' /etc/bashrc
70:    if [ $UID -gt 199 ] && [ "`/usr/bin/id -gn`" = "`/usr/bin/id -un`" ]; then
71-       umask 002
72-    else
73-       umask 022
74-    fi
-- 조건 두 개
--   $UID -gt 199          UID 가 199 보다 큼(시스템 계정 제외)
--   id -gn = id -un       기본 그룹 이름과 사용자 이름이 같음(UPG)
-- 둘 다 맞으면 umask 002, 아니면 022
[root@ol7a ~]# grep -n -A4 'id -gn' /etc/profile
59:if [ $UID -gt 199 ] && [ "`/usr/bin/id -gn`" = "`/usr/bin/id -un`" ]; then
60-    umask 002
61-else
62-    umask 022
63-fi
-- /etc/profile 의 59~63행도 같은 조건이다. 로그인 셸은 profile,
-- 비로그인 대화형 셸은 bashrc 를 거치므로 두 곳에 같은 코드가 있다

 [2] 사용자 셋과 UPG
--------------------------------------------------------------------------------

[root@ol7a ~]# for u in user1 user2 user3; do useradd $u; echo "$u:Ol7#Pass2026" | chpasswd; done; id user1; id user2; id user3
uid=1001(user1) gid=1001(user1) groups=1001(user1)
uid=1002(user2) gid=1002(user2) groups=1002(user2)
uid=1003(user3) gid=1003(user3) groups=1003(user3)
-- 1001~1003. 세 계정 모두 UID 와 같은 번호의 UPG 를 기본 그룹으로 받았다
-- 아직 보조 그룹은 없다(groups 에 자기 그룹 하나)

-- 그룹 파일에 새로 생긴 줄. 네 번째 필드(구성원 목록)가 비어 있는 것을 본다.
[root@ol7a ~]# diff /root/b08/group /etc/group
51a52,54
> user1:x:1001:
> user2:x:1002:
> user3:x:1003:
-- 51a52,54: 51번 줄 뒤에 세 줄. 넷째 필드(구성원)는 모두 비어 있다
-- 기본 그룹은 group 의 구성원 칸에 적히지 않는다

-- /etc/group 의 네 필드: 그룹 이름 : 암호 자리(x) : GID : 보조 구성원 목록
-- gshadow 는 그룹 암호와 그룹 관리자를 담는다: 이름 : 암호 : 관리자 : 구성원
[root@ol7a ~]# grep -E '^(wheel|user1):' /etc/group /etc/gshadow
/etc/group:wheel:x:10:student
/etc/group:user1:x:1001:
/etc/gshadow:wheel:::student
/etc/gshadow:user1:!::
-- wheel 은 group·gshadow 둘 다 구성원 칸에 student
-- gshadow 의 wheel 은 암호 칸이 비었고 user1 은 ! 다
--   ! 는 그룹 암호가 없다는 표시. newgrp 로 암호를 대고 들어갈 수 없다

--------------------------------------------------------------------------------
 [3] 팀 그룹 만들기 — groupadd
--------------------------------------------------------------------------------

-- -g 로 GID 를 정한다. 여러 서버에서 같은 그룹을 맞추려면 번호를 정해 두는 것이 낫다.
[root@ol7a ~]# groupadd -g 3000 devgrp; groupadd -g 3001 opsgrp; getent group devgrp opsgrp
devgrp:x:3000:
opsgrp:x:3001:
-- 3000·3001 을 지정했다.
-- GID_MIN(1000)~GID_MAX(60000) 범위 안
-- RAC 처럼 여러 서버가 파일을 나누는 곳은 GID 를 서버마다 같게 맞춘다
-- 번호를 정해 두지 않으면 서버마다 생성 순서에 따라 GID 가 달라진다
-- 지정하지 않았다면 가장 큰 GID + 1 인 1004 를 받았을 것이다

-- 이미 있는 GID 로 만들면 어떻게 되는지 함께 본다.
[root@ol7a ~]# groupadd -g 3000 testgrp; echo "exit=$?"
groupadd: GID '3000' already exists
exit=4
-- 'groupadd: GID '3000' already exists', exit=4
-- groupadd 도 useradd 처럼 번호 중복을 막는다. -o 로 강제할 수는 있다

--------------------------------------------------------------------------------
 [4] 보조 그룹 추가 — usermod -aG
--------------------------------------------------------------------------------

-- -G 보조 그룹 목록, -a(append) 는 기존 목록에 덧붙인다. -a 가 없으면 목록을 통째로 바꾼다.
[root@ol7a ~]# usermod -aG devgrp user1; usermod -aG devgrp,opsgrp user2; id user1; id user2
uid=1001(user1) gid=1001(user1) groups=1001(user1),3000(devgrp)
uid=1002(user2) gid=1002(user2) groups=1002(user2),3000(devgrp),3001(opsgrp)
-- user1 은 devgrp,
-- user2 는 devgrp·opsgrp 를 보조 그룹으로 얻었다
-- 쉼표로 여러 그룹을 한 번에 줄 수 있다
-- 쉼표 앞뒤에 공백을 넣으면 그룹 이름으로 읽지 못한다

-- 기본 그룹(gid)은 그대로 user1 이다. 보조 그룹은 /etc/group 의 넷째 필드에 이름이 들어간다.
[root@ol7a ~]# getent group devgrp opsgrp; diff /root/b08/gshadow /etc/gshadow
devgrp:x:3000:user1,user2
opsgrp:x:3001:user2
51a52,56
> user1:!::
> user2:!::
> user3:!::
> devgrp:!::user1,user2
> opsgrp:!::user2
-- getent 의 넷째 필드에 구성원 이름이 들어갔다(devgrp: user1,user2)
-- gshadow 에는 UPG 셋과 새 그룹 둘이 늘었다
-- gshadow 의 넷째 필드에도 같은 구성원이 적혔다. 두 파일을 같이 고친다

--------------------------------------------------------------------------------
 [5] 오류 ① — 그룹에 넣었는데 이미 열린 세션은 모른다
--------------------------------------------------------------------------------

-- 프로세스의 그룹 목록은 로그인할 때(su·sshd·login 이 initgroups 를 부를 때) 정해진다.
-- 실험: user3 으로 오래 도는 프로세스(긴 sleep)를 먼저 띄워 "열려 있는 세션" 역할을 시킨다.
[root@ol7a ~]# nohup su - user3 -c 'sleep 900' >/tmp/u3.log 2>&1 </dev/null &
-- 출력 없이 프롬프트만 돌아온다. 프로세스는 뒤에서 돈다
[root@ol7a ~]# sleep 2; pgrep -u user3 -l sleep
2341 sleep
-- PID 2341 이 user3 의 sleep. 이 프로세스가 "열려 있는 세션" 역할이다

-- 그 상태에서 user3 을 devgrp 에 넣는다.
[root@ol7a ~]# usermod -aG devgrp user3; id user3
uid=1003(user3) gid=1003(user3) groups=1003(user3),3000(devgrp)
-- id user3 은 /etc/group 을 읽어 답한다. devgrp 가 보인다

-- /proc/PID/status 의 Groups 줄이 그 프로세스가 실제로 가진 보조 그룹(숫자 GID)이다.
[root@ol7a ~]# grep -E '^(Uid|Gid|Groups)' /proc/$(pgrep -u user3 sleep)/status
Uid:    1003    1003    1003    1003
Gid:    1003    1003    1003    1003
Groups: 1003 
-- Uid·Gid 줄의 숫자 넷은 실제·유효·저장·파일시스템 ID
-- Groups 줄에는 1003 하나뿐. 3000(devgrp)이 없다
-- 증상   : id user3 은 groups=...,3000(devgrp) 인데 떠 있던 sleep(2341)의
--          /proc/2341/status 는 'Groups: 1003'
-- 원인   : 보조 그룹 목록은 로그인 때 initgroups 가 한 번 정하고 자식에게
--          물려준다. usermod 는 파일만 고쳤다
-- 조치   : 다시 로그인하거나(아래 새 su 세션), newgrp 로 새 셸을 띄운다
-- 재확인 : 새 세션의 /proc/self/status 에 'Groups: 1003 3000'

-- 새로 로그인한 세션은 3000 을 가진다.
[user3@ol7a ~]$ id; grep Groups /proc/self/status
uid=1003(user3) gid=1003(user3) groups=1003(user3),3000(devgrp) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
Groups: 1003 3000 
-- 새로 들어간 세션은 3000 을 가진다.
-- id 끝의 context= 는 SELinux 레이블 표시
-- id(인자 없음)는 현재 프로세스의 자격 정보를 답한다. id user3 과 다른 출처다
-- 오라클 리스너·인스턴스처럼 오래 도는 프로세스도 같은 이유로 재기동이 필요하다

--------------------------------------------------------------------------------
 [6] newgrp — 다시 로그인하지 않고 그룹 바꾸기
--------------------------------------------------------------------------------

-- newgrp 그룹이름 은 기본 그룹을 바꾼 새 셸을 띄운다. 여기서는 새 셸의 표준 입력으로 명령을 준다.
-- 구성원이면 암호를 묻지 않는다.
[user1@ol7a ~]$ echo 'id; umask; touch /tmp/ng_test; ls -l /tmp/ng_test' | newgrp devgrp
uid=1001(user1) gid=3000(devgrp) groups=3000(devgrp),1001(user1) context=unconfined_u:unconfined_r:unconfined_t:s0-s0:c0.c1023
0002
-rw-rw-r--. 1 user1 devgrp 0 Nov 16 10:48 /tmp/ng_test
-- 새 셸의 gid=3000(devgrp). 기본 그룹이 devgrp 로 바뀌었다
-- groups 목록 순서도 3000 이 앞, 1001 이 뒤
-- umask 는 0002 그대로다. 새 셸을 띄울 때 프로파일을 다시 읽지 않았다
-- 새 파일의 그룹이 devgrp 로 생겼다

-- 구성원이 아닌 그룹으로 바꾸려 하면 그룹 암호를 묻는다. 그룹 암호가 없으므로 실패한다.
[user1@ol7a ~]$ echo id | newgrp opsgrp; echo "exit=$?"
Password: newgrp: failed to crypt password with previous salt: Invalid argument
exit=1
-- 'Password:' 를 묻고 'failed to crypt password with previous salt' 로 끝났다
-- opsgrp 의 gshadow 암호 칸은 ! 라 맞출 암호 자체가 없다
-- 구성원이 아닌 그룹에는 newgrp 로 들어갈 수 없다는 뜻이 된다
[root@ol7a ~]# rm -f /tmp/ng_test

 [7] 오류 ② — usermod -G 에서 -a 를 빠뜨리면
--------------------------------------------------------------------------------

-- user2 는 devgrp·opsgrp 둘 다에 속한다. opsgrp 하나를 "추가"하려는 생각으로 -a 없이 친다.
[root@ol7a ~]# id user2; usermod -G opsgrp user2; id user2
uid=1002(user2) gid=1002(user2) groups=1002(user2),3000(devgrp),3001(opsgrp)
uid=1002(user2) gid=1002(user2) groups=1002(user2),3001(opsgrp)
-- 첫 줄(전): devgrp·opsgrp. 둘째 줄(후): opsgrp 만 남았다
[root@ol7a ~]# getent group devgrp opsgrp
devgrp:x:3000:user1,user3
opsgrp:x:3001:user2
-- devgrp 의 구성원에서 user2 가 빠졌다(user1,user3 만 남음)
-- 증상   : usermod -G opsgrp user2 뒤 id user2 가 groups=1002(user2),3001(opsgrp),
--          devgrp 구성원에서 user2 가 사라짐. 오류·경고 없음
-- 원인   : -G 는 보조 그룹 목록을 그 값으로 "바꾼다". -a 가 있어야 덧붙인다
-- 조치   : usermod -aG devgrp user2 또는 gpasswd -a user2 devgrp
-- 재확인 : id user2 에 3000(devgrp) 와 3001(opsgrp) 둘 다
--          ([변형] 에서 gpasswd -a 로 되돌려 넣는다)

--------------------------------------------------------------------------------
 [8] UPG 와 umask 002 — 새 파일의 권한
--------------------------------------------------------------------------------

-- user1(UPG) 이 만든 파일과 root 가 만든 파일을 비교한다.
[user1@ol7a ~]$ umask; touch ~/f_upg; mkdir ~/d_upg; ls -ld ~/f_upg ~/d_upg
0002
drwxrwxr-x. 2 user1 user1 6 Nov 16 10:48 /home/user1/d_upg
-rw-rw-r--. 1 user1 user1 0 Nov 16 10:48 /home/user1/f_upg
-- umask 002: 디렉터리 775(drwxrwxr-x),
-- 파일 664(-rw-rw-r--)
-- 파일에 실행 비트가 없는 것은 umask 가 아니라 touch 가 666 으로 만들기 때문
[root@ol7a ~]# touch /root/f_root; ls -l /root/f_root; rm -f /root/f_root
-rw-r--r--. 1 root root 0 Nov 16 10:48 /root/f_root
-- root 는 022 라 644. 그룹 쓰기가 없다

-- 기본 그룹이 UPG 가 아닌 사용자를 만든다. -N 은 UPG 를 만들지 않음, -g 는 기본 그룹 지정.
[root@ol7a ~]# useradd -N -g devgrp user4; id user4
uid=1004(user4) gid=3000(devgrp) groups=3000(devgrp)
-- user4 의 기본 그룹이 devgrp(3000). user4 라는 그룹은 생기지 않았다
[user4@ol7a ~]$ id -un; id -gn; umask; touch ~/f_nonupg; ls -l ~/f_nonupg
user4
devgrp
0022
-rw-r--r--. 1 user4 devgrp 0 Nov 16 10:48 /home/user4/f_nonupg
-- id -gn 이 devgrp 라 사용자 이름과 다르다 → umask 0022
-- 새 파일은 644. 기본 그룹을 여럿이 나눠 쓰므로 그룹 쓰기를 닫았다

--------------------------------------------------------------------------------
 [9] 공유 디렉터리 — setgid 없이 먼저
--------------------------------------------------------------------------------

-- 팀 디렉터리를 만들고 그룹을 devgrp, 권한을 770 으로 둔다. setgid 는 아직 없다.
[root@ol7a ~]# mkdir /srv/proj; chgrp devgrp /srv/proj; chmod 770 /srv/proj; ls -ld /srv/proj
drwxrwx---. 2 root devgrp 6 Nov 16 10:48 /srv/proj
-- 소유자 root, 그룹 devgrp, 770. 그룹 밖의 사용자는 들어오지 못한다

-- user1 이 파일을 만들면 그룹은 누구인가.
[user1@ol7a ~]$ echo v1 > /srv/proj/plan.txt; ls -l /srv/proj
total 4
-rw-rw-r--. 1 user1 user1 3 Nov 16 10:48 plan.txt
-- 그룹 칸이 user1. 만든 사람의 기본 그룹(UPG)을 따랐다

-- 같은 팀의 user3 이 이 파일을 고쳐 본다.
[user3@ol7a ~]$ id -Gn; echo v2 >> /srv/proj/plan.txt; echo "exit=$?"
user3 devgrp
/tmp/_ol7lab_user3.sh: line 1: /srv/proj/plan.txt: Permission denied
exit=1
-- user3 은 devgrp 구성원(id -Gn 에 devgrp)이지만 파일의 그룹은 user1
-- user3 에게는 기타(other) 권한 r-- 만 적용돼 쓰기가 거부됐다
-- 오류 줄 앞의 /tmp/_ol7lab_user3.sh: line 1: 은 실습 러너가 명령을
-- 스크립트 파일로 넘겨 실행해서 붙은 머리다. 터미널에서는 -bash: 로 보인다

--------------------------------------------------------------------------------
 [10] setgid 디렉터리 — 그룹을 물려준다
--------------------------------------------------------------------------------

-- g+s 를 디렉터리에 걸면 그 안에 새로 생기는 파일·디렉터리의 그룹이 디렉터리 그룹을 따른다.
-- 이미 있는 plan.txt 는 그대로다. 소급하지 않는다.
[root@ol7a ~]# chmod g+s /srv/proj; ls -ld /srv/proj; stat -c '%a %A' /srv/proj
drwxrws---. 2 root devgrp 22 Nov 16 10:48 /srv/proj
2770 drwxrws---
-- 그룹 실행 자리가 x 에서 s 로. 8진수로 2770(2 = setgid)
-- 디렉터리 크기 6 → 22. plan.txt 항목 하나가 들어 있다
[user1@ol7a ~]$ echo v1 > /srv/proj/plan2.txt; mkdir /srv/proj/sub; ls -l /srv/proj
total 8
-rw-rw-r--. 1 user1 devgrp 3 Nov 16 10:48 plan2.txt
-rw-rw-r--. 1 user1 user1  3 Nov 16 10:48 plan.txt
drwxrwsr-x. 2 user1 devgrp 6 Nov 16 10:48 sub
-- plan2.txt 와 sub 의 그룹이 devgrp. 디렉터리 그룹을 물려받았다
-- 하위 디렉터리 sub 도 drwxrwsr-x 로 s 를 물려받았다
-- 이전부터 있던 plan.txt 는 user1 그룹 그대로다. 소급하지 않는다
[user3@ol7a ~]$ echo v2 >> /srv/proj/plan2.txt; echo "exit=$?"; cat /srv/proj/plan2.txt
exit=0
v1
v2

-- 기존 파일은 chgrp 로 맞춘다. 파일 주인은 자기가 속한 그룹으로 chgrp 할 수 있다.
-- 같은 user3 이 이번에는 덧붙이기에 성공했다(exit=0, v1 다음 v2)
-- 그룹 devgrp + 권한 664(umask 002) 두 조건이 맞았다
[user1@ol7a ~]$ chgrp devgrp /srv/proj/plan.txt; ls -l /srv/proj/plan.txt
-rw-rw-r--. 1 user1 devgrp 3 Nov 16 10:48 /srv/proj/plan.txt
-- 파일 주인 user1 은 자신이 속한 devgrp 로 chgrp 할 수 있다

--------------------------------------------------------------------------------
 [11] 삭제 제한 비트(sticky) — 남의 파일을 지우지 못하게
--------------------------------------------------------------------------------

-- 디렉터리에 쓰기 권한이 있으면 파일 주인이 아니어도 그 파일을 지울 수 있다.
-- 삭제는 파일이 아니라 디렉터리를 고치는 일이기 때문이다.
[user3@ol7a ~]$ rm -f /srv/proj/plan.txt; echo "exit=$?"; ls /srv/proj
exit=0
plan2.txt
sub
-- user3 이 남의 파일 plan.txt 를 지웠다(exit=0).
-- 목록에 plan2.txt·sub 만 남았다
-- 지울 수 있었던 것은 /srv/proj 에 그룹 쓰기(w)가 있었기 때문이다

-- +t 를 건다. 그 뒤로는 파일 주인·디렉터리 주인·root 만 지울 수 있다.
[root@ol7a ~]# chmod +t /srv/proj; ls -ld /srv/proj; stat -c '%a %A' /srv/proj
drwxrws--T. 3 root devgrp 34 Nov 16 10:48 /srv/proj
3770 drwxrws--T
-- 기타 실행 자리에 T. 대문자는 기타에 x 가 없다는 뜻(소문자 t 는 x 도 있음)
-- 8진수 3770 = setgid(2) + 삭제 제한(1) + 770
[user3@ol7a ~]$ rm -f /srv/proj/plan2.txt; echo "exit=$?"
rm: cannot remove ‘/srv/proj/plan2.txt’: Operation not permitted
exit=1
-- 'rm: cannot remove ...
-- Operation not permitted', exit=1
-- user3 은 plan2.txt 에 쓸 수는 있지만(그룹 rw) 지울 수는 없다
-- 이름 바꾸기(mv)도 디렉터리를 고치는 일이라 같은 규칙으로 막힌다
-- 지울 수 있는 사람: 파일 주인 user1, 디렉터리 주인 root, root

-- 같은 장치가 이미 시스템에 있다. /tmp 가 1777 이다.
[root@ol7a ~]# stat -c '%a %A %n' /tmp /var/tmp /srv/proj
1777 drwxrwxrwt /tmp
1777 drwxrwxrwt /var/tmp
3770 drwxrws--T /srv/proj
-- /tmp·/var/tmp 는 1777, 끝자리가 소문자 t.
-- 누구나 쓰되 남의 파일은 못 지운다
-- 팀 디렉터리는 3770 으로 그룹만 열었다

--------------------------------------------------------------------------------
 [변형] gpasswd 로 구성원 관리와 그룹 관리자
--------------------------------------------------------------------------------

-- usermod -aG 는 사용자 쪽에서 붙이는 방법이다. gpasswd 는 그룹 쪽에서 붙이고 뗀다.
-- -a 사용자 추가, -d 사용자 제거. 다른 구성원은 건드리지 않는다.
[root@ol7a ~]# gpasswd -a user2 devgrp; gpasswd -d user1 devgrp; getent group devgrp
Adding user user2 to group devgrp
Removing user user1 from group devgrp
devgrp:x:3000:user3,user2
-- 메시지 두 줄이 동작을 그대로 말한다. user2 는 다시 들어오고 user1 은 빠졌다
-- [7] 에서 -G 로 잃었던 user2 의 devgrp 를 이렇게 되돌렸다
-- gpasswd 는 그룹 하나만 고치므로 user2 의 opsgrp 는 그대로다
-- 구성원 순서는 추가한 순서. user3 은 건드리지 않았다

-- -A 는 그룹 관리자 지정. 관리자는 root 가 아니어도 그 그룹의 구성원을 바꿀 수 있다.
[root@ol7a ~]# gpasswd -A user2 opsgrp; grep '^opsgrp:' /etc/gshadow
opsgrp:!:user2:user2
-- gshadow 네 필드: 이름 opsgrp,
-- 암호 !, 관리자 user2, 구성원 user2
[user2@ol7a ~]$ gpasswd -a user1 opsgrp; getent group opsgrp
Adding user user1 to group opsgrp
opsgrp:x:3001:user2,user1
-- user2(일반 사용자)가 root 없이 opsgrp 에 user1 을 넣었다

-- 관리자가 아닌 그룹은 바꿀 수 없다.
[user2@ol7a ~]$ gpasswd -a user1 devgrp; echo "exit=$?"
gpasswd: Permission denied.
exit=1
-- 'gpasswd: Permission denied.' devgrp 의 관리자는 아니다
-- 그룹 관리자는 자기 그룹에만 권한이 있다

--------------------------------------------------------------------------------
 되돌림
--------------------------------------------------------------------------------

[root@ol7a ~]# pkill -u user3 sleep; sleep 1; rm -rf /srv/proj /tmp/u3.log; for u in user1 user2 user3 user4; do userdel -r $u; done; groupdel devgrp; groupdel opsgrp
-- sleep 을 먼저 끝낸다. 프로세스가 있으면 userdel 이 거부한다(실습 06)
-- devgrp 는 user4 의 기본 그룹이라 user4 를 지운 뒤에야 groupdel 할 수 있다
[root@ol7a ~]# for f in passwd group gshadow; do diff /root/b08/$f /etc/$f >/dev/null && echo "$f 같음" || echo "$f 다름"; done; ls -la /srv; ls /home
passwd 같음
group 같음
gshadow 같음
total 4
drwxr-xr-x.  2 root root    6 Nov 16 10:48 .
dr-xr-xr-x. 17 root root 4096 Nov 11 19:49 ..
student
-- 세 파일 모두 [0] 사본과 같다.
-- /srv 는 다시 비었고 /home 은 student 만 남았다

 [정리] 관찰 요약
--------------------------------------------------------------------------------
--  항목                    시작 전        변경 후                       되돌린 뒤
--  group·gshadow 줄 수     51             56                            51 (diff 같음)
--  user3 의 열린 세션       -             Groups: 1003 (devgrp 없음)    -
--  user3 의 새 세션         -             Groups: 1003 3000             -
--  user2 보조 그룹          -             devgrp,opsgrp → -G 뒤 opsgrp  -
--  umask (UPG/비UPG/root)  0002/-/0022    user1 0002, user4 0022        -
--  /srv/proj               없음           770 → 2770 → 3770             없음
--  setgid 전 새 파일 그룹   -             user1 (user3 쓰기 거부)       -
--  setgid 뒤 새 파일 그룹   -             devgrp (user3 덧붙임 성공)    -
--  +t 뒤 남의 파일 삭제      -            Operation not permitted       -
--  opsgrp 관리자            -             user2 (devgrp 는 거부)        -
-- 확인한 사실(되돌린 뒤 passwd·group·gshadow 는 [0] 사본과 같음)
--   그룹 변경은 다음 로그인부터. 열린 프로세스는 옛 목록을 쓴다
--   -G 는 목록을 바꾼다. 한 그룹만 다룰 때는 -aG 나 gpasswd
--   newgrp 는 구성원이면 암호 없이, 아니면 그룹 암호가 있어야 들어간다
--   공유는 UPG(umask 002) + setgid + 필요하면 +t 가 함께 있어야 된다
