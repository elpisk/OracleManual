================================================================================
 제14장 실습 01 — NFS 서버와 클라이언트
 대상   : ol7a (NFS 서버), ol7b (NFS 클라이언트)
 목표   : ol7a 의 내보내기를 ol7b 에서 마운트하고 exportfs -v·nfsstat -m 을 읽는다.
          방화벽에서 열 서비스를 나눠 보고 fstab 으로 재부팅 뒤에도 붙인다
 배경   : NFS 서버는 /etc/exports 에 적은 디렉터리를 nfsd 가 커널 안에서 내보낸다.
          exports 파일은 exportfs 가 읽어 커널 내보내기 표(/var/lib/nfs/etab)로
          옮길 때만 반영된다. NFSv4 는 TCP 2049 하나로 통신하지만 showmount 와
          NFSv3 는 rpcbind(111)와 mountd 가 따로 필요하다 (본문 14.1~14.3)
 소요   : 약 40분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : root, student (ol7b 에서 쓰기 시험)
 주의   : ol7b 를 한 번 재부팅한다. ol7a 의 firewalld 영구 설정을 바꿨다가 되돌린다
 되돌림 : ol7b 의 마운트·fstab 줄 제거, ol7a 의 exports 비움·nfs-server 정지·방화벽 원복
          → findmnt -t nfs4 (빈 출력), firewall-cmd --list-services (ssh dhcpv6-client)
================================================================================

-- /srv/nfs 아래에 공유용 디렉터리를 둔다.
-- 소유자를 student 로 해 ol7b 의 student 가 쓸 수 있게 한다.
-- student 의 UID 는 두 노드 모두 1000 이다.
-- NFS 는 이름이 아니라 UID 숫자로 권한을 판단한다.
[root@ol7a ~]# id student
uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
[root@ol7b ~]# id student
uid=1000(student) gid=1000(student) groups=1000(student),10(wheel)
-- 두 노드의 student 가 1000 으로 같다.
-- 이 실습이 쓰기 시험에 student 를 쓰는 이유
[root@ol7a ~]# mkdir -p /srv/nfs/share; chown student:student /srv/nfs/share; chmod 755 /srv/nfs/share
[root@ol7a ~]# echo "hello from ol7a" > /srv/nfs/share/readme.txt; ls -ln /srv/nfs/share; df -hT /srv/nfs

 [2] /etc/exports 작성
--------------------------------------------------------------------------------
-- 한 줄 형식: 내보낼경로  클라이언트(옵션,옵션)  [클라이언트2(옵션)] ...
-- 클라이언트와 여는 괄호 사이에 공백이 없어야 한다(실습 02 에서 공백을 넣어 본다).
--   rw   : 읽기·쓰기 허용 (기본값은 ro)
--   sync : 디스크에 쓴 뒤에 응답 (기본값. 적지 않으면 exportfs 가 경고한다)
[root@ol7a ~]# echo '/srv/nfs/share  ol7b.example.com(rw,sync)' > /etc/exports; cat /etc/exports
-- 클라이언트를 이름으로 적었다.
-- ol7b 의 IP 를 /etc/hosts 로 역조회한 결과와 맞아야 한다
/srv/nfs/share  ol7b.example.com(rw,sync)

  Process: 2205 ExecStart=/usr/sbin/rpc.nfsd $RPCNFSDARGS (code=exited, status=0/SUCCESS)

 Main PID: 2205 (code=exited, status=0/SUCCESS)
   CGroup: /system.slice/nfs-server.service
-- 읽을 곳
--   Active         : active (exited). 시작 작업이 끝나고 커널 스레드만 남은 상태
--   ExecStartPre   : exportfs -r. 시작할 때 exports 를 읽는다
--   ExecStart      : rpc.nfsd. 커널에 스레드를 만들라고 시키고 끝난다
--   ExecStartPost  : gssproxy 가 떠 있으면 다시 읽힌다(Kerberos 용). 여기서는 해당 없음
--   Drop-In        : fstab 의 마운트와 순서를 맞추는 generator 설정
-- nfs-server 는 커널 nfsd 스레드를 띄우는 oneshot 유닛이라 "active (exited)" 로 남는다.
-- 함께 뜨는 서비스를 본다. rpcbind 는 소켓으로,
-- mountd·idmapd 는 의존성으로 올라온다.

active
active
active

[root@ol7a ~]# rpcinfo -p | awk '$3=="tcp" || NR==1'
-- awk 로 tcp 줄만 남겼다(udp 줄은 같은 프로그램이 한 번 더 나온다)

-- 열 해설
--   program : RPC 프로그램 번호   vers : 그 프로그램의 버전
--   proto   : tcp/udp             port : 등록된 포트
-- 이 실습에서 볼 줄
--   100000 portmapper 111   : rpcbind 자신
--   100005 mountd     20048 : v1·v2·v3 세 버전 (v3 마운트·showmount 용)
--   100003 nfs        2049  : vers 3·4. 4.1·4.2 는 4 안에 들어 있다
--   100227 nfs_acl    2049  : v3 의 ACL 보조 프로토콜

-- 실제로 듣고 있는 TCP 포트.
-- 2049(nfsd)는 커널이 열어서 프로세스 이름이 없다.
[root@ol7a ~]# ss -tlnp | grep -E ':(111|2049|20048) '

 [4] exportfs -v — 내보내기 표 읽기
--------------------------------------------------------------------------------
-- exportfs -v : 커널에 지금 걸린 내보내기 목록을 기본값까지 펼쳐 보여 준다.
-- exports 에는 rw,sync 두 개만 적었다. 나머지는 전부 기본값이다.
[root@ol7a ~]# exportfs -v
/srv/nfs/share  ol7b.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)
-- 적은 것: rw, sync. 나머지가 기본값
--   wdelay            : 쓰기를 잠시 모아 내림
--   hide              : 하위 파일 시스템을 따로 내보내야 보임
--   no_subtree_check  : 하위 트리 검사 생략
--   sec=sys           : UID·GID 숫자 인증
--   secure            : 클라이언트 포트 1024 미만만
--   root_squash       : 클라이언트 root → 65534
--   no_all_squash     : 일반 사용자는 그대로
-- exportfs 가 읽은 결과는 /var/lib/nfs/etab 에 저장된다.
-- 여기에는 생략 없이 모든 옵션이 적힌다.
[root@ol7a ~]# cat /var/lib/nfs/etab
/srv/nfs/share  ol7b.example.com(rw,sync,wdelay,hide,nocrossmnt,secure,root_squash,no_all_squash,no_subtree_check,secure_locks,acl,no_pnfs,anonuid=65534,anongid=65534,sec=sys,rw,secure,root_squash,no_all_squash)
-- etab 은 더 길다. nocrossmnt, secure_locks, acl, no_pnfs, anonuid=65534 등
-- 끝에 rw,secure,root_squash,no_all_squash 가 한 번 더 붙는 것은 출력 형식이다

 [5] 방화벽 때문에 막힌다 — 클라이언트에서 확인
--------------------------------------------------------------------------------
-- showmount -e 서버 : 서버의 mountd 에 내보내기 목록을 묻는다. rpcbind(111) → mountd 순서로 붙는다.
[root@ol7b ~]# showmount -e ol7a
clnt_create: RPC: Port mapper failure - Unable to receive: errno 113 (No route to host)
-- 증상   : showmount -e 가 "Port mapper failure ... errno 113 (No route to host)" 로 끝남
-- 111(rpcbind)에 닿지 못했다. 원인은 아래 마운트 결과와 함께 본다
-- 마운트도 시도한다.
-- 버전을 적지 않으면 7.9 클라이언트는 높은 버전부터 협상한다.
--   -v : mount.nfs 가 무엇을 시도하는지 보여 준다
--   timeout 40 : 멈춰 있으면 40초 뒤에 끊는다 (rc=124 가 나오면 시간 초과)
-- mount(2) 가 No route to host 를 7번 받고도 계속 재시도했다
-- 40초 뒤 timeout 이 끊어 rc=124. 그냥 두면 mount.nfs 는 2분(retry=2)을 채운다
-- ping 이 되는 상대에게서 No route to host 가 오면 상대 방화벽의 거부부터 의심한다
[root@ol7b ~]# mkdir -p /mnt/share
[root@ol7b ~]# time timeout 40 mount -v -t nfs ol7a:/srv/nfs/share /mnt/share; echo "rc=$?"

mount.nfs: mount(2): No route to host
mount.nfs: mount(2): No route to host

mount.nfs: mount(2): No route to host

 [6] nfs 서비스만 연다 — v4 는 되고 showmount 는 안 된다
--------------------------------------------------------------------------------
-- firewalld 의 nfs 서비스 정의에 무슨 포트가 들어 있는지 먼저 본다.
[root@ol7a ~]# for s in nfs mountd rpc-bind; do firewall-cmd --info-service=$s | grep -E '^[a-z]|  ports:'; done
nfs
  ports: 2049/tcp
mountd
  ports: 20048/tcp 20048/udp
rpc-bind
  ports: 111/tcp 111/udp
-- 서비스마다 포트
--   nfs      : 2049/tcp 하나
--   mountd   : 20048/tcp·udp ([3] 의 rpcinfo 와 같은 값)
--   rpc-bind : 111/tcp·udp
-- --permanent 는 디스크 설정만 바꾼다. --reload 로 런타임에 올린다.
[root@ol7a ~]# firewall-cmd --permanent --add-service=nfs; firewall-cmd --reload; firewall-cmd --list-services
success
success
dhcpv6-client nfs ssh
-- 조치   : nfs 서비스를 영구 설정에 넣고 reload. 런타임과 영구 둘 다 반영됐다
[root@ol7b ~]# time timeout 40 mount -t nfs ol7a:/srv/nfs/share /mnt/share; echo "rc=$?"

real    0m0.037s
user    0m0.000s
sys     0m0.004s
rc=0
-- 이번에는 0.037초 만에 rc=0. v4 는 2049 하나로 끝났다
[root@ol7b ~]# findmnt /mnt/share
TARGET     SOURCE              FSTYPE OPTIONS
/mnt/share ol7a:/srv/nfs/share nfs4   rw,relatime,vers=4.1,rsize=524288,wsize=524288,namlen=255,hard,proto=tcp,timeo=600,retrans=2,sec=sys,clientaddr=172.16.225.62,local_lock=none,addr=172.16.225.61
-- FSTYPE nfs4, vers=4.1. 옵션 없는 마운트가 4.1 로 협상됐다
[root@ol7b ~]# showmount -e ol7a
clnt_create: RPC: Port mapper failure - Unable to receive: errno 113 (No route to host)
-- showmount 는 여전히 실패. 111 이 아직 닫혀 있다
-- showmount 를 쓰려면 rpcbind 와 mountd 를 함께 연다.
[root@ol7a ~]# firewall-cmd --permanent --add-service=rpc-bind --add-service=mountd; firewall-cmd --reload; firewall-cmd --list-services
success
success
dhcpv6-client mountd nfs rpc-bind ssh
[root@ol7b ~]# showmount -e ol7a

/srv/nfs/share ol7b.example.com

[root@ol7b ~]# showmount -a ol7a

 [7] 클라이언트에서 마운트 상태 읽기
--------------------------------------------------------------------------------
[root@ol7b ~]# findmnt -t nfs4 -o TARGET,SOURCE,FSTYPE,OPTIONS
TARGET     SOURCE              FSTYPE OPTIONS
/mnt/share ol7a:/srv/nfs/share nfs4   rw,relatime,vers=4.1,rsize=524288,wsize=524288,namlen=255,hard,proto=tcp,timeo=600,retrans=2,sec=sys,clientaddr=172.16.225.62,local_lock=none,addr=172.16.225.61
[root@ol7b ~]# nfsstat -m
/mnt/share from ol7a:/srv/nfs/share
 Flags: rw,relatime,vers=4.1,rsize=524288,wsize=524288,namlen=255,hard,proto=tcp,timeo=600,retrans=2,sec=sys,clientaddr=172.16.225.62,local_lock=none,addr=172.16.225.61
-- Flags 필드
--   rw, relatime     : 일반 마운트 옵션
--   vers=4.1         : 협상된 버전
--   rsize/wsize      : 524288(512KiB). 서버 최대값으로 협상됐다
--   namlen=255       : 파일 이름 최대 길이
--   hard             : 서버 무응답 시 끝없이 재시도
--   proto=tcp        : 전송 프로토콜
--   timeo=600        : 60초(단위 0.1초)
--   retrans=2        : 주요 시간 초과까지 재시도 횟수
--   sec=sys          : 인증
--   clientaddr       : v4 에서 클라이언트가 알린 자기 주소
--   local_lock=none  : 잠금을 서버에 맡긴다
--   addr             : 서버 주소
[root@ol7b ~]# df -hT /mnt/share

[root@ol7a ~]# mkdir -p /srv/nfs/data; echo "data dir" > /srv/nfs/data/info.txt

[root@ol7a ~]# exportfs -v
/srv/nfs/share  ol7b.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)

-- exportfs -r : exports 와 exports.d 를 다시 읽어 커널 표를 맞춘다(없어진 항목은 빼고 새 항목은 넣는다).
-- exportfs -a 는 추가만 한다. 지운 항목까지 반영하려면 -r 을 쓴다.
[root@ol7a ~]# exportfs -rv
exporting ol7b.example.com:/srv/nfs/data
exporting ol7b.example.com:/srv/nfs/share

[root@ol7a ~]# exportfs -v
/srv/nfs/share  ol7b.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)

[root@ol7b ~]# showmount -e ol7a
Export list for ol7a:
/srv/nfs/data  ol7b.example.com
/srv/nfs/share ol7b.example.com
-- 재확인 : showmount -e 에 두 경로가 모두 보인다
[root@ol7b ~]# mount -t nfs ol7a:/srv/nfs/data /mnt/data; ls -l /mnt/data; touch /mnt/data/x; echo "rc=$?"
total 4
-rw-r--r--. 1 root root 9 Nov 16 10:14 info.txt
touch: cannot touch ‘/mnt/data/x’: Read-only file system
