================================================================================
 제14장 실습 04 — vsftpd 구성
 대상   : ol7a (FTP 서버), ol7b (FTP 클라이언트)
 목표   : vsftpd 를 설치하고 vsftpd.conf 의 익명·로컬 사용자·chroot 지시어를 바꿔
          가며 ol7b 의 ftp·curl 로 접속해 결과를 본다. 21번 포트만 열었을 때
          수동 모드 데이터 연결이 막히는 이유와, chroot 된 홈에 쓰기 권한이 있어
          로그인이 거부되는 오류를 재현한다
 배경   : FTP 는 제어 연결(21)과 데이터 연결을 따로 쓴다. 수동(passive) 모드에서는
          서버가 임의의 높은 포트를 열고 클라이언트가 그리로 붙는다. firewalld 의 ftp
          서비스는 21 과 함께 conntrack 의 FTP 도우미를 걸어 그 포트를 자동으로
          허용한다. vsftpd 는 chroot 한 루트 디렉터리에 쓰기 권한이 있으면 보안상
          로그인을 거부한다 (본문 14.5)
 소요   : 약 35분
 선행   : ol7-base, ol7b-base 스냅샷
 계정   : root, ftpuser1 (실습 중 만들고 지움)
 주의   : FTP 는 비밀번호를 평문으로 보낸다. 실습 망 밖에서 쓰지 않는다
 되돌림 : vsftpd 정지·비활성, vsftpd.conf 원본 복원, ftpuser1 삭제, 방화벽 원복
          → systemctl is-active vsftpd, md5sum vsftpd.conf, firewall-cmd --list-services

-- 주석과 빈 줄을 뺀 지시어만 본다.
-- 형식은 지시어=값, = 앞뒤에 공백을 넣으면 안 된다.
[root@ol7a ~]# grep -vE '^\s*(#|$)' /etc/vsftpd/vsftpd.conf
anonymous_enable=YES
local_enable=YES
write_enable=YES
local_umask=022
dirmessage_enable=YES
xferlog_enable=YES
connect_from_port_20=YES
xferlog_std_format=YES
listen=NO
listen_ipv6=YES
pam_service_name=vsftpd
userlist_enable=YES
tcp_wrappers=YES
-- 지시어 13개가 살아 있다. 이 실습에서 볼 것
--   anonymous_enable=YES  : 익명 로그인 허용(7.9 기본)
--   local_enable=YES      : 시스템 계정 로그인
--   write_enable=YES      : 올리기·삭제 같은 쓰기 명령 허용
--   local_umask=022       : 올린 파일 권한 644
--   xferlog_*             : 전송 기록
--   listen=NO, listen_ipv6=YES : IPv6 소켓 하나로 IPv4 도 받음
--   userlist_enable=YES   : user_list 에 있는 사용자 거부
--   tcp_wrappers=YES      : /etc/hosts.allow·deny 도 본다([OL8/9] TCP Wrappers 는 8 에서 빠졌다)
-- [OL8/9] OL8 의 기본 파일은 anonymous_enable=NO 다
-- 로그인을 막는 두 파일. ftpusers 는 PAM 이, user_list 는 vsftpd 가 읽는다.
[root@ol7a ~]# grep -v '^#' /etc/vsftpd/ftpusers | tr '\n' ' '; echo; grep -v '^#' /etc/vsftpd/user_list | tr '\n' ' '; echo
root bin daemon adm lp sync shutdown halt mail news uucp operator games nobody 
root bin daemon adm lp sync shutdown halt mail news uucp operator games nobody 
-- 두 파일의 내용이 같다. 시스템 계정 14개
-- 로그인 셸이 있는 root 를 막는 것이 핵심 목적이다.
-- 나머지는 원래 로그인하지 않는 계정이다
[root@ol7a ~]# grep -E 'pam_listfile|pam_shells' /etc/pam.d/vsftpd
auth       required     pam_listfile.so item=user sense=deny file=/etc/vsftpd/ftpusers onerr=succeed
auth       required     pam_shells.so
-- pam_listfile : ftpusers 에 있으면 거부(sense=deny)
-- pam_shells   : /etc/shells 에 있는 셸을 가진 계정만 허용

--------------------------------------------------------------------------------
 [4] 21번 포트만 열었을 때
--------------------------------------------------------------------------------
-- 서비스 정의 대신 포트만 연다. 실무에서 흔히 하는 방식이다.
[root@ol7a ~]# firewall-cmd -q --add-port=21/tcp; firewall-cmd --list-ports
21/tcp
-- 서비스 정의가 아니라 포트 하나만 런타임에 열었다
-- --permanent 를 주지 않아 reload 하면 사라진다
-- ftp 클라이언트를 스크립트로 몬다.
--   -i : mget 등에서 묻지 않음   -n : 자동 로그인 끔(user 명령으로 직접)
--   -v : 서버 응답 코드를 보임    -p : 수동(passive) 모드
[root@ol7b ~]# printf 'user anonymous x@\nls\nquit\n' | timeout 40 ftp -invp ol7a; echo "rc=$?"
Connected to ol7a (172.16.225.61).
220 (vsFTPd 3.0.2)
331 Please specify the password.
230 Login successful.
227 Entering Passive Mode (172,16,225,61,185,182).
-- 227 의 여섯 숫자: IP 172.16.225.61, 포트 185*256+182 = 47542
-- 응답 코드 읽기(첫 자리로 성격을 안다)
--   220 : 서비스 준비. 괄호 안이 서버 이름과 버전(vsFTPd 3.0.2)
--   331 : 사용자 이름을 받았고 비밀번호를 기다림
--   230 : 로그인 성공
--   227 : 수동 모드 진입. 데이터 연결 주소를 알려 줌
--   150 : 데이터 연결을 연다 / 226 : 전송 끝 / 221 : 연결 종료
--   2xx 성공, 3xx 추가 입력 필요, 4xx 일시 오류, 5xx 영구 오류
ftp: connect: No route to host
-- 증상   : 로그인(230)까지는 되고 ls 의 데이터 연결이 "ftp: connect: No route to host"
-- rc=0 은 ftp 프로그램이 정상 종료했다는 뜻일 뿐이다
221 Goodbye.
rc=0
-- 제어 연결(로그인)은 됐는데 목록이 오지 않았다.
-- 227 응답의 숫자 여섯 개가 데이터 연결 주소다.
-- 마지막 두 숫자 p1,p2 로 포트를 계산한다: p1*256+p2.
-- 그 포트는 방화벽에 열려 있지 않다.
-- curl 로도 본다. curl 은 EPSV(확장 수동 모드)를 먼저 쓴다.
[root@ol7b ~]# timeout 40 curl -sS --connect-timeout 10 ftp://ol7a/pub/; echo "rc=$?"
curl: (7) Failed connect to ol7a:21; No route to host
rc=7
-- curl 도 실패. 메시지에 ol7a:21 이라고 나오지만 21 은 열려 있다
-- curl 7.29 는 데이터 연결 실패도 이렇게 적는다.
-- 앞의 ftp 결과와 함께 읽는다
-- 원인   : 수동 모드 데이터 포트(47542 같은 높은 포트)가 방화벽에 없다

--------------------------------------------------------------------------------
 [7] chroot_local_user — 쓰기 가능한 홈은 거부된다
--------------------------------------------------------------------------------
-- 로컬 사용자를 홈 안에 가둔다. 주석 처리된 줄을 살린다.
[root@ol7a ~]# sed -i 's/^#chroot_local_user=YES/chroot_local_user=YES/' /etc/vsftpd/vsftpd.conf; diff /root/vsftpd.conf.orig /etc/vsftpd/vsftpd.conf
101c101
< #chroot_local_user=YES
---
> chroot_local_user=YES
-- 101번째 줄의 주석만 풀었다
-- diff 의 101c101 : 101번째 줄이 바뀌었다(c=change)
-- vsftpd 는 설정을 시작할 때 한 번 읽는다. 재시작해야 반영된다.
[root@ol7a ~]# systemctl restart vsftpd
[root@ol7b ~]# printf 'user ftpuser1 Ftp#2026\npwd\nls\nquit\n' | timeout 40 ftp -invp ol7a
Connected to ol7a (172.16.225.61).
220 (vsFTPd 3.0.2)
331 Please specify the password.
500 OOPS: chroot
Login failed.
421 Service not available, remote server has closed connection
Not connected.
-- 증상   : 비밀번호 다음에 "500 OOPS: chroot", 연결이 끊긴다
-- 예상한 "writable root" 메시지가 아니다. chroot 자체가 실패했다
-- 원인을 좁힌다. 홈 퍼미션, SELinux 거부 기록,
-- ftp 관련 SELinux 불리언을 함께 본다.
[root@ol7a ~]# ls -ldZ /home/ftpuser1; ausearch -m avc -ts recent 2>&1 | grep -c 'denied'; getsebool ftpd_full_access ftp_home_dir 2>&1

-- curl 은 스크립트에 쓰기 좋다.
-- -u 사용자:비밀번호, -T 올리기, -l 이름만 나열.
[root@ol7b ~]# curl -sS -u 'ftpuser1:Ftp#2026' -l ftp://ol7a/
hello.txt
up.txt
-- -l 은 이름만(NLST). chroot 상태라 홈 안의 두 파일만 보인다
[root@ol7b ~]# curl -sS -u 'ftpuser1:Ftp#2026' -T /etc/os-release ftp://ol7a/os.txt; curl -sS -u 'ftpuser1:Ftp#2026' ftp://ol7a/os.txt | head -2
NAME="Oracle Linux Server"
VERSION="7.9"
-- -T 로 os.txt 를 올리고 다시 받아 앞 두 줄을 보였다
-- -v 로 제어 연결의 대화를 본다. EPSV 응답의 (|||포트|) 가 데이터 포트다.
[root@ol7b ~]# curl -sv -u 'ftpuser1:Ftp#2026' -l ftp://ol7a/ 2>&1 | grep -E '^[<>] (USER|PASS|PWD|EPSV|LIST|NLST|2|3|5)' | head -14
< 220 (vsFTPd 3.0.2)
> USER ftpuser1
< 331 Please specify the password.
> PASS Ftp#2026
< 230 Login successful.
> PWD
< 257 "/"
> EPSV
< 229 Entering Extended Passive Mode (|||30002|).
< 200 Switching to ASCII mode.
> NLST
< 226 Directory send OK.
-- 대화 순서: 220 인사 → USER → 331 → PASS → 230 → PWD → EPSV → 229 → NLST → 226
-- > 는 클라이언트가 보낸 명령, < 는 서버 응답
-- 200 Switching to ASCII mode 는 TYPE A 명령의 응답이다(grep 범위 밖이라 명령 줄은 안 보임)
-- PASS Ftp#2026 이 평문으로 지나간다
-- 망 중간에서 패킷을 보는 누구나 이 비밀번호를 읽을 수 있다
-- EPSV 응답 (|||30002|) 는 포트만 알려 준다. 30002 는 pasv 범위 안이다
[root@ol7b ~]# curl -sS ftp://ol7a/; echo "rc=$?"
curl: (67) Access denied: 530
rc=67
