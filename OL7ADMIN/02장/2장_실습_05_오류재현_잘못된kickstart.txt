================================================================================
 제2장 실습 05 — 오류 재현: 잘못된 kickstart
 대상   : ol7a (kickstart 작성·검증, 설치 ISO 를 저장소로 사용)
 목표   : 지시어 오타, %end 누락, 잘못된 옵션, 존재하지 않는 패키지, 없는 %include,
          중복·충돌 지시어가 각각 어느 시점(ksvalidator 검사, 설치 프로그램의 패키지
          검사, 설치 프로그램 기동)에 드러나는지 비교하고, ksvalidator 의 종료 코드를
          믿을 수 있는지 확인한다
 배경   : ksvalidator 는 pykickstart 파서로 문법만 본다. 패키지 이름이 저장소에
          있는지, 디스크가 있는지는 모른다. 그런 오류는 설치 프로그램이 저장소와
          장치를 실제로 열어 본 뒤에야 드러난다. OL7 의 Anaconda 는 %packages 를
          yum 으로 풀기 때문에, 설치 루트를 빈 디렉터리로 준 yum 으로 그 단계를
          미리 흉내 낼 수 있다(본문 2.5·2.7절)
 소요   : 약 30분
 선행   : ol7a 를 ol7-base 스냅샷으로 되돌림. sr0 에 설치 ISO 연결
 계정   : root
 주의   : 실제 재설치는 하지 않는다(ol7b 를 지우지 않으려고). 설치 프로그램 화면은
          랩 구축 때(2026-11-11 20:03~20:05) 찍은 기록을 [12] 에 옮긴다
 되돌림 : /root 에 ks-ol7b.cfg 만 남고, findmnt /mnt 가 빈 출력(rc=1)

--------------------------------------------------------------------------------
 [2] 오류 파일 네 개 만들기
--------------------------------------------------------------------------------

-- 한 파일에 오류 하나씩. 무엇을 바꿨는지 diff 로 남긴다.
-- 네 sed 는 모두 원본을 고치지 않고(-i 없음) > 로 새 파일을 만든다.
--   typo   : 줄 첫머리 timezone 을 timezonee 로
--   noend  : %packages~%end 범위에서 %end 줄만 지움
--   badopt : --bootproto 를 --bootprot 으로(끝 글자 o 하나 빠짐)
--   nopkg  : kexec-tools 줄 뒤에 없는 패키지 이름 한 줄 추가(a 명령)

[root@ol7a ~]# sed 's/^timezone/timezonee/' /root/ks-ol7b.cfg > /root/ks-typo.cfg
[root@ol7a ~]# sed '/^%packages/,/^%end/{/^%end/d}' /root/ks-ol7b.cfg > /root/ks-noend.cfg
[root@ol7a ~]# sed 's/--bootproto=static/--bootprot=static/' /root/ks-ol7b.cfg > /root/ks-badopt.cfg
[root@ol7a ~]# sed '/^kexec-tools$/a oracle-nonexistent-pkg' /root/ks-ol7b.cfg > /root/ks-nopkg.cfg
[root@ol7a ~]# for f in typo noend badopt nopkg; do echo "== ks-$f.cfg"; diff /root/ks-ol7b.cfg /root/ks-$f.cfg; done
== ks-typo.cfg
27c27
< timezone Asia/Seoul --isUtc --nontp
---
> timezonee Asia/Seoul --isUtc --nontp
== ks-noend.cfg
46d45
< %end
== ks-badopt.cfg
17c17
< network  --bootproto=static --device=ens32 --gateway=172.16.225.2 --ip=172.16.225.62 --nameserver=172.16.225.2 --netmask=255.255.255.0 --ipv6=auto --activate
---
> network  --bootprot=static --device=ens32 --gateway=172.16.225.2 --ip=172.16.225.62 --nameserver=172.16.225.2 --netmask=255.255.255.0 --ipv6=auto --activate
== ks-nopkg.cfg
44a45
> oracle-nonexistent-pkg
-- diff 읽는 법: "27c27" 은 27번 줄이 바뀜(c), "46d45" 는 46번 줄이 지워짐(d),
-- "44a45" 는 44번 줄 뒤에 추가(a). < 는 기준 파일, > 는 오류 파일 쪽 줄이다.
-- noend 의 46번 줄은 %packages 를 닫는 %end 다. 뒤의 %addon·%anaconda 의 %end 는 그대로다.

 [3] 지시어 오타 — timezonee
--------------------------------------------------------------------------------

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-typo.cfg; echo "rc=$?"
The following problem occurred on line 27 of the kickstart file:

Unknown command: timezonee

rc=0
-- 증상   : "Unknown command: timezonee" 를 찍었는데 rc=0. 스크립트가 $? 만 보면 정상으로 넘어간다
-- 원인   : ksvalidator 는 파싱 경고를 출력만 하고 종료 코드에 반영하지 않는다(pykickstart 1.99)
-- 조치   : 판정을 "출력이 비어 있는가" 로 바꾼다([9] 의 두 번째 for 문)
-- 재확인 : [9] 에서 ks-typo.cfg 가 NG, 정상 파일 ks-ol7b.cfg 가 OK 로 갈린다
-- 설치 프로그램은 같은 줄에서 kickstart 파싱을 멈춘다. 검사에서 메시지가 나왔다면 설치도 안 된다.
-- 메시지 형식: "The following problem occurred on line N of the kickstart file:" 다음 빈 줄,
-- 그다음 원인 한 줄. N 은 원본 파일의 줄 번호라 sed -n 'Np' 로 바로 찾아갈 수 있다.

--------------------------------------------------------------------------------

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-noend.cfg; echo "rc=$?"

 [5] 잘못된 옵션 — --bootprot
--------------------------------------------------------------------------------

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-badopt.cfg; echo "rc=$?"
rc=0
-- 출력 없음, rc=0. --bootprot 은 오타인데 통과했다.
-- 오류가 나오지 않았다. 옵션 이름을 앞부분만 맞게 줄인 것과, 앞부분부터 틀린 것을 비교한다.
[root@ol7a ~]# sed 's/--bootproto=static/--bootprt=static/' /root/ks-ol7b.cfg > /root/ks-badopt2.cfg; diff /root/ks-badopt.cfg /root/ks-badopt2.cfg
17c17
< network  --bootprot=static --device=ens32 --gateway=172.16.225.2 --ip=172.16.225.62 --nameserver=172.16.225.2 --netmask=255.255.255.0 --ipv6=auto --activate
---
> network  --bootprt=static --device=ens32 --gateway=172.16.225.2 --ip=172.16.225.62 --nameserver=172.16.225.2 --netmask=255.255.255.0 --ipv6=auto --activate
-- badopt 는 --bootproto 의 앞부분, badopt2 는 중간 글자가 틀린 이름이다.

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-badopt2.cfg; echo "rc=$?"
The following problem occurred on line 17 of the kickstart file:

no such option: --bootprt

rc=0
-- --bootprt 는 "no such option" 이 나왔다(역시 rc=0). --bootprot 은 아무 말이 없었다.
-- pykickstart 의 옵션 파서(optparse)는 긴 옵션을 앞부분만 적어도 하나로 정해지면 받아들인다.
-- --bootprot 은 --bootproto 하나로만 풀리므로 정상으로 처리됐다.
-- --boot 처럼 여러 옵션의 앞부분이 되는 줄임말은?
[root@ol7a ~]# sed 's/--bootproto=static/--boot=static/' /root/ks-ol7b.cfg > /root/ks-badopt3.cfg; ksvalidator -v RHEL7 /root/ks-badopt3.cfg; echo "rc=$?"
rc=0
-- --boot 도 아무 말 없이 통과했다. network 에서 --boot 로 시작하는 옵션이 --bootproto
-- 하나뿐이기 때문이다. 줄임말이 통과한다고 써도 된다는 뜻은 아니다. 문법 버전이 바뀌어
-- 같은 앞부분을 가진 옵션이 생기면 그때부터 "ambiguous option" 이 된다.

--------------------------------------------------------------------------------
 [7] 패키지 이름은 저장소에 물어본다 — 설치 ISO 로 대조
--------------------------------------------------------------------------------

-- 설치 ISO 를 마운트해 임시 저장소로 쓴다. 먼저 저장소 파일 없이 경로만 넘겨 본다.
-- (출력이 길어 앞 세 줄만 본다)
[root@ol7a ~]# mount -o ro /dev/sr0 /mnt; yum -q --disablerepo='*' --repofrompath=iso,file:///mnt --enablerepo=iso list available oracle-nonexistent-pkg 2>&1 | head -3; echo "rc=${PIPESTATUS[0]}"
Command line error: no such option: --repofrompath
Usage: yum [options] COMMAND

rc=1
-- 증상   : "Command line error: no such option: --repofrompath", rc=1
-- 원인   : OL7 의 yum(3.4.3)에는 이 옵션이 없다. repoquery 등 yum-utils 도구에만 있다
-- 조치   : enabled=0 인 저장소 파일을 만들고 --enablerepo 로 그 저장소만 켠다(다음 명령)
-- 재확인 : 다음 yum list 가 "iso" 저장소의 패키지를 보여 준다
-- [OL8/9] dnf 에는 --repofrompath 가 있다. 8/9 문서의 예를 7 에 그대로 쓰면 이 오류가 난다.
-- 저장소 파일을 하나 만든다. enabled=0 이라 평소에는 쓰이지 않고 --enablerepo=iso 로만 켠다.
[root@ol7a ~]# printf '[iso]\nname=OL79 ISO\nbaseurl=file:///mnt\ngpgcheck=0\nenabled=0\n' > /etc/yum.repos.d/iso.repo; cat /etc/yum.repos.d/iso.repo
[iso]
name=OL79 ISO
baseurl=file:///mnt
gpgcheck=0
enabled=0
-- gpgcheck=0 은 랩 편의다. 운영에서는 gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-oracle 과
-- gpgcheck=1 로 서명을 확인한다(2.6.3).
-- isomd5sum 은 ISO 에 있지만 설치되지 않은 패키지(실습 01), 다른 하나는 없는 이름.
[root@ol7a ~]# yum -q --disablerepo='*' --enablerepo=iso list available isomd5sum oracle-nonexistent-pkg; echo "rc=$?"
Available Packages
isomd5sum.x86_64                       1:1.0.10-5.el7                        iso
rc=0
-- 이름 둘을 함께 물었는데 isomd5sum 만 나오고 rc=0 이다. 없는 이름은 조용히 빠졌다.
-- 열: 패키지.아키텍처, 버전(1: 은 epoch), 저장소 이름 iso.
-- -q 는 "Loaded plugins" 같은 머리 줄을 숨긴다. 표의 머리 "Available Packages" 는 남는다.

[root@ol7a ~]# yum -q --disablerepo='*' --enablerepo=iso list available oracle-nonexistent-pkg; echo "rc=$?"
Error: No matching Packages to list
rc=1
-- 없는 이름만 물으면 "Error: No matching Packages to list", rc=1. 이름은 하나씩 확인한다.

--------------------------------------------------------------------------------
 [8] 설치 프로그램처럼 패키지 목록을 풀어 보기 — 설치 루트에 대한 yum
--------------------------------------------------------------------------------

-- OL7 의 Anaconda 는 %packages 를 yum 으로 푼다. 빈 디렉터리를 설치 루트로 삼아
-- 같은 저장소(ISO)에 같은 패키지 이름을 넘기면, 설치 프로그램이 의존성 검사 단계에서
-- 받는 답을 미리 볼 수 있다. --assumeno 라 아무것도 설치하지 않는다.
--   --installroot          설치 대상 루트. 설치 프로그램의 /mnt/sysimage 에 해당
--   --releasever=7         빈 루트에는 release 패키지가 없어 버전을 직접 준다
--   --setopt=skip_missing_names_on_install=False   없는 이름을 건너뛰지 말고 실패
[root@ol7a ~]# mkdir -p /tmp/instroot
-- /tmp/instroot 는 빈 디렉터리다. yum 은 여기에 rpm DB 가 없으니 "아무것도 설치되지 않은
-- 새 시스템" 으로 본다. 설치 프로그램이 디스크를 포맷한 직후의 상태와 같다.
-- --assumeno 는 "Is this ok [y/N]" 질문에 자동으로 N 을 답한다. 계산만 하고 아무것도 받지 않는다.

[root@ol7a ~]# yum -q --installroot=/tmp/instroot --releasever=7 --disablerepo='*' --enablerepo=iso install --assumeno oracle-nonexistent-pkg; echo "rc=$?"
Error: Nothing to do
rc=1
-- "Error: Nothing to do", rc=1. yum 의 기본값 skip_missing_names_on_install=True 라
-- 없는 이름을 건너뛰고 나니 할 일이 없다는 뜻이다. 이름이 없다는 말은 하지 않는다.

[root@ol7a ~]# yum -q --installroot=/tmp/instroot --releasever=7 --disablerepo='*' --enablerepo=iso --setopt=skip_missing_names_on_install=False install --assumeno oracle-nonexistent-pkg kexec-tools 2>&1 | tail -5; echo "rc=${PIPESTATUS[0]}"
Error: Not tolerating missing names on install, stopping.
rc=1
-- 증상   : "Error: Not tolerating missing names on install, stopping.", rc=1
-- 원인   : 없는 이름을 건너뛰지 말라고 했으므로 kexec-tools 까지 포함한 요청 전체를 멈췄다
-- 조치   : %packages 에서 이름을 고치거나 지운다. 일부러 넘기려면 [변형] 의 --ignoremissing
-- 재확인 : kexec-tools 만 넘기면 아래처럼 설치 목록이 만들어진다
-- 설치 프로그램은 kickstart 설치에서 이 지점에 해당하는 검사로 멈추고 계속할지 묻는다(INS 3장).
-- 이 랩에서는 ol7b 를 지우지 않으려고 실제 재설치는 하지 않았다.
-- 이름이 맞는 패키지는 의존성까지 풀려 설치 목록이 나온다. 요약 줄만 본다.
[root@ol7a ~]# yum --installroot=/tmp/instroot --releasever=7 --disablerepo='*' --enablerepo=iso install --assumeno kexec-tools 2>&1 | grep -E '^(Install|Transaction Summary|Error)' | head -5
Installing:
Installing for dependencies:
Transaction Summary
Install  1 Package (+133 Dependent packages)
Installed size: 307 M
-- 빈 루트에 kexec-tools 하나를 넣으려면 의존 패키지 133개가 함께 필요하다. 설치 프로그램이
-- %packages 를 풀 때도 같은 계산을 한다. 실제 설치(560개)는 @core·@base 그룹이 더해진 결과다.
-- Installing 은 요청한 패키지, Installing for dependencies 는 끌려온 패키지다.
-- Installed size 307 M 은 설치 후 차지할 디스크 크기다. 설치 프로그램도 이 값으로 공간을 점검한다.

--------------------------------------------------------------------------------
 [9] ksvalidator 의 종료 코드를 믿을 수 있는가
--------------------------------------------------------------------------------

-- [3]~[6] 의 rc 를 한 화면에 모은다. 출력이 있었는지(줄 수)와 rc 를 나란히 본다.
-- 같은 파일을 두 번 검사한다. 첫 번째는 출력 줄 수(grep -c .), 두 번째는 종료 코드($?).
-- printf 의 %-16s 는 16칸 왼쪽 정렬이다.

[root@ol7a ~]# for f in ol7b typo noend badopt nopkg; do n=$(ksvalidator -v RHEL7 /root/ks-$f.cfg 2>&1 | grep -c .); ksvalidator -v RHEL7 /root/ks-$f.cfg >/dev/null 2>&1; printf '%-16s lines=%-3s rc=%s\n' ks-$f.cfg $n $?; done
ks-ol7b.cfg      lines=0   rc=0
ks-typo.cfg      lines=2   rc=0
ks-noend.cfg     lines=2   rc=1
ks-badopt.cfg    lines=0   rc=0
ks-nopkg.cfg     lines=0   rc=0
-- lines 는 ksvalidator 출력 중 빈 줄이 아닌 줄 수다. typo 와 noend 는 둘 다 2줄을 찍었는데
-- rc 는 0 과 1 로 다르다. badopt·nopkg 는 출력도 rc 도 정상과 같아 어떤 방법으로도 걸러지지 않는다.
-- 자동화에 넣을 때는 rc 대신 "출력이 비어 있는가"로 판정하는 편이 안전하다.
[root@ol7a ~]# for f in ol7b typo; do if [ -z "$(ksvalidator -v RHEL7 /root/ks-$f.cfg 2>&1)" ]; then echo "ks-$f.cfg OK"; else echo "ks-$f.cfg NG"; fi; done
ks-ol7b.cfg OK
ks-typo.cfg NG
-- $( ) 로 출력 전체를 받아 -z(빈 문자열)로 판정한다. 2>&1 로 오류 출력도 함께 받아야 한다.
-- 이 방법도 badopt·nopkg 는 못 거른다. 문법 검사는 첫 관문일 뿐이다.

--------------------------------------------------------------------------------
 [10] %include 와 없는 파일
--------------------------------------------------------------------------------

-- 큰 kickstart 는 %include 로 조각을 붙인다. %pre 가 만든 파일을 include 하는 경우가 많아
-- 검증 시점에는 그 파일이 없을 수 있다. 없는 파일을 include 한 경우를 본다.
-- 흔한 예: %pre 에서 디스크 크기를 보고 part 줄을 /tmp/part-include.ks 로 써 두고,
-- 본문에서 %include /tmp/part-include.ks 로 받는다. 서버마다 다른 분할을 한 파일로 처리한다.

[root@ol7a ~]# sed '/^%packages/i %include /tmp/part-include.ks' /root/ks-ol7b.cfg > /root/ks-incl.cfg; diff /root/ks-ol7b.cfg /root/ks-incl.cfg
36a37
> %include /tmp/part-include.ks
-- %packages 바로 앞에 include 줄 하나. /tmp/part-include.ks 는 만들지 않았다.

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-incl.cfg; echo "rc=$?"
rc=0
-- 없는 파일을 include 했는데 출력 없음, rc=0. 이 pykickstart 는 없는 include 파일을 조용히
-- 넘어갔다. 설치 환경에서는 %pre 가 그 파일을 만들 것이라고 가정하기 때문이다.
-- -i 는 %include 를 따라가지 않고 무시하는 옵션이다.
[root@ol7a ~]# ksvalidator -i -v RHEL7 /root/ks-incl.cfg; echo "rc=$?"
General kickstart error in input file
rc=1
-- -i 를 주자 "General kickstart error in input file", rc=1. 결과가 반대로 나왔다.
-- 메시지가 무엇이 틀렸는지 말해 주지 않는다. include 를 쓰는 파일은 ksflatten 으로 펼친 뒤
-- 펼친 결과를 검사하는 편이 원인을 찾기 쉽다.

--------------------------------------------------------------------------------
 [11] 같은 지시어 두 번, 서로 부딪치는 지시어
--------------------------------------------------------------------------------

-- 파일을 이어 붙여 고치다 보면 같은 지시어가 두 번 들어가기 쉽다.
[root@ol7a ~]# sed '/^timezone/a timezone America/New_York --isUtc' /root/ks-ol7b.cfg > /root/ks-dup.cfg; grep -n '^timezone' /root/ks-dup.cfg
27:timezone Asia/Seoul --isUtc --nontp
28:timezone America/New_York --isUtc
-- 27·28번 줄에 timezone 이 두 번.
-- sed 의 a 명령은 맞는 줄 바로 뒤에 새 줄을 붙인다.

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-dup.cfg; echo "rc=$?"
rc=0
-- 출력 없음, rc=0. 같은 명령이 두 번이면 뒤의 값이 앞을 덮는다. 이 파일로 설치하면
-- 시간대는 America/New_York 이 된다. 검사로는 드러나지 않는다.
-- anaconda-ks.cfg 를 고쳐 쓸 때 줄을 바꾸지 않고 새 줄을 덧붙이면 이렇게 된다. 고친 뒤 grep -c 로 센다.
-- autopart 와 수동 part 를 함께 쓰면 어떻게 되는가.
[root@ol7a ~]# sed '/^autopart/a part /u01 --fstype=xfs --size=10240' /root/ks-ol7b.cfg > /root/ks-mix.cfg; grep -n -E '^(autopart|part)' /root/ks-mix.cfg
31:autopart --type=lvm
32:part /u01 --fstype=xfs --size=10240
-- autopart 와 part 가 나란히 있다.
-- part 는 수동 분할 명령이다. --size 는 MiB 단위라 10240 은 10GiB.

[root@ol7a ~]# ksvalidator -v RHEL7 /root/ks-mix.cfg; echo "rc=$?"
The following problem occurred on line 32 of the kickstart file:

The part/partition and autopart commands can't be used at the same time

rc=0
-- 메시지는 나왔지만 rc=0. 서로 부딪치는 명령은 파서가 알아본다. 수동 분할을 하려면
-- autopart 를 지우고 part /boot, part pv.01, volgroup, logvol 로 전부 적어야 한다(2.3절).

 [변형] --ignoremissing 으로 같은 파일 고치기

-- 없는 패키지 오류를 "고치는" 대신 설치 프로그램이 넘어가게 하는 방법이다. 이름 오타라면

-- 묻지 말고 건너뛰라" 는 지시다. [8] 의 yum 기본값(skip_missing_names_on_install=True)과 같은 동작이다.
