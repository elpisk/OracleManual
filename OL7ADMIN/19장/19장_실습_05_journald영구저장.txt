================================================================================
 제19장 실습 05 — journald 영구 저장
 대상   : ol7a
 목표   : 기본 휘발성 journal 이 재부팅에서 사라지는 것을 보고, /var/log/journal 을 만들어
          영구 저장으로 바꾼다. 디렉터리만 만들었을 때 빠지는 단계(재시작·권한), 부팅
          목록(--list-boots)과 -b -1 조회, SystemMaxUse 한도와 --vacuum-size 를 확인한다
 배경   : journald.conf 의 Storage 기본값은 auto 다. auto 는 /var/log/journal 이 있으면
          거기에, 없으면 /run/log/journal(tmpfs)에 쓴다. OL 7.9 설치 직후에는 디렉터리가
          없어 재부팅마다 journal 이 지워진다. 영구 저장의 용량 한도는 SystemMaxUse(기본
          파일 시스템의 10%, 최대 4G), 휘발성은 RuntimeMaxUse 가 정한다 (본문 19.5·19.6)
 소요   : 약 40분
 선행   : ol7-base 스냅샷 (⚠ 재부팅 두 번, journald.conf 변경)
 계정   : root, student
 주의   : 재부팅을 두 번 한다. 끝에서 /var/log/journal 을 지우고 설정을 되돌린다.
          채우기 시험은 약 30MB 를 쓴다
 되돌림 : /var/log/journal 없음, journald.conf 원본 → ls -ld /var/log/journal, md5sum

-- 오류 흐름 ①. 디렉터리를 만들기만 하고 아무것도 하지 않는다.
-- Storage=auto 이므로 디렉터리만 있으면 영구 저장이 된다고 기대한다
[root@ol7a ~]# mkdir /var/log/journal; ls -ld /var/log/journal; sleep 3; ls -la /var/log/journal/
drwxr-xr-x. 2 root root 6 Nov 16 12:25 /var/log/journal
total 4
drwxr-xr-x.  2 root root    6 Nov 16 12:25 .
drwxr-xr-x. 10 root root 4096 Nov 16 12:25 ..
-- 빈 디렉터리다. root:root 0755. 3초를 기다려도 journald 는 아무것도 만들지 않는다
[root@ol7a ~]# journalctl --disk-usage; journalctl --header | grep '^File Path'
Archived and active journals take up 8.0M on disk.
File Path: /run/log/journal/b8658360b45f49fe8174bcd0b610ae6e/system.journal
-- 아직 /run 에 쓴다. 디렉터리는 journald 가 시작할 때나 flush 요청을 받을 때만 확인한다

-- journald 는 /var 쪽으로 옮기라는 신호를 받아야 한다. --flush 가 그 신호다(systemd-journal-flush.service 가 부팅 때 하는 일).
[root@ol7a ~]# journalctl --flush; ls -la /var/log/journal/ /var/log/journal/*/

/var/log/journal/:
total 4
drwxr-xr-x.  2 root root    6 Nov 16 12:25 .
drwxr-xr-x. 10 root root 4096 Nov 16 12:25 ..
[root@ol7a ~]# journalctl --header | grep '^File Path'; ls /run/log/journal/ 2>&1
File Path: /run/log/journal/b8658360b45f49fe8174bcd0b610ae6e/system.journal
b8658360b45f49fe8174bcd0b610ae6e
-- flush 직후에도 /var/log/journal 은 비어 있고 File Path 는 /run 이다
-- 7.9 의 journalctl --flush 는 신호(SIGUSR1)를 보내고 /run/systemd/journal/flushed 파일을 기다린다
-- 그 파일은 부팅 때 이미 생겨 있어(실습 01 [1]) 명령이 바로 끝났다. 옮기는 일은 그 뒤에 일어난다
-- 다음 단계의 ls 에서 machine-id 디렉터리가 보인다

user::rw-
group::r--
other::---
-- 몇 초 사이에 machine-id 디렉터리와 system.journal 이 생겼다. 옮기기가 끝났다
-- 그런데 디렉터리는 root:root 0755, 파일은 group::r-- 뿐이다. wheel·adm ACL 이 없다
-- 휘발성일 때의 /run/log/journal 파일에는 ACL(+) 이 있었다(실습 01 [3])

-- systemd 가 원하는 권한은 tmpfiles 설정에 있다.
[root@ol7a ~]# grep -n journal /usr/lib/tmpfiles.d/systemd.conf
25:z /run/log/journal 2755 root systemd-journal - -
26:Z /run/log/journal/%m ~2750 root systemd-journal - -
28:a+ /run/log/journal/%m - - - - d:group:adm:r-x,d:group:wheel:r-x
29:A+ /run/log/journal/%m - - - - group:adm:r-x,group:wheel:r-x
31:z /var/log/journal 2755 root systemd-journal - -
32:z /var/log/journal/%m 2755 root systemd-journal - -
33:z /var/log/journal/%m/system.journal 0640 root systemd-journal - -
35:a+ /var/log/journal    - - - - d:group:adm:r-x,d:group:wheel:r-x
36:a+ /var/log/journal    - - - - group:adm:r-x,group:wheel:r-x
37:a+ /var/log/journal/%m - - - - d:group:adm:r-x,d:group:wheel:r-x
38:a+ /var/log/journal/%m - - - - group:adm:r-x,group:wheel:r-x
39:a+ /var/log/journal/%m/system.journal - - - - group:adm:r--,group:wheel:r--
-- 줄 형식: 종류 경로 모드 소유자 그룹 나이 인자
--   z   있는 경로의 모드·소유를 맞춘다. 31~33행이 /var/log/journal 을 2755 root systemd-journal 로
--   a+  ACL 을 더한다. 35~39행이 adm·wheel 에 r-x(디렉터리)·r--(파일)
--   %m  machine-id 로 바뀐다
-- 부팅 때 systemd-tmpfiles-setup 이 이 줄을 적용한다. mkdir 로 만든 디렉터리는 그 기회를 놓쳤다
--
-- 증상   : mkdir 뒤 student(wheel)의 journalctl 이 "No journal files were opened due to
--          insufficient permissions." 를 냄. --flush 직후에는 File Path 가 /run 그대로
-- 원인   : mkdir 은 권한·ACL 을 주지 않음(root:root 0755, wheel ACL 없음).
--          옮기기는 flush 신호를 받은 journald 가 비동기로 함
-- 조치   : systemd-tmpfiles --create --prefix /var/log/journal (flush 는 이미 됨)
-- 재확인 : getfacl 에 group:wheel:r--, student 의 journalctl -n 2 출력

-- tmpfiles 로 그 설정을 적용한다.
--   --create            d·z·a 같은 줄을 실제로 만들고 권한·ACL 을 맞춘다
--   --prefix=/var/log/journal  그 경로로 시작하는 줄만
-- 부팅 때 하는 일을 지금 한다
[root@ol7a ~]# systemd-tmpfiles --create --prefix /var/log/journal; ls -ld /var/log/journal /var/log/journal/*

drwxr-sr-x+ 2 root systemd-journal 28 Nov 16 12:25 /var/log/journal/b8658360b45f49fe8174bcd0b610ae6e
-- 그룹이 systemd-journal, 권한에 setgid(s)와 ACL(+) 이 붙었다
[root@ol7a ~]# getfacl -p /var/log/journal/*/system.journal

group:wheel:r--

 [7] 한도를 작게 — SystemMaxUse=16M
--------------------------------------------------------------------------------

-- 한도를 작게 걸고 채워서 오래된 파일이 지워지는지 본다(오류 흐름 ②).
--   SystemMaxUse=16M       /var/log/journal 전체 한도
--   SystemMaxFileSize=4M   파일 하나의 크기. 이 크기가 차면 새 파일로 넘어간다(회전)
--   RateLimitBurst=0       채우기 시험 중 속도 제한을 끈다(기본 1000건/30초)
-- 원본을 남긴다
[root@ol7a ~]# cp /etc/systemd/journald.conf /root/journald.conf.orig
[root@ol7a ~]# sed -i 's/^#SystemMaxUse=/SystemMaxUse=16M/; s/^#SystemMaxFileSize=/SystemMaxFileSize=4M/; s/^#RateLimitBurst=1000/RateLimitBurst=0/' /etc/systemd/journald.conf
[root@ol7a ~]# diff /root/journald.conf.orig /etc/systemd/journald.conf

< #RateLimitBurst=1000
< #SystemMaxUse=
---
> RateLimitBurst=0
> SystemMaxUse=16M
24c24
< #SystemMaxFileSize=
---
> SystemMaxFileSize=4M
-- 세 줄이 바뀌었다. 21·22행(RateLimitBurst, SystemMaxUse)과 24행(SystemMaxFileSize)
[root@ol7a ~]# systemctl restart systemd-journald; journalctl -u systemd-journald -n 3 --no-pager

 [변형] Storage=persistent 로 지정하기
--------------------------------------------------------------------------------

-- 디렉터리 대신 설정으로 영구 저장을 강제한다. 디렉터리가 없으면 journald 가 만든다.

  systemd-journald.socket
-- 경고는 소켓이 살아 있어 메시지가 오면 journald 가 다시 뜬다는 뜻이다
[root@ol7a ~]# diff /root/journald.conf.orig /etc/systemd/journald.conf
15c15

---
> Storage=persistent
21,22c21,22

< #SystemMaxUse=
---
> RateLimitBurst=0
> SystemMaxUse=16M
24c24
< #SystemMaxFileSize=
---
> SystemMaxFileSize=4M
[root@ol7a ~]# systemctl start systemd-journald; journalctl --flush; ls -ld /var/log/journal /var/log/journal/*; journalctl --header | grep '^File Path'
drwxr-xr-x. 3 root root 46 Nov 16 12:26 /var/log/journal
drwxr-xr-x. 2 root root 28 Nov 16 12:26 /var/log/journal/b8658360b45f49fe8174bcd0b610ae6e
File Path: /var/log/journal/b8658360b45f49fe8174bcd0b610ae6e/system.journal
-- 지운 디렉터리를 journald 가 다시 만들었다. persistent 는 디렉터리가 없어도 영구 저장한다
-- 다만 이번에도 root:root 0755 다. ACL·그룹은 tmpfiles 몫이다

-- Storage=volatile 이면 /var/log/journal 이 있어도 /run 에만 쓴다.
[root@ol7a ~]# sed -i 's/^Storage=persistent/Storage=volatile/' /etc/systemd/journald.conf; systemctl restart systemd-journald; journalctl --header | grep '^File Path'

-- volatile 로 바꾸자 새 기록은 /run 의 system.journal 로 간다
-- 둘째 줄의 /var 파일은 앞에서 닫힌 파일이다. journalctl 은 읽을 수 있는 파일을 모두 보여 준다
