================================================================================
 제4장 실습 01 — chrony 서버와 클라이언트 (ol7a → ol7b)
 대상   : ol7a (시간 서버), ol7b (클라이언트)
 목표   : ol7a 의 chronyd 를 랩 안의 시간 서버로 만들고 ol7b 가 인터넷 pool 대신
          ol7a 만 바라보게 바꾼다. chrony.conf 의 server·allow·local stratum,
          chronyc sources -v·tracking·clients·serverstats 출력의 열을 읽는다
 배경   : chronyd 는 OL 7 의 기본 시간 동기화 데몬이다. 같은 데몬이 클라이언트이면서
          server 지시어로 위를 보고, allow 지시어로 아래(다른 호스트)에 시간을 준다.
          allow 가 없으면 NTP 요청을 받아도 응답하지 않는다. 바깥에서 오는 요청은
          firewalld 의 ntp 서비스(123/udp)도 통과해야 한다. local stratum 은 위쪽
          서버를 잃었을 때도 자기 시계로 계속 응답하게 한다 (본문 4.3 절)
 소요   : 약 25분
 선행   : ol7a 는 ol7-base, ol7b 는 ol7b-base. 두 노드 모두 chronyd 가 켜져 있고
          0~3.pool.ntp.org 로 동기화된 상태
 계정   : root (두 노드)
 주의   : chrony.conf 와 방화벽만 바꾼다. 끝에서 원래 파일로 되돌린다
 되돌림 : 두 노드 chrony.conf 가 백업과 같고(diff 무출력), ol7a 방화벽에 ntp 가 없고,
          ol7b 의 chronyc sources 가 다시 pool 서버 4개를 보임
================================================================================

--   Reach 0, LastRx "-" — 한 번도 응답이 없었다.
-- 마지막 줄의 [-2095ms] 는 부팅 직후 약 2초를 한 번에
--   옮긴(step) 흔적이다. 스냅샷 시각이 늦어서 생긴 차이다.

-- 설정 파일은 주석과 빈 줄을 뺀 실제 지시어만 본다.
-- grep -v '^#' 로 주석 줄을, grep -v '^$' 로 빈 줄을 뺐다. 원본 파일은
--   이보다 훨씬 길다.
[root@ol7a ~]# grep -v '^#' /etc/chrony.conf | grep -v '^$'
server 0.pool.ntp.org iburst
server 1.pool.ntp.org iburst
server 2.pool.ntp.org iburst
server 3.pool.ntp.org iburst
driftfile /var/lib/chrony/drift
makestep 1.0 3
rtcsync
logdir /var/log/chrony

-- 주석을 뺀 실제 지시어는 여덟 줄이다.
--   server ... iburst : 위쪽 서버 넷. iburst 는 시작 직후
--                       네 번을 짧은 간격으로 물음
--   driftfile         : 시계의 고유 오차(ppm) 저장 파일
--   makestep 1.0 3    : 시작 후 세 번 측정 안에서만
--                       1초 넘는 차이를 한 번에 맞춤
--   rtcsync           : 커널이 11분마다 RTC 를 맞추게 함
--   logdir            : 측정 로그를 켰을 때 쓸 곳
-- allow 가 없다. 기본 chronyd 는 시간을 받기만 한다.

[root@ol7b ~]# grep -v '^#' /etc/chrony.conf | grep -v '^$' | md5sum
09b2733c11deeebfc18a1b1b728a4c2c  -

-- 원본을 /root 에 복사해 둔다. cp -p 는 권한·시각을 보존한다. md5sum 은 두
--   노드 설정 비교용.
[root@ol7a ~]# cp -p /etc/chrony.conf /root/chrony.conf.orig; grep -v '^#' /etc/chrony.conf | grep -v '^$' | md5sum
09b2733c11deeebfc18a1b1b728a4c2c  -

-- 두 값이 09b2733c... 로 같다. 두 노드 설정이 똑같다.

[root@ol7b ~]# cp -p /etc/chrony.conf /root/chrony.conf.orig

-- ol7a 방화벽이 지금 무엇을 열어 두었는지. --list-services 는 서비스 이름만
--   한 줄로 보인다.
[root@ol7a ~]# firewall-cmd --list-services; firewall-cmd --permanent --list-services
dhcpv6-client ssh
dhcpv6-client ssh

-- 열린 서비스는 dhcpv6-client 와 ssh 뿐. ntp(123/udp)는 막혀 있다.

-- chronyd 가 어떤 UDP 포트를 열고 있는지. ss 옵션: -u UDP, -l 대기 중,
--   -p 프로세스, -n 숫자로.
[root@ol7a ~]# ss -ulpn | grep chronyd
UNCONN 0      0          127.0.0.1:323       0.0.0.0:*    users:(("chronyd",pid=1423,fd=5))
UNCONN 0      0              [::1]:323          [::]:*    users:(("chronyd",pid=1423,fd=6))

-- 열의 뜻 — 상태 | 수신 큐 | 송신 큐 | 로컬 주소:포트 | 상대 주소:포트 | 프로세스
--   UDP 는 연결이 없어 상태가 UNCONN 으로 찍힌다.
-- chronyd 는 127.0.0.1:323 과 [::1]:323 만 듣고 있다. chronyc
--   가 데몬과 이야기하는 명령 포트다.
-- 0.0.0.0:123 이 없다. NTP 서버 포트가 열려 있지 않다. 이것이 [5] 오류의
--   실마리다.

-- 주석 안에는 쓰지 않은 지시어 예시가 들어 있다. 어떤 것이 꺼져 있는지 확인한다.

19:#hwtimestamp *

32:#keyfile /etc/chrony.keys

--------------------------------------------------------------------------------
 [2] ol7a 를 서버로 — local stratum 만 넣고 allow 는 빠뜨림
--------------------------------------------------------------------------------

-- 위쪽 pool 서버는 그대로 두고, 그것을 잃었을 때 자기 시계로 stratum 10 을
--   내도록 한다.
-- 일부러 allow 는 넣지 않는다. 이 상태가 오류 ① 의 출발점이다.
[root@ol7a ~]# echo 'local stratum 10' >> /etc/chrony.conf; diff /root/chrony.conf.orig /etc/chrony.conf
38a39
> local stratum 10

-- diff 출력 "38a39" 는 원본 38 줄 뒤에(a = add) 새 파일의 39 번째 줄이
--   붙었다는 뜻. > 는 새 파일 쪽 내용.

[root@ol7a ~]# systemctl restart chronyd; sleep 3; systemctl is-active chronyd
active
[root@ol7a ~]# ss -ulpn | grep chronyd
UNCONN 0      0          127.0.0.1:323       0.0.0.0:*    users:(("chronyd",pid=2171,fd=5))
UNCONN 0      0              [::1]:323          [::]:*    users:(("chronyd",pid=2171,fd=6))

-- PID 가 바뀌었을 뿐 포트는 그대로 323 둘이다. local stratum 만으로는 서버
--   포트가 열리지 않는다.

--------------------------------------------------------------------------------
 [3] ol7b 를 ol7a 의 클라이언트로
--------------------------------------------------------------------------------

-- pool 서버 네 줄을 주석으로 막고 ol7a 한 줄만 넣는다.
-- sed 의 \(...\) 는 묶음, \1 은 그 묶음을 다시 쓰라는 뜻. 0~3 번호를 살린
--   채 앞에 # 만 붙인다.
-- iburst 는 시작 직후 4번을 짧은 간격으로 보내 첫 동기화를 빨리 끝내게 한다.
[root@ol7b ~]# sed -i 's/^server \([0-3]\)\.pool/#server \1.pool/' /etc/chrony.conf
[root@ol7b ~]# echo 'server ol7a.example.com iburst' >> /etc/chrony.conf
[root@ol7b ~]# grep -E '^#?server' /etc/chrony.conf
#server 0.pool.ntp.org iburst
#server 1.pool.ntp.org iburst
#server 2.pool.ntp.org iburst
#server 3.pool.ntp.org iburst
server ol7a.example.com iburst

-- pool 네 줄 앞에 # 이 붙었고 끝에 ol7a 한 줄이 붙었다.

[root@ol7b ~]# getent hosts ol7a.example.com
172.16.225.61   ol7a.example.com ol7a
[root@ol7b ~]# systemctl restart chronyd; sleep 20; chronyc sources
210 Number of sources = 1
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
^? ol7a.example.com              0   7     0     -     +0ns[   +0ns] +/-    0ns

-- 20초를 기다렸는데도 ^? 에 stratum 0, Reach 0, LastRx "-". 응답이
--   한 번도 오지 않았다.
-- Poll 이 7(128초)로 늘었다. 응답이 없으면 chronyd 는 조회 간격을 점점 벌린다.
-- 원인 후보는 셋이다. 이름 해석(위에서 아님을 확인), 서버 방화벽, 서버의 allow.

 [4] 오류 ② — 방화벽이 123/udp 를 막고 있음
--------------------------------------------------------------------------------

-- ol7a 쪽에서 요청이 들어오기는 하는지부터 본다.
-- serverstats 는 chronyd 가 서버로서 받은·버린 패킷 수를 센다.
[root@ol7a ~]# chronyc serverstats
NTP packets received       : 0
NTP packets dropped        : 0
Command packets received   : 1
Command packets dropped    : 0
Client log records dropped : 0

-- 서버가 받은 패킷 수다.
--   NTP packets received 0    : NTP 요청이 chronyd 까지 하나도 오지 않았다
--   Command packets received 1: 방금 친 chronyc 명령 자체(323
--     포트)
-- 방화벽에서 막혔든 포트가 닫혀 있든 이 숫자는 0 이다. 둘을 가르려면 ss 와 방화벽을 함께
--   본다.

-- 방화벽에서 거부된 패킷은 기본 설정에서 로그로 남지 않는다. 열린 서비스 목록을 다시 본다.
[root@ol7a ~]# firewall-cmd --list-services
dhcpv6-client ssh
[root@ol7a ~]# firewall-cmd --info-service=ntp | grep ports
  ports: 123/udp
  source-ports: 

-- 방화벽의 ntp 서비스 정의는 123/udp 하나다.
-- grep ports 가 source-ports 줄(빈 값)도 함께 잡았다.

-- 런타임과 영구 설정 양쪽에 ntp 를 넣는다. --permanent 만 하면 --reload
--   전까지 적용되지 않는다.
[root@ol7a ~]# firewall-cmd --add-service=ntp; firewall-cmd --permanent --add-service=ntp
success
success
[root@ol7a ~]# firewall-cmd --list-services; firewall-cmd --permanent --list-services
dhcpv6-client ntp ssh
dhcpv6-client ntp ssh

-- ol7b 에서 바로 다시 요청하게 한다. burst 4/4 는 좋은 응답 4개를 얻을 때까지
--   최대 4번 보낸다.
[root@ol7b ~]# chronyc burst 4/4; sleep 12; chronyc sources
200 OK
210 Number of sources = 1
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
^? ol7a.example.com              0   8     0     -     +0ns[   +0ns] +/-    0ns

-- burst 는 200 OK 를 돌려줬지만 결과는 여전히 ^? Reach 0. Poll 은
--   8(256초)까지 늘었다.
-- 증상   : 방화벽에 ntp 를 열었는데도 ol7b 의 sources 가 "^?
--          ol7a.example.com 0 8 0 -"
-- 원인   : 방화벽은 원인의 절반이었다. ol7a 의 chronyd 가 123 포트를 아예
--          열지 않았다([2] 의 ss 출력).
--          방화벽을 통과한 패킷도 받을 곳이 없다
-- 조치   : 방화벽 설정은 그대로 두고 [5] 에서 allow 를 넣는다
-- 재확인 : [5] 의 ss -ulpn 에 0.0.0.0:123 이 보이고 ol7b
--          sources 에 ^* 가 생김

--------------------------------------------------------------------------------
 [5] 오류 ① — allow 가 없어 응답하지 않음
--------------------------------------------------------------------------------

-- 이번에는 패킷이 ol7a 의 chronyd 까지 오는지 serverstats 로 확인한다.
[root@ol7a ~]# chronyc serverstats | head -1
NTP packets received       : 0

-- 방화벽을 연 뒤에도 NTP packets received 0.

-- 어느 대역에 시간을 줄지 allow 로 정한다. 랩 대역 172.16.225.0/24 전체를
--   허용한다.
[root@ol7a ~]# echo 'allow 172.16.225.0/24' >> /etc/chrony.conf; diff /root/chrony.conf.orig /etc/chrony.conf
38a39,40
> local stratum 10
> allow 172.16.225.0/24

-- 원본 대비 두 줄이 붙었다. local stratum 10 과 allow
--   172.16.225.0/24.

[root@ol7a ~]# systemctl restart chronyd; sleep 3; ss -ulpn | grep chronyd
UNCONN 0      0            0.0.0.0:123       0.0.0.0:*    users:(("chronyd",pid=2360,fd=7))
UNCONN 0      0          127.0.0.1:323       0.0.0.0:*    users:(("chronyd",pid=2360,fd=5))
UNCONN 0      0              [::1]:323          [::]:*    users:(("chronyd",pid=2360,fd=6))

-- 0.0.0.0:123 이 새로 열렸다. allow 가 하나라도 있어야 chronyd 가 NTP
--   서버 포트를 연다.
-- 0.0.0.0 은 모든 IPv4 주소에서 받는다는 뜻이다. 누구에게 응답할지는 allow
--   대역이 다시 거른다.

-- ol7a 가 위쪽 pool 과 다시 동기화돼야 ol7b 에게 쓸모 있는 시간을 준다. 잠시
--   기다린다.
[root@ol7a ~]# chronyc sources
210 Number of sources = 4
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
^- any.time.nl                   2   6    17    16   +457us[ +457us] +/-   18ms
^+ mail.innotab.com              2   6    17    17   +200us[ +160us] +/- 5633us
^* 121.134.215.104               2   6    17    17   +109us[  +68us] +/- 1951us
^+ 193.123.243.2                 3   6    17    17   -301us[ -342us] +/- 3920us

-- ol7a 자신은 재시작 뒤 pool 서버와 다시 동기화했다.
--   ^* 121.134.215.104, Reach 17(최근 네 번 성공).
-- ^+ 두 줄은 함께 계산에 쓰는 후보다.
-- 서버가 먼저 동기화돼 있어야 클라이언트에게 쓸모 있는 시간을 준다.

[root@ol7b ~]# chronyc burst 4/4; sleep 15; chronyc sources
200 OK
210 Number of sources = 1
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
^* ol7a.example.com              3   6    17     9    +63ns[+2110ns] +/- 3031us

-- ^* ol7a.example.com, stratum 3, Reach 17. ol7b 가
--   ol7a 를 따르기 시작했다.
-- ol7a 의 stratum 이 3 인 것은 ol7a 가 stratum 2 서버를
--   따르기 때문이다.
-- 증상   : ol7b 의 chronyc sources 가 "^? ol7a.example.com
--          0 7 0 -" (Reach 0)
-- 원인   : ol7a 의 chrony.conf 에 allow 가 없어 chronyd 가
--          123/udp 를 열지 않았다.
--          ss -ulpn 에 323 포트 둘만 있었고 serverstats 의 NTP
--            packets received 가 0
-- 조치   : ol7a 에 allow 172.16.225.0/24 를 넣고 systemctl
--          restart chronyd,
--          ol7b 에서 chronyc burst 4/4 로 바로 다시 묻게 함
-- 재확인 : ol7a 의 ss 에 0.0.0.0:123, ol7b 의 sources 에 "^*
--          ol7a.example.com",
--          아래 serverstats 의 NTP packets received 가 0
--            보다 큼

[root@ol7a ~]# chronyc serverstats | head -1
NTP packets received       : 4

-- NTP packets received 4. burst 4/4 의 네 요청이 그대로 들어왔다.
--   dropped 는 0.

--------------------------------------------------------------------------------
 [6] chronyc sources -v — 열 해석
--------------------------------------------------------------------------------

-- -v 는 각 기호와 열의 뜻을 머리말로 함께 찍는다.
[root@ol7b ~]# chronyc sources -v
210 Number of sources = 1

-- -v 는 범례를 머리말로 함께 찍는다.
-- Source mode : ^ 서버, = 피어, # 로컬 참조 시계
-- Source state: * 동기화, + 함께 계산, - 뺌, ? 연결 안 됨,
--   x 틀린 시계, ~ 변동 큼
-- Reach 17 은 이진수 1111. 최근 네 번 성공했다.
-- Poll 6 은 2^6 = 64초 간격.
-- xxxx [ yyyy ] +/- zzzz = 보정 뒤 차이 [잰 차이] +/- 오차.
-- +63ns[+2110ns] — 나노초 단위다. 같은 호스트의 두 VM 이라
--   지연이 거의 없다.

  .-- Source mode  '^' = server, '=' = peer, '#' = local clock.
 / .- Source state '*' = current synced, '+' = combined , '-' = not combined,
| /   '?' = unreachable, 'x' = time may be in error, '~' = time too variable.
||                                                 .- xxxx [ yyyy ] +/- zzzz
||      Reachability register (octal) -.           |  xxxx = adjusted offset,
||      Log2(Polling interval) --.      |          |  yyyy = measured offset,
||                                \     |          |  zzzz = estimated error.
||                                 |    |           \
MS Name/IP address         Stratum Poll Reach LastRx Last sample               
===============================================================================
^* ol7a.example.com              3   6    17    39    +63ns[+2110ns] +/- 3031us
