================================================================================
 제4장 실습 03 — 시간 어긋남 재현과 보정, 시간대와 RTC
 대상   : ol7b (시계를 틀어 놓는 쪽), ol7a (기준 시계로 조회만)
 목표   : 시계를 일부러 몇 분 틀어 놓고 chronyd 의 점진 보정(slew)과 즉시 보정(step,
          makestep)을 비교한다. timedatectl 로 시간대를 바꾸고, RTC 를 로컬 시간으로
          두는 설정이 무엇을 바꾸는지 확인한다
 배경   : 시스템 시계는 커널이 들고 있는 UTC 초 수이고, 시간대는 그것을 표시하는 방법일
          뿐이다. RTC 는 메인보드(VM 에서는 가상 하드웨어)의 배터리 시계다. chronyd 는
          큰 차이는 시작 직후에만 한 번에 고치고(makestep 1.0 3), 그 뒤에는 시계 속도를
          바꿔 천천히 따라잡는다. VMware 도구의 주기적 시간 동기화는 이 랩의 vmx 에서
          꺼 두었다 (tools.syncTime = "FALSE") (본문 4.2·4.3 절)
 소요   : 약 20분
 선행   : ol7a 는 ol7-base, ol7b 는 ol7b-base. 두 노드 모두 chronyd 로 동기화된 상태
 계정   : root
 주의   : ol7b 의 시계를 몇 분~1시간 틀어 놓는다. 다른 실습과 동시에 하지 않는다
 되돌림 : ol7b 시간대 Asia/Seoul, RTC in local TZ: no, NTP synchronized: yes,
          chronyc tracking 의 System time 이 1ms 안쪽

-- timedatectl 은 시스템 시계·RTC·시간대·동기화 상태를 한 화면에 모아
--   보인다.
[root@ol7b ~]# timedatectl
      Local time: Thu 2026-11-12 20:26:41 KST
  Universal time: Thu 2026-11-12 11:26:41 UTC
        RTC time: Thu 2026-11-12 11:26:39
       Time zone: Asia/Seoul (KST, +0900)
     NTP enabled: yes
NTP synchronized: yes
 RTC in local TZ: no
      DST active: n/a

-- 여덟 줄을 위에서부터 읽는다.
-- Local time  : 시간대(KST)를 적용한 시각
-- Universal time : UTC. 시스템 시계 그대로다
-- RTC time    : RTC 값. UTC 로 두었으므로 Universal 과 같아야
--   한다. 2초 차이는 RTC 가 초 단위로만 읽히고 갱신
--   간격이 있어서 생기는 정도다
-- Time zone   : /etc/localtime 이 가리키는
--   Asia/Seoul, +0900
-- NTP enabled : chronyd 가 enabled
-- NTP synchronized : 커널의 동기화 플래그가 켜짐
-- RTC in local TZ : no — 서버의 정상값
-- DST active  : n/a — 서울은 서머타임이 없다

-- chronyd 가 시계를 다루는 규칙 두 줄. makestep 과 rtcsync.
[root@ol7b ~]# grep -E '^(makestep|rtcsync)' /etc/chrony.conf
makestep 1.0 3
rtcsync

-- makestep 1.0 3 : 처음 세 번의 시계 갱신에서만, 1초 넘는
--   차이를 한 번에 맞춘다(step)
-- rtcsync : 커널이 11분마다 시스템 시계를 RTC 에 쓴다

-- /etc/adjtime 의 세 번째 줄이 RTC 를 UTC 로 해석할지 로컬
--   시간으로 해석할지 정한다.
[root@ol7b ~]# cat /etc/adjtime; ls -l /etc/localtime
0.000000 1794395620 0.000000
1794395620
UTC
lrwxrwxrwx. 1 root root 32 Nov 12 05:10 /etc/localtime -> ../usr/share/zoneinfo/Asia/Seoul

-- /etc/adjtime 세 줄
--   1행 : RTC 표류 보정값, 마지막 보정 시각(초), 0
--   2행 : 마지막 보정 시각
--   3행 : UTC — RTC 를 UTC 로 해석한다
-- /etc/localtime 은 zoneinfo 파일로 가는 링크다.

-- open-vm-tools 의 주기적 시간 동기화 상태. vmx 의
--   tools.syncTime 값이 그대로 보인다.
[root@ol7b ~]# rpm -q open-vm-tools; systemctl is-active vmtoolsd; vmware-toolbox-cmd timesync status
open-vm-tools-11.0.5-3.0.1.el7_9.9.x86_64
active
Disabled

-- vmtoolsd 는 돌고 있지만 주기적 시간 동기화는 Disabled.
-- 이 랩의 vmx 에 tools.syncTime = "FALSE" 가 들어 있다.

-- 기준 시계로 쓸 ol7a. 두 명령 사이에 러너가 접속을 바꾸는 시간(1초 안팎)이
--   있다.
[root@ol7b ~]# chronyc tracking | grep -E 'System time|Last offset'; date '+%T'
System time     : 0.000059880 seconds slow of NTP time
Last offset     : -0.000074359 seconds
20:26:42

-- System time 0.000000000 — step 으로 남은 차이를 0 으로
--   만들었다. Last offset 은 그 직전에 잰 38 마이크로초.


-- System time 이 마이크로초 수준. 두 노드 시각이 같다.
-- 아래 ol7a 의 date 를 기준 시계로 계속 비교한다.

[root@ol7a ~]# date '+%T'

 [5] 시계를 틀어 놓고 chronyd 재시작 — makestep 1.0 3
--------------------------------------------------------------------------------

-- 재시작 직후 세 번의 측정 안에서는 1초보다 큰 차이를 step 으로 맞춘다.
-- date -s 로 바꾼 시계가 "곧바로 되돌아가는" 대표적인 경우가 이것이다.
[root@ol7b ~]# date -s '+3 min'; date '+%T'

20:31:00

-- ol7b 를 다시 3분 앞당겼다(20:28 → 20:31).

[root@ol7b ~]# systemctl restart chronyd; sleep 12; date '+%T'
20:28:12

-- 재시작 12초 뒤 20:28:12. 기준 ol7a 와 같다.

[root@ol7a ~]# date '+%T'
20:28:12
[root@ol7b ~]# journalctl -u chronyd --no-pager -n 4
-- Logs begin at Thu 2026-11-12 20:24:51 KST, end at Thu 2026-11-12 20:28:06 KST. --
Nov 12 20:31:05 ol7b.example.com chronyd[10421]: Selected source 175.195.167.194
Nov 12 20:31:05 ol7b.example.com chronyd[10421]: System clock wrong by -179.998598 seconds, adjustment started

Nov 12 20:28:06 ol7b.example.com chronyd[10421]: Selected source 158.247.202.103

-- 새 chronyd[10421]가 "wrong by -179.998598
--   seconds" 를 보고
--   곧바로 "stepped by -179.998598 seconds".
-- 재시작 직후라 makestep 1.0 3 의 창 안이다.
-- date -s 로 바꾼 시계가 "곧바로 되돌아가는" 이유가 이것이다.
-- 시험 때문에 시각을 바꿔 두려면 먼저 동기화를 꺼야 한다.

--------------------------------------------------------------------------------
 [6] 오류 ① — timedatectl set-time 이 거부됨
--------------------------------------------------------------------------------

-- 시험 때문에 시계를 1시간 뒤로 돌려야 한다고 하자. timedatectl 로
--   시도한다.
-- date -d '-1 hour' 로 1시간 전 시각을 계산해 "YYYY-MM-DD
--   HH:MM:SS" 형식으로 넘긴다.
[root@ol7b ~]# timedatectl set-time "$(date -d '-1 hour' '+%F %T')"
Failed to set time: Automatic time synchronization is enabled

-- 증상   : timedatectl set-time 이 "Failed to set
--          time:
--          Automatic time synchronization is
--            enabled" 로 거부
-- 원인   : NTP 동기화가 켜져 있으면 timedatectl 은 수동 변경을
--          막는다. 시간 데몬과 사람이 시계를 다투지 않게 한다
-- 조치   : timedatectl set-ntp false 로 동기화를 끄고 다시
--          set-time
-- 재확인 : 아래 date 가 1시간 늦은 값, timedatectl 의 NTP
--          enabled·synchronized 가 no

-- 동기화를 끄면 chronyd 도 멈추고 비활성화된다.
[root@ol7b ~]# timedatectl set-ntp false; systemctl is-active chronyd; systemctl is-enabled chronyd
unknown
disabled

-- set-ntp false 가 chronyd 를 멈추고 disable 했다.
-- is-active 는 unknown 으로 찍혔다(실습 02 와 같다).

[root@ol7b ~]# timedatectl set-time "$(date -d '-1 hour' '+%F %T')"; date '+%T'
19:28:12

-- 이번에는 받아들여졌다. ol7b 19:28:12, ol7a 20:28:12.

[root@ol7a ~]# date '+%T'
20:28:12
[root@ol7b ~]# timedatectl | grep -E 'Local|RTC time|NTP'
      Local time: Thu 2026-11-12 19:28:12 KST
        RTC time: Thu 2026-11-12 10:28:12
     NTP enabled: no
NTP synchronized: no

-- RTC time 도 10:28:12(UTC) 로 1시간 늦어졌다.
-- set-time 은 시스템 시계와 RTC 를 함께 바꾼다. date -s 는
--   시스템 시계만 바꾼다. 두 명령의 차이다.

--------------------------------------------------------------------------------
 [7] open-vm-tools 가 시계를 되돌리는가
--------------------------------------------------------------------------------

-- 주기적 동기화는 꺼져 있다. 하지만 VMware 도구는 시작·스냅샷 복귀 같은 사건
--   때
-- 한 번 맞추는 동작도 있다. vmtoolsd 를 재시작해 실제로 시계가 바뀌는지
--   본다.
[root@ol7b ~]# date '+%T'; systemctl restart vmtoolsd; sleep 5; date '+%T'
19:28:12
20:28:15

-- vmtoolsd 재시작 전 19:28:12, 5초 뒤 20:28:15.
-- 주기적 동기화는 꺼져 있는데도 서비스가 시작할 때 호스트
--   시각으로 한 번 맞췄다. chronyd 는 멈춰 있었다.

[root@ol7a ~]# date '+%T'
20:28:17
[root@ol7b ~]# journalctl -u vmtoolsd --no-pager -n 3
-- Logs begin at Thu 2026-11-12 20:24:51 KST, end at Thu 2026-11-12 20:28:10 KST. --
Nov 12 19:28:12 ol7b.example.com systemd[1]: Stopping Service for virtual machines hosted on VMware...
Nov 12 19:28:12 ol7b.example.com systemd[1]: Stopped Service for virtual machines hosted on VMware.
Nov 12 19:28:12 ol7b.example.com systemd[1]: Started Service for virtual machines hosted on VMware.

-- 기록은 Stopping·Stopped·Started 뿐. 시각을 바꿨다는 말은
--   없다. journal 로는 원인을 알 수 없고 date 전후 비교로만
--   드러난다.
-- 증상   : 1시간 늦춰 둔 ol7b 시계가 저절로 맞음. chronyd 는
--          꺼져 있었고 journal 에 시각 변경 기록이 없음
-- 원인   : open-vm-tools 의 vmtoolsd 가 시작할 때 호스트
--          시각으로
--          한 번 맞춘다. tools.syncTime = "FALSE" 는
--            주기적
--          동기화만 끈다
-- 조치   : 시각을 일부러 틀어 둔 시험은 vmtoolsd 재시작·재부팅·
--          스냅샷 복귀 뒤 시각을 다시 확인한다
-- 재확인 : 위 date 전후 값(19:28:12 → 20:28:15)

--------------------------------------------------------------------------------
 [변형] chronyd -q — ntpdate 처럼 한 번만 맞추고 끝내기
--------------------------------------------------------------------------------

-- chronyd 데몬이 멈춘 상태에서 쓸 수 있다. -q 는 설정 대신 따옴표 안의
--   지시어를 쓰고,
-- 시계를 한 번 맞춘 뒤 종료한다. 조회만 하고 바꾸지 않으려면 -Q.
[root@ol7b ~]# timeout 40 chronyd -Q 'server 0.pool.ntp.org iburst'; echo "rc=$?"
2026-11-12T11:28:15Z chronyd version 3.4 starting (+CMDMON +NTP +REFCLOCK +RTC +PRIVDROP +SCFILTER +SIGND +ASYNCDNS +SECHASH +IPV6 +DEBUG)
2026-11-12T11:28:15Z Disabled control of system clock
2026-11-12T11:28:19Z System clock wrong by 2.635202 seconds (ignored)
2026-11-12T11:28:19Z chronyd exiting
rc=0

-- -Q 는 조회만. 줄별로
--   Disabled control of system clock : 시계를 건드리지
--     않음
--   System clock wrong by 2.635202 seconds
--     (ignored) : 2.6초
--     차이를 쟀지만 무시
-- vmtoolsd 가 맞춘 호스트 시각이 NTP 기준으로 2.6초 틀렸다.

[root@ol7b ~]# timeout 60 chronyd -q 'server 0.pool.ntp.org iburst'; echo "rc=$?"
2026-11-12T11:28:19Z chronyd version 3.4 starting (+CMDMON +NTP +REFCLOCK +RTC +PRIVDROP +SCFILTER +SIGND +ASYNCDNS +SECHASH +IPV6 +DEBUG)
2026-11-12T11:28:19Z Initial frequency -19.422 ppm
2026-11-12T11:28:24Z System clock wrong by 2.635050 seconds (step)
2026-11-12T11:28:26Z chronyd exiting
rc=0

-- -q 는 한 번 맞추고 끝낸다. "(step)" 으로 2.635050초를
--   옮겼다. Initial frequency -19.422 ppm 은 drift
--     파일 값이다.
-- ntpdate 를 대신하는 방법이다.
-- [OL8/9] ntpdate 가 없어 이 방법이 기본이다(문서 기준).

[root@ol7b ~]# date '+%T'
20:28:26
[root@ol7a ~]# date '+%T'
20:28:26

-- 두 노드가 다시 같다.

-- 바꾸기 전후의 초 수가 1 차이. 명령 사이에 초가 넘어간
--   것뿐이다. 시간대 변경이 시계를 바꾸지 않는다.

[root@ol7b ~]# timedatectl | head -4; ls -l /etc/localtime
      Local time: Thu 2026-11-12 06:28:42 EST
  Universal time: Thu 2026-11-12 11:28:42 UTC
        RTC time: Thu 2026-11-12 10:28:41
       Time zone: America/New_York (EST, -0500)
lrwxrwxrwx. 1 root root 38 Nov 12 06:28 /etc/localtime -> ../usr/share/zoneinfo/America/New_York

-- Local time 이 EST 06:28, Universal 은 그대로 11:28.
-- /etc/localtime 링크가 America/New_York 으로 바뀌었다.
-- RTC time 10:28:41 은 Universal 보다 1시간 늦다.
--   [6] 의 set-time 이 RTC 에 늦은 시각을 써 두었고, 그 뒤
--   맞춘 vmtoolsd·chronyd -q 는 시스템 시계만 바꿨다.
--   rtcsync 의 11분 주기가 아직 돌지 않았다.

-- TZ 변수는 그 명령 하나에만 다른 시간대를 쓴다.
[root@ol7b ~]# date; TZ=Asia/Seoul date; TZ=UTC date
Thu Nov 12 06:28:42 EST 2026
Thu Nov 12 20:28:42 KST 2026
Thu Nov 12 11:28:42 UTC 2026

-- 같은 순간을 세 시간대로. TZ 는 그 명령에만 적용된다.

[root@ol7b ~]# timedatectl set-timezone Asia/Seoul; timedatectl | grep 'Time zone'
       Time zone: Asia/Seoul (KST, +0900)

-- 원래 시간대로 돌렸다.

--------------------------------------------------------------------------------
 [10] 오류 ② — RTC 를 로컬 시간으로 두기
--------------------------------------------------------------------------------

-- Windows 와 듀얼 부팅하던 습관으로 RTC 를 로컬 시간으로 바꾸는 경우가
--   있다.
[root@ol7b ~]# timedatectl set-local-rtc 1
[root@ol7b ~]# timedatectl
      Local time: Thu 2026-11-12 20:28:42 KST
  Universal time: Thu 2026-11-12 11:28:42 UTC
        RTC time: Thu 2026-11-12 20:28:42
       Time zone: Asia/Seoul (KST, +0900)
     NTP enabled: yes
NTP synchronized: yes
 RTC in local TZ: yes
      DST active: n/a

-- RTC time 이 20:28:42 로 바뀌었다. 이제 RTC 를 로컬 시각으로
--   쓴다. RTC in local TZ: yes.
-- 출력 끝에 경고가 붙었다. [1;39m 같은 글자는 터미널 색상
--   제어 문자가 그대로 기록된 것이다.
-- 증상   : timedatectl 이 "Warning: The system is
--          configured to
--          read the RTC time in the local time
--            zone." 을 출력
-- 원인   : set-local-rtc 1 로 /etc/adjtime 3행이
--          LOCAL 이 됐다.
--          경고문대로 서머타임·시간대 변경 때 문제가 생기고
--          RTC 가 자동 갱신되지 않는다
-- 조치   : timedatectl set-local-rtc 0
-- 재확인 : RTC in local TZ: no, /etc/adjtime 3행 UTC

[1;39mWarning: The system is configured to read the RTC time in the local time zone.
         This mode can not be fully supported. It will create various problems
         with time zone changes and daylight saving time adjustments. The RTC
         time is never updated, it relies on external facilities to maintain it.
         If at all possible, use RTC in UTC by calling
         'timedatectl set-local-rtc 0'[0m.
[root@ol7b ~]# cat /etc/adjtime
0.000000 1794395620 0.000000
1794395620
LOCAL

-- 3행이 LOCAL 로 바뀌었다.

-- RTC 값을 직접 읽는다. hwclock -r 은 /etc/adjtime 의 해석
--   방식에 따라 표시한다.
[root@ol7b ~]# hwclock -r; cat /sys/class/rtc/rtc0/date /sys/class/rtc/rtc0/time
Thu 12 Nov 2026 08:28:43 PM KST  -0.173636 seconds
2026-11-12
20:28:43

-- sysfs 로 읽은 RTC 원시값이 20:28:43 — 로컬 시각이 들어 있다.
-- hwclock -r 은 adjtime 의 LOCAL 해석으로 같은 시각을 보인다.
--   뒤의 -0.17 초는 읽기 지연 보정값이다.

-- 되돌린다.
[root@ol7b ~]# timedatectl set-local-rtc 0; timedatectl | grep -E 'RTC'; cat /etc/adjtime
        RTC time: Thu 2026-11-12 11:28:42
 RTC in local TZ: no
0.000000 1794395620 0.000000
1794395620
UTC

-- RTC 가 다시 UTC(11:28:42)로 쓰였고 3행도 UTC.

--------------------------------------------------------------------------------
 [11] RTC 와 시스템 시계 — rtcsync 와 hwclock
--------------------------------------------------------------------------------

-- rtcsync 가 있으면 커널이 11분마다 RTC 를 시스템 시계에 맞춘다.
-- 시스템 시계(date -u)와 sysfs 로 읽은 RTC 값을 나란히 놓고,
--   hwclock 으로 직접 맞춰 본다.
[root@ol7b ~]# date -u '+%F %T'; cat /sys/class/rtc/rtc0/date /sys/class/rtc/rtc0/time
2026-11-12 11:28:42
2026-11-12
11:28:42

-- 시스템 시계(UTC)와 RTC 원시값이 같은 11:28:42 다.

[root@ol7b ~]# hwclock --systohc; hwclock -r
Thu 12 Nov 2026 08:28:45 PM KST  -0.141381 seconds

-- --systohc 는 시스템 시계를 RTC 에 쓴다. hwclock -r 은
--   adjtime 이 UTC 라 RTC 값을 로컬(KST)로 바꿔 보인다.
