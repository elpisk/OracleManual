 제17장 실습 03 — 셸 한도 확인: limits.d, soft·hard, 로그인 경로별 차이
 대상   : ol7a
 목표   : preinstall 이 둔 limits.d 파일이 어느 경로로 로그인했을 때 적용되는지
          확인한다. su - 와 su, SSH 로그인, systemd 서비스로 띄운 프로세스의
          한도를 /proc/PID/limits 로 비교하고, 서비스에는 unit 의 Limit* 로
          따로 주어야 한다는 것을 본다
 배경   : limits.conf·limits.d 는 PAM 의 pam_limits 모듈이 세션을 열 때 읽는다.
          그래서 PAM 세션을 거치는 로그인(su, sshd, login)에만 적용되고, PAM 을
          거치지 않는 systemd 서비스는 unit 파일의 LimitNOFILE= 같은 값을 쓴다.
          soft 는 실제 적용값, hard 는 사용자가 올릴 수 있는 상한이다(본문 17.7)
 소요   : 약 25분
 선행   : ol7-base 스냅샷. preinstall 을 미리 설치(출력 생략)
 계정   : root, oracle
 주의   : 없음. 만든 unit·설정 파일은 [11] 에서 지운다
 되돌림 : 만든 파일 삭제. 확인은 systemctl status limtest(없음), ls limits.d

--------------------------------------------------------------------------------
 [4] soft 와 hard — 사용자가 올릴 수 있는 범위
--------------------------------------------------------------------------------

[oracle@ol7a ~]$ ulimit -n 65536; ulimit -n
65536
-- 일반 사용자도 soft 를 hard(65536)까지는 스스로 올릴 수 있다.
--   같은 셸 안에서만 유효하다
[oracle@ol7a ~]$ ulimit -n 65537; echo "exit=$?"
/tmp/_ol7lab_oracle.sh: line 1: ulimit: open files: cannot modify limit: Operation not permitted
exit=1
-- 증상   : "ulimit: open files: cannot modify
--          limit: Operation not
--          permitted", 종료 코드 1
-- 원인   : 65537 은 hard 한도 65536 을 넘는다. 일반 사용자는
--          hard 를 넘는 값을 줄 수 없다
--          메시지 앞의 /tmp/_ol7lab_oracle.sh: line 1: 은 러너가 명령을 담은 스크립트 이름이다
--          대화형 셸이라면 -bash: ulimit: 으로 나온다
[oracle@ol7a ~]$ ulimit -Hn 4096; ulimit -Hn; ulimit -Hn 65536; echo "exit=$?"
4096
/tmp/_ol7lab_oracle.sh: line 1: ulimit: open files: cannot modify limit: Operation not permitted
exit=1
-- hard 를 4096 으로 내린 뒤 다시 65536 으로 올리려 하자
--   같은 메시지로 거부됐다
-- 일반 사용자는 hard 를 내리기만 할 수 있다. 내린 셸에서는
--   끝까지 4096 이다
-- 조치   : 영구 값은 root 가 limits.d 에서 정한다. 사용자가
--          할 수 있는 것은 soft 를 hard 까지 올리는 것뿐이다
-- 재확인 : [4] 첫 명령처럼 soft 를 65536(=hard)까지
--         올리는 것은 성공했다

 [5] su 와 su - 의 차이
--------------------------------------------------------------------------------

-- 설치 가이드의 예처럼 .bash_profile 에 환경 변수를 둔다
[root@ol7a ~]# echo 'export ORACLE_SID=orcl' >> /home/oracle/.bash_profile; tail -1 /home/oracle/.bash_profile
export ORACLE_SID=orcl
-- 설치 가이드는 oracle 의
--   환경(ORACLE_SID·ORACLE_HOME·PATH)을
--   ~/.bash_profile 에 두라고 한다
[root@ol7a ~]# su - oracle -c 'echo "nofile=$(ulimit -n) nproc=$(ulimit -u) HOME=$HOME PWD=$PWD SID=$ORACLE_SID"'
nofile=1024 nproc=16384 HOME=/home/oracle PWD=/home/oracle SID=orcl
-- su - (로그인 셸) : 한도 1024·16384, HOME·PWD 가
--   oracle 의 홈, .bash_profile 을 읽어 SID=orcl
[root@ol7a ~]# su oracle -c 'echo "nofile=$(ulimit -n) nproc=$(ulimit -u) HOME=$HOME PWD=$PWD SID=$ORACLE_SID"'
nofile=1024 nproc=16384 HOME=/home/oracle PWD=/root SID=
-- su (하이픈 없음) : 한도는 같다. pam_limits 는 두 경우 모두 돈다
-- 다른 것은 환경이다. PWD 가 /root 그대로, .bash_profile 을
--   읽지 않아 SID 가 비었다
-- 설계한 오류(su 로 전환해 한도 미적용)는 7.9 에서 재현되지
--   않았다. 실제로 겪는 문제는
--   "su 로 들어가 sqlplus 를 쳤더니 ORACLE_SID 가 없다" 쪽이다
-- HOME 은 둘 다 /home/oracle 로 나왔다. su 가 HOME 을
--   바꾸는 것은 7.9 su 의 기본 동작이다
[root@ol7a ~]# grep -E '^session' /etc/pam.d/su | head -5

 [8] systemd 서비스로 띄운 프로세스
--------------------------------------------------------------------------------

-- 같은 oracle 로, 이번에는 systemd 서비스로 sleep 을 띄운다.
--   DB 자동 기동 unit 과 같은 구조다
-- [Install] 절이 없어 enable 할 수 없는 static unit
--   이다. 시험에는 start 만 쓴다
[root@ol7a ~]# cat > /etc/systemd/system/limtest.service <<'EOF'
[Unit]
Description=limits test as oracle
[Service]
User=oracle
Group=oinstall
ExecStart=/bin/sleep 900
EOF
[root@ol7a ~]# systemctl daemon-reload; systemctl start limtest; systemctl status limtest --no-pager | head -6

   Loaded: loaded (/etc/systemd/system/limtest.service; static; vendor preset: disabled)
   Active: active (running) since Mon 2026-11-16 11:12:40 KST; 18ms ago
 Main PID: 7599 (sleep)
   CGroup: /system.slice/limtest.service
           └─7599 /bin/sleep 900
-- active (running), Main PID 7599. 이
--   PID 의 한도를 본다
[root@ol7a ~]# P=$(systemctl show -p MainPID limtest | cut -d= -f2); echo "pid=$P"; grep -E 'Limit|open files|processes|stack|locked' /proc/$P/limits
pid=7599

Max stack size            8388608              unlimited            bytes

-- 증상   : 같은 oracle 인데 open files 1024 / 4096,
--          processes 14400, stack 8MB /
--          unlimited, locked 64KB
--          [7] 의 로그인 세션 값(65536, 16384, 32MB, 128GiB)과 다르다
-- 원인   : systemd 가 띄운 프로세스는 PAM 세션을 거치지 않아
--          limits.d 를 읽지 않는다
--          대신 systemd 의 기본 한도를 받는다
[root@ol7a ~]# systemctl show limtest -p LimitNOFILE -p LimitNPROC -p LimitSTACK -p LimitMEMLOCK
LimitSTACK=18446744073709551615
LimitNOFILE=4096
LimitNPROC=14400
LimitMEMLOCK=65536
-- systemctl show 의 Limit* 는 hard 값을 보여 준다.
--   LimitNOFILE=4096, LimitNPROC=14400
-- LimitSTACK 18446744073709551615 은
--   unlimited 를 숫자로 쓴 것이다
[root@ol7a ~]# grep -E '^#?DefaultLimit(NOFILE|NPROC)' /etc/systemd/system.conf
#DefaultLimitNOFILE=
#DefaultLimitNPROC=
-- system.conf 의 DefaultLimit* 는 주석. 서비스 기본값은
--   systemd 의 내장값이다
-- 모든 서비스를 한꺼번에 바꾸려면 여기에 쓰지만, 한 서비스만
--   바꾸려면 unit 에 쓴다

-- unit 에 한도를 직접 적는다. drop-in 으로 원래 파일은 두고 덧붙인다
[root@ol7a ~]# mkdir -p /etc/systemd/system/limtest.service.d; printf '[Service]\nLimitNOFILE=1024:65536\nLimitNPROC=16384\nLimitSTACK=10485760:33554432\nLimitMEMLOCK=infinity\n' > /etc/systemd/system/limtest.service.d/limits.conf; cat /etc/systemd/system/limtest.service.d/limits.conf
[Service]
LimitNOFILE=1024:65536
LimitNPROC=16384
LimitSTACK=10485760:33554432
LimitMEMLOCK=infinity
-- 조치   : drop-in 파일에
--          LimitNOFILE=1024:65536(soft:hard),
--          LimitNPROC=16384,
--          LimitSTACK=10485760:33554432(바이트), LimitMEMLOCK=infinity 를 넣었다
-- drop-in 경로 limtest.service.d/*.conf. 원래
--   unit 을 건드리지 않아 패키지 업데이트에 덮이지 않는다
[root@ol7a ~]# systemctl show limtest -p LimitNOFILE
LimitNOFILE=4096
-- 파일을 만들었지만 daemon-reload 전이라 systemd 는 아직 옛
--   정의(4096)를 들고 있다
[root@ol7a ~]# systemctl daemon-reload; systemctl show limtest -p LimitNOFILE; P=$(systemctl show -p MainPID limtest | cut -d= -f2); grep 'open files' /proc/$P/limits
LimitNOFILE=65536
Max open files            1024                 4096                 files     
-- daemon-reload 뒤 show 는 65536 으로 바뀌었다. 그러나 떠
--   있는 프로세스는 그대로 1024 / 4096
-- unit 정의와 실행 중인 프로세스는 별개다. 정의를 바꿔도
--   프로세스는 다시 띄워야 바뀐다
[root@ol7a ~]# systemctl restart limtest; P=$(systemctl show -p MainPID limtest | cut -d= -f2); echo "pid=$P"; grep -E 'open files|processes|stack|locked' /proc/$P/limits
pid=7753
Max stack size            10485760             33554432             bytes

Max open files            1024                 65536                files     
Max locked memory         unlimited            unlimited            bytes     
-- 재확인 : restart 뒤 새 PID 7753 의 한도가 open files
--         1024 / 65536, processes 16384,
--          stack 10MB / 32MB, locked unlimited. 로그인 세션과 같아졌다

--------------------------------------------------------------------------------
 [변형] prlimit — 실행 중인 프로세스의 한도를 바꾸기
--------------------------------------------------------------------------------

[root@ol7a ~]# P=$(pgrep -u oracle -n -f 'sleep 900'); prlimit --pid $P --nofile
RESOURCE DESCRIPTION              SOFT  HARD UNITS
NOFILE   max number of open files 1024 65536 
-- prlimit --pid : 실행 중인 다른 프로세스의 한도를 읽고
--   바꾼다(prlimit 시스템 호출)
-- -n 으로 가장 최근 sleep 900, 즉 limtest
--   서비스의 프로세스를 골랐다
[root@ol7a ~]# P=$(pgrep -u oracle -n -f 'sleep 900'); prlimit --pid $P --nofile=4096:65536; prlimit --pid $P --nofile
RESOURCE DESCRIPTION              SOFT  HARD UNITS
NOFILE   max number of open files 4096 65536 
-- soft 를 4096 으로 올렸다. root 는 다른 사용자 프로세스의
--   한도도 바꿀 수 있다
[root@ol7a ~]# P=$(pgrep -u oracle -n -f 'sleep 900'); grep 'open files' /proc/$P/limits
Max open files            4096                 65536                files     
-- /proc/PID/limits 에도 바로 반영됐다. 재시작 없이 바꾸는 유일한
--   방법이지만 그 프로세스에만 해당한다
-- 서비스를 재시작하면 unit 의 값(1024)으로 돌아간다

 [10] 새 세션만 바뀐다
--------------------------------------------------------------------------------

[root@ol7a ~]# sed -i -E 's/^(oracle\s+soft\s+nofile\s+)1024$/\18192/' /etc/security/limits.d/oracle-database-preinstall-19c.conf; grep -E 'soft\s+nofile' /etc/security/limits.d/oracle-database-preinstall-19c.conf
oracle   soft   nofile    8192
-- preinstall 파일의 soft nofile 을 8192 로 바꿨다. sed
--   -E 의 \1 은 앞부분(공백 포함)을 그대로 둔다
[root@ol7a ~]# grep 'open files' /proc/$(pgrep -u oracle -o sleep)/limits
Max open files            1024                 65536                files     
-- [7] 에서 su - 세션으로 띄운 sleep(가장 오래된 것,
--   -o)은 1024 그대로다
[oracle@ol7a ~]$ ulimit -n
8192
-- 새 세션은 8192. 한도 파일은 세션을 열 때만 읽는다
-- 운영 중인 인스턴스의 한도를 바꾸려면 파일을 고친 뒤 인스턴스를 그 사용자
--   세션에서 다시 띄운다
[root@ol7a ~]# sed -i -E 's/^(oracle\s+soft\s+nofile\s+)8192$/\11024/' /etc/security/limits.d/oracle-database-preinstall-19c.conf; su - oracle -c 'ulimit -n'
1024
-- 8192 를 1024 로 되돌렸다
