================================================================================
 제5장 실습 06 — 커널 업데이트와 보존 개수
 대상   : ol7a (os-installed 스냅샷 — 설치 직후, 업데이트 전)
 목표   : UEK 와 RHCK 를 차례로 업데이트하면서 커널이 "교체"가 아니라 "추가"로
          들어오는 것을 확인한다. 업데이트 뒤 기본 부팅 커널이 무엇으로 정해지는지,
          installonly_limit 가 오래된 커널을 언제 지우는지, 실행 중인 커널은 왜
          지워지지 않는지 본다. package-cleanup 으로 같은 정리를 해 본다
 배경   : kernel·kernel-uek 는 installonly 패키지라 yum update 를 해도 이전 판을
          남긴다. 남기는 개수는 yum.conf 의 installonly_limit(기본 3)다.
          새 커널을 기본 부팅 항목으로 만들지는 /etc/sysconfig/kernel 의
          UPDATEDEFAULT·DEFAULTKERNEL 이 정한다 (본문 5.9)
 소요   : 약 40분 (커널 패키지 내려받기와 재부팅 포함)
 선행   : os-installed 스냅샷 — UEK 5.4.17-2102.201.3 과 RHCK 3.10.0-1160 만 있음
 계정   : root
 주의   : 커널을 지우는 단계가 있다. 끝나면 스냅샷으로 되돌린다
 되돌림 : os-installed 스냅샷으로 복귀. 복귀 뒤 rpm -q kernel-uek 가 2102.201.3 하나
================================================================================

-- 보존 개수와 기본 커널 규칙이 적힌 두 파일을 본다.
[root@ol7a ~]# grep -E 'installonly|^\[main' /etc/yum.conf
[main]

-- 같은 이름의 커널을 셋까지 둔다.
[root@ol7a ~]# cat /etc/sysconfig/kernel
# UPDATEDEFAULT specifies if new-kernel-pkg should make
# new kernels the default
UPDATEDEFAULT=yes

# DEFAULTKERNEL specifies the default kernel package type
DEFAULTKERNEL=kernel-uek
-- 이 두 값이 아래 결과를 정한다.
-- UPDATEDEFAULT=yes : 새로 설치되는 커널을 기본 부팅 항목으로

-- 주석에 나오는 new-kernel-pkg 가 설치 스크립트에서 이 값을 읽는다.

 [5] RHCK 업데이트 — 기본 커널은 바뀌는가
--------------------------------------------------------------------------------

-- yum update kernel 은 kernel-uek 는 건드리지 않는다.
-- 이름이 다른 패키지다.
-- 이번엔 RHCK 를 올린다.
-- DEFAULTKERNEL 이 kernel-uek 다.
[root@ol7a ~]# yum update -y kernel 2>&1 | sed -n '/^Installed:/,$p'
Installed:
  kernel.x86_64 0:3.10.0-1160.119.1.0.5.el7                                     

Complete!
-- RHCK 도 같은 방식으로 추가된다.
-- kernel 도 Installed(추가)다.
[root@ol7a ~]# rpm -q kernel; grubby --default-kernel
kernel-3.10.0-1160.el7.x86_64
kernel-3.10.0-1160.119.1.0.5.el7.x86_64
/boot/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64
-- 기본 항목은 바뀌지 않았다.
-- RHCK 둘. 기본 커널은 UEK 2136 그대로다.
[root@ol7a ~]# grubby --info=ALL | grep -E '^(index|title)'
index=0
title=Oracle Linux Server 7.9, with Linux 3.10.0-1160.119.1.0.5.el7.x86_64
index=1
title=Oracle Linux Server 7.9, with Unbreakable Enterprise Kernel 5.4.17-2136.338.4.2.el7uek.x86_64
index=2

index=3

index=4
title=Oracle Linux Server 7.9, with Linux 0-rescue-b8658360b45f49fe8174bcd0b610ae6e
index=5
-- 항목은 여섯 개가 됐다.
-- 운영에서 콘솔로 GRUB 메뉴를 보며 "맨 위가 기본"이라 짐작하면 틀린다.
-- 기본 항목은 항상 grubby --default-kernel 로 확인한다.
-- 새 RHCK 항목이 index 0 에 들어갔다.
-- 그런데 기본은 UEK 2136 이다.
-- GRUB 메뉴 맨 위와 기본 항목이 다르다.
-- 기본은 grubenv 의 saved_entry 가 정하고, 항목 순서와는 따로 간다.
-- DEFAULTKERNEL=kernel-uek 라서 RHCK 설치는 saved_entry 를 바꾸지 않았다.

--------------------------------------------------------------------------------
 [6] 기본 커널을 RHCK 로 바꿨다 되돌리기
--------------------------------------------------------------------------------

-- rpm -q --last 로 가장 최근 설치된 RHCK 이름을 얻어 경로를 만든다.
[root@ol7a ~]# grubby --set-default=/boot/vmlinuz-$(rpm -q --last kernel | head -1 | awk '{print $1}' | sed 's/^kernel-//'); grubby --default-kernel
/boot/vmlinuz-3.10.0-1160.119.1.0.5.el7.x86_64
-- grubby 는 grub.cfg 를 직접 고친다.
-- 기본이 RHCK 로 바뀌었다. 재부팅하면 RHCK 로 뜬다.
[root@ol7a ~]# grubby --set-default=/boot/vmlinuz-$(rpm -q --last kernel-uek | head -1 | awk '{print $1}' | sed 's/^kernel-uek-//'); grubby --default-kernel
/boot/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64
-- 원래 기본 커널로 돌아왔다.
-- 같은 방법으로 UEK 2136 으로 되돌렸다.

--------------------------------------------------------------------------------
 [8] 실행 중인 커널 지우기
--------------------------------------------------------------------------------

-- $(uname -r | sed …) 로 실행 커널의 패키지 이름을 만든다.
-- --assumeno 라 실제로 지워지지는 않는다.
-- 지금 실행 중인 커널을 yum 으로 지우려 한다(계획만).
[root@ol7a ~]# yum remove --assumeno kernel-uek-$(uname -r | sed 's/\.x86_64$//') 2>&1 | tail -6
Loaded plugins: langpacks, ulninfo
Skipping the running kernel: kernel-uek-5.4.17-2136.338.4.2.el7uek.x86_64
No Packages marked for removal
-- 계획 단계에서 끝나 아무것도 지우지 않았다.
-- 오류 흐름 ① — 실행 중인 커널 제거 시도
-- 증상   : "Skipping the running kernel: kernel-uek-5.4.17-2136.338.4.2…"
--          "No Packages marked for removal"
-- 원인   : yum 은 uname -r 의 커널을 보호 대상으로 둔다.
--          지우면 다음 부팅에 쓸 커널과 모듈이 사라진다.
-- 조치   : 꼭 지워야 하는 커널이면 grubby 로 다른 커널을 기본으로 두고 재부팅한 뒤 지운다
-- 재확인 : 아래 rpm -q kernel-uek 에 2136.338.4.2 가 그대로 있음
[root@ol7a ~]# rpm -e --test kernel-uek-$(uname -r | sed 's/\.x86_64$//'); echo "rc=$?"
rc=0
-- rpm -e --test 는 rc=0. rpm 은 실행 중 커널을 막지 않는다.
-- --test 라 실제로 지우지는 않았다.
-- rpm -e 였다면 지워졌다.
-- 커널 정리는 rpm 이 아니라 yum·package-cleanup 으로 한다.
[root@ol7a ~]# rpm -q kernel-uek
kernel-uek-5.4.17-2102.201.3.el7uek.x86_64
kernel-uek-5.4.17-2136.338.4.2.el7uek.x86_64
-- 실행 커널은 그대로다.
-- 두 UEK 그대로다.

--------------------------------------------------------------------------------
 [9] installonly_limit=2 로 줄이고 커널 하나 더
--------------------------------------------------------------------------------

-- 보존 개수를 2 로 줄여 정리 동작을 일부러 일으킨다.
[root@ol7a ~]# cp -p /etc/yum.conf /root/yum.conf.orig; sed -i 's/^installonly_limit=3/installonly_limit=2/' /etc/yum.conf; diff /root/yum.conf.orig /etc/yum.conf
10c10
< installonly_limit=3
---
> installonly_limit=2
-- 이 값은 [11] 에서 되돌린다.
-- 10 번째 줄 하나가 바뀌었다.
-- 이름-판 을 다 적으면 그 판이 설치된다.
-- 커널이라 기존 판과 공존한다.
-- 저장소의 바로 아래 판(338.4.1)을 설치한다.
-- 셋째 UEK 가 된다.
[root@ol7a ~]# yum install -y kernel-uek-5.4.17-2136.338.4.1.el7uek 2>&1 | sed -n '/^Dependencies Resolved/,/^Transaction Summary/p'
Dependencies Resolved

================================================================================
 Package       Arch      Version                         Repository        Size
================================================================================
Installing:
 kernel-uek    x86_64    5.4.17-2136.338.4.1.el7uek      ol7_UEKR6        112 M
Removing:
 kernel-uek    x86_64    5.4.17-2102.201.3.el7uek        @anaconda/7.9     68 M

Transaction Summary

-- @anaconda/7.9 는 설치 프로그램이 매체에서 깐 패키지라는 출처 표시다.

 [11] 되돌림 준비
--------------------------------------------------------------------------------

-- cp -p 로 시각까지 원본대로 되돌린다.
-- 보존 개수를 원래 값으로.
[root@ol7a ~]# cp -p /root/yum.conf.orig /etc/yum.conf; grep installonly_limit /etc/yum.conf
installonly_limit=3
-- 보존 개수가 기본값으로 돌아왔다.
-- 3 으로 복귀.
[root@ol7a ~]# grubby --default-kernel; df -h /boot
/boot/vmlinuz-5.4.17-2136.338.4.1.el7uek.x86_64
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1      1014M  238M  777M  24% /boot

-- /boot 사용량 193M → 238M.
-- 커널 구성 전체는 os-installed 스냅샷으로 되돌린다.
