================================================================================
 제5장 실습 01 — rpm 질의와 검증
 대상   : ol7a
 목표   : rpm 질의 옵션(-qa/-qi/-ql/-qf/-qc/-qd/-qR)으로 설치된 패키지를 읽고,
          rpm -V 출력의 아홉 칸 표시를 해석한다. 설정 파일과 실행 파일을
          각각 바꾼 뒤 검증 결과가 어떻게 다른지 비교한다
 배경   : RPM 은 설치한 파일의 크기·권한·소유자·다이제스트·수정 시각을
          /var/lib/rpm 데이터베이스에 남긴다. rpm -q 계열은 그 데이터베이스를
          읽고, rpm -V 는 데이터베이스 값과 디스크의 실제 파일을 대조한다.
          설정 파일은 바뀌는 것이 정상이라 c 표시로 따로 구분된다 (본문 5.1·5.2)
 소요   : 약 25분
 선행   : ol7-base 스냅샷 (chrony 가 설치·동작 중)
 계정   : root
 주의   : /etc/chrony.conf 와 /usr/bin/chronyc 를 바꿨다 되돌린다.
          되돌림을 빠뜨리면 rpm -Va 에 계속 남는다
 되돌림 : chrony.conf 원본 복원, rpm --setperms 로 권한 복원.
          rpm -V chrony 출력이 비어 있으면 끝
================================================================================

--------------------------------------------------------------------------------
 [0] 시작 전 상태 기록
--------------------------------------------------------------------------------

-- 바꿀 대상은 chrony 패키지의 파일 두 개다.
-- 지금 값을 먼저 남긴다.
-- rpm -V 는 문제가 없으면 아무것도 찍지 않는다.
-- 빈 출력이 정상이라 echo 로 종료 코드를 붙인다.
[root@ol7a ~]# rpm -q chrony; rpm -V chrony; echo "rc=$?"
chrony-3.4-1.0.3.el7.x86_64
rc=0
-- 이 실습은 rpm 만 쓴다. yum 은 [변형] 에서만 나온다.
-- rpm -q 결과: 이름-버전-릴리스.아키텍처 한 줄. 설치돼 있다는 뜻이다.
-- rpm -V 는 아무것도 찍지 않았고 rc=0. 검증할 차이가 없다.
[root@ol7a ~]# md5sum /etc/chrony.conf; stat -c '%A %U:%G %s %y %n' /etc/chrony.conf /usr/bin/chronyc
ef524abab890c4ad7fbfcdbe59648999  /etc/chrony.conf
-rw-r--r-- root:root 1080 2024-08-14 15:06:53.000000000 +0900 /etc/chrony.conf
-rwxr-xr-x root:root 86976 2024-08-14 15:06:54.000000000 +0900 /usr/bin/chronyc
-- md5sum 은 비교 기준으로 남겨 두는 값. 끝에서 같은지 본다.
-- stat 열: 권한 / 소유자:그룹 / 크기(바이트) / 수정 시각 / 경로.
--   chrony.conf 1080 바이트, chronyc 86976 바이트, 755.
--   수정 시각 2024-08-14 는 빌드 날짜다. 설치 시각(11-11)이 아니다.
--   rpm 은 파일을 풀 때 패키지 안의 mtime 을 그대로 살린다.
[root@ol7a ~]# rpm -qa | wc -l
565
-- 이 값은 [정리] 표에서 다시 쓴다.
-- 기준 상태의 패키지 수 565. 마지막에 다시 센다.

--------------------------------------------------------------------------------
 [1] 패키지 이름 규칙 — 이름·버전·릴리스·아키텍처
--------------------------------------------------------------------------------

-- rpm -q 이름 은 설치된 패키지의 전체 이름(NVRA)을 돌려준다.
-- --qf(queryformat)로 태그를 하나씩 뽑으면 이름의 어느 부분이 무엇인지 분명해진다.
--   %{EPOCH}   : 버전 비교에서 가장 먼저 보는 숫자. 없으면 (none)
--   %{RELEASE} : 배포판이 붙이는 꼬리. el7 은 RHEL 7 계열, .0.N 은 Oracle 이 고친 판
[root@ol7a ~]# rpm -q chrony openssh-server kernel-uek yum
chrony-3.4-1.0.3.el7.x86_64
openssh-server-7.4p1-23.0.3.el7_9.x86_64
kernel-uek-5.4.17-2102.201.3.el7uek.x86_64
kernel-uek-5.4.17-2136.338.4.2.el7uek.x86_64
yum-3.4.3-168.0.5.el7.noarch
-- kernel-uek 가 두 줄이다.
-- 같은 이름을 판별로 여러 개 둘 수 있는 installonly 패키지라서다(본문 5.9). 다른 패키지는 이름당 하나.
-- noarch 는 아키텍처와 무관한 패키지. yum 은 파이썬 코드라 noarch 다.
[root@ol7a ~]# rpm -q --qf '%-16{NAME} E=%{EPOCH} V=%{VERSION} R=%{RELEASE} A=%{ARCH}\n' chrony openssh-server kernel-uek yum
chrony           E=(none) V=3.4 R=1.0.3.el7 A=x86_64
openssh-server   E=(none) V=7.4p1 R=23.0.3.el7_9 A=x86_64
kernel-uek       E=(none) V=5.4.17 R=2102.201.3.el7uek A=x86_64
kernel-uek       E=(none) V=5.4.17 R=2136.338.4.2.el7uek A=x86_64
yum              E=(none) V=3.4.3 R=168.0.5.el7 A=noarch
-- 이름과 판을 나눠 보는 것이 이 단계의 목적이다.
-- 다섯 필드 읽기
--   NAME    : chrony, openssh-server …
--   EPOCH   : 넷 다 (none). 비교할 때 0 으로 친다.
--   VERSION : 업스트림 버전. 3.4, 7.4p1, 5.4.17, 3.4.3
--   RELEASE : 배포판 빌드 번호. 1.0.3.el7 의 ".0.3" 처럼 0 이 끼면
--             Oracle 이 RHEL 판(1.el7)을 고쳐 다시 빌드한 것이다.
--   ARCH    : x86_64 또는 noarch
-- el7_9 는 7.9 이후 나온 업데이트 판이라는 꼬리다(openssh-server).

 [4] 패키지가 설치한 파일 — -ql, -qc, -qd
--------------------------------------------------------------------------------

-- -l 은 파일 전체, -c 는 %config 로 표시된 설정 파일만, -d 는 문서 파일만.
[root@ol7a ~]# rpm -ql chrony | wc -l; rpm -qc chrony; rpm -qd chrony | head -5
26
/etc/chrony.conf
/etc/chrony.keys
/etc/logrotate.d/chrony
/etc/sysconfig/chronyd
/usr/share/doc/chrony-3.4/COPYING
/usr/share/doc/chrony-3.4/FAQ
/usr/share/doc/chrony-3.4/NEWS
/usr/share/doc/chrony-3.4/README
/usr/share/man/man1/chronyc.1.gz
-- 문서 파일은 /usr/share/doc 아래에 있다.
-- 26 은 전체 파일 수. 그중 %config 파일이 넷이다.
-- -qc 목록에 /etc/chrony.conf 가 있다.
-- 뒤에서 이 파일을 고친다.
-- -qd 는 head -5 로 앞 다섯 줄만 보였다.
-- --dump 는 파일마다 크기·시각·다이제스트·모드·소유자·config 여부를 한 줄로 보여 준다.
-- rpm -V 가 비교하는 원본 값이 바로 이것이다.
[root@ol7a ~]# rpm -q --dump chrony | grep -E '^/etc/chrony.conf |^/usr/bin/chronyc '
/etc/chrony.conf 1080 1723615613 d29d1c6f17541ec28642f37117a22adebaf408e46c4e21717308fc605d03bd2c 0100644 root root 1 0 0 X
/usr/bin/chronyc 86976 1723615614 f4e573fabd52e4f7ed36f24ea37959bf8a2693d96ee560b1e014ec322b8685ea 0100755 root root 0 0 0 X
-- --dump 열: 경로 / 크기 / mtime(유닉스 초) / 다이제스트 / 모드 / 소유자 / 그룹 / config 여부 / doc 여부 / rdev / 심볼릭 대상 1723615613 은 2024-08-14 15:06:53 KST. [0] 의 stat 시각과 같다.
-- 다이제스트는 64자리라 MD5 가 아니라 SHA-256 이다.
-- rpm -V 의 '5' 자리는 이름만 MD5 이고 실제로는 패키지에 기록된 알고리즘으로 잰다.
-- chrony.conf 는 config 칸이 1, chronyc 는 0. 모드 0100644 와 0100755.

 [5] 파일에서 패키지 찾기 — rpm -qf
--------------------------------------------------------------------------------

[root@ol7a ~]# rpm -qf /usr/sbin/chronyd /etc/chrony.conf /etc/hosts /etc/yum.conf
chrony-3.4-1.0.3.el7.x86_64
chrony-3.4-1.0.3.el7.x86_64
setup-2.8.71-11.el7.noarch
yum-3.4.3-168.0.5.el7.noarch
-- /etc/hosts 는 setup 패키지 소속이다.
-- 계정 파일(passwd, group)도 여기.
-- 어떤 패키지에도 속하지 않는 파일. 설치 프로그램이나 관리자가 만든 것이다.
[root@ol7a ~]# rpm -qf /root/anaconda-ks.cfg /etc/hostname
file /root/anaconda-ks.cfg is not owned by any package
systemd-219-78.0.17.el7_9.9.x86_64
-- 주인이 없는 파일은 rpm -V 로 검증할 수 없다.
-- anaconda-ks.cfg 는 설치 프로그램이 만든 파일이라 주인이 없다.
-- /etc/hostname 은 systemd 가 %ghost 로 선언해 두어 주인이 있다.
-- 관리자가 만든 파일을 찾을 때 "not owned by any package" 가 단서다.

 [6] 심볼릭 링크와 -qf
--------------------------------------------------------------------------------

[root@ol7a ~]# ls -l /etc/localtime /etc/grub2.cfg /usr/bin/python
lrwxrwxrwx. 1 root root 22 Nov 11 20:15 /etc/grub2.cfg -> ../boot/grub2/grub.cfg
lrwxrwxrwx. 1 root root 32 Nov 11 19:49 /etc/localtime -> ../usr/share/zoneinfo/Asia/Seoul
lrwxrwxrwx. 1 root root  7 Nov 11 20:15 /usr/bin/python -> python2
[root@ol7a ~]# rpm -qf /etc/localtime /etc/grub2.cfg /usr/bin/python
systemd-219-78.0.17.el7_9.9.x86_64
grub2-pc-2.02-0.87.0.26.el7_9.14.x86_64
python-2.7.5-94.0.1.el7_9.x86_64
-- 링크 자체를 물었다. 세 링크 모두 주인 패키지가 있다.
--   /etc/localtime → systemd (링크를 %ghost 로 소유)
--   /etc/grub2.cfg → grub2-pc
--   /usr/bin/python → python
[root@ol7a ~]# rpm -qf $(readlink -f /etc/localtime) $(readlink -f /etc/grub2.cfg) $(readlink -f /usr/bin/python)
tzdata-2024b-2.el7.noarch
grub2-pc-2.02-0.87.0.26.el7_9.14.x86_64
python-2.7.5-94.0.1.el7_9.x86_64
-- 오류 흐름 ② — 심볼릭 링크를 -qf 로 물을 때
-- 증상   : rpm -qf /etc/localtime 이 systemd-219-78.0.17.el7_9.9 를 돌려줌.
--          시간대 파일을 찾으려던 것인데 엉뚱한 패키지가 나온 셈이다.
-- 원인   : -qf 는 링크를 따라가지 않는다.
--          링크 파일 자체의 주인을 답한다.
--          ls -l 에서 /etc/localtime 이 Asia/Seoul 을 가리키는 링크로 보임.
-- 조치   : rpm -qf $(readlink -f 경로) 로 최종 대상을 물음
-- 재확인 : 바로 위 출력에서 /etc/localtime 의 답이 tzdata-2024b-2.el7 로 바뀜.
--          grub2.cfg·python 은 링크와 대상의 주인이 같아 그대로다.

 [9] 설정 파일을 바꾸고 검증 — rpm -V 의 c 표시
--------------------------------------------------------------------------------

[root@ol7a ~]# echo 'maxdistance 16.0' >> /etc/chrony.conf; tail -2 /etc/chrony.conf
#log measurements statistics tracking
maxdistance 16.0
-- 파일 끝에 한 줄을 덧붙였을 뿐이다.
-- 설정 파일 끝에 지시어 한 줄을 붙였다.
-- 서비스는 재시작하지 않았다.
[root@ol7a ~]# rpm -V chrony; echo "rc=$?"
S.5....T.  c /etc/chrony.conf
-- 크기·다이제스트·시각 세 칸이 바뀌었다.
-- 아홉 칸 표시. 점(.)은 일치, 글자는 다름, ? 는 검사 불가.
--   S 크기  M 모드  5 다이제스트  D 장치번호  L 링크 대상
--   U 소유자  G 그룹  T 수정 시각  P 기능(capabilities)
-- rpm 4.11 은 P 칸까지 아홉 칸이다.
-- 옛 문서의 "여덟 글자"는 P 이전 기준.
-- 지금 줄은 S·5·T 가 다르다.
-- 한 줄 붙였으니 크기·내용·시각이 바뀌었다.
-- 둘째 칸의 c 는 %config 파일이라는 표시다(rpm -qc 목록과 일치).
rc=1
-- 종료 코드 1. 스크립트로 검증을 돌릴 때는 출력이 아니라 이 값을 본다.
-- 오류 흐름 ① — c 표시 파일을 손상으로 오판
-- 증상   : rpm -V chrony 가 "S.5....T.  c /etc/chrony.conf" 를 찍고 rc=1
-- 원인   : 관리자가 설정을 고친 정상 변경이다.
--          c 표시는 %config 파일, 즉 바뀌는 것이 예상된 파일이라는 뜻이다.
--          패키지 손상이 아니다.
-- 조치   : 재설치하지 않는다.
--          바뀐 내용을 diff 로 확인해 의도한 변경인지 판단.
--          원본이 필요하면 [12] 처럼 보관본을 되살린다.
-- 재확인 : [12] 에서 보관본을 cp -p 로 되돌리자 이 줄이 사라짐.
