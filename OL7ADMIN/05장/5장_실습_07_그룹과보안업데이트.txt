================================================================================
 제5장 실습 07 — 그룹과 보안 업데이트
 대상   : ol7a
 목표   : yum group 으로 그룹의 구성(mandatory·default·optional)을 읽고 설치해
          어떤 패키지가 빠지는지 확인한다. yum updateinfo 로 보안 정오표(errata)를
          조회하고 --security·update-minimal 의 범위를 비교한다. yum-cron 의
          설정 파일에서 자동 업데이트 범위를 정하는 항목을 읽는다
 배경   : 그룹은 comps 메타데이터에 정의된 패키지 묶음이다. group install 은
          기본적으로 mandatory 와 default 만 설치한다. 보안 플러그인 기능은
          OL7 의 yum 에 들어 있어 updateinfo 메타데이터(ELSA·ELBA·ELEA)를
          읽는다. 이미 최신인 시스템에서는 목록이 비어 보인다 (본문 5.5·5.7)
 소요   : 약 30분
 선행   : ol7-base 스냅샷, 인터넷 접속
 계정   : root
 주의   : sudo 를 이전 판으로 내렸다 다시 올린다. 그룹 하나와 yum-cron 을
          설치했다 지운다
 되돌림 : rpm -qa | wc -l 이 565, rpm -q sudo 가 [0] 과 같으면 끝

 [2] 그룹의 구성 — group info
--------------------------------------------------------------------------------

-- info 는 설치 여부와 무관하게 구성만 보여 준다.
-- 이름에 공백이 있어 따옴표로 감싼다.
-- 'security-tools' 도 된다.
[root@ol7a ~]# yum group info 'Security Tools' 2>&1 | sed -n '/^Group:/,$p'
Group: Security Tools
 Group-Id: security-tools
 Description: Security tools for integrity and trust verification.
 Default Packages:
   -scap-security-guide
 Optional Packages:
   aide
   hmaccalc
   openscap
   openscap-utils
   scap-security-guide-doc
   scap-workbench
   strongimcv
   tncfhh
   tpm-quote-tools
   tpm-tools
   tpm2-tools
   trousers
-- 구성: Mandatory 없음, Default 1 개, Optional 12 개.
-- 패키지 앞 기호
--   =  그룹의 일원으로 설치돼 있음
--   +  다음 group install/update 때 설치될 것
--   -  설치돼 있지 않고 그룹 설치로도 들어오지 않을 것
--   기호 없음 : 그룹과 상관없이 설치돼 있거나 optional
-- scap-security-guide 앞이 - 다.
-- probe 때(mark convert 전)는 + 였다.

--------------------------------------------------------------------------------
 [3] 그룹 설치 — 무엇이 빠지는가
--------------------------------------------------------------------------------

-- mandatory·default 를 설치한다는 그룹 설치를 해 본다.
[root@ol7a ~]# yum group install -y 'Security Tools' 2>&1 | sed -n '/^Installed:/,$p'
-- Installed: 구역이 아예 없다. 아무것도 설치되지 않았다.
[root@ol7a ~]# yum group info 'Security Tools' 2>&1 | sed -n '/Default Packages/,$p'
 Default Packages:
   -scap-security-guide
 Optional Packages:
   aide
   hmaccalc
   openscap
   openscap-utils
   scap-security-guide-doc
   scap-workbench
   strongimcv
   tncfhh
   tpm-quote-tools
   tpm-tools
   tpm2-tools
   trousers
-- 오류 흐름 ① — 그룹 설치를 했는데 아무것도 안 들어옴
-- 증상   : group install 출력에 Installed: 가 없음.
--          group info 의 scap-security-guide 는 여전히 "-"
-- 원인   : mark convert 가 이 그룹을 이미 "설치됨"으로 기록했다.
--          설치된 그룹에서 빠진 default 패키지는 "-"(제외)로 표시되고 group install 이 다시 넣지 않는다. mandatory 가 없는 그룹이라 이 판정이 쉽게 난다.
-- 조치   : 필요한 패키지를 이름으로 설치한다(아래 [4] 의 yum install aide).
--          그룹 단위로 다시 깔려면 yum group remove 뒤 install 하거나 yum group mark remove 로 기록을 지운다.
-- 재확인 : [4] 에서 aide 가 Installed 로 들어옴

--------------------------------------------------------------------------------
 [4] optional 까지 넣으면 — 미리 보기만
--------------------------------------------------------------------------------

-- group_package_types 는 yum.conf(5) 에 있는 지시어다.
-- 그룹 설치 범위를 정하는 설정이 yum.conf 에 있는지 본다.
[root@ol7a ~]# grep group_package_types /etc/yum.conf; echo "grep rc=$?"
grep rc=1
-- 이 설정은 yum.conf 에 직접 넣을 수 있다.
-- 없다. 기본값 mandatory,default 가 적용된다.
[root@ol7a ~]# yum group install --assumeno --setopt=group_package_types=mandatory,default,optional 'Security Tools' 2>&1 | sed -n '/^Transaction Summary/,$p'
-- optional 까지 넣으라고 했지만 Transaction Summary 가 없다.
-- 그룹이 "설치됨" 상태라 새로 설치할 계획을 세우지 않았다.
-- 이 상태에서 group install 은 범위를 넓혀도 같은 결과다.
[root@ol7a ~]# yum install -y aide 2>&1 | sed -n '/^Installed:/,$p'
Installed:
  aide.x86_64 0:0.15.1-13.0.1.el7_9.1                                           

Complete!
-- 그룹과 상관없이 의존성 해석은 평소대로 일어난다.
-- 이름으로 설치하면 바로 들어온다.
-- aide 0.15.1-13.0.1.el7_9.1.
[root@ol7a ~]# yum group info 'Security Tools' 2>&1 | sed -n '/Default Packages/,/hmaccalc/p'
 Default Packages:
   -scap-security-guide
 Optional Packages:
   aide
   hmaccalc
-- 그룹 구성은 그대로다.
-- aide 앞에 기호가 없다.
-- optional 이라 그룹 기록과 무관하다.

 [5] 그룹 제거와 이력
--------------------------------------------------------------------------------

-- group remove 를 하기 전 이력 위치를 확인해 둔다.
-- sed '3,5p' 는 머리 두 줄을 건너뛴 셋째 줄부터. 최신이 위다.
[root@ol7a ~]# yum history list 2>&1 | sed -n '3,5p'
-------------------------------------------------------------------------------
     3 | root <root>              | 2026-11-16 12:20 | Install        |    1   
     2 | root <root>              | 2026-11-11 20:15 | I, U           |  234   
-- 이 다음이 그룹 제거다.
-- 3 번은 aide 하나(Install 1). 그룹 설치는 이력에 남지 않았다.
-- "설치됨" 그룹을 지우면 무엇이 빠지는가.
[root@ol7a ~]# yum group remove -y 'Security Tools' 2>&1 | sed -n '/^Removed:/,$p'
Removed:
  trousers.x86_64 0:0.3.14-2.el7                                                

Dependency Removed:
  cifs-utils.x86_64 0:6.2-10.el7                                                
  gnutls.x86_64 0:3.3.29-9.el7_6                                                
  libwbclient.x86_64 0:4.10.16-25.0.5.el7_9                                     
  samba.x86_64 0:4.10.16-25.0.5.el7_9                                           
  samba-client-libs.x86_64 0:4.10.16-25.0.5.el7_9                               
  samba-common-libs.x86_64 0:4.10.16-25.0.5.el7_9                               
  samba-common-tools.x86_64 0:4.10.16-25.0.5.el7_9                              
  samba-libs.x86_64 0:4.10.16-25.0.5.el7_9                                      

Complete!
-- 오류 흐름 ② — 그룹 제거가 samba 까지 지움
-- 증상   : Removed: trousers, Dependency Removed: cifs-utils, gnutls, samba, samba-libs 등 8 개
-- 원인   : group remove 는 그룹의 일원으로 설치된 패키지를 지운다.
--          trousers(optional)는 gnutls 가 끌고 온 의존 패키지였는데 그룹 일원으로 잡혀 지워졌고, trousers 에 기대는 gnutls·samba 계열이 함께 빠졌다. aide 는 이름으로 넣어 남았다.
-- 조치   : rollback 으로 기준 시점(2 번)으로 되돌린다
-- 재확인 : 아래 rpm -qa 가 557 → 565 운영 서버에서 group remove 는 반드시 --assumeno 로 계획부터 본다.
[root@ol7a ~]# rpm -qa | wc -l; yum history rollback -y $(cat /root/base_tid) 2>&1 | tail -3; rpm -qa | wc -l
557
  trousers.x86_64 0:0.3.14-2.el7                                                

Complete!
565
-- 그룹 제거 전과 같은 수다.
-- 이력은 계속 쌓인다.
-- rollback 도 새 트랜잭션이다(실습 03).
-- 그룹 기록(/var/lib/yum/groups)은 rollback 으로 지워지지 않는다.
-- rollback 이 aide 를 지우고 제거된 9 개를 되살렸다.
-- 565.

 [7] 일부러 낮춘 패키지로 정오표 보기
--------------------------------------------------------------------------------

-- 정오표를 보려면 낮은 판이 필요하다. 그래서 일부러 내린다.
-- 저장소에 있는 sudo 판을 모두 본다.
[root@ol7a ~]# yum --showduplicates list sudo 2>&1 | grep -E '^sudo' | tail -5; yum --showduplicates list sudo 2>&1 | grep -c '^sudo'
sudo.x86_64                   1.8.23-9.el7                           ol7_latest 
sudo.x86_64                   1.8.23-10.el7                          ol7_latest 
sudo.x86_64                   1.8.23-10.el7_9.1                      ol7_latest 
sudo.x86_64                   1.8.23-10.el7_9.2                      ol7_latest 
sudo.x86_64                   1.8.23-10.el7_9.3                      ol7_latest 
12
-- 이번에 내릴 판은 el7_9.1 이다.
-- ol7_latest 에 sudo 가 11 판 + 설치된 줄 1 = 12 줄.
-- 7.0 판부터 모두 쌓아 두는 저장소라 내릴 판을 고를 수 있다.
-- downgrade 는 이름-판 을 지정한다.
-- 의존성이 맞으면 바로 바뀐다.
-- sudo 는 로그인에 쓰이는 패키지라 운영 서버에서는 신중히.
-- 두 판 아래(el7_9.1)로 내린다.
[root@ol7a ~]# yum downgrade -y sudo-1.8.23-10.el7_9.1 2>&1 | sed -n '/^Removed/,$p'
Removed:
  sudo.x86_64 0:1.8.23-10.el7_9.3                                               

Installed:
  sudo.x86_64 0:1.8.23-10.el7_9.1                                               

Complete!
[root@ol7a ~]# rpm -q sudo
sudo-1.8.23-10.el7_9.1.x86_64
-- 판이 두 단계 내려갔다.
-- 1.8.23-10.el7_9.1 로 내려갔다.
-- 다운그레이드도 이력에 남는다.
[root@ol7a ~]# yum updateinfo list security 2>&1 | tail -6
Loaded plugins: langpacks, ulninfo
ELSA-2023-0291 Important/Sec. sudo-1.8.23-10.el7_9.3.x86_64
updateinfo list done
-- 이제 ELSA-2023-0291 한 건이 보인다.
-- 내린 판보다 높은 보안 정오표가 생겼기 때문이다.
-- el7_9.2 판은 보안 정오표가 없어 목록에 없다.
[root@ol7a ~]# yum updateinfo list cves 2>&1 | grep -c CVE; yum updateinfo list --sec-severity=Important 2>&1 | tail -3
1
-- CVE 기준으로 세면 1 건.
Loaded plugins: langpacks, ulninfo
ELSA-2023-0291 Important/Sec. sudo-1.8.23-10.el7_9.3.x86_64
updateinfo list done
-- --sec-severity=Important 로 걸러도 같은 한 건.

 [10] yum-cron 설정 파일
--------------------------------------------------------------------------------

-- yum-cron 은 yum 과 같은 소스 패키지에서 나온다(판 3.4.3).
-- yum-cron 은 ol7_latest 에 있고 기준 상태에는 없다.
[root@ol7a ~]# yum install -y yum-cron 2>&1 | tail -3; rpm -ql yum-cron | grep -E '^/etc'
  yum-cron.noarch 0:3.4.3-168.0.3.el7                                           

Complete!
/etc/cron.daily/0yum-daily.cron
/etc/cron.hourly/0yum-hourly.cron
/etc/yum/yum-cron-hourly.conf
/etc/yum/yum-cron.conf
-- /etc 아래 파일 넷: cron 실행 스크립트 둘(daily·hourly)과 설정 파일 둘(yum-cron.conf·yum-cron-hourly.conf).
[root@ol7a ~]# grep -E '^(update_cmd|update_messages|download_updates|apply_updates|random_sleep|emit_via)' /etc/yum/yum-cron.conf /etc/yum/yum-cron-hourly.conf
/etc/yum/yum-cron.conf:update_cmd = default
/etc/yum/yum-cron.conf:update_messages = yes
/etc/yum/yum-cron.conf:download_updates = yes
/etc/yum/yum-cron.conf:apply_updates = no
/etc/yum/yum-cron.conf:random_sleep = 360
/etc/yum/yum-cron.conf:emit_via = stdio
/etc/yum/yum-cron-hourly.conf:update_cmd = default
/etc/yum/yum-cron-hourly.conf:update_messages = no
/etc/yum/yum-cron-hourly.conf:download_updates = no
/etc/yum/yum-cron-hourly.conf:apply_updates = no
/etc/yum/yum-cron-hourly.conf:random_sleep = 15
/etc/yum/yum-cron-hourly.conf:emit_via = stdio
-- 하루짜리(yum-cron.conf)
--   update_cmd = default       : 모든 업데이트가 대상
--   update_messages = yes      : 업데이트가 있으면 알림
--   download_updates = yes     : 받아 둠
--   apply_updates = no         : 설치는 안 함
--   random_sleep = 360         : 최대 360 분 지연(서버가 몰리지 않게)
--   emit_via = stdio           : 알림은 표준 출력 → cron 메일·로그
-- 한 시간짜리(hourly)는 알림·받기 모두 no. 메타데이터만 갱신한다.
-- 운영 서버라면 update_cmd = minimal-security 같은 값으로 좁힌다.
[root@ol7a ~]# cat /etc/cron.daily/0yum-daily.cron
#!/bin/bash

# Only run if this flag is set. The flag is created by the yum-cron init
# script when the service is started -- this allows one to use chkconfig and
# the standard "service stop|start" commands to enable or disable yum-cron.
if [[ ! -f /var/lock/subsys/yum-cron ]]; then
  exit 0
fi

# Action!
exec /usr/sbin/yum-cron
-- exec 로 yum-cron 을 실행한다.
-- 인자가 없어 yum-cron.conf 를 읽는다.
-- /var/lock/subsys/yum-cron 이 없으면 아무것도 안 하고 끝난다.
-- 이 깃발 파일을 서비스가 만든다(아래).
[root@ol7a ~]# systemctl is-enabled yum-cron; systemctl cat yum-cron | grep -E 'ExecStart|ExecStop|Type'
enabled
Type=oneshot
ExecStart=/bin/touch /var/lock/subsys/yum-cron
ExecStop=/bin/rm -f /var/lock/subsys/yum-cron
-- yum-cron.service 는 oneshot 이다.
-- start 하면 깃발 파일을 만들고 stop 하면 지운다.
-- 실제 일은 cron 이 매일 0yum-daily.cron 으로 한다.
-- 설치 직후 enabled 지만 아직 start 하지 않아 깃발은 없다.
-- 6장의 cron 이 이 스크립트를 언제 부르는지 다룬다.
