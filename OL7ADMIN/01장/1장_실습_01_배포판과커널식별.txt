 대상   : ol7a (기준 상태 ol7-base)
 목표   : 이 서버가 어떤 배포판의 몇 번째 업데이트이고 어떤 커널로 떠 있는지를
          파일·패키지·커널 세 방향에서 확인하고, UEK 와 RHCK 를 이름으로 구분한다

          구분한다. (본문 1.2, 1.3 절)
 소요   : 약 25분
 선행   : ol7a 스냅샷 ol7-base
 계정   : root
 주의   : 조회 위주. [5] 에서 만드는 점검 스크립트 /root/chk_dist.sh 만 지운다
 되돌림 : /root/chk_dist.sh 삭제. `ls -a /root` 가 [0] 과 같으면 끝

 [1] /etc 아래의 release 파일들
--------------------------------------------------------------------------------

-- 배포판 정보는 /etc/*-release 파일에 들어 있다. 몇 개가 있고 어느 것이
-- 실제 파일이고 어느 것이 링크인지 -l 로 본다. 다른 배포판에서 흔한
-- *version 파일도 함께 찾는다.
[root@ol7a ~]# ls -l /etc/*release* /etc/*version*
ls: cannot access /etc/*version*: No such file or directory
-- 첫 줄은 오류다. /etc/*version* 에 맞는 파일이 없어 ls 가 패턴을 그대로 넘겨받고
-- 실패했다. Debian 계열의 /etc/debian_version 같은 파일이 7.9 에는 없다.
-- 오류가 맨 위에 찍힌 것은 stderr 가 버퍼 없이 먼저 나오기 때문이다.
-rw-r--r--. 1 root root  32 Jun 26  2024 /etc/oracle-release
-rw-r--r--. 1 root root 462 Jun 26  2024 /etc/os-release
-rw-r--r--. 1 root root  52 Jun 26  2024 /etc/redhat-release
lrwxrwxrwx. 1 root root  14 Nov 11 20:15 /etc/system-release -> oracle-release
-rw-r--r--. 1 root root  31 Jun 26  2024 /etc/system-release-cpe
-- 열 읽기: 권한, 링크 수, 소유자, 그룹, 크기, 수정 시각, 이름.
--   권한 끝의 '.' 은 SELinux 보안 문맥이 붙은 파일이라는 표시다.
--   oracle-release 32, redhat-release 52 바이트는 한 줄짜리 파일이다.
--   수정 시각 Jun 26 2024 는 패키지 빌드 시점의 시각이 그대로 보존된 것이다.
-- release 파일은 다섯 개. 그중 system-release 만 링크(l)이고 oracle-release 를 가리킨다.
-- 링크의 시각 Nov 11 20:15 는 링크를 만든 시각(패키지 설치 시각)이다.

 [2] 각 release 파일의 내용
--------------------------------------------------------------------------------

-- grep -H . 은 빈 줄이 아닌 모든 줄을 파일 이름과 함께 찍는다.
-- 파일 네 개를 cat 으로 차례로 여는 것보다 어느 줄이 어느 파일 것인지 분명하다.
[root@ol7a ~]# grep -H . /etc/oracle-release /etc/redhat-release /etc/system-release /etc/system-release-cpe
/etc/oracle-release:Oracle Linux Server release 7.9
/etc/redhat-release:Red Hat Enterprise Linux Server release 7.9 (Maipo)
/etc/system-release:Oracle Linux Server release 7.9
/etc/system-release-cpe:cpe:/o:oracle:linux:7:9:server
-- 네 파일이 한 화면에 모였다. 파일 이름이 앞에 붙어 있어 출처가 섞이지 않는다.
--   oracle-release   : Oracle Linux Server release 7.9
--   redhat-release   : Red Hat Enterprise Linux Server release 7.9 (Maipo)
--   system-release   : oracle-release 와 같은 줄(링크라서)
--   system-release-cpe : cpe:/o:oracle:linux:7:9:server — 공급자 oracle, 제품 linux,
--                        버전 7, 업데이트 9, 변형 server
-- OL 서버인데 redhat-release 에는 "Red Hat Enterprise Linux" 와 RHEL 7 의
-- 코드명 Maipo 가 그대로 들어 있다. [5] 의 오판이 여기서 나온다.

 [3] /etc/os-release — 스크립트가 읽으라고 만든 파일
--------------------------------------------------------------------------------

-- systemd 이후 배포판들이 공통으로 두는 형식이다. KEY=값 형태라 셸에서
-- 바로 읽을 수 있다.
[root@ol7a ~]# cat /etc/os-release
NAME="Oracle Linux Server"
VERSION="7.9"
ID="ol"
ID_LIKE="fedora"
VARIANT="Server"
VARIANT_ID="server"
VERSION_ID="7.9"
PRETTY_NAME="Oracle Linux Server 7.9"
ANSI_COLOR="0;31"
CPE_NAME="cpe:/o:oracle:linux:7:9:server"
HOME_URL="https://linux.oracle.com/"
BUG_REPORT_URL="https://github.com/oracle/oracle-linux"

ORACLE_BUGZILLA_PRODUCT="Oracle Linux 7"
ORACLE_BUGZILLA_PRODUCT_VERSION=7.9
ORACLE_SUPPORT_PRODUCT="Oracle Linux"
ORACLE_SUPPORT_PRODUCT_VERSION=7.9
-- 판별에 쓰는 키:
--   ID="ol"            배포판 식별자. 스크립트는 이 값으로 분기한다(RHEL 은 "rhel")
--   VERSION_ID="7.9"   업데이트 번호까지 포함한 버전
--   ID_LIKE="fedora"   비슷한 계열. RHEL 7 의 os-release 와 같은 값이다
--   PRETTY_NAME        사람에게 보이는 이름. hostnamectl 이 이 값을 쓴다
--   CPE_NAME           system-release-cpe 와 같은 값
-- 빈 줄 뒤의 ORACLE_* 네 줄은 Oracle 이 더한 키다. 버그 보고·지원 문의에 쓰는
-- 제품명과 버전이다.
-- [OL8/9] OL8 의 os-release 는 ID_LIKE="fedora" 에 PLATFORM_ID="platform:el8" 이 붙는다.

 [4] 어느 패키지가 이 파일들을 넣었나
--------------------------------------------------------------------------------

-- rpm -qf 는 파일 경로로 소유 패키지를 찾는다(f = file).
[root@ol7a ~]# rpm -qf /etc/oracle-release /etc/redhat-release /etc/os-release /etc/system-release
oraclelinux-release-7.9-1.0.13.el7.x86_64
oraclelinux-release-7.9-1.0.13.el7.x86_64
oraclelinux-release-7.9-1.0.13.el7.x86_64
oraclelinux-release-7.9-1.0.13.el7.x86_64
-- 네 파일 모두 oraclelinux-release 하나가 넣었다. /etc/redhat-release 도 그렇다.
-- 패키지 이름 읽기: 이름 oraclelinux-release, 버전 7.9, 릴리스 1.0.13.el7, 아키텍처 x86_64.
-- redhat-release 라는 이름의 패키지가 따로 깔려 있는지 확인한다.
[root@ol7a ~]# rpm -q oraclelinux-release redhat-release redhat-release-server
oraclelinux-release-7.9-1.0.13.el7.x86_64
package redhat-release is not installed
redhat-release-server-7.9-6.0.1.el7_9.x86_64
-- 결과가 예상과 다르다.
--   redhat-release 라는 패키지는 없다("is not installed").
--   그런데 redhat-release-server 는 설치돼 있다. 릴리스가 6.0.1.el7_9 이다.
--   .0.1 은 Oracle 이 고친 판이라는 표시다. RN79 8장의 Modified 목록에 이 이름이 있다.
-- 파일 /etc/redhat-release 의 주인은 oraclelinux-release 였으니, 이 패키지는
-- 파일이 아니라 "이름"을 맞추려고 있는 쪽이다. 아래에서 확인한다.
-- --whatprovides 는 "이 이름을 제공한다고 선언한 패키지"를 찾는다.
-- 패키지 이름이 아니라 기능(capability) 이름으로 묻는다.
[root@ol7a ~]# rpm -q --whatprovides redhat-release system-release
redhat-release-server-7.9-6.0.1.el7_9.x86_64
redhat-release-server-7.9-6.0.1.el7_9.x86_64
oraclelinux-release-7.9-1.0.13.el7.x86_64
-- 인자 두 개에 줄이 셋 나왔다. 기능 이름 하나를 여러 패키지가 제공할 수 있어서다.
--   redhat-release   → redhat-release-server
--   system-release   → redhat-release-server, oraclelinux-release (둘 다 제공)
-- RHEL 용 패키지가 "Requires: redhat-release" 를 걸어 두어도 OL 에서 의존성이
-- 풀리는 것은 redhat-release-server 가 그 이름을 제공하기 때문이다.
-- --provides 는 반대 방향이다. 패키지가 제공한다고 선언한 이름 목록.
[root@ol7a ~]# rpm -q --provides oraclelinux-release
config(oraclelinux-release) = 7:7.9-1.0.13.el7
oraclelinux-release = 7:7.9-1.0.13.el7
oraclelinux-release(x86-64) = 7:7.9-1.0.13.el7
system-release = 7.9-1.0.13.el7
system-release(releasever) = 7Server
-- oraclelinux-release 가 제공하는 이름은 다섯 개다. redhat-release 는 없다.
--   system-release(releasever) = 7Server — yum 의 $releasever 변수 값이 여기서 나온다.
--   앞의 7: 은 epoch 다. 버전 비교에서 가장 먼저 보는 숫자다.
-- 패키지 머리 정보 중 판별에 쓰는 줄만 고른다. -i 는 info.
[root@ol7a ~]# rpm -qi oraclelinux-release | grep -E '^(Name|Version|Release|Vendor|Packager|Build Date|Install Date|Summary)'
Name        : oraclelinux-release
Version     : 7.9
Release     : 1.0.13.el7
Install Date: Wed 11 Nov 2026 08:15:13 PM KST
Build Date  : Wed 26 Jun 2024 05:30:56 AM KST
Vendor      : Oracle America
Summary     : Oracle Linux 7 release file
-- 판별에 쓰는 필드:
--   Vendor     : Oracle America — 빌드한 주체. RHEL 패키지면 Red Hat, Inc. 가 나온다
--   Build Date : 2024-06-26 — 7.9 출하(2020년) 뒤에도 release 패키지가 다시 빌드됐다
--   Install Date : 2026-11-11 20:15 — 빌드가 2024년이니 2021년 매체에서 왔을
--                  수 없다. 기준 상태를 만든 yum update 로 들어왔다
--   Release    : 1.0.13 — Oracle 판 번호가 13 까지 올라갔다
-- Packager 줄은 이 패키지에 없어서 grep 결과에 빠졌다.

--------------------------------------------------------------------------------
 [5] 오류 재현 — /etc/redhat-release 만 보는 점검 스크립트
--------------------------------------------------------------------------------

-- 다른 배포판용으로 만든 설치 스크립트가 흔히 이렇게 판별한다.
-- 같은 방식의 짧은 스크립트를 만들어 돌려 본다.
[root@ol7a ~]# cat > /root/chk_dist.sh <<'EOF'
#!/bin/bash
if grep -q 'Red Hat Enterprise Linux' /etc/redhat-release; then
    echo "DIST=RHEL $(grep -o '[0-9.]*' /etc/redhat-release)"
else
    echo "DIST=UNKNOWN"
fi
EOF
[root@ol7a ~]# bash /root/chk_dist.sh
DIST=RHEL 7.9
-- 증상   : OL 7.9 서버에서 판별 스크립트가 "DIST=RHEL 7.9" 를 출력했다
-- 원인   : /etc/redhat-release 의 내용이 "Red Hat Enterprise Linux Server release 7.9
--          (Maipo)" 이다. [2] 에서 본 호환용 파일만 읽고 판단했다
-- 조치   : /etc/oracle-release 가 있으면 먼저 OL 로 판별하도록 순서를 바꾼다
-- 재확인 : 같은 스크립트가 "DIST=OL 7.9" 를 출력하는지 본다

-- 판별 순서를 바꾼다. /etc/oracle-release 가 있으면 먼저 그것을 본다.
[root@ol7a ~]# cat > /root/chk_dist.sh <<'EOF'
#!/bin/bash
if [ -f /etc/oracle-release ]; then
    echo "DIST=OL $(grep -o '[0-9.]*' /etc/oracle-release)"
elif grep -q 'Red Hat Enterprise Linux' /etc/redhat-release; then
    echo "DIST=RHEL $(grep -o '[0-9.]*' /etc/redhat-release)"
else
    echo "DIST=UNKNOWN"
fi
EOF
[root@ol7a ~]# bash /root/chk_dist.sh
DIST=OL 7.9
-- 판별 순서만 바꿨는데 결과가 달라졌다. 사용자 공간 프로그램은 대부분 RHEL 로
-- 판별돼도 그대로 돈다. 문제는 커널 모듈을 함께 넣는 제품이다. RHEL 커널
-- 3.10 용 모듈을 UEK 5.4 에 올리려다 실패한다.
-- os-release 의 ID 로 판별해도 된다([변형] 참고).

 [6] uname — 실행 중인 커널
--------------------------------------------------------------------------------

-- -a 는 모든 필드를 한 줄에 붙여 보여 준다.
[root@ol7a ~]# uname -a
Linux ol7a.example.com 5.4.17-2136.338.4.2.el7uek.x86_64 #3 SMP Mon Dec 23 14:42:43 PST 2024 x86_64 x86_64 x86_64 GNU/Linux
-- 한 줄에 아홉 칸이 붙어 있다. x86_64 가 세 번 나오는데 각각 -m, -p, -i 다.
-- 아래에서 옵션별로 떼어 어느 칸이 무엇인지 맞춘다.
-- 필드를 하나씩 떼어 본다. 옵션마다 한 필드다.
--   -s 커널 이름   -n 노드(호스트) 이름   -r 커널 릴리스   -v 커널 빌드 버전
--   -m 하드웨어   -p 프로세서   -i 하드웨어 플랫폼   -o 운영체제
[root@ol7a ~]# for o in s n r v m p i o; do printf -- '-%s  %s\n' $o "$(uname -$o)"; done
-s  Linux
-n  ol7a.example.com
-r  5.4.17-2136.338.4.2.el7uek.x86_64
-v  #3 SMP Mon Dec 23 14:42:43 PST 2024
-m  x86_64
-p  x86_64
-i  x86_64
-o  GNU/Linux
-- 필드 해설:
--   -s Linux               커널 이름. 리눅스면 항상 Linux
--   -n ol7a.example.com    노드 이름. /proc/sys/kernel/hostname 과 같다
--   -r 5.4.17-2136.338.4.2.el7uek.x86_64   커널 릴리스. 이 실습에서 볼 열이다
--   -v #3 SMP Mon Dec 23 14:42:43 PST 2024  같은 릴리스의 3번째 빌드, SMP(다중 CPU)
--                          지원, 빌드 시각(미국 태평양 시각)
--   -m x86_64              하드웨어(머신) 이름
--   -p / -i x86_64         프로세서·플랫폼. 배포판에 따라 unknown 이 나오기도 한다
--   -o GNU/Linux           운영체제 이름
-- uname 은 커널 하나에 대해서만 답한다. 배포판 이름은 어디에도 없다.

--------------------------------------------------------------------------------
 [7] 커널 릴리스 문자열 읽기
--------------------------------------------------------------------------------

-- 같은 값을 /proc 에서도 읽을 수 있다. uname 도 결국 커널이 내주는 값을 읽는다.
-- /proc/version 에는 커널을 빌드한 컴파일러 정보가 더 붙는다.
[root@ol7a ~]# cat /proc/sys/kernel/osrelease; cat /proc/version
5.4.17-2136.338.4.2.el7uek.x86_64
Linux version 5.4.17-2136.338.4.2.el7uek.x86_64 (mockbuild@build-ol7-x86_64.oracle.com) (gcc version 4.8.5 20150623 (Red Hat 4.8.5-39.0.3) (GCC)) #3 SMP Mon Dec 23 14:42:43 PST 2024
-- osrelease 는 uname -r 과 글자 하나 다르지 않다.
-- /proc/version 의 괄호 두 개:
--   mockbuild@build-ol7-x86_64.oracle.com — Oracle 빌드 서버의 mock 계정이 빌드했다
--   gcc 4.8.5 (Red Hat 4.8.5-39.0.3) — OL7 기본 컴파일러. 사용자 공간과 같은 gcc 다.
--   39.0.3 의 .0.3 도 Oracle 수정판 표시다.
-- 릴리스 문자열을 '-' 기준으로 잘라 본다. 앞은 업스트림 버전, 뒤는 배포판 빌드.
[root@ol7a ~]# uname -r | tr '-' '\n'
5.4.17
2136.338.4.2.el7uek.x86_64
-- 앞 5.4.17 : 업스트림 LTS 5.4 의 17번째 안정판 수정을 출발점으로 삼았다
-- 뒤 2136.338.4.2 : Oracle 빌드 번호. 2136 은 UEK R6 안의 업데이트 단위다
-- el7uek : OL7 용 UEK. RHCK 라면 이 자리가 el7 로 끝난다
-- 지금 떠 있는 커널 파일이 어느 패키지 것인지 확인한다.
[root@ol7a ~]# rpm -qf /boot/vmlinuz-$(uname -r)
kernel-uek-5.4.17-2136.338.4.2.el7uek.x86_64
-- 실행 중인 커널 파일의 주인은 kernel-uek 패키지다. $(uname -r) 을 경로에
-- 끼워 넣는 방식은 이후 장에서도 자주 쓴다(/lib/modules/$(uname -r) 등).

 [8] 오류 재현 — uname -r 로 "설치된 커널"을 보려 함

-- 이 서버에 커널이 몇 개 깔려 있는지 알고 싶어 uname -r 을 쳤다고 하자.
[root@ol7a ~]# uname -r
5.4.17-2136.338.4.2.el7uek.x86_64
-- 한 줄이다. 이것을 보고 "이 서버에는 커널이 하나"라고 적으면 틀린다.
-- 커널 패키지는 두 이름으로 나뉜다. 둘 다 물어본다.
[root@ol7a ~]# rpm -q kernel kernel-uek
kernel-3.10.0-1160.el7.x86_64
kernel-3.10.0-1160.119.1.0.5.el7.x86_64
kernel-uek-5.4.17-2102.201.3.el7uek.x86_64
kernel-uek-5.4.17-2136.338.4.2.el7uek.x86_64

--   kernel 3.10.0-1160.el7               설치 매체에서 온 RHCK
--   kernel 3.10.0-1160.119.1.0.5.el7     yum update 로 온 RHCK
--   kernel-uek 5.4.17-2102.201.3.el7uek  설치 매체에서 온 UEK

/boot/vmlinuz-3.10.0-1160.el7.x86_64

-- 증상   : uname -r 이 커널 하나(5.4.17-2136.338.4.2.el7uek.x86_64)만 보였다

 [9] UEK 와 RHCK 를 이름으로 구분
--------------------------------------------------------------------------------

-- 두 커널 패키지의 이름·버전·릴리스와 빌드 시각을 한 줄씩 뽑는다.
-- --qf(queryformat) 는 rpm 머리 태그를 골라 원하는 모양으로 찍는다.
--   %-11{NAME}  이름을 왼쪽 정렬 11칸   %{BUILDTIME:date}  빌드 시각을 날짜로
[root@ol7a ~]# rpm -q --qf '%-11{NAME} %{VERSION}-%{RELEASE}  %{BUILDTIME:date}\n' kernel kernel-uek
kernel      3.10.0-1160.el7  Fri 02 Oct 2020 09:36:15 AM KST
kernel      3.10.0-1160.119.1.0.5.el7  Mon 30 Sep 2024 12:53:44 PM KST
kernel-uek  5.4.17-2102.201.3.el7uek  Sat 24 Apr 2021 01:14:12 AM KST
kernel-uek  5.4.17-2136.338.4.2.el7uek  Tue 24 Dec 2024 07:51:32 AM KST
-- 이름 끝과 빌드 시각으로 네 커널을 줄 세운다.
--   RHCK 1160          2020-10-02  7.9 출하 시점
--   RHCK 1160.119.1.0.5 2024-09-30  업데이트판. .0.5 가 Oracle 판 번호
--   UEK 2102.201.3     2021-04-24  설치 매체 재빌드 시점
--   UEK 2136.338.4.2   2024-12-24  공개 저장소의 마지막 UEK 업데이트 무렵
-- 빌드 시각이 KST 로 바뀌어 찍힌다. uname -v 의 PST 시각(12-23 14:42)과
-- 몇 시간 차이가 나는 것은 커널 컴파일과 rpm 포장 시점이 달라서다.
-- 모듈 디렉터리도 커널마다 따로 있다.
[root@ol7a ~]# ls -1 /lib/modules/
3.10.0-1136.0.0.0.1.el7.x86_64
3.10.0-1160.119.1.0.5.el7.x86_64
3.10.0-1160.el7.x86_64
5.4.17-2102.201.3.el7uek.x86_64
5.4.17-2136.338.4.2.el7uek.x86_64
-- 디렉터리가 다섯 개다. 커널 패키지 네 개와 짝이 맞는 것 넷, 그리고
-- 3.10.0-1136.0.0.0.1.el7.x86_64 하나가 더 있다. 그런 커널 패키지는 없다.
-- 주인은 실습 03 의 [8] 에서 찾는다(kmod-kvdo 패키지).
-- 실행 중인 커널 이름에 uek 가 들어 있는지로 판별하는 한 줄.
[root@ol7a ~]# case $(uname -r) in *uek*) echo "UEK 로 부팅됨";; *) echo "RHCK 로 부팅됨";; esac
UEK 로 부팅됨
-- case 의 *uek* 패턴은 릴리스 문자열 어디에든 uek 가 있으면 맞는다.
-- 운영 스크립트에서 커널별로 모듈 경로나 파라미터를 다르게 줄 때 이 형태를 쓴다.

 [변형] 같은 판별을 다른 도구로
--------------------------------------------------------------------------------

-- os-release 를 셸 변수로 읽어 들인다(. 은 source 와 같다).
[root@ol7a ~]# . /etc/os-release; echo "ID=$ID VERSION_ID=$VERSION_ID ID_LIKE=\"$ID_LIKE\""
ID=ol VERSION_ID=7.9 ID_LIKE="fedora"
-- os-release 는 셸 문법 그대로라 source 하면 변수가 된다. 스크립트에서는
-- 하위 셸에서 읽어 현재 셸의 변수를 덮어쓰지 않게 한다: ( . /etc/os-release; echo $ID )
-- 7.9 의 기본 Python 2.7 이 배포판을 어떻게 판별하는지 본다.
[root@ol7a ~]# python -V; python -c 'import platform; print(platform.linux_distribution())'
Python 2.7.5
('Oracle Linux Server', '7.9', '')
-- Python 2.7.5 의 platform 모듈은 OL 을 제대로 판별했다. 세 번째 값(코드명)은 비어 있다.
-- RHEL 이라면 'Maipo' 가 들어간다.
-- [OL8/9] Python 3.8 이후 platform.linux_distribution() 은 없어졌다. OL8/9 에서는
--         /etc/os-release 를 읽는 distro 모듈이나 platform.freedesktop_os_release() 를 쓴다.
-- systemd 쪽 판별.
[root@ol7a ~]# hostnamectl status | grep -E 'Operating System|CPE OS Name|Kernel'
  Operating System: Oracle Linux Server 7.9
       CPE OS Name: cpe:/o:oracle:linux:7:9:server
            Kernel: Linux 5.4.17-2136.338.4.2.el7uek.x86_64
-- 세 도구 모두 "Oracle Linux Server 7.9" 로 답했다. RHEL 로 오판한 것은
-- [5] 의 손으로 짠 스크립트뿐이다.
