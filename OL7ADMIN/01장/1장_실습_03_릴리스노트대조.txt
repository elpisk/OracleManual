 [3] RN79 4장 — Btrfs 는 RHCK 에서 deprecated
--------------------------------------------------------------------------------

-- 4-1쪽: "Starting with Oracle Linux 7.4, the Btrfs file system type is
-- deprecated in RHCK ... fully supported with UEK R4 and later"
-- 두 커널의 btrfs 모듈 정보를 비교한다. -k 는 대상 커널 버전을 지정한다.
-- 실행 중이 아닌 커널의 모듈도 이렇게 조회할 수 있다.
[root@ol7a ~]# modinfo -k 3.10.0-1160.119.1.0.5.el7.x86_64 btrfs | grep -E '^(filename|description|rhelversion|srcversion|depends)'
filename:       /lib/modules/3.10.0-1160.119.1.0.5.el7.x86_64/kernel/fs/btrfs/btrfs.ko.xz
rhelversion:    7.9
srcversion:     3EE61DD3C285C3EBE5F29CC
depends:        raid6_pq,xor
-- RHCK 쪽:
--   filename    .ko.xz — xz 로 압축된 모듈 파일
--   rhelversion 7.9 — RHCK 모듈에만 붙는 필드. UEK 에는 없다
--   srcversion  소스 해시. 같은 소스면 같은 값
--   depends     먼저 올라가야 하는 모듈
-- description 줄은 btrfs 모듈에 없어서 grep 결과에 없다.
[root@ol7a ~]# modinfo -k 5.4.17-2136.338.4.2.el7uek.x86_64 btrfs | grep -E '^(filename|description|srcversion|depends)'
filename:       /lib/modules/5.4.17-2136.338.4.2.el7uek.x86_64/kernel/fs/btrfs/btrfs.ko.xz
srcversion:     A99FF3D2F2142CECC2D3FE8
depends:        libcrc32c,zstd_compress,zstd_decompress,raid6_pq,xor
-- UEK 쪽은 depends 에 zstd_compress·zstd_decompress 가 더 있다.
-- zstd 압축을 지원하는 Btrfs 라는 뜻이다. 3.10 의 Btrfs 에는 없다.
-- srcversion 도 다르다. 이름은 같은 btrfs 지만 전혀 다른 코드다.
-- modinfo 는 "모듈이 있다"는 것만 보여 준다. deprecated(지원 중단 예고)
-- 여부는 모듈이 아니라 릴리스 노트에서 확인한다.
-- 같은 이름의 모듈이 두 커널에서 어디에 있는지 파일로도 본다.
[root@ol7a ~]# ls -l /lib/modules/*/kernel/fs/btrfs/
/lib/modules/3.10.0-1160.119.1.0.5.el7.x86_64/kernel/fs/btrfs/:
total 440
-rw-r--r--. 1 root root 447680 Sep 30  2024 btrfs.ko.xz

/lib/modules/3.10.0-1160.el7.x86_64/kernel/fs/btrfs/:
total 424
-rw-r--r--. 1 root root 433940 Oct  2  2020 btrfs.ko.xz

/lib/modules/5.4.17-2102.201.3.el7uek.x86_64/kernel/fs/btrfs/:
total 480
-rw-r--r--. 1 root root 488364 Apr 24  2021 btrfs.ko.xz

/lib/modules/5.4.17-2136.338.4.2.el7uek.x86_64/kernel/fs/btrfs/:
total 544
-rw-r--r--. 1 root root 556644 Dec 24  2024 btrfs.ko.xz
-- 네 커널 모두 btrfs.ko.xz 가 있다. 크기는 RHCK 434~448KB,
-- UEK 488~557KB. 날짜는 각 커널의 빌드 날짜와 같다.
-- 3.10.0-1136.0.0.0.1 디렉터리는 와일드카드에 걸리지 않았다. 그 안에
-- kernel/fs 가 없기 때문이다([8] 에서 확인).

 [5] RN79 5장 Known Issues — DB 서버에 걸리는 항목
--------------------------------------------------------------------------------

-- 5-6쪽: "Database installation and operation fails if RemoveIPC=yes is
-- configured for systemd". 이 서버의 logind 설정을 본다.
[root@ol7a ~]# grep -n RemoveIPC /etc/systemd/logind.conf
33:#RemoveIPC=no
36:RemoveIPC=no
-- 33 행은 주석(기본값 안내), 36 행이 실제 설정이다. RemoveIPC=no 가
-- 들어 있다. 문서가 말한 대로 7.9 는 이 값을 기본으로 넣는다.
-- yes 이면 사용자가 마지막 세션에서 로그아웃할 때 그 사용자의 공유
-- 메모리·세마포어를 지운다. oracle 계정의 SGA 가 사라지는 결과가 된다.
-- 같은 쪽: 업그레이드한 시스템에서는 logind.conf.rpmnew 가 생기고 값이 안 들어갈
-- 수 있다고 적는다. .rpmnew 파일이 있는지 본다.
[root@ol7a ~]# ls -l /etc/systemd/logind.conf*
-rw-r--r--. 1 root root 997 Oct 10  2024 /etc/systemd/logind.conf
-- .rpmnew 파일은 없다. 설정 파일을 고친 적이 없어 업데이트가 그대로
-- 덮어썼다. 날짜 Oct 10 2024 는 업데이트된 systemd 패키지의 빌드 시점이다.
-- 운영 서버에서 이 파일을 고친 적이 있다면 업데이트 뒤 .rpmnew 가 생기고
-- RemoveIPC=no 가 빠질 수 있다. DB 서버 점검 항목이다(17장).
-- 5-12쪽: "Power button defaults to ACPI Suspend mode" 와 관련된 설정.
[root@ol7a ~]# grep -n HandlePowerKey /etc/systemd/logind.conf
21:#HandlePowerKey=poweroff
-- 주석 처리된 기본값은 poweroff 다. 문서의 "ACPI Suspend" 항목은 GNOME
-- 데스크톱 설정(dconf)의 동작이라고 적혀 있다. GUI 를 깔지 않은 ol7a 에서는
-- logind 의 이 값이 전원 버튼 동작을 정한다.
