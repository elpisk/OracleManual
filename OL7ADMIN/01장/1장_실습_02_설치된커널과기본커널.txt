================================================================================
 제1장 실습 02 — 설치된 커널과 기본 커널
 대상   : ol7a (기준 상태 ol7-base)
 목표   : 설치된 커널 목록, /boot 의 파일 짝, GRUB 항목 순서, 기본 부팅 커널이
          어디에 기록되는지를 확인한다. 설치 매체에서 온 커널과 업데이트로 온
          커널을 설치 시각으로 가른다
 배경   : 커널 패키지는 덮어쓰지 않고 나란히 설치된다(installonly). 커널 하나는
          /boot 에 vmlinuz·initramfs·config·System.map 네 파일을 짝으로 둔다.
          부팅할 커널은 GRUB 2 의 saved_entry(grubenv)가 정하고, grubby 가
          그 값을 읽고 바꾼다. /etc/sysconfig/kernel 의 DEFAULTKERNEL 이 새 커널
          설치 때 기본값을 넘길지 정한다. (본문 1.3.5 절, 변경 절차는 3장)
 소요   : 약 35분
 선행   : ol7a 스냅샷 ol7-base
 계정   : root, student
 주의   : [5] 에서 RHCK(3.10.0-1160.el7)의 initramfs 를 옮겼다가 dracut 으로
          다시 만든다. 기본 커널(UEK)과 GRUB 설정은 건드리지 않는다
 되돌림 : /root 에 옮긴 initramfs 를 지운다. `ls /boot | wc -l` 과
          `grubby --default-kernel` 이 [0] 과 같으면 끝

-- grubby 는 grub.cfg 를 직접 고치지 않고 항목을 조회·변경하는 도구다.
--   --default-kernel  기본 항목의 커널 경로
--   --default-index   기본 항목의 번호(0부터)
--   --default-title   기본 항목의 메뉴 제목
[root@ol7a ~]# grubby --default-kernel; grubby --default-index; grubby --default-title
/boot/vmlinuz-5.4.17-2136.338.4.2.el7uek.x86_64
0
Oracle Linux Server 7.9, with Unbreakable Enterprise Kernel 5.4.17-2136.338.4.2.el7uek.x86_64

-- 제목은 "배포판, with 커널 종류 버전".

 [5] 오류 재현 — initramfs 가 없는 커널 항목
--------------------------------------------------------------------------------

-- 누군가 /boot 를 정리하다 RHCK 의 initramfs 를 옮겨 버린 상황을 만든다.
[root@ol7a ~]# mv /boot/initramfs-3.10.0-1160.el7.x86_64.img /root/
-- GRUB 메뉴 쪽에서는 아무 일도 없어 보인다.
[root@ol7a ~]# grubby --info=/boot/vmlinuz-3.10.0-1160.el7.x86_64 | grep -E '^(index|kernel|initrd)'
index=3
kernel=/boot/vmlinuz-3.10.0-1160.el7.x86_64
initrd=/boot/initramfs-3.10.0-1160.el7.x86_64.img
-- 파일을 치웠는데 grubby 는 그대로
-- initrd 경로를 보여 준다. grubby 는
-- grub.cfg 의 글자만 읽는다.
-- 항목마다 initrd 파일이 실제로 있는지 따져 보는 점검 루프.
[root@ol7a ~]# for k in $(grubby --info=ALL | sed -n 's/^initrd=//p'); do [ -f "$k" ] && echo "OK      $k" || echo "MISSING $k"; done
OK      /boot/initramfs-5.4.17-2136.338.4.2.el7uek.x86_64.img
OK      /boot/initramfs-5.4.17-2102.201.3.el7uek.x86_64.img
OK      /boot/initramfs-3.10.0-1160.119.1.0.5.el7.x86_64.img
MISSING /boot/initramfs-3.10.0-1160.el7.x86_64.img
OK      /boot/initramfs-0-rescue-b8658360b45f49fe8174bcd0b610ae6e.img
-- 점검 루프는 잡았다.
--   MISSING .../initramfs-3.10.0-1160.el7
-- grubby 의 initrd= 줄을 꺼내 [ -f ]
-- 로 하나씩 존재를 확인한 결과다.
-- 커널 패키지 검증으로도 잡히는지 본다. -V 는 rpm 이 기록한 파일 속성과 비교한다.
[root@ol7a ~]# rpm -V kernel-3.10.0-1160.el7; echo "rc=$?"
.......T.    /etc/ld.so.conf.d/kernel-3.10.0-1160.el7.x86_64.conf
rc=1
-- rc=1 이지만 initramfs 때문이 아니다.
-- 보고된 줄은 ld.so.conf.d 의 conf 하나.
-- 9칸 표시 중 T 는 수정 시각만 다름.
-- 없어진 파일이면 "missing" 이 찍힌다.
-- initramfs 는 아무 말이 없다.
-- rpm 이 이 파일을 어떻게 기록했는지 본다.
-- --dump 열: 경로 크기 시각 해시 권한…

-- initramfs 는 rpm 이 풀어 놓는 파일이 아니라 설치 후 스크립트(dracut)가 만든다.

 [10] rescue 항목의 정체
--------------------------------------------------------------------------------

-- GRUB 메뉴 맨 끝의 rescue 항목은 어떤 커널인가. 파일 이름에 버전이 없다.
[root@ol7a ~]# ls -l /boot/*rescue*
-rw-------. 1 root root 68822193 Nov 11 19:47 /boot/initramfs-0-rescue-b8658360b45f49fe8174bcd0b610ae6e.img
-rwxr-xr-x. 1 root root  6771656 Nov 11 19:47 /boot/vmlinuz-0-rescue-b8658360b45f49fe8174bcd0b610ae6e
-- rescue initramfs 68.8M, 다른 것의
-- 세 배다. 시각은 설치 때(19:47).
-- 크기가 같은 커널 이미지를 찾아 내용까지 같은지 cmp 로 비교한다.
-- cmp 는 같으면 아무것도 출력하지 않고 종료 코드 0 을 낸다.
[root@ol7a ~]# for f in /boot/vmlinuz-[0-9]*; do cmp -s /boot/vmlinuz-0-rescue-* $f && echo "same as $f"; done
same as /boot/vmlinuz-0-rescue-b8658360b45f49fe8174bcd0b610ae6e
same as /boot/vmlinuz-3.10.0-1160.el7.x86_64
-- 첫 줄은 자기 자신과 비교한 것이다
-- (vmlinuz-0-rescue 도 [0-9] 로 시작).
-- 두 번째 줄이 답이다. rescue 커널은
-- 설치 매체의 RHCK 1160 사본이다.
-- rescue initramfs 는 호스트 전용(hostonly)이 아니라 범용으로 만들어 크다.
[root@ol7a ~]# lsinitrd /boot/initramfs-0-rescue-*.img | grep -m1 -i 'hostonly'; lsinitrd /boot/initramfs-5.4.17-2136.338.4.2.el7uek.x86_64.img | grep -m1 -i 'hostonly'
Arguments: --no-hostonly -a 'rescue'
-- rescue 는 --no-hostonly 로 만들었다.
-- 이 서버에 없는 드라이버까지 넣은
-- 범용판이라 크다. 두 번째 명령은
-- 아무것도 찍지 않았다. 일반 initramfs
-- 는 기본값 hostonly 로 만들어
-- Arguments 에 그 단어가 없다.
