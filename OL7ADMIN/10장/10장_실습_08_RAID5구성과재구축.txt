 제10장 실습 08 — RAID 5 구성과 재구축: 디스크 장애, 교체, mdadm.conf 없는 재부팅
 대상   : ol7a
 목표   : mdadm 으로 RAID 5 를 만들고 /proc/mdstat 과 mdadm --detail 을 필드
          단위로 읽는다. 디스크 하나를 fail·remove 하고 새 디스크로 재구축하는
          동안 데이터가 살아 있는지 확인한다. 빼낸 디스크에 남은 슈퍼블록,
          mdadm.conf 없이 재부팅했을 때 배열 이름이 어떻게 되는지 본다
 배경   : RAID 5 는 디스크 N 개 중 하나 몫을 패리티로 써서 한 개 장애를
          견딘다. 장애가 나면 degraded 상태로 계속 동작하고, 새 디스크를
          넣으면 나머지 디스크와 패리티로 내용을 다시 계산해 채운다(재구축).
          배열 구성은 각 디스크의 md 슈퍼블록에 있고, /etc/mdadm.conf 는
          부팅 때 어떤 이름으로 조립할지를 정한다 (본문 10.8, 10.9)
 소요   : 약 40분 (재부팅 두세 번 포함)
 선행   : storage-clean 스냅샷
 계정   : root
 주의   : sdb~sde 네 디스크를 모두 쓴다. 재부팅 전에 RAID 를 fstab 에 넣지 않는다
 되돌림 : 배열 정지, 슈퍼블록 삭제, mdadm.conf 삭제. 확인은 cat /proc/mdstat
          (배열 없음), lsblk (sdb~sde 비어 있음)

 [1] RAID 5 만들기 — 작게, 그리고 천천히
--------------------------------------------------------------------------------
-- 10G 디스크 셋을 다 쓰면 초기 동기화가 길다.
-- --size 로 디스크마다 1GiB 만 쓰고,
-- 진행 모습을 볼 수 있게 speed_limit_max
-- 를 잠시 20000(약 20MB/s)으로 낮춘다.
[root@ol7a ~]# echo 20000 > /proc/sys/dev/raid/speed_limit_max
-- --create /dev/md0 : 만들 배열 장치
-- --level=5 : RAID 레벨,
-- --raid-devices=3 : 활성 디스크 수
-- --size=1G : 디스크마다 쓸
-- 크기(생략하면 가장 작은 디스크 전체)
-- --run : "계속할까요" 질문 없이 바로 시작
[root@ol7a ~]# mdadm --create /dev/md0 --level=5 --raid-devices=3 --size=1G --run /dev/sdb /dev/sdc /dev/sdd
mdadm: largest drive (/dev/sdb) exceeds size (1048576K) by more than 1%
mdadm: Defaulting to version 1.2 metadata
mdadm: array /dev/md0 started.
-- 첫 줄 : 디스크(10G)가 --size(1G)보다
-- 1% 넘게 크다는 알림. 의도한 것이다
-- 둘째 줄 : 슈퍼블록 형식 1.2 (디스크 앞쪽 4KiB 지점)
[root@ol7a ~]# cat /proc/mdstat

      2097152 blocks super 1.2 level 5, 512k chunk, algorithm 2 [3/2] [UU_]
      [>....................]  recovery =  1.9% (20480/1048576) finish=0.8min speed=20480K/sec
-- 필드 해설
--   Personalities [raid6] [raid5] [raid4] :
--   raid456 모듈이 올라옴
--   md0 : active raid5 : 동작 중, 레벨 5
--   sdd[3] sdc[1] sdb[0] : 디스크와 역할 번호
--   2097152 blocks : 쓸 수 있는 크기
--   2GiB (1G × 3 - 패리티 1개분)
--   512k chunk, algorithm 2 : 청크 크기,
--   패리티 배치(left-symmetric)
--   [3/2] [UU_] : 필요 3,
--   동작 2, 세 번째가 아직 채워지는 중
--   recovery 1.9%, speed=20480K/sec :
--   max 20000 근처로 묶여 있다

unused devices: <none>

unused devices: <none>

-- mkfs.xfs 는 md 장치의 청크·스트라이프
-- 폭을 읽어 sunit·swidth 를 맞춘다.
[root@ol7a ~]# mkfs.xfs /dev/md0
log stripe unit (524288 bytes) is too large (maximum is 256KiB)
log stripe unit adjusted to 32KiB
meta-data=/dev/md0               isize=256    agcount=8, agsize=65408 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=0        finobt=0, sparse=0, rmapbt=0
         =                       reflink=0
data     =                       bsize=4096   blocks=523264, imaxpct=25
         =                       sunit=128    swidth=256 blks
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=2560, version=2
         =                       sectsz=512   sunit=8 blks, lazy-count=1
realtime =none                   extsz=4096   blocks=0, rtextents=0
-- 앞 두 줄 : 로그 stripe unit 이 512KiB
-- 라 최대값을 넘어 32KiB 로 줄였다는 알림
-- data 의 sunit=128
-- swidth=256 블록(4KiB)
--   sunit 128 × 4KiB = 512KiB = 청크 크기
--   swidth 256 = 데이터 디스크 2개 × sunit
-- mkfs.xfs 가 md 의 구조를 읽어 맞췄다.
-- LVM 을 끼우면 이 값을 손으로 줘야 할 때가 있다
[root@ol7a ~]# mkdir -p /data/raid; mount /dev/md0 /data/raid
[root@ol7a ~]# cp -a /usr/share/doc /data/raid/; dd if=/dev/urandom of=/data/raid/f1 bs=1M count=300 status=none
[root@ol7a ~]# md5sum /data/raid/f1 | tee /root/f1.md5; df -hT /data/raid
83c77fcb09c6cbd7b6410bdebf5756d5  /data/raid/f1
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/md0       xfs   2.0G  400M  1.6G  20% /data/raid
-- 체크섬을 /root 에 저장. 사용량 400M

 [7] 빼고 새 디스크로 재구축

-- --remove : 고장 표시된 디스크를
-- 배열에서 뺀다(물리 교체 전 단계)
[root@ol7a ~]# mdadm /dev/md0 --remove /dev/sdc
mdadm: hot removed /dev/sdc from /dev/md0
-- 물리 디스크를 빼기 전 단계. 서버를 끄지 않는다(hot)
-- 재구축을 빨리 끝내려고 이번에는 speed_limit_min 을 올린다.
-- 다른 I/O 가 있어도 이 속도는 낸다.
[root@ol7a ~]# echo 100000 > /proc/sys/dev/raid/speed_limit_min
-- 교체 디스크 sde 를 넣는다.
-- 배열이 degraded 라 바로 재구축이 시작된다.
[root@ol7a ~]# mdadm /dev/md0 --add /dev/sde

-- 조치   : --remove sdc → --add sde. 넣자마자 recovery 시작

 [정리] 관찰 요약
--------------------------------------------------------------------------------
--  항목              시작 전   작업 중                                     되돌린 뒤
--  배열              없음      md0 raid5 [3/3] → [3/2] [U_U] → [3/3]        없음
--  구성원            -         sdb·sdc·sdd → sdb·sde·sdd → sdc·sde·sdd      -
--  Events            -         18 → 40                                     -
--  재구축 속도       -         20 MB/s(max 20000) / 200 MB/s(min 100000)   -
--  f1 체크섬         -         83c77fcb... 끝까지 OK                        -
--  mdadm.conf        없음      ARRAY /dev/md0 ... UUID=837ac89c...         없음
--  speed_limit       1000/200000  바꿨다 되돌림                             1000/200000
-- 오류
--   디스크 장애      : [U_U] degraded → remove·add → [UUU]
--   빼낸 디스크 재사용 : excluded by a filter → --zero-superblock
--   md127            : 재현 안 됨(같은 호스트의 배열은 이름 유지)
