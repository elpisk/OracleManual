 제10장 실습 07 — snapper 와 thin LV: 변경 전후 스냅샷을 비교하고 되돌리기
 대상   : ol7a
 목표   : snapper 를 설치해 thin LV 위 XFS 에 구성(create-config)을 만들고
          구성 파일·권한(ALLOW_USERS)·timeline 설정을 읽는다. thin 이 아닌 LV 의
          거부와, 7.9 기본 상태(SELinux enforcing)에서 스냅샷 생성이 막히는
          원인을 로그로 찾는다. snapper 가 하려던 일(thin 스냅샷·비교·되돌리기)을
          LVM 명령으로 직접 해 보다가 읽기 전용 XFS 스냅샷 마운트에서 막히는 지점을 본다
 배경   : snapper 는 thin 스냅샷(또는 Btrfs 서브볼륨 스냅샷)을 번호로 관리하는
          도구다. 스냅샷 자체는 LVM 이 만들고, snapper 는 그것을 .snapshots
          아래 info.xml 에 번호·설명을 적고 파일 단위로 비교·복원한다. 설정 변경
          앞뒤로 pre·post 를 찍어 두는 용도에 맞다 (본문 10.7)
 소요   : 약 25분
 선행   : storage-clean 스냅샷, 인터넷(yum.oracle.com)
 계정   : root, student
 주의   : snapper 패키지를 설치한다(스냅샷 복귀로 사라짐). sdb 의 내용을 지운다
 되돌림 : snapper delete-config, LV·VG·PV 삭제, yum remove snapper.
          확인은 snapper list-configs, vgs, rpm -q snapper

 [3] thin 이 아닌 LV 에 구성하면
--------------------------------------------------------------------------------

-- -c 이름 : 구성 이름. create-config -f "lvm(xfs)" 마운트지점 : LVM 백엔드, XFS
[root@ol7a ~]# snapper -c plain create-config -f "lvm(xfs)" /data/plain
Creating config failed (invalid filesystem type).

-- 증상   : "Creating config failed (invalid filesystem type)."
-- 원인   : lvm(xfs) 백엔드는 thin LV 의 스냅샷을 쓴다. lvplain 은 thin 이 아니다
--          메시지는 파일 시스템 종류를 탓하지만 XFS 는 맞다. LV 종류가 문제다
-- 구성이 만들어졌는지 목록으로 본다
[root@ol7a ~]# snapper list-configs
Config | Subvolume
-------+----------
-- 구성 없이 스냅샷을 만들어 본다. -d : 설명
[root@ol7a ~]# snapper -c plain create -d test
Unknown config.
-- list-configs 에 plain 이 없다. 구성이 아예 만들어지지 않았다
-- 그래서 -c plain 으로 무엇을 해도 Unknown config. 이다
-- 조치   : thin LV(lvthin)의 마운트 지점에 구성을 만든다([4])

-- 같은 형식으로 thin LV 의 마운트 지점에 구성을 만든다

[root@ol7a ~]# grep -v '^#' /etc/snapper/configs/app | grep -v '^$'

TIMELINE_LIMIT_MONTHLY="10"

-- 구성 파일 필드(주석 뺀 20줄)
--   SUBVOLUME, FSTYPE : 대상과 백엔드 lvm(xfs)
--   ALLOW_USERS, ALLOW_GROUPS : 조회·생성을 허용할 일반 사용자(비어 있음)
--   NUMBER_* : 번호 기준 정리. 최대 50개, 중요 표시 10개
--   TIMELINE_CREATE="yes" : 매시간 자동 스냅샷
--   TIMELINE_LIMIT_* : 시간·일·주·월·년 단위 보관 개수
--   EMPTY_PRE_POST_CLEANUP : 바뀐 것이 없는 pre·post 쌍은 지운다
--   *_MIN_AGE 1800 : 30분이 지나야 정리 대상

 [6] 원인 찾기 — snapper 로그와 감사 로그

-- snapperd 가 친 LVM 명령 셋(150자에서 잘랐다)
--   1) lvs -o lv_attr,segtype : 대상이 thin 인지 확인
--   2) lvcreate --permission r --snapshot --name 'lvthin-snapshot1' : 스냅샷 생성
--   3) lvremove --force : 방금 만든 스냅샷 삭제
-- 만들기는 성공했다. 그 뒤 어떤 단계가 실패해 되돌렸다
-- snapper 가 만든 스냅샷 LV 가 남았는지 본다
[root@ol7a ~]# lvs -o lv_name,lv_attr,origin vgdata
  LV      Attr       Origin
  lvplain -wi-ao----       
  lvthin  Vwi-aotz--       
  tpool   twi-aotz--       
-- lvthin-snapshot1 은 남아 있지 않다

-- 스냅샷 LV 는 만들어졌다가 지워졌다. 그 사이에 무엇이 실패했는지 커널 감사 로그를 본다.
[root@ol7a ~]# ausearch -m avc -ts recent 2>&1 | grep -o 'avc: .*' | tail -2 | cut -c1-200
avc:  denied  { create } for  pid=2318 comm="snapperd" name="info.xml.tmp-CLJp3T" scontext=system_u:system_r:snapperd_t:s0-s0:c0.c1023 tcontext=system_u:object_r:default_t:s0 tclass=file permissive=0

-- 감사 로그의 한 줄
--   denied { create }   : 파일 생성 거부
--   comm="snapperd"     : 거부된 주체는 데몬
--   name="info.xml.tmp-…" : 스냅샷 기록 파일의 임시 이름
--   tcontext ...default_t : 만들려던 곳(.snapshots/1)의 형식
--   permissive=0        : 실제로 막았다
-- -Z : SELinux 보안 문맥(사용자:역할:형식:수준).
-- getenforce : 현재 모드
[root@ol7a ~]# ls -Zd /data/app/.snapshots; getenforce
drwxr-x---. root root system_u:object_r:default_t:s0   /data/app/.snapshots
Enforcing
-- .snapshots 의 형식이 default_t,
-- SELinux 는 Enforcing(7.9 설치 기본값)
-- 원인   : 새로 만든 마운트 지점(/data/app) 아래는 snapperd 가 쓸 수 있는 형식이 아니다
--          snapperd 가 info.xml 을 쓰지 못해 스냅샷을 지우고 IO Error 를 냈다
-- 이 과정은 SELinux 설정을 다루지 않는다.
-- 우회(setenforce 0)도 하지 않는다

 [8] 자동 생성(timeline) 설정
--------------------------------------------------------------------------------

-- 구성을 만들면 기본으로 매시간 timeline 스냅샷을 찍으려 한다. 끈다.
[root@ol7a ~]# grep -E 'TIMELINE_(CREATE|CLEANUP)|NUMBER_LIMIT=' /etc/snapper/configs/app
NUMBER_LIMIT="50"
TIMELINE_CREATE="yes"
TIMELINE_CLEANUP="yes"

-- 기본값 : NUMBER_LIMIT 50,
-- TIMELINE_CREATE yes, TIMELINE_CLEANUP yes
-- 풀이 작은 thin 환경에서는 매시간 스냅샷이 풀을 채운다. 끄는 것이 안전하다
[root@ol7a ~]# snapper -c app set-config TIMELINE_CREATE=no; grep TIMELINE_CREATE /etc/snapper/configs/app
TIMELINE_CREATE="no"

-- set-config 로 바꾸면 파일이 바로 고쳐진다. vi 로 고쳐도 결과는 같다
[root@ol7a ~]# ls /etc/cron.hourly/ /etc/cron.daily/ | grep snapper; grep -v '^#' /etc/cron.hourly/snapper | grep -v '^$' | head -6
snapper
snapper
umask 022
PATH=/sbin:/bin:/usr/sbin:/usr/bin
export PATH
if [ -f /etc/sysconfig/snapper ] ; then
-- cron.hourly 와 cron.daily 에 snapper 가 하나씩(6장에서 본 run-parts 가 돌린다)
-- 스크립트는 /etc/sysconfig/snapper 를 읽어 구성마다 timeline 을 만든다
-- TIMELINE_CREATE=no 인 구성은 건너뛴다.
-- 이 VM 에서는 어차피 [5] 와 같은 이유로 실패한다
    . /etc/sysconfig/snapper
fi

[root@ol7a ~]# lvcreate -s --permission r -n lvthin-pre vgdata/lvthin

[root@ol7a ~]# lvs -o lv_name,lv_attr,origin,pool_lv vgdata
  LV         Attr       Origin Pool 
  lvplain    -wi-ao----             
  lvthin     Vwi-aotz--        tpool
  lvthin-pre Vri---tz-k lvthin tpool
  tpool      twi-aotz--             
-- lvthin-pre 의 Attr Vri---tz-k
--   V : thin LV, r : 읽기 전용(--permission r)
--   다섯째 '-' : 비활성, 열째 k : 활성화 건너뛰기
-- Origin lvthin, Pool tpool. 같은 풀에서 블록을 공유한다

[root@ol7a ~]# echo "port=1522" > /data/app/conf/listener.ora; rm /data/app/conf/init.ora; echo "new" > /data/app/conf/added.txt

--------------------------------------------------------------------------------
 [10] 스냅샷 마운트 — 읽기 전용 XFS 에서 막힌다
--------------------------------------------------------------------------------

-- k 표시 때문에 -K 로 활성화하고, XFS 라 nouuid 를 붙여 읽기 전용(ro)으로 마운트한다.
[root@ol7a ~]# lvchange -ay -K vgdata/lvthin-pre; mkdir -p /mnt/pre; mount -o ro,nouuid /dev/vgdata/lvthin-pre /mnt/pre
mount: cannot mount /dev/mapper/vgdata-lvthin--pre read-only
-- 증상   : "cannot mount /dev/mapper/vgdata-lvthin--pre read-only"
-- 매퍼 이름에서 LV 이름의 하이픈이 두 개(--)로 바뀌었다
-- 원인   : 스냅샷은 마운트된 XFS 를 그대로 떴다. XFS 는 마운트할 때 로그를 재생하려 하는데
--          LV 가 읽기 전용(r)이라 쓸 수 없어 거부했다. -o ro 만으로는 피하지 못한다
-- 실습 05 의 COW 스냅샷은 쓰기 가능한 LV 라 ro,nouuid 로 마운트됐다. 여기와 다른 점이 그것이다

-- diff -rq : 다른 파일 목록(snapper status 에 해당). 마운트가 실패한 채로 이어 친 명령이다
[root@ol7a ~]# diff -rq /mnt/pre/conf /data/app/conf
diff: /mnt/pre/conf: No such file or directory

-- /mnt/pre 가 비어 있어 비교할 것이 없다
-- diff -u : 내용 차이(snapper diff 에 해당)
[root@ol7a ~]# diff -u /mnt/pre/conf/listener.ora /data/app/conf/listener.ora
diff: /mnt/pre/conf/listener.ora: No such file or directory

-- 되돌리기(snapper undochange 에 해당): 지운 파일 복사, 바뀐 파일 복사, 추가된 파일 삭제
[root@ol7a ~]# cp -a /mnt/pre/conf/init.ora /mnt/pre/conf/listener.ora /data/app/conf/; rm /data/app/conf/added.txt
cp: cannot stat ‘/mnt/pre/conf/init.ora’: No such file or directory
cp: cannot stat ‘/mnt/pre/conf/listener.ora’: No such file or directory

-- 되돌리기도 할 수 없다. rm 만 실행돼 added.txt 는 지워졌다
[root@ol7a ~]# diff -rq /mnt/pre/conf /data/app/conf; echo "diff 종료 코드 $?"
diff: /mnt/pre/conf: No such file or directory
diff 종료 코드 2
-- 종료 코드 2 = 비교 자체가 실패. (0 은 같음, 1 은 다름)
-- 이 단계는 끝내지 못했다. 고치는 방법은 [더 해 보기] 4·5 에 남긴다
