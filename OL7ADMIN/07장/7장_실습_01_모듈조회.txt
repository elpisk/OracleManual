================================================================================
 제7장 실습 01 — 모듈 조회: lsmod·modinfo 와 /lib/modules 구조
 대상   : ol7a
 목표   : lsmod 세 열과 /proc/modules 여섯 필드, modinfo 의 filename·depends·
          parm·vermagic 를 읽고, /lib/modules/<커널> 아래 파일이 무엇을 하는지
          확인한다. UEK 와 RHCK 의 같은 모듈이 서로 다른 파일이라는 것도 본다
 배경   : 커널 모듈은 커널 버전마다 따로 빌드된 .ko 파일이다. 설치된 커널마다
          /lib/modules/<버전> 디렉터리가 하나씩 있고, depmod 가 만든 modules.dep·
          modules.alias 가 modprobe 와 udev 의 색인 역할을 한다. 적재된 모듈은
          /proc/modules 와 /sys/module 에 보이지만, 커널에 내장(built-in)된 것은
          lsmod 에 나오지 않는다(본문 7.1·7.2·7.6)
 소요   : 약 20분
 선행   : ol7-base 스냅샷(UEK 5.4.17-2136.338.4.2 로 부팅)
 계정   : root
 주의   : 조회 위주. [10] 의 insmod 는 다른 커널용 모듈이라 거부되는 것을 보는 것이며
          커널 상태를 바꾸지 않는다
 되돌림 : 바꾼 것 없음. lsmod 줄 수가 [0] 과 같은지 마지막에 확인
================================================================================

 [3] lsmod — 세 열
--------------------------------------------------------------------------------
-- 적재된 모듈 목록. 머리글과 처음 몇 줄만 본다.
[root@ol7a ~]# lsmod | head -8
Module                  Size  Used by
ip6t_rpfilter          16384  1 
ip6t_REJECT            16384  2 
nf_reject_ipv6         20480  1 ip6t_REJECT
ipt_REJECT             16384  2 
nf_reject_ipv4         16384  1 ipt_REJECT
xt_conntrack           16384  11 
ebtable_nat            16384  1 
-- 열: Module · Size · Used by
-- Size 16384 처럼 4096 의 배수가 많다. UEK 5.4 는 페이지 단위로 올림한 크기를 보여 준다
-- 줄 순서는 적재 역순이다. 맨 위가 가장 나중에 올라온 모듈
-- ip6t_REJECT 2, xt_conntrack 11: 이름이 없는 숫자는 방화벽 규칙(firewalld)이 쓰는 참조다
-- 크기가 큰 순서로 다섯 개. sort -k2 -n -r : 둘째 열(Size)을 숫자로 내림차순
[root@ol7a ~]# lsmod | sed 1d | sort -k2 -n -r | head -5
xfs                  1499136  2 
drm                   532480  4 vmwgfx,drm_kms_helper,ttm
sunrpc                401408  1 
aesni_intel           372736  0 
vmwgfx                311296  1 
-- 가장 큰 것은 xfs(약 1.5MB). 루트 파일 시스템 드라이버라 크고, Used by 2 는 / 와 /boot 두 마운트다
-- drm 은 vmwgfx·drm_kms_helper·ttm 네 개의 참조 중 셋에 이름이 있다
-- sort -k2 -n -r : 둘째 칸을 숫자로(-n) 거꾸로(-r)
-- 다른 모듈에 의해 쓰이는(Used by 에 이름이 있는) 모듈만 고른다.
-- awk 'NF==4' : 네 번째 필드(사용자 목록)가 있는 줄
[root@ol7a ~]# lsmod | awk 'NR>1 && NF==4' | head -6
nf_reject_ipv6         20480  1 ip6t_REJECT
nf_reject_ipv4         16384  1 ipt_REJECT
nf_nat                 45056  2 ip6table_nat,iptable_nat
nf_conntrack          147456  2 xt_conntrack,nf_nat
nf_defrag_ipv6         24576  1 nf_conntrack
nf_defrag_ipv4         16384  1 nf_conntrack
-- NF==4 는 공백으로 나눈 칸이 넷인 줄, 즉 Used by 에 이름 목록이 있는 줄이다
-- nf_nat 은 ip6table_nat·iptable_nat 이, nf_conntrack 은 xt_conntrack·nf_nat 이 쓴다

 [4] /proc/modules — lsmod 의 원본
--------------------------------------------------------------------------------
-- lsmod 는 이 파일을 읽어 표로 보여 줄 뿐이다. 같은 모듈 세 개를 원본으로 본다.
[root@ol7a ~]# grep -E '^(xfs|libcrc32c|e1000) ' /proc/modules
xfs 1499136 2 - Live 0xffffffffc058d000
libcrc32c 16384 3 nf_nat,nf_conntrack,xfs, Live 0xffffffffc031e000
e1000 143360 0 - Live 0xffffffffc0346000
-- /proc/modules 는 여섯 칸: 이름 · 크기 · 참조 수 · 사용 모듈 · 상태 · 주소
--   xfs       참조 2, 사용 모듈 없음(-), Live
--   libcrc32c 참조 3, nf_nat,nf_conntrack,xfs, 로 끝에 쉼표가 붙는다
--   e1000     참조 0 — NIC 가 동작 중이어도 다른 모듈이 쓰지 않으면 0 이다
-- Live 는 정상 적재, 적재·해제 중이면 Loading·Unloading 이 보인다
-- 마지막 칸은 모듈이 올라간 커널 주소다. root 가 아니면 0 으로 가려진다

 [11] 오류 ② — lsmod 에 없는데 쓰이고 있는 모듈(built-in)
--------------------------------------------------------------------------------
-- modules.builtin 은 커널 이미지에 직접 들어간 모듈 목록이다. 줄 수와 SCSI·디스크 관련 항목.
[root@ol7a ~]# cd /lib/modules/$(uname -r) && wc -l modules.builtin && grep -E 'scsi|sd_mod|crc32c|ext4' modules.builtin
270 modules.builtin
kernel/arch/x86/crypto/crc32c-intel.ko
kernel/crypto/crc32c_generic.ko
kernel/drivers/scsi/scsi_mod.ko
kernel/drivers/scsi/device_handler/scsi_dh_rdac.ko
kernel/drivers/scsi/device_handler/scsi_dh_hp_sw.ko
kernel/drivers/scsi/device_handler/scsi_dh_emc.ko
kernel/drivers/scsi/device_handler/scsi_dh_alua.ko
-- 내장 목록 270 줄. SCSI 상위 계층 scsi_mod 와 다중 경로용 scsi_dh_* 넷, crc32c 둘이 내장이다
-- grep 에 넣은 ext4 는 이 목록에 없다
-- sda 는 SCSI 디스크다. 상위 계층 scsi_mod 와 디스크 드라이버 sd_mod 를 lsmod 에서 찾는다.
[root@ol7a ~]# lsmod | grep -E '^(sd_mod|scsi_mod) '; echo "rc=$?"
sd_mod                 53248  3 
rc=0
-- sd_mod 는 lsmod 에 있다(Used by 3, 이름 없음). scsi_mod 는 없다
-- scsi_mod 를 modinfo 로 찾아본다. 내장 모듈에는 .ko 파일이 없다.
[root@ol7a ~]# modinfo scsi_mod; echo "rc=$?"
modinfo: ERROR: Module scsi_mod not found.
rc=1
-- modinfo 원문: modinfo: ERROR: Module scsi_mod not found. rc=1
-- 내장 모듈은 .ko 가 없어 modinfo 가 읽을 것이 없다. kmod 20 은 내장 여부를 알려 주지 않는다
-- 그런데 /sys/module 에는 있다. 파라미터가 있는 내장 모듈이기 때문이다.
[root@ol7a ~]# ls /sys/module/scsi_mod/parameters | tr '\n' ' '; echo; cat /sys/module/scsi_mod/parameters/scan
default_dev_flags eh_deadline inq_timeout max_luns scan scsi_logging_level use_blk_mq 
sync
-- 파라미터 일곱 개. scan 값 sync 는 /proc/cmdline 의 scsi_mod.scan=sync 가 적용된 결과다
-- 내장 모듈에 modprobe 와 rmmod 를 해 본다.
[root@ol7a ~]# modprobe -v scsi_mod; echo "rc=$?"; rmmod scsi_mod; echo "rc=$?"
rc=0
rmmod: ERROR: Module scsi_mod is builtin.
rc=1
-- modprobe -v scsi_mod: 출력 없이 rc=0 — 내장 모듈은 이미 있는 것으로 친다
-- rmmod 원문: rmmod: ERROR: Module scsi_mod is builtin. rc=1
--
-- 증상   : lsmod 에 scsi_mod 가 없고 modinfo scsi_mod 는 'Module scsi_mod not found.' 인데
--          디스크(sda)는 정상 동작, /sys/module/scsi_mod 도 있음
-- 원인   : scsi_mod 는 UEK 2136 에 내장(modules.builtin 의 kernel/drivers/scsi/scsi_mod.ko)
-- 조치   : 내장 모듈은 modules.builtin 과 /sys/module 로 확인한다. 파라미터는 커널 명령줄로만 바꾼다
-- 재확인 : rmmod scsi_mod 가 'Module scsi_mod is builtin.' 으로 내장임을 직접 알려 줌
-- 대조: sd_mod 는 모듈이다. 디스크가 쓰고 있어 내릴 수 없다(-n 으로 시험만).
[root@ol7a ~]# modinfo -n sd_mod; modprobe -r -n -v sd_mod; echo "rc=$?"
/lib/modules/5.4.17-2136.338.4.2.el7uek.x86_64/kernel/drivers/scsi/sd_mod.ko.xz
modprobe: FATAL: Module sd_mod is in use.
rc=1
-- sd_mod 는 파일이 있는 모듈이지만 디스크가 쓰고 있어 -n(시험)으로도 is in use 로 거부된다
