================================================================================
 제11장 실습 03 — 오류 재현 : 노드 목록에 없는 노드를 넣으면
 대상   : rac1
 목표   : dbca 의 사전 검증이 무엇을 확인하는지 실패 메시지로 파악하고,
          아무것도 만들지 않고 멈추는 설계의 가치를 확인한다
 소요   : 약 10분
 선행   : 실습 02 완료
 계정   : oracle
 주의   : 이 실습은 실패를 목적으로 한다. 잔여물이 남지 않는다
================================================================================

--------------------------------------------------------------------------------
 [1] 정확한 노드 이름 먼저 확인
--------------------------------------------------------------------------------

[grid@rac1 ~]$ olsnodes -n -s -t
rac1    1       Active  Unpinned
rac2    2       Active  Unpinned

-- 이 클러스터의 노드는 rac1 과 rac2 다.
-- rac3 은 존재하지 않는다. 이제 그것을 일부러 넣어 본다.

--------------------------------------------------------------------------------
 [2] 오류 재현
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ dbca -silent -createDatabase \
>   -templateName General_Purpose.dbc \
>   -gdbName testdb -sid testdb \
>   -nodelist rac1,rac3 \
>   -storageType ASM -diskGroupName DATA \
>   -sysPassword Oracle_4U -systemPassword Oracle_4U \
>   -totalMemory 1000 -emConfiguration NONE

[WARNING] [DBT-01402] Unable to check whether the specified node (rac3) is part
   of any existing server pools in the Oracle Grid Infrastructure.
[FATAL] [INS-06006] Passwordless SSH connectivity not set up between the
   following node(s): [rac1, rac3].
[FATAL] [DBT-14505] Oracle RAC software is not present on nodes ([rac3])
   selected for configuration.
   ACTION: Install Oracle RAC software on all the selected nodes before doing
           database configuration.
[FATAL] [DBT-14105] The specified node(s) (rac3) is not configured with Oracle
   Grid Infrastructure.
   CAUSE: RAC database creation can only be done on nodes that are configured
          with Oracle Grid Infrastructure.
[FATAL] [DBT-14104] Some of the nodes (rac3) are not accessible.
   ACTION: Ensure that all the nodes specified for database creation are
           accessible.

                                                               (8.9초 소요)

-- 오류 : DBT-01402(경고), INS-06006, DBT-14505, DBT-14105, DBT-14104
--
-- 8.9 초 만에 다섯 개의 메시지를 내고 중단했다.

--------------------------------------------------------------------------------
 [3] 원인 파악 — 다섯 메시지를 검사 순서로 읽는다
--------------------------------------------------------------------------------

-- 메시지가 많다고 문제가 많은 것이 아니다. 검사 순서를 따라 읽으면 된다.
--
--  메시지        무엇을 검사했나                          판정
--  -----------  ---------------------------------------  ------------
--  DBT-01402    Grid 의 서버 풀에 그 노드가 있는가        확인 불가 (경고)
--  INS-06006    노드 간 암호 없는 SSH 가 되는가           안 됨
--  DBT-14505    그 노드에 RAC 소프트웨어가 있는가         없음
--  DBT-14105    Grid Infrastructure 로 구성되어 있는가    안 됨
--  DBT-14104    그 노드에 접근할 수 있는가                안 됨
--
-- 다섯 가지 검사가 모두 같은 원인 하나를 가리킨다.
-- rac3 이라는 노드가 존재하지 않는다는 것이다.
--
-- 첫 번째만 WARNING 이고 나머지 넷은 FATAL 이다.
-- 하나라도 FATAL 이면 진행하지 않는다.
-- 실습 02 [4] 의 DBT-06801 처럼 WARNING 만 있었다면 진행되었을 것이다.

--------------------------------------------------------------------------------
 [4] 조치 — 아무것도 만들어지지 않았는지 확인
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl config database
racdb

[grid@rac1 ~]$ crsctl stat res -t | grep -i testdb
   (출력 없음)

[grid@rac1 ~]$ asmcmd ls +DATA
RACDB/

[oracle@rac1 ~]$ ls -d /u01/app/oracle/admin/testdb
ls: cannot access /u01/app/oracle/admin/testdb: No such file or directory

-- 재확인 : 네 곳 모두 깨끗하다. 정말 아무것도 만들어지지 않았다.
--
-- 이것이 왜 다행인가.
--   1) 시간 — 8.9 초에 멈추므로 25 분을 낭비하지 않는다
--   2) 잔여물 — CRS 자원이나 ASM 디렉터리가 남지 않아 정리할 것이 없다
--   3) 재시도 — 인자만 고쳐 다시 실행하면 된다
--
-- 대비되는 경우가 있다. 생성이 도중에 실패하면 잔여물이 남는다.
-- 이 랩에서 실제로 그런 일이 있었고, 그때는 CRS 자원과 ASM 디렉터리,
-- 양 노드의 admin 디렉터리를 수동으로 정리해야 했다.
-- 실습 07 의 [7] 에서 그 절차를 다룬다.

--------------------------------------------------------------------------------
 [5] 흔한 실수 두 가지
--------------------------------------------------------------------------------

-- 하나. FQDN 을 쓰는 것
--
--   -nodelist rac1.localdomain,rac2.localdomain
--
--   olsnodes 가 반환하는 이름은 rac1 과 rac2 다.
--   FQDN 을 붙이면 일치하지 않아 이 실습과 같은 오류가 난다.
--   OS 의 호스트명이나 /etc/hosts 의 별칭이 아니라 Grid 가 아는 이름을 쓴다.
--
-- 둘. 노드 이름과 인스턴스 이름을 섞는 것
--
--   -nodelist testdb1,testdb2   (X)
--   -nodelist rac1,rac2         (O)
--
--   -nodelist 에는 노드 이름을, -sid 에는 인스턴스 접두어를 넣는다.
--   이 실습에서는 각각 rac1,rac2 와 testdb 다.
--
-- 두 실수 모두 같은 다섯 메시지로 나타나므로 원인을 구분하기 어렵다.
-- 실행 전에 olsnodes 결과와 대조하는 습관이 예방책이다.

--------------------------------------------------------------------------------
 [6] 사전 검증이 없다면
--------------------------------------------------------------------------------

-- 만약 dbca 가 이 검사를 하지 않고 진행했다면 어떻게 되었을까.
--
--   rac1 에는 인스턴스가 만들어지고 rac3 쪽은 실패한다.
--   그 실패가 언제 드러날지는 알 수 없다. 생성 마지막 단계일 수도 있다.
--   25 분을 쓰고 나서 반쪽짜리 데이터베이스와 잔여물을 얻는다.
--
-- 사전 검증의 가치가 여기 있다.
-- 오래 걸리는 작업일수록 시작 전에 걸러 내는 것이 중요하다.
--
-- 같은 이유로 실습 01 의 점검표를 지키는 것이 중요하다.
-- dbca 가 검사하지 않는 것들 — 노드 부하, 호스트의 다른 가상 머신,
-- 메모리 여유 — 은 사람이 확인해야 한다.
