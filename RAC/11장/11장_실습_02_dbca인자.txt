 [2] RAC 전용 인자
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ dbca -silent -createDatabase -help 2>&1 | grep -iE \
>   'nodelist|storageType|diskGroupName|databaseConfigType|totalMemory|policyManaged|adminManaged'

        [-nodelist <Node names separated by comma for the database>]
        [-memoryPercentage | -totalMemory]
        [-totalMemory <Memory allocated for Oracle in MB>]
        [-policyManaged | -adminManaged]
        [-policyManaged <Policy managed database, default option is Admin managed database>]
        [-adminManaged <Admin managed database, this is default option>]
        [-storageType < FS | ASM >]
        [-databaseConfigType <SINGLE | RAC | RACONENODE>]
            [-RACOneNodeServiceName <Service name for the service to be created
             for RAC One Node database. This option is mandatory when the
             databaseConfigType is RACONENODE>]

-- 여기서 눈여겨볼 것이 있다. grep 패턴에 diskGroupName 을 넣었는데
-- 결과에 나오지 않는다. 확인해 본다.

[oracle@rac1 ~]$ dbca -silent -createDatabase -help 2>&1 | grep -in 'diskGroupName'
   (출력 없음)

[oracle@rac1 ~]$ dbca -silent -createDatabase -help 2>&1 | grep -A3 -i 'storageType'
        [-storageType < FS | ASM >]
            -datafileDestination <Destination directory for all database files>
            [-asmsnmpPassword <ASMSNMP password for ASM monitoring>]
        [-databaseConfigType <SINGLE | RAC | RACONENODE>]

-- 원인 파악 : -diskGroupName 은 이 도움말에 아예 없다.
--             -storageType 아래에 문서화된 인자는 -datafileDestination 이다.
--             그런데 실습 04 에서 -diskGroupName DATA 로 실행했고
--             데이터파일이 +DATA/TESTDB 아래에 만들어졌다.
-- 조치     : 문서화된 형태를 쓰는 편이 안전하다.
--             -datafileDestination '+DATA' 로 쓰면 도움말과 일치한다.
--             이때는 경로이므로 + 가 필요하다.
-- 재확인   : 어느 쪽을 쓰든 생성 후 v$datafile 로 파일이 의도한
--             디스크그룹에 들어갔는지 확인한다. 그것이 최종 판정이다.
--
-- 교훈 : 도움말에 없는 인자가 동작하기도 한다. 다만 버전이 바뀌면
--        지원이 끊길 수 있으므로 문서화된 형태를 쓰는 것이 안전하다.
--        9장의 asmca 도움말 사례와 방향이 반대인 함정이다.
--        그때는 도움말이 실제보다 좁았고, 여기서는 도움말에 없는 것이 동작한다.

-- RAC 을 RAC 으로 만드는 인자는 셋이다.
--
--   -databaseConfigType RAC
--     이것이 없으면 아무 오류 없이 단일 인스턴스가 만들어진다.
--     25분이 지난 뒤에야 알게 되므로 실행 전에 반드시 확인한다.
--
--   -nodelist rac1,rac2
--     노드가 둘 이상이어야 인스턴스도 둘이 된다.
--     실습 01 [1] 의 olsnodes 결과와 같아야 한다.
--
--   -adminManaged (기본값)
--     관리자가 인스턴스와 노드의 대응을 직접 정한다.
--     -policyManaged 는 서버 풀에 맡긴다. 2노드에서는 관리자 관리가 단순하다.
--
-- RACONENODE 도 보인다. 19장에서 다룰 RAC One Node 다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — FRA 경로에 + 를 빠뜨리면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ dbca -silent -createDatabase \
>   -templateName General_Purpose.dbc \
>   -gdbName testdb -sid testdb \
>   -databaseConfigType RAC -adminManaged -nodelist rac1,rac2 \
>   -storageType ASM -diskGroupName DATA \
>   -recoveryAreaDestination FRA -recoveryAreaSize 4000 \
>   ... (이하 생략)

[FATAL] [DBT-06007] The specified location (FRA Location) is invalid.
   CAUSE: The specified location is not found on the system or is detected
          to be a file.

-- 오류 : DBT-06007
--
-- 원인 파악 : 같은 명령에서 -diskGroupName DATA 는 + 없이 통과했는데
--             -recoveryAreaDestination FRA 는 실패했다.
--
--             두 인자가 받는 값의 성격이 다르기 때문이다.
--               -diskGroupName            → 디스크그룹의 "이름"
--               -recoveryAreaDestination  → "경로"
--
--             경로에는 ASM 표기 규칙이 적용되므로 + 가 필요하다.
--             메시지의 "location" 이라는 단어가 그것이 경로임을 알려 준다.
-- 조치     : '+FRA' 로 고친다.
-- 재확인   : 고친 뒤 이 오류가 사라지는지 본다. 실습 04 에서 확인한다.
--
-- 미리 판단하는 방법 : 인자 이름을 본다.
--   Name 이 들어가면 식별자를 받는다
--   Destination 이나 Location 이 들어가면 경로를 받는다
-- 이 규칙은 다른 오라클 도구에도 대체로 통한다.

--------------------------------------------------------------------------------
 [4] 경고 재현 — FRA 크기가 권고보다 작으면
--------------------------------------------------------------------------------

-- 경로를 '+FRA' 로 고치고 크기를 5000MB 로 주면 이번에는 경고가 나온다.

[WARNING] [DBT-06801] Specified Fast Recovery Area size (5,000 MB) is less than
   the recommended value.
   CAUSE: Fast Recovery Area size should at least be three times the database
          size (2,384 MB).
   ACTION: Specify Fast Recovery Area Size to be at least three times the
           database size.

-- 이것은 오류가 아니다. WARNING 이므로 생성이 그대로 진행된다.
--
-- 앞의 DBT-06007 과 비교한다.
--   [FATAL]   → 멈춘다
--   [WARNING] → 진행한다
--
-- 로그에 메시지가 많이 나올 때 이 구분을 못 하면 정상 진행 중인 작업을
-- 실패로 오해한다.
--
-- 권고값의 근거 : FRA 에는 백업과 아카이브 로그가 쌓이므로 데이터베이스
--                크기의 3 배를 권한다. 2384MB 의 3 배면 7152MB 인데
--                5000MB 를 줬으므로 경고가 나왔다.
--
-- 실습에서는 그 용도로 쓰지 않아 작게 줘도 무방하다.
-- 운영에서 이 경고를 무시하면 나중에 FRA 가 가득 차 아카이브가 멈춘다.

--------------------------------------------------------------------------------
 [5] 최종 인자 구성
--------------------------------------------------------------------------------

-- 실습 04 에서 쓸 명령이다. 각 선택의 이유를 적어 둔다.
--
--   -templateName General_Purpose.dbc     씨앗 복사 방식 (빠르다)
--   -gdbName testdb -sid testdb           이름과 인스턴스 접두어
--   -databaseConfigType RAC               RAC 으로 만든다
--   -adminManaged                         관리자 관리
--   -nodelist rac1,rac2                   두 노드에 인스턴스
--   -storageType ASM                      ASM 사용
--   -diskGroupName DATA                   데이터파일 위치
--                                         (도움말에는 없는 인자. 문서화된
--                                          형태는 -datafileDestination '+DATA')
--   -recoveryAreaDestination '+FRA'       FRA 위치 (경로이므로 + 필요)
--   -recoveryAreaSize 5000                권고보다 작지만 실습용
--   -createAsContainerDatabase true       CDB 로 만든다
--   -pdbName testpdb                      PDB 하나
--   -totalMemory 800                      랩 자원에 맞춰 최소로
--   -redoLogFileSize 20                   기본 200MB 를 줄임
--   -emConfiguration NONE                 EM Express 구성 생략
--   -sampleSchema false                   샘플 스키마 생략
--   -ignorePreReqs                        이 랩은 전제 조건이 이미 충족됨
--
-- 마지막 넷은 생성 시간과 자원을 아끼려는 선택이다.
-- 운영에서는 -totalMemory 를 이렇게 작게 주지 않고
-- -ignorePreReqs 도 습관적으로 쓰지 않는다.
