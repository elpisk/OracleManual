 제4장 실습 04 — 계정 가드 확인
 대상   : rac1
 목표   : Oracle 설치 도구에 걸린 계정 가드를 직접 확인하고, 잘못 실행해도
          시스템이 무손상임을 검증한다
 소요   : 약 25분
 선행   : GI 설치가 완료되어 있을 것
 계정   : root, grid, oracle
 주의   : 일부러 잘못된 계정으로 실행한다. 모두 가드에 막히므로 안전하다.
          실행 후 반드시 클러스터 상태를 확인하는 것까지가 실습이다.
================================================================================

--------------------------------------------------------------------------------

-- 무손상을 검증하려면 기준이 필요하다. 먼저 기록해 둔다.

[grid@rac1 ~]$ crsctl check cluster -all | grep -c online

[grid@rac1 ~]$ crsctl query css votedisk | tail -1

[grid@rac1 ~]$ olsnodes -s -n

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

--------------------------------------------------------------------------------
 [2] 오류 재현 (1) — root.sh 를 grid 로
--------------------------------------------------------------------------------

[grid@rac1 ~]$ /u01/app/19.3.0/grid/root.sh
Check /u01/app/19.3.0/grid/install/root_rac1.localdomain_2026-09-01_15-01-34-311480080.log
for the output of root script

-- 화면에는 로그 경로만 나온다. 성공인지 실패인지 알 수 없다.

[grid@rac1 ~]$ cat /u01/app/19.3.0/grid/install/root_rac1.localdomain_2026-09-01_15-01-34-311480080.log
You must be logged in as user with UID as zero (e.g. root user) to run root
configuration script.
Log in as user with UID as zero (e.g. root user) and restart root configuration
script execution.

-- 원인 파악
--   root.sh 의 권한은 755 라 누구나 실행할 수 있다.
--   스크립트 안에서 UID 가 0 인지 검사하고 아니면 즉시 중단한다.

[grid@rac1 ~]$ ls -l /u01/app/19.3.0/grid/root.sh; id -u
-rwxr-xr-x. 1 root oinstall 405 Aug 31 19:03 /u01/app/19.3.0/grid/root.sh
1001

-- 조치 — 이 스크립트는 설치 시점에만 root 로 실행한다.
--   구성이 끝난 클러스터에서 다시 실행하지 않는다.

--------------------------------------------------------------------------------
 [3] 오류 재현 (2) — gridSetup.sh 를 root 로
--------------------------------------------------------------------------------

[root@rac1 ~]# cd /u01/app/19.3.0/grid
[root@rac1 grid]# ./gridSetup.sh -silent -help

ERROR: You must not be logged in as root to run this tool.

-- 원인 파악
--   반대 방향의 가드다. 설치 도구는 root 로 실행하면 안 된다.
--   root 로 실행하면 소프트웨어 파일이 root 소유로 만들어지고,
--   이후 설치 사용자가 패치하거나 구성을 바꾸거나 제거할 수 없게 된다.
--   -help 조차 거부한다. 실제 동작 전에 계정부터 검사한다.

-- 조치 — 설치 사용자로 실행한다.
[root@rac1 grid]# su - grid
[grid@rac1 ~]$ cd /u01/app/19.3.0/grid && ./gridSetup.sh -silent -help 2>&1 | head -4
(정상적으로 사용법이 출력된다)

--------------------------------------------------------------------------------
 [4] 오류 재현 (3) — deinstall 을 root 로
--------------------------------------------------------------------------------

[root@rac1 ~]# /u01/app/19.3.0/grid/deinstall/deinstall -help
You must not be logged in as root to run /u01/app/19.3.0/grid/deinstall/deinstall.
Log in as Oracle user and rerun /u01/app/19.3.0/grid/deinstall/deinstall.

-- 원인 파악
--   같은 이유다. 제거 도구도 설치 사용자로 실행한다.
--   메시지가 Log in as Oracle user 라고 구체적으로 안내한다.

[root@rac1 ~]# ls -l /u01/app/19.3.0/grid/deinstall/deinstall
-rwxr-x---. 1 grid oinstall 11224 Aug 31 19:03 deinstall

--   권한이 750 이다. root 는 권한 검사를 통과하지만 스크립트 안에서 거부한다.

-- 조치 — 이 실습에서는 deinstall 을 실제로 실행하지 않는다.
--   정상 동작 중인 클러스터를 지우는 명령이기 때문이다.
--   도구가 존재하고 어떤 가드가 걸려 있는지만 확인한다.

--------------------------------------------------------------------------------
 [5] 오류 재현 (4) — crsctl 변경 계열을 grid 로
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl config crs
CRS-4563: Insufficient user privileges.

CRS-4000: Command Config failed, or completed with errors.

-- 원인 파악
--   crsctl 의 모든 하위 명령이 grid 로 되는 것은 아니다.
--   config, enable, disable, set 계열은 root 를 요구한다.
--   check, get, status 계열은 grid 로 된다.

[grid@rac1 ~]$ crsctl check has
CRS-4638: Oracle High Availability Services is online

[grid@rac1 ~]$ crsctl get css misscount
CRS-4678: Successful get misscount 30 for Cluster Synchronization Services.

-- 조치 — root 로 실행한다. PATH 에 Grid 홈이 없으므로 전체 경로를 쓴다.
[root@rac1 ~]# /u01/app/19.3.0/grid/bin/crsctl config crs
CRS-4622: Oracle High Availability Services autostart is enabled.

--------------------------------------------------------------------------------
 [6] 가드 정리
--------------------------------------------------------------------------------

--  도구                       실행 계정      잘못 실행하면
--  ------------------------   ------------   ------------------------------------
--  root.sh                    root           UID 검사 후 중단(사유는 로그 파일)
--  rootcrs.sh                 root           권한 750 이라 실행 자체가 안 됨
--  gridSetup.sh               설치 사용자    ERROR: You must not be logged in as root
--  runInstaller               설치 사용자    같은 형태의 거부
--  deinstall                  설치 사용자    Log in as Oracle user and rerun
--  crsctl config/enable/set   root           CRS-4563: Insufficient user privileges
--  crsctl check/get/status    grid 가능      -
--
-- 규칙은 단순하다.
--   시스템을 바꾸는 스크립트는 root 로
--   소프트웨어를 다루는 도구는 설치 사용자로
-- 두 가드가 반대 방향으로 걸려 있어 잘못 실행해도 대개 즉시 막힌다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) root.sh 를 grid 로 → UID 검사 후 중단. 사유는 로그 파일에
--   2) gridSetup.sh 를 root 로 → ERROR: You must not be logged in as root
--   3) deinstall 을 root 로 → Log in as Oracle user and rerun
--   4) crsctl config 를 grid 로 → CRS-4563: Insufficient user privileges
--   5) 가드가 양방향으로 걸려 있다
--   6) 네 번 모두 아무것도 바꾸지 않았다
--
-- 무손상 검증 방법
--   기준 상태를 먼저 기록하고, 실행 후 같은 항목을 다시 확인해 비교한다.
--   보팅 파일의 File Universal Id 와 OCR ID 까지 같으면 확실하다.
--
-- 가드가 있다고 방심하지 않는다. 실행 전에 whoami 로 계정을 확인하는 습관이
-- 우선이다. 가드가 없는 명령도 많다.
