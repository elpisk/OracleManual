 대상   : rac1
 목표   : asmcmd cp 로 ASM 안팎으로 파일을 옮기고, 안으로 넣을 때 지정한
          경로가 별칭이 되는 것을 확인한다
 소요   : 약 25분
 선행   : 실습 05 로 +TEST 에 파일 두 개가 있을 것
 계정   : grid

--------------------------------------------------------------------------------
 [1] 복사 대상 확인
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd ls -l +TEST/RACDB/DATAFILE
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  Y    TS_ALIAS.256.1242847959
DATAFILE  UNPROT  FINE     SEP 01 19:00:00  Y    TS_TPL.257.1242848005

-- 실습 05 에서 만든 두 파일이다. 하나는 COARSE, 하나는 FINE 이다.
-- 작은 쪽(50MB)을 복사 대상으로 쓴다.

--------------------------------------------------------------------------------
 [2] ASM 밖으로 꺼낸다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd cp +TEST/RACDB/DATAFILE/ts_tpl.257.1242848005 /tmp/copy_out.dbf
copying +TEST/RACDB/DATAFILE/ts_tpl.257.1242848005 -> /tmp/copy_out.dbf

[grid@rac1 ~]$ ls -lh /tmp/copy_out.dbf
-rw-r-----. 1 grid oinstall 51M Sep  1 19:34 /tmp/copy_out.dbf

-- 두 가지를 읽는다.
--
-- 첫째, 50MB 테이블스페이스가 51MB 파일로 나왔다. 실습 01 에서 본 헤더
-- 블록 하나 때문이다. v$asm_file 의 크기가 50.0078125MB 였고 ls -lh 가
-- 반올림해 51M 으로 보여 준다.
--
-- 둘째, 소유자가 grid:oinstall 이다. asmcmd 를 실행한 계정이 그대로
-- 파일 소유자가 된다. oracle 계정이 이 파일을 읽어야 한다면 권한을
-- 조정해야 한다. 두 계정이 oinstall 그룹을 공유하므로 그룹 읽기 권한이
-- 있으면 접근할 수 있다.

[grid@rac1 ~]$ ls -l /tmp/copy_out.dbf
-rw-r-----. 1 grid oinstall 52436992 Sep  1 19:34 /tmp/copy_out.dbf

-- 정확한 바이트는 52,436,992 다. 계산해 보면
--   52,436,992 / 8192 = 6401 블록
--   6400 블록이 50MB, 나머지 1블록이 헤더다.

--------------------------------------------------------------------------------
 [3] ASM 안으로 넣는다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ sqlplus -s / as sysasm
SQL> alter diskgroup TEST add directory '+TEST/mydir';

Diskgroup altered.

[grid@rac1 ~]$ asmcmd cp /tmp/copy_out.dbf +TEST/mydir/copied.dbf
copying /tmp/copy_out.dbf -> +TEST/mydir/copied.dbf

[grid@rac1 ~]$ asmcmd ls -l +TEST/mydir
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  N    copied.dbf => +TEST/ASM/DATAFILE/copied.dbf.258.1242848061

-- 출력을 정확히 읽어야 한다.
--
-- 우리가 지정한 경로는 +TEST/mydir/copied.dbf 였다.
-- 그런데 실제 파일은 +TEST/ASM/DATAFILE/copied.dbf.258.1242848061 에
-- 만들어졌고, 우리가 지정한 경로는 별칭(Sys=N)이 되었다.
--
-- ASM 은 파일을 항상 자기 규칙대로 저장한다. 태그.파일번호.incarnation
-- 형식을 벗어난 이름으로는 파일을 만들지 않는다. 사용자가 지정한 경로는
-- 별칭으로 처리한다.
-- 실습 03 에서 본 이름 계층이 여기서도 그대로 작동한다.

--------------------------------------------------------------------------------
 [4] ASM 이라는 디렉터리는 무엇인가
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd ls +TEST
ASM/
RACDB/
mydir/

[grid@rac1 ~]$ asmcmd ls -l +TEST/ASM/DATAFILE
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  Y    copied.dbf.258.1242848061

-- ASM 이라는 디렉터리가 새로 생겼다.
--
-- 데이터베이스가 만든 파일은 DB_UNIQUE_NAME 디렉터리(RACDB) 아래에 놓인다.
-- 그러나 asmcmd 로 넣은 파일은 어느 데이터베이스의 것인지 알 수 없다.
-- 그래서 ASM 이라는 디렉터리를 쓴다.
--
-- 태그도 눈여겨보라. copied.dbf.258.1242848061 에서 태그가 copied.dbf 다.
-- 확장자를 포함한 파일 이름 전체가 태그가 되었다. 데이터베이스가 만들 때는
-- 테이블스페이스 이름이 태그가 되는 것과 다르다.

--------------------------------------------------------------------------------
 [5] 오류 재현 — 같은 이름으로 다시 복사하면
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd cp /tmp/copy_out.dbf +TEST/mydir/copied.dbf
copying /tmp/copy_out.dbf -> +TEST/mydir/copied.dbf

[grid@rac1 ~]$ asmcmd ls -l +TEST/mydir
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  N    copied.dbf => +TEST/ASM/DATAFILE/copied.dbf.258.1242848061

[grid@rac1 ~]$ asmcmd ls -l +TEST/ASM/DATAFILE
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  Y    copied.dbf.258.1242848061
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  Y    copied.dbf.259.1242848120

-- 오류 : 오류가 나지 않는다. 이것이 문제다.
-- 원인 파악 : 명령은 성공했고 별칭 copied.dbf 는 여전히 258 번 파일을
--             가리킨다. 그런데 ASM/DATAFILE 아래에 259 번 파일이 새로
--             생겼다. 이름 없는 고아 파일이 만들어진 것이다.
--             유닉스 cp 는 대상 파일을 덮어쓰지만 ASM 은 새 파일을 만들고
--             별칭은 그대로 둔다. 반복하면 공간만 계속 소비된다.
-- 조치     : 같은 이름으로 다시 복사하기 전에 기존 별칭과 파일을 먼저
--             정리한다. 또는 매번 다른 이름을 쓴다.
-- 재확인   : 고아 파일을 확인하고 정리한다.

[grid@rac1 ~]$ sqlplus -s / as sysasm

SQL> select f.file_number, f.bytes/1024/1024 mb, a.name
  2    from v$asm_file f, v$asm_diskgroup g,
  3         (select file_number, name from v$asm_alias
  4           where group_number=(select group_number from v$asm_diskgroup where name='TEST')
  5             and system_created='N' and file_number <> 4294967295) a
  6   where f.group_number=g.group_number and g.name='TEST'
  7     and f.file_number=a.file_number(+)
  8   order by f.file_number;

FILE_NUMBER         MB NAME
----------- ---------- --------------------
        256 100.007813
        257 50.0078125
        258 50.0078125 copied.dbf
        259 50.0078125

-- 259 번에 사용자 별칭이 없다. 고아 파일이다.
-- 259 번을 지운다.

[grid@rac1 ~]$ asmcmd rm +TEST/ASM/DATAFILE/copied.dbf.259.1242848120
[grid@rac1 ~]$ asmcmd ls -l +TEST/ASM/DATAFILE
Type      Redund  Striped  Time             Sys  Name
DATAFILE  UNPROT  COARSE   SEP 01 19:00:00  Y    copied.dbf.258.1242848061

--------------------------------------------------------------------------------
 [6] 디스크그룹 사이 복사
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd cp +TEST/ASM/DATAFILE/copied.dbf.258.1242848061 +FRA/moved.dbf
copying +TEST/ASM/DATAFILE/copied.dbf.258.1242848061 -> +FRA/moved.dbf

[grid@rac1 ~]$ asmcmd ls -l +FRA
Type  Redund  Striped  Time  Sys  Name
                             Y    ASM/
                             Y    RACDB/
                             N    moved.dbf => +FRA/ASM/DATAFILE/moved.dbf.261.1242848200

-- 같은 규칙이 적용된다. 지정한 이름은 별칭이 되고 실제 파일은 ASM 디렉터리
-- 아래에 정규 이름으로 저장된다.
--
-- 이 방식으로 디스크그룹 사이에 파일을 옮길 수 있다. 다만 대용량 파일은
-- RMAN 이 병렬 처리와 압축을 지원하므로 더 낫다.

-- 정리한다.
[grid@rac1 ~]$ asmcmd rm +FRA/moved.dbf
[grid@rac1 ~]$ asmcmd ls +FRA
ASM/
RACDB/

-- 별칭을 지우면 실제 파일도 함께 지워졌다.
-- 실습 04 의 drop alias 와 다르다. asmcmd rm 은 별칭과 대상 파일을 함께
-- 지우고, SQL 의 drop alias 는 별칭만 지운다. 명령의 성격이 다르다.

[grid@rac1 ~]$ asmcmd ls +FRA/ASM
(비어 있음)

--------------------------------------------------------------------------------
 [7] 할 수 있는 것과 없는 것
--------------------------------------------------------------------------------

-- 할 수 있다
--   SPFILE, 컨트롤파일, 아카이브 로그, RMAN 백업셋을 ASM 안팎으로 옮긴다
--   디스크그룹 사이로 파일을 옮긴다
--   ASM 안의 파일을 직접 볼 수 없을 때 꺼내서 확인한다
--
-- 할 수 없다
--   열려 있는 데이터파일의 일관된 복사
--
-- 왜 안 되는가. 복사 도중 데이터베이스가 그 파일의 블록을 갱신하면 사본의
-- 앞부분과 뒷부분이 서로 다른 시점의 내용을 갖게 된다. 그 사본으로는
-- 복구할 수 없다.
--
-- 실제로 시도해 보면 명령 자체는 성공한다. 오류가 나지 않으므로 백업이
-- 만들어진 줄 알기 쉽다. 이것이 위험한 이유다.
--
-- 백업은 RMAN 을 쓴다. RMAN 은 블록 일관성을 보장하고 병렬 처리와 압축도
-- 지원한다. asmcmd cp 는 파일을 꺼내 보는 용도로 쓴다.

--------------------------------------------------------------------------------
 [9] 정리
--------------------------------------------------------------------------------

-- 재현한 오류
--   같은 이름으로 재복사 — 오류 없이 고아 파일이 생긴다 (조용한 실패)
--
-- 확인한 것
--   1) 50MB 파일이 52,436,992 바이트로 나온다. 헤더 블록 1개 포함
--   2) asmcmd 실행 계정이 파일 소유자가 된다
--   3) ASM 안으로 넣으면 지정 경로가 별칭이 되고 실제 파일은 정규 이름
--   4) 소속 DB 를 알 수 없으면 ASM 디렉터리를 쓴다
--   5) 태그가 파일 이름 전체(copied.dbf)가 된다
--   6) 같은 이름으로 재복사하면 고아 파일이 쌓인다
--   7) asmcmd rm 은 별칭과 파일을 함께 지운다. SQL 의 drop alias 와 다르다
--   8) 열린 데이터파일 복사는 성공하지만 복구에 쓸 수 없다
--
-- 실무 지침
--   asmcmd cp 는 꺼내 보는 용도다. 백업은 RMAN 으로 한다.
--   같은 이름으로 반복 복사하는 스크립트는 고아 파일을 쌓으므로,
--   복사 전에 기존 파일을 지우거나 이름에 타임스탬프를 붙인다.
