================================================================================
 제14장 실습 02 — srvctl 자원별 문법, status 와 config
 대상   : rac1
 목표   : srvctl 의 3단 구조를 익히고 대상별 출력을 한 번에 훑는다.
          status 와 config 를 한 세트로 쓰는 습관을 만든다
 소요   : 약 25분
 선행   : 실습 01 완료
 계정   : oracle, grid
================================================================================

--------------------------------------------------------------------------------
 [1] status — 대상별로 훑어본다
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[grid@rac1 ~]$ srvctl status listener
Listener LISTENER is enabled
Listener LISTENER is running on node(s): rac1,rac2

[grid@rac1 ~]$ srvctl status scan
SCAN VIP scan1 is enabled
SCAN VIP scan1 is running on node rac1

[grid@rac1 ~]$ srvctl status scan_listener
SCAN Listener LISTENER_SCAN1 is enabled
SCAN listener LISTENER_SCAN1 is running on node rac1

[grid@rac1 ~]$ srvctl status asm
ASM is running on rac1,rac2

[grid@rac1 ~]$ srvctl status vip -n rac1
VIP 172.16.225.111 is enabled
VIP 172.16.225.111 is running on node: rac1

-- 출력 형식이 통일되어 있지 않다는 것을 먼저 알아 두자.
-- 파싱해야 한다면 대상마다 따로 짜야 한다.
--
-- 공통점은 "enabled 인가" 와 "running 인가" 를 나눠 말한다는 것이다.
-- 이것이 disable 과 stop 의 구분에 대응한다.
--
-- scan 과 scan_listener 가 나뉘어 있는 것을 눈여겨본다.
-- SCAN 은 IP 자원이고 SCAN 리스너는 그 IP 에서 듣는 프로세스다.
-- 별개의 자원이며 한쪽만 죽을 수 있다. 15장에서 이 구분이 다시 필요하다.

--------------------------------------------------------------------------------
 [2] nodeapps — 여러 자원을 한 번에
--------------------------------------------------------------------------------

[grid@rac1 ~]$ srvctl status nodeapps
VIP 172.16.225.111 is enabled
VIP 172.16.225.111 is running on node: rac1
VIP 172.16.225.112 is enabled
VIP 172.16.225.112 is running on node: rac2
Network is enabled
Network is running on node: rac1
Network is running on node: rac2
ONS is enabled
ONS daemon is running on node: rac1
ONS daemon is running on node: rac2

-- VIP·네트워크·ONS 를 묶은 이름이다.
-- 노드가 이상할 때 개별 자원을 하나씩 조회하는 것보다 이 하나가 빠르다.

--------------------------------------------------------------------------------
 [3] config — 정의를 읽는다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ srvctl config scan
SCAN name: rac-scan, Network: 1
Subnet IPv4: 172.16.225.0/255.255.255.0/ens33, static
Subnet IPv6:
SCAN 1 IPv4 VIP: 172.16.225.120
SCAN VIP is enabled.

[grid@rac1 ~]$ srvctl config listener
Name: LISTENER
Type: Database Listener
Network: 1, Owner: grid
Home: <CRS home>
End points: TCP:1521
Listener is enabled.

[grid@rac1 ~]$ srvctl config asm
ASM home: <CRS home>
Password file: +CRS/orapwASM
ASM listener: LISTENER
ASM instance count: 3
Cluster ASM listener: ASMNET1LSNR_ASM

-- 트러블슈팅에 쓰이는 줄만 알면 된다.
--
--   네트워크 문제  → Subnet 과 인터페이스 이름 (여기서는 ens33)
--   권한 문제      → Owner (리스너는 grid 소유다)
--   접속 문제      → End points (TCP:1521)
--
-- 리스너 소유자가 grid 라는 사실은 자주 걸린다. oracle 로 lsnrctl 을
-- 실행해 권한 오류를 만나는 일이 흔하고, 리스너 로그도 grid 로 봐야 한다.
--
-- ASM instance count 가 3 이다. 노드는 둘인데 3 이며 이것이 Flex ASM 의
-- 카디널리티다. 슬롯 하나가 비어 있는 상태이고 정상이다.

--------------------------------------------------------------------------------
 [4] status 와 config 를 한 세트로
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[oracle@rac1 ~]$ srvctl config database -d racdb | egrep 'instances|Configured|Start options|Stop options|Management|Disk Groups'
Start options: open
Stop options: immediate
Management policy: AUTOMATIC
Disk Groups: DATA,FRA
Database instances: racdb1,racdb2
Configured nodes: rac1,rac2

-- 둘을 비교해야 판단이 선다.
-- 정의는 두 노드인데 한 노드만 떠 있다면 그것이 문제다.
-- config 만 보면 지금 상태를 모르고, status 만 보면 원래 몇 개인지 모른다.
--
-- 여기에 crsctl stat res ora.racdb.db -t 를 더하면 TARGET 까지 보인다.
-- TARGET 이 OFFLINE 이면 CRS 는 올릴 생각이 없다는 뜻이므로
-- 아무리 기다려도 안 올라온다. 12장에서 확인한 그대로다.

--------------------------------------------------------------------------------
 [5] 옵션은 -help 로 확인한다
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl start database -help
Starts the database.

Usage: srvctl start database -db <db_unique_name> [-startoption <start_options>]
       [-startconcurrency <start_concurrency>] [-node <node> |
       -serverpool "<serverpool_list>"] [-eval] [-verbose]
    -startoption <start_options>   Options to startup command (OPEN, MOUNT ...)
    -startconcurrency <n>          동시에 기동할 인스턴스 수
    -eval                          실행하지 않고 영향만 계산한다

-- -help 를 습관으로 삼는 것이 좋다. 문서보다 빠르고 그 환경의 실제
-- 버전을 반영한다.
--
-- 눈여겨볼 옵션 둘.
--   -startconcurrency  이 랩처럼 호스트 CPU 가 넉넉하지 않으면 1 로 두어
--                      순차 기동한다. 동시에 올리다 부하가 급등해 노드가
--                      축출된 적이 있다.
--   -eval              서비스가 여럿 걸린 DB 를 내릴 때 무엇이 함께
--                      내려가는지 미리 볼 수 있다.

--------------------------------------------------------------------------------
 [6] 흔한 오류 — 옵션 이름을 잘못 쓰면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -db racdb -foo
PRKO-2002 : Invalid command line option: -foo

-- 원인 파악 : PRKO 는 명령행을 해석하는 단계에서 나는 오류다.
--             자원을 조회하러 가기도 전에 거부되었다.
--             즉 명령 자체가 틀린 것이지 자원 상태와는 무관하다.
-- 조치     : srvctl status database -help 로 실제 옵션 이름을 확인한다.
--             19c 는 -db 와 -d 를 모두 받지만 버전에 따라 다르므로
--             도움말을 확인하는 것이 확실하다.
-- 재확인   : 올바른 옵션으로 다시 실행해 출력이 나오는지 본다.

[oracle@rac1 ~]$ srvctl status database -db racdb -verbose
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.
