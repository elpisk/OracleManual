================================================================================
 제9장 실습 02 — GV$ 로 두 ASM 인스턴스 함께 보기
 대상   : rac1 (일부 rac2)
 목표   : V$ 가 접속한 인스턴스만 보여 준다는 것을 확인하고, GV$ 로 두 노드의
          대칭을 점검하는 방법을 익힌다
 소요   : 약 20분
 선행   : 양 노드 CRS 정상, racdb1·racdb2 모두 OPEN
 계정   : grid
================================================================================

--------------------------------------------------------------------------------
 [1] 사전 확인 — 두 인스턴스가 정말 떠 있는가
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl check cluster -all
**************************************************************
rac1:
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online
**************************************************************
rac2:
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online
**************************************************************

[oracle@rac1 ~]$ srvctl status database -d racdb
Instance racdb1 is running on node rac1
Instance racdb2 is running on node rac2

-- 두 인스턴스가 확실히 떠 있는 상태에서 시작한다.
-- 이 확인을 먼저 해 두어야 다음 단계의 결과를 오해하지 않는다.

--------------------------------------------------------------------------------
 [2] V$ASM_CLIENT — rac1 에서 조회
--------------------------------------------------------------------------------

[grid@rac1 ~]$ sqlplus -s / as sysasm

SQL> select group_number, instance_name, db_name, status from v$asm_client
  2   order by group_number, instance_name;

GROUP_NUMBER INSTANCE_NAME     DB_NAME    STATUS
------------ ----------------- ---------- ------------
           1 +ASM1             +ASM       CONNECTED
           1 rac1.localdomain  _OCR       CONNECTED
           2 +ASM1             +ASM       CONNECTED
           2 racdb1            racdb      CONNECTED
           3 racdb1            racdb      CONNECTED

5 rows selected.

-- racdb1 은 보이는데 racdb2 가 없다.
-- [1] 에서 racdb2 가 running 인 것을 확인했으므로 장애가 아니다.
-- V$ 는 접속한 인스턴스가 아는 것만 보여 주고, racdb2 는 rac2 의 +ASM2 에
-- 붙어 있기 때문이다.
--
-- 클라이언트가 셋인 것도 눈여겨본다.
--   +ASM  : ASM 의 SPFILE·패스워드 파일이 +CRS 와 +DATA 안에 있어
--           자기 자신이 클라이언트로 잡힌다
--   _OCR  : 인스턴스가 아니라 CRS 데몬이다. OCR 파일이 +CRS 에 있으므로
--           CRS 도 ASM 의 클라이언트다. 그래서 INSTANCE_NAME 자리에
--           인스턴스명이 아니라 호스트명이 들어간다
--   racdb : 데이터베이스 인스턴스

--------------------------------------------------------------------------------
 [3] rac2 에서 같은 조회 — 대칭 확인
--------------------------------------------------------------------------------

[grid@rac2 ~]$ sqlplus -s / as sysasm

SQL> select group_number, instance_name, db_name, status from v$asm_client
  2   order by group_number, instance_name;

GROUP_NUMBER INSTANCE_NAME     DB_NAME    STATUS
------------ ----------------- ---------- ------------
           1 +ASM2             +ASM       CONNECTED
           1 rac2.localdomain  _OCR       CONNECTED
           2 +ASM2             +ASM       CONNECTED
           2 racdb2            racdb      CONNECTED
           3 racdb2            racdb      CONNECTED

5 rows selected.

-- 정확히 거울상이다. +ASM1 자리에 +ASM2, racdb1 자리에 racdb2.
-- 두 노드를 각각 조회하면 전체가 보이지만 노드 수만큼 접속해야 한다.

--------------------------------------------------------------------------------
 [4] GV$ 로 한 번에
--------------------------------------------------------------------------------

[grid@rac1 ~]$ sqlplus -s / as sysasm

SQL> select inst_id, group_number, instance_name, db_name, status
  2    from gv$asm_client order by inst_id, group_number, instance_name;

   INST_ID GROUP_NUMBER INSTANCE_NAME     DB_NAME    STATUS
---------- ------------ ----------------- ---------- ------------
         1            1 +ASM1             +ASM       CONNECTED
         1            1 rac1.localdomain  _OCR       CONNECTED
         1            2 +ASM1             +ASM       CONNECTED
         1            2 racdb1            racdb      CONNECTED
         1            3 racdb1            racdb      CONNECTED
         2            1 +ASM2             +ASM       CONNECTED
         2            1 rac2.localdomain  _OCR       CONNECTED
         2            2 +ASM2             +ASM       CONNECTED
         2            2 racdb2            racdb      CONNECTED
         2            3 racdb2            racdb      CONNECTED

10 rows selected.

-- 5 행이 10 행이 되었다. rac1 에 한 번 접속해 전체를 봤다.
-- INST_ID 로 어느 인스턴스의 행인지 구분한다.
--
-- 점검 요령 : 이 결과가 좌우 대칭인지만 보면 된다.
--             대칭이 깨져 있으면 그 자체가 이상 신호이고,
--             어느 쪽 행이 빠졌는지가 곧 문제의 위치다.

--------------------------------------------------------------------------------
 [5] 대칭이 의미 있는 경우와 아닌 경우
--------------------------------------------------------------------------------

SQL> select inst_id, name, state, type, total_mb, free_mb
  2    from gv$asm_diskgroup order by inst_id, group_number;

   INST_ID NAME     STATE       TYPE     TOTAL_MB    FREE_MB
---------- -------- ----------- ------ ---------- ----------
         1 CRS      MOUNTED     NORMAL      12288      11324
         1 DATA     MOUNTED     EXTERN      61440      56916
         1 FRA      MOUNTED     EXTERN      24576      23636
         2 CRS      MOUNTED     NORMAL      12288      11324
         2 DATA     MOUNTED     EXTERN      61440      56916
         2 FRA      MOUNTED     EXTERN      24576      23636

6 rows selected.

-- 디스크그룹은 두 인스턴스가 같은 값을 갖는다. 행만 두 배가 되었다.
-- 그래도 의미가 있다. 두 인스턴스가 같은 디스크그룹을 같은 크기로
-- 마운트하고 있는지 검증할 수 있기 때문이다.
--
-- 반대로 V$ASM_CLIENT·V$ASM_OPERATION 처럼 인스턴스마다 답이 다른 뷰는
-- GV$ 로 봐야 비로소 전체가 보인다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — rac1 에서 +ASM2 를 보려고 SID 만 바꾸면
--------------------------------------------------------------------------------

-- "rac2 의 인스턴스를 보고 싶으니 ORACLE_SID 만 +ASM2 로 바꾸면 되지 않을까"
-- 라는 발상이 자연스럽게 나온다. 실제로 해 본다.

[grid@rac1 ~]$ export ORACLE_HOME=/u01/app/19.3.0/grid
[grid@rac1 ~]$ export ORACLE_SID=+ASM2
[grid@rac1 ~]$ sqlplus -s / as sysasm
select 1 from dual
*
ERROR at line 1:
ORA-01034: ORACLE not available
Process ID: 0
Session ID: 0 Serial number: 0

-- 오류 : ORA-01034
--
-- 원인 파악 : / as sysasm 은 bequeath 접속이다. 리스너를 거치지 않고
--             로컬 프로세스로 붙으므로 그 SID 의 인스턴스가 이 노드에
--             실제로 떠 있어야 한다.
--             +ASM2 는 rac2 에서 돌고 있고 rac1 에는 없다.
--             SID 는 인스턴스를 가리키는 이름일 뿐 원격 접속 수단이 아니다.
-- 조치     : 두 가지 길이 있다.
--             (1) rac2 에 ssh 로 접속해 그 노드에서 V$ 를 조회한다.
--             (2) rac1 에 그대로 있으면서 GV$ 를 조회한다.
--             [3] 이 (1) 이고 [4] 가 (2) 다.
-- 재확인   : SID 를 되돌리고 정상 접속되는지 확인한다.

[grid@rac1 ~]$ export ORACLE_SID=+ASM1
[grid@rac1 ~]$ sqlplus -s / as sysasm

SQL> select instance_name, status from v$instance;

INSTANCE_NAME    STATUS
---------------- ------------
+ASM1            STARTED

1 row selected.

SQL> exit

-- 환경 변수 하나 때문이었음이 확정되었다.
-- 원격 인스턴스를 보는 방법은 SID 변경이 아니라 GV$ 이거나 원격 접속이다.

--------------------------------------------------------------------------------
 [7] GV$ 의 함정 — 진단 중에는 쓰지 않는다
--------------------------------------------------------------------------------

-- GV$ 조회는 조회를 던진 인스턴스가 다른 인스턴스에 병렬 슬레이브를 띄우고
-- 그 결과를 인터커넥트로 받아 합치는 방식이다.
--
-- 따라서 상대 인스턴스가 응답하지 못하면
--   - 조회 자체가 멈추거나
--   - 그 인스턴스의 행만 빠진 채로 돌아온다
--
-- 노드 장애를 진단하는 중에 GV$ 를 쓰면 세션이 걸릴 수 있다는 뜻이다.
-- 실제로 장애 대응 중에 습관적으로 GV$ 를 조회했다가 응답을 못 받고
-- 시간을 버리는 일이 흔하다.
--
-- 원칙 : 진단 중에는 각 노드에 직접 접속해 V$ 를 본다.
--        GV$ 는 클러스터가 건강할 때 전체 대칭을 훑는 용도로 쓴다.

SQL> exit
