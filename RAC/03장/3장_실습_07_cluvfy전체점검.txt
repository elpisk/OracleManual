--     root 소유에 다른 사용자는 읽기와 실행만 가능하다. grid 는 쓸 수 없다.
--     이것이 설치 완료 후의 정상 상태다.
--
--   즉 두 실패 모두 "설치 전 상태가 아니다"라는 사실을 정확히 지적한 것이다.
--   시스템에 문제가 있는 것이 아니다.

-- 조치 — 명령을 상황에 맞게 고른다.
--   설치 전 : runcluvfy.sh stage -pre crsinst
--   설치 후 : cluvfy stage -post crsinst
[grid@rac1 ~]$ cluvfy stage -post crsinst -n rac1,rac2 | tail -3

Post-check for cluster services setup was successful.

-- 재확인
--   같은 시스템인데 결과가 다르다. 검사 기준이 다르기 때문이다.
--
-- 배운 것
--   cluvfy 의 stage 는 시점을 지정하는 것이다. 시점에 맞지 않는 stage 를
--   쓰면 정상 상태를 실패로 보고한다. 실패 메시지를 보고 무작정 고치려
--   들면 오히려 클러스터를 망가뜨린다.
--   PRVG-11750 을 보고 /var/tmp/.oracle 을 지우면 Clusterware 프로세스 간
--   통신이 끊긴다. PRVG-11931 을 보고 Grid 홈 소유권을 grid 로 바꾸면
--   보안 구성이 깨진다. 둘 다 하면 안 되는 조치다.

--------------------------------------------------------------------------------
 [3] 설치 전 점검에서 실패 항목을 해소하는 절차
--------------------------------------------------------------------------------

-- 이 실습 환경의 실제 구축 과정에서 다섯 가지가 걸렸다. 그 순서를 정리한다.
--
-- 1차 실행 결과
--   PRVF-7530  Sufficient physical memory is not available on node "rac1"
--              [Required physical memory = 8GB (8388608.0KB)]
--   PRVG-11550 Package "cvuqdisk" is missing on node "rac1"
--   PRVG-13606 chrony daemon is not synchronized with any external time source
--   PRVG-1017  NTP configuration file "/etc/ntp.conf" is present on nodes
--   PRVG-2064  There are no configured name servers in the file
--              "/etc/resolv.conf"
--   PRVG-10048 Name "rac1" was not resolved to an address of the specified type
--
-- 해소 순서와 이유
--   (1) 메모리 — VM 을 정지해야 하므로 가장 먼저 한다.
--       vmx 의 memsize 를 8192 에서 9216 으로 올리고 재기동한다.
--       재기동 후 grep MemTotal /proc/meminfo 로 확인한다.
--
--   (2) cvuqdisk — 두 노드에 설치한다. 재기동이 필요 없다.
--       export CVUQDISK_GRP=oinstall 을 먼저 실행해야 그룹이 맞는다.
--       rpm -iv /u01/app/19.3.0/grid/cv/rpm/cvuqdisk-1.0.10-1.rpm
--       두 번째 노드에는 RPM 파일만 복사해 같은 방식으로 설치한다.
--
--   (3) 시간 동기 — chronyd 와 ntpd 를 정지·비활성화하고 설정 파일을 치운다.
--       파일이 남아 있으면 Oracle 이 NTP 를 쓰겠다는 뜻으로 읽는다.
--       systemctl stop chronyd; systemctl disable chronyd
--       mv /etc/chrony.conf /etc/chrony.conf.orig
--       이후 CTSS 가 시간 동기를 맡는다.
--
--   (4) 이름 해석 — 두 조건을 함께 만족시켜야 한다.
--       dnsmasq 를 설치하고 /etc/hosts 를 DNS 로 서비스한다.
--       resolv.conf 에 nameserver 127.0.0.1 을 넣고 chattr +i 로 고정한다.
--
-- 한 번에 하나씩 고치는 것이 원칙이다. 여러 항목을 동시에 고치면 무엇이
-- 효과가 있었는지 알 수 없고, 한 조치가 다른 항목을 새로 깨뜨렸을 때
-- 추적하기 어렵다. 실제로 resolv.conf 를 비웠다가 다른 오류가 났다.

--------------------------------------------------------------------------------
 [4] 항목만 좁혀 확인하는 방법
--------------------------------------------------------------------------------

-- 전체 점검은 시간이 걸린다. 조치 직후에는 해당 항목만 comp 로 확인한다.

[grid@rac1 ~]$ cluvfy comp scan | tail -3
Verification of SCAN was successful.

[grid@rac1 ~]$ cluvfy comp nodereach -n rac1,rac2 | tail -3
Verification of node reachability was successful.

[grid@rac1 ~]$ cluvfy comp ocr -n rac1,rac2 | tail -3
Verification of OCR integrity was successful.

[grid@rac1 ~]$ cluvfy comp vdisk -n rac1,rac2 | tail -3
Verification of Voting Disk was successful.

-- 각 항목을 확인한 뒤 마지막에 전체를 한 번 돌리는 것이 효율적이다.

--------------------------------------------------------------------------------
 [5] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) stage -post crsinst 는 28개 항목을 검사하고 1.6분이 걸렸다
--   2) 설치 완료 환경에서 stage -pre crsinst 는 PRVG-11750 과 PRVG-11931 로
--      실패한다. 시스템 문제가 아니라 stage 를 잘못 고른 것이다
--   3) /var/tmp/.oracle 은 Clusterware 의 소켓·잠금 디렉터리다. 지우면 안 된다
--   4) Grid 홈은 설치 후 root 소유가 된다. 정상이다
--   5) 실패 항목은 한 번에 하나씩 고친다
--   6) 조치 직후에는 comp 로 좁혀 확인하고 마지막에 전체를 돌린다
--   7) WARNING 은 판단하고 그 이유를 기록한다
--
-- 이 실습은 조회만 했으므로 원상 복구할 것이 없다.
-- 다만 PRVG-11750 이나 PRVG-11931 을 보고 조치를 취하지 않았는지
-- 반드시 확인한다. 그 두 항목은 손대면 안 되는 것이다.
