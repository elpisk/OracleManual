 제3장 실습 03 — cluvfy 로 SCAN 점검
 대상   : rac1
 목표   : cluvfy 의 명령 체계를 익히고 comp 단위로 항목을 좁혀 점검하며,
          PASSED · WARNING · FAILED 를 구분해 읽는다
 소요   : 약 20분
 선행   : Clusterware 가 기동되어 있을 것
 계정   : grid

--------------------------------------------------------------------------------
 [1] cluvfy 명령 체계
--------------------------------------------------------------------------------

-- 설치 전과 후에 쓰는 실행 파일이 다르다.
--   설치 전 : 미디어 루트의 runcluvfy.sh
--             Oracle 소프트웨어 없이도 동작하도록 만들어졌다
--   설치 후 : Grid 홈의 bin/cluvfy. PATH 에 들어 있다

[root@rac1 ~]# su - grid
[grid@rac1 ~]$ which cluvfy
/u01/app/19.3.0/grid/bin/cluvfy

[grid@rac1 ~]$ ls /u01/app/19.3.0/grid/runcluvfy.sh
/u01/app/19.3.0/grid/runcluvfy.sh

-- 둘 다 있다. 미디어를 Grid 홈에 직접 풀었기 때문이다(19c 이미지 기반 설치).

-- 주요 사용 형태
--   runcluvfy.sh stage -pre crsinst -n rac1,rac2    설치 전 전체 점검
--   cluvfy stage -post crsinst -n rac1,rac2         설치 후 검증
--   cluvfy comp scan                                SCAN 이름 해석
--   cluvfy comp nodereach -n rac1,rac2              노드 도달 가능성
--   cluvfy comp nodecon -n rac1,rac2 -verbose       노드 간 연결과 MTU
--   cluvfy comp ocr -n rac1,rac2                    OCR 무결성
--   cluvfy comp vdisk -n rac1,rac2                  보팅 파일

--------------------------------------------------------------------------------

--     Name Service Switch Configuration File Integrity ...PASSED   (가장 안쪽)

--
--   두 노드에서 각각 같은 경고가 나온다. 클러스터 전체 관점의 검사이므로
--   모든 노드에서 확인하기 때문이다.

--------------------------------------------------------------------------------
 [3] PASSED · WARNING · FAILED 를 구분한다
--------------------------------------------------------------------------------

-- PASSED   요건을 만족했다. 넘어간다.
-- WARNING  권장 사항을 따르지 않았거나 최적이 아니다. 판단이 필요하다.
--          감수하기로 했다면 그 판단과 이유를 문서에 남긴다.
-- FAILED   요건을 만족하지 못했다. 반드시 해소하고 넘어간다.
--
-- 이 실습 환경의 판단
--   PRVG-11368 (SCAN IP 하나)  →  감수한다.
--   이유 : 학습 목적이며 SCAN 재지시 동작을 확인하는 데는 하나로 충분하다.
--          DNS 라운드로빈으로 세 개를 돌리려면 별도 DNS 서버가 필요하다.
--   운영 환경 설계 시에는 반드시 세 개를 권장한다.

--------------------------------------------------------------------------------
 [4] 오류 재현 — FAILED 는 어떻게 보이는가
--------------------------------------------------------------------------------

-- 경고와 실패의 차이를 눈으로 보기 위해 일부러 실패를 만든다.
-- 존재하지 않는 노드 이름을 넘긴다.

[grid@rac1 ~]$ cluvfy comp nodereach -n rac1,rac9

Failures were encountered during execution of CVU verification request
"node reachability".

Verifying Node Reachability ...FAILED
rac9: PRVF-4083 : Node reachability check failed from node "rac1"
      PRKN-1034 : Failed to retrieve IP address of host "rac9"
      unknown host exception for host "rac9"


CVU operation performed:      node reachability
Date:                         Sep 1, 2026 2:28:13 PM
CVU home:                     /u01/app/19.3.0/grid/
User:                         grid

-- 경고와 다른 점
--   머리말이 Warnings 가 아니라 Failures 다
--   판정이 WARNING 이 아니라 FAILED 다
--   successful 로 끝나는 줄이 없다
--
-- 원인 파악
--   세 줄을 아래에서 위로 읽는다.
--     unknown host exception for host "rac9"   근본 원인 — 이름 해석 실패
--     PRKN-1034 Failed to retrieve IP address  원인 — 그래서 IP 를 못 얻었다
--     PRVF-4083 Node reachability check failed 결과 — 도달 검사가 실패했다
--
--   첫 줄만 읽으면 도달 불가로 오해해 네트워크나 방화벽을 뒤지게 된다.
--
--   확인할 것
[grid@rac1 ~]$ nslookup rac9
Non-authoritative answer:
*** Can't find rac9: No answer

[grid@rac1 ~]$ grep -c rac9 /etc/hosts
0

--   이름이 등록되어 있지 않다. 철자 오류이거나 아직 추가하지 않은 노드다.

-- 조치 — 올바른 이름으로 실행한다.
[grid@rac1 ~]$ cluvfy comp nodereach -n rac1,rac2

Verifying Node Reachability ...PASSED

Verification of node reachability was successful.

-- 재확인
--   PASSED 로 바뀌었다. 이름 해석 문제였음이 확정된다.

 [6] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) 설치 전은 runcluvfy.sh, 설치 후는 bin/cluvfy
--   2) comp 로 항목을 좁혀 빠르게 확인할 수 있다
--   3) 들여쓰기가 검사의 계층을 나타낸다
--   4) PASSED · WARNING · FAILED 를 구분해 읽는다

--   6) FAILED 는 머리말이 Failures 이고 successful 줄이 없다
--   7) 오류는 아래에서 위로 읽어야 진짜 원인이 나온다
--
-- 이 실습은 조회만 했으므로 원상 복구할 것이 없다.
