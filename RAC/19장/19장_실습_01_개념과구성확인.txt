 제19장 실습 01 — RAC One Node 개념과 구성 확인
 대상   : rac1, rac2
 목표   : 지금의 racdb 가 어떤 유형인지 확인하고, RAC One Node 로 바꾸는 데
          필요한 조건과 명령을 미리 읽는다
 소요   : 약 15분
 선행   : 18장 완료. racdb 양 노드 OPEN, 부하 4 이하
 계정   : oracle, root
 주의   : 이 장은 데이터베이스 유형을 바꿨다가 되돌린다. 바뀌는 것은 OCR 의
          데이터베이스 자원 정의이므로 VM 스냅샷으로는 되돌릴 수 없다

--------------------------------------------------------------------------------
 [1] RAC One Node 란
--------------------------------------------------------------------------------

-- 세 가지 데이터베이스 구성을 나란히 놓는다.
--
--   단일 인스턴스    노드 하나, 인스턴스 하나. 노드가 죽으면 끝이다.
--   RAC              노드 여럿, 인스턴스 여럿이 동시에 연다.
--   RAC One Node     노드 여럿을 후보로 두고, 인스턴스는 하나만 돈다.
--                    필요하면 그 인스턴스를 다른 노드로 옮긴다(온라인 재배치).
--
-- RAC One Node 는 공유 스토리지와 Clusterware 는 RAC 와 같고,
-- 동시에 여는 인스턴스가 하나라는 점만 다르다.
-- 노드 유지보수 때 데이터베이스를 다른 노드로 옮겨 두는 용도로 쓴다.
--
-- 18장에서 rac2 를 지운 뒤의 상태와 헷갈리기 쉽다.
-- 그때는 "인스턴스가 하나뿐인 RAC" 였다. 다른 노드로 옮기는 기능이 없었다.

-- 있으므로 스냅샷으로 되돌아가지 않는다. 수동 백업을 함께 둔다.

--
-- 기본 서비스(racdb, racpdb1) 말고는 srvctl 에 등록된 서비스가 없다.
-- 실습 02 에서 이것이 걸림돌이 된다.

--------------------------------------------------------------------------------
 [5] 명령 미리 읽기
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl convert database -help

Convert RAC One Node database to RAC database having one instance.
Usage: srvctl convert database -db <db_unique_name> -dbtype RAC [-node <node>]

Convert RAC database having one instance to RAC One Node database.
Usage: srvctl convert database -db <db_unique_name> -dbtype RACONENODE [-instance <inst_name>] [-timeout <timeout>]
    -instance <inst_name>          Instance name prefix; required for administrator-managed RAC One Node database
    -timeout <timeout>             Online relocation timeout in minutes

-- 사용법 설명에 조건이 이미 적혀 있다.
--
--   "RAC database having one instance"
--     RAC → RAC One Node 는 인스턴스가 하나인 RAC 만 바꿀 수 있다.
--     반대 방향의 결과도 "RAC database having one instance" 다.
--
--   -instance 는 인스턴스 이름이 아니라 접두어(prefix)다.
--     관리자 관리형에서는 필수다.
--
--   -timeout 은 온라인 재배치 때 원래 인스턴스가 내려가기를 기다리는 시간(분)이다.

[oracle@rac1 ~]$ srvctl relocate database -help

Initiate online relocation of the RAC One Node database.
Usage: srvctl relocate database -db <db_unique_name> {[-node <target>] [-timeout <timeout>] [-stopoption <stop_option>] | -abort [-revert]} [-drain_timeout <timeout>] [-verbose]
    -abort                         Abort failed online relocation
    -revert                        Remove target node of failed online relocation request from the candidate server list of administrator-managed RAC One Node database

-- -abort 와 -revert 가 있다는 것은 재배치가 중간에 실패할 수 있다는 뜻이다.
-- 실패한 재배치를 정리하는 명령이 따로 준비되어 있다.

--------------------------------------------------------------------------------
 [5-1] 흔한 오류 — 일반 RAC 에 relocate 를 치면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl relocate database -db racdb -node rac2
PRCD-1146 : Database racdb is not a RAC One Node database

-- 0.5초 만에 거부됐다.
--
-- 원인 파악 : 온라인 재배치는 RAC One Node 전용 기능이다.
--             일반 RAC 는 이미 모든 노드에서 인스턴스가 돌고 있으므로
--             옮긴다는 개념이 없다. 15장의 서비스 재배치
--             (srvctl relocate service)와 이름이 비슷해 헷갈린다.
--               srvctl relocate service    서비스를 다른 인스턴스로 옮긴다 (RAC)
--               srvctl relocate database   인스턴스를 다른 노드로 옮긴다 (One Node)
-- 조치     : 유형부터 확인한다. srvctl config database 의 Type 줄.
-- 재확인   : 아무것도 바뀌지 않았다.

[oracle@rac1 ~]$ srvctl status database -db racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.
