================================================================================
 제19장 실습 04 — 오류 재현: 재배치 중에 다른 명령을 내면
 대상   : rac1, rac2
 목표   : rac1 로 되돌리는 재배치를 걸어 두고, 진행 중에 재배치·정지·설정 변경을
          차례로 시도해 무엇이 막히고 무엇이 통하는지 확인한다
 소요   : 약 15분 (재배치 85.9초)
 선행   : 실습 03 완료 — racdb_2 가 rac2 에서 Open
 계정   : oracle
================================================================================

--------------------------------------------------------------------------------
 [1] 재배치를 걸어 둔다
--------------------------------------------------------------------------------

-- 세션 A 에서 rac1 로 되돌리는 재배치를 시작했다.

[세션 A] [oracle@rac1 ~]$ srvctl relocate database -db racdb -node rac1 -verbose

-- 15초 뒤 세션 B 에서 상태를 본다.

[세션 B, 15초] [oracle@rac1 ~]$ srvctl status database -db racdb -v
Instance racdb_2 is running on node rac2 with online services ronsvc. Instance status: Open.
Online relocation: ACTIVE
Source instance: racdb_2 on rac2
Destination instance: racdb_1 on rac1

-- 재배치 중이다. 목적지 인스턴스 이름은 racdb_1 이다.
-- 실습 02 에서 구성에만 있던 그 이름이 이제 실제로 뜬다.

--------------------------------------------------------------------------------
 [2] 같은 데이터베이스를 또 재배치하면
--------------------------------------------------------------------------------

[세션 B, 16초] [oracle@rac1 ~]$ srvctl relocate database -db racdb -node rac2
PRCD-1161 : Online relocation failed for RAC One Node database racdb
PRCD-1164 : An online relocation request for RAC One Node database racdb is already active

-- 2.8초 만에 거부됐다.
--
-- 원인 파악 : 재배치는 데이터베이스당 하나만 진행된다. PRCD-1164 가 이유다.
--             PRCD-1161 은 "이번 재배치 요청이 실패했다" 는 겉 메시지일 뿐이고
--             진행 중인 세션 A 의 재배치가 실패한 것은 아니다.
--             두 줄을 위에서부터 읽으면 재배치 자체가 깨진 것으로 오해하기 쉽다.
--             아래쪽 줄이 원인이다.
-- 조치     : 세션 A 가 끝나기를 기다린다. 다른 노드로 보내고 싶었다면
--             끝난 뒤 다시 relocate 한다.
-- 재확인   : [5] 에서 세션 A 가 정상 완료된 것을 본다.

--------------------------------------------------------------------------------
 [3] 데이터베이스를 정지하면
--------------------------------------------------------------------------------

[세션 B, 18초] [oracle@rac1 ~]$ srvctl stop database -db racdb
PRKO-2143 : Cannot stop RAC One Node database when an online relocation request for the database is already active

-- 2.5초 만에 거부됐다.
--
-- 원인 파악 : 재배치 중에는 인스턴스 둘이 잠시 함께 돈다.
--             그 사이에 데이터베이스를 내리면 어느 쪽을 어떤 순서로 내릴지,
--             재배치를 어떻게 마무리할지가 모호해진다. srvctl 이 아예 막는다.
-- 조치     : 꼭 지금 멈춰야 한다면 재배치를 먼저 끝내거나,
--             실패한 재배치라면 srvctl relocate database -db racdb -abort 로 정리한 뒤 정지한다.
-- 재확인   : 데이터베이스는 계속 열려 있다.

--------------------------------------------------------------------------------
 [4] 재배치 시간 제한을 바꾸면 — 이것은 통한다
--------------------------------------------------------------------------------

[세션 B, 20초] [oracle@rac1 ~]$ srvctl modify database -db racdb -timeout 10

-- 10.0초 걸렸고 rc=0 이다. 오류 없이 받아들여졌다.
-- 재배치와 정지는 막혔는데 설정 변경은 통했다. 그리고 진행 중인 재배치에 바로 반영됐다.

--------------------------------------------------------------------------------
 [5] 세션 A 의 결과
--------------------------------------------------------------------------------

[세션 A]
Configuration updated to two instances
Instance racdb_1 started
Services relocated
Waiting for up to 10 minutes for instance racdb_2 to stop ...
Instance racdb_2 stopped
Configuration updated to one instance

-- 85.9초에 끝났다.
--
-- "Waiting for up to 10 minutes" 를 본다. 실습 03 에서는 30 minutes 였다.
-- 세션 A 는 timeout 30 인 상태로 시작했는데, 대기 단계에 들어갈 때는
-- 세션 B 가 바꾼 10 분을 읽었다.
--
-- rac2 알럿 로그에서도 확인된다.

[oracle@rac2 ~]$ grep -nE 'Shutting down ORACLE|_shutdown_completion_timeout|Instance shutdown complete' >   /u01/app/oracle/diag/rdbms/racdb/racdb_2/trace/alert_racdb_2.log
664:Shutting down ORACLE instance (transactional local) (OS id: 23804)
740:ALTER SYSTEM SET _shutdown_completion_timeout_mins=10 SCOPE=MEMORY;
833:Instance shutdown complete (OS id: 23804)

-- 실습 03 에서는 30 이었던 값이 10 으로 들어갔다.
-- srvctl 은 정지를 시작하는 순간의 구성 값을 읽어 이 파라미터로 넘긴다.
--
-- 이 동작은 양날이다.
--   좋은 쪽   오래 걸리는 재배치의 대기 상한을 도중에 줄일 수 있다.
--   나쁜 쪽   다른 사람이 같은 데이터베이스의 설정을 바꾸면 진행 중인 내 작업이
--             예상과 다른 값으로 끝난다. 대기 상한이 짧아지면 세션이 남아 있는
--             인스턴스를 그만큼 빨리 정리한다.
--
-- 재배치 중에는 그 데이터베이스의 srvctl modify 도 하지 않는 것으로 운영 규칙을 정한다.

[oracle@rac1 ~]$ srvctl status database -db racdb -v
Instance racdb_1 is running on node rac1 with online services ronsvc. Instance status: Open.
Online relocation: INACTIVE

[oracle@rac1 ~]$ srvctl config database -db racdb | grep -E "Candidate|instances|timeout"
Online relocation timeout: 10
Candidate servers: rac1,rac2
Database instances: racdb_1

-- rac1 으로 돌아왔다. 이번에는 인스턴스 이름이 racdb_1 이다.
-- 처음의 racdb1 과 다르다. 접두어 방식으로 이름이 바뀐 것이다.
-- 재배치 시간 제한은 10 으로 남았다.

--------------------------------------------------------------------------------
 [6] 정리
--------------------------------------------------------------------------------

--   명령                        재배치 중   메시지
--   -------------------------   ---------   ------------------------
--   srvctl status database      가능        Online relocation: ACTIVE
--   srvctl relocate database    거부        PRCD-1161 + PRCD-1164
--   srvctl stop database        거부        PRKO-2143
--   srvctl modify -timeout      가능        진행 중인 재배치에 반영됨
--
-- 재배치 소요 시간은 rac1 → rac2 가 99.5초, rac2 → rac1 이 85.9초였다.

================================================================================
 실습 04 종료 — racdb_1 on rac1, timeout 10, 재배치 중 명령 4종의 반응 확인
