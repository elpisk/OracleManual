================================================================================
 제16장 실습 05 — 오류 재현, 필수 속성 없이 AC 를 켜려 하면
 대상   : rac1
 목표   : AC 의 필수 조합을 오류로 확인하고, 문법 오류와 의미 오류의
          성격 차이를 구분한다
 소요   : 약 20분
 선행   : 실습 04 완료
 계정   : oracle
 주의   : 이 실습의 명령은 모두 거부된다. 기존 서비스에 영향이 없다
================================================================================

--------------------------------------------------------------------------------
 [0] 시작 전 상태
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl config service -d racdb | grep 'Service name'
Service name: ch16_ac
Service name: ch16_lb

[oracle@rac1 ~]$ srvctl status service -d racdb
Service ch16_ac is running on instance(s) racdb1
Service ch16_lb is running on instance(s) racdb1,racdb2

-- 이 상태가 실습 끝까지 유지되어야 한다.

--------------------------------------------------------------------------------
 [1] 오류 재현 A — TRANSACTION 인데 commit_outcome 없이
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl add service -d racdb -s ch16_bad \
>                  -preferred racdb1 -available racdb2 -failovertype TRANSACTION
PRCD-1259 : Addition or modification of failover type to TRANSACTION is not allowed
            when commit outcome is set to FALSE

-- 원인 파악 : -failovertype TRANSACTION 은 -commit_outcome TRUE 를 요구한다.
--             메시지가 이유까지 알려 주는 드문 사례다.
--             근본 이유는 두 기능의 관계에 있다.
--             트랜잭션을 재생하려면 먼저 그 트랜잭션이 커밋되었는지
--             알아야 한다. 이미 커밋된 것을 다시 실행하면 중복이 된다.
--             commit_outcome 이 그 판정을 가능하게 하는 장치이므로
--             없이는 재생을 켤 수 없다.
-- 조치     : 두 옵션을 함께 준다.
--               srvctl add service -d racdb -s <서비스> \
--                 -preferred racdb1 -available racdb2 \
--                 -failovertype TRANSACTION -commit_outcome TRUE
--             실습 04 에서 그렇게 만들었다.
-- 재확인   : 거부된 뒤 서비스가 만들어지지 않았는지 확인한다.

[oracle@rac1 ~]$ srvctl config service -d racdb -s ch16_bad
PRCR-1001 : Resource ora.racdb.ch16_bad.svc does not exist

-- 서비스가 만들어지지 않았다. PRCR-1001 이 그 근거다.
--
-- 이 확인이 중요하다. 거부되면 아무것도 남지 않는다.
-- 15장에서 PRKO-2101 을 봤을 때와 같은 종류의 안전장치이며,
-- 잘못된 정의가 저장되지 않는다.
--
-- 만약 만들어졌다면 기동할 때가 되어서야 문제를 알게 되고,
-- 그때는 이미 애플리케이션 접속 문자열이 그 서비스 이름에
-- 의존하고 있을 수 있다. 만들 때 막아 주는 것이 훨씬 싸게 먹힌다.

--------------------------------------------------------------------------------
 [2] 오류 재현 B — 없는 값을 주면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl add service -d racdb -s ch16_bad2 -preferred racdb1 -failovertype FOO
PRKO-3125 : Invalid value FOO for command line option failovertype

[oracle@rac1 ~]$ srvctl add service -d racdb -s ch16_bad3 -preferred racdb1 -rlbgoal FASTEST
PRKO-3125 : Invalid value FASTEST for command line option rlbgoal

-- 원인 파악 : 값 자체가 목록에 없다.
--             failovertype 의 값은 NONE, SESSION, SELECT, TRANSACTION, AUTO 다.
--             rlbgoal 의 값은 NONE, SERVICE_TIME, THROUGHPUT 이다.
--             FASTEST 는 이름만 보면 그럴듯해서 흔히 하는 실수다.
--             PRKO 접두어이므로 명령행 해석 단계에서 걸렸다.
--             자원을 조회하러 가기도 전에 거부되었다는 뜻이다.
-- 조치     : -help 로 값 목록을 확인한다.
--               srvctl add service -help | grep -E 'failovertype|rlbgoal'
--             값 목록을 외우려 하지 말고 도움말을 보는 습관을 들인다.
-- 재확인   : 메시지에 잘못된 값과 옵션 이름이 함께 나오므로
--             그것만 보고도 오타를 찾을 수 있다.

[oracle@rac1 ~]$ srvctl add service -help 2>&1 | grep -E 'failovertype |rlbgoal '
    -failovertype   (NONE | SESSION | SELECT | TRANSACTION | AUTO)   Failover type
    -rlbgoal        (SERVICE_TIME | THROUGHPUT | NONE)   Runtime Load Balancing Goal

--------------------------------------------------------------------------------
 [3] 두 오류의 성격 차이
--------------------------------------------------------------------------------

-- 같은 명령에서 나온 오류지만 성격이 다르다.
--
--   PRKO-3125   값이 목록에 없다. 문법 오류다.
--               해결: -help 로 값 목록을 확인한다.
--               접두어가 PRKO 이므로 명령행 해석 단계다.
--
--   PRCD-1259   값은 모두 유효한데 조합이 안 된다. 의미 오류다.
--               해결: 왜 그 조합이 필요한지를 이해해야 한다.
--               접두어가 PRCD 이므로 데이터베이스 계층까지 갔다 거부되었다.
--
-- 이 구분이 오류를 만났을 때 어디를 볼지 정해 준다.
-- 14장에서 정리한 접두어 체계가 그대로 쓰인다.
--
-- 문법 오류는 도움말로 5초 만에 해결된다.
-- 의미 오류는 그 기능이 왜 그렇게 설계되었는지를 알아야 풀린다.

--------------------------------------------------------------------------------
 [4] 참고 — 다른 조합도 확인해 본다
--------------------------------------------------------------------------------

-- TRANSACTION 이 아닌 값은 commit_outcome 없이도 만들어진다.
-- SELECT 는 진행 중이던 조회를 이어서 하는 것이라
-- 커밋 여부를 판정할 필요가 없기 때문이다.
--
--   srvctl add service -d racdb -s <서비스> -preferred racdb1 \
--     -failovertype SELECT
--
-- 이 실습에서는 만들지 않는다. 정리할 것을 늘리지 않기 위해서다.
-- 필요하면 만들어 보고 반드시 지운다.
--
-- 조회 위주 애플리케이션이라면 SELECT 로 충분한 경우가 많다.
-- 트랜잭션 재생은 얻는 것도 크지만 애플리케이션 검토 부담도 크다.
