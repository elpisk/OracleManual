-- compatible.asm 은 19.0.0.0.0 인데 compatible.rdbms 만 10.1.0.0.0 이다.
--
-- 왜 그런가. 4장에서 사용한 응답 파일 gridsetup.rsp 를 보면 답이 나온다.
--   oracle.install.asm.diskGroup.redundancy=NORMAL

-- 중복도와 AU 크기는 지정했지만 compatible 계열 항목이 없다. 지정하지 않으면
-- ASM 은 compatible.rdbms 에 가장 낮은 값인 10.1.0.0.0 을 넣는다.
--
-- 19c 로 설치했으니 모든 기능이 켜져 있으리라 생각하기 쉽지만, 디스크그룹
-- 속성은 설치 버전과 무관하게 기본값을 따른다. 디스크 OFFLINE/ONLINE, 즉
-- fast mirror resync 는 11.1 에서 들어온 기능이라 막혀 있었다.
--
-- 재확인   : alert.log 에도 같은 기록이 남았는지 본다.

-- 상향하기 전에, 같은 값으로 설정하면 어떻게 되는지 본다.

SQL> alter diskgroup CRS set attribute 'compatible.rdbms'='10.1.0.0.0';

Diskgroup altered.

-- 성공한다. 현재 값과 같으므로 실질적인 변경이 없기 때문이다.
-- 이 결과를 기억해 둔다. 잠시 뒤 같은 명령이 실패한다.

SQL> alter diskgroup CRS set attribute 'compatible.rdbms'='11.2.0.0.0';

Diskgroup altered.

SQL> select name, value from v$asm_attribute
  2   where group_number = (select group_number from v$asm_diskgroup where name='CRS')
  3     and name like 'compatible%';

NAME                VALUE
------------------- ------------
compatible.asm      19.0.0.0.0
compatible.rdbms    11.2.0.0.0

-- 11.2 로 올렸다. 왜 19.0 이 아니라 11.2 인가.
-- 필요한 최소 값만 올리는 것이 원칙이다. ORA-15283 이 요구한 것은 11.1
-- 이상이고, 19.0 까지 올리면 데이터베이스 쪽 호환성 제약이 함께 걸린다.

-- 이제 다시 낮춰 본다.
SQL> alter diskgroup CRS set attribute 'compatible.rdbms'='10.1.0.0.0';
alter diskgroup CRS set attribute 'compatible.rdbms'='10.1.0.0.0'
*
ERROR at line 1:
ORA-15032: not all alterations performed
ORA-15242: could not set attribute compatible.rdbms
ORA-15244: new compatibility setting less than current [11.2.0.0.0]

-- 오류 : ORA-15242, ORA-15244
-- 원인 파악 : 조금 전에는 같은 명령이 성공했다. 그때는 현재 값이 10.1 이라
--             같은 값 설정이었고, 지금은 11.2 에서 10.1 로 낮추는 것이다.
--             compatible 속성은 올릴 수만 있고 낮출 수 없다.
-- 조치     : 낮추려면 디스크그룹을 삭제하고 다시 만드는 수밖에 없다.
--             그런데 +CRS 에는 OCR 과 Voting File 이 들어 있다. 삭제한다는
--             것은 클러스터를 재구축한다는 뜻이다. 실질적으로 되돌릴 수 없다.
-- 재확인   : 값이 11.2 로 유지되고 있는지 확인한다. 실패한 명령이 값을
--             건드리지 않았다.

-- ※ 이 장의 다른 모든 실습은 원상 복구된다. 이 한 가지만 예외다.
--    실습 시작 전 [0] 의 공유 디스크 백업이 필요한 이유 중 하나가 이것이다.

 [6] repair_timer 가 0인 이유
--------------------------------------------------------------------------------

-- 일반적인 ASM 디스크를 내리면 REPAIR_TIMER 가 흐르기 시작한다.
-- DISK_REPAIR_TIME 안에 다시 올리면 변경분만 재동기화하고, 넘기면 디스크가
-- 강제로 제거되어 전체 리밸런스가 일어난다.

SQL> select name, value from v$asm_attribute
  2   where group_number = (select group_number from v$asm_diskgroup where name='CRS')
  3     and name like '%repair%';

NAME                    VALUE
----------------------- ------
disk_repair_time        12.0h
failgroup_repair_time   24.0h

-- 12시간이면 넉넉하다. 그런데 1분을 기다려도 타이머가 움직이지 않는다.

SQL> select name, mode_status, repair_timer from v$asm_disk
  2   where group_number = (select group_number from v$asm_diskgroup where name='CRS')
  3   order by disk_number;

NAME       MODE_ST REPAIR_TIMER
---------- ------- ------------
CRS_0000   ONLINE             0
CRS_0001   ONLINE             0
CRS_0002   OFFLINE            0

-- 이유는 alert.log 의 op = clear mandatory 에 있다.
-- Voting File 을 담은 디스크는 mandatory 속성을 갖는다. 그 속성이 해제된
-- 디스크에는 통상적인 repair timer 가 적용되지 않는다. Voting File 은 이미
-- 재배치로 처리되었으므로 타이머로 관리할 대상이 아니다.
--
-- 설정을 잘못한 것이 아니다. alert.log 를 함께 읽지 않으면 설명할 수 없는
-- 현상이다.

-- 재현한 오류
--   ORA-15032 / ORA-15283   compatible.rdbms 가 11.1 미만
--   ORA-15242 / ORA-15244   compatible 속성 하향 시도
--
-- 확인한 것
--   1) 19c 로 설치해도 compatible.rdbms 기본값은 10.1 이다
--   2) 응답 파일에 항목이 없으면 ASM 이 가장 낮은 값을 넣는다
--   3) compatible 속성은 올릴 수만 있고 낮출 수 없다
--   4) 같은 값 설정은 성공하지만 낮추면 ORA-15244 다
--   5) 디스크를 내리면 MODE_STATUS OFFLINE, PATH 빈 값, VOTING_FILE N
--   6) TOTAL_MB 는 그대로다. 제거가 아니라 접근 불가 표시다
--   7) USABLE_FILE_MB 가 줄어든다. 3634 였다
--   8) Voting File 이 2개가 되었지만 과반수라 클러스터는 정상이다
--   9) OFFLINE 과 Voting File 재배치는 별개 단계다. 약 4초 시차가 있었다
--  10) Voting File 디스크는 mandatory 속성 때문에 repair timer 가 흐르지 않는다
--  11) 복구 시 그 디스크의 FUID 는 새로 부여된다. 정상이다
--  12) alert.log 의 clear mandatory 와 assign mandatory 가 대칭을 이룬다
--
-- 실무 체크리스트 (디스크 교체 전)
--   USABLE_FILE_MB 가 양수인가
--   해당 디스크가 VOTING_FILE=Y 인가
--   중복도가 Normal 이상인가
--   DISK_REPAIR_TIME 이 작업 시간보다 긴가
--   작업 전후 crsctl query css votedisk 로 FUID 를 기록했는가
