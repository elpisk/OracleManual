 [1] 두 메시지를 분리해 본다
--------------------------------------------------------------------------------

[root@rac1 ~]# ocrconfig -showbackup
PROT-24: Auto backups for the Oracle Cluster Registry are not available
PROT-25: Manual backups for the Oracle Cluster Registry are not available

-- 오류 : PROT-24, PROT-25
-- 원인 파악 : 두 줄이 함께 나오지만 서로 다른 것을 말한다. 옵션으로 분리해
--             확인하면 명확해진다.

[root@rac1 ~]# ocrconfig -showbackup auto
PROT-24: Auto backups for the Oracle Cluster Registry are not available

[root@rac1 ~]# ocrconfig -showbackup manual
PROT-25: Manual backups for the Oracle Cluster Registry are not available

-- PROT-24 는 자동 백업이 없다는 뜻, PROT-25 는 수동 백업이 없다는 뜻이다.
-- 실패가 아니라 상태 보고다. 보여 줄 것이 없다는 의미다.
--
-- 그러나 상태 자체는 위험 신호다. 지금 클러스터에 문제가 생기면 되돌릴
-- 수단이 아무것도 없다.
--
-- 조치     : 원인을 둘로 나눠 확인한다. 수동 백업은 아무도 실행하지 않아서
--             없는 것이 명백하다. 자동 백업이 없는 이유를 [2] 에서 찾는다.
-- 재확인   : 실습 03 에서 수동 백업을 만든 뒤 PROT-25 가 사라지는지 본다.

--------------------------------------------------------------------------------
 [2] 자동 백업이 없는 이유 — crsd 기동 시각
--------------------------------------------------------------------------------

-- OCR 자동 백업은 crsd 가 4시간 주기로 수행한다. 그렇다면 crsd 가 언제부터
-- 돌고 있는지가 답이다.

[root@rac1 ~]# ps -eo pid,lstart,cmd | grep crsd.bin | grep -v grep
 4244 Tue Sep  1 15:53:29 2026 /u01/app/19.3.0/grid/bin/crsd.bin reboot

[root@rac2 ~]# ps -eo pid,lstart,cmd | grep crsd.bin | grep -v grep
 4393 Tue Sep  1 15:53:07 2026 /u01/app/19.3.0/grid/bin/crsd.bin reboot

[root@rac1 ~]# date; uptime
Tue Sep  1 16:17:18 KST 2026
 16:17:18 up 26 min,  0 users,  load average: 1.47, 1.63, 1.43

-- crsd 는 15:53:29 에 떴고 지금은 16:17:18 이다. 24분이 지났을 뿐이다.
-- 4시간 주기가 아직 한 번도 돌지 않았다.
--
-- 여기서 중요한 함정이 하나 있다. 이 타이머는 crsd 가 재시작될 때마다
-- 0으로 초기화된다. 실습 환경처럼 클러스터를 자주 내렸다 올리면 자동 백업이
-- 영원히 만들어지지 않을 수 있다.
--
-- 운영 환경에서도 마찬가지다. 야간 배치를 위해 매일 새벽 클러스터를 내리는
-- 사이트라면 4시간 연속 가동이 성립하지 않는다.

-- 경과 시간을 직접 보려면 etime 을 쓴다.
[root@rac1 ~]# ps -eo etime,cmd | grep crsd.bin | grep -v grep
      23:49 /u01/app/19.3.0/grid/bin/crsd.bin reboot

--             cdata 아래의 localhost 와 rac1 은 빈 디렉터리다.
-- 조치     : 문서를 믿는 대신 백업을 한 번 만들어 출력이 알려 주는 경로를
--             읽는다. 실습 03 에서 수행한다.
-- 재확인   : rac2 에서도 같은지 확인한다.

[root@rac2 ~]# ls -la /u01/app/19.3.0/grid/cdata/rac-cluster/

--------------------------------------------------------------------------------
 [4] OLR 은 이미 백업되어 있다
--------------------------------------------------------------------------------

[root@rac1 ~]# ocrconfig -local -showbackup

rac1  2026/08/31 19:27:29  /u01/app/grid/crsdata/rac1/olr/autobackup_20260831_192729.olr  724960844

rac1  2026/08/31 19:14:14  /u01/app/grid/crsdata/rac1/olr/backup_20260831_191414.olr      724960844

-- OCR 은 백업이 없는데 OLR 은 두 벌이나 있다. 왜 다른가.
--
--   19:14:14  backup_      root.sh 가 OLR 을 만든 직후 남긴 것
--   19:27:29  autobackup_  구성이 완료된 뒤 Clusterware 가 스스로 남긴 것
--
-- OLR 의 자동 백업은 주기가 아니라 사건 기반이다. 구성이 바뀌는 시점에 찍는다.
-- OCR 은 리소스 상태가 계속 변하므로 주기적으로 떠야 하고, OLR 은 구성이
-- 바뀔 때만 갱신되므로 사건 기반으로 충분하다.
--
-- 저장 위치도 cdata 가 아니라 olr 디렉터리다.
[root@rac1 ~]# ls -la /u01/app/grid/crsdata/rac1/olr/
total 1476
-rw-------. 1 root oinstall 503484 Aug 31 19:27 autobackup_20260831_192729.olr
-rw-------. 1 root oinstall 503484 Aug 31 19:14 backup_20260831_191414.olr
-rw-------. 1 root oinstall 503484 Sep  1 15:53 rac1_19.olr

-- 맨 끝의 724960844 는 패치 레벨이다. ocrdump 의
-- SYSTEM.version.activeversion.patchlevel 과 같은 값이며, 패치 레벨이 다른
-- 백업으로는 복원하면 안 되기 때문에 목록에 함께 표시된다.

--------------------------------------------------------------------------------
 [5] OLR 백업은 노드 로컬이다
--------------------------------------------------------------------------------

[root@rac2 ~]# ocrconfig -local -showbackup

rac2  2026/08/31 19:30:21  /u01/app/grid/crsdata/rac2/olr/autobackup_20260831_193021.olr  724960844

rac2  2026/08/31 19:16:09  /u01/app/grid/crsdata/rac2/olr/backup_20260831_191609.olr      724960844

-- rac2 에서는 rac2 의 백업만 보인다. rac1 의 것은 보이지 않는다.
-- OCR 백업 목록은 어느 노드에서 조회해도 같지만, OLR 백업 목록은 노드마다
-- 다르다.
--
-- 실무적 의미가 크다. rac1 이 통째로 사라지면 rac1 의 OLR 백업도 함께
-- 사라진다. 그때는 복구가 아니라 노드 재구축, 즉 rootcrs.sh -deconfig 후
-- root.sh 재실행이 정답이다.

--------------------------------------------------------------------------------
 [6] 백업 위치 설정은 어디에 있는가
--------------------------------------------------------------------------------

-- OCR 백업과 관련한 crsd 의 내부 동작은 추적 파일에 남는다.

[root@rac1 ~]# ls -l /u01/app/grid/diag/crs/rac1/crs/trace/crsd.trc
-rw-rw----. 1 root oinstall 10485760 Sep  1 16:17 /u01/app/grid/diag/crs/rac1/crs/trace/crsd.trc

[root@rac1 ~]# grep -i 'OCR.BACKUP.LOC' /u01/app/grid/diag/crs/rac1/crs/trace/crsd.trc | tail -3
procr_get_value_ext:[SYSTEM.OCR.BACKUP.LOC] insize [4097]
procr_get_value_ext:[SYSTEM.OCR.BACKUP.LOC] retval [0] type [3] outsize [5]
procr_get_value_ext:[SYSTEM.OCR.BACKUP.LOC] value [+CRS]

-- 백업 위치가 OCR 안의 SYSTEM.OCR.BACKUP.LOC 키에 저장되어 있고 값이 +CRS 다.
-- 백업 위치 설정 자체가 OCR 안에 들어 있다. 그래서 어느 노드에서 조회해도
-- 같은 값이 나오고, 한 노드에서 바꾸면 전 노드에 즉시 반영된다.
--
-- 실습 03 에서 이 값을 바꿔 보면 왜 아무 디렉터리나 지정할 수 없는지 알게 된다.

--------------------------------------------------------------------------------
 [7] 진단 결론 정리
--------------------------------------------------------------------------------

-- 확인한 사실을 표로 정리한다.
--
--   항목            OCR                          OLR
--   ----            ---                          ---
--   현재 백업       없음 (PROT-24/25)            두 벌 (설치 시점)
--   자동 백업 방식  4시간 주기                   구성 변경 사건
--   백업 위치       +CRS (SYSTEM.OCR.BACKUP.LOC) 노드 로컬 olr 디렉터리
--   목록 범위       모든 노드에서 동일           노드마다 다름
--   손실 시 대응    백업에서 복원                노드 재구축
--
-- 자동 백업이 없는 원인은 확정되었다. crsd 연속 가동 시간이 24분으로
-- 4시간에 미치지 못했다. 스토리지 문제도, 권한 문제도, 설정 문제도 아니다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) PROT-24 는 자동 백업, PROT-25 는 수동 백업이 없다는 상태 보고
--   2) 자동 백업 주기는 4시간이고 crsd 재시작마다 타이머가 초기화된다
--   3) ps -eo pid,lstart,cmd 로 crsd 기동 시각을 확인해 원인을 확정한다
--   4) cdata 아래에 클러스터명 디렉터리가 없다. 12c 이후 기본 위치는 ASM
--   5) OLR 백업은 설치 시점에 이미 두 벌 있고 사건 기반이다
--   6) OLR 백업 목록은 노드마다 다르다. 노드 소실 시 복구 불가
--   7) 백업 위치 설정은 OCR 의 SYSTEM.OCR.BACKUP.LOC 키에 있다
--
-- 실무 지침
--   자동 백업에만 의존하지 않는다. 정지 직전에 -manualbackup 을 배치에
--   추가하고, 가능하면 정지 시각을 조정해 연속 가동 4시간을 확보한다.
--   PROT-24 가 계속 나온다면 스토리지나 권한이 아니라 crsd 기동 시각부터
--   확인한다.
--
-- 다음 실습에서 이 상태를 해소한다. 수동 백업을 만들면 PROT-25 가 사라지고
-- 백업이 실제로 어디에 놓이는지 확인할 수 있다.
