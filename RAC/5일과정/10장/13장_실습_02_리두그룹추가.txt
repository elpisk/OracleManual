================================================================================
 제13장 실습 02 — 리두 그룹 추가와 양 노드 확인
 대상   : rac1, rac2
 목표   : 스레드를 지정해 리두 그룹을 추가하고, 그것이 다른 노드에서 즉시
          보이는 것을 확인한다. 사용 중인 그룹을 지울 때의 오류를 재현한다
 소요   : 약 25분
 선행   : 실습 01 완료, racdb 양 노드 OPEN
 계정   : oracle, grid
================================================================================

--------------------------------------------------------------------------------
 [1] 스레드 1 에 그룹 추가
--------------------------------------------------------------------------------

[rac1] SQL> set timing on
[rac1] SQL> alter database add logfile thread 1 group 5 ('+DATA','+FRA') size 50M;

Database altered.

Elapsed: 00:00:03.20

-- 3.2 초다. ASM 이 두 디스크그룹에 50MB 파일을 하나씩 만들고
-- 컨트롤파일을 갱신하는 시간이다.
--
-- 명령의 각 부분.
--   thread 1        → RAC 전용. 어느 스레드에 붙일지 지정한다.
--   group 5         → 그룹 번호. 기존과 겹치면 안 된다.
--   ('+DATA','+FRA')→ 멤버 둘. 디스크그룹만 적으면 ASM 이 이름을 짓는다.
--   size 50M        → 실습용 크기다. 운영에서는 200MB 이상을 쓴다.
--
-- thread 절을 빠뜨리면 오류가 나지 않고 명령을 실행한 인스턴스의
-- 스레드에 붙는다. 오류가 없으므로 더 위험하다.
-- rac1 에서 실행하면서 스레드 2 에 추가하려 했다면 조용히 어긋난다.

--------------------------------------------------------------------------------
 [2] 만들어진 것 확인
--------------------------------------------------------------------------------

[rac1] SQL> select group#, thread#, bytes/1024/1024 mb, members, status
  2    from v$log order by group#;

    GROUP#    THREAD#         MB    MEMBERS STATUS
---------- ---------- ---------- ---------- ----------------
         1          1        200          2 INACTIVE
         2          1        200          2 CURRENT
         3          2        200          2 CURRENT
         4          2        200          2 INACTIVE
         5          1         50          2 UNUSED

5 rows selected.

-- STATUS 가 UNUSED 다. 만들어졌지만 로그 스위치가 아직 그 그룹 차례까지
-- 오지 않았다는 뜻이다. 한 번이라도 쓰이면 이 값은 다시 나오지 않는다.
--
-- THREAD# 가 1 이다. thread 절이 제대로 먹었다.

[rac1] SQL> select group#, member from v$logfile where group#=5 order by member;

    GROUP# MEMBER
---------- ------------------------------------------------------
         5 +DATA/RACDB/ONLINELOG/group_5.279.1243078375
         5 +FRA/RACDB/ONLINELOG/group_5.261.1243078377

2 rows selected.

-- ASM 이 OMF 규칙으로 이름을 지었다. group_5.<파일번호>.<타임스탬프> 형식이다.
-- 9장에서 본 ASM 파일 이름 규칙 그대로다.

--------------------------------------------------------------------------------
 [3] 다른 노드에서 즉시 보이는가
--------------------------------------------------------------------------------

[rac2] SQL> select group#, thread#, bytes/1024/1024 mb, status from v$log order by group#;

    GROUP#    THREAD#         MB STATUS
---------- ---------- ---------- ----------------
         1          1        200 INACTIVE
         2          1        200 CURRENT
         3          2        200 CURRENT
         4          2        200 INACTIVE
         5          1         50 UNUSED

5 rows selected.

-- rac2 에서 아무것도 하지 않았는데 그룹 5 가 보인다.
--
-- 이유는 리두 구성이 컨트롤파일에 기록되고 컨트롤파일은 공유 스토리지에
-- 있기 때문이다. 별도의 동기화 절차가 없다.
--
-- 다만 "보인다" 와 "쓸 수 있다" 는 다르다. 그룹 5 는 스레드 1 의 것이므로
-- rac2 의 racdb2 는 이것을 쓰지 못한다. 목록에는 보이지만 쓰지는 않는다.
-- 이 구분이 이 장 전체를 관통한다.

--------------------------------------------------------------------------------
 [4] 오류 재현 — 사용 중인 그룹을 지우면
--------------------------------------------------------------------------------

[rac1] SQL> alter database drop logfile group 2;
alter database drop logfile group 2
*
ERROR at line 1:
ORA-01623: log 2 is current log for instance racdb1 (thread 1) - cannot drop
ORA-00312: online log 2 thread 1: '+DATA/RACDB/ONLINELOG/group_2.263.1242761749'
ORA-00312: online log 2 thread 1: '+FRA/RACDB/ONLINELOG/group_2.257.1242761759'

-- 원인 파악 : 그룹 2 가 지금 CURRENT 다. 지금 쓰고 있는 리두는 지울 수 없다.
--             메시지에 "instance racdb1 (thread 1)" 이 들어 있다.
--             이것이 RAC 다운 점이다. 단일 인스턴스라면 그냥
--             current log 라고만 하고 끝난다.
--             함께 나온 ORA-00312 두 줄은 그 그룹의 멤버 파일 경로다.
--             멤버가 둘이므로 두 줄이다. 오류 하나에서 그룹 구성까지 읽힌다.
-- 조치     : 메시지가 racdb1 이라고 했으므로 rac1 에서 로그 스위치를 한다.
--             racdb2 에서 아무리 스위치해도 스레드 1 의 CURRENT 는 안 바뀐다.
--             스위치 후 STATUS 가 ACTIVE 라면 체크포인트까지 해서
--             INACTIVE 로 만든 뒤에 지운다.
-- 재확인   : v$log 를 다시 조회해 STATUS 가 INACTIVE 인지 보고 지운다.
--             지운 뒤에는 스레드마다 그룹이 여전히 둘 이상인지 확인한다.

-- 참고로 이 실습에서는 그룹 2 를 실제로 지우지 않는다.
-- 스레드 1 에는 그룹 1·2 밖에 없으므로 하나를 지우면 최소 두 그룹 조건에
-- 걸린다. 크기를 바꾸는 실제 절차는 아래 [5] 를 참고한다.

--------------------------------------------------------------------------------
 [5] 참고 — 리두 크기를 바꾸는 절차 (여기서는 실행하지 않는다)
--------------------------------------------------------------------------------

-- 지우고 다시 만드는 것이 아니라 새로 만들고 옛것을 빼는 순서다.
--
--   1. 새 크기의 그룹을 스레드마다 필요한 만큼 먼저 추가한다.
--      alter database add logfile thread 1 group 11 ('+DATA','+FRA') size 500M;
--      alter database add logfile thread 1 group 12 ('+DATA','+FRA') size 500M;
--      alter database add logfile thread 2 group 13 ('+DATA','+FRA') size 500M;
--      alter database add logfile thread 2 group 14 ('+DATA','+FRA') size 500M;
--
--   2. 지우려는 그룹이 CURRENT 에서 벗어나게 한다.
--      (해당 스레드의 인스턴스에서)
--      alter system switch logfile;
--      alter system checkpoint;
--
--   3. INACTIVE 를 확인하고 지운다.
--      select group#, thread#, status from v$log order by group#;
--      alter database drop logfile group 1;
--
-- 1 번을 먼저 하는 이유가 중요하다. 스레드마다 최소 두 그룹이 있어야 하므로
-- 옛것을 먼저 지우려 하면 그룹이 모자라 거부된다.
-- 2 번을 어느 노드에서 하느냐가 RAC 의 차이점이다.

--------------------------------------------------------------------------------
 [6] 정리 — 그룹 5 삭제
--------------------------------------------------------------------------------

[rac1] SQL> alter database drop logfile group 5;

Database altered.

[rac1] SQL> select group#, thread#, bytes/1024/1024 mb, status from v$log order by group#;

    GROUP#    THREAD#         MB STATUS
---------- ---------- ---------- ----------------
         1          1        200 INACTIVE
         2          1        200 CURRENT
         3          2        200 CURRENT
         4          2        200 INACTIVE

4 rows selected.

-- 그룹 5 는 UNUSED 였으므로 바로 지워졌다.
-- 한 번도 쓰이지 않은 그룹은 CURRENT 나 ACTIVE 가 될 일이 없기 때문이다.

[grid@rac1 ~]$ asmcmd find +DATA 'group_5*'
   (출력 없음)

[grid@rac1 ~]$ asmcmd find +FRA 'group_5*'
   (출력 없음)

-- 기준선인 4 그룹으로 복귀했다.
