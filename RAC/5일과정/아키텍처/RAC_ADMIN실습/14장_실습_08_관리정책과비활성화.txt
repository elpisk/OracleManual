================================================================================
 제14장 실습 08 — 관리 정책과 enable · disable, srvctl 설정이 자원 속성이 되는 곳
 대상   : rac1 (racdb2 를 한 번 내렸다 올린다)
 목표   : srvctl modify database -policy 가 자원 속성 MANAGEMENT_POLICY 와
          AUTO_START 를 어떻게 바꾸는지 보고, disable 이 정지와 어떻게 다른지
          실제로 기동이 막히는 오류로 확인한다
 소요   : 약 20분
 선행   : 실습 05 완료, racdb 양 노드 OPEN
 계정   : oracle, grid
 주의   : 끝에서 정책을 AUTOMATIC 으로, racdb2 를 enable 로 되돌린다.
          disable 상태로 두면 노드 재부팅 뒤 racdb2 가 올라오지 않는다
================================================================================

--------------------------------------------------------------------------------
 [1] 출발점
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl config database -db racdb | grep -iE 'policy|start options|stop options'
Start options: open
Stop options: immediate
Management policy: AUTOMATIC

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr MANAGEMENT_POLICY,AUTO_START,ENABLED
NAME=ora.racdb.db
MANAGEMENT_POLICY=AUTOMATIC
AUTO_START=restore
ENABLED=1

-- srvctl 이 보여 주는 "Management policy" 가 자원 속성에서는 두 줄이다.
--   MANAGEMENT_POLICY  정책 이름 그대로
--   AUTO_START         Clusterware 가 스택 기동 때 이 자원을 어떻게 할지
-- AUTOMATIC 의 AUTO_START 는 restore 다. 스택이 내려가기 전 상태로 되돌린다.
-- 그래서 srvctl 로 먼저 내려 둔 DB 는 스택을 다시 올려도 내려간 채 남는다.
-- "AUTOMATIC 인데 왜 안 올라오나" 의 답이 이 값이다.

--------------------------------------------------------------------------------
 [2] MANUAL 과 NORESTART
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl modify database -db racdb -policy MANUAL
[oracle@rac1 ~]$ srvctl config database -db racdb | grep -i policy
Management policy: MANUAL

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr MANAGEMENT_POLICY,AUTO_START,ENABLED
NAME=ora.racdb.db
MANAGEMENT_POLICY=MANUAL
AUTO_START=never
ENABLED=1

[oracle@rac1 ~]$ srvctl modify database -db racdb -policy NORESTART
[oracle@rac1 ~]$ srvctl config database -db racdb | grep -i policy
Management policy: NORESTART

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr MANAGEMENT_POLICY,AUTO_START,ENABLED
NAME=ora.racdb.db
MANAGEMENT_POLICY=NORESTART
AUTO_START=never
ENABLED=1

-- 두 정책 모두 AUTO_START 가 never 다. 스택이 올라와도 DB 를 올리지 않는다.
-- 그런데 정책 이름은 다르게 남는다. AUTO_START 만으로는 둘이 구분되지 않는다.
--
-- 문서가 적는 차이는 장애 뒤의 동작이다.
--   MANUAL     스택 기동 때 자동으로 올리지 않는다. 사람이 srvctl 로 올리면
--              그 뒤의 장애에는 Clusterware 가 재기동을 시도한다.
--   NORESTART  자동 기동도 하지 않고, 장애가 나도 다시 올리지 않는다.
-- 장애 뒤 동작은 이 실습에서 재현하지 않았다. 확인할 때는 MANAGEMENT_POLICY 를 본다.
--
-- 두 명령 모두 DB 가 OPEN 인 채로 바로 끝났다. 정책 변경은 자원 정의만 바꾼다.

--------------------------------------------------------------------------------
 [3] 흔한 오류 — 정책 이름을 잘못 쓰면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl modify database -db racdb -policy RANDOM
PRKO-2003 : Invalid command line option value: RANDOM

-- 원인 파악 : PRKO 는 명령행 해석 단계의 오류다(실습 02 [6]).
--             2002 는 옵션 이름이, 2003 은 옵션 값이 틀렸을 때 나온다.
--             자원에는 손대지 않았다.
-- 조치     : srvctl modify database -help 로 받을 수 있는 값
--             (AUTOMATIC · MANUAL · NORESTART)을 확인한다.
-- 재확인   : crsctl stat res -p -attr MANAGEMENT_POLICY 가 그대로인지 본다.

[oracle@rac1 ~]$ srvctl modify database -db racdb -policy AUTOMATIC
[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr MANAGEMENT_POLICY,AUTO_START,ENABLED
NAME=ora.racdb.db
MANAGEMENT_POLICY=AUTOMATIC
AUTO_START=restore
ENABLED=1

--------------------------------------------------------------------------------
 [4] disable 은 정지가 아니다
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl disable instance -db racdb -instance racdb2
[oracle@rac1 ~]$ srvctl status database -db racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

-- 명령은 조용히 끝났고 racdb2 는 계속 OPEN 이다.
-- disable 은 "앞으로 Clusterware 가 이 인스턴스를 관리하지 않는다" 는 표시다.
-- 떠 있는 인스턴스를 내리지는 않는다.

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -v -attr ENABLED,STATE,TARGET
NAME=ora.racdb.db 1 1
ENABLED=1
STATE=ONLINE
TARGET=ONLINE

ENABLED=0
STATE=ONLINE
TARGET=ONLINE

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr 'ENABLED,ENABLED@SERVERNAME(rac2)'
NAME=ora.racdb.db
ENABLED=1
ENABLED@SERVERNAME(rac2)=0

-- 자원 하나(ora.racdb.db)에 인스턴스가 둘이다. disable 은 자원 전체가 아니라
-- rac2 에 대한 값만 바꿨다. 정적 속성에는 ENABLED@SERVERNAME(rac2)=0 으로,
-- 실행 상태(-v)에는 두 번째 인스턴스의 ENABLED=0 으로 나온다.
-- srvctl config database 출력에는 이 표시가 없었다. 확인은 crsctl 로 한다.

--------------------------------------------------------------------------------
 [5] 흔한 오류 — disable 된 인스턴스를 올리려 하면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl stop instance -db racdb -instance racdb2
>>> 42.5초

-- 정지는 된다. disable 은 기동만 막는다.

[oracle@rac1 ~]$ srvctl start instance -db racdb -instance racdb2
PRCR-1013 : Failed to start resource ora.racdb.db
PRCR-1064 : Failed to start resource ora.racdb.db on node rac2
CRS-2662: Resource 'ora.racdb.db' is disabled on server 'rac2'

[oracle@rac1 ~]$ srvctl start database -db racdb
PRCR-1079 : Failed to start resource ora.racdb.db
CRS-2665: Resource 'ora.racdb.db' is disabled on 'rac2'

-- 원인 파악 : 맨 아래 CRS 줄이 원인이다. 위의 PRCR 은 "자원 계층에서 실패" 라는
--             요약이다(실습 07 의 겹쳐 읽는 규칙).
--             인스턴스를 지정하면 CRS-2662, 데이터베이스 전체를 올리면 CRS-2665 다.
--             두 번 모두 Clusterware 가 rac2 에서 자원을 올리기를 거부했다.
-- 조치     : srvctl enable instance -db racdb -instance racdb2 로 표시를 지운다.
--             sqlplus 로 startup 하면 올라가기는 하지만 Clusterware 의 관리
--             밖에 놓인다. 장애가 나도 다시 올려 주지 않는다.
-- 재확인   : ENABLED@SERVERNAME(rac2)=1 을 확인하고 srvctl 로 기동한다.

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -t
--------------------------------------------------------------------------------
Name           Target  State        Server                   State details
--------------------------------------------------------------------------------
Cluster Resources
--------------------------------------------------------------------------------
ora.racdb.db
      1        ONLINE  ONLINE       rac1                     Open,HOME=/u01/app/o
                                                             racle/product/19.3.0
                                                             /dbhome_rac,STABLE
      2        OFFLINE OFFLINE                               Instance Shutdown,ST
                                                             ABLE
--------------------------------------------------------------------------------

-- 실습 03 의 판단 기준대로 읽으면 TARGET 이 OFFLINE 이므로 장애가 아니다.
-- 그런데 원인이 disable 인지 단순 정지인지는 이 표에 나오지 않는다.
-- OFFLINE 인스턴스를 볼 때 ENABLED 값을 함께 보는 습관이 필요하다.

--------------------------------------------------------------------------------
 [6] 되돌리기
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl enable instance -db racdb -instance racdb2
[oracle@rac1 ~]$ srvctl start instance -db racdb -instance racdb2
>>> 32.6초
[oracle@rac1 ~]$ srvctl status database -db racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p -attr 'ENABLED,ENABLED@SERVERNAME(rac2),AUTO_START'
NAME=ora.racdb.db
ENABLED=1
ENABLED@SERVERNAME(rac2)=1
AUTO_START=restore

-- enable 만으로는 올라오지 않는다. 표시를 지운 뒤 start 를 따로 한다.
-- 정책 AUTOMATIC, racdb2 enable, 두 인스턴스 OPEN 으로 처음과 같다.
