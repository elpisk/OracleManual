 제16장 실습 10 — TAF 가 살리지 못하는 것: 첫 호출, 트랜잭션, SESSION 유형
 대상   : rac1 (세션), rac2 (세션을 끊는 DBA)
 목표   : 인스턴스를 죽이지 않고 세션 하나만 끊어 TAF 반응을 본다.
          kill session 과 disconnect session 을 비교하고, 열린 트랜잭션이
          어떻게 되는지, -failovertype SESSION 이면 조회가 어떻게 되는지 잰다
 소요   : 약 25분
 선행   : 실습 09 완료 (ch16_taf · ch16_fan 이 racdb2 에서 실행)
 계정   : oracle
================================================================================

--------------------------------------------------------------------------------
 [1] 준비와 기준 시간
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status service -db racdb
Service ch16_fan is running on instance(s) racdb2
Service ch16_taf is running on instance(s) racdb2
[oracle@rac1 ~]$ srvctl status database -db racdb
Instance racdb1 is not running on node rac1
Instance racdb2 is running on node rac2

-- 실습 09 [3] 에서 죽인 racdb1 이 아직 올라오는 중이다. 이 실습은 세션 단위로만
-- 끊으므로 racdb2 하나로 충분하다. 끊긴 세션은 같은 racdb2 로 다시 붙는다.

[rac1] SQL> create table system.ch16_t (n number, inst varchar2(10));
Table created.

[oracle@rac1 ~]$ /tmp/taf_q2.sh ch16_taf /tmp/taf_base.out; grep -E 'Elapsed|rows selected|racdb' /tmp/taf_base.out

30 rows selected.
Elapsed: 00:00:15.13

-- 실습 09 [3] 의 조회를 끊김 없이 돌린 시간이다. 30 행 × 0.5 초.

--------------------------------------------------------------------------------
 [2] 쉬고 있는 세션 — kill session 과 disconnect session
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ cat /tmp/taf_idle2.sh        (요지)
( echo "select 'BEFORE' tag, <인스턴스>, sid, serial#, failed_over from v\$session where ...;"
  sleep 15
  echo "select 'AFTER1' tag, ... ;"
  echo "select 'AFTER2' tag, ... ;"
) | sqlplus -s system/<비밀번호>@rac-scan:1521/$1

-- 접속해 한 번 묻고 15 초 쉰 뒤 두 번 더 묻는다. 쉬는 4 초째에 rac2 에서 세션을 끊는다.

[oracle@rac1 ~]$ nohup /tmp/taf_idle2.sh ch16_taf /tmp/taf_kill2.out &
[rac2] SQL> alter system kill session '142,62181' immediate;          -- 14:41:36.24

[oracle@rac1 ~]$ cat /tmp/taf_kill2.out
TAG    INST            SID    SERIAL# FAI
------ -------- ---------- ---------- ---
BEFORE racdb2          142      62181 NO
select 'AFTER1' tag, ...
*
ERROR at line 1:
ORA-03113: end-of-file on communication channel
Process ID: 10952
Session ID: 142 Serial number: 56603

TAG    INST            SID    SERIAL# FAI
------ -------- ---------- ---------- ---
AFTER2 racdb2          142      56603 YES

[oracle@rac1 ~]$ nohup /tmp/taf_idle2.sh ch16_taf /tmp/taf_disc2.out &
[rac2] SQL> alter system disconnect session '142,63612' immediate;    -- 14:41:57.49

[oracle@rac1 ~]$ cat /tmp/taf_disc2.out
BEFORE racdb2          142      63612 NO
ERROR at line 1:
ORA-03113: end-of-file on communication channel
Process ID: 11214
Session ID: 30 Serial number: 48926
AFTER2 racdb2           30      48926 YES

-- 비교용 — TAF 가 없는 ch16_fan
[oracle@rac1 ~]$ nohup /tmp/taf_idle2.sh ch16_fan /tmp/notaf_kill2.out &
[rac2] SQL> alter system kill session '30,33646' immediate;           -- 14:42:18.71

[oracle@rac1 ~]$ cat /tmp/notaf_kill2.out
BEFORE racdb2           30      33646 NO
ERROR at line 1:
ORA-03113: end-of-file on communication channel
Process ID: 11223
Session ID: 30 Serial number: 33646
ERROR:
ORA-03114: not connected to ORACLE

-- TAF 서비스에서는 kill 이든 disconnect 든 결과가 같았다.
--   AFTER1 : ORA-03113. 끊긴 것을 처음 알아챈 호출은 오류를 그대로 받는다.
--   AFTER2 : 새 세션(SERIAL# 이 바뀜)에서 정상. FAILED_OVER=YES.
-- AFTER1 오류 메시지의 Serial number 가 이미 새 세션의 번호(56603, 48926)다.
-- AFTER2 의 SERIAL# 과 같다. 오류를 돌려줄 때 이미 TAF 가 재접속을 끝낸 것으로 보인다.
-- TAF 가 없는 서비스는 AFTER1 의 ORA-03113 다음에 ORA-03114 로 연결이 없다.
--
-- 흔한 오해 — "TAF 를 켜면 애플리케이션은 오류를 보지 않는다"
--   쉬던 세션의 다음 호출은 오류를 받았다. 이어진 것은 그 다음 호출부터다.
--   애플리케이션은 ORA-03113 을 받으면 같은 호출을 한 번 다시 내야 한다.
--   실습 09 [3] 처럼 fetch 도중이던 조회만 오류 없이 이어졌다.

--------------------------------------------------------------------------------
 [3] 열린 트랜잭션이 있을 때
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ cat /tmp/taf_tx2.sh          (요지)
insert into system.ch16_t values (3, <인스턴스>);     -- 이 뒤 15 초 쉰다
select count(*) from system.ch16_t;
insert into system.ch16_t values (4, <인스턴스>);
commit;
rollback;
insert into system.ch16_t values (5, <인스턴스>);
commit;
select * from system.ch16_t order by 1;

-- 같은 흐름을 ROLLBACK 을 넣은 판(행 1 · 2)으로 먼저 한 번 했다. 그 결과 행 2 만 남아 있다.

[oracle@rac1 ~]$ nohup /tmp/taf_tx2.sh ch16_taf /tmp/taf_tx2.out &
[rac2] SQL> alter system disconnect session '142,61702' immediate;    -- 14:43:00.27

[oracle@rac1 ~]$ cat /tmp/taf_tx2.out
1 row created.
select count(*) from system.ch16_t
                   *
ERROR at line 1:
ORA-03113: end-of-file on communication channel
Process ID: 12315
Session ID: 159 Serial number: 40917

1 row created.
Commit complete.
Rollback complete.
1 row created.
Commit complete.

         N INST
---------- --------
         2 racdb2
         4 racdb2
         5 racdb2

-- 행 3 이 없다. 끊기기 전에 넣고 커밋하지 않은 행은 롤백됐다.
-- 문서는 이때 ORA-25402(transaction must roll back)를 받는다고 적는다. 이 실습의
-- SQL*Plus 19c 에서는 [2] 와 같은 ORA-03113 이 났고 ORA-25402 는 보지 못했다.
-- 그 다음 insert(행 4)는 ROLLBACK 없이 바로 성공했다. 새 세션에서 새 트랜잭션이 된 것이다.
--
-- 진단 — 이 출력에서 위험한 지점
--   오류 한 줄 뒤로 "1 row created", "Commit complete" 가 이어진다. 로그만 훑으면 모두
--   커밋된 것처럼 보인다. 행 3 은 조용히 사라졌다.
--   트랜잭션 도중 ORA-03113 을 받으면 그 트랜잭션을 처음부터 다시 낸다. TAF 는 진행 중인
--   트랜잭션을 살리지 않는다. 살리는 것은 Application Continuity 의 일이다(실습 11).

--------------------------------------------------------------------------------
 [4] -failovertype SESSION 이면 조회는
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl modify service -db racdb -service ch16_taf -failovertype SESSION
[oracle@rac1 ~]$ srvctl config service -db racdb -service ch16_taf | egrep 'Failover (type|method)'
Failover type: SESSION
Failover method: BASIC

[rac1] SQL> alter session set container=racpdb1;
[rac1] SQL> select name, failover_type, failover_method from dba_services where name like 'ch16%';
NAME        FAILOVER_TYPE  FAILOVER_METHOD
----------  -------------  ---------------
ch16_fan
ch16_taf    SESSION        BASIC

-- 서비스를 멈추지 않고 바꿨는데 데이터베이스의 정의에도 바로 들어갔다.

[oracle@rac1 ~]$ nohup /tmp/taf_q2.sh ch16_taf /tmp/taf_sess.out &
-- 7 초 뒤
[rac2] SQL> alter system disconnect session '148,27540' immediate;    -- 14:43:32.19
ERROR at line 1:
ORA-00031: session marked for kill

[oracle@rac1 ~]$ cat /tmp/taf_sess.out
INST     FAI
-------- ---
racdb2   NO

         N
----------
         1
  ...
        13
ERROR:
ORA-25401: can not continue fetches

13 rows selected.

Elapsed: 00:00:07.36

INST     FAI
-------- ---
racdb2   YES

-- 세션은 새로 만들어졌지만 조회는 13 행에서 끊겼다. SESSION 유형은 세션만 살리고 열린
-- 커서는 살리지 않는다. 실습 09 [3] 의 같은 조회가 SELECT 유형에서는 끝까지 이어졌다.
-- DBA 쪽에는 ORA-00031 이 나왔다. 세션이 PL/SQL 함수 안에서 자고 있어 바로 정리되지
-- 못하고 "끊을 대상으로 표시" 된 것이다. 클라이언트 쪽은 7.36 초째에 끊김을 받았다.

--------------------------------------------------------------------------------
 [5] 정리
--------------------------------------------------------------------------------

  끊길 때 상태            TAF SELECT                    TAF SESSION         TAF 없음
  ----------------------  ----------------------------  ------------------  -----------------
  쉬는 중                 다음 호출 ORA-03113, 그 뒤 정상   재지 않음          ORA-03113 → 03114
  fetch 도중 (같은 결과)  끝까지 이어 받음               ORA-25401           ORA-03113
  커밋 안 한 트랜잭션     ORA-03113, 트랜잭션 사라짐      재지 않음          재지 않음

-- kill session 과 disconnect session 은 TAF 반응에서 차이가 없었다.
