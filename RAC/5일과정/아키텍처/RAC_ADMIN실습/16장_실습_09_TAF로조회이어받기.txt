================================================================================
 제16장 실습 09 — TAF SELECT, 인스턴스가 죽어도 조회가 이어지는가
 대상   : rac1 (세션은 racdb1 에 붙는다)
 목표   : 서버 쪽 TAF(-failovertype SELECT)를 준 서비스와 주지 않은 서비스로
          같은 조회를 돌리다 인스턴스를 죽인다. 조회가 이어지는 조건과
          ORA-25401 이 나는 조건을 가른다. 이어 받는 데 걸린 시간을 잰다
 소요   : 약 30분 (인스턴스 재기동 대기 포함)
 선행   : 실습 08 완료
 계정   : root, oracle
 주의   : racdb1 을 두 번 강제로 죽인다
================================================================================

--------------------------------------------------------------------------------
 [1] TAF 서비스와 느린 조회 준비
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl relocate service -db racdb -service ch16_fan -oldinst racdb2 -newinst racdb1
[oracle@rac1 ~]$ srvctl add service -db racdb -service ch16_taf -pdb racpdb1 \
                   -preferred racdb1 -available racdb2 \
                   -failovertype SELECT -failovermethod BASIC -failoverretry 30 -failoverdelay 5
[oracle@rac1 ~]$ srvctl start service -db racdb -service ch16_taf
[oracle@rac1 ~]$ srvctl status service -db racdb
Service ch16_fan is running on instance(s) racdb1
Service ch16_taf is running on instance(s) racdb1
[oracle@rac1 ~]$ srvctl config service -db racdb -service ch16_taf | egrep -i 'failover|TAF'
Failover type: SELECT
Failover method: BASIC
Failover retries: 30
Failover delay: 5
Failover restore: NONE
TAF policy specification: NONE

-- ch16_fan 은 TAF 가 없는 비교 대상이다. 둘 다 지금 racdb1 에 있다.

[rac1] SQL> create or replace function system.ch16_slow(n number) return number is
            begin dbms_session.sleep(0.5); return n; end;
            /
Function created.

-- 한 행에 0.5 초씩 걸리게 하는 함수다. 30 행이면 15 초 동안 fetch 가 이어진다.
-- 그 사이에 인스턴스를 죽인다.

[oracle@rac1 ~]$ cat /tmp/taf_q.sh            (요지)
sqlplus -s system/<비밀번호>@rac-scan:1521/$1 <<'Y'
set arraysize 1
-- ① 붙은 인스턴스와 협상된 TAF 유형
select sys_context('userenv','instance_name') inst, failover_type, failover_method, failed_over
  from v$session where sid = sys_context('userenv','sid');
-- ② 느린 조회. 시각과 인스턴스 이름을 같이 찍는다
select n, to_char(systimestamp,'HH24:MI:SS.FF2') t, sys_context('userenv','instance_name') inst
  from (select level n from dual connect by level <= 30) where system.ch16_slow(n) = n;
-- ③ ① 과 같은 조회
Y

-- arraysize 1 로 한 행씩 받아 오게 해서 fetch 도중에 끊기게 한다.

--------------------------------------------------------------------------------
 [2] 첫 시도 — 조회 결과에 인스턴스 이름과 시각이 들어 있을 때
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ nohup /tmp/taf_q.sh ch16_taf /tmp/taf_sel.out &
[oracle@rac1 ~]$ nohup /tmp/taf_q.sh ch16_fan /tmp/notaf.out &
-- 8 초 뒤
[root@rac1 ~]# date '+%T.%3N'; kill -9 $(pgrep -x ora_pmon_racdb1)
14:35:34.268

[oracle@rac1 ~]$ cat /tmp/taf_sel.out
INST     FAILOVER_TYPE FAILOVER_METHOD FAI
-------- ------------- --------------- ---
racdb1   SELECT        BASIC           NO

         N T           INST
---------- ----------- --------
         1 14:35:26.40 racdb1
         2 14:35:26.40 racdb1
  ...
        21 14:35:26.40 racdb1
ERROR:
ORA-25401: can not continue fetches

21 rows selected.

INST     FAILOVER_TYPE FAILOVER_METHOD FAI
-------- ------------- --------------- ---
racdb2   SELECT        BASIC           YES

[oracle@rac1 ~]$ cat /tmp/notaf.out
INST     FAILOVER_TYPE FAILOVER_METHOD FAI
-------- ------------- --------------- ---
racdb1   NONE          NONE            NO
  ... 1~21 행은 위와 같다 ...
ERROR:
ORA-03113: end-of-file on communication channel
Process ID: 11467
Session ID: 156 Serial number: 46217

21 rows selected.

ERROR:
ORA-03114: not connected to ORACLE

-- TAF 를 준 세션은 racdb2 로 다시 붙었다. ③ 에서 FAILED_OVER=YES 다.
-- 그런데 조회 ② 는 21 행에서 ORA-25401 로 끊겼다. 이어 받지 못했다.
-- TAF 가 없는 세션은 ORA-03113 뒤에 연결 자체가 없어졌다(ORA-03114).
--
-- 원인 파악 : TAF SELECT 는 새 인스턴스에서 조회를 처음부터 다시 실행하고, 이미 받은
--             21 행을 건너뛴 뒤 22 행부터 넘겨준다. 다시 실행한 결과가 처음과 같아야
--             이어 붙일 수 있다. 이 조회는 행마다 systimestamp 와 instance_name 을 찍는다.
--             새 인스턴스에서 돌리면 두 값이 달라진다. 앞 21 행을 재현할 수 없으니
--             fetch 를 이어 가지 못한다.
-- 조치     : 결과가 실행할 때마다 같은 조회로 [3] 에서 다시 잰다.
-- 시각 열이 모든 행에서 14:35:26.40 으로 같다. systimestamp 는 문장마다 한 번 정해진다.
-- 조회가 시작된 시각이 14:35:26 이고, 8 초 뒤에 kill 했다는 것도 이 값으로 알 수 있다.

--------------------------------------------------------------------------------
 [3] 다시 — 결과가 늘 같은 조회
--------------------------------------------------------------------------------

-- racdb1 이 자동으로 다시 올라온 뒤 서비스 둘을 racdb1 로 되돌렸다.

[oracle@rac1 ~]$ srvctl relocate service -db racdb -service ch16_taf -oldinst racdb2 -newinst racdb1
[oracle@rac1 ~]$ srvctl relocate service -db racdb -service ch16_fan -oldinst racdb2 -newinst racdb1

[oracle@rac1 ~]$ cat /tmp/taf_q2.sh           (요지)
set arraysize 1 timing on
select sys_context('userenv','instance_name') inst, failed_over from v$session where sid = sys_context('userenv','sid');
select n from (select level n from dual connect by level <= 30) where system.ch16_slow(n) = n;
select sys_context('userenv','instance_name') inst, failed_over from v$session where sid = sys_context('userenv','sid');

[oracle@rac1 ~]$ nohup /tmp/taf_q2.sh ch16_taf /tmp/taf_sel2.out &
-- 8 초 뒤
[root@rac1 ~]# date '+%T.%3N'; kill -9 $(pgrep -x ora_pmon_racdb1)
14:37:16.296

[oracle@rac1 ~]$ cat /tmp/taf_sel2.out
INST     FAI
-------- ---
racdb1   NO

         N
----------
         1
         2
  ...
        29
        30

30 rows selected.

Elapsed: 00:00:35.12

INST     FAI
-------- ---
racdb2   YES

-- 이번에는 30 행이 빠짐없이 나왔다. 오류도 없다. 사용자 눈에는 조회가 잠깐 멈췄다가
-- 끝까지 간 것으로 보인다. 그 사이 세션은 racdb1 에서 racdb2 로 넘어갔다.
-- 같은 조회를 끊김 없이 돌리면 15.13 초다(실습 10 [1]). 20 초가 더 걸렸다.
-- 인스턴스 장애를 알아채는 시간, 재접속, 새 인스턴스에서 앞 행을 다시 만들어 건너뛰는
-- 시간이 모두 이 안에 있다. 앞 행이 많고 비싼 조회일수록 이어 받는 데 오래 걸린다.

--------------------------------------------------------------------------------
 [4] 이 실습에서 본 것
--------------------------------------------------------------------------------

  조회 / 서비스              fetch 도중 인스턴스 장애           다음 문장
  -------------------------  ---------------------------------  -----------------------
  결과 같은 조회 / TAF       이어 받음 (15 초 → 35 초)           racdb2, FAILED_OVER=YES
  결과 달라지는 조회 / TAF   ORA-25401 (21 행에서 멈춤)          racdb2, FAILED_OVER=YES
  같은 조회 / TAF 없음       ORA-03113                           ORA-03114 연결 없음

-- TAF 는 "세션" 과 "열린 조회" 를 따로 살린다. 세션은 두 경우 모두 살아났다.
-- 조회를 이어 주는 것은 결과를 다시 만들 수 있을 때뿐이다.
-- 행마다 시각 · 시퀀스 · 노드 이름 같은 값을 찍는 조회, ORDER BY 없이 순서가 바뀔 수
-- 있는 조회는 TAF SELECT 로 이어지지 않을 수 있다. 애플리케이션은 ORA-25401 을 받으면
-- 조회를 처음부터 다시 낸다.
