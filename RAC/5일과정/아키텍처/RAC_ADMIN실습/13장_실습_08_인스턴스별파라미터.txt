================================================================================
 제13장 실습 08 — 인스턴스마다 같게 · 다르게, SPFILE 의 SID 항목
 대상   : rac1 (rac2 인스턴스를 한 번 재기동)
 목표   : sid='*' 와 sid='racdb2' 항목이 SPFILE 과 메모리에 각각 어떻게 들어가는지
          보고, 둘이 겹칠 때 재기동 후 어느 쪽이 이기는지 확인한다.
          정적 파라미터와 없는 항목 삭제의 오류를 구분한다
 소요   : 약 20분 (racdb2 재기동 약 100초 포함)
 선행   : racdb 양 노드 OPEN
 계정   : oracle
 주의   : racdb2 를 한 번 내렸다 올린다. 그동안 racdb2 의 세션은 끊긴다.
          실습 끝에서 open_cursors 를 원래 값(*=300)으로 되돌린다
================================================================================

--------------------------------------------------------------------------------
 [0] SPFILE 에서 인스턴스별로 갈린 항목
--------------------------------------------------------------------------------

[rac1] SQL> select sid, name, value from v$spparameter
  2   where isspecified='TRUE' and sid<>'*' order by name, sid;

SID      NAME                           VALUE
-------- ------------------------------ ----------------------------------------
racdb1   instance_number                1
racdb2   instance_number                2
racdb1   thread                         1
racdb2   thread                         2
racdb1   undo_tablespace                UNDOTBS1
racdb2   undo_tablespace                UNDOTBS2

6 rows selected.

-- SPFILE 에 값이 지정된 항목은 모두 30 개다. 그중 인스턴스 이름이 붙은 것은
-- 세 파라미터, 여섯 줄뿐이다. 나머지 24 개는 sid='*' 로 두 인스턴스가 함께 쓴다.
--
-- 세 가지 모두 반드시 달라야 하는 것들이다. 같으면 기동이 안 되거나
-- 실습 04 의 ORA-30013 처럼 충돌한다. dbca 가 만들 때 넣어 준다.

--------------------------------------------------------------------------------
 [1] 한 인스턴스만 바꾸기
--------------------------------------------------------------------------------

[rac1] SQL> select inst_id, name, value, ismodified from gv$parameter
  2   where name='open_cursors' order by inst_id;

   INST_ID NAME           VALUE      ISMODIFIED
---------- -------------- ---------- ----------
         1 open_cursors   300        FALSE
         2 open_cursors   300        FALSE

[rac1] SQL> alter system set open_cursors=400 scope=both sid='racdb2';

System altered.

[rac1] SQL> select inst_id, name, value, ismodified from gv$parameter
  2   where name='open_cursors' order by inst_id;

   INST_ID NAME           VALUE      ISMODIFIED
---------- -------------- ---------- ----------
         1 open_cursors   300        FALSE
         2 open_cursors   400        SYSTEM_MOD

[rac1] SQL> select sid, name, value from v$spparameter
  2   where name='open_cursors' and isspecified='TRUE' order by sid;

SID      NAME           VALUE
-------- -------------- ----------
*        open_cursors   300
racdb2   open_cursors   400

-- rac1 에서 실행했는데 racdb2 의 메모리가 바뀌었다. ISMODIFIED 가 SYSTEM_MOD 다.
-- SPFILE 에는 기존 *.open_cursors=300 이 남고 racdb2.open_cursors=400 이 추가됐다.
-- 한 파라미터에 줄이 둘이 된다.

--------------------------------------------------------------------------------
 [2] 겹친 상태에서 sid='*' 로 바꾸면
--------------------------------------------------------------------------------

[rac1] SQL> alter system set open_cursors=350 scope=both sid='*';

System altered.

[rac1] SQL> select inst_id, name, value, ismodified from gv$parameter
  2   where name='open_cursors' order by inst_id;

   INST_ID NAME           VALUE      ISMODIFIED
---------- -------------- ---------- ----------
         1 open_cursors   350        SYSTEM_MOD
         2 open_cursors   350        SYSTEM_MOD

[rac1] SQL> select sid, name, value from v$spparameter
  2   where name='open_cursors' and isspecified='TRUE' order by sid;

SID      NAME           VALUE
-------- -------------- ----------
*        open_cursors   350
racdb2   open_cursors   400

-- 메모리와 SPFILE 이 서로 다른 말을 한다.
--   메모리   두 인스턴스 모두 350. sid='*' 가 지금 떠 있는 모든 인스턴스에 적용됐다.
--   SPFILE   racdb2.open_cursors=400 이 그대로 있다. sid='*' 는 * 줄만 고친다.
-- 지금 조회만 보면 두 노드가 같다. 다음 재기동에서 racdb2 만 400 으로 돌아간다.

--------------------------------------------------------------------------------
 [3] racdb2 재기동 — 어느 쪽이 이기는가
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl stop instance -d racdb -i racdb2
>>> 50.8초
[oracle@rac1 ~]$ srvctl start instance -d racdb -i racdb2
>>> 48.6초
[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[rac1] SQL> select inst_id, name, value, ismodified from gv$parameter
  2   where name='open_cursors' order by inst_id;

   INST_ID NAME           VALUE      ISMODIFIED
---------- -------------- ---------- ----------
         1 open_cursors   350        SYSTEM_MOD
         2 open_cursors   400        FALSE

-- racdb2 가 400 으로 올라왔다. SPFILE 에 * 줄과 racdb2 줄이 함께 있으면
-- 인스턴스 이름이 붙은 줄이 이긴다.
-- ISMODIFIED 가 FALSE 인 것도 본다. 기동 때 SPFILE 에서 읽은 값이므로
-- 실행 중에 바뀐 적이 없다.
--
-- 운영에서 자주 생기는 일이다. 누군가 한 노드만 바꿔 둔 항목이 남아 있으면
-- 나중에 sid='*' 로 고쳐도 그 노드만 재기동 후 옛 값으로 돌아간다.
-- 메모리만 보면 찾을 수 없다. v$spparameter 를 sid 별로 봐야 보인다.

--------------------------------------------------------------------------------
 [4] 인스턴스 항목 지우기와 흔한 오류
--------------------------------------------------------------------------------

[rac1] SQL> alter system reset open_cursors scope=spfile sid='racdb2';

System altered.

[rac1] SQL> select sid, name, value from v$spparameter
  2   where name='open_cursors' and isspecified='TRUE' order by sid;

SID      NAME           VALUE
-------- -------------- ----------
*        open_cursors   350

-- racdb2 줄이 지워졌다. racdb2 의 메모리는 아직 400 이다.
-- scope=spfile 이므로 메모리는 건드리지 않는다.

[rac1] SQL> alter system reset open_cursors scope=spfile sid='racdb2';
alter system reset open_cursors scope=spfile sid='racdb2'
*
ERROR at line 1:
ORA-32010: cannot find entry to delete in SPFILE

-- 원인 파악 : 지울 줄이 없다. 방금 지웠기 때문이다.
--             reset 은 SPFILE 에서 그 sid 의 줄을 찾아 지우는 명령이다.
--             sid='racdb2' 로 지정했으므로 * 줄은 찾지 않는다.
-- 조치     : v$spparameter 에서 지우려는 sid 의 줄이 있는지 먼저 본다.
--             * 줄을 지우려면 sid='*' 로 지정한다.
-- 재확인   : 같은 조회에서 원하는 줄만 남았는지 본다.

--------------------------------------------------------------------------------
 [5] 흔한 오류 — 정적 파라미터를 메모리에서 바꾸려 하면
--------------------------------------------------------------------------------

[rac1] SQL> alter system set processes=400 scope=memory sid='*';
alter system set processes=400 scope=memory sid='*'
                 *
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

[rac1] SQL> alter system set processes=400 scope=memory sid='racdb2';
alter system set processes=400 scope=memory sid='racdb2'
                 *
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

-- 원인 파악 : processes 는 실행 중에 바꿀 수 없는 파라미터다.
--             sid 를 무엇으로 주든 결과가 같다. 막히는 것은 scope=memory 다.
-- 조치     : scope=spfile 로 넣고 인스턴스를 재기동한다.
--             RAC 라면 srvctl stop/start instance 로 한 노드씩 돌려
--             서비스가 끊기지 않게 한다.
-- 재확인   : 재기동 뒤 gv$parameter 로 두 인스턴스 값을 본다.

[rac1] SQL> select name, issys_modifiable, isinstance_modifiable from v$parameter
  2   where name in ('open_cursors','processes','undo_tablespace','cluster_database','db_name');

NAME                 ISSYS_MOD ISINS
-------------------- --------- -----
processes            FALSE     FALSE
cluster_database     FALSE     FALSE
undo_tablespace      IMMEDIATE TRUE
db_name              FALSE     FALSE
open_cursors         IMMEDIATE TRUE

-- 두 열을 함께 읽는다.
--   ISSYS_MODIFIABLE      실행 중 alter system 으로 바꿀 수 있는가
--                         FALSE 면 scope=spfile 과 재기동이 필요하다
--   ISINSTANCE_MODIFIABLE 인스턴스마다 다른 값을 줄 수 있는가
--                         FALSE 면 sid 를 붙여 메모리에서 따로 바꿀 수 없다
-- open_cursors 와 undo_tablespace 는 둘 다 TRUE 쪽이다.
-- processes 는 둘 다 막혀 있지만 SPFILE 에 racdb2.processes 를 넣고
-- 재기동해 인스턴스마다 다르게 둘 수는 있다.

--------------------------------------------------------------------------------
 [6] 정리
--------------------------------------------------------------------------------

[rac1] SQL> alter system set open_cursors=300 scope=both sid='*';

System altered.

[rac1] SQL> select inst_id, name, value, ismodified from gv$parameter
  2   where name='open_cursors' order by inst_id;

   INST_ID NAME           VALUE      ISMODIFIED
---------- -------------- ---------- ----------
         1 open_cursors   300        SYSTEM_MOD
         2 open_cursors   300        SYSTEM_MOD

[rac1] SQL> select sid, name, value from v$spparameter
  2   where name='open_cursors' and isspecified='TRUE' order by sid;

SID      NAME           VALUE
-------- -------------- ----------
*        open_cursors   300

-- SPFILE 은 처음과 같다(*.open_cursors=300 한 줄).
-- 메모리 값도 300 이다. ISMODIFIED 의 SYSTEM_MOD 는 다음 재기동까지 남는다.
