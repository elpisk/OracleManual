================================================================================
 제14장 실습 11 — 의존 관계 트리와 연쇄 정지, VIP 를 내리면 무엇이 따라 내려가나
 대상   : rac1 (rac2 의 VIP 와 노드 리스너를 잠깐 내린다)
 목표   : crsctl stat res -dependency 로 기동 · 정지 · 끌어올림(pullup) 의존을
          트리로 읽는다. rac2 의 VIP 를 강제로 내려 리스너가 함께 내려가고,
          VIP 를 올리면 리스너가 저절로 따라 올라오는 것을 확인한다
 소요   : 약 20분
 선행   : 실습 05 완료, racdb 양 노드 OPEN
 계정   : oracle, grid
 주의   : [4] 에서 몇 초 동안 rac2 의 노드 리스너가 없다. 그동안 rac2 VIP 로
          들어오는 새 접속은 실패한다. 이미 붙어 있는 세션과 SCAN 접속은 영향이 없다
================================================================================

--------------------------------------------------------------------------------
 [1] 데이터베이스 자원의 기동 의존 트리
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -dependency
================================================================================
Resource Start Dependencies
================================================================================
----------------------------------ora.racdb.db----------------------------------
ora.racdb.db(ora.database.type)->
| ora.DATA.dg(ora.diskgroup.type)[hard:global:uniform]
| | ora.asm(ora.asm.type)[hard,pullup:always]
| | | type:ora.asm_listener.type[hard:type,pullup:type]
| | | | ora.asmnet1.asmnetwork(ora.asm_network.type)[hard,pullup]
| | | ora.ASMNET1LSNR_ASM.lsnr(ora.asm_listener.type)[weak]
| | | | ora.asmnet1.asmnetwork(ora.asm_network.type)[hard,pullup]
| ora.FRA.dg(ora.diskgroup.type)[hard:global,pullup:global]
| | ora.asm(ora.asm.type)[hard,pullup]
| | | ...
| type:ora.listener.type[weak:type]
| | type:ora.cluster_vip_net1.type[hard:type,pullup:type]
| | | ora.net1.network(ora.network.type)[hard,pullup]
| | | ora.gns<Resource not found>[weak:global]
| type:ora.scan_listener.type[weak:type:global]
| | ora.scan1.vip(ora.scan_vip.type)[hard,pullup]
| | | ora.net1.network(ora.network.type)[hard,pullup:global:active]
| | | ...
| ora.ons(ora.ons.type)[weak:uniform]
| | ora.net1.network(ora.network.type)[hard,pullup]
| ora.gns<Resource not found>[weak:global]
--------------------------------------------------------------------------------

-- 실습 05 [4] 에서 START_DEPENDENCIES 한 줄로 읽던 것을 트리로 펼친 것이다.
-- 들여쓰기 한 단계가 "이것이 먼저 있어야 한다" 한 단계다.
--
-- 대괄호 안의 낱말.
--   hard     그 자원이 ONLINE 이어야 기동할 수 있다
--   weak     있으면 먼저 올리려 하지만 없어도 기동한다
--   pullup   그 자원이 올라오면 이 자원도 따라 올린다
--   global   다른 노드의 것이어도 된다
--   uniform  모든 인스턴스에 대해 따진다
--   type:    특정 자원이 아니라 그 유형의 자원(노드 리스너 전체 등)
--
-- DB 는 디스크그룹에 hard, 리스너 · SCAN 리스너 · ONS 에는 weak 이다.
-- 디스크그룹이 없으면 못 뜨지만 리스너가 없어도 DB 는 뜬다. [4] 에서 확인한다.
--
-- ora.gns<Resource not found> 는 GNS 를 쓰지 않는 랩이라 나온다. weak 이라 무해하다.
--
-- DATA 와 FRA 의 표기가 다르다. DATA 는 [hard:global:uniform] 뿐이고
-- FRA 는 [hard:global,pullup:global] 이다. 같은 역할의 디스크그룹이라도
-- 정의는 따로 저장된다. 비교할 때는 디스크그룹마다 따로 본다.

================================================================================
Resource Stop Dependencies
================================================================================
----------------------------------ora.racdb.db----------------------------------
ora.racdb.db(ora.database.type)->
--------------------------------------------------------------------------------

-- -stop 과 -pullup 은 "이 자원이 움직이면 누가 따라 움직이나" 를 보여 준다.
-- [1] 의 기동 트리와 화살표 방향이 반대다.
--   rac2 VIP 가 내려가면   노드 리스너가 따라 내려간다
--   rac2 VIP 가 올라오면   노드 리스너가 따라 올라온다
--   racdb 가 내려가면      따라 내려가는 자원이 없다
-- 서비스를 만들었다면 racdb 아래에 서비스가 나왔을 것이다(15장 실습).

[grid@rac1 ~]$ crsctl stat res ora.LISTENER.lsnr -p -attr START_DEPENDENCIES,STOP_DEPENDENCIES
NAME=ora.LISTENER.lsnr
START_DEPENDENCIES=hard(type:ora.cluster_vip_net1.type) pullup(type:ora.cluster_vip_net1.type)
STOP_DEPENDENCIES=hard(intermediate:type:ora.cluster_vip_net1.type)

-- 리스너 쪽 정의에 적힌 것을 VIP 쪽에서 거꾸로 본 것이 [2] 의 두 트리다.

--------------------------------------------------------------------------------
 [3] 흔한 오류 — 의존 자원이 있는 VIP 를 그냥 내리면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl stop vip -node rac2
PRCR-1065 : Failed to stop resource ora.rac2.vip
CRS-2974: unable to act on resource 'ora.rac2.vip' on server 'rac2' because that would require stopping or relocating resource 'ora.LISTENER.lsnr' but the appropriate force flag was not specified

-- 원인 파악 : CRS-2974 가 이유를 그대로 말한다. VIP 를 내리려면 리스너도 내려야
--             하는데 -force 가 없다. [2] 의 정지 의존이 실제로 작동한 것이다.
--             15장 실습에서 서비스가 도는 인스턴스를 내릴 때 본 오류와 같은 번호다.
--             자원 종류가 달라도 "따라 움직여야 할 자원" 이 있으면 같은 오류가 난다.
-- 조치     : 함께 내려가도 되는지 판단한 뒤 -force 를 붙인다.
--             무엇이 따라 내려가는지는 [2] 의 -dependency -stop 으로 미리 본다.
-- 재확인   : 아무것도 바뀌지 않았는지 crsctl stat res -t 로 본다.

-- 세 자원의 상태가 다 다르다.
--   rac2 VIP       TARGET OFFLINE / STATE OFFLINE   사람이 내렸다
--   rac2 리스너    TARGET ONLINE  / STATE OFFLINE   의존 때문에 따라 내려갔다
--   racdb2         TARGET ONLINE  / STATE ONLINE    weak 이라 영향 없다
--
-- 리스너의 TARGET 이 ONLINE 으로 남은 것이 중요하다. 사람이 리스너를 내린 것이
-- 아니므로 "원래는 떠 있어야 한다" 는 의도가 그대로 있다.
-- 실습 10 [3] 의 점검 필터(TARGET = ONLINE and STATE != ONLINE)에 걸리는 상태다.

[oracle@rac1 ~]$ srvctl status vip -node rac2
VIP 172.16.225.112 is enabled
VIP 172.16.225.112 is not running
[oracle@rac1 ~]$ srvctl status listener -node rac2
Listener LISTENER is enabled on node(s): rac2
Listener LISTENER is not running on node(s): rac2

[oracle@rac2 ~]$ lsnrctl status
 TNS-12560: TNS:protocol adapter error
  TNS-00511: No listener
   Linux Error: 111: Connection refused

[rac2] SQL> select value from v$parameter where name='local_listener';

VALUE
------------------------------------------------------------
 (ADDRESS=(PROTOCOL=TCP)(HOST=172.16.225.112)(PORT=1521))

-- racdb2 의 local_listener 는 rac2 VIP(172.16.225.112)의 리스너다.
-- 지금 그 주소에는 VIP 도 리스너도 없다. racdb2 는 열려 있지만 VIP 경로로는
-- 새 접속을 받을 수 없다. 이미 붙은 세션은 리스너를 거치지 않으므로 그대로다.

 [5] VIP 를 올리면 — 끌어올림
--------------------------------------------------------------------------------

-- VIP 만 올렸는데 리스너도 올라왔다. [2] 의 pullup 이다.
-- 리스너의 TARGET 이 ONLINE 으로 남아 있었기 때문에 끌어올릴 대상이 됐다.
-- 사람이 srvctl stop listener 로 내린 리스너였다면 TARGET 이 OFFLINE 이라
-- 따라 올라오지 않는다.

[oracle@rac1 ~]$ srvctl start listener -node rac2
PRCC-1015 : LISTENER was already running on rac2
PRCR-1004 : Resource ora.LISTENER.lsnr is already running

-- 올리려 하면 이 메시지를 만난다. 스크립트라면 status 로 먼저 확인한다.
