 제15장 실습 10 — 드레인, 정지 옵션에 따라 세션이 어떻게 되는가
 대상   : rac1 (세션은 rac2 의 racdb2 에 붙는다)
 목표   : 서비스를 멈출 때 붙어 있던 세션의 운명을 정지 옵션
          TRANSACTIONAL · IMMEDIATE · NONE 별로 실측한다. 트랜잭션이 있는 세션과
          없는 세션을 나눠 보고, 드레인 시간 동안 srvctl 이 기다리는지 확인한다
 소요   : 약 35분
 선행   : 실습 09 완료 (ch15_root 가 racdb2 에서 실행, 드레인 30초 · TRANSACTIONAL 저장)
 계정   : oracle
 주의   : ch15_root 로 붙은 세션은 끊길 수 있다. 다른 작업이 이 서비스를 쓰지 않게 한다
================================================================================

--------------------------------------------------------------------------------
 [1] 준비 — 세션을 붙여 둘 스크립트
--------------------------------------------------------------------------------

[rac1] SQL> create table system.ch15_t (n number, who varchar2(30));
Table created.

[oracle@rac1 ~]$ cat /tmp/dr_open2.sh          (요지)
#!/bin/bash
S=$1; W=${2:-75}
# 세션 1 : 접속해 한 번 조회하고 W 초 쉰 뒤 다시 조회 — 트랜잭션 없음
( echo "select 'IDLE START '||...instance_name...||' sid='||...sid... from dual;"
  sleep $W
  echo "select 'IDLE AFTER '||... from dual;" ) | sqlplus -s system/<비밀번호>@rac-scan:1521/$S > /tmp/dr_idle.out 2>&1 &
# 세션 2 : 접속해 insert 하고 W 초 쉰 뒤 commit — 열린 트랜잭션
( echo "select 'TX START '||... from dual;"
  echo "insert into system.ch15_t values (1,'tx');"
  sleep $W
  echo "commit;"
  echo "select 'TX AFTER '||... from dual;" ) | sqlplus -s system/<비밀번호>@rac-scan:1521/$S > /tmp/dr_tx.out 2>&1 &

[oracle@rac1 ~]$ cat /tmp/dr_run.sh            (요지)
# 5 초마다 GV$SESSION 에서 그 서비스의 USER 세션 수를 세며 srvctl 을 실행하고 걸린 시간을 찍는다

-- 쉬는 동안의 세션은 서버 쪽에서 보면 INACTIVE 다. 커넥션 풀이 빌려주지 않은
-- 연결과 같은 모양이다. 세션 2 는 그 상태로 트랜잭션을 들고 있다.

-- 트랜잭션을 든 세션은 30~36 초 사이에 끊겼다. 저장된 드레인 시간 30 초만큼 기다린 것이다.

-- 애플리케이션이 드레인 시간 안에 트랜잭션을 끝내고 연결을 반납해야 손실이 없다.

-- IMMEDIATE 는 트랜잭션 여부와 관계없이 드레인 시간 동안 세션이 스스로 나가기를
-- 기다리고, 시간이 다 되면 남은 세션을 모두 끊었다.
-- 이 회차의 insert 도 롤백됐다. [5] 를 마친 뒤 테이블에 [5] 의 한 행만 있었다.

-- 70 초 넘게 GV$SESSION 의 SERVICE_NAME 이 ch15_root 인 채로 남아 있었다.
-- 멈춘 서비스로 붙은 세션이 계속 일하는 것이다. 실습 04 의 relocate 와 같은 원리다.
-- 서비스 정지는 새 접속만 막는다. 기존 세션을 비우는 것은 정지 옵션이 한다.

--------------------------------------------------------------------------------
 [6] 세 옵션의 실측 정리
--------------------------------------------------------------------------------

  정지 옵션        트랜잭션 없는 세션        트랜잭션 있는 세션             srvctl 반환
  --------------   -----------------------   ----------------------------   -----------
  TRANSACTIONAL    바로 끊음 (6 초 안)       드레인 시간 뒤 끊음 · 롤백     0.7~0.8 초
  IMMEDIATE        드레인 시간 뒤 끊음       드레인 시간 뒤 끊음 · 롤백     0.7 초
  NONE             끊지 않음                 끊지 않음 · commit 성공        1.0 초

-- 진단 — "드레인 시간 동안 srvctl 이 기다린다" 는 오해
--   세 경우 모두 srvctl 은 1 초 안에 돌아왔다. 드레인은 그 뒤에 데이터베이스가 한다.
--   유지보수 스크립트가 srvctl stop service 다음 줄에서 바로 인스턴스를 내리면
--   드레인 시간을 주지 않은 것과 같다. 남은 세션 수를 GV$SESSION 으로 확인하고 넘어간다.
--
-- 이 실습의 정지는 모두 -force 없이 했고 오류가 없었다. 저장된 값과 명령행 값 모두 쓰였다.
-- 문서상 -force 를 붙이면 드레인 없이 모든 세션을 끊는다. 이 실습에서는 재지 않았다.
