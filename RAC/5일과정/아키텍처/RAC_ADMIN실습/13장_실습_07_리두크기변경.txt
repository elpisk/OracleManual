================================================================================
 제13장 실습 07 — 리두로그 크기 바꾸기, 새로 만들고 옛것을 빼는 순서
 대상   : rac1 (rac2 는 확인만)
 목표   : 두 스레드의 리두 그룹을 200MB 에서 100MB 로 바꾸고 다시 200MB 로
          되돌린다. 지울 수 없는 세 가지 상태(최소 그룹 수, CURRENT, ACTIVE)를
          오류 번호로 구분한다. 다른 스레드의 로그 스위치를 한 노드에서 일으킨다
 소요   : 약 30분
 선행   : 실습 02 완료, racdb 양 노드 OPEN, ARCHIVELOG 여부는 상관없다
 계정   : oracle, grid
 주의   : 실습 끝에서 원래 구성(스레드마다 200MB 그룹 둘)으로 되돌린다.
          멤버 파일 이름은 새로 만들어지므로 처음과 달라진다
================================================================================

-- 이것을 100MB 로 바꾸는 것이 목표다. 리두 그룹에는 크기를 바꾸는 명령이 없다.
-- 새 크기의 그룹을 만들고 옛 그룹을 지우는 방법뿐이다.

 [1] 흔한 오류 — 옛것부터 지우려 하면
--------------------------------------------------------------------------------

-- 그룹 2 는 INACTIVE 다. 지금 쓰지도 않고 복구에도 필요 없다.
-- 그런데도 먼저 지우려 하면 거부된다.

[rac1] SQL> alter database drop logfile group 2;
alter database drop logfile group 2
*
ERROR at line 1:
ORA-01567: dropping log 2 would leave less than 2 log files for instance racdb1 (thread 1)
ORA-00312: online log 2 thread 1: '+DATA/RACDB/ONLINELOG/group_2.263.1248275565'
ORA-00312: online log 2 thread 1: '+FRA/RACDB/ONLINELOG/group_2.258.1248275571'

-- 원인 파악 : 활성 스레드는 그룹이 둘 이상이어야 한다. 스레드 1 에는 1·2 뿐이라
--             하나를 지우면 하나만 남는다. 상태가 INACTIVE 여도 소용없다.
--             메시지에 "instance racdb1 (thread 1)" 이 함께 나온다.
--             스레드 2 의 그룹이 몇 개든 스레드 1 의 계산에는 들어가지 않는다.
-- 조치     : 새 그룹을 먼저 만든다. 순서를 바꾸는 것 말고는 방법이 없다.
-- 재확인   : v$thread 의 GROUPS 열이 스레드마다 3 이상인지 보고 지운다.

 [4] 다른 스레드의 로그 스위치 — SWITCH ALL LOGFILE
--------------------------------------------------------------------------------

-- 남은 1 과 4 는 CURRENT 다. CURRENT 를 벗어나려면 로그 스위치가 필요하다.
-- alter system switch logfile 은 실행한 인스턴스의 스레드만 넘긴다.
-- rac1 에서 두 스레드를 모두 넘기려면 ALL 을 붙인다.

[rac1] SQL> alter system switch all logfile;

Elapsed: 00:00:00.10

        14          2          0        100 UNUSED

-- 스레드 1 은 넘어갔고 스레드 2 는 그대로다.

-- 요청만 보내고 돌아온 것이다. 바로 조회하면 이렇게 반쯤 진행된 상태가 보인다.

 [5] 흔한 오류 — ACTIVE 와 CURRENT
--------------------------------------------------------------------------------

[rac1] SQL> alter database drop logfile group 1;

[rac1] SQL> alter database drop logfile group 4;

ERROR at line 1:
ORA-01623: log 4 is current log for instance racdb2 (thread 2) - cannot drop
ORA-00312: online log 4 thread 2: '+DATA/RACDB/ONLINELOG/group_4.271.1248276143'
ORA-00312: online log 4 thread 2: '+FRA/RACDB/ONLINELOG/group_4.260.1248276153'

-- 원인 파악 : 오류 번호가 다르다.
--               ORA-01624  그룹 1 은 ACTIVE. 스위치는 됐지만 그 안의 변경이
--                          아직 데이터파일에 다 쓰이지 않아 인스턴스 복구에 필요하다.
--               ORA-01623  그룹 4 는 아직 CURRENT. racdb2 가 지금 쓰고 있다.
--             [1] 의 ORA-01567 까지 세 번호가 세 가지 상태에 하나씩 대응한다.
--               ORA-01567  그룹 수 부족        → 새 그룹부터 만든다
--               ORA-01623  CURRENT            → 해당 스레드에서 스위치
--               ORA-01624  ACTIVE             → 체크포인트
-- 조치     : ACTIVE 는 체크포인트로 INACTIVE 로 만든다. RAC 에서는 GLOBAL 을
--             붙여 모든 인스턴스가 체크포인트하게 한다.
-- 재확인   : v$log 의 STATUS 를 다시 본다.

[rac1] SQL> alter system checkpoint global;
System altered.
Elapsed: 00:00:00.23

        14          2          0        100 UNUSED

6 rows selected.

-- 그룹 1 은 INACTIVE 가 됐다. 그룹 4 는 아직 CURRENT 다.
-- 몇 초 뒤 다시 조회했다.

[rac1] SQL> select group#, thread#, sequence#, bytes/1024/1024 mb, status
  2    from v$log order by thread#, group#;

    GROUP#    THREAD#  SEQUENCE#         MB STATUS
---------- ---------- ---------- ---------- ----------------
         1          1         19        200 INACTIVE
        11          1         20        100 CURRENT

6 rows selected.

-- 이제 스레드 2 도 넘어갔다. [4] 의 요청을 racdb2 가 처리한 것이다.
-- 스위치와 체크포인트가 모두 끝나 그룹 4 도 INACTIVE 다.
--
-- 기다리지 않고 확실히 넘기려면 archive log current 를 쓴다.
-- 모든 스레드를 넘기고, 아카이브가 끝날 때까지 돌아오지 않는다.

[rac1] SQL> alter system archive log current;
System altered.
Elapsed: 00:00:02.79

[rac1] SQL> select group#, thread#, sequence#, bytes/1024/1024 mb, status
  2    from v$log order by thread#, group#;

    GROUP#    THREAD#  SEQUENCE#         MB STATUS
---------- ---------- ---------- ---------- ----------------
         1          1         19        200 INACTIVE
        11          1         20        100 INACTIVE
        12          1         21        100 CURRENT
         4          2         14        200 INACTIVE
        13          2         15        100 ACTIVE
        14          2         16        100 CURRENT

6 rows selected.

-- 0.1 초와 2.79 초의 차이가 두 명령의 차이다.
--   switch all logfile    요청만 보내고 바로 돌아온다
--   archive log current   모든 스레드가 넘어가고 아카이브까지 끝나야 돌아온다
-- 스크립트에서 다음 단계가 스위치 결과에 기대고 있다면 뒤의 것을 쓴다.

 [7] 되돌리기 — 같은 순서를 한 번 더

[rac1] SQL> alter database add logfile thread 1 group 1 ('+DATA','+FRA') size 200M;
Elapsed: 00:00:15.13
[rac1] SQL> alter database add logfile thread 1 group 2 ('+DATA','+FRA') size 200M;
Elapsed: 00:00:18.92
[rac1] SQL> alter database add logfile thread 2 group 3 ('+DATA','+FRA') size 200M;
Elapsed: 00:00:15.38
[rac1] SQL> alter database add logfile thread 2 group 4 ('+DATA','+FRA') size 200M;
Elapsed: 00:00:15.08

-- 200MB 는 그룹 하나에 15~19 초다. 100MB 일 때는 6~9 초였다.
-- 크기에 거의 비례한다. ASM 이 파일을 만들며 공간을 미리 채우기 때문이다.
-- 운영에서 1GB 그룹 여러 개를 만들 때는 이 시간을 작업 계획에 넣는다.

[rac1] SQL> alter system archive log current;     -- CURRENT 가 1 · 3 에 올 때까지 반복
[rac1] SQL> alter system checkpoint global;
[rac1] SQL> alter database drop logfile group 11;
[rac1] SQL> alter database drop logfile group 12;
[rac1] SQL> alter database drop logfile group 13;
[rac1] SQL> alter database drop logfile group 14;

-- archive log current 를 세 번 했을 때 두 스레드의 CURRENT 가 1 · 3 으로 왔다.
-- 스레드 1 은 11 → 12 → 1, 스레드 2 는 13 → 14 → 3 순으로 넘어갔다.
-- 새로 만든 UNUSED 그룹이 차례를 받기까지 스위치가 몇 번 필요하다.
