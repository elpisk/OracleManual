================================================================================
 제14장 실습 09 — 실행하기 전에 결과 보기, srvctl predict 와 crsctl eval
 대상   : rac1
 목표   : 자원 하나가 실패하거나 정지할 때 무엇이 함께 움직이는지 실행 없이
          미리 본다. 두 도구의 미리 보기가 각각 어디까지 되는지, 관리자 관리
          데이터베이스에서 막히는 곳을 확인한다
 소요   : 약 20분
 선행   : 실습 05 완료
 계정   : oracle, grid
 주의   : 모두 평가만 한다. 자원 상태는 바뀌지 않는다
================================================================================

--------------------------------------------------------------------------------
 [1] 흔한 오류 — srvctl stop -eval
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl stop database -help | grep -i eval
    -eval                          Evaluates the effects of event without making any changes to the system

[oracle@rac1 ~]$ srvctl stop database -db racdb -eval
PRKO-2712 : Administrator-managed database racdb is not supported with -eval option

[oracle@rac1 ~]$ srvctl start database -db racdb -eval
PRKO-2712 : Administrator-managed database racdb is not supported with -eval option

[oracle@rac1 ~]$ srvctl stop instance -db racdb -instance racdb2 -eval
PRKO-2002 : Invalid command line option: -eval

-- 원인 파악 : 도움말에는 -eval 이 있는데 이 데이터베이스에는 쓸 수 없다.
--             racdb 는 관리자 관리(Database is administrator managed) 다.
--             -eval 은 서버 풀로 배치가 정해지는 정책 관리 데이터베이스용이다.
--             인스턴스 단위 명령(stop instance)에는 옵션 자체가 없어 PRKO-2002 다.
--             같은 "안 된다" 도 번호가 다르다. 2712 는 이 DB 에 안 맞는 옵션,
--             2002 는 그 명령에 없는 옵션이다.
-- 조치     : 관리자 관리 DB 의 영향 범위는 srvctl predict 로 본다([2]).
-- 재확인   : srvctl config database 의 마지막 줄로 관리 방식을 확인한다.

--------------------------------------------------------------------------------
 [2] srvctl predict — "이것이 실패하면"
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl predict -help
The SRVCTL predict command evaluates the consequences of resource failure.

Usage: srvctl predict database -db <database_name> [-verbose]
Usage: srvctl predict service -db <database_name> -service <service_name> [-verbose]
Usage: srvctl predict asm [-node <node_name>] [-verbose]
Usage: srvctl predict diskgroup -diskgroup <diskgroup_name> [-verbose]
Usage: srvctl predict vip -vip <vip_name> [-verbose]
Usage: srvctl predict network [-netnum <network_number>] [-verbose]
Usage: srvctl predict listener -listener <listener_name> [-verbose]
Usage: srvctl predict scan -scannumber <scan_ordinal_number> [-netnum <network_number>] [-verbose]
Usage: srvctl predict scan_listener -scannumber <scan_ordinal_number> [-netnum <network_number>] [-verbose]
...

-- 첫 줄이 정확하다. 정지가 아니라 실패(failure)의 결과를 평가한다.

[grid@rac1 ~]$ srvctl predict vip -vip rac2 -verbose
VIP rac2 will be started on node rac1
Listener LISTENER will be stopped

-- rac2 의 VIP 가 실패하면 VIP 는 rac1 로 옮겨 가고, rac2 의 노드 리스너는 멈춘다.
-- VIP 가 옮겨 가는 것은 새 접속을 받으려는 것이 아니다. 클라이언트가 오래
-- 기다리지 않고 바로 거절당하게 하려는 것이다(아키텍처 한글판 VIP 절).
-- 리스너가 멈추는 것은 리스너가 VIP 에 hard 의존하기 때문이다(실습 11).

[grid@rac1 ~]$ srvctl predict scan_listener -scannumber 1 -verbose
Listener LISTENER_SCAN1 will be started on node rac2
VIP scan1 will be started on node rac2

-- SCAN 리스너가 실패하면 리스너와 SCAN VIP 가 함께 rac2 로 간다.
-- 둘은 같은 노드에 있어야 하는 짝이다. 실습 12 에서 실제로 옮긴다.

[grid@rac1 ~]$ srvctl predict asm -node rac2 -verbose
Resource RG: ora.asmgroup will be stopped
Listener ASMNET1LSNR_ASM will be stopped
Resource ora.CH9DG.dg will be stopped
Resource ora.CRS.dg will be stopped
Resource ora.DATA.dg will be stopped
Resource ora.FRA.dg will be stopped
Resource ora.asm will be stopped
Resource ora.asmnet1.asmnetwork will be stopped

-- rac2 의 ASM 이 실패하면 ASM 그룹 자원들이 멈춘다. 그런데 racdb 는 목록에 없다.
-- Flex ASM 이라 racdb2 는 rac1 의 ASM 으로 옮겨 붙기 때문이다
-- (6장 실습 08, Flex ASM 장애 전환). 일반 ASM 이었다면 racdb2 가 함께 멈췄다.

[grid@rac1 ~]$ srvctl predict diskgroup -diskgroup DATA -verbose
Resource ora.DATA.dg will be stopped

[grid@rac1 ~]$ srvctl predict database -db racdb -verbose
Database racdb will be stopped on nodes rac1,rac2

-- DATA 디스크그룹 실패의 결과로 racdb 정지가 나오지 않는다.
-- predict 는 바로 붙은 자원만 계산하고, 의존을 끝까지 따라가지 않는 것으로 보인다.
-- 영향 범위를 넓게 보려면 의존 관계(실습 11)와 함께 읽는다.

--------------------------------------------------------------------------------
 [3] crsctl eval — ora. 자원에는 쓸 수 없다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl eval -help | grep -E 'eval (start|stop|fail|relocate) resource '
  crsctl eval start resource {<resname>|-w <filter>}[-n server] [-f]
  crsctl eval stop resource {<resname>|-w <filter>} [-f]
  crsctl eval relocate resource { <resName> [-s <server>] | -all -s <server> | -w <filter> } {-n <server>} [-f]
  crsctl eval fail resource {<resname> | -w <filter>} [-n <server>] [-env "<attr>=<val>[,...]"]

[grid@rac1 ~]$ crsctl eval stop resource ora.rac2.vip
CRS-4995:  The command 'stop  resource' is invalid in crsctl. Use srvctl for this command.

[grid@rac1 ~]$ crsctl eval fail resource ora.racdb.db -n rac2
CRS-4995:  The command 'fail  resource' is invalid in crsctl. Use srvctl for this command.

-- 원인 파악 : 실습 01 · 04 에서 본 CRS-4995 다. eval 이 붙어도 경계는 같다.
--             ora. 자원에 대한 start · stop · fail 은 평가조차 crsctl 로 하지 않는다.
-- 조치     : ora. 자원은 srvctl predict 로 본다. crsctl eval 은 도움말대로
--             사용자 자원(실습 06 의 자원 같은 것)이나 서버 · 서버 풀을
--             평가할 때 쓴다. 서버 평가는 [4] 에서 실제로 된다.
-- 재확인   : 같은 대상을 srvctl predict 로 다시 본다.

--------------------------------------------------------------------------------
 [4] crsctl eval 로 되는 것 — 서버를 빼면
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl eval delete server rac2 -explain

Stage Group 1:
--------------------------------------------------------------------------------
Stage  Required Action
--------------------------------------------------------------------------------

    1      E    Server 'rac2' is removed from server pool 'Generic'.
           Y    Resource 'ora.CH9DG.dg' (2/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.CRS.dg' (2/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.DATA.dg' (2/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.FRA.dg' (2/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.LISTENER.lsnr' (rac2) will be in state 'OFFLINE'.
           Y    Resource 'ora.asm' (2/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.asmgroup' (ora.asmgroup 2/1) will be in state
                'OFFLINE'.
           Y    Resource 'ora.asmnet1.asmnetwork' (2/1) will be in state
                'OFFLINE'.
           Y    Resource 'ora.chad' (rac2) will be in state 'OFFLINE'.
           Y    Resource 'ora.net1.network' (rac2) will be in state 'OFFLINE'.
           Y    Resource 'ora.ons' (rac2) will be in state 'OFFLINE'.
           Y    Resource 'ora.rac2.vip' (1/1) will be in state 'OFFLINE'.
           Y    Resource 'ora.racdb.db' (2/1) will be in state 'OFFLINE'.

    2      Y    Resource 'ora.rac2.vip' (1/1) will be in state
                'ONLINE|INTERMEDIATE' on server 'rac1'.

--------------------------------------------------------------------------------

-- 서버 rac2 가 클러스터에서 빠지면 무엇이 되는지 단계별로 나온다.
-- 관리자 관리 DB 라도 서버 단위 평가는 된다.
--
-- 읽는 법.
--   (2/1)            카디널리티 ID 2 의 첫 번째 인스턴스. racdb 의 2 번은 racdb2 다
--   1 단계           rac2 의 자원이 모두 OFFLINE. racdb2 도 여기 있다
--   2 단계           rac2 의 VIP 만 rac1 에서 INTERMEDIATE 로 뜬다
--   INTERMEDIATE     떠 있지만 정상 상태는 아니다. 노드 VIP 는 원래 노드가
--                    없으면 접속을 받지 않고 거절만 한다
-- [2] 의 predict vip 와 같은 결론을 노드 전체 범위로 본 것이다.
-- 노드를 유지보수로 내리기 전에 이 출력을 남겨 두면 정지 후 상태와 맞춰 볼 수 있다.

--------------------------------------------------------------------------------
 [5] 두 도구 정리
--------------------------------------------------------------------------------

-- 이 랩(관리자 관리 DB, Flex ASM)에서 확인한 범위다.
--
--   무엇을 보나               도구                         결과
--   DB · 인스턴스 정지 영향   srvctl stop ... -eval        PRKO-2712 / PRKO-2002
--   자원 하나의 실패 영향     srvctl predict <대상>         된다. 바로 붙은 자원까지
--   ora. 자원 평가            crsctl eval stop/fail        CRS-4995
--   노드 하나가 빠질 때       crsctl eval delete server     된다. 단계별
--
-- 어느 쪽도 실제 정지의 결과를 보장하지는 않는다. 평가는 지금의 정의와 상태로
-- 계산한 것이다. 실행한 뒤에는 crsctl stat res -t 로 다시 본다.
