================================================================================
 제14장 실습 01 — 두 명령의 역할 분담, 경계를 넘어 보기
 대상   : rac1
 목표   : srvctl 과 crsctl 이 각각 무엇을 다루는지 확인하고, 경계를 넘었을 때
          오라클이 어떻게 막는지 직접 본다
 소요   : 약 20분
 선행   : racdb 양 노드 OPEN, 부하 4 이하
 계정   : oracle, grid
================================================================================

--------------------------------------------------------------------------------
 [1] 두 도움말을 나란히 본다
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl
Usage: srvctl <command> <object> [<options>]
    commands: enable|disable|export|import|start|stop|relocate|status|add|remove|
              modify|getenv|setenv|unsetenv|config|convert|update|upgrade|
              downgrade|predict
    objects: database|instance|service|nodeapps|vip|network|asm|diskgroup|
             listener|scan|scan_listener|srvpool|server|filesystem|cvu|cha|
             ons|volume|mgmtdb| ... (총 40여 개)

[grid@rac1 ~]$ crsctl
Usage: crsctl <command> <object> [<options>]
    command: add|check|config|create|delete|disable|enable|eval|export|get|
             modify|query|replace|set|setperm|start|status|stop|unpin|unset

-- 모양이 다르다는 것 자체가 성격 차이를 말해 준다.
--
--   srvctl 은 대상 목록을 미리 보여 준다. 오라클이 정의한 자원 종류가
--   정해져 있기 때문이다.
--
--   crsctl 은 대상 목록이 없다. resource·type·crs·cluster·css 같은 것이
--   오는데, 사용자가 새 자원을 만들 수 있으므로 목록을 미리 못 정한다.

--------------------------------------------------------------------------------
 [2] 경계를 넘어 본다 — 오류 재현
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl stop resource ora.racdb.db
CRS-4995:  The command 'Stop  resource' is invalid in crsctl. Use srvctl for this command.

[grid@rac1 ~]$ echo $?
1

[grid@rac1 ~]$ crsctl start resource ora.racdb.db
CRS-4995:  The command 'Start  resource' is invalid in crsctl. Use srvctl for this command.

[grid@rac1 ~]$ echo $?
1

-- 원인 파악 : 데이터베이스는 오라클 제품 자원이므로 srvctl 의 관할이다.
--             crsctl 이 자원 수준에서 강제로 내리면 세션 정리와
--             체크포인트를 건너뛰게 되고, 12장에서 확인한
--             정상 종료와 비정상 종료의 구분이 무너진다.
--             그래서 오라클이 명시적으로 막는다.
-- 조치     : 메시지가 알려 준 대로 srvctl 을 쓴다.
--               srvctl stop instance -d racdb -i racdb1
--             이 실습에서는 실제로 내리지 않는다. 오류만 확인한다.
-- 재확인   : 종료 코드가 1 인지 본다. 스크립트에서 이 명령을 쓰면
--             실패로 처리되므로 미리 알아 두어야 한다.

-- 주의: 데이터베이스는 이 시도로 아무 영향을 받지 않았다.
--       거부되었으므로 상태가 바뀌지 않는다.

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

--------------------------------------------------------------------------------
 [3] 그런데 조회는 된다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p | egrep '^NAME=|^TYPE=|^AUTO_START|^CARDINALITY'
NAME=ora.racdb.db
TYPE=ora.database.type
AUTO_START=restore
CARDINALITY=2

-- 읽기는 열려 있고 쓰기만 막혔다. 이 비대칭이 두 도구의 관계를 잘 보여 준다.
--
-- 이유는 이렇다. 자원 정의는 OCR 에 저장되어 있고 crsctl 은 OCR 을 읽는
-- 도구다. 데이터베이스 자원의 정의도 OCR 에 있으므로 읽는 것은 자연스럽다.
--
-- 반면 "정지" 라는 동작은 제품 지식이다. crsctl 은 데이터베이스가 무엇인지
-- 모르고 어떻게 내려야 하는지도 모른다.

--------------------------------------------------------------------------------
 [4] crsctl 로만 되는 일 — 스택 상태
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl check crs
CRS-4638: Oracle High Availability Services is online
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online

[grid@rac1 ~]$ crsctl check cluster -all
**************************************************************
rac1:
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online
**************************************************************
rac2:
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online
**************************************************************

[grid@rac1 ~]$ crsctl check css
CRS-4529: Cluster Synchronization Services is online

-- 세 명령의 차이.
--
--   check crs        실행한 노드의 스택. OHAS(CRS-4638)를 포함해 넷.
--   check cluster    모든 노드. OHAS 를 뺀 셋.
--   check css        CSSD 하나만.
--
-- OHAS 가 check cluster 에 없는 이유는 그것이 클러스터가 형성되기 전 단계의
-- 노드별 데몬이기 때문이다. 클러스터 관점의 조회 대상이 아니다.
--
-- 실무 순서. 어느 노드가 문제인지 모를 때 check cluster -all 을 먼저 돌리고,
-- 응답이 없는 노드를 찾으면 그 노드에 붙어 check crs 로 들어간다.

--------------------------------------------------------------------------------
 [5] 정리 — 선택 기준
--------------------------------------------------------------------------------

-- 오라클 제품 자원이면 srvctl, 클러스터 자체나 사용자 자원이면 crsctl.
--
-- 헷갈릴 때의 요령. srvctl 을 먼저 시도한다. 잘못 골랐어도
-- crsctl 이 CRS-4995 로 친절하게 알려 주기 때문이다.
--
-- 반대 방향으로는 안내가 없다. srvctl 로 사용자 자원을 다루려 하면
-- 그저 대상을 모른다는 사용법 출력만 나온다.
-- 그래서 사용자 자원은 처음부터 crsctl 로 다룬다고 기억해 두는 편이 낫다.
