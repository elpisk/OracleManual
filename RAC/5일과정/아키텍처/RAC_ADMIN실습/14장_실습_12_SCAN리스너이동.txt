================================================================================
 제14장 실습 12 — SCAN 리스너와 SCAN VIP 옮기기, 짝으로 움직이는 자원
 대상   : rac1, rac2
 목표   : SCAN 리스너를 rac2 로 옮겼다가 SCAN VIP 를 기준으로 되돌린다.
          리스너와 VIP 가 함께 움직이는 것, 옮긴 뒤 인스턴스가 다시 등록되는
          시간을 확인한다. 이동 명령의 흔한 오류를 본다
 소요   : 약 20분
 선행   : 실습 11 완료
 계정   : oracle, grid
 주의   : 이동하는 5 초 남짓 동안 SCAN 으로 새 접속을 할 수 없다.
          이 랩은 SCAN VIP 가 하나뿐이라 그 시간 동안 대신 받을 SCAN 리스너가 없다
================================================================================

 [3] SCAN 리스너를 rac2 로
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl relocate scan_listener -scannumber 1 -node rac2
>>> 5.5초

[grid@rac1 ~]$ crsctl stat res ora.scan1.vip ora.LISTENER_SCAN1.lsnr -t
--------------------------------------------------------------------------------
Name           Target  State        Server                   State details
--------------------------------------------------------------------------------
Cluster Resources
--------------------------------------------------------------------------------
ora.LISTENER_SCAN1.lsnr
      1        ONLINE  ONLINE       rac2                     STABLE
ora.scan1.vip
      1        ONLINE  ONLINE       rac2                     STABLE
--------------------------------------------------------------------------------

-- 리스너만 옮기라고 했는데 SCAN VIP 도 rac2 로 갔다.
-- SCAN 리스너는 SCAN VIP 주소로 듣는다. 주소가 없는 노드에서는 뜰 수 없으므로
-- 둘은 늘 같은 노드에 있다. 실습 09 의 predict scan_listener 결과와 같다.

[root@rac2 ~]# ip -4 addr show ens33 | grep inet
    inet 172.16.225.102/24 brd 172.16.225.255 scope global noprefixroute ens33
    inet 172.16.225.112/24 brd 172.16.225.255 scope global secondary ens33:1
    inet 172.16.225.120/24 brd 172.16.225.255 scope global secondary ens33:2

-- rac2 의 ens33 에 주소가 셋이다. 공용 IP(.102), 노드 VIP(.112), SCAN VIP(.120).
-- VIP 는 별도 장치가 아니라 같은 인터페이스에 얹힌 보조 주소다.

[grid@rac2 ~]$ lsnrctl services LISTENER_SCAN1 | grep Instance | sort | uniq -c
      5   Instance "racdb1", status READY, has 1 handler(s) for this service...
      5   Instance "racdb2", status READY, has 1 handler(s) for this service...

-- 옮기고 5 초 뒤의 조회다. 두 인스턴스가 다섯 서비스 모두에 등록돼 있다.
-- 리스너가 새 노드에서 뜨고 5 초 안에 두 인스턴스가 다시 등록됐다.
-- 그 뒤 30 초 동안 5 초마다 봤는데 내내 같았다.

[grid@rac1 ~]$ lsnrctl status LISTENER_SCAN1
 TNS-12560: TNS:protocol adapter error
  TNS-00511: No listener
   Linux Error: 2: No such file or directory

-- rac1 에서는 LISTENER_SCAN1 이 없다고 나온다. lsnrctl 은 자기 노드의
-- 리스너에게만 묻는다. SCAN 리스너가 어디 있는지는 srvctl status scan_listener 로 본다.

--------------------------------------------------------------------------------
 [4] 흔한 오류 — 이동 명령
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl relocate scan_listener -scannumber 1 -node rac2
PRCR-1105 : Failed to relocate resource ora.LISTENER_SCAN1.lsnr to node rac2
PRCR-1089 : Failed to relocate resource ora.LISTENER_SCAN1.lsnr.
CRS-2731: Resource 'ora.LISTENER_SCAN1.lsnr' is already running on server 'rac2'

[oracle@rac1 ~]$ srvctl relocate scan_listener -scannumber 2 -node rac1
PRCR-1001 : Resource ora.LISTENER_SCAN2.lsnr does not exist

-- 원인 파악 : 두 경우가 다르다.
--               CRS-2731   이미 그 노드에 있다. 해가 없는 실패다
--               PRCR-1001  2 번 SCAN 리스너가 없다. SCAN 주소가 하나뿐이다
--             -scannumber 는 SCAN VIP 의 순번이다. 자원 이름 LISTENER_SCAN<n> 의 n 과 같다.
--             SCAN 주소가 셋인 클러스터라면 1~3 이 있다.
-- 조치     : srvctl status scan_listener 로 순번과 현재 노드를 먼저 본다.
-- 재확인   : 같은 명령으로 위치가 바뀌었는지 본다.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

-- 걸린 시간도 5.3 초로 [3] 과 비슷하다.

[oracle@rac1 ~]$ srvctl status scan; srvctl status scan_listener
SCAN VIP scan1 is enabled
SCAN VIP scan1 is running on node rac1
SCAN Listener LISTENER_SCAN1 is enabled
SCAN listener LISTENER_SCAN1 is running on node rac1

[grid@rac1 ~]$ lsnrctl services LISTENER_SCAN1 | grep Instance | sort | uniq -c
      5   Instance "racdb1", status READY, has 1 handler(s) for this service...
      5   Instance "racdb2", status READY, has 1 handler(s) for this service...

-- 처음 위치(rac1)로 돌아왔고 두 인스턴스 모두 등록돼 있다.
--
-- relocate 는 "임시" 이동이다. 도움말 첫 줄도 Temporarily relocate 다.
-- SCAN 리스너는 정해진 노드가 없어서, 노드가 재기동되거나 장애가 나면
-- Clusterware 가 알아서 다시 배치한다. 운영에서 쓰는 때는 노드 유지보수 전에
-- SCAN 을 미리 다른 노드로 비켜 두는 경우다.
