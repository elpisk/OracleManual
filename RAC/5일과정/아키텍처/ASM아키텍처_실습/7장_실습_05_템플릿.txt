 [3] 사용자 템플릿을 만든다
--------------------------------------------------------------------------------

SQL> alter diskgroup TEST add template mytpl attributes (unprotected fine);

Diskgroup altered.

SQL> select entry_number, name, redundancy, stripe, system
  2    from v$asm_template
  3   where group_number=(select group_number from v$asm_diskgroup where name='TEST')
  4     and system='N';

ENTRY_NUMBER NAME             REDUND STRIPE S
------------ ---------------- ------ ------ -
         426 MYTPL            UNPROT FINE   N

-- SYSTEM 이 N 이다. 사용자가 만든 템플릿이다.
-- ENTRY_NUMBER 426 은 기본 템플릿들(200~423)보다 뒤에 붙는다.
--
-- attributes 절에 두 가지를 지정했다.
--   unprotected  중복도. unprotected / mirror / high 중 하나
--   fine         스트라이프 방식. coarse / fine 중 하나
--
-- 중복도는 디스크그룹이 허용하는 범위 안에서만 지정할 수 있다.
-- External 디스크그룹에 mirror 를 지정할 수는 없다.

 [7] 템플릿 변경은 기존 파일에 적용되지 않는다
--------------------------------------------------------------------------------

SQL> alter diskgroup TEST alter template mytpl attributes (coarse);

Diskgroup altered.

SQL> select entry_number, name, redundancy, stripe from v$asm_template
  2   where group_number=(select group_number from v$asm_diskgroup where name='TEST')
  3     and system='N';

ENTRY_NUMBER NAME             REDUND STRIPE
------------ ---------------- ------ ------
         426 MYTPL            UNPROT COARSE

-- 템플릿은 COARSE 로 바뀌었다. 그런데 이미 만든 파일은 어떻게 되었을까.

SQL> select file_number, striped from v$asm_file
  2   where group_number=(select group_number from v$asm_diskgroup where name='TEST')
  3   order by file_number;

FILE_NUMBER STRIPE
----------- ------
        256 COARSE
        257 FINE

-- 파일 257 은 여전히 FINE 이다.
--
-- 템플릿은 파일을 만들 때만 참조된다. 이미 만들어진 파일의 저장 방식은
-- 바뀌지 않는다. 바꾸려면 파일을 다시 만들어야 한다.
--
-- 이 점을 모르고 템플릿만 바꾼 뒤 성능이 개선되기를 기다리는 실수가 흔하다.
-- 반대로 말하면 템플릿 변경은 안전하다. 기존 파일을 건드리지 않으므로
-- 되돌리기도 쉽다. 6장의 compatible 속성처럼 한 방향뿐인 변경이 아니다.

-- 되돌린다.
SQL> alter diskgroup TEST alter template mytpl attributes (fine);

Diskgroup altered.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- 재현한 오류
--   ORA-01119 / ORA-17502 / ORA-15060   없는 템플릿 지정 (3계층)
--   ORA-15032 / ORA-15008               시스템 템플릿 삭제 시도
--
-- 확인한 것
--   1) 기본 템플릿은 22개. CONTROLFILE 만 FINE
--   2) REDUNDANCY 는 디스크그룹 중복도를 따른다. +CRS 는 MIRROR
--   3) 템플릿은 디스크그룹마다 독립적으로 22개씩 있다
--   4) 사용자 템플릿은 SYSTEM='N', ENTRY_NUMBER 는 424 이상
--   5) +DG(템플릿) 형식으로 지정한다
--   6) 같은 DATAFILE 종류라도 템플릿에 따라 COARSE / FINE 이 갈린다
--   7) 시스템 템플릿은 지울 수 없지만 속성 변경은 가능하다
--   8) 템플릿 변경은 이후 파일에만 적용된다. 기존 파일은 그대로다
--
-- 실무 활용
--   갱신이 잦고 작은 테이블스페이스 -> FINE 으로 부하 분산
--   Normal DG 의 아카이브 로그      -> unprotected 로 용량 절약
--   재생성 가능한 임시 파일         -> unprotected
--   단, 적용 대상은 이후 만드는 파일뿐이라는 점을 항상 확인한다.
