================================================================================
 제4장 실습 01 — 응답 파일 읽기
 대상   : rac1
 목표   : GI 설치에 쓴 응답 파일의 항목을 성격별로 묶어 이해하고,
          판단이 필요한 항목과 형식이 낯선 항목을 구분한다
 소요   : 약 25분
 선행   : Grid 미디어가 홈에 풀려 있을 것
 계정   : grid
================================================================================

--------------------------------------------------------------------------------
 [1] 템플릿에서 시작한다
--------------------------------------------------------------------------------

-- 빈 파일에서 시작하지 않는다. 미디어에 모든 항목과 설명이 담긴 템플릿이 있다.

[grid@rac1 ~]$ ls -l /u01/app/19.3.0/grid/install/response/
total 76
-rw-r--r--. 1 grid oinstall 36648 Aug 31 19:03 grid_2026-08-31_07-02-05PM.rsp
-rw-r-----. 1 grid oinstall 36221 Jan 19  2019 gridsetup.rsp
-rw-r-----. 1 grid oinstall  1541 May 21  2016 sample.ccf

[grid@rac1 ~]$ f=/u01/app/19.3.0/grid/install/response/gridsetup.rsp
[grid@rac1 ~]$ echo "전체 $(wc -l < $f) / 주석 $(grep -c '^#' $f) / 실제항목 $(grep -vE '^#|^$' $f | wc -l)"
전체 653 / 주석 525 / 실제항목 64

-- 653줄 중 525줄이 주석이고 실제 항목은 64개다. 주석에 각 항목의 의미와
-- 가능한 값이 적혀 있다. 이것을 복사해 값을 채우면 항목 이름을 외울 필요가
-- 없고 빠뜨리는 항목도 줄어든다.
--
-- 파일이 셋 있는 점도 눈여겨본다.
--   gridsetup.rsp                        원본 템플릿(2019년 미디어 날짜)
--   grid_2026-08-31_07-02-05PM.rsp       설치 관리자가 남긴 사본
--   sample.ccf                           클러스터 구성 파일 샘플
--
-- 두 번째 파일이 유용하다. 설치 관리자가 실제로 사용한 응답 값을 시각을 붙여
-- 저장해 둔 것이다. 원래 쓴 응답 파일을 잃어버렸어도 여기서 확인할 수 있다.
-- 다만 비밀번호는 저장되지 않으므로 그 부분은 비어 있다.

--------------------------------------------------------------------------------
 [2] 실제로 사용한 응답 파일
--------------------------------------------------------------------------------

-- 주석과 빈 줄을 걷어 낸 최종 형태다. 비밀번호는 자리표시자로 바꿔 두었다.

oracle.install.responseFileVersion=/oracle/install/rspfmt_crsinstall_response_schema_v19.0.0
INVENTORY_LOCATION=/u01/app/oraInventory
oracle.install.option=CRS_CONFIG
ORACLE_BASE=/u01/app/grid

oracle.install.asm.OSDBA=asmdba
oracle.install.asm.OSOPER=asmoper
oracle.install.asm.OSASM=asmadmin

oracle.install.crs.config.scanType=LOCAL_SCAN
oracle.install.crs.config.gpnp.scanName=rac-scan
oracle.install.crs.config.gpnp.scanPort=1521

oracle.install.crs.config.ClusterConfiguration=STANDALONE
oracle.install.crs.config.configureAsExtendedCluster=false
oracle.install.crs.config.clusterName=rac-cluster
oracle.install.crs.config.gpnp.configureGNS=false
oracle.install.crs.config.autoConfigureClusterNodeVIP=false

oracle.install.crs.config.clusterNodes=rac1:rac1-vip:HUB,rac2:rac2-vip:HUB
oracle.install.crs.config.networkInterfaceList=ens33:172.16.225.0:1,ens160:172.16.119.0:5

oracle.install.crs.configureGIMR=false
oracle.install.asm.configureGIMRDataDG=false

oracle.install.crs.config.storageOption=FLEX_ASM_STORAGE
oracle.install.crs.config.useIPMI=false

oracle.install.asm.SYSASMPassword=<SYSASM 비밀번호>
oracle.install.asm.monitorPassword=<ASMSNMP 비밀번호>
oracle.install.asm.diskGroup.name=CRS
oracle.install.asm.diskGroup.redundancy=NORMAL
oracle.install.asm.diskGroup.AUSize=4
oracle.install.asm.diskGroup.disks=/dev/asmdisk/crs1,/dev/asmdisk/crs2,/dev/asmdisk/crs3
oracle.install.asm.diskGroup.disksWithFailureGroupNames=/dev/asmdisk/crs1,,/dev/asmdisk/crs2,,/dev/asmdisk/crs3,
oracle.install.asm.diskGroup.diskDiscoveryString=/dev/asmdisk/*
oracle.install.asm.configureAFD=false

oracle.install.crs.configureRHPS=false
oracle.install.crs.config.ignoreDownNodes=false
oracle.install.config.managementOption=NONE
oracle.install.config.omsPort=0
oracle.install.crs.rootconfig.executeRootScript=false

--------------------------------------------------------------------------------
 [3] 성격별로 묶어 읽는다
--------------------------------------------------------------------------------

-- 설치 종류
--   option=CRS_CONFIG        클러스터를 구성한다
--                            다른 값: CRS_SWONLY(소프트웨어만),
--                                     HA_CONFIG(단일 노드 Oracle Restart),
--                                     UPGRADE(업그레이드)
--
-- 위치
--   INVENTORY_LOCATION       인벤토리 경로
--   ORACLE_BASE              grid 계정의 base. Grid 홈은 이 아래가 아니다
--
-- 클러스터
--   clusterName=rac-cluster  클러스터 이름. cemutlo -n 으로 확인된다
--   ClusterConfiguration=STANDALONE  독립 클러스터. 다른 값은 DOMAIN, MEMBERDB 등
--   configureAsExtendedCluster=false 확장 클러스터(사이트 분리) 아님
--   clusterNodes             hostname:vip:role 형식
--
-- SCAN
--   scanType=LOCAL_SCAN      GNS 없이 DNS 나 hosts 로 해석
--   scanName / scanPort      rac-scan, 1521
--   configureGNS=false       GNS 미사용
--   autoConfigureClusterNodeVIP=false  VIP 를 자동 구성하지 않고 직접 지정
--
-- 네트워크
--   networkInterfaceList     이름:서브넷:용도
--
-- ASM 권한
--   OSDBA=asmdba OSOPER=asmoper OSASM=asmadmin
--   3장에서 만든 그룹과 대응한다
--
-- 디스크그룹
--   name=CRS redundancy=NORMAL AUSize=4
--   disks / disksWithFailureGroupNames / diskDiscoveryString
--
-- 기타
--   configureGIMR=false      관리 저장소 미사용
--   storageOption=FLEX_ASM_STORAGE  Flex ASM
--   configureAFD=false       ASM Filter Driver 미사용(udev 로 대신함)
--   useIPMI=false            IPMI 미사용
--   configureRHPS=false      Rapid Home Provisioning 미사용
--   managementOption=NONE    EM 등록 없음
--   rootconfig.executeRootScript=false  root.sh 를 자동 실행하지 않음

--------------------------------------------------------------------------------
 [4] 형식이 낯선 항목
--------------------------------------------------------------------------------

-- networkInterfaceList
--   ens33:172.16.225.0:1,ens160:172.16.119.0:5
--   이름:서브넷:용도 를 쉼표로 이어 붙인다.
--   용도 코드  1=public  5=ASM+private  2=private only  3=ASM only  0=미사용
--   인터페이스 이름은 실제 값이어야 한다. 3장에서 확인한 값을 쓴다.

-- disksWithFailureGroupNames
--   /dev/asmdisk/crs1,,/dev/asmdisk/crs2,,/dev/asmdisk/crs3,
--   디스크와 장애 그룹 이름을 쌍으로 적는다.
--   이름을 지정하지 않으면 그 자리가 비어 쉼표가 연속된다.
--   오타로 보고 고치면 파싱이 어긋난다.
--   장애 그룹을 명시하려면 /dev/asmdisk/crs1,FG1,/dev/asmdisk/crs2,FG2 형식이다.

-- clusterNodes
--   rac1:rac1-vip:HUB,rac2:rac2-vip:HUB
--   hostname:vip:role 형식. HUB 는 Flex Cluster 의 역할이며
--   일반 클러스터에서는 모든 노드가 HUB 다. LEAF 는 Flex Cluster 전용이다.

--------------------------------------------------------------------------------
 [5] 판단이 필요한 항목 셋
--------------------------------------------------------------------------------

-- 나머지는 3장에서 확인한 환경 값을 옮겨 적는 것이다.
-- 실제로 판단이 필요한 것은 셋뿐이다.
--
--   diskGroup.redundancy
--     NORMAL 이면 보팅 파일 3벌, EXTERNAL 이면 1벌, HIGH 면 5벌이다.
--     1벌이면 그 디스크가 죽을 때 클러스터가 멈춘다. NORMAL 을 택했다.
--
--   configureGIMR
--     별도 디스크그룹과 수십 GB 가 필요하고 설치 시간도 길어진다.
--     얻는 것은 CHM 이력의 장기 보관이다. 학습 목적에는 영향이 없어 false.
--
--   rootconfig.executeRootScript
--     true 면 설치 관리자가 root.sh 를 자동 실행한다.
--     false 로 두면 노드 순서를 직접 통제하고 각 단계 출력을 확인할 수 있다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — 응답 파일이 잘못됐을 때
--------------------------------------------------------------------------------

-- 무인 설치는 값이 잘못되어도 실행한 뒤에야 알 수 있다. 두 경우를 확인한다.
-- 둘 다 파일 검증 단계에서 멈추므로 시스템에 아무 영향이 없다.

-- (1) 파일이 없을 때
[grid@rac1 grid]$ ./gridSetup.sh -silent -responseFile /tmp/nosuch.rsp
Launching Oracle Grid Infrastructure Setup Wizard...

[FATAL] [INS-10101] The given response file /tmp/nosuch.rsp is not found.
   CAUSE: The given response file is either not accessible or do not exists.
   ACTION: Give a correct response file location.
           (Note: relative path is not supported)

-- 원인 파악
--   ACTION 절의 괄호가 중요한 정보를 담고 있다. 상대 경로는 지원되지 않는다.
--   ./gridsetup.rsp 처럼 상대 경로로 넘기면 파일이 있어도 이 오류가 난다.
--   반드시 절대 경로를 쓴다.

-- (2) 파일 형식이 맞지 않을 때
[grid@rac1 grid]$ : > /tmp/empty.rsp
[grid@rac1 grid]$ ./gridSetup.sh -silent -responseFile /tmp/empty.rsp
Launching Oracle Grid Infrastructure Setup Wizard...

[FATAL] [INS-10105] The given response file /tmp/empty.rsp is not valid.
   CAUSE: Syntactically incorrect response file. Either unexpected variables
          are specified or expected variables are not specified in the
          response file.
   ACTION: Refer the latest product specific response file template
   SUMMARY:
       - cvc-complex-type.2.4.b: The content of element 'properties' is not
         complete. One of '{oracle.install.responseFileVersion,
         oracle.install.option, SELECTED_LANGUAGES, ORACLE_HOSTNAME,
         INVENTORY_LOCATION, UNIX_GROUP_NAME, ORACLE_BASE, ORACLE_HOME,
         ... (기대되는 변수 목록이 90개 넘게 이어진다)
         oracle.install.crs.deleteNode.nodes}' is expected.

-- 원인 파악
--   응답 파일은 스키마로 검증된다. 빈 파일이라 필수 변수가 하나도 없어
--   XML 스키마 검증(cvc-complex-type)에 걸렸다.
--   SUMMARY 에 나열되는 목록이 이 버전에서 인식하는 변수 전체다.
--   오타가 있는 변수 이름을 넣어도 unexpected variables 로 같은 오류가 난다.
--   이 목록은 응답 파일을 작성할 때 참고 자료로도 쓸 수 있다.

-- 조치 — 템플릿에서 시작하고 절대 경로로 지정한다.
[grid@rac1 ~]$ cp /u01/app/19.3.0/grid/install/response/gridsetup.rsp /tmp/gridsetup.rsp
[grid@rac1 ~]$ chmod 600 /tmp/gridsetup.rsp
[grid@rac1 ~]$ rm -f /tmp/empty.rsp

-- 재확인 — 두 오류 모두 검증 단계에서 멈췄으므로 시스템은 무손상이다.
[grid@rac1 ~]$ crsctl check cluster -all | grep -c online
6
[oracle@rac1 ~]$ srvctl status database -d racdb
Instance racdb1 is running on node rac1
Instance racdb2 is running on node rac2

-- 배운 것
--   응답 파일 관련 오류는 INS-101xx 계열이며 파일 검증 단계에서 난다.
--   아무것도 설치되지 않으므로 되돌릴 것이 없다.
--   상대 경로가 지원되지 않는다는 점을 기억한다.
--   비밀번호가 들어가는 파일이므로 권한을 600 으로 두고 설치 후 shred 로 지운다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) 템플릿은 653줄, 주석 525줄, 실제 항목 64개
--   2) 설치 관리자가 사용한 응답 값을 사본으로 남긴다(비밀번호 제외)
--   3) 항목은 성격별로 열 묶음 정도로 정리된다
--   4) 형식이 낯선 것은 networkInterfaceList, disksWithFailureGroupNames, clusterNodes
--   5) 판단이 필요한 것은 redundancy, configureGIMR, executeRootScript 셋
--   6) 비밀번호 두 항목은 평문이며 600 권한과 설치 후 삭제가 원칙이다
--   7) 응답 파일 오류는 INS-101xx 계열이며 검증 단계에서 멈춘다
--   8) 상대 경로는 지원되지 않는다
--
-- 이 실습은 파일 조회와 임시 파일 생성뿐이며 임시 파일은 지웠다.
-- 오류 재현도 검증 단계에서 멈췄으므로 시스템은 무손상이다.
-- 클러스터 상태를 확인해 두 인스턴스가 running 인지 보고 종료한다.
