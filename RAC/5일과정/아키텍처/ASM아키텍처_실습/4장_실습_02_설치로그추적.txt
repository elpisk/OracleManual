--
-- 접두어만 보고 어느 도구의 로그인지 알 수 있다.
-- 2026-07-29 와 2026-08-12 의 InstallActions 는 원본 이미지를 만들 때
-- 단일 인스턴스 소프트웨어를 설치한 기록이다. 클론이라 그대로 남아 있다.

--------------------------------------------------------------------------------
 [2] 시도 이력 읽기
--------------------------------------------------------------------------------

[grid@rac1 ~]$ ls -dt /u01/app/oraInventory/logs/GridSetupActions*
/u01/app/oraInventory/logs/GridSetupActions2026-08-31_07-02-05PM
/u01/app/oraInventory/logs/GridSetupActions2026-08-31_06-58-56PM

[grid@rac1 ~]$ for d in /u01/app/oraInventory/logs/GridSetupActions*; do
>   echo "$d  $(du -sh $d | cut -f1)"
> done
/u01/app/oraInventory/logs/GridSetupActions2026-08-31_06-58-56PM  12M
/u01/app/oraInventory/logs/GridSetupActions2026-08-31_07-02-05PM  19M

-- 디렉터리가 둘이다. 시각을 보면 06:58:56 이 먼저이고 07:02:05 가 나중이다.
-- 3분 간격으로 두 번 실행했다는 뜻이며, 첫 번째가 실패해 재시도한 것이다.
--
-- 크기 차이도 단서가 된다. 12M 과 19M 이다. 실패한 시도는 도중에 멈추므로
-- 로그가 작다. 성공한 시도는 끝까지 진행해 더 크다.
--
-- ls -dt 는 최신 순으로 정렬하므로 맨 위가 마지막 시도다.
-- 실패 원인을 찾을 때는 그 아래, 즉 실패한 시도의 디렉터리를 본다.

 [3] 실패 원인 찾기
--------------------------------------------------------------------------------

[grid@rac1 ~]$ cd /u01/app/oraInventory/logs/GridSetupActions2026-08-31_06-58-56PM
[grid@rac1 GridSetupActions2026-08-31_06-58-56PM]$ ls
gridSetupActions2026-08-31_06-58-56PM.log
gridSetupActions2026-08-31_06-58-56PM.err

time2026-08-31_06-58-56PM.log

[grid@rac1 ...]$ grep -m3 -A3 'INS-13013' gridSetupActions2026-08-31_06-58-56PM.log
SEVERE:  [Aug 31, 2026 7:00:13 PM] [FATAL] [INS-13013] Target environment does
         not meet some mandatory requirements.
   CAUSE: Some of the mandatory prerequisites are not met. See logs for details.
   ACTION: Identify the list of failed prerequisite checks from the log.
          Then either from the log file or from installation manual find
          the appropriate configuration to meet the prerequisites and fix it
          manually.
INFO:  [Aug 31, 2026 7:00:13 PM] Advice is ABORT

-- 읽는 법
--   SEVERE 는 로그 수준이다. INFO, WARNING, SEVERE 순으로 심각하다.
--   대괄호 안의 시각이 실패 시점이다. 06:58:56 에 시작해 07:00:13 에 멈췄으니
--   1분 17초, 약 1.3분 만에 실패했다.
--   CAUSE 절이 로그 경로를 알려 주는데 지금 보고 있는 그 파일이다.
--   마지막 줄의 Advice is ABORT 가 설치 관리자의 최종 판단이다.

--------------------------------------------------------------------------------
 [4] 오류 재현 — 최신 디렉터리만 보고 판단하면
--------------------------------------------------------------------------------

-- 설치가 실패했다는 신고를 받고 습관적으로 가장 최근 디렉터리를 연다.

[grid@rac1 ~]$ D=$(ls -dt /u01/app/oraInventory/logs/GridSetupActions* | head -1)
[grid@rac1 ~]$ echo $D
/u01/app/oraInventory/logs/GridSetupActions2026-08-31_07-02-05PM

[grid@rac1 ~]$ grep -c 'INS-13013' $D/gridSetupActions*.log
0

[grid@rac1 ~]$ grep -c 'FATAL' $D/gridSetupActions*.log
0

-- 원인 파악
--   실패 흔적이 하나도 없다. 이 디렉터리는 성공한 재시도의 로그이기 때문이다.
--   실패는 그 앞의 시도에서 났고 로그도 그쪽에 있다.
--   최신 디렉터리만 보면 로그에 오류가 없다는 잘못된 결론에 이른다.

-- 조치 — 시각 순으로 전체를 나열하고 실패한 시도를 찾는다.
[grid@rac1 ~]$ for d in $(ls -dt /u01/app/oraInventory/logs/GridSetupActions*); do
>   n=$(grep -c 'FATAL' $d/gridSetupActions*.log 2>/dev/null)
>   printf '%-40s FATAL=%s\n' "$(basename $d)" "$n"
> done
GridSetupActions2026-08-31_07-02-05PM    FATAL=0
GridSetupActions2026-08-31_06-58-56PM    FATAL=1

-- 재확인
[grid@rac1 ~]$ grep -m1 'FATAL' /u01/app/oraInventory/logs/GridSetupActions2026-08-31_06-58-56PM/gridSetupActions*.log
SEVERE:  [Aug 31, 2026 7:00:13 PM] [FATAL] [INS-13013] Target environment does not meet some mandatory requirements.

-- 배운 것
--   설치를 여러 번 시도했다면 로그 디렉터리도 여러 개다.
--   최신 것이 성공한 시도일 수 있으므로 실패 원인은 그 앞에서 찾는다.
--   전체를 훑어 FATAL 이나 SEVERE 가 있는 디렉터리를 먼저 찾는 것이 빠르다.
--   디렉터리 크기도 단서가 된다. 도중에 멈춘 시도는 로그가 작다.

--------------------------------------------------------------------------------
 [5] root.sh 로그는 위치가 다르다
--------------------------------------------------------------------------------

[grid@rac1 ~]$ ls -lt /u01/app/19.3.0/grid/install/root_*.log
-rw-r--r--. 1 grid oinstall  294 Sep  1 15:01 root_rac1.localdomain_2026-09-01_15-01-34-311480080.log
-rw-------. 1 grid oinstall 3800 Aug 31 19:14 root_rac1.localdomain_2026-08-31_19-08-23-573156101.log

-- 인벤토리가 아니라 Grid 홈 아래 install 디렉터리에 남는다.
-- 이름은 root_<호스트>_<날짜>_<시각>.log 형식이며 실행할 때마다 새로 만들어진다.
--
-- 두 파일의 크기가 크게 다르다.
--   3800 바이트 (08-31 19:08)  실제 설치 때의 실행. 성공했다
--   294 바이트  (09-01 15:01)  실습 04 에서 grid 로 실행한 것. 거부됐다

[grid@rac1 ~]$ cat /u01/app/19.3.0/grid/install/root_rac1.localdomain_2026-09-01_15-01-34-311480080.log
You must be logged in as user with UID as zero (e.g. root user) to run root
configuration script.
Log in as user with UID as zero (e.g. root user) and restart root configuration
script execution.

-- 세 줄뿐이다. 계정 문제로 즉시 중단된 것이다.
-- 실제 실행이었다면 CRS-2672, CRS-2676 같은 자원 기동 메시지가 이어진다.
-- 로그 크기만 봐도 두 경우를 구분할 수 있다.

-- 어느 단계가 오래 걸렸는지 파악할 때 유용하다.
--
-- 로그 자체의 시각으로도 알 수 있다. 첫 줄과 마지막 줄의 타임스탬프 차이가
-- 전체 소요 시간이다. 실습 환경의 성공 시도는 6.0분이었다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) 설치 로그는 /u01/app/oraInventory/logs 아래
--   2) GridSetupActions 는 GI, InstallActions 는 DB 소프트웨어
--   3) 시도마다 디렉터리가 만들어지고 시각이 이름에 들어간다
--   4) 최신 디렉터리가 성공한 시도일 수 있으므로 전체를 훑는다
--   5) FATAL 개수와 디렉터리 크기가 실패 여부의 단서다
--   6) root.sh 로그는 Grid 홈 아래 install 디렉터리에 있다
--   7) time<시각>.log 가 단계별 소요 시간을 담는다
--
-- 이 실습은 조회만 했으므로 원상 복구할 것이 없다.
