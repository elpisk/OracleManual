--------------------------------------------------------------------------------
 [2] 이름 해석의 두 조건
--------------------------------------------------------------------------------

-- cluvfy 의 요구는 두 가지를 동시에 만족하는 것이다.
--   조건 1 : /etc/resolv.conf 에 네임서버가 지정되어 있을 것
--   조건 2 : 그 네임서버가 클러스터 노드 이름을 풀 수 있을 것
--
-- 이 실습 환경은 구축 과정에서 두 번 막혔다.
--
--   첫 시도 — resolv.conf 를 비웠다
--     PRVG-2064 : There are no configured name servers in the file
--                 "/etc/resolv.conf"
--     조건 1 실패. hosts 로 이름은 풀리지만 네임서버가 없다.
--
--   두 번째 시도 — NAT 게이트웨이의 DNS 를 넣었다
--     PRVG-10048 : Name "rac1" was not resolved to an address of the
--                  specified type
--     PRVF-5636 : The DNS response time for an unreachable node exceeded
--                 "15000" ms
--     조건 2 실패. 네임서버는 있지만 rac1 을 모른다.

--------------------------------------------------------------------------------
 [3] dnsmasq 구성 확인
--------------------------------------------------------------------------------

[root@rac1 ~]# cat /etc/dnsmasq.conf
# RAC 랩 — /etc/hosts 를 DNS 로 서비스한다.
domain-needed
bogus-priv
local=/localdomain/
domain=localdomain
expand-hosts
listen-address=127.0.0.1
bind-interfaces
no-resolv

[root@rac1 ~]# systemctl is-active dnsmasq
active

[root@rac1 ~]# cat /etc/resolv.conf
search localdomain
nameserver 127.0.0.1

[root@rac1 ~]# lsattr /etc/resolv.conf
----i----------- /etc/resolv.conf

-- 설정 항목마다 이유가 있다.
--   expand-hosts        hosts 의 짧은 이름에 domain 을 붙여 FQDN 으로도 응답
--   domain=localdomain  붙일 도메인 이름
--   local=/localdomain/ 이 도메인은 상위로 넘기지 않고 직접 답한다
--   no-resolv           resolv.conf 를 상위 DNS 목록으로 읽지 않는다
--   listen-address      로컬에서만 응답. 외부에 DNS 를 노출하지 않는다
--
-- no-resolv 를 빠뜨리면 무한 참조가 된다. resolv.conf 가 127.0.0.1 을
-- 가리키므로 dnsmasq 가 자기 자신을 상위 DNS 로 삼게 된다.
--
-- lsattr 의 i 플래그는 chattr +i 로 건 것이다. NetworkManager 가 재부팅 때
-- resolv.conf 를 되돌리지 못하게 한다. 수정이 필요하면 chattr -i 로 잠시 푼다.

--------------------------------------------------------------------------------
 [4] 정방향 해석 — 일곱 이름 모두
--------------------------------------------------------------------------------

[root@rac1 ~]# for h in rac1 rac2 rac1-vip rac2-vip rac1-priv rac2-priv rac-scan; do
>   printf '  %-12s ' $h
>   nslookup $h 2>/dev/null | awk '/^Address: /{print $2}' | tail -1
> done
  rac1         172.16.225.101
  rac2         172.16.225.102
  rac1-vip     172.16.225.111
  rac2-vip     172.16.225.112
  rac1-priv    172.16.119.101
  rac2-priv    172.16.119.102
  rac-scan     172.16.225.120

-- FQDN 으로도 되는지 확인한다. expand-hosts 가 동작하는지 보는 것이다.
[root@rac1 ~]# nslookup rac-scan.localdomain | tail -3

Name:   rac-scan.localdomain
Address: 172.16.225.120

--------------------------------------------------------------------------------
 [5] 역방향 해석
--------------------------------------------------------------------------------

[root@rac1 ~]# nslookup 172.16.225.120
120.225.16.172.in-addr.arpa     name = rac-scan.localdomain.

-- hosts 파일만으로 정방향과 역방향이 모두 갖춰졌다.
-- dnsmasq 가 hosts 를 읽어 양쪽 영역을 자동으로 만들어 주기 때문이다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — 등록되지 않은 이름
--------------------------------------------------------------------------------

[root@rac1 ~]# nslookup rac9

Non-authoritative answer:
*** Can't find rac9: No answer

[root@rac1 ~]# grep -c rac9 /etc/hosts
0

-- 원인 파악
--   rac9 는 /etc/hosts 에 없다. dnsmasq 가 hosts 를 근거로 답하므로
--   없는 이름은 답할 수 없다.
--   local=/localdomain/ 설정 때문에 이 도메인 질의를 상위로 넘기지 않아
--   NXDOMAIN 이 아니라 No answer 로 나온다.
--
--   이 상태로 cluvfy 에 rac9 를 넘기면 앞 실습에서 본 오류가 난다.
--     PRVF-4083 → PRKN-1034 → unknown host exception

-- 조치 — 실제 노드를 추가한다면 세 곳을 모두 갱신한다.
--   1) 모든 노드의 /etc/hosts 에 새 이름과 주소를 추가
--   2) dnsmasq 재시작 (hosts 를 다시 읽게 한다)
--   3) 조직 DNS 를 쓴다면 그쪽에도 등록
[root@rac1 ~]# systemctl restart dnsmasq

-- 재확인
[root@rac1 ~]# nslookup rac2 | tail -3

Name:   rac2.localdomain
Address: 172.16.225.102

-- 배운 것
--   dnsmasq 는 /etc/hosts 를 읽어 응답한다. hosts 를 고쳤으면 재시작해야
--   반영된다. 그리고 두 노드의 hosts 를 함께 고쳐야 한다. 한쪽만 고치면
--   그 노드에서만 이름이 풀려 간헐적으로 보이는 문제가 된다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) 2노드에 필요한 이름은 일곱이며 FQDN 과 짧은 이름을 함께 등록한다
--   2) 두 노드의 hosts 는 diff 로 대조한다
--   3) 이름 해석은 네임서버 존재와 이름 해석 가능이라는 두 조건을 함께 만족해야 한다
--   4) dnsmasq 의 expand-hosts 와 no-resolv 가 핵심 설정이다
--   5) chattr +i 로 resolv.conf 를 고정한다
--   6) 정방향 일곱 개와 SCAN 역방향이 모두 되어야 한다
--   7) PRVG-11368 은 경고이며 판단과 이유를 기록한다
--
-- 이 실습은 조회와 dnsmasq 재시작만 했다. 재시작은 구성을 바꾸지 않으므로
-- 원상 복구할 것이 없다.
