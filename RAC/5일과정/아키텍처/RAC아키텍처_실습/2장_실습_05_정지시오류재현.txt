 제2장 실습 05 — 정지 시 오류 재현
 대상   : rac1(정상 유지) / rac2(정지 대상)
 목표   : crsctl stop cluster 와 crsctl stop crs 를 차례로 실행해 두 스택의
          차이를 눈으로 확인하고, CRS-4639 · CRS-4535 · PRKH 계열 오류가
          각각 어느 계층을 가리키는지 판별한다
 소요   : 약 40분
 선행   : 두 노드 모두 정상. 다른 실습을 병행하지 않을 것
 계정   : root(Grid 홈 전체 경로 사용), grid, oracle
 주의   : rac2 의 Clusterware 를 정지한다. rac1 은 건드리지 않는다.
          반드시 마지막에 복구를 확인한다.

 [6] 오류 재현 — 스택 전체가 내려간 상태
--------------------------------------------------------------------------------

[root@rac2 ~]# $GB/crsctl check has
CRS-4639: Could not contact Oracle High Availability Services

[root@rac2 ~]# $GB/crsctl check crs
CRS-4639: Could not contact Oracle High Availability Services

[root@rac2 ~]# $GB/crsctl status resource -t -init
CRS-4639: Could not contact Oracle High Availability Services
CRS-4000: Command Status failed, or completed with errors.

[root@rac2 ~]# su - oracle -c 'srvctl status database -d racdb'
PRKH-1010 : Unable to communicate with CRS services.
PRKH-3003 : An attempt to communicate with the CSS daemon failed

[root@rac2 ~]# su - grid -c 'olsnodes -s'
PRCO-19: Failure retrieving list of nodes in the cluster
PRCO-2: Unable to communicate with the clusterware

-- 원인 파악
--   [3]과 결정적으로 다른 점은 check has 다. 그때는 CRS-4638 online 이었는데
--   지금은 CRS-4639 다. ohasd 자체가 죽었다는 뜻이다.
--   그래서 -init 조회마저 실패한다. 물어볼 상대가 없기 때문이다.
--
--   오류 코드 대응표
--     명령                             stop cluster 후    stop crs 후
--     crsctl check has                 CRS-4638 online    CRS-4639
--     crsctl check crs                 4638 + 4535/4530/4534   CRS-4639
--     crsctl status resource -t -init  정상 조회          CRS-4639
--     crsctl status resource -t        CRS-4535           CRS-4535
--     srvctl status database           PRKH-1010/3003     PRKH-1010/3003
--     olsnodes -s                      PRCO-19/PRCO-2     PRCO-19/PRCO-2
--
--   판별 요령
--     CRS-4639 가 보이면 ohasd 부터 살린다 → crsctl start has
--     CRS-4638 은 나오는데 CRS-4535 가 뒤따르면 crsd 이하만 문제다
--       → crsctl start cluster

-- 조치
[root@rac2 ~]# $GB/crsctl start has
CRS-4123: Oracle High Availability Services has been started.

-- 재확인 — 40초 뒤
[root@rac2 ~]# $GB/crsctl check crs
CRS-4638: Oracle High Availability Services is online
CRS-4537: Cluster Ready Services is online
CRS-4529: Cluster Synchronization Services is online
CRS-4533: Event Manager is online

 [9] 정리
--------------------------------------------------------------------------------

-- 두 명령의 차이 (실측)
--   항목                stop cluster        stop crs
--   정지 범위           CRS 계층            노드 스택 전체
--   ohasd               남는다              종료된다
--   check has           CRS-4638 online     CRS-4639
--   -init 조회          가능                불가
--   출력 마지막         CRS-2792            CRS-2792→2793→4133
--   소요                0.5분               2.6분
--   복구 명령           start cluster       start has
--
-- 오류 코드가 가리키는 계층
--   CRS-4639  ohasd 에 닿지 못함 (스택 전체)
--   CRS-4535  crsd 에 닿지 못함
--   CRS-4530  ocssd 에 닿지 못함
--   CRS-4534  evmd 에 닿지 못함
--   PRKH-1010 / PRKH-3003  srvctl 이 CSS 와 통신 실패
--   PRCO-19 / PRCO-2       olsnodes 가 클러스터와 통신 실패
--
-- 원상 복구 점검 순서 (반드시 수행)
--   1) crsctl check cluster -all — 두 노드 모두 세 줄 online
--   2) olsnodes -s -n — 두 노드 모두 Active
--   3) srvctl status database -d racdb -v — 두 인스턴스 Open (1~2분 대기)
--   4) GV$INSTANCE 2행, GV$PDBS 양쪽 READ WRITE
--   5) 자원 배치 비교 — 필요하면 srvctl relocate
--
-- 복구되지 않으면 rac-base 스냅샷으로 되돌린다. 다만 스냅샷은 OS 디스크만
-- 덮으므로 ASM 안의 데이터베이스는 되돌아가지 않는다는 점을 감안한다.
