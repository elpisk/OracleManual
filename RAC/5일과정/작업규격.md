# Oracle 19c RAC 5일 과정 교안 작업 규격

기존 RAC 20장 교안(`RAC/NN장/`)을 5일(40시간) 과정용 17장으로 다시 쓴다. 설치 내용은 빼고,
실습 환경과 경로는 `RAC/RAC_Install_Guide_rac1_rac2_v2.docx`(설치 가이드 v2)를 그대로 따른다.
교안에는 일차(Day 1~5)를 쓰지 않는다. 일정은 `RAC/_기획/RAC_과정구성_5일.md` 에만 둔다.

## 1. 산출물

작업 폴더 `RAC/5일과정/NN장/` (NN = 두 자리)

| 파일 | 규격 |
|---|---|
| `본문.mk` → `{N}장_{제목}.docx` | 14,000~22,000자. 그림 4개 이상. 학습 목표 → 본문 절 → 요약 → 퀴즈 6문항 → 실습 개요 |
| `슬라이드.mk` → `{N}장_{제목}.pptx` | 28~45장. 그림 슬라이드 4장 이상. 타이틀·학습 목표·Agenda·섹션·요약·퀴즈·실습 개요 외 모든 슬라이드에 노트 200~500자 |
| `../img_src/NN_이름.svg` → `../img/NN_이름.png` | 장마다 4~6개. docx 와 pptx 가 같은 PNG 를 쓴다 |

빌드와 검사 (`RAC/5일과정` 에서):

```
python3 tools/render.py
python3 tools/docbuild.py NN장/본문.mk tools/template.docx NN장/{N}장_{제목}.docx
python3 tools/pptbuild.py NN장/슬라이드.mk NN장/{N}장_{제목}.pptx
python3 tools/verify.py NN
```

### 2-1. 빼는 것 (설치 내용)

- VM 생성, OS 설치, 공유 디스크 생성, udev 규칙 작성, SSH 등가성, `runcluvfy`/`cluvfy stage -pre crsinst`,
  `gridSetup.sh`, `root.sh` 실행 절차, `runInstaller`, `dbca -createDatabase`, 응답 파일 작성.
- 설치 결과로 생긴 것을 **읽고 확인하는 것**은 남긴다: `oifcfg getif`, `srvctl config scan`, Grid 홈 구조, `/etc/oratab`, `srvctl config database`, 스레드·UNDO 구성 조회.
- 설치를 언급해야 할 때는 "설치 가이드 v2 의 6장(Grid Infrastructure 설치)" 처럼 한 줄로 가리키고 넘어간다.

### 2-2. 13장 보강 범위

기존 16장은 FAN·부하 분산 권고·AC 를 다뤘다. 13장은 여기에 클라이언트 페일오버 전체 그림을 더한다.

- Connect-Time Failover — `ADDRESS_LIST`, `FAILOVER=on`, `LOAD_BALANCE=on`, SCAN 이름이 IP 3개(이 랩은 1개)로 풀리는 구조, `CONNECT_TIMEOUT`·`RETRY_COUNT`·`TRANSPORT_CONNECT_TIMEOUT`
- TAF — 클라이언트 `FAILOVER_MODE=(TYPE=SESSION|SELECT)(METHOD=BASIC|PRECONNECT)` 와 서버 쪽 `srvctl -failovertype SESSION|SELECT -failovermethod BASIC`, 서버 설정이 우선하는 규칙, `V$SESSION.FAILOVER_TYPE/METHOD/FAILED_OVER`, 진행 중 트랜잭션은 롤백된다는 한계
- FAN 과 FCF — ONS(로컬 6100, 원격 6200), FAN 이벤트(UP/DOWN/관리 이벤트), FAN 을 받는 풀(UCP, ODP.NET, OCI 세션 풀)이 끊긴 연결을 즉시 정리하는 FCF
- AC 와 TAC — `-failovertype TRANSACTION -commit_outcome TRUE`(Transaction Guard), 19c TAC 는 `-failovertype AUTO -failover_restore AUTO`, 재생 조건과 재생되지 않는 것
- 비교표 하나: 감지 주체 / 무엇이 이어지는가 / 진행 중 트랜잭션 / 필요한 클라이언트

TAF·FCF·TAC 는 기존 트랜스크립트에 실측이 없다. 본문은 개념과 구성 문법까지만 쓰고 출력 예시를 지어내지 않는다.

## 4. 마크업

본문(`docbuild.py`): `@H1 @H2 @H3 @P @B @BOLD @CODE…@END @TBL…@END @NOTE 제목…@END @BP 제목…@END @CASE 제목…@END @QUIZ 제목…@END @IMG 파일.png | 그림 N-M. 설명`

- `@H1 제N장  제목` 하나. 절은 `@H2 N.M  제목`, 소절은 `@H3 N.M.K  제목`
- 표는 첫 줄이 머리글, 칸 구분자 `|`. 인라인 `` `코드` `` 와 `**굵게**` 를 쓸 수 있다(굵게는 경고·표 머리 외에는 쓰지 않는다)
- 그림 캡션은 `그림 N-M. …` 형식으로 장 안에서 번호를 매긴다

슬라이드(`pptbuild.py`): `@TITLE Oracle Database 19c RAC 과정|주제|부제|제N장`, `@PLAIN 제목`, `@SEC 번호|제목`, `@SLIDE 제목|캡션`, `@IMG 파일.png|제목|캡션`, `@NOTE 노트`, `- 불릿`

- 순서: TITLE → PLAIN 학습 목표 → PLAIN Agenda → (SEC → SLIDE/IMG …) 반복 → PLAIN 요약 → PLAIN 퀴즈 → PLAIN 실습 개요
- 불릿은 슬라이드당 3~6개, 한 줄 40자 안팎. PPT 에는 백틱·별표를 쓰지 않는다

## 5. 그림

SVG 를 손으로 쓰고 `tools/render.py` 로 PNG 를 만든다. 개념을 보여 주는 구조도·흐름도·비교도를 그린다. 화면 캡처나 출력 텍스트를 그림으로 만들지 않는다.

- 파일명 `NN_영문소문자.svg` (예: `06_rebalance.svg`). 장 번호 접두어 필수
- 크기 `viewBox="0 0 1600 900"` (16:9). 세로로 긴 그림이 꼭 필요하면 `1600 1000` 까지
- 글꼴 `font-family="Pretendard, sans-serif"`, 명령·경로는 `font-family="JetBrains Mono, monospace"`. 글자 크기 최소 22px(제목 34~40px)
- 배경 흰색. 색은 아래 팔레트만 쓴다

| 용도 | 색 |
|---|---|
| 강조(제목 띠, 핵심 화살표, 경고) | `#C0392B` |
| 노드·서버 상자 | 테두리 `#34495E`, 채움 `#ECF0F1` |
| 스토리지·ASM | 테두리 `#2471A3`, 채움 `#D6EAF8` |
| 네트워크(공용) | `#1E8449` / (사설) `#B9770E` |
| 정상 상태 | `#27AE60`, 비정상 `#C0392B`, 보조 글자 `#5D6D7E` |
| 본문 글자 | `#212F3D` |

- 상자는 `rx="12"` 둥근 사각형, 선 굵기 3. 화살표는 `<marker>` 로 정의해 쓴다
- 한 그림에 상자 12개, 글자 줄 25개를 넘기지 않는다. 그림 안 글자는 한국어로 쓰고 Oracle 고유 명칭(OCR, SCAN, ASM, Cache Fusion 등)은 영문 그대로
- 다 그린 뒤 PNG 를 열어(Read 도구) 글자 겹침·잘림이 없는지 눈으로 확인한다

## 6. 문체 (SECURITY 작업규격 4절과 같다)

- 본문은 개조식(`@B`)과 평서체(`~다`). 절 도입 `@P` 1~2문장. 독자를 부르지 않는다
- 금지: 재진술 맺음("~것이 핵심이다", "~라는 뜻이다"), 볼드 라벨 남발, "A가 아니라 B다" 대조 공식 장당 5회 이내, 줄표 장당 10회 이내, "결국/즉/바로" 연속, 메타 표현("~라는 점", "~를 기억해 두자"), 근거 없는 수식어, 매 절 끝 예고 불릿, "실측/우리 환경/여러분"
- 본문 설명은 개념 중심. 트랜스크립트의 출력은 `@CODE` 로 짧게 인용할 수 있지만(10줄 이내), 숫자를 일반 법칙처럼 쓰지 않는다
- DB 테이블은 "테이블", 일반 표는 "표"
- 노트: 강사가 그대로 읽을 수 있는 설명 말투(~습니다), 200~500자, "이 슬라이드는~" 으로 시작하지 않는다
- 퀴즈 6문항: `@QUIZ 퀴즈` 안에 문항, 정답과 해설은 바로 뒤 `@NOTE 정답과 해설` 에
