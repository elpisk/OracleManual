================================================================================
 제14장 실습 04 — 오류 재현, crsctl 로 DB 자원을 직접 정지하면
 대상   : rac1
 목표   : 도구 경계를 넘는 시도를 여러 각도로 해 보고 오라클이 무엇을 막고
          무엇을 허용하는지 확인한다
 소요   : 약 20분
 선행   : 실습 03 완료
 계정   : oracle, grid
 주의   : 이 실습의 명령은 모두 거부되거나 조회뿐이다. DB 에 영향이 없다
================================================================================

--------------------------------------------------------------------------------
 [0] 시작 전 상태
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -t
--------------------------------------------------------------------------------
Name           Target  State        Server                   State details
--------------------------------------------------------------------------------
Cluster Resources
--------------------------------------------------------------------------------
ora.racdb.db
      1        ONLINE  ONLINE       rac1                     Open,HOME=/u01/app/...
      2        ONLINE  ONLINE       rac2                     Open,HOME=/u01/app/...
--------------------------------------------------------------------------------

-- 이 상태가 실습 끝까지 유지되어야 한다.

--------------------------------------------------------------------------------
 [1] 오류 재현 — 정지 시도
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl stop resource ora.racdb.db
CRS-4995:  The command 'Stop  resource' is invalid in crsctl. Use srvctl for this command.

[grid@rac1 ~]$ echo $?
1

-- 원인 파악 : 데이터베이스는 오라클 제품 자원이며 srvctl 의 관할이다.
--             crsctl 은 자원 모델을 다루는 일반 도구라 데이터베이스를
--             어떻게 내려야 하는지 모른다.
--             세션 정리와 체크포인트를 건너뛰면 12장에서 확인한
--             정상 종료와 비정상 종료의 구분이 무너진다.
-- 조치     : srvctl stop instance -d racdb -i racdb1 을 쓴다.
--             메시지가 무엇을 써야 하는지까지 알려 주므로 따라가면 된다.
-- 재확인   : 데이터베이스 상태가 그대로인지 본다. 거부되었으므로
--             바뀐 것이 없어야 한다.

[grid@rac1 ~]$ crsctl stat res ora.racdb.db | egrep 'TARGET|STATE'
TARGET=ONLINE       , ONLINE
STATE=ONLINE on rac1, ONLINE on rac2

-- 변화 없음. 시도 자체가 차단되었으므로 부작용도 없다.

--------------------------------------------------------------------------------
 [2] 기동 시도도 같은가
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl start resource ora.racdb.db
CRS-4995:  The command 'Start  resource' is invalid in crsctl. Use srvctl for this command.

[grid@rac1 ~]$ echo $?
1

-- 메시지의 명령 이름만 'Start resource' 로 바뀌었다.
-- 상태를 바꾸는 명령은 방향과 무관하게 모두 막힌다.

--------------------------------------------------------------------------------
 [3] 그러면 무엇이 허용되는가
--------------------------------------------------------------------------------

[grid@rac1 ~]$ crsctl stat res ora.racdb.db -p | egrep '^NAME=|^TYPE=|^AUTO_START|^CARDINALITY|^CHECK_INTERVAL|^RESTART_ATTEMPTS|^UPTIME_THRESHOLD'
NAME=ora.racdb.db
TYPE=ora.database.type
AUTO_START=restore
CARDINALITY=2
CHECK_INTERVAL=900
RESTART_ATTEMPTS=2
UPTIME_THRESHOLD=1h

[grid@rac1 ~]$ echo $?
0

-- 조회는 잘 된다. 종료 코드도 0 이다.
--
-- 정리하면 이렇다.
--   읽기 (stat res, stat res -p)        → 허용
--   쓰기 (start, stop, relocate)        → CRS-4995 로 거부
--
-- 자원 정의는 OCR 에 있고 crsctl 은 OCR 을 읽는 도구다.
-- 읽는 것은 자연스럽고, 제품 지식이 필요한 동작만 막았다.

--------------------------------------------------------------------------------
 [4] 반대 방향 — srvctl 로 사용자 자원을 다루려 하면
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status resource
Usage: srvctl <command> <object> [<options>]
    commands: enable|disable|export|import|start|stop|relocate|status|add|remove|
              modify|getenv|setenv|unsetenv|config|convert|update|upgrade|
              downgrade|predict
    objects: database|instance|service|nodeapps|vip|network|asm|diskgroup|
             listener|scan|scan_listener|srvpool|server|filesystem|cvu|cha|
             ons|volume|mgmtdb| ... (총 40여 개)

-- resource 라는 대상이 없으므로 사용법만 출력된다.
-- CRS-4995 같은 친절한 안내가 없다.
--
-- 즉 안내는 한 방향으로만 있다.
--   crsctl 로 오라클 자원을 다루려 하면  → srvctl 을 쓰라고 알려 준다
--   srvctl 로 사용자 자원을 다루려 하면  → 그저 대상을 모른다고 한다
--
-- 그래서 헷갈릴 때는 srvctl 을 먼저 시도하는 것이 요령이고,
-- 사용자 자원은 처음부터 crsctl 로 다룬다고 기억해 두는 편이 낫다.

--------------------------------------------------------------------------------
 [5] 오류 재현 — srvctl 쪽의 오류들
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -d nodb
PRCD-1120 : The resource for database nodb could not be found.
PRCR-1001 : Resource ora.nodb.db does not exist

[oracle@rac1 ~]$ srvctl status instance -d racdb -i racdb9
PRKO-3032 : Invalid instance name(s): racdb9

[oracle@rac1 ~]$ srvctl start instance -d racdb -i racdb1
PRCC-1015 : racdb was already running on rac1
PRCR-1004 : Resource ora.racdb.db is already running

-- 세 가지가 각각 다른 계층에서 나왔다.
--
--   PRCD-1120 + PRCR-1001  데이터베이스 계층과 자원 계층.
--                          진짜 원인은 아래 줄에 있다.
--   PRKO-3032              명령행 해석 계층. 인스턴스 이름 자체가 틀렸다.
--   PRCC-1015 + PRCR-1004  공통 계층과 자원 계층.
--                          오류처럼 보이지만 원하는 결과다.
--
-- 마지막 것은 특히 주의한다. 스크립트에서 이것을 실패로 처리하면
-- 기동 스크립트를 두 번 돌렸을 때 두 번째부터 뒷단계가 통째로 건너뛰어진다.
-- 기동·정지 스크립트는 멱등해야 하며, 종료 코드만 보지 말고
-- 먼저 srvctl status 로 상태를 확인하는 것이 깔끔한 방법이다.

--------------------------------------------------------------------------------
 [6] 최종 확인
--------------------------------------------------------------------------------

[oracle@rac1 ~]$ srvctl status database -d racdb -v
Instance racdb1 is running on node rac1. Instance status: Open.
Instance racdb2 is running on node rac2. Instance status: Open.

[grid@rac1 ~]$ crsctl stat res | grep -c '^NAME='
17

-- 데이터베이스도 자원 개수도 그대로다.
-- 이 실습은 거부된 명령과 조회뿐이었으므로 당연한 결과다.
