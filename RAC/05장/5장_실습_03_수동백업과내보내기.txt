 [1] 권한 가드 — 읽기와 쓰기의 경계
--------------------------------------------------------------------------------

[grid@rac1 ~]$ ocrconfig -showbackup
PROT-24: Auto backups for the Oracle Cluster Registry are not available
PROT-25: Manual backups for the Oracle Cluster Registry are not available

-- 읽기는 grid 로도 된다. 상태 조회이므로 허용된다.

[grid@rac1 ~]$ ocrconfig -manualbackup
PROT-20: Insufficient permission to proceed. Require privileged user

[grid@rac1 ~]$ ocrconfig -export /tmp/g.dmp
PROT-20: Insufficient permission to proceed. Require privileged user

-- 오류 : PROT-20
-- 원인 파악 : 백업 생성은 OCR 을 읽어 새 파일을 만드는 쓰기 작업이다.
--             OCR 은 Clusterware 의 구성 그 자체이므로 변경 계열 명령의
--             권한을 root 로 좁혀 두었다.
-- 조치     : root 로 실행한다. 자동화 스크립트를 만들 때 이 점이 중요하다.
--             grid 계정의 cron 에 넣으면 매번 PROT-20 으로 실패한다.
--             root 의 cron 이거나 sudo 를 거쳐야 한다.
-- 재확인   : 실패한 명령이 파일을 남기지 않았는지 본다.

[grid@rac1 ~]$ ls -l /tmp/g.dmp
ls: cannot access /tmp/g.dmp: No such file or directory

 [2] 수동 백업 — 출력 한 줄을 정확히 읽는다
--------------------------------------------------------------------------------

[root@rac1 ~]# ocrconfig -manualbackup

rac2  2026/09/01 16:09:24  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_160924.ocr.258.1242835765  724960844

-- 이 한 줄에 세 가지 사실이 들어 있다.
--
-- (1) 위치가 +CRS 디스크그룹 안이다
--     파일시스템이 아니다. 실습 02 에서 cdata 아래를 뒤졌지만 없었던 이유다.
--     12c 이후 OCR 백업의 기본 위치는 ASM 이다.
--
-- (2) 파일명 끝에 .258.1242835765 가 붙었다
--     ASM 파일 번호(258)와 incarnation(1242835765)이다. ASM 안의 정규
--     파일로 저장되었다는 뜻이다.
--
-- (3) 맨 앞의 노드 이름이 rac2 다
--     명령은 rac1 에서 실행했다. 그런데 rac2 가 찍혔다.
--
-- (3)이 처음 보면 오류처럼 보인다. 오류가 아니다. OCR 백업은 명령을 받은
-- 노드가 아니라 OCR 마스터 노드가 수행한다. crsd 중 하나가 마스터 역할을
-- 맡고, OCR 변경 요청은 그쪽으로 넘겨 직렬화한다. 어느 노드에서 명령해도
-- 결과는 같다.

-- 백업 목록을 다시 확인한다.
[root@rac1 ~]# ocrconfig -showbackup
PROT-24: Auto backups for the Oracle Cluster Registry are not available

rac2  2026/09/01 16:09:24  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_160924.ocr.258.1242835765  724960844

-- PROT-25 가 사라졌다. 수동 백업이 생겼기 때문이다.
-- PROT-24 는 여전히 남아 있다. 자동 백업은 아직 없다.

-- rac2 에서 조회해도 같은 목록이 보인다.
[root@rac2 ~]# ocrconfig -showbackup
PROT-24: Auto backups for the Oracle Cluster Registry are not available

rac2  2026/09/01 16:09:24  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_160924.ocr.258.1242835765  724960844

-- OCR 백업 목록은 클러스터 공용이다. 실습 02 에서 본 OLR 백업 목록과 대비된다.

--------------------------------------------------------------------------------
 [3] 백업 위치를 바꿔 본다 — 오류 재현
--------------------------------------------------------------------------------

-- 백업을 로컬 디렉터리에 두고 싶다고 하자. 디렉터리를 만들고 소유자까지
-- 맞춘다.

[root@rac1 ~]# mkdir -p /u01/app/grid/ocrbackup
[root@rac1 ~]# chown grid:oinstall /u01/app/grid/ocrbackup
[root@rac1 ~]# ls -ld /u01/app/grid/ocrbackup
drwxr-xr-x. 2 grid oinstall 6 Sep  1 16:17 /u01/app/grid/ocrbackup

[root@rac1 ~]# ocrconfig -backuploc /u01/app/grid/ocrbackup
PROT-42: The specified location '/u01/app/grid/ocrbackup' designates an invalid
         storage type for Oracle Cluster Registry backup files.

-- 오류 : PROT-42
-- 원인 파악 : 핵심 어구는 designates an invalid storage type 이다. 권한이나
--             소유자 문제가 아니라 저장소 종류가 잘못되었다는 뜻이다.
--             /u01 은 각 노드의 로컬 디스크다. rac1 에만 백업이 쌓이면
--             rac1 이 통째로 사라졌을 때 백업도 함께 사라진다. 백업의 목적
--             자체를 달성할 수 없으므로 Clusterware 가 아예 막는다.
--             여기서 chmod 나 chown 을 반복하면 시간만 낭비한다.
-- 조치     : ASM 디스크그룹, ACFS, 공유 NFS 중 하나를 지정한다.
--             로컬에 사본이 필요하면 -manualbackup 이 아니라 -export 를 쓴다.
-- 재확인   : 설정이 바뀌지 않았는지 확인한다.

[root@rac1 ~]# ocrconfig -manualbackup

rac2  2026/09/01 16:17:06  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_161706.ocr.259.1242836227  724960844
rac2  2026/09/01 16:09:24  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_160924.ocr.258.1242835765  724960844

-- 여전히 +CRS 에 만들어졌다. 실패한 -backuploc 이 설정을 바꾸지 않았다.

[root@rac1 ~]# ls -la /u01/app/grid/ocrbackup/
total 4
drwxr-xr-x. 2 grid oinstall    6 Sep  1 16:17 .
drwxrwxr-x. 9 grid oinstall 4096 Sep  1 16:17 ..

-- 만들어 둔 디렉터리는 비어 있다.

-- 유효한 값으로 명시 설정해 본다.
[root@rac1 ~]# ocrconfig -backuploc +CRS
[root@rac1 ~]# ocrconfig -manualbackup

rac2  2026/09/01 16:17:13  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_161713.ocr.260.1242836233  724960844
rac2  2026/09/01 16:17:06  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_161706.ocr.259.1242836227  724960844
rac2  2026/09/01 16:09:24  +CRS:/rac-cluster/OCRBACKUP/backup_20260901_160924.ocr.258.1242835765  724960844

-- 세 벌이 쌓였다. 최신순으로 정렬된다.

-- 만들어 둔 빈 디렉터리는 지운다.
[root@rac1 ~]# rmdir /u01/app/grid/ocrbackup

--------------------------------------------------------------------------------
 [4] ASM 안의 백업 파일 실체
--------------------------------------------------------------------------------

[grid@rac1 ~]$ asmcmd ls -l +CRS/rac-cluster/OCRBACKUP
Type       Redund  Striped  Time             Sys  Name
OCRBACKUP  MIRROR  COARSE   SEP 01 16:00:00  Y    backup_20260901_160924.ocr.258.1242835765
OCRBACKUP  MIRROR  COARSE   SEP 01 16:00:00  Y    backup_20260901_161706.ocr.259.1242836227
OCRBACKUP  MIRROR  COARSE   SEP 01 16:00:00  Y    backup_20260901_161713.ocr.260.1242836233

-- 읽어야 할 컬럼이 둘이다.
--
--   Type    OCRBACKUP   ASM 이 파일 종류를 알고 있다. 일반 데이터 파일이
--                       아니라 OCR 백업 전용 종류다
--   Redund  MIRROR      두 벌로 미러링되어 있다
--
-- MIRROR 인 이유는 +CRS 가 Normal 중복도이기 때문이다. 백업 파일 자체가
-- 이미 디스크 한 장 손실을 견딘다.
--
-- Redund 컬럼은 세 값을 갖는다.
--   UNPROT  보호 없음 (External 디스크그룹)
--   MIRROR  두 벌     (Normal)
--   HIGH    세 벌     (High)

-- 같은 디렉터리의 다른 항목도 본다.
[grid@rac1 ~]$ asmcmd ls +CRS/rac-cluster/
ASMPARAMETERFILE/
OCRBACKUP/
OCRFILE/

-- OCRFILE 이 OCR 본체, OCRBACKUP 이 백업, ASMPARAMETERFILE 이 ASM SPFILE 이다.
-- Voting File 은 여기에 없다. 실습 01 에서 확인한 그대로다.

--------------------------------------------------------------------------------
 [5] 논리적 내보내기 — export
--------------------------------------------------------------------------------

[root@rac1 ~]# ocrconfig -export /root/ocr_ch5.dmp
PROT-58: successfully exported the Oracle Cluster Registry contents to file
         '/root/ocr_ch5.dmp'

-- PROT-58 은 성공 메시지다. PROT- 로 시작한다고 모두 오류가 아니다.

[root@rac1 ~]# ls -la /root/ocr_ch5.dmp
-rw-------. 1 root root 208896 Sep  1 16:09 /root/ocr_ch5.dmp

[root@rac1 ~]# file /root/ocr_ch5.dmp
/root/ocr_ch5.dmp: data

-- 208,896바이트, 약 204KB 다. 물리적 백업이 OCR 저장 공간 전체
-- 491,684KB(약 480MB)를 뜨는 데 반해 export 는 실제로 존재하는 키만
-- 직렬화한다. 그래서 2000배 이상 작다.
--
-- 그리고 저장 위치가 /root 다. 로컬 파일시스템에 만들어졌다.
-- PROT-42 의 저장 위치 제약은 -backuploc 설정에만 적용되고 -export 에는
-- 적용되지 않는다.
--
-- file 명령이 data 라고 답한 것은 텍스트가 아닌 바이너리라는 뜻이다.
-- 내용을 사람이 읽으려면 ocrdump 를 쓴다.

-- 키마다 소유자가 다른 것도 확인한다.
[root@rac1 ~]# head -8 /root/ocrdump_ch5.txt | tail -5

UNDEF :

            OTHER_PERMISSION : PROCR_READ, USER_NAME : grid, GROUP_NAME : asmdba}

-- SYSTEM 은 grid:asmdba 인데 SYSTEM.version 은 root:root 였다.
-- OCR 의 접근 제어는 파일 단위가 아니라 키 단위다. 그래서 파일 복사로는
-- 백업이 되지 않고 전용 명령을 써야 한다.

--------------------------------------------------------------------------------
 [7] 두 백업의 비교
--------------------------------------------------------------------------------

--   항목            -manualbackup (물리적)   -export (논리적)
--   ----            ----------------------   ----------------
--   대상            저장 영역 전체           존재하는 키만
--   실측 크기       491,684KB 영역           208,896바이트
--   저장 위치       +CRS (강제)              임의 경로
--   위치 제약       ASM/공유FS 만 (PROT-42)  없음
--   성공 메시지     백업 목록 한 줄          PROT-58
--   복원 명령       ocrconfig -restore       ocrconfig -import
--   용도            일상·자동 백업           업그레이드 전, 원격 보관
--
-- 둘은 대체재가 아니라 보완재다.
--   물리적 백업은 자동으로 쌓이지만 ASM 안에 있다. +CRS 디스크그룹 자체가
--   날아가면 백업도 함께 날아간다.
--   export 는 자동으로 만들어지지 않지만 204KB 짜리 파일이라 어디든 둘 수 있다.
--
-- 실무 기준: 구성 변경 직전에 둘 다 실행하고, export 파일은 클러스터 밖의
-- 백업 서버로 복사한다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- 확인한 것
--   1) 읽기는 grid, 쓰기는 root (PROT-20)
--   2) 백업 위치는 +CRS 디스크그룹 안. 파일시스템이 아니다
--   3) 명령은 rac1 에서 실행했는데 OCR 마스터인 rac2 가 수행했다
--   4) 로컬 디렉터리는 백업 위치가 될 수 없다 (PROT-42)
--   5) 백업 파일은 Redund MIRROR 로 저장된다. 백업 자체가 보호받는다
--   6) export 는 208,896바이트이고 로컬 파일시스템에 쓸 수 있다 (PROT-58)
--   7) OCR 에는 428개 키가 있고 키마다 소유자와 권한이 다르다
--
-- 현재 상태
--   수동 백업 3벌 (+CRS/rac-cluster/OCRBACKUP/)
--   논리적 export 1벌 (/root/ocr_ch5.dmp)
--   PROT-25 는 해소되었고 PROT-24 는 남아 있다
--
-- 이제 되돌릴 지점이 생겼다. 실습 04 부터 구성을 실제로 변경한다.
