 [2] 오류 재현 — 없는 디스크그룹
--------------------------------------------------------------------------------

[root@rac1 ~]# ocrconfig -add +NOSUCHDG
PROT-30: The Oracle Cluster Registry location to be added is not usable.
PROC-50: The Oracle Cluster Registry location to be added is inaccessible on nodes rac1.

-- 오류 : PROT-30, PROC-50
-- 원인 파악 : 두 줄이 계층을 나눠 말한다.
--             PROT-30 은 상위 계층의 판정으로 "추가하려는 위치를 쓸 수 없다"
--             는 결론이다.
--             PROC-50 은 하위 계층의 근거로 "어느 노드에서 접근할 수 없는가"
--             를 알려 준다. 여기서는 rac1 이 찍혔다.
-- 조치     : PROC-50 의 노드 목록을 조사 범위로 쓴다. 3노드 이상 클러스터에서
--             한 노드만 나온다면 그 노드에 접속해 v$asm_diskgroup 이
--             MOUNTED 인지, v$asm_disk 에 디스크가 보이는지, udev 규칙과
--             장치 권한이 맞는지를 순서대로 확인한다.
--             모든 노드가 나온다면 디스크그룹 자체가 없는 것이므로 노드
--             개별 조사는 불필요하다.
-- 재확인   : 구성이 바뀌지 않았는지 본다.

[root@rac1 ~]# ocrcheck -config
Oracle Cluster Registry configuration is :
         Device/File Name         :       +CRS

-- 그대로다.

 [5] ocr.loc 자동 전파
--------------------------------------------------------------------------------

[root@rac1 ~]# cat /etc/oracle/ocr.loc
#Device/file  getting replaced by device +DATA/rac-cluster/OCRFILE/registry.255.1242835831
ocrconfig_loc=+CRS/rac-cluster/OCRFILE/registry.255.1242760249
ocrmirrorconfig_loc=+DATA/rac-cluster/OCRFILE/registry.255.1242835831
local_only=false

[root@rac2 ~]# cat /etc/oracle/ocr.loc
#Device/file  getting replaced by device +DATA/rac-cluster/OCRFILE/registry.255.1242835831
ocrconfig_loc=+CRS/rac-cluster/OCRFILE/registry.255.1242760249
ocrmirrorconfig_loc=+DATA/rac-cluster/OCRFILE/registry.255.1242835831
local_only=false

-- 두 노드의 내용이 한 글자까지 같다. rac1 에서 명령 한 번을 실행했을 뿐인데
-- rac2 의 파일도 갱신되었다. local_only 의 대소문자까지 통일되었다.
--
-- 새 키 ocrmirrorconfig_loc 이 생겼다. 세 번째부터는 ocrconfig_loc3,
-- ocrconfig_loc4 처럼 번호가 붙는다.
--
-- 이것이 ocr.loc 을 직접 편집하면 안 되는 이유다. ocrconfig 는 ASM 안의 실제
-- 파일 생성, 로컬 ocr.loc 갱신, 다른 노드 ocr.loc 갱신을 하나의 작업으로
-- 처리한다. 텍스트 편집은 한 곳만 바꾼다.

-- ASM 쪽에서 새 파일을 확인한다.
[grid@rac1 ~]$ asmcmd ls -l +DATA/rac-cluster/OCRFILE
Type     Redund  Striped  Time             Sys  Name
OCRFILE  UNPROT  COARSE   SEP 01 16:00:00  Y    REGISTRY.255.1242835831

-- Redund 가 UNPROT 이다. +DATA 는 External 중복도이므로 ASM 이 미러링하지
-- 않는다. 같은 OCR 이 +CRS 에서는 MIRROR, +DATA 에서는 UNPROT 으로 저장된다.
-- 다중화를 했다고 모든 사본이 동등하게 보호되는 것은 아니다.

 [8] 마지막 한 벌은 지울 수 없다

[root@rac1 ~]# ocrconfig -delete +CRS
PROT-28: Cannot delete or replace the only configured Oracle Cluster Registry location.

-- 오류 : PROT-28
-- 원인 파악 : OCR 을 0벌로 만드는 것을 Clusterware 가 스스로 금지한다.
--             OCR 이 없으면 crsd 가 뜰 수 없고 클러스터가 성립하지 않는다.
--             delete 뿐 아니라 replace 도 같은 이유로 막힌다.
-- 조치     : 위치를 옮기려면 순서를 지킨다. 새 위치를 먼저 add 하고 그다음
--             옛 위치를 delete 한다. [6][7] 에서 한 것이 정확히 그 순서다.
--             -replace 로 한 번에 처리할 수도 있지만 중간 상태에서 검증할
--             기회가 사라지므로 운영 환경에서는 add 후 delete 를 권한다.
-- 재확인   : 구성이 그대로인지 확인한다.

[root@rac1 ~]# ocrcheck -config
Oracle Cluster Registry configuration is :
         Device/File Name         :       +CRS

-- 실패한 명령이 아무것도 바꾸지 않았다.

 [10] 정리
--------------------------------------------------------------------------------

-- 재현한 오류
--   PROT-30 / PROC-50   없는 디스크그룹. PROC-50 이 노드 이름을 알려 준다
--   PROT-29             이미 등록된 위치
--   PROT-28             마지막 한 벌 삭제 시도
--
-- 확인한 것
--   1) OCR 은 최대 5벌. ocrcheck 가 항상 5개 슬롯을 보여 준다
--   2) 다중화해도 ID, Total space, Used space 는 변하지 않는다
--   3) ocr.loc 은 명령 한 번으로 모든 노드에 자동 전파된다
--   4) 두 번째 위치는 ocrmirrorconfig_loc 키로 기록된다
--   5) +DATA 의 사본은 UNPROT 이다. 보호 수준은 위치마다 다르다
--   6) 두 벌일 때는 하나를 지워도 클러스터가 정상이다
--   7) 지웠다 다시 만들면 ASM 파일 번호는 바뀌고 ID 는 유지된다
--
-- 실무 절차 (무중단 OCR 이전)
--   1) ocrcheck 로 ID 기록, -manualbackup 과 -export 실행
--   2) ocrconfig -add <새 위치>
--   3) ocrcheck 로 두 위치 모두 succeeded 확인, 전 노드 ocr.loc 일치 확인
--   4) 일정 시간 관찰
--   5) ocrconfig -delete <옛 위치>
--   6) ocrcheck 로 ID 불변 확인, 다시 -manualbackup
