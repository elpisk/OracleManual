--------------------------------------------------------------------------------
 [2] 조치 — 권한을 받고 원본 함수 만들기
--------------------------------------------------------------------------------

-- 원본 코드를 문법만 정리해 그대로 옮겼다. 키는 16진수처럼 보이는 48글자 문자열을
-- STRING_TO_RAW 로 바꾼 것이고, 암호문은 CAST_TO_VARCHAR2 로 문자열 컬럼에 넣는다.

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT SELECT ON hr.employees TO cr_owner;

Grant succeeded.

SYS@orcl> CONNECT cr_owner/oracle
Connected.
CR_OWNER@orcl> CREATE TABLE cr_emp AS
  2    SELECT employee_id, last_name, email, salary FROM hr.employees;

Table created.

CR_OWNER@orcl> CREATE OR REPLACE FUNCTION encrypt_value (input_string IN VARCHAR2)
  2  RETURN VARCHAR2 IS
  3    raw_key     RAW(128) := UTL_I18N.STRING_TO_RAW('0DEEFB5B6967D85F614E038E771F9DCC7AE48C85B08D9F7E', 'AL32UTF8');
  4    l_encrypted RAW(512);
  5    l_type      NUMBER := DBMS_CRYPTO.DES3_CBC_PKCS5;
  6  BEGIN
  7    l_encrypted := DBMS_CRYPTO.ENCRYPT(UTL_RAW.CAST_TO_RAW(input_string), l_type, raw_key);
  8    RETURN UTL_RAW.CAST_TO_VARCHAR2(l_encrypted);
  9  END;
 10  /

Function created.

CR_OWNER@orcl> CREATE OR REPLACE FUNCTION decrypt_value (input_string IN VARCHAR2)
  2  RETURN VARCHAR2 IS
  3    raw_key     RAW(128) := UTL_I18N.STRING_TO_RAW('0DEEFB5B6967D85F614E038E771F9DCC7AE48C85B08D9F7E', 'AL32UTF8');
  4    l_decrypted RAW(512);
  5    l_type      NUMBER := DBMS_CRYPTO.DES3_CBC_PKCS5;
  6  BEGIN
  7    l_decrypted := DBMS_CRYPTO.DECRYPT(UTL_RAW.CAST_TO_RAW(input_string), l_type, raw_key);
  8    RETURN UTL_RAW.CAST_TO_VARCHAR2(l_decrypted);
  9  END;
 10  /

Function created.

CR_OWNER@orcl> ALTER TABLE cr_emp ADD (encrypt_name VARCHAR2(100));

Table altered.

CR_OWNER@orcl> UPDATE cr_emp SET encrypt_name = encrypt_value(last_name);

107 rows updated.

CR_OWNER@orcl> COMMIT;

Commit complete.

-- ★ 107행 모두 암호화됐다. 오류는 없다. 원본이 쓴 DES3_CBC_PKCS5 는 이전 호환용 스위트이고
--    새로 만드는 코드는 AES 를 쓴다(03).

-- ★ 바이트 수는 모두 8(DES3 블록 크기)인데 LENGTH 가 5, 4, 6 처럼 들쭉날쭉하다.

--    같은 DB 안에서는 바이트가 그대로 보존돼 107건 모두 복호화된다.

 정리

-- - 원본 함수는 같은 DB 안에서는 동작하지만 세 가지 위험이 있다.
--   (1) 암호문을 VARCHAR2 에 저장: 문자 집합 변환에서 손상(ORA-28817).
--   (2) 키를 소스에 고정: DBA_SOURCE 로 노출.
--   (3) DES3 스위트: 이전 호환용. 새 코드는 AES256 + CBC + PKCS5.
-- - cr_emp 와 두 함수는 05 에서 사용자와 함께 철거한다.
