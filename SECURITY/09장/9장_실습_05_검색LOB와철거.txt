 제9장 실습 05 — 검색·LOB·철거
 대상    : oel7v9 orcl
 목표    : IV 를 쓴 암호화 컬럼은 동등 검색도 되지 않는다는 것을 확인하고,
          키를 건 MAC 컬럼으로 인덱스 검색을 만든다. CLOB 암호화 오버로드를 쓴 뒤 모두 철거한다
 소요    : 약 25분
 변경    : email_mac 컬럼과 인덱스. 마지막에 cr_owner, cr_keymgr 철거
================================================================================

--    범위 검색, 정렬, LIKE 도 같은 이유로 인덱스를 쓸 수 없다.

--------------------------------------------------------------------------------
 [2] 키를 건 MAC 으로 검색 컬럼 만들기
--------------------------------------------------------------------------------

-- MAC 키를 코드에 적은 것은 시연용이다. 실제로는 cr_keys 처럼 분리 보관한다.

SQL> CONNECT cr_owner/oracle
Connected.
CR_OWNER@orcl> ALTER TABLE cr_emp ADD (email_mac RAW(32));

Table altered.

CR_OWNER@orcl> DECLARE
  2    v_mk RAW(32) := UTL_I18N.STRING_TO_RAW('search-mac-key-demo-0123456789ab', 'AL32UTF8');
  3  BEGIN
  4    UPDATE cr_emp SET email_mac = DBMS_CRYPTO.MAC(UTL_I18N.STRING_TO_RAW(email, 'AL32UTF8'), DBMS_CRYPTO.HMAC_SH256, v_mk);
  5    COMMIT;
  6  END;
  7  /

PL/SQL procedure successfully completed.

CR_OWNER@orcl> CREATE INDEX cr_emp_mac_ix ON cr_emp (email_mac);

Index created.

CR_OWNER@orcl> VARIABLE m VARCHAR2(64)
CR_OWNER@orcl> BEGIN
  2    :m := RAWTOHEX(DBMS_CRYPTO.MAC(UTL_I18N.STRING_TO_RAW('SKING', 'AL32UTF8'), DBMS_CRYPTO.HMAC_SH256,
  3                   UTL_I18N.STRING_TO_RAW('search-mac-key-demo-0123456789ab', 'AL32UTF8')));
  4  END;
  5  /

PL/SQL procedure successfully completed.

CR_OWNER@orcl> COL email FOR a10
CR_OWNER@orcl> SELECT employee_id, cr_keymgr.cr_pkg.dec(email_enc) AS email FROM cr_emp WHERE email_mac = HEXTORAW(:m);

-- ★ 이메일의 HMAC-SHA256 값을 따로 저장하고 인덱스를 걸었다. 검색어의 MAC 을 계산해 비교하면
--    INDEX RANGE SCAN 으로 한 행을 찾는다. 키 없는 해시는 사전 대입으로 원문을 추측당할 수 있어
--    검색용 컬럼에는 키를 건 MAC 을 쓴다. 동등 검색만 되고 범위 검색은 여전히 안 된다.

 [3] 오류 재현 — CLOB 를 함수형 ENCRYPT 에 / 조치
--------------------------------------------------------------------------------

SQL> CONNECT cr_owner/oracle
Connected.
CR_OWNER@orcl> SET SERVEROUTPUT ON
CR_OWNER@orcl> DECLARE
  2    v_typ PLS_INTEGER := DBMS_CRYPTO.ENCRYPT_AES256 + DBMS_CRYPTO.CHAIN_CBC + DBMS_CRYPTO.PAD_PKCS5;
  3    v_key RAW(32) := DBMS_CRYPTO.RANDOMBYTES(32);
  4    v_src CLOB := RPAD('memo ', 5000, 'x');
  5    v_enc BLOB;
  6  BEGIN
  7    v_enc := DBMS_CRYPTO.ENCRYPT(v_src, v_typ, v_key);
  8  END;
  9  /
  v_enc := DBMS_CRYPTO.ENCRYPT(v_src, v_typ, v_key);
           *
ERROR at line 7:
ORA-06550: line 7, column 12:
PLS-00306: wrong number or types of arguments in call to 'ENCRYPT'
ORA-06550: line 7, column 3:
PL/SQL: Statement ignored


CR_OWNER@orcl> DECLARE
  2    v_typ PLS_INTEGER := DBMS_CRYPTO.ENCRYPT_AES256 + DBMS_CRYPTO.CHAIN_CBC + DBMS_CRYPTO.PAD_PKCS5;
  3    v_key RAW(32) := DBMS_CRYPTO.RANDOMBYTES(32);
  4    v_src CLOB := RPAD('memo ', 5000, 'x');
  5    v_enc BLOB;
  6    v_dec CLOB;
  7  BEGIN
  8    DBMS_LOB.CREATETEMPORARY(v_enc, TRUE);
  9    DBMS_LOB.CREATETEMPORARY(v_dec, TRUE);
 10    DBMS_CRYPTO.ENCRYPT(v_enc, v_src, v_typ, v_key);
 11    DBMS_CRYPTO.DECRYPT(v_dec, v_enc, v_typ, v_key);
 12    DBMS_OUTPUT.PUT_LINE('src ' || DBMS_LOB.GETLENGTH(v_src) || ' chars, enc ' || DBMS_LOB.GETLENGTH(v_enc)
 13                         || ' bytes, dec ' || DBMS_LOB.GETLENGTH(v_dec) || ' chars, same=' ||
 14                         CASE WHEN DBMS_LOB.COMPARE(v_src, v_dec) = 0 THEN 'Y' ELSE 'N' END);
 15  END;
 16  /
src 5000 chars, enc 5008 bytes, dec 5000 chars, same=Y

PL/SQL procedure successfully completed.

-- ★ CLOB 를 RAW 반환 함수형 ENCRYPT 에 넘기자 PLS-00306. LOB 은 프로시저형 오버로드
--    ENCRYPT(dst BLOB, src CLOB, ...) 를 쓴다. 결과는 BLOB 이며 dst 는 덮어쓴다.
--    5000자 CLOB 이 5008바이트로 암호화되고 복호화 결과가 원본과 같다(same=Y).

--    DBMS_CRYPTO 실행 권한 보유자도 처음처럼 0 이다.

================================================================================
 정리
================================================================================

-- - 무작위 IV 를 쓴 암호문은 비교·인덱스가 불가능하다. 검색이 필요하면 키를 건 MAC 컬럼을 따로 둔다.
-- - LOB 은 프로시저형 ENCRYPT/DECRYPT 를 쓴다(함수형에 넘기면 PLS-00306).
-- - 이 장에서 만든 cr_owner, cr_keymgr 와 모든 객체·권한을 철거했다.
