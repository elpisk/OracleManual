================================================================================
 제4장 실습 04 — 역할 부여와 구버전 API
 대상    : oel7v9 orcl
 목표    : ACE 의 주체로 역할을 쓰고 역할 활성화 여부가 판정에 미치는 영향을 본다.
          원본 자료의 CREATE_ACL·ASSIGN_ACL 이 19c 에서 어떻게 남는지 확인한다
 소요    : 약 20분
 변경    : 역할 acl_web_role, 사용자 acl_u3, 구버전 ACL acl_legacy.xml
================================================================================

--------------------------------------------------------------------------------
 [1] 역할에 ACE, 역할을 끄면
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> CREATE ROLE acl_web_role;

Role created.

SYS@orcl> CREATE USER acl_u3 IDENTIFIED BY oracle;

User created.

SYS@orcl> GRANT CREATE SESSION, acl_web_role TO acl_u3;

Grant succeeded.

SYS@orcl> BEGIN
  2    DBMS_NETWORK_ACL_ADMIN.APPEND_HOST_ACE(
  3      host       => '172.16.225.50',
  4      lower_port => 8090,
  5      ace        => xs$ace_type(privilege_list => xs$name_list('http'),
  6                                principal_name => 'ACL_WEB_ROLE',
  7                                principal_type => xs_acl.ptype_db));
  8  END;
  9  /

PL/SQL procedure successfully completed.

SYS@orcl> CONNECT acl_u3/oracle
Connected.
ACL_U3@orcl> SELECT SUBSTR(UTL_HTTP.REQUEST('http://172.16.225.50:8090/'), 1, 40) AS page FROM dual;

--------------------------------------------------------------------------------
 [2] 구버전 API — CREATE_ACL / ASSIGN_ACL, 같은 이름 재생성
--------------------------------------------------------------------------------

-- 원본 실습의 방식이다. 12c 부터 디프리케이트됐지만 하위 호환을 위해 남아 있다.

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> BEGIN
  2    DBMS_NETWORK_ACL_ADMIN.CREATE_ACL(
  3      acl         => 'acl_legacy.xml',
  4      description => 'legacy API test',
  5      principal   => 'ACL_U3',
  6      is_grant    => TRUE,
  7      privilege   => 'connect');
  8    DBMS_NETWORK_ACL_ADMIN.ASSIGN_ACL(
  9      acl        => 'acl_legacy.xml',
 10      host       => 'oel7v9',
 11      lower_port => 8090);
 12  END;
 13  /

PL/SQL procedure successfully completed.

SYS@orcl> BEGIN
  2    DBMS_NETWORK_ACL_ADMIN.CREATE_ACL(
  3      acl         => 'acl_legacy.xml',

  6      is_grant    => TRUE,
  7      privilege   => 'connect');
  8  END;
  9  /

-- ★ CREATE_ACL + ASSIGN_ACL 은 성공했다. 같은 이름으로 다시 CREATE_ACL 하면
--    ORA-46212: XS entity with this name already exists. ACL 이 RAS(XS) 객체로 저장된다는 흔적이다.
--    이름은 /sys/acls/acl_legacy.xml 로 보이고, 구버전 뷰 DBA_NETWORK_ACLS 와 새 뷰 DBA_HOST_ACLS 에
--    같은 내용이 나온다. 그 ACE 는 DBA_HOST_ACES 에서 일반 ACE 와 똑같이 보인다(host 는 소문자로 저장).

--------------------------------------------------------------------------------
 [3] 구버전 ACL 로 접속
--------------------------------------------------------------------------------

SQL> CONNECT acl_u3/oracle
Connected.
ACL_U3@orcl> SET ROLE NONE;

Role set.

ACL_U3@orcl> SELECT SUBSTR(UTL_HTTP.REQUEST('http://oel7v9:8090/'), 1, 40) AS page FROM dual;

PAGE
------------------------------------------------------------------------------------------------------------------------
<html><body>ACL test page on oel7v9</bod

1 row selected.

-- ★ 역할을 끈 상태에서도 구버전 ACL 의 connect 권한으로 http://oel7v9:8090/ 을 읽는다.
--    connect 는 UTL_HTTP 도 포함한다. 두 방식으로 만든 ACL 이 한 체계 안에서 함께 판정된다.

 정리
================================================================================

-- - 역할에도 ACE 를 줄 수 있으나 역할이 켜진 세션에서만 유효하다.
-- - CREATE_ACL·ADD_PRIVILEGE·ASSIGN_ACL 은 디프리케이트. 기존 ACL 은 그대로 동작하고 새 뷰에도 보인다.
-- - 새로 만드는 설정은 APPEND_HOST_ACE 로 통일한다.
