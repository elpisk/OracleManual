-- "경고 로그(Alert Log) 내용을 Syslog로 전송"은 사실과 다르다. 경고 로그는 syslog 로 가지 않는다.
--        AUDIT_SYSLOG_LEVEL 은 전통 감사 기록(AUDIT_TRAIL=OS)과 SYS 작업 감사(AUDIT_SYS_OPERATIONS=TRUE, 기본값)를
--        .aud 파일 대신 syslog 로 보낸다. 통합 감사 기록은 UNIFIED_AUDIT_SYSTEMLOG(19c, UNIX 계열)로 보낸다.
- 오라클의 감사 기록을 유닉스/리눅스 시스템의 표준 로깅 시설인 Syslog로 전송하는 기능
- 오라클 DB의 중요한 감사 메시지(SYS 접속과 작업, Startup/Shutdown, 로그인 실패 등)를 OS 레벨의 로깅 시스템에 통합하여 중앙 집중식으로 관리하고 모니터링
- DB 관리자가 DB 안의 감사 기록을 지우거나 고쳐도 OS 쪽 기록은 남는다. syslog 를 원격 로그 서버로 넘기면 DBA 권한과 분리된 보관이 된다.

- Facility 코드: 로그 메시지가 어떤 유형의 시스템 또는 애플리케이션에서 발생했는지를 분류

- Priority: 메시지가 얼마나 긴급하고 중요한지를 나타냄.

심각도 레벨 | 의미 | 설명 및 사용 예시
debug | Debugging | 디버깅 정보만 포함하는 매우 상세한 메시지. 개발 및 문제 해결 시에만 기록.
info | Informational | 시스템의 일반적인 작동 정보. 가장 낮은 수준의 심각도(예: Success login)
notice | Notice | 일반적이지만 중요한 조건. 특별한 조치는 필요 없지만, 주목할 만한 이벤트 (예: DB Startup/Shutdown 성공)
warning | Warning | 잠재적인 문제나 오류를 나타내는 경고. 즉각적인 조치는 불필요할 수 있으나, 모니터링이 필요 (예: 디스크 공간 임계값 초과)
err | Error | 오류 조건. 기능에 영향을 미치는 문제. 프로그램이 정상적으로 동작하지 못함. (예: I/O 오류, ORA-00000 일반 오류)
crit | Critical | 시스템의 중요한 기능에 영향을 미치는 치명적인 조건입니다. 즉시 조치 (예: 하드웨어 고장, DB 인스턴스 Crash)
alert | Alert | 즉각적인 조치가 필요함을 나타냅니다. 상태가 매우 심각하며, 시스템 관리자에게 즉시 고지 (예: DB 테이블스페이스 99% 사용)
emerg | Emergency | 가장 심각한 레벨. 시스템 사용이 불가능하며 즉시 시스템을 복구. PANIC 상태와 동의어로 간주 (예: OS Crash)

-- 파라미터 값은 'facility.priority' 형식이다. Oracle 은 감사 기록을 이 facility·priority 로 내보내고,
--        rsyslog 규칙이 받는 범위(local1.* 는 모든 priority, local1.err 는 err 이상)에 들어야 파일에 남는다.

--  AUDIT_SYSLOG_LEVEL 은 정적 파라미터다. SCOPE 없이(메모리 포함) 바꾸면 ORA-02095 가 난다.
SYS@orcl> ALTER SYSTEM SET AUDIT_SYSLOG_LEVEL='local1.warning';
ALTER SYSTEM SET AUDIT_SYSLOG_LEVEL='local1.warning'
                 *
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

SYS@orcl> ALTER SYSTEM SET AUDIT_SYSLOG_LEVEL='local1.warning' SCOPE=SPFILE;

System altered.

--  추가: 통합 감사 기록도 syslog 로 보낸다. 이 파라미터도 정적이라 SCOPE=SPFILE 로 넣고 재기동한다.
SYS@orcl> ALTER SYSTEM SET UNIFIED_AUDIT_SYSTEMLOG='local1.warning' SCOPE=SPFILE;

System altered.
