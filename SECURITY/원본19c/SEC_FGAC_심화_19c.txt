■ SECURITY

KEY WORDS
- FGAC 심화 : 전역 컨텍스트, 정책 유형과 커서 공유, update_check, 열 마스킹, 정책 그룹, 드라이빙 컨텍스트, VPD 오류 진단

<<실습 개요>>
- 난이도 : 상. SEC_FGAC 실습(로컬 컨텍스트, ADD_POLICY, update_check 기본형)을 마친 뒤 진행함
- 상황 : DB 계정 하나(FGX_APP)로 접속을 풀링하는 다중 테넌트 주문 애플리케이션. 실제 사용자는 CLIENT_IDENTIFIER 로 구분함
- 계정
    FGX_OWN  주문 테이블 ORDERS 소유자
    FGX_SEC  보안 관리 스키마. 컨텍스트 패키지와 정책 함수를 소유하고 DBMS_RLS 를 실행함
    FGX_APP  애플리케이션 풀 계정
    FGX_AUD  감사 담당 조회 계정
- 앱 사용자(FGX_SEC.APP_USERS) : ALICE 10번 테넌트 MANAGER, CAROL 10번 테넌트 CLERK, BOB 20번 테넌트 MANAGER
- 순서 : 1 준비 → 2 전역 컨텍스트 → 3 STATIC 정책의 함정 → 4 CONTEXT_SENSITIVE → 5 SYS_CONTEXT 술어 → 6 DML 통제 → 7 열 마스킹 → 8 오류 진단 → 9 정책 그룹 → 10 정책 면제 → 11 정리
- 구간끼리 이어지므로 순서대로 진행함. 앞 구간이 남긴 정책이 다음 구간의 결과에 영향을 줌
- 정책 함수가 몇 번 실행됐는지는 패키지 변수 POL_PKG.G_CALLS 로 셈. 패키지 상태는 세션 단위라 FGX_APP 세션 안에서 조회함

<<1. 준비 — 계정, 테이블, 컨텍스트>>
- 컨텍스트 두 개를 ACCESSED GLOBALLY 로 만듦. FGX_CTX 는 테넌트와 역할, FGX_DRV 는 9구간에서 정책 그룹을 고르는 드라이빙 컨텍스트

<<3. STATIC 정책의 함정>>
- STATIC 정책은 정책 함수를 한 번만 실행하고 그 술어를 SGA 에 캐시해 모든 세션이 재사용함
- 함수가 컨텍스트 값을 술어 문자열에 리터럴로 이어 붙이면, 처음 실행한 사용자의 값이 이후 모든 사용자에게 적용됨

  3    FUNCTION tenant_pred(p_schema IN VARCHAR2, p_obj IN VARCHAR2) RETURN VARCHAR2;
  4    FUNCTION calls RETURN NUMBER;
  5  END;

<<10. 정책 면제 — EXEMPT ACCESS POLICY>>
- VPD 정책은 테이블 소유자에게도 적용됨. 정책을 받지 않는 것은 SYS 접속과 EXEMPT ACCESS POLICY 권한을 가진 사용자뿐
- 이 권한은 객체 단위로 줄 수 없어서 모든 스키마의 VPD 정책을 한꺼번에 우회함
- 기본 통합 감사 정책 ORA_SECURECONFIG 에 EXEMPT ACCESS POLICY 사용 감사가 들어 있음
