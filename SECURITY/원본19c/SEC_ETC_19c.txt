■ SSL

- 네트워크 통신을 암호화하고 인증하는 표준 기술
- 도청/스니핑(Eavesdropping/Sniffing) 방지
- 중간자 공격(Man-in-the-Middle Attack) 방지
- 구성요소 : 오라클 지갑 (Oracle Wallet): 보안 자격 증명(Security Credentials)을 저장하는 컨테이너.
  ✓ 공개 키/개인 키 쌍 (Private Key/Public Key Pair): 암호화에 사용되는 핵심 키
  ✓ 인증서 (Certificate): 서버나 클라이언트의 신원을 증명. 보통 신뢰할 수 있는 제 3 의 기관(CA)에 의해 서명된 서버 인증서와, 통신 상대방의 인증서를 신뢰할 수 있도록 등록한 신뢰 인증서(Trusted Certificates)가 포함.
--  19c 문서는 SSL 대신 TLS라는 이름을 쓴다(19.3에서 쓸 수 있는 최고 버전은 TLS 1.2). sqlnet.ora 파라미터는 SSL_* 이름이 그대로 동작한다.
- 구성 파일

| 구성 요소       | 역할                                                           | 핵심 파일                       |
|-----------------|----------------------------------------------------------------|---------------------------------|
| Oracle Wallet   | 인증서와 개인 키를 저장하는 금고 역할                          | cwallet.sso (지갑 파일)         |
| 서버 설정       | 데이터베이스 리스너가 암호화된 연결(TCPS)을 수신하도록 설정    | listener.ora, sqlnet.ora        |
| 클라이언트 설정 | 서버의 인증서를 신뢰하고 TCPS 프로토콜을 사용하도록 설정       | tnsnames.ora, sqlnet.ora        |
| TCPS            | TCP 위에 SSL/TLS 암호화 계층을 추가하여 통신하는 프로토콜       | 포트 번호 (일반적으로 2484)     |

--  원본은 서버(orcl)와 클라이언트(prod) 두 서버로 진행한다. 실측은 OEL7V9 한 대에서 했으므로 scp 대신 cp로 파일을 옮긴다.
--  공용 listener.ora·sqlnet.ora를 건드리지 않도록 서버용 /u01/app/oracle/server_tns, 클라이언트용 /u01/app/oracle/client_tns 디렉터리를 따로 두고 TNS_ADMIN으로 지정한다.

[oracle@oel7v9 ~]$ cd /u01/app/oracle/client_wallet

3) 데이터베이스 내 사용자 생성

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> create user client identified externally as 'CN=client,O=oracle,C=ro';

User created.

SYS@orcl> grant create session to client;

Grant succeeded.

참고: 데이터베이스 내 사용자는 해당 인증서의 고유 이름(DN)을 지정하여 생성.
이전에 생성된 사용자 인증서는 DN 'CN=client,O=oracle,C=ro'를 가졌으므로,
데이터베이스에서 사용자를 생성할 때 동일한 문자열을 사용.

위의 모든 단계를 수행한 후, 데이터베이스 서버 머신의 server_wallet 및 client_wallet 디렉터리에
서버와 클라이언트 모두에 필요한 모든 인증서가 준비 완료.

4) 서버 측 리스너 구성(orcl DB에서 )

-TCPS 리스너 주소 구성:

Net Manager를 사용하여 새 TCPS 리스너를 생성하거나 기존 리스너에 새 TCPS 주소를 및  지갑 위치를 추가.
-- [19c 랩] 기본 LISTENER를 재기동하지 않도록 TCPS 전용 리스너 LISTENER_SSL(포트 1522)을 server_tns에 따로 만든다.
-- [19c 랩] 정적 등록(SID_DESC)의 ENVS로 TNS_ADMIN을 넘겨야 이 리스너가 띄운 서버 프로세스가 server_tns/sqlnet.ora(서버 지갑)를 읽는다.
[oracle@oel7v9 ~]$ mkdir /u01/app/oracle/server_tns
[oracle@oel7v9 ~]$ cd /u01/app/oracle/server_tns
[oracle@oel7v9 server_tns]$ printf '%s\n' 'LISTENER_SSL =' '   (DESCRIPTION_LIST =' '      (DESCRIPTION =' '         (ADDRESS = (PROTOCOL = TCPS)(HOST = oel7v9)(PORT = 1522))' '      )' '   )' 'SID_LIST_LISTENER_SSL =' '   (SID_LIST =' '      (SID_DESC =' '         (GLOBAL_DBNAME = orcl)' '         (ORACLE_HOME = /u01/app/oracle/product/19.3.0/dbhome_1)' '         (SID_NAME = orcl)' '         (ENVS = "TNS_ADMIN=/u01/app/oracle/server_tns")' '      )' '   )' 'WALLET_LOCATION =' '   (SOURCE=' '     (METHOD=File)' '      (METHOD_DATA=' '        (DIRECTORY=/u01/app/oracle/server_wallet)))' > listener.ora
[oracle@oel7v9 server_tns]$ cat listener.ora
LISTENER_SSL =
   (DESCRIPTION_LIST =
      (DESCRIPTION =
         (ADDRESS = (PROTOCOL = TCPS)(HOST = oel7v9)(PORT = 1522))
      )
   )
SID_LIST_LISTENER_SSL =
   (SID_LIST =
      (SID_DESC =
         (GLOBAL_DBNAME = orcl)
         (ORACLE_HOME = /u01/app/oracle/product/19.3.0/dbhome_1)
         (SID_NAME = orcl)
         (ENVS = "TNS_ADMIN=/u01/app/oracle/server_tns")
      )
   )
WALLET_LOCATION =
   (SOURCE=
     (METHOD=File)
      (METHOD_DATA=
        (DIRECTORY=/u01/app/oracle/server_wallet)))

5) 서버 측 sqlnet.ora 구성( orcl DB에서 )

-- [19c] SSL_VERSION = 0은 19.3에서 오류 없이 받아들여졌고 접속도 됐다(아래 9)). 문서에 적힌 값은 undetermined, 1.0, 1.1, 1.2 등이므로 실무에서는 SSL_VERSION = 1.2(또는 TLS_VERSION)로 적는다.
[oracle@oel7v9 ~]$ cd /u01/app/oracle/server_tns
[oracle@oel7v9 server_tns]$ printf '%s\n' 'SQLNET.AUTHENTICATION_SERVICES= (BEQ, TCPS)' 'SSL_VERSION = 0' 'SSL_CLIENT_AUTHENTICATION = TRUE' 'WALLET_LOCATION =' '   (SOURCE =' '     (METHOD = FILE)' '      (METHOD_DATA =' '        (DIRECTORY = /u01/app/oracle/server_wallet)' '      )' '     )' > sqlnet.ora
[oracle@oel7v9 server_tns]$ cat sqlnet.ora
SQLNET.AUTHENTICATION_SERVICES= (BEQ, TCPS)
SSL_VERSION = 0
SSL_CLIENT_AUTHENTICATION = TRUE
WALLET_LOCATION =
   (SOURCE =
     (METHOD = FILE)
      (METHOD_DATA =
        (DIRECTORY = /u01/app/oracle/server_wallet)
      )
     )

8) 데이터베이스 구성

-- [19c] 원본의 다음 작업은 하지 않는다.
--   alter system set remote_os_authent=FALSE scope=spfile
--   alter system set os_authent_prefix='' scope=spfile;
--   shut immediate / startup
-- [19c] REMOTE_OS_AUTHENT는 11g부터 디프리케이트이고 기본값이 FALSE다. 인증서 사용자는 IDENTIFIED EXTERNALLY AS 'DN'으로 DN과 직접 연결되므로 OS_AUTHENT_PREFIX(기본 ops$)와 관계가 없다.
-- [19c] 값을 그대로 둔 채 9)에서 인증서 로그인이 되는 것으로 확인한다(11장 실측과 같음). DB 재기동도 필요 없다.
SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> show parameter remote_os_authent

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
remote_os_authent                    boolean     FALSE
SYS@orcl> show parameter os_authent_prefix

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
os_authent_prefix                    string      ops$

■ Proxy Authentication

- 프록시 인증은 중간 계층(Middle Tier)에 있는 하나의 공통 사용자 계정(프록시 사용자)이 최종 사용자(End User)를 대신하여 데이터베이스에 접속하는 방식. 애플리케이션 서버(프록시)가 데이터베이스에 연결할 때, "나는 애플리케이션 서버(프록시)지만, 지금 이 연결은 '실제 사용자 A'를 위한 거야"라고 알리는 것.
- 프록시 사용자 (Proxy User): 애플리케이션 서버가 데이터베이스에 접속하는 데 사용하는 실제 DB 계정. 이 계정은 비밀번호 없이 최종 사용자를 대신하여 연결할 수 있는 권한을 부여받음
- 클라이언트 사용자 (Client User/Target User): 애플리케이션을 사용하는 최종 사용자. 데이터베이스 세션은 이 사용자의 권한으로 실행
- 프록시 인증의 작동 방식 (두 가지 유형)
  1. 비밀번호 기반 프록시 인증 (Password-Based Proxy):
     o 프록시 사용자 (APPSERVER)가 최종 사용자(USER_A)의 비밀번호를 받아서 접속.
     o CONNECT APPSERVER[USER_A] IDENTIFIED BY user_a_password; 형태로 연결.
  2. 비밀번호 없는 프록시 인증 (No-Password Proxy):
     o 프록시 사용자 (APPSERVER)가 자신의 비밀번호를 사용하여 접속하고, 최종 사용자(USER_A)의 비밀번호 없이도 대신 연결.
     o 이 경우, 프록시 사용자는 최종 사용자를 대신할 수 있는 권한만 있으면 됨. (CONNECT APPSERVER[USER_A];) 이 방식이 가장 일반적.
-- 19c의 RESOURCE 역할에는 SODA_APP 역할이 들어 있어 USER1의 SESSION_ROLES에 SODA_APP이 함께 보인다(원본 출력과 같음).

-- [19c] AUTHENTICATED USING 절은 디프리케이트되었다(19c SQL Reference ALTER USER). AUTHENTICATED USING PASSWORD는 AUTHENTICATION REQUIRED로 바뀌어 저장되고, CERTIFICATE·DISTINGUISHED NAME은 AUTHENTICATION REQUIRED를 생략한 것과 같다. 19c에서는 [WITH ROLE ...] [AUTHENTICATION REQUIRED]로 쓴다.

■ Secure Application Role

- 특정 애플리케이션이나 세션 조건이 충족될 때만 권한을 활성화
- 구성 요소
  ✓ Application Role: CREATE ROLE ... IDENTIFIED GLOBALLY 또는 IDENTIFIED USING <package> 구문으로 생성
  ✓ Activation Procedure: 롤을 활성화하기 위한 로직을 포함하는 저장 프로시저
  ✓ Verification Logic: 프로시저 내에서 현재 세션 정보(예: IP 주소, OS 사용자, 특정 애플리케이션 변수)를 확인하여 권한 부여의 적합성을 판단
-- IDENTIFIED GLOBALLY는 엔터프라이즈 사용자(디렉터리)용 전역 역할이다. Secure Application Role은 IDENTIFIED USING [schema.]package|procedure로만 만든다.

■ Application contexts

- 모든 사용자가 데이터베이스에 로그인할 때마다 트리거에 의해 자동으로 설정
- 세션용 개인 명찰(Name Tag)
- 사용자가 데이터베이스에 로그인하면, 오라클은 그 사용자만을 위한 보이지 않는 명찰을 하나 발급
  이 명찰에는 '부서=영업팀', '직급=과장', '접속IP=192.168.10.5'와 같은 정보를 이름=값 형태로 여러 개 기록해 둘 수 있다.
- 사용자가 쿼리를 실행할 때, 오라클은 이 명찰의 내용을 확인하여 "영업팀 소속이니 영업 관련 데이터만 보여주자"와 같은 동적이고 세밀한 접근 제어를 수행. 이 명찰 정보는 다른 세션과 공유되지 않으며, 로그 아웃하면 사라진다
- 구성 요소:
  - Context Namespace: 명찰 자체를 정의. (CREATE CONTEXT)
  - Trusted Package: 명찰에 내용을 기록할 수 있는 유일한 허가된 주체(PL/SQL 패키지).
  - SYS_CONTEXT 함수: 명찰의 내용을 읽어오는 함수.

  8        INTO v_dept_id
  9        FROM hr.employees
 10       WHERE email = UPPER(SYS_CONTEXT('USERENV', 'SESSION_USER'));

■ TDE

- 데이터베이스 사용자나 애플리케이션에게는 투명하게(Transparent) 작동.
  - Transparent : 데이터를 저장하거나 검색할 때, 암호화/복호화 과정이 애플리케이션 코드의 수정 없이 데이터베이스 내부에서 자동으로 처리. 개발자는 데이터가 암호화되었는지조차 알 필요가 없다.
  - Data Encryption : 디스크에 저장되는 데이터(Data at Rest)를 암호화하여, 데이터 파일 자체가 유출되더라도 내용을 읽을 수 없도록 보호한다

--  이 절은 키스토어를 한 번도 만든 적 없는 DB가 필요해서 DBCA로 만든 임시 DB SECTDE(19.3 non-CDB)에서 실측함.
--       경로는 /u01/app/oracle/admin/orcl/wallet 대신 /u01/app/oracle/admin/sectde/wallet,
--       데이터 파일은 /u01/app/oracle/oradata/ORCL 대신 /u01/app/oracle/sectdedata/SECTDE를 씀.
-- WALLET_ROOT(18c부터)는 정적 파라미터라 SCOPE=SPFILE 후 재기동이 필요함. TDE_CONFIGURATION은 그 뒤에 SCOPE=BOTH로 설정함.
