== DBMS_REDACT의 주요 특징
- 실시간 마스킹 (Real-time Redaction): 데이터를 쿼리할 때마다 즉시 마스킹이 적용
- 정책 기반 (Policy-based): 마스킹 규칙은 테이블/뷰의 특정 컬럼에 대한 정책으로
            특정 조건(예: 사용자, IP 주소, 애플리케이션 등)이 충족될 때만 활성화.
- 투명성 (Transparency): 애플리케이션 코드 변경 없이 데이터 마스킹을 적용
- 다양한 마스킹 유형: 컬럼의 데이터 타입에 따라 다양한 마스킹 방식을 제공
  (Full, Partial, Regular Expression, Random, Nullify등)
-- [19c] 마스킹은 조회 결과에만 적용됨. 버퍼 캐시·데이터 파일에는 원래 값이 있고, WHERE·ORDER BY는 원래 값으로 평가됨.
--       SYS와 EXEMPT REDACTION POLICY 권한 보유자에게는 적용되지 않음.

< FULL MASKING>
- 마스킹된  데이터를 볼 사용자: sking
- 마스킹되지 않은 원본 데이터를 볼 사용자: scott
-- SKING 계정은 SEC_ETC Application Context 절에서 만든 계정(create user sking identified by sking; grant create session)을 그대로 씀.

-  SELECT 권한 부여
SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT SELECT ON hr.employees TO sking;

Grant succeeded.

SYS@orcl> GRANT SELECT ON hr.employees TO scott;

Grant succeeded.

- dbms_redact 실행 권한 부여
SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT EXECUTE ON DBMS_REDACT TO hr;

Grant succeeded.

SYS@orcl> GRANT EXECUTE ON DBMS_REDACT TO SYSTEM;

Grant succeeded.

- MASKING 정책 생성
SQL> conn hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ADD_POLICY (
  3      object_schema   => 'HR',
  4      object_name     => 'employees',
  5      policy_name     => 'MASK_SALARY_POLICY',
  6      expression      => 'SYS_CONTEXT(''USERENV'', ''SESSION_USER'') != ''SCOTT'' AND SYS_CONTEXT(''USERENV'', ''SESSION_USER'') != ''HR''',
  7      column_name     => 'SALARY',
  8      function_type   => DBMS_REDACT.FULL );
  9  END;
 10  /

PL/SQL procedure successfully completed.

(* function_type:
DBMS_REDACT.FULL: 컬럼 값 전체를 마스킹. 숫자 0, 문자열 공백 한 칸, 날짜 0001-01-01
DBMS_REDACT.PARTIAL: 지정한 패턴에 따라 부분적으로 마스킹(예: 신용카드 번호의 마지막 4자리만 표시).
DBMS_REDACT.REGEXP: 정규식 패턴과 일치하는 부분을 치환
DBMS_REDACT.NONE: 조건이 일치해도 마스킹하지 않음
DBMS_REDACT.RANDOM: 난수 또는 임의의 문자로 마스킹
DBMS_REDACT.NULLIFY: 값을 NULL로 마스킹
-- [19c] FULL의 날짜 값은 0000-00-00이 아니라 0001-01-01(REDACTION_VALUES_FOR_TYPE_FULL 뷰).
--       NULL 마스킹 상수는 DBMS_REDACT.NULLIFY(12.2부터). REGEXP를 목록에 넣음.
