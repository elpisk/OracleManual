================================================================================
 제7장 실습 05 — 정책 유형·면제·관리
 대상    : oel7v9 orcl
 목표    : CONTEXT_SENSITIVE 정책 유형과 V$VPD_POLICY 로 실제 붙은 술어를 보고,
          EXEMPT ACCESS POLICY·ENABLE_POLICY·DROP_POLICY 로 정책을 관리한 뒤 원복한다
 소요    : 약 20분
 변경    : HR 에 권한 부여 후 회수. 마지막에 이 장에서 만든 객체 전부 철거
================================================================================

--------------------------------------------------------------------------------
 [1] 정책 유형을 CONTEXT_SENSITIVE 로
--------------------------------------------------------------------------------

-- 기본 유형 DYNAMIC 은 문장을 실행할 때마다 정책 함수를 부른다.
-- CONTEXT_SENSITIVE 에 namespace·attribute 를 주면 HR_CONTEXT.DEPT 가 바뀔 때만 함수를 다시 부른다.

SQL> CONNECT sysadmin_vpd/oracle
Connected.
SYSADMIN_VPD@orcl> BEGIN
  2    DBMS_RLS.DROP_POLICY('SCOTT', 'EMP', 'EMP_SAL_POLICY');
  3    DBMS_RLS.ADD_POLICY(
  4      object_schema   => 'SCOTT',
  5      object_name     => 'EMP',
  6      policy_name     => 'EMP_DEPT_POLICY',
  7      function_schema => 'SYSADMIN_VPD',
  8      policy_function => 'RLS_DEPT',
  9      statement_types => 'SELECT',
 10      policy_type     => DBMS_RLS.CONTEXT_SENSITIVE,
 11      namespace       => 'HR_CONTEXT',
 12      attribute       => 'DEPT');
 13  END;
 14  /

PL/SQL procedure successfully completed.

SYSADMIN_VPD@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> COL policy_name FOR a16
SYS@orcl> SELECT policy_name, policy_type, enable FROM dba_policies WHERE object_owner = 'SCOTT';

POLICY_NAME      POLICY_TYPE              ENA
---------------- ------------------------ ---
EMP_DEPT_POLICY  CONTEXT_SENSITIVE        YES

1 row selected.

-- ★ POLICY_TYPE 이 CONTEXT_SENSITIVE 로 보인다.

--------------------------------------------------------------------------------
 [2] V$VPD_POLICY 로 실제 붙은 술어 보기
--------------------------------------------------------------------------------

SQL> CONNECT scott/tiger
Connected.
SCOTT@orcl> EXEC sysadmin_vpd.hr_ctx_pkg.set_dept(10)

PL/SQL procedure successfully completed.

SCOTT@orcl> SELECT COUNT(*) FROM emp;

  COUNT(*)
----------
         3

1 row selected.

SCOTT@orcl> EXEC sysadmin_vpd.hr_ctx_pkg.set_dept(30)

PL/SQL procedure successfully completed.

SCOTT@orcl> SELECT COUNT(*) FROM emp;

  COUNT(*)
----------
         6

1 row selected.

SCOTT@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> COL policy FOR a16
SYS@orcl> COL predicate FOR a20
SYS@orcl> SELECT DISTINCT policy, predicate FROM v$vpd_policy WHERE object_owner = 'SCOTT' ORDER BY predicate;

POLICY           PREDICATE
---------------- --------------------
EMP_DEPT_POLICY  deptno = 10
EMP_DEPT_POLICY  deptno = 30

2 rows selected.

-- ★ 같은 커서라도 컨텍스트 값에 따라 deptno = 10, deptno = 30 두 술어가 붙었다.
--    V$VPD_POLICY 는 공유 풀 커서 기준이라 누가 어떤 술어로 실행했는지 사후 확인에 쓴다.

--------------------------------------------------------------------------------
 [3] EXEMPT ACCESS POLICY
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT SELECT ON scott.emp TO hr;

Grant succeeded.

SYS@orcl> CONNECT hr/hr
Connected.
HR@orcl> SELECT COUNT(*) FROM scott.emp;

  COUNT(*)
----------
         0

1 row selected.

HR@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT EXEMPT ACCESS POLICY TO hr;

Grant succeeded.

SYS@orcl> CONNECT hr/hr
Connected.
HR@orcl> SELECT COUNT(*) FROM scott.emp;

  COUNT(*)
----------
        14

1 row selected.

-- ★ SELECT 권한만 받은 HR 은 컨텍스트가 없어 0건이다.
--    EXEMPT ACCESS POLICY 를 받자 14건 전부 보인다. 이 권한은 DB 의 모든 VPD 정책을 건너뛴다.
--    Data Pump 로 정책 걸린 테이블을 통째로 내보낼 때 정도로만 쓰고 감사 대상으로 둔다.

--------------------------------------------------------------------------------
 [4] 끄기와 켜기, 오류 재현 — 없는 정책 이름
--------------------------------------------------------------------------------

SQL> CONNECT sysadmin_vpd/oracle

SYSADMIN_VPD@orcl> EXEC DBMS_RLS.ENABLE_POLICY('SCOTT', 'EMP', 'EMP_DEPT_POLICY', FALSE)

SYSADMIN_VPD@orcl> CONNECT scott/tiger
Connected.
SCOTT@orcl> SELECT COUNT(*) FROM emp;

  COUNT(*)

        14

SCOTT@orcl> CONNECT sysadmin_vpd/oracle

SYSADMIN_VPD@orcl> EXEC DBMS_RLS.ENABLE_POLICY('SCOTT', 'EMP', 'EMP_DEPT_POLICY', TRUE)

SYSADMIN_VPD@orcl> EXEC DBMS_RLS.DROP_POLICY('SCOTT', 'EMP', 'EMP_DEPT_POLCY')
BEGIN DBMS_RLS.DROP_POLICY('SCOTT', 'EMP', 'EMP_DEPT_POLCY'); END;

*
ERROR at line 1:
ORA-28102: policy does not exist
ORA-06512: at "SYS.DBMS_RLS_INT", line 133
ORA-06512: at "SYS.DBMS_RLS", line 151
ORA-06512: at line 1


SYSADMIN_VPD@orcl> EXEC DBMS_RLS.DROP_POLICY('SCOTT', 'EMP', 'EMP_DEPT_POLICY')

PL/SQL procedure successfully completed.

-- ★ ENABLE_POLICY(..., FALSE) 로 끄면 즉시 14건이 보인다. 정의는 남아 있어 TRUE 로 다시 켠다.
--    이름을 틀리면 ORA-28102: policy does not exist. 철자를 고쳐 다시 실행했다.

-- - EXEMPT ACCESS POLICY 와 SYS 접속은 모든 정책을 우회한다.
-- - 이 장에서 만든 sysadmin_vpd·HR_CONTEXT·정책을 모두 지웠다.
