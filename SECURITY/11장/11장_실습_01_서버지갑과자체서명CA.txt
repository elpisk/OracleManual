================================================================================
 제11장 실습 01 — 서버 지갑과 자체 서명 CA
 대상    : oel7v9 (서버·클라이언트 역할을 디렉터리로 나눔), oracle OS 사용자
 목표    : orapki 로 서버 지갑을 만들고 자체 서명 인증서를 CA 로 준비한다.
          원본 자료의 512비트 키와 같은 디렉터리 재생성이 19.3 에서 어떻게 동작하는지 확인한다
 소요    : 약 20분
 변경    : /home/oracle/tls 아래 지갑·설정 (05 에서 철거). 공용 network/admin 은 건드리지 않음
================================================================================

--------------------------------------------------------------------------------
 [1] 작업 디렉터리와 기준 상태
--------------------------------------------------------------------------------

-- 원본 자료의 orcl(서버)·prod(클라이언트) 두 머신을 한 VM 의 디렉터리 네 개로 나눠 흉내 낸다.
-- 공용 설정 파일의 md5 를 기록해 두고 05 에서 다시 비교한다.

[oracle@oel7v9 ~]$ mkdir -p /home/oracle/tls/server_wallet /home/oracle/tls/client_wallet /home/oracle/tls/server_tns /home/oracle/tls/client_tns
[oracle@oel7v9 ~]$ chmod 700 /home/oracle/tls
[oracle@oel7v9 ~]$ md5sum $ORACLE_HOME/network/admin/*.ora
10d7442986929ce050326f853ae81d8a  /u01/app/oracle/product/19.3.0/dbhome_1/network/admin/listener.ora
4842bc60cd301476deead5025d27f03e  /u01/app/oracle/product/19.3.0/dbhome_1/network/admin/sqlnet.ora
14f51ab7a8f0f31b6329300054a4fd18  /u01/app/oracle/product/19.3.0/dbhome_1/network/admin/tnsnames.ora
[oracle@oel7v9 ~]$ lsnrctl status | grep -i 'Listening\|Alias'
Alias                     LISTENER
Listening Endpoints Summary...

-- ★ 기존 리스너 LISTENER 만 떠 있다. TCPS 주소는 없다.

--------------------------------------------------------------------------------
 [2] 서버 지갑 생성 (auto-login)
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ orapki wallet create -wallet /home/oracle/tls/server_wallet -pwd 'Server#2026' -auto_login
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 ~]$ ls -l /home/oracle/tls/server_wallet
total 8
-rw-------. 1 oracle dba 194 Oct 27 20:33 cwallet.sso
-rw-------. 1 oracle dba   0 Oct 27 20:33 cwallet.sso.lck
-rw-------. 1 oracle dba 149 Oct 27 20:33 ewallet.p12
-rw-------. 1 oracle dba   0 Oct 27 20:33 ewallet.p12.lck

-- ★ -auto_login 으로 cwallet.sso 가 함께 생겼다. 리스너와 서버 프로세스는 비밀번호를 입력할 수 없으므로 TLS 지갑은 auto-login 이어야 한다.
--    실습 기록을 위해 -pwd 를 명령행에 썼다. 운영에서는 -pwd 를 빼고 대화식으로 입력한다.

--------------------------------------------------------------------------------
 [3] 원본 그대로 512비트 키로 자체 서명 인증서
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ orapki wallet add -wallet /home/oracle/tls/server_wallet -dn 'CN=server' -keysize 512 -self_signed -validity 365 -pwd 'Server#2026'
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 ~]$ orapki wallet display -wallet /home/oracle/tls/server_wallet
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Requested Certificates: 
User Certificates:
Subject:        CN=server
Trusted Certificates: 
Subject:        CN=server

-- ★ 19.3 의 orapki 는 512비트 키를 거부하지 않았다. 명령이 성공했다고 안전한 키 길이라는 뜻은 아니다.
--    자체 서명 인증서는 User Certificates 와 Trusted Certificates 양쪽에 같은 DN 으로 들어간다.
--    이 인증서가 CA 역할을 한다.

--------------------------------------------------------------------------------
 [4] 함정 — 같은 디렉터리에 다시 create
--------------------------------------------------------------------------------

-- 512비트 인증서를 버리고 새로 만들려고 같은 디렉터리에 wallet create 를 다시 실행한다.

[oracle@oel7v9 ~]$ orapki wallet create -wallet /home/oracle/tls/server_wallet -pwd 'Server#2026' -auto_login
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 ~]$ orapki wallet display -wallet /home/oracle/tls/server_wallet
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Requested Certificates: 
User Certificates:
Subject:        CN=server
Trusted Certificates: 
Subject:        CN=server

-- ★ "successfully completed" 가 나왔지만 기존 CN=server 인증서가 그대로 남아 있다. create 는 기존 지갑을 비우지 않는다.
--    이 상태에서 새 인증서를 추가하면 같은 지갑에 여러 사용자 인증서가 섞인다. 예비 시험에서 이렇게 섞인 지갑으로
--    접속하자 클라이언트가 ORA-29024: Certificate validation failure 로 모두 실패했다.

--------------------------------------------------------------------------------
 [5] 오류 재현과 조치 — 지갑을 비우고 2048비트로
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ rm -f /home/oracle/tls/server_wallet/*
[oracle@oel7v9 ~]$ orapki wallet create -wallet /home/oracle/tls/server_wallet -pwd 'Server#2026' -auto_login
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 ~]$ orapki wallet add -wallet /home/oracle/tls/server_wallet -dn 'CN=oel7v9,O=itwill,C=KR' -keysize 2048 -self_signed -validity 365 -pwd 'server2026'
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

oracle.security.crypto.core.CipherException: Invalid padding string (or incorrect password)
PKI-02003: Unable to load the wallet at: /home/oracle/tls/server_wallet
[oracle@oel7v9 ~]$ orapki wallet add -wallet /home/oracle/tls/server_wallet -dn 'CN=oel7v9,O=itwill,C=KR' -keysize 2048 -self_signed -validity 365 -pwd 'Server#2026'
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 ~]$ orapki wallet display -wallet /home/oracle/tls/server_wallet
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Requested Certificates: 
User Certificates:
Subject:        CN=oel7v9,O=itwill,C=KR
Trusted Certificates: 
Subject:        CN=oel7v9,O=itwill,C=KR

-- ★ 지갑 파일을 지우고 새로 만들었다. 지갑 비밀번호를 틀리게 주면 PKI-02003: Unable to load the wallet
--    (앞줄의 incorrect password 가 원인). 올바른 비밀번호로 2048비트 인증서를 넣었다.
--    지갑에는 CN=oel7v9,O=itwill,C=KR 하나만 있다.

--------------------------------------------------------------------------------
 [6] CA 인증서 내보내기
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ cd /home/oracle/tls
[oracle@oel7v9 tls]$ orapki wallet export -wallet /home/oracle/tls/server_wallet -dn 'CN=server' -cert ./server_ca.cert
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Please check DN, could not found certificate with matching DN.
[oracle@oel7v9 tls]$ orapki wallet export -wallet /home/oracle/tls/server_wallet -dn 'CN=oel7v9,O=itwill,C=KR' -cert ./server_ca.cert
Oracle PKI Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Operation is successfully completed.
[oracle@oel7v9 tls]$ head -3 server_ca.cert
-----BEGIN CERTIFICATE-----
MIIC4jCCAcoCEQCpGqvcY5DGSOl8UoWXRJhVMA0GCSqGSIb3DQEBCwUAMC8xCzAJ
BgNVBAYTAktSMQ8wDQYDVQQKEwZpdHdpbGwxDzANBgNVBAMTBm9lbDd2OTAeFw0y

-- ★ 옛 DN(CN=server)으로 내보내려 하자 "could not found certificate with matching DN". 지갑에 없는 DN 이다.
--    올바른 DN 으로 내보낸 server_ca.cert 는 Base64(PEM) 형식이다. 이 파일을 클라이언트 지갑의 신뢰 인증서로 넣는다.

================================================================================
 정리
================================================================================

-- - TLS 지갑은 auto-login 으로 만든다.
-- - 19.3 orapki 는 512비트 키도, 기존 지갑 위의 create 도 오류 없이 받아들인다. 결과를 orapki wallet display 로 직접 확인한다.
-- - 섞인 지갑은 지우고 새로 만든다. 2048비트 이상을 쓴다.
