================================================================================
 제5장 실습 01 — 링크 생성과 링크 유형
 대상    : oel7v9 orcl(로컬) → sales(원격), 같은 서버의 두 인스턴스
 목표    : 고정 사용자 링크와 연결 사용자 링크를 만들고, 생성 시점이 아니라 사용 시점에
          드러나는 오류(ORA-01017, ORA-12154, ORA-02085)를 구분한다
 소요    : 약 25분
 변경    : orcl: sec05_own 사용자와 링크 3개 / sales: sec05_rmt·sec05_own 사용자 (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] 기준 상태
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> COL owner FOR a10
SYS@orcl> COL db_link FOR a12
SYS@orcl> COL username FOR a12
SYS@orcl> COL host FOR a8
SYS@orcl> COL valid FOR a5
SYS@orcl> SELECT owner, db_link, username, host FROM dba_db_links ORDER BY 1, 2;

OWNER      DB_LINK      USERNAME     HOST
---------- ------------ ------------ --------
PHR        REMOTE_PDB   HR           pdb
SYS        SYS_HUB                   SEEDDATA

SYS@orcl> SHOW PARAMETER global_names

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
global_names                         boolean     FALSE
SYS@orcl> SELECT * FROM global_name;

------------------------------------------------------------------------------------------------------------------------
ORCL

1 row selected.

-- ★ 기존 링크는 실습과 무관한 두 개뿐이다. GLOBAL_NAMES 는 FALSE, orcl 의 전역 이름은 ORCL 이다.

--------------------------------------------------------------------------------
 [2] 원격(sales) 계정과 테이블 준비
--------------------------------------------------------------------------------

-- 원격 DB 의 SYSTEM 으로 접속해 링크가 접속할 계정을 만든다. 프롬프트가 SYSTEM@SALES 로 바뀐다.

SQL> CONNECT system/oracle_4U@SALES
Connected.
SYSTEM@SALES> CREATE USER sec05_rmt IDENTIFIED BY sec05_rmt QUOTA 10M ON users;

User created.

SYSTEM@SALES> GRANT CREATE SESSION, CREATE TABLE TO sec05_rmt;

Grant succeeded.

SYSTEM@SALES> CREATE TABLE sec05_rmt.emp AS
  2    SELECT employee_id AS empno, last_name AS ename, salary AS sal, department_id AS deptno
  3      FROM hr.employees WHERE department_id IN (10, 20, 30);

Table created.

SYSTEM@SALES> SELECT COUNT(*) FROM sec05_rmt.emp;

  COUNT(*)
----------
         9

1 row selected.

-- ★ 원격 테이블 emp 는 sales 의 HR.EMPLOYEES 에서 10·20·30번 부서 9명을 복사했다.

--------------------------------------------------------------------------------
 [3] 로컬(orcl) 링크 소유자 준비
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> CREATE USER sec05_own IDENTIFIED BY sec05_own;

User created.

SYS@orcl> GRANT CREATE SESSION, CREATE DATABASE LINK, CREATE PROCEDURE, CREATE VIEW TO sec05_own;

Grant succeeded.

-- ★ 링크를 만들려면 CREATE DATABASE LINK 시스템 권한이 필요하다. 프로시저·뷰는 02 에서 쓴다.

--------------------------------------------------------------------------------
 [4] 오류 재현 — 잘못된 비밀번호와 잘못된 별칭
--------------------------------------------------------------------------------

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> CREATE DATABASE LINK sales_lnk
  2    CONNECT TO sec05_rmt IDENTIFIED BY wrong_pw
  3    USING 'SALES';

Database link created.

SEC05_OWN@orcl> SELECT COUNT(*) FROM emp@sales_lnk;
SELECT COUNT(*) FROM emp@sales_lnk
                         *
ERROR at line 1:
ORA-01017: invalid username/password; logon denied
ORA-02063: preceding line from SALES_LNK


SEC05_OWN@orcl> CREATE DATABASE LINK sales_bad
  2    CONNECT TO sec05_rmt IDENTIFIED BY sec05_rmt
  3    USING 'SALSE';

Database link created.

SEC05_OWN@orcl> SELECT COUNT(*) FROM emp@sales_bad;
SELECT COUNT(*) FROM emp@sales_bad
                         *
ERROR at line 1:
ORA-12154: TNS:could not resolve the connect identifier specified

-- ★ 두 링크 모두 'Database link created.' 로 만들어졌다. CREATE DATABASE LINK 는 접속을 시험하지 않는다.
--    비밀번호가 틀린 링크는 처음 쓰는 순간 ORA-01017 과 함께 ORA-02063(어느 링크에서 온 오류인지)을 낸다.
--    USING 의 별칭 SALSE 는 로컬 tnsnames.ora 에 없어 ORA-12154 가 난다. 별칭은 로컬 서버에서 해석된다.

--------------------------------------------------------------------------------
 [5] 조치 — 다시 만들고 확인
--------------------------------------------------------------------------------

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> DROP DATABASE LINK sales_bad;

Database link dropped.

SEC05_OWN@orcl> DROP DATABASE LINK sales_lnk;

Database link dropped.

SEC05_OWN@orcl> CREATE DATABASE LINK sales_lnk
  2    CONNECT TO sec05_rmt IDENTIFIED BY sec05_rmt
  3    USING 'SALES';

Database link created.

SEC05_OWN@orcl> SELECT COUNT(*) FROM emp@sales_lnk;

  COUNT(*)
----------
         9

1 row selected.

SEC05_OWN@orcl> COL global_name FOR a12
SEC05_OWN@orcl> SELECT * FROM global_name@sales_lnk;

GLOBAL_NAME
------------
SALES

1 row selected.

SEC05_OWN@orcl> SELECT USER FROM dual@sales_lnk;

USER
------------------------------------------------------------------------------------------------------------------------
SEC05_OWN

1 row selected.

SEC05_OWN@orcl> COL username FOR a12
SEC05_OWN@orcl> SELECT username FROM user_users@sales_lnk;

USERNAME
------------
SEC05_RMT

1 row selected.

-- ★ 링크를 다시 만들자 9건이 조회된다.
--    SELECT USER FROM dual@sales_lnk 는 SEC05_OWN(로컬 사용자)을 돌려준다. USER 는 로컬에서 평가된다.
--    원격에서 실제로 접속한 계정은 user_users@sales_lnk 처럼 원격 뷰를 조회해야 보인다. SEC05_RMT 다.

--------------------------------------------------------------------------------
 [6] 연결 사용자 링크 — 원격에 같은 계정이 없으면
--------------------------------------------------------------------------------

-- CONNECT TO 절이 없는 링크는 현재 세션의 사용자 이름과 비밀번호로 원격에 접속한다.

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> CREATE DATABASE LINK sales_cu USING 'SALES';

Database link created.

SEC05_OWN@orcl> SELECT username FROM user_users@sales_cu;
SELECT username FROM user_users@sales_cu
                                *
ERROR at line 1:
ORA-01017: invalid username/password; logon denied
ORA-02063: preceding line from SALES_CU


SEC05_OWN@orcl> CONNECT system/oracle_4U@SALES
Connected.
SYSTEM@SALES> CREATE USER sec05_own IDENTIFIED BY sec05_own;

User created.

SYSTEM@SALES> GRANT CREATE SESSION TO sec05_own;

Grant succeeded.

SYSTEM@SALES> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> COL username FOR a12
SEC05_OWN@orcl> SELECT username FROM user_users@sales_cu;

USERNAME
------------
SEC05_OWN

1 row selected.

-- ★ 원격 sales 에 SEC05_OWN 이 없을 때는 ORA-01017. 같은 이름·비밀번호의 계정을 원격에 만들자 접속된다.
--    링크에 비밀번호가 저장되지 않는 대신, 두 DB 의 계정과 비밀번호를 맞춰 관리해야 한다.

--------------------------------------------------------------------------------
 [7] 오류 재현 — GLOBAL_NAMES = TRUE
--------------------------------------------------------------------------------

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> ALTER SESSION SET global_names = TRUE;

Session altered.

SEC05_OWN@orcl> COL username FOR a12
SEC05_OWN@orcl> SELECT username FROM user_users@sales_lnk;
SELECT username FROM user_users@sales_lnk
                                *
ERROR at line 1:
ORA-02085: database link SALES_LNK connects to SALES


SEC05_OWN@orcl> CREATE DATABASE LINK sales
  2    CONNECT TO sec05_rmt IDENTIFIED BY sec05_rmt
  3    USING 'SALES';

Database link created.

SEC05_OWN@orcl> SELECT username FROM user_users@sales;

USERNAME
------------
SEC05_RMT

1 row selected.

SEC05_OWN@orcl> ALTER SESSION SET global_names = FALSE;

Session altered.

-- ★ GLOBAL_NAMES 를 켜면 링크 이름이 원격 DB 의 전역 이름과 같아야 한다.
--    SALES_LNK 는 ORA-02085 로 거부되고, 이름이 SALES 인 링크는 동작한다.
--    링크 이름만 보고 어느 DB 로 가는지 알 수 있게 강제하는 설정이다. 세션 수준으로 바꿨다가 되돌렸다.

--------------------------------------------------------------------------------

OWNER      DB_LINK      USERNAME     HOST     VALID
---------- ------------ ------------ -------- -----
SEC05_OWN  SALES        SEC05_RMT    SALES    YES
SEC05_OWN  SALES_CU                  SALES    YES
SEC05_OWN  SALES_LNK    SEC05_RMT    SALES    YES

3 rows selected.

-- ★ 고정 사용자 링크는 USERNAME 에 원격 계정이, 연결 사용자 링크는 빈 값이 나온다.
--    19c 의 DBA_DB_LINKS 에는 VALID 열이 있다. 비밀번호가 틀려도 YES 로 남으므로 접속 가능 여부의 근거는 아니다.

================================================================================
 정리
================================================================================

-- - CREATE DATABASE LINK 는 접속을 검증하지 않는다. 첫 사용에서 ORA-01017/ORA-12154 로 드러난다.
-- - USING 별칭은 링크를 만든 로컬 서버의 tnsnames.ora 로 해석된다.
-- - 고정 사용자 링크 = 링크에 원격 계정 저장 / 연결 사용자 링크 = 세션 계정으로 접속.
-- - 원격 접속 계정 확인은 USER 가 아니라 user_users@링크 로 한다.
