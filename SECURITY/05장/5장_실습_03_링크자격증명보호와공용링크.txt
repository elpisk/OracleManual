 제5장 실습 03 — 링크 자격 증명 보호와 공용 링크
 대상    : oel7v9 orcl → sales
 목표    : 링크에 저장된 비밀번호가 어디에 어떤 형태로 남는지, 원격 비밀번호를 바꿨을 때
          링크를 고치는 방법(ALTER DATABASE LINK)과 그 권한, 공용 링크의 위험을 확인한다
 소요    : 약 25분
 변경    : sales: sec05_rmt 비밀번호 변경 / orcl: sec05_own 에 ALTER DATABASE LINK 권한, 공용 링크 생성 후 삭제

--------------------------------------------------------------------------------
 [2] DBA 계정이 LINK$ 를 읽으면
--------------------------------------------------------------------------------

SQL> CONNECT system/oracle
Connected.
SYSTEM@orcl> SELECT name, userid FROM sys.link$;
SELECT name, userid FROM sys.link$
                             *
ERROR at line 1:
ORA-01031: insufficient privileges


SYSTEM@orcl> SELECT COUNT(*) FROM dba_db_links;

  COUNT(*)
----------
         5

1 row selected.

-- ★ DBA 역할을 가진 SYSTEM 도 SYS.LINK$ 는 ORA-01031 로 막힌다. SELECT ANY DICTIONARY 에서
--    LINK$ 같은 민감한 딕셔너리 테이블은 제외되어 있다. DBA_DB_LINKS 는 볼 수 있다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 원격 비밀번호 교체
--------------------------------------------------------------------------------

SQL> CONNECT system/oracle_4U@SALES
Connected.
SYSTEM@SALES> ALTER USER sec05_rmt IDENTIFIED BY sec05_new;

User altered.

SYSTEM@SALES> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> SELECT COUNT(*) FROM emp@sales_lnk;
SELECT COUNT(*) FROM emp@sales_lnk
                         *
ERROR at line 1:
ORA-01017: invalid username/password; logon denied
ORA-02063: preceding line from SALES_LNK

-- ★ 원격 계정 비밀번호를 바꾸자 링크가 ORA-01017 로 실패한다. 링크는 옛 비밀번호를 그대로 들고 있다.
--    비밀번호 만료 정책이 걸린 원격 계정을 링크에 쓰면 정기적으로 같은 장애가 난다.

--------------------------------------------------------------------------------
 [4] 조치 — ALTER DATABASE LINK
--------------------------------------------------------------------------------

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> ALTER DATABASE LINK sales_lnk CONNECT TO sec05_rmt IDENTIFIED BY sec05_new;
ALTER DATABASE LINK sales_lnk CONNECT TO sec05_rmt IDENTIFIED BY sec05_new
*
ERROR at line 1:
ORA-01031: insufficient privileges


SEC05_OWN@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT ALTER DATABASE LINK TO sec05_own;

Grant succeeded.

SYS@orcl> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> ALTER DATABASE LINK sales_lnk CONNECT TO sec05_rmt IDENTIFIED BY sec05_new;

Database link altered.

SEC05_OWN@orcl> SELECT COUNT(*) FROM emp@sales_lnk;

  COUNT(*)
----------
         9

1 row selected.

SEC05_OWN@orcl> CONNECT hr/hr
Connected.
HR@orcl> SELECT COUNT(*) FROM rmt_emp;

  COUNT(*)
----------
         9

1 row selected.

-- ★ 링크 소유자도 ALTER DATABASE LINK 는 ORA-01031. 이 명령은 별도 시스템 권한(ALTER DATABASE LINK)이 필요하다.
--    권한을 받은 뒤 비밀번호만 바꾸자 링크와 그 링크를 쓰는 뷰(HR 의 rmt_emp)가 함께 살아났다.
--    DROP/CREATE 와 달리 뷰·프로시저가 INVALID 를 거치지 않는다.

--------------------------------------------------------------------------------
 [5] CURRENT_USER 링크
--------------------------------------------------------------------------------

SQL> CONNECT sec05_own/sec05_own
Connected.
SEC05_OWN@orcl> CREATE DATABASE LINK sales_curr CONNECT TO CURRENT_USER USING 'SALES';

Database link created.

SEC05_OWN@orcl> SELECT username FROM user_users@sales_curr;
SELECT username FROM user_users@sales_curr
                                *
ERROR at line 1:
ORA-01017: invalid username/password; logon denied


SEC05_OWN@orcl> DROP DATABASE LINK sales_curr;

Database link dropped.

-- ★ CONNECT TO CURRENT_USER 링크는 만들어지지만 로컬 DB 계정으로는 ORA-01017 로 접속하지 못한다.
--    current user 링크는 두 DB 가 모두 아는 전역 사용자(Enterprise User Security)를 전제로 한다.

--------------------------------------------------------------------------------
 [6] 공용 링크의 위험
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> CREATE PUBLIC DATABASE LINK sec05_pub
  2    CONNECT TO sec05_rmt IDENTIFIED BY sec05_new
  3    USING 'SALES';

Database link created.

SYS@orcl> CONNECT scott/tiger
Connected.
SCOTT@orcl> SELECT COUNT(*) FROM emp@sec05_pub;

  COUNT(*)
----------
         9

1 row selected.

SCOTT@orcl> SELECT USER FROM dual@sec05_pub;

USER
------------------------------------------------------------------------------------------------------------------------
SCOTT

1 row selected.

SCOTT@orcl> COL username FOR a12
SCOTT@orcl> SELECT username FROM user_users@sec05_pub;

USERNAME
------------
SEC05_RMT

1 row selected.

SCOTT@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> DROP PUBLIC DATABASE LINK sec05_pub;

Database link dropped.

SYS@orcl> CONNECT scott/tiger
Connected.
SCOTT@orcl> SELECT COUNT(*) FROM emp@sec05_pub;
SELECT COUNT(*) FROM emp@sec05_pub
                         *
ERROR at line 1:
ORA-02019: connection description for remote database not found

-- ★ SYS 가 만든 공용 링크는 아무 권한도 받지 않은 SCOTT 도 쓸 수 있다. 원격에서는 SEC05_RMT 로 접속된다.
--    USER 는 여기서도 로컬 사용자(SCOTT)를 돌려주므로, 원격 계정은 user_users 로 확인했다.
--    공용 링크를 지우자 SCOTT 는 ORA-02019. 공용 링크 = 원격 계정을 DB 의 모든 사용자와 공유.

--------------------------------------------------------------------------------
 [7] 링크를 만들 수 있는 계정
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> COL grantee FOR a24
SYS@orcl> SELECT grantee, privilege FROM dba_sys_privs
  2   WHERE privilege IN ('CREATE DATABASE LINK', 'CREATE PUBLIC DATABASE LINK', 'DROP PUBLIC DATABASE LINK')
  3     AND grantee NOT IN ('SYS', 'DBA', 'IMP_FULL_DATABASE', 'GSMADMIN_INTERNAL', 'GGSYS', 'RECOVERY_CATALOG_OWNER')
  4   ORDER BY 2, 1;

GRANTEE                  PRIVILEGE
------------------------ ----------------------------------------
BI                       CREATE DATABASE LINK
HR                       CREATE DATABASE LINK
IX                       CREATE DATABASE LINK
OE                       CREATE DATABASE LINK
PHR                      CREATE DATABASE LINK
SEC05_OWN                CREATE DATABASE LINK
SH                       CREATE DATABASE LINK

7 rows selected.

-- ★ 샘플 스키마(BI, HR, IX, OE, SH 등)가 CREATE DATABASE LINK 를 갖고 있다. 이 권한이 있으면
--    아무 원격 DB 로든 나가는 통로를 만들 수 있다. 업무에 필요 없는 계정에서는 회수 대상이다.

================================================================================
 정리
================================================================================

-- - 링크 비밀번호는 SYS.LINK$ 에 암호화(PASSWORDX)되어 저장되고 DBA 도 직접 읽지 못한다.
-- - 원격 비밀번호 변경 → ALTER DATABASE LINK ... IDENTIFIED BY (ALTER DATABASE LINK 권한 필요).
-- - CURRENT_USER 링크는 전역 사용자 환경에서만 의미가 있다.
-- - 공용 링크는 저장된 원격 계정 권한을 모든 사용자에게 열어 준다.
