--------------------------------------------------------------------------------
 [2] 프록시 세션 식별
--------------------------------------------------------------------------------

-- 프록시 세션을 하나 띄워 둔 채 다른 세션에서 조회해야 하므로 셸에서 백그라운드 세션을 연다.

[oracle@oel7v9 ~]$ echo 'EXEC DBMS_SESSION.SLEEP(20)' | sqlplus -s 'prx_app[prx_user1]/prx_app' > /dev/null &
[oracle@oel7v9 ~]$ sleep 3
[oracle@oel7v9 ~]$ echo "SELECT s.sid, s.username, i.authentication_type, i.osuser FROM v\$session s JOIN v\$session_connect_info i ON s.sid = i.sid WHERE s.username = 'PRX_USER1' AND ROWNUM = 1;" > /tmp/prx_q.sql
[oracle@oel7v9 ~]$ sqlplus -s / as sysdba @/tmp/prx_q.sql < /dev/null

       SID
----------
USERNAME
--------------------------------------------------------------------------------
AUTHENTICATION_TYPE
--------------------------
OSUSER
--------------------------------------------------------------------------------
       223
PRX_USER1
PROXY
oracle


[oracle@oel7v9 ~]$ rm -f /tmp/prx_q.sql
[oracle@oel7v9 ~]$ wait

-- ★ V$SESSION_CONNECT_INFO.AUTHENTICATION_TYPE 이 PROXY 로 나온다.
--    V$SESSION.USERNAME 은 대상 사용자 PRX_USER1 이다. 운영 중 프록시 세션을 골라낼 때 이 열을 쓴다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 프록시 계정 잠금
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER prx_app ACCOUNT LOCK;

User altered.

SYS@orcl> CONNECT prx_app[prx_user1]/prx_app
ERROR:
ORA-28000: The account is locked.


Warning: You are no longer connected to ORACLE.
SYS@orcl> CONNECT prx_user1/prx_user1
Connected.
PRX_USER1@orcl> SHOW USER
USER is "PRX_USER1"
PRX_USER1@orcl> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER prx_app ACCOUNT UNLOCK;

User altered.

-- ★ 프록시 계정이 잠기면 그 계정을 거치는 모든 대상 사용자 접속이 ORA-28000 으로 막힌다.
--    prx_user1 의 직접 접속에는 영향이 없다. 애플리케이션 서버 계정 하나를 잠그면 그 서버만 차단된다.
--    UNLOCK 으로 되돌렸다.

--    DBA_PROXIES 에서 prx_user1 행이 사라졌다.

--    AUDIT_UNIFIED_ENABLED_POLICIES 에서 켜진 대상을 확인하고 NOAUDIT ... BY prx_app 으로 끈 뒤 삭제했다.
--    사용자 0, 역할 0, 정책 0. 실습 전 상태와 같다. 감사 기록 자체는 감사 기록 관리(13장) 몫이라 남겨 둔다.
