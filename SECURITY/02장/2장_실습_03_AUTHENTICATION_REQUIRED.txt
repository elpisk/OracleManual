================================================================================
 제2장 실습 03 — AUTHENTICATION REQUIRED
 대상    : oel7v9 orcl
 목표    : 대상 사용자의 자격 증명을 요구하는 프록시 허용과,
          원본 자료의 옛 문법(AUTHENTICATED USING PASSWORD)이 19c 에서 어떻게 처리되는지 확인한다
 소요    : 약 15분
 변경    : prx_user3 생성 (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] AUTHENTICATION REQUIRED 로 허용
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> CREATE USER prx_user3 IDENTIFIED BY prx_user3;

User created.

SYS@orcl> GRANT CREATE SESSION TO prx_user3;

Grant succeeded.

SYS@orcl> ALTER USER prx_user3 GRANT CONNECT THROUGH prx_app AUTHENTICATION REQUIRED;

User altered.

SYS@orcl> COL proxy FOR a10
SYS@orcl> COL client FOR a10
SYS@orcl> SELECT proxy, client, authentication, authorization_constraint FROM dba_proxies WHERE client = 'PRX_USER3';

PROXY      CLIENT     AUT AUTHORIZATION_CONSTRAINT
---------- ---------- --- -----------------------------------
PRX_APP    PRX_USER3  YES PROXY MAY ACTIVATE ALL CLIENT ROLES

1 row selected.

-- ★ AUTHENTICATION 이 YES 다. 프록시가 대상 사용자의 비밀번호까지 제시해야 한다.

--------------------------------------------------------------------------------
 [2] 오류 재현 — 비밀번호 없이 대신 접속
--------------------------------------------------------------------------------

SQL> CONNECT prx_app[prx_user3]/prx_app
ERROR:
ORA-28150: proxy not authorized to connect as client

-- ★ ORA-28150: proxy not authorized to connect as client.
--    SQL*Plus 의 프록시[대상] 형식은 프록시 비밀번호만 넘기므로 이 조건을 만족시킬 방법이 없다.
--    대상 사용자 비밀번호를 함께 넘기는 것은 OCI·JDBC 프록시 세션 API 의 몫이다.

--------------------------------------------------------------------------------
 [3] 옛 문법으로 부여해 보기
--------------------------------------------------------------------------------

-- 원본 자료는 AUTHENTICATED USING PASSWORD / DISTINGUISHED NAME / CERTIFICATE 형식을 소개한다.

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER prx_user3 GRANT CONNECT THROUGH prx_app AUTHENTICATED USING PASSWORD;

User altered.

SYS@orcl> COL proxy FOR a10
SYS@orcl> COL client FOR a10
SYS@orcl> SELECT proxy, client, authentication, authorization_constraint FROM dba_proxies WHERE client = 'PRX_USER3';

PROXY      CLIENT     AUT AUTHORIZATION_CONSTRAINT
---------- ---------- --- -----------------------------------
PRX_APP    PRX_USER3  YES PROXY MAY ACTIVATE ALL CLIENT ROLES

1 row selected.

-- ★ 19c 에서도 오류 없이 받아들인다. 결과는 AUTHENTICATION=YES 로 AUTHENTICATION REQUIRED 와 같다.
--    SQL Language Reference 19c 는 AUTHENTICATED USING 절을 디프리케이트로 분류하고, PASSWORD 는
--    AUTHENTICATION REQUIRED 로 변환되며 DN·CERTIFICATE 는 이 절을 생략한 것과 같다고 적고 있다.

--------------------------------------------------------------------------------
 [4] 조치 — 인증 요구 해제 후 재확인
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER prx_user3 GRANT CONNECT THROUGH prx_app;

User altered.

SYS@orcl> COL proxy FOR a10
SYS@orcl> COL client FOR a10
SYS@orcl> SELECT proxy, client, authentication FROM dba_proxies WHERE client = 'PRX_USER3';

PROXY      CLIENT     AUT
---------- ---------- ---
PRX_APP    PRX_USER3  NO

1 row selected.

SYS@orcl> CONNECT prx_app[prx_user3]/prx_app
Connected.
PRX_USER3@orcl> SHOW USER
USER is "PRX_USER3"

-- ★ 조건 없이 다시 GRANT 하면 AUTHENTICATION 이 NO 로 바뀌고 접속된다.
--    같은 프록시·대상 쌍에 GRANT 를 다시 실행하면 이전 조건을 덮어쓴다.

================================================================================
 정리
================================================================================

-- - AUTHENTICATION REQUIRED: 프록시가 대상 사용자의 비밀번호도 제시해야 한다. 없으면 ORA-28150.
-- - AUTHENTICATED USING PASSWORD 는 19c 에서 AUTHENTICATION REQUIRED 로 변환된다(디프리케이트 문법).
-- - 같은 쌍에 다시 GRANT 하면 조건이 바뀐다. 조건 변경에 REVOKE 가 필요 없다.
