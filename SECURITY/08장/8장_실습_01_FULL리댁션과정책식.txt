================================================================================
 제8장 실습 01 — FULL 리댁션과 정책 식
 대상    : oel7v9 orcl (non-CDB, 19.3)
 목표    : HR.EMPLOYEES.SALARY 에 FULL 리댁션 정책을 걸고,
          정책 식(expression)에 따라 사용자마다 다른 값이 보이는 것을 확인한다
 소요    : 약 20분
 변경    : 사용자 sking 생성, HR 에 DBMS_REDACT 실행 권한, SCOTT 에 SELECT 권한 (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] 기준 상태
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> COL first_name FOR a10
SYS@orcl> COL last_name FOR a10
SYS@orcl> COL phone_number FOR a14
SYS@orcl> SELECT COUNT(*) FROM redaction_policies;

  COUNT(*)
----------
         0

SYS@orcl> SELECT employee_id, first_name, salary FROM hr.employees WHERE employee_id BETWEEN 100 AND 104 ORDER BY 1;

EMPLOYEE_ID FIRST_NAME     SALARY
----------- ---------- ----------
        100 Steven          24000
        101 Neena           17000
        102 Lex             17000
        103 Alexander        9000
        104 Bruce            6000

5 rows selected.

-- ★ 리댁션 정책은 하나도 없다. 100~104번 사원의 급여는 24000, 17000, 17000, 9000, 6000 이다.

--------------------------------------------------------------------------------
 [2] 사용자와 권한
--------------------------------------------------------------------------------

-- 원본 실습과 같은 구성이다. sking 은 가려진 값을, scott 은 원래 값을 보게 될 사용자다.

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> CREATE USER sking IDENTIFIED BY sking;

User created.

SYS@orcl> GRANT CREATE SESSION TO sking;

Grant succeeded.

SYS@orcl> GRANT SELECT ON hr.employees TO sking;

Grant succeeded.

SYS@orcl> GRANT SELECT ON hr.employees TO scott;

Grant succeeded.

-- ★ 리댁션은 SELECT 권한을 막지 않는다. 두 사용자 모두 같은 SELECT 권한을 받는다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — DBMS_REDACT 실행 권한 없이 정책 만들기
--------------------------------------------------------------------------------

SQL> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ADD_POLICY(
  3      object_schema => 'HR',
  4      object_name   => 'EMPLOYEES',
  5      policy_name   => 'MASK_SALARY_POLICY',
  6      expression    => 'SYS_CONTEXT(''USERENV'', ''SESSION_USER'') NOT IN (''SCOTT'', ''HR'')',
  7      column_name   => 'SALARY',
  8      function_type => DBMS_REDACT.FULL);
  9  END;
 10  /
    function_type => DBMS_REDACT.FULL);
                     *
ERROR at line 8:
ORA-06550: line 8, column 22:
PLS-00201: identifier 'DBMS_REDACT' must be declared
ORA-06550: line 2, column 3:
PL/SQL: Statement ignored

-- ★ PLS-00201: identifier 'DBMS_REDACT' must be declared.
--    DBMS_REDACT 는 PUBLIC 에 열려 있지 않다. 19.3 기본 상태에서 실행 권한은
--    EXECUTE_CATALOG_ROLE, IMP_FULL_DATABASE 에만 있다(05 마지막 조회 참고).
--    자기 테이블에 정책을 걸려면 CREATE TABLE 과 DBMS_REDACT 실행 권한이 필요하다.

--------------------------------------------------------------------------------
 [4] 조치 — 실행 권한을 준 뒤 다시 등록
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> GRANT EXECUTE ON DBMS_REDACT TO hr;

Grant succeeded.

SYS@orcl> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ADD_POLICY(
  3      object_schema => 'HR',
  4      object_name   => 'EMPLOYEES',
  5      policy_name   => 'MASK_SALARY_POLICY',
  6      expression    => 'SYS_CONTEXT(''USERENV'', ''SESSION_USER'') NOT IN (''SCOTT'', ''HR'')',
  7      column_name   => 'SALARY',
  8      function_type => DBMS_REDACT.FULL);
  9  END;
 10  /

PL/SQL procedure successfully completed.

-- ★ 정책 식은 SCOTT 와 HR 이 아닌 세션에서 TRUE 다. 식이 TRUE 일 때 리댁션이 일어난다.

================================================================================
 정리
================================================================================

-- - 정책 = 객체 + 컬럼 + 리댁션 방식 + 정책 식. 식이 TRUE 인 세션에서 값이 바뀐다.
-- - 정책을 만들려면 DBMS_REDACT 실행 권한이 필요하다(없으면 PLS-00201).
-- - FULL 기본값: 숫자 0, 문자 공백 한 칸, 날짜 2001-01-01.
