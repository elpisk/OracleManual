================================================================================
 제8장 실습 02 — REGEXP 와 PARTIAL
 대상    : oel7v9 orcl (DB 문자셋 AL32UTF8)
 목표    : 주민번호 뒷자리와 전화번호 가운데 자리를 가린다.
          테이블당 정책 하나라는 제약과, 패턴이 맞지 않는 값의 처리를 확인한다
 소요    : 약 25분
 변경    : HR.CUSTOMERS 테이블과 정책 MASK_CUST_POLICY (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] 고객 테이블 준비
--------------------------------------------------------------------------------

-- 원본 실습의 CUSTOMERS 를 그대로 만든다. 5번 고객의 주민번호만 하이픈 없이 넣었다.

SQL> CONNECT hr/hr

--------------------------------------------------------------------------------
 [2] 주민번호 뒷자리 REGEXP 리댁션
--------------------------------------------------------------------------------

SQL> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ADD_POLICY(
  3      object_schema         => 'HR',
  4      object_name           => 'CUSTOMERS',
  5      policy_name           => 'MASK_CUST_POLICY',
  6      expression            => 'SYS_CONTEXT(''USERENV'', ''SESSION_USER'') != ''HR''',
  7      column_name           => 'SSN_NO',
  8      function_type         => DBMS_REDACT.REGEXP,
  9      regexp_pattern        => '([0-9]{6}-)([0-9]{7})',
 10      regexp_replace_string => '\1#######');
 11  END;
 12  /

PL/SQL procedure successfully completed.

HR@orcl> CONNECT sking/sking
Connected.
SKING@orcl> COL customer_name FOR a12
SKING@orcl> COL ssn_no FOR a16
SKING@orcl> COL phone_number FOR a14
SKING@orcl> SELECT customer_id, customer_name, ssn_no, phone_number FROM hr.customers ORDER BY 1;

CUSTOMER_ID CUSTOMER_NAM SSN_NO           PHONE_NUMBER
----------- ------------ ---------------- --------------
          1 김경인       900101-#######   010-1111-2222
          2 전민경       950515-#######   010-3333-4444
          3 한민지       901225-#######   010-5555-6666
          4 김산         920303-#######   010-7777-8888
          5 성지민                        010-2222-5555

5 rows selected.

-- ★ 패턴에 맞는 1~4번은 앞 6자리와 하이픈만 남고 뒤 7자리가 #로 바뀌었다.
--    5번은 하이픈이 없어 패턴이 맞지 않았다. 이때는 FULL 리댁션이 적용되어 공백으로 나온다.
--    형식이 섞인 데이터에서는 정규식 하나로 모든 값을 다룰 수 없다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 같은 테이블에 두 번째 정책
--------------------------------------------------------------------------------

SQL> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ADD_POLICY(
  3      object_schema => 'HR',
  4      object_name   => 'CUSTOMERS',
  5      policy_name   => 'MASK_PHONE_POLICY',
  6      expression    => '1=1',
  7      column_name   => 'PHONE_NUMBER',
  8      function_type => DBMS_REDACT.FULL);
  9  END;
 10  /
BEGIN
*
ERROR at line 1:
ORA-28069: A data redaction policy already exists on this object.
ORA-06512: at "SYS.DBMS_REDACT_INT", line 3
ORA-06512: at "SYS.DBMS_REDACT", line 21
ORA-06512: at line 2

-- ★ ORA-28069: A data redaction policy already exists on this object.
--    테이블·뷰 하나에는 정책을 하나만 둘 수 있다. 컬럼을 더 가리려면 기존 정책에
--    ALTER_POLICY(ADD_COLUMN)로 컬럼을 추가한다. 정책 식도 하나를 공유한다.

--------------------------------------------------------------------------------
 [4] 조치 — ALTER_POLICY 로 전화번호 컬럼 추가 (문자 PARTIAL)
--------------------------------------------------------------------------------

-- PARTIAL 문자 형식은 '입력 형식,출력 형식,가림 문자,시작,끝' 이다.
-- 매뉴얼은 문자 PARTIAL 에 고정 폭 문자셋을 전제하고, UTF-8 같은 가변 폭 문자셋에는 정규식을 권한다.

SQL> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ALTER_POLICY(
  3      object_schema       => 'HR',
  4      object_name         => 'CUSTOMERS',
  5      policy_name         => 'MASK_CUST_POLICY',
  6      action              => DBMS_REDACT.ADD_COLUMN,
  7      column_name         => 'PHONE_NUMBER',
  8      function_type       => DBMS_REDACT.PARTIAL,
  9      function_parameters => 'VVVFVVVVFVVVV,VVV-VVVV-VVVV,*,4,7');
 10  END;
 11  /

PL/SQL procedure successfully completed.

HR@orcl> CONNECT sking/sking
Connected.
SKING@orcl> COL phone_number FOR a14
SKING@orcl> SELECT customer_id, phone_number FROM hr.customers ORDER BY 1;

CUSTOMER_ID PHONE_NUMBER
----------- --------------
          1 010-****-2222
          2 010-****-4444
          3 010-****-6666
          4 010-****-8888
          5 010-****-5555

5 rows selected.

-- ★ AL32UTF8 인 이 DB 에서도 ASCII 로만 된 전화번호에는 PARTIAL 이 동작했다.
--    4~7번째 자리가 *로 바뀌었다. 한글처럼 여러 바이트 문자가 섞인 컬럼에서는 위치가 어긋날 수 있다.
--    다음 단계에서 매뉴얼 권고대로 REGEXP 로 바꾼다.

--------------------------------------------------------------------------------
 [5] MODIFY_COLUMN 으로 REGEXP 로 바꾸기
--------------------------------------------------------------------------------

SQL> CONNECT hr/hr
Connected.
HR@orcl> BEGIN
  2    DBMS_REDACT.ALTER_POLICY(
  3      object_schema         => 'HR',
  4      object_name           => 'CUSTOMERS',
  5      policy_name           => 'MASK_CUST_POLICY',
  6      action                => DBMS_REDACT.MODIFY_COLUMN,
  7      column_name           => 'PHONE_NUMBER',
  8      function_type         => DBMS_REDACT.REGEXP,
  9      regexp_pattern        => '([0-9]{3})-([0-9]{4})-([0-9]{4})',
 10      regexp_replace_string => '\1-****-\3');
 11  END;
 12  /

PL/SQL procedure successfully completed.

HR@orcl> CONNECT sking/sking
Connected.
SKING@orcl> COL customer_name FOR a12
SKING@orcl> COL ssn_no FOR a16

-- ★ 결과는 같지만 형식이 다른 값이 들어오면 동작이 갈린다. PARTIAL 은 위치로, REGEXP 는 패턴으로 가린다.
--    HR 은 정책 식이 FALSE 라 원래 값(5번의 하이픈 없는 주민번호 포함)을 본다.

================================================================================
 정리
================================================================================

-- - REGEXP: 패턴에 맞는 부분만 치환한다. 패턴이 맞지 않는 값은 FULL 리댁션된다.
-- - 테이블당 정책은 하나(ORA-28069). 컬럼 추가·변경은 ALTER_POLICY 의 ADD_COLUMN·MODIFY_COLUMN.
-- - 문자 PARTIAL 은 고정 폭 전제. 가변 폭 문자셋에서는 REGEXP 를 쓴다.
