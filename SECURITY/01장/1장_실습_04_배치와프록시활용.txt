================================================================================
 제1장 실습 04 — 배치와 프록시 활용
 대상    : oel7v9 orcl, oracle OS 사용자
 목표    : Data Pump 를 /@별칭 으로 실행하고, 크론처럼 환경 변수가 없는 실행에서 생기는 문제를 재현한다.
          프록시 자격 증명(proxy[target])을 지갑에 넣어 쓴다
 소요    : 약 20분
 변경    : 디렉터리 객체 SEPS_DIR, 테이블 SEPS_APP.SEPS_T, 프록시 권한 (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] Data Pump 준비
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> HOST mkdir -p /home/oracle/seps/dp

SYS@orcl> CREATE DIRECTORY seps_dir AS '/home/oracle/seps/dp';

Directory created.

SYS@orcl> GRANT READ, WRITE ON DIRECTORY seps_dir TO seps_app;

Grant succeeded.

SYS@orcl> CREATE TABLE seps_app.seps_t (id NUMBER);

Table created.

SYS@orcl> INSERT INTO seps_app.seps_t VALUES (1);

1 row created.

SYS@orcl> COMMIT;

Commit complete.

-- ★ 디렉터리 객체와 테이블 한 개를 만든다. 디렉터리 권한은 지갑 계정 SEPS_APP 에 준다.

--------------------------------------------------------------------------------
 [2] Data Pump 를 지갑으로 실행
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
 [3] 오류 재현 — 크론처럼 빈 환경에서 실행
--------------------------------------------------------------------------------

-- env -i 로 환경 변수를 모두 지우고 ORACLE_HOME·PATH 만 넘긴다. 크론은 로그인 셸을 거치지 않아 이와 비슷한 환경에서 돈다.

[oracle@oel7v9 ~]$ env -i HOME=/home/oracle ORACLE_HOME=$ORACLE_HOME PATH=$ORACLE_HOME/bin:/usr/bin:/bin bash -c "echo 'SHOW USER' | sqlplus -s -L /@seps_app"
ERROR:
ORA-12154: TNS:could not resolve the connect identifier specified


SP2-0751: Unable to connect to Oracle.  Exiting SQL*Plus
[oracle@oel7v9 ~]$ env -i HOME=/home/oracle ORACLE_HOME=$ORACLE_HOME PATH=$ORACLE_HOME/bin:/usr/bin:/bin TNS_ADMIN=/home/oracle/seps/tns bash -c "echo 'SHOW USER' | sqlplus -s -L /@seps_app"
USER is "SEPS_APP"

-- ★ TNS_ADMIN 이 없으면 공용 $ORACLE_HOME/network/admin 의 tnsnames.ora 를 읽는다. 거기에는 seps_app 별칭이 없어 ORA-12154.
--    TNS_ADMIN 만 더해 주자 같은 명령이 SEPS_APP 으로 접속됐다. 배치 스크립트는 첫 줄에서 TNS_ADMIN 을 설정한다.

--------------------------------------------------------------------------------
 [4] 오류 재현 — CONNECT THROUGH 권한 없이 프록시 자격 증명
--------------------------------------------------------------------------------

-- 사용자 이름 자리에 seps_app[seps_rpt] 를 넣는다. 저장하는 비밀번호는 프록시 사용자 SEPS_APP 의 것이다.

[oracle@oel7v9 ~]$ cd /home/oracle/seps/tns
[oracle@oel7v9 tns]$ printf '%s\n' 'SEPS_PROXY =' '  (DESCRIPTION =' '    (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521))' '    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))' >> tnsnames.ora
[oracle@oel7v9 tns]$ printf 'SepsApp#2\nSepsApp#2\nWallet#2026\n' | mkstore -wrl /home/oracle/seps/wallet -createCredential seps_proxy 'seps_app[seps_rpt]'

[oracle@oel7v9 tns]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 tns]$ echo 'SHOW USER' | sqlplus -s -L /@seps_proxy
ERROR:
ORA-01017: invalid username/password; logon denied


SP2-0751: Unable to connect to Oracle.  Exiting SQL*Plus

-- ★ 프록시 권한이 아직 없어 실패한다. 19.3 에서 이 경우 오류는 ORA-28150 이 아니라 ORA-01017 로 나왔다.
--    메시지만 보면 비밀번호 문제처럼 보이므로, 프록시 자격 증명이 실패하면 PROXY_USERS 부터 확인한다.

--------------------------------------------------------------------------------
 [5] 조치 — 프록시 권한 부여
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER seps_rpt GRANT CONNECT THROUGH seps_app;

User altered.

-- ★ SEPS_RPT 가 SEPS_APP 을 통해 접속하는 것을 허용한다. 프록시 구성의 세부 옵션은 2장에서 다룬다.

--------------------------------------------------------------------------------
 [6] 프록시 실패는 감사 기록에 어떻게 남았나
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> EXEC DBMS_AUDIT_MGMT.FLUSH_UNIFIED_AUDIT_TRAIL

PL/SQL procedure successfully completed.

SYS@orcl> COL t FOR a8
SYS@orcl> COL dbusername FOR a10
SYS@orcl> COL dbproxy_username FOR a10
SYS@orcl> SELECT TO_CHAR(event_timestamp, 'HH24:MI:SS') t, NVL(dbusername, '(null)') dbusername, dbproxy_username, return_code
  2    FROM unified_audit_trail
  3   WHERE return_code <> 0
  4     AND event_timestamp >= (SELECT created FROM dba_users WHERE username = 'SEPS_APP')
  5   ORDER BY event_timestamp;

T        DBUSERNAME DBPROXY_US RETURN_CODE
-------- ---------- ---------- -----------
20:23:28 (null)                       1017
20:23:44 SEPS_APP                     1017
20:24:08 SEPS_RPT   SEPS_APP          1017

3 rows selected.

-- ★ 20:24:08 행이 직전의 프록시 실패다. DBUSERNAME 은 대상 사용자 SEPS_RPT, DBPROXY_USERNAME 은 SEPS_APP 이다.
--    ORA-01017 로만 보이던 실패가 감사 기록에서는 프록시 시도였다는 것까지 드러난다.

--------------------------------------------------------------------------------
 [7] 다시 프록시 접속
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 ~]$ echo "SELECT SUBSTR(SYS_CONTEXT('USERENV','SESSION_USER'),1,10) usr, SUBSTR(SYS_CONTEXT('USERENV','PROXY_USER'),1,10) proxy FROM dual;" | sqlplus -s -L /@seps_proxy

USR
----------------------------------------
PROXY
----------------------------------------
SEPS_RPT
SEPS_APP

-- ★ SESSION_USER 는 SEPS_RPT, PROXY_USER 는 SEPS_APP. 지갑에는 SEPS_RPT 비밀번호가 없다.
--    대상 사용자가 여럿이어도 프록시 계정 하나의 비밀번호만 지갑에 두면 된다.

 정리

-- - expdp 등 OCI 기반 도구는 /@별칭 으로 지갑을 쓴다. 로그에는 비밀번호가 가려진다.
-- - 크론 등 빈 환경에서는 TNS_ADMIN 이 없어 ORA-12154. 스크립트에서 직접 설정한다.
-- - 프록시 자격 증명은 CONNECT THROUGH 권한이 있어야 하고, 없으면 19.3 에서 ORA-01017 로 실패했다.
