================================================================================
 제1장 실습 02 — 클라이언트 구성과 접속
 대상    : oel7v9 orcl, oracle OS 사용자
 목표    : 별도 TNS_ADMIN 에 sqlnet.ora·tnsnames.ora 를 만들고 /@별칭 으로 접속한다.
          WALLET_OVERRIDE 누락과 별칭 누락이 각각 어떤 오류를 내는지 확인한다
 소요    : 약 15분
 변경    : /home/oracle/seps/tns 의 설정 파일 (05 에서 철거)
================================================================================

--------------------------------------------------------------------------------
 [1] 오류 재현 — WALLET_OVERRIDE 없이 접속
--------------------------------------------------------------------------------

-- sqlnet.ora 에 WALLET_LOCATION 만 넣었다. tnsping 은 별칭 주소만 확인한다.

[oracle@oel7v9 ~]$ cd /home/oracle/seps/tns
[oracle@oel7v9 tns]$ printf '%s\n' 'WALLET_LOCATION =' '  (SOURCE =' '    (METHOD = FILE)' '    (METHOD_DATA = (DIRECTORY = /home/oracle/seps/wallet))' '  )' > sqlnet.ora
[oracle@oel7v9 tns]$ printf '%s\n' 'SEPS_APP =' '  (DESCRIPTION =' '    (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521))' '    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))' > tnsnames.ora
[oracle@oel7v9 tns]$ cat sqlnet.ora tnsnames.ora
WALLET_LOCATION =
  (SOURCE =
    (METHOD = FILE)
    (METHOD_DATA = (DIRECTORY = /home/oracle/seps/wallet))
  )
SEPS_APP =
  (DESCRIPTION =
    (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521))
    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))
[oracle@oel7v9 tns]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 tns]$ tnsping seps_app | tail -2
Attempting to contact (DESCRIPTION = (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521)) (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))
OK (0 msec)
[oracle@oel7v9 tns]$ echo 'SHOW USER' | sqlplus -s -L /@seps_app
ERROR:
ORA-01017: invalid username/password; logon denied


SP2-0751: Unable to connect to Oracle.  Exiting SQL*Plus

-- ★ tnsping 은 OK 인데 접속은 ORA-01017.
--    지갑 위치를 알아도 SQLNET.WALLET_OVERRIDE 가 없으면 /@ 접속에 지갑의 자격 증명을 쓰지 않는다.
--    사용자 이름과 비밀번호가 빈 채로 인증을 시도한 셈이다(03 의 감사 기록에서 사용자 이름 없는 실패로 보인다).

--------------------------------------------------------------------------------
 [2] 조치 — SQLNET.WALLET_OVERRIDE = TRUE
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ cd /home/oracle/seps/tns
[oracle@oel7v9 tns]$ echo 'SQLNET.WALLET_OVERRIDE = TRUE' >> sqlnet.ora
[oracle@oel7v9 tns]$ cat sqlnet.ora
WALLET_LOCATION =
  (SOURCE =
    (METHOD = FILE)
    (METHOD_DATA = (DIRECTORY = /home/oracle/seps/wallet))
  )
SQLNET.WALLET_OVERRIDE = TRUE
[oracle@oel7v9 tns]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 tns]$ echo 'SHOW USER' | sqlplus -s -L /@seps_app
USER is "SEPS_APP"

-- ★ 한 줄을 더하자 SEPS_APP 으로 접속됐다. 명령에는 사용자 이름도 비밀번호도 없다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 자격 증명은 있는데 별칭이 없다
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 ~]$ echo 'SHOW USER' | sqlplus -s -L /@seps_rpt
ERROR:
ORA-12154: TNS:could not resolve the connect identifier specified


SP2-0751: Unable to connect to Oracle.  Exiting SQL*Plus
[oracle@oel7v9 ~]$ cd /home/oracle/seps/tns
[oracle@oel7v9 tns]$ printf '%s\n' 'SEPS_RPT =' '  (DESCRIPTION =' '    (ADDRESS = (PROTOCOL = TCP)(HOST = oel7v9)(PORT = 1521))' '    (CONNECT_DATA = (SERVER = DEDICATED)(SERVICE_NAME = orcl)))' >> tnsnames.ora
[oracle@oel7v9 tns]$ echo 'SHOW USER' | sqlplus -s -L /@seps_rpt
USER is "SEPS_RPT"

-- ★ 지갑에는 seps_rpt 자격 증명이 있지만 tnsnames.ora 에 SEPS_RPT 별칭이 없어 ORA-12154.
--    별칭은 주소를, 지갑은 계정을 정한다. 둘 다 있어야 접속된다.
--    별칭을 추가하자 SEPS_RPT 로 접속됐다.

--------------------------------------------------------------------------------
 [4] 접속 정보 확인
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 ~]$ echo "SELECT SUBSTR(SYS_CONTEXT('USERENV','SESSION_USER'),1,10) usr, SUBSTR(SYS_CONTEXT('USERENV','AUTHENTICATION_METHOD'),1,10) auth, SUBSTR(SYS_CONTEXT('USERENV','NETWORK_PROTOCOL'),1,6) proto FROM dual;" | sqlplus -s -L /@seps_app

USR
----------------------------------------
AUTH					 PROTO
---------------------------------------- ------------------------
SEPS_APP
PASSWORD				 tcp


[oracle@oel7v9 ~]$ ps -ef | grep -c '[S]epsApp'
0

-- ★ AUTHENTICATION_METHOD 는 PASSWORD, NETWORK_PROTOCOL 은 tcp.
--    서버 입장에서는 일반 비밀번호 로그인과 구분되지 않는다.
--    ps 출력에서 비밀번호 문자열(SepsApp)을 찾으면 0건이다. 명령행에 비밀번호가 없기 때문이다.

 정리
================================================================================

-- - 클라이언트 sqlnet.ora 에 WALLET_LOCATION 과 SQLNET.WALLET_OVERRIDE = TRUE 가 함께 필요하다(빠지면 ORA-01017).
-- - 접속 문자열이 tnsnames.ora 에 없으면 ORA-12154.
-- - 공용 network/admin 대신 TNS_ADMIN 으로 SEPS 구성을 분리했다.
