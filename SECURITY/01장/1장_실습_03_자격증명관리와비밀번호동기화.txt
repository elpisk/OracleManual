================================================================================
 제1장 실습 03 — 자격 증명 관리와 비밀번호 동기화
 대상    : oel7v9 orcl, oracle OS 사용자
 목표    : 중복 등록, DB 비밀번호 변경 후 동기화, 저장 비밀번호 열람, 삭제를 차례로 해 보고
          실패한 로그인이 감사 기록에 어떻게 남는지 확인한다
 소요    : 약 20분
 변경    : SEPS_APP 비밀번호 변경, seps_rpt 자격 증명 삭제
================================================================================

--------------------------------------------------------------------------------
 [1] 오류 재현 — 같은 접속 문자열로 다시 등록
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ printf 'Other#123\nOther#123\nWallet#2026\n' | mkstore -wrl /home/oracle/seps/wallet -createCredential seps_app seps_rpt
Oracle Secret Store Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Your secret/Password is missing in the command line 
Enter your secret/Password:   
Re-enter your secret/Password:   
Enter wallet password:   
Secret Store error occurred: oracle.security.pki.OracleSecretStoreException: Credential already exists

-- ★ Credential already exists. 같은 접속 문자열(seps_app)에 다른 계정(seps_rpt)을 넣으려 했다.
--    지갑은 접속 문자열을 키로 쓰므로 한 접속 문자열에 자격 증명은 하나뿐이다.

--------------------------------------------------------------------------------
 [2] DB 쪽에서 비밀번호 변경
--------------------------------------------------------------------------------

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> ALTER USER seps_app IDENTIFIED BY "SepsApp#2";

User altered.

-- ★ 정기 비밀번호 변경을 흉내 낸다. 지갑은 이 변경을 모른다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 옛 비밀번호가 남은 지갑
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 ~]$ echo 'SHOW USER' | sqlplus -s -L /@seps_app
ERROR:
ORA-01017: invalid username/password; logon denied


SP2-0751: Unable to connect to Oracle.  Exiting SQL*Plus

-- ★ ORA-01017. 배치가 재시도를 반복하면 실패가 쌓여 계정이 잠긴다(DEFAULT 프로파일 10회).

--------------------------------------------------------------------------------
 [4] 조치 — -modifyCredential 로 지갑 동기화
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ printf 'SepsApp#2\nSepsApp#2\nWallet#2026\n' | mkstore -wrl /home/oracle/seps/wallet -modifyCredential seps_app seps_app
Oracle Secret Store Tool Release 19.0.0.0.0 - Production

[oracle@oel7v9 ~]$ export TNS_ADMIN=/home/oracle/seps/tns
[oracle@oel7v9 ~]$ echo 'SHOW USER' | sqlplus -s -L /@seps_app
USER is "SEPS_APP"

-- ★ 지갑의 비밀번호를 새 값으로 바꾸자 바로 접속된다. 비밀번호 변경 절차에는 이 단계와 접속 확인이 함께 들어가야 한다.

--------------------------------------------------------------------------------
 [5] 저장된 비밀번호 보기
--------------------------------------------------------------------------------

[oracle@oel7v9 ~]$ printf 'Wallet#2026\n' | mkstore -wrl /home/oracle/seps/wallet -viewEntry oracle.security.client.password1
Oracle Secret Store Tool Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
Copyright (c) 2004, 2019, Oracle and/or its affiliates. All rights reserved.

Enter wallet password:   
oracle.security.client.password1 = SepsApp#2

-- ★ -viewEntry 로 password 항목을 열면 DB 비밀번호가 평문으로 나온다.
--    지갑 비밀번호를 아는 사람은 지갑 안의 모든 DB 비밀번호를 볼 수 있다.

--------------------------------------------------------------------------------

-- ★ 삭제 후 목록에는 seps_app 만 남는다. 별칭 SEPS_RPT 는 여전히 tnsnames.ora 에 있지만
--    지갑에 자격 증명이 없어 ORA-01017 로 실패한다(ORA-12154 가 아니다).

--------------------------------------------------------------------------------
 [7] 실패한 로그인은 감사 기록에 어떻게 남나
--------------------------------------------------------------------------------

-- orcl 은 기본 Unified Auditing 정책 ORA_LOGON_FAILURES 가 켜져 있다. 큐에 있는 기록을 먼저 내려쓴다.

SQL> CONNECT / AS SYSDBA
Connected.
SYS@orcl> EXEC DBMS_AUDIT_MGMT.FLUSH_UNIFIED_AUDIT_TRAIL

PL/SQL procedure successfully completed.

SYS@orcl> COL dbusername FOR a10
SYS@orcl> COL action_name FOR a8
SYS@orcl> COL t FOR a8
SYS@orcl> SELECT TO_CHAR(event_timestamp, 'HH24:MI:SS') t, NVL(dbusername, '(null)') dbusername, action_name, return_code
  2    FROM unified_audit_trail
  3   WHERE return_code = 1017
  4     AND event_timestamp >= (SELECT created FROM dba_users WHERE username = 'SEPS_APP')
  5   ORDER BY event_timestamp;

T        DBUSERNAME ACTION_N RETURN_CODE
-------- ---------- -------- -----------
20:23:28 (null)     LOGON           1017
20:23:44 SEPS_APP   LOGON           1017

2 rows selected.

SYS@orcl> COL username FOR a10
SYS@orcl> SELECT username, account_status FROM dba_users WHERE username LIKE 'SEPS%';

USERNAME   ACCOUNT_STATUS
---------- --------------------------------
SEPS_RPT   OPEN
SEPS_APP   OPEN

2 rows selected.

-- ★ 이 장에서 계정을 만든 뒤 ORA-01017 은 세 번 났지만 기록은 두 건이다.
--    - 20:23:28 (null): 02 의 WALLET_OVERRIDE 누락. 사용자 이름 없이 시도해 이름이 비어 있다.
--    - 20:23:44 SEPS_APP: 옛 비밀번호. 계정 이름이 남는다.
--    - 자격 증명을 지운 별칭(seps_rpt)의 실패는 기록되지 않았다. 같은 조건을 따로 재현해도 결과가 같았다(19.3).
--    실패 로그인 감사만으로 지갑 설정 문제를 모두 잡을 수는 없다. 계정은 아직 OPEN 이다.

================================================================================
 정리
================================================================================

-- - 한 접속 문자열에 자격 증명 하나. 중복 등록은 Credential already exists.
-- - DB 비밀번호를 바꾸면 -modifyCredential 로 지갑을 맞춘다. 놓치면 ORA-01017 이 반복된다.
-- - -viewEntry 는 저장 비밀번호를 평문으로 보여 준다. 지갑 비밀번호도 DB 비밀번호만큼 관리한다.
-- - 자격 증명이 없는 별칭은 ORA-01017 로 실패하며 감사 기록에도 남지 않았다.
