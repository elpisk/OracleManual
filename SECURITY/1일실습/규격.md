# SECURITY 1일 실습 트랜스크립트 — 작업 규격

산출물: `SECURITY_1일실습_트랜스크립트.docx` 1개. 원고 `1일실습.mk`를 `tools\docbuild.py`로 빌드한다.
대상: SQL·PL/SQL·Admin 과정을 마친 중급 이상. 사용자 생성, GRANT, sqlplus 접속, 리스너 같은 기초 설명은 하지 않는다.
랩: OEL7V9 orcl 19.3 non-CDB(mixed 감사 모드). TDE 실습만 전용 임시 DB에서 측정하고, 측정이 끝나면 지운다.

## 실습 하나의 구성 (원고 조각 `labs\NN.mk`)

```
@H2 실습 NN  제목
@TBL
항목 | 내용
목표 | ...
소요 | NN분
접속 | 사용하는 계정·세션
변경 | 실습이 만드는 것 (끝에서 모두 지움)
@END
@H3 NN.1  실습 전에 — <핵심 개념 한 줄 제목>
@B ... (개조식 평서체, 1,500~2,500자. 원리·내부 동작·딕셔너리 뷰·19c 기준 주의점·설계 판단)
@NOTE / @CASE 는 필요할 때만
@H3 NN.2  진행 순서
@TBL  단계 | 하는 일 | 확인할 것
@H3 NN.3  실습 스크립트
@P [1] 단계 제목
@CODE
(실측 출력 그대로. 해설은 출력 사이에 "-- ★ ..." 줄로만 넣음)
@END
... [n] 까지
@H3 NN.4  정리와 확인 포인트
@B 결과에서 읽어야 할 것 3~5개, 실무 적용 시 판단 기준
```

- 설명이 먼저 오고 스크립트가 뒤따른다. 스크립트 안의 프롬프트·출력은 실측 그대로 두고 고치지 않는다(긴 반복 행만 `-- (중략: n행)`으로 줄일 수 있음).
- 수준은 중급 이상에 맞춘다. 단순 성공 흐름만 보여 주지 말고, 실습마다 의도된 오류 흐름(ORA-/TNS-/PKI- 등)을 하나 이상 넣는다. 원인 진단을 딕셔너리 뷰나 트레이스로 확인하는 단계도 넣는다.
- 각 실습은 혼자 돌아가야 한다. 앞 실습의 객체에 기대지 않는다. 마지막 단계에서 만든 것을 모두 지우고, 지워졌는지 확인하는 조회를 남긴다.
- 문체는 `C:\Users\itwill\.claude\CLAUDE.md`를 따른다. 개조식에 평서체(~다/~함/~됨)로 쓰고, 독자를 직접 부르지 않는다. 재진술로 끝맺지 않고, 볼드 라벨을 남발하지 않으며, 메타 코멘트를 넣지 않는다.
- 근거 우선순위는 19c 공식 매뉴얼, 실측 결과, 원 교안(`..\NN장\본문.mk`) 순이다. 원 교안 장 본문과 트랜스크립트에서 확인된 19.3 동작과 어긋나면 안 된다.

## VM 공유 규칙 (포크 3개가 동시에 쓰는 경우)
- 이름은 실습마다 고유한 접두사를 붙인다: `D01_`…`D10_` (사용자는 `d01_app` 식).
- orcl 재기동과 기본 LISTENER 재기동은 금지한다. 공용 sqlnet.ora·tnsnames.ora는 수정하지 않는다.
  - 01·09의 클라이언트 설정은 실습 전용 `TNS_ADMIN` 디렉터리에 둔다.
  - 09의 TCPS는 별도 리스너(예: LISTENER_D09, 포트 2484)로 한다. listener.ora에 항목을 추가했다가 끝나면 백업과 md5가 같아지도록 되돌린다.
- 08(TDE)은 DBCA로 만든 임시 DB(예: d08tde)에서 측정한다. 삭제 후 DBCA가 다시 쓴 tnsnames.ora를 `tnsnames.ora.bak_sec_20261027`로 되돌리고 md5를 확인한다. orcl의 기존 TDE 구성과 `tde_keystore_keep`은 건드리지 않는다.
- 10에서는 이미 있던 감사 기록을 지우지 않는다. 정리 실행을 보여 줄 때는 가장 오래된 기록보다 앞선 기준 시각을 써서 삭제 0건이 나오게 한다. EMP_FGA 정책과 ORA_* 기본 정책은 그대로 둔다.
- sales DB, 사용자 크론, RMAN 설정은 건드리지 않는다. HR/SCOTT 데이터를 바꿨다면 끝에서 원복한다.
- 측정 산출: 스크래치 `raw\D\NN.json`(runch 형식), 원고 조각 `1일실습\labs\NN.mk`.
