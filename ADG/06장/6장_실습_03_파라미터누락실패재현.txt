>>> 원인 파악
    ★ **5장 실습 05 의 첫 번째 실패와 글자 하나까지 같다.**

      경고 번호     RMAN-05538          같다
      오류 번호     RMAN-05001          같다
      줄 수         11줄                같다
      경로          .../Chicago/...     같다
      실패 시점     마운트 직후         같다

      다른 것은 스크립트뿐이다. 5장에서는 convert 파라미터가 없었고,
      지금은 db_create_file_dest 가 없다.

    ★ 이 사실이 알려 주는 것
      RMAN 에게 두 파라미터는 **같은 질문에 대한 두 가지 대답**이다.

        질문   : 복제한 파일을 어디에 둘 것인가
        대답 A : db_file_name_convert 로 경로를 치환하라 (5장)
        대답 B : db_create_file_dest 아래에 알아서 두어라 (6장)

      둘 중 하나는 답해야 한다. 아무 답도 하지 않으면
      RMAN 은 원본 경로를 그대로 쓰려 하고, 이름 충돌 검사가 막는다.

    ★ RMAN-05538 의 문면도 다시 읽어 둔다.
        warning: implicitly using DB_FILE_NAME_CONVERT
      OMF 파라미터를 주려던 상황인데도 경고는 DB_FILE_NAME_CONVERT 를
      말한다. RMAN 내부적으로는 결국 경로 치환 규칙으로 환원되기 때문이다.
      경고 문구만 보고 "convert 를 쓰라는 뜻인가" 하고 5장 방식으로
      돌아갈 필요는 없다. db_create_file_dest 를 주어도 해결된다.

>>> 조치
    pfile 과 스크립트 양쪽에 db_create_file_dest 를 넣는다.
    한쪽만 넣으면 어느 한 시점에서 값이 사라진다.

[oracle@boston-srv ~]$ cat > $ORACLE_HOME/dbs/initboston.ora <<'EOF'

db_create_file_dest=/u03/app/oracle/oradata

--------------------------------------------------------------------------------
 [5] 정리 — 세 가지 실패의 대조
--------------------------------------------------------------------------------

  상황                          오류                        시점         잔재
  ----------------------------- --------------------------- ------------ ------
  6장 없는 경로                 ORA-01261/01262/01034       기동 전      없음
  6장 지시 없음                 RMAN-05538 + RMAN-05001x11  마운트 직후  없음
  5장 지시 없음                 RMAN-05538 + RMAN-05001x11  마운트 직후  없음
  5장 디렉터리 없음             ORA-17628 + ORA-19505       전송 도중    있음

  ★ 잔재가 남는 것은 5장의 네 번째 경우뿐이다.
    OMF 를 쓰면 '전송 도중 실패'라는 유형 자체가 사라진다.
    경로 문제는 기동 시점에, 지시 누락은 마운트 직후에 걸리기 때문이다.

--------------------------------------------------------------------------------
 [6] 정리
--------------------------------------------------------------------------------

  · 파일 배치 지시가 없으면 방식과 무관하게 RMAN-05001 이 난다
  · db_create_file_dest 와 db_file_name_convert 는 같은 질문의 두 대답이다
  · RMAN-05538 경고문은 항상 DB_FILE_NAME_CONVERT 를 말한다. 해석에 주의한다
  · 이 실패는 파일 전송 전이므로 잔재가 없다
  · OMF 파라미터는 pfile 과 스크립트 SET 양쪽에 준다
