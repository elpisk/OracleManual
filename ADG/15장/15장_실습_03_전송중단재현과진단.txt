-- ★ 세 열이 한꺼번에 바뀌었다.
--
--   STATUS      VALID → ERROR
--   VALID_NOW   YES   → INACTIVE
--   ERROR       (빈값) → ORA-12541: TNS:no listener
--
-- ★ ERROR 열에 실제 원인이 그대로 들어 있다.
--   이것이 이 뷰의 값어치다.
--   Broker 의 SHOW 는 "문제가 있다" 까지만 말한다.
--
-- ★ VALID_NOW=INACTIVE 는 실습 02 에서 본 값이다.
--   설정은 유효한데 지금 동작하지 않는다는 뜻이다.

SYS@chicago> SELECT name, value FROM v$parameter
  2            WHERE name='log_archive_dest_state_2';

NAME                     VALUE
------------------------ --------------------
log_archive_dest_state_2 ENABLE

1 row selected.

-- ★ 파라미터는 ENABLE 그대로다.
--   14장에서 Broker 로 껐을 때는 RESET 이었다.
--
-- ★ 두 열의 조합이 진단의 열쇠다.
--
--   STATE_2   V$ARCHIVE_DEST.STATUS   해석
--   --------  ----------------------  ------------------------
--   ENABLE    VALID                   정상
--   ENABLE    ERROR                   장애다. ERROR 열을 읽는다
--   RESET     DEFERRED                Broker 가 껐다
--   DEFER     DEFERRED                사람이 SQL 로 껐다
--
-- ★ 이 표만으로 "장애인가 설정인가" 가 갈린다.

-- ★ 이 실습에서 확인한 것
--
--   ① 리스너를 내리면 STATUS=ERROR, VALID_NOW=INACTIVE
--   ② ERROR 열에 ORA-12541 이 그대로 들어온다
--   ③ 파라미터는 ENABLE 그대로 — RESET·DEFER 와 구별된다
--   ④ V$DATAGUARD_STATUS 에 Warning 인데 봐야 하는 행이 있었다
--   ⑤ 알림 로그에는 접속 문자열과 프로세스가 있다
--   ⑥ archiver continuing — MaxPerformance 이므로 Primary 는 멈추지 않는다
--   ⑦ Standby 에서는 MRP0 가 WAIT_FOR_LOG, RFS(LGWR) 가 사라진다
--   ⑧ 그때도 두 지연은 0 이었다
--   ⑨ Broker 는 ORA-16857 로 경보했다
--   ⑩ 복구에 ReopenSecs 300 만큼 걸렸다
--   ⑪ 조치 직후 Broker 가 ERROR 로 보인 것은 판정 시차다
--
-- ★ 다음 실습에서 적용의 진행을 자세히 본다.
