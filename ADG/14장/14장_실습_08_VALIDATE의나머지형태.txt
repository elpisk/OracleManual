 제14장 실습 08 — VALIDATE 의 나머지 형태
 대상   : chicago-srv (dgmgrl), boston-srv
 목표   : VALIDATE 의 여섯 가지 구문을 모두 써 보고 결과를 해석한다.
          VALIDATE DATABASE 가 검사하지 않는 것을 실측으로 확인한다
 소요   : 약 40분
 변경   : boston 리스너의 정적 등록을 잠시 제거했다가 복원한다

 [1] 구문 전체를 먼저 본다
--------------------------------------------------------------------------------

[oracle@chicago-srv ~]$ dgmgrl -silent sys/****@chicago "help validate"

Performs an exhaustive set of validations for a member

Syntax:

  VALIDATE DATABASE [VERBOSE] <database name>;

  VALIDATE DATABASE [VERBOSE] <database name> DATAFILE <datafile number>
    OUTPUT=<file name>;

  VALIDATE DATABASE [VERBOSE] <database name> SPFILE;

  VALIDATE FAR_SYNC [VERBOSE] <far_sync name>
    [WHEN PRIMARY IS <database name>];

  VALIDATE NETWORK CONFIGURATION FOR { ALL | <member name> };

  VALIDATE STATIC CONNECT IDENTIFIER FOR { ALL | <database name> };

-- ★ 여섯 가지다. 실습 01 에서 쓴 것은 첫 번째뿐이었다.
--
-- ★ 네 번째(FAR_SYNC)는 10장 구성에서만 쓴다.
--   지금은 Far Sync 가 없으므로 나머지 다섯을 본다.
--
-- ★ help 를 먼저 보는 습관을 들인다.
--   14장에서 START OBSERVER 구문을 확인할 때도 같은 방법을 썼다.

--   ORA- 가 아니라 DGM- 이다. DGMGRL 자체가 낸 오류다.
--   14장에서 정리한 대로 판정 스크립트는 여러 접두어를 다뤄야 한다.

--   DBMS_DBCOMP 의 블록 비교 결과다.
--   VALIDATE ... DATAFILE 은 그것을 Broker 명령으로 감싼 것이다.
--
-- ★ 표를 읽는 법
--
--   ID        블록 유형 (아래 설명이 붙어 있다)
--   TOTAL     찾은 블록 수
--   CORR      손상된 블록          ← 0 이어야 한다
--   SKIPPED   비교 대상이 아닌 것 (빈 블록, 직접 로드 등)
--   DIFFV     버전이 다른 블록 쌍  ← 적용 중이면 자연스럽다
--   SAMEV&C   버전·체크섬·내용이 모두 같음
--   LWLOC     로컬의 lost write    ← 0 이어야 한다
--   LWRMT     원격의 lost write    ← 0 이어야 한다
--   DIFFPAIR  버전은 같은데 내용이 다름 ← 0 이어야 한다. 데이터 불일치
--
-- ★ 실측에서 CORR·LWLOC·LWRMT·DIFFPAIR 이 모두 0 이다. 정상이다.
--
-- ★ 06 번(trans data) 행의 DIFFV 210 은 문제가 아니다.
--   Standby 가 적용 중이므로 순간적으로 버전이 다른 블록이 있는 것이 당연하다.
--
-- ★ 무엇을 잡는가.
--   lost write 는 전송·적용이 정상인데도 데이터가 조용히 어긋나는 사고다.
--   지연이나 시퀀스로는 절대 드러나지 않는다.
--   15장에서 만들 점검표로도 잡히지 않는 종류의 문제다.

--------------------------------------------------------------------------------
 [9] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① VALIDATE 는 여섯 가지 구문이 있다
--   ② DATAFILE 에는 OUTPUT= 이 필수다 (빠뜨리면 Syntax error)
--   ③ OUTPUT 에 경로를 주면 DGM-17138 — 파일 이름만 준다
--   ④ 결과 파일은 대상(Standby) 쪽 trace 디렉터리에 생긴다
--   ⑤ 내용은 5장의 DBMS_DBCOMP 블록 비교 결과다
--   ⑥ CORR·LWLOC·LWRMT·DIFFPAIR 가 0 이어야 한다
--   ⑦ 없는 파일 번호는 ORA-53201 + SYS.DBMS_DBCOMP 스택
--   ⑧ SPFILE 은 초기화 파라미터를 비교한다 (실측 4개 차이)
--   ⑨ 15장에서 켰던 log_archive_trace 의 흔적이 여기 남아 있다
--   ⑩ NETWORK CONFIGURATION 은 양방향 연결 + 정적 식별자를 시험한다
--   ⑪ ★ VALIDATE DATABASE 는 Primary 의 정적 등록만 검사한다
--   ⑫ 대상의 정적 등록이 없어도 Ready for Switchover: Yes 가 나온다
--
-- ★ 다음 실습에서 Broker 가 남기는 로그를 읽는다.
