================================================================================
 제14장 실습 01 — VALIDATE 읽기
 대상   : chicago-srv (dgmgrl)
 목표   : 건강한 구성에서 VALIDATE DATABASE 의 출력을 항목별로 해석한다.
          VERBOSE 가 무엇을 더 보여 주는지 확인한다
 소요   : 약 25분
 변경   : 없음 (전부 조회)
================================================================================

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
 [2] VALIDATE DATABASE — Standby
--------------------------------------------------------------------------------

DGMGRL> validate database 'boston'

  Database Role:     Physical standby database
  Primary Database:  chicago

  Ready for Switchover:  Yes
  Ready for Failover:    Yes (Primary Running)

  Flashback Database Status:
    chicago:  Off
    boston :  Off

  Managed by Clusterware:
    chicago:  NO
    boston :  NO
    Validating static connect identifier for the primary database chicago...
    The static connect identifier allows for a connection to database "chicago".

  Log Files Cleared:
    chicago Standby Redo Log Files:  Cleared
    boston Online Redo Log Files:    Not Cleared
    boston Standby Redo Log Files:   Available

-- ★ 항목마다 뜻이 있다.
--
--   Ready for Switchover     계획된 전환이 지금 가능한가
--   Ready for Failover       비계획 전환이 지금 가능한가
--                            (Primary Running) 은 Primary 가 살아 있다는 뜻
--   Flashback Database Status  16장의 Reinstate 와 관련
--   Managed by Clusterware   RAC/Clusterware 관리 여부
--   static connect identifier  13장의 _DGMGRL 접속을 실제로 시험한다
--   Log Files Cleared        전환 후 쓸 로그 파일이 준비되어 있는가
--
-- ★ 정적 등록을 실제로 접속해 시험한다는 점이 인상적이다.
--   13장에서 "정적 등록이 없으면 역할 전환이 중간에 멈춘다" 고 했는데
--   VALIDATE 는 그것을 미리 확인해 준다.
--
-- ★ boston Online Redo Log Files: Not Cleared 는 경고가 아니다.
--   Standby 의 온라인 리두는 아직 쓰이지 않았을 뿐이며
--   전환되면 그때 정리된다.

--------------------------------------------------------------------------------
 [3] VALIDATE DATABASE — Primary
--------------------------------------------------------------------------------

DGMGRL> validate database 'chicago'

  Database Role:    Primary database

  Ready for Switchover:  Yes

  Flashback Database Status:
    chicago:  Off

  Managed by Clusterware:
    chicago:  NO
    Validating static connect identifier for the primary database chicago...
    The static connect identifier allows for a connection to database "chicago".

-- ★ Primary 쪽은 항목이 적다.
--
--   Ready for Failover 가 없다. Primary 로 Failover 할 일이 없기 때문이다.
--   Log Files Cleared 도 없다.
--
-- ★ 두 출력을 비교하면 각 항목이 왜 있는지 알 수 있다.
--   Standby 에만 있는 항목은 전부 "받는 쪽" 의 관심사다.

  Future Log File Groups Configuration:
    Thread #  Online Redo Log Groups  Standby Redo Log Groups Status

-- ★ Future 는 역할이 바뀐 뒤를 가정한 계산이다.
--
--   Current  chicago 온라인 3 + boston SRL 4
--   Future   boston 온라인 3 + chicago SRL 4
--
--   전환 후에도 Sufficient SRLs 인지 미리 확인해 준다.
--
-- ★ 4장에서 배운 규칙(SRL 은 온라인 그룹 수 + 1)이
--   양방향으로 지켜져야 한다는 뜻이며 VALIDATE 가 대신 계산한다.
--
-- ★ 손으로 이것을 확인하려면 양쪽에서 V$LOG 와 V$STANDBY_LOG 를
--   각각 조회해 비교해야 한다.

--------------------------------------------------------------------------------
 [7] 오류 재현 — 없는 멤버를 검증하면
--------------------------------------------------------------------------------

DGMGRL> validate database 'seattle'

Object "seattle" was not found

>>> 원인 파악

-- ★ 구성에 없는 이름이다.
--
-- ★ 13장에서 본 것과 같은 표현이다.
--   DGMGRL 은 멤버 이름 오류를 ORA- 번호가 아니라 문장으로 알려 준다.
--   스크립트에서 결과를 판정할 때 오류 번호만 찾으면 이런 경우를 놓친다.
--
-- ★ 반면 속성 이름을 틀리면 ORA-16538,
--   속성 값을 틀리면 ORA-16790 이 나온다.
--   같은 도구인데 오류 표현이 일관되지 않다.

>>> 조치

DGMGRL> show configuration

-- 멤버 이름을 먼저 확인한다.

>>> 재확인

DGMGRL> validate database 'boston'

  Database Role:     Physical standby database
  Primary Database:  chicago

  Ready for Switchover:  Yes
  Ready for Failover:    Yes (Primary Running)

-- ★ 올바른 이름을 주면 동작한다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① VALIDATE 는 "지금 전환할 수 있는가" 를 묻는다
--   ② Ready for Switchover / Ready for Failover 가 핵심 답이다
--   ③ 정적 등록을 실제로 접속해 시험한다
--   ④ Primary 쪽은 항목이 적다 — Failover 대상이 아니므로
--   ⑤ VERBOSE 는 Gap Status·용량·임시 파일까지 보여 준다
--   ⑥ Future 구성으로 전환 후의 SRL 충분성을 미리 계산한다
--   ⑦ 속성을 양쪽 나란히 표로 보여 준다
--   ⑧ 없는 멤버는 ORA- 번호 없이 문장으로 알려 준다
--
-- ★ 다음 실습에서 SHOW 와 VALIDATE 가 다른 답을 내는 것을 확인한다.
