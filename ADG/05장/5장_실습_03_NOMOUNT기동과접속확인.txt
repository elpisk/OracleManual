================================================================================
 제5장 실습 03 — Standby 인스턴스 NOMOUNT 기동과 접속 확인
 대상   : boston-srv Standby (chicago-srv 에서 접속)
 목표   : Standby 를 헐고 NOMOUNT 로 띄운 뒤, Primary 에서 원격 SYS 접속이
          되는지 확인한다. 3장 정적 등록의 효과가 여기서 회수된다
 소요   : 약 20분
 경고   : 이 실습부터 Standby 를 **실제로 헐어 버린다.**
          되돌릴 수 없으므로 개인 실습 환경에서만, VM 스냅샷을 뜬 뒤 수행한다.
================================================================================

--------------------------------------------------------------------------------
 [1] 기존 Standby 를 내린다
--------------------------------------------------------------------------------

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;

Database altered.

SYS@boston> SHUTDOWN IMMEDIATE
Database closed.
Database dismounted.
ORACLE instance shut down.

-- 적용을 먼저 멈추고 내린다. MRP 가 돌고 있으면 종료가 지연될 수 있다.

--------------------------------------------------------------------------------
 [2] 기존 파일을 제거한다
--------------------------------------------------------------------------------

[oracle@boston-srv ~]$ rm -rf /u03/app/oracle/oradata/Boston/datafile/*.dbf
[oracle@boston-srv ~]$ rm -rf /u03/app/oracle/oradata/Boston/controlfile/*
[oracle@boston-srv ~]$ rm -f $ORACLE_HOME/dbs/spfileboston.ora

-- ★ 세 가지를 지운다.
--   ① 데이터 파일  — 새로 복제할 것이므로
--   ② 컨트롤 파일  — DUPLICATE 가 새로 만든다
--   ③ spfile       — 이것이 남아 있으면 pfile 대신 spfile 을 읽는다
--
-- ★★ 주의: 하위 디렉터리는 지우지 않는다.
--   *.dbf 만 지정한 것에 주목한다.
--   datafile/* 로 지우면 pdbseed 와 chicago_pdb1 디렉터리까지 사라져
--   실습 05 에서 볼 ORA-19505 가 발생한다.

[oracle@boston-srv ~]$ ls -R /u03/app/oracle/oradata/Boston

/u03/app/oracle/oradata/Boston:
controlfile  datafile  onlinelog

/u03/app/oracle/oradata/Boston/controlfile:

/u03/app/oracle/oradata/Boston/datafile:
chicago_pdb1  pdbseed

/u03/app/oracle/oradata/Boston/datafile/chicago_pdb1:

/u03/app/oracle/oradata/Boston/datafile/pdbseed:

/u03/app/oracle/oradata/Boston/onlinelog:
redo01.log  redo02.log  redo03.log
stdbyredo04.log  stdbyredo05.log  stdbyredo06.log

-- 하위 디렉터리 두 개가 남아 있는 것을 확인한다.
-- 온라인 로그 파일은 남겨 두어도 되고 지워도 된다. REUSE 로 덮어쓴다.

--------------------------------------------------------------------------------
 [3] 최소 pfile 확인
--------------------------------------------------------------------------------

[oracle@boston-srv ~]$ cat > $ORACLE_HOME/dbs/initboston.ora <<'EOF'
db_name=chicago
enable_pluggable_database=true
EOF

[oracle@boston-srv ~]$ cat $ORACLE_HOME/dbs/initboston.ora
db_name=chicago
enable_pluggable_database=true

--------------------------------------------------------------------------------
 [4] NOMOUNT 기동
--------------------------------------------------------------------------------

SYS@boston> STARTUP NOMOUNT PFILE='/u01/app/oracle/product/19.3.0/dbhome_1/dbs/initboston.ora'
ORACLE instance started.

Total System Global Area  356512392 bytes
Fixed Size                  9134728 bytes
Variable Size             289406976 bytes
Database Buffers           50331648 bytes
Redo Buffers                7639040 bytes

SYS@boston> SELECT instance_name, status FROM v$instance;

INSTANCE_NAME    STATUS
---------------- ------------
boston           STARTED

1 row selected.

-- ★ SGA 가 356MB 로 아주 작다.
--   pfile 에 메모리 파라미터를 주지 않아 기본값으로 뜬 것이다.
--   Primary 는 SGA 3GB(3,221,225,472 bytes)인데 비교하면 1/9 수준이다.
--
--   복제 과정에서 spfile 이 만들어지면 Primary 와 같은 규모가 된다.
--   즉 지금의 작은 SGA 는 임시 상태다.
--
-- ★ STATUS = STARTED 가 NOMOUNT 를 뜻한다.
--   MOUNTED 나 OPEN 이면 DUPLICATE 가 시작되지 않는다 (실습 01 의 RMAN-05500).

--------------------------------------------------------------------------------
 [5] 결정적 확인 — Primary 에서 원격 SYS 접속
--------------------------------------------------------------------------------

[oracle@chicago-srv ~]$ sqlplus -s "sys/oracle@boston as sysdba"

SQL> SELECT instance_name, status FROM v$instance;

INSTANCE_NAME    STATUS
---------------- ------------
boston           STARTED

SQL> EXIT

-- ★ 이 접속이 이 실습의 목적이다.
--
--   3장에서 정적 등록을 그토록 강조한 이유가 여기서 완결된다.
--   NOMOUNT 인스턴스는 리스너에 정상 등록되지 않는다.
--   동적 등록만 있으면 status 가 BLOCKED 가 되어 접속이 거부된다.
--
--   3장 실습 03 에서 재현한 그 상황이 정확히 이 지점이다.
--     정적 등록 없음 + NOMOUNT → ORA-12528
--     정적 등록 있음 + NOMOUNT → 접속 성공 (STATUS=STARTED)

[oracle@boston-srv ~]$ lsnrctl status | grep -A2 'Service "boston"'

Service "boston" has 1 instance(s).
  Instance "boston", status UNKNOWN, has 1 handler(s) for this service...

-- status 가 UNKNOWN 이다. 정적 등록으로 광고되고 있다는 뜻이다.
-- 리스너는 boston 인스턴스가 어떤 상태인지 모르지만 일단 접속을 넘겨준다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — RMAN 접속 시 auxiliary 표시 확인
--------------------------------------------------------------------------------

-- DUPLICATE 를 시작하기 전 마지막 확인이다.

[oracle@chicago-srv ~]$ rman target "'sys/oracle@chicago as sysdba'" \
>   auxiliary "'sys/oracle@boston as sysdba'"

Recovery Manager: Release 19.0.0.0.0 - Production
Copyright (c) 1982, 2019, Oracle and/or its affiliates.  All rights reserved.

connected to target database: CHICAGO (DBID=1852041610)
connected to auxiliary database: CHICAGO (not mounted)

RMAN>

-- ★ 이 두 줄이 시작해도 좋다는 신호다.
--
--   target    : CHICAGO (DBID=1852041610)   ← 원본. DBID 가 표시된다
--   auxiliary : CHICAGO (not mounted)       ← 대상. "(not mounted)" 가 핵심
--
--   auxiliary 쪽에 DBID 가 표시되면 이미 마운트된 것이므로 진행하면 안 된다.
--   실습 01 에서 그 상태로 시도했다가 RMAN-05500 을 만났다.
--
--   auxiliary 이름이 CHICAGO 인 것도 확인한다.
--   BOSTON 으로 나오면 pfile 의 db_name 이 잘못된 것이다 (실습 02).

>>> 원인 파악
    이 지점에서 막힌다면 원인은 전부 3장에서 구성한 Oracle Net 쪽이다.
    오류 번호가 어느 구성이 잘못됐는지 그대로 가리킨다.

    ORA-12528  → 정적 등록이 없다. 3장 실습 03 으로 돌아간다
    ORA-12514  → 리스너가 서비스를 모른다. listener.ora 확인
    ORA-01017  → 패스워드 파일 불일치. 3장 실습 05 로 돌아간다
    ORA-01034  → 인스턴스가 없다. NOMOUNT 기동을 확인한다
    TNS-12535  → 방화벽·네트워크. 3장 실습 06 으로 돌아간다

    3장에서 재현한 오류들이 전부 여기서 나타날 수 있다.
    이 실습이 3장의 시험대인 셈이다.

>>> 조치와 재확인
    위 표에 따라 해당 장으로 돌아가 조치한 뒤,
    다시 RMAN 에 접속해 "(not mounted)" 가 나오는지 확인한다.

RMAN> EXIT

--------------------------------------------------------------------------------
 [7] 정리 — DUPLICATE 시작 전 점검표
--------------------------------------------------------------------------------

  항목                            확인 방법                        기대값
  ------------------------------- -------------------------------- ---------------
  Standby 인스턴스 상태           V$INSTANCE.STATUS                STARTED
  기존 데이터 파일 제거           ls .../datafile/*.dbf            없음
  하위 디렉터리 존재              ls -R .../Boston/datafile        pdbseed 등 있음
  spfile 제거                     ls $ORACLE_HOME/dbs/spfile*      없음
  pfile 내용                      cat initboston.ora               db_name=chicago
  리스너 정적 등록                lsnrctl status                   UNKNOWN
  원격 SYS 접속                   sqlplus sys/...@boston           성공
  RMAN auxiliary 표시             rman target ... auxiliary ...    (not mounted)

  여덟 항목이 모두 통과하면 실습 04 로 넘어간다.
