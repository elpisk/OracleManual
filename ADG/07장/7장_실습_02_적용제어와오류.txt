================================================================================
 제7장 실습 02 — 적용 제어와 두 가지 오류
 대상   : boston-srv Standby
 목표   : 적용을 켜고 끄는 세 명령을 익히고, 그 과정에서 나는 오류
          ORA-16136 과 ORA-01153 을 구분한다
 소요   : 약 25분
 변경   : 적용을 여러 번 껐다 켠다. 마지막에 실시간 적용으로 복귀한다
================================================================================

--------------------------------------------------------------------------------
 [1] 세 가지 명령
--------------------------------------------------------------------------------

-- 중지
ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;

-- 기동 (아카이브 적용이라고 알려진 형태)
ALTER DATABASE RECOVER MANAGED STANDBY DATABASE DISCONNECT FROM SESSION;

-- 기동 (실시간 적용이라고 알려진 형태)
ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
  USING CURRENT LOGFILE DISCONNECT FROM SESSION;

-- ★ DISCONNECT FROM SESSION 의 역할
--   명령을 내린 세션과 무관하게 백그라운드에서 계속 돌게 한다.
--   이 절이 없으면 세션이 붙잡혀 다른 작업을 할 수 없다.
--   운영에서는 사실상 필수다.
--
-- ★ USING CURRENT LOGFILE 이 실시간 적용을 뜻한다 —
--   오래된 문서는 그렇게 설명한다.
--   19c 에서도 그러한지는 실습 04 에서 실측으로 확인한다.

--------------------------------------------------------------------------------
 [2] 현재 상태 확인
--------------------------------------------------------------------------------

SYS@boston> SELECT process, status, sequence# FROM v$managed_standby
  2            WHERE process='MRP0';

PROCESS   STATUS        SEQUENCE#
--------- ------------ ----------
MRP0      APPLYING_LOG         64

1 row selected.

-- 적용이 돌고 있다. 이 상태에서 시작한다.

--------------------------------------------------------------------------------
 [3] 오류 재현 ① — 이미 돌고 있는데 다시 기동하면
--------------------------------------------------------------------------------

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
  2            USING CURRENT LOGFILE DISCONNECT FROM SESSION;

alter database recover managed standby database using current logfile disconnect from session
*
ERROR at line 1:
ORA-01153: an incompatible media recovery is active

-- 다른 형태로도 시도해 본다.

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
  2            DISCONNECT FROM SESSION;

alter database recover managed standby database disconnect from session
*
ERROR at line 1:
ORA-01153: an incompatible media recovery is active

>>> 원인 파악
    "호환되지 않는 미디어 복구가 활성 상태다."

    ★ 두 형태 모두 같은 오류다. 명령의 종류와 무관하다.
      근본 규칙은 하나다. **MRP 는 하나만 존재할 수 있다.**

    ★ 4장에서 이 오류를 이미 만났다.
      그때는 서로 다른 적용 방식을 겹쳐 실행해서였고,
      지금은 같은 방식을 두 번 실행해서다.
      메시지의 "incompatible" 은 "다른 종류"라는 뜻이 아니라
      "지금 상태와 양립할 수 없다"는 뜻으로 읽어야 한다.

    ★ 이 오류는 아무것도 바꾸지 않는다.
      기존 MRP 는 그대로 돌고 있다. 확인해 둔다.

SYS@boston> SELECT process, status, sequence# FROM v$managed_standby
  2            WHERE process='MRP0';

PROCESS   STATUS        SEQUENCE#
--------- ------------ ----------
MRP0      APPLYING_LOG         64

>>> 조치
    이미 원하는 상태이면 아무것도 하지 않는다.
    적용 방식을 바꾸려는 것이었다면 CANCEL 을 먼저 낸다.

>>> 재확인
    CANCEL 후 기동하면 정상 수행된다. [4] 에서 확인한다.

--------------------------------------------------------------------------------
 [4] 오류 재현 ② — 멈춰 있는데 다시 멈추면
--------------------------------------------------------------------------------

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;

Database altered.

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;

alter database recover managed standby database cancel
*
ERROR at line 1:
ORA-16136: Managed Standby Recovery not active

>>> 원인 파악
    "관리 대상 Standby 복구가 활성 상태가 아니다."
    멈출 것이 없다는 뜻이다.

    ★ 이 오류도 무해하다. 상태를 확인해 둔다.

SYS@boston> SELECT COUNT(*) mrp FROM v$managed_standby WHERE process='MRP0';

       MRP
----------
         0

      이미 0 이었고 여전히 0 이다. 달라진 것이 없다.

>>> 조치
    의도한 상태(중지)에 이미 도달했으므로 조치가 필요 없다.

>>> 재확인
    기동하면 정상 수행된다.

SYS@boston> ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
  2            USING CURRENT LOGFILE DISCONNECT FROM SESSION;

Database altered.

SYS@boston> SELECT process, status, sequence# FROM v$managed_standby
  2            WHERE process='MRP0';

PROCESS   STATUS        SEQUENCE#
--------- ------------ ----------
MRP0      APPLYING_LOG         73

--------------------------------------------------------------------------------
 [5] 두 오류의 대조
--------------------------------------------------------------------------------

  오류        상황                    실제 상태  손상  대응
  ----------- ----------------------- ---------- ----- ----------------------
  ORA-01153   돌고 있는데 기동 시도   돌고 있음  없음  원하는 상태면 그대로
  ORA-16136   멈춰 있는데 중지 시도   멈춰 있음  없음  원하는 상태면 그대로

  ★ 둘 다 "이미 그 상태다"라는 알림이다.
    오류처럼 보이지만 실은 멱등성(idempotency) 위반 알림에 가깝다.
    같은 명령을 두 번 내도 결과는 같고 두 번째만 거부된다.

--------------------------------------------------------------------------------
 [6] 안전한 재기동 순서
--------------------------------------------------------------------------------

  적용 방식을 바꾸거나 재기동할 때는 항상 이 순서를 따른다.

    ① ALTER DATABASE RECOVER MANAGED STANDBY DATABASE CANCEL;
       → 이미 멈춰 있으면 ORA-16136. 무시한다.

    ② 몇 초 기다린다
       → MRP 가 완전히 종료되기를 기다린다.

    ③ ALTER DATABASE RECOVER MANAGED STANDBY DATABASE
         USING CURRENT LOGFILE DISCONNECT FROM SESSION;

    ④ SELECT process, status, sequence# FROM v$managed_standby
         WHERE process='MRP0';
       → 행이 나오는지 확인한다.

  ★ 반대로 CANCEL 없이 기동부터 시도하면 ORA-01153 이 나고,
    지금 어떤 방식으로 돌고 있는지 확인하는 단계가 더 든다.

  ★ 스크립트로 자동화한다면 ①의 ORA-16136 을 무시하도록 작성한다.
    SQL*Plus 에서는 WHENEVER SQLERROR 설정을 그 구간만 풀어 준다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

  · 명령은 셋이다 — CANCEL / 기동 / USING CURRENT LOGFILE 기동
  · DISCONNECT FROM SESSION 은 사실상 필수다
  · ORA-01153: 돌고 있는데 기동 시도. 두 형태 모두 같은 오류
  · ORA-16136: 멈춰 있는데 중지 시도
  · 두 오류 모두 상태를 바꾸지 않는다. 무해하다
  · 재기동은 CANCEL → 대기 → 기동 → 확인 순서로 한다
