================================================================================
 제4장 실습 01 — DBCA silent 모드로 CDB 생성
 대상   : chicago-srv Primary
 목표   : 구축 시 실제로 실행한 DBCA 명령과 로그를 읽고, 각 옵션이 Data Guard
          관점에서 무엇을 정하는지 확인한다
 소요   : 약 20분 (실제 생성은 약 12분)
 주의   : 이 실습은 이미 만들어진 chicago 를 다시 만들지 않는다.
          구축 시 남긴 로그를 읽고 해석하는 실습이다.
================================================================================

--------------------------------------------------------------------------------
 [1] 실행한 명령
--------------------------------------------------------------------------------

[oracle@chicago-srv ~]$ export ORACLE_SID=chicago
[oracle@chicago-srv ~]$ $ORACLE_HOME/bin/dbca -silent -createDatabase \
>   -templateName General_Purpose.dbc \
>   -gdbname chicago \
>   -sid chicago \
>   -createAsContainerDatabase true \
>   -numberOfPDBs 1 \
>   -pdbName chicago_pdb1 \
>   -pdbAdminPassword oracle \
>   -useLocalUndoForPDBs true \
>   -responseFile NO_VALUE \
>   -characterSet AL32UTF8 \
>   -totalMemory 4096 \
>   -sysPassword oracle \
>   -systemPassword oracle \
>   -enableArchive false \
>   -recoveryAreaDestination /u03/app/oracle/fast_recovery_area \
>   -recoveryAreaSize 15360 \
>   -datafileDestination /u03/app/oracle/oradata/Chicago

-- Data Guard 관점에서 각 옵션의 의미
--
--   -gdbname / -sid       둘 다 chicago. 이 값이 DB_NAME 이 되며 Standby 도 같다
--   -characterSet         양쪽이 같아야 한다 (복제본이므로 자동으로 같아진다)
--   -totalMemory 4096     Standby 도 비슷한 크기가 필요하다. 적용 성능에 영향
--   -enableArchive false  여기서는 끄고 실습 02 에서 수동 전환한다
--   -recoveryAreaSize     15360MB. 가득 차면 Primary 가 멈추므로 감시 대상
--   -datafileDestination  경로 지정 방식. 6장에서 OMF 방식과 대조한다

--------------------------------------------------------------------------------
 [2] 오류 재현 — 이미 존재하는 SID 로 실행하면
--------------------------------------------------------------------------------

-- 구축 당시 /etc/oratab 에 chicago 항목을 미리 넣어 둔 상태로 DBCA 를 실행했다.

[WARNING] [DBT-10328] Specified GDB Name (chicago) may have a potential conflict
   with an already existing database on the system.
   ACTION: Specify a different GDB Name that does not conflict with existing
   databases on the system.
[FATAL] [DBT-10317] Specified SID Name (chicago) already exists.
   ACTION: Specify a different SID Name that does not already exist.


>>> 원인 파악
    DBCA 는 /etc/oratab 을 읽어 같은 SID 가 이미 있는지 검사한다.
    실제 인스턴스가 없어도 oratab 에 항목이 있으면 중복으로 판단한다.

    [WARNING] 는 진행을 막지 않지만 [FATAL] 은 즉시 중단시킨다.
    두 표시를 구분해서 읽어야 한다.

>>> 조치
    oratab 에서 해당 항목을 지운다.
    DBCA 가 생성 후 스스로 등록하므로 미리 넣어 둘 필요가 없다.

[root@chicago-srv ~]# sed -i '/^chicago:/d' /etc/oratab
[root@chicago-srv ~]# grep -v '^#' /etc/oratab | grep -v '^$'
(비어 있음)

>>> 재확인
    다시 실행하면 DBT-10317 없이 정상 진행된다.
    생성이 끝난 뒤 oratab 을 확인하면 DBCA 가 등록해 둔 것을 볼 수 있다.

[oracle@chicago-srv ~]$ grep -v '^#' /etc/oratab | grep -v '^$'
chicago:/u01/app/oracle/product/19.3.0/dbhome_1:N

-- 실습 환경이라 'oracle' 을 쓰므로 예상된 경고이며 생성은 그대로 진행된다.
--
-- ★ 3장에서 확인한 것과 대조해 둔다.
--   orapwd 로 패스워드 파일을 새로 만들 때는 같은 규칙이
--   경고가 아니라 **거부**로 작동한다 (OPW-00029).
--   같은 규칙인데 적용 강도가 다르다.

--------------------------------------------------------------------------------
 [6] 정리 — DBCA 가 정하는 것과 나중에 바꾸는 것
--------------------------------------------------------------------------------

  DBCA 가 정하고 사실상 못 바꾸는 것     DBCA 이후에 바꾸는 것
  -------------------------------------- --------------------------------------
  DB_NAME                                ARCHIVELOG 모드     (실습 02)
  문자셋 (AL32UTF8)                      FORCE LOGGING       (실습 03)
  DB_BLOCK_SIZE                          Standby Redo Log    (실습 04)
  PDB 구성                               Data Guard 파라미터 (2장)
  데이터 파일 경로 방식                  보호 모드           (2장)

  1장 실습 05 의 점검표에 문자셋과 블록 크기가 들어 있는 이유가 여기 있다.
  생성 시점에 확정되며 사실상 되돌릴 수 없다.
