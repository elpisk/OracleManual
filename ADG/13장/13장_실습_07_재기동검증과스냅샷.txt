 [3] 스냅샷 — 이번에는 꺼진 상태로
--------------------------------------------------------------------------------

C:\> vmrun snapshot "D:\ADG\CHICAGO\ADG-CHICAGO.vmx" broker-ready
C:\> vmrun snapshot "D:\ADG\BOSTON\ADG-BOSTON.vmx"   broker-ready

C:\> vmrun listSnapshots "D:\ADG\CHICAGO\ADG-CHICAGO.vmx"
Total snapshots: 3
adg-configured
pre-logical
broker-ready

-- ★ 12장에서는 실행 중 상태로 찍었다. 이번에는 꺼진 상태다.
--   이유가 있다.
--
-- ★ 실행 중 스냅샷은 메모리까지 저장하므로 되돌리면 그대로 이어진다.
--   편리하지만 Standby 에서는 위험할 수 있다.
--   메모리 안의 복구 상태와 디스크의 리두가 미묘하게 어긋날 수 있고,
--   되돌린 직후에는 정상으로 보이다가 나중에 드러난다.
--
-- ★ 꺼진 상태 스냅샷은 시간이 더 걸리고 되돌린 뒤 기동 절차가 필요하지만
--   복귀가 신뢰할 수 있다.
--
-- ★ 되돌린 뒤에는 "MRP0 이 살아 있고 지연이 0" 만으로 판정하지 않는다.
--   로그 전환을 한 번 걸어 새 리두가 실제로 적용되는지 확인한다.
--   [5] 에서 그렇게 한다.

-- ★ 그대로다.
--
--   구성이 유지된 이유는 두 가지다.
--   ① DG_BROKER_START 를 SCOPE=BOTH 로 켰으므로 재기동 후에도 TRUE
--   ② 구성 파일 dr1/dr2 가 디스크에 있으므로 DMON 이 읽어 복원
--
-- ★ Real Time Query 가 ON 이고 Average Apply Rate 가 64 KByte/s 다.
--   Broker 가 MRP 를 스스로 띄웠고 실제로 적용하고 있다는 뜻이다.
--   우리가 MRP 를 띄우는 SQL 을 실행한 적이 없다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — 뷰만 믿으면
--------------------------------------------------------------------------------

-- ★ 여기서 멈추면 안 된다.
--   뷰가 모두 정상인데 실제로는 적용이 안 되는 경우가 있다.
--   되돌리기나 재기동 뒤에는 반드시 데이터로 확인한다.

SYS@chicago> DROP TABLE system.bk_t PURGE;

DROP TABLE system.bk_t PURGE
                       *
ERROR at line 1:
ORA-00942: table or view does not exist

>>> 원인 파악

-- 이 실습을 처음 수행하면 테이블이 없으므로 나오는 오류다.
-- 스크립트를 반복 실행할 수 있게 하려고 DROP 을 먼저 넣었을 뿐이다.
--
-- ★ 오류지만 문제가 아닌 경우를 구별할 줄 알아야 한다.
--   12장 실습 01 에서도 같은 패턴을 썼다.

>>> 조치

SYS@chicago> CREATE TABLE system.bk_t(id NUMBER, tag VARCHAR2(24));
SYS@chicago> INSERT INTO system.bk_t VALUES(1,'after-restart');
SYS@chicago> COMMIT;
SYS@chicago> ALTER SYSTEM ARCHIVE LOG CURRENT;

System altered.

>>> 재확인

-- 40초 뒤

SYS@boston> COL tag FOR a20
SYS@boston> SELECT id, tag FROM system.bk_t;

        ID TAG
---------- --------------------
         1 after-restart

1 row selected.

-- ★ 새 리두가 실제로 적용됐다.
--   이것이 확인되어야 재기동이 성공한 것이다.

--------------------------------------------------------------------------------
 [8] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① 종료 순서 — Standby 먼저, Primary 나중
--   ② 스냅샷은 꺼진 상태로 찍는다
--   ③ 실행 중 스냅샷은 Standby 에서 위험할 수 있다
--   ④ 구성이 재기동을 넘어 유지된다
--      (SCOPE=BOTH + 디스크의 구성 파일)
--   ⑤ Broker 가 MRP 를 스스로 띄운다. 우리가 SQL 을 실행하지 않았다
--   ⑥ 뷰만 믿지 않는다. 데이터로 확인한다
--
-- ★ 13장을 마친다.
--   14장은 이 구성 위에서 모니터링과 검증 명령을 다룬다.
