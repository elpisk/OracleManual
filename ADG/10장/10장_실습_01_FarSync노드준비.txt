 제10장 실습 01 — Far Sync 노드 준비와 컨트롤 파일
 대상   : chicago-srv Primary, farsync-srv (신규 3번째 노드)
 목표   : Far Sync 전용 컨트롤 파일을 Primary 에서 만들고, 필요한 파일을
          새 노드로 옮긴다. 무엇이 필요하고 무엇이 필요 없는지 구분한다
 소요   : 약 40분

--------------------------------------------------------------------------------
 [1] 세 번째 노드
--------------------------------------------------------------------------------

-- 이 장은 노드가 하나 더 필요하다. 템플릿 VM 을 복제해 만들었다.
--
--   호스트명  farsync-srv
--   IP        172.16.225.62
--   메모리    2048MB   (chicago/boston 은 6144MB)
--   CPU       2        (chicago/boston 은 4)
--   ORACLE_SID  farsync
--
-- ★ 자원이 눈에 띄게 적다. Far Sync 는 데이터를 적용하지 않으므로
--   버퍼 캐시도 크게 필요 없고 데이터 파일도 없다.
--   이것이 Far Sync 를 쓰는 실질적 이유 중 하나다.

[oracle@farsync-srv ~]$ hostname
farsync-srv

[oracle@farsync-srv ~]$ cat /etc/hosts
127.0.0.1   localhost localhost.localdomain
172.16.225.60   chicago-srv
172.16.225.61   boston-srv
172.16.225.62   farsync-srv

-- ★ 세 노드 모두 같은 /etc/hosts 를 갖도록 맞춘다.
--   3장에서 Primary 와 Standby 를 연결할 때 했던 일과 같다.
--   이름 해석이 안 되면 뒤의 모든 단계가 TNS 오류로 끝난다.

[oracle@farsync-srv ~]$ ping -c 1 chicago-srv | head -2
PING chicago-srv (172.16.225.60) 56(84) bytes of data.
64 bytes from chicago-srv (172.16.225.60): icmp_seq=1 ttl=64 time=0.421 ms

[oracle@farsync-srv ~]$ ping -c 1 boston-srv | head -2
PING boston-srv (172.16.225.61) 56(84) bytes of data.
64 bytes from boston-srv (172.16.225.61): icmp_seq=1 ttl=64 time=0.512 ms

-- ★ Far Sync 는 Primary 와도 Standby 와도 통신해야 한다.
--   받는 것은 Primary 에게서, 보내는 것은 Standby 에게로 간다.
--   양쪽 모두 확인한다.

[oracle@farsync-srv ~]$ ls $ORACLE_HOME/bin/oracle
/u01/app/oracle/product/19.3.0/dbhome_1/bin/oracle

-- ★ 오라클 바이너리가 있어야 한다. 그것도 Primary 와 같은 19.3.0 이어야 한다.
--   Far Sync 는 리두를 다루므로 리두 형식이 같아야 하기 때문이다.
--   실습에서는 같은 템플릿에서 복제했으므로 자동으로 일치한다.

--------------------------------------------------------------------------------
 [2] 컨트롤 파일은 Primary 가 만든다
--------------------------------------------------------------------------------

SYS@chicago> SELECT name, db_unique_name, database_role, open_mode FROM v$database;

NAME      DB_UNIQUE_NAME   DATABASE_ROLE    OPEN_MODE
--------- ---------------- ---------------- --------------------
CHICAGO   chicago          PRIMARY          READ WRITE

1 row selected.

SYS@chicago> ALTER DATABASE CREATE FAR SYNC INSTANCE CONTROLFILE AS '/tmp/farsync.ctl';

Database altered.

[oracle@chicago-srv ~]$ ls -l /tmp/farsync.ctl
-rw-r-----. 1 oracle dba 18989056 Aug 27 15:34 /tmp/farsync.ctl

-- ★ 18,989,056 바이트, 약 19MB 다.
--
--   3장에서 만든 Standby 컨트롤 파일과 크기가 비슷하다.
--   실제로 데이터 파일 목록, 로그 그룹 정의, 아카이브 이력 같은
--   메타데이터를 그대로 담고 있기 때문이다.
--
--   다른 것은 파일 안에 기록된 "유형" 이다.
--   실습 02 에서 CONTROLFILE_TYPE 으로 확인한다.

-- ★ 명령의 형태를 기억한다.
--
--   Standby 용   ALTER DATABASE CREATE STANDBY CONTROLFILE AS '...';
--   Far Sync 용  ALTER DATABASE CREATE FAR SYNC INSTANCE CONTROLFILE AS '...';
--
--   FAR SYNC INSTANCE 라는 낱말이 들어간다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 이름을 잘못 쓰면
--------------------------------------------------------------------------------

SYS@chicago> ALTER DATABASE CREATE FARSYNC INSTANCE CONTROLFILE AS '/tmp/x.ctl';

alter database create farsync instance controlfile as '/tmp/x.ctl'
                      *
ERROR at line 1:
ORA-00900: invalid SQL statement

>>> 원인 파악

-- FAR 와 SYNC 사이에 공백이 있어야 한다.
-- 파라미터 이름은 DB_UNIQUE_NAME=farsync 처럼 붙여 쓰지만
-- SQL 구문에서는 FAR SYNC 로 띄어 쓴다.
--
-- 헷갈리기 쉬운 지점이므로 표로 정리한다.
--
--   SQL 구문        FAR SYNC INSTANCE      (띄어 쓴다)
--   DATABASE_ROLE   FAR SYNC               (띄어 쓴다)
--   CONTROLFILE_TYPE  FARSYNC              (붙여 쓴다)
--   DB_UNIQUE_NAME    farsync              (우리가 정한 이름)

>>> 조치

SYS@chicago> ALTER DATABASE CREATE FAR SYNC INSTANCE CONTROLFILE AS '/tmp/x.ctl';

Database altered.

>>> 재확인

[oracle@chicago-srv ~]$ ls -l /tmp/x.ctl
-rw-r-----. 1 oracle dba 18989056 Aug 27 15:55 /tmp/x.ctl

[oracle@chicago-srv ~]$ rm -f /tmp/x.ctl

-- ★ 확인용으로 만든 것이므로 지운다.
--   컨트롤 파일은 만들 때마다 그 시점의 상태를 담는다.
--   실제로 쓸 것은 /tmp/farsync.ctl 하나면 된다.

--------------------------------------------------------------------------------

[oracle@chicago-srv ~]$ scp $ORACLE_HOME/dbs/orapwchicago \
>   oracle@farsync-srv:/u01/app/oracle/product/19.3.0/dbhome_1/dbs/orapwfarsync
orapwchicago                                  100% 2048     2.3MB/s   00:00

-- ★ 옮기는 것은 두 개뿐이다.
--
--   ① 컨트롤 파일 — Far Sync 인스턴스의 전부라고 해도 된다
--   ② 패스워드 파일 — Primary 가 원격으로 접속해 리두를 보내려면 필요하다
--
-- ★ 옮기지 않는 것을 보면 Far Sync 의 성격이 드러난다.
--
--   데이터 파일    없다. 적용하지 않으므로 필요 없다
--   임시 파일      없다. 정렬할 일이 없다
--   SPFILE         없다. 실습에서는 pfile 로 기동한다
--   리두 로그      없다. 실습 03 에서 SRL 만 만든다
--
-- ★ 패스워드 파일의 이름이 orapw<SID> 규칙을 따라 바뀐다는 점을 놓치기 쉽다.
--   Far Sync 의 SID 는 farsync 이므로 orapwfarsync 가 되어야 한다.
--   3장에서 orapwchicago 를 orapwboston 으로 옮긴 것과 같다.

[oracle@farsync-srv ~]$ ls -l /u01/app/oracle/oradata/FARSYNC/
total 18544
-rw-r--r--. 1 oracle dba 18989056 Aug 27 15:38 control01.ctl

[oracle@farsync-srv ~]$ ls -l $ORACLE_HOME/dbs/orapwfarsync
-rw-r-----. 1 oracle dba 2048 Aug 27 15:38 /u01/app/oracle/product/19.3.0/dbhome_1/dbs/orapwfarsync
