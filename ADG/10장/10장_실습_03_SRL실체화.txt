================================================================================
 제10장 실습 03 — SRL 실체화
 대상   : farsync-srv
 목표   : SRL 정의가 컨트롤 파일과 함께 상속된다는 것을 확인하고,
          정의만 있고 파일이 없는 상태를 CLEAR LOGFILE 로 해결한다
 소요   : 약 25분
 변경   : SRL 파일 4개 생성 (200MB × 4)
================================================================================

--------------------------------------------------------------------------------
 [1] SRL 을 만들려고 하면
--------------------------------------------------------------------------------

-- Far Sync 는 리두를 받아 SRL 에 쓴다. 그러므로 SRL 이 반드시 있어야 한다.
-- 4장에서 boston 에 SRL 을 만들었던 것과 같은 명령을 쓴다.

SYS@farsync> ALTER DATABASE ADD STANDBY LOGFILE THREAD 1 GROUP 4
  2            '/u01/app/oracle/oradata/FARSYNC/stdby04.log' SIZE 200M;

-- ★ 이미 있다. 만들 필요가 없었다.
--
--   컨트롤 파일이 Primary 의 로그 그룹 정의를 그대로 담아 왔기 때문이다.
--   4~7번 SRL 은 4장에서 chicago 에 만든 것이다.
--
-- ★ 경로가 바뀐 것을 주목한다.
--
--   chicago 원본  /u03/app/oracle/oradata/Chicago/stdbyredo04.log
--   farsync       /u01/app/oracle/oradata/FARSYNC/stdbyredo04.log
--
--   log_file_name_convert 가 변환한 결과다.
--   실습 02 의 pfile 에 넣었던 그 파라미터가 여기서 일한다.
--
-- ★ 1~3번 ONLINE 그룹은 경로가 그대로 Chicago 다.
--   log_file_name_convert 는 SRL 만 바꾼 것이 아니라 규칙에 맞는 것을 바꾼다.
--   1~3번의 원본 경로는 /u03/.../Chicago/redo01.log 이므로 변환 대상이지만
--   Far Sync 는 온라인 리두를 쓰지 않아 실제로는 의미가 없다.
--   실습 06 에서 V$LOG 를 조회해 이 점을 확인한다.

--------------------------------------------------------------------------------
 [2] 정의는 있는데 파일이 없다
--------------------------------------------------------------------------------

[oracle@farsync-srv ~]$ ls -l /u01/app/oracle/oradata/FARSYNC/
total 18544
-rw-r--r--. 1 oracle dba 18989056 Aug 27 15:38 control01.ctl

-- ★ 컨트롤 파일 하나뿐이다. SRL 파일이 없다.
--
--   8장에서 본 UNNAMED 파일과 성격이 같은 상태다.
--   컨트롤 파일은 "이런 파일이 있어야 한다" 고 말하는데 실제로는 없다.
--
-- ★ 이 상태로 리두를 받으면 어떻게 될까.
--   RFS 가 SRL 을 열려다 실패한다.
--   그래서 경로를 전환하기 전에 반드시 해결해야 한다.

--------------------------------------------------------------------------------
 [3] 조치 — CLEAR LOGFILE
--------------------------------------------------------------------------------

>>> 조치

SYS@farsync> ALTER DATABASE CLEAR LOGFILE GROUP 4;

Database altered.

SYS@farsync> ALTER DATABASE CLEAR LOGFILE GROUP 5;

Database altered.

SYS@farsync> ALTER DATABASE CLEAR LOGFILE GROUP 6;

Database altered.

SYS@farsync> ALTER DATABASE CLEAR LOGFILE GROUP 7;

Database altered.

-- ★ CLEAR LOGFILE 은 "이 로그 그룹을 비운다" 는 명령이다.
--   파일이 없으면 만들어 준다. 그것이 여기서 쓰는 이유다.
--
-- ★ 왜 ADD 가 아니라 CLEAR 인가.
--
--   정의가 이미 있으므로 ADD 는 중복이다 → ORA-01184
--   DROP 후 ADD 도 되지만 두 단계이고 상속된 경로 정보를 잃는다
--   CLEAR 는 한 단계이고 컨트롤 파일의 정의를 그대로 쓴다
--
--   8장에서 UNNAMED 파일을 CREATE DATAFILE ... AS NEW 로 채운 것과
--   같은 발상이다. 정의는 남기고 실체만 만든다.
--
-- ★ 주의 — CLEAR 는 그 로그의 내용을 버리는 명령이다.
--   운영 중인 SRL 에는 함부로 쓰지 않는다.
--   지금은 갓 만든 인스턴스라 버릴 내용이 없어서 안전하다.

--   Primary 의 온라인 리두와 같은 크기다.

--
--     크기  온라인 리두와 같아야 한다
--     개수  온라인 그룹 수 + 1 (3 + 1 = 4)
--
--   크기를 우리가 지정하지 않았는데도 맞는 것은
--   컨트롤 파일의 정의에 크기가 들어 있기 때문이다.

-- ★ UNASSIGNED 는 "아직 아무 시퀀스도 담고 있지 않다" 는 뜻이다.
--   4장에서 boston 의 SRL 을 처음 만들었을 때와 같은 상태다.
--   리두가 들어오기 시작하면 하나가 ACTIVE 로 바뀐다.

--------------------------------------------------------------------------------
 [4] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① SRL 정의는 컨트롤 파일과 함께 상속된다 → ADD 하면 ORA-01184
--   ② 경로는 log_file_name_convert 가 바꿔 준다
--   ③ 정의는 있고 파일은 없다
--   ④ ALTER DATABASE CLEAR LOGFILE GROUP n 으로 실체를 만든다
--   ⑤ 크기는 컨트롤 파일의 정의를 따른다 (209,715,712바이트 = 200MB)
--   ⑥ 만든 직후 상태는 UNASSIGNED
--
-- ★ 이제 Far Sync 는 리두를 받을 준비가 되었다.
--   남은 것은 네트워크다. 다음 실습에서 Oracle Net 을 구성한다.
