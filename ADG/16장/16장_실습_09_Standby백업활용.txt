================================================================================
 제16장 실습 09 — Standby 를 백업에 활용한다
 대상   : boston-srv(Standby), chicago-srv(Primary)
 목표   : Standby 에서 RMAN 백업을 받고 그것이 Primary 에서 쓸 수 있는지 확인한다.
          카탈로그 없이 쓰려면 무엇이 더 필요한지 실측으로 안다
 소요   : 약 35분
 변경   : 백업을 만들었다가 지운다. 역할은 바뀌지 않는다
================================================================================

--------------------------------------------------------------------------------
 [1] 왜 Standby 에서 받는가
--------------------------------------------------------------------------------

-- ★ Data Guard 의 실무 이점 중 하나다.
--
--   ① Primary 의 부하를 덜어 준다.
--      백업은 I/O 를 많이 쓴다. 업무 시간에 받기 어려운 이유다.
--
--   ② 같은 데이터베이스다.
--      DBID 가 같고 파일 번호가 같으므로
--      Standby 에서 받은 백업으로 Primary 를 복구할 수 있다.
--
--   ③ Standby 는 어차피 조회 전용이다.
--      9장의 Active Data Guard 라면 열린 채로 받는다.
--
-- ★ 다만 조건이 있다. 그것을 이 실습에서 확인한다.

SYS@boston> SELECT dbid, name, database_role FROM v$database;

      DBID NAME       DATABASE_ROLE
---------- ---------- ----------------
1852041610 CHICAGO    PHYSICAL STANDBY

SYS@chicago> SELECT dbid, name, database_role FROM v$database;

      DBID NAME       DATABASE_ROLE
---------- ---------- ----------------
1852041610 CHICAGO    PRIMARY

-- ★ DBID 가 같다. 5장에서 DUPLICATE 로 복제했으므로 당연하다.
--   RMAN 은 DBID 로 데이터베이스를 식별한다.
--   그래서 양쪽 백업이 서로 통한다.

--------------------------------------------------------------------------------

>>> 원인 파악

-- ★ RMAN-06820. 경고이고 백업은 진행됐다.
--
-- ★ 무엇을 하려 한 것인가.
--   아카이브 로그를 빠짐없이 백업하려면
--   Primary 의 현재 로그를 먼저 아카이브해야 한다.
--   그래서 Standby 의 RMAN 이 Primary 에 접속을 시도한다.
--
-- ★ cannot connect to remote database
--   rman target / 로 접속했으므로 Primary 자격증명이 없다.
--
-- ★ 이 경고를 없애려면 Primary 접속 정보를 주고 실행한다.
--
--   rman target sys/****@boston catalog ... 가 아니라
--   Standby 백업에서는 다음처럼 Primary 를 알려 주는 방식이 있다.
--   실무에서는 대개 경고를 그대로 두고
--   아카이브 백업은 Primary 에서 받는 쪽을 택한다.

--------------------------------------------------------------------------------
 [5] 조치 ① — 복구 카탈로그
--------------------------------------------------------------------------------

-- ★ 정공법이다. 별도 데이터베이스에 카탈로그를 두고
--   양쪽이 그곳에 이력을 남긴다.
--
--   rman target / catalog rcat/****@catdb
--
-- ★ 그러면 어느 쪽에서 받았든 양쪽이 다 본다.
--
-- ★ Data Guard 환경에서 중요한 설정이 하나 있다.
--
--   RMAN> configure db_unique_name 'boston' connect identifier 'boston';
--
--   카탈로그는 DB_UNIQUE_NAME 으로 구성원을 구별한다.
--   DBID 가 같으므로 그것만으로는 어느 쪽인지 알 수 없기 때문이다.
--   실습 01 에서 DB_NAME 이 아니라 DB_UNIQUE_NAME 으로 구별한다고 한 것이
--   여기서도 그대로 적용된다.
--
-- ★ 이 실습 환경에는 카탈로그용 데이터베이스가 없다.
--   그래서 아래의 두 번째 방법을 실측한다.

 [7] 정리
--------------------------------------------------------------------------------

RMAN> change backuppiece '/home/oracle/df7_4550tgnc_1_1' uncatalog;

[oracle@chicago-srv ~]$ rm -f /home/oracle/df7_*

[oracle@boston-srv ~]$ rman target /
RMAN> delete noprompt backup;

-- ★ 실습으로 만든 것을 지운다.
--   운영이라면 보존 정책(CONFIGURE RETENTION POLICY)에 맡긴다.

-- ★ 등록 해제를 빠뜨리면 어떻게 되는가.
--   파일은 지웠는데 컨트롤 파일에는 남아
--   나중에 복구할 때 없는 조각을 찾는다.
--   CROSSCHECK BACKUP 으로 정리할 수 있다.

--------------------------------------------------------------------------------
 [8] 실무 지침
--------------------------------------------------------------------------------

-- ★ ① 복구 카탈로그를 쓴다.
--      Data Guard 를 운영한다면 사실상 필수다.
--      CONFIGURE DB_UNIQUE_NAME 으로 구성원을 등록한다.
--
-- ★ ② 데이터 파일 백업은 Standby 에서, 아카이브는 Primary 에서.
--      RMAN-06820 경고를 피하는 가장 단순한 배분이다.
--
-- ★ ③ 컨트롤 파일 자동 백업 위치를 정한다.
--      FORMAT 절이 적용되지 않으므로 따로 설정한다.
--
-- ★ ④ 역할이 바뀌면 백업 스크립트도 따라가야 한다.
--      16장 실습 03 에서 확인한 대로 전환은 언제든 일어난다.
--      "boston 에서 백업" 이라고 고정하면 전환 후 Primary 를 백업하게 된다.
--      15장의 원칙대로 역할을 먼저 판정하고 분기한다.
--
-- ★ ⑤ Failover 뒤에는 반드시 전체 백업을 새로 받는다.
--      실습 07 에서 확인한 대로 OPEN RESETLOGS 로 인큐네이션이 바뀐다.

--------------------------------------------------------------------------------
 [9] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① 양쪽 DBID 가 같다 (1852041610). RMAN 은 DBID 로 식별한다
--   ② Standby 에 접속해도 RMAN 은 DB_NAME(CHICAGO)을 보여 준다
--   ③ 열린 채로 백업할 수 있다 (실측 2,820MB → 550MB, 57초)
--   ④ 아카이브 백업은 RMAN-06820 경고가 난다 (Primary 접속 불가)
--   ⑤ 컨트롤 파일 자동 백업은 FORMAT 을 따르지 않고 FRA 로 간다
--   ⑥ ★ Primary 에서는 그 백업이 보이지 않는다 (boston 11건 / chicago 2건)
--   ⑦ 백업 이력은 받은 쪽 컨트롤 파일에만 있다
--   ⑧ 조각을 옮기고 CATALOG START WITH 로 등록하면 쓸 수 있다
--   ⑨ 등록하면 chicago 의 파일 이름(users01.dbf)으로 인식된다
--   ⑩ 경로가 달라도 파일 번호가 같으면 그대로 쓸 수 있다
--
-- ★ 16장의 실습이 끝났다.
--   1장에서 시작한 과정이 여기서 닫힌다.
