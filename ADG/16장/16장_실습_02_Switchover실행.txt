================================================================================
 제16장 실습 02 — Switchover 실행
 대상   : chicago-srv (dgmgrl)
 목표   : DGMGRL 로 역할을 바꾸고 출력의 각 줄이 무엇을 뜻하는지 읽는다.
          정적 등록이 어디에서 쓰이는지 확인한다
 소요   : 약 25분
 변경   : 역할이 바뀐다 (실습 03 에서 되돌린다)
================================================================================

--------------------------------------------------------------------------------
 [1] 표식을 남긴다
--------------------------------------------------------------------------------

SYS@chicago> INSERT INTO system.bk_t VALUES(94,'before-swo');
SYS@chicago> COMMIT;

Commit complete.

SYS@boston> COL tag FOR a16
SYS@boston> SELECT id, tag FROM system.bk_t WHERE id=94;

        ID TAG
---------- ----------------
        94 before-swo

1 row selected.

-- ★ 전환 전에 넣은 행이 이미 Standby 에 도착해 있다.
--   전환 후에도 남아 있는지 확인할 표식이다.

--------------------------------------------------------------------------------
 [2] 한 줄이다
--------------------------------------------------------------------------------

DGMGRL> switchover to 'boston'

Performing switchover NOW, please wait...
Operation requires a connection to database "boston"
Connecting ...
Connected to "boston"
Connected as SYSDBA.
New primary database "boston" is opening...
Operation requires start up of instance "chicago" on database "chicago"
Starting instance "chicago"...
Connected to an idle instance.
ORACLE instance started.
Connected to "chicago"
Database mounted.
Database opened.
Connected to "chicago"
Switchover succeeded, new primary is "boston"

-- ★ 실측 소요 약 64초.
--   명령은 한 줄이고 나머지는 Broker 가 한다.

--------------------------------------------------------------------------------
 [3] 출력을 단계로 나눠 읽는다
--------------------------------------------------------------------------------

-- ★ Performing switchover NOW, please wait...
--      남은 리두를 보내고 역할 전환을 시작한다.
--      이 시점부터 Primary 는 새 트랜잭션을 받지 않는다.
--
-- ★ Operation requires a connection to database "boston"
--    Connecting ... / Connected to "boston" / Connected as SYSDBA.
--      대상에 접속한다. 13장에서 지정한 접속 식별자를 쓴다.
--
-- ★ New primary database "boston" is opening...
--      새 Primary 를 연다. 여기까지는 대상 쪽 일이다.
--
-- ★ Operation requires start up of instance "chicago" on database "chicago"
--    Starting instance "chicago"...
--    Connected to an idle instance.
--      옛 Primary 를 다시 기동한다.
--      idle instance 라는 것은 그 시점에 chicago 가 내려가 있다는 뜻이다.
--
-- ★ ORACLE instance started. / Database mounted. / Database opened.
--      새 Standby 로 올린다.
--
-- ★ Switchover succeeded, new primary is "boston"
--      완료.

--------------------------------------------------------------------------------
 [4] Connected to an idle instance 가 핵심이다
--------------------------------------------------------------------------------

-- ★ 옛 Primary 는 전환 과정에서 한 번 내려간다.
--   그 상태의 인스턴스에 접속하려면
--   리스너에 정적으로 등록되어 있어야 한다.
--   동적 등록은 인스턴스가 살아 있을 때만 유효하기 때문이다.
--
-- ★ 13장에서 listener.ora 에 적은 것이 이것이다.
--
--   (SID_DESC =
--     (GLOBAL_DBNAME = chicago_DGMGRL)
--     (ORACLE_HOME = /u01/app/oracle/product/19.3.0/dbhome_1)
--     (SID_NAME = chicago))
--
-- ★ 그때는 "역할 전환에 필요하다" 고만 했는데
--   그 필요가 여기서 구체적으로 드러난다.
--
-- ★ 이 등록이 없으면 전환은
--   New primary ... is opening 다음에서 멈춘다.
--   새 Primary 는 올라갔는데 옛 Primary 를 되살리지 못한 상태가 된다.
--   실습 01 의 VALIDATE 가 이것을 미리 시험해 준 것이다.
--
-- ★ Database opened. 도 읽어 둔다.
--   새 Standby 가 마운트에서 그치지 않고 열렸다.
--   Broker 가 이전 상태(Active Data Guard)를 기억하고 재현한 것이다.

--------------------------------------------------------------------------------
 [5] 역할이 뒤바뀌었다
--------------------------------------------------------------------------------

SYS@chicago> COL db_unique_name FOR a10
SYS@chicago> COL switchover_status FOR a22
SYS@chicago> SELECT db_unique_name, database_role, open_mode, switchover_status
  2            FROM v$database;

DB_UNIQUE_ DATABASE_ROLE    OPEN_MODE            SWITCHOVER_STATUS
---------- ---------------- -------------------- ----------------------
chicago    PHYSICAL STANDBY READ ONLY WITH APPLY NOT ALLOWED

1 row selected.

SYS@boston> SELECT db_unique_name, database_role, open_mode, switchover_status
  2            FROM v$database;

DB_UNIQUE_ DATABASE_ROLE    OPEN_MODE            SWITCHOVER_STATUS
---------- ---------------- -------------------- ----------------------
boston     PRIMARY          READ WRITE           TO STANDBY

1 row selected.

-- ★ 실습 01 의 두 줄이 그대로 바뀌었다.
--   READ ONLY WITH APPLY 까지 그대로다.
--   9장에서 만든 Active Data Guard 가 전환 후에도 유지된다.

SYS@chicago> SELECT process, status, sequence# FROM v$managed_standby
  2            WHERE process='MRP0';

PROCESS   STATUS         SEQUENCE#
--------- ------------ ----------
MRP0      APPLYING_LOG         86

1 row selected.

-- ★ chicago 에 MRP0 가 떴다. 우리가 명령을 내리지 않았다.
--   Broker 의 Intended State 가 역할과 함께 옮겨 갔기 때문이다.
--   13장에서 배운 개념이 전환에서 이렇게 작동한다.

--------------------------------------------------------------------------------
 [6] 오류 재현 — 전환 후 같은 명령을 또 내리면
--------------------------------------------------------------------------------

DGMGRL> switchover to 'boston'      -- 이미 boston 이 Primary 인 상태에서

Performing switchover NOW, please wait...
Error: ORA-16558: database specified for switchover is not a standby database

Failed.
Unable to switchover, primary database is still "boston"

>>> 원인 파악

-- ★ ORA-16558. 대상이 Standby 가 아니라는 뜻이다.
--
-- ★ 실수처럼 보이지만 실무에서 생긴다.
--   전환 스크립트가 역할을 확인하지 않고
--   고정된 이름으로 전환을 시도하는 경우다.
--
-- ★ 마지막 줄이 중요하다.
--   primary database is still "boston"
--   실패했지만 아무것도 바뀌지 않았다.
--   Performing switchover NOW 까지 출력됐다고 해서
--   중간 상태가 되지는 않았다.

>>> 조치

DGMGRL> show configuration

Configuration - dg_chicago

  Members:
  boston  - Primary database
    chicago - Physical standby database

-- 현재 역할을 먼저 확인한다.
-- 전환 대상은 지금 Standby 인 쪽이다.

>>> 재확인

SYS@boston> SELECT database_role FROM v$database;

DATABASE_ROLE
----------------
PRIMARY

1 row selected.

-- ★ 뷰가 사실이다. 여기서 확인하고 대상을 정한다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① 명령은 switchover to '<대상>' 한 줄이다
--   ② 실측 소요 약 64초
--   ③ 출력은 대상 접속 → 새 Primary 개방 → 옛 Primary 재기동 순서
--   ④ Connected to an idle instance — 정적 등록이 여기서 쓰인다
--   ⑤ Database opened — Active Data Guard 가 재현된다
--   ⑥ 두 역할이 그대로 뒤바뀐다
--   ⑦ MRP0 가 자동으로 뜬다 (Intended State 가 함께 옮겨 간다)
--   ⑧ 자기 자신으로 전환하면 ORA-16558, 상태는 그대로다
--
-- ★ 다음 실습에서 전환 후 무엇이 바뀌었는지 보고 되돌린다.
