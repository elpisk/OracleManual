================================================================================
 제16장 실습 06 — 플래시백 준비
 대상   : chicago-srv, boston-srv
 목표   : Failover 뒤 Reinstate 가 가능하도록 양쪽에 플래시백을 켠다.
          공간과 로그 파일을 확인하고 켤 때의 전제를 익힌다
 소요   : 약 25분
 변경   : 양쪽에 FLASHBACK ON. 이후 장에서도 켜 둔 채로 쓴다
================================================================================

--------------------------------------------------------------------------------
 [1] 왜 필요한가
--------------------------------------------------------------------------------

-- ★ 14장에서 FSFO 를 켤 때 경고를 봤다.
--
--   DGMGRL> enable fast_start failover
--   Warning: ORA-16827: Flashback Database is disabled
--
--   그때는 경고만 하고 넘어갔다.
--
-- ★ Failover 뒤에 옛 Primary 를 되살리려면 플래시백이 있어야 한다.
--
--   Failover 는 Standby 가 받은 데까지만 살리고 나머지를 버린다.
--   옛 Primary 에는 버려진 변경이 남아 있으므로
--   그대로는 새 Primary 의 Standby 가 될 수 없다.
--   플래시백으로 그 지점까지 되감아야 한다.
--
-- ★ 없으면 어떻게 되는가.
--   옛 Primary 를 버리고 6장의 절차로 새로 만든다.
--   데이터 파일 전체를 다시 복제해야 하므로 시간이 크게 늘어난다.

--------------------------------------------------------------------------------

 [3] 켠다
--------------------------------------------------------------------------------

SYS@chicago> ALTER DATABASE FLASHBACK ON;

Database altered.

SYS@chicago> SELECT flashback_on, open_mode, database_role FROM v$database;

FLASHBACK_ON       OPEN_MODE            DATABASE_ROLE
------------------ -------------------- ----------------
YES                READ WRITE           PRIMARY

1 row selected.

-- ★ 열린 채로 켤 수 있다.
--   예전 버전에서는 마운트 상태를 요구했으나
--   19c 에서는 READ WRITE 인 채로 켰다.
--
-- ★ Standby 쪽도 켠다. 마운트 상태에서도 성공한다.

SYS@boston> ALTER DATABASE FLASHBACK ON;

Database altered.

SYS@boston> SELECT flashback_on, log_mode, open_mode FROM v$database;

FLASHBACK_ON       LOG_MODE     OPEN_MODE
------------------ ------------ --------------------
YES                ARCHIVELOG   READ ONLY WITH APPLY

1 row selected.

-- ★ 양쪽 다 켜졌다.
--   Reinstate 가 필요한 쪽은 Failover 때 Primary 였던 쪽이므로
--   양쪽에 모두 켜 두어야 어느 방향이든 대비된다.

-- ★ 이 오류는 무해하다. 이미 원하는 상태이기 때문이다.

  2                 flashback_size/1024/1024 fb_mb
  3            FROM v$flashback_database_log;

-- ★ 이 뷰로 얼마나 되감을 수 있는지 알 수 있다.
--
--   OLDEST_FLASHBACK_SCN   여기까지 되감을 수 있다
--   RETENTION_TARGET       목표 보존 시간(분). 기본 1440(24시간)
--   FLASHBACK_SIZE         지금 쓰고 있는 크기
--
-- ★ Reinstate 는 Failover 시점까지만 되감으면 되므로
--   보존 시간이 길 필요는 없다.
--   다만 Failover 를 늦게 알아채면 그만큼 필요하다.

--------------------------------------------------------------------------------
 [6] 대가
--------------------------------------------------------------------------------

-- ★ 플래시백을 켜면 치르는 비용
--
--   ① 공간 — FRA 에 플래시백 로그가 쌓인다
--   ② 쓰기 — 블록이 바뀌기 전 이미지를 기록하므로 I/O 가 는다
--   ③ 관리 — FRA 포화를 감시해야 한다
--
-- ★ 얻는 것
--
--   ① Failover 후 Reinstate 가 가능하다 (실습 07)
--   ② FSFO 의 Auto-reinstate 가 동작한다 (14장)
--   ③ 실수한 변경을 되감을 수 있다 (Data Guard 와 무관한 이점)
--
-- ★ 14장의 DelayMins 와 같은 구조의 거래다.
--   무엇을 사고 무엇을 파는지 알고 결정한다.
--
-- ★ Data Guard 를 운영한다면 켜는 쪽을 권한다.
--   Reinstate 를 못 하면 재구축이며, 그 시간이 훨씬 크다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① 전제는 FRA 지정과 ARCHIVELOG 모드
--   ② 19c 에서는 열린 채로 ALTER DATABASE FLASHBACK ON 이 된다
--   ③ Standby 는 마운트 상태에서도 켜진다
--   ④ 이미 켜져 있으면 ORA-38706 + ORA-38713
--   ⑤ 오류가 두 줄이면 두 번째 줄이 이유다
--   ⑥ 켜는 순간 200MB×2 의 .flb 파일이 생긴다
--   ⑦ V$FLASHBACK_DATABASE_LOG 로 되감을 수 있는 범위를 본다
--   ⑧ 공간·쓰기·관리를 치르고 Reinstate 를 산다
--
-- ★ 다음 실습에서 실제로 Failover 하고 되살린다.
