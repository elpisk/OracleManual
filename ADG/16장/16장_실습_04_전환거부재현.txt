================================================================================
 제16장 실습 04 — 전환이 거부되는 경우
 대상   : chicago-srv (dgmgrl)
 목표   : 전환 명령이 거부되는 상황을 모아 오류를 구별한다.
          실패한 명령이 상태를 바꾸지 않는다는 것을 확인한다
 소요   : 약 20분
 변경   : 없음 (전부 실패하는 명령)
================================================================================

--------------------------------------------------------------------------------
 [1] 출발점
--------------------------------------------------------------------------------

DGMGRL> show configuration

Configuration - dg_chicago

  Protection Mode: MaxPerformance
  Members:
  chicago - Primary database
    boston  - Physical standby database

Fast-Start Failover:  Disabled

Configuration Status:
SUCCESS

-- ★ 실습 03 을 마친 상태다.
--   이 실습의 명령은 모두 실패하므로 상태가 바뀌지 않아야 한다.
--   그것을 확인하는 것도 이 실습의 목적이다.

--------------------------------------------------------------------------------
 [2] 오류 재현 — 없는 멤버
--------------------------------------------------------------------------------

DGMGRL> switchover to 'seattle'

Object "seattle" was not found

>>> 원인 파악

-- ★ 13·14장에서 본 것과 같은 표현이다.
--   ORA- 번호가 아니라 문장으로 알려 준다.
--
-- ★ 이 성질이 스크립트에서 함정이 된다.
--
--   실패 판정을 "출력에 ORA- 가 있는가" 로만 하면
--   이 경우를 성공으로 오인한다.
--
-- ★ DGMGRL 의 종료 코드도 함께 확인하는 것이 안전하다.
--   그리고 전환 후에는 반드시 SHOW CONFIGURATION 으로 결과를 본다.
--   14장에서 enable 계열 명령에 대해 세운 원칙과 같다.

>>> 조치

DGMGRL> show configuration

-- 멤버 이름을 확인한다. chicago 와 boston 뿐이다.

>>> 재확인

DGMGRL> validate database 'boston'

  Ready for Switchover:  Yes

-- ★ 올바른 이름은 동작한다. 구성은 그대로다.

--------------------------------------------------------------------------------
 [3] 오류 재현 — 자기 자신으로
--------------------------------------------------------------------------------

DGMGRL> switchover to 'chicago'

Performing switchover NOW, please wait...
Error: ORA-16558: database specified for switchover is not a standby database

Failed.
Unable to switchover, primary database is still "chicago"

>>> 원인 파악

-- ★ ORA-16558. 대상이 Standby 가 아니다.
--
-- ★ 앞의 경우와 출력 구조가 다르다.
--
--   없는 멤버   : 명령을 시작조차 하지 않는다 (문장만)
--   자기 자신   : Performing switchover NOW 까지 출력한다
--
-- ★ 그러나 결과는 같다. 아무것도 바뀌지 않았다.
--   마지막 줄이 그것을 명시한다.
--   Unable to switchover, primary database is still "chicago"
--
-- ★ Broker 가 전환을 시작하기 전에 대상을 검사하는 것이 아니라
--   시작한 뒤에 검사한다는 뜻이다.
--   그래도 되돌릴 수 있는 지점에서 멈춘다.

>>> 조치

SYS@chicago> SELECT db_unique_name FROM v$database WHERE database_role='PRIMARY';

DB_UNIQUE_NAME
--------------------
chicago

1 row selected.

-- ★ 뷰로 현재 Primary 를 확인하고 그 반대를 대상으로 삼는다.

>>> 재확인

DGMGRL> show configuration

Configuration Status:
SUCCESS

-- ★ 구성은 그대로다.

--------------------------------------------------------------------------------
 [4] 14장에서 만든 거부 두 가지
--------------------------------------------------------------------------------

-- ★ 14장에서 VALIDATE 로 확인한 두 상황을 떠올린다.
--   실제로 전환을 시도하면 같은 이유로 막힌다.
--
-- ★ 첫째 — 전송이 꺼져 있을 때
--
--   DGMGRL> edit database 'boston' set property 'LogShipping'='OFF';
--   DGMGRL> validate database 'boston'
--
--     Ready for Switchover:  No
--
--   Switchover 는 무손실이어야 하므로
--   보내지 못한 리두가 있으면 진행할 수 없다.
--
-- ★ 둘째 — 적용 지연이 걸려 있을 때
--
--   DGMGRL> edit database 'boston' set property 'DelayMins'='2';
--   DGMGRL> validate database 'boston'
--
--     Error: Switchover to this standby is not possible because
--     an apply delay has been set
--
--   VALIDATE 가 이유를 문장으로 준다.
--
-- ★ 두 경우 모두 원인을 해소하면 다시 Yes 가 된다.
--   LogShipping 을 ON 으로, DelayMins 를 0 으로 되돌린다.
--
-- ★ 이것이 실습 01 에서 사전 점검을 강조한 이유다.
--   VALIDATE 가 Yes 인지 먼저 보면 실패할 전환을 시도하지 않는다.

--------------------------------------------------------------------------------
 [5] 오류를 구별하는 표
--------------------------------------------------------------------------------

-- ★ 지금까지 만난 전환 관련 오류
--
--   표현                                          원인
--   --------------------------------------------  ----------------------
--   Object "..." was not found                    멤버 이름이 없다
--   ORA-16558                                     대상이 Standby 가 아니다
--   Ready for Switchover: No (전송 차단)          보낼 것이 남았다
--   an apply delay has been set                   DelayMins 가 걸렸다
--   ORA-16653 (실습 07)                           Reinstate 대상에 접속 불가
--   ORA-16661 (실습 07)                           Reinstate 가 필요하다
--
-- ★ 오류 번호가 있는 것과 없는 것이 섞여 있다.
--   판정 스크립트는 두 가지를 모두 다뤄야 한다.

--------------------------------------------------------------------------------
 [6] 실패는 상태를 바꾸지 않는다
--------------------------------------------------------------------------------

SYS@chicago> SELECT db_unique_name, database_role, open_mode, switchover_status
  2            FROM v$database;

DB_UNIQUE_ DATABASE_ROLE    OPEN_MODE            SWITCHOVER_STATUS
---------- ---------------- -------------------- ----------------------
chicago    PRIMARY          READ WRITE           TO STANDBY

1 row selected.

SYS@boston> SELECT db_unique_name, database_role, open_mode FROM v$database;
SYS@boston> SELECT process, status, sequence# FROM v$managed_standby WHERE process='MRP0';

DB_UNIQUE_ DATABASE_ROLE    OPEN_MODE
---------- ---------------- --------------------
boston     PHYSICAL STANDBY READ ONLY WITH APPLY

PROCESS   STATUS         SEQUENCE#
--------- ------------ ----------
MRP0      APPLYING_LOG         91

-- ★ 세 번의 실패한 명령 뒤에도 구성이 온전하다.
--
-- ★ 이것이 Broker 로 전환하는 이유 중 하나다.
--   실패하면 시작 지점으로 남는다.
--   실습 05 에서 그렇지 않은 경우를 본다.

--------------------------------------------------------------------------------
 [7] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① 없는 멤버는 문장으로만 알려 준다 (ORA- 번호 없음)

--   ③ 후자는 Performing switchover NOW 까지 출력한다

--   ⑥ 오류 번호가 있는 것과 없는 것이 섞여 있다
--   ⑦ 실패한 Broker 명령은 상태를 바꾸지 않는다
--
