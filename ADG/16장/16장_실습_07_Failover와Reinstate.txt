================================================================================
 제16장 실습 07 — Failover 와 Reinstate
 대상   : chicago-srv, boston-srv
 목표   : Primary 를 강제 종료하고 Failover 한 뒤 옛 Primary 를 되살린다.
          Switchover 와 무엇이 다른지 실측으로 확인한다
 소요   : 약 60분
 변경   : Failover → Reinstate → Switchover 로 원래 역할까지 되돌린다
 주의   : OPEN RESETLOGS 를 수반하므로 이후 백업 계획이 바뀐다
          시작 전에 꺼진 상태의 VM 스냅샷을 확보한다

-- ★ 실측
--
--   Switchover   약 64초 / 69초 / 55초
--   Failover     약 24초

--
-- ★ 재해 대응의 총 소요는 Failover 시간만이 아니다.
--
--   상황 판단           사람이 결정한다 (자동이면 FSFO 의 Threshold)
--   Failover            24초
--   애플리케이션 재접속  접속 문자열과 재시도 설정에 달렸다
--   Reinstate           51초 (업무 재개 후에 해도 된다)
--
-- ★ 14장에서 본 estimated startup time 11초와 함께
--   이 숫자들이 RTO 를 말할 근거가 된다.

 [11] 정리
--------------------------------------------------------------------------------

-- ★ 이 실습에서 확인한 것
--
--   ① Standby 는 Possible network disconnect 라고만 말한다
--   ② 그 메시지의 ERROR_CODE 는 0 — 15장 필터로 걸러진다
--   ③ Broker 는 ORA-1034 로 적는다 (SQL*Plus 는 ORA-01034)
--   ④ Ready for Failover 의 괄호가 (Primary Not Running) 으로 바뀐다
--   ⑤ Failover 는 두 줄, 24초
--   ⑥ MaxPerformance 인데도 손실이 없었다 (보장은 아니다)
--   ⑦ RESETLOGS_TIME 이 갱신된다 — 새 인큐네이션
--   ⑧ 구성에 (disabled) + ORA-16661 인데 상태는 SUCCESS
--   ⑨ 내려간 채로 Reinstate 하면 ORA-16653
--   ⑩ 옛 Primary 는 MOUNT 까지만 올리고 자기를 PRIMARY 라고 말한다
--   ⑪ Reinstate 51초, 이후 시퀀스가 4 로 시작
--   ⑫ 전환 직후 ORA-16786 은 판정 시차
--
-- ★ 16장의 실습이 끝났다.
--   1장에서 시작한 과정이 여기서 닫힌다.
