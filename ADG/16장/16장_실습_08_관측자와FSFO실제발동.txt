-- ★ 역할은 바뀌었는데 아직 MOUNTED 이고 MRP 도 없다.
--
-- ★ 실습 07 의 수동 Reinstate 에서는
--   READ ONLY WITH APPLY / MRP0 APPLYING_LOG 였다.
--   차이는 확인 시점이다.
--
-- ★ 재편입은 "역할을 되돌리는 것" 까지이고
--   그다음 Intended State(APPLY-ON, 열기)를 적용하는 것은
--   Broker 가 이어서 하는 별개의 단계다.
--   조금 더 기다리면 READ ONLY WITH APPLY 가 된다.
--
-- ★ 즉 자동 전환 뒤에는 두 번 확인해야 한다.
--   ① 역할이 돌아왔는가  ② 적용이 시작됐는가
--   ①만 보고 끝내면 복제가 아직 없는 구간을 놓친다.

-- ★ 이 실습에서 확인한 것
--
--   ① 관측자는 인스턴스 없는 호스트에서도 돈다 (소프트웨어만 필요)
--   ② CONNECT IDENTIFIER IS 형식은 자격증명을 다시 요구한다 (ORA-01017)
--   ③ nohup + 전경 실행 형식이 자동화에 맞다
--   ④ 관측자 이름은 호스트 이름을 쓴다
--   ⑤ SHOW OBSERVER 의 Last Ping 두 줄이 감시 생존 신호다
--   ⑥ 자동 전환까지 약 69초 (threshold 30초 + 확인 + 전환 33초)
--   ⑦ 전환 중 Standby 는 MOUNTED 를 거친다
--   ⑧ ★ 관측자는 "Standby 가 방금까지 Primary 와 연락했다" 면 한 번 거부한다
--   ⑨ 자동 전환도 OPEN RESETLOGS 를 수반한다
--   ⑩ 전환 후 ORA-16824(새 Primary) + ORA-16661(옛 Primary, disabled)
--   ⑪ MOUNT 만 해 두면 약 42초에 자동 재편입된다
--   ⑫ 재편입 중에는 ORA-16657
--   ⑬ 재편입 직후에는 아직 MOUNTED 다. 적용 시작은 그다음 단계다
--   ⑭ 정리 순서는 STOP OBSERVER → DISABLE → 대상 삭제
--
-- ★ 다음 실습에서 Standby 를 백업에 활용한다.
