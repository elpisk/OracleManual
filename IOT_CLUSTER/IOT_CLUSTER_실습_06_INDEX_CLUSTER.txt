--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 클러스터(cluster) 는 여러 테이블의 행을 **같은 블록에** 담는 구조다.
-- 부서 10 의 부서 행 하나와 그 부서 직원 행 전부를 한 블록에 모아 두면
-- 조인할 때 블록 하나만 읽으면 된다. 그것이 클러스터의 아이디어다.
--
--   일반 구조 : [DEPT 블록] ... [EMP 블록] [EMP 블록] ...   -> 여러 블록을 읽는다
--   클러스터  : [deptno=10 : DEPT 1행 + EMP n행]            -> 한 블록에 모여 있다
--
-- 인덱스 클러스터는 클러스터 키 값을 인덱스로 찾아 그 블록으로 간다.
--
-- 목표
--   (1) CREATE CLUSTER · SIZE 절의 의미를 이해한다
--   (2) 클러스터 인덱스가 없으면 쓸 수 없다는 것을 확인한다 (ORA-02032)
--   (3) 두 테이블을 같은 클러스터에 두고 딕셔너리 세 개를 읽는다
--   (4) ANALYZE CLUSTER 로 avg_blocks_per_key 를 얻고 그 의미를 본다
--   (5) 조인 실행계획에서 TABLE ACCESS CLUSTER 를 확인한다
-- 작업 유형 : 구조 확인

--------------------------------------------------------------------------------
[2] 사전 조건
--------------------------------------------------------------------------------
-- · USERS 테이블스페이스에 여유가 조금 있으면 된다 (이 실습은 1MB 도 쓰지 않는다)
-- · 클러스터는 별도 옵션이 필요 없다. Standard Edition 에서도 쓸 수 있다
-- · 클러스터는 Oracle 초기부터 있는 기능이고 지금은 거의 쓰이지 않는다.
--   왜 쓰이지 않는지를 실측으로 이해하는 것이 이 실습의 목적이기도 하다

-- SIZE 512 의 의미
--   하나의 클러스터 키 값이 쓸 것으로 예상하는 바이트 수다.
--   8K 블록이면 8192 / 512 = 16, 즉 블록 하나에 키 16개를 담도록 계산한다.
--   너무 작게 잡으면 한 키의 행이 여러 블록으로 흘러넘치고(체인),
--   너무 크게 잡으면 블록이 비어서 공간이 낭비된다.
--   -> 키 하나당 평균 데이터 크기를 먼저 추정해야 한다. 이것이 클러스터 설계의 어려움이다.
--
-- dba_clusters 를 읽는 법
--   cluster_type = INDEX   인덱스 클러스터 (해시 클러스터는 HASH)
--   hashkeys = 0           인덱스 클러스터이므로 해시 키가 없다
--   single_table = N       여러 테이블을 담을 수 있다
--   avg_blocks_per_key     아직 비어 있다. ANALYZE CLUSTER 를 해야 채워진다
--
-- 세그먼트가 CLUSTER 타입으로 하나 생겼다. 이 세그먼트에 모든 테이블의 행이 들어간다.

-- 딕셔너리 세 개를 읽는다.
--   dba_tables.cluster_name   그 테이블이 어느 클러스터에 속하는가
--                             blocks · num_rows 는 통계 수집 전이라 비어 있다
--   dba_clu_columns           클러스터 정의 컬럼 <-> 테이블 컬럼 매핑
--                             테이블마다 컬럼 이름이 달라도 된다
--   dba_segments              **DEPT_CLU · EMP_CLU 세그먼트가 없다**
--                             두 테이블의 데이터가 모두 PERSONNEL_CLUSTER 세그먼트에 있다
--
-- 이것이 클러스터의 핵심이다. 테이블은 논리적 이름일 뿐이고 저장은 클러스터 단위다.
-- 따라서 테이블 하나만 TRUNCATE · MOVE · 압축하는 것이 불가능하거나 제한된다.

-- 조인 비용 비교 (부서 10 의 직원 5002명)
--
--   구조       | 계획                                         | Buffers
--   -----------|----------------------------------------------|--------
--   클러스터   | NESTED LOOPS + TABLE ACCESS CLUSTER          |   16
--   일반 테이블| NESTED LOOPS + TABLE ACCESS FULL(EMP_HEAP_C) |   18
--
-- 차이가 16 대 18 로 작다. 데이터가 작아서 힙 쪽도 풀 스캔 17블록으로 끝났기 때문이다.
-- 클러스터의 이득이 나타나는 조건은 다음과 같다.
--   · 키가 아주 많고 (부서가 수만 개)
--   · 키마다 행 수가 적고 균일하며 (부서당 직원 10명 정도)
--   · 항상 키 하나씩 조인해서 읽는다
-- 이 조건에서는 힙이 인덱스 + 테이블 접근을 반복하는 동안 클러스터는 블록 1개로 끝난다.
--
-- TABLE ACCESS CLUSTER 라는 연산 이름을 기억한다.
-- 그 아래에 INDEX UNIQUE SCAN (클러스터 인덱스) 가 붙는 것이 클러스터 접근의 형태다.

-- 클러스터를 지우는 법
--   DROP CLUSTER ...                    -> 테이블이 남아 있으면 ORA-00951
--   DROP CLUSTER ... INCLUDING TABLES   -> 속한 테이블까지 함께 지운다
--   DROP TABLE 로 테이블을 먼저 다 지우고 나서 DROP CLUSTER 를 해도 된다

[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1. 인덱스 클러스터는 신규 설계에 거의 쓰지 않는다.
--    이유는 세 가지다.
--      · SIZE 추정이 어렵고 틀리면 avg_blocks_per_key 가 커져 이득이 사라진다
--      · 테이블 단위 관리(TRUNCATE · MOVE · 파티션) 가 제한된다
--      · 대량 INSERT 가 느리고 공간 낭비가 크다
--    같은 목적(조인 블록 지역성) 은 지금은 파티션·IOT·머티리얼라이즈드 뷰로 달성한다.
--
-- 2. 그래도 알아야 하는 이유는 진단이다.
--    실행계획에 TABLE ACCESS CLUSTER 가 보이면 그 테이블은 클러스터에 속해 있고,
--    세그먼트·통계·관리 방법이 전부 다르다. 모르면 원인을 찾을 수 없다.
--
-- 3. 순서를 외운다.
--    CREATE CLUSTER -> CREATE INDEX ON CLUSTER -> CREATE TABLE ... CLUSTER
--    인덱스를 빼먹으면 ORA-02032 다. 복구 스크립트를 짤 때도 이 순서를 지켜야 한다.
--
-- 4. avg_blocks_per_key 가 클러스터의 건강 지표다.
--      SELECT cluster_name, avg_blocks_per_key FROM dba_clusters;
--    1 에 가까우면 정상, 커지면 SIZE 를 다시 잡고 재구성해야 한다.
--    값을 채우려면 ANALYZE CLUSTER COMPUTE STATISTICS 를 돌려야 한다 (dbms_stats 아님).
--
-- 5. 세그먼트가 클러스터 단위라는 것을 기억한다.
--    dba_segments 에 테이블 이름이 없다. 용량 산정 쿼리가 테이블 기준이면 누락된다.
--      SELECT segment_name, segment_type, bytes FROM dba_segments
--      WHERE  segment_type = 'CLUSTER';
--
-- 6. 이 실습에서 본 오류
--    ORA-02032  클러스터 인덱스 없이 사용        -> CREATE INDEX ON CLUSTER
--    ORA-00951  테이블이 남은 클러스터 DROP      -> INCLUDING TABLES
