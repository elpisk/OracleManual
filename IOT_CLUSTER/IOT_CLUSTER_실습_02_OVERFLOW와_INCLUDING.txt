--------------------------------------------------------------------------------
[1] 시나리오 개요
--------------------------------------------------------------------------------
-- IOT 는 데이터를 인덱스 리프 블록에 담는다. 그런데 행이 너무 크면 담을 수 없다.
-- 리프 블록 하나에 행 하나만 들어가면 B*Tree 가 깊어져 인덱스 구실을 못 한다.
-- 그래서 Oracle 은 행의 일부를 떼어 낼 곳(OVERFLOW 세그먼트) 을 요구한다.
--
--   [인덱스 세그먼트]  기본키 + 자주 쓰는 앞쪽 컬럼
--   [오버플로 세그먼트] 나머지 큰 컬럼
--
-- 어디서 자를지는 두 가지 방법으로 정한다.
--   PCTTHRESHOLD n   블록의 n% 를 넘으면 그 지점부터 잘라 낸다 (기본 50)
--   INCLUDING col    그 컬럼까지 인덱스에 두고 이후 컬럼은 전부 오버플로로 (권장)
--
-- 목표
--   (1) OVERFLOW 가 없으면 CREATE 자체가 거부되는 것을 확인한다
--   (2) INCLUDING 으로 자르는 위치를 지정하고 딕셔너리에서 확인한다
--   (3) 인덱스만 읽는 조회와 오버플로까지 읽는 조회의 비용 차이를 측정한다
--   (4) PCTTHRESHOLD 의 유효 범위를 확인한다
--   (5) 비트맵 인덱스에 MAPPING TABLE 이 필요한 이유를 본다
-- 작업 유형 : 구조 설계

--     블록의 절반을 넘는 행을 인덱스에 두면 리프 블록에 행이 하나만 들어가므로 금지한다.
--   PCTTHRESHOLD 만 쓰면 include_column 이 0 이다 (지정하지 않았다는 뜻).
--   나중에 ALTER TABLE ... PCTTHRESHOLD n 으로 바꿀 수 있고, 기존 행은 그대로 남는다.
--   즉 바꿔도 이미 저장된 행이 재배치되지는 않는다. 새로 넣는 행부터 적용된다.

-- ORA-28669: bitmap index can not be created on an IOT with no mapping table
--   비트맵 인덱스는 물리 ROWID 를 비트 위치로 쓴다. IOT 는 논리 ROWID 라 불가능하다.
--   그래서 Oracle 은 "논리 ROWID <-> 물리 ROWID" 대응표(MAPPING TABLE) 를 요구한다.
--   MAPPING TABLE 절을 주면 SYS_IOT_MAP_nnn 힙 테이블이 하나 더 생기고
--   그 위에 비트맵 인덱스를 만들 수 있다 (iot_type = IOT_MAPPING).
--
--   비용 : 세그먼트가 하나 더 늘고 DML 마다 대응표를 유지해야 한다.
--          IOT 에 비트맵 인덱스가 정말 필요한지 먼저 따져 본다.

[8] 실무 포인트

-- 1. OVERFLOW 는 선택이 아니라 대부분 필수다.
--    VARCHAR2(4000) 이나 긴 설명 컬럼이 하나라도 있으면 CREATE 가 막힌다.
--    설계 단계에서 OVERFLOW 테이블스페이스를 어디로 할지 함께 정한다.
--
-- 2. INCLUDING 을 쓰고, 컬럼 순서를 조회 빈도 순으로 정렬한다.
--    자주 쓰는 컬럼을 앞에 모아 INCLUDING 안쪽에 넣는 것이 IOT 설계의 핵심이다.
--    실측에서 그 경계 하나로 범위 조회 Buffers 가 8 대 258 로 갈렸다.
--
-- 3. 오버플로 접근은 실행계획에 보이지 않는다.
--    계획은 INDEX UNIQUE SCAN 한 줄로 똑같다. Buffers·Reads 로만 구분된다.
--    IOT 튜닝은 반드시 ALLSTATS LAST 실측으로 한다.
--
-- 4. PCTTHRESHOLD 는 1~50 이고 이후 변경은 새 행에만 적용된다.
--    이미 저장된 행을 재배치하려면 ALTER TABLE ... MOVE 로 다시 써야 한다.
--
-- 5. 비트맵 인덱스가 필요하면 MAPPING TABLE 을 만들어야 한다.
--    세그먼트와 DML 비용이 늘어난다. 이 조건이 걸리면 힙을 다시 검토한다.
--
-- 6. 이 실습에서 본 오류
--    ORA-01429  OVERFLOW 없이 큰 행을 가진 IOT 생성  -> OVERFLOW 절 추가
--    ORA-25179  PCTTHRESHOLD 51 이상                 -> 1~50 범위로
--    ORA-28669  MAPPING TABLE 없이 비트맵 인덱스      -> MAPPING TABLE 절 추가
