[1] 시나리오 개요
--------------------------------------------------------------------------------
-- 일반 테이블(heap) 은 데이터를 넣은 순서대로 아무 블록에나 담고, 인덱스는 따로 만든다.
-- IOT(Index Organized Table) 는 그 둘을 하나로 합친다. 테이블 자체가 B*Tree 인덱스다.
--
--   heap :  [테이블 세그먼트] + [인덱스 세그먼트]   -> 조회할 때 두 번 읽는다
--   IOT  :  [인덱스 세그먼트 하나]                 -> 한 번에 끝난다
--
-- 목표
--   (1) ORGANIZATION INDEX 구문과 기본키 필수 조건을 확인한다
--   (2) 세그먼트가 인덱스 하나뿐이라는 것을 딕셔너리로 확인한다
--   (3) 실행계획에서 TABLE ACCESS BY INDEX ROWID 단계가 사라지는 것을 본다
--   (4) 정렬(SORT ORDER BY) 이 필요 없어지는 것을 힙과 나란히 비교한다
--   (5) IOT 의 ROWID 는 물리 주소가 아니라 논리 주소임을 확인한다
-- 작업 유형 : 구조 확인

-- IOT 는 기본키가 없으면 존재할 수 없다. 기본키가 곧 저장 순서이기 때문이다.

  2  ORGANIZATION INDEX TABLESPACE users;
ORGANIZATION INDEX TABLESPACE users
             *
ERROR at line 2:
ORA-25175: no PRIMARY KEY constraint found

-- ORA-25175: no PRIMARY KEY constraint found
--   ORGANIZATION INDEX 를 쓰려면 PRIMARY KEY 를 함께 정의해야 한다.
--   UNIQUE 제약으로는 안 된다. 기본키여야 한다.

-- 기본키를 주고 다시 만든다. PCTFREE 0 은 IOT 에서 흔히 쓰는 설정이다.
-- 값이 중간에 끼어드는 일이 적다면 블록을 꽉 채우는 쪽이 낫다.

--   dba_tables.iot_type = 'IOT'      이 테이블은 IOT 다
--   dba_tables.blocks   = 비어 있다  테이블 세그먼트가 없으므로 블록 수도 없다

--   dba_segments        = 아직 한 건도 없다
--                                    19c 는 세그먼트 생성을 미룬다(deferred)
--
-- 기억할 점 : IOT 의 크기·블록 수·통계는 dba_tables 가 아니라 dba_indexes 를 봐야 한다.

--------------------------------------------------------------------------------
[8] 실무 포인트
--------------------------------------------------------------------------------
-- 1. IOT 는 "기본키로만 조회하는 테이블" 을 위한 구조다.
--    코드 테이블, 매핑 테이블, 이력 조회 키가 명확한 테이블이 대상이다.
--    실제로 HR 샘플 스키마의 COUNTRIES 가 IOT 다 (실습 08 에서 확인한다).
--
-- 2. 세그먼트가 하나라는 사실이 모든 성질의 출발점이다.
--    조회는 한 번에 끝나고, 정렬이 필요 없고, 공간은 절약되지만,
--    반대로 모든 컬럼이 인덱스 안에 들어가므로 인덱스가 커진다 (실습 04).
--
-- 3. 모니터링 쿼리를 고쳐야 한다.
--    IOT 의 크기·통계는 dba_indexes 에 있다. dba_tables.blocks 는 NULL 이다.
--    세그먼트 이름도 테이블 이름이 아니라 기본키 인덱스 이름이다.
--
-- 4. ROWID 가 논리 주소다.
--    DBMS_ROWID 를 쓰는 코드, ROWID 를 화면에 들고 다니는 코드,
--    ROWID 로 재접근하는 배치는 IOT 전환 대상에서 제외하거나 함께 수정한다.
--
-- 5. 기본키는 나중에 바꿀 수 없다.
--    IOT 를 고른다는 것은 기본키 설계를 확정한다는 뜻이다.
--    키가 바뀔 가능성이 있으면 힙으로 둔다.
