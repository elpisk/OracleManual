======================================================================
[1단계] 트랜잭션 전용 GTT(ON COMMIT DELETE ROWS, 기본값) 생성
======================================================================

- ON COMMIT 절을 생략하면 기본값 DELETE ROWS (커밋 시 행 삭제 = 트랜잭션 전용)
HR@hrpdb> create global temporary table gtt_txn (
  2    id  number,
  3    val varchar2(30)
  4  );

Table created.

- 데이터 딕셔너리에서 임시 테이블 속성 확인 (TEMPORARY=Y, DURATION=SYS$TRANSACTION)
HR@hrpdb> select table_name, temporary, duration
  2  from user_tables where table_name='GTT_TXN';

TABLE_NAME  T DURATION
----------- - ---------------
GTT_TXN     Y SYS$TRANSACTION

- 행을 넣고 커밋 전에는 데이터가 보인다
HR@hrpdb> insert into gtt_txn values (1,'a');

1 row created.

HR@hrpdb> insert into gtt_txn values (2,'b');

1 row created.

HR@hrpdb> select count(*) from gtt_txn;

  COUNT(*)
----------
         2

- 커밋하면 트랜잭션 전용 GTT의 행이 자동으로 사라진다
HR@hrpdb> commit;

Commit complete.

HR@hrpdb> select count(*) from gtt_txn;

  COUNT(*)
----------
         0

======================================================================
[2단계] 세션 전용 GTT(ON COMMIT PRESERVE ROWS) 생성
======================================================================

- PRESERVE ROWS는 커밋해도 데이터가 세션 종료 시까지 유지된다
HR@hrpdb> create global temporary table gtt_sess (
  2    id  number,
  3    val varchar2(30)
  4  ) on commit preserve rows;

Table created.

HR@hrpdb> insert into gtt_sess
  2  select level, 'row'||level from dual connect by level <= 5;

5 rows created.

HR@hrpdb> commit;

Commit complete.

- 커밋 후에도 데이터가 그대로 남아 있음 (세션 전용)
HR@hrpdb> select count(*) from gtt_sess;

  COUNT(*)
----------
         5

======================================================================
[3단계] GTT 정의 변경 제약 확인 (사용 중 세션이 있으면 변경 불가)
======================================================================

- (실수) 현재 세션이 gtt_sess에 데이터를 갖고 있는 상태에서 컬럼 추가 시도
HR@hrpdb> alter table gtt_sess add (memo varchar2(50));
alter table gtt_sess add (memo varchar2(50))
*
ERROR at line 1:
ORA-14450: attempt to access a transactional temp table already in use

- 원인: 세션 전용 GTT에 데이터가 남아 있으면 정의를 바꿀 수 없다.
-   해당 GTT의 데이터를 먼저 비우면(TRUNCATE) 정의 변경이 가능해진다.
HR@hrpdb> truncate table gtt_sess;

Table truncated.

HR@hrpdb> alter table gtt_sess add (memo varchar2(50));

Table altered.

- 컬럼이 추가된 것을 확인
HR@hrpdb> select column_name from user_tab_columns
  2  where table_name='GTT_SESS' order by column_id;

COLUMN_NAME
--------------------
ID
VAL
MEMO

======================================================================
[4단계] 데이터가 세션에 프라이빗함을 리두 관점에서 확인
======================================================================

- GTT는 리두를 거의 생성하지 않음(언두에 대한 리두만). 통계로 대략 확인
HR@hrpdb> set autotrace on statistics
HR@hrpdb> insert into gtt_sess (id,val)
  2  select level,'x' from dual connect by level <= 1000;

1000 rows created.

Statistics
----------------------------------------------------------
        ...
         148  redo size
        ...

HR@hrpdb> set autotrace off
HR@hrpdb> rollback;

Rollback complete.

- [정리]
-   GTT 정의는 딕셔너리에 영구, 모든 세션 공유 / 데이터는 세션 프라이빗
-   ON COMMIT DELETE ROWS(기본)=트랜잭션 전용, PRESERVE ROWS=세션 전용
-   사용 중 세션이 데이터를 가지면 정의 변경 불가(ORA-14450) -> TRUNCATE 후 변경
-   리두를 거의 생성하지 않아 대량 중간 데이터 스테이징에 이상적
HR@hrpdb> drop table gtt_txn purge;

Table dropped.

HR@hrpdb> drop table gtt_sess purge;

Table dropped.
