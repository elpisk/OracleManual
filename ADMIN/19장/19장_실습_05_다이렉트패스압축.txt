-- 목표: 기본 압축(BASIC)은 다이렉트 패스 삽입에만 적용됨을 직접 확인한다.

SYS@hrpdb> show con_name

CON_NAME

HRPDB

======================================================================
[1단계] 기본 압축(ROW STORE COMPRESS BASIC) 테이블 생성
======================================================================

- 압축 대상으로 삼을 원본(비압축) 테이블을 준비: 반복값이 많아야 압축 효과가 큼
SYS@hrpdb> create table hr.src_data (id number, dept varchar2(20), note varchar2(100))
  2  tablespace users;

Table created.

SYS@hrpdb> insert /*+ append */ into hr.src_data
  2  select level,
  3         case mod(level,4) when 0 then 'SALES' when 1 then 'HR'
  4                           when 2 then 'IT' else 'FINANCE' end,
  5         rpad('note',100,'x')
  6  from dual connect by level <= 200000;

200000 rows created.

SYS@hrpdb> commit;

Commit complete.

- 기본 압축 테이블 생성 (COMPRESS = ROW STORE COMPRESS BASIC)
SYS@hrpdb> create table hr.comp_basic (id number, dept varchar2(20), note varchar2(100))
  2  tablespace users
  3  row store compress basic;

Table created.

- 압축 속성 확인 (COMPRESSION=ENABLED, COMPRESS_FOR=BASIC)
SYS@hrpdb> select compression, compress_for from user_tables
  2  where table_name='COMP_BASIC';

COMPRESSION   COMPRESS_FOR
------------- ------------------------------
ENABLED       BASIC

======================================================================
[2단계] 일반 경로 INSERT는 기본 압축이 적용되지 않음
======================================================================

- (관찰용) 먼저 '일반' INSERT ... SELECT 로 데이터를 넣는다 (다이렉트 패스 아님)
SYS@hrpdb> insert into hr.comp_basic select * from hr.src_data;

200000 rows created.

SYS@hrpdb> commit;

Commit complete.

- 세그먼트 크기 확인: 일반 경로로 넣었으므로 압축되지 않아 크게 나옴
SYS@hrpdb> select blocks, bytes/1024/1024 as mb from user_segments
  2  where segment_name='COMP_BASIC';

    BLOCKS         MB
---------- ----------
      3072         24

- 기본 압축은 다이렉트 패스에만 적용된다는 점을 확인하기 위해 테이블을 비운다
SYS@hrpdb> truncate table hr.comp_basic;

Table truncated.

======================================================================
[3단계] 다이렉트 패스 삽입(APPEND 힌트)으로 다시 적재 -> 압축 적용
======================================================================

- (실수) APPEND 힌트를 주었으나 커밋 전에 같은 세션에서 테이블을 조회하려 함
SYS@hrpdb> insert /*+ append */ into hr.comp_basic select * from hr.src_data;

200000 rows created.

SYS@hrpdb> select count(*) from hr.comp_basic;
select count(*) from hr.comp_basic
                     *
ERROR at line 1:
ORA-12838: cannot read/modify an object after modifying it in parallel

- 원인: 다이렉트 패스(APPEND) 이후에는 커밋 전 같은 세션에서 그 객체를 읽을 수 없다.
-   먼저 커밋한 뒤 조회한다.
SYS@hrpdb> commit;

Commit complete.

SYS@hrpdb> select count(*) from hr.comp_basic;

  COUNT(*)
----------
    200000

- 다이렉트 패스로 적재된 세그먼트 크기 확인: 압축되어 블록 수가 크게 줄었다
SYS@hrpdb> select blocks, bytes/1024/1024 as mb from user_segments
  2  where segment_name='COMP_BASIC';

    BLOCKS         MB
---------- ----------
      1152          9

- 비교: 같은 200,000행이 일반 경로 24MB -> 다이렉트 패스 압축 9MB로 감소

======================================================================
[4단계] 이후 일반 INSERT는 압축되지 않은 채 추가됨을 확인
======================================================================

- 압축 테이블이라도 일반 경로 INSERT로 들어간 새 행은 압축되지 않는다
SYS@hrpdb> insert into hr.comp_basic
  2  select 900000+level, 'SALES', rpad('note',100,'x')
  3  from dual connect by level <= 50000;

50000 rows created.

SYS@hrpdb> commit;

Commit complete.

- 세그먼트가 다시 상대적으로 크게 늘어남(새 50,000행은 비압축 저장)
SYS@hrpdb> select blocks, bytes/1024/1024 as mb from user_segments
  2  where segment_name='COMP_BASIC';

    BLOCKS         MB
---------- ----------
      1920         15

- [정리]
-   기본 압축(BASIC)은 다이렉트 패스(CTAS, INSERT /*+ APPEND */, SQL*Loader 다이렉트)에만 적용
-   일반 경로 INSERT/UPDATE로 들어간 데이터는 압축되지 않음
-   따라서 기본 압축은 한 번 적재 후 주로 읽는 이력/DW 테이블에 적합
-   ORA-12838: APPEND 후 커밋 전 같은 세션에서 그 객체 접근 불가 -> 커밋 후 조회
SYS@hrpdb> drop table hr.comp_basic purge;

Table dropped.

SYS@hrpdb> drop table hr.src_data purge;

Table dropped.
