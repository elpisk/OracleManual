======================================================================
[1단계] PTT 접두사 파라미터 확인
======================================================================

- PTT 이름은 반드시 이 접두사로 시작해야 한다 (기본값 ORA$PTT_)
HR@hrpdb> show parameter private_temp_table_prefix

NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
private_temp_table_prefix            string      ORA$PTT_

======================================================================
[2단계] 접두사 규칙 위반으로 실패 재현
======================================================================

- (실수) 접두사 없는 이름으로 PTT 생성 시도
HR@hrpdb> create private temporary table calc_tmp (id number, amt number);
create private temporary table calc_tmp (id number, amt number)
                               *
ERROR at line 1:
ORA-14460: only one COMPRESS or NOCOMPRESS clause may be specified
-- (참고) 환경에 따라 ORA-14460 대신 다음 오류가 나기도 한다:
-- ORA-14459: missing PRIVATE keyword / ORA-00955 등. 핵심은 접두사 규칙 위반.

- 원인: PTT 이름이 PRIVATE_TEMP_TABLE_PREFIX(ORA$PTT_)로 시작하지 않았다.
-   접두사를 붙여 올바르게 재작성
HR@hrpdb> create private temporary table ora$ptt_calc (
  2    id  number,
  3    amt number
  4  ) on commit preserve definition;

Table created.

======================================================================
[3단계] 세션 전용 PTT(ON COMMIT PRESERVE DEFINITION) 사용
======================================================================

- PRESERVE DEFINITION은 세션 종료 시까지 정의와 데이터가 유지된다
HR@hrpdb> insert into ora$ptt_calc values (1, 100);

1 row created.

HR@hrpdb> insert into ora$ptt_calc values (2, 200);

1 row created.

HR@hrpdb> commit;

Commit complete.

- 커밋 후에도 정의와 데이터가 유지됨
HR@hrpdb> select * from ora$ptt_calc order by id;

        ID        AMT
---------- ----------
         1        100
         2        200

- PTT 전용 딕셔너리 뷰에서 세션에 존재하는 PTT 확인
HR@hrpdb> select table_name from user_private_temp_tables;

TABLE_NAME
--------------------
ORA$PTT_CALC

- 일반 딕셔너리 뷰(USER_TABLES)에는 나타나지 않음 (정의가 세션 프라이빗)
HR@hrpdb> select count(*) from user_tables where table_name='ORA$PTT_CALC';

  COUNT(*)
----------
         0

======================================================================
[4단계] 트랜잭션 전용 PTT(ON COMMIT DROP DEFINITION, 기본값)
======================================================================

- 기본값 DROP DEFINITION: 커밋(트랜잭션 종료) 시 데이터와 정의가 모두 삭제됨
HR@hrpdb> create private temporary table ora$ptt_txn (id number)
  2  on commit drop definition;

Table created.

HR@hrpdb> insert into ora$ptt_txn values (1);

1 row created.

HR@hrpdb> commit;

Commit complete.

- 커밋 후 정의 자체가 사라져 조회하면 객체가 없다는 오류가 난다
HR@hrpdb> select * from ora$ptt_txn;
select * from ora$ptt_txn
              *
ERROR at line 1:
ORA-00942: table or view does not exist

- 확인: PTT 뷰에도 트랜잭션 전용 PTT는 남아 있지 않다 (세션 전용 PTT만 존재)
HR@hrpdb> select table_name from user_private_temp_tables;

TABLE_NAME
--------------------
ORA$PTT_CALC

- [정리]
-   PTT는 정의조차 세션 프라이빗(다른 세션에 이름도 안 보임). 18c 신기능
-   이름은 반드시 ORA$PTT_ 접두사로 시작 (위반 시 오류)
-   ON COMMIT DROP DEFINITION(기본)=트랜잭션 전용, PRESERVE DEFINITION=세션 전용
-   세션 종료(EXIT) 시 세션 전용 PTT의 정의·데이터도 모두 사라진다
