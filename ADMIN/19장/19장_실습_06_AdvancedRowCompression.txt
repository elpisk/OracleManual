======================================================================
[1단계] 원본 데이터 준비
======================================================================

SYS@hrpdb> create table hr.src_data (id number, dept varchar2(20), note varchar2(100))
  2  tablespace users;

Table created.

SYS@hrpdb> insert /*+ append */ into hr.src_data
  2  select level,
  3         case mod(level,4) when 0 then 'SALES' when 1 then 'HR'
  4                           when 2 then 'IT' else 'FINANCE' end,
  5         rpad('note',100,'x')
  6  from dual connect by level <= 200000;

200000 rows created.

SYS@hrpdb> commit;

Commit complete.

======================================================================
[2단계] Advanced Row Compression 테이블 생성
======================================================================

- (실수) 구/신 구문을 섞어서 잘못 입력
SYS@hrpdb> create table hr.comp_adv (id number, dept varchar2(20), note varchar2(100))
  2  compress advanced for oltp;
compress advanced for oltp
                     *
ERROR at line 2:
ORA-00922: missing or invalid option

- 원인: 구문 혼용. 올바른 구문은 ROW STORE COMPRESS ADVANCED (구식은 COMPRESS FOR OLTP).
SYS@hrpdb> create table hr.comp_adv (id number, dept varchar2(20), note varchar2(100))
  2  tablespace users
  3  row store compress advanced;

Table created.

- 압축 속성 확인 (COMPRESS_FOR=ADVANCED)
SYS@hrpdb> select compression, compress_for from user_tables
  2  where table_name='COMP_ADV';

COMPRESSION   COMPRESS_FOR
------------- ------------------------------
ENABLED       ADVANCED

======================================================================
[3단계] 일반 경로 INSERT로도 압축이 유지되는지 확인
======================================================================

- 기본 압축과 달리 '일반' INSERT ... SELECT 로 넣어도 압축이 적용된다
SYS@hrpdb> insert into hr.comp_adv select * from hr.src_data;

200000 rows created.

SYS@hrpdb> commit;

Commit complete.

- 세그먼트 크기 확인: 일반 경로였는데도 압축되어 블록 수가 작다
SYS@hrpdb> select blocks, bytes/1024/1024 as mb from user_segments
  2  where segment_name='COMP_ADV';

    BLOCKS         MB
---------- ----------
      1152          9

- 비교용: 같은 데이터를 비압축 테이블에 일반 경로로 넣으면 약 24MB (실습_05 참조)
-   -> Advanced Row Compression은 일반 DML 경로에서도 압축을 유지함이 확인됨

======================================================================
[4단계] UPDATE 후에도 압축이 유지되는지 확인
======================================================================

- 대량 UPDATE 수행 (OLTP성 갱신을 모사)
SYS@hrpdb> update hr.comp_adv set note = rpad('updated',100,'y')
  2  where mod(id,2)=0;

100000 rows updated.

SYS@hrpdb> commit;

Commit complete.

- 갱신 후에도 블록이 임계치 도달 시 자동 재압축되어 크기가 크게 튀지 않는다
SYS@hrpdb> select blocks, bytes/1024/1024 as mb from user_segments
  2  where segment_name='COMP_ADV';

    BLOCKS         MB
---------- ----------
      1408         11

- 참고: 블록은 처음 비압축으로 채워지다 임계치 도달 시 배치 압축되고, 갱신 후 재압축됨
-   -> 갱신이 잦은 OLTP 테이블에서도 압축 효과를 유지 가능(단, Advanced Compression 옵션 필요)

- [정리]
-   Advanced Row Compression = ROW STORE COMPRESS ADVANCED (구: COMPRESS FOR OLTP)
-   기본 압축과 달리 일반 INSERT/UPDATE 등 모든 DML에 압축 유지
-   갱신이 잦은 OLTP 테이블에 적합 / Advanced Compression 옵션 라이선스 필요
SYS@hrpdb> drop table hr.comp_adv purge;

Table dropped.

SYS@hrpdb> drop table hr.src_data purge;

Table dropped.
