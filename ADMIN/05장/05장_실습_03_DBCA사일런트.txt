-- 5장 실습_03: DBCA Silent 모드로 CDB 생성(-createDatabase) 및 삭제(-deleteDatabase) 실습
--   그래픽 없이 셸 명령만으로 CDB를 생성하고 검증한 뒤 삭제한다.
--   중간에 명령어 오타로 인한 오류를 만나 원인을 파악하고 수정해 성공에 이르는 흐름을 포함한다.
--   목표: General Purpose 템플릿 + CDB + PDB(pdb1) + AL32UTF8 + ARCHIVELOG 로 ORCL 생성 → 삭제

======================================================================
[0단계] 사전 확인: 사용할 템플릿과 대상 경로
======================================================================

[oracle@dbsvr ~]$ echo $ORACLE_HOME
/u01/app/oracle/product/19.3.0/dbhome_1

- 사일런트 모드에서 지정할 시드형 템플릿(.dbc)이 존재하는지 확인
[oracle@dbsvr ~]$ ls $ORACLE_HOME/assistants/dbca/templates/*.dbc
General_Purpose.dbc   Data_Warehouse.dbc

- 데이터파일/FRA 대상 디렉터리가 준비되어 있는지 확인
[oracle@dbsvr ~]$ ls -d /u02/app/oracle/oradata /u03/app/oracle/fast_recovery_area
/u02/app/oracle/oradata
/u03/app/oracle/fast_recovery_area

======================================================================
[1단계] (오류 재현) 옵션 오타로 인한 실패
======================================================================

- (실수1) -createDatabase 를 -createDatbase 로 오타. DBCA가 명령을 이해하지 못한다.
[oracle@dbsvr ~]$ $ORACLE_HOME/bin/dbca -silent -createDatbase \
>     -templateName General_Purpose.dbc -gdbname ORCL -sid ORCL
DBCA_PROGRESS : Command line argument "-createDatbase" is not valid.
[FATAL] Invalid command line arguments were specified.

- 원인: 서브커맨드 철자 오류(-createDatbase → -createDatabase). 올바른 옵션으로 재시도하되,
--   이번에는 (실수2) 템플릿 파일명을 존재하지 않는 이름으로 잘못 지정한다.
[oracle@dbsvr ~]$ $ORACLE_HOME/bin/dbca -silent -createDatabase \
>     -templateName GeneralPurpose.dbc -gdbname ORCL -sid ORCL \
>     -createAsContainerDatabase true -numberOfPDBs 1 -pdbName pdb1 \
>     -characterSet AL32UTF8 -totalMemory 1800 \
>     -sysPassword Welcome_1 -systemPassword Welcome_1 -pdbAdminPassword Welcome_1
[FATAL] [DBT-06103] The template (GeneralPurpose.dbc) does not exist.
   ACTION: Provide a valid template that exists.

- 원인: 템플릿 파일명 오타. 실제 파일명은 'General_Purpose.dbc'(밑줄 포함)다. 0단계 ls 결과와 대조해 확인.

======================================================================
[2단계] (수정) 올바른 전체 명령으로 CDB 생성
======================================================================

- 옵션과 템플릿명을 바로잡아 전체 명령을 실행한다(백슬래시는 줄 연결).
[oracle@dbsvr ~]$ $ORACLE_HOME/bin/dbca -silent -createDatabase \
>     -templateName General_Purpose.dbc -gdbname ORCL \
>     -sid ORCL -createAsContainerDatabase true \
>     -numberOfPDBs 1 -pdbName pdb1 -useLocalUndoForPDBs true \
>     -responseFile NO_VALUE -characterSet AL32UTF8 \
>     -totalMemory 1800 -sysPassword Welcome_1 \
>     -systemPassword Welcome_1 -pdbAdminPassword Welcome_1 \
>     -emConfiguration DBEXPRESS -dbsnmpPassword Welcome_1 \
>     -emExpressPort 5500 -enableArchive true \
>     -recoveryAreaDestination /u03/app/oracle/fast_recovery_area \
>     -recoveryAreaSize 15000 \
>     -datafileDestination /u02/app/oracle/oradata

======================================================================
[4단계] (정리 실습) 사일런트 모드로 데이터베이스 삭제
======================================================================

- (실수3) 삭제 대상 이름을 실제와 다르게(-sourceDB ORCL1) 지정 → 대상을 찾지 못해 실패
[oracle@dbsvr ~]$ $ORACLE_HOME/bin/dbca -silent -deleteDatabase \
>     -sourceDB ORCL1 -sysPassword Welcome_1
[FATAL] [DBT-00012] The specified database (ORCL1) does not exist.
   ACTION: Specify an existing database.

- 원인: -sourceDB 값 오타(ORCL1 → ORCL). 되돌릴 수 없는 파괴적 작업이므로 대상 이름을 반드시 재확인한다.
--   또한 실행 전 백업이 있는지 확인한다(실습 환경이므로 백업 생략).

- 올바른 대상으로 삭제 실행
[oracle@dbsvr ~]$ $ORACLE_HOME/bin/dbca -silent -deleteDatabase \
>     -sourceDB ORCL -sid ORCL \
>     -sysPassword Welcome_1

Prepare for db operation
32% complete
Connecting to database
39% complete
...

- 삭제 확인: 인스턴스 프로세스가 더 이상 존재하지 않는다
[oracle@dbsvr ~]$ ps -ef | grep [p]mon_ORCL
[oracle@dbsvr ~]$

- [정리]
--   1) 사일런트 모드는 -silent 와 서브커맨드(-createDatabase / -deleteDatabase)로 동작한다.
--   2) 옵션 철자(-createDatabase)와 템플릿 파일명(General_Purpose.dbc)의 정확성이 중요하다.
--   3) 생성 후 v$database / v$pdbs / nls_database_parameters 로 검증하는 습관을 들인다.
--   4) -deleteDatabase 는 되돌릴 수 없으므로 -sourceDB 대상 이름을 반드시 재확인하고 백업을 확인한다.
--   5) 사일런트 명령은 셸 스크립트로 저장해 형상 관리하면 재해복구/동일환경 재구축에 그대로 재현할 수 있다.
[oracle@dbsvr ~]$
