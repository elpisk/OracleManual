-- 5장 실습_01: DBCA 대화형 모드로 데이터베이스 생성 실습
--   대화형 GUI는 텍스트로 그대로 옮길 수 없으므로, 마법사의 각 단계에서 '무엇을 입력하는지'를
--   안내하는 형식으로 정리하고, 생성이 끝난 뒤 SQL*Plus로 결과를 검증하는 흐름으로 구성한다.
--   목표: General Purpose 템플릿 + CDB + PDB(pdb1) + 문자집합 AL32UTF8 + ARCHIVELOG 로 새 DB(ORCL) 생성

======================================================================
[0단계] 사전 준비: 환경 변수와 리스너 확인
======================================================================

- oracle 계정으로 서버에 로그인한 뒤 ORACLE_HOME/PATH가 설정되어 있는지 확인
[oracle@dbsvr ~]$ echo $ORACLE_HOME
/u01/app/oracle/product/19.3.0/dbhome_1

- 대화형 마법사는 그래픽(X11)이 필요하다. SSH X11 포워딩이 켜져 있는지 DISPLAY로 확인
[oracle@dbsvr ~]$ echo $DISPLAY
localhost:10.0

- 리스너가 떠 있어야 생성 후 서비스가 등록된다. 상태 확인
[oracle@dbsvr ~]$ lsnrctl status | head -n 6
LSNRCTL for Linux: Version 19.0.0.0.0 - Production
Status of the listener
Alias                     LISTENER
Version                   TNSLSNR for Linux: Version 19.0.0.0.0 - Production
Uptime                    0 days 0 hr. 12 min. 3 sec

======================================================================
[1단계] DBCA 실행 (실수 → 원인 파악 → 수정)
======================================================================

- (실수) 명령 이름을 잘못 입력. 'dbca'가 아니라 'dcba'로 오타
[oracle@dbsvr ~]$ dcba
-bash: dcba: command not found

- 원인: 실행 파일명 오타. Database Configuration Assistant의 명령은 dbca 이다. 올바르게 재실행
[oracle@dbsvr ~]$ dbca

- (마법사가 뜨지 않고 아래 경고가 콘솔에 출력되는 경우가 있다)
--   [WARNING] Cannot connect to X11 window server using ':0.0'
- 원인: DISPLAY 미설정 또는 X11 포워딩 비활성. ssh -X 로 재접속하거나 DISPLAY를 지정한 뒤 다시 실행
--   (그래픽 환경을 못 쓰는 서버라면 실습_03의 사일런트 모드를 사용한다)
[oracle@dbsvr ~]$ export DISPLAY=localhost:10.0
[oracle@dbsvr ~]$ dbca
- => DBCA 마법사 창이 정상적으로 열린다.

======================================================================
[2단계] 마법사 각 단계 입력값 안내
======================================================================

- (1) Database operation: 'Create a database' 선택
- (2) Creation mode: 'Advanced configuration' 선택
--        (Typical은 빠르지만 문자집합/아카이브를 세밀히 지정하기 어렵다)
- (3) Deployment type:
--        Database type = Oracle Single Instance database
--        Template     = General Purpose or Transaction Processing
- (4) Database identification:
--        Global database name = ORCL
--        SID                  = ORCL
--        [v] Create as Container database  (체크)
--        [v] Create a Container database with one or more PDBs
--        Number of PDBs = 1,  PDB name prefix = pdb1
- (5) Storage option:
--        Use template file for database storage attributes 또는
--        Use Oracle-Managed Files(OMF) 선택,  Datafile location = /u02/app/oracle/oradata
- (6) Fast Recovery Area:
--        [v] Specify Fast Recovery Area = /u03/app/oracle/fast_recovery_area,  Size = 15000 MB
--        [v] Enable archiving  (아카이브 로그 모드 활성화 → 백업/시점복구 대비)
- (7) Network configuration: 기존 LISTENER 선택(또는 새 리스너 생성)
- (8) Configuration options:
--        Memory: [v] Use Automatic Memory Management, Total memory = 1800 MB
--        Character sets 탭: [v] Use Unicode(AL32UTF8)   <== 이 실습의 핵심 선택
--        National character set = AL16UTF16
--        Connection mode = Dedicated server mode
- (9) Management options: [v] Configure EM Database Express, EM Express port = 5500
- (10) User credentials:
--        SYS / SYSTEM / PDBADMIN 비밀번호 입력 (실습에서는 Welcome_1)
- (11) Creation option:
--        [v] Create database
--        [v] Generate database creation scripts  (스크립트도 함께 생성 → 재현/검토용)
--        Script destination = /u01/app/oracle/admin/ORCL/scripts
- (12) Summary 화면에서 선택 내용을 최종 확인한 뒤 'Finish' 클릭
--        진행 막대와 함께 생성이 수행된다(수 분 소요). 완료 후 창을 닫는다.

======================================================================
[3단계] 생성 결과 검증: SQL*Plus로 접속
======================================================================

- 새로 만든 인스턴스 환경으로 전환 (oraenv 사용, SID=ORCL)
[oracle@dbsvr ~]$ . oraenv
ORACLE_SID = [cdb1] ? ORCL
The Oracle base remains unchanged with value /u01/app/oracle

- SYSDBA(OS 인증)로 접속
[oracle@dbsvr ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

- 프롬프트를 사용자@인스턴스 형태로 지정
SQL> set sqlprompt "_user'@'_connect_identifier> "

- 데이터베이스가 새 이름으로 OPEN 되었는지, CDB인지, 아카이브 모드인지 한 번에 확인
SYS@ORCL> select name, open_mode, cdb, log_mode from v$database;

NAME      OPEN_MODE            CDB LOG_MODE
--------- -------------------- --- ------------
ORCL      READ WRITE           YES ARCHIVELOG

- 함께 만든 PDB(pdb1)가 존재하고 어떤 상태인지 확인
SYS@ORCL> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 PDB1                           READ WRITE

======================================================================
[4단계] 문자집합이 의도대로(AL32UTF8) 생성되었는지 확인
======================================================================

- 데이터베이스 문자집합과 국가 문자집합 확인
SYS@ORCL> select parameter, value
  2  from nls_database_parameters
  3  where parameter in ('NLS_CHARACTERSET','NLS_NCHAR_CHARACTERSET');

PARAMETER                      VALUE
------------------------------ ----------------
NLS_CHARACTERSET               AL32UTF8
NLS_NCHAR_CHARACTERSET         AL16UTF16

- (실수) MOUNT 단계에서만 조회 가능한 정보를 잘못 이해해, PDB가 닫혀 있다고 착각하고
--   먼저 열려 있는지 다시 확인 없이 pdb1에 바로 접속을 시도했다고 가정 → 컨테이너 전환은 정상 동작
SYS@ORCL> alter session set container = pdb1;

Session altered.

- 현재 컨테이너가 PDB1로 바뀌었는지 확인
SYS@ORCL> show con_name

CON_NAME
------------------------------
PDB1

- 루트로 복귀
SYS@ORCL> alter session set container = cdb$root;

Session altered.

======================================================================
[5단계] DBCA가 생성한 '생성 스크립트' 확인 (이 장의 두 번째 학습 목표)
======================================================================

- 11단계에서 지정한 스크립트 폴더에 생성 스크립트가 저장되어 있다
SYS@ORCL> host ls /u01/app/oracle/admin/ORCL/scripts

ORCL.sh        ORCL.sql       CreateDB.sql    CreateDBFiles.sql
CreateDBCatalog.sql           postDBCreation.sql   init.ora

- [정리]
--   1) DBCA 대화형 마법사의 각 단계에서 템플릿/CDB·PDB/저장소/FRA·아카이브/문자집합/메모리를 지정했다.
--   2) 핵심 선택은 (8) 단계의 문자집합 = AL32UTF8, (6) 단계의 Enable archiving 이다.
--   3) 생성 후 v$database / v$pdbs / nls_database_parameters 로 결과를 검증했다.
--   4) 'Generate database creation scripts'로 스크립트도 함께 얻어 재현/검토가 가능하다.
SYS@ORCL> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
