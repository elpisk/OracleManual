======================================================================
[1단계] DISPATCHERS 구성: TCP 프로토콜용 디스패처 2개
======================================================================

- (실수) 프로토콜 값을 오타(TPC)로 지정하여 디스패처 구성 시도
SYS@cdb1> alter system set dispatchers='(PROTOCOL=TPC)(DISPATCHERS=2)' scope=both;
alter system set dispatchers='(PROTOCOL=TPC)(DISPATCHERS=2)' scope=both
*
ERROR at line 1:
ORA-00119: invalid specification for system parameter DISPATCHERS
ORA-24323: value not allowed

- 원인: PROTOCOL 값이 잘못됨(TPC -> 올바른 값은 TCP). 디스패처가 인식하는 프로토콜 이름을 써야 함.
-   올바른 프로토콜(TCP)로 재시도
SYS@cdb1> alter system set dispatchers='(PROTOCOL=TCP)(DISPATCHERS=2)' scope=both;

System altered.

- 설정 문자열이 반영되었는지 확인
SYS@cdb1> show parameter dispatchers

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
dispatchers                          string      (PROTOCOL=TCP)(DISPATCHERS=2)
max_dispatchers                      integer

- 디스패처 프로세스가 D000, D001 로 시작되었는지 확인
SYS@cdb1> select name, network, status, conf_indx, busy
  2  from v$dispatcher
  3  order by name;

NAME   NETWORK                                        STATUS     CONF_INDX       BUSY
------ ---------------------------------------------- ---------- --------- ----------
D000   (ADDRESS=(PROTOCOL=tcp)(HOST=dbsvr)(PORT=...)) WAIT               0          0

======================================================================
[2단계] 디스패처 추가 속성: CONNECTIONS / SERVICE 지정
======================================================================

- CONNECTIONS(디스패처당 최대 연결 수)와 SERVICE(리스너 등록 서비스 이름)를 함께 지정
SYS@cdb1> alter system set dispatchers='(PROTOCOL=TCP)(DISPATCHERS=2)(CONNECTIONS=500)(SERVICE=cdb1_shared)' scope=both;

System altered.

- 리스너에 cdb1_shared 서비스의 디스패처 핸들러가 등록되었는지 확인

======================================================================
[3단계] 상한 파라미터 구성: MAX_SHARED_SERVERS / SHARED_SERVER_SESSIONS / CIRCUITS
======================================================================

- 참고: 전체 SESSIONS 값 확인 (SHARED_SERVER_SESSIONS는 이보다 작게 잡아 전용 세션을 예약)
SYS@cdb1> show parameter sessions

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
sessions                             integer     472
shared_server_sessions               integer

- 공유 서버 최대 개수를 20으로 제한 (PMON이 자동 생성할 수 있는 공유 서버의 상한)
SYS@cdb1> alter system set max_shared_servers=20 scope=both;

System altered.

- (실수) 공유 세션 총수를 전체 SESSIONS(472)보다 크게(500) 설정 시도 -> 의미상 부적절
SYS@cdb1> alter system set shared_server_sessions=500 scope=both;
alter system set shared_server_sessions=500 scope=both
*
ERROR at line 1:
ORA-02017: integer value required
ORA-00093: shared_server_sessions must be between 0 and 472

- 원인: SHARED_SERVER_SESSIONS는 전체 SESSIONS(472)를 초과할 수 없다.
-   전용 서버용 세션을 남기기 위해 472보다 작은 값(예: 450)으로 재설정
SYS@cdb1> alter system set shared_server_sessions=450 scope=both;

System altered.

- 가상 회로 상한 설정: 공유 메모리에 생성될 가상 회로 수를 제한해 SGA를 보호
SYS@cdb1> alter system set circuits=500 scope=both;

System altered.

- 세 상한 파라미터가 모두 반영되었는지 확인

[5단계] 요청 큐/응답 큐 상태로 병목 진단 준비

- 공통 요청 큐(COMMON)와 디스패처 응답 큐의 대기 항목/평균 대기 확인

---------------- ---------- -------- ---------- ----------
00                COMMON            0         42          1
00000000B1A20100 DISPATCHER        0         17          1

- [정리]
-   · DISPATCHERS 는 (PROTOCOL=TCP)(DISPATCHERS=n) 형식으로 개수/속성을 지정한다.
-     CONNECTIONS(디스패처당 최대 연결), SERVICE(리스너 등록 서비스명)를 함께 줄 수 있다.
-   · MAX_SHARED_SERVERS / SHARED_SERVER_SESSIONS / CIRCUITS 는 모두 '상한'이며 자원 보호용.
-     SHARED_SERVER_SESSIONS 는 전체 SESSIONS 보다 작게 잡아 전용 세션을 예약한다.
-   · V$SHARED_SERVER_MONITOR / V$CIRCUIT / V$QUEUE 로 동작과 병목을 검증한다.
