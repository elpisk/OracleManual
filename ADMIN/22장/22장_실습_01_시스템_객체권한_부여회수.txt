-- 22장 실습_01: 시스템 권한과 객체 권한 부여/회수 실습 (GRANT/REVOKE, WITH ADMIN/GRANT OPTION)

- 루트 컨테이너로 SYSDBA 접속된 상태 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 실습은 salespdb 안에서 진행한다.
SYS@cdb1> alter session set container = salespdb;

Session altered.

======================================================================
[1단계] 실습용 사용자 생성 및 시스템 권한 부여
======================================================================

SYS@salespdb> create user hr_dev identified by Dev#2024;

User created.

- (실수) 방금 만든 hr_dev 로 접속을 시도 -> 권한이 없어 로그인 불가
SYS@salespdb> connect hr_dev/Dev#2024@salespdb
ERROR:
ORA-01045: user HR_DEV lacks CREATE SESSION privilege; logon denied


Warning: You are no longer connected to ORACLE.

- 원인: CREATE USER 만으로는 접속조차 못 한다. CREATE SESSION 시스템 권한이 필요.
- 다시 관리자로 접속해 접속 권한과 테이블 생성 권한을 부여한다.
SYS@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.

SYS@salespdb> grant create session, create table to hr_dev;

Grant succeeded.

- 이제 hr_dev 로 정상 접속된다.
SYS@salespdb> connect hr_dev/Dev#2024@salespdb
Connected.

======================================================================
[2단계] 부여된 시스템 권한 확인
======================================================================

HR_DEV@salespdb> select privilege from session_privs order by privilege;

PRIVILEGE
--------------------
CREATE SESSION
CREATE TABLE

- 관리자 관점에서 직접 부여된 시스템 권한 확인
HR_DEV@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.

SYS@salespdb> select privilege, admin_option
  2  from   dba_sys_privs where grantee='HR_DEV' order by privilege;

PRIVILEGE            ADM
-------------------- ---
CREATE SESSION       NO
CREATE TABLE         NO

======================================================================
[3단계] 객체 권한 부여 (WITH GRANT OPTION)
======================================================================

- 조회 전용 사용자 hr_report 생성
SYS@salespdb> create user hr_report identified by Rep#2024;
User created.
SYS@salespdb> grant create session to hr_report;
Grant succeeded.

- HR 소유자가 자신의 EMPLOYEES 를 hr_report 에 SELECT 부여(재부여 허용)
SYS@salespdb> connect hr/hr@salespdb
Connected.
HR@salespdb> grant select on employees to hr_report with grant option;

Grant succeeded.

- 특정 컬럼만 UPDATE 허용 (컬럼 수준 객체 권한)
HR@salespdb> grant update (salary) on employees to hr_dev;

Grant succeeded.

- 부여된 객체 권한 확인
HR@salespdb> select grantee, privilege, grantable
  2  from   user_tab_privs where table_name='EMPLOYEES' order by grantee;

GRANTEE      PRIVILEGE   GRA
------------ ----------- ---
HR_REPORT    SELECT      YES

======================================================================
[4단계] (오류 -> 원인 -> 수정) 권한 없는 객체에 접근 시도
======================================================================

- hr_dev 로 접속해 HR.EMPLOYEES 전체를 조회 시도
HR@salespdb> connect hr_dev/Dev#2024@salespdb
Connected.
HR_DEV@salespdb> select employee_id, salary from hr.employees where rownum <= 1;

EMPLOYEE_ID     SALARY
----------- ----------
        100      24000

- (실수) salary 만 UPDATE 권한이 있는데 commission_pct 를 수정 시도
HR_DEV@salespdb> update hr.employees set commission_pct = 0.1 where employee_id = 100;
update hr.employees set commission_pct = 0.1 where employee_id = 100
                        *
ERROR at line 1:
ORA-01031: insufficient privileges

- 원인: hr_dev 에는 salary 컬럼에 대한 UPDATE 만 있고 commission_pct 권한은 없다.
- 수정: 허용된 salary 컬럼만 갱신하면 정상 처리된다.
HR_DEV@salespdb> update hr.employees set salary = salary where employee_id = 100;

1 row updated.

HR_DEV@salespdb> rollback;
Rollback complete.

======================================================================
[5단계] 시스템 권한 회수(연쇄되지 않음 확인)
======================================================================

SYS@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.

- hr_dev 에게 WITH ADMIN OPTION 으로 CREATE VIEW 부여
SYS@salespdb> grant create view to hr_dev with admin option;
Grant succeeded.

- hr_dev 가 그 권한을 hr_report 에 재부여
SYS@salespdb> connect hr_dev/Dev#2024@salespdb
Connected.
HR_DEV@salespdb> grant create view to hr_report;
Grant succeeded.

- 관리자가 hr_dev 에게서 CREATE VIEW 회수
HR_DEV@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.
SYS@salespdb> revoke create view from hr_dev;
Revoke succeeded.

- 확인: hr_dev 는 사라졌지만 hr_report 의 CREATE VIEW 는 남아 있다(비연쇄).
SYS@salespdb> select grantee, privilege from dba_sys_privs
  2  where privilege='CREATE VIEW' and grantee in ('HR_DEV','HR_REPORT');

GRANTEE      PRIVILEGE
------------ --------------------
HR_REPORT    CREATE VIEW

- [정리] CREATE USER != 접속 가능(ORA-01045), 컬럼 수준 권한 위반은 ORA-01031,
-   시스템 권한 회수는 연쇄되지 않아 재부여분이 남는다.
SYS@salespdb> exit
