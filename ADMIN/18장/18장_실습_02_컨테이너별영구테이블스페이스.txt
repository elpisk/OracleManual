SQL> set sqlprompt "_user'@'_connect_identifier> "

- 현재 CDB에 어떤 PDB가 열려 있는지 확인
SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 PDB1                           READ WRITE
         5 SALESPDB                       READ WRITE

======================================================================
[1단계] pdb1에 app_data 테이블스페이스 생성
======================================================================

SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@cdb1> create tablespace app_data
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/app_data01.dbf' size 300M
  3    autoextend on next 100M maxsize 5G;

Tablespace created.

======================================================================
[2단계] 루트에 접속한 채로 salespdb에 만들려다 겪는 흔한 실수
======================================================================

- 루트로 돌아옴
SYS@cdb1> alter session set container = cdb$root;

Session altered.

- (실수) salespdb로 전환하지 않은 채(현재 CDB$ROOT) 곧바로 생성 시도.
-   이렇게 하면 salespdb가 아니라 '루트'에 테이블스페이스가 만들어진다.
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 의도한 컨테이너가 아님을 확인했으므로, 반드시 salespdb로 전환 후 진행
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@cdb1> show con_name

CON_NAME
------------------------------
SALESPDB

- pdb1과 '같은 이름' app_data 생성 (서로 완전히 독립적인 테이블스페이스)
SYS@cdb1> create tablespace app_data
  2    datafile '/u01/app/oracle/oradata/CDB1/salespdb/app_data01.dbf' size 300M
  3    autoextend on next 100M maxsize 5G;

Tablespace created.

======================================================================
[3단계] 루트에서 CDB_TABLESPACES로 컨테이너별 조회
======================================================================

SYS@cdb1> alter session set container = cdb$root;

Session altered.

- 같은 이름 APP_DATA가 CON_ID 3(pdb1)과 5(salespdb)에 각각 존재함을 확인
SYS@cdb1> select con_id, tablespace_name
  2  from   cdb_tablespaces
  3  where  tablespace_name = 'APP_DATA'
  4  order  by con_id;

    CON_ID TABLESPACE_NAME
---------- ------------------------------
         3 APP_DATA
         5 APP_DATA

- 각 컨테이너의 데이터 파일 경로가 서로 다름을 확인 (독립적 저장소)
SYS@cdb1> select con_id, file_name
  2  from   cdb_data_files
  3  where  tablespace_name = 'APP_DATA'
  4  order  by con_id;

    CON_ID FILE_NAME
---------- ------------------------------------------------------------
         3 /u01/app/oracle/oradata/CDB1/pdb1/app_data01.dbf
         5 /u01/app/oracle/oradata/CDB1/salespdb/app_data01.dbf

======================================================================
[4단계] 컨테이너 혼동 사고 시뮬레이션 및 예방
======================================================================

- (실수) 'pdb1의 app_data를 늘려달라'는 요청을 salespdb에 접속한 채로 수행하면?
SYS@cdb1> alter session set container = salespdb;

Session altered.

- 여기서 alter tablespace app_data ... 를 실행하면 salespdb 것이 바뀐다.
-   요청은 pdb1이었으므로, 반드시 대상 컨테이너를 먼저 확인해야 한다.
SYS@cdb1> show con_name

CON_NAME
------------------------------
SALESPDB

- 올바른 대상(pdb1)으로 전환한 뒤 작업
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@cdb1> alter database datafile
  2    '/u01/app/oracle/oradata/CDB1/pdb1/app_data01.dbf' resize 500M;

Database altered.

- [정리] 테이블스페이스는 컨테이너 로컬 객체:
-   1) 어느 컨테이너에서 CREATE 했는가가 전부
-   2) 여러 컨테이너에 같은 이름을 두려면 각 컨테이너에 개별 생성
-   3) 작업 전 SHOW CON_NAME + CDB_TABLESPACES로 CON_ID 대조가 사고 예방의 핵심
