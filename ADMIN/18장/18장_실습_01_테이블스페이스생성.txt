======================================================================
[1단계] 가장 기본적인 영구 테이블스페이스 생성 (숨은 기본값 확인)

- 이름과 데이터 파일 경로/크기만 지정하는 가장 단순한 형태
SYS@cdb1> create tablespace users_app
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/users_app01.dbf'
  3    size 100M;

Tablespace created.

- 방금 만든 테이블스페이스의 관리 속성 확인
-   19c 기본값: LOCAL(로컬 관리) + AUTO(ASSM) + SMALLFILE + PERMANENT
SYS@cdb1> select tablespace_name, extent_management, allocation_type,
  2         segment_space_management, contents, bigfile, logging
  3  from   dba_tablespaces
  4  where  tablespace_name = 'USERS_APP';

TABLESPACE_NAME  EXTENT_MAN ALLOCATIO SEGMEN CONTENTS  BIG LOGGING
---------------- ---------- --------- ------ --------- --- -------
USERS_APP        LOCAL      SYSTEM    AUTO   PERMANENT NO  LOGGING

======================================================================
[2단계] BIGFILE 테이블스페이스 생성
======================================================================

- (실수) 빅파일인데 데이터 파일을 두 개 지정 -> 빅파일은 파일이 하나뿐이라 오류
SYS@cdb1> create bigfile tablespace sales_big
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/sales_big01.dbf' size 1G,
  3             '/u01/app/oracle/oradata/CDB1/pdb1/sales_big02.dbf' size 1G;
  datafile '/u01/app/oracle/oradata/CDB1/pdb1/sales_big01.dbf' size 1G,
                                                                        *
ERROR at line 2:
ORA-32771: cannot add file to bigfile tablespace

- 원인: BIGFILE 테이블스페이스는 데이터 파일을 정확히 하나만 가진다.
-   파일을 하나만 지정하고, 대신 자동 확장으로 용량을 확보하도록 수정
SYS@cdb1> create bigfile tablespace sales_big
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/sales_big01.dbf'
  3    size 1G
  4    autoextend on next 500M maxsize 20G;

Tablespace created.

- 빅파일은 파일이 하나이므로 테이블스페이스 자체를 리사이즈할 수 있다
SYS@cdb1> alter tablespace sales_big resize 2G;

Tablespace altered.

- BIGFILE 여부 확인 (BIG=YES)
SYS@cdb1> select tablespace_name, bigfile from dba_tablespaces
  2  where tablespace_name = 'SALES_BIG';

TABLESPACE_NAME  BIG
---------------- ---
SALES_BIG        YES

======================================================================
[3단계] EXTENT MANAGEMENT UNIFORM / SEGMENT SPACE MANAGEMENT
======================================================================

- 모든 익스텐트를 1MB 고정 크기로 할당하는 UNIFORM 방식
SYS@cdb1> create tablespace fixed_ext
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/fixed_ext01.dbf' size 200M
  3    extent management local uniform size 1M;

Tablespace created.

- ALLOCATION_TYPE이 UNIFORM으로 지정되었는지 확인
SYS@cdb1> select tablespace_name, allocation_type, initial_extent
  2  from   dba_tablespaces
  3  where  tablespace_name = 'FIXED_EXT';

TABLESPACE_NAME  ALLOCATIO INITIAL_EXTENT
---------------- --------- --------------
FIXED_EXT        UNIFORM         1048576

======================================================================
[4단계] LOGGING vs NOLOGGING
======================================================================

- 스테이징 용도의 NOLOGGING 테이블스페이스 생성
SYS@cdb1> create tablespace stage_data
  2    datafile '/u01/app/oracle/oradata/CDB1/pdb1/stage_data01.dbf' size 100M
  3    nologging;

Tablespace created.

- LOGGING 컬럼이 NOLOGGING으로 지정되었는지 확인
SYS@cdb1> select tablespace_name, logging from dba_tablespaces
  2  where tablespace_name in ('USERS_APP','STAGE_DATA')
  3  order by tablespace_name;

TABLESPACE_NAME  LOGGING
---------------- ---------
STAGE_DATA       NOLOGGING
USERS_APP        LOGGING

- NOLOGGING은 대량 작업 속도를 높이지만, 백업 사이 적재 데이터는 미디어 복구 불가.
-   따라서 재적재 가능한 스테이징 영역에만 쓰고 사용 직후 백업하는 것이 원칙.
- 필요하면 ALTER로 다시 LOGGING으로 전환 가능
SYS@cdb1> alter tablespace stage_data logging;

Tablespace altered.

- [정리] 이번 실습에서 확인한 것:
-   1) CREATE TABLESPACE의 19c 기본값(LOCAL/ASSM/SMALLFILE/LOGGING)
-   2) BIGFILE은 파일 정확히 1개, 테이블스페이스 단위 RESIZE 가능
-   3) EXTENT UNIFORM으로 익스텐트 크기 고정
-   4) NOLOGGING의 용도와 위험
