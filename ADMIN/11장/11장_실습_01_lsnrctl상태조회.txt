-- 11장 실습_01: 기본 리스너 상태 조회(lsnrctl status/services) 실습
--   목표: 기본 리스너 LISTENER의 엔드포인트, 로그 경로, 등록된 서비스와
--         서비스 핸들러 상태(READY/UNKNOWN)를 확인한다.

======================================================================
[1단계] 리스너 프로세스와 유틸리티 위치 확인 (쉘)
======================================================================

- OS에서 리스너 실행 파일(tnslsnr) 프로세스가 떠 있는지 확인
-   리스너는 인스턴스와 독립적인 별도 백그라운드 프로세스다
[oracle@dbsvr ~]$ ps -ef | grep tnslsnr | grep -v grep
oracle    3812     1  0 09:05 ?        00:00:00 /u01/app/oracle/product/19.0.0/dbhome_1/bin/tnslsnr LISTENER -inherit

- lsnrctl 유틸리티 경로 확인
[oracle@dbsvr ~]$ which lsnrctl
/u01/app/oracle/product/19.0.0/dbhome_1/bin/lsnrctl

======================================================================
[2단계] (실수) 존재하지 않는 리스너 이름으로 상태 조회 -> 오류 재현
======================================================================

- 기본 리스너 이름을 LISTENER1로 잘못 알고 상태를 조회 시도
[oracle@dbsvr ~]$ lsnrctl status listener1

LSNRCTL for Linux: Version 19.0.0.0.0 - Production on 22-JUL-2026 10:12:44

Copyright (c) 1991, 2019, Oracle.  All rights reserved.

Connecting to (DESCRIPTION=(CONNECT_DATA=(SERVICE_NAME=))(ADDRESS=(PROTOCOL=IPC)(KEY=LISTENER1)))
TNS-01101: Could not find listener name or service name LISTENER1
 TNS-01102: Listener failed to find the service you requested

- 원인: 기본 리스너의 이름은 LISTENER1이 아니라 LISTENER다.
-   lsnrctl 뒤에 리스너 이름을 생략하면 기본 리스너 LISTENER를 대상으로 한다.

======================================================================
[3단계] 기본 리스너 LISTENER 상태 조회 (이름 생략 = 기본 리스너)
======================================================================

- 리스너 이름을 생략하고 상태 조회 -> 기본 리스너 LISTENER가 대상이 됨
[oracle@dbsvr ~]$ lsnrctl status

- 읽는 법:
-   * Alias=LISTENER : 기본 리스너의 이름
-   * Listening Endpoints : TCP 포트 1521에서 대기 (기본 포트)
-   * Listener Parameter File : listener.ora 경로 (동적 등록만 쓰면 매우 단출함)
-   * Listener Log File : ADR 아래 리스너 로그(진단 출발점)
-   * Services Summary : 현재 리스너가 알고 있는 서비스 목록
-   * status READY : 동적 등록으로 실제 준비 상태가 반영됨 (핵심)

======================================================================
[4단계] 서비스 핸들러 상세 확인 (lsnrctl services)
======================================================================

- 각 서비스가 어떤 종류의 핸들러(DEDICATED/DISPATCHER)를 몇 개 갖고
-   어떤 상태인지 상세 확인
[oracle@dbsvr ~]$ lsnrctl services

LSNRCTL for Linux: Version 19.0.0.0.0 - Production on 22-JUL-2026 10:14:20

Copyright (c) 1991, 2019, Oracle.  All rights reserved.

Connecting to (DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=dbsvr)(PORT=1521)))
Services Summary...
Service "cdb1.example.com" has 1 instance(s).
  Instance "cdb1", status READY, has 1 handler(s) for this service...
    Handler(s):
      "DEDICATED" established:12 refused:0 state:ready
         LOCAL SERVER
Service "salespdb.example.com" has 1 instance(s).
  Instance "cdb1", status READY, has 1 handler(s) for this service...
    Handler(s):
      "DEDICATED" established:3 refused:0 state:ready
         LOCAL SERVER
The command completed successfully

- 읽는 법:
-   * Handler "DEDICATED" ... state:ready : 전용 서버 핸들러가 새 연결을 받을 준비됨
-   * established/refused : 지금까지 확립/거부된 연결 수 (부하 파악의 근거)
-   * 이 정보들은 동적 등록으로 LREG가 실시간으로 밀어 넣은 값이다

======================================================================

- 인스턴스가 등록하는 로컬 리스너 값 확인
-   비어 있으면 기본값으로 호스트의 1521 포트 리스너를 가리킨다
SYS@cdb1> show parameter local_listener

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
local_listener                       string

- 인스턴스가 광고하는 서비스 이름 확인 (lsnrctl 출력의 서비스와 대응)
SYS@cdb1> show parameter service_names

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
service_names                        string      cdb1.example.com

- 인스턴스가 인식한 리스너 네트워크 등록 정보 확인
SYS@cdb1> select type, host, port from v$listener_network where type = 'LOCAL LISTENER';

TYPE            HOST                 PORT
--------------- -------------------- ----------
LOCAL LISTENER  dbsvr                1521

- [정리]
--   * 기본 리스너 이름은 LISTENER, 기본 포트는 1521
--   * lsnrctl status = 요약, lsnrctl services = 핸들러 상세(READY/부하)
--   * 동적 등록 서비스는 status READY로 표시된다 (실제 상태 반영)
--   * 인스턴스 SERVICE_NAMES <-> 리스너 Services Summary가 일치해야 접속 성공
