-- 목표: 종료 메시지의 차이와 다음 기동 시 복구 여부를 모드별로 직접 비교한다.

SYS@cdb1> alter session set nls_date_format='YYYY-MM-DD HH24:MI:SS';

======================================================================
[모드 1] NORMAL: 모든 세션이 스스로 나갈 때까지 대기 (기본값)
======================================================================

- 현재 사용자 세션이 있는지 확인 (있으면 NORMAL은 끝나지 않는다)
SYS@cdb1> select count(*) from v$session where type='USER' and username is not null;

  COUNT(*)
----------
         1

- (참고) 위 1건은 지금 이 SYS 세션 자신이다. 다른 사용자 세션이 있으면
-   NORMAL 종료는 그 세션이 끊길 때까지 무한 대기하므로 실무에서 잘 쓰지 않는다.

- SHUTDOWN(옵션 생략)은 NORMAL과 동일하게 동작함을 확인
-   여기서는 다른 사용자 세션이 없으므로 곧 완료된다
SYS@cdb1> shutdown normal
Database closed.
Database dismounted.
ORACLE instance shut down.

- NORMAL은 정상 종료: Database closed / dismounted 메시지가 출력됨 = 일관 상태
SYS@cdb1> startup
ORACLE instance started.

Total System Global Area 2046827888 bytes
Fixed Size                  9145712 bytes
Variable Size            1358954496 bytes
Database Buffers          671088640 bytes
Redo Buffers                7639040 bytes
Database mounted.
Database opened.

======================================================================
[모드 2] TRANSACTIONAL: 진행 중 트랜잭션이 끝나면 세션을 내보냄
======================================================================

- TRANSACTIONAL로 종료 (활성 트랜잭션이 없으면 즉시 완료)
SYS@cdb1> shutdown transactional
Database closed.
Database dismounted.
ORACLE instance shut down.

- 역시 정상 종료(일관 상태). 다음 기동에 복구 없음
SYS@cdb1> startup
ORACLE instance started.
Database mounted.
Database opened.

======================================================================
[모드 3] IMMEDIATE: 기다리지 않지만 롤백+체크포인트로 일관 종료 (실무 표준)
======================================================================

- IMMEDIATE로 종료. 미커밋 트랜잭션 롤백 후 CLOSE/DISMOUNT
SYS@cdb1> shutdown immediate
Database closed.
Database dismounted.
ORACLE instance shut down.

- Database closed/dismounted 메시지 = 정상 종료 절차를 밟음 = 일관 상태로 닫힘
SYS@cdb1> startup
ORACLE instance started.
Database mounted.
Database opened.

- 정상 종료였음을 근거로, 마지막 종료가 깨끗했는지 상태를 확인
-   OPEN_MODE=READ WRITE 이며 즉시 사용 가능
SYS@cdb1> select open_mode from v$database;

OPEN_MODE
--------------------
READ WRITE

======================================================================
[모드 4] ABORT: 정리 없이 즉시 종료 -> 다음 기동 시 인스턴스 복구
======================================================================

- (실수) 종료 후 곧바로 백업을 뜨려다 ABORT 직후임을 자각
-   ABORT 직후의 데이터베이스는 비일관 상태이므로 백업은 권장되지 않는다
SYS@cdb1> shutdown abort
ORACLE instance shut down.

- [주목] ABORT는 'Database closed./dismounted.'가 없다.
-   곧바로 'ORACLE instance shut down.'만 출력 = 정리 없이 죽였다는 증거

- 다음 기동. OPEN 단계에서 SMON이 자동 인스턴스 복구를 수행한 뒤 열린다
SYS@cdb1> startup
ORACLE instance started.

Total System Global Area 2046827888 bytes
Fixed Size                  9145712 bytes
Variable Size            1358954496 bytes
Database Buffers          671088640 bytes
Redo Buffers                7639040 bytes
Database mounted.
Database opened.

- 복구가 자동으로 완료되어 정상 OPEN 되었음을 확인
SYS@cdb1> select status from v$instance;

STATUS
------------
OPEN

======================================================================
[정리] 종료 모드별 요약
======================================================================
-   NORMAL        : 세션이 모두 나갈 때까지 대기 / 일관 / 복구 불필요 (기본값)
-   TRANSACTIONAL : 트랜잭션이 끝나면 세션 종료 / 일관 / 복구 불필요
-   IMMEDIATE     : 기다림 없이 롤백+체크포인트 / 일관 / 복구 불필요 (실무 표준)
-   ABORT         : 정리 없이 즉시 종료 / 비일관 / 다음 기동 시 복구 필요(자동)
- 공통점: 네 모드 모두 종료 시작 후 새 접속은 허용하지 않는다.

SYS@cdb1> exit
