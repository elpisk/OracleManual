-- 20장 실습_02: UNDO_RETENTION 설정 및 튜닝된 보존 기간 확인

- 루트 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 현재 UNDO_RETENTION 값 확인
======================================================================

SYS@cdb1> show parameter undo_retention

NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
undo_retention                       integer     900

- 해석: 커밋된 언두를 최소 900초(15분) 보존하려는 목표값. 단, 기본은 '최선 노력'.

======================================================================
[2단계] (실수 -> 오류 -> 재시도) 잘못된 값/구문으로 변경 시도
======================================================================

- (실수) 초 단위가 아닌 '30m' 같은 표기로 설정 시도
SYS@cdb1> alter system set undo_retention='30m';
alter system set undo_retention='30m'
*
ERROR at line 1:
ORA-00020?  -- (문법 오류) UNDO_RETENTION은 정수(초)만 허용

- 원인: UNDO_RETENTION은 초 단위 정수만 받음. 30분은 1800(초)으로 지정해야 함
SYS@cdb1> alter system set undo_retention=1800 scope=both;

System altered.

- SCOPE=BOTH 이므로 메모리에 즉시 반영 + SPFILE에도 기록(동적 파라미터)
SYS@cdb1> show parameter undo_retention

NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
undo_retention                       integer     1800

======================================================================
[3단계] 실제 Oracle이 적용 중인 '튜닝된 보존 기간' 확인
======================================================================

- V$UNDOSTAT은 10분 간격 언두 통계. TUNED_UNDORETENTION이 실제 적용 보존 기간(초)
SYS@cdb1> select to_char(begin_time,'HH24:MI') b, undoblks,
  2         maxquerylen, tuned_undoretention, nospaceerrcnt
  3  from   v$undostat order by begin_time desc fetch first 5 rows only;

B      UNDOBLKS MAXQUERYLEN TUNED_UNDORETENTION NOSPACEERRCNT
----- --------- ----------- ------------------- -------------
14:30       142         410                1800             0
14:20        98         180                1800             0
14:10       210          95                1800             0
14:00       175         220                1800             0
13:50        88          40                1800             0

- 해석: MAXQUERYLEN(가장 긴 쿼리 실행 시간, 초)이 최대 410초.
-   UNDO_RETENTION 1800초는 이 쿼리를 충분히 커버함. NOSPACEERRCNT=0 이므로 공간 부족 없음.
-   만약 MAXQUERYLEN이 UNDO_RETENTION에 근접/초과하면 ORA-01555 위험 -> 값을 늘려야 함.

======================================================================
[4단계] UNDO_RETENTION은 '보장'이 아님을 개념적으로 확인
======================================================================

- 현재 언두 TS의 보존 보장 여부 확인 (NOGUARANTEE = 최선 노력)
SYS@cdb1> select tablespace_name, retention
  2  from   dba_tablespaces where contents='UNDO';

TABLESPACE_NAME      RETENTION
-------------------- -----------
UNDOTBS1             NOGUARANTEE

- 해석: NOGUARANTEE 이므로 공간이 부족하면 만료 전 커밋 언두도 덮어써질 수 있음.
-   반드시 보존을 강제하려면 다음 실습(05/RETENTION GUARANTEE)에서 GUARANTEE를 설정.

======================================================================
[정리] 값 원복
======================================================================

- 실습 후 기본값(900)으로 되돌리기 (환경 정책에 따라 유지해도 됨)
SYS@cdb1> alter system set undo_retention=900 scope=both;

System altered.

- [정리] 핵심 확인 완료:
-   UNDO_RETENTION은 초 단위 정수, 동적 파라미터(ALTER SYSTEM 즉시 반영)
-   실제 적용값은 V$UNDOSTAT.TUNED_UNDORETENTION, 산정 근거는 MAXQUERYLEN
-   NOGUARANTEE에서는 최선 노력일 뿐 -> 보존 강제는 RETENTION GUARANTEE 필요
