-- 20장 실습_03: 고정 크기 언두 테이블스페이스 사이징 (DBMS_UNDO_ADV + AUTOEXTEND OFF)

- 루트 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 현재 언두 데이터 파일과 자동확장 여부 확인
======================================================================

SYS@cdb1> select file_name, bytes/1024/1024 mb, autoextensible, maxbytes/1024/1024 max_mb
  2  from   dba_data_files where tablespace_name='UNDOTBS1';

FILE_NAME                                       MB AUT     MAX_MB
--------------------------------------------- ---- --- ----------
/u01/app/oracle/oradata/CDB1/undotbs01.dbf     200 YES      32768

- 해석: 현재 200MB이며 AUTOEXTEND=YES(자동확장). 공간 사용이 예측 불가능함.
-   예측 가능한 운영을 위해 고정 크기로 전환하려 함.

======================================================================
[2단계] 목표 보존 기간에 필요한 언두 크기 산정 (Undo Advisor)
======================================================================

- DBMS_UNDO_ADV.REQUIRED_UNDO_SIZE(초)는 목표 보존을 만족하는 데 필요한 언두 크기(MB) 반환
- 목표: UNDO_RETENTION 1800초를 커버하는 크기 산정
SYS@cdb1> select dbms_undo_adv.required_undo_size(1800) as need_mb from dual;

   NEED_MB
----------
       350

- 해석: 1800초 보존을 위해 약 350MB가 필요. 이 값을 근거로 고정 크기를 350MB로 결정.
-   (주의) V$UNDOSTAT에 대표 부하가 충분히 쌓인 뒤 실행해야 정확함.

======================================================================
[3단계] (실수 -> 오류 -> 재시도) 현재 사용량보다 작게 리사이즈 시도
======================================================================

- (실수) 우선 100MB로 축소 시도 - 현재 사용 중인 언두보다 작으면 실패
SYS@cdb1> alter database datafile '/u01/app/oracle/oradata/CDB1/undotbs01.dbf' resize 100M;
alter database datafile '/u01/app/oracle/oradata/CDB1/undotbs01.dbf' resize 100M
*
ERROR at line 1:
ORA-03297: file contains used data beyond requested RESIZE value

- 원인: 파일 뒷부분에 이미 사용 중인 언두 익스텐트가 있어 100MB로 축소 불가.
-   산정값(350MB)으로 리사이즈하면 정상 처리됨
SYS@cdb1> alter database datafile '/u01/app/oracle/oradata/CDB1/undotbs01.dbf' resize 350M;

Database altered.

======================================================================
[4단계] 자동확장 OFF로 고정 크기 확정
======================================================================

SYS@cdb1> alter database datafile '/u01/app/oracle/oradata/CDB1/undotbs01.dbf' autoextend off;

Database altered.

- 고정 크기 전환 결과 확인 (AUTOEXTENSIBLE=NO)
SYS@cdb1> select file_name, bytes/1024/1024 mb, autoextensible
  2  from   dba_data_files where tablespace_name='UNDOTBS1';

FILE_NAME                                       MB AUT
--------------------------------------------- ---- ---
/u01/app/oracle/oradata/CDB1/undotbs01.dbf     350 NO

- 고정 크기에서는 GUARANTEE가 켜져 있으면 공간 부족 시 DML 실패 위험 -> NOGUARANTEE 유지 확인
SYS@cdb1> select tablespace_name, retention from dba_tablespaces where contents='UNDO';

TABLESPACE_NAME      RETENTION
-------------------- -----------
UNDOTBS1             NOGUARANTEE

- 해석: 고정 350MB + NOGUARANTEE. Oracle이 350MB 공간에 맞춰 TUNED_UNDORETENTION을 자동 조정함.

======================================================================
[정리] 필요 시 자동확장 재활성화(상한 지정)로 절충 구성
======================================================================

- 폭증 대비가 필요하면 자동확장 ON + MAXSIZE 상한으로 절충 가능(선택)
SYS@cdb1> alter database datafile '/u01/app/oracle/oradata/CDB1/undotbs01.dbf'
  2  autoextend on next 50M maxsize 1G;

Database altered.

- [정리] 핵심 확인 완료:
-   DBMS_UNDO_ADV.REQUIRED_UNDO_SIZE(초)로 필요 크기 산정 -> RESIZE -> AUTOEXTEND OFF로 고정
-   현재 사용량보다 작게 RESIZE하면 ORA-03297
-   고정 크기에서는 NOGUARANTEE 권장, 폭증 대비는 AUTOEXTEND ON + MAXSIZE 절충
