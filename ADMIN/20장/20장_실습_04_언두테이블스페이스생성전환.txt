-- 20장 실습_04: 언두 테이블스페이스 생성 / 전환 / 삭제 (무중단 교체)

- 루트 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 현재 사용 중인 언두 테이블스페이스 확인
SYS@cdb1> show parameter undo_tablespace

NAME                                 TYPE        VALUE
------------------------------------ ----------- ----------
undo_tablespace                      string      UNDOTBS1

======================================================================
[1단계] 새 언두 테이블스페이스 생성 (고정 크기)
======================================================================

- (실수) 일반 CREATE TABLESPACE로 만들면 언두 전용이 아니라 영구 TS가 됨
SYS@cdb1> create tablespace undotbs2
  2  datafile '/u01/app/oracle/oradata/CDB1/undotbs02.dbf' size 350M;

Tablespace created.

- 확인해 보니 CONTENTS가 PERMANENT -> 언두 TS가 아님. 잘못 생성됨
SYS@cdb1> select tablespace_name, contents from dba_tablespaces where tablespace_name='UNDOTBS2';

TABLESPACE_NAME      CONTENTS
-------------------- ---------
UNDOTBS2             PERMANENT

- 원인: 언두 TS는 반드시 CREATE UNDO TABLESPACE로 만들어야 함. 잘못 만든 것 삭제 후 재생성
SYS@cdb1> drop tablespace undotbs2 including contents and datafiles;

Tablespace dropped.

- 올바르게 CREATE UNDO TABLESPACE로 재생성 (자동확장 OFF)
SYS@cdb1> create undo tablespace undotbs2
  2  datafile '/u01/app/oracle/oradata/CDB1/undotbs02.dbf' size 350M autoextend off;

Tablespace created.

SYS@cdb1> select tablespace_name, contents, status from dba_tablespaces where tablespace_name='UNDOTBS2';

TABLESPACE_NAME      CONTENTS  STATUS
-------------------- --------- --------
UNDOTBS2             UNDO      ONLINE

======================================================================
[2단계] 인스턴스가 사용할 언두 TS를 새 것으로 전환
======================================================================

SYS@cdb1> alter system set undo_tablespace=undotbs2 scope=both;

System altered.

- 전환 확인
SYS@cdb1> show parameter undo_tablespace

NAME                                 TYPE        VALUE
------------------------------------ ----------- ----------
undo_tablespace                      string      UNDOTBS2

- 이제 새 트랜잭션은 UNDOTBS2를 사용. 기존 UNDOTBS1은 아직 활성 트랜잭션이 있으면 정리 대기.

======================================================================
[3단계] (실수 -> 오류 -> 재시도) 활성 트랜잭션이 남은 기존 TS 즉시 삭제 시도
======================================================================

- 기존 언두 TS에 아직 정리되지 않은 언두가 있는 상태에서 삭제 시도
SYS@cdb1> drop tablespace undotbs1 including contents and datafiles;
drop tablespace undotbs1 including contents and datafiles
*
ERROR at line 1:
ORA-30013: undo tablespace 'UNDOTBS1' is currently in use

- 원인: 전환 직후 기존 TS는 남은 트랜잭션이 끝날 때까지 PENDING OFFLINE 상태.
-   잠시 후(활성 트랜잭션 종료 후) 재시도하면 정상 삭제됨
SYS@cdb1> drop tablespace undotbs1 including contents and datafiles;

Tablespace dropped.

- 최종 언두 TS 목록 확인 (UNDOTBS2만 남음)
SYS@cdb1> select tablespace_name, contents, status from dba_tablespaces where contents='UNDO';

TABLESPACE_NAME      CONTENTS  STATUS
-------------------- --------- --------
UNDOTBS2             UNDO      ONLINE

======================================================================
[정리] 원래 이름 체계로 복귀(선택)
======================================================================

- 운영 표준이 UNDOTBS1 이라면 다시 UNDOTBS1을 만들어 되돌릴 수 있음(여기서는 UNDOTBS2 유지)
- [정리] 핵심 확인 완료:
-   언두 TS는 CREATE UNDO TABLESPACE로 생성(일반 CREATE TABLESPACE는 영구 TS가 됨)
-   ALTER SYSTEM SET UNDO_TABLESPACE로 온라인 전환, 기존 TS는 PENDING OFFLINE
-   활성 트랜잭션 종료 전 DROP 시 ORA-30013 -> 종료 후 재시도
