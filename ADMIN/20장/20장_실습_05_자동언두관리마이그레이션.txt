-- 20장 실습_05: 자동 언두 관리(AUM)로의 마이그레이션 및 검증

- 루트 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 현재 언두 관리 방식 확인
======================================================================

SYS@cdb1> show parameter undo_management

NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
undo_management                      string      AUTO

- 해석: 이미 AUTO(자동 언두 관리). 과거 수동 롤백 세그먼트 방식(MANUAL)은 12c부터 미지원.
-   이 실습은 '수동 -> 자동' 전환 개념과 검증 절차를 확인하는 데 목적이 있음.

======================================================================
[2단계] (실수 -> 오류) 수동 모드(MANUAL)로 되돌리려는 시도의 위험 확인
======================================================================

- (실수) 옛 방식이 그리워 MANUAL로 되돌리려 SPFILE에 기록 시도
SYS@cdb1> alter system set undo_management=manual scope=spfile;

System altered.

- 주의: UNDO_MANAGEMENT는 정적 파라미터라 재기동해야 반영됨.
-   MANUAL은 12c 이후 권장되지 않으며, 재기동 시 자동 언두 세그먼트를 쓰지 못해
-   ORA-01552 (cannot use system rollback segment) 등 심각한 문제가 발생할 수 있음.
-   => 반드시 AUTO로 원복해야 안전
SYS@cdb1> alter system set undo_management=auto scope=spfile;

System altered.

======================================================================
[3단계] 자동 언두 관리 정상 동작에 필요한 조건 점검
======================================================================

- (a) UNDO_MANAGEMENT=AUTO 인지
SYS@cdb1> select value from v$parameter where name='undo_management';

VALUE
--------
AUTO

- (b) 유효한 언두 테이블스페이스가 지정되어 온라인인지
SYS@cdb1> select a.value undo_ts, t.status
  2  from   v$parameter a, dba_tablespaces t
  3  where  a.name='undo_tablespace' and t.tablespace_name=a.value;

UNDO_TS              STATUS
-------------------- --------
UNDOTBS2             ONLINE

- (c) 언두 세그먼트가 온라인으로 자동 관리되는지
SYS@cdb1> select status, count(*) from dba_rollback_segs
  2  where tablespace_name='UNDOTBS2' group by status;

STATUS             COUNT(*)
---------------- ----------
ONLINE                   10

- 해석: AUTO + 온라인 언두 TS + 온라인 언두 세그먼트 => 자동 언두 관리 정상 동작.

======================================================================
[4단계] 자동 튜닝 동작 확인 (Oracle이 보존/세그먼트를 스스로 조정)
======================================================================

- V$UNDOSTAT으로 자동 튜닝된 보존 기간과 언두 사용 통계 확인
SYS@cdb1> select to_char(begin_time,'HH24:MI') b, tuned_undoretention,
  2         maxquerylen, ssolderrcnt, nospaceerrcnt
  3  from   v$undostat order by begin_time desc fetch first 3 rows only;

B      TUNED_UNDORETENTION MAXQUERYLEN SSOLDERRCNT NOSPACEERRCNT
----- ------------------- ----------- ----------- -------------
15:10                 900         120           0             0
15:00                 900          85           0             0
14:50                 900         210           0             0

- 해석: SSOLDERRCNT(ORA-01555 발생 수)=0, NOSPACEERRCNT=0 이면 자동 관리가 워크로드를 잘 감당 중.
-   이 값들이 증가하면 언두 TS 크기/UNDO_RETENTION 조정이 필요하다는 신호.

======================================================================
[정리]
======================================================================

- [정리] 핵심 확인 완료:
-   19c에서는 AUTO가 유일 지원. MANUAL 전환은 위험(정적 파라미터 + ORA-01552 우려) -> AUTO 유지
-   AUM 정상 조건 = AUTO + 온라인 언두 TS + 온라인 언두 세그먼트
-   자동 튜닝 상태는 V$UNDOSTAT(TUNED_UNDORETENTION/SSOLDERRCNT/NOSPACEERRCNT)로 점검
