-- 2장 실습_01: 프로세스 아키텍처 및 구조 확인(클라이언트/서버/백그라운드 프로세스 구분)

- 1장과 동일한 CDB1 환경에 SYSDBA로 접속된 상태에서 시작 (프롬프트는 사용자@인스턴스 형태)
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 인스턴스에 붙어 있는 모든 프로세스 조망: V$PROCESS
======================================================================

- V$PROCESS는 인스턴스에 연결된 모든 OS 프로세스(백그라운드+서버)를 보여 줌
-   BACKGROUND=1 이면 백그라운드 프로세스, NULL 이면 서버/클라이언트 계열
SYS@cdb1> select count(*) as total_proc,
  2         count(background) as background_proc,
  3         count(*) - count(background) as server_etc
  4  from v$process;

TOTAL_PROC BACKGROUND_PROC SERVER_ETC
---------- --------------- ----------
        62              39         23

- 백그라운드 프로세스만 골라서 OS 프로세스 ID(SPID)와 실행 프로그램명을 확인
-   ora_<약어>_<SID> 형태로 OS에 실재함을 눈으로 확인 (실습_08에서 상세)
SYS@cdb1> select spid, pname, program
  2  from v$process
  3  where background = 1 and rownum <= 8
  4  order by pname;

SPID        PNAME PROGRAM
----------- ----- ------------------------------------------------

3006        DBW0  oracle@dbsvr (DBW0)
2998        DIAG  oracle@dbsvr (DIAG)
3010        LGWR  oracle@dbsvr (LGWR)
2988        PMON  oracle@dbsvr (PMON)
2990        PMAN  oracle@dbsvr (PMAN)
2994        PSP0  oracle@dbsvr (PSP0)
2996        VKTM  oracle@dbsvr (VKTM)

8 rows selected.

======================================================================
[2단계] 세션과 서버 프로세스의 연결 확인: V$SESSION (프로세스 유형 구분)
======================================================================

- V$SESSION.TYPE 으로 세션을 BACKGROUND / USER 로 구분
-   USER 세션은 사용자가 접속한 세션, BACKGROUND 세션은 백그라운드 프로세스의 세션
SYS@cdb1> select type, count(*) from v$session group by type;

TYPE         COUNT(*)
---------- ----------
BACKGROUND         39
USER                3

- 내 현재 세션이 어떤 서버 프로세스(PADDR)와 연결되어 있는지 확인
-   SERVER='DEDICATED' 이면 전용 서버 프로세스가 이 세션 하나만 담당함
SYS@cdb1> select s.sid, s.serial#, s.server, s.username, p.spid
  2  from   v$session s join v$process p on s.paddr = p.addr
  3  where  s.sid = sys_context('USERENV','SID');

       SID    SERIAL# SERVER    USERNAME   SPID
---------- ---------- --------- ---------- -----------
       389      12345 DEDICATED SYS        4210

======================================================================
[3단계] 백그라운드 세션과 사용자 세션을 프로그램별로 구분
======================================================================

- 백그라운드 세션의 대표 프로그램(PROGRAM)을 확인 (괄호 안이 프로세스 약어)
SYS@cdb1> select sid, program
  2  from   v$session
  3  where  type = 'BACKGROUND' and rownum <= 6
  4  order  by sid;

       SID PROGRAM
---------- ------------------------------------------------
         2 oracle@dbsvr (PMON)
         3 oracle@dbsvr (CLMN)
         4 oracle@dbsvr (PSP0)
         5 oracle@dbsvr (VKTM)
         8 oracle@dbsvr (DBW0)
         9 oracle@dbsvr (LGWR)

======================================================================
[4단계] 전용 서버/공유 서버 구성 여부 확인
======================================================================

- (실수) 전용/공유 서버 구성을 보려고 파라미터명을 잘못 입력
SYS@cdb1> show parameter shared_server

- 원인: 파라미터 이름이 틀림. 실제 파라미터는 SHARED_SERVERS(복수형).
-   SHOW PARAMETER는 오타여도 조용히 아무 행도 안 내므로, 정확한 이름으로 재시도
SYS@cdb1> show parameter shared_servers

NAME                                 TYPE        VALUE
------------------------------------ ----------- -------
max_shared_servers                   integer
shared_servers                       integer     0

- SHARED_SERVERS=0 이므로 현재는 공유 서버가 비활성(=전용 서버 전용 구성)
-   따라서 위 3단계에서 본 것처럼 사용자 세션은 모두 SERVER='DEDICATED'
SYS@cdb1> select distinct server from v$session where type = 'USER';

SERVER
---------
DEDICATED

- 디스패처(공유 서버의 관문)도 기동되어 있지 않음을 확인 (0 rows)
SYS@cdb1> select name, status from v$dispatcher;

no rows selected

- [정리] 프로세스 구조 확인 완료:
-   V$PROCESS = 모든 OS 프로세스(서버+백그라운드), BACKGROUND 컬럼으로 구분
-   V$SESSION = 세션-서버프로세스 연결, TYPE(USER/BACKGROUND)/SERVER(DEDICATED/SHARED)로 구분
-   현재 cdb1은 전용 서버 구성(SHARED_SERVERS=0)
SYS@cdb1>
