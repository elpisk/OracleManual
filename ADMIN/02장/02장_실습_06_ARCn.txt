-- 2장 실습_06: ARCn(Archiver) 프로세스 확인 - 아카이브 로그 모드와 아카이버 구성

- CDB1 루트에 SYSDBA로 접속된 상태에서 시작
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] ARCHIVELOG 모드 확인 (ARCn은 ARCHIVELOG 모드에서만 동작)
======================================================================

- 데이터베이스가 아카이브 로그 모드인지 확인
-   ARCHIVELOG 이면 리두 로그를 덮어쓰기 전 ARCn이 아카이브 목적지로 복사함
SYS@cdb1> select log_mode from v$database;

LOG_MODE
------------
ARCHIVELOG

- 아카이빙 활성화 상태와 다음 아카이브 대상 로그 순번을 한눈에 확인
SYS@cdb1> archive log list

Database log mode              Archive Mode
Automatic archival             Enabled
Archive destination            USE_DB_RECOVERY_FILE_DEST
Oldest online log sequence     57
Next log sequence to archive   59
Current log sequence           59

======================================================================
[2단계] ARCn 프로세스 존재 확인
======================================================================

- 아카이버 프로세스(ARC0~)가 기동되어 있는지 확인
-   ARCHIVELOG 모드이므로 최소 하나 이상의 ARCn이 존재해야 정상
SYS@cdb1> select name, description, paddr
  2  from   v$bgprocess
  3  where  name like 'ARC%'
  4  order  by name;

NAME  DESCRIPTION              PADDR
----- ------------------------ ----------------
ARC0  Archival Process 0       000000009A4021F0
ARC1  Archival Process 1       000000009A403A70
ARC2  Archival Process 2       00
ARC3  Archival Process 3       00

- 해석: ARC0/ARC1이 기동 중(PADDR<>00), ARC2/ARC3은 대기 슬롯(미기동).
-   Oracle은 아카이빙 부하에 따라 필요한 만큼 자동으로 추가 기동함.

======================================================================
[3단계] LOG_ARCHIVE_MAX_PROCESSES 파라미터 조회 (아카이버 최대 개수)
======================================================================

- 아카이버 프로세스 최대 개수 확인 (기본 4, 최대 30까지 구성 가능)
SYS@cdb1> show parameter log_archive_max_processes

NAME                                 TYPE        VALUE
------------------------------------ ----------- -------
log_archive_max_processes            integer     4

- 아카이브 목적지도 함께 확인 (LOG_ARCHIVE_DEST_1 = 로컬 FRA)
SYS@cdb1> show parameter log_archive_dest_1

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
log_archive_dest_1                   string

- 값이 비어 있으면 기본 목적지(USE_DB_RECOVERY_FILE_DEST)로 아카이빙됨. FRA 경로 확인
SYS@cdb1> show parameter db_recovery_file_dest

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
db_recovery_file_dest                string      /u01/app/oracle/fast_recovery_area
db_recovery_file_dest_size           big integer 10G

======================================================================
[4단계] 강제 로그 스위치로 아카이빙 유발 및 확인
======================================================================

- 아카이빙 전 생성된 아카이브 로그 개수 확인
SYS@cdb1> select count(*) from v$archived_log where dest_id = 1;

  COUNT(*)
----------
        58

- (실수) 모든 로그 그룹을 아카이브하려고 명령어를 잘못 입력 (ALL LOGS는 없는 구문)
SYS@cdb1> alter system archive log all;
alter system archive log all
                         *
ERROR at line 1:
ORA-02231: missing or invalid option to ALTER DATABASE

- 원인: 잘못된 구문. 로그 스위치로 아카이빙을 유발하는 올바른 명령으로 재시도
-   로그 스위치가 일어나면 방금 채워진 그룹을 ARCn이 아카이브 목적지로 복사함
SYS@cdb1> alter system switch logfile;

System altered.

- 아카이브 로그가 1개 늘었는지 확인 (ARCn이 실제로 아카이빙을 수행했음)
SYS@cdb1> select sequence#, name, completion_time
  2  from   v$archived_log
  3  where  dest_id = 1
  4  order  by sequence# desc
  5  fetch  first 3 rows only;

 SEQUENCE# NAME                                                    COMPLETION_TIME
---------- ------------------------------------------------------- -------------------
        59 /u01/app/oracle/fast_recovery_area/CDB1/archivelog/...  24-JUL-26
        58 /u01/app/oracle/fast_recovery_area/CDB1/archivelog/...  24-JUL-26
        57 /u01/app/oracle/fast_recovery_area/CDB1/archivelog/...  24-JUL-26

- [정리] ARCn 확인 완료:
-   ARCn = ARCHIVELOG 모드에서만 동작하는 선택적 프로세스, 로그 스위치가 주된 트리거
-   LOG_ARCHIVE_MAX_PROCESSES(기본4/최대30)로 개수 조절, LOG_ARCHIVE_DEST_n으로 목적지 다중화
-   ALTER SYSTEM SWITCH LOGFILE로 아카이빙 유발 -> V$ARCHIVED_LOG로 결과 확인
