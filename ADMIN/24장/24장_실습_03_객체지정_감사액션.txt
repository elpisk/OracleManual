-- 24장 실습_03: 객체 지정(Object-Specific) 감사 액션 설정 (ACTIONS ... ON)
-- 목표: 특정 테이블에 대한 SELECT/DML 만 감사하는 객체 지정 정책을 만든다.
-- 주의: 객체 지정 감사는 대상 객체가 있는 컨테이너(여기서는 PDB1)에서 로컬 정책으로 만든다.

- 대상 객체가 있는 PDB 로 이동한다.
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@cdb1> show con_name

CON_NAME
------------------------------
PDB1

======================================================================
[1단계] (오류 -> 원인 -> 수정) 존재하지 않는 객체 지정
======================================================================

- (실수) 테이블 이름을 EMPLOYEE(오타)로 지정.
SYS@cdb1> create audit policy emp_access_pol
  2    actions select on hr.employee;
  actions select on hr.employee
                        *
ERROR at line 2:
ORA-00942: table or view does not exist

- 원인: HR 스키마의 실제 테이블은 EMPLOYEES 이며, EMPLOYEE 는 존재하지 않는다.
- 수정: 올바른 객체명으로 다시 작성한다.
SYS@cdb1> create audit policy emp_access_pol
  2    actions select on hr.employees,
  3            insert on hr.employees,
  4            update on hr.employees,
  5            delete on hr.employees;

Audit policy created.

======================================================================
[2단계] 정책 활성화
======================================================================

SYS@cdb1> audit policy emp_access_pol;

Audit succeeded.

- 정책 구성 확인 (객체 지정 감사는 object_schema/object_name 이 채워진다)
SYS@cdb1> select audit_option, object_schema, object_name, object_type
  2  from   audit_unified_policies
  3  where  policy_name = 'EMP_ACCESS_POL'
  4  order  by audit_option;

AUDIT_OPTION  OBJECT_SCHEMA  OBJECT_NAME   OBJECT_TYPE
------------- -------------- ------------- -----------
DELETE        HR             EMPLOYEES     TABLE
INSERT        HR             EMPLOYEES     TABLE
SELECT        HR             EMPLOYEES     TABLE
UPDATE        HR             EMPLOYEES     TABLE

======================================================================
[3단계] 감사 대상 활동 발생
======================================================================

SYS@cdb1> connect hr/Oracle_123@pdb1
Connected.
HR@cdb1> select count(*) from employees;

  COUNT(*)
----------
       107

HR@cdb1> update employees set salary = salary where employee_id = 100;

1 row updated.

HR@cdb1> commit;

Commit complete.

======================================================================
[4단계] 감사 레코드 확인
======================================================================

HR@cdb1> connect sys/Oracle_123@pdb1 as sysdba
Connected.
SYS@cdb1> select dbusername, action_name, object_name, return_code
  2  from   unified_audit_trail
  3  where  object_name = 'EMPLOYEES'
  4  and    unified_audit_policies = 'EMP_ACCESS_POL'
  5  order  by event_timestamp desc
  6  fetch first 5 rows only;

DBUSERNAME  ACTION_NAME   OBJECT_NAME   RETURN_CODE
----------- ------------- ------------- -----------
HR          UPDATE        EMPLOYEES               0
HR          SELECT        EMPLOYEES               0

- SELECT 와 UPDATE 가 각각 별도 레코드로 남았다(BY ACCESS 방식).

======================================================================
[정리]
======================================================================
- 객체 지정 감사: ACTIONS action ON schema.object 형태로 작성한다.
- 존재하지 않는 객체 지정은 ORA-00942 -> 정확한 스키마.객체명으로 수정.
- 로컬 객체 감사는 그 객체가 있는 PDB 의 로컬 정책으로 만든다.
- 정리
SYS@cdb1> noaudit policy emp_access_pol;

Noaudit succeeded.

SYS@cdb1> drop audit policy emp_access_pol;

Audit policy dropped.
