-- 24장 실습_02: 시스템 전반(System-Wide) 감사 옵션 설정 (PRIVILEGES / ACTIONS)
-- 목표: 시스템 권한 감사(PRIVILEGES)와 시스템 액션 감사(ACTIONS)를 구분해 설정한다.

SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] (오류 -> 원인 -> 수정) 권한 없는 사용자가 정책 생성 시도
======================================================================

- 일반 관리 계정으로 접속했다고 가정하고, AUDIT SYSTEM 권한이 없는 상태로 시도.
SYS@cdb1> connect appadmin/Oracle_123@cdb1
Connected.
APPADMIN@cdb1> create audit policy sys_priv_pol
  2    privileges create any table, drop any table;
create audit policy sys_priv_pol
*
ERROR at line 1:
ORA-01031: insufficient privileges

- 원인: 감사 정책 생성에는 AUDIT SYSTEM 권한(또는 AUDIT_ADMIN 롤)이 필요하다.
- 수정: 보안 관리자(AUDIT_ADMIN 롤 보유)로 다시 접속한다.
APPADMIN@cdb1> connect sys/Oracle_123@cdb1 as sysdba
Connected.

======================================================================
[2단계] PRIVILEGES 절 - 시스템 권한 사용 감사
======================================================================

- 강력한 ANY 권한의 실제 사용을 감사한다.
SYS@cdb1> create audit policy sys_priv_pol
  2    privileges create any table, drop any table, alter any table;

Audit policy created.

SYS@cdb1> audit policy sys_priv_pol;

Audit succeeded.

======================================================================
[3단계] ACTIONS 절 - 시스템 액션(문장 유형) 감사
======================================================================

- DDL 과 로그온/로그오프 등 문장 유형을 감사한다.
SYS@cdb1> create audit policy ddl_logon_pol
  2    actions create table, drop table, alter table,
  3            create user, drop user, logon, logoff;

Audit policy created.

SYS@cdb1> audit policy ddl_logon_pol;

Audit succeeded.

======================================================================
[4단계] 권한 감사와 액션 감사의 차이 확인
======================================================================

- 자기 스키마에 테이블을 만드는 활동을 유발한다.
SYS@cdb1> connect hr/Oracle_123@pdb1
Connected.
HR@cdb1> create table t_priv_test (id number);

Table created.

- 루트로 돌아와 감사 결과를 비교한다.
HR@cdb1> connect sys/Oracle_123@cdb1 as sysdba
Connected.
SYS@cdb1> select dbusername, action_name, unified_audit_policies
  2  from   unified_audit_trail
  3  where  object_name = 'T_PRIV_TEST';

DBUSERNAME  ACTION_NAME    UNIFIED_AUDIT_POLICIES
----------- -------------- ----------------------
HR          CREATE TABLE   DDL_LOGON_POL

- 관찰: 자기 스키마 CREATE TABLE 은 별도 ANY 권한이 필요 없으므로
-   PRIVILEGES CREATE ANY TABLE 감사(SYS_PRIV_POL)로는 잡히지 않고,
-   ACTIONS CREATE TABLE 감사(DDL_LOGON_POL)로만 잡힌다.
- 이것이 '권한 관점'과 '문장 관점'의 핵심 차이다.

======================================================================
[정리]
======================================================================
- PRIVILEGES: 시스템 권한이 실제 사용될 때 감사(권한 관점).
- ACTIONS: 특정 문장 유형이 실행될 때 감사(문장 관점).
- 정책 생성 권한 부족은 ORA-01031 -> AUDIT_ADMIN 롤/AUDIT SYSTEM 권한으로 해결.
- 정리
SYS@cdb1> noaudit policy sys_priv_pol;

Noaudit succeeded.

SYS@cdb1> noaudit policy ddl_logon_pol;

Noaudit succeeded.

SYS@cdb1> connect hr/Oracle_123@pdb1
Connected.
HR@cdb1> drop table t_priv_test purge;

Table dropped.

HR@cdb1> exit
