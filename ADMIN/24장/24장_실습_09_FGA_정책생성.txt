-- 24장 실습_09: Fine-Grained Auditing(FGA) 정책 생성 (DBMS_FGA)
-- 목표: 특정 컬럼과 조건이 결합된 정밀 감사를 DBMS_FGA.ADD_POLICY 로 구성한다.

SYS@cdb1> alter session set container = pdb1;

Session altered.

======================================================================
[1단계] (오류 -> 원인 -> 수정) 존재하지 않는 감사 컬럼 지정
======================================================================

- (실수) 감사 컬럼명을 SAL(오타)로 지정. 실제 컬럼은 SALARY.
SYS@cdb1> begin
  2    dbms_fga.add_policy(
  3      object_schema   => 'HR',
  4      object_name     => 'EMPLOYEES',
  5      policy_name     => 'FGA_HIGH_SALARY',
  6      audit_column    => 'SAL',
  7      audit_condition => 'SALARY > 100000',
  8      statement_types => 'SELECT,UPDATE');
  9  end;
 10  /
begin
*
ERROR at line 1:
ORA-28710: invalid audit column
ORA-06512: at "SYS.DBMS_FGA", line 20
ORA-06512: at line 2

- 원인: audit_column 에 지정한 SAL 컬럼이 HR.EMPLOYEES 에 존재하지 않는다.
- 수정: 올바른 컬럼명 SALARY 로 다시 등록한다.
SYS@cdb1> begin
  2    dbms_fga.add_policy(
  3      object_schema     => 'HR',
  4      object_name       => 'EMPLOYEES',
  5      policy_name       => 'FGA_HIGH_SALARY',
  6      audit_column      => 'SALARY',
  7      audit_condition   => 'SALARY > 100000',
  8      statement_types   => 'SELECT,UPDATE',
  9      audit_column_opts => DBMS_FGA.ANY_COLUMNS);
 10  end;
 11  /

PL/SQL procedure successfully completed.

======================================================================
[2단계] (오류 -> 원인 -> 수정) 같은 이름으로 재등록
======================================================================

- (실수) 조건을 바꾸려고 동일 policy_name 으로 다시 ADD_POLICY.
SYS@cdb1> begin
  2    dbms_fga.add_policy(
  3      object_schema   => 'HR',
  4      object_name     => 'EMPLOYEES',
  5      policy_name     => 'FGA_HIGH_SALARY',
  6      audit_column    => 'SALARY',
  7      audit_condition => 'SALARY > 200000');
  8  end;
  9  /
begin
*
ERROR at line 1:
ORA-28101: policy already exists
ORA-06512: at "SYS.DBMS_FGA", line 20
ORA-06512: at line 2

- 원인: 동일 객체에 같은 이름의 FGA 정책이 이미 존재한다.
- 수정: 기존 정책을 삭제한 뒤 다시 등록하거나, 그대로 사용한다. 여기서는 유지.

======================================================================
[4단계] 감사 대상 활동 발생 및 확인
======================================================================

- 조건(SALARY>100000)을 만족하는 고액 급여 행 조회.
SYS@cdb1> connect hr/Oracle_123@pdb1
Connected.
HR@cdb1> select employee_id, salary from employees where salary > 100000;

        101      17000

- 조건 미달 행만 조회하면 감사되지 않는다(정밀 감사).
HR@cdb1> select employee_id from employees where salary < 5000;

EMPLOYEE_ID
-----------
        132

- FGA 감사 레코드 확인 (통합 감사 추적에 함께 기록됨)
HR@cdb1> connect sys/Oracle_123@pdb1 as sysdba
Connected.
SYS@cdb1> select dbusername, action_name, object_name, fga_policy_name
  2  from   unified_audit_trail
  3  where  fga_policy_name = 'FGA_HIGH_SALARY'
  4  order  by event_timestamp desc
  5  fetch first 3 rows only;

DBUSERNAME  ACTION_NAME  OBJECT_NAME  FGA_POLICY_NAME
----------- ------------ ------------ ----------------
HR          SELECT       EMPLOYEES    FGA_HIGH_SALARY

- 관찰: 조건을 만족하는 고액 급여 조회만 감사되었다.

======================================================================
[정리]
======================================================================
- FGA 는 컬럼(audit_column)+조건(audit_condition)까지 내려간 정밀 감사다.
- 잘못된 컬럼은 ORA-28710, 동일 이름 재등록은 ORA-28101.
- 통합 감사가 켜진 환경에서 FGA 레코드도 UNIFIED_AUDIT_TRAIL 로 조회된다.
- 정리
SYS@cdb1> exec dbms_fga.disable_policy('HR','EMPLOYEES','FGA_HIGH_SALARY');

PL/SQL procedure successfully completed.

SYS@cdb1> exec dbms_fga.drop_policy('HR','EMPLOYEES','FGA_HIGH_SALARY');

PL/SQL procedure successfully completed.
