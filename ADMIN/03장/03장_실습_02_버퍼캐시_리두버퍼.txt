======================================================================
[1단계] 버퍼 캐시(기본 풀) 크기와 버퍼 풀 구성 확인
======================================================================

- 기본 버퍼 캐시 크기 확인 (ASMM에서 자동 배분되어 0으로 표시될 수 있음)
SYS@cdb1> show parameter db_cache_size

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
db_cache_size                        big integer 0

- 실제 각 버퍼 풀의 크기와 블록 크기 확인 (현재는 DEFAULT 풀만 존재)
SYS@cdb1> select name, block_size/1024 as kb, current_size as mb
  2  from v$buffer_pool where current_size > 0;

NAME                 KB         MB
-------------------- -- ----------
DEFAULT               8        640

======================================================================
[2단계] 버퍼 캐시 히트율 확인
======================================================================

- 논리적 읽기 대비 물리적 읽기로 히트율 계산 (히트율이 높을수록 디스크 I/O가 적음)
SYS@cdb1> select 1 - (phy.value / (cur.value + con.value)) as hit_ratio
  2  from v$sysstat cur, v$sysstat con, v$sysstat phy
  3  where cur.name = 'db block gets'
  4    and con.name = 'consistent gets'
  5    and phy.name = 'physical reads';

 HIT_RATIO
----------
    .96412

======================================================================
[3단계] 버퍼 캐시 어드바이저 — 캐시를 늘리면 물리 읽기가 얼마나 줄까
======================================================================

- (실수) size_factor 컬럼명을 오타(size_facter)로 입력
SYS@cdb1> select size_for_estimate as mb, size_facter,
  2         estd_physical_read_factor
  3  from v$db_cache_advice where name = 'DEFAULT' and block_size = 8192;
select size_for_estimate as mb, size_facter,
                                 *
ERROR at line 2:
ORA-00904: "SIZE_FACTER": invalid identifier

- 원인: 컬럼명 철자 오류. 올바른 이름은 SIZE_FACTOR
SYS@cdb1> select size_for_estimate as mb, size_factor,
  2         estd_physical_read_factor as rd_factor
  3  from v$db_cache_advice
  4  where name = 'DEFAULT' and block_size = 8192
  5    and size_factor in (0.5, 1, 1.5, 2);

        MB SIZE_FACTOR  RD_FACTOR
---------- ----------- ----------
       320        .500      1.418
       640       1.000      1.000
       960       1.500       .903
      1280       2.000       .871

- 해석: 캐시를 2배(1280MB)로 늘려도 물리 읽기는 약 13%만 감소 → 투자 대비 효과가 완만

======================================================================
[4단계] 리두 로그 버퍼 크기 확인
======================================================================

- 리두 로그 버퍼 크기 확인 (LOG_BUFFER는 정적 값)
SYS@cdb1> show parameter log_buffer

NAME                                 TYPE        VALUE
------------------------------------ ----------- --------
log_buffer                           big integer 7700480

- V$SGAINFO에서 Redo Buffers로도 확인 가능
SYS@cdb1> select name, round(bytes/1024/1024,2) as mb
  2  from v$sgainfo where name = 'Redo Buffers';

NAME                                     MB
-------------------------------- ----------
Redo Buffers                           7.34

======================================================================
[5단계] 리두 로그 버퍼 부족 여부 확인
======================================================================

- 리두 버퍼가 부족해 재시도한 횟수 (0이거나 매우 작아야 바람직)
SYS@cdb1> select name, value from v$sysstat
  2  where name = 'redo buffer allocation retries';

NAME                                  VALUE
------------------------------- -----------
redo buffer allocation retries            7

- 해석: 재시도 7회는 매우 적음 → 리두 로그 버퍼 크기는 충분한 상태

- [정리] 버퍼 캐시는 DB_CACHE_SIZE(자동/하한)와 V$BUFFER_POOL로, 리두 버퍼는 LOG_BUFFER(정적)로 관리
