- 목표치(TARGET)와 하드 리밋(LIMIT)을 함께 확인

======================================================================
[2단계] PGA 사용 통계 확인 (V$PGASTAT)
======================================================================

- 현재 할당량/최대치/디스크로 넘어간 작업 관련 통계
SYS@cdb1> select name, value from v$pgastat
  2  where name in ('aggregate PGA target parameter',
  3    'total PGA allocated','maximum PGA allocated',
  4    'over allocation count');

NAME                                     VALUE
------------------------------- --------------
aggregate PGA target parameter       536870912
total PGA allocated                  198443008
maximum PGA allocated                412536832
over allocation count                        0

- 해석: over allocation count=0 → PGA 목표치 초과 배분이 없었음(TARGET이 충분)

======================================================================
[3단계] 작업 영역이 메모리에서 완결된 비율 확인

- optimal(메모리 완결)/onepass/multipass 실행 수 → optimal 비율이 높아야 좋음
SYS@cdb1> select name, value from v$sysstat
  2  where name like 'workarea executions%';

======================================================================
[4단계] 프로세스별 PGA 사용량 상위 확인
======================================================================

- (실수) 컬럼명 pga_used를 잘못 입력 (실제 컬럼은 pga_used_mem)
SYS@cdb1> select pid, spid, pga_used from v$process
  2  where pga_used_mem > 0 order by pga_used_mem desc;
select pid, spid, pga_used from v$process
                  *
ERROR at line 1:
ORA-00904: "PGA_USED": invalid identifier

- 원인: 컬럼명 오류. 올바른 컬럼은 PGA_USED_MEM / PGA_ALLOC_MEM
SYS@cdb1> select pid, spid,
  2         round(pga_used_mem/1024/1024,1) as used_mb,
  3         round(pga_alloc_mem/1024/1024,1) as alloc_mb
  4  from v$process
  5  where pga_used_mem > 0 order by pga_used_mem desc fetch first 5 rows only;

       PID SPID          USED_MB   ALLOC_MB
---------- --------- ---------- ----------
        42 8123            18.4       22.7
        37 8090            11.2       14.0
        29 8041             6.8        9.1
        21 8002             3.1        4.4
        14 7960             2.0        3.2

======================================================================
[5단계] PGA 어드바이저 — 목표치를 바꾸면 히트율이 어떻게 될까
======================================================================

- PGA_AGGREGATE_TARGET을 여러 배수로 바꿀 때 예상 캐시 히트율
SYS@cdb1> select round(pga_target_for_estimate/1024/1024) as target_mb,
  2         pga_target_factor as factor,
  3         estd_pga_cache_hit_percentage as hit_pct
  4  from v$pga_target_advice
  5  where pga_target_factor in (0.5, 1, 2, 4);

 TARGET_MB     FACTOR    HIT_PCT
---------- ---------- ----------
       256        0.5         91
       512        1.0         97
      1024        2.0         99
      2048        4.0         99

- 해석: 512MB에서 이미 97%, 1024MB에서 99% → 이미 포화에 가까움. 더 늘려도 이득 미미

- [정리] PGA는 TARGET(목표)과 LIMIT(하드 리밋)으로 관리하며,
-   적정 TARGET은 V$PGA_TARGET_ADVICE로 근거를 잡는다.
