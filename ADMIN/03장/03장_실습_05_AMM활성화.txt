======================================================================
[2단계] AMM으로 전환하기 위한 파라미터 설정 (오류 → 수정)
======================================================================

- (실수) 정적 파라미터인 MEMORY_MAX_TARGET을 SCOPE 없이(메모리 즉시 변경) 설정 시도
SYS@cdb1> alter system set memory_max_target = 3G;
alter system set memory_max_target = 3G
*
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

- 원인: MEMORY_MAX_TARGET은 정적(static) 파라미터라 실행 중 즉시 변경 불가.
-   반드시 SCOPE=SPFILE로 지정한 뒤 재기동해야 함
SYS@cdb1> alter system set memory_max_target = 3G scope=spfile;

System altered.

- 상한을 먼저 잡았으니 목표(MEMORY_TARGET)를 상한 이하로 지정
SYS@cdb1> alter system set memory_target = 2G scope=spfile;

System altered.

- AMM에서는 개별 SGA_TARGET/PGA_AGGREGATE_TARGET을 0(또는 하한)으로
SYS@cdb1> alter system set sga_target = 0 scope=spfile;

System altered.

SYS@cdb1> alter system set pga_aggregate_target = 0 scope=spfile;

System altered.

======================================================================
[5단계] AMM이 SGA/PGA를 하나로 관리하는지 컴포넌트로 확인
======================================================================

- SGA Target/PGA Target이 AMM 관리 하에 자동 값으로 잡혀 있음
SYS@cdb1> select component, round(current_size/1024/1024) as mb
  2  from v$memory_dynamic_components
  3  where component in ('SGA Target','PGA Target');

COMPONENT                    MB
-------------------- ----------
SGA Target                 1408
PGA Target                  640

- [정리] MEMORY_TARGET(목표)+MEMORY_MAX_TARGET(상한)으로 AMM 활성화.
-   MEMORY_MAX_TARGET은 정적이라 변경 시 재기동 필요. 모니터링은 실습_06에서.
