- 프롬프트를 사용자@인스턴스 형태로 지정 (실습 환경 glogin.sql 설정)
SQL> set sqlprompt "_user'@'_connect_identifier> "
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 세 선택적 풀의 크기를 한 번에 확인 (V$SGAINFO)
======================================================================

- 라지/자바/스트림 풀의 현재 크기 (스트림 풀 0 = 복제 기능 미사용)
SYS@cdb1> select name, round(bytes/1024/1024,1) as mb, resizeable
  2  from v$sgainfo
  3  where name in ('Large Pool Size','Java Pool Size','Streams Pool Size')
  4  order by name;

NAME                                     MB RES
-------------------------------- ---------- ---
Java Pool Size                           16 Yes
Large Pool Size                          32 Yes
Streams Pool Size                         0 Yes

======================================================================
[2단계] 파라미터 값으로도 확인 (0 = 자동 배분/미사용)
======================================================================

- 세 풀의 파라미터 값 확인
SYS@cdb1> show parameter pool_size

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
java_pool_size                       big integer 0
large_pool_size                      big integer 0
shared_pool_size                     big integer 0
streams_pool_size                    big integer 0

- 해석: 모두 0 → ASMM이 워크로드에 맞춰 자동 배분 중. V$SGAINFO의 실제 값이 현재 배분 결과

======================================================================
[3단계] 라지 풀 사용 항목 확인 (V$SGASTAT)
======================================================================

- 라지 풀 내부 항목 (free memory 위주면 아직 대용량 작업이 없었다는 뜻)
SYS@cdb1> select name, round(bytes/1024/1024,2) as mb
  2  from v$sgastat where pool = 'large pool' order by bytes desc;

NAME                        MB
------------------- ----------
free memory              30.02
PX msg pool               1.98

======================================================================
[4단계] 스트림 풀을 수동으로 조금 할당해 보기 (오류 → 수정)
======================================================================

- (실수) 단위 없이 숫자만 입력하면 바이트로 해석되어 너무 작은 값이 됨
SYS@cdb1> alter system set streams_pool_size = 16;
alter system set streams_pool_size = 16
*
ERROR at line 1:
ORA-02097: parameter cannot be modified because specified value is invalid
ORA-00093: streams_pool_size must be between 0 and ...

- 원인: 16(바이트)은 그래뉼 최소 단위보다 작아 유효하지 않음. 단위(M)를 붙여 재시도
SYS@cdb1> alter system set streams_pool_size = 16M scope=both;

System altered.

- 스트림 풀이 16MB로 잡혔는지 확인
SYS@cdb1> select round(bytes/1024/1024,1) as mb
  2  from v$sgainfo where name = 'Streams Pool Size';

        MB
----------
        16

- 실습 후 원상 복구 (자동 배분으로 되돌림)
SYS@cdb1> alter system set streams_pool_size = 0 scope=both;

System altered.

======================================================================
[5단계] 자바 풀 사용 현황 확인
======================================================================

- 자바 풀 항목 (DB 내부 Java 미사용 환경이면 free memory 위주)
SYS@cdb1> select name, round(bytes/1024/1024,2) as mb
  2  from v$sgastat where pool = 'java pool' order by bytes desc;

NAME                        MB
------------------- ----------
free memory              15.62
JOXLE                     0.31

- [정리] 라지/자바/스트림 풀은 선택적 영역. 해당 기능을 쓸 때만 의미가 있으며,
-   ASMM/AMM에 맡기면 워크로드 요구 시 Oracle이 자동으로 배분한다.
