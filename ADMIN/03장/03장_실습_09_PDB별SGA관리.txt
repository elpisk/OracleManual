-- 3장 실습_09: PDB별 SGA 사용량 관리 실습
-- 목표: 공유 SGA에서 특정 PDB의 SGA 사용을 SGA_TARGET/SGA_MIN_SIZE로 제한
-- 전제: CDB는 ASMM 상태(실습_07). AMM이면 PDB SGA_TARGET 설정 불가

- 프롬프트를 사용자@인스턴스 형태로 지정 (실습 환경 glogin.sql 설정)
SQL> set sqlprompt "_user'@'_connect_identifier> "
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] CDB 전체 SGA와 PDB 목록 확인 (SGA는 CDB가 공유)
======================================================================

- CDB의 SGA_TARGET 확인
SYS@cdb1> show parameter sga_target

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
sga_target                           big integer 2G

- PDB 목록 확인 (각 PDB는 별도 SGA를 갖지 않고 CDB의 SGA를 공유)
SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 SALESPDB                       READ WRITE
         4 HRPDB                          READ WRITE

======================================================================
[2단계] 특정 PDB(salespdb)로 이동해 SGA 사용 제한 설정 (오류 → 수정)
======================================================================

SYS@cdb1> alter session set container = salespdb;

Session altered.

- (실수) SGA_MIN_SIZE를 SGA_TARGET보다 크게 설정 시도 (하한이 상한보다 클 수 없음)
SALES@cdb1> alter system set sga_min_size = 1200M scope=both;
alter system set sga_min_size = 1200M
*
ERROR at line 1:
ORA-32017: failure in updating SPFILE
ORA-56746: invalid value 1200M for parameter sga_min_size; must be smaller than or equal to sga_target

- 원인: SGA_MIN_SIZE(보장 하한)는 그 PDB의 SGA_TARGET 이하여야 함
-   먼저 PDB의 SGA_TARGET(상한)을 설정한 뒤 그보다 작은 하한을 지정
SALES@cdb1> alter system set sga_target = 900M scope=both;

System altered.

SALES@cdb1> alter system set sga_min_size = 300M scope=both;

System altered.

======================================================================
[3단계] PDB의 개별 풀 상한도 지정 가능
======================================================================

- 이 PDB가 쓸 수 있는 버퍼 캐시 상한 지정
SALES@cdb1> alter system set db_cache_size = 500M scope=both;

System altered.

- 설정 확인 (PDB 컨텍스트에서 조회)
SALES@cdb1> show parameter sga_target

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
sga_target                           big integer 900M

======================================================================
[4단계] 루트로 돌아가 컨테이너별 SGA 파라미터 비교
======================================================================

SALES@cdb1> alter session set container = cdb$root;

Session altered.

- CON_ID별로 설정된 SGA 파라미터 확인 (0=미설정, PDB는 CON_ID로 구분)
SYS@cdb1> select con_id, name, value
  2  from v$system_parameter
  3  where name in ('sga_target','sga_min_size')
  4    and con_id in (0,3,4) order by con_id, name;

    CON_ID NAME             VALUE
---------- ---------------- ----------
         0 sga_min_size     0
         0 sga_target       2147483648
         3 sga_min_size     314572800
         3 sga_target       943718400
         4 sga_min_size     0
         4 sga_target       0

- 해석: CON_ID 3(salespdb)만 제한이 걸려 있고, CON_ID 4(hrpdb)는 미설정(CDB 공유분을 그대로 사용)

======================================================================
[5단계] 핵심 개념 확인
======================================================================

- PDB별 파라미터는 공유 SGA에서의 '몫'을 제한하는 울타리일 뿐, 독립 SGA 생성이 아님
SYS@cdb1> select 'SGA는 CDB가 공유, PDB별 값은 공유분의 상/하한' as concept from dual;

CONCEPT
-------------------------------------------------
SGA는 CDB가 공유, PDB별 값은 공유분의 상/하한

- [정리] PDB SGA_TARGET(상한)/SGA_MIN_SIZE(하한)로 PDB의 SGA 사용을 제한한다.
-   CDB가 ASMM/수동일 때만 가능하며, SGA 자체는 여전히 CDB가 공유한다.
