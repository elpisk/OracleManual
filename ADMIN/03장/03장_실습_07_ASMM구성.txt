======================================================================
[2단계] AMM을 끄고 ASMM으로 전환 (오류 → 수정)
======================================================================

- (실수) memory_target을 그대로 둔 채 sga_target을 설정하려 함
SYS@cdb1> alter system set sga_target = 2G scope=both;
alter system set sga_target = 2G scope=both
*
ERROR at line 1:
ORA-02097: parameter cannot be modified because specified value is invalid
ORA-00830: cannot set sga_target when memory_target is set (AMM 활성 상태)

- 원인: AMM(memory_target>0)이 켜져 있으면 SGA_TARGET을 자유롭게 설정할 수 없음
-   먼저 memory_target을 0으로 내려 AMM을 꺼야 함
SYS@cdb1> alter system set memory_target = 0 scope=spfile;

System altered.

- SGA 상한과 목표, PGA 목표를 SPFILE에 설정
SYS@cdb1> alter system set sga_max_size = 3G scope=spfile;

System altered.

SYS@cdb1> alter system set sga_target = 2G scope=spfile;

System altered.

SYS@cdb1> alter system set pga_aggregate_target = 700M scope=spfile;

System altered.

- 개별 풀은 0(자동) → V$SGAINFO의 실제 값이 MMAN의 배분 결과
SYS@cdb1> select component,
  2         round(current_size/1024/1024) as mb, last_oper_type
  3  from v$sga_dynamic_components
  4  where current_size > 0 order by current_size desc;

- [정리] AMM을 끄려면 memory_target=0 → sga_target 설정. ASMM은 SGA 내부만 MMAN이 자동 조정.
-   PGA는 pga_aggregate_target으로 별도 관리. HugePages 병용이 가능해 큰 SGA 운영에 적합.
