-- 10장 실습_03: Directory Naming(LDAP) 개념 확인
--   목표: 네이밍 방법 우선순위(NAMES.DIRECTORY_PATH)를 확인/설정하고,
--         디렉터리 네이밍(LDAP)의 개념과 로컬 네이밍과의 차이를 정리한다.
--   주의: 실제 LDAP 서버(OID/AD) 구축은 범위 밖. 여기서는 클라이언트 측 설정과 개념 확인에 집중.

======================================================================
[1단계] 현재 sqlnet.ora의 네이밍 방법 우선순위 확인
======================================================================

[oracle@dbsvr ~]$ export TNS_ADMIN=/u01/app/oracle/net_config
[oracle@dbsvr ~]$ cat $TNS_ADMIN/sqlnet.ora 2>/dev/null
# (파일이 없거나 비어 있을 수 있음)

- sqlnet.ora가 없으면 기본 우선순위가 적용된다(대개 TNSNAMES, EZCONNECT 순).
-   백업 후 명시적으로 우선순위를 지정해 본다
[oracle@dbsvr ~]$ cp $TNS_ADMIN/sqlnet.ora $TNS_ADMIN/sqlnet.ora.bak 2>/dev/null; echo done
done

======================================================================
[2단계] (실수) NAMES.DIRECTORY_PATH 철자 오류로 설정
======================================================================

- (실수) 파라미터 이름을 NAMES.DIRECTORY_PACH 로 잘못 입력
[oracle@dbsvr ~]$ cat > $TNS_ADMIN/sqlnet.ora <<'EOF'
NAMES.DIRECTORY_PACH = (TNSNAMES, LDAP, EZCONNECT)
NAMES.DEFAULT_DOMAIN = us.oracle.com
EOF

- 별칭 sales로 tnsping을 시도해 어떤 adapter가 쓰이는지 확인
[oracle@dbsvr ~]$ tnsping sales

TNS Ping Utility for Linux: Version 19.0.0.0.0 - Production

Used parameter files:
/u01/app/oracle/net_config/sqlnet.ora
Used TNSNAMES adapter to resolve the alias
Attempting to contact (DESCRIPTION = (ADDRESS = (PROTOCOL = TCP)(HOST =
dbsvr.us.oracle.com)(PORT = 1521)) (CONNECT_DATA = (SERVER = DEDICATED)
(SERVICE_NAME = salespdb.us.oracle.com)))
OK (0 msec)

- 원인: NAMES.DIRECTORY_PACH 는 오타라 무시되고 기본 우선순위(TNSNAMES 우선)로 동작한 것.
-   의도한 우선순위 지정이 반영되지 않았다. 올바른 파라미터명 NAMES.DIRECTORY_PATH 로 수정.
[oracle@dbsvr ~]$ cat > $TNS_ADMIN/sqlnet.ora <<'EOF'
# 네이밍 방법 시도 순서: 로컬(tnsnames) -> 디렉터리(LDAP) -> Easy Connect
NAMES.DIRECTORY_PATH = (TNSNAMES, LDAP, EZCONNECT)
NAMES.DEFAULT_DOMAIN = us.oracle.com
EOF

======================================================================
[3단계] 수정된 우선순위 확인
======================================================================

[oracle@dbsvr ~]$ cat $TNS_ADMIN/sqlnet.ora
# 네이밍 방법 시도 순서: 로컬(tnsnames) -> 디렉터리(LDAP) -> Easy Connect
NAMES.DIRECTORY_PATH = (TNSNAMES, LDAP, EZCONNECT)
NAMES.DEFAULT_DOMAIN = us.oracle.com

- 로컬(tnsnames)에 sales가 있으므로 여전히 TNSNAMES adapter로 먼저 해석됨
[oracle@dbsvr ~]$ tnsping sales | grep -E "adapter|OK"
Used TNSNAMES adapter to resolve the alias
OK (0 msec)

- 만약 tnsnames.ora에 없는 별칭이라면 다음 순서인 LDAP(디렉터리 네이밍)를 시도하게 된다
-   (LDAP 서버가 구성되어 있지 않으면 그 다음 EZCONNECT를 시도)
[oracle@dbsvr ~]$ tnsping onlyInLdapAlias | grep -E "adapter|TNS-|OK"
TNS-03505: Failed to resolve name

- 위 결과는 이 실습 환경에 LDAP 서버가 없어 최종적으로 이름을 해석하지 못한 것.
-   실제 환경에서 OID/Active Directory가 구성되어 있으면 LDAP adapter로 해석되어 접속된다.

======================================================================
[4단계] 디렉터리 네이밍 개념 정리 (LDAP)
======================================================================

- 디렉터리 네이밍의 요구/동작을 SQL*Plus 접속 없이 개념적으로 정리한다.
[oracle@dbsvr ~]$ cat <<'NOTE'
[디렉터리 네이밍(Directory Naming) 개념 정리]
1) 저장 위치: 연결 식별자를 클라이언트 로컬 파일이 아니라
   중앙집중식 LDAP 호환 디렉터리 서버에 저장한다.
   - 지원 디렉터리: Oracle Internet Directory(OID), Microsoft Active Directory Services
2) 동작: 사용자가 별칭 제공 -> 알려진 서비스의 '외부' 목록(중앙 LDAP)과 대조
         -> 일치 시 호스트/프로토콜/포트/서비스 이름으로 변환
   - 로컬 네이밍과의 유일한 실질 차이 = 목록이 로컬 파일이 아니라 외부(중앙)에 있다는 점
3) 이점: 구성이 자주 변경되는 대규모 조직에 적합.
         서버 주소/서비스가 바뀌어도 중앙 디렉터리 한 번만 갱신하면 모든 클라이언트가 즉시 반영.
         (로컬 네이밍처럼 수백 대 tnsnames.ora를 배포/갱신할 필요 없음)
4) 지원: 모든 Oracle Net 프로토콜 + 고급 옵션(페일오버/로드밸런싱). 사용자 경험은 로컬 네이밍과 동일.
5) 활성화: sqlnet.ora의 NAMES.DIRECTORY_PATH에 LDAP을 포함하고, ldap.ora로 디렉터리 접속 정보를 지정.
NOTE
[디렉터리 네이밍(Directory Naming) 개념 정리]
1) 저장 위치: 연결 식별자를 클라이언트 로컬 파일이 아니라
   중앙집중식 LDAP 호환 디렉터리 서버에 저장한다.
   - 지원 디렉터리: Oracle Internet Directory(OID), Microsoft Active Directory Services
2) 동작: 사용자가 별칭 제공 -> 알려진 서비스의 '외부' 목록(중앙 LDAP)과 대조
         -> 일치 시 호스트/프로토콜/포트/서비스 이름으로 변환
   - 로컬 네이밍과의 유일한 실질 차이 = 목록이 로컬 파일이 아니라 외부(중앙)에 있다는 점
3) 이점: 구성이 자주 변경되는 대규모 조직에 적합.
         서버 주소/서비스가 바뀌어도 중앙 디렉터리 한 번만 갱신하면 모든 클라이언트가 즉시 반영.
         (로컬 네이밍처럼 수백 대 tnsnames.ora를 배포/갱신할 필요 없음)
4) 지원: 모든 Oracle Net 프로토콜 + 고급 옵션(페일오버/로드밸런싱). 사용자 경험은 로컬 네이밍과 동일.
5) 활성화: sqlnet.ora의 NAMES.DIRECTORY_PATH에 LDAP을 포함하고, ldap.ora로 디렉터리 접속 정보를 지정.

- [정리]
-   NAMES.DIRECTORY_PATH가 네이밍 방법의 시도 순서(폴백)를 정한다.
-   파라미터명 철자 오류는 조용히 무시되어 기본값으로 동작하므로, 반드시 tnsping의 adapter 표시로 검증.
-   로컬 vs 디렉터리 = 저장 위치(로컬 파일 vs 중앙 LDAP)만 다르고 사용자 경험/기능은 동일.
[oracle@dbsvr ~]$
