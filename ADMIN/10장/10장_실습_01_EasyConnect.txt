-- 10장 실습_01: Easy Connect 네이밍으로 접속 실습
--   목표: 클라이언트 구성 파일 없이 host[:port]/service 형식으로 접속하고,
--         포트/서비스 이름 생략 규칙과 오류(ORA-12514) 상황을 확인한다.

- 먼저 서버에서 대상 데이터베이스의 서비스 이름 관련 파라미터를 확인 (SYSDBA 로컬 접속)
[oracle@dbsvr ~]$ sqlplus / as sysdba

- 프롬프트를 사용자@인스턴스 형태로 지정 (실습 환경 glogin.sql 설정)
SQL> set sqlprompt "_user'@'_connect_identifier> "
SYS@cdb1> show con_name

------------------------------
CDB$ROOT

[1단계] 접속에 필요한 정보 확인: 호스트 / 포트 / 프로토콜 / 서비스 이름
======================================================================

- 데이터베이스가 광고하는 서비스 이름 확인 (SERVICE_NAMES = DB_NAME + DB_DOMAIN)
SYS@cdb1> show parameter service_names

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------
service_names                        string      cdb1.us.oracle.com

- DB_NAME / DB_DOMAIN 개별 확인 (전역 데이터베이스 이름 = DB_NAME.DB_DOMAIN)
SYS@cdb1> show parameter db_name
NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
db_name                              string      cdb1

SYS@cdb1> show parameter db_domain
NAME                                 TYPE        VALUE
------------------------------------ ----------- --------------
db_domain                            string      us.oracle.com

- 리스너가 어느 호스트/포트/프로토콜에서 대기하며 어떤 서비스를 등록했는지 확인
SYS@cdb1> host lsnrctl status | grep -E "Listening|Service|Instance"
Listening Endpoints Summary...
  (DESCRIPTION=(ADDRESS=(PROTOCOL=tcp)(HOST=dbsvr.us.oracle.com)(PORT=1521)))

Service "salespdb.us.oracle.com" has 1 instance(s).
  Instance "cdb1", status READY, has 1 handler(s) for this service...

- 정리: 호스트=dbsvr.us.oracle.com, 포트=1521, 프로토콜=TCP, 서비스=cdb1.us.oracle.com / salespdb.us.oracle.com

======================================================================

- Easy Connect는 클라이언트 구성 파일(tnsnames.ora) 없이 문자열만으로 접속한다
[oracle@dbsvr ~]$ sqlplus system@dbsvr.us.oracle.com:1521/salespdb.us.oracle.com

SQL*Plus: Release 19.0.0.0.0 - Production on Wed Jul 22 10:07:44 2026
Enter password:
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SYSTEM@dbsvr.us.oracle.com:1521/salespdb.us.oracle.com> show con_name

CON_NAME
------------------------------
SALESPDB

- 실제로 어떤 서비스로 접속되었는지 확인
SYSTEM@...salespdb.us.oracle.com> select sys_context('USERENV','SERVICE_NAME') svc from dual;

SVC
------------------------------
salespdb.us.oracle.com

======================================================================
[3단계] (실수) 잘못된 서비스 이름으로 접속 시도 -> ORA-12514
======================================================================

SYSTEM@...salespdb.us.oracle.com> exit

- (실수) 서비스 이름을 salespdb 로 잘못 입력 (도메인 누락 + 등록되지 않은 이름)
[oracle@dbsvr ~]$ sqlplus system@dbsvr.us.oracle.com:1521/salespbd
Enter password:
ERROR:
ORA-12514: TNS:listener does not currently know of service requested in
connect descriptor

- 원인: 리스너는 살아 있으나(TNS-12541 아님) 요청한 서비스 이름 salespbd 가 등록되어 있지 않음(오타)
-   리스너에 실제 등록된 서비스 이름을 다시 확인
[oracle@dbsvr ~]$ lsnrctl status | grep "Service \""
Service "cdb1.us.oracle.com" has 1 instance(s).
Service "salespdb.us.oracle.com" has 1 instance(s).

- 올바른 서비스 이름(salespdb.us.oracle.com)으로 재접속 -> 성공
[oracle@dbsvr ~]$ sqlplus system@dbsvr.us.oracle.com:1521/salespdb.us.oracle.com
Enter password:
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SYSTEM@...salespdb.us.oracle.com> select 'connected' as status from dual;

STATUS
---------
connected

======================================================================
[4단계] 단축 형식 확인: 포트 생략(->1521), 서비스 생략(->호스트명과 동일 가정)
======================================================================

SYSTEM@...salespdb.us.oracle.com> exit

- CDB 루트의 서비스 이름(cdb1.us.oracle.com)이 호스트명과 다를 경우, 서비스 생략 접속은 실패할 수 있다
-   (실수) 서비스 생략 시 '호스트명 = 서비스명' 가정이 성립하지 않는 경우
[oracle@dbsvr ~]$ sqlplus system@dbsvr.us.oracle.com
Enter password:
ERROR:
ORA-12514: TNS:listener does not currently know of service requested in
connect descriptor

- 원인: 서비스 이름 생략 시 Oracle Net은 '서비스명 = 호스트명(dbsvr.us.oracle.com)'으로 가정하는데,
-   실제 등록된 서비스는 cdb1.us.oracle.com 이라 이름이 일치하지 않아 실패.
-   단축이 성립하려면 서비스 이름과 호스트 이름이 동일해야 한다. 서비스 이름을 명시해 접속.
[oracle@dbsvr ~]$ sqlplus system@dbsvr.us.oracle.com:1521/cdb1.us.oracle.com
Enter password:
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SYSTEM@dbsvr.us.oracle.com:1521/cdb1.us.oracle.com> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 참고: 포트 생략은 1521이 기본이라 대개 성립한다. 아래는 포트만 생략(서비스는 명시)
SYSTEM@...cdb1.us.oracle.com> host sqlplus -s system/oracle@dbsvr.us.oracle.com/cdb1.us.oracle.com <<< "select 1 from dual;"

         1
----------
         1

- [정리]
-   Easy Connect = 클라이언트 구성 파일 불필요, TCP/IP만, 형식은 host[:port][/service_name]
-   포트 생략 -> 1521 가정 / 서비스 생략 -> 호스트명과 동일 서비스 가정(조건 맞을 때만 성립)
-   ORA-12514 = 리스너는 살아 있으나 요청 서비스 미등록/오타 -> lsnrctl status로 서비스명 확인
