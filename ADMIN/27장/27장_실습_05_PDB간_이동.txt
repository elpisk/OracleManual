================================================================================
 27장 실습 05 — PDB 간 데이터 내보내기/가져오기
 목표: pdb1의 HR.EMPLOYEES 를 pdb2로 이동(같은 CDB 내 두 PDB)
 환경: CDB=cdb1, 원본 PDB=pdb1, 대상 PDB=pdb2
================================================================================

-- [1] 두 PDB에서 같은 물리 경로를 가리키는 디렉터리 객체를 각각 만든다.
$ sqlplus sys@pdb1 as sysdba
SYS@pdb1> CREATE DIRECTORY shared_dir AS '/u01/app/oracle/shared';
Directory created.
SYS@pdb1> GRANT READ, WRITE ON DIRECTORY shared_dir TO system;
Grant succeeded.
SYS@pdb1> EXIT

$ sqlplus sys@pdb2 as sysdba
SYS@pdb2> CREATE DIRECTORY shared_dir AS '/u01/app/oracle/shared';
Directory created.
SYS@pdb2> GRANT READ, WRITE ON DIRECTORY shared_dir TO system;
Grant succeeded.
SYS@pdb2> EXIT

$ mkdir -p /u01/app/oracle/shared

--------------------------------------------------------------------------------
-- [2] 원본 PDB1에서 특정 테이블만 내보내기 (TABLES 모드)
--------------------------------------------------------------------------------
$ expdp system@pdb1 TABLES=hr.employees DIRECTORY=shared_dir \
        DUMPFILE=emp_p1.dmp LOGFILE=emp_p1_exp.log

Export: Release 19.0.0.0.0 - Production on Wed Aug 5 14:20:07 2026
Connected to: Oracle Database 19c Enterprise Edition Release 19.0.0.0.0
. . exported "HR"."EMPLOYEES"          17.08 KB     107 rows
Job "SYSTEM"."SYS_EXPORT_TABLE_01" successfully completed ...

--------------------------------------------------------------------------------
-- [3] 첫 시도: 대상 PDB2로 가져오기 → 대상 스키마 HR 없음
--------------------------------------------------------------------------------
$ impdp system@pdb2 TABLES=hr.employees DIRECTORY=shared_dir \
        DUMPFILE=emp_p1.dmp LOGFILE=emp_p2_imp.log

Import: Release 19.0.0.0.0 - Production on Wed Aug 5 14:25:33 2026
Connected to: Oracle Database 19c Enterprise Edition Release 19.0.0.0.0
Processing object type TABLE_EXPORT/TABLE/TABLE
ORA-39083: Object type TABLE:"HR"."EMPLOYEES" failed to create with error:
ORA-01918: user 'HR' does not exist

-- 원인 파악:
--   PDB2 에는 HR 스키마가 존재하지 않는다. TABLES 모드는 대상 소유자가
--   미리 있어야 하며, 없으면 REMAP_SCHEMA로 기존 사용자에게 매핑해야 한다.

--------------------------------------------------------------------------------
-- [4] 수정: PDB2에 대상 스키마 생성 후 재실행 (또는 REMAP_SCHEMA)
--------------------------------------------------------------------------------
$ sqlplus system@pdb2
SYSTEM@pdb2> CREATE USER hr IDENTIFIED BY oracle
  2          DEFAULT TABLESPACE users QUOTA UNLIMITED ON users;
User created.
SYSTEM@pdb2> GRANT CREATE SESSION, CREATE TABLE TO hr;
Grant succeeded.
SYSTEM@pdb2> EXIT

$ impdp system@pdb2 TABLES=hr.employees DIRECTORY=shared_dir \
        DUMPFILE=emp_p1.dmp LOGFILE=emp_p2_imp2.log \
        TABLE_EXISTS_ACTION=REPLACE

Connected to: Oracle Database 19c Enterprise Edition Release 19.0.0.0.0
Processing object type TABLE_EXPORT/TABLE/TABLE
. . imported "HR"."EMPLOYEES"          17.08 KB     107 rows
Job "SYSTEM"."SYS_IMPORT_TABLE_01" successfully completed ...

--------------------------------------------------------------------------------
-- [5] 검증
--------------------------------------------------------------------------------
$ sqlplus hr@pdb2
HR@pdb2> SELECT COUNT(*) FROM employees;
  COUNT(*)
----------
       107

-- 참고: 덤프파일 없이 옮기려면 대상 PDB2에 PDB1을 가리키는 DB 링크를 만들고
--       impdp ... NETWORK_LINK=... 를 사용하면 된다(실습 07 참조).

-- 결론:
--   1) PDB 간 이동도 '원본 내보내기 → 대상 가져오기' 패턴으로 동일하다.
--   2) 같은 서버의 두 PDB는 하나의 공유 경로를 각각 디렉터리 객체로 매핑한다.
--   3) TABLES 모드는 대상 소유자가 있어야 하며 없으면 REMAP_SCHEMA로 매핑한다.
