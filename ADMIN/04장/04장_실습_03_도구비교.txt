-- 4장 실습_03: Oracle 데이터베이스 도구(SQL*Plus/SQL Developer/DBCA/EM Express) 비교 확인
-- 목표: 각 도구가 무엇을 할 수 있는지 데이터 딕셔너리/포트/서비스로 확인하고,
--       '도구별로 되는 것과 안 되는 것'의 경계를 실증한다.
--       EM Express 포트 조회/전역 포트 설정, 잘못된 상태 변경 시도의 오류를 재현/수정.

======================================================================
[1단계] SQL*Plus - 인스턴스 제어(다른 GUI로는 불가한 영역) 확인
======================================================================

- OS 인증으로 루트에 접속
[oracle@dbsvr ~]$ sqlplus / as sysdba

Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SQL> set sqlprompt "_user'@'_connect_identifier> "

- SQL*Plus는 관리 권한(SYSDBA)으로 인스턴스 상태를 제어할 수 있음
-   현재 데이터베이스 로그 모드와 오픈 상태 확인
SYS@cdb1> select name, open_mode, log_mode, cdb from v$database;

NAME      OPEN_MODE            LOG_MODE     CDB
--------- -------------------- ------------ ---
CDB1      READ WRITE           NOARCHIVELOG YES

- 이 도구가 사용하는 클라이언트 프로그램 이름 확인(세션의 PROGRAM 컬럼)
SYS@cdb1> select program from v$session where sid = sys_context('USERENV','SID');

PROGRAM
------------------------------------------------
sqlplus@dbsvr (TNS V1-V3)

======================================================================
[2단계] EM Express - 포트 조회와 전역 포트 설정(브라우저 관리 도구)
======================================================================

- EM Express가 사용하는 HTTPS 포트 확인
SYS@cdb1> select dbms_xdb_config.gethttpsport() as https_port from dual;

HTTPS_PORT
----------
      5500

- (실수) 전역 포트 활성화 프로시저 이름을 잘못 입력(setglobalport - 존재하지 않음)
SYS@cdb1> exec dbms_xdb_config.setglobalport(true);
BEGIN dbms_xdb_config.setglobalport(true); END;

      *
ERROR at line 1:
ORA-06550: line 1, column 7:
PLS-00302: component 'SETGLOBALPORT' must be declared

- 원인: 올바른 프로시저명은 SETGLOBALPORTENABLED 이다. 정확한 이름으로 재실행.
SYS@cdb1> exec dbms_xdb_config.setglobalportenabled(true);

PL/SQL procedure successfully completed.

- 전역 포트가 활성화되면 단일 포트(5500)로 CDB와 모든 PDB의 EM Express에 접근 가능
-   브라우저 접속 URL 예: https://dbsvr:5500/em
SYS@cdb1> select dbms_xdb_config.isglobalportenabled() as global_enabled from dual;

GLOBAL_ENABLED
--------------
             1

======================================================================
[3단계] EM Express의 제약 실증 - DB가 열려 있어야만 동작
======================================================================

- EM Express는 데이터베이스 안에서 서비스되므로 'DB가 닫히는 상태 변경'은 불가.
-   예: ARCHIVELOG 모드 전환은 DB를 MOUNT로 내렸다 올려야 하므로 EM Express로 못 함.
-   이 작업은 SQL*Plus SYSDBA로만 가능함을 직접 확인한다.

- (실수) DB가 OPEN인 상태에서 바로 ARCHIVELOG 모드로 변경 시도
SYS@cdb1> alter database archivelog;
alter database archivelog
*
ERROR at line 1:
ORA-01126: database must be mounted in this instance and not open in any
instance

- 원인: ARCHIVELOG 전환은 MOUNT 상태에서만 가능. 정상 종료 후 MOUNT로 재기동.
SYS@cdb1> shutdown immediate
Database closed.
Database dismounted.
ORACLE instance shut down.

SYS@cdb1> startup mount
ORACLE instance started.

Total System Global Area 2046827888 bytes
Fixed Size                  9145712 bytes
Variable Size            1358954496 bytes
Database Buffers          671088640 bytes
Redo Buffers                7639040 bytes
Database mounted.

- MOUNT 상태에서 ARCHIVELOG 모드로 전환 후 DB 오픈
SYS@cdb1> alter database archivelog;

Database altered.

SYS@cdb1> alter database open;

Database altered.

- 로그 모드가 ARCHIVELOG로 바뀐 것을 확인
-   (핵심) 이 과정 전체는 DB가 닫힌 구간을 포함하므로 EM Express로는 수행 불가,
-   SQL*Plus의 SYSDBA 접속만이 처리할 수 있다.
SYS@cdb1> select log_mode from v$database;

LOG_MODE
------------
ARCHIVELOG

======================================================================
[4단계] SQL Developer / DBCA - 접속 방식과 실행 위치 비교
======================================================================

- SQL Developer는 원격 클라이언트에서 JDBC로 접속하는 GUI 도구.
-   리스너에 등록된 서비스로 접속하므로, 등록 서비스 목록을 확인해 둔다.
[oracle@dbsvr ~]$ lsnrctl status | grep -i "Service \""
Service "cdb1" has 1 instance(s).
Service "hrpdb" has 1 instance(s).
Service "salespdb" has 1 instance(s).

- SQL Developer 연결(Basic) 예시 값:
-   Hostname=dbsvr / Port=1521 / Service name=hrpdb / Username=hr
-   DBA 작업을 하려면 View > DBA 로 DBA 내비게이터를 열고, DBA 권한 계정으로 연결해야 함.

- DBCA는 원격 GUI가 아니라 'CDB가 있는 서버의 OS'에서 실행하는 도구.
-   설치된 데이터베이스 소프트웨어(ORACLE_HOME) 위치와 함께 확인
[oracle@dbsvr ~]$ echo $ORACLE_HOME
/u01/app/oracle/product/19.3.0/dbhome_1

- DBCA 실행 파일이 $ORACLE_HOME/bin 에 있음을 확인 (sqlplus/lsnrctl 등과 같은 위치)
[oracle@dbsvr ~]$ ls $ORACLE_HOME/bin | grep -E "^(dbca|sqlplus|sql|lsnrctl|adrci)$"
adrci
dbca
lsnrctl
sqlplus

- DBCA 사일런트 모드는 화면 없이 데이터베이스를 생성/삭제할 수 있음(도움말로 옵션 확인)
[oracle@dbsvr ~]$ dbca -silent -help 2>&1 | head -5
-createDatabase - Command to Create a database.
-deleteDatabase - Command to Delete a database.
-configureDatabase - Command to Configure a database.
-createTemplateFromDB - Command to Create a template.
-createCloneTemplate - Command to Create a clone template.

======================================================================
[5단계] 도구별 역할 정리(실증 결과)
======================================================================

- 확인 결과를 표로 정리:
-   SQL*Plus        : 커맨드라인, SYSDBA 인스턴스 제어(STARTUP/SHUTDOWN/ARCHIVELOG) 가능
-                     -> 닫힌 DB 작업까지 유일하게 처리, 자동화의 기반
-   SQL Developer   : 원격 GUI(JDBC), 개발+DBA 내비게이터로 관리, 화면은 계정 권한을 반영
-   DBCA            : 서버 OS에서 실행, CDB/PDB 생성/삭제(대화형/사일런트)
-   EM Express      : 브라우저(HTTPS 5500), 열린 DB 하나 모니터링/관리
-                     -> 인스턴스 시작이나 ARCHIVELOG 전환 같은 상태 변경은 불가
SYS@cdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
