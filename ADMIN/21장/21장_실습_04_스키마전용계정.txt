-- 21장 실습_04: 스키마 전용 계정(Schema Only Account) 생성 실습

- salespdb 로 접속하여 현재 컨테이너 확인
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@salespdb> show con_name

CON_NAME
------------------------------
SALESPDB

======================================================================
[1단계] 스키마 전용 계정 생성 (NO AUTHENTICATION)
======================================================================

- 인증 수단 없이 객체만 소유하는 계정 생성
SYS@salespdb> create user app_schema no authentication
  2  default tablespace users quota unlimited on users;

User created.

- 인증 유형 확인: AUTHENTICATION_TYPE = NONE
SYS@salespdb> select username, authentication_type, account_status
  2  from   dba_users where username='APP_SCHEMA';

USERNAME     AUTHENTICATION_TYPE   ACCOUNT_STATUS
------------ --------------------- --------------
APP_SCHEMA   NONE                  OPEN

- 해석: 계정 상태는 OPEN 이지만 인증 수단이 NONE 이라 직접 로그인은 불가능하다.

======================================================================
[2단계] (실수 -> 오류 -> 재시도) 스키마 전용 계정으로 로그인 시도
======================================================================

- 이 계정에 접속 권한을 준 뒤 로그인이 되는지 확인
SYS@salespdb> grant create session, create table to app_schema;

Grant succeeded.

- (실수) 비밀번호가 없는 계정으로 로그인 시도
SYS@salespdb> connect app_schema/anything@salespdb
ERROR:
ORA-01017: invalid username/password; logon denied


Warning: You are no longer connected to ORACLE.

- 원인: NO AUTHENTICATION 계정은 비밀번호가 아예 없어 어떤 비밀번호로도 인증 불가(ORA-01017).
-   이것이 스키마 전용 계정의 목적: 로그인 자격 증명 자체를 없애 침입 경로 제거.

======================================================================
[3단계] 스키마 소유 객체를 다른 계정이 대신 만들어 사용
======================================================================

- 관리자로 재접속하여 app_schema 스키마에 테이블 생성(소유자 지정)
SYS@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.

SYS@salespdb> create table app_schema.orders
  2  (id number primary key, amount number);

Table created.

- 실제 접속하는 업무 계정(local_user)을 만들고 app_schema 객체 권한만 부여
SYS@salespdb> create user local_user identified by User_Pw#1
  2  default tablespace users quota 10m on users;
User created.
SYS@salespdb> grant create session to local_user;
Grant succeeded.
SYS@salespdb> grant select, insert on app_schema.orders to local_user;
Grant succeeded.

- local_user 로 접속하여 app_schema 객체 사용
SYS@salespdb> connect local_user/User_Pw#1@salespdb
Connected.
LOCAL_USER@salespdb> insert into app_schema.orders values (1, 5000);
1 row created.
LOCAL_USER@salespdb> commit;
Commit complete.

- 해석: 스키마(app_schema)는 객체만 소유, 실제 접속/작업은 local_user가 수행.

======================================================================
[4단계] 스키마 전용 <-> 일반 계정 전환
======================================================================

SYS@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.

- 유지보수 위해 임시 비밀번호 부여(일반 계정으로 전환)
SYS@salespdb> alter user app_schema identified by Temp_Pw#1;
User altered.

- 작업 완료 후 다시 스키마 전용으로 되돌림
SYS@salespdb> alter user app_schema no authentication;
User altered.

SYS@salespdb> select username, authentication_type
  2  from dba_users where username='APP_SCHEMA';

USERNAME     AUTHENTICATION_TYPE
------------ -------------------
APP_SCHEMA   NONE

======================================================================
[정리] 실습 객체 삭제
======================================================================

SYS@salespdb> drop user local_user cascade;
User dropped.
SYS@salespdb> drop user app_schema cascade;
User dropped.

- [정리] 핵심 확인 완료:
-   NO AUTHENTICATION=인증유형 NONE, 직접 로그인 불가(ORA-01017).
-   객체 소유 전용 스키마로 활용, ALTER USER 로 일반/전용 계정 상호 전환.
SYS@salespdb> exit
