-- 21장 실습_01: 데이터베이스 사용자 계정 개념 및 Oracle 제공 관리자 계정 확인

- 루트 컨테이너로 SYSDBA 접속된 상태에서 현재 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 사용자와 스키마의 1:1 관계 확인
======================================================================

- HR 사용자가 소유한 객체(스키마)의 개수 확인 → 사용자=스키마 소유자
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@salespdb> select owner, count(*) obj_cnt
  2  from   dba_objects where owner='HR' group by owner;

OWNER      OBJ_CNT
---------- ----------
HR                 34

- 해석: HR '사용자'를 만들면 HR '스키마'가 함께 생기며, HR이 만든 객체는 HR 스키마에 담긴다.
-   사용자(접속 주체)와 스키마(소유 객체 집합)는 1:1로 대응한다.

======================================================================
[2단계] Oracle 제공 관리자 계정과 상태 확인
======================================================================

SYS@salespdb> alter session set container = cdb$root;

Session altered.

- ORACLE_MAINTAINED='Y' 는 오라클이 자동 생성/유지하는 내부 계정
SYS@cdb1> select username, account_status, oracle_maintained
  2  from   dba_users
  3  where  username in ('SYS','SYSTEM','XDB','DBSNMP','AUDSYS')
  4  order  by username;

USERNAME     ACCOUNT_STATUS       ORA
------------ -------------------- ---
AUDSYS       EXPIRED & LOCKED     Y
DBSNMP       EXPIRED & LOCKED     Y
SYS          OPEN                 Y
SYSTEM       OPEN                 Y
XDB          EXPIRED & LOCKED     Y

- 해석: SYS/SYSTEM 만 OPEN 이고, 나머지 내부 스키마는 EXPIRED & LOCKED(비활성).
-   필요한 기능의 계정만 선별적으로 여는 것이 보안 원칙이다.

======================================================================
[3단계] 관리 권한(SYSDBA 등)을 가진 계정 확인
======================================================================

- 비밀번호 파일에 등록된 관리 권한 계정 목록
SYS@cdb1> select username, sysdba, sysoper, sysbackup
  2  from   v$pwfile_users order by username;

USERNAME     SYSDB SYSOP SYSBA
------------ ----- ----- -----
SYS          TRUE  TRUE  FALSE
SYSBACKUP    FALSE FALSE TRUE

- 해석: SYS는 SYSDBA/SYSOPER, SYSBACKUP은 백업/복구 전용 권한만 가진다.
-   최소 권한 원칙: 백업 담당자에겐 SYSDBA 대신 SYSBACKUP 만 부여한다.

======================================================================
[4단계] (실수 -> 오류 -> 재시도) 잠긴 내부 계정으로 접속 시도
======================================================================

- (실수) 비활성(EXPIRED & LOCKED)인 XDB 계정으로 접속을 시도
SYS@cdb1> connect xdb/xdb@salespdb
ERROR:
ORA-28000: the account is locked


Warning: You are no longer connected to ORACLE.

- 원인: XDB 계정은 설치 직후 잠금(LOCKED) 상태라 접속 불가.
-   실제로 XDB 기능이 필요할 때만 관리자가 계정을 열어야 한다(여기서는 열지 않음).

- 다시 SYSDBA 로 정상 접속
SYS@cdb1> connect sys@cdb1 as sysdba
Enter password:
Connected.

SYS@cdb1> select account_status from dba_users where username='SYS';

ACCOUNT_STATUS
--------------------
OPEN

- [정리] 핵심 확인 완료:
-   사용자=스키마(1:1), Oracle 제공 내부 계정은 대부분 EXPIRED & LOCKED,
-   관리 권한은 V$PWFILE_USERS 로 확인, 잠긴 계정 접속은 ORA-28000 발생.
SYS@cdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
