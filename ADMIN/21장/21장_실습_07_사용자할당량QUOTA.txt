-- 21장 실습_07: 사용자 할당량(Quota) 지정 실습

- salespdb 로 전환하여 현재 컨테이너 확인
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@salespdb> show con_name

CON_NAME
------------------------------
SALESPDB

======================================================================
[1단계] 할당량 없이 사용자 생성 (기본 할당량 0)
======================================================================

- DEFAULT TABLESPACE 는 지정했지만 QUOTA 는 지정하지 않음
SYS@salespdb> create user quota_demo identified by Demo_Pw#1
  2  default tablespace users temporary tablespace temp;
User created.
SYS@salespdb> grant create session, create table to quota_demo;
Grant succeeded.

- 할당량 확인 → DBA_TS_QUOTAS 에 아무 행도 없음(=0)
SYS@salespdb> select tablespace_name, max_bytes
  2  from dba_ts_quotas where username='QUOTA_DEMO';

no rows selected

- 해석: 할당량을 명시하지 않으면 기본 0이라 USERS 에 객체를 만들 수 없다.

======================================================================
[2단계] (실수 -> 오류 -> 재시도) 할당량 0 상태에서 테이블 생성
======================================================================

SYS@salespdb> connect quota_demo/Demo_Pw#1@salespdb
Connected.

- (실수) 할당량이 없는 USERS 에 테이블 생성 시도
QUOTA_DEMO@salespdb> create table t1 (id number) tablespace users;
create table t1 (id number) tablespace users
*
ERROR at line 1:
ORA-01950: no privileges on tablespace 'USERS'

- 원인: USERS 에 대한 할당량이 0 이라 세그먼트를 만들 수 없다(ORA-01950).
-   해결: 관리자가 QUOTA 를 부여해야 한다.

QUOTA_DEMO@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.
SYS@salespdb> alter user quota_demo quota 100m on users;
User altered.

- 재시도 → 성공
SYS@salespdb> connect quota_demo/Demo_Pw#1@salespdb
Connected.
QUOTA_DEMO@salespdb> create table t1 (id number) tablespace users;

Table created.

======================================================================
[3단계] 할당량 초과 시나리오 (ORA-01536)
======================================================================

- 작은 할당량으로 줄인 뒤 대량 데이터 삽입으로 초과 유발
QUOTA_DEMO@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.
SYS@salespdb> alter user quota_demo quota 1m on users;
User altered.

SYS@salespdb> connect quota_demo/Demo_Pw#1@salespdb
Connected.
QUOTA_DEMO@salespdb> insert into t1
  2  select level from dual connect by level <= 200000;
insert into t1
*
ERROR at line 1:
ORA-01536: space quota exceeded for tablespace 'USERS'

- 원인: 할당량은 있으나(1M) 데이터가 그 한도를 초과(ORA-01536).
-   ORA-01950(할당량 0=권한없음)과 ORA-01536(할당량 초과)의 차이에 유의.
-   해결: 할당량을 늘리거나 데이터를 줄인다.
QUOTA_DEMO@salespdb> connect sys@salespdb as sysdba
Enter password:
Connected.
SYS@salespdb> alter user quota_demo quota unlimited on users;
User altered.

======================================================================
[4단계] UNLIMITED TABLESPACE 권한과 할당량 조회
======================================================================

- 개별 QUOTA 대신 UNLIMITED TABLESPACE 권한 부여(모든 TS 무제한)
SYS@salespdb> grant unlimited tablespace to quota_demo;
Grant succeeded.

- 사용자별 할당량/사용량 확인 (max_bytes=-1 은 무제한)
SYS@salespdb> select tablespace_name, bytes/1024/1024 used_mb,
  2  decode(max_bytes,-1,'UNLIMITED',to_char(max_bytes/1048576)) quota_mb
  3  from dba_ts_quotas where username='QUOTA_DEMO';

TABLESPACE_NAME   USED_MB    QUOTA_MB
----------------- ---------- ----------
USERS                     0  UNLIMITED

- UNLIMITED TABLESPACE 권한 회수 → 새 할당은 다시 QUOTA 규칙 적용(기존 객체는 유지)
SYS@salespdb> revoke unlimited tablespace from quota_demo;
Revoke succeeded.

======================================================================
[정리] 실습 객체 삭제
======================================================================

SYS@salespdb> drop user quota_demo cascade;
User dropped.

- [정리] 핵심 확인 완료:
-   기본 할당량 0 → ORA-01950(권한없음), 할당량 초과 → ORA-01536.
-   QUOTA n/UNLIMITED ON ts 로 부여, UNLIMITED TABLESPACE 는 모든 TS 무제한(강력).
