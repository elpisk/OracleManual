-- 21장 실습_06: OS 인증 및 권한 있는 사용자의 OS 인증 실습

======================================================================
[1단계] OS_AUTHENT_PREFIX 파라미터 확인
======================================================================

- 서버의 OS 사용자 이름 확인
[oracle@dbsvr ~]$ whoami
oracle

[oracle@dbsvr ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

- OS 인증 시 DB 계정 이름 앞에 붙는 접두사(기본 OPS$)
SYS@cdb1> show parameter os_authent_prefix

NAME                  TYPE      VALUE
--------------------- --------- ------
os_authent_prefix     string    OPS$

- 해석: OS 계정 oracle 은 DB 계정 OPS$ORACLE 로 매핑되어야 자동 인증된다.

======================================================================
[2단계] OS 인증 계정 생성 (IDENTIFIED EXTERNALLY)
======================================================================

SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@salespdb> create user ops$oracle identified externally
  2  default tablespace users quota 10m on users;
User created.
SYS@salespdb> grant create session to ops$oracle;
Grant succeeded.

- 인증 유형 확인: EXTERNAL
SYS@salespdb> select username, authentication_type from dba_users
  2  where username='OPS$ORACLE';

USERNAME     AUTHENTICATION_TYPE
------------ -------------------
OPS$ORACLE   EXTERNAL

======================================================================
[3단계] (실수 -> 오류 -> 재시도) 접두사 없는 이름으로 OS 인증 시도
======================================================================

- (실수) 접두사 없이 'oracle' 이라는 이름으로 외부 인증 계정을 만들고 OS 접속 시도
SYS@salespdb> create user oracle identified externally
  2  default tablespace users quota 1m on users;
User created.
SYS@salespdb> grant create session to oracle;
Grant succeeded.

- OS oracle 사용자로 sqlplus / 접속 시도 → 어떤 계정에 매핑되나?
SYS@salespdb> exit
[oracle@dbsvr ~]$ sqlplus /@salespdb
ERROR:
ORA-01017: invalid username/password; logon denied

- 원인: OS_AUTHENT_PREFIX=OPS$ 이므로 OS 이름 oracle 은 DB 계정 OPS$ORACLE 을 찾는다.
-   접두사 없는 'oracle' 계정은 매핑 대상이 아니라서 인증 실패(ORA-01017).
-   해결: 접두사가 붙은 OPS$ORACLE 계정으로 매핑되므로 그 계정을 사용해야 한다.

[oracle@dbsvr ~]$ sqlplus /@salespdb

SQL*Plus: Release 19.0.0.0.0 - Production
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

OPS$ORACLE@salespdb> show user
USER is "OPS$ORACLE"

- 해석: OS oracle 사용자가 비밀번호 없이 OPS$ORACLE 계정으로 자동 인증됨.

======================================================================
[4단계] 원격 OS 인증 위험과 권한 있는 사용자의 OS 인증
======================================================================

OPS$ORACLE@salespdb> connect / as sysdba
Connected.

- 원격 OS 인증은 위조 위험 → 반드시 FALSE 유지
SYS@cdb1> show parameter remote_os_authent

NAME                  TYPE      VALUE
--------------------- --------- ------
remote_os_authent     boolean   FALSE

- 권한 있는 사용자의 OS 인증: OS의 dba 그룹 멤버가 sqlplus / as sysdba 로 접속
[oracle@dbsvr ~]$ id oracle
uid=54321(oracle) gid=54321(oinstall) groups=54321(oinstall),54322(dba),54323(oper)

- 해석: oracle 은 dba 그룹(OSDBA) 멤버라 sqlplus / as sysdba 로 SYSDBA 인증 가능.
-   DB가 안 열려 있어도 인증되어 STARTUP/SHUTDOWN 을 수행할 수 있다.

======================================================================
[정리] 실습 객체 삭제
======================================================================

SYS@cdb1> alter session set container = salespdb;
Session altered.
SYS@salespdb> drop user ops$oracle cascade;
User dropped.
SYS@salespdb> drop user oracle cascade;
User dropped.

- [정리] 핵심 확인 완료:
-   OS 인증 계정=IDENTIFIED EXTERNALLY(인증유형 EXTERNAL), 이름은 접두사(OPS$)+OS이름.
-   접두사 불일치 시 ORA-01017, REMOTE_OS_AUTHENT는 FALSE 유지, dba 그룹이 SYSDBA OS인증.
SYS@salespdb> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
