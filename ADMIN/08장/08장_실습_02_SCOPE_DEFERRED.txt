======================================================================
[1단계] 현재 SPFILE 로 기동되었는지 확인 (SCOPE 사용 전제 조건)
======================================================================

- spfile 파라미터에 값이 있으면 SPFILE 로 기동한 것 (SCOPE=SPFILE/BOTH 사용 가능)
SYS@cdb1> show parameter spfile

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
spfile                               string      /u01/app/oracle/dbs/spfilecdb1.ora

======================================================================
[2단계] SCOPE=MEMORY : 즉시 적용, 재시작 시 소실
======================================================================

- 변경 전 값 확인
SYS@cdb1> show parameter db_cache_advice

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
db_cache_advice                      string      ON

- 메모리에만 적용 (SPFILE 에는 기록되지 않음)
SYS@cdb1> alter system set db_cache_advice = READY scope=memory;

System altered.

- 현재 메모리 값은 바뀌었지만, SPFILE 값은 그대로임을 두 뷰로 비교
SYS@cdb1> select
  2    (select value from v$parameter      where name='db_cache_advice') as mem_value,
  3    (select value from v$spparameter     where name='db_cache_advice') as spfile_value
  4  from dual;

MEM_VALUE   SPFILE_VALUE
----------- ------------
READY       ON

- 해석: MEMORY 변경은 재시작 시 SPFILE 값(ON)으로 되돌아감

======================================================================
[3단계] SCOPE=SPFILE : 즉시 효과 없음, 재시작 후 지속 (정적 파라미터)
======================================================================

- processes 는 정적 파라미터(ISSYS_MODIFIABLE=FALSE). 즉시 변경을 시도하면?
SYS@cdb1> alter system set processes = 500 scope=memory;
alter system set processes = 500 scope=memory
*
ERROR at line 1:
ORA-02095: specified initialization parameter cannot be modified

- 원인: processes 는 정적 파라미터라 메모리 즉시 변경 불가. SPFILE 에 기록 후 재시작해야 함
SYS@cdb1> alter system set processes = 500 scope=spfile;

System altered.

- 확인: 현재(메모리) 값은 그대로, SPFILE 값만 변경됨
SYS@cdb1> select
  2    (select value from v$parameter  where name='processes') as mem_value,
  3    (select value from v$spparameter where name='processes') as spfile_value
  4  from dual;

MEM_VALUE   SPFILE_VALUE
----------- ------------
320         500

- (실제 반영은 재시작 후) shutdown immediate; startup 을 하면 processes=500 적용됨
-   실습에서는 다른 세션 영향을 피하기 위해 재기동은 생략하고 원복만 수행
SYS@cdb1> alter system set processes = 320 scope=spfile;

System altered.

======================================================================
[4단계] SCOPE=BOTH : 즉시 + 지속 (SPFILE 기동 시 SCOPE 생략의 기본값)
======================================================================

- 즉시 반영 + SPFILE 기록을 한 번에
SYS@cdb1> alter system set open_cursors = 400 scope=both;

System altered.

- 두 값이 모두 400 으로 일치함을 확인
SYS@cdb1> select
  2    (select value from v$parameter  where name='open_cursors') as mem_value,
  3    (select value from v$spparameter where name='open_cursors') as spfile_value
  4  from dual;

MEM_VALUE   SPFILE_VALUE
----------- ------------
400         400

======================================================================
[5단계] DEFERRED : 이후 접속 세션부터 적용
======================================================================

- audit_file_dest 등 즉시 변경이 막힌 파라미터를 DEFERRED 없이 바꾸면?
SYS@cdb1> alter system set backup_tape_io_slaves = TRUE;
alter system set backup_tape_io_slaves = TRUE
*
ERROR at line 1:
ORA-02096: specified initialization parameter is not modifiable with this option

- 원인: 이 파라미터는 즉시 변경 불가(ISSYS_MODIFIABLE=DEFERRED). DEFERRED 로 재시도
SYS@cdb1> alter system set backup_tape_io_slaves = TRUE deferred;

System altered.

- 해석: 지금 접속한 세션에는 미적용, 앞으로 새로 접속하는 세션부터 적용됨

- (실습 정리) 변경 값 원복
SYS@cdb1> alter system set open_cursors = 300 scope=both;

System altered.

- [정리]
-   MEMORY=즉시/휘발, SPFILE=재시작 후/지속, BOTH=즉시+지속(생략 시 기본)
-   정적 파라미터는 MEMORY 변경 불가(ORA-02095) -> SCOPE=SPFILE + 재시작
-   ISSYS_MODIFIABLE=DEFERRED 파라미터는 DEFERRED 키워드 필수(ORA-02096 회피)
SYS@cdb1> exit
