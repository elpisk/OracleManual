======================================================================
[1단계] 동적 성능 뷰의 성격 확인 (V$FIXED_TABLE)
======================================================================

- 존재하는 동적 성능 뷰(v$)의 개수 확인 — 메모리 기반 가상 테이블
SYS@cdb1> select count(*) from v$fixed_table where name like 'V$%';

  COUNT(*)
----------
      1350

======================================================================
[2단계] V$SESSION — 현재 접속 세션 조회
======================================================================

- 사용자 세션(백그라운드 제외)을 사용자/프로그램/머신과 함께 조회
SYS@cdb1> col username format a12
SYS@cdb1> col program  format a22
SYS@cdb1> col machine  format a16
SYS@cdb1> select sid, serial#, username, program, machine
  2  from v$session
  3  where type = 'USER' and username is not null;

       SID    SERIAL# USERNAME     PROGRAM                MACHINE
---------- ---------- ------------ ---------------------- ----------------
        31      41022 SYS          sqlplus@dbsvr (TNS V1) dbsvr
       142      13907 HR           JDBC Thin Client       EDXX9P1

- 특정 머신에서 최근 하루 로그인한 세션만 필터링
SYS@cdb1> select sid, serial#, username, to_char(logon_time,'HH24:MI') as logon
  2  from v$session
  3  where machine = 'EDXX9P1' and logon_time > sysdate - 1;

       SID    SERIAL# USERNAME     LOGON
---------- ---------- ------------ -----
       142      13907 HR           09:55

======================================================================
[3단계] V$SQL — 자원을 많이 사용한 SQL 조회
======================================================================

- (실수) 존재하지 않는 컬럼명(cpu_seconds)으로 조회
SYS@cdb1> select sql_id, cpu_seconds from v$sql where rownum <= 5;
select sql_id, cpu_seconds from v$sql where rownum <= 5
                *
ERROR at line 1:
ORA-00904: "CPU_SECONDS": invalid identifier

- 원인: V$SQL 의 CPU 시간 컬럼명은 CPU_TIME(마이크로초 단위). 올바른 컬럼으로 재조회
SYS@cdb1> select sql_id, cpu_time, executions,
  2         substr(sql_text,1,40) as sql_text
  3  from v$sql
  4  where cpu_time > 200000
  5  order by cpu_time desc
  6  fetch first 5 rows only;

SQL_ID          CPU_TIME EXECUTIONS SQL_TEXT
------------- ---------- ---------- ----------------------------------------
9bx2c1kq3d8yf    4821330         12 SELECT * FROM SALES WHERE REGION = :B1
c7pk0m3nzra11    1330442          3 SELECT COUNT(*) FROM BIG_TABLE T1, ...

======================================================================
[4단계] V$LOCK — 블로킹 락 조회 (V$SESSION 과 조인)
======================================================================

- 다른 세션을 막고 있는(BLOCK>0) 락 보유 세션과 보유 시간 확인
SYS@cdb1> select sid, type, id1, id2, ctime as hold_sec, block
  2  from v$lock
  3  where block > 0;

       SID TY        ID1        ID2   HOLD_SEC      BLOCK
---------- -- ---------- ---------- ---------- ----------
       142 TX     524312       1837        213          1

- 블로킹 세션이 누구인지 V$SESSION 과 조인해 식별 (진단 표준 경로)
SYS@cdb1> select s.sid, s.username, s.program, s.machine
  2  from v$lock l join v$session s on l.sid = s.sid
  3  where l.block > 0;

       SID USERNAME     PROGRAM                MACHINE
---------- ------------ ---------------------- ----------------
       142 HR           JDBC Thin Client       EDXX9P1

- 해석: SID 142(HR, EDXX9P1)가 트랜잭션 락(TX)을 213초째 붙들어 다른 세션을 대기시킴
-        조치 판단 전, 반드시 원인 세션/SQL 을 먼저 확인해야 함

- [정리]
-   V$FIXED_TABLE 로 전체 v$ 뷰 목록 확인 (메모리 기반 가상 테이블)
-   진단 경로: V$LOCK(block>0) -> V$SESSION(누구) -> V$SQL(무슨 SQL)
-   V$SQL 의 CPU 시간 컬럼은 CPU_TIME(마이크로초), 데이터는 실시간 변동(읽기 일관성 미보장)
