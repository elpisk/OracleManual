-- 23장 실습_06: 멀티테넌트 아키텍처에서 프로파일 할당 (ALTER USER ... PROFILE, DROP ... CASCADE)

- 루트 컨테이너로 SYSDBA 접속된 상태 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 공통 프로파일 생성 후 PDB 로컬 사용자에 할당
======================================================================

- 루트에서 공통 프로파일 준비(앞 실습에서 만들었다면 생략 가능).
SYS@cdb1> create profile c##corp_prof limit
  2    failed_login_attempts 5
  3    password_life_time 90
  4    container = all;

Profile created.

- PDB 로 이동해 로컬 사용자 HR 에게 공통 프로파일을 할당한다.
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@cdb1> alter user hr profile c##corp_prof;

User altered.

- 확인: 로컬 사용자에게 공통 프로파일 할당이 가능하다.
SYS@cdb1> select username, profile from dba_users where username = 'HR';

USERNAME   PROFILE
---------- --------------
HR         C##CORP_PROF

======================================================================
[2단계] 새 사용자 생성 시 로컬 프로파일 지정
======================================================================

- PDB 로컬 프로파일 준비
SYS@cdb1> create profile app_local limit sessions_per_user 8;
Profile created.

- CREATE USER ... PROFILE 로 처음부터 프로파일을 지정
SYS@cdb1> create user app_svc identified by Svc#2024 profile app_local;
User created.
SYS@cdb1> grant create session to app_svc;
Grant succeeded.

======================================================================
[3단계] (오류 -> 원인 -> 수정) 없는 프로파일 할당 + 적용 시점
======================================================================

- (실수) 오타로 존재하지 않는 프로파일을 할당 시도
SYS@cdb1> alter user app_svc profile app_locall;
alter user app_svc profile app_locall
*
ERROR at line 1:
ORA-02380: profile APP_LOCALL does not exist

- 원인: 프로파일 이름 오타(app_locall). 실제 존재하는 이름으로 지정한다.
- 수정: 올바른 이름 app_local 로 재할당.
SYS@cdb1> alter user app_svc profile app_local;

User altered.

- (참고) 프로파일 변경은 이미 접속 중인 세션에 소급 적용되지 않는다.
- 새 프로파일이 SESSIONS_PER_USER 를 낮춰도 기존 세션은 유지되고, 새 세션부터 제한된다.

======================================================================
[4단계] (오류 -> 원인 -> 수정) 할당 사용자가 있는 프로파일 삭제
======================================================================

- app_local 은 app_svc 에게 할당되어 있다. (실수) 그냥 삭제 시도.
SYS@cdb1> drop profile app_local;
drop profile app_local
*
ERROR at line 1:
ORA-02382: profile APP_LOCAL has users assigned, cannot delete without CASCADE

- 원인: 할당된 사용자가 있어 그냥 삭제할 수 없다.
- 안전 절차: 먼저 어떤 사용자가 쓰는지 확인한다(정책 완화 위험 점검).
SYS@cdb1> select username from dba_users where profile = 'APP_LOCAL';

USERNAME
----------
APP_SVC

- 수정: CASCADE 로 삭제하면 사용자는 자동으로 DEFAULT 프로파일로 재할당된다.
SYS@cdb1> drop profile app_local cascade;

Profile dropped.

- 확인: app_svc 의 프로파일이 DEFAULT 로 바뀌었다.
SYS@cdb1> select username, profile from dba_users where username = 'APP_SVC';

USERNAME   PROFILE
---------- --------------
APP_SVC    DEFAULT

======================================================================
[5단계] 계정 잠금 해제와 정리
======================================================================

- 실습 마무리로 HR 프로파일을 원래대로 되돌린다.
SYS@cdb1> alter user hr profile default;
User altered.

- [정리] 할당은 CREATE/ALTER USER ... PROFILE, 없는 프로파일=ORA-02380,
-   할당 사용자 있는 프로파일 삭제=ORA-02382 -> DROP ... CASCADE(사용자는 DEFAULT로).
SYS@cdb1> exit
