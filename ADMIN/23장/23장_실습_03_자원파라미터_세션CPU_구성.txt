-- 23장 실습_03: 프로파일 자원 파라미터(세션/CPU/IDLE_TIME 등) 구성 및 한도 초과 확인

- 루트 컨테이너로 SYSDBA 접속된 상태 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] (오류 -> 원인 -> 수정) RESOURCE_LIMIT 미활성 상태 점검
======================================================================

- 자원 제한 실습 전에 RESOURCE_LIMIT 값을 확인한다.
SYS@cdb1> show parameter resource_limit

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
resource_limit                       boolean     FALSE

- (주의) FALSE 이면 세션·콜 자원 제한을 아무리 설정해도 적용되지 않는다.
- 수정: TRUE 로 변경한다.
SYS@cdb1> alter system set resource_limit = true;

System altered.

======================================================================
[2단계] 세션·CPU·시간 제한 프로파일 생성
======================================================================

SYS@cdb1> alter session set container = pdb1;

Session altered.

- 단위 유의: CPU 는 100분의 1초(센티초), 시간(CONNECT/IDLE)은 분.
SYS@cdb1> create profile oltp_prof limit
  2    sessions_per_user 2
  3    cpu_per_call      2000      -- 20초
  4    connect_time      60        -- 60분
  5    idle_time         10;       -- 10분

Profile created.

- 실습용 사용자 생성 후 프로파일 할당
SYS@cdb1> create user oltp_user identified by Oltp#2024;
User created.
SYS@cdb1> grant create session to oltp_user;
Grant succeeded.
SYS@cdb1> alter user oltp_user profile oltp_prof;
User altered.

======================================================================
[3단계] (오류 -> 원인 -> 수정) 동시 세션 수 한도 초과
======================================================================

- oltp_user 는 SESSIONS_PER_USER 가 2 다. 세 번째 세션을 열면 거부된다.
- (첫 번째, 두 번째 세션은 이미 접속되어 있다고 가정하고 세 번째 접속 시도)
SYS@cdb1> connect oltp_user/Oltp#2024@pdb1
ERROR:
ORA-02391: exceeded simultaneous SESSIONS_PER_USER limit


Warning: You are no longer connected to ORACLE.

- 원인: 이미 2개 세션이 열려 있어 세 번째 병행 세션이 한도를 초과했다.
- 수정1: 기존 세션 하나를 종료하거나, 수정2: 한도를 늘린다. 여기선 한도를 늘린다.
SYS@cdb1> connect sys@pdb1 as sysdba
Enter password:
Connected.
SYS@cdb1> alter profile oltp_prof limit sessions_per_user 5;

Profile altered.

- (주의) 변경은 새 세션부터 적용된다. 이제 추가 접속이 허용된다.
SYS@cdb1> connect oltp_user/Oltp#2024@pdb1
Connected.

======================================================================
[4단계] 콜 CPU 한도 초과 확인 (문장만 실패, 세션 유지)
======================================================================

- CPU_PER_CALL 한도를 낮춰 폭주 쿼리를 재현한다.
OLTP_USER@pdb1> connect sys@pdb1 as sysdba
Enter password:
Connected.
SYS@cdb1> alter profile oltp_prof limit cpu_per_call 50;   -- 0.5초
Profile altered.

- oltp_user 로 CPU 를 많이 쓰는 카티전 조인을 실행 -> 콜 한도 초과
SYS@cdb1> connect oltp_user/Oltp#2024@pdb1
Connected.
OLTP_USER@pdb1> select count(*)
  2  from   all_objects a, all_objects b;
from   all_objects a, all_objects b
       *
ERROR at line 1:
ORA-02393: exceeded call limit on CPU usage

- 원인: 단일 콜의 CPU 사용이 CPU_PER_CALL(0.5초)을 초과했다.
- 확인: 콜 한도 초과는 그 문장만 실패시키고 세션은 살아 있다.
OLTP_USER@pdb1> select 'still connected' as status from dual;

STATUS
---------------
still connected

- [정리] SESSIONS_PER_USER 초과=ORA-02391(접속 거부), CPU_PER_CALL 초과=ORA-02393
-   (문장만 실패, 세션 유지). 프로파일 변경은 새 세션부터 적용된다.
OLTP_USER@pdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
