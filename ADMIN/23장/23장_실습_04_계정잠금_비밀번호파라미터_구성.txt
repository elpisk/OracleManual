-- 23장 실습_04: 계정 잠금 및 비밀번호 관련 파라미터 구성 (FAILED_LOGIN_ATTEMPTS, ORA-28000)

- 루트 컨테이너로 SYSDBA 접속된 상태 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

SYS@cdb1> alter session set container = pdb1;

Session altered.

======================================================================
[1단계] 계정 잠금·비밀번호 파라미터 프로파일 생성
======================================================================

- 로그인 실패 3회 시 잠금, 약 1시간 후 자동 해제, 수명·재사용도 함께 지정.
SYS@cdb1> create profile secure_prof limit
  2    failed_login_attempts 3
  3    password_lock_time    0.0417     -- 약 1시간(1/24)
  4    password_life_time    90
  5    password_grace_time   7
  6    password_reuse_time   365
  7    password_reuse_max    5;

Profile created.

- 실습용 사용자 생성 및 프로파일 할당
SYS@cdb1> create user lockuser identified by Lock#2024;
User created.
SYS@cdb1> grant create session to lockuser;
Grant succeeded.
SYS@cdb1> alter user lockuser profile secure_prof;
User altered.

======================================================================
[2단계] (오류 -> 원인 -> 수정) 로그인 3회 실패로 계정 잠김
======================================================================

- 잘못된 비밀번호로 3회 접속 시도
SYS@cdb1> connect lockuser/wrong1@pdb1
ERROR:
ORA-01017: invalid username/password; logon denied

SYS@cdb1> connect lockuser/wrong2@pdb1
ERROR:
ORA-01017: invalid username/password; logon denied

SYS@cdb1> connect lockuser/wrong3@pdb1
ERROR:
ORA-01017: invalid username/password; logon denied

- 이제 올바른 비밀번호로 접속해도 계정이 잠겨 있다.
SYS@cdb1> connect lockuser/Lock#2024@pdb1
ERROR:
ORA-28000: the account is locked


Warning: You are no longer connected to ORACLE.

- 원인: FAILED_LOGIN_ATTEMPTS(3)를 초과해 계정이 자동 잠겼다(ORA-28000).

======================================================================
[3단계] 계정 상태 확인 및 수동 잠금 해제
======================================================================

SYS@cdb1> connect sys@pdb1 as sysdba
Enter password:
Connected.

SYS@cdb1> select username, account_status, lock_date
  2  from   dba_users where username = 'LOCKUSER';

USERNAME   ACCOUNT_STATUS       LOCK_DATE
---------- -------------------- ---------
LOCKUSER   LOCKED(TIMED)        22-JUL-26

- LOCKED(TIMED) 는 로그인 실패 누적으로 잠긴 상태다. LOCK_DATE 에 잠긴 시각 기록.
- 수정: PASSWORD_LOCK_TIME 자동 해제를 기다리지 않고 즉시 해제한다.
SYS@cdb1> alter user lockuser account unlock;

User altered.

- 이제 올바른 비밀번호로 정상 접속되고, 성공 시 실패 카운터는 0으로 초기화된다.
SYS@cdb1> connect lockuser/Lock#2024@pdb1
Connected.

======================================================================
[4단계] (오류 -> 원인 -> 수정) 이전 비밀번호 재사용 시도
======================================================================

- 비밀번호를 한 번 바꾼 뒤, 곧바로 원래 비밀번호로 되돌려 본다.
LOCKUSER@pdb1> alter user lockuser identified by NewPw#2024;
User altered.

LOCKUSER@pdb1> alter user lockuser identified by Lock#2024;
alter user lockuser identified by Lock#2024
*
ERROR at line 1:
ORA-28007: the password cannot be reused

- 원인: PASSWORD_REUSE_TIME(365)·PASSWORD_REUSE_MAX(5) 조건을 아직 충족하지 못했다.
- 수정: 규칙에 걸리지 않는 새 비밀번호로 변경한다.
LOCKUSER@pdb1> alter user lockuser identified by Fresh#2024;

User altered.

- [정리] 실패 누적 잠금=ORA-28000/LOCKED(TIMED), 해제는 ACCOUNT UNLOCK,
-   재사용 규칙 위반=ORA-28007. 비밀번호 제한은 RESOURCE_LIMIT 과 무관하게 항상 적용.
LOCKUSER@pdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
