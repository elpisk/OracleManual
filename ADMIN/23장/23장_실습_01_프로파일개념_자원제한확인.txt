-- 23장 실습_01: 프로파일 개념 및 사용자 자원 제한 확인 (DBA_PROFILES, RESOURCE_LIMIT)

- 루트 컨테이너로 SYSDBA 접속된 상태 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] RESOURCE_LIMIT 초기화 파라미터 확인
======================================================================

- 커널 자원 제한이 실제로 강제되려면 RESOURCE_LIMIT 이 TRUE 여야 한다.
SYS@cdb1> show parameter resource_limit

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
resource_limit                       boolean     FALSE

- (주의) 값이 FALSE 다. 이 상태에서는 CPU_PER_SESSION 등 자원 제한이 무시된다.
- 뒤 실습을 위해 TRUE 로 변경한다(동적 파라미터라 즉시 반영, 새 세션부터 적용).
SYS@cdb1> alter system set resource_limit = true;

System altered.

SYS@cdb1> show parameter resource_limit

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------
resource_limit                       boolean     TRUE

======================================================================
[2단계] DEFAULT 프로파일의 제한 값 조회
======================================================================

- 모든 프로파일 정의는 DBA_PROFILES 에서 확인한다.
SYS@cdb1> select resource_name, resource_type, limit
  2  from   dba_profiles
  3  where  profile = 'DEFAULT'
  4  order  by resource_type, resource_name;

RESOURCE_NAME                    RESOURCE_TYPE LIMIT
-------------------------------- ------------- ----------
COMPOSITE_LIMIT                  KERNEL        UNLIMITED
CPU_PER_CALL                     KERNEL        UNLIMITED
CPU_PER_SESSION                  KERNEL        UNLIMITED
SESSIONS_PER_USER                KERNEL        UNLIMITED
FAILED_LOGIN_ATTEMPTS            PASSWORD      10
PASSWORD_LIFE_TIME               PASSWORD      180
PASSWORD_REUSE_MAX               PASSWORD      UNLIMITED
...

- RESOURCE_TYPE 이 KERNEL 이면 자원 제한, PASSWORD 면 비밀번호 관리 항목이다.
- DEFAULT 의 FAILED_LOGIN_ATTEMPTS=10, PASSWORD_LIFE_TIME=180 이 19c 기본값이다.

======================================================================
[3단계] 사용자에게 할당된 프로파일 확인
======================================================================

- 실습은 pdb1 안에서 진행한다.
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@cdb1> select username, profile, account_status
  2  from   dba_users
  3  where  username in ('HR','SYSTEM')
  4  order  by username;

USERNAME   PROFILE    ACCOUNT_STATUS
---------- ---------- --------------------
HR         DEFAULT    OPEN
SYSTEM     DEFAULT    OPEN

- 별도 지정을 하지 않은 사용자는 모두 DEFAULT 프로파일을 따른다.

======================================================================
[4단계] (오류 -> 원인 -> 수정) 존재하지 않는 프로파일 조회 오타
======================================================================

- (실수) 프로파일 이름을 'DEFULT' 로 잘못 입력해 값이 하나도 안 나온다.
SYS@cdb1> select resource_name, limit from dba_profiles
  2  where  profile = 'DEFULT';

no rows selected

- 원인: 오류는 아니지만 프로파일 이름 오타로 결과가 비었다(DEFULT -> DEFAULT).
- (실수2) 이번엔 존재하지 않는 프로파일을 사용자에게 할당해 본다.
SYS@cdb1> alter user hr profile no_such_prof;
alter user hr profile no_such_prof
*
ERROR at line 1:
ORA-02380: profile NO_SUCH_PROF does not exist

- 원인: 실제로 없는 프로파일을 할당하려 해서 발생. 먼저 프로파일을 만들어야 한다.
- 수정: 존재하는 프로파일(DEFAULT)로 지정하면 정상 처리된다.
SYS@cdb1> alter user hr profile default;

User altered.

- [정리] 자원 제한은 RESOURCE_LIMIT=TRUE 전제, 프로파일 정의는 DBA_PROFILES,
-   사용자 할당은 DBA_USERS.PROFILE 로 확인. 없는 프로파일 할당은 ORA-02380.
SYS@cdb1> exit
