-- 6장 실습_03: catcdb.sql 스크립트 실행으로 데이터 딕셔너리 구축 확인
-- 목표: CREATE DATABASE 직후에는 딕셔너리 뷰가 없음을 확인하고, catcdb.sql로 구축한 뒤
--       뷰 조회가 정상 동작함을 검증한다. 마무리로 utlrp.sql/SPFILE 생성까지 수행한다.
-- 전제: 실습_01에서 CDB1을 생성해 OPEN 상태이며, 아직 카탈로그 스크립트는 미실행.

======================================================================
[1단계] CREATE DATABASE 직후 상태에서 딕셔너리 조회 시도 (오류 재현)
======================================================================

[oracle@dbsvr ~]$ export ORACLE_SID=CDB1
[oracle@dbsvr ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production on Fri Jul 24 11:15:33 2026
Version 19.3.0.0.0

Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0

SQL> set sqlprompt "_user'@'_connect_identifier> "

- 데이터베이스는 이미 OPEN 상태다(실습_01에서 생성).
SYS@CDB1> select open_mode, cdb from v$database;

OPEN_MODE            CDB
-------------------- ---
READ WRITE           YES

- (실수) 아직 catcdb.sql을 돌리지 않았는데 딕셔너리 뷰부터 조회
SYS@CDB1> select count(*) from dba_tablespaces;
select count(*) from dba_tablespaces
                     *
ERROR at line 1:
ORA-00942: table or view does not exist

- 원인: DBA_TABLESPACES 같은 데이터 딕셔너리 뷰는 CREATE DATABASE만으로는
--   만들어지지 않는다. 카탈로그 스크립트(catcdb.sql 또는 catalog.sql)가
--   딕셔너리 뷰와 공개 동의어를 설치해야 조회가 가능하다.

- 표준 PL/SQL 패키지도 아직 없음을 확인 (DBMS_UTILITY 호출 시도)
SYS@CDB1> begin dbms_utility.compile_schema('SYS'); end;
  2  /
begin dbms_utility.compile_schema('SYS'); end;
      *
ERROR at line 1:
ORA-06550: line 1, column 7:
PLS-00201: identifier 'DBMS_UTILITY' must be declared

======================================================================
[2단계] catcdb.sql 실행으로 데이터 딕셔너리와 표준 패키지 설치
======================================================================

- catcdb.sql은 $ORACLE_HOME/rdbms/admin 에 있다(?/ 는 ORACLE_HOME 축약).
-   CDB 루트와 시드에 딕셔너리 뷰/표준 PL/SQL 패키지를 설치한다(수십 분 소요 가능).
SYS@CDB1> @?/rdbms/admin/catcdb.sql
...
catcdb: Setting parallel level to 1
...
catcdb: Completed successfully.

PL/SQL procedure successfully completed.

======================================================================
[3단계] 딕셔너리 구축 결과 검증
======================================================================

- 이제 DBA_TABLESPACES 뷰가 정상 조회된다(1단계 오류가 해소됨).
SYS@CDB1> select count(*) from dba_tablespaces;

  COUNT(*)
----------
         5

- 컨테이너별 테이블스페이스가 딕셔너리로 조회되는지 확인
SYS@CDB1> select tablespace_name from dba_tablespaces order by tablespace_name;

TABLESPACE_NAME
------------------------------
SYSAUX
SYSTEM
TEMP
UNDOTBS
USERS

- 표준 PL/SQL 패키지도 사용 가능해졌는지 확인(무효 객체 여부 조회)
SYS@CDB1> select status, count(*) from dba_objects
  2  where object_type='PACKAGE' group by status order by status;

STATUS    COUNT(*)
-------- ----------
INVALID          6
VALID          1180

- INVALID 객체가 일부 보인다 → 설치 과정의 의존성 순서 때문. utlrp.sql로 재컴파일.

======================================================================
[4단계] 마무리: 무효 객체 재컴파일과 SPFILE 생성
======================================================================

- 무효(INVALID) 객체를 일괄 재컴파일
SYS@CDB1> @?/rdbms/admin/utlrp.sql
...
PL/SQL procedure successfully completed.

- 재컴파일 후 무효 객체가 0인지 확인 (0이면 정상)
SYS@CDB1> select count(*) from dba_objects where status='INVALID';

  COUNT(*)
----------
         0

- (실수) 텍스트 PFILE 없이 SPFILE을 만들려다 경로/이름 혼동으로 실패 재현
SYS@CDB1> create spfile from pfile='/u01/app/oracle/product/19c/dbs/initCDBX.ora';
create spfile from pfile='/u01/app/oracle/product/19c/dbs/initCDBX.ora'
*
ERROR at line 1:
ORA-27041: unable to open file
Linux-x86_64 Error: 2: No such file or directory

- 원인: initCDBX.ora 라는 잘못된 파일명을 지정했다. 실제 PFILE은 initCDB1.ora.
--   인자를 생략하면 기본 위치의 init<SID>.ora(=initCDB1.ora)를 사용한다.
SYS@CDB1> create spfile from pfile;

File created.

- SPFILE 사용 여부 확인(값이 채워져 있으면 SPFILE로 기동 중)
SYS@CDB1> show parameter spfile

NAME       TYPE        VALUE
---------- ----------- --------------------------------------------------
spfile     string      /u01/app/oracle/product/19c/dbs/spfileCDB1.ora

- [정리]
--   1) CREATE DATABASE만으로는 딕셔너리 뷰/표준 패키지가 없어 조회가 실패(ORA-00942/PLS-00201).
--   2) catcdb.sql이 딕셔너리 뷰와 표준 PL/SQL 패키지를 설치한다.
--   3) 설치 후 utlrp.sql로 무효 객체 재컴파일, CREATE SPFILE FROM PFILE로 마무리.
--   이로써 SQL 명령어만으로 만든 CDB가 운영 가능한 완전한 상태가 되었다.
SYS@CDB1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
