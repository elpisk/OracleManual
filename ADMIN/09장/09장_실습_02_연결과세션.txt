-- 9장 실습_02: 접속(Connection)과 세션(Session)의 차이 확인

- 개념: 연결(connection)=사용자 프로세스와 인스턴스 사이의 물리적 통신 경로(선)
-        세션(session)=현재 사용자 로그인 상태를 나타내는 논리적 엔티티
- 목표: 동일한 사용자이름으로 여러 세션을 동시에 만들 수 있음을 직접 관찰

======================================================================
[1단계] 첫 번째 세션 접속 (터미널 1) — HR 사용자로 PDB에 접속
======================================================================

- Easy Connect 로 salespdb에 접속 (host:port/service 형식)
[oracle@dbsvr ~]$ sqlplus hr@dbsvr.example.com:1521/salespdb.example.com

SQL*Plus: Release 19.0.0.0.0 - Production on Mon Jul 27 10:31:12 2026
Version 19.3.0.0.0

Enter password:
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SQL> set sqlprompt "_user'@'_connect_identifier> "
HR@salespdb.example.com> show con_name

CON_NAME
------------------------------
SALESPDB

- 내 세션의 식별 정보 확인 (SID/SERIAL#/SERVER 방식)
HR@salespdb.example.com> select sid, serial#, server
  2  from v$session
  3  where sid = sys_context('userenv','sid');

       SID    SERIAL# SERVER
---------- ---------- ---------
       142      31007 DEDICATED

- 이 세션을 유지한 채 두 번째 터미널에서 같은 사용자로 접속한다

======================================================================
[2단계] 두 번째 세션 접속 (터미널 2) — 같은 HR 사용자로 다시 접속
======================================================================

[oracle@dbsvr ~]$ sqlplus hr@dbsvr.example.com:1521/salespdb.example.com

SQL*Plus: Release 19.0.0.0.0 - Production on Mon Jul 27 10:32:40 2026
Version 19.3.0.0.0

Enter password:
Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production

SQL> set sqlprompt "_user'@'_connect_identifier> "
HR@salespdb.example.com> select sid, serial#, server
  2  from v$session
  3  where sid = sys_context('userenv','sid');

       SID    SERIAL# SERVER
---------- ---------- ---------
       155      12904 DEDICATED

- 같은 사용자이름(HR)인데 SID가 142 -> 155 로 다른 별개의 세션이 만들어졌다

======================================================================
[3단계] 하나의 사용자에 여러 세션이 존재함을 확인 (관리자 세션에서)
======================================================================

- 관리자로 접속해 전체 세션을 조회 (SYSDBA, 로컬 OS 인증)
[oracle@dbsvr ~]$ sqlplus / as sysdba
...
SQL> set sqlprompt "_user'@'_connect_identifier> "

- (실수) 컬럼명을 잘못 입력: v$session에는 logon_date가 아니라 logon_time
SYS@cdb1> select sid, serial#, username, logon_date from v$session
  2  where username = 'HR';
select sid, serial#, username, logon_date from v$session
                                *
ERROR at line 1:
ORA-00904: "LOGON_DATE": invalid identifier

- 원인: 접속 시각 컬럼의 정확한 이름은 LOGON_TIME 이다. 수정 후 재조회
SYS@cdb1> select sid, serial#, username, server, logon_time
  2  from v$session
  3  where username = 'HR'
  4  order by logon_time;

       SID    SERIAL# USERNAME   SERVER    LOGON_TIME
---------- ---------- ---------- --------- -------------------
       142      31007 HR         DEDICATED 27-JUL-2026 10:31:12
       155      12904 HR         DEDICATED 27-JUL-2026 10:32:40

- 동일 사용자 HR에 대해 2개의 세션이 동시에 존재함을 확인 (하나의 사용자, 여러 세션)

- 사용자별 세션 수로 다시 집계
SYS@cdb1> select username, count(*) as session_cnt
  2  from v$session
  3  where username is not null
  4  group by username
  5  order by session_cnt desc;

USERNAME             SESSION_CNT
-------------------- -----------
HR                             2
SYS                            1

- 각 세션이 어떤 서버 프로세스(OS PID)와 짝지어졌는지 확인 (전용 서버는 1:1 대응)
SYS@cdb1> select s.sid, s.server, p.spid as os_pid
  2  from v$session s join v$process p on s.paddr = p.addr
  3  where s.username = 'HR' order by s.sid;

       SID SERVER    OS_PID
---------- --------- ------------
       142 DEDICATED 18422
       155 DEDICATED 18461

- 두 세션이 서로 다른 OS 프로세스(18422, 18461)에 1:1로 연결되어 있음
-   => 전용 서버 방식에서는 세션마다 전용 서버 프로세스가 배정된다

- [정리]
-   연결=물리적 통신 경로(선), 세션=논리적 로그인 상태
-   동일 사용자이름으로 같은 인스턴스에 여러 세션을 동시에 만들 수 있다
-   전용 서버에서는 세션-서버 프로세스가 1:1 (12장 공유 서버에서는 달라짐)

- 실습 정리: 두 HR 세션을 각각 종료
HR@salespdb.example.com> exit    -- (터미널 1, 2 각각에서 실행)
SYS@cdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
