-- 14장 실습_04: PDB_FILE_NAME_CONVERT 파라미터를 이용한 PDB 생성

- PDB_FILE_NAME_CONVERT는 FILE_NAME_CONVERT 절과 같은 '원본->대상' 치환 규칙을
-   인스턴스 수준에서 한 번 설정해 두는 것이다. 이후 절 없이도 규칙이 적용된다.
[oracle@dbsvr ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production on Wed Jul 22 11:41:52 2026
Version 19.3.0.0.0

Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0

SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- OMF가 켜져 있으면 파라미터보다 우선하므로, 이 실습에서는 OMF를 끈다.
SYS@cdb1> alter system set db_create_file_dest='';

System altered.

======================================================================
[1단계] (실수) SCOPE=MEMORY로만 설정 -> 재시작 후 사라지는 문제 재현
======================================================================

- 우선 MEMORY로만 설정해 본다(현재 인스턴스에만 적용, SPFILE 미저장).
SYS@cdb1> alter system set pdb_file_name_convert=
  2  '/u01/app/oracle/oradata/CDB1/pdbseed','/u01/app/oracle/oradata/CDB1/pdb3'
  3  scope=memory;

System altered.

- 값이 반영됐는지 확인
SYS@cdb1> show parameter pdb_file_name_convert

NAME                       TYPE     VALUE
-------------------------- -------- ---------------------------------------------
pdb_file_name_convert      string   /u01/app/oracle/oradata/CDB1/pdbseed,
                                     /u01/app/oracle/oradata/CDB1/pdb3

- 그러나 SCOPE=MEMORY라 SPFILE에는 저장되지 않았다. 재시작하면 사라진다.
-   표준 규칙으로 유지하려면 SCOPE=BOTH로 다시 설정한다.
SYS@cdb1> alter system set pdb_file_name_convert=
  2  '/u01/app/oracle/oradata/CDB1/pdbseed','/u01/app/oracle/oradata/CDB1/pdb3'
  3  scope=both;

System altered.

======================================================================
[2단계] 대상 디렉터리 준비 후 절 없이 PDB 생성
======================================================================

- 치환 규칙의 대상 디렉터리를 미리 만든다.
SYS@cdb1> host mkdir -p /u01/app/oracle/oradata/CDB1/pdb3

- FILE_NAME_CONVERT 절 없이 생성 (파라미터 규칙이 자동 적용됨)
SYS@cdb1> create pluggable database pdb3
  2    admin user pdb3_admin identified by "Welcome_1234" roles=(connect);

Pluggable database created.

======================================================================
[3단계] 파라미터 규칙대로 파일이 배치되었는지 확인
======================================================================

SYS@cdb1> select con_id, pdb_name, status from cdb_pdbs where pdb_name='PDB3';

    CON_ID PDB_NAME             STATUS
---------- -------------------- --------------
         6 PDB3                 NEW

- 원본 파일명이 유지된 채 디렉터리만 .../pdbseed -> .../pdb3 로 치환됨을 확인
SYS@cdb1> select tablespace_name, file_name from cdb_data_files
  2  where con_id=6 order by tablespace_name;

TABLESPACE_NAME  FILE_NAME
---------------- ---------------------------------------------------
SYSAUX           /u01/app/oracle/oradata/CDB1/pdb3/sysaux01.dbf
SYSTEM           /u01/app/oracle/oradata/CDB1/pdb3/system01.dbf
UNDOTBS1         /u01/app/oracle/oradata/CDB1/pdb3/undotbs01.dbf

- 해석: OMF와 달리 파일명(system01.dbf 등)은 원본 그대로, 디렉터리만 치환.

======================================================================
[4단계] 우선순위 확인 - 문장의 FILE_NAME_CONVERT 절이 파라미터를 이긴다
======================================================================

- 파라미터가 살아 있어도, 특정 PDB만 다른 위치에 두려면 절을 명시하면 된다.
SYS@cdb1> host mkdir -p /u01/app/oracle/oradata/CDB1/pdb3b

SYS@cdb1> create pluggable database pdb3b
  2    admin user pdb3b_admin identified by "Welcome_1234" roles=(connect)
  3    file_name_convert=('/u01/app/oracle/oradata/CDB1/pdbseed',
  4                       '/u01/app/oracle/oradata/CDB1/pdb3b');

Pluggable database created.

SYS@cdb1> select file_name from cdb_data_files
  2  where con_id=(select con_id from cdb_pdbs where pdb_name='PDB3B')
  3  and tablespace_name='SYSTEM';

FILE_NAME
------------------------------------------------------------
/u01/app/oracle/oradata/CDB1/pdb3b/system01.dbf

- 해석: 파라미터는 .../pdb3 를 가리키지만, 절에 준 .../pdb3b 가 우선 적용됨.
-   즉 '문장 수준 지정'이 '인스턴스 수준 지정'을 이긴다.

======================================================================
[5단계] 열어서 확인 후 정리
======================================================================

SYS@cdb1> alter pluggable database pdb3 open;

Pluggable database altered.

SYS@cdb1> select pdb_name, status from cdb_pdbs where pdb_name in ('PDB3','PDB3B')
  2  order by pdb_name;

PDB_NAME             STATUS
-------------------- --------------
PDB3                 NORMAL
PDB3B                NEW

======================================================================
[정리]
======================================================================
- PDB_FILE_NAME_CONVERT: 인스턴스 수준 치환 규칙. 절 없이 생성 가능.
- 원본 파일명 유지, 디렉터리만 치환(OMF의 자동 파일명과 다름).
- SCOPE=MEMORY는 재시작 시 사라짐 -> 표준화하려면 SCOPE=BOTH.
- 우선순위: 문장 FILE_NAME_CONVERT 절 > 인스턴스 PDB_FILE_NAME_CONVERT 파라미터.
