-- 14장 실습_03: OMF(DB_CREATE_FILE_DEST)를 이용한 PDB 생성

- Oracle Managed Files(OMF)를 켜면 파일 이름과 경로를 Oracle이 자동으로 정한다.
-   DBA는 상위 디렉터리 하나만 지정하면 되고, FILE_NAME_CONVERT 절이 필요 없다.
[oracle@dbsvr ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production on Wed Jul 22 11:03:18 2026
Version 19.3.0.0.0

Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0

SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

======================================================================
[1단계] 현재 OMF 설정 확인 (기본은 비어 있음)
======================================================================

SYS@cdb1> show parameter db_create_file_dest

NAME                      TYPE        VALUE
------------------------- ----------- ------------------------------
db_create_file_dest       string

- 값이 비어 있으므로 OMF가 꺼져 있다. 대상 디렉터리를 지정해 켠다.

======================================================================
[2단계] (실수) 존재하지 않는 디렉터리를 OMF 대상으로 지정 -> 생성 시 오류
======================================================================

- OMF도 지정한 '상위 디렉터리'는 미리 존재해야 한다.
SYS@cdb1> alter system set db_create_file_dest='/u01/app/oracle/oradata/CDB1/pdb2';

System altered.

SYS@cdb1> create pluggable database pdb2
  2    admin user pdb2_admin identified by "Welcome_1234" roles=(connect);
create pluggable database pdb2
*
ERROR at line 1:
ORA-19504: failed to create file
"/u01/app/oracle/oradata/CDB1/pdb2/CDB1/..."
ORA-27040: file create error, unable to create file
Linux-x86_64 Error: 2: No such file or directory

- 원인: 지정한 상위 디렉터리 .../CDB1/pdb2 가 아직 없음. 만든 뒤 재시도한다.
SYS@cdb1> host mkdir -p /u01/app/oracle/oradata/CDB1/pdb2

======================================================================
[3단계] 디렉터리 생성 후 OMF로 PDB 생성 -> 성공 (절이 필요 없음)
======================================================================

SYS@cdb1> create pluggable database pdb2
  2    admin user pdb2_admin identified by "Welcome_1234" roles=(connect);

Pluggable database created.

- FILE_NAME_CONVERT 절 없이 간결하게 생성되었다. 파일 위치는 OMF가 결정한다.

======================================================================
[4단계] 자동 생성된 파일 경로/이름 확인
======================================================================

- 새 PDB(PDB2)의 CON_ID를 확인
SYS@cdb1> select con_id, pdb_name, status from cdb_pdbs where pdb_name='PDB2';

    CON_ID PDB_NAME             STATUS
---------- -------------------- --------------
         5 PDB2                 NEW

- OMF가 만든 데이터 파일 경로를 확인 (o1_mf_ 형식의 자동 파일명)
SYS@cdb1> select file_name from cdb_data_files where con_id=5 order by 1;

FILE_NAME
------------------------------------------------------------------------
/u01/app/oracle/oradata/CDB1/pdb2/CDB1/<GUID>/datafile/o1_mf_sysaux_%u_.dbf
/u01/app/oracle/oradata/CDB1/pdb2/CDB1/<GUID>/datafile/o1_mf_system_%u_.dbf
/u01/app/oracle/oradata/CDB1/pdb2/CDB1/<GUID>/datafile/o1_mf_undotbs1_%u_.dbf

- 해석: 관리자가 파일명을 정하지 않아도 Oracle이 고유한 이름으로 자동 생성.
-   DB별/PDB별 하위 디렉터리 아래 o1_mf_* 규칙을 따른다(충돌·덮어쓰기 방지).

======================================================================
[5단계] 열어서 NORMAL 확인
======================================================================

SYS@cdb1> alter pluggable database pdb2 open;

Pluggable database altered.

SYS@cdb1> select pdb_name, status from cdb_pdbs where pdb_name='PDB2';

PDB_NAME             STATUS
-------------------- --------------
PDB2                 NORMAL

======================================================================
[정리]
======================================================================
- OMF는 DB_CREATE_FILE_DEST로 켜며, 상위 디렉터리만 지정하면 파일명/경로 자동.
- 상위 디렉터리는 미리 존재해야 한다(없으면 ORA-27040).
- OMF는 대량 생성/ASM 환경에서 특히 편리하다. 단 컨테이너 범위 전역에 영향.
SYS@cdb1> exit

Version 19.3.0.0.0
