-- 1장 실습_02: 멀티테넌트 컨테이너 데이터베이스(CDB) 소개 및 구성요소(root/PDB$SEED/PDB) 확인

- 루트 컨테이너로 SYSDBA 접속된 상태에서 현재 컨테이너 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 현재 컨테이너의 이름/CON_ID를 USERENV 컨텍스트로도 확인 (루트는 항상 CON_ID=1)
SYS@cdb1> select sys_context('USERENV','CON_NAME') as con_name,
  2         sys_context('USERENV','CON_ID')   as con_id
  3  from dual;

CON_NAME             CON_ID
-------------------- --------------------
CDB$ROOT             1

======================================================================
[1단계] 이 데이터베이스가 CDB(컨테이너 데이터베이스)인지 확인
======================================================================

- V$DATABASE의 CDB 컬럼이 YES면 멀티테넌트 컨테이너 데이터베이스
-   (루트에서 조회하는 V$DATABASE.CON_ID는 0으로 표기됨)
SYS@cdb1> select name, cdb, con_id from v$database;

NAME      CDB     CON_ID
--------- ------- ----------
CDB1      YES              0

======================================================================
[2단계] CDB 구성요소(root / PDB$SEED / 사용자 PDB) 목록 확인
======================================================================

- CDB에 속한 PDB 목록과 오픈 모드 확인
-   CON_ID=2는 시드(PDB$SEED, 복제 원본이라 항상 READ ONLY), 3 이상은 사용자 PDB
SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 SALESPDB                       READ WRITE
         4 HRPDB                          READ WRITE

- 데이터 딕셔너리 뷰(CDB_PDBS)로 PDB의 상태(STATUS) 확인 - V$PDBS와 상호 보완
SYS@cdb1> select pdb_id, pdb_name, status, con_id from cdb_pdbs order by pdb_id;

    PDB_ID PDB_NAME             STATUS         CON_ID
---------- -------------------- -------------- ----------
         2 PDB$SEED             NORMAL                  2
         3 SALESPDB             NORMAL                  3
         4 HRPDB                NORMAL                  4

- 세 종류 컨테이너(루트+시드+PDB)를 V$CONTAINERS로 한 번에 조망
-   V$PDBS와 달리 루트(CDB$ROOT, CON_ID=1)까지 포함해서 보여 줌
SYS@cdb1> select con_id, name, open_mode from v$containers order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         1 CDB$ROOT                       READ WRITE
         2 PDB$SEED                       READ ONLY
         3 SALESPDB                       READ WRITE
         4 HRPDB                          READ WRITE

======================================================================
[3단계] 공통 사용자(common user) 생성 실습 (실수 -> 오류 -> 재시도)
======================================================================

- 공통 사용자는 반드시 '루트에서' 'C## 접두사'로 생성해야 함
- (실수) 접두사 없이 공통 사용자 생성 시도
SYS@cdb1> create user dba_admin identified by "Welcome_1234" container=all;
create user dba_admin identified by "Welcome_1234" container=all
            *
ERROR at line 1:
ORA-65096: invalid common user or role name

- 원인: CONTAINER=ALL(공통 사용자)인데 이름이 C##/c##로 시작하지 않음.
-   C## 접두사를 붙여 재시도
SYS@cdb1> create user c##dba_admin identified by "Welcome_1234" container=all;

User created.

- 공통 사용자에게 모든 컨테이너 범위(CONTAINER=ALL)로 권한 부여
SYS@cdb1> grant create session, select_catalog_role to c##dba_admin container=all;

Grant succeeded.

======================================================================
[4단계] 컨테이너 컨텍스트 전환 실습 (실수 -> 오류 -> 재시도)
======================================================================

- (실수) 존재하지 않는 PDB 이름으로 컨텍스트 전환 시도
SYS@cdb1> alter session set container = salepdb;
ERROR:
ORA-65011: Pluggable database SALEPDB does not exist.

- 원인: PDB 이름 오타(salepdb). 실제 이름은 SALESPDB. 올바른 이름으로 재시도
SYS@cdb1> alter session set container = salespdb;

Session altered.

- 컨텍스트가 SALESPDB로 전환되었는지 확인
SYS@salespdb> show con_name

CON_NAME
------------------------------
SALESPDB

- 로컬 사용자(local user)는 접두사 제한 없이 현재 PDB 안에만 생성/존재
SYS@salespdb> create user sales_app identified by "Welcome_1234";

User created.

SYS@salespdb> grant create session, resource to sales_app;

Grant succeeded.

- 루트로 복귀
SYS@salespdb> alter session set container = cdb$root;

Session altered.

======================================================================
[5단계] CON_ID별 사용자 분포 확인 (공통 vs 로컬의 차이)
======================================================================

- 공통 사용자는 여러 컨테이너에, 로컬 사용자는 생성된 PDB 하나에만 존재하는지 확인
-   COMMON='YES'면 공통 사용자, 'NO'면 로컬 사용자
SYS@cdb1> select username, common, con_id from cdb_users
  2  where username in ('C##DBA_ADMIN','SALES_APP')
  3  order by username, con_id;

USERNAME             COM     CON_ID
-------------------- --- ----------
C##DBA_ADMIN         YES          1
C##DBA_ADMIN         YES          3
C##DBA_ADMIN         YES          4
SALES_APP            NO           3

- 해석: 공통 사용자 C##DBA_ADMIN은 루트(1)와 모든 사용자 PDB(3,4)에 존재하지만,
-   로컬 사용자 SALES_APP은 자신이 생성된 SALESPDB(CON_ID=3)에만 존재함.

- CON_ID와 컨테이너 이름을 조인해 공통 사용자의 분포를 한눈에 확인
SYS@cdb1> select u.con_id, c.name as container, u.username
  2  from   cdb_users u join v$containers c on u.con_id = c.con_id
  3  where  u.username = 'C##DBA_ADMIN'
  4  order  by u.con_id;

    CON_ID CONTAINER            USERNAME
---------- -------------------- --------------------
         1 CDB$ROOT             C##DBA_ADMIN
         3 SALESPDB             C##DBA_ADMIN
         4 HRPDB                C##DBA_ADMIN

======================================================================
[정리] 실습 계정 삭제
======================================================================

- 로컬 사용자는 해당 PDB 안에서 삭제
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@salespdb> drop user sales_app cascade;

User dropped.

- 공통 사용자는 루트에서 CONTAINER=ALL로 모든 컨테이너에서 제거
SYS@salespdb> alter session set container = cdb$root;

Session altered.

SYS@cdb1> drop user c##dba_admin cascade container=all;

User dropped.

- [정리] CDB 핵심 확인 완료:
-   구성요소 = 루트(CDB$ROOT, CON_ID=1) + 시드(PDB$SEED, CON_ID=2, READ ONLY) + 사용자 PDB(3+)
-   사용자   = 공통(C## 접두사, 루트 생성, 모든 컨테이너 인식) vs 로컬(특정 PDB 전용)
-   조회     = SHOW CON_NAME / V$PDBS / CDB_PDBS / V$CONTAINERS / CDB_USERS(CON_ID 기준)
