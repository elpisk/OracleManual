================================================================================
 31장 실습 05 — Advisory Framework(어드바이저 종류) 확인
 목표: DBA_ADVISOR_* 딕셔너리 뷰로 등록된 어드바이저와 태스크를 조회하고,
       DBMS_ADVISOR 공통 흐름(CREATE_TASK→...→GET_TASK_REPORT)을 이해한다.
 환경: CDB=cdb1 (루트 컨테이너에서 수행)
================================================================================

-- [1] 현재 데이터베이스에 등록된 어드바이저 목록을 확인한다.
$ sqlplus sys@cdb1 as sysdba

SYS@cdb1> SET LINESIZE 160
SYS@cdb1> COLUMN advisor_name FORMAT A34
SYS@cdb1> SELECT advisor_name FROM dba_advisor_definitions ORDER BY advisor_name;

ADVISOR_NAME
----------------------------------
ADDM
Automatic Database Diagnostic Monitor
SQL Access Advisor
SQL Tuning Advisor
Segment Advisor
Undo Advisor
...

-- 어드바이저가 달라도 실행 이력·결과는 DBA_ADVISOR_* 로 통일 조회된다.

--------------------------------------------------------------------------------
-- [2] (오류 → 원인 → 수정)
--     뷰 이름을 잘못 기억해 단수형 DBA_ADVISOR_TASK 로 조회하려다 오류를 만난다.
--------------------------------------------------------------------------------
SYS@cdb1> SELECT task_name, advisor_name, status
  2       FROM  dba_advisor_task            -- (오타: 단수형)
  3      ORDER BY task_name;
  FROM  dba_advisor_task
        *
ERROR at line 2:
ORA-00942: table or view does not exist

SYS@cdb1> -- 원인 파악: 뷰 이름은 복수형 DBA_ADVISOR_TASKS 다. 프레임워크 뷰는
SYS@cdb1> --   DEFINITIONS / TASKS / FINDINGS / RECOMMENDATIONS / ACTIONS 로 구성된다.
SYS@cdb1> -- 사전에서 정확한 이름을 확인한다.
SYS@cdb1> SELECT table_name FROM dictionary
  2       WHERE table_name LIKE 'DBA_ADVISOR%' ORDER BY table_name;

TABLE_NAME
------------------------------
DBA_ADVISOR_ACTIONS
DBA_ADVISOR_DEFINITIONS
DBA_ADVISOR_FINDINGS
DBA_ADVISOR_RECOMMENDATIONS
DBA_ADVISOR_TASKS

SYS@cdb1> -- 수정: 복수형 DBA_ADVISOR_TASKS 로 조회한다.
SYS@cdb1> COLUMN task_name    FORMAT A28
SYS@cdb1> COLUMN advisor_name FORMAT A26
SYS@cdb1> COLUMN status       FORMAT A11
SYS@cdb1> SELECT task_name, advisor_name, status, execution_start
  2       FROM  dba_advisor_tasks
  3      ORDER BY execution_start DESC FETCH FIRST 5 ROWS ONLY;

AUTO_SPACE_ADVISOR_...       Segment Advisor            COMPLETED   22-JUL-26 02:00:01

-- [3] 어드바이저 발견 사항이 공통 뷰(DBA_ADVISOR_FINDINGS)에 어떻게 담기는지 본다.
--------------------------------------------------------------------------------
SYS@cdb1> COLUMN message FORMAT A50
SYS@cdb1> SELECT task_name, type, ROUND(impact,1) AS impact, message
  2       FROM  dba_advisor_findings
  3      WHERE task_name = 'ADDM_120_121'
  4      ORDER BY impact DESC;

-- ADDM 도 어드바이저의 하나이므로 결과가 DBA_ADVISOR_FINDINGS 에 공통 형식으로 나타난다.

--------------------------------------------------------------------------------
-- [4] '증상 → 어드바이저' 대응 감각 정리(주석으로 요약).
--------------------------------------------------------------------------------
SYS@cdb1> -- 특정 SQL 하나가 느림              → SQL Tuning Advisor  (DBMS_SQLTUNE)
SYS@cdb1> -- 신규 앱의 인덱스 설계 통째 검토    → SQL Access Advisor  (DBMS_ADVISOR)
SYS@cdb1> -- 테이블스페이스 공간이 자꾸 부족    → Segment Advisor     (DBMS_SPACE)
SYS@cdb1> -- 버퍼 캐시를 늘릴지 고민            → Memory Advisor      (V$..._ADVICE)
SYS@cdb1> -- ORA-01555(snapshot too old) 잦음  → Undo Advisor        (V$UNDOSTAT)
SYS@cdb1> -- 인스턴스 복구가 오래 걸림          → MTTR Advisor        (V$MTTR_TARGET_ADVICE)

--------------------------------------------------------------------------------
-- [정리]
--------------------------------------------------------------------------------
-- 1) 모든 어드바이저는 DBMS_ADVISOR 공통 API 위에서 동일 패턴으로 동작한다:
--    CREATE_TASK → SET_TASK_PARAMETER → EXECUTE_TASK → GET_TASK_REPORT.
-- 2) 실행 이력/결과는 DBA_ADVISOR_* (DEFINITIONS/TASKS/FINDINGS/RECOMMENDATIONS/ACTIONS)
--    에 공통 형식으로 저장되어 통일된 방식으로 조회·비교할 수 있다.
-- 3) 뷰 이름은 복수형이다(단수형 조회 시 ORA-00942). DICTIONARY 로 확인하는 습관.
-- 4) ADDM 이 문제를 지목하면 해당 어드바이저가 구체안을 낸다(진단 파이프라인).

SYS@cdb1> EXIT
