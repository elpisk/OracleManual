-- 13장 실습_02: CMAN_RULES(RULE_LIST)로 접근 제어 필터링 규칙(SRC/DST/SRV/ACT) 설정

- (전제) 실습_01에서 cman01 이 기동되어 있고 기본 규칙 2개가 적재된 상태이다.
-   이번 실습에서는 재무 DB(dbsvr) 접근을 특정 서브넷만 허용하도록 규칙을 세밀화한다.
[oracle@proxysvr ~]$ export TNS_ADMIN=$ORACLE_HOME/network/admin
[oracle@proxysvr ~]$ cd $TNS_ADMIN

- 접근 통제 설계(문서로 먼저 정리):
-   · 허용: 재무팀 서브넷 192.0.2.0/24 -> dbsvr 의 FINDB01 서비스만
-   · 관리: proxysvr 자기 자신에 대한 cmon 관리 연결 허용
-   · 그 외 모든 소스는 drop(응답 없이 폐기)하여 존재 자체를 숨김

======================================================================
[1단계] RULE_LIST 작성: SRC/DST/SRV/ACT 조합 + 마지막 포괄 차단(drop)
======================================================================

- (실수) 재무팀 서브넷을 192.0.20.0/24 로 잘못 입력한다(오타: 2 -> 20).
-   또한 규칙은 위에서부터 순서대로 평가되므로, 포괄 drop 규칙을 accept 규칙보다
-   위에 두면 허용 규칙이 영영 평가되지 않는 점도 함께 주의해야 한다(여기선 순서는 맞게 둔다).
[oracle@proxysvr admin]$ cat > cman.ora <<'EOF'
cman01=
  (CONFIGURATION=
    (ADDRESS=(PROTOCOL=tcp)(HOST=proxysvr)(PORT=1521))
    (RULE_LIST=
      (RULE=(SRC=192.0.20.0/24)(DST=dbsvr)(SRV=FINDB01)(ACT=accept)
        (ACTION_LIST=(AUT=off)(MCT=120)(MIT=30)))
      (RULE=(SRC=127.0.0.1)(DST=proxysvr)(SRV=cmon)(ACT=accept))
      (RULE=(SRC=*)(DST=*)(SRV=*)(ACT=drop)))
    (PARAMETER_LIST=
      (LOG_LEVEL=SUPPORT)
      (TRACING=on)
      (MAX_GATEWAY_PROCESSES=8)
      (MIN_GATEWAY_PROCESSES=3)))
EOF

- 규칙을 반영: CMCTL에 진입하여 reload (재기동 없이 규칙만 다시 읽음)
[oracle@proxysvr admin]$ cmctl administer cman01

======================================================================
[4단계] reject vs drop 차이 확인: 비허용 서비스 접근은 reject로 명시 거부
======================================================================

- 마지막 포괄 규칙을 잠시 reject 로 바꿔 클라이언트가 받는 응답 차이를 관찰(교육용)
-   drop: 무응답 폐기(타임아웃/refused처럼 보임) / reject: 명시적 거부 오류 즉시 반환
[oracle@proxysvr admin]$ grep 'ACT=drop\|ACT=reject' cman.ora
      (RULE=(SRC=*)(DST=*)(SRV=*)(ACT=drop)))

- [정리]
-   · RULE은 SRC(소스)/DST(목적지)/SRV(서비스)/ACT(accept|reject|drop) 조합으로 구성한다.
-   · 규칙은 위에서부터 평가되어 처음 일치한 규칙의 액션이 적용된다(구체적 규칙을 위로).
-   · 화이트리스트(허용만 나열 + 마지막 포괄 drop) 구조가 안전하며, 로그로 반드시 검증한다.
-   · SRC 대역 오타는 '허용해야 할 접속이 막히는' 대표 원인 -> show rules + 로그로 진단한다.
[oracle@proxysvr admin]$
