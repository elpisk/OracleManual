-- 13장 실습_05: DISPATCHERS의 MULTIPLEX 속성으로 세션 멀티플렉싱 구성

- 세션 멀티플렉싱은 공유 서버(디스패처)의 존재를 전제로 한다.
-   데이터베이스 서버(dbsvr)의 DISPATCHERS에 PROTOCOL과 MULTIPLEX 속성을 설정해 활성화한다.

CDB$ROOT

======================================================================
[1단계] 전제 확인: 공유 서버/디스패처가 구성되어 있는가
======================================================================

- (전제) 12장에서 shared_servers>0 으로 공유 서버가 활성화되어 있어야 멀티플렉싱이 의미가 있다.
SYS@cdb1> show parameter shared_servers

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
max_shared_servers                   integer     40
shared_servers                       integer     2

- 현재 DISPATCHERS 설정 확인 (아직 MULTIPLEX 속성은 없음)
SYS@cdb1> show parameter dispatchers

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
dispatchers                          string      (PROTOCOL=TCP)(DISPATCHERS=2)
max_dispatchers                      integer

======================================================================
[2단계] MULTIPLEX 값 오타로 설정 시도 -> ORA-24323 -> 수정
======================================================================

- (실수) MULTIPLEX 값을 오타(ONN)로 지정하여 설정 시도. 유효 값은 1/ON/YES/TRUE/BOTH/IN/OUT/0/NO/OFF/FALSE.
SYS@cdb1> alter system set dispatchers='(PROTOCOL=TCP)(MULTIPLEX=ONN)(DISPATCHERS=2)' scope=spfile;
alter system set dispatchers='(PROTOCOL=TCP)(MULTIPLEX=ONN)(DISPATCHERS=2)' scope=spfile
*
ERROR at line 1:
ORA-00119: invalid specification for system parameter DISPATCHERS
ORA-24323: value not allowed

- 원인: MULTIPLEX 값 오타(ONN). 유효 값(ON)으로 정정한다.
-   여기서는 '들어오고 나가는 세션 모두'를 다중화하기 위해 ON(=BOTH)을 사용한다.
SYS@cdb1> alter system set dispatchers='(PROTOCOL=TCP)(MULTIPLEX=ON)(DISPATCHERS=2)' scope=spfile;

System altered.

======================================================================
[3단계] 멀티플렉싱은 동적 변경 불가: 재시작이 필요함을 확인
======================================================================

- (확인) MULTIPLEX는 ALTER SYSTEM으로 '동적으로' 켤 수 없다. scope=memory/both 로 즉시 반영을
-   시도해도 실행 중 인스턴스의 멀티플렉싱 동작은 바뀌지 않는다. 그래서 scope=spfile 로만 넣었다.
SYS@cdb1> show parameter dispatchers

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
dispatchers                          string      (PROTOCOL=TCP)(DISPATCHERS=2)
max_dispatchers                      integer

- 위처럼 실행 중 값(메모리)은 아직 이전 값이다(멀티플렉싱 미적용). SPFILE 반영 값을 확인
SYS@cdb1> select value from v$spparameter where name = 'dispatchers';

VALUE
--------------------------------------------------------------------------------
(PROTOCOL=TCP)(MULTIPLEX=ON)(DISPATCHERS=2)

- 멀티플렉싱을 실제로 켜려면 인스턴스를 재시작해야 한다.
SYS@cdb1> shutdown immediate
Database closed.

======================================================================
[4단계] 재시작 후 검증: MULTIPLEX가 실제로 반영되었는가
======================================================================

- 재시작 후 실행 중(메모리) DISPATCHERS 값에 MULTIPLEX=ON 이 반영됨
SYS@cdb1> show parameter dispatchers

NAME                                 TYPE        VALUE
------------------------------------ ----------- ------------------------------
dispatchers                          string      (PROTOCOL=TCP)(MULTIPLEX=ON)(DIS
                                                 PATCHERS=2)
max_dispatchers                      integer

- 디스패처 프로세스가 정상 기동되었는지 확인 (D000, D001)
SYS@cdb1> select name, network, status from v$dispatcher order by name;

NAME   NETWORK                                            STATUS
------ -------------------------------------------------- ----------------
D000   (ADDRESS=(PROTOCOL=tcp)(HOST=dbsvr)(PORT=...))     WAIT
D001   (ADDRESS=(PROTOCOL=tcp)(HOST=dbsvr)(PORT=...))     WAIT

- 멀티플렉싱은 하나의 물리적 연결(회로 집합) 위로 여러 세션이 얹히는 형태로 관찰된다.
-   V$CIRCUIT으로 디스패처-회로 관계를 확인 (CMAN 경유 세션이 들어오면 회로가 늘어난다)
SYS@cdb1> select dispatcher, count(*) circuits
  2  from v$circuit
  3  group by dispatcher
  4  order by dispatcher;

DISPATCHER         CIRCUITS
---------------- ----------
0000000090A1B2C0          3

- 참고: MULTIPLEX=ON 이면 같은 목적지(같은 디스패처)로 향하는 다수 세션이 하나의 전송 연결로
-   다중화되므로, 서버가 유지하는 물리적 연결 수가 클라이언트 수보다 훨씬 적게 유지된다.
SYS@cdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0

- [정리]
-   · 멀티플렉싱은 DISPATCHERS에 (PROTOCOL=TCP)(MULTIPLEX=ON) 처럼 속성을 추가해 활성화한다.
-   · MULTIPLEX 유효 값: 1/ON/YES/TRUE/BOTH(양방향), IN(유입만), OUT(발신만), 0/NO/OFF/FALSE(끔).
-   · ALTER SYSTEM으로 동적 활성화가 불가하므로 SPFILE에 반영 후 인스턴스를 재시작해야 한다.
-   · 공유 서버(디스패처) + CMAN 등록(실습_04) + 클라이언트 CMAN 경로(실습_03)가 정렬되어야 실제 다중화가 일어난다.
