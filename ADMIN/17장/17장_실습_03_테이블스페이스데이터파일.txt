======================================================================
[1단계] 현재 테이블스페이스별 데이터 파일 개수 확인
======================================================================

- 테이블스페이스별로 데이터 파일이 몇 개인지 집계
SYS@cdb1> select tablespace_name, count(*) as file_cnt,
  2         sum(bytes)/1024/1024 as total_mb
  3  from   dba_data_files
  4  group  by tablespace_name
  5  order  by tablespace_name;

TABLESPACE_NAME  FILE_CNT   TOTAL_MB
---------------- -------- ----------
SYSAUX                  1        550
SYSTEM                  1        340
USERS                   1          5

======================================================================
[2단계] 한 테이블스페이스에 데이터 파일 추가 -> 1:N 관계 실습
======================================================================

- (실수) OMF(DB_CREATE_FILE_DEST) 없이 SIZE만 지정하고 파일명을 빠뜨려 시도
SYS@cdb1> alter tablespace users add datafile size 20m;
alter tablespace users add datafile size 20m
*
ERROR at line 1:
ORA-02236: invalid file name

- 원인: OMF가 구성되지 않은 환경에서는 데이터 파일의 경로/이름을 명시해야 함
-   파일명을 지정해 다시 추가
SYS@cdb1> alter tablespace users add datafile
  2  '/u01/app/oracle/oradata/CDB1/salespdb/users02.dbf'
  3  size 20m autoextend on next 10m maxsize 500m;

Tablespace altered.

- USERS 테이블스페이스가 이제 2개의 데이터 파일로 구성됨(1:N)
SYS@cdb1> select file_id, file_name, bytes/1024/1024 as mb,
  2         autoextensible, maxbytes/1024/1024 as max_mb
  3  from   dba_data_files
  4  where  tablespace_name='USERS' order by file_id;

   FILE_ID FILE_NAME                                  MB AUT  MAX_MB
---------- ----------------------------------- --------- --- -------
         7 .../salespdb/users01.dbf                    5 YES     500
        12 .../salespdb/users02.dbf                   20 YES     500

======================================================================
[3단계] 데이터 파일은 하나의 테이블스페이스에만 속함(N:1) 확인
======================================================================

- 각 데이터 파일이 어느 테이블스페이스에 속하는지 -> 각 파일은 정확히 1개 TS에만 매핑
SYS@cdb1> select file_id, tablespace_name from dba_data_files
  2  order by file_id;

   FILE_ID TABLESPACE_NAME
---------- ----------------
         5 SYSTEM
         9 SYSAUX
         7 USERS
        12 USERS

- 하나의 file_id가 두 개의 tablespace_name을 가질 수 없음(구조적으로 불가)

======================================================================
[4단계] 세그먼트가 여러 데이터 파일에 분산 저장될 수 있음 확인
======================================================================

- 두 파일에 걸치도록 큰 테이블을 만들고 대량 삽입
SYS@cdb1> create table hr.spread_demo (id number, pad char(200))
  2  segment creation immediate tablespace users;

Table created.

SYS@cdb1> insert /*+ append */ into hr.spread_demo
  2  select level, 'x' from dual connect by level <= 30000;

30000 rows created.

SYS@cdb1> commit;

Commit complete.

- 이 세그먼트의 익스텐트가 여러 file_id에 분산되었는지 확인
SYS@cdb1> select file_id, count(*) as ext_cnt,
  2         sum(blocks) as blk
  3  from   dba_extents
  4  where  owner='HR' and segment_name='SPREAD_DEMO'
  5  group  by file_id order by file_id;

   FILE_ID    EXT_CNT        BLK
---------- ---------- ----------
         7         14        320
        12         12        448

- 하나의 세그먼트가 file 7 과 file 12 두 데이터 파일에 걸쳐 저장됨(논리는 하나의 세그먼트)

======================================================================
[5단계] 정리 및 원복
======================================================================

SYS@cdb1> drop table hr.spread_demo purge;

Table dropped.

- 실습으로 추가한 데이터 파일 제거(테이블스페이스는 유지)
SYS@cdb1> alter tablespace users drop datafile
  2  '/u01/app/oracle/oradata/CDB1/salespdb/users02.dbf';

Tablespace altered.

- [정리] 테이블스페이스:데이터파일 = 1:N, 데이터파일:테이블스페이스 = N:1
-        하나의 세그먼트는 같은 TS의 여러 데이터 파일에 분산될 수 있음
SYS@cdb1> exit
