CDB$ROOT

======================================================================
[1단계] 컨테이너 목록 확인 (루트/시드/PDB)
======================================================================

SYS@cdb1> select con_id, name, open_mode from v$containers order by con_id;

    CON_ID NAME                 OPEN_MODE
---------- -------------------- ----------
         1 CDB$ROOT             READ WRITE
         2 PDB$SEED             READ ONLY
         3 SALESPDB             READ WRITE
         4 HRPDB                READ WRITE

======================================================================
[2단계] CDB_TABLESPACES로 컨테이너별 SYSTEM/SYSAUX 확인
======================================================================

- 모든 컨테이너의 SYSTEM/SYSAUX가 CON_ID별로 각각 존재함을 확인
SYS@cdb1> select con_id, tablespace_name
  2  from   cdb_tablespaces
  3  where  tablespace_name in ('SYSTEM','SYSAUX')
  4  order  by con_id, tablespace_name;

    CON_ID TABLESPACE_NAME
---------- ----------------
         1 SYSAUX
         1 SYSTEM
         2 SYSAUX
         2 SYSTEM
         3 SYSAUX
         3 SYSTEM
         4 SYSAUX
         4 SYSTEM

8 rows selected.

- 각 컨테이너가 자체 SYSTEM/SYSAUX를 가지므로, 4개 컨테이너 x 2 = 8행

======================================================================
[3단계] 컨테이너별 전체 테이블스페이스 구성(로컬 언두 포함) 확인
======================================================================

SYS@cdb1> select con_id, tablespace_name, contents
  2  from   cdb_tablespaces
  3  order  by con_id, tablespace_name;

    CON_ID TABLESPACE_NAME  CONTENTS

         3 SYSTEM           PERMANENT
         3 TEMP             TEMPORARY

         3 USERS            PERMANENT

- 로컬 언두 모드인지 확인 (19c 기본값 LOCAL)
SYS@cdb1> select property_name, property_value
  2  from   database_properties
  3  where  property_name = 'LOCAL_UNDO_ENABLED';

PROPERTY_NAME          PROPERTY_VALUE
---------------------- ---------------
LOCAL_UNDO_ENABLED     TRUE

======================================================================
[4단계] 접속 컨테이너에 따라 조회 범위가 달라짐 체험
======================================================================

- (실수) 루트에서 DBA_ 뷰로 'salespdb의 SYSTEM 파일'을 보려 했으나 루트 것만 나옴
SYS@cdb1> select tablespace_name, file_name from dba_data_files
  2  where tablespace_name='SYSTEM';

TABLESPACE_NAME  FILE_NAME
---------------- ------------------------------------------
SYSTEM           /u01/app/oracle/oradata/CDB1/system01.dbf

- 원인: DBA_ 뷰는 '현재 접속 컨테이너'만 보여줌. salespdb를 보려면 그 PDB로 전환해야 함
SYS@cdb1> alter session set container = salespdb;

Session altered.

SYS@cdb1> select tablespace_name, file_name from dba_data_files
  2  where tablespace_name='SYSTEM';

TABLESPACE_NAME  FILE_NAME
---------------- --------------------------------------------------
SYSTEM           /u01/app/oracle/oradata/CDB1/salespdb/system01.dbf

- salespdb는 루트와 별개의 SYSTEM 데이터 파일을 가짐(격리/이식성의 근거)

======================================================================
[5단계] 정리
======================================================================

- 루트로 돌아와 CON_ID 요약
SYS@cdb1> alter session set container = cdb$root;

Session altered.

SYS@cdb1> select con_id, count(*) as ts_cnt
  2  from   cdb_tablespaces group by con_id order by con_id;

    CON_ID     TS_CNT
---------- ----------
         1          5
         2          3
         3          5
         4          5

- [정리]
-   각 컨테이너(루트/시드/PDB)는 자체 SYSTEM/SYSAUX를 가짐
-   19c 로컬 언두 모드에서 각 PDB는 자체 언두 테이블스페이스도 가짐
-   DBA_ 뷰는 접속 컨테이너 기준, CDB_ 뷰는 CON_ID로 전체 조망
