-- 26장 실습_03: 데이터 손실 방지 옵션 실습
-- 목표: ROWS(커밋/저장 빈도), Resumable(공간 부족 시 대기 후 재개),
--       UNRECOVERABLE(리두 미생성 -> 적재 후 백업 필요) 옵션의 동작을 확인한다.
--       할당량(quota) 부족으로 적재가 실패하는 상황을 만나 Resumable 로 해결한다.

======================================================================
[1단계] 대상 테이블과 소량 할당량 사용자 준비
======================================================================

[oracle@dbsvr ~]$ sqlplus sys/oracle@pdb1 as sysdba

SYS@pdb1> create user loader identified by loader
  2    default tablespace users quota 64K on users;   -- 일부러 매우 작은 할당량

User created.

SYS@pdb1> grant create session, create table to loader;

Grant succeeded.

SYS@pdb1> conn loader/loader@pdb1
Connected.

LOADER@pdb1> create table big_load ( id number, pad varchar2(200) );

Table created.

LOADER@pdb1> exit
[oracle@dbsvr ~]$

======================================================================
[2단계] 대량 입력 데이터 생성(약 5000행)과 컨트롤 파일
======================================================================

[oracle@dbsvr ~]$ awk 'BEGIN{for(i=1;i<=5000;i++) printf "%d,%s\n", i, "PADDINGDATA_0123456789_0123456789_0123456789"}' > big.csv
[oracle@dbsvr ~]$ wc -l big.csv
5000 big.csv

[oracle@dbsvr ~]$ cat > big.ctl <<'EOF'
LOAD DATA
INFILE 'big.csv'
APPEND
INTO TABLE big_load
FIELDS TERMINATED BY ','
TRAILING NULLCOLS
( id, pad )
EOF

======================================================================
[3단계] ROWS 로 커밋 빈도 제어 (전통적 경로)
======================================================================

- rows=1000 : 1000행마다 커밋(복구 지점을 촘촘히)
[oracle@dbsvr ~]$ sqlldr userid=loader/loader@pdb1 control=big.ctl log=big.log rows=1000 2>&1 | head -20

Version 19.3.0.0.0

Path used:      Conventional
Commit point reached - logical record count 1000
Commit point reached - logical record count 2000

======================================================================
[4단계] (오류 -> 원인 -> 수정) 할당량 부족으로 적재 중단 -> Resumable 로 해결
======================================================================

- 작은 할당량(64K) 때문에 적재 도중 공간 부족으로 실패한다.
[oracle@dbsvr ~]$ grep -i "ORA-" big.log | head -3
ORA-01536: space quota exceeded for tablespace 'USERS'

- 테이블 상태 확인: 일부만 적재되고 멈췄다.
[oracle@dbsvr ~]$ sqlplus loader/loader@pdb1

LOADER@pdb1> select count(*) from big_load;

  COUNT(*)
----------
       XXX     -- 5000 보다 작은 값(중간에 중단)

LOADER@pdb1> exit

- 원인: 사용자 loader 의 USERS 테이블스페이스 할당량이 64K 로 매우 작아,
        적재 도중 ORA-01536(space quota exceeded)으로 적재가 중단되었다.
- 수정 방안 1: 할당량을 늘린다. 방안 2(권장): Resumable 을 켜서 공간 부족 시
        즉시 실패하지 않고 대기하도록 하고, 그 사이 DBA 가 할당량을 늘려 자동 재개시킨다.

- 먼저 테이블을 비우고, Resumable 로 다시 시도한다.
[oracle@dbsvr ~]$ sqlplus loader/loader@pdb1

LOADER@pdb1> truncate table big_load;

Table truncated.

LOADER@pdb1> exit

- Resumable 활성화 로드(최대 1시간 대기). 이 세션은 공간 부족 시 '중단' 상태로 대기한다.
[oracle@dbsvr ~]$ sqlldr userid=loader/loader@pdb1 control=big.ctl log=big2.log \
>        rows=1000 resumable=true resumable_name='big_load_job' resumable_timeout=3600 &
[1] 24680

- (다른 터미널에서) DBA 가 중단된 재개 가능 작업을 확인하고 할당량을 늘린다.
[oracle@dbsvr ~]$ sqlplus sys/oracle@pdb1 as sysdba

SYS@pdb1> select name, status, error_msg from dba_resumable;

NAME           STATUS      ERROR_MSG
-------------- ----------- ----------------------------------------
big_load_job   SUSPENDED   ORA-01536: space quota exceeded for ...

-- SUSPENDED(중단) 상태다. 즉시 실패하지 않고 대기 중이다. 할당량을 늘려 준다.
SYS@pdb1> alter user loader quota unlimited on users;

User altered.

SYS@pdb1> exit

- 할당량이 늘자 중단되었던 적재가 자동으로 재개되어 완료된다.
[oracle@dbsvr ~]$ wait
[1]+  Done      sqlldr userid=loader/loader@pdb1 control=big.ctl ...

[oracle@dbsvr ~]$ grep -i "successfully loaded" big2.log
  5000 Rows successfully loaded.

======================================================================
[5단계] UNRECOVERABLE 다이렉트 로드와 백업 필요성 확인
======================================================================

[oracle@dbsvr ~]$ sqlplus loader/loader@pdb1

LOADER@pdb1> truncate table big_load;

Table truncated.

LOADER@pdb1> exit

- 다이렉트 + UNRECOVERABLE : 리두를 생성하지 않아 더 빠르지만 미디어 복구 불가.
[oracle@dbsvr ~]$ sqlldr userid=loader/loader@pdb1 control=big.ctl log=big3.log \
>        direct=true unrecoverable

SQL*Loader: Release 19.0.0.0.0 - Production on Mon Aug 10 11:20:33 2026
Version 19.3.0.0.0

Table BIG_LOAD:
  5000 Rows successfully loaded.

[oracle@dbsvr ~]$ grep -i "Path used" big3.log
Path used:      Direct

-- 주의: UNRECOVERABLE 로 적재한 데이터는 리두가 없어, 지금 데이터파일이 손상되어
--       백업으로 복구하면 이 5000행을 재현할 수 없다. 따라서 반드시 적재 직후
--       해당 테이블스페이스(또는 DB)를 백업해야 한다.
[oracle@dbsvr ~]$ rman target / <<'EOF'
BACKUP TABLESPACE users;
EOF
-- (실습 환경에서는 개념 확인용. 운영에서는 적재 직후 백업이 데이터 손실 방지의 핵심.)

======================================================================
[정리]
======================================================================
- ROWS: 전통 경로에선 커밋 단위(작게=복구 지점 촘촘), 다이렉트 경로에선 데이터 저장 지점.
- Resumable(RESUMABLE=TRUE): 공간 부족(ORA-01536/01653 등) 시 실패 대신 SUSPENDED 로
  대기 -> DBA 가 공간/할당량 확보 시 자동 재개. DBA_RESUMABLE 로 모니터링.
- UNRECOVERABLE: 다이렉트 경로 전용. 리두 미생성으로 빠르나 미디어 복구 불가 ->
  적재 직후 반드시 백업.

- 뒷정리
[oracle@dbsvr ~]$ sqlplus sys/oracle@pdb1 as sysdba

SYS@pdb1> drop user loader cascade;

User dropped.

SYS@pdb1> exit
[oracle@dbsvr ~]$ rm -f big.csv big.ctl big.log big2.log big3.log
[oracle@dbsvr ~]$
