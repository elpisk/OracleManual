-- 26장 실습_04: SQL*Loader Express Mode 실습
-- 목표: 컨트롤 파일 없이 TABLE= 파라미터만으로 CSV 를 적재한다.
--       기본 명명 규칙(테이블명.dat, 쉼표 구분)과 자동 생성 컨트롤 파일을 확인하고,
--       데이터 파일명이 규칙과 달라 발생하는 오류를 만나 data= 로 해결한다.

======================================================================
[1단계] 대상 테이블 준비
======================================================================

[oracle@dbsvr ~]$ sqlplus hr/oracle@pdb1

HR@pdb1> create table product (
  2    prod_id   number(6),
  3    prod_name varchar2(40),
  4    price     number(10)
  5  );

Table created.

HR@pdb1> exit
[oracle@dbsvr ~]$

======================================================================
[2단계] (오류 -> 원인 -> 수정) 기본 규칙과 파일명 불일치
======================================================================

- 먼저 규칙과 다른 이름(products_2026.csv)으로 데이터를 만든다.
[oracle@dbsvr ~]$ cat > products_2026.csv <<'EOF'
1001,Keyboard,25000
1002,Mouse,15000
1003,Monitor,220000
EOF

- Express Mode: TABLE=product 만 지정하고 실행(컨트롤 파일 없음).
--   기본 규칙상 SQL*Loader 는 입력 파일명을 'product.dat' 로 가정한다.
[oracle@dbsvr ~]$ sqlldr userid=hr@pdb1 table=product

SQL*Loader: Release 19.0.0.0.0 - Production on Mon Aug 10 13:05:12 2026
Version 19.3.0.0.0

Express Mode Load, Table: PRODUCT
Data file(s): product.dat

SQL*Loader-500: Unable to open file (product.dat)
SQL*Loader-553: file not found
SQL*Loader-509: System error: No such file or directory

- 원인: Express Mode 는 기본적으로 입력 파일을 '테이블명.dat', 즉 product.dat 로
        가정한다. 그런데 실제 파일명은 products_2026.csv 라서 파일을 찾지 못했다.
- 수정: data= 파라미터로 실제 데이터 파일명을 지정한다.

[oracle@dbsvr ~]$ sqlldr userid=hr@pdb1 table=product data=products_2026.csv

SQL*Loader: Release 19.0.0.0.0 - Production on Mon Aug 10 13:06:40 2026
Version 19.3.0.0.0

Express Mode Load, Table: PRODUCT
Data file(s): products_2026.csv

Table PRODUCT:
  3 Rows successfully loaded.

Check the log files:
  product.log
  product.log_xt
for more information about the load.

======================================================================
[3단계] 적재 결과와 자동 생성 로그·컨트롤 파일 확인
======================================================================

[oracle@dbsvr ~]$ sqlplus hr/oracle@pdb1

HR@pdb1> select prod_id, prod_name, price from product order by prod_id;

   PROD_ID PROD_NAME             PRICE
---------- --------------- -----------
      1001 Keyboard              25000
      1002 Mouse                 15000
      1003 Monitor              220000

-- 컨트롤 파일을 전혀 작성하지 않았는데도, 딕셔너리의 컬럼 정보를 이용해
-- prod_id/prod_name/price 순서로 CSV 필드가 자동 매핑되어 적재되었다.

HR@pdb1> exit

- Express Mode 는 실행 시 자동으로 컨트롤 파일 내용을 로그에 남긴다.
[oracle@dbsvr ~]$ grep -iA12 "Express Mode generated control file" product.log
Express Mode generated control file:
LOAD DATA
INFILE 'products_2026.csv'
APPEND
INTO TABLE PRODUCT
FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
TRAILING NULLCOLS
( PROD_ID, PROD_NAME, PRICE )

-- 이 자동 생성 컨트롤 파일을 저장해 두면, 나중에 복잡한 변환이 필요할 때
-- 이를 손질해 정식 컨트롤 파일로 발전시킬 수 있다.

======================================================================
[4단계] (참고) 기본 규칙에 맞춘 실행
======================================================================

- 파일명을 product.dat 로 맞추면 data= 없이 TABLE= 만으로 적재된다.
[oracle@dbsvr ~]$ sqlplus hr/oracle@pdb1 <<'EOF'
truncate table product;
exit
EOF
[oracle@dbsvr ~]$ cp products_2026.csv product.dat
[oracle@dbsvr ~]$ sqlldr userid=hr@pdb1 table=product

Express Mode Load, Table: PRODUCT
Data file(s): product.dat

Table PRODUCT:
  3 Rows successfully loaded.

-- 이번엔 data= 를 생략해도 규칙대로 product.dat 를 찾아 적재했다.

======================================================================
[정리]
======================================================================
- Express Mode: TABLE=테이블명 만으로 컨트롤 파일 없이 CSV 적재.
- 기본 규칙: 데이터 파일=테이블명.dat, 구분자=쉼표, 감싸기=큰따옴표,
  컬럼 순서대로 자동 매핑, 다이렉트 경로 우선 시도.
- 파일명이 규칙과 다르면 SQL*Loader-500/553(file not found) -> data= 로 지정.
- 자동 생성 컨트롤 파일은 로그에서 확인 가능하며 정식 컨트롤 파일의 출발점이 된다.
- 복잡한 변환·WHEN 조건·다중 테이블 적재는 여전히 정식 컨트롤 파일이 필요하다.

- 뒷정리
[oracle@dbsvr ~]$ sqlplus hr/oracle@pdb1

HR@pdb1> drop table product purge;

Table dropped.

HR@pdb1> exit
[oracle@dbsvr ~]$ rm -f products_2026.csv product.dat product.log product.log_xt
[oracle@dbsvr ~]$
