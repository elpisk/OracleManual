-- 16장 실습_03: PDB 내에서 ALTER SYSTEM 명령 사용 제약 확인 - ORA-65040 재현

- CDB 루트에 SYSDBA로 연결된 상태에서 시작
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 실습 대상 pdb1으로 컨텍스트 전환
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@pdb1> show con_name

CON_NAME
------------------------------
PDB1

======================================================================
[1단계] PDB에서 변경 불가한 파라미터 변경 시도 (실수 -> ORA-65040)
======================================================================

- (실수) 인스턴스 전역 설정인 db_block_size를 PDB에서 바꾸려 시도
SYS@pdb1> alter system set db_block_size = 16384 scope=spfile;
alter system set db_block_size = 16384 scope=spfile
*
ERROR at line 1:
ORA-65040: operation not allowed from within a pluggable database

- 원인 확인: db_block_size의 ISPDB_MODIFIABLE이 FALSE인지 조회
SYS@pdb1> select name, ispdb_modifiable from v$parameter
  2  where name = 'db_block_size';

NAME                 ISPDB_MODIFIABLE
-------------------- ----------------
db_block_size        FALSE

- 해석: db_block_size는 CDB 생성 시점에 고정되는 인스턴스 전역 값이라 PDB에서 변경할 수 없다.
-   이런 파라미터는 루트에서만, 그것도 재생성 수준으로만 다룬다.

======================================================================
[2단계] PDB에서 허용되는 파라미터 변경 (ISPDB_MODIFIABLE=TRUE)
======================================================================

- open_cursors는 TRUE이므로 PDB에서 정상적으로 변경된다
SYS@pdb1> alter system set open_cursors = 400 scope=both;

System altered.

SYS@pdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     400

======================================================================
[3단계] 실행은 되지만 영향이 인스턴스 전체에 미치는 동작성 명령
======================================================================

- 체크포인트 강제: DBWn이 인스턴스 공유 버퍼 캐시의 더티 블록을 기록
SYS@pdb1> alter system checkpoint;

System altered.

- 공유 풀 비우기: 공유 풀은 CDB 전체가 공유하는 자원
SYS@pdb1> alter system flush shared_pool;

System altered.

- 해석: 위 두 명령은 PDB 안에서 실행 가능하지만 대상 자원(버퍼 캐시·공유 풀)이
-   인스턴스 공유 자원이므로 실제 영향은 CDB 전역에 미친다.
-   ('설정의 격리'와 '동작의 공유'를 구분하는 것이 이 실습의 핵심)

======================================================================
[4단계] PDB에서 인스턴스 생명주기 작업 시도 (실수 -> 오류)
======================================================================

- (실수) PDB 세션에서 인스턴스 자체를 종료하려 시도
SYS@pdb1> shutdown immediate;
ORA-65040: operation not allowed from within a pluggable database

- 원인: STARTUP/SHUTDOWN은 인스턴스(루트/CDB) 수준 개념이다.
-   PDB는 이미 떠 있는 인스턴스 위에서 열고 닫히는 컨테이너일 뿐이므로
-   PDB 세션에서 인스턴스를 종료할 수 없다. PDB는 CLOSE로 닫는다.
SYS@pdb1> alter session set container = cdb$root;

Session altered.

- 인스턴스 종료가 필요하면 루트에서 수행한다(여기서는 실습이므로 실행하지 않음).
SYS@cdb1> select sys_context('USERENV','CON_NAME') as con_name from dual;

CON_NAME
------------------------------
CDB$ROOT

- [정리] PDB 내 ALTER SYSTEM 3가지 판단 질문:
-   1) 설정(SET)인가 동작 명령인가?
-   2) 설정이면 대상 파라미터 ISPDB_MODIFIABLE이 TRUE인가? (FALSE면 ORA-65040)
-   3) 동작이면 자원이 PDB 전용인가 인스턴스 공유인가?
SYS@cdb1> exit
Disconnected from Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.3.0.0.0
[oracle@dbsvr ~]$
