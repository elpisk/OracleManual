-- 16장 실습_06: PDB 초기화 파라미터 변경 전/후 비교 시나리오 - 격리성 검증

- CDB 루트에 SYSDBA로 연결된 상태에서 시작
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

- 실습 대상 PDB 두 개(pdb1, pdb2)를 정상 오픈
SYS@cdb1> alter pluggable database pdb1, pdb2 open read write force;

Pluggable database altered.

======================================================================
[1단계] 변경 전 - 루트와 두 PDB의 open_cursors 값 스냅샷
======================================================================

- 루트 값 확인
SYS@cdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     50

- 컨테이너별 실제 값을 한 번에 비교 (V$SYSTEM_PARAMETER를 CON_ID로 조회)
SYS@cdb1> select c.con_id, c.name as container, p.value as open_cursors
  2  from v$containers c
  3  join v$system_parameter p on 1=1
  4  where p.name='open_cursors' and c.con_id in (1,3,4)
  5  order by c.con_id;

- (실수) 위 조인은 컨테이너별 값을 정확히 구분하지 못한다.
-   V$SYSTEM_PARAMETER는 현재 접속 컨테이너의 값만 보여 주므로, 각 PDB에 전환해 확인해야 한다.
-   올바른 방법으로 다시 진행한다.

- pdb1의 변경 전 값
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@pdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     50

- pdb2의 변경 전 값
SYS@pdb1> alter session set container = pdb2;

Session altered.

SYS@pdb2> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     50

======================================================================
[2단계] pdb1에서만 값을 변경 (SCOPE=BOTH)
======================================================================

SYS@pdb2> alter session set container = pdb1;

Session altered.

SYS@pdb1> alter system set open_cursors = 500 scope=both;

System altered.

======================================================================
[3단계] 변경 후 - 세 컨테이너 비교로 격리성 검증
======================================================================

- pdb1: 500으로 바뀜
SYS@pdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     500

- pdb2: 여전히 50 (영향 없음)
SYS@pdb1> alter session set container = pdb2;

Session altered.

SYS@pdb2> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     50

- 루트: 여전히 50 (영향 없음)
SYS@pdb2> alter session set container = cdb$root;

Session altered.

SYS@cdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     50

- 결론: pdb1의 변경은 pdb1에만 적용되고 루트·pdb2에는 파급되지 않는다(멀티테넌트 격리성).

======================================================================
[4단계] SCOPE 차이 확인 - MEMORY vs BOTH의 재기동 후 동작
======================================================================

- pdb1에서 MEMORY로만 300 설정 (저장하지 않음)
SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@pdb1> alter system set open_cursors = 300 scope=memory;

System altered.

SYS@pdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     300

- PDB를 닫았다 다시 열면 MEMORY 변경은 사라지고 저장된 값(500)으로 복원됨
SYS@pdb1> alter session set container = cdb$root;

Session altered.

SYS@cdb1> alter pluggable database pdb1 close immediate;

Pluggable database altered.

SYS@cdb1> alter pluggable database pdb1 open;

Pluggable database altered.

SYS@cdb1> alter session set container = pdb1;

Session altered.

SYS@pdb1> show parameter open_cursors

NAME                                 TYPE        VALUE
------------------------------------ ----------- -----
open_cursors                         integer     500

- 해석: SCOPE=MEMORY는 재오픈 시 사라지고, SCOPE=BOTH로 저장한 값(500)이 복원된다.
-   PDB의 SPFILE-범위 값은 물리 SPFILE이 아니라 PDB 내부(PDB_SPFILE$)에 저장되어
-   PDB를 다른 CDB로 옮겨도 함께 따라간다.

- [정리] 전/후 비교 시나리오 결론:
-   변경 전후를 각 컨테이너에 전환해 SHOW PARAMETER로 비교하는 것이 가장 정확
-   ISPDB_MODIFIABLE=TRUE 파라미터의 PDB 변경은 그 PDB에만 격리 적용
-   SCOPE=BOTH만 재오픈 후에도 유지, MEMORY는 휘발
