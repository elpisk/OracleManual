-- 16장 실습_05: PDB 삭제(DROP PLUGGABLE DATABASE) 실습 - KEEP/INCLUDING DATAFILES

- CDB 루트에 SYSDBA로 연결된 상태에서 현재 PDB 목록 확인
SYS@cdb1> show con_name

CON_NAME
------------------------------
CDB$ROOT

SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 PDB1                           READ WRITE
         4 PDB2                           READ WRITE
         5 PDB3                           READ WRITE

======================================================================
[1단계] 열려 있는 PDB 드롭 시도 (실수 -> ORA-65025 -> 닫고 재시도)
======================================================================

- (실수) pdb3가 열려 있는 상태에서 곧바로 드롭 시도
SYS@cdb1> drop pluggable database pdb3 including datafiles;
drop pluggable database pdb3 including datafiles
*
ERROR at line 1:
ORA-65025: Pluggable database PDB3 is not closed on all instances.

- 원인: PDB를 드롭하려면 모든 인스턴스에서 닫혀(MOUNTED) 있어야 한다.
-   표준 절차는 '닫기 -> 드롭' 두 단계. 먼저 즉시 닫는다.
SYS@cdb1> alter pluggable database pdb3 close immediate;

Pluggable database altered.

SYS@cdb1> select name, open_mode from v$pdbs where name='PDB3';

NAME                           OPEN_MODE
------------------------------ ----------
PDB3                           MOUNTED

======================================================================
[2단계] 데이터 파일까지 삭제하며 드롭 (INCLUDING DATAFILES)
======================================================================

- 완전 폐기: 메타데이터 제거 + 데이터 파일 디스크에서 삭제
SYS@cdb1> drop pluggable database pdb3 including datafiles;

Pluggable database dropped.

- 드롭 후 pdb3가 목록에서 사라졌는지 확인
SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 PDB1                           READ WRITE
         4 PDB2                           READ WRITE

======================================================================
[3단계] 데이터 파일을 보존하며 드롭 (KEEP DATAFILES, 기본값)
======================================================================

- 안전을 위해 드롭 전에 언플러그로 '탈출구'(아카이브)를 남겨 둔다
SYS@cdb1> alter pluggable database pdb2 close immediate;

Pluggable database altered.

SYS@cdb1> alter pluggable database pdb2 unplug into '/backup/pdb2.pdb';

Pluggable database altered.

- 이제 메타데이터만 제거하고 데이터 파일은 디스크에 남긴다 (KEEP는 기본값이라 생략 가능)
SYS@cdb1> drop pluggable database pdb2 keep datafiles;

Pluggable database dropped.

- 드롭 결과 확인: CDB에는 pdb1만 남음
SYS@cdb1> select con_id, name, open_mode from v$pdbs order by con_id;

    CON_ID NAME                           OPEN_MODE
---------- ------------------------------ ----------
         2 PDB$SEED                       READ ONLY
         3 PDB1                           READ WRITE

======================================================================
[4단계] 잘못된 옵션으로 언플러그 대상 드롭 방지 확인
======================================================================

- (주의 사례) 언플러그해서 다른 CDB로 옮길 PDB는 INCLUDING DATAFILES로 지우면 안 된다.
-   그렇게 하면 재플러그에 쓸 데이터 파일이 사라져 복구가 불가능해진다.
-   위 3단계처럼 KEEP DATAFILES(또는 언플러그만)로 파일을 보존해야 한다.

- 생애 주기 이력에서 드롭/언플러그 흔적 확인 (현존 PDB는 CDB_PDBS에서 조회)
SYS@cdb1> select pdb_name, status from cdb_pdbs order by pdb_name;

PDB_NAME             STATUS
-------------------- --------------
PDB$SEED             NORMAL
PDB1                 NORMAL

- 해석: 완전히 드롭된 pdb2·pdb3는 CDB_PDBS·V$PDBS 어디에서도 더 이상 조회되지 않는다.

- [정리] PDB 드롭 핵심:
-   전제: 모든 인스턴스에서 닫힘(MOUNTED). 열려 있으면 ORA-65025.
-   KEEP DATAFILES(기본)=파일 보존, INCLUDING DATAFILES=파일까지 삭제.
-   되돌릴 수 없으므로 드롭 전 언플러그(.pdb) 또는 백업 권장.
